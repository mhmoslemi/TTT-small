```python
def compute_c5(h, dx):
    corr = np.correlate(h, 1.0 - h, mode="full")
    return float(np.max(corr) * dx)

def obj_func(h, dx, alpha, penalty):
    corr = np.correlate(h, 1.0 - h, mode="full")
    vals = corr * dx
    m = float(np.max(vals))
    shifted = alpha * (vals - m)
    smooth_max = m + float(np.log(np.sum(np.exp(shifted)) / len(shifted))) / alpha
    sum_diff = float(np.sum(h)) - len(h) / 2.0
    return smooth_max + penalty * sum_diff * sum_diff

def project_box_sum(h, c):
    n = len(h)
    lo = float(h.min()) - 2.0
    hi = float(h.max()) + 2.0
    for _ in range(100):
        mid = (lo + hi) / 2.0
        proj = np.clip(h - mid, 0.0, 1.0)
        if float(np.sum(proj)) > c:
            lo = mid
        else:
            hi = mid
    t = (lo + hi) / 2.0
    return np.clip(h - t, 0.0, 1.0)
```

One issue: in `optimize_piecewise`, the position parameters can be in any order (the function sorts them internally). But this creates a non-differentiability when two positions cross. L-BFGS-B might have trouble with this.

A fix: constrain the positions to be ordered, i.e., 0 <= pos[0] <= pos[1] <= ... <= pos[m-1] <= 1. This can be done by parameterizing them as cumulative sums of non-negative quantities.

```python
def piecewise_h_params(params, n, n_steps):
    """params: [d0, d1, ..., d_{m-1}, v0, v1, ..., v_{m-1}]
    where d_i >= 0, and positions are cumulative sums (normalized to [0,1])
    """
    m = n_steps
    d = params[:m]  # gaps, all >= 0
    values = params[m:2*m]
    
    # Cumulative sum gives unnormalized positions
    cumsum = np.cumsum(d)
    total = cumsum[-1]
    if total < 1e-10:
        total = 1.0
    positions = cumsum / total * 2.0  # Now in [0, 2]
    
    x = np.linspace(0.0, 2.0, n, endpoint=False)
    indices = np.searchsorted(positions, x, side='right') - 1
    indices = np.clip(indices, 0, m - 1)
    h = values[indices]
    return h

def piecewise_obj2(params, n, n_steps, dx, alpha, penalty):
    h = piecewise_h_params(params, n, n_steps)
    return obj_func(h, dx, alpha, penalty)

def optimize_piecewise2(n, dx, n_steps, alpha, penalty, max_iter, rng):
    m = n_steps
    # Bounds: gaps in [0, 1], values in [0, 1]
    bounds = [(0.0, 1.0)] * (2 * m)
    
    x0 = rng.rand(2 * m)
    x0[:m] = np.abs(x0[:m]) + 0.01  # Ensure positive gaps
    
    result = minimize(
        piecewise_obj2, x0,
        args=(n, n_steps, dx, alpha, penalty),
        method='L-BFGS-B',
        bounds=bounds,
        options={'maxiter': max_iter, 'ftol': 1e-10}
    )
    
    h = piecewise_h_params(result.x, n, n_steps)
    return project_box_sum(h, n / 2.0)
```

One more idea: **alternating minimization**. Fix all h values except one, optimize that one coordinate, then move to the next. This is coordinate descent and can be quite effective for non-convex problems.

For a single coordinate h[j], the objective is:
smooth_max_k (corr[k] * dx) where corr[k] depends on h[j] linearly (since corr[k] = sum_i h[i](1-h[i+k-n+1]) is bilinear, and fixing all h[i] for i≠j makes it linear in h[j]).

So for a fixed h[j], the correlation at lag k is:
corr[k] = c0[k] + h[j] * c1[k]

where c0[k] and c1[k] are constants (depending on the other h values).

The objective is max_k (c0[k] + h[j]*c1[k]) * dx.

This is a convex function of h[j] (max of linear functions)! So we can minimize it exactly for each coordinate.

This is a great insight! We can use **exact coordinate descent**:
1. For each coordinate j, compute the effect of h[j] on all correlations
2. Minimize the (smooth approximated) max over h[j] in [0,1]
3. Repeat until convergence

This is much better than L-BFGS-B because:
- Each coordinate step is exact (or nearly exact with smooth max)
- No issues with the sum constraint (we can handle it separately)
- Guaranteed to decrease the objective at each step

The terms involving h[j] are:

```python
                lambda x: smooth_max_1d(C + x * F, dx, alpha),
                bounds=(0.0, 1.0),
                method='bounded',
                options={'xatol': 1e-10}
            )
            h[j] = res.x
        
        # Project to satisfy sum constraint
        if sum_constraint:
            h = project_box_sum(h, n / 2.0)
    
    return h
```

But actually, I'm recomputing the full correlation at each coordinate, which is O(n^2). So per sweep it's O(n^3). For n=47, each correlate call is fast (it's implemented in C), so this should be fine.

Actually, I can avoid recomputing the full correlation by updating it incrementally. After changing h[j], the new correlation is:
new_corr[k] = old_corr[k] + (new_hj - old_hj) * F[k]

This is O(n) per coordinate (for the update), making the whole sweep O(n^2). Much better!
