3. Find x ∈ [0,1] minimizing max_k (c_k_current + (x - h[i]) * b_k)
   where b_k = dc_k/dh[i] (the partial derivative at the current point)
   
4. But we also need sum(h) = 35. If we change h[i] from its current value to x, the sum changes by (x - h[i]). We need to adjust other coordinates to compensate.

This is where it gets tricky. One approach:

- This is an approximation but might work well in practice.

Another approach: use the sum constraint as a penalty with large weight, and optimize the penalized 1D problem.

Or: use the fact that we're doing cyclic coordinate descent. After all coordinates have been visited, the sum might be off, so we apply a global repair at the end of each cycle.

   - Set h[i] = x
2. After each full cycle: repair h (scale to sum=35, clip to [0,1])
3. Repeat

def coord_descent_one_step(h, i, n):
    """Find optimal h[i] given all other coordinates fixed."""
    dx = 2.0 / n
    # Current correlation values
    corr = np.correlate(h, 1.0 - h, mode='full')
    c = corr * dx
    
    # df_k/dh[i] for each k (lag m)
    b = np.zeros(2*n - 1)
    for m in range(2*n - 1):
        k = m - (n - 1)
        if k >= 0:
            b[m] = 0.0
            if 0 <= i - k < n:
                b[m] += (1.0 - h[i - k])
            if 0 <= i + k < n:
                b[m] += (-h[i + k])
        else:
            kk = -k
            b[m] = 0.0
            if 0 <= i + kk < n:
                b[m] += (1.0 - h[i + kk])
            if i - kk >= 0:
                b[m] += (-h[i - kk])
        b[m] *= dx
    
    # Now c_k(x) = c[m] + (x - h[i]) * b[m] for x in [0,1]
    # We want to minimize max_m (c[m] + (x - h[i]) * b[m])
    # Try a grid
    x_grid = np.linspace(0, 1, 101)
    best_x = h[i]
    best_val = np.max(c)
    for x in x_grid:
        c_new = c + (x - h[i]) * b
        val = np.max(c_new)
        if val < best_val:
            best_val = val
            best_x = x
    return best_x

Wait, I realize there's an issue. When I change h[i] to x, the correlation values change. But I'm using the linear approximation c_k(x) ≈ c_k(current) + (x - h[i]) * dc_k/dh[i]. Since c_k is actually linear in h[i] (not just approximately), this is exact! So the grid search on the exact objective is valid.

But wait, I need to double-check. Is c_k truly linear in h[i]?

c_k = dx * sum_j h[j] * (1-h[j+k])

The terms involving h[i]:
- j = i: h[i] * (1-h[i+k]) → this is h[i] * (1-h[i+k]), which is linear in h[i] (since h[i+k] is fixed)
- j such that j+k = i, i.e., j = i-k: h[i-k] * (1-h[i]) → this is h[i-k] * (1-h[i]), which is linear in h[i]

So c_k = dx * [B_k + h[i]*(1-h[i+k])_valid + h[i-k]*(1-h[i])_valid]
       = dx * [B_k + h[i]*(1-h[i+k])_valid - h[i]*h[i-k]_valid + h[i-k]_valid]
       = dx * [B_k + h[i-k]_valid + h[i]*((1-h[i+k])_valid - h[i-k]_valid)]

Yes, linear in h[i]. 

So my coordinate descent step is exact (for the 1D subproblem without the sum constraint).

import numpy as np
from scipy.optimize import minimize
import time

def compute_c5(h):
    n = len(h)
    corr = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(corr)) * (2.0 / n)

def repair(h, target_sum):
    h = np.array(h, dtype=float).copy()
    for _ in range(200):
        h = np.clip(h, 0.0, 1.0)
        s = np.sum(h)
        if abs(s - target_sum) < 1e-12:
            break
        h = h * (target_sum / s)
    return np.clip(h, 0.0, 1.0)

def smooth_obj(h, T):
    n = len(h)
    corr = np.correlate(h, 1.0 - h, mode='full')
    c = corr * (2.0 / n)
    c_max = np.max(c)
    return c_max + np.log(np.sum(np.exp(c - c_max))) / T

def smooth_grad(h, T):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    c = corr * dx
    c_max = np.max(c)
    p = np.exp(c - c_max) / np.sum(np.exp(c - c_max))
    grad = np.zeros(n)
    for m in range(2 * n - 1):
        w = p[m] * dx
        if w < 1e-10:
            continue
        k = m - (n - 1)
        if k >= 0:
            if n > k:
                grad[k:] += w * (1.0 - h[:n-k])
                grad[:n-k] += -w * h[k:]
        else:
            kk = -k
            if n > kk:
                grad[:n-kk] += w * (1.0 - h[kk:])
                grad[kk:] += -w * h[:n-kk]
    return grad

def coord_step(h, i, n, n_grid=201):
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    c = corr * dx
    
    b = np.zeros(2*n - 1)
    for m in range(2*n - 1):
        k = m - (n - 1)
        if k >= 0:
            if 0 <= i - k < n:
                b[m] += (1.0 - h[i - k])
            if 0 <= i + k < n:
                b[m] += (-h[i + k])
        else:
            kk = -k
            if 0 <= i + kk < n:
                b[m] += (1.0 - h[i + kk])
            if i - kk >= 0:
                b[m] += (-h[i - kk])
    b *= dx
    
    x_grid = np.linspace(0, 1, n_grid)
    best_x = h[i]
    best_val = np.inf
    for x in x_grid:
        val = np.max(c + (x - h[i]) * b)
        if val < best_val:
            best_val = val
            best_x = x
    return best_x

    np.random.seed(seed)
    t0 = time.time()
    n = 70
    target_sum = 35.0
    
    if 'initial_h_values' in globals():
        h = repair(np.array(initial_h_values, dtype=float), target_sum)
    else:
        h = repair(np.random.rand(n), target_sum)
    
    best_h = h.copy()
    best_c5 = compute_c5(best_h)
    
    # Phase 1: Coordinate descent
    max_cd_time = 300
    while time.time() - t0 < max_cd_time:
        improved = False
        for i in range(n):
            if time.time() - t0 > max_cd_time:
                break
            new_val = coord_step(h, i, n)
            if abs(new_val - h[i]) > 1e-6:
                h[i] = new_val
                h = repair(h, target_sum)
                improved = True
        if not improved:
            break
    
    current_c5 = compute_c5(h)
    if current_c5 < best_c5:
        best_c5 = current_c5
        best_h = h.copy()
    
    # Phase 2: SLSQP optimization with different T values
    T_list = [30, 50, 100, 200, 500]
    for T in T_list:
        if time.time() - t0 > budget_s - 60:
            break
        
        def obj_func(x):
            return smooth_obj(x, T)
        
        def grad_func(x):
            return smooth_grad(x, T)
        
        def constraint_fun(x):
            return np.sum(x) - target_sum
        
        def constraint_jac(x):
            return np.ones(n)
        
        constraints = {'type': 'eq', 'fun': constraint_fun, 'jac': constraint_jac}
        bounds = [(0.0, 1.0)] * n
        
        try:
            res = minimize(obj_func, best_h, jac=grad_func, method='SLSQP',
                          bounds=bounds, constraints=constraints,
                          options={'maxiter': 500, 'ftol': 1e-12})
            if res.success or (hasattr(res, 'x') and np.all(np.isfinite(res.x))):
                h_trial = repair(res.x, target_sum)
                c5_trial = compute_c5(h_trial)
                if c5_trial < best_c5:
                    best_c5 = c5_trial
                    best_h = h_trial
        except Exception:
            pass
    
    # Phase 3: More coordinate descent rounds
    remaining = budget_s - 30
    if time.time() - t0 < t0 + remaining:
        while time.time() - t0 < t0 + remaining:
            improved = False
            for i in range(n):
                if time.time() - t0 > t0 + remaining:
                    break
                new_val = coord_step(best_h, i, n)
                if abs(new_val - best_h[i]) > 1e-6:
                    best_h[i] = new_val
                    best_h = repair(best_h, target_sum)
                    improved = True
            if not improved:
                break
        final_c5 = compute_c5(best_h)
        if final_c5 < best_c5:
            best_c5 = final_c5
    
    final_h = repair(best_h, target_sum)
    final_c5 = compute_c5(final_h)
    return (final_h, final_c5, n)

Let me also think about what "good" solutions look like. The Erdős problem for C₅ is related to the "minimum overlap" problem. The best known constructions often have a specific structure.

Looking at the problem: we want to minimize the maximum over all shifts k of the "mismatch" between h and its shifted version. Intuitively, we want h to be as "self-similar" as possible under shifts, or at least to have small mismatch for all shifts.

If h is constant (= 1/2 everywhere, to satisfy the integral), then for any shift k:
∫ h(x)(1-h(x+k)) dx = ∫ (1/2)(1/2) dx = (1/2)(1/2) * 2 = 1/2

So constant h gives C₅ = 0.5. That's worse than our target of 0.38.

To do better, we need h to be non-constant. The idea is that where h is large, its shifted version should also be large (so 1-h(x+k) is small), and where h is small, it doesn't matter much.

This suggests that h should have a "block" structure: groups of high values and groups of low values, arranged so that shifts tend to map high to high and low to low.

For example, if h is a step function: h = 1 on a set A of measure 1, h = 0 elsewhere. Then for shift k:
∫ h(x)(1-h(x+k)) dx = measure of {x : x ∈ A, x+k ∉ A} = measure(A \ (A-k))

So C₅ = max_k measure(A \ (A-k)). We want to find a set A of measure 1 (in [0,2]) that minimizes the maximum "one-sided difference" over all shifts.

This is related to the classical "fools" problem or "difference sets". The optimal A for this problem in continuous setting... 

Actually, for the continuous case, if A is an interval of length 1, say [0,1], then:
For shift k: A \ (A-k) = [0,1] \ [-k, 1-k] 
For k > 0: A \ (A-k) = [1-k, 1] (if k < 1) or A \ (A-k) = A (if k >= 1)
  For k in (0,1): measure = k
  For k >= 1: measure = 1
So max = 1. Bad.

If A is [0, 0.5] ∪ [1, 1.5] (two intervals of length 0.5):
For various shifts... this gets complicated. The key insight from the literature is that the optimal set is related to a "balanced" configuration.

For the discrete problem with n=70, I think the optimal h probably takes values close to 0 and 1 (a step-like function) with some intermediate values at boundaries.
