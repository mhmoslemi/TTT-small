1. Approach and rationale

The central method is an exact-metric, active-cut linear-program trust-region descent for the nonsmooth discrete minimax problem `max_k corr(h,1-h)[k]*dx`, followed by purely exact candidate validation. This is materially different from using a globally smoothed log-sum-exp approximation or a direct nonlinear least-squares/quasi-Newton surrogate. Instead of replacing the nonsmooth max by a smooth scalar function, the method:

- keeps the complete unknown vector `h` feasible;
- forms a local measure of the dominant correlation constraints by their true gradients at the current `h`;
- solves a genuinely convex/linear LP: minimize an auxiliary scalar `t` subject to first-order proposed reductions of the selected true terms plus affine constraints (`sum h = n/2`, `0 <= h <= 1`, and a trust region);
- obtains a proposed step from that LP;
- immediately tries that direction by exact line search using the actual `np.correlate(h,1-h,'full')*dx` objective;
- accepts or shrinks exactly according to the true objective, never according to the LP lower/model value.

This choice is motivated by three observations. First, the true objective is `max_k f_k(h)`, and at a point several `f_k` can dominate. The correct local object is not one differentiable average, but a small convex LP controlling competitive upper first-order estimates for the active set. Second, the products `h_i*h_j` make the exact problem nonconvex; the method therefore must not claim a global minimizer. It uses the linear model only to propose a direction and always validates with the exact evaluator. Third, the parent is close to the desired record. The target is only small: it requires a high-resolution local walk from an already good vector and a few diversified feasible seeds, not a global resolution attempt. The allowed local method should be stable and promising enough for that owner improvement if an exact fallback is always maintained.

The method also addresses resolution drift: lower surrogate values and rounding can perturb the vector, but no candidate is accepted without feasibility repair and a fresh exact score. The final best vector is always evaluated by grad same formulas as the gold evaluator.

2. Mathematical specification

2.1 Discrete representation and objective

For an output vector `h` of length `n`, define

`dx = 2.0/n`, and `target = n/2.0`.

The allowed set is

`Q_n = { h in R^n : 0 <= h_i <= 1, sum_i h_i = target }`.

Exact objective on `Q_n` is

`C5(h) = max_{k=0}^{2n-2} r_k(h) * dx`

where `r = np.correlate(h, 1 - h, mode="full")`. Inputs must be `float64`; the returned score must use this orientation and all `2n-1` terms. Use no convention derived only from totals: the returned score is `float(np.max(r * dx))`.

2.2 Raw-term layout and gradient formulas

Let `a = h`, `b = 1 - h`, and `r = np.correlate(a, b, mode='full')`. `np.correlate(a,b,'full')` is convolution with `b` reversed. For output index `p = 0,...,2n-2`, define physical lag

`d = p - (n-1)`, so `d ∈ {-(n-1),...,n-1}`.

The exact raw row is:

- For `d = 0`:

`r_{n-1}(h) = sum_{i=0}^{n-1} h_i (1 - h_i)`.

- For `d = q > 0`:

`r_{n-1+q}(h) = sum_{i=q}^{n-1} h_i (1 - h_{i-q})`.

- For `d = -q < 0`:

`r_{n-1-q}(h) = sum_{i=0}^{n-1-q} h_i (1 - h_{i+q})`.

The scalar objective component is `f_p = dx * r_p`; `C5(h) = max_p f_p`. Gradients below are for `f_p = dx * r_p`.

For `d = q > 0`:

- `grad[0 : n-q] -= dx * h[q : n]`
- `grad[q : n] += dx * (1 - h[0 : n-q])`

For `d = -q < 0`:

- `grad[0 : n-q] += dx * (1 - h[q : n])`
- `grad[q : n] -= dx * h[0 : n-q]`

For `d = 0`:

- `grad += dx * (1 - 2*h)`

These slices are direct termwise derivatives. Each selection row used by the LP must correspond exactly to a physical correlation index `p` selected from the actual `np.correlate` value array. A setup validation is mandatory: choose a modest test length (`m = min(n, 8)`) and, for a few rows and one random vector, compare the slice gradient against central differences of the exact one-row expression obtained from the same slice or from standard convolution. If a one-row gradient bug is found, use the loop-based row expression that explicitly computes all valid products and its finite-difference derivative; however, the primary plan is the slice formulas above, which match the stated convolution orientation. Do not silently produce or store an unpamount formulation.

2.3 The LP subproblem at a current feasible point `x`

At a feasible current point `x`, fix a list `I` of correlation indices `p` (the selected terms). For each `p ∈ I`, compute the true current assigned value

`A_p = f_p(x)`, and gradient `g_p = grad f_p(x)`.

Propose a new vector `z` and auxiliary model maximum `t`. The LP is

`minimize t`

subject to

1. `t >= A_p + g_p^T (z - x)` for every selected p,
2. `sum_i z_i = target`,
3. `0 <= z_i <= 1`,
4. optional trust region, at first no global trust; later a radius `rho` gives
   `max(0, x_i - rho) <= z_i <= min(1, x_i + rho)`,
5. physical nonnegativity `t >= 0`, because true terms are nonnegative.

Written as all-affine data, first constraints become

`-t - g_p^T z <= -A_p + g_p^T x`.

All other constraints are affine. This subproblem is supported by `scipy.optimize.linprog` with any available LP method (prefer `HiGHS`, then `interior-point` or `simplex` if only those are present), or a CVXPY affine constraint model using an available LP/SOCP solver. It is genuinely an LP over variables `(t,z)` with affine constraints. It is not claimed to solve the original bilinear problem; it is a standard first-order linearization subproblem that is numerically well-conditioned and does not use invalid convex approximations of product constraints.
