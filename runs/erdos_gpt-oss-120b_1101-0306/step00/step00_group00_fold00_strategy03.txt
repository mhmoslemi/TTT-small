<strategy>
1. Approach and rationale

Central method and why it is different

The proposed scheme is an exact-metric, primal feasible-line descent in the finite simplex polytope, combined with (i) one-dimensional exact/grid/golden searches along actual objective values, (ii) pairwise edge moves that preserve the discrete integral constraint exactly, and (iii) deterministic multi-start seeding of nearby feasible perturbations. It differs from the two prior plans in both architecture and cost acceptance mechanism:

- It does not replace the non-smooth minimax objective by a log-sum-exp surrogate and then try to make the result fit the original metric.
- It does not solve a first-order linearized linear program whose model directions are proposed before exact evaluation.
- Instead, every search step remains in the feasible box-with-fixed-sum set. The only quantities that affect accept/reject and the global best value are the actual evaluator values obtained by computing `np.correlate(h, 1-h, mode="full") * dx`.

The central bottleneck being attacked is this: the parent construction is already highly optimized, so the remaining margin is extremely small. To find it, the optimizer must expose slightly different feasible intersections of the active raw correlation constraints. Smooth surrogates and large affine models can be trapped in the same basin; a primal exact line/edge explorer can frequently traverse the feasible segment between active terms and test candidate intersections directly using the real evaluator.

The method uses finite differences and random/active directions only as proposal generation. It treats them as heuristics. There is no claim of global optimality. Because the raw functions are products of entries of `h`, the problem is genuinely non-convex and the one-dimensional line objective is generally max of many quadratic/affine pieces, not a convex scalar problem. Exact line search is therefore not a formal convex line minimization; it is a bounded, dense, adaptive 1D search whose output is accepted only if the formal objective gets better.

Why this remains mathematically safe

Feasibility is maintained by explicit operations:

- all candidate transformations are followed by a bounded monotone feasibility projection;
- a pairwise move preserves the sum exactly whenever the pair values are modified to `(t, pair-total-t)`;
- all accepted updates are validated with a final finite feasibility check;
- the fallback is the supplied parent construction or any valid vector produced by the feasibility machinery.

The score returned is recalculated with the official objective formula before `run` exits.

Important honest limitations

- This is a local search, not a certificate that no better sequence exists.
- The one-dimensional line search uses grid plus local refinement and is not guaranteed to detect a very narrow isolated offset along a proposed direction.
- Multiple starts are necessary because the actual objective has many local minima.
- If no candidate improves the parent, the run must nevertheless return the best feasible vector found, normally the parent itself.

2. Mathematical specification

2.1 Discrete representation and exact objective

For a returned vector of length `n`, use floating entries `h[0],...,h[n-1]` and

`dx = 2.0 / n`.

The discrete feasibility polytope is

`Q_n = {h in R^n : 0 <= h_i <= 1 for all i, sum_i h_i = n/2}`.

For an input vector `h`, the authoritative score is

`raw = np.correlate(h, 1.0 - h, mode="full")`

and

`C5(h) = max(raw) * dx`.

There are `2n-1` raw values, including both signed lag directions. The implementation must use exactly this unmodified `np.correlate` orientation. If score evaluation needs to be repeated for a candidate transformation, do it after the candidate has been made feasible, except that proposals and ray tests inside the line search may evaluate temporarily infeasible-looking numeric vectors with tiny floating violations; the final stored accepted vector must satisfy the constraints.

Coordinates and n-generation

If a global variable named `initial_h_values` exists and is a valid non-empty numeric vector, it is the default resolution. Let its length be `n0`. If it is absent or invalid, use `n0=45` as the base resolution. Other generated search dimensions, if time permits, are:

- `n0`,
- `max(4, round(0.75*n0))`,
- `round(1.25*n0)` but never above 90 if running in a budget of 1100 seconds,
- `max(2, n0-1)`,
- `n0+1`.

These are optional transfer search dimensions. Candidates at different lengths are compared only through their official C5 values; the final winner is the strictly lowest official value. If two candidates have objective values within `1e-11`, prefer the smaller length because the task prefers little-end small sequence candidates.

2.2 Feasibility repair that enforces the box and sum simultaneously

A coordinate clipping followed by arbitrary rescaling can spoil either the bounds or the sum. Use instead the monotone uniform additive relaxation plus a fixed capacity correction.

For `target = m/2.0` (use `m` for the current dimension before the eventual output length choice), first cast input to float, replace non-finite values with 0.5, and clip it to [0,1]. If the sum is already target within a tolerance `tol_sum = 1e-11 * max(1,target)`, return it.

Otherwise solve for a scalar shift `alpha` such that

`F(alpha) = sum_i clip(u_i + alpha, 0, 1) = target`

where `u` is the clipped base vector. Define safe bracket endpoints:

`alpha_below = -u_max - 1.0`

`alpha_above = 1.0 - u_min + 1.0`

and `u_max=max(u)`, `u_min=min(u)`. Then for all `alpha below threshold` we have `F=0` and for `alpha above threshold` we have `F=m`, while `0 <= target=m/2 <= m`. Solve by bisection for about 60 iterations or until interval length `1e-13`.

After bisection construct `h=clip(u+alpha_best,0,1)`. If the square and finite small errors make sum inaccurate, perform a single simultaneous capacity fix:

Let `r = target - sum(h)`.

If `r > 0`, let `slack = 1-h`, `S=sum(slack)`. If `S <= tol_sum`, set `S=eps`. If `r > S`, truncate `r=S`. Then

`h += r * slack / S`.

If `r < 0`, let `addr=h`, `B=sum(h)`. If `B <= tol_sum`, set `B=eps`. If `-r > B`, set `-r=B`. Then

`h = h + r * h / B`.

This exact-allocation step does not break the individual bounds because the allocated amount is distributed only among coordinates with the correct directional slack. Finally, set each entry that is antithetically close to 0 or 1 to exactly those bounds (for example `abs(h_i) < 1e-16`) and similarly if `abs(1-h_i)<1e-16`. Then evaluate and record. If the projection completely fails due to a floating-case pathological condition, return a deterministic feasible base vector of appropriate dimension: `np.full(n,0.5)`, target over an even target; but note target n/2 already exactly energy. This is not generally good scoring but always valid.

A helper intent:

`make_feasible_vector(vec) -> h_float64`

must return a size consistent vector satisfying both constraints or flag failure after a small recovery count.

2.3 Exact metric helper

There must be one canonical official metric function, preferably named `official_c5_score` or similar. Its responsibilities:

- Input: a feasible `h` numeric array.
- If any value is non-finite, set to 0.5 or return a large numerical penalty, e.g. 100.0, but final vectors have to be made feasible before final scoring.
- Compute `raw = np.correlate(h, 1.0 - h, mode='full')`.
- Compute `dx = 2.0 / h.size`.
- Return `float(np.max(raw) * dx)`.

No freed auxiliary smooth surrogate, LSE value, or raw approximation is ever accepted for global comparison.

Use `float64` for all arrays. A raw maximization uses Python/NumPy float arithmetic. If the maximum is not finite, treat score as `inf`.

2.4 Binary/threshold feasibility and target parity

When generating sequence candidates that are mostly 0/1, integrate with the exact target sum `n/2`. Let `q_int = floor(n/2)`. The fractional remainder is `frac_target=n/2-q_int`, which is 0 if `n` is even and 0.5 if `n` is odd.

Construction pattern:

1. Choose deterministic or seeded index order `a` length `n` without copying any parent numeric values. Allow random permutation, golden-ratio low discrepancy sequence, or sine-rank ordering.
2. Set `h[a[i]]=1` for `i=0,...,q_int-1`.
3. If `frac_target > 0`, set the next unused index to `frac_target` (half coordinate). If the application context requires fractional distributions and the sum target fractional, continuing balance is enough.
4. If the ordering is deterministic/rank-based arrival, the vector is automatically exact feasible; otherwise apply `make_feasible_vector` to avoid floating drift.

These sequences can sometimes trap a much lower local objective.

2.5 One-dimensional feasible line directions to explore local constraints

A proposal direction `d∈R^n` must satisfy:

`sum_i d_i = 0`

by explicit adjustment: `d = d - mean(d)`. Nonzero maximum entries make segment movement. Normalize to `max_abs_d = 1`, but if max absolute value is less than `1e-12`, use a synthetic lower scale and proceed. A line vector is technically not a convex direction under the actual metric; direction is heuristic.

Feasible interval around current base point `h`: For each coordinate `j`, satisfy `0 <= h_j + alpha*d_j <= 1`. Let lower bound `L` and upper bound `U` be the interval intersection around alpha=0. Algorithm:

Start `L=-large`, `U=large`, finite fallback set 100. For each component:

- if `abs(d_j) <= eps`, this component places no restriction;
- if `d_j > 0`, it imposes `alpha >= -h_j/d_j` and `alpha <= (1-h_j)/d_j`;
- if `d_j < 0`, it imposes `alpha >= (1-h_j)/d_j` and `alpha <= -h_j/d_j`.

Intersect, adding tiny slack `1e-14` to make more inclusive. If `U-L < 1e-8` or the interval fails finite, accept that direction attempt only with tiny fallback alpha `0` and reject by zero movement verification (for simplicity, if `U-L < width_min`, reject this line proposal and try another). If exact start is feasible and the interval arithmetic is stable, any coordinate inside [`[L, U]`] yields a feasible `h + alpha*d` before floating drift. Tiny residual after vector updates is corrected by the classifier described below.
