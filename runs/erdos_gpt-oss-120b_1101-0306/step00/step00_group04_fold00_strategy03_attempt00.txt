1. Approach and rationale

1.1 Central idea

The authoritative task is to return a feasible vector `h` of length `N` for which

`C5(h) = max(np.correlate(h, 1 - h, mode="full")) * (2.0 / N)`

is as small as possible. The supplied parent is already very close to the desired upper bound, so the main bottleneck is not constructing a completely new feasible family, but performing a high-precision local move on a tightly constrained, nonsmooth, bilinear surface.

The primary method proposed here is different from smoothed gradient optimizers, low-dimensional parameterized families, and reduction/large-scale heuristics. It treats the objective as a finite max over lag functions `P_s(h)` and constructs, at each candidate center, a convex quadratic envelope for a small set of currently active or near-active lags. The envelope gives a convex quadratic program whose feasible set is exactly the constraint set `0 <= h_i <= 1`, `sum h_i = N/2`, plus a small trust region that keeps the move local. The program is solved with CVXPY when available. The exact discrete objective is then evaluated by the required `np.correlate` formula, and only exact improvements are accepted. This lets the search use second-order-style activity information while still making no claim of global optimality or of a convex relaxation being answer-close.

The method attacks three failures of generic local search:

1. The maximum objective is nonsmooth; a smooth surrogate can follow inactive lags or trade off a false reduction in the smoothed objective for no true lag reduction.
2. Direct optimizers can become stuck at box constraints or at active-lag plateaus.
3. Random perturbation or hard clipping can violate the affine equality and thus produce invalid candidates or artificially inflated scores.

The proposal uses strict delay-tested acceptance: model reduction is only a candidate generator; every accepted vector or returned best vector is judged using the original evaluator formula exactly.

1.2 Why this should help the supplied parent

A parent near `0.38085` is likely locally difficult to move because only a small set of lags are active at the maximum, those active lags may be balanced against each other by the box and sum constraints, and tiny changes in one lag can push another lag over the threshold. The active-set convex quadratic envelopes attack this structure by explicitly requiring the envelope of several selected maximal lags to decrease together under a trust-region movement. Exact acceptance then prevents the surrogate from accepting a vector that does not reduce the authoritative discrete objective.

The method also creates useful side-channel improvements:

- Small acceptances from the trust-region program create a trajectory near the parent.
- If the convex envelope respects only current active lags but another lag becomes the new maximum, reevaluation exposes that and the active set is refreshed.
- A second line-search stage along the model-generated direction and along exact feasible pair moves can exploit nonsmooth regions where model construction is too coarse.
- Resolution transformations keep the Option of returning a shorter vector if a smaller length admits the same or better score. There is no attempt to force a smaller `N` unless the smaller candidate remains valid and improves or ties within a tight tolerance.

1.3 Major limitation and claim policy

This is not a global optimizer. The quadratic envelope is designed to prefer reductions in currently active lags and to keep the search local. There is no proof that memorized optimum is found, nor proof that a solution below `0.3808` will be found. All bound claims are upper-bound claims by explicit feasibility plus the reported evaluated objective. Every result returned or stored must pass exact `0 <= h_i <= 1`, `sum(h_i) = N/2` tolerance, and exact objective reevaluation.

2.1 Internal lag representation

Characteristic manual scalar objectives `Q_q(h)`, indexed by absolute shift `q`, are used for active-set construction. Let `q ∈ {-(N - 1), ..., N - 1}`. Define, in nondimensional but uniformly hydrated scaling by `dx`:

For `q >= 0`:

`Overlap(q) = sum_{i=0}^{N - q - 1} h[i] * (1.0 - h[i + q])`

For `q < 0`, with `r = -q`:

`Overlap(q) = sum_{i=0}^{N - r - 1} h[i + r] * (1.0 - h[i])`

Then

`P_q(h) = dx * Overlap(q)`.

This manually indexed family is constructed from the same terms as linear cross-correlation between `h` and `1-h` and differs at worst by a permutation in lag order due to the usual way `np.correlate` indexes output. Therefore the maximum over all `q` is exactly the same as the maximum of the required formula. 2.2 Manual gradients for the internal objective

These gradients are gradients of the manual `P_q`, not of `1 - minimum autocorrelation`. They must be component terms.

For `q > 0`, let `L = N - q`.

`G_q(i) += dx * (1.0 - h[i + q])` for `i = 0, ..., L-1`.

`G_q(i + q) -= dx * h[i]` for `i = 0, ..., L-1`.

Equivalently:

`G_q[0:L] += dx * (1 - h[q:N])`

`G_q[q:N] -= dx * h[0:L]`

For `q = 0`:

`G_0[i] = dx * (1 - 2 h[i])`, all `i`.

For `q < 0`, let `r = -q`, `L = N - r`.

`G_q[0:L] -= dx * h[r:N]`

`G_q[r:N] += dx * (1 - h[0:L])`

All components begin at `0` for each new gradient. The signs above are for the same manual objective with the same relative indexing operation; do not reverse one formula independently.
