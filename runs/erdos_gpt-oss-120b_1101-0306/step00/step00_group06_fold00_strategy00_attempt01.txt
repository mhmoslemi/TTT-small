1. Approach and rationale
-------------------------

1.1 Central idea
- Treat the discretized variable `h ∈ [0,1]^n` with the discrete integral constraint
  `sum(h) = n/2` exactly, as a box-constrained continuous problem in the hyperplane.
- The authoritative objective is the maximum of all directed finite-support correlations:
  `C5(h) = max_k Σ_i h_i (1 - h_{i+k}) * dx`, where `dx = 2/n`, with all negative and positive shifts and zero shift included. The implementation must reproduce this with the actual `np.correlate` formula at all acceptance and final return points.
- Because products `h_i * h_j` make the exact problem nonconvex, no CVXPY formulation is used. The primary solver is a local nonlinear constrained optimizer on a smoothed maximum surrogate, combined with continuation in smoothing temperature. This explores the active correlation constraints in a differentiable model while never accepting a surrogate score: every accepted candidate is scored by the exact discrete objective.
- A second, stronger exact-epigraph local refinement is used selectively: variables are `(e, h)` and the objective is `minimize e` subject to `e >= all correlation components` and feasibility. The constraints are nonconvex, so this is not a global method, but it directly attacks the true maximum ocean and can sharpen a smoothed candidate. It is always followed by exact evaluation and feasibility repair, and used only within strict time limits.
- Multistart over multiple discretization resolutions and over structured/Fourier/random initializations helps escape parent-local minima. Down/upsampling transfers high-resolution information to lower-resolution discretizations where small sequence sizes are preferred.

1.2 Why this can improve the supplied parent
- The supplied `initial_h_values`, if feasible, is a high-quality local point. Direct smooth-gradient local descent and exact epigraph refinement from it can reduce active peak correlations if there is residual slack.
- Moderate resolution changes, especially `0.7*n_samples`, `1.4*n_samples`, and half-size variants, may reveal a better discrete construction because the finite-correlation grid changes. Smaller resolutions are cheap and can also return better exact scores for the evaluated discrete objective, which is meaningful because the benchmark metric is defined on the returned vector.
- Random Fourier/structured initializations plus random feasible perturbations add global search diversity without relying on unproven global claims.

1.3 Limitations and hypotheses
- The method is explicitly local/multistart, not a certified global optimizer. It may fail to reach the theoretical bound.
- Smooth surrogate minimization does not have the same global behavior as exact max minimization, but the surrogate gradient is derived from the exact correlation components and acceptance is exact.
- The epigraph formulation is local nonlinear programming; SLSQP success only means a local KKT candidate, not global optimality.
- Resolution changes may change the exact score in both directions. Every transferred candidate is re-optimized and evaluated at its own dimension before acceptance.

2. Mathematical specification
-----------------------------

2.1 Discrete object and exact objective
- For a returned vector `h = h_0,...,h_{n-1}`, use `dx = 2.0 / n` and exact integral mass constraint:
  `sum(h) * dx = 1`, equivalently `sum(h) = S` where `S = n/2`.
- The authoritative evaluated objective is:
  `C5(h) = max(np.correlate(h, 1.0 - h, mode="full") * dx)`.
- This is linear finite-support correlation. It is not circular correlation, and not `1 - min autocorrelation`. It includes all `2n-1` lags: zero shift, positive shift, and negative shift. Boundary overlap is handled automatically by the full correlation array.

2.2 Equivalent component representation
Define component values `g(h)`, a vector of length `2n-1`, which contains exactly the same multiset of correlation values as the evaluator’s full correlation times `dx`:
- Zero shift:
  `g_zero = dx * Σ_{i=0}^{n-1} h_i (1 - h_i)`.
- Positive shift component, for `d=1,...,n-1`:
  `A_d = dx * Σ_{i=0}^{n-d-1} h_i * (1 - h_{i+d})`.
- Opposite directed shift component, for `d=1,...,n-1`:
  `B_d = dx * Σ_{i=0}^{n-d-1} h_{i+d} * (1 - h_i)`.
- Store or compute the component vector in some fixed order, for example:
  `[g_zero, A_1,...,A_{n-1}, B_1,...,B_{n-1}]`.
- This vector has the same multiset of values as `np.correlate(h,1-h)*dx`, possibly with a sign/position permutation. The unordered maximum is identical. Therefore exact acceptance may use the component maximum, but the final and all acceptance checks must still be diagonalized by direct re-evaluation with the actual evaluator formula `np.correlate(...) * dx`.

2.3 Smooth surrogate and its exact gradient
- Let `g_j` be any component value in the component representation.
- Define a stable smooth maximum for a dimensionless temperature `tau`:
  `Phi_tau(h) = log( Σ_j exp(g_j / tau) )`, equivalently stable with `m=max(g)`:
  `Phi_tau(h) = m + tau * log( Σ_j exp((g_j - m)/tau) )`.
  Adding a constant such as `-log(2n-1)` is optional; it does not change the gradient. Do not subtract the constant when filling `Phi` if it makes numerical ranges nonintuitive; use unnormalized log-sum-exp and choose starting temperatures based on the actual `C5` scale.
- Let weights be:
  `p_j = exp((g_j - m)/tau) / Σ_k exp((g_k - m)/tau)`.
  Then `∇Phi = Σ_j p_j ∇g_j`.
- Component gradients, including `dx`:
  - Zero shift:
    `∂g_zero / ∂h_i = dx * (1 - 2h_i)`.
  - Positive shift `A_d`, `L = n-d`:
    For each `i=0,...,L-1`:
    `∂A_d / ∂h_i      = dx * (1 - h_{i+d})`,
    `∂A_d / ∂h_{i+d}  = - dx * h_i`.
  - Opposite shift `B_d`, `L = n-d`:
    For each `r=0,...,L-1` corresponding source index `i = r+d` and target index `t = r`:
    `∂B_d / ∂h_{r+d}  = dx * (1 - h_r)`,
    `∂B_d / ∂h_r      = - dx * h_{r+d}`.
- Implementation must place these contributions into one length-`n` gradient vector by accumulating slices over all shifts. All shifts and both directions must be present because the maximum includes both boundary and interior overlaps.

2.4 Exact epigraph local formulation
- Variables: `x = [e, h_0, ..., h_{n-1}]`.
- Bounds: `0 <= h_i <= 1`; `e` bound should be `(0.0, 1.50)` or a modest practical range such as `(-0.05, 1.5)`. The reliable range used should start no lower than 0 and upper generous (e.g. `0.0` to `1.5`) to allow slack while preventing runaway.
- Equality: `e` unchanged by sum constraint; the equality applies only to `h`: `sum(h) = n/2`.
- Inequality constraints: for every component vector value `g_j(h)` with the same component vector code used in the smooth method:
  `e - g_j(h) >= 0`.
  Since `g_j` already includes `dx`, these constraints force `e >= max_j g_j`.
- The objective is the linear function `e`.
- The vector-valued inequality function returns `e_vec - g(h_vec)`, where `e_vec` has shape `(2n-1,)`. The Jacobian has shape `(2n-1, n+1)`:
  - column corresponding to `e` is all `1`;
  - columns in `h` are the negatives of the component gradients: Jacobian row `j` and variable `i` equals `-∂g_j/∂h_i`.
- This exact epigraph formulation corresponds to the original discrete maximum. Because the constraints are nonconvex, it should not be claimed globally optimal. It is used only as a local refinement subject to exact objective reevaluation and feasibility repair.

2.5 Feasible joint repair, projection onto box-simplex
- Feasible set:
  `F = { x ∈ R^n : 0 <= x_i <= 1 for all i, sum(x) = S }`, with `S = n/2`.
- Implement a dedicated `project_boxsum(z, S)` helper:
  1. If `z` is empty, return an empty array.
  2. If any entries are infinite, replace with large finite values at the clipping bounds, or return all `0.5 * z_i + 0.5*...` after cleaning? Prefer: `z = np.where(np.isfinite(z), z, 0.0)`, then continue.
  3. Define `s(lambda) = sum(clip(z + lambda, 0, 1))`, monotone nondecreasing in `lambda`.
  4. Choose bracketing `lo` and `hi` wide: `span = max(1, np.max(np.abs(z)))`; initially `lo=-2*span`, `hi=2*span`.
  5. If `s(lo) > S`, `lo` is too high; widen positive shift by moving `lo` negative exponentially (`lo *= 2`) until `s(lo) <= S`; similarly widen `hi` until `s(hi) >= S`. This handles broad offsets.
  6. Run about 80 scalar bisection iterations: at each step compute `mid`, `smid`; if `smid > S` set the upper side; if `smid < S` set lower side. If `smid == S` or change is negligible, break. On numerical/plateau cases, take mid and then residual repair dominates.
  7. Return `x = clip(z + lambda, 0, 1)`.
  8. Compute residual `r = S - sum(x)`. If `abs(r) > 1e-12`, repair by mass transfers within remaining bounds:
     - If `r > 0`, sum available room `room_i = 1 - x_i`; if enough room across variables exists, repeatedly add `min(r, room_i)` to variables with largest room until residual vanishes within tolerance.
     - If `r < 0`, subtract available room similarly from entries with `room_i = x_i`.
     - If residual cannot be consumed due to finite precision but `abs(r)` is below absolute `1e-10`, leave it. If still larger, make one final coordinate adjusted toward bound by the exact residual as long as no bound is grossly violated. This final step guarantees a practically satisfying feasibility routine.
- Do not rely on clipping then scaling separately because that can violate the sum constraint. Projection and the residual repair jointly enforce `0 <= h_i <= 1` and sum equality within numerical tolerance.

2.6 Dimension transfer and feasibility preservation
- For downsampling vector from length `n` to length `m`:
  - Create `x = np.linspace(0.0, n-1.0, n)` and `x_new = np.linspace(0.0, n-1.0, m)`, use linear interpolation to get tentative values.
  - Since this interpolation may not preserve sum, project with `project_boxsum(interpolated, m/2)`.
- For upsampling from length `n` to length `m > n`:
  - interpolate onto `m` points using the same coordinate stretching:
    `x_new = np.linspace(0.0, n-1.0, m)`.
  - Project to sum `m/2`.
- After any transfer, reevaluate exact C5 using dimension `m` and exact feasibility using length `m` sum constraint.
- Keep candidates with exact scored values, and when choosing best prefer smaller objective first, smaller dimension only on ties.

3.2 Constants and normalization
- Distance الشعور units: all objective values are scalar C5 values already multiplied by `dx`; they are in the same units as the evaluator. Use `tau` in these same units.
- Utility minima: `tau_start = 0.16 * max(1e-3, max(0.45, J_best or best(optional feasible reference))) + 0.004`. For a sensible `J_best ≈ 0.38`, this starts around `0.065` to `0.075`. For a default uniform `J=0.5`, around `0.084`. This avoids too-large temperature while keeping smoothness.
