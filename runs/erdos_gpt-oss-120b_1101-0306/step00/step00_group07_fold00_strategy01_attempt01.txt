1. Approach and rationale

Central idea. Use a convex epigraph linearization of the discrete minimax objective, solve the linear subproblem exactly as a linear program, and then judge every proposed move with the original evaluator. The search is kept target-free and parent-preserving: the supplied current construction is always validated, scored, and kept as a fallback whenever it exists. The main update is a linearized trust-region step: at the current feasible vector, replace every finite supported cross-correlation term by its first-order affine approximation, minimize the maximum of these affine functions subject only to the feasible box and linear mass constraint, and then exact-score a one-dimensional search from the old point toward the LP solution. If no exact improvement is obtained, shrink the trust bound and continue. A secondary exact active-gradient line search and bounded random mass-transfer probe fill idle time and provide escape from first-order trust stalls.

This differs substantively from both smooth log-sum-exp smoothing and coordinate-pair/SLSQP plans in the prior proposal. The primary descent model is a linear programming subproblem for the whole epigraph, not a smoothed maximum or a local nonlinear optimizer. The solving basis is: all finite correlation lags are represented simultaneously as affine constraints over the current iterate, the variable `t` bounds the maximum of these affine lower-side terms, and only an exact scoring test computes the returned numerical bound. No step is accepted based on `t` or on the linear objective. The method uses exact finite bounds `0<=h_i<=1` and exact mass conservation by construction, followed by a numerical feasibility finalizer. Constraints and scoring are never replaced by a non-equivalent autocorrelation surrogate.

Why this could improve the parent. A good parent is likely close to a constrained stationary point for the nonsmooth maximum. Many seemingly bad directions in a coordinate search become useful because they reduce several active lag values at once. The LP subproblem can find a simultaneous, constrained, non-neighborhood direction that lowers the first-order maximum of all lag terms within the feasible box. Exact line sampling and repeated exact acceptance mitigate the fact that the objective is bilinear and the linearized subproblem has no global guarantee. The method is therefore a local but non-smooth minimax optimizer, while still:
- requiring only local updates,
- enforcing the constraints with one robust routine,
- comparing every proposed vector with the authoritative `np.correlate` metric,
- preserving a valid fallback parent or algorithmic base.

Honest limitations. The original discrete problem is nonconvex because terms contain products `h_i h_j`. The linearized problem is only locally relevant and the solution of its LP is not guaranteed to lower the true discrete objective. No global optimum or global convergence is claimed. Every reported bound is the exact evaluator value of the returned array. The active-gradient stage and random stage are stochastic auxiliaries used only for exact candidate invention; they also do not claim optimality.

2. Mathematical specification

2.1 Runtime dimensions and constraints

At execution in `run`:
- If there is no supplied parent, choose `n = 95` for the initial feasible candidate so that the default run starts in the same numerical scale as the supplied parent. This value can be changed only under the resolution stage described in Section 4.
- For any vector length `n`, set `dx = 2.0 / float(n)`.
- Feasible continuous set is
  `H = { h in R^n : 0 <= h_i <= 1 for i=0,...,n-1 and sum_i h_i = n/2 }`.
  Since `integral = sum(h)*dx` and `dx = 2/n`, `integral=1` is exactly `sum(h)=n/2`.

2.2 Authoritative scoring

For a length-n array `h`:
```
hm = 1.0 - h
vals = np.correlate(h, hm, mode="full") * (2.0 / n)
score = max(vals)
```
This produces `2*n - 1` finite support cross-correlation values and is the only accepted decision score. It includes both lag directions. Do not replace this with `1 - minimum autocorrelation`; boundary terms are different and different resolutions must be scored by this exact formula.

2.3 Internal full-lag terms used only for gradients and linearizations

Define the internal term set on an index `p = 0,...,T-1` where `T = 2*n - 1` and `offset = n - 1`. Put
`d = p - offset`. This enumerates integer shifts `d` from `-(n-1)` to `n-1`.

For internal term `p`:
```
a_e = max(0, -d)
b_e = min(n, n - d)
ell = b_e - a_e
hm = 1.0 - h
G[p] = dx * dot( h[a_e:a_e+ell], hm[a_e+d:a_e+d+ell] )
```
This set is cross-correlation values over all full lags. The evaluator `np.correlate` may reverse public lag order relative to this `d` order. Reversal ordering does not matter for a maximum-epigraph LP because all `T` constraints are included.

Before enabling gradient/LP guidance, do a runtime calibration:
- On two or three small test vectors (they do not need to be feasible) compute internal vector `G` and official vector `vals. Compute `dx*correlate(...)` for the official.
- Compare `np.sort(G)` and `np.sort(vals_abs)` elementwise.
- Use a tolerance of roughly `1e-10 * max(1.0, max(vals_abs))` and require near zero differences.
- If sorted matching fails severely, mark the guidance context unavailable and use only exact-line random and structure-preserving mutations. The scoring and returned bounds are still official; wrong internal guidance only corresponds degraded MATLAB not invalidity.

2.4 Exact internal-affine gradients

For shift `d` and overlap start `a_e` length `ell`, define the two index intervals:

- first-factor interval `F = [a_e, a_e+ell)`
- second-factor interval `S = [a_e+d, a_e+d+ell)`

Since `hm=1-h`, linearization around `h0`:

`Grad[p]` is the gradient of `G[p]` w.r.t. `h`. Start with all zeros. Then:
1. First factor:
   for each coordinate `j` in `F`, add `dx * hm[j+d]` (where `hm=1-h0`).  
   In slice notation: `grad[F] += dx * hm[a_e+d : a_e+d+ell]`.
2. Second factor:
   for each coordinate `j` in `S`, if `i = j-d in F`, subtract `dx * h0[i]`.  
   In slice notation: `grad[TestStart : TestStart+ell] -= dx * h0[F]`.

For `d=0`, the two additions into the same coordinate correctly yield
`dx*(1-h_i) - dx*h_i = dx*(1-2*h_i)`. This is the derivative of `dx*h_i*(1-h_i)`.

These gradients match the internal term values used in the constraints.`.

2.5 Linearized epigraph LP

Let the current state be a feasible (public? approximately after feasibility repair) vector `h0`. Let `F = max_p G[p]` from the internal terms; use the exact score of `h0` only for record/dedup, not the epigraph RHS. For each lag `p`, affine approximation:
`alpha_p(h) = G[p] + Grad[p]^T (h - h0)`.

Introduce variable `t` and solve a continuous LP in variables `x = [h_0,...,h_{n-1}, t]`:
```
minimize t
subject to:
  alpha_p(h) <= t   for all p=0,...,T-1
  sum_i h_i = n/2
  lb_i <= h_i <= ub_i   for all i
  0 <= t <= 2
```
Where trust box is bounded around `h0` by `delta`:
`lb_i = max(0, h0_i - delta)` and `ub_i = min(1, h0_i + delta)`.

Convert the lag inequalities to the scipy `linprog` dense/sparse standard form:
```
Grad[p] dot h - t <= Grad[p] dot h0 - G[p]
```
So `A_ub[p,:n] = Grad[p]`, last coefficient is `-1`, `b_ub[p] = dot(Grad[p], h0) - G[p]`.
The equality row has ones in first `n` coefficients and zero in `t`, RHS `n/2`.
Linear program sizes: `T <= 189` lag constraints for `n=95`, plus `n` variables. The linear program is convex and `linprog` supports the interval box constraints, equality sum, and affine inequality constraints directly. There is no claim that its solution is feasible for or optimal for the original problem; it is a proposed Lusing exact next-checking.

If a global SciPy linear method fails with `method="highs"`, try `method="interior-point"` or the default. Use small tolerances such as `fun_tol = 1e-11`, `x_tol = 1e-11`. If all fail, drop the step only.

2.6 Active-gradient auxiliary direction

When the LP fails to give an exact improvement after a few uses of the same LP tumor, construct a weighted active gradient direction for exact line search.
For internal term vector `G0`:
- Let `Fwork = max(G0)`.
- Set temperature `tau = max(5e-5, 0.12 * Fwork)` and update `tau` multiplicatively if descent fails (`tau *= 0.75`, or recompute once). This temperature is a search heuristic, not a proof parameter.
- Define
  `w_p = exp((G0[p] - Fwork)/tau)`, normalize weights to sum 1. Numerical compute stable by subtracting `Fwork` in exponent.
- Weighted gradient:
  `gA = Σ_p w_p Grad[p]`.
  Already computed gradients `Grad[p]` can be accumulated as the weights are cumulative.
- Use `dir = -gA`, then remove mass change `dir -= mean(dir)` so its mass sum is zero.
- If `max(abs(dir)) < 1e-12`, skip. Otherwise normalize `dir /= max(abs(dir))`.
