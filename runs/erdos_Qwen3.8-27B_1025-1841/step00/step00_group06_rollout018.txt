- c[n-1+s] = sum_{i=0}^{n-1-s} h[i+s]*(1-h[i]) for s ≥ 0
- c[n-1-s] = sum_{i=0}^{n-1-s} h[i]*(1-h[i+s]) for s ≥ 0

In both cases, the "shift" s means we're comparing h at position i with h at position i+s.

For the positive shift s: c[n-1+s] = sum_i h[i+s]*(1-h[i])
For the negative shift s: c[n-1-s] = sum_i h[i]*(1-h[i+s])

These are actually the same quantity! c[n-1+s] and c[n-1-s] are different:
- c[n-1+s] counts (1,0) pairs at distance s: h[i+s]=1, h[i]=0... no wait.
  c[n-1+s] = sum h[i+s]*(1-h[i]): h[i+s]=1 and h[i]=0
  
- c[n-1-s] = sum h[i]*(1-h[i+s]): h[i]=1 and h[i+s]=0

So they count different things! c[n-1+s] counts 0→1 transitions (going right) and c[n-1-s] counts 1→0 transitions (going right).

For a binary sequence, c[n-1+s] + c[n-1-s] = number of positions where h[i] ≠ h[i+s] (for i < n-s).

OK so for the targeted search, if the max is at c[n-1+s] (positive shift s), the contributors are positions i where h[i+s]=1 and h[i]=0. To reduce this, I want to either:
- Make h[i] more like 1 (reduce (1-h[i]))
- Make h[i+s] more like 0 (reduce h[i+s])

But changing h[i] affects other shifts too.

    c = np.correlate(h, 1.0 - h, mode='full')
    k_max = np.argmax(c)

    if s == 0:

        # ∂/∂h[m] = (1-h[m-s]) [if m-s >= 0, from h[i+s] with i=m-s]
