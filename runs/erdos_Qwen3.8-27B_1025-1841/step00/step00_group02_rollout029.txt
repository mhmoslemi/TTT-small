def compute_C5(h):
    n = len(h)

    corr = np.correlate(h, 1-h, mode="full")

def project_feasible(z, target_sum):
    lo, hi = -2.0, 2.0
    for _ in range(80):
        mid = (lo + hi) / 2
        h = np.clip(z - mid, 0, 1)
        if h.sum() > target_sum:
            lo = mid
        else:
            hi = mid
    return np.clip(z - (lo + hi) / 2, 0, 1)

def corr_gradient(h, k, n):
    """Gradient of c_k (the k-th lag correlation) w.r.t. h"""
    # c_k = sum_{valid n} h[n+k] * (1-h[n])
    # index in full array: k + (n-1)
    grad = np.zeros(n)
    for j in range(n):
        val = 0.0
        if 0 <= j - k < n:  # h[j] appears as h[n+k] with n=j-k
            val += (1 - h[j-k])
        if 0 <= j + k < n:  # h[j] appears as h[n] with n=j, and h[n+k]=h[j+k]
            val -= h[j+k]
        grad[j] = val
    return grad

    dx = 2.0 / n
    corr = np.correlate(h, 1-h, mode="full")
    
    if eps > 0:
        # Smooth max
        m = np.max(corr)
        smooth = m + eps * np.log(np.exp((corr - m) / eps).sum())
        # Weighted gradient
        weights = np.exp((corr - m) / eps)
        weights /= weights.sum()
        # Need gradient of each c_k

        for k_idx in range(2*n-1):

                total_grad += weights[k_idx] * corr_gradient(h, k, n)
        return dx * smooth, dx * total_grad

OK the O(N²) scan of all swaps is too slow for large N. Let me use a smarter approach.

**Smarter binary local search:**

Instead of trying all (i,j) pairs, I'll use the following heuristic:
1. Find the worst lag k*.
2. For each position i where h[i]=1 and h[i+k*]=0 (if valid), this position "contributes" to the overlap at lag k*.
3. To fix this, I want to either:
   a. Change h[i] to 0 (and change some h[j]=0 to 1 to maintain the sum)
   b. Change h[i+k*] to 1 (and change some h[j]=1 to 0)
4. For option (a): the best j is one where changing h[j] from 0 to 1 doesn't create new overlaps. Specifically, j should be such that h[j+k*]=1 (so it doesn't add to the overlap at k*) and h[j-k*]=0 (so it doesn't add to the overlap at -k*).
5. For option (b): similar reasoning.

This gives O(N) candidates per step, and evaluating each is O(N) (recomputing the correlation). Total: O(N²) per step. With a few hundred steps, O(N²) × 100 = O(100N²). For N=360, that's about 13M operations per step evaluation, times 100 steps = 1.3B. In Python, maybe 30-60 seconds. Feasible.

But actually, I can be even smarter. Let me precompute the "contribution" of each position to each lag, and use that to quickly evaluate the effect of a swap.

For position i (h[i]=1), its contribution to c_k is:
- (1-h[i-k]) if i-k is valid (i appears as h[n+k] with n=i-k)
- 0 if i-k is not valid

Actually, let me just use a simpler but effective approach: **random perturbation + re-optimization**.

1. Start from a good initial binary configuration.
2. At each step, pick a random position i with h[i]=1 and a random position j with h[j]=0.
3. Swap them.
4. If the new C5 is better, accept; otherwise reject (or accept with probability exp(-Δ/T) for simulated annealing).
5. Repeat.

This is O(N²) per step (one correlation computation) and can run for many steps within the time budget.

For N=360, each correlation is O(N²) = O(130K) operations. In numpy, this takes maybe 1-2ms. So I can do about 500-1000 steps per second. Over 100 seconds, that's 50,000-100,000 steps. Should be enough to find a good local optimum.
