Wait, I have a problem with the SLSQP formulation. The `cons_ineq` function returns a vector, and SLSQP should handle that. But the computational cost of evaluating it (computing the full correlation) might be high when SLSQP does numerical differentiation.

Let me think about this. SLSQP with numerical gradients for 81 variables will evaluate the constraint function 81+1 = 82 times per "function evaluation" (for the Jacobian row by row, or using finite differences). Each evaluation is O(n²) = 6400. So 82*6400 = 525K operations per gradient step. For 80 variables, one iteration might involve 80 gradient evaluations = 42M operations. At ~1 GFLOPS, that's 42ms per iteration. 500 iterations = 21s. That's a lot but within budget if we only do it a couple times.

Actually, SLSQP uses a quasi-Newton update for the Hessian and finite differences for gradients. The number of function evaluations per iteration is roughly n+1 = 82 (for the gradient) + some for the Hessian update. So maybe 100 evaluations per iteration. 500 iterations * 100 * 6400 = 320M operations ≈ 0.3s at 1 GFLOPS. Actually much faster than I feared.

This is doable but complex. Let me skip it for now and rely on numerical gradients.
