def subgrad_polish(h, n, max_iters, time_limit, lr_init=0.002, topK=5):
    dx = 2.0 / n
    h = project_to_feasible(h.copy(), n)
    corr = compute_corr_fft(h)
    best_c5 = corr.max() * dx
    best_h = h.copy()
    start = time.time()
    lr = lr_init
    v = np.zeros(n)
    stall = 0
    patience = 200

    for it in range(max_iters):
        if time.time() - start > time_limit:
            break
        
        c5_cur = corr.max() * dx
        if c5_cur < best_c5 - 1e-15:
            best_c5 = c5_cur
            best_h = h.copy()
            stall = 0
        else:
            stall += 1

        top_idx = np.argsort(corr)[-topK:]
        grad = np.zeros(n)
        for ki in top_idx:
            d = ki - n + 1
            j0 = max(0, d)
            j1 = min(n, n + d)
            if j0 < j1:
                idx = np.arange(j0, j1)
                grad[idx] += (1.0 - h[idx - d])
            j0b = max(0, -d)
            j1b = min(n, n - d)
            if j0b < j1b:
                idx = np.arange(j0b, j1b)
                grad[idx] -= h[idx + d]
        grad *= dx / topK

        cur_lr = lr / (1.0 + it * 0.005)
        v = 0.85 * v - cur_lr * grad
        h = project_to_feasible(h + v, n)
        corr = compute_corr_fft(h)

        if stall > patience:
            lr *= 0.7
            v *= 0.5
            stall = 0
            if lr < 1e-14:
                break

    return best_h, best_c5

This is a classic 1D minimax problem. The solution is:
- Sort the lines by slope
- The minimum of the max is at the intersection of two adjacent lines (in the upper envelope)

For efficiency, we can:
1. Compute the current max: M = max_k c_k
2. Find the k* that achieves the max
3. The optimal t is where c_{k*}(t) = the next highest c_k(t)
4. Or t = 0 or t = 1 if the max is monotonically decreasing/increasing

This gives us a fast coordinate descent:
- For each i (in random or sequential order):
  - Compute α_k for the critical k's (those with c_k close to the max)
  - Find the optimal t
  - Update h[i] = t
  - Update c_k values (only those affected by i)

The "update c_k values" step: changing h[i] to t changes c_k by α_k * (t - h[i]_old). So we can update c_k incrementally.
