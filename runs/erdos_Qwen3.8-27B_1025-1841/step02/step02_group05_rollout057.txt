def project_to_feasible(g, n):
    target = n / 2.0
    lo = g.min() - 2.0
    hi = g.max() + 2.0
    for _ in range(60):
        mid = (lo + hi) / 2.0
        s = np.sum(np.clip(g - mid, 0.0, 1.0))
        if s > target:
            lo = mid
        else:
            hi = mid
    return np.clip(g - (lo + hi) / 2.0, 0.0, 1.0)

def interp_periodic(h, target_n):
    n = len(h)
    if n == target_n:
        return h.copy()
    x_old = np.arange(n) * (2.0 / n)
    x_new = np.arange(target_n) * (2.0 / target_n)
    return np.interp(x_new, x_old, h, period=2.0)

def compute_c5(h):
    n = len(h)
    return np.correlate(h, 1.0 - h, mode='full').max() * (2.0 / n)

def smooth_gradient(h, p, dx):
    """Compute gradient of log-sum-exp objective given h and softmax probabilities p."""
    n = len(h)
    grad = np.zeros(n)
    for k in range(2 * n - 1):
        pk = p[k]
        if pk < 1e-14:
            continue
        sh = k - n + 1
        j0 = max(0, sh)
        j1 = min(n, sh + n)
        if j0 < j1:
            grad[j0:j1] += pk * (1.0 - h[j0-sh:j1-sh])
        j0b = max(0, -sh)
        j1b = min(n, n - sh)
        if j0b < j1b:
            grad[j0b:j1b] -= pk * h[j0b+sh:j1b+sh]
    grad *= dx
    return grad

    best_h = h.copy()

        tau = tau_start * (tau_end / tau_start) ** progress

        max_c = corr.max()
        c5_now = max_c * dx

**New idea: use a more aggressive exploration strategy.**

The key issue with gradient-based methods on max-type objectives is that they get stuck on a particular "dominant" shift k*. Even though the smooth approximation uses all shifts, the effective gradient is dominated by the top few.

What if I explicitly enforce that NO shift is too large? I.e., add a penalty for the SECOND and THIRD largest correlations, not just the max.

Modified objective: 
f(h) = max_k corr[k] + 0.1 * second_max(corr) + 0.05 * third_max(corr)

This is more sensitive to the "tail" of the correlation distribution and might push all correlations down more evenly.

Or: f(h) = (corr[k*])² + ε * Σ_k corr[k]² (where k* is the argmax)

The squared penalty makes it more sensitive to large values.

Let me try this: use a p-norm of the correlations instead of the max or log-sum-exp:
f(h) = (Σ_k corr[k]^p)^(1/p) for large p (like p=20, 50, 100)

As p→∞, this approaches the max. For finite p, it's smoother and pushes all correlations down.

The gradient of the p-norm:
∂f/∂h[j] = (1/p) (Σ_k corr[k]^p)^{1/p - 1} * Σ_k p * corr[k]^{p-1} * ∂corr[k]/∂h[j]

For large p, corr[k*]^{p-1} dominates, and it's similar to the max gradient but with a slight "smearing" to the next-largest correlations.

Let me implement this:

```python
def pnorm_obj_grad(h, p_norm, dx):
    n = len(h)
    corr = np.correlate(h, 1.0 - h, mode='full')
    # p-norm of positive part (since corr can be negative)
    corr_pos = np.maximum(corr, 0)
    pnorm = (np.sum(corr_pos ** p_norm)) ** (1.0 / p_norm)
    # Gradient
    weights = corr_pos ** (p_norm - 1)
    if pnorm > 0:
        weights = weights / (pnorm ** (p_norm - 1))
    else:
        weights = np.zeros_like(weights)
    # grad[j] = sum_k weights[k] * dcorr[k]/dh[j]
    grad = np.zeros(n)
    for k in range(2 * n - 1):
        wk = weights[k]
        if abs(wk) < 1e-14:
            continue
        sh = k - n + 1
        j0 = max(0, sh)
        j1 = min(n, sh + n)
        if j0 < j1:
            grad[j0:j1] += wk * (1.0 - h[j0-sh:j1-sh])
        j0b = max(0, -sh)
        j1b = min(n, n - sh)
        if j0b < j1b:
            grad[j0b:j1b] -= wk * h[j0b+sh:j1b+sh]
    grad *= dx
    return pnorm * dx, grad
```

For p=20-100, this should be smooth enough for gradient methods while still emphasizing the max.
