Now, let me also think about a smarter local search. Instead of random pairs, I can:
1. Identify the "worst" shift (where c is maximum)
2. Find positions that contribute most to that shift
3. Propose flips that specifically reduce that shift

For shift s (in the original indexing), c[s] = ∑ⱼ h[j] * (1-h[j+s])
The "bad" positions are where h[j]=1 and h[j+s]=0 (these contribute 1 to the sum).
Flipping h[j] from 1 to 0 reduces c[s] by 1.
But flipping h[j+s] from 0 to 1 ALSO reduces c[s] by 1 (since now 1-h[j+s]=0).

So a good move is: flip h[j] from 1→0 AND h[j+s] from 0→1, where both are valid.
This reduces c[s] by 2 (one from the direct term, one from the partner).

But it might increase other shifts. Let me check:
Δc[t] = h[b+t] + h[b-t] - h[a+t] - h[a-t]
where a = j+s (the 0 we're flipping to 1), b = j (the 1 we're flipping to 0).

So Δc[t] = h[j+s+t] + h[j+s-t] - h[j+t] - h[j-t]

This is a specific pattern. For t=0: h[j+s] + h[j+s] - h[j] - h[j] = 0 + 0 - 1 - 1 = -2. Wait, h[j+s] is 0 (we're about to flip it to 1, but in the current state it's 0). And h[j] = 1. So Δc[0] = 0 + 0 - 1 - 1 = -2. Good, that reduces c[0] by 2.

For t=s: h[j+2s] + h[0] - h[j+s] - h[j-s] = h[j+2s] + h[0] - 0 - h[j-s]

def project_to_feasible(g, n):
    target = n / 2.0
    lo = g.min() - 2.0
    hi = g.max() + 2.0

        s = np.sum(np.clip(g - mid, 0.0, 1.0))
        if s > target:
            lo = mid
        else:
            hi = mid
