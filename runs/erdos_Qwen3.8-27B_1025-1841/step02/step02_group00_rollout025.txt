For val=0 (flipping 0→1): change = +1·[(1-h[i+s]) - h[i+s]] = 1 - h[i+s] - h[i-s]

In general: r = cp[2*n-3 : 3*n-2][::-1] = cp[3:7][::-1] for n=3. ✓

So the gradient formula is:
grad[i] = dx * (1 - q[i] - r[i])

where q = np.convolve(h, p, mode='full')[n-1 : 2n-2]
      r = np.correlate(h, p, mode='full')[2n-3 : 3n-2][::-1]

Let me verify the gradient formula itself with a numerical check.

For the objective F = (1/T)*log(sum_k exp(T*corr[k]))*dx:
dF/dh[i] = dx * sum_k p[k] * d(corr[k])/dh[i]
where p[k] = exp(T*corr[k]) / sum_exp

d(corr[k])/dh[i] = (1-h[i+n-1-k]) - h[i-n+1+k] (with out-of-bounds = 0)

So dF/dh[i] = dx * sum_k p[k] * [(1-h[i+n-1-k]) - h[i-n+1+k]]
= dx * [(sum_k p[k]) - sum_k p[k]*h[i+n-1-k] - sum_k p[k]*h[i-n+1+k]]
= dx * [1 - q[i] - r[i]]

where q[i] = sum_k p[k]*h[i+n-1-k] and r[i] = sum_k p[k]*h[i-n+1+k]

This confirms the formula. Note that sum_k p[k] = 1 (since p is a probability distribution).

Now, with this efficient gradient, I can use L-BFGS-B for fast optimization.

The total cost per gradient evaluation:
- Compute corr: O(n²) with np.correlate (but fast in C)
- Compute p: O(n)
- Compute q (convolution): O(n log n) with FFT
- Compute r (correlation): O(n²) with np.correlate (but fast in C)

Wait, np.correlate and np.convolve are both O(n²) in general (they don't use FFT for real inputs by default in older numpy). But they're implemented in C and are quite fast.

For n=2048, the correlation array has length 4095. np.correlate(h, p, mode='full') where both have length
- h: length 2048
- p: length 4095
This is O(2048 * 4095) ≈ 8M operations. In C, that's maybe 1-2ms.

np.convolve(h, p, mode='full') is similar: O(2048 * 4095) ≈ 8M.

So each gradient evaluation is maybe 5-10ms (including the initial correlate for corr).

L-BFGS-B does one gradient evaluation per iteration (it uses the gradient to compute the search direction). With max_iter=1000, that's about 5-10 seconds. Very fast!

But wait, L-BFGS-B also does line searches, which require multiple function evaluations. Each function evaluation requires computing corr (O(n²) in C, maybe 1-5ms). With ~10 line search iterations per L-BFGS-B step, the total cost per step is maybe 50-100ms. For 1000 steps, that's 50-100 seconds.

This is very feasible! I can do multiple L-BFGS-B runs with different temperatures and starting points.
