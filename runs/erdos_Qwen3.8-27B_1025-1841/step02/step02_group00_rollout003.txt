def make_feasible(h, n):
    h = np.clip(h.copy(), 0.0, 1.0)
    target = n / 2.0
    for _ in range(100):
        diff = target - h.sum()
        if abs(diff) < 1e-12:
            break
        if diff > 0:
            mask = h < 1.0 - 1e-14
        else:
            mask = h > 1e-14
        cnt = mask.sum()
        if cnt == 0:
            break
        h[mask] += diff / cnt
        h = np.clip(h, 0.0, 1.0)
    return h

def objective_and_grad(h, T):
    n = len(h)
    dx = 2.0 / n
    g = np.correlate(h, 1.0 - h, mode='full')
    g_max = float(np.max(g))
    shifted = g - g_max
    exps = np.exp(T * shifted)
    exp_sum = exps.sum()
    val = (g_max + np.log(exp_sum) / T) * dx
    p = exps / exp_sum
    
    grad = np.zeros(n)
    for m in range(2 * n - 1):
        if p[m] < 1e-25:
            continue
        s = m - n + 1
        pm = p[m]
        if s >= 0:
            grad[s:] += pm * (1.0 - h[:n-s])
            grad[:n-s] -= pm * h[s:]
        else:
            sp = -s
            grad[:n-sp] += pm * (1.0 - h[sp:])
            grad[sp:] -= pm * h[:n-sp]
    grad *= dx
    return val, grad

def upsample(h, new_n):
    old_n = len(h)
    if old_n == new_n:
        return make_feasible(h.copy(), new_n)
    old_x = np.linspace(0, 2, old_n, endpoint=False)
    new_x = np.linspace(0, 2, new_n, endpoint=False)
    h_new = np.interp(new_x, old_x, h, period=2.0)
    return make_feasible(h_new, new_n)

So the change in g_k when h[i] → h[i]+δ is:
δ * [(1 - h[i-s]) if valid] - δ * h[i+s] if valid  (for shift s)
Wait, this is exactly ∂g_k/∂h[i] * δ (the linear approximation)? No, it's exact because g_k is bilinear (linear in each argument separately).

Yes! Since g_k = sum_v h[v+s] - sum_v h[v+s]*h[v], and we're only changing h[i]:
- In sum_v h[v+s]: changes by δ if i = v+s for some valid v, i.e., v = i-s is valid.
- In sum_v h[v+s]*h[v]: 
  - If i = v+s: term h[v+s]*h[v] = h[i]*h[v] changes by δ*h[v] = δ*h[i-s]
  - If i = v: term h[v+s]*h[v] = h[v+s]*h[i] changes by h[v+s]*δ = h[i+s]*δ

So Δg_k = δ * [indicator(i-s valid as v) - indicator(i-s valid)*h[i-s] - indicator(i+s valid)*h[i+s]]
= δ * [(1-h[i-s]) * indicator - h[i+s] * indicator]

This is exactly the partial derivative I computed before! And it's exact (not just a linear approximation) because g_k is bilinear.

So: g_k(δ) = g_k + δ * ∂g_k/∂h[i] (exact, for a single element change)

For a pair change (h[i]+δ, h[j]-δ):
g_k(δ) = g_k + δ * (∂g_k/∂h[i] - ∂g_k/∂h[j]) (exact!)

This is because the bilinear terms cross-couple: when changing both h[i] and h[j], the cross term h[i]*h[j] appears. Let me check:

g_k = sum_v h[v+s]*(1-h[v])

Change h[i] → h[i]+δ and h[j] → h[j]-δ:
New g_k = sum_v h'[v+s]*(1-h'[v])

If i ≠ j (which they are, since it's a pair):
- The cross terms h[i]*h[j] don't exist in the same term (they're in different v positions unless i-v = j or j-v = i, i.e., i-j = v or j-i = v, which would mean the same v gives both i and j as v+s and v. For s ≠ 0, i ≠ j, so v can't equal both i-s and j simultaneously unless s = i-j).

Wait, there IS a cross term when i = j+s or j = i+s (i.e., s = i-j or s = j-i). In that case, the term h[i]*h[j-something] appears and both changes affect it.

Specifically, if s = i - j (i.e., j = i - s): then the term v = j gives h[j+s]*h[j] = h[i]*h[j]. After the change: (h[i]+δ)*(h[j]-δ) = h[i]*h[j] - h[i]*δ + h[j]*δ - δ^2.

So there's a -δ^2 term! This means g_k(δ) is NOT linear in δ when the pair (i,j) happens to be at a specific shift relationship.

Specifically, for shift s where j = i - s (i.e., the same term contains both h[i] and h[j]):
Δg_k = -δ^2 (second order)

And for shift s where i = j - s (i.e., i = j - s, same thing):
Same thing.

So there's at most one (or two) shifts where the δ^2 term appears. For all other shifts, g_k(δ) is linear.

This means φ(δ) = max_k g_k(δ) is the max of:
- O(n) linear functions
- Possibly 1-2 quadratic functions (with -δ^2 term, so they're concave quadratics)

The max of concave quadratics and lines is still... well, it's the max of convex (affine) and concave (quadratic) functions. The max of these is not necessarily convex.

However, since the -δ^2 term is small (δ is small, at most 1), the quadratic perturbation is small. For practical purposes, treating g_k(δ) ≈ g_k + δ * d_k (ignoring the -δ^2 term) is a good approximation. And the true minimum is close to the approximate minimum.

So my plan: ignore the quadratic term, do ternary search on the linear approximation, then verify and fine-tune with a few exact evaluations.
