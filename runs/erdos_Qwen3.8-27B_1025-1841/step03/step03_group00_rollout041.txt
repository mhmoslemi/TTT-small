    """Compute all correlation values (the 'full' cross-correlation of h and 1-h)."""

def soft_max_objective(h, n, T, mu):
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    mc = np.max(corr)
    shifted = T * (corr - mc)
    shifted = np.clip(shifted, -100, 100)
    soft = (mc + np.log(np.sum(np.exp(shifted))) / T) * dx
    viol = np.sum(h) - n / 2.0
    return soft + mu * viol * viol

def lbgfb_smooth(h_start, n, T, mu, max_iter=300):
    dx = 2.0 / n
    def f(h):
        corr = np.correlate(h, 1.0 - h, mode='full')
        mc = np.max(corr)
        shifted = T * (corr - mc)
        shifted = np.clip(shifted, -80, 80)
        soft = (mc + np.log(np.sum(np.exp(shifted))) / T) * dx
        viol = np.sum(h) - n / 2.0
        return soft + mu * viol * viol
    bounds = [(0.0, 1.0)] * n
    res = minimize(f, h_start, method='L-BFGS-B', bounds=bounds,
                   options={'maxiter': max_iter, 'ftol': 1e-16, 'gtol': 1e-12})
    return make_feasible(res.x, n)

def binary_local_search_swaps(h_bin, n, rng, max_rounds=50, n_tries_per_round=5000):
    """Binary local search using pair swaps (preserves count)."""
    h = h_bin.copy()
    current_c = corr_values(h)
    current_max = float(np.max(current_c))
    ones = np.where(h > 0.5)[0].copy()
    zeros = np.where(h <= 0.5)[0].copy()
    
    for rnd in range(max_rounds):
        improved = False
        for _ in range(n_tries_per_round):
            ii = rng.randint(len(ones))
            jj = rng.randint(len(zeros))
            oi = ones[ii]
            oj = zeros[jj]
            if oi == oj:
                continue
            
            # Compute delta for all correlation values
            # Δc_k for the 'full' correlation
            # h changes: h[oi] 1->0, h[oj] 0->1
            # For corr[t] = sum_m h[m] * (1-h[m-t+(n-1)])... 
            # Let me use the direct formula.
            # corr[t] = sum_{m valid} h[m+t-(n-1)] * (1-h[m])
            
            # Effect on corr[t]:
            # h[oi] appears as h[m+t-(n-1)] = h[oi] when m+t-(n-1) = oi, i.e., t = oi + (n-1) - m
            #   for valid m: gives contribution change of -(1-h[m]) for each such m
            # h[oi] appears as (1-h[m]) = (1-h[oi]) when m = oi, i.e., t anywhere valid with m=oi
            #   gives contribution change of -h[oi+t-(n-1)] for each valid t with m=oi
            # Similarly for h[oj].
            
            # This is getting complex. Let me just recompute the correlation for affected indices.
            # Actually, for efficiency, let me just compute the new max directly.
            
            h[oi] = 0.0
            h[oj] = 1.0
            
            # Only recompute if it could improve
            # Quick check: compute corr at the current argmax position
            # Actually, let's just do a full recompute for correctness (it's O(n^2) but n=1024 means ~10^6 ops)
            new_c = np.correlate(h, 1.0 - h, mode='full')
            new_max = float(np.max(new_c))
            
            if new_max < current_max:
                current_max = new_max
                current_c = new_c
                # Update ones and zeros
                ones = np.delete(ones, ii)
                zeros = np.delete(zeros, jj)
                ones = np.append(ones, oj)
                zeros = np.append(zeros, oi)
                improved = True
            else:
                h[oi] = 1.0
                h[oj] = 0.0
        
        if not improved:
            break
    
    dx = 2.0 / n
    return h, current_max * dx

Hmm, the full recompute of correlation for each swap is O(n^2) which for n=1024 is about 10^6 operations. With 5000 tries per round and 50 rounds, that's 2.5 * 10^9 operations. At ~10^8 per second in numpy (correlate is implemented in C), that's about 25 seconds per call. That's feasible.

But wait, np.correlate is O(n^2) for 'full' mode? Let me check. For arrays of length n, 'full' correlation has 2n-1 output values, each requiring O(n) multiplications. So total is O(n^2). For n=1024, that's about 2*10^6 operations per call. In C (which numpy uses), this should be very fast, maybe 0.1ms per call. So 5000 calls would be about 0.5 seconds. That's fine.

Actually, I can do even better. Instead of full correlate, I can compute the change in the correlation more efficiently.

For a swap (oi, oj) where h[oi]: 1→0 and h[oj]: 0→1:
The change in corr[t] for each t:
- corr[t] = sum_m h[m+t-(n-1)] * (1-h[m]) (for valid m)

The change due to h[oi]: 1→0:
- As the "first" factor: h[m+t-(n-1)] = 1 was at m+t-(n-1) = oi, so t = oi+n-1-m. For each valid m, corr[t] changes by -(1-h[m]).
- As the "second" factor: (1-h[m]) = 0 was at m = oi, so corr[t] changes by -h[oi+t-(n-1)] for each valid t.

The change due to h[oj]: 0→1:
- As the "first" factor: h[m+t-(n-1)] = 0 was at m+t-(n-1) = oj, so t = oj+n-1-m. For each valid m, corr[t] changes by +(1-h[m]).
- As the "second" factor: (1-h[m]) = 1 was at m = oj, so corr[t] changes by +h[oj+t-(n-1)] for each valid t.

So the total change in corr[t] is:
Δcorr[t] = -(1-h[m1]) - h[oi+t-(n-1)] + (1-h[m2]) + h[oj+t-(n-1)]
where m1 = oi+n-1-t (the m such that oi is the "first" factor) and m2 = n-1-t+... 

This is getting complicated. Let me just use the full recompute approach since it's fast enough in numpy.

Actually, I just realized there's a much simpler way to think about the delta. Let me define:
g = 1 - h (the complement)
corr[t] = sum_m h[m+t-(n-1)] * g[m]

If I change h[oi] from 1 to 0, then g[oi] changes from 0 to 1.
If I change h[oj] from 0 to 1, then g[oj] changes from 1 to 0.

So the changes are:
- h[oi]: 1→0 affects corr[t] for t = oi + (n-1) - m (for each valid m in the sum). The change is -g[m] = -(1-h[m]) for each such m.
  But also, g[oi]: 0→1 affects corr[t] for t = oi + (n-1) - m... wait, g[oi] appears as g[m] when m=oi, so it affects corr[t] where m=oi is valid, i.e., t ranges over valid values with m=oi. The change is +h[oi+t-(n-1)].

Let me just define the four "impulse" responses:
1. h[oi] 1→0: subtracts a "vector" A_oi where A_oi[t] = 1 if h[oi] appears in corr[t] as the first factor, 0 otherwise. Specifically, A_oi[t] = g[m] where m = oi + (n-1) - t (if valid).

Ugh, this is getting too complicated for the analysis. Let me just use the straightforward approach: for each candidate swap, recompute the full correlation and check the max. With numpy, this is fast enough.

Let me also add a "directed" local search: instead of random pair selection, try pairs that are "likely" to help. For example, if the current max is at lag k*, then swapping a 1 at position i with a 0 at position i+k* might reduce the correlation at that lag.
