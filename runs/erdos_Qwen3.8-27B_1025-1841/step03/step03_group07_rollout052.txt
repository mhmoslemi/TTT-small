This is a convex problem (min of convex functions, convex constraints). Frank-Wolfe applies to:

Here F(h) = max_k f_k(h), P = {h : sum(h)=n/2, 0≤h≤1}

FW iteration:
1. Compute subgradient g of F at current h
2. Solve: v = argmin_{u ∈ P} <g, u> (linear minimization over P)
3. h = (1-t)*h + t*v

Step 2: min <g, u> s.t. sum(u) = n/2, 0 ≤ u ≤ 1
This is: pick the n/2 smallest components of g, set them to 1, rest to 0.
Wait, min sum(g[i]*u[i]) with sum(u)=n/2, 0≤u≤1:

- Or: line search along h + t*(v-h)

- A "move" is: set h[a]=0, h[b]=1 (where currently h[a]=1, h[b]=0)
- This maintains the sum constraint
- Evaluate the new C5

To make this fast, I'll:
- Precompute the shift contributions for the current h
- For a candidate move (a→b), compute the change in each corr[k]
- Accept if max corr decreases

The change in corr[k] for moving 1 from a to b:
- Old: corr[k] counts positions i where h[i]=1, h[i+k]=0
- After move: h'[a]=0, h'[b]=1
- For shift k (where k = s + n - 1 in the np.correlate indexing, s is the actual shift):
  - Position a no longer contributes as a "1": lose 1 if h[a+s]=0 (and indices valid)
  - Position a now is a "0": gain 1 if h[i]=1 and i+s=a (i.e., i=a-s, h[a-s]=1)
  - Position b now contributes as a "1": gain 1 if h[b+s]=0 (and indices valid)
  - Position b was a "0": lose 1 if h[i+s]=b was counted... wait, this is getting confusing.

Let me use a cleaner formulation. For shift s (can be negative), the correlation at shift s is:
C(s) = sum_{i: 0≤i<n, 0≤i+s<n} h[i] * (1-h[i+s])

After changing h[a] from 1 to 0 and h[b] from 0 to 1:
C'(s) - C(s) = [change due to a becoming 0] + [change due to b becoming 1] - [cross terms]

For position a (1→0):
- It was contributing +1 to C(s) for each s where h[a+s]=0 (a is the "1" in the pair)
- It was contributing -1 to C(s) for each s where h[a-s]=1 (a is the "0" in the pair, wait...)

Actually: C(s) = sum_i h[i]*(1-h[i+s])
For a specific i, the term is h[i]*(1-h[i+s]).
- If h[i]=1, h[i+s]=0: contributes 1
- If h[i]=1, h[i+s]=1: contributes 0
- If h[i]=0: contributes 0

So for the pair (i, i+s), it contributes 1 iff h[i]=1 and h[i+s]=0.

When we change h[a]: 1→0:
- For shifts s where a is the first index: i=a, need a+s valid. Contribution was 1 if h[a+s]=0, now 0. Change: -1 if h[a+s]=0.
- For shifts s where a is the second index: i+s=a, i=a-s. Contribution was 1 if h[a-s]=1 (and h[a]=0... wait, h[a] was 1, so (1-h[a])=0, so the pair (a-s, a) contributed 0 originally). After change: h[a]=0, so if h[a-s]=1, now contributes 1. Change: +1 if h[a-s]=1.

When we change h[b]: 0→1:
- For shifts s where b is the first index: i=b. Was 0 (h[b]=0), now 1 if h[b+s]=0. Change: +1 if h[b+s]=0.
- For shifts s where b is the second index: i+s=b, i=b-s. Was: h[b-s]*(1-h[b]) = h[b-s]*1 = h[b-s]. Now: h[b-s]*(1-h[b]) = h[b-s]*0 = 0. Change: -h[b-s] (i.e., -1 if h[b-s]=1).

So total change for C(s):
ΔC(s) = -[h[a+s]=0] + [h[a-s]=1] + [h[b+s]=0] - [h[b-s]=1]
(where brackets mean indicator, and we need valid indices)

This is O(1) per shift! But we need to check all 2n-1 shifts... that's O(n) per candidate move.

For n=4000, O(n) = 4000 operations per candidate. If we try 1000 candidates, that's 4M operations, very fast.

But we need to track the MAX, not just the value at one shift. So after computing ΔC(s) for all s, we need:
new_max = max_s (C(s) + ΔC(s))

We can compute this in O(n) if we have C(s) stored.

So the local search algorithm:
1. Start with binary h, compute C(s) for all s, find max
2. For a batch of candidate (a,b) pairs:
   a. Compute ΔC(s) for all s: O(n)
   b. new_max = max(C + ΔC): O(n)
   c. If new_max < current_max, accept the move
3. Update C(s) for accepted moves: O(n)

Total per iteration: O(n * batch_size)

With batch_size = 100 and n=4000: 400K operations, very fast.

This could allow millions of local search steps in the time budget!

Wait, but recomputing the full correlation for each move is O(n²). For n=4000, that's 16M ops. In numpy, np.correlate is implemented in C and should be fast. Let me estimate: for two arrays of length 4000, the full correlation has 7999 outputs. Each output requires up to 4000 multiply-adds. Total: ~16M FLOPs. At ~10 GFLOPS for numpy on a single core, that's ~1.6ms. So 50 moves = 80ms per round. In 40s, we can do ~500 rounds × 50 moves = 25000 moves. That's plenty.

But actually, we can do better by computing the delta analytically:

For a move (a: 1→0, b: 0→1), the change in corr at shift s (represented by k = s + n - 1 in the full output):

The original corr at index k (shift s = k - n + 1):
C[k] = sum_{i: max(0,-s) ≤ i ≤ min(n-1, n-1-s)} h[i+s] * (1-h[i])
     = sum over valid (i, i+s) pairs

Actually, it's easier to think of it as:
C[k] = sum_i h[i] * (1-h[i+s]) where i ranges over values where both i and i+s are in [0, n-1].

For the move:
- h[a] changes from 1 to 0
- h[b] changes from 0 to 1

Effect on C[k] (shift s):
Old contribution of a: 
- If a+s is valid (0 ≤ a+s < n): h[a]*(1-h[a+s]) = 1*(1-h[a+s]) → now 0
- If a-s is valid (0 ≤ a-s < n): h[a-s]*(1-h[a]) = h[a-s]*0 = 0 → now h[a-s]*1

Old contribution of b:
- If b+s is valid: h[b]*(1-h[b+s]) = 0 → now (1-h[b+s])
- If b-s is valid: h[b-s]*(1-h[b]) = h[b-s] → now 0

So ΔC[k] = -[a+s valid]*(1-h[a+s]) + [a-s valid]*h[a-s] + [b+s valid]*(1-h[b+s]) - [b-s valid]*h[b-s]

All O(1) per k! So we can compute ΔC for all 2n-1 shifts in O(n) time.

Then new_max = max_k (C[k] + ΔC[k]) in O(n).

Total per move: O(n) = O(8000) ≈ very fast!
