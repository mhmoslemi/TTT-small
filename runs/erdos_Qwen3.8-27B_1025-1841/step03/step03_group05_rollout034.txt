def subgrad_at_shift(h, shift):
    """Subgradient of c_{n-1+shift} with respect to h."""
    n = len(h)

    if s >= n:
        return np.zeros(n)
    g = np.zeros(n)
    if shift >= 0:

        g[:n-s] -= h[s:]
    else:

The fundamental issue is that the FISTA gradient is a weighted average of subgradients, which gives a direction that reduces the "average" of the top correlations. But what we really want is to reduce the maximum. When the maximum is achieved at a single lag (or a few), the gradient should be concentrated on those lags.

With power p=500, the weights are essentially: w_k ∝ |c_k|^{499}, which means the weight is almost entirely on the maximum lag. So the gradient is essentially the subgradient at the argmax. This is correct for reducing the max, but it might cause oscillation (reducing one lag increases another).

The **key insight** I'm missing: we need to reduce the maximum without increasing the second maximum (and so on). This is a **minimax** problem, and the right approach is to use the **normal cone** condition: at the optimum, the 0 vector should be in the convex hull of the subgradients at the active lags.

In practice, this means:
- If only one lag is active, the subgradient at that lag should be 0 (which means we're at a local minimum for that lag)
- If multiple lags are active, we need a convex combination of their subgradients to give 0

The FISTA approach with high p essentially tries to find a point where the subgradient at the argmax is close to 0. But this might not be the global optimum if there are other lags that could become the maximum.

A better approach: **alternate between reducing different lags**.
1. Find the current maximum lag k1
2. Optimize to reduce c_{k1} (using its subgradient)
3. Check if c_{k1} is still the maximum
4. If not, find the new maximum lag k2 and optimize to reduce c_{k2}
5. Repeat

This is essentially the "cyclical" approach. Let me implement this.

Actually, this is what the targeted_refine function does (it targets all lags within 1% of the max). The issue is that it uses a fixed small step size, which might be too conservative.

    corr = np.correlate(h, 1.0 - h, mode='full')

def project_c(h, n):
    target = n / 2.0
    lo, hi = -2.0, 2.0
    for _ in range(60):
