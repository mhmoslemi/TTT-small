```python
        h = np.clip(h, 0.0, 1.0)

        if len(zeros) == 0:
            break
        idx = zeros[np.argmax(h[zeros])]
        b[idx] = 1
    return b

    old_x = np.linspace(0.0, 2.0, old_n)
    new_x = np.linspace(0.0, 2.0, new_n)
    h_new = np.interp(new_x, old_x, h)
    return make_feasible(h_new, new_n)

                best_corr = corr.copy()

            b[j] = 0
```

```python
    if state.c5 < best_c5:
        best_c5 = state.c5
        best_b = state.b.copy()
    return best_b, best_c5
```

Hmm, but there's an issue. After `state.apply(i, j, state._new_corr)`, the `state._new_corr` becomes the new correlation. But then in the next iteration of the inner loop, `state.eval_swap(i2, j2)` will use `state.corr` which has been updated. That's correct.

But wait, `state._new_corr` is a pre-allocated buffer. After `state.apply`, we set `state.corr = state._new_corr`. Then in the next `eval_swap`, we compute `np.add(state.corr, self._tmp, out=self._new_corr)`. But `state.corr` IS `self._new_corr`! So we're reading from and writing to the same array!

This is a bug. I need to either:
1. Copy the correlation when applying: `self.corr = self._new_corr.copy()`
2. Use a separate buffer for the new correlation

Option 1 is simpler but adds a copy (O(n) per swap). Option 2 requires two buffers.
