import numpy as np
import time

def compute_c5(h, dx):
    corr = np.correlate(h, 1.0 - h, mode="full")
    return float(np.max(corr)) * dx

def make_binary(n, rng):
    h = np.zeros(n)
    pos = rng.choice(n, size=n//2, replace=False)
    h[pos] = 1.0
    return h

def upsample_to_binary(h_src, n_new):
    n_src = len(h_src)
    if n_src == n_new:
        return h_src.copy()
    x_src = np.linspace(0, 2, n_src, endpoint=False)
    x_new = np.linspace(0, 2, n_new, endpoint=False)
    vals = np.interp(x_new, x_src, h_src)
    target = n_new // 2
    idx = np.argsort(vals)[::-1][:target]
    h = np.zeros(n_new)
    h[idx] = 1.0
    return h

def greedy_sweep(h, dx):
    """One pass of greedy local search. Returns (c5, improved)."""
    ones = np.where(h == 1)[0]
    zeros = np.where(h == 0)[0]
    c5 = compute_c5(h, dx)
    improved = False
    
    for i in ones:
        for j in zeros:
            if h[i] != 1 or h[j] != 0:
                continue
            h[i] = 0
            h[j] = 1
            new_c5 = compute_c5(h, dx)
            if new_c5 < c5 - 1e-12:
                c5 = new_c5
                improved = True
            else:
                h[i] = 1
                h[j] = 0
    
    return c5, improved

def local_search(h, dx, time_limit, rng):
    n = len(h)
    best_c5 = compute_c5(h, dx)
    best_h = h.copy()
    start = time.time()
    
    while time.time() - start < time_limit:
        # Greedy sweeps
        progress = True
        while progress and time.time() - start < time_limit:
            c5, improved = greedy_sweep(h, dx)
            if c5 < best_c5:
                best_c5 = c5
                best_h = h.copy()
            progress = improved
        
        if time.time() - start >= time_limit:
            break
        
        # Perturb to escape local minimum
        ones = np.where(h == 1)[0]
        zeros = np.where(h == 0)[0]
        n_pert = min(5, len(ones), len(zeros))
        for _ in range(n_pert):
            i = int(rng.choice(ones))
            j = int(rng.choice(zeros))
            h[i] = 0
            h[j] = 1
            ones = np.where(h == 1)[0]
            zeros = np.where(h == 0)[0]
        
        # Continue with greedy from perturbed state
        # (will be handled by next iteration of outer while)
    
    return best_h, best_c5

Let me also add an optimization: if the current c5 equals the theoretical lower bound for this n, stop early.

Theoretical lower bound: The sum of all correlation values = sum_k sum_i h[i+k]*(1-h[i]) over all valid (i,k) pairs.
= sum_i [h[i] * (number of j where h[j]=0)] = (n/2) * (n/2) = n²/4

Wait, that's for the circular case. For the linear case, it's more complex.

Actually, for the linear case:
sum_{k=-(n-1)}^{n-1} sum_{i: valid} h[i+k]*(1-h[i])
= sum over all pairs (i, j) where i≠j, h[j]=1, h[i]=0, j-i = k
= sum over all pairs (i, j) where h[j]=1, h[i]=0, i≠j
= (n/2) * (n/2) - (number of i where h[i]=1 AND h[i]=0, which is 0)
= n²/4

Wait, but each pair (i,j) is counted exactly once (at k=j-i). And i≠j is guaranteed since h[i]=0, h[j]=1.

So sum of all correlation values = n²/4 (for binary with n/2 ones).

The number of lags is 2n-1. So the average correlation value = (n²/4) / (2n-1) ≈ n/8 for large n.

But the max must be at least the average, so max_corr ≥ n²/(4(2n-1)) ≈ n/8.

For n=48: n/8 = 6. So max_corr ≥ 6, meaning C₅ ≥ 6 * 2/48 = 0.25.
For n=128: n/8 = 16. C₅ ≥ 16*2/128 = 0.25.

So the theoretical lower bound is about 0.25 regardless of n. The current record is 0.38, so there's room to improve to closer to 0.25.

But achieving exactly n/8 for all lags is impossible due to edge effects (fewer valid positions at extreme lags). The practical lower bound is a bit higher.

Let me also think: for a "perfect" construction where all interior lags have exactly n/8, what does max_corr look like?
- Interior lags (|k| < n/4 or so): ≈ n/8
- Edge lags (|k| close to n): much less (only 1-2 valid positions)
- So max is determined by the interior lags ≈ n/8

But can we achieve exactly n/8 at all interior lags? That requires a very specific combinatorial design. For n=48, we'd need 6 at each of the "middle" lags. This is related to difference sets.

A (v, k, λ) difference set in Z_v: a subset S of Z_v with |S|=k such that every nonzero element of Z_v is expressed as a difference of exactly λ elements of S. 

If we had a (48, 24, λ) difference set, then for each nonzero shift k in Z_48, the number of (i,j) ∈ S² with j-i=k would be λ. This is the "circular" version. For the linear version, it's different.

A (48, 24, 12) difference set would give λ=12 for each shift. But we need the "cross" difference (S ∩ (S-k)^c), not the "self" difference.

Let me think differently. For binary h with |A|=n/2:
count(k) = #{i: h[i+k]=1, h[i]=0} = |A ∩ (A-k)^c ∩ valid range|

If the set A is "well-distributed", then for shift k:
|A ∩ (A-k)| ≈ (n/2)²/n = n/4 (by the pigeonhole / mixing principle)
count(k) = |A| - |A ∩ (A-k)| ≈ n/2 - n/4 = n/4

Wait, that gives max ≈ n/4, C₅ ≈ n/4 * 2/n = 1/2. That's the random level.

But we can do better. For a "structured" set like an arithmetic progression or a Sidon set, the differences are more uniform.

Actually, I think the key insight is: we want |A ∩ (A-k)| to be as LARGE as possible for the shifts where the valid range is large. This means we want A to have high "auto-correlation" at those shifts.

But we also want count(k) = |A| - |A∩(A-k)| to be SMALL, which means |A∩(A-k)| should be LARGE.

For a random set: |A∩(A-k)| ≈ |A|²/n = n/4, so count ≈ n/4.
For a "clustered" set (all 1s together): |A∩(A-k)| is large for small k (up to n/2-|k|), small for large k. Max count is at the boundary shift.

For a "periodic" set (every other position): |A∩(A-k)| = 0 for odd k, n/2-|k| for even k. Max count is at odd k: n/2. Bad.

For a "BCH code" or other structured set: potentially better.

I think the optimal construction for small n can be found by computer search, which is what we're doing.
