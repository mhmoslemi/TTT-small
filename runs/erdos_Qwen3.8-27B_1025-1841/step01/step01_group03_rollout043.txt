```python
    positive = corr[n-1:]
    k = int(np.argmax(positive))
    obj = positive[k] * dx

        grad[:n-k] += (1.0 - h[k:])
        grad[k:] -= h[:n-k]

    """Project h onto {h: sum(h) = target_sum, 0 <= h <= 1}"""

    if abs(diff) < 1e-10:
        return h

    for _ in range(100):

            h = np.clip(h, 0, 1)
```

The binary local search is key because the problem has a natural binary structure. For a binary sequence, flipping a bit at position p changes the correlation at every lag k by a computable amount.

Let me think about the binary local search more carefully:

For binary h, corr_full[k] (at index k in the full output) = sum_i h[i] * (1-h[i + shift_k]) where shift_k = k - (n-1).

If we flip h[p] (0→1 or 1→0), how does each correlation change?

If h[p] was 0 and becomes 1:
- For each shift s: h[p] contributes to corr at positions where it appears as h[i] (i=p) or as h[i+s] (i=p-s).
  - As h[i] with i=p: contributes (1-h[p+s]) to corr at shift s (if p+s < n)
  - As h[i+s] with i=p-s: contributes (1-h[p-s]) to corr at shift s (if p-s >= 0)

Wait, this is getting complicated. Let me just compute the effect directly.

Actually, for the practical implementation, I'll just:
1. Compute the full correlation array
2. For each position p, try flipping h[p]
3. Recompute the max (or update it incrementally)
4. Accept the flip if it reduces the max

The incremental update is:
- If h[p] changes from 0 to 1:
  - For each shift s (in full correlation index k, shift = k-(n-1)):
    - If p is in range as first arg: corr[k] changes by (1 - h[p+shift]) → but h[p+shift] might also change... no, we're only changing h[p].
    
Let me define it more carefully. Let the full correlation at index k be:
C[k] = sum_i h[i] * v[i + k - (n-1)] where v = 1-h

So C[k] = sum_i h[i] * (1 - h[i + k - (n-1)])

If we change h[p] from 0 to 1:
- Terms where h[i] = h[p]: i = p, contributes (1 - h[p + k - (n-1)]) to C[k] (if 0 ≤ p+k-(n-1) ≤ n-1)
- Terms where h[i + k - (n-1)] = h[p]: i + k - (n-1) = p, i = p - k + (n-1), contributes h[p-k+(n-1)] * 1 to C[k]... wait, this is the v part.

Actually, C[k] = sum_i a[i] * b[i + k - (n-1)] where a = h, b = 1-h.

If a[p] changes by δ (from 0 to 1, δ=+1) and b[p] changes by -δ (from 1 to 0):
ΔC[k] = δ * b[p + k - (n-1)] + a[p + k - (n-1)] * (-δ)
       = δ * (b[p + k - (n-1)] - a[p + k - (n-1)])
       = δ * ((1 - h[p + k - (n-1)]) - h[p + k - (n-1)])
       = δ * (1 - 2*h[p + k - (n-1)])

(valid when 0 ≤ p + k - (n-1) ≤ n-1)

This is a nice formula! For a 0→1 flip (δ=+1):
ΔC[k] = 1 - 2*h[p + k - (n-1)] (if the index is valid)

This is +1 if h[p+k-(n-1)] = 0, and -1 if h[p+k-(n-1)] = 1.

So flipping h[p] from 0 to 1 increases C[k] by 1 where h[p+k-(n-1)]=0 and decreases it by 1 where h[p+k-(n-1)]=1.

The net effect on C[k] is: (number of 0s in the "window" centered at p shifted by k) - (number of 1s in that window).

For the local search, I want to find the flip that most reduces the max C[k]. This is a bit tricky because the max is a non-smooth function.

A simpler approach: focus on the lag(s) that currently have the maximum correlation, and try flips that reduce those specific correlations.

Wait, I realize the local search might be slow because for each position p, I'm computing the flip effect which involves a vector of length 2n-1. For n=80, that's 159 elements per flip, and 80 positions, so about 12720 operations per sweep. That's fast.

But the issue is that after each accepted flip, I need to recheck all positions. Let me use a greedy approach: in each sweep, find the single best flip (the one that most reduces the max), apply it, and repeat.

Actually, a simpler and often effective approach: for each position, compute the new max if we flip it, and pick the flip that gives the lowest new max. Apply it. Repeat until no improvement.

Let me also think about the continuous optimization more carefully. The key advantage of continuous values is that we can "smooth out" the correlations. For example, if h[p] = 0.5, it contributes half as much as h[p] = 1 to the correlations.

For the continuous case, the objective is:
f(h) = max_k C[k] * dx where C[k] = sum_i h[i] * (1-h[i+k-(n-1)])

This is the max of bilinear functions. The gradient is well-defined except at points where two C[k] values are tied for the max.

I'll use a subgradient method: pick the active constraint (argmax), compute its gradient, take a step.

For the constraint sum(h) = n/2, I'll use a Lagrange multiplier or projection.

Let me write a more complete implementation:

```python
import numpy as np
import scipy.optimize as optimize
import time

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    return np.max(corr) * dx

def full_corr(h):
    return np.correlate(h, 1.0 - h, mode='full')

def gradient_active(h, k):
    """Gradient of C[k] (the k-th element of full correlation) w.r.t. h."""
    n = len(h)
    shift = k - (n - 1)
    grad = np.zeros(n)
    if shift >= 0:
        # C[k] = sum_{i=0}^{n-1-shift} h[i+shift] * (1-h[i])
        # d/dh[m] = (1-h[m-shift]) for m in [shift, n-1] (from first factor)
        #           - h[m-shift] for m in [0, n-1-shift] (from second factor)
        if shift < n:
            grad[shift:] += (1.0 - h[:n-shift])
            grad[:n-shift] -= h[shift:]
    else:
        j = -shift
        # C[k] = sum_{i=0}^{n-1-j} h[i] * (1-h[i+j])
        # d/dh[m] = (1-h[m+j]) for m in [0, n-1-j]
        #           - h[m-j] for m in [j, n-1]
        if j < n:
            grad[:n-j] += (1.0 - h[j:])
            grad[j:] -= h[:n-j]
    return grad

def project_onto_simplex(h, target_sum):
    """Project h onto {h: sum(h) = target_sum, 0 <= h <= 1}."""
    h = h.copy()
    # Iterate: clip and adjust
    for _ in range(100):
        h = np.clip(h, 0, 1)
        diff = target_sum - h.sum()
        if abs(diff) < 1e-12:
            break
        if diff > 0:
            mask = h < 1.0
            if not mask.any():
                break
            h[mask] += diff / mask.sum()
        else:
            mask = h > 0.0
            if not mask.any():
                break
            h[mask] += diff / mask.sum()
    h = np.clip(h, 0, 1)
    # Final adjustment
    diff = target_sum - h.sum()
    if abs(diff) > 1e-10:
        # Distribute among non-saturated values
        mask = (h > 0.01) & (h < 0.99)
        if mask.any():
            h[mask] += diff / mask.sum()
            h = np.clip(h, 0, 1)
    return h
```

Key idea: The problem is min max_k C_k(h) subject to sum(h) = n/2, 0 ≤ h ≤ 1.

This is a min-max problem. We can use:
1. **Bisection on t**: Check if there exists h with C_k(h) ≤ t for all k. This is a feasibility problem with bilinear constraints, which is non-convex.
2. **Direct optimization**: Minimize max_k C_k(h) using subgradient methods.
3. **Alternating direction method**: Alternate between optimizing h and updating the max.

For option 2, the subgradient method would be:
- At each iteration, find k* = argmax C_k(h)
- Compute gradient of C_{k*}(h)
- Take a step in the negative gradient direction
- Project onto the constraint set

- Replace max with a soft-max: f_β(h) = (1/β) * log(sum_k exp(β * C_k(h) / dx))

- Decrease β over time

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    return np.max(corr) * dx

def full_corr(h):
    return np.correlate(h, 1.0 - h, mode='full')

def gradient_of_corr_k(h, k):
    n = len(h)
    shift = k - (n - 1)
    grad = np.zeros(n)
    if shift >= 0:
        if shift < n:
            grad[shift:] += (1.0 - h[:n-shift])
            grad[:n-shift] -= h[shift:]
    else:
        j = -shift
        if j < n:
            grad[:n-j] += (1.0 - h[j:])
            grad[j:] -= h[:n-j]
    return grad

def project(h, target_sum):
    h = np.clip(h, 0, 1)
    for _ in range(200):

        if abs(diff) < 1e-12:
            break

            mask = h > 0.0
