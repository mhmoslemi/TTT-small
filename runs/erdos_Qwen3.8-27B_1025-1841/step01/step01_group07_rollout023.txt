M-sequences of length 2^m - 1 have the property that their autocorrelation is -1 at all non-zero lags. But our problem is slightly different (cross-correlation with complement).

Let me convert: for a binary sequence s ∈ {±1}^n (where s[i] = 2h[i]-1), the autocorrelation at lag m is:
R(m) = sum_i s[i]*s[i+m]

For an m-sequence of length n = 2^m - 1, R(0) = n and R(m) = -1 for all m ≠ 0.

Now, our conv[k] (in terms of s):
conv[k] = sum_i h[i]*(1-h)[n-1-k+i]
= sum_i (s[i]+1)/2 * (1-s[n-1-k+i])/2
= (1/4) sum_i (s[i]+1)(1-s[n-1-k+i])
= (1/4) sum_i [s[i] - s[i]*s[n-1-k+i] + 1 - s[n-1-k+i]]

Let m = n-1-k:
= (1/4) sum_i [s[i] - s[i]*s[i+m] + 1 - s[i+m]]

The first and last terms: sum_i s[i] - sum_i s[i+m] = sum_i s[i] - sum_{j=m}^{m+n-1-valid} s[j]
For the full overlap (when valid), this is approximately 0 if the sequence is balanced.

The middle term: -sum_i s[i]*s[i+m] = -R(m) (autocorrelation at lag m)

So conv[k] ≈ (1/4)[0 - R(m) + count] where count is the number of valid terms.

For a balanced sequence (sum s = 0):
conv[k] ≈ (1/4)[count - R(m)]

Actually, for the swap-based approach, when I swap h[i] (1→0) and h[j] (0→1):
The change in conv[k] for each k can be computed analytically.

conv[k] = sum_t h[t] * (1-h)[n-1-k+t] (for valid t)

After swap: h[i] becomes 0, h[j] becomes 1.
Change in conv[k]:
- From h[i]: was h[i]*(1-h)[n-1-k+i] = 1*(1-h)[n-1-k+i], now 0. Change: -(1-h)[n-1-k+i]
- From h[j]: was h[j]*(1-h)[n-1-k+j] = 0, now 1*(1-h)[n-1-k+j]. Change: +(1-h)[n-1-k+j]
- From (1-h) terms: (1-h)[n-1-k+t] changes when n-1-k+t = i or j, i.e., t = k+1-n+i or t = k+1-n+j
  - When (1-h)[i] changes from 0 to 1 (since h[i] was 1, now 0): (1-h) changes, affecting conv[k] when n-1-k+t = i, i.e., t = k+1-n+i
    Change: h[k+1-n+i] * (1-1) - h[k+1-n+i] * (1-0) = -h[k+1-n+i] (if valid)
    Wait, (1-h) goes from 0 to 1, so the product h[t]*(1-h)[...] goes from 0 to h[t]. Change: +h[t] where t = k+1-n+i.
  - When (1-h)[j] changes from 1 to 0 (since h[j] was 0, now 1): (1-h) changes, affecting conv[k] when n-1-k+t = j, i.e., t = k+1-n+j
    Change: h[t]*(1-0) - h[t]*(1-1) = +h[t]... wait, (1-h) goes from 1 to 0, so product goes from h[t] to 0. Change: -h[t] where t = k+1-n+j.

So total change in conv[k]:
= -(1-h_old)[n-1-k+i] + (1-h_old)[n-1-k+j] + h_old[k+1-n+i] - h_old[k+1-n+j]
(only for valid indices)

This is O(1) per k, so O(n) to compute the full change vector. Then we find the max.

But we still need O(n) to compute the new max. Unless we maintain the conv array and update it in O(n), then find the max in O(n). Total O(n) per step.

    return np.correlate(h, 1-h, mode='full')

If h[i] is allowed to be in [0,1], the objective is:
C₅ = max_k [sum_t h[t] * (1-h[n-1-k+t])] * (2/n)

This is a quadratic function of h (product of pairs of h values). The constraint is sum(h) = n/2, 0 ≤ h ≤ 1.

For a fixed k, the inner expression is:
f_k(h) = sum_t h[t] - sum_t h[t]*h[n-1-k+t] (for valid t)

The first term is linear (depends on which t are in the valid range), the second is a quadratic form.

The max of these over k is a piecewise-quadratic function. Minimizing it is non-convex.

However, there's a simple observation: if we take a binary solution h* and perturb it slightly (h[i] = h*[i] + ε*t[i] for small ε), the change in C₅ is:
dC₅/dε ≈ max_k [sum_t (h*[t]*t[n-1-k+t] + h*[n-1-k+t]*t[t]) ] * (2/n)
(ignoring second-order terms)

This is a linear function of t (for the k that achieves the max). So we could try to find a direction t that decreases all the active constraints simultaneously. This is essentially a linear programming approach.
