### 1. Discretisation choices

*Select a small set of grid sizes.*  
The bound is insensitive to the exact N (it approximates the true continuous constant), but a finer grid gives more flexibility while keeping evaluation cheap.

```
grid_sizes = [120, 160, 200]          # 2/N = dx ≥ 0.01

For each N we keep the exact constraint  

```

The algorithm will be executed on each N in turn; the best final bound among them is returned.

### 2. Core mathematical objects

*Correlation vector*  
Given a candidate `h` (length N), compute the full correlation

```
c = correlate(h, 1‑h, mode='full')      # length 2·N‑1
c *= 2/N
```

The i‑th element corresponds to shift `k = (i‑(N‑1))*dx`.  
The objective is `max(c)`.

*Smoothed max* – replace the hard max by a differentiable “soft‑max”

```
Sα(c) = (1/α)·log( Σ_i exp(α·c_i) )
```

For large α, `Sα(c) → max(c)`.  
Choosing a modest α (e.g. α≈5) yields a smooth landscape; α is increased gradually (annealing) so that the descent first follows a gently smoothed surface and later focuses on the true maximum.

### 3. Projection onto the feasible set

The feasible set is the intersection of the hyper‑cube `[0,1]^N` with the affine hyperplane `∑h = N/2`.  
Projecting a possibly infeasible vector `z` onto this set can be done in two steps:

1. **Clip** to `[0,1]`: `z ← np.clip(z,0,1)`.
2. **Simplex‑with‑upper‑bound projection**:  
   Solve `min ||h‑z||²` s.t. `0 ≤ h_i ≤ 1` and `∑h = N/2`.  
   A standard algorithm (bisection on a Lagrange multiplier with clipping) runs in `O(N log N)` and is trivial to implement.

All iterative updates (gradient steps, DE mutations, etc.) are followed by this projection, guaranteeing feasibility at every iteration.

### 5. Deterministic refinement – Projected Gradient Descent with annealed α

For each promising vector from DE (including the best one), perform a deterministic optimisation:

1. **Initialize** `h₀` = projected candidate.
2. **Loop** while time remains in the refinement window (next 30 % of total budget):

   * Form the soft‑max weights

### 6. Binary projection and high‑resolution local search

The continuous optimum may contain fractional entries that are difficult to realise with a step‑function.  
We therefore **binarise**:

1. **Threshold** the continuous solution at 0.5 → binary vector `b ∈ {0,1}^N`.  
   The sum may deviate from `N/2`.  
2. **Repair** by swapping bits: if `∑b > N/2`, flip the smallest‑value ones to zero; if `< N/2`, flip the largest‑value zeros to one. After this repair we obtain a *feasible binary* start `b₀`.

Now perform an intensive **swap‑based local search**:

* **Move** – select a random pair `(i,j)` with `b_i=1, b_j=0` and exchange them.
* **Evaluation** – the current correlation vector `c` and the current maximum `C5` are maintained.
  When a swap occurs only the entries of `c` that involve indices `i` or `j` change.  
  For each shift `k` we can update `c_k` in constant time:
  - If `i ≤ N‑k‑1` the term `h_i` appears in the linear part of `c_k`; swapping changes it from 1 to 0 (or vice‑versa).  
  - If `i+k < N` the product term `h_i·h_{i+k}` changes similarly, and the same for `j`.  
  Consequently the whole update costs **O(N)** per swap—a cheap operation for N ≤ 200.
* **Acceptance** – accept the swap if it *strictly* reduces the current maximum; otherwise reject.  
  Occasionally (probability 1 % / iteration) accept a worsening move to escape plateaus (a tiny simulated‑annealing flavour).
* **Best‑ever tracking** – keep the globally best binary vector found across all restarts.

The binary search is allocated the remaining **40 %** of the time budget (≈240 s).  
We run many independent restarts (e.g. 20 of them) each starting from a different binaryisation of a DE/gradient solution (or from a completely random feasible binary vector).  
Because the per‑move cost is low, we can afford **hundreds of thousands** of swaps per restart.

### 7. Optional MILP verification / improvement (small N)

For the *smallest* grid size (e.g. N = 120) we can formulate a **feasibility MILP** to prove that a given target bound `t` is attainable:

*Variables*  
`h_i ∈ {0,1}` (binary), auxiliary products `y_{i,k} ∈ {0,1}` for each overlapping pair (`i,i+k`).  
*Constraints*  
```
∑_i h_i = N/2
for every shift k (1 ≤ k ≤ N‑1):
    Σ_i y_{i,k} ≥ L_k - (t·N/2)        # L_k = number of overlapping positions = N‑k
    y_{i,k} ≤ h_i
    y_{i,k} ≤ h_{i+k}
    y_{i,k} ≥ h_i + h_{i+k} – 1
```
The right‑hand side derives from the definition  
`c_k = (2/N)·[ L_k·0.5  – Σ_i y_{i,k} ] ≤ t`.  
We binary‑search on `t` (starting from the best bound already found) and ask the MILP solver (CBC via CVXPY) for feasibility.  
If feasible, we obtain a *provably optimal* binary vector for that N, which can be up‑scaled to the larger grids by interpolation.  
Because the MILP size grows as O(N²), we limit this step to N ≤ 120 and allocate at most **30 s**; if it finishes early we keep its solution, otherwise we fall back to the swap‑based result.
