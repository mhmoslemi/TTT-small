**1.  Re‑formulation of the objective**

The quantity to be minimised is  

\[
C_5(h)=\max_{k}\int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx .
\]

Because \(\int_0^2h(x)\,dx=1\) is fixed,  

\[
C_5(h)=1-\min_{k}\int_0^2 h(x)h(x+k)\,dx .
\]

Hence the problem is *maximise the smallest autocorrelation* of \(h\).  
Denote the discrete version (step‑function with spacing \(\Delta x=2/N\)) by  

\[
g_k(h)=\sum_{i=0}^{N-1}h_i\,h_{i+k},\qquad k=-(N-1),\dots ,N-1 .
\]

The target becomes  

\[
\max_h \; \min_k g_k(h) \qquad\text{s.t.}\qquad
0\le h_i\le 1,\; \sum_i h_i = N/2 .
\]

This is a non‑convex quadratic max‑min problem.  The key insight is that the *worst* shift
\(k^\star=\arg\min_k g_k\) tells us exactly where the autocorrelation is lacking; any
modification that increases \(g_{k^\star}\) can only improve (or keep) the objective.

**2.  High‑level algorithmic pipeline**

The pipeline consists of three orthogonal modules that are run sequentially
(their runtimes are adjusted to respect the 600 s budget):

| Stage | Goal | Core technique | Why it is different |
|------|------|----------------|---------------------|
| A – Binary Max‑Min Search | Obtain a high‑quality 0/1 solution (exact sum constraint) | Targeted pairwise swaps that raise the autocorrelation of the current worst shift; Simulated‑annealing acceptance to escape shallow local minima | Instead of blind random moves, each move directly attacks the bottleneck shift. |
| B – Smooth‑gradient ascent on the continuous problem | Refine the binary solution into a possibly fractional one that smooths the autocorrelation curve | Replace the non‑smooth max by a soft‑max (log‑sum‑exp) surrogate, compute analytical gradients of the surrogate, and perform projected gradient ascent (or L‑BFGS‑B) with box‑ and equality‑projections | Uses first‑order information, which the previous code never exploited. |

The best construction from all three stages is kept as the final answer.

**3.  Stage A – Targeted binary swap hill‑climb**

*Representation* – a NumPy integer vector `h ∈ {0,1}^N` with exactly `N/2` ones.
*Initialisation* – draw a random permutation of the indices, set the first `N/2` to 1; also create a deterministic seed from `initial_h_values` (threshold at 0.5).

*Iteration* (repeat until time expires or a patience counter reaches a tolerance):

1. Compute the full autocorrelation vector `g = np.correlate(h, h, mode='full')`.
2. Find the *worst* shift `k* = argmin(g)`.  The corresponding index in the correlation array is `idx = k* + N - 1`.
3. Build two candidate index sets:
   * `A = { i | 0≤i<N, 0≤i+k*<N, h_i = 1, h_{i+k*}=0 }` – a 1 that does **not** meet a 1 after the shift.
   * `B = { j | 0≤j<N, 0≤j+k*<N, h_j = 0, h_{j+k*}=1 }` – a 0 that **does** meet a 1 after the shift.
4. If both sets are non‑empty, draw a modest random sample (e.g. up to 30 elements from each) and evaluate every cross‑pair `(i∈A, j∈B)`:
   * Swapping `h_i` and `h_j` changes only those correlation entries that involve positions `i` or `j`.  For a vector of length ≤200 the full recomputation (`c5_of`) is still cheap; use it to obtain the new objective value.
   * Keep the swap with the largest reduction in `C_5`.  If a strict improvement is found, perform the swap, reset the *no‑improvement* counter and continue.
5. If no improving swap exists (or one of the sets is empty), perform a *exploratory* move:
   * Randomly pick a 1‑index and a 0‑index and swap them (cost‑free, sum stays correct).
   * Accept the move with a small probability `exp(-(ΔC)/T)` where `ΔC` is the increase and `T` is a temperature that decays slowly (simulated‑annealing schedule).  This allows the algorithm to cross plateaus.
6. Update the best‑ever solution seen so far.

*Complexity*: each iteration needs one correlation (≈ N² operations) and at most a few hundred cheap trial swaps; with `N=140` an iteration takes < 0.02 s, so thousands of iterations fit comfortably in a few minutes.

**4.  Stage B – Smooth‑max surrogate + projected gradient ascent**

The exact max is replaced by a smooth approximation:

\[
\Phi_\beta(h)=\frac{1}{\beta}\log\Bigl( \sum_k \exp\bigl(\beta\,c_k(h)\bigr)\Bigr),\qquad 
c_k(h)=\Delta x\sum_i h_i\bigl(1-h_{i+k}\bigr),
\]

with a temperature‑like parameter `β`.  As `β→∞`, `Φ_β → max_k c_k`.  For moderate `β` (e.g. 15–30) the function is differentiable and its gradient can be written analytically:

\[
\frac{\partial \Phi_\beta}{\partial h_j}
=
\frac{\sum_k w_k\, (1-2h_{j+k})}{\sum_k w_k},
\quad 
w_k = \exp\bigl(\beta\,c_k(h)\bigr).
\]

These gradients are cheap to compute because they are linear combinations of shifted vectors; the whole gradient can be obtained with a few FFT‑based convolutions or directly with `np.correlate`.

*Algorithm* (projected gradient ascent; can be upgraded to L‑BFGS‑B using SciPy):

1. **Start** from the best binary vector obtained in Stage A, cast to float.
2. **Loop** while time permits:
   * Compute `c = np.correlate(h, 1-h, mode='full')*Δx`.
   * Build the weight vector `w = np.exp(β * c)` (use `β` large enough that the weighted sum concentrates on the worst shifts).
   * Compute the gradient `g` using the formula above (implemented by two convolutions: one with `w` and one with `w` shifted).
   * **Projection step** – we need to stay inside the box `[0,1]^N` **and** preserve the total mass `∑h = N/2`:
     * First take an unconstrained step `h' = h + η g` (with step size `η`).
     * Clip `h'` to `[0,1]`.
     * Enforce the equality constraint by a simple *affine projection*:  
       `h'' = h' - (∑h' - N/2)/N * 1`.  
       If clipping created new violations, iterate a few times (the dimension is tiny so a couple of washes suffice).  This yields a feasible `h`.
   * Evaluate `C_5` of `h''`.  If it improved, keep `h = h''` and possibly increase `η`; otherwise reduce `η` (e.g. multiply by 0.7) and retry.
   * **β schedule** – start with a moderate value (β≈10) to obtain a smooth landscape, then increase it gradually (multiply by 1.2 every few seconds) so that the optimizer focuses on the true max.
3. Keep the best feasible vector encountered.

Because the gradient directly pushes the autocorrelation of the current worst shift upward, the method converges far faster than blind random moves.

**5.  Stage C – Global optimisation in a low‑dimensional block space**

Many excellent constructions are “banded”: the function stays almost constant on long sub‑intervals and jumps only a few times.  To explore this family efficiently we parameterise \(h\) by \(B\) constant blocks:

* Let \(B\) be a small integer (e.g. 8 – 12).  
* Block lengths are equal (or differ by at most one to fill the domain exactly).  
* The block heights \(\mathbf{u}=(u_1,\dots,u_B)\) satisfy \(0\le u_b\le1\) and the weighted sum constraint  

  \[
  \sum_{b=1}^{B} \ell_b\,u_b = \frac{N}{2},
  \qquad \ell_b\approx N/B .
  \]

  This is a **bounded simplex** in \(\mathbb{R}^B\).

*Construction from \(\mathbf{u}\)* – expand each block to a constant segment of length `ℓ_b`, giving a full length‑\(N\) vector `h`.

*Optimization* – use `scipy.optimize.differential_evolution` (DE) on the *unconstrained* variables \(\mathbf{x}\in[0,1]^B\).  Inside the DE objective:

  1. Project \(\mathbf{x}\) onto the bounded simplex (efficient water‑filling algorithm: clamp to [0,1], then distribute the surplus/deficit over non‑clamped coordinates iteratively).
  2. Build the full `h` from the projected heights.
  3. Return `c5_of(h)` (the quantity to be minimised).

DE explores globally because the dimension \(B\) is tiny;  a population of size `10*B` and `max_iter≈200` yields only a few thousand objective evaluations, well within the remaining time budget.

After DE finishes, take the best block‑vector, expand to `h` and feed it to Stage B for a final gradient polish (the gradient step can climb out of the block‑space while preserving the discovered macroscopic pattern).
