- To accelerate: Instead of recomputing full correlation each time, we can compute Δc efficiently.

Let's attempt to compute Δc for a swap of bits at positions p (1→0) and q (0→1). Let's define h' = h with these swapped. For each shift s, the change in correlation c_s = sum_i h_i (1 - h_{i+s}) changes only for indices i where i is p or q or i-s is p or q (i.e., i = p or q or i = p - s or i = q - s). Actually each term h_i involves product with 1-h_{i+s}. Changing values at two positions will affect terms where either the left index or the right index is one of the swapped positions.

Complex but doable: O(N) update for all s parity, which might be easier than O(N log N) compute from scratch. N=200, O(N) per proposal is fine. Actually O(N) per propose would be 200 operations vs FFT O(N log N) ~ 200*8=1600. So we can implement incremental update.

Design:

Compute arrays for each shift s: c_s = sum_{i=0}^{N-s-1} h[i] - sum_{i=0}^{N-s-1} h[i] * h[i+s].

When swapping values at positions p and q (p<q), we need to update for each shift s (0 ≤ s ≤ N-1). Because contributions at shift s involve pairs (i,i+s). Which pairs involve p or q as either i or i+s.

Thus:

- For each s, if 0 ≤ p ≤ N-s-1 => term includes h[p] in sum_i h[i]; also term includes product h[p] * h[p+s] if p+s < N.

- Similarly if 0 ≤ p - s ≤ N-s-1 => i = p - s yields term includes product h[p - s] * h[p] in the product sum.

- Same for q.

Thus O(N) update: for s in [0,N-1], compute contributions delta_c_s due to changes at p and q. But we need to recompute c array after each swap for max.
