### 1.  Problem reformulation

For a discretised step‑function `h ∈ ℝ^N` (step size `dx = 2/N`) the overlap integral used by the judge is  

```
O_k(h) = ∫_0^2 h(x)·(1‑h(x+k))dx
       = ( Σ_i h_i·(1‑h_{i+k}) )·dx                (zero‑padding outside [0,2])
```

Let  

```
r_k(h) = Σ_i h_i·h_{i+k}          (autocorrelation at lag k)
```

Because `Σ_i h_i = N/2` (the integral constraint) we have  

```
O_k(h) = ( N/2 – r_k(h) )·dx = 1 – 2·r_k(h)/N .
```

Hence  

```
C5(h) = max_k O_k(h) = 1 – 2·min_k r_k(h)/N .
```

**Goal** – make the *smallest* autocorrelation as large as possible (equivalently minimise `C5`).  
If we enforce `r_k ≥ t` for every shift `k` the objective becomes the linear maximise‑`t` problem

```
maximise   t
subject to r_k(h) ≥ t   ∀k,
           Σ_i h_i = N/2,
           0 ≤ h_i ≤ 1 .
```

The quadratic terms `h_i·h_{i+k}` prevent convexity.  We therefore **linearise** them by introducing binary products, turning the whole model into a mixed‑integer linear program (MILP).  After solving the MILP we can optionally improve the binary solution by a fast continuous local search and by a low‑dimensional evolutionary search.

The strategy below is **fundamentally different** from the earlier differential‑evolution / simulated‑annealing pipeline: it builds an *exact* optimisation model for a *binary* version of the problem, solves it with an MILP solver, and then refines the result with deterministic pairwise moves and a small‑parameter CMA‑ES search.

--------------------------------------------------------------------
### 2.  MILP formulation (binary version)

1. **Decision variables**
   * `h_i ∈ {0,1}`  for `i = 0,…,N‑1` – the step‑function values.
   * `q_{i,k} ∈ {0,1}`  for every admissible pair `(i,k)` with `i+k < N`.  
     `q_{i,k}` shall represent the product `h_i·h_{i+k}`.
   * `t ∈ ℤ , t ≥ 0`  – the lower bound on every autocorrelation value.

2. **Linearisation (McCormick) constraints** – for each pair `(i,k)` :

   ```
   q_{i,k} ≤ h_i
   q_{i,k} ≤ h_{i+k}
   q_{i,k} ≥ h_i + h_{i+k} – 1
   ```

   These three constraints are necessary and sufficient for binary variables.

3. **Autocorrelation aggregates**  

   For each lag `k = 0,…,N‑1` define  

   ```
   r_k = Σ_{i=0}^{N‑1‑k} q_{i,k}            (integer)
   ```

   Note that `r_0 = Σ_i h_i = N/2` automatically because `q_{i,0}=h_i`.

4. **Min‑autocorrelation enforcement**  

   ```
   r_k ≥ t   for all k = 1,…,N‑1 .
   ```

   (The `k=0` constraint is redundant, the value is fixed.)

5. **Mass constraint**  

   ```
   Σ_i h_i = N/2 .
   ```

6. **Box constraints** – already implied by the binary nature of `h_i`.

7. **Objective** – maximise `t`.  
   The optimal value `t*` yields a final bound  

   ```
   C5 = 1 – 2·t*/N .
   ```

8. **Symmetry‑breaking (optional, speeds up the solver)**  
   * Fix `h_0 = 1` and `h_1 = 0` – any optimal solution can be rotated / reflected to satisfy it.
   * Order the first `N/2` variables non‑increasingly (e.g. `h_i ≥ h_{i+1}` for `i < N/2`) – also a linear constraint.

--------------------------------------------------------------------
### 3.  Solving the MILP

* **Problem size** – choose `N` modest enough for a full MILP but still fine enough to give a tight bound.  
  A good trade‑off is `N = 100` (≈ 5 000 product variables, ≈ 5 000 constraints).  
* **Solver** – use `cvxpy` with an open‑source MILP backend that is guaranteed to be present, e.g. `GLPK_MI` or `CBC`.  
* **Time budget** – allocate **≈ 30 %** of the total runtime to the MILP (`budget_milp = 0.3·budget_s`).  
  Pass the remaining time to the solver via its `maxTime` / `TimeLimit` parameter (if available).  
* **Result handling**  
  * If the solver finishes optimally, keep the binary vector `h_bin` and the integer `t*`.  
  * If the solver stops early (time‑out or reaches a feasible solution), extract the *best incumbent* (`h_bin`, `t_inc`).   The incumbent still satisfies all constraints, only `t` may be sub‑optimal – it is acceptable as a starting point for the next phase.

--------------------------------------------------------------------
### 4.  Fast binary local improvement (Phase 1)

Even when the MILP yields a high‐quality binary vector, a simple deterministic local search can often raise `t` a few more units.

1. **Data structures**  
   * Store the current autocorrelation vector `r = np.convolve(h, h, mode='full')` (full convolution gives all lags).  
   * Keep `t_cur = min_{k>0} r_k`.

2. **Pairwise exchange move** – select a zero‐position `i` (where `h_i = 0`) and a one‑position `j` (`h_j = 1`).  
   * Define `Δ = +1` at `i` and `Δ = –1` at `j`.  
   * The effect on each lag `k` is linear and can be updated in O(N):  

   ```
   Δr_k = Δ·( h_{i+k} + h_{i‑k} )   +   (‑Δ)·( h_{j+k} + h_{j‑k} )
   ```

   (terms with out‑of‑range indices are ignored).

3. **Greedy improvement**  
   * For every candidate pair `(i,j)` compute the *new* minimal autocorrelation `t_new = min_k (r_k + Δr_k)`.  
   * Pick the pair that maximises `t_new`.  
   * If `t_new > t_cur` execute the swap, update `h`, `r`, and `t_cur`.  
   * Repeat until a full sweep finds no improving pair.

4. **Escaping local plateaus**  
   * After `L_no_improve` unsuccessful sweeps, perform a *random* swap (choose any `(i,j)`) and continue.  
   * Keep the best solution seen during the whole phase.
