**1.  Reformulation – a smooth surrogate for the max**

For a discretisation with `N` points (`dx = 2/N`) we have  

```
C5(h) = max_s   C_s ,   C_s = dx·∑_i h[i]·(1 – h[i+s]) .
```

The max is non‑smooth, which makes random walks inefficient.  Replace it by a
parameterised smooth approximation (log‑sum‑exp, also called “soft‑max”)  

```
F_ε(h) = ε·log ( ∑_s exp( C_s / ε ) ) .
```

* When ε is large the landscape is very smooth (all shifts contribute),
* When ε → 0, `F_ε → max_s C_s = C5`.

Optimising `F_ε` for a decreasing sequence `ε_1 > ε_2 > … > ε_T` provides a
continuation (homotopy) that guides the iterates toward a good local minimum of
the original objective.

**2.  Analytic gradient of the smooth surrogate**

Define the (unscaled) correlation  

```
c_s = ∑_i h[i]·(1 – h[i+s])            (zero padding outside [0,N) )
```

so `C_s = dx·c_s`.  The gradient of a single term (for a fixed shift `s`) is

```
∂c_s/∂h[k] = 1 – h[k+s] – h[k–s]     (missing terms are omitted)
```

Multiplying by `dx` gives the gradient of `C_s`.

For the smooth surrogate

```
w_s = exp( C_s / ε ) / ∑_t exp( C_t / ε )      (soft‑max weights)
∇F_ε = Σ_s w_s · ∇C_s .
```

Thus one evaluation of `F_ε` and `∇F_ε` consists of:

* a full correlation `c = np.correlate(h, 1‑h, mode='full')`,
* scaling by `dx`,
* forming the soft‑max weights (subtract the maximal `C_s` first for numerical stability),
* a **single** vectorised pass that builds the gradient using the two shifted
  copies of `h` (the same code that yields the sub‑gradient for a single shift,
  but now linearly combined with the weights `w_s`).

Both the value and the gradient are obtained in **O(N²)** time, the same cost
as the original evaluation.

**3.  Feasibility – box constraints and exact sum**

*Box bounds* `[0,1]` are provided directly to a bound‑constrained optimiser
(e.g. L‑BFGS‑B).

*Equality constraint* `∑_i h[i] = N/2` is enforced **after each optimisation
iteration** by an Euclidean projection onto the intersection of the box and the
hyperplane.  The projection is the “water‑filling’’ operation:

```
find λ such that   Σ_i clip( v_i + λ , 0 , 1 ) = N/2 .
```

`F(λ) = Σ_i clip(v_i+λ,0,1)` is monotone, with `F(−∞)=0` and `F(+∞)=N`,
so a 50‑iteration binary search for λ yields the projection to machine
precision.  A tiny redistribution on the free (non‑bound) entries removes the
last rounding error, guaranteeing the sum **exactly** equals `N/2`.

**4.  Optimisation routine – continuation + quasi‑Newton**

*Outer continuation*: a list of decreasing ε’s, e.g.

```
ε ∈ [ 0.10 , 0.05 , 0.02 , 0.01 , 0.005 , 0.002 , 0.001 ] .
```

*Inner optimiser*: for the current ε we run a bound‑constrained L‑BFGS‑B
(maximum of 150 iterations, early stop when the norm of the projected gradient
drops below 1e‑6).  After each L‑BFGS step we project the iterate onto the
feasibility set.  When the inner optimiser terminates we **re‑project** once
more to flush any tiny sum violation, then pass the result as the start vector
for the next, smaller ε.

Because `F_ε` is smooth, L‑BFGS‑B uses curvature information and typically needs
far fewer iterations than a plain simulated annealing.  The continuation
strategy prevents the optimiser from being trapped in the rugged landscape that
appears when ε is tiny.

**5.  Diversity – multi‑start with problem‑specific seeds**

* **Uniform seed**: `h = 0.5·1_N` (satisfies the sum exactly).
* **Two‑peak seed** – high value `u≈0.9` on the two outer intervals of total

* **Random continuous seeds** – draw `h∼U[0,1]` and renormalise.

**6.  Final polishing – max‑based sub‑gradient descent**

The continuation stops at ε = 0.001, which already yields a vector extremely
close to a local optimum of the original problem, but the soft‑max still
averages over many shifts.  A last deterministic phase refines the solution
directly on the nonsmooth objective:

```
repeat
    s* = argmax C_s   (worst shift)
    g  = dx·( 1 – shift_left(h,s*) – shift_right(h,s*) )
    h' = project( h – η·g )    # η small, e.g. 0.02 → 0.05
    if C5(h') < C5(h): h = h'
until time runs out or improvement < 1e‑7
```

Only a few hundred sub‑gradient steps are necessary; each step costs the same

**8.  Expected behaviour and failure‑mode handling**

* *Stagnation on a bad local minimum*: mitigated by multi‑start and by the

  from shallow traps).
* *Numerical overflow in the soft‑max*: before exponentiation subtract the
  maximal `C_s` (standard log‑sum‑exp trick), keeping the exponentials in a
  safe range.
* *Violation of the sum constraint after L‑BFGS*: the projection step restores
  feasibility; if the optimiser repeatedly pushes the point onto a bound,

* *Excessive runtime*: each correlation is only O(N²) with N = 140 (≈20 k
