### Step 1: Choose discretisation n.

Goal: keep n moderate for speed but enough to capture subtle structure. Past best used n=45. We hypothesize that a larger n (e.g., 120 or 180) gives more flexibility to lower C5. We'll adopt a dynamic scheme: start with n=120 to explore, then upscale to n=240 for final refinement.

### Step 2: Generate initial binary sequence.

Use an "irrational rotation" method to generate a balanced Sturmian word with exactly n/2 ones (or adjust). This gives a good initial low-discrepancy pattern.

Procedure: Choose α = (√5-1)/2 (≈0.618). For i=0..n-1 compute t = (i⋅α) mod 1. Set `h_i = 1 if t < 0.5 else 0`. Count ones; if not exactly n/2, change the smallest excess bits (set to 1 or 0) to reach exactly n/2.

### Step 3: Evaluate overlap vector.

Compute correlation array `c = np.correlate(h, 1 - h, mode='full')`, multiply by `dx = 2/n` to get the actual overlap values `g_s`. The maximum `C5_current = max(g_s)`.

Keep the `g_s` array and its index list.

### Step 4: Local search with targeted swaps.

Define a function `delta_swap(i, j)` that returns the change in each shift value if we swap a 1 at i with a 0 at j.

But we primarily need the new maximum after swap. So we can compute new `g_s` as `g_s + delta_s(i,j)`. We can compute `delta_s` efficiently:

For each shift s, the contribution of position i to `g_s` is:
- if i in overlapping region for s: term = h_i * (1 - h_{i+s}).
When we swap i (currently 1 becomes 0) and j (currently 0 becomes 1), the contributions change:

- At position i (was 1, becomes 0):
   - loss of `+ (1 - h_{i+s})` (since term was 1 * (1 - h_{i+s}))
   - gain of `0` (since new term is 0)
   => delta = - (1 - h_{i+s}) for each s where i in O_s.

- At position i as second factor (i appears as i-s):
   - originally term contributed from some k = i-s: k's term had `h_k * (1 - h_i)`. Since h_i becomes 0, `1 - h_i` changes from 0 to 1. So term for that k changes by `+ h_k` (if k in range).
Thus for each shift s where i-s in range, delta = + h_{i-s}.

Similarly for position j (0→1) we have opposite signs:
- As first factor: `+ (1 - h_{j+s})`
- As second factor: `- h_{j-s}`

Thus total delta for shift s is:

Δ_s(i,j) = - (1 - h_{i+s}) + (h_{i-s}) + (1 - h_{j+s}) - (h_{j-s})   (with indices out of range ignored).

All terms can be evaluated with pre‑computed arrays. However we can compute it on the fly O(1) per shift? Actually each shift requires up to 4 lookups per i/j. Doing this for all s (2n-1) is O(n) per swap. That's acceptable if we evaluate maybe 10k swaps per second with n=200.

Thus algorithm:

- While time left:
   - Determine the current worst shift `s_max` (where `g_s` is maximal).
   - Identify positions i (where h_i = 1) that contribute most to `g_{s_max}`: those with `1 - h_{i+s_max}` large (i.e., h_{i+s_max}=0) because each such i adds 1 to the overlap. Similarly, identify positions j (where h_j = 0) that are “good candidates” to become 1; those where `1 - h_{j+s_max}` is 0 (i.e., h_{j+s_max}=1) so swapping will reduce the overlap. In practice: pick random 1‑positions i with h_{i+s_max}=0 and random 0‑positions j with h_{j+s_max}=1, then compute full delta and accept if improves.
   - Perform the swap if it reduces the maximum overlap (or with some probability to escape).
   - Update `g_s` efficiently: for each s, add Δ_s(i,j) to `g_s`. Store new max.

This approach directly attacks the worst shift and is more focused than generic gradient.

### Step 5: Tabu list and diversification.

To avoid cycling, keep a tabu list of recently swapped pairs (i,j) for e.g., 100 iterations. Do not consider swaps in the tabu list unless they produce a substantial improvement (e.g., >1e‑4 reduction).

If after a given number of steps (e.g., 2000) no improvement occurs, perform a *perturbation*: randomly flip a block of ~5% of bits (maintaining balance) to jump out of a local basin.

### Step 6: Multi‑scale refinement.

After reaching a plateau for `n=120`, upscale:

- Interpolate the binary vector to `n'=240` via duplication: repeat each entry twice (or use linear interpolation then threshold to maintain half ones).  
- Now run the same targeted‑swap local search on the larger grid, starting from this upscaled pattern. Because the pattern already has good correlation at coarse scale, the fine‑scale search can adjust local mismatches and further reduce max overlap.

Optionally repeat with `n=480` if time permits.

### Step 7: Optional continuous polishing.

After the final binary solution is obtained, we may improve slightly by allowing fractional values around the boundaries for a few iterations of projected gradient descent (as earlier but starting from a very good binary vector). Use a tiny step size and stop after a few hundred iterations; this can bring the max overlap a few hundredths down (e.g., 0.3799 → 0.3795). Because the binary solution is already near‑optimal, the continuous improvement will be marginal but could be enough to cross the 0.3807 threshold.

### Step 8: Handling the equality constraint.

All swaps preserve the total number of ones, so the balance constraint is automatically satisfied during the binary search. During the continuous polish stage we will project onto the hyperplane (as described earlier) to maintain the sum exactly.

### Step 9: Algorithmic flow (pseudocode outline):

1. **Set** `budget = budget_s`, start timer.
2. **Choose** base resolution `n0 = 120`.  
3. **Generate** initial balanced Sturmian binary `h0`.  
4. **LocalSwapSearch**(h0, n0, time_limit = 0.5 * budget). Returns best binary `h1` and its `C5_1`.
5. **Upscale** to `n1 = 240` via duplication → `h1_up`.  
6. **LocalSwapSearch**(h1_up, n1, remaining_time) → best `h2`, `C5_2`.  
7. **If** remaining_time > small threshold, run **ContinuousPolish** on `h2` with projected gradient descent for a few hundred iterations.  
8. **Return** best vector found (binary or continuous) and its `C5` from `evaluate_erdos_solution`.

All functions are implemented with pure NumPy and simple loops; the core swap evaluation is O(n) per candidate, allowing >10 000 candidates per second on a single CPU.

### 10. Expected failure modes and mitigation

| Failure mode | Reason | Mitigation |
|--------------|--------|------------|
| Stagnation (no improvement) | The binary landscape may contain deep local minima where any single swap increases the max overlap. | Use block swaps (swap multiple 1‑bits with multiple 0‑bits simultaneously) and random perturbations; also implement a temperature schedule (simulated annealing) allowing occasional uphill moves. |
| Overshoot of max shift after perturbation | Random flips may temporarily raise the max overlap dramatically, wasting time. | Limit perturbation magnitude; after each perturbation, immediately apply a short greedy descent to bring the max back down before resuming normal swaps. |
| Time exhaustion before reaching target | If n is too large, per‑iteration cost grows O(n²) for updating all shifts. | Keep n moderate (≤ 300) and use the O(n) incremental update; also allocate more time to the early coarse stage where improvements are larger. |
| Projection errors after continuous polish | Floating‑point rounding could drift the sum away from exactly n/2. | After each gradient step, apply the exact water‑filling projection; enforce strict clipping after the final projection. |
| Numerical overflow in soft‑max when using large γ (if we use it in any step) | Exponentials may overflow. | Subtract the current maximum before exponentiating (standard log‑sum‑exp trick). |

### 11. Why this approach is materially different

- **Discrete combinatorial focus**: Instead of treating `h` as a continuous vector and using generic NLP solvers, the core search works on *binary* step functions and manipulates them via explicit *swap* operations. This mirrors the original combinatorial nature of the minimum overlap problem.
- **Targeted worst‑shift reduction**: The algorithm explicitly identifies the worst shift and designs moves that reduce its contribution, unlike global gradient methods that treat all shifts uniformly.
- **Multi‑scale upsampling**: Starting from a low‑resolution combinatorial pattern and progressively refining on finer grids exploits hierarchical structure; previous attempts used a fixed resolution.
- **Hybrid discrete‑continuous polishing**: After obtaining an excellent binary configuration, a short projected‑gradient refinement is applied, blending discrete and continuous optimisation in a novel way.
- **Use of Sturmian/irrational‑rotation initialization**: This deterministic number‑theoretic seed is a different starting point from the simple random perturbations used before.

All of these components together form a coherent, mathematically motivated optimization pipeline distinct from the previous SLSQP‑centric methods. The expectation is that by directly attacking the worst shift with targeted swaps and exploiting the balanced‑word structure, we can lower the maximal overlap below the 0.3807 target within the 600‑second budget.
