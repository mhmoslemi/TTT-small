**1.  Problem reformulation**

The quantity to be minimized is  

\[
C_{5}(h)=\max _{k}\int_{0}^{2}h(x)\bigl(1-h(x+k)\bigr)\,dx .
\]

Because  

\[
\int_{0}^{2}h(x)\,dx=1,
\qquad 
\int_{0}^{2}h(x)\bigl(1-h(x+k)\bigr)\,dx
    =1-\int_{0}^{2}h(x)h(x+k)\,dx,
\]

the objective is equivalent to  

\[
\min_{h}\;C_{5}(h)=1-\max_{h}\;\min_{k}\;R_{k}(h),
\qquad
R_{k}(h):=\int_{0}^{2}h(x)h(x+k)\,dx .
\]

Thus we want **maximise the smallest autocorrelation** of the function under the constraints  

* \(0\le h(x)\le1\) for all \(x\);
* \(\int_{0}^{2}h(x)\,dx=1\).

**2.  Discretisation**

Choose a modest even number of points \(N\) (e.g. \(N=128\); any even \(N\le 200\) is acceptable).  
Define a uniform mesh \(x_{i}=i\Delta,\;\Delta=2/N\) and the vector  

\[
\mathbf{h}=(h_{0},\dots ,h_{N-1})^{\!\top},\qquad
h_{i}\in[0,1],\qquad
\sum_{i=0}^{N-1}h_{i}=N/2. 
\]

For a shift \(k\in\{-N+1,\dots ,N-1\}\) the discrete autocorrelation is  

\[
R_{k}(\mathbf{h})=\Delta\sum_{i=0}^{N-1-|k|}h_{i}\,h_{i+|k|},
\]

which is exactly the correlation computed by `np.correlate(h,h,'full')*Δ`.  
Consequently  

\[
C_{5}(\mathbf{h})=1-\min_{k}R_{k}(\mathbf{h}) .
\]

**3.  A binary exact model (MILP) – the core novelty**

The simplest admissible step functions are binary: \(h_{i}\in\{0,1\}\).  
If a binary optimum exists (it is known that extremal solutions can be taken binary), solving the binary problem yields a *feasible* upper bound for the original continuous problem.

Introduce binary variables  

\[
a_{i}\in\{0,1\},\qquad i=0,\dots ,N-1,
\]

with the volume constraint  

\[
\sum_{i}a_{i}=N/2 .
\]

For each admissible pair \((i,k)\) (i.e. \(i\) and \(j=i+k\) both lie in \([0,N-1]\)) define an auxiliary binary variable  

\[
w_{i,k}=a_{i}\,(1-a_{j}) .
\]

The product can be linearised **exactly** with three inequalities (McCormick’s formulation collapses to the exact hull when the factors are binary):

```
w_{i,k} ≤ a_i
w_{i,k} ≤ 1 - a_j
w_{i,k} ≥ a_i - a_j
w_{i,k} ≥ 0
```

For a fixed shift \(k\) the overlap integral is  

\[
\int h(x)\bigl(1-h(x+k)\bigr)=\Delta\sum_{i} w_{i,k}.
\]

Introduce a continuous variable \(t\) that upper‑bounds all these integrals:

\[
\Delta\sum_{i} w_{i,k}\;\le\; t,\qquad\forall k=-N+1,\dots ,N-1.
\]

The **mixed‑integer linear program (MILP)** is therefore  

\[
\begin{aligned}
\min\;& t \\
\text{s.t.}\;&
\Delta\sum_{i} w_{i,k}\le t &&\forall k,\\
&w_{i,k}\le a_i,\; w_{i,k}\le 1-a_j,\\
&w_{i,k}\ge a_i-a_j,\; w_{i,k}\ge 0 &&\forall(i,k),\\
&\sum_i a_i = N/2,\\
&a_i\in\{0,1\},\; w_{i,k}\in\{0,1\},\; t\ge0.
\end{aligned}
\]

All constraints are linear; the only non‑convexity is the integrality of the variables.

**Why this is materially different:**  
The previous solution used a stochastic pairwise‑mass‑transfer annealer.  
Here we **solve an exact combinatorial optimisation problem** for binary step functions, obtaining a provably feasible bound without any randomness. The MILP can be tackled with the CBC or GLPK back‑ends exposed by `cvxpy`. For \(N\approx 120\) the model has roughly \(N\) binary variables and \(\approx N(2N-1)\) auxiliary binaries – a size that modern MILP solvers handle comfortably within a few minutes.

**4.  Managing the MILP within the time budget**

* **Size control** – start with \(N=120\) (so the volume constraint forces exactly 60 ones).  
* **Shift pruning** – the worst overlap is never attained at the extreme shifts \(|k|\approx N\) because the overlapping interval shrinks to zero. We may safely drop the outer 10 % of shifts (e.g. only enforce constraints for \(|k|\le 0.9\,N\)). This reduces the number of `w` variables by ≈20 % with negligible impact on the bound.  
* **Solver time limit** – pass `max_seconds` (or the equivalent `MIPGap`/`TimeLimit`) to the CBC solver so that, if optimality cannot be proven, the best feasible solution found so far is returned.  
* **Warm‑start** – before invoking the solver, generate a good feasible binary vector using the greedy constructive heuristic described in section 5 and feed it to the solver as an initial solution (CBC accepts a `start` hint via `Problem(..., warm_start=True)` in `cvxpy`).  

If the MILP finishes (optimal or best‑known) early we immediately obtain an upper bound `t*` and a binary vector `a*`. If the solver hits the time limit we still keep the best feasible `a*` found.

**5.  Greedy constructive heuristic (fallback & seeding)**

When the MILP is too large or the time limit is very tight, a deterministic greedy algorithm supplies a decent binary candidate:

1. Initialise all \(a_i=0\).  
2. Maintain for each shift \(k\) the current overlap sum  
   \(S_k = \Delta\sum_{i} a_i\,(1-a_{i+k})\).  
3. Repeat \(N/2\) times:  
   * For each still‑zero index \(i\) compute the *increment* in the worst shift if we set \(a_i←1\):  
     \(\Delta S_k(i)=\Delta\bigl[(1-a_{i+k})-a_{i+k}\bigr]\) for the admissible \(k\).  
   * Let \(k^*\) be the shift with the largest current \(S_k\) (the current worst overlap).  
   * Choose the index \(i\) that **minimises** the increase \(\Delta S_{k^*}(i)\) and set \(a_i←1\).  
   * Update all \(S_k\) efficiently (O(N) per insertion).  

The algorithm runs in \(O(N^2)\) time, negligible for \(N≤200\). The resulting binary vector is a guaranteed feasible point for the MILP and a strong seed for later refinement.

**6.  Continuous refinement of a feasible point (smooth max‑min gradient descent)**

Binary solutions often leave slack in the box constraints; allowing fractional values can lower the maximum overlap further. From a feasible binary vector \(a\) we construct the continuous start \(\mathbf{h}^{(0)}=a\) (or a very slight smoothing to avoid flat derivatives) and run a *projected gradient descent* on the **smoothed max** objective

\[
F_{\beta}(\mathbf{h})=
\frac{1}{\beta}
\log\!\Bigl(\sum_{k} \exp\bigl(\beta\,(1-R_{k}(\mathbf{h}))\bigr)\Bigr).
\]

* As \(\beta\to\infty\) the function approaches the true maximum, but for moderate \(\beta\) it is differentiable.  
* Gradient:  
  \[
  \nabla F_{\beta}(\mathbf{h})
   = -\Delta\!\sum_{k}\!w_{k}\,\bigl(\mathbf{h}_{\text{shift }k}+\mathbf{h}_{\text{shift }-k}\bigr),
  \]
  where  
  \[
  w_{k}=
  \frac{\exp(-\beta\,R_{k}(\mathbf{h}))}{\sum_{j}\exp(-\beta\,R_{j}(\mathbf{h}))}
  \]
  (a softmax over the autocorrelations).  

* **Projection onto the feasible set** (box \([0,1]\) and total‑mass constraint) is performed by the closed‑form *bisection on a Lagrange multiplier*:

  Find \(\lambda\) such that  
  \[
  \sum_{i}\operatorname{clip}\!\bigl(h_i-\lambda,\;0,\;1\bigr)=N/2 .
  \]
  The function of \(\lambda\) is monotone, so a 40‑iteration bisection yields machine‑precision projection.

* **Schedule** – start with a moderate smoothness \(\beta_{0}=1\) and increase geometrically to \(\beta_{\max}=50\) over the allocated iterations; use a step size that decays linearly from \(\alpha_{0}=1.0\) to \(10^{-4}\).  

* **Termination** – stop when the elapsed time for this phase reaches its quota (e.g. 30 % of the total budget) or when the improvement in the true objective \(C_{5}=1-\min_kR_k\) falls below \(10^{-6}\).

**7.  Targeted sub‑gradient refinement (worst‑shift only)**

After the smooth phase, a cheap *worst‑shift* sub‑gradient step sharply pushes the smallest autocorrelation upward:

1. Compute the full autocorrelation vector \(R_k(\mathbf{h})\).  
2. Identify the worst shift \(k_{\mathrm{w}}=\arg\min_k R_k\).  
3. The exact gradient of \(R_{k_{\mathrm{w}}}\) is  
   \[
   \nabla R_{k_{\mathrm{w}}}(\mathbf{h})=
   \Delta\bigl(\mathbf{h}_{\text{shift }k_{\mathrm{w}}}+\mathbf{h}_{\text{shift }-k_{\mathrm{w}}}\bigr).
   \]  
4. Perform a **max‑imisation** step (since we want to increase \(R_{k_{\mathrm{w}}}\)):  
   \[
   \mathbf{h}\leftarrow\mathbf{h}+\eta\,\nabla R_{k_{\mathrm{w}}}(\mathbf{h}),
   \]
   followed by the same projection as in step 6.  
5. Decrease \(\eta\) geometrically (e.g. halve every 500 iterations).  

Running this loop for the remaining time (≈ 30 % of the budget) typically eliminates the last few hundredths of the overlap.

**8.  Final local random‑move polishing**

As a last‑ditch improvement, reuse the very cheap pairwise‑mass‑transfer move from the original submission:

* pick two indices \(i\neq j\); move a tiny amount \(\delta\) from \(h_i\) to \(h_j\) while preserving feasibility;  
* accept the move only if \(C_{5}\) does not increase;  
* gradually reduce the allowed \(\delta\) (e.g. start at \(0.1\) and halve every 2000 accepted moves).  

Because the vector is already near‑optimal, this phase only explores a local neighbourhood and finishes quickly.

**9.  Time‑budget allocation (single‑CPU, 600 s)**

| Phase | Goal | Approx. time |
|------|------|--------------|
| 0. Pre‑compute shift tables, set \(N\) | negligible | < 5 s |
| 1. Greedy constructive (fallback & seed) | fast binary candidate | 5 % of total |
| 2. MILP (binary optimum) | primary bound (if it finishes) | 40 % of total (run with `max_seconds = 0.4·budget`) |
| 3. Smooth max‑min gradient descent | lift binary solution to fractional | 25 % of total |
| 4. Worst‑shift sub‑gradient refinement | tighten the bound | 20 % of total |
| 5. Random‑move polishing | final tweak | remaining ≤ 10 s |

If the MILP terminates early (common for \(N≈120\)), the saved time is re‑distributed to phases 3 and 4, allowing more iterations and a tighter final bound.

**10.  Expected failure modes and mitigations**

| Failure | Reason | Mitigation |
|---------|--------|------------|
| MILP exceeds memory / time | Too many `w_{i,k}` variables (large N, all shifts) | Prune extreme shifts, start with a smaller \(N\) (e.g. 100), use greedy solution as warm start |
| Solver returns only a weak feasible point | Tight integrality gap, insufficient time | Continue with the greedy binary vector (guaranteed feasible) and skip to phase 3 |
| Gradient descent stalls in a plateau | Flat soft‑max for very large \(\beta\) | Keep \(\beta\) moderate until the true max is identified, then increase; use momentum (exponential moving average of gradients) |
| Projection bisection loses precision | Numerical overflow for extreme \(\lambda\) | Initialise search interval as \([\,-\max(h)-1,\;\max(h)+1\,]\) which always brackets the solution; stop after a fixed number of iterations (40) which yields < \(10^{-12}\) error |
| Sub‑gradient overshoots | Step size too large when the worst shift involves many non‑zero entries | Use a decaying step schedule; clip the update \(\eta\,\nabla R_{k_{\mathrm{w}}}\) so that no entry moves more than 0.1 in a single iteration |

**11.  Output format**

The function `run` will:

* initialise the random seed,
* build the greedy binary vector,
* run the MILP (with the optional time limit),
* if a binary feasible point is obtained, launch the smooth gradient phase, then the worst‑shift sub‑gradient phase,

* return a tuple `(h_values, c5_bound, n_points)` where `h_values` is the final continuous vector (length `n_points=N`) and `c5_bound` is the evaluated `C5` (max overlap).
