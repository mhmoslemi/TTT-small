**Goal** – Produce a binary step‑function `h` on `[0,2]` (discretised with `n` points, `dx=2/n`) with exactly `n/2` entries equal to 1 (the rest 0) such that  

\[
C_5(h)=dx\;\max_{\ell}\;c_\ell,\qquad 
c_\ell =\sum_{i=0}^{n-1}h_i\bigl(1-h_{i+\ell}\bigr),\; -n<\ell<n
\]

is as small as possible.  The record to beat is `C5 ≤ 0.38092`.

The proposed method is a **population‑based memetic algorithm** (genetic algorithm + intensive local refinement).  
It differs fundamentally from the earlier hill‑climbing / annealing strategies by exploring many solutions in parallel, using recombination operators that respect the cardinality constraint, and by applying fast incremental updates of the correlation during local optimisation.

---

### 1. Problem representation

* Choose an **even** integer `n` (default 200).  
* A candidate solution is a NumPy vector `h` of length `n` with entries in `{0,1}` and `∑h = n/2`.  
* The fitness of a candidate is `‑C5(h)` (the smaller the overlap, the larger the fitness).

All arithmetic will be performed with `float64` but the values stay integral.

---

### 2. Efficient evaluation of the overlap

* The full aperiodic correlation needed for the objective is  
  `c = np.correlate(h, 1‑h, mode='full')` (length `2n‑1`).  
* The raw maximum `c.max()` is multiplied by `dx = 2.0/n` to obtain `C5`.  
* For the **local refinement** stage we avoid recomputing the whole correlation after each swap.  
  A swap of a 1 at position `i` and a 0 at position `j` changes only the ordered pairs that contain `i` or `j`.  
  The delta for each lag can be updated in **O(n)** time by the following rule (derived from the definition of the correlation):

```
Δc_{k−i}  += (h_j‑h_i)*(1‑h_k)          for every k≠i,j
Δc_{i−k}  += h_k*(h_i‑h_j)              (same loop)
Δc_{k−j}  += (h_i‑h_j)*(1‑h_k)
Δc_{j−k}  += h_k*(h_j‑h_i)
Δc_{j‑i}  += (h_j‑h_i)                  # pair (i,j)
Δc_{i‑j}  -= (h_j‑h_i)                  # pair (j,i)
```

  After applying the deltas we can compute the new maximum with a simple `max()` over the updated array (size ≈ 400).  This yields a cheap test for acceptance of a swap.

---

### 3. Initial population

Population size `P` = 40 (adjustable).  The initial pool is built from three sources to guarantee diversity:

| Source | How it is generated |
|--------|----------------------|
| **Random** | Sample `n/2` distinct indices uniformly and set them to 1. |
| **Structured seeds** | (a) Strictly alternating pattern `[1,0,1,0,…]`. (b) One contiguous block of length `n/2`. (c) A “two‑block” pattern `[1…1,0…0,1…1,0…0]` with roughly equal block sizes. |
| **Warm start** | If the global variable `initial_h_values` exists, resize it to length `n` by nearest‑neighbour replication, then repair the cardinality by swapping the smallest‑value entries to reach exactly `n/2` ones. |

All individuals are repaired to satisfy the cardinality constraint by a simple **swap‑repair**: if the number of ones is too high, flip randomly chosen ones to 0; if too low, flip zeros to 1.  The repair never changes the total number of ones by more than one per flip, preserving randomness.

---

### 4. Genetic operators

#### 4.1 Selection  
Use **binary tournament selection** (two individuals are sampled uniformly, the one with larger fitness wins).  This gives a mild selection pressure and helps keep diversity.

#### 4.2 Crossover  
* **Uniform crossover**: for each position `p`, the offspring receives `h_p` from parent A with probability 0.5, otherwise from parent B.  
* The offspring will usually violate the cardinality constraint.  A **repair step** restores the exact number of ones:

  1. Compute `Δ = current_ones – n/2`.  
  2. If `Δ>0` (too many ones), choose `Δ` indices among those that are 1 and flip them to 0 uniformly at random.  
  3. If `Δ<0` (too few), flip `|Δ|` zeros to ones in the same way.  

  This repair preserves as much of the parental structure as possible while guaranteeing feasibility.

#### 4.3 Mutation  
For each offspring, with probability `p_mut = 0.2` perform **swap mutation**:

* Choose `m` random disjoint pairs of indices (`m` ≈ 1–3) where each pair consists of a 1 and a 0, and exchange their values.  
* Optionally, with probability `0.05` perform a **block mutation**: pick a contiguous block of length `b` (random between 2 and `n/10`) containing `b₁` ones; move the block to another random location by swapping the whole block with the region at the destination, then repair the cardinality locally (still only swaps, so the number of ones stays unchanged).

All mutations respect the `0/1` domain and maintain the exact sum.

---

### 5. Memetic (local) improvement

After an offspring has been created and repaired, we apply a **short local search** to increase its quality before it enters the next generation:

* Run a bounded number of iterations (e.g. 150) of the **swap‑hill‑climber** described in §2.
* Accept a swap only if it **strictly decreases** the current `C5`.  
* Because the correlation update is O(n) and `n` is modest, this local step costs only a few milliseconds per individual.

This memetic step dramatically improves the baseline GA performance and pushes promising individuals toward local optima early.

---

### 6. Evolutionary loop

```
while time_remaining > ε:
    - Select two parents (tournament)
    - Produce an offspring by uniform crossover + repair
    - Mutate the offspring
    - Apply the short memetic improvement
    - Evaluate its exact C5 (full np.correlate)
    - Insert offspring into the new population
    - Keep the best E = 2 elite individuals from the previous generation unchanged
    - When the new population reaches size P, replace the old one
    - Update the global best solution if needed
```

*The loop checks the wall‑clock after each generation; if less than 5 s remain, it breaks and proceeds to the final refinement phase.*

Typical runtime per generation (P = 40, n = 200) is ≈ 0.04 s, allowing > 800 generations comfortably within a 600 s budget.

---

### 7. Final intensive local refinement

Take the **best binary vector** discovered by the GA (`h_best`).  
Perform a **long‑run hill‑climber** that explores the whole neighbourhood:

* Initialise `corr = np.correlate(h_best, 1‑h_best, mode='full')`.
* Run up to `L = 200 000` swap attempts (or until the remaining time drops below 2 s):
  * Randomly pick a 1‑index `i` and a 0‑index `j`.  
  * Compute the correlation delta using the O(n) update of §2 (with a copy of `corr`).  
  * Accept the swap only if the new maximum correlation is **strictly smaller**.  
  * If accepted, replace `h_best` and the stored `corr` with the updated versions.

Because the improvement steps become rarer as the solution approaches a local optimum, the algorithm naturally terminates after a long stretch without any accepted swap, ensuring we have exhausted the reachable neighbourhood.

---

### 8. Optional fine‑tuning with fractional values (optional fallback)

If after the binary refinement the achieved bound is still above the target, a **continuous polishing** stage can be attempted:

* Start from the binary `h_best` and allow each entry to become a real number in `[0,1]`.  
* Perform a few gradient‑descent steps on the **log‑sum‑exp surrogate**  

  \[
  F_\alpha(h)=\frac{dx}{\alpha}\log\Bigl(\sum_{\ell}e^{\alpha\,c_\ell(h)}\Bigr)
  \]

  (here `c_ℓ(h)=Σ h_i(1‑h_{i+ℓ})`).  
* After each gradient step, project onto the **capped simplex** (box constraints `[0,1]` and `∑h = n/2`).  
* When `α` becomes large (≈ 200), `F_α` is essentially the true `C5`.  
* Finally **threshold** the fractional solution back to a binary one by keeping the `n/2` largest entries.  
* Run the binary hill‑climber again to clean up any artefacts.

This stage is optional because it requires additional implementation and may not be necessary if the memetic GA already reaches the target bound.

---

### 9. Time‑budget handling

* Record `t_start = time.time()`.  
* After each GA generation, compute `elapsed = time.time() - t_start`.  
* If `elapsed > 0.9·budget_s`, stop the evolutionary loop and jump to the final refinement.  
* The final hill‑climber runs until `time.time() - t_start` exceeds `budget_s - 0.5` s, guaranteeing termination before the hard limit.

All heavy operations (full correlation, local delta updates) are bounded by O(n log n) or O(n) with tiny constants, ensuring the algorithm stays comfortably within the 600 s budget for `n ≤ 200`.

### 10. Expected advantages over previous approaches

| Aspect | Earlier hill‑climbing / annealing | New memetic GA |
|--------|-----------------------------------|----------------|
| **Search space exploration** | Single trajectory, prone to early trapping | Parallel population, recombination creates large jumps |
| **Diversity** | Relies on random restarts | Built‑in via tournament selection and mutation |
| **Exploitation** | Local swaps only | Memetic refinement after each offspring plus a dedicated final hill‑climber |
| **Scalability** | Needs many iterations for a single candidate | Evaluates many candidates per generation, each cheaply (correlation length ≤ 400) |
| **Constraint handling** | Swap moves preserve cardinality automatically | Repair‑after‑crossover guarantees exact sum for every generation |
| **Speed** | Re‑computes full correlation for every move (O(n²) if naive) | Uses incremental O(n) updates for swaps; full correlation only on population evaluation |
| **Potential to beat the record** | May stall at a local optimum | Larger exploratory moves (crossover, block mutation) increase chance of finding a better arrangement |

### 11. Deliverable – `run` implementation outline

`run(seed=42, budget_s=600, **kwargs)` will:

1. Set the random seed.
2. Choose `n = 200` (or a slightly smaller even number if time is already tight).
3. Build the initial population as described in §3.
4. Execute the evolutionary loop (§6) respecting the wall‑clock.
5. Perform the intensive hill‑climber on the best individual (§7).
6. Compute the final bound `c5_bound = dx * max(np.correlate(best_h, 1‑best_h, mode='full'))`.
7. Return `(best_h, c5_bound, n)`.

All helper functions (correlation update, repair, projection, tournament, etc.) are defined at module top‑level, use only `numpy`, `random`, and `time`, and are written to run efficiently on a single CPU.

By combining global recombination, mutation, and fast exact local optimisation, this strategy explores a far richer set of configurations than a simple random walk and is therefore much more likely to discover a step‑function with `C5` below the current record (target ≤ 0.3807).
