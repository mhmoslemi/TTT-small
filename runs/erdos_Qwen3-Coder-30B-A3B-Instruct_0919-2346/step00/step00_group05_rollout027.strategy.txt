**Goal** – Produce a step function `h` on `[0,2]` (discretised into `n` equally spaced points) that satisfies  

* `0 ≤ h[i] ≤ 1` for all `i`,
* `∑_{i=0}^{n-1} h[i] = n/2`  (so that the integral of `h` over `[0,2]` equals 1),

and that **minimises**  

```
C5(h) = max_k   ∫_0^2 h(x)·(1 – h(x+k)) dx .
```

The evaluation routine used later is  

```
c = np.correlate(h, 1 – h, mode='full')
C5 = np.max(c) * (2.0 / n)      # dx = 2/n
```

### 1. Re‑express the objective in combinatorial form

Because the grid is finite and the integral is approximated by a Riemann sum,
for an integer shift `k` (indices outside `{0,…,n‑1}` are treated as zero)

```
f_k(h) = Σ_i h[i]·(1 – h[i+k])
      = Σ_i h[i]  –  Σ_i h[i]·h[i+k] .
```

The total mass `Σ_i h[i]` is fixed (`= n/2`).  
Hence

```
C5(h) = (n/2 – min_k Σ_i h[i]·h[i+k])  * dx .
```

*Minimising the maximal overlap* is equivalent to **maximising the minimal
autocorrelation**  

```
τ(h) := min_{k}  Σ_i h[i]·h[i+k] .
```

If we can find a feasible `h` with a large `τ`, the corresponding bound is

```
C5 = (n/2 – τ) * (2/n) .
```

### 2. Introduce exact product variables – a MILP formulation

The term `h[i]·h[i+k]` is bilinear.  We linearise it **exactly** by introducing
auxiliary variables

```
y[i,k]  ≡  h[i] * h[i+k] ,   for all i and all non‑negative shifts k.
```

Because `h[i]` lives in `[0,1]` we can enforce the relationship by the
**McCormick envelope** (tight when `h` is binary).  For every pair `(i,k)` :

```
y[i,k] ≥ 0
y[i,k] ≤ h[i]
y[i,k] ≤ h[i+k]
y[i,k] ≥ h[i] + h[i+k] – 1 .
```

When `h[i]` and `h[i+k]` are forced to be binary (`{0,1}`) these four constraints
make `y[i,k]` exactly equal to the product.

We also need a variable `τ` that bounds the autocorrelation from **below**:

```
τ ≤ Σ_i y[i,k]      for each shift k = 0,…,n‑1 .
```

The *objective* is to **maximise τ**.

Finally we add the original feasibility constraints:

```
0 ≤ h[i] ≤ 1                 (box)
Σ_i h[i] = n/2               (mass)
```

Optionally we may *force binary* `h[i] ∈ {0,1}` (the MILP then searches over
binary sequences of length `n` with exactly `n/2` ones).  This yields a pure
combinatorial problem; if the solver supplies a binary solution we have an
exact step function.  If the solver returns a fractional `h`, we can keep it
(as a valid continuous step function) or round it afterwards.

### 3. Symmetry reduction and variable pruning

The autocorrelation is symmetric: `Σ_i h[i]·h[i+k] = Σ_i h[i]·h[i–k]`.  
Therefore it is sufficient to impose the τ‑constraints only for **non‑negative**
shifts `k = 0,…,n‑1`.  The `k = 0` constraint simply reads `τ ≤ Σ_i h[i]`,
which is redundant because `Σ_i h[i] = n/2` is constant; we can drop it.

The product variables for `k = 0` are unnecessary: `y[i,0] = h[i]`.  For `k>0`
the index `i+k` runs only up to `n‑1`, so for each shift `k` we need only
`n‑k` variables.  The total number of `y`‑variables is  

```
∑_{k=1}^{n-1} (n‑k) = n·(n‑1)/2 .
```

For `n = 70` this is 2 415 variables – still modest for a modern MILP solver.

To break the global complement symmetry (`h → 1 – h`) we can fix the first
entry:

```
h[0] = 1   (or 0, whichever we prefer)
```

This eliminates the mirror‑image duplicate solutions and speeds up the branch‑and‑bound.

### 7. Optional post‑process refinement (gradient‑free)

If the best solution found is binary (or already very good) but we still have
some time left, we can apply a **purely combinatorial improvement** that does
not touch the MILP:

* Identify the shift `k*` that attains the maximal overlap (`C5`).
* Scan all index pairs `(i, i+k*)` with `h[i]=1` and `h[i+k*]=0`.  
  Swapping the values of `h[i]` and `h[i+k*]` (i.e., moving a “1” forward by
  `k*`) reduces `f_{k*}` by exactly `1` and does not increase any other shift
  by more than `1`.  Accept the swap if the resulting `C5` strictly decreases.
* Repeat until no improving swap exists.  This local search is guaranteed to
  terminate quickly (the number of possible swaps is O(n²)) and can shave a
  few × 10⁻⁴ off the bound.

Because the moves preserve the binary nature and the total count of ones,
the final vector remains feasible.
