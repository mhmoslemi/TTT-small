**Overview**

We treat the Erdős overlap problem as a *difference‑of‑convex* (DC) program and apply a **Successive Linear Approximation (SLA)** (also called the convex‑concave procedure).  
At each outer iteration we *linearise* every bilinear overlap term around the current iterate, which turns the original non‑convex “max of quadratics” into a **linear program (LP)**.  Solving the LP yields a new feasible vector that is guaranteed to minimise the *linearised* worst‑case overlap.  Repeating this process converges to a locally optimal step function.  The whole scheme is dramatically different from direct projected gradient descent: it relies on exact LP solutions rather than heuristics, and it simultaneously addresses *all* shifts through the auxiliary scalar `t`.

The method is lightweight (≈ O(n²) constraints for `n≈70`), fits easily into the 600 s budget, and can be combined with cheap random restarts and a short refinement phase.

### 1. Mathematical formulation

For a discrete step function `h ∈ ℝⁿ` (grid points on `[0,2]`) let `dx = 2/n`.  
Define the overlap for an integer shift `k∈{-(n-1),…,n-1}`

```
f_k(h) = Σ_{i=0}^{n-1} h_i·(1 – h_{i+k})      (zero padding for i+k out of range)
```

The quantity to minimise is

```
C₅(h) = max_k   f_k(h)·dx .
```

`f_k` is a *concave* quadratic (because of the negative product term).  
Write

```
f_k(h) = Σ_i h_i  –  Σ_i h_i·h_{i+k}
       = Σ_i h_i  –  P_k(h)
```

where `P_k(h) = Σ_i h_i·h_{i+k}` is the bilinear part.

The feasible set is the **capped simplex**

```
0 ≤ h_i ≤ 1               (box)
Σ_i h_i = n/2             (mass = 1 → Σ h_i·dx = 1)
```

---

### 2. Linearising the bilinear term

For a fixed `k` the product `h_i·h_{i+k}` is linearised at the current point `h⁽ʳ⁾` using first‑order Taylor expansion:

```
h_i·h_{i+k} ≈ h_i⁽ʳ⁾·h_{i+k}⁽ʳ⁾
            + h_{i+k}⁽ʳ⁾·(h_i – h_i⁽ʳ⁾)
            + h_i⁽ʳ⁾·(h_{i+k} – h_{i+k}⁽ʳ⁾) .
```

Summing over `i` and simplifying (zero padding handled by ignoring out‑of‑range indices) gives

```
P_k(h) ≈ Σ_i ( h_{i+k}⁽ʳ⁾·h_i + h_i⁽ʳ⁾·h_{i+k} )  –  Σ_i h_i⁽ʳ⁾·h_{i+k}⁽ʳ⁾ .
```

Insert into `f_k`:

```
f_k(h) ≈ Σ_i ( 1 – h_{i+k}⁽ʳ⁾ – h_{i−k}⁽ʳ⁾ )·h_i   +   Σ_i h_i⁽ʳ⁾·h_{i+k}⁽ʳ⁾ .
```

Define for each shift `k`

* coefficient vector   
  `a^{(r)}_{i,k} = 1 – h^{(r)}_{i+k} – h^{(r)}_{i−k}` (outside the interval → term = 0),
* constant term   
  `c^{(r)}_k = Σ_i h^{(r)}_i·h^{(r)}_{i+k}`.

Thus the *linearised* worst‑case overlap constraint becomes

```
t ≥ a^{(r)}_k·h  +  c^{(r)}_k      for every shift k .
```

The scalar `t` is an upper bound on the true max; minimising `t` drives the max overlap down.

### 3. Outer SLA loop (Successive Linear Approximation)

**Input**  
* `n` – number of discretisation points (use the length of `initial_h_values`, typically 70).  
* `S = n/2` – required sum of `h`.  

**Algorithm (per restart)**

1. **Initial feasible point** `h^{(0)}`  
   *If `initial_h_values` exists* → use it (already feasible).  
   Otherwise generate a random vector `v∈[0,1]ⁿ` and **project** it onto the capped simplex (see §4).

2. **Iterative linearisation** (`r = 0,1,…`)  
   a. **Compute coefficients** `a^{(r)}_{·,k}` and constants `c^{(r)}_k` for all shifts `k = -(n-1)…(n-1)`.  
   b. **Form LP**  

      *Variables*: `h ∈ ℝⁿ`, scalar `t`.  

      *Objective*: `minimise t`.  

      *Constraints* (for every shift `k`):  
      `a^{(r)}_k·h + c^{(r)}_k ≤ t`.  

      *Mass constraint*: `Σ_i h_i = S`.  

      *Box*: `0 ≤ h_i ≤ 1`.  

      *Optional slack*: add `ε_k ≥ 0` with a large penalty `M·ε_k` to guarantee feasibility if the linearised system becomes infeasible (see §5).

   c. **Solve the LP** using a fast solver (`cvxpy` with ECOS/GLPK, or `scipy.optimize.linprog`).  
      Obtain `(h^{LP}, t^{LP})`.

   d. **Damping / under‑relaxation** (to avoid oscillations):  

      Choose `λ ∈ (0,1]` (e.g., `λ = 0.7`).  
      Set  

      ```
      h^{(r+1)} = λ·h^{LP} + (1‑λ)·h^{(r)} .
      ```

   e. **Projection onto the capped simplex** (tiny numerical drift may violate the exact sum). Use the water‑filling / bisection method described in §4.

   f. **Evaluation**: compute the true overlap `C₅(h^{(r+1)})` via correlation.  
      Keep track of the best vector seen across all iterations.

   g. **Convergence test** – stop when  
      * relative change in `t` ≤ 1e‑6 **and**  
      * relative change in `C₅` ≤ 1e‑6,  
      or after a modest hard cap (e.g., 30 outer iterations).

   h. **Time‑budget check** – after each outer iteration, abort the current restart if `time_elapsed > 0.95·budget`.

3. **Post‑SLA polishing** (optional, cheap local search)  
   *Pick the shift `k*` giving the current worst overlap*.  
   *Perform a targeted “mass‑transfer”*: choose `i` with `h_i > 0` and `i+k` with `h_{i+k} < 1`, move a tiny amount `δ` from `i` to `i+k` (preserves sum, respects bounds). Accept if `C₅` improves. Do a few hundred such moves; they are essentially a fine‑grained hill‑climb on the already near‑optimal point.

4. **Multiple restarts** – repeat steps 1‑3 from different random feasible starts (or from the current best perturbed by a small noise). Keep the globally best `h` and its `C₅`.

5. **Return** `best_h`, `best_C5`, `n`.

### 4. Projection onto the capped simplex (box + sum)

Given a vector `v ∈ ℝⁿ` (after a linear step or after LP solving), we need the Euclidean projection onto

```
{ h | 0 ≤ h_i ≤ 1,   Σ h_i = S } .
```

The projection can be obtained by solving for a scalar λ such that

```
h_i(λ) = clip( v_i – λ , 0 , 1 )
```

satisfies `Σ_i h_i(λ) = S`.  
`Σ h_i(λ)` is monotone decreasing in λ, so a simple bisection on λ converges in ~50 iterations:

* Initialise `λ_low = -2`, `λ_high = 2` (any interval that forces all `h_i(λ_low)=1` and all `h_i(λ_high)=0`).  
* While `λ_high – λ_low` > tolerance:  
  * `λ_mid = (λ_low + λ_high)/2`.  
  * Compute `h_mid = clip(v – λ_mid, 0, 1)`.  
  * If `Σ h_mid > S` → need larger λ (`λ_low = λ_mid`), else → smaller λ (`λ_high = λ_mid`).  
* Return `h = clip(v – (λ_low+λ_high)/2, 0, 1)`.

Complexity O(n log precision); negligible for n≈70.

---

### 5. Handling infeasibility and numerical robustness

* **Slack variables** – if the linearised constraints force `t` below the true minimal value, the LP may become infeasible. Introduce a non‑negative slack `ε_k` for each shift:

  ```
  a^{(r)}_k·h + c^{(r)}_k ≤ t + ε_k ,   ε_k ≥ 0 .
  ```

  Add a large penalty `M·Σ ε_k` (e.g., `M = 10⁴`) to the objective together with `t`. This guarantees a feasible LP while strongly discouraging slack usage.

* **Bounded `t`** – we can safely set a lower bound `t ≥ 0` (overlap cannot be negative) and an upper bound `t ≤ 2` (the integral of a product of two ≤1 functions on a domain of length 2).

* **Damping factor `λ`** – empirically a value between 0.5 and 0.9 reduces the risk of cycling and improves stability.

* **Numerical tolerance** – after solving the LP, enforce `h_i = min(max(h_i,0),1)` before projection, to discard tiny violations caused by solver tolerance.

### 6. Multi‑scale refinement (optional)

1. **Coarse stage** – run the SLA on `n = 70`.  
2. **Interpolation** – double the resolution: for each original point create two copies (`h'_{2i}=h'_{2i+1}=h_i/2`). This preserves the total mass (`Σ h' = Σ h = S`).  
3. **Fine stage** – treat the interpolated vector (now `n' = 140`) as a new start and run the SLA again.  
4. **Optional final polishing** – low‑dimensional random moves as in §3 d.

Because the LP size grows only quadratically, the fine stage still runs within the time budget.

### 7. Computational budget and expected performance

* **LP size**: `n` variables + 1 (`t`) + (2n‑1) linear constraints ≈ 140 constraints for `n=70`. Solvers finish each LP in < 0.01 s on a single CPU.  
* **Outer iterations**: ≤ 30 per restart → < 0.3 s per restart.  
* **Number of restarts**: with a 600 s budget we can comfortably execute > 100 restarts, each potentially improving the best bound.  
* **Polishing moves**: a few thousand cheap targeted transfers add < 0.1 s total.

Thus the full pipeline comfortably fits the 600 s limit while exploring a rich set of candidate solutions.

### 8. Failure‑mode checklist

| Potential issue | Detection | Remedy |
|-----------------|-----------|--------|
| LP infeasibility | Solver returns `infeasible` | Include slack variables with large penalty; fallback to previous iterate. |
| Cycling between two points | `h` repeats after two or three outer iterations | Reduce damping `λ`, or add a small random perturbation before the next linearisation. |
| Convergence to a poor local optimum | Best `C₅` after many restarts stays above 0.3810 | Increase number of restarts, enlarge the random perturbation radius, or initialise from a *binary* feasible vector (half‑ones, half‑zeros). |
| Numerical drift of sum constraint | After LP, `|Σ h – S| > 1e‑8` | Apply the capped‑simplex projection immediately after each LP solve. |
| Exhaustion of time before any improvement | No time left for restarts | Prioritise longer SLA runs on the best start; skip polishing if time is low. |

### 9. Summary of the distinct strategy

1. **Model** the max‑overlap as the maximum of linearised functions.  
2. **Iteratively solve** a *global* LP that simultaneously reduces *all* shift constraints.  
3. **Enforce** feasibility exactly via a cheap projection onto the capped simplex.  
4. **Refine** with inexpensive targeted mass‑transfer moves.  
5. **Repeat** from numerous random starts (and optionally from a finer grid) to escape local minima.

Because the core optimisation step is an LP rather than a gradient step, the method explores a different region of the solution space and leverages the power of convex optimisation.  This constitutes a materially different approach from prior gradient‑based heuristics and is well‑suited to the tight time budget while offering a realistic path to a bound below the current record (target `C₅ ≤ 0.3807`).
