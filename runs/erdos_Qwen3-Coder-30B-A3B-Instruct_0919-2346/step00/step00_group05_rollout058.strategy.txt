Instead of manipulating a full‑resolution grid (70–200 variables) we treat the optimal step function as a *small number of constant blocks*.  The optimisation is performed directly on the block parameters (lengths and heights).  This reduces the problem to a handful of continuous variables, makes the evaluation of the worst‑case overlap exact (no numerical correlation), and allows the use of proven global‑optimisation techniques that are impossible on a high‑dimensional vector.

### 1. Parameterisation of the step function

* Choose a modest number **M** of blocks (e.g. 3 ≤ M ≤ 6).  
  A block *b* is described by a pair `(ℓ_b , α_b)` where  

  * `ℓ_b > 0` – its length (width) on the interval `[0,2]`,
  * `α_b ∈ [0,1]` – its constant height.

* Blocks are placed consecutively from left to right, starting at `x=0`.  
  The *order* of blocks is a free variable; we will keep the order as given
  (no rearrangement) because any permutation can be represented by a different
  set of `(ℓ,α)` values.

* **Feasibility constraints** become simple linear equalities/inequalities  

  ```
  Σ_{b=1..M} ℓ_b                = 2                (total length)
  Σ_{b=1..M} ℓ_b * α_b          = 1                (mass = ∫ h = 1)
  ℓ_b > 0 ,   0 ≤ α_b ≤ 1      for every b .
  ```

  The first constraint fixes the domain, the second enforces the integral
  condition.

* The decision vector therefore has `2M` real components.  For M=5 the
  dimension is only 10 – trivially searchable with global optimisation.

### 2. Exact evaluation of the worst‑case overlap for a given block vector

For a *fixed* block description we can compute the overlap integral  
`F(k) = ∫_0^2 h(x)·(1‑h(x+k)) dx` for any shift `k` analytically:

1. **Overlap of two blocks**  
   Let block `p` occupy `[x_p , x_p+ℓ_p]` with height `α_p`, and block `q`
   occupy `[x_q , x_q+ℓ_q]` with height `α_q`.  
   Their contribution to `∫ h·(1‑h_k)` when block `p` overlaps block `q` after a
   shift of `k` is  

   ```
   contribution(p,q,k) = α_p·(1‑α_q)· length( [x_p , x_p+ℓ_p] ∩ [x_q+k , x_q+k+ℓ_q] )
   ```

   where the intersection length is `max(0, min(x_p+ℓ_p, x_q+k+ℓ_q) – max(x_p, x_q+k))`.

2. **All‑pair sum**  
   The total overlap for shift `k` is the sum of the contributions over all
   ordered pairs `(p,q)`.  Because both `h` and `1‑h` are piecewise constant,
   `F(k)` is a **piecewise linear** function of `k`.  Breakpoints occur exactly
   when any two block edges align, i.e. when  

   ```
   k = x_p – x_q    or    k = x_p+ℓ_p – (x_q+ℓ_q) .
   ```

   There are at most `2·M·(M‑1)` distinct breakpoints (including the two
   domain edges `k = –2` and `k = +2`).  Between two consecutive breakpoints
   the set of overlapping block pairs is constant, so `F(k)` is linear there.

3. **Maximum over all shifts**  
   To obtain `C5` we scan the sorted list of breakpoints, evaluate `F(k)` at
   each breakpoint and also at the interior point of every linear segment
   (the extremum of a linear function on an interval is attained at one of its
   ends, so evaluating at the breakpoints alone suffices).  The maximal value
   multiplied by `dx = 1` (because we work with exact integrals) is the bound
   for the given block vector.

The whole evaluation is **O(M²)** – negligible even for M=6.
