**Goal**  
Find a step function `h` on `[0,2]` (discretised to `n` points, `dx = 2/n`) with  
`0 ≤ h[i] ≤ 1`, `∑ h[i] = n/2` that minimizes  

```
C5 = max_k  ∑_i h[i]·(1‑h[i+k]) · dx                (correlation with “full’’ mode)
```

A smaller `C5` gives a tighter upper bound for the Erdős constant `C₅`.  
The record is `C5 ≈ 0.38092` with `n = 70`.  
We must produce a better bound (target ≤ 0.3807) while keeping `n` modest (< 1 000) and respecting the 600 s time limit.

### 1. Mathematical Reformulation  

For a fixed shift `ℓ ≥ 0` (the same values appear for `ℓ < 0` because of symmetry)

```
f_ℓ(h) = Σ_{i=0}^{n‑ℓ‑1} h[i]·(1‑h[i+ℓ])
       = Σ_i h[i] – Σ_i h[i]·h[i+ℓ]               (over the overlapping region)
```

Since `Σ_i h[i] = n/2` is constant, minimizing `max_ℓ f_ℓ(h)` is **equivalent** to **maximising the smallest self‑overlap**

```
g_ℓ(h) = Σ_i h[i]·h[i+ℓ] .
```

Thus we want a vector `h` (binary or fractional) such that *for every shift* the number (or weight) of positions where both copies are 1 is as large as possible.  

For a binary vector `h∈{0,1}ⁿ` with exactly `n/2` ones the quantity `f_ℓ` is an integer count of “1‑aligned‑with‑0’’ pairs, i.e.

```
f_ℓ =  # { i | h[i]=1 and h[i+ℓ]=0 } .
```

Therefore: **reducing the worst‑case `f_ℓ` is done by moving a ‘1’ that is mismatched with a ‘0’ to a place where it aligns with a ‘1’ in the shifted copy.** This insight drives the principal local‑search moves.

### 2. Overall Algorithmic Pipeline  

The pipeline consists of **four successive stages**; each stage uses the best solution from the previous one as a warm start:

| Stage | Purpose | Variables | Core Technique |
|------|---------|-----------|----------------|
| **A** | Generate a diverse pool of *binary* candidate vectors. | `h ∈ {0,1}ⁿ`, `∑h = n/2` | Random half‑filled vectors + structured families (Beatty / Sturmian words, repeated blocks, “gap‑limited’’ patterns). |
| **B** | Deterministic *targeted* local improvement on the binary vectors. | Same binary `h`. | Swap a mismatched `1` with a matching `0` for the *worst* shift (the one with maximal `f_ℓ`). Accept only improving swaps; fall back to random swaps if no improving pair exists. |
| **C** | Refine the best binary solution in the *continuous* domain. | `h ∈ [0,1]ⁿ` (real‑valued, sum fixed). | Projected gradient descent on the non‑convex objective `max_ℓ f_ℓ(h)`. The gradient is taken only from the current worst shift; a diminishing step size and a projection onto the simplex plus box constraints keep feasibility. |
| **D** (optional, time‑allowing) | Solve a *binary MILP* for a smaller discretisation to possibly improve the bound further and to obtain a provable certificate. | Binary `h`, auxiliary linearisation variables `w_{i,ℓ}` for `h[i]·(1‑h[i+ℓ])`. | Exact linearisation (McCormick + binary) → MILP: **min t** s.t. `Σ_i w_{i,ℓ} ≤ t` ∀ℓ, `∑h = n/2`, `0≤w≤1`, and the three standard product constraints (`w ≤ h`, `w ≤ 1‑h_shift`, `w ≥ h‑h_shift`). Solved with CBC (or GLPK) with a time cap; the best feasible solution is fed back to Stage C. |

The stages are **time‑controlled**: Stage A & B are fast (seconds); Stage C runs for the bulk of the budget (hundreds of seconds); Stage D is attempted only if roughly 30 s remain, because MILP solving is the most expensive.

### 3. Detailed Steps

#### 3.1 Choose Discretisation (`n`)  

*Target*: a balance between resolution (larger `n` → potentially better bound) and problem size (MILP and gradient‑descent cost).  
Empirically, `n = 180` (dx ≈ 0.0111) gives a good trade‑off:
- Number of pairwise product variables ≈ n·(n+1)/2 ≈ 16 300 (still easy for LP/MILP).
- Correlation evaluation cost ≈ O(n²) ≈ 3·10⁴ operations, negligible.

The algorithm is written with `n` as a *parameter*; the final `run` can lower `n` if the time budget runs out.

#### 3.2 Stage A – Pool Generation  

1. **Random half‑filled vectors**  
   - For each of `R₁ = 20` seeds: pick `n/2` distinct indices uniformly, set those positions to 1.
2. **Beatty (Sturmian) sequences**  
   - For a set of slopes `α` in a dense grid around 0.5 (e.g. `α = (p/q)` with `q ≤ 15`), generate `h[i] = 1` if `{i·α}` falls in the first half of the unit interval, else 0. This yields a low‑discrepancy distribution of ones.
3. **Gap‑limited patterns**  
   - Construct vectors where the distance between consecutive ones never exceeds a prescribed bound `G` (e.g. `G = 3`). These guarantee that for small shifts many ones stay aligned.
4. **Block‑repetition patterns**  
   - Choose a short binary word `w` of length `ℓ₀` with exactly `ℓ₀/2` ones (ℓ₀ even). Repeat it `⌈n/ℓ₀⌉` times and truncate to length `n`. Try all words of length up to `ℓ₀=8` (≈ 70 candidates).

All generated vectors are stored; for each we compute `C5` using the fast NumPy correlation (`np.correlate`). Keep the **best `K = 5`** vectors (lowest `C5`) as seeds for Stage B.

#### 3.3 Stage B – Targeted Binary Local Search  

For each seed vector `h`:

1. **Pre‑compute** the full array `s = np.correlate(h, 1‑h, mode='full')` (integer counts).  
   The index `ℓ` (shift) corresponding to the *worst* value is `ℓ_max = argmax(s) – (n‑1)`.  
2. **Identify mismatched positions** for this shift:
   - `M1 = { i | i ≤ n‑ℓ_max‑1, h[i]=1, h[i+ℓ_max]=0 }`  (ones that cause a penalty).  
   - `M0 = { i | i ≤ n‑ℓ_max‑1, h[i]=0, h[i+ℓ_max]=1 }`  (zeros that could be turned into ones to repair the penalty).  
   Both sets can be obtained with simple NumPy boolean indexing.
3. **Improvement move**  
   - If `M1` and `M0` are non‑empty, pick a random `i∈M1` and `j∈M0` and **swap** (`h[i]←0`, `h[j]←1`).  
   - Re‑evaluate `s` (full correlation) and accept the swap **iff** the new maximal value `max(s)` is **strictly smaller**.  
   - If the swap does not improve, revert it.
4. **Stuck condition** – when `M1` or `M0` is empty (no improving swap):
   - Perform a *random* pair swap (pick a random 1‑position and a random 0‑position).  
   - Accept it only if it does **not** increase `max(s)` by more than a tiny tolerance (e.g., `+1`). This injects diversity and lets the algorithm escape plateaus.
5. **Loop control** – repeat steps 1‑4 up to a maximum of `I_B = 40 000` iterations **or** until `max(s)` stops improving for `2000` consecutive attempts.
6. **Record** the best vector (lowest `max(s)`) found for this seed.

Because each swap changes only two entries, the correlation can be **incrementally updated** in O(`n`) time, but a full recompute (`np.correlate`) is cheap for `n≈180` and keeps the code simple.

After processing all `K` seeds we keep the **overall best binary vector** `h_bin_best` and its integer worst‑case count `S_best = max_ℓ f_ℓ(h_bin_best)`.

If `C5_best = S_best·dx` already satisfies the target (≤ 0.3807) we can stop; otherwise we proceed to Stage C.

#### 3.4 Stage C – Continuous Projected Gradient Descent  

We now treat `h ∈ [0,1]ⁿ` (real values). The current binary vector is used as the initial point (cast to float).

**Objective**: `Φ(h) = max_ℓ f_ℓ(h)`, where  

```
f_ℓ(h) = Σ_{i=0}^{n‑ℓ‑1} h[i]·(1‑h[i+ℓ]).
```

**Gradient of the active shift** (`ℓ* = argmax f_ℓ`):

For a fixed `ℓ* ≥ 0`

```
∂f_ℓ*/∂h[i] =  { 1‑h[i+ℓ*]               if i ≤ n‑ℓ*-1
               -h[i‑ℓ*]                 if i ≥ ℓ*
               0                         otherwise }
```

The gradient is the sum of the two contributions (the two overlapping windows).  
We compute it in vectorised form:

```
grad = np.zeros(n)
grad[:n‑ℓ*]   += 1 - h[ℓ*:]
grad[ℓ*: ]    -= h[:-ℓ*]
```

**Projection onto the feasible set**  
The feasible set is the intersection of a *box* (`0 ≤ h ≤ 1`) and an *affine hyperplane* (`Σ h = n/2`).  
After a gradient step `h' = h - η·grad` we:

1. **Clip**: `h' = np.clip(h', 0, 1)`.
2. **Adjust the sum**: compute `Δ = Σh' – n/2`.  
   - Identify the set `U = { i | 0 < h'[i] < 1 }` (non‑saturated indices).  
   - If `U` is non‑empty, shift the values in `U` uniformly by `‑Δ/|U|` and re‑clip; iterate at most two times (standard projection onto the simplex with box constraints).  
   - If `U` is empty (all variables at a bound), the point is at a vertex; we skip the projection step for that iteration (rare).

**Step‑size schedule**  

```
η₀ = 0.05   (initial)
η_t = η₀ / sqrt(t+1)           (t = iteration counter)
```

**Acceptance rule** – similar to a deterministic descent:
- Compute the new `Φ(h')`.  
- If `Φ(h') ≤ Φ(h)` accept `h←h'`.  
- Otherwise reject and keep the old `h`.  

Optionally, a *weak* simulated‑annealing acceptance (`exp(-(Φnew‑Φold)/T)`) with a slowly cooling temperature `T` can be added to escape shallow local minima.

**Termination** – run for at most `I_C = 3000` successful gradient steps or until the improvement in `Φ` over the last `500` steps is < 1e‑5.  

At the end, evaluate the true `C5` using the exact product (no linearisation):

```
s_ℓ = Σ_i h[i]·(1‑h[i+ℓ])   (full correlation)
C5 = max_ℓ s_ℓ · dx .
```

If the resulting `C5` meets the target we finish; otherwise we move to Stage D.

#### 3.5 Stage D – Exact Binary MILP (time‑permitting)  

Because the binary problem is a pure *0‑1* optimization with a linear objective after product linearisation, we can pose it as an MILP.

**Variables**

- `h_i ∈ {0,1}`  for `i = 0,…,n‑1`.
- `w_{i,ℓ} ∈ [0,1]` for each admissible pair `(i,ℓ)` with `i+ℓ < n`.  
  `w_{i,ℓ}` is intended to equal `h_i·(1‑h_{i+ℓ})`.

**Constraints (McCormick for binary case, which becomes exact)**  

```
w_{i,ℓ} ≤ h_i
w_{i,ℓ} ≤ 1 – h_{i+ℓ}
w_{i,ℓ} ≥ h_i – h_{i+ℓ}
```

- **Shift constraints**  
  For each shift `ℓ`  

```
Σ_{i=0}^{n‑ℓ‑1} w_{i,ℓ} ≤ t .
```

- **Measure constraint** `Σ_i h_i = n/2`.
- Boxing: `0 ≤ h_i ≤ 1` (automatically enforced by binary type) and `0 ≤ w_{i,ℓ} ≤ 1`.

**Objective**: `minimise t`.

**Symmetry‑breaking** (optional, speeds up MIP)

- Force `h_0 = 1` (we can always translate the set without affecting the objective).  
- Force `h_{n‑1} = 0` (break reflection symmetry).  

**Solver**: Use `cvxpy` with the CBC solver (`Solver='CBC'`).  
Pass a time limit: `cbc_params['maxSeconds'] = remaining_time`.  
If the solver finds a feasible integer solution before the limit, extract the binary `h` and compute the exact `C5`.  
If the solver only returns a *best‑so‑far* feasible solution (CBC provides this), we still keep it.

Because the MILP size is roughly `n·(n+1)/2 ≈ 16 300` binary variables plus the same number of continuous `w` variables, solving for `n = 120` typically completes within 30–60 seconds on a single core; for `n = 180` it may be near the time limit, hence we switch to `n = 120` only if the remaining budget is ≤ 90 s.

If Stage D produces a better `C5` than Stage C, we replace the current best solution.

### 4. Implementation Sketch (top‑level structure)

```text
run(seed=42, budget_s=600, **kwargs):
    start_time = time.time()
    rng = np.random.default_rng(seed)

    # 1. Choose n adaptively (start with 180, possibly shrink if time low)
    n = 180
    dx = 2.0 / n

    # 2. Stage A – generate candidate binaries
    candidates = []
    candidates.extend(random_half_filled(rng, n, count=20))
    candidates.extend(beatty_sequences(rng, n, slopes=grid_around_0.5))
    candidates.extend(gap_limited_sequences(rng, n, max_gap=3, count=10))
    candidates.extend(block_repeat_sequences(n, max_block_len=8))

    # 3. Evaluate all candidates, keep best K=5
    best_seeds = select_top_k(candidates, k=5)

    # 4. Stage B – targeted binary improvement
    best_h_bin, best_S = None, np.inf
    for h0 in best_seeds:
        h_opt, S_opt = binary_targeted_improvement(h0, rng, time_limit=remaining())
        if S_opt < best_S:
            best_h_bin, best_S = h_opt, S_opt

    # 5. Check bound
    C5_cur = best_S * dx
    if C5_cur <= 0.3807:
        return (best_h_bin.tolist(), C5_cur, n)

    # 6. Stage C – continuous gradient descent
    h_cont = best_h_bin.astype(float)           # warm start
    h_cont, C5_cont = continuous_gradient_descent(h_cont, dx, time_limit=remaining())
    if C5_cont < C5_cur:
        best_h, best_C5 = h_cont, C5_cont
    else:
        best_h, best_C5 = best_h_bin, C5_cur

    # 7. Stage D – exact binary MILP (if time remains > 30 s)
    if remaining() > 30:
        n_milp = 120                               # smaller for tractability
        best_h_milp, C5_milp = solve_binary_milp(n_milp,
                                                warm_start=best_h,
                                                time_limit=remaining())
        if C5_milp < best_C5:
            # upscale to original n by linear interpolation (preserves integral)
            best_h = upscale(best_h_milp, n)
            best_C5 = C5_milp

    return (best_h.tolist(), best_C5, n)
```

All helper functions (`random_half_filled`, `beatty_sequences`, `gap_limited_sequences`, `binary_targeted_improvement`, `continuous_gradient_descent`, `solve_binary_milp`, `upscale`, `remaining`) are defined **at module level** (no closures). Each respects the time budget by checking `time.time()` after critical loops.

### 6. Anticipated Failure Modes & Mitigations  

| Failure Mode | Why it can happen | Mitigation |
|--------------|-------------------|------------|
| **MILP trivial solution (all `w = 0`)** | If `h` is allowed to be fractional, McCormick relaxation under‑estimates product. | Use *binary* `h` variables for the MILP; the three McCormick constraints become exact, eliminating the trivial relaxation. |
| **Gradient descent stalls at a non‑optimal local minimum** | Non‑convex landscape; projection may keep us in a basin. | Introduce occasional *random perturbations*: after every `500` iterations add a small random bump (±0.02) to a random subset of entries and re‑project. |
| **Swap loop in Stage B never finds improving pair** | When `M1` or `M0` empty. | Fall back to a *random* 1‑0 swap; accept if it does not increase the max count by more than `+1`. This injects diversity. |
| **Time‑budget overrun** | MILP or gradient loops could overrun. | Each stage checks remaining time via a helper `remaining()` and breaks early; MILP is called only if at least `30 s` remain. |
| **Infeasible projection after gradient step** (all variables at bounds yet sum mismatched) | Rare, but can happen after an aggressive step. | Reduce step size (`η ← η/2`) and retry; if still infeasible, revert to previous iterate. |
| **Numerical overflow in correlation** | Using `np.int64` for large `n` is safe (max sum ≤ n). | Keep correlation in `int64`; convert to `float` only for final `C5` computation. |
