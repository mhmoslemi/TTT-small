### 1.  Problem reformulation (discrete setting)

* Let `n` be an even integer (the number of sample points).  
* `h ∈ [0,1]^n` is the step‑function sampled on a uniform grid,  
  `dx = 2 / n`.  
* The overlap for a discrete shift `ℓ ∈ {-(n‑1),…,n‑1}` is  

\[
a_\ell(h)=\sum_{i=0}^{n-1} h_i\bigl(1-h_{i+\ell}\bigr)\,dx ,
\qquad
h_{i+\ell}=0\;\text{if}\;i+\ell\notin[0,n-1].
\]

The objective required by the competition is  

\[
C_5(h)=\max_{\ell} a_\ell(h).
\]

We must **minimise** `C5` under the linear constraints  

\[
0\le h_i\le 1,\qquad\sum_{i=0}^{n-1}h_i = n/2 .
\]

### 2.  Smooth surrogate for the max‑operator

The max is non‑differentiable, so we replace it by a log‑sum‑exp
approximation with a temperature parameter `β>0`:

\[
f_\beta(h)=\frac{1}{\beta}\,
\log\!\Bigl(\sum_{\ell} \exp\bigl(\beta\,a_\ell(h)\bigr)\Bigr).
\]

When `β→∞`, `fβ → maxℓ aℓ`.  For moderate `β` the function is smooth,
strictly convex in each direction and its gradient can be written in closed
form.

Define the *unnormalised weights*

\[
w_\ell=\exp\bigl(\beta\,a_\ell(h)\bigr),\qquad 
\tilde w_\ell=\frac{w_\ell}{\sum_m w_m}\; .
\]

The derivative of a single overlap term (ignoring the constant `dx`
which does not affect the optimisation) is  

\[
\frac{\partial a_\ell}{\partial h_j}=1-
\mathbf 1_{j+\ell<n}\,h_{j+\ell}
-\mathbf 1_{j-\ell\ge0}\,h_{j-\ell},
\]

where the indicator functions enforce the zero‑padding at the borders.
Consequently

\[
\nabla f_\beta(h)_j
   =\sum_{\ell}\tilde w_\ell\Bigl(1-
      h_{j+\ell}{\bf 1}_{j+\ell<n}
      -h_{j-\ell}{\bf 1}_{j-\ell\ge0}\Bigr).
\]

The weight vector `\tilde w` is a probability distribution,
hence the term `∑ℓ \tilde wℓ = 1`.  Therefore the gradient can be
computed as  

\[
\nabla f_\beta(h)_j
   = 1 - \sum_{\ell>0}\tilde w_\ell\bigl(
        h_{j+\ell}\ {\bf 1}_{j+\ell<n}
      + h_{j-\ell}\ {\bf 1}_{j-\ell\ge0}\bigr)
     -\tilde w_0\;(2h_j).
\]

All sums are linear combinations of *shifted* copies of `h`.  They can be
evaluated efficiently by a **single correlation** between the weight
vector `\tilde w` and the current `h` (and also with the reversed weight
vector for the “left‑shift” part).  With `numpy` this costs
`O(n log n)` using FFT, which is negligible for the modest `n` we will use
(`n ≤ 200`).

### 3.  Projection onto the feasible set  

After an unconstrained gradient step we must return to

\[
\mathcal{S}= \Bigl\{h\in\mathbb R^n\;:\;
0\le h_i\le 1,\;\sum_i h_i = n/2\Bigr\}.
\]

`𝑆` is a *bounded simplex*.  Its Euclidean projection has a closed‑form
“water‑filling” algorithm:

1. Find a scalar `λ` such that  

   \[
   \sum_{i=0}^{n-1} \operatorname{clip}\bigl(v_i-λ,\,0,\,1\bigr)=n/2,
   \]

   where `v` is the point after the gradient step.
2. The projected point is  

   \[
   h_i^{\text{new}}=
   \operatorname{clip}\bigl(v_i-λ,\,0,\,1\bigr).
   \]

The scalar `λ` can be obtained by a simple bisection because the left‑hand
side is a monotone decreasing function of `λ`.  Ten‑to‑twenty iterations
are sufficient to reach machine precision; the cost is `O(n log ε)` and
negligible compared with the gradient evaluation.

### 4.  Continuation on the temperature β

A high `β` gives a very sharp approximation of the max but creates many
local minima.  We therefore **start with a low temperature** (e.g. `β=1`)
to explore a smooth landscape, then **increase β geometrically** (multiply
by `γ≈1.3` every few hundred iterations) until a final value
`β_max≈30–40` is reached.  At each temperature we run a few hundred
gradient steps, re‑initialising the step size after each temperature jump.

The step size `α` is kept constant (`α≈0.2`) while `β` is low and is
reduced geometrically (`α←α·0.98`) as `β` grows, which stabilises the
iterations near the non‑smooth regime.

```
    # ---------- gradient step ----------
    v ← h - α * grad
    # ---------- projection ----------
    h ← projection_onto_bounded_simplex(v, target_sum)

    # ---------- schedule ----------
    if iteration % refresh == 0:
        β ← min(β*γ, β_max)
        α ← max(α*0.98, α_min)
```

All operations are vectorised; a single iteration for `n≈120` finishes in
well under a millisecond, so several ten‑thousands of iterations comfortably
fit inside the 600 s budget.

### 6.  From fractional to binary – rounding + local polishing

The optimisation described above yields a *fractional* vector `h*`
that typically satisfies the constraints and already attains a very low
value of `C5` (often below the current record).  
To obtain a legitimate **step‑function** we perform a deterministic
rounding:

1. Sort the indices by descending `h*_i`.  
2. Set the highest `n/2` entries to `1`, the rest to `0`.  
   The resulting binary vector `h_bin` obeys the exact sum constraint.

Because rounding may increase the overlap, we subsequently **polish**
`h_bin` with a fast *pair‑swap hill‑climber* that works directly on the
correlation array:

*Maintain the full correlation* `corr = np.correlate(h_bin, 1‑h_bin, 'full')`.  
When swapping a `1` at position `i` with a `0` at `j`, the change of
`corr` can be updated in `O(n)` time (the contribution of the two changed
positions to every shift is recomputed analytically; the formula is the
same as the one used in the analysis section of the previous solution).
After each accepted swap we also update the current maximum `C5`.

The hill‑climber runs until **no improving swap** is found after a full
pass over a random sample of `O(n)` candidate pairs, or until the remaining
time is below a small threshold.  This deterministic refinement typically
improves the bound by a few thousandths, often pushing the binary solution
below the target `0.3807`.

### 7.  Multi‑restart and time management

* **First stage** (smooth optimisation) is run **three times** with different
  random seeds; each run is limited to 30 % of the total budget.  
  The best `h*` among the three is kept.
* **Second stage** (round‑and‑polish) is performed on the best fractional
  solution; the hill‑climber is allowed the remaining time (≈ 30 % of the
  budget).  
  If the hill‑climber terminates early we can restart it from a fresh
  random binary initialisation and keep the best result observed so far.

All timing checks are performed with `time.time();` the function returns
as soon as the remaining budget would be insufficient for the next major
iteration.
