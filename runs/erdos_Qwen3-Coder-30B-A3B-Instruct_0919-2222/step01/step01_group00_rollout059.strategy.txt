### 2. Global stochastic search – Simulated Annealing (SA)

**Why SA?**  
* Works with non‑convex, non‑smooth objectives.  
* Easy to enforce the exact sum‑constraint by moving *mass* between two blocks (increase one, decrease another).  
* Provides a simple “any‑time” improvement mechanism that can be stopped at any moment.

#### 2.1. State representation
`state = h_s` – the `S` block heights (always kept feasible by projection after each move).

#### 2.2. Move generation (mass‑swap)
1. Pick two distinct block indices `i ≠ j`.  
2. Choose a random `δ` uniformly in `[-δ_max, δ_max]`.  
3. Propose `h_s' = h_s.copy(); h_s'[i] += δ; h_s'[j] -= δ`.  
4. Project `h_s'` onto the capped simplex (ensures `0≤h_s'≤1` and the sum constraint).  
5. Compute `Δ = obj(h_s') – obj(h_s)`.  

The projection step automatically discards illegal proposals, so the acceptance test only sees a feasible neighbour.

#### 2.3. Temperature schedule
*Initial temperature* `T0` chosen so that typical `Δ` values are accepted with probability ≈ 0.8. Empirically set `T0 = 0.1 * (obj_initial)`.  
*Cooling*: geometric decay `T ← α·T` with `α = 0.997` per iteration.  
*Stopping*: when `T` falls below `1e‑4` or the allotted time slice (≈ 0.35 · budget) ends.

#### 2.4. Acceptance rule
Metropolis: accept if `Δ ≤ 0` or with probability `exp(-Δ/T)` (Δ is positive because we minimise).  

#### 2.5. Multiple independent chains
Run **3** chains sequentially, each with a fresh random seed and a different `δ_max` (e.g. `0.2`, `0.1`, `0.05`). Keep the best overall state. The total time spent on SA is limited to ≈ 30 % of the overall budget.

### 3. Local refinement – Projected Gradient Descent (PGD) with smoothed max

The SA chain typically ends near a basin of attraction, but the solution can often be pushed a little further by following the gradient of a *smooth* approximation of the max‑correlation.

#### 3.1. Smoothed max (log‑sum‑exp)
For a vector `c = full_corr(h)`, define

```
smooth_max(c; α) = (1/α) * log( Σ_i exp(α * c_i) )
```

When `α → ∞` this converges to the true max. We start with a modest `α₀ = 5` and increase it geometrically (`α ← 1.5·α`) after every few PGD epochs, ending near `α = 200`.

#### 3.2. Gradient of smooth_max w.r.t. h
Let `w_i = exp(α * c_i) / Σ_j exp(α * c_j)`.  
For a given shift `k` (corresponding to index `i` in `c`), the correlation entry is

```
c_k = Σ_t h[t] - Σ_t h[t] * h[t+k]   (out‑of‑range indices are ignored)
```

Derivative w.r.t. a component `h[p]`:

```
∂c_k / ∂h[p] = 1
               - (h[p+k] if p+k < n else 0)
               - (h[p‑k] if p‑k ≥ 0 else 0)
```

Thus the gradient of `smooth_max` is

```
∇_h = Σ_k w_k * ( 1 - h_shift_plus(p,k) - h_shift_minus(p,k) )
```

All three terms can be built with vectorised shifts (using `np.roll` with zero‑fill masks). The computational cost is `O(S·n)` per gradient, negligible compared to the FFT correlation.

#### 3.3. PGD iteration
1. Compute `h = repeat(h_s)`.  
2. Evaluate `c = full_corr(h)` and `w` from the current `α`.  
3. Build gradient `g` as above (vector of length `n`).  
4. Collapse the gradient onto the block‑level: `g_s = average of g over each block`.  
5. Update `h_s ← h_s – η·g_s` with a diminishing step‑size `η` (start `η₀ = 0.05`, multiply by `0.95` every epoch).  
6. Project `h_s` back onto the capped simplex.  
7. Repeat for a fixed number of epochs (≈ 200) or until time expires.

The PGD phase occupies roughly the next **30 %** of the budget (after SA). Because the objective is non‑convex, we may restart PGD from the best SA state a few times with different `α₀` to avoid poor local minima.

### 4. Binary‑only hill‑climb (fallback / complementary search)

Binary patterns (`h[i] ∈ {0,1}`) are a classic restricted version of the problem. They are cheap to evaluate and sometimes beat continuous solutions for this specific constant.

#### 4.1. Initialisation
Generate a random binary vector with exactly `n_points/2` ones (uniform random permutation of a fixed‑weight vector).

#### 4.2. Swap move
Pick a random `i` with `h[i]=1` and a random `j` with `h[j]=0`. Swap the values (`h[i]=0`, `h[j]=1`). Compute the new objective using the fast FFT correlation.  

If the new `C5` is **strictly smaller**, keep the swap; otherwise reject.  

Perform this greedy hill‑climb for a large number of iterations (e.g. `5·n_points·10⁴`). Keep the best binary vector seen.

#### 4.3. Time allocation
Run the binary hill‑climb in the final **15 %** of the budget. If it discovers a solution with `C5` ≤ current best, replace the incumbent.

Binary patterns can be converted to a continuous step function simply by using the binary vector itself (no projection needed). The final result is automatically feasible.

### 6. Expected performance & failure mitigations

| Potential issue | Mitigation |
|-----------------|------------|
| **Projection failure** (no feasible λ) | The capped‑simplex algorithm stops when the feasible interval for λ collapses; in that case fall back to a simple scaling `(h * (target_sum / np.sum(h)))` followed by clipping and a second scaling pass. |
| **SA stagnation** | Use three independent chains with decreasing `δ_max`. Also schedule occasional “restart” moves where `δ` is drawn from a larger range (e.g. `0.5`) with probability `0.01`. |
| **PGD divergence** | The step‑size is reduced geometrically; if an iteration increases the objective, undo the step and halve `η`. |
| **Overflow in log‑sum‑exp** | Subtract `max(c)` before exponentiation (`exp(α*(c - c_max))`). |
| **Time overrun** | Every major loop (`SA`, `PGD`, binary) checks the remaining budget before starting a new epoch. The algorithm can stop early and still return a valid incumbent. |
| **Discrete resolution limit** | If after the allotted budget the bound is still > 0.3807, increase `S` (e.g. to 16) and rerun only the PGD phase on the retained best SA state – this is cheap because PGD works on the already‑good region. |
| **Numerical noise in FFT** | Use `np.fft.rfft` / `irfft` with `dtype=np.float64`. After the inverse transform, clip tiny negative values (`<0`) to zero before taking the max. |

### 7. Why this strategy is “materially different”

* **Parameter reduction** – instead of optimizing all `n_points` variables (as in the SLSQP code), we optimise a low‑dimensional block‑height vector (`S≈14`). This changes the landscape dramatically and allows powerful global optimisation (SA, DE) that would be prohibitive in 70‑dim space.
* **Exact feasibility via projection** – the previous approach used equality constraints inside the optimiser; we keep every iterate feasible, eliminating penalty tuning and avoiding infeasible intermediate states.
* **Fast FFT‑based correlation** – reduces evaluation cost from `O(n²)` to `O(n log n)`, enabling thousands of objective evaluations per second.
* **Smooth max surrogate** – provides a gradient where the original max is nondifferentiable, something the SLSQP routine never used.
* **Hybrid stochastic‑deterministic pipeline** – combines SA (global exploration), PGD (local gradient‑driven polishing), and a dedicated binary hill‑climb (discrete exploration). The previous script only used repeated SLSQP restarts.
* **Time‑aware orchestration** – explicit budgeting and early‑exit guarantees a usable answer even under the tight 600 s limit.

By exploiting these ideas the algorithm can explore a much larger, better‑structured search space and is expected to find step functions with `C5` ≤ 0.3800, comfortably beating the target 0.3807.
