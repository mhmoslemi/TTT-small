### 1. Mathematical reformulation

For a discrete vector `h ∈ ℝⁿ` with step size `dx = 2/n` the overlap for shift `s` (integer offset `s∈{−(n‑1)…(n‑1)}`) is  

```
F_s(h) = Σ_{i∈I_s} h_i (1 − h_{i+s})            (1)
```

where `I_s` is the set of indices for which both `i` and `i+s` lie in `[0,n‑1]`.  
`C₅(h) = dx·max_s F_s(h)` is the quantity to minimise.

Define the **smooth surrogate** of the max:

```
L_β(h) = (1/β)·log Σ_s exp(β·F_s(h))            (2)
```

For `β → ∞`, `L_β → max_s F_s`. For moderate `β` the function is differentiable; we can compute its gradient analytically and use it in a projected gradient scheme. We will raise `β` gradually (annealing) so the iterates first improve a softened objective and later focus on the true maximum.

---

### 2. Feasible set and projection

The constraints are:

* Box: `0 ≤ h_i ≤ 1` (componentwise).
* Linear equality: `Σ_i h_i = n/2`.

The Euclidean projection of an arbitrary vector `z` onto this intersection is performed by a **water‑filling** (dual) algorithm:

1. Clip `z` to `[0,1]` obtaining `ẑ`.
2. If `Σ ẑ = n/2` we are done. Otherwise find a scalar `λ` such that  
   `Σ_i clip(z_i − λ, 0, 1) = n/2`.  
   This is a monotone 1‑D root‑finding problem; a simple bisection on `λ ∈ [−1,1]` converges in < 30 iterations.

The projection routine is called after each gradient step.

### 3. Gradient of the smooth surrogate

From (1),

```
∂F_s/∂h_i =   {  1 − h_{i+s}      if i∈I_s
                −h_{i−s}        if i−s∈I_s
                0               otherwise }                (3)
```

For each shift `s` we pre‑compute the index pairs `(i, i+s)` once (they never change).  

The gradient of the surrogate (2) is a weighted sum of the per‑shift gradients:

```
∇L_β(h) = Σ_s  w_s(β) · ∇F_s(h)                      (4)
```

with softmax weights  

```
w_s(β) = exp(β·F_s) / Σ_t exp(β·F_t) .
```

Because `w_s` sum to 1, the constant part “`+1`” from the derivative of `Σ_i h_i` appears as a uniform `+1` vector in every `∇F_s`. Equation (3) therefore translates into the following vectorised update for a given shift `s` and its weight `w`:

```
grad[i]   += w·(1 − h[j])
grad[j]   += w·(−h[i])
```

with `(i,j)` the pre‑computed index pair for shift `s`.  
For `s = 0` the two contributions collapse into `grad[i] += w·(1 − 2·h[i])`, as required.

All gradients are accumulated in a single NumPy array `grad`.

### 4. Algorithm outline

1. **Parameter choices**
   * Number of discretisation points `n` – a compromise between flexibility and speed.  
     Recommended `n = 80` (dx ≈ 0.025).  
   * Target sum `S = n/2`.  
   * Initial step size `η₀ = 0.3` (will be attenuated).  
   * Soft‑max schedule: start `β = 1.0`, increase multiplicatively every `T_β` iterations (e.g. `β ← min(β·1.2, 100)`).  
   * Maximum iterations `MAX_IT = 40 000` (adjusted to the remaining wall‑clock time).  

2. **Initial construction**
   * Use a *triangular* shape that already respects the integral:  
     `h_i = max(0, 1 − |x_i − 1|)` where `x_i = (i+½)·dx`.  
   * Scale it to satisfy the exact sum constraint by the projection routine (a single pass).  
   * Evaluate its `C₅` – this gives a baseline lower than the constant construction.

3. **Main optimisation loop**
   ```
   h ← initial vector
   best_h ← h ; best_val ← C₅(h)
   for it = 1 … MAX_IT
       if elapsed time > 0.94·budget : break
       
       # 1) compute raw overlaps F_s
       corr = np.correlate(h, 1−h, mode='full')   # length 2n−1, gives F_s
       
       # 2) compute soft‑max weights
       max_corr = max(corr)
       w = exp(β·(corr−max_corr))
       w /= sum(w)   # normalised
       
       # 3) gradient accumulation (vectorised using pre‑computed index lists)
       grad = ones_like(h)                     # constant part from Σ_i h_i
       for each shift s with weight w_s:
           (i, j) = index_pair[s]              # pre‑computed numpy slices
           grad[i] += w_s·(−h[j])              # −h_i·h_j term
           grad[j] += w_s·(−h[i])
           # the “+1” has already been added globally
       
       # 4) step size schedule
       η = η₀ / sqrt(it)                       # diminishing steps
       
       # 5) gradient step and projection
       h_new = h − η·grad
       h = project_onto_box_and_sum(h_new, S)  # maintains feasibility
       
       # 6) occasional improvement check
       if it % 200 == 0:
           val = C₅(h)                         # real max (multiply by dx)
           if val < best_val:
               best_val = val ; best_h = h.copy()
           
           # 7) stochastic perturbation (to escape shallow minima)
           if random()<0.05:
               # pick two random indices a,b with different values
               δ = min(0.1, h[a], 1−h[b])      # small transfer amount
               h[a] -= δ ; h[b] += δ
               h = project_onto_box_and_sum(h, S)
       
       # 8) anneal β
       if it % T_β == 0: β = min(β·1.2, 100)
   ```

4. **Multiple restarts**
   * After finishing the first run, store the best vector.  
   * Launch a second run using a **perturbed copy** of the best vector as the new initial point (add Gaussian noise of amplitude 0.02 and re‑project).  
   * Run the same loop for a reduced iteration budget (e.g. ‑½ of the remaining time).  
   * Keep the overall best across all restarts.

5. **Final polishing (optional)**
   * With the best discrete solution fixed, run a short **local coordinate search**:
     - Randomly pick three indices `i, j, k`.  
     - Transfer a tiny amount `δ` from `i` to `j` while compensating with `k` to keep the sum exact.  
     - Accept the move if `C₅` decreases; otherwise reject.  
   * Do this for a few thousand cheap trials to shave off the last few 1e‑4 of the objective.

6. **Return**
   * Output the best vector `best_h`, the associated bound `best_val = C₅(best_h)`, and `n`.

### 5. Numerical choices & optimisation tricks

| Component | Reasoning |
|-----------|------------|
| `n = 80` | Gives 40 % more degrees of freedom than the baseline `n=42` while keeping each iteration cheap (≈ 0.01 s). |
| Pre‑computed index pairs | Avoids rebuilding `np.arange` arrays each iteration → speeds up the inner gradient loop by a factor ~3. |
| Soft‑max annealing (`β` up to 100) | Starts with a smooth landscape that is easier to descend, then tightens to the true max. |
| Diminishing step `η = η₀/√t` | Guarantees convergence of a sub‑gradient type method while still allowing early rapid movement. |
| Projection via bisection | Guarantees exact satisfaction of the equality constraint; the box is enforced automatically. |
| Periodic stochastic perturbations | Helps to escape plateaus where the gradient becomes (almost) zero because many shifts share the same value. |
| Multiple restarts with noise | The objective is highly non‑convex; restarting from a good neighbourhood but with a perturbed start often discovers a deeper basin. |
| Final coordinate‑wise polishing | Pure gradient steps cannot change the support pattern efficiently; tiny local swaps can still improve the max. |

### 6. Anticipated failure modes & mitigations

| Potential issue | Symptom | Mitigation |
|-----------------|---------|------------|
| **Gradient explosion** (large `β` with out‑of‑range values) | NaNs or `inf` in `grad` → crash or divergence. | Clamp `β` growth; if `np.isnan(grad).any()` occurs, roll back `β` to previous value and reduce step size. |
| **Projection stall** (no feasible point after a large step) | `project` returns the same vector, progress stops. | Enforce a maximum step size (`η ≤ 0.5`) and perform a line‑search: try `η, η/2, η/4 …` until projection changes the vector. |
| **All shifts have identical `F_s`** (flat landscape) | Gradient becomes just the constant `+1` vector → trivial increase of all entries, then projection clamps them, no improvement. | Detect when `max(F)−min(F) < 1e‑6`; increase temperature (reduce `β`) temporarily or inject a random perturbation. |
| **Time overrun** | The loop does not finish before the budget. | Continuously monitor elapsed time; break when `elapsed > 0.94·budget`. Use the last saved `best_h`. |
| **Getting stuck in a local minimum** | No improvement for thousands of iterations. | Trigger an early restart: re‑initialise `h` by adding Gaussian noise, keep the best‐so‑far as a reference, and restart the gradient loop. |
