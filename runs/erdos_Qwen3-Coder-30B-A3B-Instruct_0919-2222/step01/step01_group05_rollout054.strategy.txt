#### 1.2 Linearisation of the bilinear term
For every (i,d) with a valid overlap we enforce the McCormick envelope for a product of two binary variables:

```
zᵢ,ᵈ ≤ bᵢ
zᵢ,ᵈ ≤ bᵢ₊₍₍d₎₎
zᵢ,ᵈ ≥ bᵢ + bᵢ₊₍₍d₎₎ – 1
```

Because bᵢ,bᵢ₊₍₍d₎₎ are binary, these three inequalities force `zᵢ,ᵈ = bᵢ·bᵢ₊₍₍d₎₎`.

```
s_d = Σ_{i=0}^{n‑d‑1} zᵢ,ᵈ            (for d ≥ 0)
```

For negative shifts we obtain the same value due to symmetry, so we only need d = 0,…,n‑1.

Introduce a single scalar `t` and enforce

```
t ≥ w – s_d     for every d = 0,…,n‑1 .
```

Because `dx` is a constant factor, minimising `t` is equivalent to minimising the true bound `C₅`.

* z‑variables: Σ_{d=1}^{41} (n‑d) = 861  
* s‑variables: 42  
* total binary variables ≈ 945 – easily handled by modern MIP solvers.

#### 1.8 Result of Stage 1
The solver yields a binary vector `b*`.  
Exact bound:
```
C5_binary = ( w – min_d s_d ) * dx = max_d ( w – s_d ) * dx .
```
If `C5_binary` ≤ 0.3807 we can stop and return `b*` (converted to float).  
Otherwise we continue to Stage 2.

--------------------------------------------------------------------
### 2. Fractional refinement (continuous local search)

The binary optimum is usually *almost* optimal; a tiny redistribution of the unit mass can improve the worst‑shift overlap because the formulation `C₅(d)=w–Σ hᵢhᵢ₊₍₍d₎₎` is strictly decreasing when the product term grows.

We therefore treat `h` as a continuous vector, initialise it with the binary optimum (`h = b*`), and run a **simulated‑annealing mass‑transfer** algorithm that respects the two hard constraints.

#### 2.1 Move definition
1. Randomly pick two distinct indices `i` (currently > 0) and `j` (currently < 1).  
2. Choose a transfer amount `δ` uniformly in  
   `δ ∈ (0, min(hᵢ, 1‑hⱼ, Δ))`, where `Δ` is a decreasing bound (start Δ = 0.2).  
3. Update  
   `hᵢ ← hᵢ – δ` , `hⱼ ← hⱼ + δ`.  
   This automatically preserves the total sum Σhᵢ.

The move keeps all components inside `[0,1]` by construction.

#### 2.2 Objective evaluation
Compute the exact bound:
```
corr = np.correlate(h, 1‑h, mode='full')
C5 = max(corr) * dx .
```
`dx = 2.0 / n`.  
The evaluation is O(n²) but for n ≤ 60 it costs only a few microseconds.

#### 2.3 Acceptance rule (Metropolis)
Let `C5_cur` be the current bound, `C5_new` the bound after the move.

```
if C5_new ≤ C5_cur:   accept
else:                 accept with probability exp( -(C5_new‑C5_cur)/T )
```

Temperature schedule (geometric cooling):
```
T_k = T0 * α^k    with  T0 = 0.02 * C5_binary   and   α = 0.995 .
```
The schedule is tied to the iteration counter `k`.  

The cooling is stopped early if no improvement has been seen for a large number of steps (e.g. 5000).

#### 2.4 Projection (optional safety)
If rounding errors push Σhᵢ away from `n/2` by more than 1e‑9, renormalise:
```
h ← h * (n/2) / Σh .
```
Clipping after scaling restores the box constraints.

#### 2.5 Termination
Run the SA loop until the overall time budget is exhausted (remaining time after the MILP phase).  
Keep the best vector ever encountered (`best_h`, `best_C5`).

--------------------------------------------------------------------
### 3. Multi‑grid strategy (optional but cheap)

The MILP‑plus‑SA pipeline is executed for a short list of grid sizes, e.g.

```
grid_sizes = [42, 48, 60]
```

* For each `n` we repeat Stage 1 (MILP) with the same time budget allocation (≈ 0.35 · budget).  
* The best result among all `n` is returned.

Because the objective depends only on the *ratio* λ/(n‑d), a different discretisation can sometimes produce a slightly better fractional overlap; trying a few modestly larger `n` is therefore worthwhile and still cheap.

--------------------------------------------------------------------
### 4. Final post‑processing

1. **Exact normalisation** – after the SA phase, enforce the integral exactly:
   ```
   h ← h * (n/2) / np.sum(h)
   ```
   Clip any entry that drifted outside `[0,1]` back into the interval (the drift is at most 1e‑12).

2. **Bound recomputation** – compute the final C₅ using the full correlation routine given in the problem statement.

3. **Return** – `(h, C5, n)` where `h` is a NumPy 1‑D array of length `n`.
