### 1. Mathematical reformulation

For each integer shift `s∈{-(n‑1)…(n‑1)}` let  

```
f_s(h) = Σ_{i∈I_s} h[i]·(1‑h[i+s])         (no dx factor)
```

where `I_s` are the indices where both `i` and `i+s` lie in `[0,n‑1]`.  
`C5 = dx·max_s f_s(h)`.

Minimising the max is equivalent to **minimising a smooth approximation of the max**, e.g. the soft‑max (log‑sum‑exp) or a temperature‑scaled weighted sum:

```
Lβ(h) = Σ_s w_s(β)·f_s(h) ,   w_s = exp(β·(f_s‑max_f))/Σ_t exp(β·(f_t‑max_f))
```

When β→∞, the weights concentrate on the worst shift, so minimising `Lβ` drives `max_s f_s` down.

The constraints are linear (box and one equality). The gradient of each `f_s` is simple:

```
∂f_s/∂h[i] =  1  – h[i+s]          if i∈I_s  (first term)
∂f_s/∂h[i+s] = –h[i]               if i∈I_s  (second term)
```

Thus for a given weight `w_s` the contribution to the full gradient is


### 2. Projection onto the feasible set

After a gradient step we must enforce  

* box: `0 ≤ h ≤ 1`  
* equality: `Σ h = target = n/2`   (since `dx·Σ h = 1`).

Projecting onto the intersection of a hyperplane and a box can be done by a **water‑filling (1‑D root‑finding) algorithm**:

1. Start from the unconstrained point `z = h – α·grad`.  
2. Find a scalar `λ` such that `proj_i = clip(z_i – λ, 0, 1)` satisfies `Σ proj_i = target`.  
3. Solve for `λ` with a fast bisection (the function `Σ clip(z_i – λ,0,1) – target` is monotone).  
4. Return `proj`.

This projection is exact (up to numeric tolerance) and cheap (O(n) per iteration).

### 8. Anticipated failure modes and mitigations

1. **Overshooting** – Large step sizes may push many entries to the box limits, causing gradient stalling. Mitigation: adopt diminishing step schedule and monitor the norm of the gradient; if `||grad||` is huge, reduce `α_t`.

2. **Soft‑max collapse too early** – If `β` grows too fast, weights concentrate before the iterate has moved, effectively optimizing a noisy max and getting stuck. Mitigation: keep `β` low for the first few thousand iterations, then increase slowly.

3. **Projection stagnation** – For a given `z`, the water‑filling root may be at the box boundaries causing many entries stuck at 0 or 1, limiting movement. Mitigation: add a small random jitter before projection (e.g., `z += 1e‑4·randn`) to keep interior.

4. **Numerical overflow in exp** – When `β` is large, `exp(β·(c‑max_c))` can underflow. Use the subtraction of `max_c` (already in plan) and, if needed, clamp the exponent to a safe range.

5. **Binary SA poor scaling** – Full correlation recomputed each swap is O(n²); keep `n` modest (≤100) and limit SA iterations to a few tens of thousands.

6. **Time budget overflow** – All loops contain a time‑check; the outer loop stops before the deadline, and any long‑running subroutine (e.g., final SLSQP) is limited with its own `maxiter` and early abort if time is low.
