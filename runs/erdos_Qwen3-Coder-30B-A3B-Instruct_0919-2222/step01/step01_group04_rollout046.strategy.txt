**Overall Idea – Max‑Min Reformulation**  
The quantity to be minimized is  

\[
C_{5}(h)=\max_{k}\int_{0}^{2}h(x)\bigl(1-h(x+k)\bigr)\,dx
        =1-\min_{k}\int_{0}^{2}h(x)h(x+k)\,dx .
\]

Thus we need a step function \(h\) (average value \(½\)) whose *auto‑correlation*  
\(\displaystyle R(k)=\int_{0}^{2}h(x)h(x+k)\,dx\) is as large as possible for every shift \(k\).  
The problem is therefore a **max‑min quadratic program**:
\[
\max_{h\in[0,1]^{N}}\;\;\min_{k\neq0} \;R(k)
\quad\text{s.t.}\quad \sum_{i}h_i = N/2,
\]
where we discretise \(h\) on \(N\) points (the supplied `initial_h_values` gives \(N=70\)).  

The algorithm below tackles the problem in two very different phases:
1. **Discrete max‑min search** (binary vectors) to obtain a strong combinatorial “seed”.
2. **Continuous refinement** of a smoothed version of that seed by a *projected Adam sub‑gradient* method, with an optional soft‑max smoothing of the max‑operator.

This is fundamentally different from the earlier L‑BFGS/Nelder‑Mead pipeline – it uses a combinatorial hill‑climb, a low‑dimensional global search, and a custom projection/Adam loop.

### 1. Discrete Seed: binary max‑min optimisation

1. **Parameterisation**  
   Work with a binary vector \(b\in\{0,1\}^{N}\) with exactly \(N/2\) ones (the integral constraint becomes \(\sum b_i=N/2\)).

2. **Objective for binary vectors**  
   For a shift \(k\) the overlap is the integer count  
   \[
   T_k(b)=\sum_{i}b_i\,b_{i+k},
   \]
   where the sum is taken over the overlapping indices only (exactly what `np.correlate(b,b,'full')` returns).  
   The binary max‑min problem is \(\max_{b}\;\min_{k\neq0} T_k(b)\).

3. **Random sampling**  
   Generate a large number (e.g. 20 000) of random binary vectors by selecting uniformly at random a set of \(N/2\) positions.  
   Keep the vector with the highest \(\min_k T_k\). This gives a good baseline in a few seconds.

4. **Hill‑climbing / simulated‑annealing improvement**  
   Repeatedly propose a swap of a “1’’ at index \(i\) with a “0’’ at index \(j\).  
   *Fast evaluation*: after each swap recompute the full correlation with `np.correlate` (cost \(O(N^2)\) with \(N=70\) is negligible).  
   Accept the swap if it strictly increases \(\min_k T_k\); otherwise accept with a probability \(\exp\!\bigl((\Delta)/\tau\bigr)\) where \(\tau\) is a temperature that is slowly cooled (e.g. geometric schedule).  
   Stop the annealing after a fixed time budget (≈ 10 % of the total budget) or when no improvement occurs for several hundred proposals.

5. **Result** – a binary pattern \(b^\star\) with a maximal worst‑case overlap \(\tau_{\text{bin}}:=\min_k T_k(b^\star)\).

At this point \(\tau_{\text{bin}}\) is usually ≈ 17–18 (the theoretical average for binary is ≈ 17.25).  This seed already beats a random start and will be the basis for the continuous phase.

### 2. Continuous Seed: smoothing the binary pattern

The binary pattern is too “spiky’’; by smoothing we raise the pairwise products while respecting the box constraints.

1. **Triangular kernel** – convolve the binary vector with  
   \[
   w = \bigl[0.25,\;0.5,\;0.25\bigr].
   \]  
   The convolution is performed with `mode='same'` (zero padding on the ends).  
   The resulting vector \(h^{(0)}\) takes values only in \(\{0,\tfrac13,\tfrac23,1\}\).

2. **Projection onto the feasible set**  
   After smoothing we project onto the set  
   \[
   \mathcal{F}=\bigl\{h\in[0,1]^{N}\;\big|\;\sum_i h_i=N/2\bigr\}.
   \]  
   This is done by a simple one‑dimensional root‑find for a scalar \(\lambda\):  
   \[
   \hat h_i = \operatorname{clip}\!\bigl(h^{(0)}_i+\lambda,\;0,\;1\bigr),\qquad
   \sum_i\hat h_i = N/2 .
   \]  
   Because the left‑hand side is monotonically increasing in \(\lambda\), a binary search (≈ 50 iterations) converges quickly to machine precision.

3. **Optional multi‑kernel start** – repeat the above with a wider kernel (e.g. \([0.1,0.2,0.4,0.2,0.1]\)) and keep all produced seeds for the next phase.  This yields several diverse starting points without extra cost.

### 3. Continuous Refinement – Projected Adam on the max‑overlap

#### 3.1 Sub‑gradient of the max‑overlap

For a given vector \(h\) let  

\[
f_k(h)=\sum_{i\in I_k} h_i\bigl(1-h_{i+k}\bigr),
\qquad
C_5(h)=\max_k f_k(h),
\]  

where \(I_k=\{i\mid 0\le i,i+k<N\}\).  
If \(k^\star\) is a shift attaining the maximal value (there may be several), a sub‑gradient of \(C_5\) is the average of the gradients of the active shifts:

\[
\partial C_5(h)=\frac{1}{|A|}\sum_{k\in A}\nabla f_k(h),\qquad  
A=\{k\mid f_k(h)=C_5(h)\}.
\]

The gradient of a *single* shift can be built in **\(O(N)\)** time:

```text
grad = 0
if k >= 0:
    i = 0 … N‑k‑1
    grad[i]            += 1 - h[i+k]      # derivative w.r.t. the “left’’ entry
    grad[i+k]          -= h[i]            # derivative w.r.t. the “right’’ entry
else:
    k = -k
    i = k … N‑1
    grad[i]            += 1 - h[i‑k]
    grad[i‑k]          -= h[i]
```

The formula already respects the fact that the linear term \(\sum_i h_i\) disappears for indices outside the overlap region.

#### 3.2 Smooth max (optional)

To avoid the non‑smoothness of the pure max, replace it by a **log‑sum‑exp**:

\[
\Phi_\alpha(h)=\frac{1}{\alpha}\log\!\Bigl(\sum_k e^{\alpha f_k(h)}\Bigr),
\]

with a modest \(\alpha\) (e.g. 8–12).  
Its gradient is a weighted sum of the per‑shift gradients, where the weights are the soft‑max probabilities.  This gives a smoother descent direction while still driving down the worst overlap.

Both options can be toggled; the pure max works well together with occasional random perturbations, while the smoothed version helps in the very early stage.

#### 3.3 Adam update with projection

1. **Adam state** – maintain first‑moment \(m\) and second‑moment \(v\) vectors (both initialise to zero).  
2. **Learning‑rate schedule** – start with a relatively large step (e.g. \(\eta_0=0.1\)) and decay it as \(\eta_t=\eta_0/(1+\gamma t)\) (with \(\gamma\approx10^{-4}\)).  
3. **Update rule** (for iteration \(t\))  
   \[
   m \gets \beta_1 m + (1-\beta_1)\,\partial C_5(h),\qquad
   v \gets \beta_2 v + (1-\beta_2)\,\bigl(\partial C_5(h)\bigr)^2,
   \]
   \[
   \hat m = m/(1-\beta_1^{t}),\quad
   \hat v = v/(1-\beta_2^{t}),
   \]
   \[
   h \gets h - \eta_t \,\frac{\hat m}{\sqrt{\hat v}+ \epsilon }.
   \]  
   Typical Adam parameters: \(\beta_1=0.9,\;\beta_2=0.999,\;\epsilon=10^{-8}\).

4. **Projection** – after the Adam step project the updated vector back onto \(\mathcal{F}\) using the same scalar‑\(\lambda\) bisection described in section 2.2.

5. **Acceptance & bookkeeping** – compute the current \(C_5\).  If it improves the best value seen so far, store the vector as `best_h`.  Keep a running timer; stop when the overall time budget (≈ 600 s) is reached.

#### 3.4 Exploration mechanisms

* **Noise injection** – every few hundred iterations add a small Gaussian jitter (\(\sigma\approx0.02\)) to the current iterate, project, and continue.  This helps escape shallow local minima.
* **Multi‑start** – run the Adam loop for a few thousand iterations from each of the seeds generated in step 2 (different kernels, also a random continuous start).  The total number of iterations is limited so that the overall wall‑clock stays under the budget; the best final `best_h` over all runs is returned.
* **Early‑stop heuristic** – if the improvement in the last \(M\) iterations is below a tolerance (e.g. \(10^{-6}\)), re‑initialise from the current best with a fresh Adam state to allow a different descent trajectory.

### 4. Evaluation & Return

*After the optimisation loop finishes*:
1. Compute the final bound with the supplied evaluator (or the same `np.correlate` routine):  

   \[
   C_5^{\text{final}} = \max_k\bigl(\text{corr}(h,1-h)\bigr)\times\frac{2}{N}.
   \]  

2. Return the tuple `(h, C_5^{\text{final}}, N)`.  
   The vector `h` already satisfies all constraints because every iteration ends with a projection onto \(\mathcal{F}\) and box clipping.

### 6. Anticipated Failure Modes & Mitigations

| Failure mode                              | Symptom                               | Mitigation                                                                            |
|-------------------------------------------|---------------------------------------|---------------------------------------------------------------------------------------|
| **Projection stalls** – λ‑search fails to reach the target sum because many components are stuck at 0 or 1. | `np.sum(w)` never crosses the target during bisection. | Initialise the bisection interval wider (`lo = -max(v)-5`, `hi = 1-min(v)+5`). The monotonicity guarantees convergence. |
| **Gradient vanishes** – after many iterations all entries are at a box bound, so the sub‑gradient becomes zero. | No further improvement despite many iterations. | Inject Gaussian noise periodically; also restart Adam moments to avoid momentum lock‑in. |
| **Getting trapped in a poor local minimum** – a single start may converge to ~0.383. | Repeated runs produce the same bound. | Use the binary seed (which already pushes the worst‑overlap up) and multiple smoothing kernels; also run a few short differential‑evolution searches in the 10‑dimensional block‑parameter space to provide diverse seeds. |
| **Numerical overflow in soft‑max** – for large α the exponentials blow up. | NaNs in the gradient. | Clamp the exponentials: subtract the max \(f_k\) before exponentiation (`exp(α*(f‑max_f))`). |
| **Time overrun** – too many iterations or too many seeds. | The function is killed before returning. | Constantly check `time.time()` after each outer iteration; allocate a fixed time slice to each stage (binary, global low‑dim search, Adam). |
| **Violation of the integral constraint** after rounding or clipping. | Returned `h` does not sum to `N/2`. | The final projection step guarantees the sum exactly; verify a final sanity check before return. |

### 7. Summary of the Workflow

1. **Read** the global `initial_h_values` to obtain \(N\).  
2. **Binary max‑min search** (random sampling + annealed hill‑climb) → \(b^\star\).  
3. **Smooth** \(b^\star\) with one or two kernels → initial continuous vectors \(\{h^{(0)}_j\}\).  
4. **Project** each \(h^{(0)}_j\) onto \(\mathcal{F}\).  
5. **For each start** run a **projected Adam** loop:  
   - evaluate the worst shift(s);  
   - compute sub‑gradient (or soft‑max weighted gradient);  
   - Adam update;  
   - project onto \(\mathcal{F}\);  
   - record the best‑ever \(C_5\).  
   - inject noise periodically.  
6. **Stop** when the wall‑clock reaches the supplied budget (≈ 600 s).  
7. **Return** the best vector found together with its \(C_5\) value and \(N\).

This approach combines a combinatorial max‑min seed, explicit control of the integral constraint via a fast scalar projection, and a modern first‑order optimizer that directly targets the worst overlap.
