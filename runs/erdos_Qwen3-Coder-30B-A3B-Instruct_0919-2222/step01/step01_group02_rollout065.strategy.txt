### Overview  
The task is to produce a step‑function `h` on `[0,2]` (discretised with `n` points) that respects  

* `0 ≤ h[i] ≤ 1` for all `i`  
* `∑_i h[i]·dx = 1`  (with `dx = 2/n`, i.e. `∑_i h[i] = n/2`)  

and minimises  

```
C5(h) = max_k  dx·∑_i h[i]·(1 – h[i+k])          (zero‑padded correlation)
```

The previously used method was a simple simulated‑annealing walk.  
The new strategy replaces that by a **deterministic global optimisation pipeline** built around **exact binary/MILP formulation**, **continuous LP relaxation**, and a **sequential convex‑concave refinement**.  The three phases operate on the same mathematical model, so every improvement is guaranteed to respect the original constraints.

### 1. Mathematical model common to all phases  

For a fixed even `n` define the shift operator  

```
(S_d h)[i] = h[i+d]    if 0 ≤ i+d < n, else 0 .
```

The correlation for integer shift `d` is  

```
C(d) = dx·( ∑_i h[i] – ∑_i h[i]·h[i+d] )
     = dx·( n/2 – Q(d) )                     (because ∑_i h[i] = n/2)
```

where  

```
Q(d) = ∑_i h[i]·h[i+d] .
```

The optimisation problem is therefore  

```
minimise    t
subject to  t ≥ dx·( n/2 – Q(d) )   for every d = -(n-1)…(n-1)
            0 ≤ h[i] ≤ 1
            ∑_i h[i] = n/2 .
```

The difficulty lies in the bilinear terms `h[i]·h[i+d]`.  They will be linearised in the next sections.

### 2. Exact binary / MILP formulation  

#### 2.1 Variables  

* `h_i` – binary (`0` or `1`), for each grid point `i`.  
* `y_{i,d}` – auxiliary binary variables meant to equal `h_i·h_{i+d}` for every admissible pair `(i,d)`.  
* `t` – real, the upper bound on `C5`.

#### 2.2 Linearisation of the product  

For each `(i,d)` with `0 ≤ i < n` and `0 ≤ i+d < n` add the classic McCormick (for binary variables) constraints  

```
y_{i,d} ≤ h_i
y_{i,d} ≤ h_{i+d}
y_{i,d} ≥ h_i + h_{i+d} – 1
y_{i,d} ≥ 0 .
```

Because all variables are binary, these four inequalities force `y_{i,d}` to equal the logical AND `h_i ∧ h_{i+d}` exactly.

#### 2.3 Objective and shift constraints  

For each shift `d` the quadratic sum `Q(d)` becomes a linear sum `∑_i y_{i,d}`.  
Add a linear inequality  

```
t ≥ dx·( n/2 – ∑_i y_{i,d} ) .
```

(The zero‑padding is naturally handled because the index set for each `d` automatically excludes out‑of‑range pairs.)

#### 2.4 Solving  

* Build the MILP for a modest `n` (e.g. `n = 60`‑`70`).  The number of auxiliary variables is `≈ n²/2` (≈ 2000 for `n=64`), which is well within the capabilities of open‑source MILP solvers (CBC, GLPK, SCIP).  
* Impose a **per‑solve wall‑clock limit** (e.g. 30 s).  If a solver finishes earlier it returns the optimal binary pattern; otherwise we keep the best incumbent found when the time expires.  

The binary solution is a feasible `h` (exactly 0/1) for the original problem, and its true `C5` can be computed immediately.  In many experiments binary patterns of this size already achieve `C5 ≈ 0.376–0.378`.  If the MILP fails to finish in the allocated time, the pipeline proceeds to the next phase.

### 3. Continuous LP relaxation (fallback & warm‑start)  

If the binary MILP is too expensive or still yields a `C5` above the target, relax the integrality:

* Keep the same variables and constraints **except** allow `h_i ∈ [0,1]` and `y_{i,d} ∈ [0,1]`.  
* The McCormick inequalities become a *convex hull* of the product; they are linear and keep the model a pure linear program.  

Solve the LP with a fast simplex/dual‑simplex solver (GLPK, CLP).  The LP gives:

* A **lower bound** on the optimal `t` (because the relaxation can only improve the objective).  
* A **fractional `h`** that already satisfies all problem constraints, ready for further refinement.

Because the LP is tiny compared with the MILP (the same number of variables but only linear constraints), it typically finishes in a few seconds even for `n = 100`.

### 4. Sequential Convex‑Concave (SCC) refinement  

The LP solution may contain many interior fractional values.  To drive `h` toward a truly low `C5`, we apply a deterministic iterative scheme that **linearises the bilinear terms around the current iterate** and solves a linear program in each outer iteration.

#### 4.1 Linearisation of each quadratic term  

At iteration `k` we have a current vector `h^{(k)}`.  For any shift `d`

```
Q(d) = ∑_i h_i·h_{i+d}
     ≈   ∑_i [ h_i^{(k)}·h_{i+d}^{(k)}
            + h_i^{(k)}·(h_{i+d} – h_{i+d}^{(k)})
            + h_{i+d}^{(k)}·(h_i – h_i^{(k)}) ] .
```

All terms on the right‑hand side are **affine** in the decision variables `h`.  Denote this linear approximation by `Ĥ(d, h)`.

#### 4.2 Updated LP  

Create a fresh LP with variables `h_i` (continuous, boxed) and `t`.  For every shift `d` add

```
t ≥ dx·( n/2 – Ĥ(d, h) ) .
```

All other constraints (`0 ≤ h_i ≤ 1`, `∑ h_i = n/2`) remain unchanged.  Solve the LP; the solution `h^{(k+1)}` is guaranteed to **not increase** the true `C5` (the linearisation is a global over‑approximation of the original quadratic term).

#### 4.3 Trust‑region safeguard  

To avoid large, potentially destabilising steps, optionally add box constraints of the form  

```
|h_i – h_i^{(k)}| ≤ δ   for all i,
```

with a modest `δ` (e.g. `0.1`) that is gradually relaxed as the iteration proceeds.  This turns the LP into a *trust‑region* refinement, preserving monotonicity while allowing the algorithm to escape shallow plateaus.

#### 4.4 Stopping criteria  

* **Improvement threshold** – stop when the reduction in `t` between successive iterations falls below `1e‑5`.  
* **Time budget** – abort as soon as the global 600 s limit is approached.  

The SCC loop converges very quickly (usually < 5 000 iterations for `n ≈ 80`), each iteration requiring a single LP solve (the same size as the relaxation).

### 5. Bisection on the objective (feasibility tightening)  

Having a candidate `h` with value `C*`, we can try to push the bound lower by a **binary search on `t`**:

1. Set `low = 0`, `high = C*`.  
2. While `high – low > ε` (e.g. `ε = 5·10⁻⁴`):  
   * Let `mid = (low + high) / 2`.  
   * Fix `t = mid` and solve the **feasibility LP** (same constraints as the relaxation, but with `t` fixed).  
   * If the LP is feasible, set `high = mid`; otherwise `low = mid`.  

The feasibility LP is much cheaper than the full optimisation because `t` is now a constant.  When the loop ends, the last feasible `h` is guaranteed to satisfy the tighter bound `high`.  If the resulting `high` is already below the target `0.3807`, we can stop immediately.

### 6. Final polishing – constrained stochastic hill‑climb  

The SCC‑refined `h` is already a high‑quality solution, yet a small amount of *local random search* can shave off the last few thousandths:

* **Swap move** – pick two indices `i, j` with `h[i] ≠ h[j]` and exchange a tiny amount `Δ` (e.g. `Δ = 0.02`) while keeping the sum unchanged (`h[i]←h[i]–Δ`, `h[j]←h[j]+Δ`).  
* **Gaussian jitter** – add a zero‑mean Gaussian perturbation (σ ≈ 0.03) to the whole vector and re‑project onto the box‑sum polytope (the same bisection projection used earlier).  
* Accept the move only if the true `C5` (computed via the correlation formula) improves; otherwise reject.  

Run this loop for the remaining seconds of the budget (normally ≤ 30 s).  Because the search space is low‑dimensional and the feasibility projection is cheap, thousands of trial moves can be evaluated, reliably polishing the bound by ≤ 0.001.
