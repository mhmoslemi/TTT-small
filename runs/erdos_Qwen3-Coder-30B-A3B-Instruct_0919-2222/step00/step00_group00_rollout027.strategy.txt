### Overview  
We solve the Erdős minimum‑overlap problem by **exactly linearising the quadratic objective**, turning it into a **mixed‑integer linear programme (MILP)**, and letting a modern MIP solver (CBC, GLPK, … via CVXPY) find a provably good binary step‑function.  The MILP gives us a high‑quality *feasible* solution for a modest discretisation; we then *polish* that solution with fast O(n) swap updates and optionally repeat the whole pipeline on a finer grid obtained by up‑sampling.  The approach is fundamentally different from pure hill‑climbing or smooth‑max gradient descent: it uses a deterministic linearisation, global branch‑and‑bound search, and exact McCormick constraints for the product terms.

---

### 1.  Discretisation and decision variables  

* Choose an even number of sample points `n`.  Typical values start with `n = 80` (≈ 160 ms for a single correlation) and may be increased later to `n = 120` or `n = 160` if time permits.  
* Let `h_i ∈ {0,1}` for `i = 0,…,n‑1` be the binary step‑function values.  
* For every *ordered* pair `(i,j)` that can appear together in a correlation term – i.e. for each shift `k = j‑i` with `0 ≤ i < n`, `0 ≤ j < n` – introduce an auxiliary binary variable  

```
y_{i,j}  ≈  h_i · h_j .
```  

Because both factors are binary, the classical McCormick (big‑M) constraints are **exact**:

```
y_{i,j} ≤ h_i
y_{i,j} ≤ h_j
y_{i,j} ≥ h_i + h_j – 1
y_{i,j} ≥ 0 .
```

Only pairs with `j = i+k` for a given shift `k` are needed; this reduces the total number of `y` variables from O(n²) to the sum over all shifts of the overlap length, i.e. `∑_{k=-(n-1)}^{n-1} (n–|k|) = n²`.  In practice we store them as a flat vector indexed by `(i,k)` to avoid a full matrix.

* The **mass constraint** `∑_i h_i = n/2` enforces the integral condition `∫_0^2 h = 1`.

* To break the global flip symmetry `h ↔ 1−h`, fix the first entry, e.g. `h_0 = 1`.  This does not affect the optimum because any optimal solution can be mirrored; it merely halves the search tree.

---

### 2.  Linear expression of each overlap  

For a shift `k` (integer number of sample steps, ranging from `-(n‑1)` to `+(n‑1)`) the discrete overlap integral equals

```
c_k = Σ_{i=0}^{n-1} h_i·(1 – h_{i+k}) ,   where the term is omitted if i+k is out of bounds.
```

Using the auxiliary `y` variables we write

```
c_k = Σ_i h_i  –  Σ_{i : 0≤i,i+k<n} y_{i,i+k} .
```

The first sum `Σ_i h_i` is a constant `n/2` for every feasible point, so it can be dropped from the optimisation objective; only the second sum matters.

---

### 3.  Min‑max formulation  

Introduce a scalar variable `M ≥ 0` that upper‑bounds every shift overlap:

```
for every shift k:
    Σ_i h_i  –  Σ_{i : i+k∈[0,n)} y_{i,i+k}  ≤  M .
```

Because the constant `Σ_i h_i = n/2` is known, the left‑hand side reduces to `n/2 – Σ y_{i,i+k}`.  Minimising `M` therefore maximises the *minimum* self‑intersection and directly minimises the discrete analogue of `C₅`.

The complete MILP is:

```
minimise   M

subject to
    h_i ∈ {0,1}                     ∀i
    y_{i,j} ∈ {0,1}                 ∀valid (i,j)
    y_{i,j} ≤ h_i
    y_{i,j} ≤ h_j
    y_{i,j} ≥ h_i + h_j – 1
    Σ_i h_i = n/2
    h_0 = 1                         (symmetry break)
    n/2 – Σ_{i : i+k∈[0,n)} y_{i,i+k} ≤ M   ∀ shifts k
    M ≥ 0 .
```

All constraints are linear; the model is a pure MILP.

### 4.  Building the model with CVXPY  

* **Variables**  
  - `h = cp.Variable(n, boolean=True)`  
  - `y = cp.Variable(num_pairs, boolean=True)` (flattened index).  
  - `M = cp.Variable(nonneg=True)`.  

* **Constraints**  
  - Mass: `cp.sum(h) == n/2`.  
  - Symmetry: `h[0] == 1`.  
  - McCormick: for each pair `(i, j)` add the three linear inequalities listed above.  
  - Overlap bounds: for each shift `k` compute the linear expression `n/2 - cp.sum(y[indices_for_shift_k])` and enforce `≤ M`.  
  - Box on `h` is implicit in the boolean type; `y` are also boolean, guaranteeing exact product.

* **Solver invocation**  
  - Use `cp.CBC` (or `GLPK_MI`) selectable via CVXPY, because they handle pure integer models.  
  - Pass a **time limit** (e.g. `solver_args={'maxSeconds': remaining_time}`) so the solver returns the best incumbent if full optimality is not reached within the allotted budget.  
  - Request the solver to keep the best feasible solution (`MIPGap` tolerance can be left at default).

Because the model size grows quadratically with `n`, we deliberately start with `n = 80`.  For `n = 80` the number of `y` variables is `80·(80+1)/2 ≈ 3 200`; the total constraint count stays well below 10 000, which CBC can process in tens of seconds.

### 5.  Extracting a candidate step‑function  

When the solver finishes (optimally or with an incumbent), read the binary values of `h`.  Compute the true overlap bound:

1. Convert `h` to a NumPy array of floats.  
2. Compute the full correlation `c = np.correlate(h, 1‑h, mode='full')`.  
3. The discrete bound is `Ĉ = (c.max() * dx)`, where `dx = 2.0 / n`.

### 6.  Fast polishing of the binary incumbent  

Even though the MILP supplies a high‑quality binary solution, the branch‑and‑bound search may stop early, leaving room for cheap local improvement:

* **Data structures** – keep the correlation vector `c` and two Python sets `ONES` and `ZEROS`.  
* **Incremental update** – a swap of a `1` at index `i` with a `0` at index `j` changes `c` in O(n) using the same formulas employed in hill‑climbing methods:
  - For each `j ≥ i` add `‑1·(1‑h[j])` to `c[j‑i+off]`.  
  - For each `j ≤ i` subtract `‑1·h[j]` from `c[i‑j+off]`.  
  - Then repeat with `+1` for the second index `j`.  
  (`off = n‑1` is the shift offset.)

* **Targeted swap heuristic** – the current worst shift is `k* = argmax c`.  Build:
  - `A = {i∈ONES | i+k*∈[0,n) and h[i+k*] = 0}` (pairs that *contribute* to the worst overlap).  
  - `B = {j∈ZEROS | j+k*∈[0,n) and h[j+k*] = 1}` (pairs that would *reduce* it if turned on).  
  - If both sets are non‑empty, pick a random `i∈A`, `j∈B` and perform the swap.  This guarantees a reduction of the worst overlap by exactly 1 unit in the correlation count.

* **Fallback random swaps** – if `A` or `B` is empty, sample a random `(i,j)` pair from `ONES×ZEROS` and accept the swap only when `max(c)` does not increase.  

* **Iteration budget** – continue swapping until either no improving swap is found for a full sweep of `|ONES|·|ZEROS|` attempts, or the global time budget is within a safety margin (2 s).  

Because each swap is O(n) and `n ≤ 160`, millions of swaps easily fit in the remaining time.

### 7.  Multi‑resolution continuation  

After polishing at size `n₁`, we can generate a **finer discretisation** `n₂ = 2·n₁`:

1. **Upsample** the binary pattern by repeating each entry `r = n₂ / n₁` times (`r` is an integer).  The upsampled array automatically satisfies the integral constraint because the number of ones doubles proportionally.
2. Feed this upsampled pattern as a *warm start* to a new MILP with `n = n₂`.  In CVXPY we can initialise the variables `h` and `y` with the previous values (boolean to boolean).  The solver then starts from a feasible point close to a good optimum, often converging faster.
3. Run the same MILP‑+‑polish pipeline for the larger `n`.  Because the problem size roughly quadruples, we allocate a smaller portion of the remaining budget (e.g. 1/3 of the remaining seconds) to each larger grid.

Iterating this refinement yields increasingly smooth step‑functions; the max overlap generally drops or remains stable because the finer grid permits more nuanced placement of the `1` blocks.
