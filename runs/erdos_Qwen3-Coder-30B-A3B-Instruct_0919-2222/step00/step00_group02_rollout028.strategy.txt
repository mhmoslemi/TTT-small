**Algorithm**: *Successive Linear Programming (SLP) / Convex–concave Procedure*.

1. Initialise h^0 with a feasible vector (perhaps the `initial_h_values` or a random balanced vector).
2. For iteration t:
   - For each shift k, compute current product term p_{i,k} = h_i^t h_{i+k}^t.
   - Linearize the quadratic term around h^t: for current shift, the function f_k(h) = -∑_i h_i h_{i+k} is approximated by its first order Taylor expansion:
   
   \[
   f_k(h) ≈ f_k(h^t) + \nabla f_k(h^t)^\top (h - h^t),
   \]
   
   where \(\nabla f_k\big|_{h^t} = -(h_{i+k}^t, i=0,...,n-1) - (h_{i-k}^t, i=0,...,n-1)\) (with out‑of‑bounds treated as 0).
   - Build a **convex linear program** that minimises the maximum of these linear approximations plus the constant term ∑ h_i ensures the objective. Introduce an auxiliary variable t to bound all linear approximations:
   
   \[
   \begin{aligned}
   \min_{h,t} \; t\\
   \text{s.t. } & \sum_i h_i - \bigl[ f_k(h^t) + \nabla f_k(h^t)^\top (h - h^t)\bigr]\le t,\quad \forall k,\\
           & 0\le h_i \le 1,\quad \forall i,\\
           & \sum_i h_i = n/2.
   \end{aligned}
   \]
   
   This is a linear program because all terms are affine in h and t.
   - Solve the LP (cvxpy with ECOS/GLPK). Obtain new solution h^{t+1}.
3. Stop when improvement in t is below tolerance or after a fixed number of iterations (e.g., 30). The final h is feasible for the original problem (since we keep the exact constraints) and typically yields a low upper bound because at each iteration we tighten towards a stationary point.
4. Optionally perform a *polishing* step: treat the final h as a starting point for a short simulated‑annealing binary refinement (project to binary by rounding, then run the earlier local swaps). The combination often beats purely local methods.
