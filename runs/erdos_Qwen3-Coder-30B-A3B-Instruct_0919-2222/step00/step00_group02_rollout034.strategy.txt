### Overview  
The algorithm proceeds in three successive *layers* that are each based on a fundamentally different optimisation principle:

1. **Deterministic combinatorial seeds** – generate balanced binary vectors from mathematically known families (Legendre / quadratic‑residue sequences, m‑sequences, Beatty/irrational‑slope partitions).  
2. **Batch‑swap improvement via maximum‑matching** – for the current worst shift, solve a bipartite matching problem that simultaneously swaps as many mismatched (1,0)–(0,1) pairs as possible, thereby reducing the worst‑overlap by up to 2 per matched pair in a single iteration.  
3. **LP‑relaxation + projected soft‑max gradient refinement** – formulate a convex relaxation of the original max‑overlap problem with McCormick linearisations, solve it to obtain a high‑quality fractional vector, then polish it by a projected gradient descent on a smooth max‑overlap surrogate.

Each layer is time‑controlled; the best vector found at any stage is kept as the global answer.

### 1. Deterministic combinatorial seeds  

| Family | Construction (balanced) | Typical autocorrelation behaviour |
|--------|------------------------|------------------------------------|
| **Quadratic‑residue (Legendre)** | For prime \(p\equiv3\pmod4\) take the indicator of quadratic residues modulo \(p\); duplicate or truncate to reach an even length \(n\) and flip the last bit if necessary to obtain exactly \(n/2\) ones. | Autocorrelation values are either \(-1\) or a small constant; the maximum overlap is already close to the theoretical optimum. |
| **Maximum‑length m‑sequence** | Generate an LFSR of degree \(d\) with primitive polynomial; the period is \(2^{d}-1\). Truncate to the first \(n\) bits, then append the complement of the first bit to reach an even number of ones. | m‑sequences have two‑level autocorrelation (a large peak at shift 0 and a flat low value elsewhere). |
| **Beatty (irrational‑slope) partition** | Choose \(\alpha=\frac{\sqrt5-1}{2}\) (the golden ratio conjugate). Set \(a_i=1\) iff \(\lfloor i\alpha\rfloor\) is even, otherwise \(0\). Adjust by swapping a few bits to enforce exactly \(n/2\) ones. | Produces a sequence with a near‑constant distribution of distances between consecutive ones, which empirically yields low maximal overlap. |
| **Random balanced** | Shuffle a vector with \(n/2\) ones and \(n/2\) zeros. | Serves as a universal baseline. |

For every even length \(n\) in a pre‑chosen list (e.g.  
\(N=\{30,36,40,45,50,60,70,80,90,100,120,150,180,200\}\)), each family is instantiated (when possible) and the **max‑overlap count**  

\[
M(h)=\max_{k}\sum_{i}h_i\bigl(1-h_{i+k}\bigr)
\]

is computed via FFT‑based convolution (cost \(O(n\log n)\)).  
The best seed for each \(n\) (lowest \(M\)) is kept for the next layer.

### 2. Batch‑swap improvement using maximum‑matching  

#### 2.1. Rationale  
For a fixed shift \(s\) the term  

\[
M_s(h)=\sum_i h_i\bigl(1-h_{i+s}\bigr)
\]

counts ordered mismatches (1 followed \(s\) positions later by 0).  
If we identify a set of *disjoint* mismatched pairs \((i,j)\) with  

\[
h_i=1,\;h_{i+s}=0,\qquad
h_j=0,\;h_{j+s}=1,
\]

and swap the values at \(i\) and \(j\), each pair eliminates **two** mismatches for shift \(s\).  
Performing **all** such disjoint swaps simultaneously yields the maximal possible reduction of \(M_s\) in one iteration.

Finding the largest collection of disjoint pairs is exactly a **maximum bipartite matching** problem:

* Left side – indices \(i\) with \((h_i,h_{i+s})=(1,0)\).  
* Right side – indices \(j\) with \((h_j,h_{j+s})=(0,1)\).  
* Edge \((i,j)\) exists if swapping \(i\) and \(j\) does not create a conflict (i.e. \(i\neq j\) and the two pairs are distinct).  
Because any left node can be matched to any right node, the graph is complete bipartite; the matching reduces to taking \(\min(|L|,|R|)\) arbitrary pairs.  Nevertheless we keep the full Hopcroft–Karp implementation ( \(O(\sqrt{n}m)\) ) to stay general and to allow future extensions (e.g., weighted edges if we want to penalise impact on other shifts).

#### 2.2. Iterative scheme  

For a given seed vector \(h\):

1. Compute the full overlap vector \(O_k\) and locate the *worst* shift \(s^\* = \operatorname{argmax}_k O_k\).  
2. Build the sets \(L,R\) of mismatched positions for shift \(s^\*\).  
3. Run Hopcroft–Karp to obtain a maximum matching \(\mathcal{M}\).  
4. Apply all swaps in \(\mathcal{M}\) simultaneously, obtaining a new binary vector \(h'\).  
5. Re‑evaluate \(O_k\). If the new worst value \(M(h')\) is strictly smaller, accept the move and repeat from step 1.  
6. If the matching produces zero reduction (i.e. \(|\mathcal{M}|=0\) or the new worst value does not improve), fall back to a *single‑swap* local search (random 1↔0 swap accepted only when it does not increase the max).  

Because each accepted batch reduces the worst count by at least 2, the number of outer iterations is bounded by \(M_0/2\), where \(M_0\) is the worst count of the seed (typically < 50 for the families above).  The total work is therefore negligible compared with the later LP stage.

### 3. LP relaxation with McCormick envelopes + projected soft‑max gradient polishing  

#### 3.1. Convex relaxation  

Introduce continuous variables \(x_i\in[0,1]\) for the step heights and auxiliary variables  
\(w_{i,k}\) to represent the product \(x_i x_{i+k}\) (out‑of‑range indices are forced to 0).  
For each product we add the four McCormick linear constraints:

\[
\begin{aligned}
w_{i,k} &\ge 0,\\
w_{i,k} &\le x_i,\\
w_{i,k} &\le x_{i+k},\\
w_{i,k} &\ge x_i + x_{i+k} - 1 .
\end{aligned}
\]

The original max‑overlap condition  

\[
\sum_i x_i - \sum_i w_{i,k} \le t,\qquad \forall k,
\]

with a scalar variable \(t\) (the upper bound on the overlap) yields a **linear program**:

\[
\min\; t\quad\text{s.t.}\quad
\sum_i x_i = n/2,\;
0\le x_i\le 1,\;
\text{McCormick constraints},\;
\sum_i x_i - \sum_i w_{i,k}\le t.
\]

We build this model with `cvxpy` and solve it using the ECOS solver (fast for ≤ 80 variables; for larger \(n\) we limit the LP to the first 80 indices and keep the remainder fixed from the binary improvement step). The LP solution gives:

* a fractional vector \(x^\star\) that already satisfies the balance constraint,
* a lower bound \(t^\star\) on the achievable worst‑overlap.

Because the McCormick envelope is exact when the underlying variables are binary, the LP bound is often *tight* for the binary optimum; we therefore use \(x^\star\) as a warm start for the next stage.

#### 3.2. Projected soft‑max gradient descent  

Define the vector of exact overlaps  

\[
o_k(x)=\sum_i x_i\bigl(1-x_{i+k}\bigr)
\]

and the **soft‑max surrogate**

\[
F_\alpha(x)=\frac{1}{\alpha}\log\Bigl(\sum_{k}e^{\alpha\,o_k(x)}\Bigr),
\qquad \alpha>0.
\]

When \(\alpha\) is small the function is smooth and its gradient is well‑behaved; as \(\alpha\) grows the surrogate converges to the true max.  

**Gradient of a single shift** (derived analytically):  

\[
\frac{\partial o_k}{\partial x_i}=1-
\bigl[x_{i+k}\mathbf{1}_{i+k<n}+x_{i-k}\mathbf{1}_{i-k\ge0}\bigr].
\]

The gradient of the surrogate is a convex combination of these per‑shift gradients with weights

\[
p_k=\frac{e^{\alpha o_k}}{\sum_j e^{\alpha o_j}}.
\]

All components are computed with NumPy vectorised slices (no Python loops).

**Projection onto the feasible set** (box \([0,1]\) plus sum \(=n/2\)) is performed with a *water‑filling* algorithm:

* Find \(\lambda\) such that \(x_i^{\text{proj}} = \operatorname{clip}(v_i-\lambda,0,1)\) satisfies \(\sum_i x_i^{\text{proj}} = n/2\).  
* Because the sum is monotone in \(\lambda\), a binary search with 40 iterations yields machine‑precision \(\lambda\).  

**Continuation schedule**  
Start with \(\alpha_0=1\) and gradually increase (\(\alpha_{j+1}=2\alpha_j\)) up to \(\alpha_{\max}=80\). For each \(\alpha\) run a fixed number of gradient steps (e.g. 200) with step size \(\eta_t = \eta_0 / \sqrt{t+1}\) (\(\eta_0\approx0.2\)). After each step:

1. Compute the true worst overlap \(M(x)=\max_k o_k(x)\).  
2. If \(M(x) <\) current best, record the vector.  
3. If the step fails to improve after a full \(\alpha\) stage, halve \(\eta_0\) to increase stability.

The continuation from low to high \(\alpha\) guarantees that the iterates stay in a basin of the LP solution and converge rapidly to a vector whose true max overlap is ≤ the LP value plus a tiny numerical slack.

#### 3.3. Final polishing  

When the gradient phase terminates (either because the time budget is exhausted or the improvement stalls), we perform a **single‑swap clean‑up**:

* Identify the current worst shift \(s\).  
* Enumerate all mismatched pairs for \(s\) (as in layer 2) and test each swap individually; accept any that reduce the true max.  
* Iterate until no improving swap exists.

The resulting vector is the final candidate.

### 4. Time‑budget management  

The total wall‑clock budget (600 s) is split dynamically:

1. **Seed generation** – 5 % of the budget (≈ 30 s).  
   *Run every family for every \(n\) in the list; keep the best seed per \(n\).*
2. **Batch‑swap layer** – 20 % (≈ 120 s).  
   *Apply the matching‑reduction to the best seed of each \(n\) sequentially; stop early for an \(n\) once its worst count falls below the integer target \(\lfloor0.3807\,n/2\rfloor\).*
3. **LP + gradient layer** – remaining time (≈ 450 s).  
   *Process the lengths still not meeting the target, starting from the largest \(n\) (most promising for a fractional improvement). The LP for \(n\le80\) is cheap; for larger \(n\) we solve a *partial* LP on a sliding window of 80 variables while keeping the rest fixed. The gradient phase runs until the allocated time for that length expires or the improvement stalls.*

At any moment the algorithm checks `time.time()`; if the remaining time falls below a safety threshold (10 s) it aborts the current stage and returns the currently best vector.

Because the algorithm explores multiple lengths, multiple deterministic families, and both combinatorial and convex optimisation techniques, it explores a substantially larger region of the feasible space than a pure hill‑climbing or pure gradient approach. | Failure mode | Detection | Remedy |

| **Matching graph too dense (O(n²) edges)** for large \(n\) | Memory usage spikes or construction time > 0.1 s per iteration. | Switch to *greedy* matching: randomly pair mismatched 1s and 0s up to a fixed quota (e.g., 0.5 · min\(|L|,|R|\)). |

| **All deterministic families unavailable for a chosen \(n\)** | No prime‑based Legendre or primitive‑polynomial LFSR of appropriate length. | Fall back to the random balanced seed for that \(n\). |

All safeguards are lightweight and incur negligible extra cost.
