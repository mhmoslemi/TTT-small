**Overview**  
The task is to produce a step function \(h:[0,2]\to[0,1]\) with average \(1/2\) that minimises  

\[
C_5(h)=\max_{k\in\mathbb Z}\int_0^2h(x)\,\bigl(1-h(x+k)\bigr)dx .
\]

When the interval is discretised into \(n\) equally‑spaced points (\(dx=2/n\)) the problem becomes  

\[
\begin{aligned}
\text{minimise}&\qquad  t   \\
\text{subject to}&\qquad 
\underbrace{\sum_{i=0}^{n-1}h_i(1-h_{i+k})}_{O_k(h)}\le t\;,\qquad\forall k\in\{-n+1,\dots ,n-1\},\\
& 0\le h_i\le 1,\qquad\sum_{i=0}^{n-1}h_i=n/2 .
\end{aligned}
\tag{P}
\]

The only non‑convexity lies in the bilinear products \(h_i h_{i+k}\) inside each \(O_k\).
The proposed **materially new** methodology replaces the generic local‑swap / gradient
heuristics by a **structured convex relaxation + column generation** combined with a
**parametric Sturmian construction**.  The two pipelines run in parallel; the
better of the two final candidates is returned.

--------------------------------------------------------------------
### 1. Convex relaxation with McCormick envelopes and cutting‑plane (column‑generation)

#### 1.1. Reformulation  

Introduce an auxiliary variable for every product that appears in the constraints:

\[
w_{i,k}= h_i\,h_{i+k},\qquad 0\le i<n,\; -n+1\le k\le n-1,\; i+k\in[0,n-1].
\]

\(O_k\) becomes a linear expression in the new variables:

\[
O_k(h)=\underbrace{\sum_i h_i}_{=n/2}-\sum_i w_{i,k}.
\]

The bilinear relation is relaxed by the classic **McCormick envelope** (valid because
\(h_i\in[0,1]\)):

\[
\begin{aligned}
0 &\le w_{i,k}\le h_i,\\
0 &\le w_{i,k}\le h_{i+k},\\
w_{i,k} &\ge h_i+h_{i+k}-1 .
\end{aligned}
\tag{M}
\]

With (M) the constraints \(O_k\le t\) become linear in \((h,w,t)\).  The resulting
program is a **linear program (LP)**.

#### 1.2. Column‑generation (cutting‑plane) loop  

The LP contains one inequality for each shift \(k\).  Adding all \(2n-1\) constraints
would make the model large, but in practice **only a handful of “most dangerous”
shifts are active** at the optimum.  The algorithm therefore starts with a tiny
seed set \(K\subset\{-n+1,\dots,n-1\}\) (e.g. \(K=\{0,\pm1,\pm2\}\)) and iteratively
enriches it:

```
Initialize K = {0, ±1, ±2}.
repeat
    solve LP   (h, w, t)  with constraints only for k∈K.
    compute O_k(h) for *all* shifts k by evaluating the full convolution
        O_k = (n/2) - Σ_i h_i h_{i+k}   (use the current fractional h, no w needed)
    let k* = argmax_k O_k                # the worst shift for the current h
    if O_{k*} ≤ t + ε   stop (ε a tiny tolerance)
    else                add k* to K and repeat
```

Because each LP is modest (the number of auxiliary variables is \(|K|\cdot n\)),
modern open‑source LP solvers (`ECOS`, `GLPK`, `CBC` via `cvxpy`) solve it within
milliseconds even for \(n\) up to 250.  The loop converges in ≤ 10‑15 iterations
in practice: each iteration eliminates the current worst shift, and the bound
\(t\) monotonically decreases.

#### 1.3. Obtaining a feasible *fractional* vector  

When the loop stops we have a feasible point \((h^\star,t^\star)\) of the relaxed
problem with  

\[
C_5(h^\star)=\frac{2t^\star}{n}\;\le\; \text{target bound}.
\]

\(h^\star\) is fractional in general, but already respects every global constraint
(average ½, box constraints) and all the max‑overlap inequalities for the full
set of shifts (the last LP added the true worst shift, so the relaxed constraints
hold for *all* shifts).

#### 1.4. Dependent rounding that preserves the sum  

To turn the fractional solution into a legitimate step function we apply a **swap‑rounding**
procedure, a variant of *pairwise dependent rounding*:

1. While some entries are strictly between 0 and 1, pick a pair \((i,j)\) with
   \(0<h_i<1\) and \(0<h_j<1\) and **identical fractional part** (or simply any
   two non‑integral entries).
2. Let \(\delta=\min\{h_i,\,1-h_j\}\).  With probability \(\tfrac12\) set  
   \((h_i,h_j)\leftarrow (h_i-\delta,\,h_j+\delta)\); otherwise set  
   \((h_i,h_j)\leftarrow (h_i+\delta,\,h_j-\delta)\).
3. This operation preserves the total sum, never leaves the interval \([0,1]\), and
   moves at least one coordinate to an integer.

The process ends with a binary vector \(\hat h\) and exactly the same sum \(n/2\).
Because each rounding step changes the product \(h_i h_{i+k}\) by at most
\(\delta\) and because the McCormick envelope guarantees that the original
fractional \(w_{i,k}\) lay between the two extreme integral possibilities,
the rounding can worsen any overlap at most by a *controlled* amount.
Empirically the increase in \(t\) is ≤ 1 count (i.e. \(2/n\) in the final bound).

#### 1.5. Post‑rounding local improvement (optional)  

If the binary \(\hat h\) slightly exceeds the target bound, a very cheap
deterministic **worst‑shift swap** (same mechanic as in the earlier strategies)
is performed for at most a few hundred iterations to repair the occasional
increase.  Because the starting point is already near‑optimal, only a handful of
swaps are necessary.

### 2. Analytic parametric construction based on Sturmian (Beatty) sequences

A completely different line of attack uses a *closed‑form* family of 0/1 vectors
with excellent autocorrelation properties.  For an irrational slope
\(\alpha\in(0,1)\) define

\[
a_i(\alpha,\tau)=
\begin{cases}
1 &\text{if } \{i\alpha+\tau\}<\tfrac12,\\[2mm]
0 &\text{otherwise},
\end{cases}\qquad i=0,\dots,n-1,
\tag{S}
\]

where \(\{\cdot\}\) denotes the fractional part and \(\tau\in[0,1)\) is a
phase‑shift.  The sequence is a **Sturmian word** (a Beatty sequence) and,
by classical discrepancy theory, distributes the ones as uniformly as possible.
Its empirical autocorrelation \(\sum_i a_i a_{i+k}\) is known to be close to the
theoretical optimum for many \(k\).

#### 2.1. One‑dimensional optimisation of \(\alpha,\tau\)

For a fixed \(n\) we treat \(\alpha,\tau\) as continuous parameters and minimise

\[
F(\alpha,\tau)=\max_{k}|\,\tfrac12 n -\sum_i a_i(\alpha,\tau)a_{i+k}(\alpha,\tau)\,|
\]
(the inner quantity equals the overlap count \(O_k\) for a binary vector).  
Because \(a_i\) is piecewise constant in \((\alpha,\tau)\), \(F\) is a **step
function**; nevertheless its landscape can be explored efficiently by a
**grid‑search + refinement**:

1. Coarse grid: take \(M=200\) equally spaced values of \(\alpha\) in
   \([0.2,0.8]\) and \(L=100\) values of \(\tau\) in \([0,1)\).  For each pair compute
   the binary vector (via the simple rule (S)) and its max‑overlap.
2. Keep the best 10 % of candidates and perform a **local golden‑section search**
   separately on \(\alpha\) and \(\tau\) (the objective is cheap to evaluate: one
   correlation per evaluation).
3. The search terminates when the improvement over the last refinement step is
   < \(10^{-4}\) in the bound.

Because the construction is deterministic, the cost is entirely dominated by the
correlation evaluations, which are \(O(n^2)\) but cheap for \(n\le 300\).  The
resulting binary vector \(a^\star\) typically achieves a bound already **below
0.381** for moderate sizes (e.g. \(n=120\) gives a bound around 0.3795).

#### 2.2. Small‑scale local polishing  

Although Sturmian vectors are excellent, a few *targeted swaps* can shave off
the remaining slack:

* Run a light **worst‑shift swap** routine (single‑swap improvement, no annealing)
  for at most \(0.5n\) operations, starting from \(a^\star\).  
* Because the baseline is already very close to optimum, each accepted swap reduces
  the max‑overlap by exactly one count, and the process stops after a few dozen
  steps.

The final vector may be binary or, if the budget is exhausted, we keep the
fractional version obtained by **interpolating** the two neighbouring values of
\(\alpha\) (i.e. linearising the step at the optimum) to gain a fractional bound
slightly better than the integer one.

### 3. Orchestration and time‑budget handling

Both pipelines are **independent** and can be executed sequentially or in parallel
(if the platform permits a single process).  The orchestrator works as follows:

1. **Select a set of discretisation sizes** \(N=\{30,45,60,90,120,150,200\}\).  
   The list is ordered from small to large so that early cheap searches can
   already produce a useful bound.
2. **Allocate time**: give each \(n\) a quota proportional to its size, but reserve
   a final 30 s for the polishing stage.  The total never exceeds the 600 s limit.
3. **Run the LP‑column‑generation pipeline** for the current \(n\) until either
   (i) the bound drops below the target \(0.3807\) or (ii) the allocated time for
   that size expires.  Keep the best \((h,t)\) across all \(n\).
4. **Run the Sturmian‑search pipeline** for the *largest* \(n\) that still has at
   least 60 s remaining.  Because this pipeline is deterministic and cheap, it
   always finishes within its quota.
5. **Compare the two candidates** (LP‑derived binary after rounding vs. polished
   Sturmian binary).  Return the one with the smaller actual bound
   \(c_5 = 2t/n\) (or \(2\,\max_k O_k/n\) for the Sturmian vector).
6. **Safety net**: if, for any unexpected reason, no candidate improves on the
   pre‑loaded `initial_h_values`, return that vector together with its bound.
