    # For a shift k, k in [0, 2], corresponds to index = mid + k

    # Actually, let's reconsider. 
    # We're shifting h by k where k is in [0, 2], and we're correlating 
    # h(x) and (1 - h(x+k)); 
    # k ranges from -1 to +1 to cover full support overlaps (constant form).
    # For each positive shift k (in [0,1]), h(x) overlaps with 1 - h(x+k).

    # For a shift k, the cross term is h(x) * (1 - h(x+k))

    # But this is confusing - let's just extract what we need for k from -1 to +1
    # That spans dx to 1-dx in the temporal domain...
    
    # As per correlation definition, we get:
    # shift=-1 means h[0]*1-h[1] + h[1]*1-h[2] ... 
    # indices in the correlation_vector are 0 to 2*n_points-2
    # shift_k corresponds to index = mid + k
    # So shift from k=-1 to k=1 means indices mid-1 to mid+1
    # But to align with the actual problem definition: 
    # shift k from -1, -0.5, 0, 0.5, 1 corresponds to the output array
    # But since the shift is between -1 and 1 (so 3 shifts in total), 
    # and indices go from 0 to 2*n_points-2,

    # since correlation has 2*n-1 elements for n points:

    # But actually, to align with all shifts from -1, 0, 1

    # look at it as a function of shift, extract all valid shifts.
    # Indeed:
    # Correlation indices go: - (n_points-1) to + (n_points-1)
    # We want overlap for shifts from -1 to +1 on [0,2] domain.
    # This is what the full correlation will compute when we extract: 
    
    # What we want to compute:
    # C5 = max_k \int h(x)(1 - h(x+k)) dx, where k in [0,2]
    # If we think of h as a step function over intervals, 
    # and shift it by k in [0,2], that does give us an integration interval.
    # But in discrete correlation, when we compute, we associate a shift.
    # A way to extract the shifts reliably:
    # Let's calculate manually what those shifts are:
    # To get k = 0 to 2 (which approximates a small region)

    # k = 1 => index = (1/dx + n_points-1)

    # k = -1 => index = n_points*(-1/2 + 1) - 1 = n_points/2 - 1
    # k = 1 => index = n_points*(1/2 + 1) - 1 = 3*n_points/2 - 1

    # This gives middle (n_points) elements of correlation

    C5_values = correlation[significant_indices:end_idx] * dx

def evaluate_h_correct(h_values, n_points):
    """Corrected evaluation function using proper shift calculation."""
    dx = 2.0 / n_points
    
    # Compute the full correlation of h and 1-h
    corr = np.correlate(h_values, 1 - np.array(h_values), mode='full')
    
    # The full correlation array has length 2*n_points - 1
    # The shift between 0 and 2 translates to appropriate indices
    # The leftmost shift corresponds to index 0 of correlation
    # shift = (index - (n_points-1)) * dx
    # We want to find the maximum overlap for shift in [0,2]
    # This means we want to compare only those values where:
    # -1 <= shift <= 1 (for [0,2] interval with dx=2/n)
    # From the shift formula:
    # index = shift/dx + (n_points-1)
    # So shift in [-1, 1] => index in [-1/dx + n_points-1, 1/dx + n_points-1]
    # Since dx = 2/n_points, -1/dx = -n_points/2, 1/dx = n_points/2
    # So shift in [-1,1] => index in [n_points/2 - 1, 3*n_points/2 - 1]
    # We take the subsequence that corresponds to average overlap with shift in [0,2]
    # phrased differently: 
    # shift indices from -1 to +1 correspond to looking at 
    # correlations from middle of array displaced by approximately n_points/2 
    # but for [0,2], the shift k ranges from 0 to 2, which means offset from the
    # center (for dx = 2/n), corresponds to overlapping by shift in [-1, 1] (by symmetry)
    # Let's make sure we are looking at universal part
    
    mid_idx = len(corr) // 2  # This should be n_points-1
    # To get the overlap for all valid shifts, we can try to take 
    # indices from [-1 ... 1] which corresponds to
    # now to take indices correctly:
    
    # shift 0 would be index mid_idx
    # shift 1 would correspond to index mid_idx + n_points * 1 / 2  = mid_idx + n_points/2  
    #        where we split by dx = 2/n_points  
    # shift -1 would be index mid_idx - n_points/2
    
    # indexing: [mid_idx - n_points/2, mid_idx + n_points/2]
    start_idx = int(n_points/2) - 1
    end_idx = int(3*n_points/2) - 1
    if start_idx < 0:
        start_idx = 0
    if end_idx > len(corr):
        end_idx = len(corr)   
    if end_idx <= start_idx:
        return 0.0
    
    C5_values = corr[start_idx:end_idx] * dx
    return max(C5_values)
