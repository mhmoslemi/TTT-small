In the overlap region, both contributions are added. This is correct per our derivation.

Let me verify with n=3, p=0:
Role 1: m from 2 to 4. G[0, 2:5] = [1-h[0], 1-h[1], 1-h[2]]
Role 2: m from 0 to 2. G[0, 0:3] += [-h[2], -h[1], -h[0]]

G[0] = [-h[2], -h[1], (1-h[0])+(-h[0]), 1-h[1], 1-h[2]]
     = [-c, -b, 1-2a, 1-b, 1-c] ✓

Great!

Role 1 for p: G[p, 249-p : 499-p] = 1 - h (250 values)
Role 2 for p: G[p, p : p+250] += -h[::-1] (250 values)

This is very clean and fast to vectorize.

Now let me think about the greedy step more carefully.

In the greedy step, I want to find the pair (i, j) with h[i]=1, h[j]=0 that minimizes max(c + G[j,:] - G[i,:]).

Vectorized approach:
- For a given i, compute d = c - G[i,:] (shape (2n-1,))
- For all j in zeros, compute d + G[j, :] (shape (len(zeros), 2n-1))
- Find the j that minimizes the max along axis=1

The memory for this is len(zeros) * (2n-1) = 125 * 499 ≈ 62,000 floats ≈ 0.5 MB per i. Total over all i: 250 * 0.5 MB = 125 MB. That's a lot if done all at once, but fine if done one i at a time.

Time per i: 125 * 499 ≈ 62,000 additions + 125 max-reductions of size 499. In NumPy, this should be very fast (microseconds to a few ms).

Total greedy pass time: 250 * (a few ms) ≈ 1 second. Maybe less with optimization.

Good, it's symmetric as expected.

Now, one more consideration: after a swap, G changes not just for the swapped positions but for all positions. This is because G[p, m] depends on h values at other positions.

However, if I only use G for the O(n) evaluation of a swap, and I'm willing to accept a small error from stale G, I can avoid rebuilding G after every swap.

The error from stale G: if h changes slightly (one 1→0 and one 0→1), the change in G[p, m] is at most 1 (since h values change by at most 1). So the error in max(c + G[j,:] - G[i,:]) is at most 2. This is a significant error compared to C₅ ~ 0.38.

So I do need to keep G updated. But I can rebuild it after each accepted swap (O(n²) = 62,500 ops for n=250, which is very fast in NumPy).

Actually, build_G with the vectorized version is:
```python
def build_G(h, n):
    G = np.zeros((n, 2*n-1))
    for p in range(n):
        G[p, n-1-p : 2*n-1-p] = 1.0 - h
        G[p, p : p+n] += -h[::-1]
    return G
```

This is a loop of n=250 iterations, each doing two slice assignments of length 250. Total: 250 * 2 * 250 = 125,000 operations. In Python with NumPy, this should take about 1-5 ms.

So rebuilding G after each swap is very affordable.
