At s=-1, affected positions: x=i=0 (need 0≤0-1<4? No! x=0, x+s = -1, not valid). So x=0 is NOT in A(-1).
x=i-s = 0-(-1) = 1. Is x=1 in A(-1)? Need 0≤1<4 and 0≤1-1=0<4. Yes.
Change at x=1: old = h[1]*(1-h[0]) = 1*1 = 1. new = h[1]*(1-h_new[0]) = 1*0 = 0. Change: -1.

So delta_add[0][-1] = -1. ✓ (matches my formula)

delta_rem[1][-1]: change when h[1] goes 1→0 (h=[0,1,0,1] → [0,0,0,1]):
At s=-1, affected positions: x=j=1 (in A(-1)? 0≤1<4 and 0≤0<4. Yes).
x=j-s = 1-(-1) = 2. In A(-1)? 0≤2<4 and 0≤1<4. Yes.

Change at x=1: old = h[1]*(1-h[0]) = 1*1 = 1. new = 0*(1-h[0]) = 0. Change: -1.
Change at x=2: old = h[2]*(1-h[1]) = 0*0 = 0. new = h[2]*(1-0) = 0*1 = 0. Change: 0.

So delta_rem[1][-1] = -1. ✓ (matches my formula)

Now the interaction: when we do BOTH changes simultaneously (h → [1,0,0,1]):
At x=1: old = h[1]*(1-h[0]) = 1*(1-0) = 1. new = h'[1]*(1-h'[0]) = 0*(1-1) = 0. Change: -1.
At x=2: old = 0*(1-1) = 0. new = 0*(1-0) = 0. Change: 0.

Total change from the "swap" at s=-1: -1.

But delta_add + delta_rem = -1 + (-1) = -2. The interaction correction should be +1 (not +2!).

Where did I go wrong? Let me see. The issue is that delta_add and delta_rem are not independent when they affect the same position.

At s=-1, delta_add affects position x=1 (as x=i-s), and delta_rem affects position x=1 (as x=j). Position x=1 is affected by BOTH operations!

In delta_add[0][-1], the change at x=1 is: h[1]*(1-h_new[0]) - h[1]*(1-h[0]) = 1*0 - 1*1 = -1.
In delta_rem[1][-1], the change at x=1 is: h_new[1]*(1-h[0]) - h[1]*(1-h[0]) = 0*1 - 1*1 = -1.

But the actual change at x=1 is: h'[1]*(1-h'[0]) - h[1]*(1-h[0]) = 0*0 - 1*1 = -1.

Sum of individual changes: -1 + (-1) = -2. Actual: -1. Overcount: -1.

The overcount happens because both delta_add and delta_rem "claim" the change at x=1, but the actual change is less than the sum. Specifically:
- delta_add says: at x=1, the change is due to h[0] going 0→1: contribution changes from h[1]*(1-0) to h[1]*(1-1) = 0.
- delta_rem says: at x=1, the change is due to h[1] going 1→0: contribution changes from 1*(1-h[0]) to 0*(1-h[0]) = 0.
- Actual: contribution changes from 1*(1-0) to 0*(1-1) = 0.

The "interaction" is: delta_add computed the change assuming h[1] stays at 1 (it does in the "add only" scenario). delta_rem computed the change assuming h[0] stays at 0 (it does in the "remove only" scenario). But in the actual swap, both change simultaneously.

The overcount at position x=1 is:
(delta_add contribution) + (delta_rem contribution) - (actual contribution)
= [h[1]*(1-h_new[0]) - h[1]*(1-h[0])] + [h_new[1]*(1-h[0]) - h[1]*(1-h[0])] - [h_new[1]*(1-h_new[0]) - h[1]*(1-h[0])]
= h[1]*(1-h_new[0]) + h_new[1]*(1-h[0]) - h[1]*(1-h[0]) - h_new[1]*(1-h_new[0])
= h[1] - h[1]*h_new[0] + h_new[1] - h_new[1]*h[0] - h[1] + h[1]*h[0] - h_new[1] + h_new[1]*h_new[0]
= -h[1]*h_new[0] + h_new[1] - h_new[1]*h[0] + h[1]*h[0] + h_new[1]*h_new[0]
= h_new[1]*(1-h[0]) + h[1]*h[0] - h[1]*h_new[0] + h_new[1]*h_new[0] - h_new[1]

Hmm this is getting nowhere analytically. Let me just accept that the simple formula + corrections doesn't work perfectly and use a different approach.

**Practical approach: Just compute the delta numerically for the affected positions.**

For a swap (i, j), the affected correlation bins are those at shifts s where:
- i+s ∈ [0,n-1] (i is a valid x)
- j+s ∈ [0,n-1] (j is a valid x)
- i-s ∈ [0,n-1] (i is a valid x+s)
- j-s ∈ [0,n-1] (j is a valid x+s)

For each such shift s, the delta is computed by checking at most 4 positions: i, j, i-s, j-s (deduplicated).

The number of affected shifts is at most n (when i and j are in the middle). For each affected shift, the computation is O(1). So total is O(n) per swap, which is fast enough.

In numpy, I can vectorize this:

```python
def compute_swap_delta(h, i, j, n):
    """Compute delta in correlation when h[i]: 0->1, h[j]: 1->0."""
    # Affected shifts: those where any of i, j, i-s, j-s is in [0, n-1]
    # s range: [max(-i, i-n+1, -j, j-n+1), min(n-1-i, i, n-1-j, j)]
    # Simplify: s in [-(n-1), n-1] but we can narrow it.
    
    # I'll just iterate over the affected range.
    s_min = max(-i, i-n+1, -j, j-n+1)
    s_max = min(n-1-i, i, n-1-j, j)
    
    if s_min > s_max:
        return np.zeros(2*n-1)
    
    delta = np.zeros(2*n-1)
    shifts = np.arange(s_min, s_max+1)
    
    # For each shift, compute delta by checking positions {i, j, i-s, j-s}
    # Vectorize over shifts:
    # Positions: i (constant), j (constant), i-shifts, j-shifts
    
    # For position i: valid when 0<=i<n (always) and 0<=i+shift<n
    # For position j: valid when 0<=j<n (always) and 0<=j+shift<n
    # For position i-shift: valid when 0<=i-shift<n and 0<=i<n (always)
    # For position j-shift: valid when 0<=j-shift<n and 0<=j<n (always)
    
    # Build the set of unique positions for each shift and compute delta.
    # This is hard to vectorize due to deduplication. Let me just loop.
    
    result = np.zeros(len(shifts))
    for idx, s in enumerate(shifts):
        positions = set()
        for x in (i, j):
            if 0 <= x < n and 0 <= x + s < n:
                positions.add(x)
        for x in (i - s, j - s):
            if 0 <= x < n and 0 <= x + s < n:
                positions.add(x)
        
        d = 0.0
        for x in positions:
            hx = h[x]
            hxs = h[x + s]
            # new values
            h_x = 1.0 if x == i else (0.0 if x == j else hx)
            h_xs = 1.0 if (x + s) == i else (0.0 if (x + s) == j else hxs)
            d += h_x * (1.0 - h_xs) - hx * (1.0 - hxs)
        result[idx] = d
    
    delta[n-1+s_min : n-1+s_max+1] = result
    return delta
```

This is O(n) per swap but with a Python loop over at most n shifts. For n=250, that's 250 iterations. In Python, each iteration does ~4 set operations and ~4 position checks. Probably 5-20 microseconds per iteration, so 1.25-5 ms per swap.

Over 1000 seconds, that's 200K-800K swaps. That might be enough to improve the solution, but it's not as fast as I'd like.

**Faster approach: Precompute and use numpy more aggressively.**

Actually, let me reconsider. The key operation in the inner loop is:
```
for x in positions:  (at most 4 elements)
    compute h_x * (1-h_xs) - hx * (1-hxs)
```
