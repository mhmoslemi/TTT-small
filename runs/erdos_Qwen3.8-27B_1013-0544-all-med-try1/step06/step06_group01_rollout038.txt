Let me focus on making the coordinate descent efficient. For each coordinate i:
- C_k as a function of x = h[i] is: C_k(x) = A_k + B_k * x where A_k and B_k are constants (given other h values)
- We want to minimize max_k (A_k + B_k * x) over x ∈ [0, 1]
- This is a 1D minimax of linear functions, solvable by finding the intersection points

The optimal x is where the two "largest" linear functions cross (or at a boundary).

Algorithm for 1D minimax of linear functions:
1. For each k, compute A_k and B_k
2. The function f(x) = max_k (A_k + B_k * x) is piecewise linear and convex
3. Find the minimum by:
   a. Evaluate f at x=0 and x=1
   b. Find the "knee point" where the active set changes
   c. The minimum is at the point where the slope changes from negative to positive

More efficiently: sort the lines by slope. The lower envelope (well, upper envelope since we're taking max) changes at intersection points. The minimum of the max is at the last point where the slope is still negative, or at the first point where it becomes positive.

Actually, for a set of lines y = A_k + B_k * x, the max of these lines is a convex piecewise-linear function. Its minimum is at the point where the slope changes from negative to positive.

Algorithm:
1. Compute all (A_k, B_k) pairs
2. The slope of the max at point x is B_{k*(x)} where k* is the argmax
3. Start at x=0, find which line is active
4. Move right until we hit an intersection with another line that has a larger slope
5. Repeat until the active line has positive slope
6. The minimum is at the last intersection point where the slope was still ≤ 0

This is O(n log n) per coordinate (n = number of lags = 2n-1 ≈ 2n).

Total: O(n * n log n) = O(n² log n) per sweep. For n=95, that's about 95 * 95 * 7 ≈ 63K operations per sweep. Very fast!

    return grad
