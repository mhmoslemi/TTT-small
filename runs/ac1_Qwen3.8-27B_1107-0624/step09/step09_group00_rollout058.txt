Actually, I want to also consider the **proximal gradient** approach more carefully.

The problem: minimize `f(a) = max_k c_k(a)` subject to `a >= 0, sum(a) = 1`.

The proximal gradient step is:
1. Compute gradient (or subgradient) `g = ∂f(a)`
2. Take a step: `y = a - (1/L) * g` where `L` is a Lipschitz constant
3. Project: `a_new = Proj_simplex(y)` where `Proj_simplex` projects onto `{a : a >= 0, sum(a) = 1}`

The projection onto the simplex is well-known and can be computed in `O(n log n)` time.

The issue is computing `L` (the Lipschitz constant of the gradient). For `f(a) = max_k c_k(a)`, the gradient is `g_i = a_{i+k*} + a_{i-k*}` (for the active lag `k*`), so `||g|| <= 2 * ||a||_1 = 2` (since `sum(a) = 1`). But this is a very loose bound.

A tighter bound: `||g||_2 <= sqrt(2) * ||a||_2` (for a single active lag). And `||a||_2 <= ||a||_1 = 1`. So `L <= sqrt(2)` is a reasonable bound. But in practice, the effective Lipschitz constant might be smaller.

For FISTA, the step size is `1/L`. If `L` is too large, the method is slow. If `L` is too small, it diverges. We can use backtracking to find a good `L`.

Let me implement FISTA with backtracking:

```python
def fista(a, deadline, ...):
    a = normalize(a)
    t = 1.0
    L = 1.0  # initial Lipschitz estimate
    y = a.copy()
    for iteration:
        # Compute gradient at y
        c = convolve(y, y)
        k_star = argmax(c)
        g = subgradient(c, y, k_star)  # or weighted active set
        
        # Backtracking line search
        while True:
            x_new = proj_simplex(y - g / L)
            if f(x_new) <= f(y) - 0.5 / L * ||g||^2:
                break
            L *= 2
        
        # Update
        t_new = (1 + sqrt(1 + 4*t*t)) / 2
        y = x_new + (t - 1) / t_new * (x_new - a)
        a = x_new
        t = t_new
```
