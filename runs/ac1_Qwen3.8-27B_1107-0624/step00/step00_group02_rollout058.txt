```python
import numpy as np
import time
from scipy.optimize import linprog

def solve_lp(g_upper_bounds, n, f, M):
    # Maximize sum(g) subject to:
    # g[i] >= 0 for all i
    # For each k = 0..2n-2: sum_i f[i]*g[k-i] <= M (where g[j]=0 if j<0 or j>=n)
    # 
    # The convolution (f*g)[k] = sum_{i=max(0,k-n+1)}^{min(k,n-1)} f[i]*g[k-i]
    # This is a linear function of g.
    
    # Variables: g[0], g[1], ..., g[n-1] (n variables)
    # Objective: maximize sum(g) -> minimize -sum(g)
    
    c = -np.ones(n)  # minimize -sum(g)
    
    # Inequality constraints: A_ub @ g <= b_ub
    # For each k = 0..2n-2:
    #   sum_i f[i]*g[k-i] <= M
    # where the valid i range is max(0, k-n+1) <= i <= min(k, n-1), 
    # and the g index is k-i, which ranges from k-min(k,n-1) to k-max(0,k-n+1)
    
    # Let me write this more carefully.
    # (f*g)[k] = sum_{i=0}^{n-1} f[i] * g[k-i] where g[j] = 0 if j < 0 or j >= n
    # = sum_{i: 0<=k-i<n} f[i] * g[k-i]
    # = sum_{i: max(0,k-n+1)<=i<=min(k,n-1)} f[i] * g[k-i]
    
    # For a given k, the coefficient of g[j] (where j = k-i, so i = k-j) is f[k-j]
    # (provided 0 <= k-j < n, i.e., k-n+1 <= j <= k)
    # Also need 0 <= j < n.
    # So j ranges from max(0, k-n+1) to min(k, n-1).
    # And the coefficient of g[j] is f[k-j].
    
    A_ub = np.zeros((2*n-1, n))
    for k in range(2*n-1):
        j_min = max(0, k - n + 1)
        j_max = min(k, n-1)
        for j in range(j_min, j_max + 1):
            A_ub[k, j] = f[k - j]
    b_ub = np.full(2*n-1, M)
    
    # Bounds: g[i] >= 0
    bounds = [(0, None)] * n
    
    result = linprog(c, A_ub=A_ub, b_ub=b_ub, bounds=bounds, method='highs')
    if result.success:
        return result.x
    return None
```

Let me reconsider the problem. For large n, we need a sequence where the convolution is as flat as possible. The uniform sequence gives a triangular convolution (peaked in the middle). We need to "flatten" the convolution.

One idea: use a sequence with alternating high and low values in a specific pattern. But for non-negative sequences, this is limited.

Another idea: use a sequence that's high in the first half and low in the second half (or a smooth transition). This would make the "center" of the convolution (which involves products of opposite elements) smaller.
