from scipy.optimize import linprog
import time

def build_convolution_matrix(f):
    """Build the matrix A such that (A @ g)[k] = (f*g)[k] for full convolution."""
    n = len(f)
    # For lag k, (f*g)[k] = sum_{i} f[i] * g[k-i] where 0<=i<n and 0<=k-i<n
    # So the coefficient of g[j] in lag k is f[k-j] (if 0<=k-j<n)
    # Result matrix is (2n-1) x n
    A = np.zeros((2*n-1, n))
    for j in range(n):
        # g[j] appears in lags k where 0<=k-j<n, i.e., j <= k <= j+n-1
        # For such k, the coefficient is f[k-j]
        for k in range(j, j+n):
            A[k, j] = f[k-j]
    return A

def solve_lp_step(f, n, max_time=30):
    """Solve the LP: min M s.t. (f*g)[k] <= M, sum(g)=1, g>=0."""
    # Variables: g[0], ..., g[n-1], M => total n+1
    # Objective: minimize M => c = [0, ..., 0, 1]
    c = np.zeros(n+1)
    c[-1] = 1.0
    
    # Inequality constraints: (f*g)[k] - M <= 0 for k=0,...,2n-2

    A_conv = build_convolution_matrix(f)  # shape (2n-1, n)
    A_ub = np.hstack([A_conv, -np.ones((2*n-1, 1))])
    b_ub = np.zeros(2*n-1)
    
    # Equality: sum(g) = 1
    A_eq = np.zeros((1, n+1))
    A_eq[0, :n] = 1.0
    b_eq = np.array([1.0])

        g = np.clip(g, 0, None)
        g_sum = g.sum()
        if g_sum > 0:
            g = g / g_sum
        return g
    return None

        # Subgradient: sg[j] = f[k_star - j] if 0 <= k_star - j < n
        sg = np.zeros(n)
        j_min = max(0, k_star - n + 1)
        j_max = min(n - 1, k_star)
        for j in range(j_min, j_max + 1):
            sg[j] = f[k_star - j]
        
        # Update
        eta = eta0 / (1 + t * 0.01)  # decreasing step size
        g = g * np.exp(-eta * sg / M)
        g = np.clip(g, 1e-15, None)  # keep positive
        g = g / g.sum()
        
        if g.max() < best_g.max() * 0.95:  # improvement check
            best_g = g.copy()
    
    return best_g

Hmm, the convergence of subgradient methods is slow. Let me think of a better approach.

Actually, I recall that for this type of problem (minimizing the max of linear functions over a simplex), there's a well-known algorithm called the **K tegoridis algorithm** or more generally, we can use **mirror descent with the negative entropy** (which gives the multiplicative weights update).

The mirror descent update for minimizing max_k (a_k^T g) over the simplex is:
g_j(t+1) = g_j(t) * exp(-eta * (a_k*(t))^T e_j) / Z
where k*(t) is the argmax at step t, and Z is the normalization constant.

This is exactly what I wrote above. The convergence rate is O(1/sqrt(T)) for the subgradient method, but in practice it can be much faster.

However, I think for this problem, a better approach might be to use the **full LP** but with a smart solver. Let me try the following:

1. Use the LP with HiGHS solver, with a time limit of 30-60 seconds per solve.
2. Alternate between optimizing g (given f) and optimizing f (given g).
3. After convergence, do local search.

For n=3809, the LP has 3810 variables and 7617 inequality constraints + 1 equality constraint. HiGHS should handle this in a few seconds.

Let me estimate: with 1800 seconds and 30 seconds per LP solve, I can do about 60 LP solves. That's 30 alternations (30 g-optimizations + 30 f-optimizations). This should be enough for convergence.

But I'm worried about the matrix construction time. Building the sparse matrix for n=3809 involves creating arrays of length n^2 = 14.5M. This should take about 0.1-0.5 seconds. So the total time per LP solve is about 0.5 (matrix) + 5-20 (solve) = 5-20 seconds. With 1800 seconds, I can do 100-300 LP solves.
