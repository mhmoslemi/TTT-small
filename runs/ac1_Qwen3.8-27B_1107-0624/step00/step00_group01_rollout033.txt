**Practical approach: Iterative water-filling**

5. Average the gradients: g = (1/|S|) * sum_{k in S} g_k.
6. Move mass in the direction -g (i.e., from high g to low g), maintaining sum(a) = 1 and a >= 0.
7. Repeat.

This is essentially a projected subgradient method for minimizing max_k C[k] subject to a >= 0, sum(a) = 1.

**Faster approach: Direct computation of the gradient and a simple update rule**

Instead of solving an LP, I can:
1. Compute C = convolve(a, a).
2. Find k* = argmax C.
3. Compute the "contribution" of each position j to C[k*]: contrib[j] = a[j] * a[k*-j] (for valid j).
4. The "sensitivity" (gradient) is: grad[j] = a[k*-j] (for valid j, 0 otherwise).
5. To reduce C[k*], move mass from high-sensitivity positions to low-sensitivity positions.

A simple rule:
- Let S = set of positions j that contribute to C[k*] (i.e., 0 <= k*-j < n).
- Among S, identify positions with high a[k*-j] (these contribute most to C[k*]).
- Reduce a[j] for high-contributing j, and increase a[j] for low-contributing or non-contributing j.
- Maintain sum(a) = 1 and a >= 0.

This is a "mass movement" heuristic. Let me make it more precise:

```
For each iteration:
1. C = convolve(a, a)
2. k* = argmax C
3. For j in valid range: grad[j] = a[k*-j]
   For j not in valid range: grad[j] = 0 (or small epsilon)
4. Sort positions by grad[j].
5. Move a small amount of mass from top-quantile positions to bottom-quantile positions.
6. Project to a >= 0, sum(a) = 1.
```

This is O(n log n) per iteration (for the sort). For n=6000, each iteration is fast, and we can do many iterations.

But there's a subtlety: moving mass from position j to position j' changes C[k] for ALL k, not just k*. So we might be creating new peaks elsewhere.

To address this, we can:
- Use a small step size (move only a small amount of mass).
- After each step, recompute C and check if the max decreased.
- If not, revert.

This is essentially a local search / hill climbing.

**Even better: Use the "top-peak" penalty method**

Instead of just minimizing the current peak, penalize the top-K peaks:
Penalty = sum_{k in top_K} C[k]^2 (or similar)

    score = 2.0 * n * np.max(C) / (sum_a ** 2)

            i_start2 = max(0, k_star2 - n + 1)

And C[0] = a[0]^2, C[2n-2] = a[n-1]^2. For these to be close to the average, we need a[0] ≈ a[n-1] ≈ (sum a)/sqrt(2n-1).

For a "typical" element a[i] ≈ (sum a)/n, we have a[0]^2 ≈ (sum a)^2/n^2, while the average is (sum a)^2/(2n-1) ≈ (sum a)^2/(2n). So a[0]^2 is about 2 times the average. This means the edges of the convolution will be about 2x the average.

To make C[0] = a[0]^2 close to the average, we need a[0] to be smaller than "typical". This suggests a sequence that's smaller at the edges and larger in the middle... but that's what I tried before (Hanning window) and it made the center peak even larger!

The fundamental tension: making the edges small reduces C[0] and C[2n-2], but makes the center (where all terms contribute) larger.

The resolution: we need a sequence where NO particular alignment gives a large overlap. This is a combinatorial/design problem.

What about **m-sequences** (maximum length sequences)? These are binary sequences with "almost perfect" periodic auto-correlation. But we need the LINEAR convolution, not the periodic auto-correlation.

For an m-sequence of length 2^m - 1, the periodic auto-correlation is 1 at lag 0 and -(2^m-1)/3 (or similar) at other lags. The linear convolution would be related but different.

What about a "sparse" sequence where the 1s are placed at "Sidon set" positions? A Sidon set is a set where all pairwise sums are distinct. This minimizes the number of collisions in the convolution.

For a sequence a with a[i] = 1 for i in S (a Sidon set) and 0 otherwise:
C[k] = |{i in S : k-i in S}| = |{i in S : i and k-i both in S}|
This is the number of representations of k as a sum of two elements of S.
For a Sidon set, each k has at most 1 representation, so C[k] <= 1 for all k.

sum_a = |S|.

For a Sidon set in {0, 1, ..., n-1}, the maximum size is about sqrt(n). So |S| ≈ sqrt(n).
score ≈ 2n / n = 2.

**Let me go back to the numerical optimization approach and really think about what makes it work.**

The key constraint: max_k C[k] < (sum a)^2 / n for score < 2.

Equivalently: for all k, sum_i a[i]*a[k-i] < (sum a)^2 / n.

Let's normalize: let s = sum a, and define p[i] = a[i]/s (so sum p = 1, p >= 0).
Then: for all k, sum_i p[i]*p[k-i] * s^2 < s^2 / n
=> for all k, sum_i p[i]*p[k-i] < 1/n.

So we need a probability distribution p on {0,...,n-1} such that the "convolution" (p*p)[k] < 1/n for all k.

Note that (p*p)[0] = p[0]^2, so we need p[0] < 1/sqrt(n). Similarly p[n-1] < 1/sqrt(n).

And (p*p)[n-1] = sum p[i]*p[n-1-i] < 1/n.

For a uniform distribution p[i] = 1/n:
(p*p)[k] = (k+1)/n^2 for k = 0,...,n-1 (ramp up)
(p*p)[n-1] = n/n^2 = 1/n (exactly at the bound!)
(p*p)[k] = (2n-1-k)/n^2 for k = n,...,2n-2 (ramp down)

So the uniform distribution achieves max (p*p) = 1/n exactly, giving score = 2.

To get score < 2, we need a distribution where max (p*p) < 1/n. This means the convolution must be STRICTLY below the uniform distribution's peak.

The uniform distribution gives a TRIANGULAR convolution (ramp up to 1/n at the center, ramp down). To get a flatter convolution, we need to "spread" the mass more evenly across the convolution positions.

One way to do this: make p[i] non-uniform in a way that "fills in" the edges of the convolution (making C[0], C[1], etc. larger) while "reducing" the center (making C[n-1] smaller).

Specifically:
- Increase p[0] (and p[n-1]) to increase C[0] (and C[2n-2]).
- Decrease p in the middle to decrease C[n-1].
- But this creates a "bimodal" distribution, which might make C[n/2] or C[3n/2] large.

This is the fundamental trade-off. The optimal solution is where all C[k] are as equal as possible (as close to 1/(2n-1) * n = n/(2n-1) ≈ 1/2 * 1/n as possible).
