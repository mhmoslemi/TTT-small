**Multiplicative Update Algorithm:**

Goal: Minimize max_k conv(a,a)[k] subject to a >= 0, sum(a) = 1.

In each iteration:
1. Compute c = conv(a,a).
2. Compute the "excess" at each lag: e_k = c_k - mean(c) (or c_k - target).
3. For each position i, compute its "load":
   load_i = sum_k e_k * a[k-i] / (2*c_k)  [for valid k, i]
   (This measures how much a[i] contributes to the excess peaks.)
4. Update: a[i] *= (1 - η * load_i) for η small.
   Or: a[i] *= exp(-η * load_i).
5. Renormalize: a /= a.sum().

Actually, a cleaner formulation:

We want to minimize f(a) = max_k c_k where c_k = sum_i a_i * a_{k-i}.

The "gradient" of c_k with respect to a_i is a_{k-i} (or 2*a_{k-i} with the double-counting).

If we use the top-M lags (those with the highest c_k), the gradient of the "soft max" is:
grad_i = sum_{k in top_M} w_k * a_{k-i} where w_k are weights (e.g., softmax of c_k).

Then the multiplicative update is:
a_i *= exp(-η * grad_i)

This is essentially gradient descent in the "log" space, but without the renormalization step (which is implicit in the multiplicative form).

Let me compare this to the previous Adam approach:
- Previous: z_i -= lr * grad_i (additive update in log space).
- New: a_i *= exp(-η * grad_i) which is equivalent to z_i -= η * grad_i in log space.

So it's the same! The multiplicative update IS the log-space gradient descent.

The difference would be in how we compute the "gradient" (which lags to include, weighting scheme, etc.) and in the step size schedule.
