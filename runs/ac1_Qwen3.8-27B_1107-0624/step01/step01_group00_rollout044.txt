- Move δ from a[i] to a[j] (or vice versa)
- The change in c[k] is: Δc[k] = δ*(a[k-j] - a[k-i]) (approximately, for small δ)
- We want to choose δ > 0 to minimize max c

This is a 1D problem: minimize max_k (c[k] + δ*(a[k-j] - a[k-i])) over δ in [0, min(a[i], something)].

For a given pair (i,j), the optimal δ can be found by bisection: we want the largest δ such that c[k] + δ*(a[k-j] - a[k-i]) <= current_max for all k (or we accept a small increase in max).

This is essentially a linear programming problem in 1D!

**Algorithm: Paired swap descent**
1. Compute c = a*a
2. Find k* = argmax c, M = c[k*]
3. For a random pair (i, j):
   a. Determine the best direction: move from i to j or from j to i
   b. Find the maximum δ that keeps max(c + δ*Δ) <= M (or as close to M as possible)
   c. Apply the swap with a fraction of the optimal δ (e.g., 0.5-1.0)
4. Repeat

This is like a cutting-plane method in disguise. Each swap either decreases the max or keeps it the same while potentially setting up for future decreases.

The challenge is efficiency: computing the optimal δ for each pair requires evaluating the max over all k, which is O(n). With O(n^2) possible pairs, each iteration is O(n^3). For n=512, that's about 134 million operations per full pass, which might be too slow.

But we can be smarter: only consider pairs where the swap is likely to help. Specifically:
- We want to move mass from a "blame" position to a "safe" position
- Position i has "blame" proportional to how much it contributes to the peaks
- Position j is "safe" if moving mass there doesn't significantly increase any c[k]

Let me simplify: at each step, pick the position i that most contributes to c[k*] (the max), and move a small amount to a random position j (or the position that most reduces the increase in other c[k]).
