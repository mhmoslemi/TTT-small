    n = len(a)
    a = a / a.sum()
    best_a = a.copy()
    best_max = float(_fft_convolve(a, a).max())
    
    step_size = 0.1
    no_improve = 0
    
    for it in range(max_iter):
        if time.monotonic() > deadline:
            break
        
        c = _fft_convolve(a, a)
        M = float(c.max())
        
        if M < best_max:
            best_max = M
            best_a = a.copy()
            no_improve = 0
        else:
            no_improve += 1
        
        # Find active set (positions where conv is close to max)
        # Start with exact peak, expand as needed
        tol = max(1e-10, M * 1e-6)
        active = np.where(c >= M - tol)[0]
        
        # Compute subgradient
        g = np.zeros(n)
        for k in active:
            j_lo = max(0, k - n + 1)
            j_hi = min(k, n - 1)
            if j_lo <= j_hi:
                g[j_lo:j_hi+1] += a[k-j_hi:k-j_lo+1]
        g /= len(active)
        
        # Center the gradient to maintain sum
        d = g - g.mean()
        
        # Line search
        improved = False
        for scale in [step_size, step_size*0.5, step_size*0.1, step_size*2]:
            a_new = a - scale * d
            a_new = np.maximum(a_new, 0)
            s = a_new.sum()
            if s < 1e-15:
                continue
            a_new /= s
            max_new = float(_fft_convolve(a_new, a_new).max())
            if max_new < M:
                a = a_new
                improved = True
                break
        
        if not improved:
            step_size *= 0.5
            if step_size < 1e-8:
                break
        elif step_size < 1.0:
            step_size = min(step_size * 1.2, 1.0)
    
    return best_a, 2*n*best_max

This is cleaner but might be slow due to the FFT in the line search. Let me optimize:

Instead of doing a full FFT for each candidate step, I can approximate the new max:
new_conv[k] ≈ c[k] - 2*scale*sum(active contributions to k from d)

Actually, for a small step, the change in conv is:
Δconv[k] ≈ 2 * (a * d)[k] (first-order approximation)

So: new_max ≈ max_k (c[k] + 2*scale*(a*d)[k] for k near peak)

We only need to check the active positions and their neighbors.

Let me implement this:

    a = a / a.sum()
    best_a = a.copy()
    c = _fft_convolve(a, a)
    best_max = float(c.max())
    
    step_size = 0.1
    no_improve = 0
    
    for it in range(max_iter):
        if time.monotonic() > deadline:
            break
        
        M = float(c.max())
        
        if M < best_max:
            best_max = M
            best_a = a.copy()
            no_improve = 0
        else:
            no_improve += 1
            if no_improve > 100:
                break
        
        # Active set
        tol = max(1e-10, M * 1e-8)
        active = np.where(c >= M - tol)[0]
        
        # Subgradient
        g = np.zeros(n)
        for k in active:
            j_lo = max(0, k - n + 1)
            j_hi = min(k, n - 1)
            if j_lo <= j_hi:
                g[j_lo:j_hi+1] += a[k-j_hi:k-j_lo+1]
        g /= len(active)
        
        # Center
        d = g - g.mean()
        
        # First-order approximation of new conv
        # Δconv ≈ 2 * conv(a, d) (since d is centered, this is good)
        delta_conv = 2 * _fft_convolve(a, d)
        
        # Find best step size using the approximation
        # new_conv[k] ≈ c[k] + t * delta_conv[k]
        # We want to minimize max_k new_conv[k]
        # The peak will be at positions where c[k] is high
        # For the active positions: new_M ≈ M + t * delta_conv[active]
        # We want M + t * min(delta_conv[active]) < M, i.e., delta_conv[active] < 0
        # The optimal t (for the active positions) is limited by when another position catches up
        
        # Simple: try a few step sizes using the approximation
        best_t = 0.0
        best_approx_max = M
        for t_candidate in [0.05, 0.1, 0.2, 0.5, 1.0]:
            approx_new = c + t_candidate * delta_conv
            approx_max = float(approx_new.max())
            if approx_max < best_approx_max:
                best_approx_max = approx_max
                best_t = t_candidate
        
        if best_t == 0.0:
            step_size *= 0.5
            if step_size < 1e-10:
                break
            continue
        
        # Apply the step
        a_new = a - best_t * d
        a_new = np.maximum(a_new, 0)
        s = a_new.sum()
        if s < 1e-15:
            break
        a_new /= s
        
        # Verify with exact computation
        c_new = _fft_convolve(a_new, a_new)
        max_new = float(c_new.max())
        
        if max_new < M:
            a = a_new
            c = c_new
            step_size = min(step_size * 1.1, 2.0)
        else:
            # Approximation was optimistic, try smaller step
            for t_small in [best_t * 0.1, best_t * 0.01]:
                a_try = a - t_small * d
                a_try = np.maximum(a_try, 0)
                s_try = a_try.sum()
                if s_try < 1e-15:
                    continue
                a_try /= s_try
                max_try = float(_fft_convolve(a_try, a_try).max())
                if max_try < M:
                    a = a_try
                    c = _fft_convolve(a, a)
                    break
            else:

Now, let me think about the coordinate descent polishing step.

For coordinate descent, the key observation is:
- If we decrease a_j (where a_j > 0), all convolution values that involve a_j decrease (or stay the same)
- The peak of conv can only decrease or stay the same
- So the optimal move is to set a_j as small as possible (0) for coordinates that contribute to the peak

But we can't set all of them to 0 (the sum must remain 1). So the strategy is:
1. Identify which coordinates contribute most to the peak
2. Reduce those coordinates, redistributing their mass to coordinates that don't contribute to the peak (or contribute less)

This is essentially what the gradient step does, but coordinate descent can be more precise.

For the final polish, I'll use a more targeted approach:
- For the peak position p, the contribution is sum_j a_j * a[p-j]
- We want to minimize this while keeping sum(a) = 1
- The "cheapest" way to reduce it is to reduce the product a_j * a[p-j]
- For each pair (j, p-j), we can reduce one of them at the cost of increasing the other convolution values

Actually, for the final polish, I think the best approach is:
1. Fix all coordinates except those that directly contribute to the peak
2. Optimize those coordinates to minimize the peak

For the peak at position p:
conv_p = sum_j a_j * a[p-j] (valid j)

If we only change a_j (keeping all others fixed), the constraint is:
a_j * a[p-j] + (other terms) ≤ M

So a_j ≤ M / a[p-j] (if a[p-j] > 0)

But a_j also appears in other convolution values:
conv_k for k ≠ p might involve a_j * a[k-j]

The new value would be: conv_k_new = conv_k_old - a_j_old * a[k-j] + a_j_new * a[k-j] = conv_k_old + (a_j_new - a_j_old) * a[k-j]

Since a_j_new < a_j_old (we're reducing), this decreases conv_k (if a[k-j] > 0) or doesn't change it.

So reducing a_j (for j that contributes to conv_p) can only help! The question is how much we can reduce it.

The limiting factor is: we need sum(a) = 1, so if we reduce a_j, we need to increase some other a_i. Increasing a_i will increase some convolution values.

So the strategy is:
1. Reduce a_j (for peak-contributing j)
2. Increase a_i (for non-peak-contributing i)
3. Choose i such that the increase in convolution is minimal

This is a 2-coordinate swap: (a_j, a_i) → (a_j - δ, a_i + δ)

The change in conv_p: -δ * a[p-j] (decrease, good)
The change in conv_k (k ≠ p): -δ * a[k-j] + δ * a[k-i] (could go either way)

We want: for all k, the change doesn't make conv_k exceed M.

This gives us a linear constraint on δ:
For k where a[k-i] > a[k-j]: δ * (a[k-i] - a[k-j]) ≤ M - conv_k
So: δ ≤ (M - conv_k) / (a[k-i] - a[k-j])

And δ ≤ a_j (can't make a_j negative)

The optimal δ is the minimum of all these bounds.

This gives us an exact way to do 2-coordinate descent!
