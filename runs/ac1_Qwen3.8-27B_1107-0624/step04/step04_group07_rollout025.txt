Actually, let me reconsider the whole approach. The LP fixed-point method is:
- Given a, compute M = max(conv(a,a))
- Solve: max sum(b) s.t. conv(a,b) <= M, b >= 0
- Update a = (1-t)*a + t*b

This is essentially a "mirror descent" or "projected gradient" method in disguise. The LP gives the optimal direction to move.

The key question is: how many iterations does it take to converge? And is the local optimum found by LP the global optimum?

For the linear profile, let's see what the LP would do:
- Start with a = [1, 2, ..., n] (normalized)
- M = max(conv(a,a)) = conv[n] (approximately)
- The LP finds b that maximizes sum(b) subject to conv(a,b) <= M
- Since a is increasing, conv(a,b) = sum_i a_i * b_{k-i} is a weighted sum of b's
- The constraint is tightest at the lag where conv is maximized
- The LP would push b to be as large as possible where a is small (to keep conv(a,b) small)
- This would make b more "front-loaded" (larger at the beginning)
- But that would increase conv[0] = b[0]^2...

Actually, the LP doesn't constrain b*b, only a*b. So the LP solution might have a large b[0] which would increase the self-convolution of the new a.

This is the fundamental limitation of the LP fixed-point: it linearizes the quadratic objective, and the linear approximation can be poor.

A better approach might be to use a second-order method or to solve the original nonconvex problem more directly.

Let me think about using scipy's SLSQP or trust-constr with the smooth-max objective.

The smooth-max objective: f(a) = softmax(beta * conv(a,a)) ≈ max(conv(a,a))
Gradient: grad_i = sum_k w_k * (a_{i+k} + a_{i-k}) (with boundary handling)

This is smooth (C^infty) for any beta > 0, so we can use standard nonlinear optimization.

The constraint is: a >= 0, sum(a) = 1.

I'll use L-BFGS-B with the log-parameterization to handle non-negativity:
- Parameterize a_i = exp(z_i) / sum(exp(z_j))
- Optimize z without constraints (the softmax automatically ensures a >= 0, sum(a) = 1)

This is essentially what the Adam code does, but using L-BFGS-B instead of Adam. L-BFGS-B uses quasi-Newton methods which should converge faster.

import numpy as np
import time
from scipy.optimize import minimize, linprog
from scipy.sparse import csr_matrix

def _next_pow2(n):
    k = 1
    while k < n:
        k <<= 1
    return max(2, k)

def _full_convolve(a):
    n = len(a)
    if n == 0:
        return np.array([])
    N = _next_pow2(2 * n - 1)
    fa = np.fft.rfft(a, N)
    c = np.fft.irfft(fa * fa, N)[:2 * n - 1]
    return np.maximum(c, 0.0)

def _score(a):
    n = len(a)
    c = _full_convolve(a)
    return float(2.0 * n * c.max())

def _smooth_max_and_weights(c, beta):
    m = c.max()
    x = (c - m) / beta
    ex = np.exp(x)
    s = ex.sum()
    w = ex / s
    sm = m + beta * np.log(s)
    return sm, w

def _cross_correlate(w, a):
    n = len(a)
    N = _next_pow2(2 * n - 1)
    fw = np.fft.rfft(w, N)
    fa = np.fft.rfft(a[::-1], N)
    h = np.fft.irfft(fw * fa, N)
    return h[n-1:2*n-1]

def _grad_score(a, beta):
    """Gradient of smooth-max of self-convolution w.r.t. a."""
    c = _full_convolve(a)
    _, w = _smooth_max_and_weights(c, beta)
    g = _cross_correlate(w, a)
    return g

def _logit_optimize(a0, deadline, beta_init=None, max_iter=2000):
    """Optimize in logit space using L-BFGS-B."""
    n = len(a0)
    a = np.maximum(a0, 1e-15)
    a = a / a.sum()
    z = np.log(a)
    z -= z.mean()
    
    if beta_init is None:
        c = _full_convolve(a)
        beta_init = 0.05 * c.max()
    
    beta = beta_init
    
    def objective(z):
        a = np.exp(z - z.max())
        a = a / a.sum()
        c = _full_convolve(a)
        sm, _ = _smooth_max_and_weights(c, beta)
        return 2.0 * n * sm  # We minimize 2n * max(conv) subject to sum=1
    
    def gradient(z):
        a = np.exp(z - z.max())
        a = a / a.sum()
        c = _full_convolve(a)
        _, w = _smooth_max_and_weights(c, beta)
        g_conv = _cross_correlate(w, a)
        # Chain rule: d(conv)/dz = d(conv)/da * da/dz
        # da/dz_i = a_i (since a_i = exp(z_i - max(z)) / sum(exp(z_j - max(z)))
        # and the max and sum terms cancel in the gradient)
        # Actually for softmax: a_i = exp(z_i) / sum(exp(z_j))
        # da_i/dz_k = a_i * (delta_ik - a_k)
        # d(f)/dz_k = sum_i d(f)/da_i * da_i/dz_k
        # = sum_i g_conv_i * a_i * (delta_ik - a_k)
        # = g_conv_k * a_k - a_k * sum_i g_conv_i * a_i
        dot = np.dot(g_conv, a)
        dz = a * (g_conv - dot)
        return 2.0 * n * dz
    
    best_z = z.copy()
    best_score = 2.0 * n * _full_convolve(a).max()
    
    for iteration in range(max_iter):
        if time.monotonic() > deadline:
            break
        
        res = minimize(objective, z, jac=gradient, method='L-BFGS-B',
                      options={'maxiter': 50, 'gtol': 1e-6})
        
        z = res.x
        a = np.exp(z - z.max())
        a = a / a.sum()
        sc = 2.0 * n * _full_convolve(a).max()
        
        if sc < best_score:
            best_score = sc
            best_z = z.copy()
        
        # Decay beta
        if iteration % 10 == 0:
            beta *= 0.8
            beta = max(beta, 1e-6 * _full_convolve(a).max())
    
    a_best = np.exp(best_z - best_z.max())
    a_best = a_best / a_best.sum()
    return a_best, 2.0 * n * _full_convolve(a_best).max()

Let me also think about the LP approach. The LP fixed-point is:
1. Compute M = max(conv(a, a))
2. Solve LP: max sum(b) s.t. A @ b <= M * 1, b >= 0
   where A is the matrix with A[k, i] = a[k-i] (the "convolution matrix")
3. Update: a_new = (1-t) * a + t * b / sum(b)

The key insight is that step 2 finds the direction that maximizes the "sum" subject to the linearized constraint. This is like a "water-filling" or "balancing" operation.

- Predict: conv(a_new, a_new) ≈ 2*(1-t)*conv(a, b) + t^2 * conv(b, b) (rough approximation)
- We want max of this to be <= M
