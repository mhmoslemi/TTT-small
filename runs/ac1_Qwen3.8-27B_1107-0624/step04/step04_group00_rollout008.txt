```python
def _project_simplex(v):
    """Project v onto the probability simplex {a >= 0, sum(a) = 1}."""
    n = len(v)
    if n == 0:
        return v
    u = np.sort(v)[::-1]
    cssv = np.cumsum(u)
    rho = np.nonzero(u * np.arange(1, n+1) > (cssv - 1))[0][-1]
    theta = (cssv[rho] - 1) / (rho + 1.0)
    return np.maximum(v - theta, 0)
```


This is very efficient! Each iteration is O(n log n) for the FFT convolution + O(n) for the rest.

- This is the "hard" top-K subgradient.
- Can be noisy but might converge faster.

Option 3: Adaptive T based on the gap between top peaks.

- Start with large T (smooth, looks at all peaks)
- Gradually decrease T (focus on top peaks)

```python
    out_n = n + m - 1
    N = _next_pow2(out_n)

    fb = np.fft.rfft(b, N)
    r = np.fft.irfft(fa * fb, N)[:out_n]

    n = len(v)
    if n == 0:
        return v

    rng_ = np.arange(1, n+1)

    if not cond.any():
        return np.ones(n) / n
    rho = np.nonzero(cond)[0][-1]

def _subgradient_optimize(a_init, deadline, rng, T_init=1.0, T_min=0.001, n_iter_max=50000):
    """Subgradient method with continuation on T and momentum."""
    n = len(a_init)
    a = a_init.copy()
    s = a.sum()
    if s > 0:
        a = a / s
    else:
        a = np.ones(n) / n
    
    best_a = a.copy()
    best_score = _score_norm(a)
    
    # Momentum
    v = np.zeros(n)
    m = np.zeros(n)
    t = 0
    b1, b2, eps = 0.9, 0.999, 1e-8
    lr_base = 0.5
    
    T = T_init
    T_decay = (T_min / T_init) ** (1.0 / max(1, n_iter_max))
    
    for it in range(n_iter_max):
        if time.monotonic() > deadline:
            break
        t += 1
        
        # Compute convolution and weights
        c = _full_convolve(a, a)
        cm = c.max()
        w = _compute_subgrad_weights(c, T)
        
        # Compute gradient
        g = _compute_gradient(a, w)
        
        # Adam update
        m = b1 * m + (1 - b1) * g
        v = b2 * v + (1 - b2) * (g * g)
        mh = m / (1 - b1**t)
        vh = v / (1 - b2**t)
        
        # Step
        a_new = a - lr_base * mh / (np.sqrt(vh) + eps)
        a_new = _project_simplex(a_new)
        
        if not np.all(np.isfinite(a_new)):
            break
        
        # Evaluate
        sc = _score_norm(a_new)
        if sc < best_score:
            best_score = sc
            best_a = a_new.copy()
        
        a = a_new
        
        # Update T
        T *= T_decay
        T = max(T, T_min)
        
        # Periodic restart
        if t % 5000 == 0:
            noise = 0.01 * rng.normal(size=n)
            a_pert = _project_simplex(a + noise)
            sc_pert = _score_norm(a_pert)
            if sc_pert < best_score:
                best_a = a_pert.copy()
                best_score = sc_pert
                a = a_pert
    
    return best_a, best_score
```

But actually, I can make it much faster using FFT. Let me reconsider.

The key computation is: `g[i] = sum_{j=0}^{n-1} a[j] * w[j+i]` for `i = 0, ..., n-1`.

This is the cross-correlation of `a` and `w` at lags `0, 1, ..., n-1`.

Using FFT:
1. Zero-pad `a` to length N and `w` to length N, where N >= len(a) + len(w) - 1 = n + 2n-2 = 3n-2.
2. Compute `A = rfft(a_padded, N)`, `W = rfft(w_padded, N)`.
3. The linear cross-correlation is `ifft(A * conj(W))` (or `ifft(conj(A) * W)` depending on convention).

Let me verify the convention:
- `ifft(fft(f) * conj(FFT(g)))` gives the circular cross-correlation `(f ⋆ g)[n] = sum_m f[m] * g[m-n]`.
- With zero-padding to avoid circular effects, this gives the linear cross-correlation.

So: `corr[n] = sum_m a[m] * w[m-n]` (linear cross-correlation of a and w).

I want `g[i] = sum_j a[j] * w[j+i]`. Let `m = j+i`, so `j = m-i`:
`g[i] = sum_m a[m-i] * w[m]` (where `a[m-i]` is 0 when `m-i < 0` or `m-i >= n`).

This is `(w ⋆ a)[i] = sum_m w[m] * a[m-i]` (cross-correlation of w and a at lag i).

So `g[i] = (w ⋆ a)[i]` = `ifft(fft(w) * conj(fft(a)))[i]` (with zero-padding).

```python
def _compute_gradient_fft(a, w):
```

Let me now think about the **continuation schedule** more carefully.

The key insight is:
- Large T: the weights are spread across many peaks, giving a smooth gradient that moves the solution toward balancing all peaks.
- Small T: the weights concentrate on the top peak(s), giving a gradient that directly attacks the maximum.

A good schedule:
1. Start with T such that the top ~10% of peaks get significant weight.
2. Gradually decrease T over the course of the optimization.
3. At the end, T should be very small (attacking only the top 1-3 peaks).

Alternatively, use an **adaptive** T based on the current peak structure:
- If the top peak is much larger than the second, use small T.

Let me also consider a **different angle**: what if the optimal sequence has a specific structure?

Looking at the problem from the perspective of the convolution:
- We want `conv(a,a)[k]` to be as flat as possible.
- The sum of all `conv(a,a)[k]` is fixed (= S^2 = 1 if normalized).
- So we're trying to make a "flat" distribution over 2n-1 positions.

The constraint `a >= 0` is the key difficulty. If a could be negative, we could use a DFT-based approach: choose the DFT of a to be "flat" (all |A(f)|^2 equal), which gives a flat autocorrelation. But with the non-negativity constraint, this is impossible.

One approach: start with a "flat DFT" sequence (which has constant amplitude, like a ZC sequence), project it to be non-negative, and then optimize.

Actually, for a real sequence, the autocorrelation being flat means the power spectrum is flat, which means the sequence is "white noise-like" (uncorrelated). But a non-negative sequence can't be white noise (it's always positively correlated with itself at lag 0).
