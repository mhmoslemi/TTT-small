## 1. Approach and rationale

The previous method alternated between exact evaluation and first-order active-set linear programming for the nonsmooth max objective. That is a reasonable local tool but is easily trapped by the numerous nearly active lags and by boundary effects. The proposed program keeps exact‑objective acceptance but changes the search mechanism to a smooth generalized-maximum surrogate, then refines it over a continuation in the smoothing parameter. The smooth surrogate gradient is computed analytically from the finite-support linear correlation evaluator. This gives an equality–box constrained objective and gradient suitable for scipy’s successful equality-constrained SQP methods, while the returned and used bound is always recomputed from the actual evaluator.

The main idea is to minimize

\[
F_\tau(h)=\tau \log\left(\sum_{r=0}^{2n-2}\exp(Q_r(h)/\tau)\right),
\]

where \(Q(h)\) is the exact 2n−1 correlation values. As \(\tau\downarrow 0\), \(F_\tau(h)\) approaches the exact objective up to the small additive smoothing bias \(\tau\log(2n-1)\), after the necessary difference equation is made clear in Section 2. Each \(h\) produced by the smooth solver is immediately projected back to the original feasible set and evaluated with the exact objective; only exact objective decreases are accepted into the global best solution. Thus no relaxation is claimed and no final bound is based on the surrogate.

This method addresses two limitations of the prior attempted run:

1. The prior program only used nearly active lags and often became stale. The smoothing forms weighted combinations of all lags, initially many and later concentrated on the top lags; this lets paths cross small active-set changes and enables larger moves away from one local finite-lag structure.

2. The prior program did not explicitly exploit the smooth differentiability of the surrogate and a general equality constrained solver. A continuation with increasing sharpening can refine at nearly the exact maximum over the feasible hyperplane, not just over a small trust segment.

This is not a global optimizer. Tata search and best parent retention are explicitly retained because smooth local systems can be nonmonotone. Different smoothing sequences, resolutions, parent transform variants, and random perturbations are specified; all families are reported with the exact metric.

## 2. Mathematical specification

### Representation and exact objective

For an array length \(n\), dx = 2 / n. For entries \(0\le h_i\le 1\), a positive sample has units satisfying sum\(h_i dx\) = 1, equivalently sum\(h_i = n/2\). Let b = 1-h. Let

\[
P = 2n-1,
\qquad Q_r(h)=dx\sum_{\text{valid shifts }r}h_i(1-h_{r_i}),
\]

where the 2n−1 correlations are precisely those returned by

\[
Q = np\text{.correlate}(h,1-h,\text{mode='full'}) * dx.
\]

The exact reported score is

\[
C(h)=\max_{r=0}^{P-1} Q_r(h).
\]

Include every lag; do not replace with negative autocorrelation. The objective is asymmetrically sensitive to endpoint lengths because nonzero shifts overlap shorter intervals.

### Constraint set

The variables are \(h_i\). Constraints are simultaneous:

\[
0\le h_i\le1, \quad \sum_i h_i = n/2.
\]

These are assigned a value target \(t = n/2\). If \(n\) is odd, \(t=n/2\), a float value. This uses the given evaluation criterion exactly. Do not repeatedly clip and rescale in a way that loses either requirement; use the jointly constrained projection given below.

### Smooth surrogate and weights

For numerical stability compute instead of the direct log-sum-exp form

\[
F_\tau(h)=M(h)+\tau\log\left(\sum_r \exp((Q_r-M)/\tau)\right),
\qquad M=\max_r Q_r.
\]

This is exactly \(\tau\log\sum_r\exp(Q_r/\tau)\). Smoothing parameter \(\tau>0\) may be dimensional. It approximates the maximum with an additive bias \(\tau\log P\). We keep exact \(C(h)\) separately for answer acceptance. Define normalized weights

\[
w_r=\frac{\exp((Q_r-M)/\tau)}{\sum_s\exp((Q_s-M)/\tau)},
\quad \sum_rw_r=1,\quad w_r\ge0.
\]

Use a small floor such as exp 0 for underflows; weights sum is recomputed explicitly after normalization. For a zero row \(Q_r\), \(w_r\) may be zero unless all values are equal.

Gradient propagates through \(F_\tau\):

\[
\nabla F_\tau = \sum_r w_r \nabla Q_r.
\]

For small \(\tau\) the calculation must subtract M before exponentiating. This is the only gradient used.

### Gradient of the finite correlation rows

The returned array order in exact evaluation is the order used by the law associated with \(np.correlate(h,1-h,\mathrm{full})\). Let output index \(r\) correspond to lag \(\ell = r-(n-1)\), \(\ell\in[-(n-1),n-1]\).

To reduce indexing ambiguity, a initialization code should do a small numerical check for \(Q\) output rows; if the gradient row fails, do not launch the analytic SQP. Assuming that formula is valid, define the following row \(g_\ell\) with n entries:

- \(\ell=0\):  \((g_\ell)_i = dx(1-2h_i)\).
- \(\ell>0\):  
  for valid i satisfying \(i\ge\ell\): add dx(1- h_{i-\ell}); for i satisfying \(i+\ell<n\): add \(-dx\,h_{i+\ell}\); remaining entries 0. Equivalently,
  \[
  (g_\ell)_i = dx[(1-h_{i-\ell})_+] - dx[h_{i+\ell}]_+,
  \]
    with k terms truncated if i-\ell is valid and i+\ell valid; values closer to zero in 0 or negative beyond range enter only valid terms.
- \(\ell<0\), \(m=-\ell\): 
  for valid i satisfying 0\le i<n-m\): add dx(1-h_{i+m}); for i satisfying i\ge m\): add \(-dx h_{i-m}\); 0 otherwise. Equivalently,
  \[
  (g_\ell)_i = dx(1-h_{i+m})\text{ where }i+m<n - dx h_{i-m}\text{ where }i-m\ge0.
  \]

These formulas directly differentiate \(dx\,h_i(1-h_j)\) with respect to either the first or second factor. They scale by dx because q includes the discretization weight. The index mapping to output index \(M=\ell+n-1\) should also be tested with finite differences. At startup choose h which is not all 0/1 such as smoothed from valid input or 0.5 plus tiny random approximation, compute a random output index \(M\), and compare
\[
(Q(\text{tiny finite differences of grid})-\)/\text{ perturbation step}
\]
 to the row generated for M. A consistent analytic relation and correct gradient formulas imply the finite difference matching (roughly \( <1e-7\) absolute).

If first check fails with too big a mismatch, one correction attempt can swap the \(\ell>0\) and \(\ell<0\) assignments and recheck; if still bad do not run solver relying on the gradient. Otherwise the gradient is ready.

For each call, only the weighted sum \(\sum w_r g_r\) is needed. However, computing full dense rows is comfortable up to size 600; M=2n−1 rows.
