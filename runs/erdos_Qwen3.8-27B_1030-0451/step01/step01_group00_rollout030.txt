Actually, let me think about this more carefully. The function g(α) = max_k (c_k + α f_k) is convex and piecewise linear. Its minimum is at a point where the subgradient contains 0. This happens at a "kink" of the function, which is an intersection point of two of the lines {c_k + α f_k}.

The number of kinks is at most O(n) (since there are n+1 = 2n-1 lines, and each pair of lines intersects at most once, giving at most O(n²) intersection points, but only O(n) of them are on the upper envelope).

For a convex piecewise linear function with m pieces, we can find the minimum in O(m) time by walking along the pieces. But identifying which pieces are on the upper envelope is O(n²) in the worst case.

For practical purposes, my 40-evaluation approach should find a good approximation to the optimum. If I want to be more precise, I could use the fact that the derivative of g at α is f_{k*(α)} where k*(α) is the argmax. So I can do a "bisection on the derivative":
1. At α, compute k* = argmax(c + αf)
2. If f_{k*} < 0, the function is decreasing, so the minimum is at α' > α
3. If f_{k*} > 0, the function is increasing, so the minimum is at α' < α
4. If f_{k*} = 0, we're at the minimum (or on a flat region)

This is essentially binary search on a piecewise linear function, and it converges in O(log(n/ε)) steps. Each step requires O(n) to compute the argmax. So total is O(n log(n/ε)).

```python
def find_best_alpha(corr, f, alpha_max):
```

But wait, the bisection only works correctly if the function is actually monotone in the slope. For a piecewise linear convex function, the slope is non-decreasing, so bisection works. The issue is that at a kink point, the subgradient is an interval [f_{k1}, f_{k2}] where k1 and k2 are the two active constraints. If 0 is in this interval, we're at the minimum.

My bisection criterion (slope < 0 → go right, slope > 0 → go left) handles this correctly in the limit: as lo and hi converge to the kink, the argmax will flip between k1 and k2, and the slope will oscillate between f_{k1} < 0 and f_{k2} > 0. The final midpoint will be at the kink.

Actually, there's a subtlety: at a kink, the argmax is not unique. np.argmax will pick the first index, which might always give the same slope. Let me handle this by checking if there are multiple argmax values:

```python
        active = np.where(np.abs(vals - max_val) < 1e-10)[0]
        if len(active) > 1:

            slopes = f[active]
            if np.min(slopes) < 0 < np.max(slopes) or np.any(np.abs(slopes) < 1e-10):
                break

                lo = mid
            else:
                hi = mid

                lo = mid
            elif f[k_star] > 0:
                hi = mid
            else:
```

def project_constraint(p, n):
    target = n / 2.0
    p = np.clip(p, -2.0, 2.0)  # Ensure finite
    lo = np.min(p) - 1.0
    hi = np.max(p) + 1.0
    for _ in range(100):
        mid = 0.5 * (lo + hi)
        proj = np.clip(p - mid, 0.0, 1.0)
        s = np.sum(proj)
        if s > target:
            lo = mid
        else:
            hi = mid
    lam = 0.5 * (lo + hi)
    proj = np.clip(p - lam, 0.0, 1.0)
    diff = target - np.sum(proj)
    if abs(diff) > 1e-12:

        nm = int(np.sum(mask))
