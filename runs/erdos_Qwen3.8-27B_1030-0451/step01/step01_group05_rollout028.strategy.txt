1. Approach and rationale

1.1. Central idea

The primary search will be a **trust-region linearized active-lag solver** (TR-LP). At a feasible vector `h`, the exact objective is the maximum of the `2*n - 1` available overlap values. Instead of replacing that max by a smooth log-sum-exp surrogate and running a nonconvex SLSQP-style local solver, each proposed step is obtained from a **linear programming master problem** that keeps a linearized version of the current lag values and forces a new upper bound `t` on all modeled lags. The trust-region variables are the coordinate changes `x_i`; feasibility is enforced by linear variables that preserve the exact mass sum and keep each coordinate in [0,1]. The candidate generated by the solver is injected into the true evaluator. If the true score improves, it is accepted as the new center; if not, the trust region is reduced and a secondary **exact quadratic transfer-model** step is tried. Thus the linear model is only a guide: every accepted proposition is scored by the authoritative finite-support correlation max.

This is materially different from the previously used smooth surrogate/SLSQP and random pair-search modes. The new approach:
- directly linearizes all current overlap constraints in an LP, not a smoothed scalar penalty;
- searches jointly over all coordinates with a linear master problem under a mass-transportation trust radius;
- uses exact finite algebra only for local curvature correction, not as the primary proposal mechanism;
- caps dimension at moderate values (about 60–160) because the LP has variables and dense active-lag rows proportional to `n` and subquadratic pairs can be cleared locally at these dimensions.

1.2. Why it may improve the parent

The supplied parent is near the known numerical optimum, but previous SLSQP/pair-search results are limited by:
- surrogate bias: a log-sum-exp surrogate values all lags peacefully, not precisely the Minimax condition;
- first-order prediction: exact improvement might require curved directions that a scalar surrogate de-emphasizes;
- local basin trapping: pair moves using only current first-order gradient sort cannot realize coordinated mass moves that linear programming can choose among all forced constraints.

The TR-LP solves a convex subproblem:
  minimize t subject to all lag linearization constraints,
which is exactly the form needed for a graph-directed active set. It can find candidate-group制动器 mass moves not easily found by greedy transfers.

Because the bilinear terms were not solved exactly, the LP prediction may understate curvature. Exact evaluation lowers trust-face losses. Meanwhile, each accepted proposal is guaranteed feasible by linear variables plus optional joint projection. Exact quadratic correction handles curvature directions missed by linear mass-transfer curves.

This approach gives a plausible path to improve parent from an ~0.381 local basin toward current-record level by progressive active-set reoptimization plus exploration from alternative over-build initial feasible choices within fixed 1100s.

1.3. Limitations and non-optimality claims

- The original problem is nonconvex. The LP subproblem is convex only because the objective and current values linearly approximate the overlap. It is a trust/linearization model, not a global lower envelope certificate.
- The subproblem may produce a proposal that strictly decreases only the first-order model but increases the exact evaluator due to curvature and inactive-overlap interaction. A true score່悬殊 acts as rejection.
- The exact finite largest `2n - 1` maximization is the authoritative objective. No claim of mathematical global minimum is made. Candidate acceptance never uses the smooth or first-order model value except as a guide.
- Different dimensions correspond to different discrete problems; they are judged separately and the recommended resolution prefers smaller dimension only near ties. This is not to rate-by same numerical continuum across resolutions, but because codes have objective units such as time intervals-free constants.

1.4. Correctness constraints respected

The actual score is always:
```
C(h) = max(np.correlate(h, 1.0 - h, mode="full")) * dx
```
where `dx = 2/tlen`. Both positive and negative lags are considered because full backlash provides all side coordinates. Constraints are handled by respecting unit bound and sum linear algebra, not by applying clipping and rescaling arbitrary. At the end any inaccuracy is fixed by a feasibility projection computed from the current `h`.
