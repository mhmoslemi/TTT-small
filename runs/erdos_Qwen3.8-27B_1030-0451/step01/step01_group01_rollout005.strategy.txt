1. Approach and rationale
1.1 Central idea
Treat the discrete problem as a nonconvex minimax problem and solve it by repeatedly reducing the true evaluator objective, not a surrogate that is mistaken for the objective. Maintain a globally best feasible vector, generate several diverse feasible starts, and for each start perform a small but coordinated set of exact-objective operations:
- a weighted active-lag exact line search (including single strongest-lag gradients, not only a log-sum objective),
- 1-D pair-transfer searches using the evaluator directly,
- a nonlinear relaxation of the exact active mini‑max constraints with equality and box constraints using SciPy minimization (the relaxation is local; relaxation outcomes are accepted only after re-evaluation with the true evaluator),
- random and deterministic perturbations preserving the sum constraint, and
- optional moderate resolution enlargement from the best small-grid vector.

1.2 Why it could improve the provided parent
The supplied 84-sample construction is likely sitting in a neighboring basin of a local stationary point of the smooth log-sum approximation or of independently generated direction choices. Its exact active constraint set may contain multiple tight lagged correlations. Exposing these constraints directly in a small exact mini-max subproblem can move simultaneously in tangent directions that the previous sequential line search did not choose. Pair-transfer scans and re-randomized starts can reduce the risk of being trapped in a local basin whose threshold after discretization appears optimal. This approach is not claimed to be a globally optimal exact solver for the nonconvex problem, because no exact optimality certificate is possible with the budget. However, exact re-evaluation ensures that any returned bound is certified by the evaluator, and multiple candidate pools increase likelihood of an improvement.

1.3 Important limitations
- The exact objective is bilinear and nonconvex. Local SLSQP-based active relaxation does not prove global optimality.
- Selected constraints are a subset of all lags. Improving selected constraints may worsen unselected lags; acceptance is exact and therefore monotone in retained best value.
- Constraint gradients depend on being exactly consistent with `np.correlate(h, 1-h, mode="full")`. A combinatorial convention test is given below. If the gradient is syntheticly replaced with finite differences, performance decreases but correctness does not require knowing it.
- The program must stop before wall time ends. Some outer methods keep bounded internal stopping caps. Solver results are treated as proposals and re-evaluated before acceptance.

2. Mathematical specification
2.1 Decision vector and exact evaluator
For a returned sample count `n`, define `dx = 2.0 / n`. Let
`V(h) = np.correlate(h, 1.0 - h, mode="full") * dx`.
The exact objective is
`C5(h) = max(V(h))`.
This is used everywhere. It contains all 2n - 1 linear-lag correlations and includes both negative and positive shifts. The domain restriction is produced by the `full` correlation and boundary weights implicitly supplied by the finite length. Do not replace it by autocorrelation, circular correlation, or `1` minus anything without verification.

Feasible set:
`0 <= h[i] <= 1` for all i, and `sum(h) = n / 2` (equivalently integral = 1).

2.2 Joint feasibility repair
The feasible set is intersection of a box and one hyperplane. Implement `project_sum_box(x, target)` so that it never uses independent clip-then-rescale for repair, because that can break either range or sum.
Robust algorithm:
1. Use bisection on parameter `s` to find a clamped shifted vector `y(s) = clip(x + s, 0, 1)` whose sum is within tolerance of `target`.
2. If finite nonzero residual remains, add positive residual to indices with headroom `1-y` or subtract negative residual from indices with positive amount; push toward boundaries, followed by another small interior correction. Clip after each operation.
This helper is called whenever a generated, interpolated, solver-returned, or stored vector is accepted, and again before returning. Numerical sum tolerance `|sum - target| <= 1e-10 / 1e-12` is used unless budget has expired; if impossible, use the vector with smallest absolute sum error.

2.3 Correlation lag convention and gradient
For each correlation index `k = 0,...,2n-2`, create its signed lag `s = k - (n-1)` and overlap length `L = n - abs(s)`. Define two possible exact pair formulas per lag, and choose the convention by a deterministic one-time test against `np.correlate`.
Convention A:
- if `s >= 0`: pair slices `a = slice(s, n)`, `b = slice(0, n-s)`, terms `h[a] * (1 - h[b])`.
- if `s < 0`: set `t = -s`, `L = n + s`; slices `a = slice(0, L)`, `b = slice(t, n)`, terms `h[a] * (1 - h[b])`.
Convention B (swapped for the positive-lag branch; for negative branch use the corresponding swapped slices): goal is to match the actual `np.correlate` sequence exactly on small arrays.
Implementation inference `infer_pair_mode(n)`:
- Create a small deterministic test vector, e.g. `h_test = 1 + 0.013 * np.arange(n)` clipped to `(0,1)` or something with irregular distinct values; prefer fractional clipping or non-linear spacing so that prefix sums of distinct products do not collapse.
- For every `k` test both candidate pair sums against `corr_all[k]`, tolerance `1e-11 * tol`. If one match wins for all indices, set `PAIR_MODE = 'A'` or `'B'`. If both or neither match, repeat using another deterministic vector; if it still cannot infer, fall back to conservative finite differences for gradients and gradients exact only objective-based local scans.
When `PAIR_MODE` known, gradient of scaled correlation at index `k` multiplied by `dx` is obtained as:
`g = zeros(n)`
`g[a] += dx * (1 - h[b])`
`g[b] -= dx * h[a]`
where `(a,b)` are the slices for that `PAIR_MODE`. The sum constraint does not appear inside gradient; direction repair will preserve it.

2.4 Minimax constraints in reduced model
Directed problem solved repeatedly:
Decision vector `z = [h[0,...,h[n-1], t]`.
Minimize linear objective `t`.
Subject for selected indices `I`:
`t - V_k(h) >= 0`, for each `k ∈ I`.
Equality: `sum(h[:n]) - n/2 = 0`.
Box: `0 <= h[i] <= 1`; `0 <= t <= 1`.
Inequality convention in SciPy: the user supplies `phi_k(z) = t - V_k(h)` and requires `phi_k >= 0`. Its Jacobian row is
`d phi_k = [-grad_corr_k(h), -1]`
where `-grad_corr_k` is the negative of gradient of scaled correlation `V_k`. This is exact once gradients map to the true evaluator.
This subproblem is local and may be nonconvex if full objective is imposed (because terms are bilinear; product Hessian is indefinite). It is not claimed to be convex. The solver can impose a subset. Acceptance always recomputes complete `max(V(repaired h))`.

For an approximate search vector `y` with approximate weights (LSE or active gradients), the actual test is `C5(project_sum_box(h + step * d, n/2))`. Direction may be:
- `d1 = -sum(w_k * grad_corr_k)`, with smooth softmax weights,
- `d2 = -grad_corr_index(max_index)` strongest single, and
- `d3 = active_sumgrad minus a small weighted-average analog in a different sign?` For each cycle try all; whichever succeeds best after exact evaluation.
This avoids optimizing only global smoothed partial and relying on it.
