1. Approach and rationale

1.1 Central idea

Construct a materially different search that alternates between two exact, fully feasible mechanisms rather than the previous linear-quadratic nonlinear solver route:

1. A low-dimensional surrogate manifold, searched globally with a custom bounded differential-evolution loop. The surrogate is a logistic function of polynomial/orthogonal basis functions. Its bias term is root-solved so the integral constraint `sum(h) * dx = 1` is enforced exactly or near exactly at every function evaluation. This lets the program sample many shapes without relying on clipping-based repair that destroys feasibility.

2. A vector-space exact pair displacement search. For carefully selected pairs of samples the code moves two values by `+lambda` and `-lambda`, preserving the sum exactly up to floating-point rounding, and evaluates the true evaluator objective for every proposed displacement. This local method is intentionally cheap and aims only at small, monotone improvements in the original discrete metric.

The program never optimizes a replacement circular-correlation objective, never drops boundary terms, and never reports a convex bound without an exact candidate. Its output is always a feasible step vector and the exact max value of `np.correlate(h, 1-h, mode='full') * dx`.

1.2 Why this may improve the supplied parent

The supplied parent is already a strong local solution. To get below its value, the search needs both:

- escape possibly narrow basins created by many nearly active constraints, and
- very accurate acceptance testing of candidate changes.

The previous parent-based refinement spends significant effort on large linear/quadratic localizations and general-purpose constrained solvers. The new method changes basis in three ways:

- Global diversity is obtained by a low-dimensional smooth family, not by perturbing the full high-dimensional vector directly. This finding is a mathematical fact: a continuous logistic basis covers a wide manifold of admissible shapes. The claim that it finds a better value is a heuristic hypothesis, not an optimality claim.
- The exact discrete objective is preserved in every acceptance test. This is exact by construction.
- Vector refinement uses elementary pair moves because they exactly preserve the mass constraint without general projection, and exact line candidates are scored by the original evaluator.

This also makes use of a practical viewpoint about the evaluator: the evaluator only maximizes over the finitely many sampled lags. Therefore another part of the plan deliberately explores smaller resolutions that are still meaningful enough to be useful. This is not a proof that smaller is better for the underlying continuous problem, but it is a legitimate algorithmic variation for the stated discrete optimization target.

1.3 Overall pipeline

The implementation:

1. Validates the global `initial_h_values` as a parent fallback. If absent, constructs a deterministic fallback and adds it to best-candidate storage.

2. Tries a bounded vector-pair local descent directly on the parent at its native resolution and at several resampled resolutions.

3. Runs a low-dimensional logistic-basis differential-evolution search at selected resolutions and dimensions. Candidate population submissions are always exact feasible vectors generated by the family evaluator.

4. Whenever the low-dimensional global search reaches a dispatch criterion, passes only selected discrete candidates through the exact pair-displacement local minimizer.

5. Chooses between all valid candidates. Choose by exact discrete evaluation, and within a tolerance of 1e-10 in C_5 prefer fewer samples. This preference is free in the current discrete evaluation.

The algorithm must never discard the parent unless a valid candidate of exact-evaluation no worse is confirmed.

2. Mathematical specification

2.1 Discrete representation

For each candidate resolution `n_points` that the program considers n points > 0. The vector is `h` of shape `(n_points,)`. The midpoint grid is

`dx = 2.0 / n_points`,
`x_i = (i + 0.5) * dx, i = 0,...,n_points-1`.
