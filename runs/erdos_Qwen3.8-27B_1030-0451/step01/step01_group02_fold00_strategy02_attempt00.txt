1. Approach and rationale

1.1 Central idea

The parent construction is a continuous fractional solution. A materially different path to a better discrete bound is to first convert it into balanced binary problems of the size used by the evaluator, then improve those discrete configurations with combinatorial stochastic local search. The key innovation is that the search is not continuity-preserving: it works in 0/1 vectors while preserving `sum(h) = n_points/2` exactly by exchanging a 1-bit with a 0-bit. Every move is tested in the original objective with the official correlation evaluator, so no relaxed objective, circular convolution, or unnormalized autocorrelation substitute is used.

Why this can improve the parent:

- The current best reported bound is very close to a quantized discrete optimum. The gap between parent levels corresponds to a small number of discrete overlap-count levels. A successful combinatorial move that lowers the active overlap count by only a few units can produce the desired bound.
- A fractional local search can change several coordinates genuinely, but many distinct improvements are more naturally discovered by moving hard discontinuities of the solution. Once near a binary pattern, the conflicting overlap constraints are effectively about which discrete boundaries exist between positions distance `d` apart. Active-lag-distance swaps exchange neighboring boundary structure directly.
- Simulating local discrete neighborhoods can escape the continuum basin of the supplied vector. The stochastic component allows equal-cost rearrangements, since overlap minimizers often have many interchangeable equal-maximal lag states.
- Multi-resolution trials are allowed because the returned objective is evaluated on whatever vector is returned. Shorter resolved states can give a smaller discrete maximum; the code does not artificially prefer larger arrays except when the current result from identical bound resolution is worse.

Correctness boundary:

- The method is a heuristic local/stochastic search, not a proof of global optimality.
- Every proposed possiblily are accepted only when, after feasibility repair or after a feasible transfer, they do not exhibit bound violation on the original evaluator.
- No solver claims a global optimum. Invalid suggestions from feasibility screening do not degrade accepted states.

1.2 Three main stages

The chain is:

1. Validate or construct a continuous parent solution.
2. Generate many balanced binary configurations at selected finite grids (0/1 vectors with exactly the support count `n_points/2`), and run active-distance stochastic local search under the exact discrete/continuous objective.
3. Optional greedy continuous refinement around the incumbent, using exact feasible pairwise bit/mass transfers.

All improvement releases are evaluated using:
