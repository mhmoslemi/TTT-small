For a binary solution, the key insight is:
- The objective is C₅ = max_d O(d) * dx
- We want to minimize the maximum O(d)
- A good heuristic: focus on reducing the lags that are currently at or near the maximum

**Move types:**
1. **Single flip (with compensation)**: Flip h[i] from 1→0 and h[j] from 0→1. This maintains the sum constraint.
2. **Block swap**: Swap a contiguous block of 1s with a contiguous block of 0s of the same length.
3. **Rotation**: Rotate the entire pattern by 1 position (circular). This doesn't change the circular autocorrelation but changes the non-circular one due to boundary effects.

- Temperature schedule: start high, decrease geometrically.
- At each step, propose a random move, compute ΔC₅, accept with probability min(1, exp(-ΔC₅/T)).
- Periodically (every K steps), do a "reheat" to escape local optima.

**Better approach: Gradient-guided local search**

1. Compute the current C₅ and the active lags.
2. Compute the "pressure" on each position: for each position i, compute how much increasing h[i] would help (decrease the active lags) vs hurt.
3. Use this to guide which swaps to try.

The gradient of O(d) at the active lags gives us this information. Specifically:
- If ∂O(d*)/∂h[i] > 0 (for an active lag d*), then increasing h[i] would increase O(d*), which is bad. So we want to decrease h[i].
- If ∂O(d*)/∂h[i] < 0, then increasing h[i] would decrease O(d*), which is good.

So the "descent direction" for h[i] is: we want to decrease h[i] when the net gradient is positive, and increase h[i] when the net gradient is negative.

For a binary solution, this translates to: if h[i] = 1 and the net gradient at i is positive, we want to flip i to 0 (and flip some j with h[j]=0 and negative gradient to 1).

```python
def compute_active_gradient(h, n_active=10):
    """Compute gradient contributions from the most active lags."""
    N = len(h)
    dx = 2.0 / N
    corr = np.correlate(h, 1.0 - h, mode='full') * dx
    c_max = np.max(corr)
    
    # Find top lags
    sorted_lags = np.argsort(-corr)
    active_lags = sorted_lags[:n_active]
    
    # Compute gradient as sum over active lags
    g = np.zeros(N)
    for r in active_lags:
        d = r - (N - 1)
        weight = corr[r] / c_max  # normalize by max
        if d >= 0:
            n = N - d
            g[:n] += weight * (1.0 - h[d:])
            g[d:] -= weight * h[:n]
        else:
            dd = -d
            n = N - dd
            g[:n] += weight * (1.0 - h[dd:])
            g[dd:] -= weight * h[:n]
    
    return g
```

The move generation: for a bottleneck lag d*, we want to reduce O(d*). This means we want to change some h[i]=1, h[i+d*]=0 pairs to either h[i]=0, h[i+d*]=0 or h[i]=1, h[i+d*]=1.

The first option (set h[i]=0) means we flip position i from 1 to 0 (and flip some other position from 0 to 1 to maintain the sum).
The second option (set h[i+d*]=1) means we flip position i+d* from 0 to 1 (and flip some other position from 1 to 0).

So the "targeted move" for bottleneck lag d* is:
- Find a position i where h[i]=1 and h[i+d*]=0.
- Flip h[i] to 0 and h[i+d*] to 1 (or flip h[i] to 0 and some other 0 to 1).

This directly reduces O(d*) by 1 (or 2 if we do the second option).

Let me implement this:

```python
def targeted_swap(h, d_star, rng):
    """Find a swap that reduces O(d_star)."""
    N = len(h)
    # Find positions where h[i]=1 and h[i+d_star]=0 (for d_star >= 0)
    if d_star >= 0:
        n = N - d_star
        candidates = np.where((h[:n] == 1.0) & (h[d_star:] == 0.0))[0]
    else:
        dd = -d_star
        n = N - dd
        candidates = np.where((h[dd:] == 1.0) & (h[:n] == 0.0))[0]
    
    if len(candidates) == 0:
        return None
    
    # Pick a random candidate
    i = candidates[rng.integers(len(candidates))]
    
    if d_star >= 0:
        # Flip h[i] from 1 to 0, and h[i+d_star] from 0 to 1
        j = i + d_star
    else:
        # Flip h[i+d_star] from 1 to 0, and h[i] from 0 to 1
        j = i + d_star  # this is i - dd, which is the position with h=0
    
    # Wait, I need to be more careful.
    # For d_star >= 0: we want h[i]=1, h[i+d_star]=0.
    # Option A: flip h[i] to 0. Need to flip some other 0 to 1.
    # Option B: flip h[i+d_star] to 1. Need to flip some other 1 to 0.
    # Option B is a "free" swap: flip h[i] stays 1, h[i+d_star] becomes 1.
    #   But we need to maintain sum, so we need to flip some other 1 to 0.
    # Actually, for a direct 2-swap:
    #   Flip h[i]: 1→0 and h[i+d_star]: 0→1. This maintains the sum!
    #   And it reduces O(d_star) by 1 (the pair (i, i+d_star) no longer contributes).
    #   But it might increase O(d') for other lags d'.
    
    # So the swap is: h[i] and h[i+d_star] (or h[i] and h[i-d_star] for negative d)
    # This is a "local" swap that targets the specific lag.
    
    return i, j
```

This is a very targeted move! Let me build the algorithm around this.

**Algorithm: Targeted Binary Local Search**

1. Compute C₅ and identify the lag(s) d* achieving the maximum.
2. For the bottleneck lag d*, find all "bad pairs" (i, i+d*) where h[i]=1, h[i+d*]=0.
3. For each bad pair, compute the "cost" of the swap: how much would other lags increase?
4. Perform the swap with the lowest cost (that still reduces the maximum).
5. Repeat.

The "cost" computation is the expensive part. But we can approximate it:
- The swap at (i, i+d*) changes O(d') by at most 4 for each d' (the positions i and i+d* each affect at most 2 terms in O(d')).
- So we can compute the exact change in O(d') for all d' in O(N) time.

So ∂O(d)/∂h(i) = (1-h(i+d)) * 1[i ≤ N-1-d] - h(i-d) * 1[d ≤ i ≤ N-1]

For a change δ in h(i): ΔO(d) = δ * ∂O(d)/∂h(i)

For two changes δi at position i and δj at position j:
ΔO(d) = δi * ∂O(d)/∂h(i) + δj * ∂O(d)/∂h(j)
