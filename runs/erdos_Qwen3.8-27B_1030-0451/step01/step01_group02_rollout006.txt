- For k = 0: h(x)(1-h(x)) = 0 everywhere → integral = 0
- For k = 0.5: h(x) = 1 when x ∈ [0,1), h(x+0.5) = 1 when x+0.5 ∈ [0,1) i.e. x ∈ [-0.5, 0.5)
  So h(x)(1-h(x+0.5)) = 1 when x ∈ [0, 0.5) (h(x)=1, h(x+0.5)=0) → integral = 0.5
  Wait, h(x+0.5) = 1 when x+0.5 ∈ [0,1), i.e., x ∈ [-0.5, 0.5). So for x ∈ [0, 0.5): h(x)=1, h(x+0.5)=1 → h(x)(1-h(x+0.5)) = 0
  For x ∈ [0.5, 1): h(x)=1, h(x+0.5)=0 → h(x)(1-h(x+0.5)) = 1
  For x ∈ [1, 1.5): h(x)=0 → 0
  For x ∈ [1.5, 2): h(x)=0 → 0
  Integral = 0.5

- For k = 1: h(x)(1-h(x+1)):
  x ∈ [0,1): h(x)=1, h(x+1)=0 → 1
  x ∈ [1,2): h(x)=0 → 0
  Integral = 1

  So C₅ = 1 for this simple square wave. That's terrible.

  For k = 1.5: h(x)(1-h(x+1.5)):
  x ∈ [0, 0.5): h(x)=1, h(x+1.5)=0 (since x+1.5 ∈ [1.5, 2)) → 1
  x ∈ [0.5, 1): h(x)=1, h(x+1.5)=1 (since x+1.5 ∈ [2, 2.5) but we only have [0,2])
  
  Wait, in the discrete setting with mode='full', the correlation only includes terms where both h[i] and h[i+k] are valid indices. So for the continuous analog, we'd only integrate where both x and x+k are in [0,2].

  For k > 0: ∫₀^{2-k} h(x)(1-h(x+k)) dx
  For k < 0: ∫_{|k|}² h(x)(1-h(x+k)) dx = ∫₀^{2-|k|} h(x+|k|)(1-h(x)) dx

  So for the square wave h = 1 on [0,1), 0 on [1,2):
  k = 1: ∫₀¹ h(x)(1-h(x+1)) dx = ∫₀¹ 1*(1-0) dx = 1
  
  That's the worst case. C₅ = 1.

  What about a "balanced" sequence? If h alternates: 1,0,1,0,... for n=720 (360 ones, 360 zeros):
  k = 1: h(x)(1-h(x+1)) counts 1s followed by 0s = 360 (for the non-wrapping case, it's about 359)
  k = 2: h(x)(1-h(x+2)) counts 1s followed by 1s at distance 2 = 0
  k = 3: same as k=1 by periodicity: 359
  etc.
  
  So the max is about 360, giving C₅ = (2/720) * 360 = 1. Still bad.

  What if we use a more complex pattern? Like a Thue-Morse sequence or a de Bruijn sequence?

  Actually, for the problem at hand, the key is to minimize the MAXIMUM over all lags. The optimal solution should "spread" the overlap evenly across all lags.

  Let me think about what the theoretical minimum is. We have n/2 = 360 ones. For each pair of positions (i, j) with h[i]=1, there's a contribution to lag (j-i) and lag (i-j). The total number of (1,0) ordered pairs is (n/2)*(n/2) = n²/4. These pairs are spread across 2n-1 lags (well, n-1 positive and n-1 negative lags, plus lag 0 which is always 0 for binary).
  
  If perfectly balanced, each lag would have n²/4/(2n-2) ≈ n/8 ones. So C₅ ≈ (2/n) * n/8 = 1/4
