1. Approach and rationale

The current parent is already close to the known numerical optimum, so the objective is to leave its immediate basin without losing feasibility or failing within the fixed time limit. The parent-level smooth gradient methods can be effective, but they are easily attracted to stationary points of a particular smoothing temperature or pair-move heuristic. This plan uses a different local operator built directly from the discrete evaluator: a two-point mass-exchange step for which the entire overlap vector is available as an exact pointwise formula. For each exchange candidate, a candidate lag-overlap vector is produced exactly, rather than inferred from one full correlation call per random/move trial. This allows many more exact line evaluations than are possible by recomputing the full correlation many times.

The core idea is:

- Represent the discrete state as:
  - a feasible step vector `h` of length `n`;
  - the non-smooth objective `max(raw_lags) * dx`, where `raw_lags` is the unscaled `np.correlate(h, 1-h, mode="full")` result.
- Make a tentative transfer of mass between two coordinates: increase one coordinate by `d` and decrease another by `d`. Bounds guarantee `0 <= h_i <= 1` and the sum always remains exactly the same.
- For any fixed exchange pair `(a,b)`, derive an exact formula for the full overlap vector as a quadratic function of `d`. This formula is not merely a first-order linear approximation; it includes the exact quadratic self-term and exchange-term contributions created by products `h_a(1-h_b)` and `h_b(1-h_a)`.
- Minimize a search-friendly version of the exact one-dimensional exchange objective using grid scans and local refinement, then evaluate the best accepted candidate with the authoritative discrete objective.
- Use active-lag-weighted gradients only for selecting promising exchange pairs; acceptance is always based on exact values, not the gradient surrogate.
- Surround the coordinate descent with simulated-exchange and randomized-start escapes so that coordinate moves are not the only route out of the parent basin.

Why this can improve the supplied parent or solve the task:

- Fact: the finite objective is a maximum over `2n-1` finite-support linear-correlation lags. A correct pair-exchange update can be generated exactly from state vectors without calling the correlation function for every proposed move.
- Hypothesis/justified heuristic: at near-record scores, the active set of lags is small. An exchange step that optimizes the exact overlap vector for one pair can reduce the maximum by adding to coordinates whose sensitivity to the active lag set is small and removing from coordinates whose sensitivity is large.
- Fact: after every accepted two-point move, the sum is conserved exactly by algebra, and bounds are respected by the exchange interval. Feasibility is maintained by construction rather than by repeated projections.
- Limitation/hypothesis: smooth gradient and smoothing-Tau information may choose misleading pairs because the scalar dual objective is not convex. Candidate acceptance corrects this by exact scoring, but some good moves remain hidden in untested directions. Simulated exchange and multistart are heuristics for escaping those basins; their effectiveness is not guaranteed.

This approach is intentionally different from successive clipped full-vector projections, fixed-gain augmentations, and pure Frank-Wolfe gradient directions. It focuses the search on a richer parameterization of exact line moves: transfers between pairs are optimized under the evaluator rather than only adjusting along a global projected smoothed point.

2. Mathematical specification

Let `n` be the number of sample points. Define:

- `dx = 2 / n`
- desired integral `S = 1`
- exact sum constraint: `sum(h) = n / 2`
- bounds: `0 <= h_i <= 1`, all components finite.

The authoritative discrete objective is:

`Score(h) = max(K in 0..2n-2) [ correlation(K) * dx ]`

where `correlation = np.correlate(h, 1-h, mode="full")`.

Define the raw lag array:

`raw(K) = np.correlate(h, 1_h, mode="full")[K]`

and the scaled objective array:

`objectives(K) = raw(K) * dx`.

The center lag index is:

`center = n - 1`

and the integer shift associated with lag `K` is:

`shift = K - (n - 1)`.

2.1 Pairwise transfer update and exact overlap formula

Take two different coordinate indices `a` and `b`. Define a line move:

`h_i'(d) = h_i + u_i d`

where `u_a = 1`, `u_b = -1`, and `u_i = 0` for all other indices.

The domain interval is the intersection of both coordinate constraints:

`d` for coordinate `a`: `0 <= h_a + d <= 1`

`d` for coordinate `b`: `0 <= h_b - d <= 1`

Thus:

`d_lo = max(-h_a, h_b - 1)`  
`d_hi = min(1 - h_a, h_b)`

If `d_hi < d_lo`, clamp both to `0` because numerical roundoff made an impossible interval.

Important fact: along this line, the overlap objective for every lag is exactly quadratic in `d`:

`raw_new(K; d) = raw(K) + d * lin(K) + d^2 * quad(K)`,

where `lin(K)` is the first-order sensitivity of the raw correlation to increasing `a` and decreasing `b`, and `quad(K)` is an explicit small structured correction.

Define the raw sensitivity coefficient for one coordinate change (increase only):

`col_i(K) = d raw(K) / d h_i`.

A coordinate `i` appears as the first member of a nonzero product in correlation terms with partner `j = i + shift`, where `j` is any index. Likewise, it appears as the second member in terms with partner `j = i - shift`. Therefore:

`col_i(K)` receives `+ (1 - h_{i+shift})` whenever the partner `j = i+shift` is valid; and receives `- h_{i-shift}` whenever `j = i-shift` is valid.

For numerical efficiency, this row can be built using slice additions. With `L = 2n - 1`, let `center = n - 1`. Initialize `col = zeros(L)`. Then:

- First occurrence slice:

  `start_first = center - i`  
  `col[start_first : start_first + n] += 1 - h[:]`

- Second occurrence slice:

  `col[i : i + n] -= h[::-1]`

This slice expression is equivalent to checking all valid products for coordinate `i`. It can be left-supported for any ordinary in-range `i`.

For transfer pair `(a,b)`:

`lin = col_a - col_b`.

Exact quadratic term:

`quad = zeros(L)`.

The quadratic correction comes from the expansion of products `(h_a + d)(1 - (h_a + d))`, `(h_b - d)(1 - (h_b - d))`, and the cross terms where `a` pairs with `b` or `b` pairs with `a`:

- self terms: for coordinate pairs where first and second are the same coordinate, the quadratic coefficient is negative. With the transfer moving `a` by `+d` and `b` by `-d`, the combined raw contribution for the two self terms is `-2`.
- pair cross terms: if `a` pairs with `b`, the cross term has a positive quadratic contribution `+1`; if `b` pairs with `a`, the reverse lag also has a quadratic contribution `+1`.

Therefore:

`quad[center] -= 2`

If `a != b` (the normal positive time nonzero terms):

`quad[center + (b - a)] += 1`

`quad[center + (a - b)] += 1`

These indices are guaranteed to be between `0` and `2n-2` because `a,b` are valid coordinates. The same raw array order will have `center + a - b` for the reverse shift.

For any `d`:

`raw_new = raw + d * lin + quad * d * d`

The exact scalar overlap score along the line is:

`score_line(d) = dx * max_k raw_new(k)`

This is exact for the finite board. It avoids the common pitfall of approximating only the first derivative of `h_i(1-h_j)`. At the objective value level, the exact score one can interpret with objective units. If an implementation stores objective units directly (scaled by `dx`), the same expressions apply with all quantities multiplied by `dx`, including the quadratic term. Choose one convention and keep it consistent. A recommended convention is to maintain the uncorrelated correlation array `raw` plus the three exact quadratic filers in `raw` notation. Do not mix with the scaled array during one dutive step.

This line exactness is exact because each product type has first-order-change vector and a rank vector over the affected correlation indices; the resulting lag is quadratic since it doesn't have higher-order terms.
