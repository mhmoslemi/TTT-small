1. Approach and rationale

1.1 Central change versus the previous smooth-max/SLSQP approach

The authoritative evaluator is a nonsmooth maximum over discrete lags:

C5(h) = max_l dx * np.correlate(h, 1 - h, mode="full")[l], where dx = 2.0 / n.

The supplied parent/near-parent construction and the previous program suggest that a single smoothed log-sum-exp surrogate plus SLSQP has become stuck in a flat local plateau. In that regime the exact optimum is controlled by a small number of active or near-active correlation lags; smoothing all lags simultaneously overweights irrelevant lags and compresses the active constraint structure. SLSQP then solves a different stationary problem than the nonsmooth maximum.

This plan uses a different primary optimization mechanism:

- It never optimizes the true nonsmooth objective through a full-dimensional constrained nonlinear program.
- At each feasible iterate, it computes one exact correlation vector and constructs a few first-order tangent directions built only from the active/near-active maximum correlations.
- For each such direction, it performs an exact one-dimensional line search over the original feasible set, evaluating the authentic evaluator at the projected points.
- A step is accepted only if the exact C5 decreases by a strict tolerance.
- Multiple starting formulations are evaluated, including the supplied parent, harmless value-permutation families, Fourier low-rank variants, and simple cyclic reversal variants.
- If computation time allows, a resolution ladder is used: the best coarse solution is interpolated to a finer grid and polished; the final answer is judged only by the exact discrete objective on the returned grid.

This is materially different from previous smooth schedules and solvers. It treats the exact nonsmooth maximum directly through line-searched tangent directions, and it does not depend on solving a smoothed full problem.

1.2 Why this could improve the current construction

The remaining gap from about 381121 to about 38085 or 3808 is small. Such small improvements in a minimax overlap problem often require balancing the exact peak values of several lags. Active-lag direction generation makes the algorithm explicitly target the lags that are actually contributing to the maximum. The exact one-dimensional search avoids excessive stiffness/step-size damage. Because every accepted update is exactly evaluated, the algorithm cannot accumulate surrogate-model regressions that hide a bad step. The low-dimensional seed families and resolution ladder give independent opportunities to arrive at a better basin.

1.3 What is a mathematical fact and what is only a heuristic

Facts:

- The problem is a finite-dimensional bilinear nonconvex optimization problem because each correlation product contains h_i * h_j.
- The metric stated in the task is exact, and all candidates must be judged by that metric.
- The current program provides only a heuristic trial construction. No global optimum is claimed.

Heuristics:

- Active-lag projections and line searches are intended to produce descent directions for the true maximum, but the objective may still have nearby maxima with all first-order proposals failing due to minierno constraints.
- Fourier and value-reordering seeds are only meant to provide alternate starts; they are not proven better.
- Resolution polishing can improve or worsen the exact discrete maximum because the evaluator changes the set of discrete shifts; every resolution candidate is accepted only after exact comparison on its own grid.

2. Mathematical specification

2.1 Representation, units, and exact objective

For a returned numeric vector h of length n:

- h must be a one-dimensional float64 array.
- dx = 2.0 / n.
- The exact evaluator, and only this evaluator, defines the return value:

```

```

The vector np.correlate(..., mode="full") has length 2n - 1. The central entry at index n - 1 is lag/offset zero; entries on both sides both directions are included.

The feasibility constraints are:

- For all i: 0 <= h[i] <= 1.
- sum(h) * dx = 1, equivalently sum(h) = n / 2.

The returned objective must satisfy the exact evaluator applied to the exact returned array, after final feasibility repair.

2.2 Correlation/indexing convention needed for gradients

For gradient generation, use the standard NumPy correlation definition induced by:

np.correlate(h, v, mode="full")

Equivalently, for length n:

c[ell] = dx * sum over pairs (i, j) such that j - i = r(ell) of h[i] * v[j]

where

```
r(ell) = (n - 1) - ell, ell = 0, 1, ..., 2n - 2.
```

Here v[j] = 1 - h[j]. This mapping is important. It includes both lag directions because r takes values from n - 1 down to -(n - 1).

For a given correlation index ell:

- If r = (n - 1) - ell >= 0, the valid pairs are (i, i + r), i = 0, ..., n - 1 - r.
- If r < 0, let a = -r > 0. Valid pairs are (j + a, j), j = 0, ..., n - 1 - a. Equivalently i = j + a, j = 0, ..., n - 1 - a.

Each correlation is

c[ell] = dx * sum_pairs h[i] * (1 - h[j])

with terms missing outside the finite support interval. Do not replace the target by a periodic rotation or by 1 minus an autocorrelation minimum without preserving the boundary terms; the exact evaluator is finite-support linear correlation.

2.3 Gradient of an individual correlation lag

Let w[ell] be a scalar weight for the correlation at index ell. We multiply c[ell] by w[ell] and differentiate. For each valid pair (i, j):

- d/d h[i] of h[i] * (1 - h[j]) = 1 - h[j].
- d/d h[j] of h[i] * (1 - h[j]) = -h[i].

Therefore multiply by dx.

A top-level helper routine that the coder must implement, e.g. `accumulate_grad_term(grad, ell, h, weight, dx)`, does exactly:

- offset r = (n - 1) - ell.
- For weight = 0, do nothing.
- If r >= 0:
  - lo_i = 0, hi_i = n - 1 - r.
  - hi_i >= lo_i means valid overlap.
  - grad[lo_i : hi_i + 1] += weight * dx * (1.0 - h[lo_i + r : hi_i + 1 + r])
  - grad[lo_i + r : hi_i + 1 + r] -= weight * dx * h[lo_i : hi_i + 1]

- If r < 0:
  - a = -r
  - lo_j = 0, hi_j = n - 1 - a
