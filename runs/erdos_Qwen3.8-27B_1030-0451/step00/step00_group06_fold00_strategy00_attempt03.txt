1. Approach and rationale

The central idea is a deterministic, budget-aware, active-set projected-gradient/minimax local refinement of the supplied parent, followed by resolution refinement and a final exact rational-grid projection of the selected vector. The nonconvex objective is the maximum over all finite-support lags of
F_d(h)=dx sum_i h[i](1-h[i+d]).
A smooth global choice (e.g. log不归 one fixed surrogate) is often poor because maximum constraints are very sparse and the true optimum is a critical surface. Instead, in each phase, we optimize a weighted average of the currently largest constraints. This average is smooth; its gradient gives a descent direction on the active set, and we check the true unsmoothed evaluator before accepting. This addresses the main bottleneck of local minimax algorithms: the flat max makes many constraints irrelevant, while unmodeled hidden constraints can rise into the maximum. The method mitigates this by expanding the active set, decreasing tolerances, repeatedly using line searches on the true metric, and using parent/resolution transfers to broaden neighborhoods.

Method limitations are explicit: the method is local/nonconvex and cannot claim a global optimum. The goal is a certified improvement of a supplied parent by using true evaluator acceptance only. Acceptance of raw floating candidates is always cross-checked by the final exact-grid vector. If the final rounding produces a worse true value, the final `run` returns a previous validated solution, not just the raw accepted one.

Main pipeline:
1. Validate/repair and exactly make feasible the supplied parent.
2. Run an active-set projected-gradient descent with staged active-containing tolerances, stochastic escapes, and randomized small perturbations at parent resolution.
3. Transfer parents to small/medium targets up to a strict maximum (larger only if time permits).
4. Optimize transferred candidates with the same local routine.
5. Always keep a globally best exactly feasible array and its true bound returned by the official evaluator.
6. Before and after the time limit, construct an exact binary-fraction output for the globally best raw candidate and return such a vector. If no parent/converged candidate works, a deterministic feasible fallback is available.

2. Mathematical specification

2.1 Input and feasible set
Let `N` be a positive integer and `dx=2.0/N`. We require:
- `x[i] in [0,1]`;
- exactly feasible sum: `sum_i x[i] = N/2`;
- true objective:
```
C5_true(vector) = max_k (dx * sum over valid indices h[i] * (1-h[i+d_k]))
```
where `d_k = k-(N-1), k=0,...,2N-2`. The evaluator uses
`np.max(dx*np.correlate(h,1-h,mode='full'))`.

For local machinery, define an internally selected lag array. Let `g[i]=1-h[i]`.
Define internal values `I[k]` for the `2N-1` shifts `d = k-(N-1)`:
```
I[dindex] = dx * sum over first indices A valid (A+d=N-> valid) h[A]*(1-h[A+d]).
```
Equivalently:
```
If d >= 0: valid first indices A = 0 .. N-d-1; value = dx*dot(h[0:N-d], g[d:N])
If d < 0:  valid first indices A = -d .. N-1;  value = dx*dot(h[-d:N], g[0:N+d])
```
The objective set `{I[d]}` is the exact same set as the evaluator’s terms because evaluator terms at lag `d` equal internal terms at lag `-d`. Therefore `max(I)==max(np.correlate(h,1-h)*dx)` exactly for every h. In computations, use this internal formulation for all gradient/active operations if desired. If using a faster array,
```
I[0:2N-1] = dx*np.correlate(h, 1-h, 'full')[::-1]
```
belongs to this internal convention. The final returned bound must still be re-evaluated with the official `np.correlate` formula.

2.2 Active constraints and weighted gradient
At a current `h`, let `I=True` internal objective values and `m=max(I)`. Let `T_stage` be a tolerance. Choose:
```
active_indices = top_K indices sorted by I; or all indices with I>=m-T_stage; capped by K_max currently.
soft_weights[j] = exp(-(m-I[j])/tau), for active, tau=(T_stage/4+1e-10)
soft_weights /= max(sum(soft_weights),1e-300)
```
Stage parameters are supplied below. The weighted scalar is
```
Q(h)=sum_j w[j] * I_j(h)
```
For one lag `d` with weight `w`, weighted contribution `w*dx*F_d`. Its derivative `U[d,w]` on variables is:
For `d >= 0`:
- first variables `A = 0..N-d-1`: add `w*dx*(1-h[A+d])`.
- second variables `A+d` for A=0..N-d-1: add `-w*dx*h[A]`.
For `d < 0`:
- first variables `A = -d..N-1`: add `w*dx*(1-h[A+d])` because `A+d >=0`.
- second variables `A`? More clearly vectorized: for negative d, the same pairs are `A_pair_first=-d..N-1` and `B_pair=A_pair_first+d`. Use slice form:
```
g_array(A_slice) += w*dx*g_array(B_slice)
g_array(B_slice) += -w*dx*h_array(A_slice)
```
More carefully for `d<0`, first slice `A = np.arange(-d,N)`, second slice `B = np.arange(0,N+d)` has equal lengths and represents `B=A+d`. Add derivative over arrays `g[A]+=w*dx*g[B]` and `g[B]+=-w*dx*h[A]`. This same slice implementation is for both signs: if `d>=0`, first slice `A=0:N-d`, second slice `B=d:N`; if `d<0`, first slice `A=-d:N`, second slice `B=0:N+d`.

For each active term, perform those two vectorized additions. Sum contributions over all active terms gives raw gradient `Graw`.

To maintain `sum h` first order, subtract mean:
```
Gt = Graw - (sum(Graw)/N)*ones(N)
```
This is only a tangent projection; after the step, repair feasibility again.

2.3 Projection under box and sum constraint
Given raw vector `y` in `[0,1]`, return `proj` with feasible sum by proportional capped repair:
- Start `x=clip(y,0,1)`.
- `A=float(N)/2`.
- For up to 30 iterations:
  - `e=A-sum(x)`
  - break if `abs(e)<=1e-13*N`.
  - if `e>0`: `slack=np.maximum(0,1-x)`; `slotsup = (slack>1e-15)`; if none, break and return infeasible.
    `add = e*slack/slotsup.sum`; `add=np.minimum(add,slack)`; `x += add`.
  - if `e<0`: `slack=np.maximum(0,x-0)`; `slotsdown=(slack>1e-15)`; `sub = abs(e)*slack/slotsdown.sum`; `sub=np.minimum(sub,slack)`; `x -= sub`.
This converges because the exact target is between the post-clip minimum and maximum feasible sums. If no iteration converges, immediately invoke the exact integer-grid projection for that vector instead.

The proportional repair does not preserve feasibility if the resulting x is then clipped again without another pass; hence the capped waterfill above.

2.4 Exact binary-grid output and guarantee of sum feasibility
Use a power-of-two grid `S`, default `1<<18=262144`. For each candidate, construct integer unit array `u_i` approximating `x_i*S` and force integer sum
```
U = int(N*S/2)
```
which is an integer because `S` is even. Procedure:
1. Clamp raw `x` to `[0,1]` and replace non-finite values with 0.5.
2. `t = x*S`.
3. `u = np.floor(t + 1e-12).astype(np.int64)` clipped to `0..S`.
4. `defit = U - u.sum()`. If positive:
   - `rem = t-u`.
   - among all indices with `u<S`, choose the `defit` highest-rem slots; default allocation adds one unit each. If `defit` exceeds count available (should not occur usually), greedily add one unit to the currently highest fractional remainder repeatedly up to small number; also bounded by cap status.
5. If negative: remove `-defit` lowest fractional-rem擁有 units from indices with `u>0`, again `np.int64`.
6. `output = u.astype(float) / float(S)`.
Because `S` is a power of 2, each output entry is an exactly representable binary fraction, and `sum(output)` is exactly `U/S=N/2`, barring pathological integer overflow—not occurring for N under 2500 at this scale. Binary fractions remain in `[0,1]`. Exactness can be checked using integer sum rather than depending only on floating sum, but the final representation also satisfies exact ordinary sum.

When using multiple scales, try S in `[1<<18, 1<<16, 1<<20]` and choose output that has the lowest official `C5_true` among scale attempts and whose exact unit sum equals N/2. Store corresponding `c5_bound = C5_true(h_out)`.

2.5 Resolution transfer
Given a valid parent h0 length N0, a target N1 can be smaller/equal or larger. Sets:
- For `N1 == N0`: just return repair/raw candidate.
- For `N1 < N0`: decimate nearest/area-ish with `even_spread`. Define `idx = round(tabulation to 0..N0-1)` or `np.linspace(0,N0-1,N1).astype(int)`. Then integer-grid feasibility and convex repair. It is only a fallback, not primary, because lower resolution may worsen metric. Run local after transfer only if exact candidate is within reasonable tolerance.
- For `N1 > N0`: interpolate at new cell centers:
```
x0 = (np.arange(N0)+0.5)*2/N0
x1 = (np.arange(N1)+0.5)*2/N1
h1_raw = np.interp(x1, x0, h0, left=h0[0], right=h0[0])
```
After interpolation, clip and proportional-repair sum. A transfer with this linear interpolation preserves integral well and typically creates lower/rougher no-split peaks. Then always call exact-grid projection, official evaluate, and local refine.

2.6 Optimality honesty
Because the objective is max of bilinear terms, not convex; varying h changes both h and 1-h. The algorithm's subproblems average smooth terms, but accept only by `C5_true(h_out)`. No claim of global optimality; certified items are only true bounds based on returned feasible h.
