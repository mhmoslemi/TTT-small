1. Approach and rationale

Central idea. Use a deterministic, feasibility-preserving block-coordinate descent in which each proposed move is a one-dimensional mass-transfer direction and the move is chosen by an exact-or-near-exact minimization of the original discrete evaluator over that line. This is materially different from local linear-programming, SLSQP, proximal SMM, or generic active-set quadratic methods: it never builds a convex relaxation of the bilinear problem for the final decision. Every accepted candidate is scored by the exact finite-support linear correlation objective. The search space is not circular, not pixel-by-pixel convex, and not a generic smooth surrogate optimum. It consists of continuous coordinate paths

    h_i(α) = h_i + α d_i,   sum_i d_i = 0,

so that the integral constraint remains exact for every α. The box constraint is enforced by the α-interval itself. An univariate minimizer over that interval chooses the best feasible point on the current transfer direction.

Why this addresses the bottleneck. The objective is the maximum over many lag correlations. The hard part is the max, not only the bilinear correlations. As soon as one coordinate, or a few coordinates carrying mass, are changed, the lag correlations change as continuous piecewise-quadratic functions of the line parameter α. Therefore a line move can be optimized much more aggressively than a small fixed step. This line-minimization perspective turns the local min-max correction problem into many scalar searches on feasible interval endpoints α. It avoids the common problem in gradient methods where tiny subgradient steps only reduce a smoothed proxy and pay no immediate respect to the true max. Pair and small-block searches move mass from coordinates that worsen the largest lags to coordinates that reduce them, while retaining exact integral conservation.

Justified facts used below.

- The authoritative evaluator is `max(np.correlate(h, 1-h, mode="full")) * dx`, with `dx = 2.0/n_points`. This is finite-support linear correlation, not circular correlation.
- For any direction with `sum(d)=0`, moving along `h + αd` preserves `sum(h)` exactly.
- Because `h_i(α) = h_i + αd_i`, each correlation value along the line is a polynomial in α of degree at most two:

      V_l(α) = dx * [a_l + b_l α + c_l α^2].

  The polynomial coefficients are obtained by bilinearity of `np.correlate`.
- For a binary, 0/1, or continuous step, the box constraint can be enforced before optimizing α by computing the exact feasible interval of α for the direction.

Heuristic hypotheses, not guarantees.

- The true optimum has most, but not all, mass moved between coordinates connected by large-lag gradients.
- Pair and small-block line searches will find improvements near current near-optimal step functions, especially after transferring the supplied parent to slightly finer grids.
- Multiple restarts with different grid resolutions and transfer variants improve chances of crossing persistent local plateaus.
- There is no global-guarantee from scalar coordinate descent; every proposal must be challenged by exact evaluation.

Limitations.

- Scalar max of quadratics along a line is not guaranteed unimodal. It is therefore handled by dense scanning, local bracketing/refinement, root candidates from the most active polynomials, and exact rejection of any candidate that does not actually reduce the original evaluator.
- Very large grid dimensions increase cost. The plan keeps n almost always below roughly 250 and uses adaptive scanning intervals.

2. Mathematical specification

Discrete representation.

Let n = n_points, dx = 2.0/n. The candidate is a vector h ∈ R^n.

Constraints:

    0 ≤ h_i ≤ 1
    sum_i h_i = n/2

These are both feasible after algorithmic repair. No clip-then-rescale sequence is used for final feasibility.

Exact objective.

For a vector h, define:

    raw_l = sum over valid pairs (i,j=j+i-lag?) of h_i * (1 - h_j)
    V_l = raw_l * dx
    score(h) = max_l V_l

The implementation uses the supplied `evaluate_erdos_solution` when present and valid; otherwise it recomputes:

    score(h) = max(np.correlate(h, 1.0 - h, mode="full")) * dx

An exact implementation that must match `np.correlate` uses lag index lag = -(n-1), ..., n-1 and position p = lag + (n-1), with

    start = max(0, -lag)
    stop = min(n, n-lag)
    i = arange(start, stop)
    j = i + lag
    raw[p] = dot(h[i], 1 - h[j])

This orientation has been checked against `np.correlate` for random vectors. If this auxiliary match is requested programmatically, do it with a small random vector and compare numeric order; if it fails, disable only auxiliary custom-value reuse and continue using NumPy's authoritative `np.correlate` to produce all exact scores.

Line direction.

A valid step direction d must satisfy:

    sum(d_i) = 0
    there exists α such that 0 ≤ h_i + αd_i ≤ 1

For pair moves:

    choose p and q and transfer amount from p to q
    d_p = -1, d_q = +1, all others 0

Then h_new(α) = h + αd is:

    h_p - α, h_q + α, other h unchanged

and sum remains exactly the same.

Feasible α interval.

For general d, define for each i:

    if d_i > 0:
        lower_i = (0 - h_i)/d_i
        upper_i = (1 - h_i)/d_i
    if d_i < 0:
        lower_i = (1 - h_i)/d_i
        upper_i = (0 - h_i)/d_i
    if d_i == 0:
        lower_i = -infinity, upper_i = +infinity

Then:

    α_lo = max_i lower_i
    α_hi = min_i upper_i

If α_lo ≤ α_hi, interval is feasible. For the usual pair direction d_p=-1, d_q=+1 with α≥0 move:

    α ∈ [0, min(h_p, 1-h_q)]

and 0 is always in the feasible interval.

Exact polynomial line values.

Let:

    b = 1 - h
    A = h, B = 1-h

For h(α) = h + αd:

    1 - h(α) = b - αd

By bilinearity of `np.correlate`:

    raw(α) = corr(h, b)
             + α * corr(d, b)
             - α * corr(h, d)
             - α^2 * corr(d, d)

Therefore the scaled correlation values are:

    V(α) = dx * max(raw(α))

where `raw(α)` is the full-length vector length M=2n-1. Define:

    a_l = corr(h, b)[l]
    bcoef_l = corr(d, b)[l] - corr(h, d)[l]
    c_l = -corr(d, d)[l]

Then:

    V_l(α) = dx * (a_l + bcoef_l α + c_l α^2)

This is constructed directly with NumPy `np.correlate(..., mode="full")` so the ordering is exactly the evaluator's.

Scalar minimization over α.

The ideal scalar problem is:

    minimize max_l (a_l + b_l α + c_l α^2)

over [α_lo, α_hi]. This may be non-unimodal but is one-dimensional and continuous. The coder should use a deterministic multi-candidate search:

1. Include endpoints α_lo, α_hi, and α=0.
2. Scan a uniform grid over feasible interval (adaptive count: 33, 49, 65, 97 depending on remaining time and n).
3. For all quadratic functions with nonzero c, include drift algebraic vertices α_v = -b/(2c), keeping only those inside feasible interval and finite.
4. Include deterministic pair/intersection candidates for a controlled set of most active constraints, to avoid expensive all-pairs enumeration for large n.
5. Run only bounded one-dimensional minimization, e.g. `scipy.optimize.minimize_scalar` / `scipy.optimize.fminbound`, in several bracketed intervals that contain or are adjacent to low grid values, candidate vertices, or best intersections. Limit to a small number of brackets per line move.
6. Evaluate all final candidate α values in exact or polynomial-vector mode. Due to polynomial representation, this polynomial evaluation must be accurate enough to match the evaluator; nevertheless acceptance tests candidate vector by exact evaluator.

Active intersection set.

For n up to about 84, include all constraints or K=M. For larger n, use K = min(M, max(50, min(120, 1.5*n))). The active constraints for intersection include:

    - constraints with raw values at α=0 closest to max;
    - constraints whose line slope |bcoef_l| is large;
    - constraints with quadratic c_l close to boundaries of feasible interval predicted by a_l + bcoef_lα_l + c_lα_l^2.

For K selected functions, solve roots of equality of pairs k and ℓ:

    (a_k-a_l) + (b_k-b_l)α + (c_k-c_l)α² = 0

Use a stable quadratic root formula. Add real roots in [α_lo,α_hi]. Pair enumeration is the atomic candidate generation for observed top-lag crossings. If K=120, at most about 7140 pairs; acceptable for occasional refined moves, not for every simple scan. When implementing, be adaptive:

    - if n>128, reduce K to 80 and limit intersections to top 40 for most moves, after improving sections allowing top 70.
