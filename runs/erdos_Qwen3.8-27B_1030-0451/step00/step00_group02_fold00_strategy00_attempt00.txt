1. Approach and rationale

The problem is to minimize an exact discrete overlap score over step-function samples h satisfying
- 0 <= h[i] <= 1,
- sum(h) = n/2 exactly for the chosen n,
and to report a vector whose score according to the evaluator is as low as possible, preferably below 0.3808.

The important mathematical facts are:

- The true score is a maximum over all 2n-1 finite-support correlations and is nonconvex because it contains bilinear terms h[i] * h[j]. A direct convex CVX/QCLP formulation is not meaningful; any surrogate must be judged only by the original exact score.
- The supplied exact evaluator is authoritative. Candidate vectors must be analyzed with exactly the same metric, including the factor dx = 2.0/n and all lags.
- The parent construction of n=81 samples is a very good local starting point, but large resolution-only replication may not exploit boundary effects. A search over a small family of powers-of-parent resolutions, say n = n0, 2*n0, 3*n0, 4*n0, 6*n0, 8*n0, with n0 = len(initial_h_values if present), gives a cheap way to keep a strong parent while allowing finer pixel-level adjustments that can shave about 5e-5 in the objective.
- To search nonconvex space safely, use a hierarchy:
  1. Preserve and validate the parent exactly as a fallback. Parent values are never embedded as literals; parent data are used only through runtime interpolation/replication from the supplied array.
  2. Resolve parent to several nearby resolutions, resampling/projection then evaluating exact scores.
  3. Lease smoothed log-sum-exp surrogate objectives to propose feasible local directions. The surrogate is deliberately optimized, but every global acceptance is exact.
  4. Use tightly constrained local moves (pairwise/tleiplet projections) that preserve sum and bounds exactly, and accept only when the exact score improves.
  5. Add randomized parent-parent mixes, Euclidean projections, random feasible designs, and low/moderate noise restarts. The parent remains retained if none beat it.
- Numerical feasibility is crucial: repeatedly project vectors to the feasible set: box constraints plus the exact sum target n/2. This way, random candidate generation and line search do not gradually break the constraint. This is the core feasibility mechanism; one does not rely on a solver’s equality constraint alone.
- The method remains local: it gives no global optimality proof. It is designed as a robust computational construction method, because the task is to return a feasible sample that lowers the exact score, not certify optimality.
- If the target is reached early, the search may return it; if not, the best feasible fallback is returned before the deadline.
