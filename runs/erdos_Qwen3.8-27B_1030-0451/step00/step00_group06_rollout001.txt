```python
    weights = np.exp(beta * c5_shifted)
    weights /= weights.sum()
    
    grad = np.zeros(n)
    dx = 2.0 / n
    
    for k in range(len(c5_arr)):
        if weights[k] < 1e-12:
            continue
        d = k - (n - 1)
        w = weights[k] * dx
        
        if d >= 0:
            # First term: (1-h[i+d]) for i in [0, n-1-d]
            i_range = np.arange(0, n - d)
            grad[i_range] += w * (1.0 - h[i_range + d])
            # Second term: -h[i-d] for i in [d, n-1]
            i_range2 = np.arange(d, n)
            grad[i_range2] -= w * h[i_range2 - d]
        else:
            ad = -d
            # First term: (1-h[i-ad]) for i in [ad, n-1]  → h[i] * (1-h[i-ad])
            # Wait, let me redo this.
            # d = -ad, so result = sum_{j=0}^{n-1-ad} h[j]*(1-h[j+ad])
            # ∂/∂h[i] = (1-h[i+ad])*I(0≤i≤n-1-ad) - h[i-ad]*I(ad≤i≤n-1)
            i_range = np.arange(0, n - ad)
            grad[i_range] += w * (1.0 - h[i_range + ad])
            i_range2 = np.arange(ad, n)
            grad[i_range2] -= w * h[i_range2 - ad]
    
    return grad
```

This is O(n * n) = O(n²) per evaluation of the gradient, which for n=512 is about 262k operations. In Python with numpy vectorization inside the loop, each iteration of the k-loop does O(n) work, and we have n iterations, so total is O(n²) ≈ 262k numpy operations. Each numpy operation on an array of size ~512 takes maybe 1-5 microseconds, so total per gradient evaluation is maybe 1-5 ms. Over 5000 iterations, that's 5-25 seconds. That's fine!

But wait, we only need to process the non-zero weights. With beta=50, the softmax will be very peaked, so only a few k values will have significant weight. This makes it much faster in practice.

Actually, let me reconsider the whole approach. Maybe I should focus more on the binary optimization and less on the continuous one, since:
1. The continuous problem has a complicated feasible set projection
2. The binary solutions are already quite good
3. The initial_h_values (which is likely fractional) might not be much better than a good binary solution

Let me focus on making the binary SA really good.

Key improvements for the SA:
1. Use a "multi-start" approach: try several different initial configurations
2. Use "pairwise swap" moves (swap a 1 and a 0)
3. Use "2-swap" moves (swap two 1s, or swap two 0s) - these don't change the sum but can improve structure
4. Use targeted moves that focus on critical shifts
5. Use "restart" strategy: if stuck for too long, restart with a perturbed version of the best found

Actually, "2-swap" moves (swap two 1s) don't change the set of 1 positions in a way that affects the sum, but they do change which positions are 1. Wait, no - if I swap h[a]=1 with h[b]=1, nothing changes. I need to swap a 1 with a 0.

What about "2-1 swap": move two 1s simultaneously? This could escape local optima better.

Let me also think about a "construction" approach:
- Build the sequence one position at a time
- At each step, place a 1 or 0 to minimize the maximum overlap so far
- This is a greedy algorithm

Actually, for this type of problem, a better approach might be:
1. Start with a random configuration
2. Use a "hill climbing" approach: try all possible single swaps, pick the best one, repeat until no improvement
3. Then use SA to escape local optima
4. Alternate between hill climbing and SA

The "try all swaps" step is O(n²) per iteration (n/2 ones × n/2 zeros possible swaps), each requiring an O(n) or O(n log n) evaluation. For n=512, that's 65k swaps × 512 ops = 33M ops per full pass. In numpy, this might take ~0.1 seconds per pass. So we can do about 10-20 passes per second. Over 1000 seconds, that's 10000-20000 full passes. That should be more than enough to converge.

But actually, evaluating each swap requires the full correlation, which is O(n log n) with FFT or O(n²) with direct computation. For n=512, np.correlate is probably O(n²) ≈ 262k ops, taking maybe 100 microseconds. So 65k swaps × 100μs = 6.5 seconds per full pass. That's too slow for many passes.

Instead, I can use incremental updates. When I swap h[a] (1→0) and h[b] (0→1):
- The change in correlation at shift d is:
  - For the term involving h[a]: at shift d, if a is in range, the contribution changes
  - For the term involving h[b]: similar

Specifically, for shift d (where d = k - (n-1)):
Before: h[a]=1, h[b]=0
After: h[a]=0, h[b]=1

The correlation at shift d changes by:
Δ_c(d) = [new contribution from a] - [old contribution from a] + [new from b] - [old from b]
