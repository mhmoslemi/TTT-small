1.1 Central idea

The primary approach is an exact, constraint-preserving coordinate method based on pairwise transfer lines. A move is specified by choosing two grid indices `i != j` and a scalar transfer amount `s`, replacing the pair by

```
h_i <- h_i + s
h_j <- h_j - s
```

This automatically preserves the linear constraint

```
sum(h) = n
```

if `sum(h) == n/2` holds before the move and if all assigned values remain in `[0, 1]`. The feasible interval for `s` is computed exactly from the two endpoint constraints.

The critical observation is that for such a pairwise transfer, the entire raw full-correlation risk vector is known along the line as a simple quadratic expression, without recomputing `np.correlate` repeatedly. For every lag index `r`,

```
R_r(s) = R_r(0) + A_r(i,j) s + G_r(i,j) s^2
```

where:

- `R_r(0)` is the raw correlation array at the current feasible point.
- `A_r(i,j)` is the directional derivative of raw risk `R_r` with respect to increasing coordinate `i` and decreasing coordinate `j`.
- `G_r(i,j)` is zero except at the two lags corresponding to `d = +|i-j|` and `d = -|i-j|`, where it equals `+1`.

Because each `R_r(s)` is either affine or convex quadratic, and because the maximum of convex functions is convex, the restricted line subproblem

```
minimize Π(s) = max_r R_r(s)
subject to s in [s_lo, s_hi]
```

is exactly convex in one dimension, even though the original problem is nonconvex. Therefore every accepted move is a globally optimal move along its selected pair-transfer line, evaluated with the exact discrete objective.

This is materially different from smoothing the maximum and running general gradient methods, and also different from solving a relaxed LP or trusting surrogate objectives. Here the internal candidate search is exact on one-dimensional affine/quadratic restrictions of the true objective, and every candidate is accepted only after exact reevaluation using the evaluator-compatible formula.

1.2 Why this may improve the supplied parent

The supplied parent is already a high-quality optimization, not a random construction. Therefore the main bottleneck is not gross shape search; it is extremely fine boundary/tie movement in cases where the maximum correlation is repeated across many adjacent lags. Pairwise transfers are ideal for final polishing because:

- They preserve the sum constraint by construction.
- They keep `[0,1]` bounds by restricting to exact intervals.
- They exploit the fact that bilinear correlation terms change linearly or quadratically along a two-coordinate direction.
- They can identify exact subgradient-minimizing steps and escape small plateau regions when a selected pair can lower the maximum raw risk.
- They require relatively small helper arrays and run efficiently for resolution `n around 338`.

1.3 Scope and claims

This method is a nonconvex local and basin-hopping heuristic. It is not a global optimality proof. It should be presented as a tested construction method. No line-search guarantee extends beyond the chosen pair-transfer line. The algorithm will retain the best exact feasible construction discovered and will return a valid fallback if no improvement is found.

1.4 Overall architecture

Maintain a set of candidate constructions, each represented by a flat one-dimensional array `h`. Score every initial and every improved construction using the authoritative exact metric:

```
dx = 2.0 / n
score(h) = dx * max(np.correlate(h, 1.0 - h, mode="full"))
```

Run multiple exact pair-polishing passes with different pair-generation biases and, optionally, lower/optimal resolution transfers. If any construction reaches or improves below the target bound, keep it. Otherwise return the smallest tied resolution or the best score found after final revalidation.

2. Mathematical specification

2.1 Evaluation, raw risk, and lag indexing

Let `n = len(h)` and

```
dx = 2.0 / n
```

The authoritative bound is

```
C(h) = dx * max_r Q_r(h)
```

where

```
Q_r(h) = np.correlate(h, 1.0 - h, mode="full")[r]
```

for `r = 0, ..., 2n-2`.

Define lag

```
d = r - (n - 1)
```

so that `d = -(n-1), ..., n-1`. The evaluation-compatible raw term is

```
Q_r(h) = sum over p  h[p + d] * (1 - h[p])
```

where the sum is over all integer `p` for which both `p` and `p+d` lie in `[0, n-1]`. This indexing must exactly match the output of `np.correlate(h, 1.0 - h, mode="full")`.

The feasible constraints are

```
0 <= h[i] <= 1 for all i
sum(h) = n / 2
```

For even `n`, exact feasibility can be constructed by pair-symmetric assignments. For odd `n`, exact feasibility can be constructed by symmetric pairs and fixed middle value `0.5`.

2.2 Pair transfer line

Select two indices `u` and `v`, `u != v`, and increase `u` by `s` while decreasing `v` by `s`:

```
h_u(s) = h_u + s
h_v(s) = h_v - s
```

All other coordinates are fixed. The feasible interval for `s` follows from `[0,1]` bounds:

```
-s_lower_u = -h_u    from h_u + s >= 0
upper_u    =  1 - h_u from h_u + s <= 1
-s_lower_v =  h_v - 1 from h_v - s <= 1
upper_v    =  h_v     from h_v - s >= 0

s_lo = max(-h_u, h_v - 1)
s_hi = min(1 - h_u, h_v)
```

If `s_hi - s_lo` is below a tiny tolerance, no move is attempted. The interval contains both positive and negative transfer directions, so one line search covers both directions.

2.3 Directional derivative terms

For a current `h`, define for a valid coordinate `t` and raw index `r`, with lag `d = r-(n-1)`:

```
shifted_term: participation where t = p+d
original_term participation where t = p contribution derivative = -h[t+d]
```

The exact raw partial derivative is

```
p_t(r; h) = I(0 <= t-d < n) * (1 - h[t-d])
            - I(0 <= t+d < n) * h[t+d]
```

For the pair transfer `(u,v)` the directional derivative is

```
A_r(u,v) = p_u(r; h) - p_v(r; h)
```

No numerical differentiation is required or permitted except as a sanity test.

2.4 Quadratic correction

The raw risk vector is quadratic along a pair-transfer line due to product terms where the two changed coordinates directly multiply. For a pair with index distance

```
m = abs(u - v)
```

the quadratic correction is

```
G_r(u,v) = 1 if r = (n - 1) + m or r = (n - 1) - m
G_r(u,v) = 0 otherwise
```

If `m == 0`, the pair is invalid.

The exact raw array along the line is therefore

```
Q(s) = Q + A s + G s^2
```

The scalar line objective is

```
F(s) = max(Q(s))
```

Each component `Q_r(s)` is either affine or `s^2 + affine(s)`, hence convex. `F(s)` is the maximum of convex functions, hence convex on the bounded interval `[s_lo, s_hi]`.

2.5 Feasible move acceptance

Given the best point `s*` from the convex line subproblem:

1. Verify `s_lo <= s* <= s_hi` up to floating-point tolerance.
2. Verify that both new coordinate values lie in `[0,1]` up to a tolerance; if not, clamp to the exact BP interval endpoint and range back to a neighboring point by floating-checking again.
3. Update `h` by applying the transfer.
4. Compute the exact new raw risk vector:

```
Q_new = np.correlate(h, 1.0 - h, mode="full")
```

5. Compute the exact scalar score using `dx * np.max(Q_new)`.
6. Accept if the exact new score is better than the current state score by at least `accept_raw_tol * dx`.
7. Retain the exact new state; do not rely on `Q + A s + G s^2` for the final score.

The exact array can be used internally during a pass for speed, but every output or important accepted state should be checked with `np.correlate`.

2.6 Resolution transfer

Because `n` can be changed, every returned vector must remain feasible at its own `n`. The final dimension is determined from the input parent length, not hardcoded.

For transfer interpolation:

1. Treat the parent array as approximate samples of the same step-function shape over `[0,2]`.
2. If the parent is approximately pair-antisymmetric, define interpolation only on the half-profile.
3. For odd target `n`, pair `floor(n/2)` values and make the middle sample `0.5`.
4. For even target `n`, pair `n/2` values. For pair parameter `p_k` from linear interpolation, define:

```
h[k] = p_k
h[n-1-k] = 1 - p_k
```

This construction gives exact sum `n/2`, since every pair sums to one and, if odd `n`, the middle value contributes `0.5`.

If the parent is not approximately pair-antisymmetric, one can transfer to the result after linear resampling and then apply anti regularization to the interpolated samples. However priority is placed on the exact-qp simultaneous direct-parent optimization, so the transfer path is optional and never treated as essential.

3. Implementation procedure

3.1 Top-level helper responsibilities

All helpers are top-level and stateless except through explicit passed arrays. No closures, lambdas, or dynamically captured state.

3.1.1 `score_exact(h)`

Input: `h` one-dimensional float array.

Procedure:

1. `n = len(h)`.
2. If `n < 8` or `n == 0`, return `+inf` and mark invalid or use a fallback generation function.
3. Compute:

```
Q = np.correlate(h, 1.0 - h, mode="full")
scale = 2.0 / n
c = float(np.max(Q) * scale)
```

4. Return both the C value and raw vector `Q` if needed.

3.1.2 `feasibility_ok(h)`

Input: `h`.

Procedure:

1. Require one-dimensional, finite values.
2. Require `min >= -tol_bounds` and `max <= 1 + tol_bounds`.
3. Compute `target = 0.5 * len(h)`.
4. Require `abs(sum(h) - target) <= tol_sum`.
5. Return boolean.

Best ranges `tol_bounds = tol_sum = 1e-7` for validation; constructed expressions should be nearer machine precision.

3.1.3 `repair_bounded_sum(h)`

Input: a generally invalid finite array or one with minor sum drift.

Procedure:

1. Clip entries into `[0,1]` using clipping only to remove gross violations.
2. Compute `target = n/2` and `diff = target - sum(h)`.
3. For `diff > 0` repeatedly increase coordinates with slack to `1`.

```
available = 1 - h
while diff > tol and any(available > tol):
   choose a coordinate set, e.g. largest values first
   move up to min(diff, sum(available))
   distribute amount proportional to available on selected coordinates
   diff -= amount
   h += increments
```

4. For `diff < 0`, repeat symmetrically decreasing coordinates with slack `h`.
5. After convergence, if residual is within a numerical tolerance, stop.
6. If still slightly invalid, stop.

This repair is for fallback and interpolated transfers, not the main solver. A constructed antisymmetric doubling yields exact sums algebraically and should remain best.
