1. Approach and rationale

1.1 Central idea

The supplied construction is already near the known numerical optimum, so a generic global search is less valuable than a method that can make extremely small, feasible simultaneous adjustments while exactly preserving the prescribed mass. The proposed method uses the exact evaluator as the only final arbiter but moves the function by solving a sequence of active-constraint linear programs (LPs) on the full finite-support objective.

At a feasible point `h`, the exact objective is

`C(h) = (2 / n) * max_r Q_r(h)`,

where

`Q_r(h) = np.correlate(h, 1 - h, mode="full")[r]`.

Write `F(h) = max_r Q_r(h)` and let the raw maximum be `K = F(h)`. The algorithm forms an active set of correlation lags `r` whose `Q_r(h)` values are equal to or very close to `K`. For those lags, it linearizes the true quadratic correlation terms using exact one-coordinate derivatives. Then it asks a small LP for a nearby feasible vector `h'` that makes all active linearized correlations no larger than `K - δ`, while minimizing the amount moved inside a trust region. The proposed `h'` is immediately re-evaluated using the original evaluator. It is accepted only if the exact score improves (or maybe if it is equal but has better tie properties). This sequence constitutes an active-plane descent method for the original nonsmooth objective.

The method is materially different from smoothing the maximum, pairwise coordinate line search as the principal engine, antisymmetric half-reparameterization as the sole feasible model, or relying on a convex relaxation without an exact recovery mechanism. Here:

- the full vector `h` is the decision variable,
- exact first-order derivatives of every active correlation term guide the motion,
- the LP solves a convex linearized min-over-active-descent feasibility problem with trust-region and mass constraints,
- all candidate decisions are accepted only by exact maximum-correlation evaluation,
- the finite-support evaluator definition is never replaced by autocorrelation identities, circular correlation, or min-over-lag reparameterizations.

1.2 Why this may improve the supplied parent

Near the record bound, a single directional move may improve one correlation lag only to create a tie or slight increase at another lag. The important computation is simultaneous: all active lags should be reduced together, and nearby lags should be controlled as secondary active constraints. The LP does exactly this: it rotates visible mass in the direction given by active gradients without violating bounds or the exact sum constraint, while using a trust region near the current reconstruction.

This is helpful because the parent construction is probably already a basin of the nonconvex global problem; the central bottleneck is the extremely flat plateau structure at high correlation. Parenthetically, including a small number of exact restricted pair-transfer line checks at the end gives a local fallback using the original evaluator without making those transfers the main algorithm.

1.3 Facts, heuristics, and limitations

Justified discrete facts:

1. For any vector `h` with `len(h)=n`, the evaluator is exactly `dx * max(np.correlate(h, 1-h, full))` with `dx = 2/n`.
2. Each term `Q_r(h)` is a finite polynomial of degree two in the coordinates of `h`.
3. Exact one-coordinate derivatives of `Q_r` can be written algebraically.
4. In Euclidean projection onto the constraints, the objective, trust-region, and local mask are projectionby exact projection.

Heuristic hypotheses:

1. Linearizing top risks yields a useful interference direction for the true bilinear objective.
2. A trust-region LP reduction avoids large artificial moves caused by extrapolating linear approximations.
3. Multiple starts and resolution transfers increase escape from suboptimal basins.
4. A short exact line search can improve an activated LP plateau by resolving one-dimensional tie cases out of step.

Limitations:

1. The LP is only a local planning model. It is not a global certificate.
2. Linearized risk can be feasible while the exact bilinear vector worsens; hence exact acceptance is mandatory.
3. The algorithm does not prove a global optimum, only returns a found better construction if improved feasibility is found.
4. Small discrete errors and adjacent local basins are intrinsic to the evaluator's nonconvexity.

2. Mathematical specification

2.1 Exact objective, indexing, and finite support

Let `h` be a real array length `n`, `dx = 2.0 / n`, `b = 1 - h`, and `y = np.correlate(h, b, mode="full")`. The output length is `L = 2n - 1`. Use lag index offset `c = n - 1`,

`d(r) = r - c`, for `r = 0, ..., L - 1`.

The value output by `np.correlate(h, b, mode='full')` at index `r` is

`Q_r(h) = sum_p h[p + d(r)] * (1 - h[p])`,

where the sum consists of integer `p` such that both indices are within `{0,...,n-1}`:

`0 <= p < n` and `0 <= p + d < n`.

For `n = 4`, large linear indices `r=0..6` correspond to `d=-15,-8,-2,-1,0,1,2`.

Constraint denominator in scale metric:

`C(h) = dx * max_r Q_r(h)`.

A vector is exactly feasible if:

- every coordinate is within tolerance of `[0, 1]`,
- `sum_i h_i = n / 2` within tolerance,
- `h` has length `n` and is one-dimensional.

Final candidates should be repaired with exact perbound and mass correction, not approximate by only clipping some objective portion of the final.

`g_{r,t} = sum` over all p in P(r) such that `p+d = t` of `(1 - h[p])`
