1. Approach and rationale

Central idea. Treat the supplied `initial_h_values` as a feasible parent only if it validates. Optimize the exact evaluator objective directly, using an ensemble of local nonconvex improvement methods: (a) a trust-region sequential linear model for the active correlation constraints, (b) smooth log-sum-exp approximate minimax with `scipy.optimize.minimize` using SLSQP and analytic gradients, (c) projected steepest descent / active-weight polishing, and (d) resolution-transfer restarts to try larger grids. The returned candidate is always the feasible vector with the smallest exact evaluator score found so far; failed or worse local steps are discarded.

Why this addresses the bottleneck. The original objective is intrinsically bilinear because each term contains products `h_i * (1-h_j)`. The feasible set is convex but the objective is not convex. Convex solvers such as CVXPY cannot directly solve the global problem. The method therefore does not claim global optimality. It improves via local descent and restarts, while every candidate is accepted only after exact evaluator recomputation. The parent can have a score near the desired threshold; tiny improvements are feasible if the local search reduces the currently active maximum overlaps and/or transfers the solution to a fine grid where boundary effects and fractional values can be exploited.

Primary approach. The primary workhorse is sequential active linearization: at a prospective point, compute all correlation values, select the largest constraints, build a linearized minimax LP with the original feasibility constraints, solve the LP trust-region subproblem, project the solution exactly onto the feasible box/simplex, and accept only if the exact original score improves. The sequence is paired with smooth log-sum-exp SLSQP for smoother cooperative convergence and random perturbations to escape stagnation.

Justified facts versus heuristic hypotheses.
- Exact evaluator objective and feasibility constraints are exactly implemented.
- Projection onto `0 <= h <= 1`, `sum(h)=n/2` is mathematically valid and does not rely on clip-then-rescale.
- Gradient formulas for correlation terms and log-sum-exp smoothing are derived below and should match finite differences.
- Linearized subproblems are not equivalent to the original objective because the original bilinear terms are nonconvex. Candidate acceptance is therefore exact and conservative.
- Larger grids can represent smoother or more finely structured step functions that the coarse grid cannot; the transfer heuristic is a hypothesis and is accepted only by exact score.

Limitations.
- No global guarantee. The current parent may already be a local optimum under some basins; target 0.3808 may require very tight performance.
- Results may degrade for very large `n` due slower optimization; the implementation caps dimensions and uses deadline-safe logic.
- If all improvement methods fail, the valid parent is returned as fallback.
- Finite precision can make values very close to the target ambiguous. Use explicit feasibility tolerance and final exact validation.

Exact evaluator objective.

  `C = np.correlate(h, 1.0 - h, mode="full") * dx`.
- `np.correlate` uses full lag support, not circular autocorrelation, and naturally includes only boundary-overlap terms at each lag. Don’t reformulate it as `1 - minimum autocorrelation` unless proving equivalence; the integration domain overlaps shift exactly on truncated supports.

Floating order and internal custom correlation.

1. Approach and rationale

Central idea. Use the supplied parent construction as the safe initial point when it validates. Optimize the exact discrete evaluator by combining several local nonconvex improvement methods, while always returning the feasible vector with the smallest exact evaluator score found so far. The main local engines are: (a) an active-constraint trust-region sequential linear model solved as a linear program, (b) smooth log-sum-exp approximate minimax refinement using `scipy.optimize.minimize(method="SLSQP")` with analytic gradients, (c) projected steepest-descent polishing on weighted active constraints, and (d) resolution-transfer restarts to a finer grid that can express features the parent grid may not represent. Whenever one variant improves the exact score, candidate acceptance rules keep that result. Otherwise the parent or constant fallback is retained.

Why this addresses the bottleneck. The search objective is
`max_lag v_lag(h)`, where each `v_lag(h)` contains products `h_i * (1 - h_j)`. The feasible set
`{h in [0,1]^n : sum(h)=n/2}` is convex, but the objective is bilinear and nonconvex. Thus a standard convex program is not an exact solution. The strategy avoids claiming a convex-quadrature global optimum. It uses exact evaluation to reject any model candidate that fails in the real objective. The active linear model aggressively reduces currently large overlap terms while keeping boundary constraints feasible. The smooth SLSQP phase helps through regions where top-layer models are too coarse. Projected gradients deliberately stay inside the feasible box/simplex. Resolution transfer gives the optimizer more degrees of freedom, which can improve boundary-overlap accuracy merely by representing the function on a finer grid.

Justified facts. Exact evaluator mode is linear correlation over full lags, not circular autocorrelation. Sum and box constraints are jointly enforced by exact projection. Gradient formulas for lagged bilinear correlation and log-sum-exp smoothing are derived below. Candidate acceptance is exact.

Heuristic hypotheses. Larger grids often represent similar step functions with smaller local overshoots. Random perturbations and smooth optimizers may find improvements near a near-local optimum. No method guarantees global optimality. If no stage improves, returning the valid parent remains feasible. If the parent already meets a target simply as valid fallback, it is still returned only if its exact score does so; additional local stages may still try to improve it.

Main limitations. The method is local/globalized-random, radical nonconvex, and it may return parent if the tiny target is not achieved. Very small budgets force far fewer loops and restarts. Exact score differences may be near double precision. Checks make numerical invalidity conservative.
