1. Approach and rationale

1.1 Central idea.

The task is to produce a feasible vector `h` whose exact evaluator score  
`dx * max(np.correlate(h, 1 - h, "full"))` is strictly better than the supplied parent bound. This is a constrained finite-dimensional bilinear nonconvex minimax problem, so a direct global convex solver is mathematically inappropriate. The proposed construction is a **certified local-global hybrid**, but one that is materially different from broad random/convex heuristics:

1. All accepted updates are tested by the exact evaluator. Smooth objectives, log-sum-exp surrogates, and low-rank parameterizations are only proposal generators or local descent maps; they never determine acceptance by themselves.
2. The method retains a **low-dimensional DCT-informed perturbation space** on top of the parent vector. This is better suited to step functions than unconstrained high-dimensional random perturbations, because the important improvements are usually smooth low-frequency changes of an already feasible balanced profile.
3. The primary local polish is **exact active-coordinate mass-transfer descent**: exact feasible transfers of mass from one index to another along the Euclidean sum hyperplane, chosen using activated correlation gradients. Since many lags are near-active, this is more robust than optimizing only a single correlation.
4. A smooth constrained minimax solver is used only as a local proposal generator from promising parent-family candidates; exact acceptance and feasibility repair decide inclusion.
5. The parent is always kept as a safe fallback. The algorithm returns the best feasible exact-score vector found; if nothing improves the parent, it returns the validated parent.

1.2 What bottleneck this addresses.

The evaluator objective is a maximum over all `2n - 1` finite-support linear-correlation lags. Improving a tight parent by about `1e-4` or less requires controlling many partially active lags simultaneously. Gradient descent on one lag can raise another. The important bottlenecks are therefore:

- Acceptance must be based on the actual max over all lags, not a smoothed or scalarized individual correlation.
- Feasibility requires simultaneously enforcing `0 <= h_i <= 1` and `sum(h) = n/2`; clip-and-rescale can destroy the mass constraint or the bounds.
- Local optima often have many equal active correlation maxima; simple steepest descent may make no exact progress, so the method needs exact low-rank direction exploration and exact mass-transfer moves.

1.3 Justified facts and heuristics.

Justified facts:

- The discrete objective is a finite max over bilinear functions. It is nonconvex in general. The parent fallback is always a valid upper bound if it is feasible.
- The sum-hyperplane plus box constraints are convex and easy to maintain by exact water-filling feasibility repair.
- The evaluator is finite linear correlation. There is no exact reduction to only autocorrelation without preserving boundary terms; the implementation must use `np.correlate(...)` directly for scoring.
- For small `n` such as 81, evaluating the full objective is cheap, so exact acceptance at many trial moves is feasible.

Heuristic hypotheses:

- DCT low-modes are good directions for smoothing an already optimized step profile.
- Activated-lag gradients identify likely beneficial mass transfers.
- Exploring dimensions near the parent dimension can reveal discrete artifacts and may find better scores at small cases near 81.
- A deterministic low-rank global search can occasionally move out of the parent's narrow local basin without taking the infeasible large jumps that ruin a very tight bound.

No global optimality or target attainment is claimed; the algorithm returns the best exact feasible bound found.

2. Mathematical specification

2.1 Discrete representation.

For a dimension `n`, `dx = 2.0 / n`. Samples `h = h[0], ..., h[n-1]` approximate a step function over `[0,2]` by equal cells `h_i`. Feasibility is:

- `0 <= h[i] <= 1` for all `i`
- `sum_i h[i] = n / 2`

The targets `n` should preferably be small, below 250 samples. If a parent vector is supplied with length `n_p` and valid mean, use that dimension by default. Optional nearby dimensions may also be searched for performance reasons.

2.2 Exact objective with the evaluator convention.

Let `q = 1 - h`. Let

`R = np.correlate(h, q, mode="full")`

so `len(R) = 2*n - 1`. Evaluating the score is:

`C5(h) = max(R) * dx`

This exact formula is authoritative everywhere. No summation identity or autocorrelation substitute may replace it.

For correspondence and gradients only, map evaluator index `m in 0..2*n-2` to finite-support shift `s = m - (n - 1)`. The correlation term corresponding to that shift is:

`Phi_s(h) = dx * sum_{j: 0 <= j < n, 0 <= j+s < n} h[j+s] * (1 - h[j])`

For `s >= 0`, valid `j` are `0 .. n-1-s`. For `s < 0`, valid `j` are `-s .. n-1`.

The objective is:

`F_0(h) = max_s Phi_s(h)`

2.3 Smooth surrogate.

For a positive smoothing parameter `tau`, define

`F_tau(h) = tau * log(sum_{m=0}^{2*n-2} exp(Phi_m(h) / tau))`

This upper-bounds `F_0(h)` with accuracy no worse than `tau * log(2n - 1)`. A numerically stable computation subtracts `Phi_max / tau` before exponentials. If `tau` is too small, exponent weights concentrate on active maxima; if too large, too many irrelevant lags are averaged. Choose a small sequence from around `0.02` down to `1e-4`.

2.4 Log-sum-exp gradient.

The gradient of `F_tau` is a weighted sum of gradients of all `Phi_s`, with weights

`w_s = exp((Phi_s - Phi_max) / tau) / sum_k exp((Phi_k - Phi_max) / tau)`

For each shift `s`, loop over valid `j`, let `a = j + s`. Then:

- From the factor `(1 - h[j])`, derivative wrt `h[j]`:
  `grad[j] += dx * w_s * (-h[a])`
- From the factor `h[a]`, derivative wrt `h[a]`:
  `grad[a] += dx * w_s * (1 - h[j])`

If `s=0`, both derivative contributions refer to the same index and correctly combine to `dx * w_s * (1 - 2 h[j])`.

Note on orientation: if the implementation's gradient is accidentally sign/flipped, exact objective acceptance still protects validity. However, better direction investigation is obtained if the gradient orientation matches the finite-shift formula above and is checked against the evaluator on random feasible examples.

2.5 Feasible joint projection / exact repair.

Use a joint water-filling projection, not clip-then-rescale. Given arbitrary finite vector `z` and target mass `S = n/2`, find `mu` such that

`f(mu) = sum_i clip(z_i - mu, 0, 1) = S`.

`f(mu)` is nonincreasing and maps `[min(z) - 1.5, max(z) + 1.5]` to an interval around `S`; use bisection or a small number of Newton-style iterations. 40+ iterations attain high precision. After `mu`, set

`y_i = clip(z_i - mu, 0, 1)`.

Then perform a final exact `sum` repair:

- Compute `res = S - sum(y)`.
- If `abs(res) < 1e-12`, stop.
- If there are interior indices with `eps < y_i < 1 - eps`, add `res / count` to each interior index and clip to residual `0`.
- If none, iteratively adding to indices with `y_i < 1` until `res <= 0`, and subtracting from indices with `y_i > 0` if `res < 0`, choosing least-change indices.
- Finally `y = clip(y, 0, 1)`; if this moves the sum back slightly, carry out a tiny residual transfer between one index that can receive and one that can donate, preserving `0 <= y <= 1`.

The returned vector by this procedure has bounds satisfied by construction and exact `sum = n/2` up to floating point tolerance `<= 1e-10`. The final validator recomputes `max(np.correlate(...))` after this true repair. This is used for:

- parent validation;
- projecting any candidate from unconstrained low-rank maps;
- auditing project ends in partial solver steps;
- final return feasibility.

2.6 Dimension transfer.

If the global vector `h_parent` of dimension `p` is transferred to `n`:

Use piecewise-linear center interpolation:

`x_parent = (arange(p) + 0.5) / p`

`x_new = (arange(n) + 0.5) / n`

`z = np.interp(x_new, x_parent, h_parent, left=h_parent[0], right=h_parent[-1])`

Then `z = joint_project(z, n/2)`. Also perform the reverse projection if `n < p` using the same center-interpolation method. The exact objective is computed with the actual `dx = 2/n`. Compare dimensions only by exact `C5` values; keep smaller dimension only when it is no worse than another dimension by a tolerance of `1e-12`.

2.7 Low-rank map.

Given a feasible base vector `base` of dimension `n`, d DCT-style columns `B[:, k]`, and coefficient vector `beta`, define:

`z(beta) = base + scale_factor * (B @ beta)`

The projection map is

`h(beta) = joint_project(z(beta), n/2)`

The DCT basis can be generated by:

`B[:, k] = cos(pi * (2*i + 1) * freq_k / n)`

for `i=0..n-1`, normalized columnwise to maximum absolute value `1`. Use a small number of positive low-frequency DCT modes, e.g. frequencies `1, 2, 3, 4, 6, 8, 12, 16, 24, 32, 48, 64` filtered to values below `n-1`, with randomized seeded dither modes later, up to `d=16` or `20`. The base vector `beta=0` maps to `joint_project(base, n/2)`, which is identical to the parent if it is feasible before projection, preserving the parent.

The exact scalar objective for low-rank global/semi-global solver is `F_0(h(beta))`. Another scalar is smooth `F_tau(h(beta))`. The least-restricting scaling is:

`scale_factor = max(1e-6, 0.12 * current_best_score)`.

For the parent score near 0.38, this gives raw perturbations around a few percent of the interval for the unprojected vector, and the water-filling projection prevents infeasible changes.

2.8 Restricted exact local parametric moves.

For two indices `u` (donor) and `v` (receiver), and transfer amount `delta`, define:

`h'_u = h_u - delta`

`h'_v = h_v + delta`

`h'_i = h_i` otherwise.

This always preserves sum exactly. Feasibility requires:

`0 <= delta <= min(h_u, 1 - h_v)`.

If `h_u` is the donor, the gradient prediction for the composite weighted surrogate (weights `w_s`) is

predicted change `= delta * (grad[v] - grad[u])`.

Therefore, if `grad[u] > grad[v]`, the proxy suggests decreasing the objective by moving mass from `u` to `v`. Candidate ordering should use `grad[u] - grad[v]` descending among feasible pairs. The exact objective has to be tested after selecting `delta`.

2.9 Active candidate storage.

All stored candidates are the exact full evaluator score of the vector stored. `best_h`, `best_score`, and `best_n` together represent output. Overwrite a stored candidate only when exact evaluator score is smaller by `1e-13` or equal within `1e-12` with the dimension reduction priority. Do not use smooth surrogate scores as a primary ranking criterion.
