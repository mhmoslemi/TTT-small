Let me think about the gradient. The objective is f(h) = max_k (sum_i h[i]*(1-h[i+k]) * dx). This is the max of linear functions (in the product h[i]*(1-h[i+k]) it's bilinear, but if we fix which k achieves the max, it's linear in each variable separately).

Actually, for a fixed set of active constraints (the k values achieving the max), the objective is:
g(h) = sum_k w[k] * sum_i h[i]*(1-h[i+k]) * dx

The gradient with respect to h[j] is:
sum_k w[k] * dx * sum_{i: i=j or i+k=j} [contribution]

For h[j]: it appears as h[i] when i=j (contributing (1-h[j+k])*dx) and as h[i+k] when i+k=j, i.e., i=j-k (contributing (-h[j-k])*dx).

So: ∂g/∂h[j] = dx * sum_k w[k] * [(1-h[j+k]) - h[j-k]] (with appropriate boundary handling)

This is essentially a convolution. Let me think about implementing this efficiently.

For the discrete case with n points and dx = 2/n:
- correlation c[k] = sum_{i=max(0,-k)}^{min(n-1, n-1-k)} h[i]*(1-h[i+k])
- The gradient of c[k] with respect to h[j]:
  - h[j] appears as h[i] when i=j and j+k < n: contribution (1-h[j+k])
  - h[j] appears as h[i+k] when i+k=j, i.e., i=j-k and j-k >= 0: contribution -h[j-k]
  - So ∂c[k]/∂h[j] = (1-h[j+k]) * [j+k < n] - h[j-k] * [j-k >= 0]

The full gradient of the weighted sum:
∂(sum_k w[k]*c[k])/∂h[j] = sum_k w[k] * [(1-h[j+k])*[j+k<n] - h[j-k]*[j-k>=0]]

This can be computed as a convolution:
= (w * (1-h))[j] - (w * h)[j] (approximately, with boundary effects)

Actually more precisely, if we define W[k] = w[k] for k in range, then:
sum_k w[k] * (1-h[j+k]) = sum over valid k of w[k]*(1-h[j+k]) = (w convolved with (1-h)) at position j
sum_k w[k] * h[j-k] = (w convolved with h) at position j (with appropriate indexing)

    n = len(h)
    dx = 2.0 / n
    c = np.correlate(h, 1-h, mode="full")
    return np.max(c) * dx, c * dx

def project_feasible(h, target_sum):
    """Project h onto {h: sum(h)=target_sum, 0<=h<=1}"""
    n = len(h)
    h = np.clip(h, 0, 1)
    # Need to adjust to make sum exactly target_sum
    # Use iterative water-filling
    for _ in range(100):
        s = np.sum(h)
        if abs(s - target_sum) < 1e-12:
            break
        diff = target_sum - s
        # Add diff/n to all, then re-clip
        h = h + diff / n
        h = np.clip(h, 0, 1)
    # Final exact fix: adjust one element
    s = np.sum(h)
    diff = target_sum - s
    if abs(diff) > 1e-15:
        # Find an element that can absorb the adjustment
        if diff > 0:
            idx = np.argmax(1 - h)
        else:
            idx = np.argmin(h)
        h[idx] += diff
    return h

Let me also think about whether there's a connection to the problem being a "max-min" or "min-max" problem that can be approached via game theory (von Neumann minimax).

The problem is: min_h max_k f(h,k) where f(h,k) = ∫h(x)(1-h(x+k))dx.

By minimax (if we relax h to be a probability distribution), this equals max_{p over k} min_h E_k[f(h,k)].

The inner min_h of E_k[f(h,k)] subject to ∫h=1, 0≤h≤1 is a linear programming problem. The dual involves finding probabilities p over k such that for all feasible h, E_k[f(h,k)] is minimized.

But this duality only holds if we allow h to be a "mixture" (i.e., h is a random step function). In the deterministic setting, the gap between min_h max_k and max_p min_h is the "duality gap."
