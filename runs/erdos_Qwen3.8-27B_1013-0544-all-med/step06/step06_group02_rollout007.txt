            g[lag:] += 1.0 - h[:N-lag]
            g[:N-lag] -= h[lag:]
    else:
        l = -lag
        if l < N:
            g[:N-l] += 1.0 - h[l:]
            g[l:] -= h[:N-l]
    return g

def soft_grad(h, corr, dx, alpha):
    N = len(h)
    m = corr.max()
    w = np.exp(alpha * (corr - m))
    ws = w.sum()
    if ws < 1e-300:
        ks = np.argmax(corr)
        return grad_lag_fast(h, ks - (N-1), N) * dx
    w /= ws
    g = np.zeros(N)
    for j in range(len(w)):
        if w[j] > 1e-9:
            g += w[j] * grad_lag_fast(h, j - (N-1), N)
    return g * dx

1. The soft_grad function loops over ALL 2N-1 lags, which for N=120 is 239 iterations. Each iteration calls grad_lag_fast which is O(N). So soft_grad is O(N^2) per call. With N=120, that's about 14400 operations per gradient evaluation. The correlation is also O(N^2) for the naive implementation but numpy uses FFT-based for large inputs.

Actually, np.correlate for mode='full' with length N arrays creates a 2N-1 output. The cost is O(N * 2N) = O(N^2) for the naive implementation. For N=120, this is fine.

The main bottleneck in the gradient computation is the loop over 2N-1 lags in soft_grad. For N=120, that's 239 lags, each requiring an O(N) operation, so O(N^2) ≈ 14400 operations. This should be fast enough.

This should be faster when alpha is large (fewer active lags).

Let me also think about whether I should try a completely different approach. What about:

**Approach: Minimax via bisection on t**

We want to find the minimum t such that there exists h with:
- c_k(h) * dx ≤ t for all k
- 0 ≤ h[i] ≤ 1
- sum(h) = N/2

This is a feasibility problem. We can solve it with:
1. Bisection on t
2. For each t, check feasibility (this is a QP since c_k is bilinear)

But solving a QP with bilinear constraints is non-convex... unless we linearize.

Actually, c_k(h) = sum_i h[i](1-h[i+k]) = sum_i h[i] - sum_i h[i]h[i+k]

The term sum_i h[i]h[i+k] is the problem. If we linearize it (e.g., DC programming / successive linearization), we get a convex QP at each iteration.

But this might be too complex for the time budget. Let me stick with the gradient approach but make it more effective.

One key improvement: instead of using the soft max over ALL lags, I should focus on the top few lags. The max is determined by the largest few lags, and the gradient in their direction is what matters.

Let me also add a "top-k" approach:

```python
def top_k_grad(h, corr, dx, k=5):
    N = len(h)
    # Get top k lags
    top_idx = np.argsort(corr)[-k:]
    w = np.zeros(len(corr))
    w[top_idx] = 1.0 / k
    g = np.zeros(N)
    for j in top_idx:
        g += w[j] * grad_lag_fast(h, j - (N-1), N)
    return g * dx
```

This is simpler and might work better for the "sharp max" regime.

def project_feasible(v, N):
    target = N / 2.0
    lo, hi = -2.0, 2.0
    for _ in range(100):
        mid = (lo + hi) / 2.0
        if np.clip(v - mid, 0.0, 1.0).sum() > target:
            lo = mid
        else:
            hi = mid
    lam = (lo + hi) / 2.0
    h = np.clip(v - lam, 0.0, 1.0)
    diff = target - h.sum()

            h[mask] += diff / mask.sum()
            h = np.clip(h, 0.0, 1.0)
