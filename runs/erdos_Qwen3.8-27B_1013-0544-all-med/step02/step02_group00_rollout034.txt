    best_c5, best_corr = compute_c5_and_corr(h)

            break

The key insight for the Erdős problem is that we want h(x) and h(x+k) to be "anti-correlated" for all k simultaneously. This is like a "greedy" coloring problem.

One approach that works well for similar problems is the "alternating projection" method:
1. For each lag k in turn:
   a. Find the direction that reduces the overlap at lag k
   b. Take a step in that direction
   c. Project back onto the feasible set

This is like a block coordinate descent on the lags.

Another idea: **minimax approach**. At the optimum, we want all top lags to be equal. So we can use the following iterative scheme:
1. Compute all lag values
2. Find the maximum
3. For the lag(s) achieving the maximum, compute the gradient
4. Take a step to reduce that lag
5. Repeat

But this is essentially what the subgradient method does.

import numpy as np
from scipy.optimize import minimize, Bounds
import time

def compute_c5_and_corr(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode="full") * dx
    return float(np.max(corr)), corr

def project_h(h, target_sum):
    h = np.clip(h, 0.0, 1.0)
    for _ in range(100):
        diff = target_sum - h.sum()
        if abs(diff) < 1e-15:
            break
        free = (h > 1e-12) & (h < 1.0 - 1e-12)
        if free.sum() == 0:
            free = np.ones(len(h), dtype=bool)
        h[free] += diff / free.sum()
        h = np.clip(h, 0.0, 1.0)
    return h

def active_gradient(h, active, n):
    """Gradient of sum of active lag values w.r.t. h."""
    G = np.zeros(n)
    for k in active:
        lo = max(0, k - n + 1)
        hi = min(n - 1, k)
        j = np.arange(lo, hi + 1)
        G[lo:hi+1] += (1.0 - 2.0 * h[k - j])
    return G

def smooth_max(x, beta):
    m = np.max(x)
    x_shift = np.clip(beta * (x - m), -500, 500)
    return m + np.log(np.sum(np.exp(x_shift)) / len(x)) / beta

  And h[j] appears in: h[j]*(1-h[j+d]) [from k=j] and h[i]*(1-h[j]) [from k=i=j-d]
  
  The term h[i]*(1-h[j]) involves BOTH h[i] and h[j]!
  
  If we change h[i] → h[i]+δ and h[j] → h[j]-δ:
  The term h[i]*(1-h[j]) becomes (h[i]+δ)*(1-h[j]+δ) = h[i]*(1-h[j]) + δ*(1-h[j]) + δ*h[i] + δ²
  
  The other terms involving h[i]: h[i-d]*(1-h[i])+... → h[i-d]*(1-h[i]-δ) (change: -δ*h[i-d])
  The other terms involving h[j]: h[j]*(1-h[j+d])+... → (h[j]-δ)*(1-h[j+d]) (change: -δ*(1-h[j+d]))
  
  And this pair (i,j) also affects OTHER lags. For lag d' ≠ d:
  h[i] appears in V_{d'} as h[i]*(1-h[i+d']) (if valid) and h[i-d']*(1-h[i]) (if valid)
  h[j] appears in V_{d'} as h[j]*(1-h[j+d']) (if valid) and h[j-d']*(1-h[j]) (if valid)
  
  So changing h[i] and h[j] affects ALL lags, not just lag d.

This makes coordinate pair descent complicated. Let me abandon this approach and stick with the subgradient method.
