        # Normalize pressure
        pressure = pressure / np.max(pressure)
        
        # Reduce high-pressure elements, increase low-pressure elements
        # Use a proportional update
        target = S / n  # average value
        reduction = 0.1
        a_new = a.copy()
        for j in range(n):
            if pressure[j] > 0.5:
                a_new[j] = a[j] * (1 - reduction * pressure[j])
            else:
                a_new[j] = a[j] * (1 + reduction * (1 - pressure[j]))
        
        # Rescale to maintain sum
        a_new = a_new * (S / np.sum(a_new))
        a = a_new
    
    return a
```

This is O(n * num_peaks * num_iters) in the worst case, which could be slow. But with FFT, the convolution is fast.

Actually, let me simplify. The "pressure" on `a[j]` from peak `k` is `a[k-j]` (the amount by which `a[j]` contributes to `c[k]`). But really, the gradient of `c[k]` w.r.t. `a[j]` is `2*a[k-j]`. So the pressure is proportional to `a[k-j]`.

A simpler version:
- `pressure[j] = sum_{k in peaks} a[k-j]` (for valid `k-j`)
- This is the cross-correlation of `a` with the indicator of the peaks.
- Can be computed with FFT.

Then:
- Reduce `a[j]` proportionally to `pressure[j]`.
- Increase `a[j]` where `pressure[j]` is small.

Let me implement this more carefully:

```python
def reweighting_step(a, n, alpha=0.1):
    """One step of iterative reweighting to reduce max(a*a)."""
    S = np.sum(a)
    c = compute_autocorrelation(a)
    peak = np.max(c)
    
    # Create a "target" profile: we want c to be as flat as possible
    # The ideal is c[k] = S^2 / (2n-1) for all k
    # Define "excess" at each k
    target = S**2 / (2*n - 1)
    excess = np.maximum(0, c - target)
    
    # Pressure on a[j] = sum_k excess[k] * a[k-j] / peak
    pressure = np.convolve(a[::-1], excess)[n-1:n-1+n]
    
    # Normalize
    if np.max(pressure) < 1e-15:
        return a
    
    pressure = pressure / np.max(pressure)
    
    # Update: reduce where pressure is high, increase where low
    # a_new[j] = a[j] * (1 - alpha * (pressure[j] - avg_pressure))
    avg_p = np.mean(pressure)
    a_new = a * (1 - alpha * (pressure - avg_p))
    a_new = np.maximum(a_new, 0)
    
    # Rescale
    a_new = a_new * (S / np.sum(a_new))
    
    return a_new
```

This is much more efficient! Each step is O(n log n) for the FFT. I can do thousands of steps in a few seconds.

Let me think about whether this converges. The update reduces `a[j]` where it contributes to the "excess" in the autocorrelation, and increases it elsewhere. This should reduce the peak of the autocorrelation over time.

However, there's a risk: if we reduce too much, we might create new peaks elsewhere. The parameter `alpha` controls the aggressiveness of the update. Small `alpha` is safe but slow.

Let me also add a "smoothing" step: after the reweighting, apply a slight Gaussian blur to avoid oscillations.

**Let me also think about the optimal step size.**

The objective is `f(a) = max_k (a*a)[k]`. We want to minimize this subject to `sum(a) = S` and `a >= 0`.

The reweighting step is essentially a (negative) gradient step on `f(a)`, projected onto the constraint set. The gradient of `f(a)` at the argmax `k*` is `2 * a[k*-j]` (shifted `a`). The reweighting uses a "soft" version of this, summing over all excess indices.

For convergence, I need `alpha` to be small enough. A safe choice is `alpha = 1 / (2 * max(a))` (related to the Lipschitz constant of the gradient).

```python
import numpy as np
import time

def fft_convolve(a, b):
    """Full convolution using FFT."""
    n, m = len(a), len(b)
    size = n + m - 1
    fft_size = 1 << (size - 1).bit_length()
    return np.fft.irfft(np.fft.rfft(a, fft_size) * np.fft.rfft(b, fft_size))[:size]

def fft_autocorr(a):
    """Full autocorrelation a*a using FFT."""
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    fa = np.fft.rfft(a, fft_size)
    return np.fft.irfft(fa * fa)
