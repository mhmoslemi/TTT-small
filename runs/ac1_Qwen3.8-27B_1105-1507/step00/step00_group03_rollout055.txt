`dc[k]/da[m] = a[k-m]` (if `0 <= k-m < n`, i.e., m appears as the first factor) + `a[k-m]` (if `0 <= k-m < n`, i.e., m appears as the second factor, meaning `k-i = m` so `i = k-m`)

Wait, both terms require `0 <= k-m < n`. And they're both equal to `a[k-m]`. So:

`dc[k]/da[m] = 2 * a[k-m]` if `0 <= k-m < n`, else 0.

Hmm wait, that's not right either. Let me be very explicit.

`c[k] = sum_i a[i] * a[k-i]` where the sum is over all `i` such that `0 <= i < n` and `0 <= k-i < n`.

The term involving `a[m]` appears when:
- `i = m` (so we need `0 <= k-m < n`, contributing `a[m] * a[k-m]`, derivative w.r.t. a[m] is `a[k-m]`)
- `k-i = m`, i.e., `i = k-m` (so we need `0 <= k-m < n` and `0 <= i = k-m < n`, contributing `a[k-m] * a[m]`, derivative w.r.t. a[m] is `a[k-m]`)

But these are the same condition (`0 <= k-m < n`), and they give the same contribution `a[k-m]`. But wait, are they the same term or different terms?

If `i = m` and `k-i = m`, that means `k = 2m`, and in that case we have a single term `a[m]^2` whose derivative is `2*a[m]`. In the sum formula, when `i = m` and `k-i = m`, it's the same term counted once. So:

`dc[k]/da[m] = a[k-m]` (from `i=m` term) + `a[k-m]` (from `k-i=m` term) if `i ≠ k-i` (i.e., `m ≠ k-m`, i.e., `2m ≠ k`)
`dc[k]/da[m] = 2*a[m]` if `2m = k` (the term is `a[m]^2`)

In both cases, `dc[k]/da[m] = a[k-m] + a[m]` when `m = k/2`... no wait.

OK let me just use the standard result: for `c[k] = sum_i a[i]a[k-i]`, we have `dc[k]/da[m] = a[k-m] + a[m-k]` where we define `a[j] = 0` for j outside [0, n-1].

When `k-m` is in [0,n-1]: first term is `a[k-m]`
When `m-k` is in [0,n-1]: second term is `a[m-k]` = `a[k-m]` if `m-k = k-m`... no, `a[m-k]` where `m-k` is the index.

Hmm, I think the cleanest way is:
`dc[k]/da[m] = a[k-m]` (if `0 <= k-m <= n-1`) + `a[k-m]` (if `0 <= k-m <= n-1`)

Wait no. Let's use the symmetry. `c[k] = c[2n-2-k]` IF a is symmetric. In general, that's not true.

Let me just use: `dc[k]/da[m] = a[k-m]` where `a[j] = 0` for `j` outside `[0, n-1]`.

No wait, that's only the contribution from `a[m]` being the first factor. The second factor `a[k-i]` contributes when `k-i = m`, i.e., `i = k-m`, and the derivative is `a[i] = a[k-m]`.

So total: `dc[k]/da[m] = a[k-m] + a[k-m] = 2*a[k-m]` when `0 <= k-m < n`.

But when `i = m` and `i = k-m` simultaneously (i.e., `m = k-m`, `k = 2m`), we've double-counted. In that case, the term is `a[m]^2` and the derivative is `2*a[m]`, which equals `2*a[k-m] = 2*a[m]`. So it's consistent!

So: `dc[k]/da[m] = 2*a[k-m]` if `0 <= k-m < n`, else 0.

Therefore: `dg/da[m] = 2 * sum_{k: 0<=k-m<n} c[k] * 2*a[k-m] = 4 * sum_{j=0}^{n-1} c[m+j] * a[j]`

where I substituted `j = k-m`.

So `dg/da[m] = 4 * (a * c)[m]` where `*` denotes cross-correlation-like operation: `(a*c)[m] = sum_{j=0}^{n-1} a[j] * c[m+j]`.

This is like a cross-correlation of `a` with `c`, but with indices shifted.

Now, for projected gradient descent:
- Gradient: `grad[m] = 4 * sum_{j=0}^{n-1} a[j] * c[m+j]`
- Update: `a_new[m] = max(0, a[m] - η * grad[m])`
- Renormalize: `a_new = a_new / sum(a_new) * target_sum`

But this gradient might have interesting properties. Note that `grad[m]` is always non-negative (since both a and c are non-negative). So the gradient descent always pushes values down. After renormalization, the relative proportions change.

This is actually a form of "exponentiated gradient" or "multiplicative update" if we think of it in log-space.

Actually, for non-negative optimization, multiplicative updates are often better:
`a[m] ← a[m] * exp(-η * grad[m])` or `a[m] ← a[m] * (1 - η * grad[m])` (for small η)

Let me think about this more. Since the gradient is non-negative, we're always decreasing all components, and then renormalizing. The components that decrease the most (relative to their current value) are the ones with the largest gradient, which are the ones contributing most to the peak convolution. This should help flatten the convolution.
