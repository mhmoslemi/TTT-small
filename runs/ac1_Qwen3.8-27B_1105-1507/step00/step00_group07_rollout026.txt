```python
def fast_autocorr(a):

    n = len(a)
    size = 2 * n - 1
```

```python
    """Reduce the peak of the autocorrelation via coordinate descent."""
    n = len(a)
    S = a.sum()
    a = a.copy()
    
    for it in range(n_iter):
        # Compute autocorrelation
        R = fast_autocorr(a)
        k_star = np.argmax(R)
        peak = R[k_star]

        # R[k] = sum_i a[i] a[i-k] for i in [k, n-1]
        # dR[k]/da[i] = a[i-k] (if i >= k) + a[i+k] (if i+k < n)

        pressure[k:] += a[:n-k]
        # For i in [0, n-k-1]: pressure[i] += a[i+k]
```

```python
    a = a.copy() / S  # unit sum

        fa = np.fft.rfft(a, 2 * n)
```

```python
    # Gradient: for each m, grad[m] = 2 * a[k_star - m] if 0 <= k_star - m < n
    grad = np.zeros(n)
    lo = max(0, k_star - n + 1)
    hi = min(n - 1, k_star)
    for m in range(lo, hi + 1):
        grad[m] = 2 * a[k_star - m]
    
    # Gradient step
    a_new = a - lr * grad
    a_new = np.maximum(a_new, 0)
    
    # Renormalize
    S = a.sum()
    if a_new.sum() > 0.01:
        a_new = a_new * S / a_new.sum()
    
    return a_new
```

This is O(n) per step (plus O(n log n) for the FFT). I can do many iterations quickly.

But there's a problem: the subgradient method is known to be slow for non-differentiable objectives. The max function is non-smooth, and the subgradient can oscillate.

To improve, I can use:
1. **Averaged subgradient**: Use the average of recent subgradients
2. **Nesterov acceleration**: Use momentum
3. **Proximal gradient**: Use a proximal operator (the projection onto {a >= 0, sum(a) = S})

Let me also consider: maybe I should try a completely different initialization. What if I use a sequence that's designed to have flat convolution from the start?

One idea: use a **random sequence with equal variance**. If a[i] are i.i.d. with mean mu and variance sigma^2, then:
- E[conv[k]] = n * (mu^2 + sigma^2 * indicator(k=0)) for k=0, and n*mu^2 for k≠0 (approximately)
- Var[conv[k]] ≈ n * (something)

The peak will be dominated by the variance term. To minimize the peak, we want small variance, which means small sigma. In the limit sigma→0, we get the uniform sequence (score=2).

So random sequences won't help. We need a structured sequence.

Let me try yet another angle. What if I think of this as an optimization problem and use a proper solver?

minimize: max_k (a*a)[k]
subject to: a >= 0, sum(a) = S

This is a convex optimization problem! The objective is the maximum of linear functions (each (a*a)[k] is quadratic in a, but... wait, it's not linear in a).

Actually, (a*a)[k] = sum_j a[j]*a[k-j] is a quadratic form in a (quadratic, not linear). So the objective max_k (a*a)[k] is the maximum of quadratic functions, which is convex (max of convex functions is convex). And the constraint set {a >= 0, sum(a) = S} is convex. So this IS a convex optimization problem!

We can solve it using:
- SOCP (Second-Order Cone Program): introduce variable t, minimize t subject to (a*a)[k] <= t for all k, a >= 0, sum(a) = S
- But (a*a)[k] <= t is not a convex constraint in general (it's a quadratic constraint, which defines a convex set if the quadratic is convex, but (a*a)[k] as a function of a is not convex in general)

Wait, is (a*a)[k] = sum_j a[j]*a[k-j] convex as a function of a? The Hessian involves the matrix that maps a to (a*a)[k]. Let me check: (a*a)[k] = a^T M_k a where M_k is a symmetric matrix with M_k[j, k-j] = 1/2 (for valid indices). The Hessian is 2*M_k. For this to be PSD (convex), M_k must be PSD.

M_k has entries M_k[j, l] = 1/2 if l = k-j, else 0. This is half of a permutation matrix (the reversal matrix for lag k). A permutation matrix has eigenvalues that are roots of unity, so it's not PSD in general. So (a*a)[k] is NOT convex in a!

Therefore, the problem is NOT convex. We can't use standard convex optimization.

    """Compute np.convolve(a, a, 'full') via FFT."""
