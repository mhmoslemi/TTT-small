This is clean and correct. For k = n-1: j_min = 0, j_max = n-1, g[j] = 2*a[n-1-j] = 2*a_reversed[j].

    best_score = float(evaluate_sequence(best.tolist()))

    # But we need to maintain sum > 0.01 for the evaluator
    
    while time.monotonic() < deadline:
        # Phase 1: Gradient-based peak reduction
        a = best.copy()
        eta = 0.01  # learning rate
        no_improve = 0
        
        for iteration in range(10000):
            if time.monotonic() > deadline:
                break
            
            c = fft_convolve(a, a)
            k_star = np.argmax(c)
            
            # Compute gradient
            g = gradient_at_peak(a, k_star)
            
            # Update
            a_new = a - eta * g
            a_new = np.maximum(0.0, a_new)
            sum_new = np.sum(a_new)
            if sum_new < 1e-10:
                break
            a_new = a_new * (np.sum(a) / sum_new)
            
            # Check improvement
            score = compute_objective_fast(a_new)
            if score < best_score - 1e-10:
                best = a_new.copy()
                best_score = score
                no_improve = 0
            else:
                no_improve += 1
            
            a = a_new
            eta *= 0.999  # slowly decay learning rate
            
            if no_improve > 500:
                break
        
        # Phase 2: Random perturbation to escape local minimum
        if time.monotonic() > deadline:
            break
        
        a = best.copy()
        # Add random perturbation
        perturbation_scale = 0.1 * np.mean(a)
        a = a + rng.normal(0, perturbation_scale, n)
        a = np.maximum(0, a)
        a = a * (np.sum(best) / np.sum(a))
    
    # Final verification
    final_score = float(evaluate_sequence(best.tolist()))
    if np.isfinite(final_score) and final_score < best_score:
        best_score = final_score
    
    return [float(x) for x in best]

Wait, I realize there's an issue with the gradient approach. When we compute the gradient of the peak and take a step in the negative direction, we're trying to reduce the peak. But the gradient of the peak with respect to a is a "mirrored" copy of a. Taking a step in the negative gradient direction means:

a_new[j] = a[j] - eta * 2 * a[k*-j]

This reduces a[j] where a[k*-j] is large. Since a[k*-j] is the "mirror" of a[j] (for k* = n-1), this means we're reducing the "heaviest" part of a.

But after rescaling to maintain the sum, the effect is: we're "redistributing" weight from heavy positions to light positions. This should reduce the peak over time.

However, there's a subtlety: reducing the peak at one position might increase peaks at other positions. The algorithm only looks at the current maximum, so it might oscillate.

To address this, I can use a "soft" version: instead of just the maximum, use the top-K peaks with weights proportional to their excess over the mean.

Let me also consider using the "additive" approach from the state-of-the-art description:
1. Compute c = conv(a, a), M = max(c).
2. Find the "optimal" perturbation direction using an LP or a simpler heuristic.
3. Apply the perturbation.

For the LP approach, the constraint is conv(g, a) <= M for all positions. The objective is to maximize sum(g). This is a linear program with n variables and 2n-1 constraints.

For n=4498, this LP has 4498 variables and 8995 constraints. The constraint matrix is banded (each row has at most n non-zeros, but typically fewer). This should be solvable with GLOP or CBC in a reasonable time.

But we don't want to solve an LP at every iteration (too slow). We can solve it less frequently (e.g., every 100 gradient steps) or use it as a "restart" mechanism.
