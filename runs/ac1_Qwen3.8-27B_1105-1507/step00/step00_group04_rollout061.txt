Actually, let me reconsider. The LP approach from the paper is:
- Given current `f` with `M = ||f*f||_inf`
- Solve: max `sum b_j` s.t. `b >= 0`, `||f*b||_inf <= M`
- Get `b*`, normalize to `g = b* / sum(b*)`
- Update `f = (1-t)f + t*g`

The key question is: what step size `t` to use?

If we use `t=1` (jump all the way to `g`), we might overshoot. If `t` is too small, convergence is slow.

A good approach is line search: try `t in {0.1, 0.2, ..., 1.0}` and pick the best.

But each evaluation of `max(a*a)` costs O(n²) (or O(n log n) with FFT). So line search with 10 points costs 10 * O(n²) per iteration.

For n=512, that's 10 * 262K = 2.6M operations per iteration. Very fast.

For n=4096, that's 10 * 16M = 160M operations per iteration. Still fast (under a second).

The LP is the bottleneck. For n=4096, the LP has 4096 variables and 8191 constraints. This might take a few seconds per iteration.

import numpy as np
import time
from scipy.optimize import linprog
from scipy import sparse

def solve_lp_direction(a, M):
    """Solve the LP: max sum(g) s.t. g >= 0, (a*g)_k <= M for all k."""
    n = len(a)
    # Constraint matrix A: (2n-1) x n, where A[k, j] = a[k-j] if 0 <= k-j < n else 0
    # We want A @ g <= M (vector of M's)
    
    # Build the sparse constraint matrix
    rows = []
    cols = []
    vals = []
    for k in range(2*n - 1):
        for j in range(max(0, k-n+1), min(n, k+1)):
            idx = k - j
            if 0 <= idx < n:
                rows.append(k)
                cols.append(j)
                vals.append(a[idx])
    
    A = sparse.csr_matrix((vals, (rows, cols)), shape=(2*n-1, n))
    b = np.full(2*n-1, M)
    
    # Maximize sum(g) = -minimize -sum(g)
    c = -np.ones(n)
    
    result = linprog(c, A_ub=A, b_ub=b, bounds=[(0, None)]*n, method='highs')
    
    if result.success:
        return result.x
    else:
        return a.copy()  # Fallback: use current point

def optimize_sequence_lp(a, max_iters=1000, time_budget=600):
    """Optimize using LP-based direction finding."""
    a = a.astype(np.float64).copy()
    a = np.maximum(a, 0)
    s = np.sum(a)
    if s < 1e-10:
        a = np.ones_like(a)
        s = 1.0
    a = a / s  # Normalize to sum = 1
    
    n = len(a)
    best_a = a.copy()
    best_m = np.max(np.convolve(a, a))
    start_time = time.monotonic()
    
    for it in range(max_iters):
        if time.monotonic() - start_time > time_budget:
            break
        
        c = np.convolve(a, a)
        M = np.max(c)
        
        # Solve LP
        g = solve_lp_direction(a, M)
        g_sum = np.sum(g)
        
        if g_sum <= 1.0 + 1e-6:
            # Can't improve with this direction
            break
        
        # Normalize g to sum = 1
        g = g / g_sum
        
        # Line search
        best_t = 0.0
        best_m_new = M
        for t in [0.05, 0.1, 0.2, 0.3, 0.5, 0.7, 1.0]:
            a_new = (1-t)*a + t*g
            m_new = np.max(np.convolve(a_new, a_new))
            if m_new < best_m_new:
                best_m_new = m_new
                best_t = t
        
        if best_t == 0.0:
            break
        
        a = (1-best_t)*a + best_t*g
        
        if best_m_new < best_m:
            best_m = best_m_new
            best_a = a.copy()
        
        # Check convergence
        if M - best_m < 1e-8:
            break
    
    return best_a, best_m

Let me try a different approach: **subgradient method with momentum**.

The subgradient of `max_k c_k` at a point where the max is achieved at indices S is:
`grad = (1/|S|) * sum_{k in S} grad_k`

where `grad_k[j] = a[k-j] + a[j]` (with a[m]=0 for m out of range).

Then we do:
`a_new = a - lr * grad`
`a_new = project(a_new)` (project onto {a >= 0, sum(a) = 1})

The projection onto {a >= 0, sum(a) = 1} is the "water-filling" operation: find λ such that `sum(max(a - lr*grad - λ, 0)) = 1`, then set `a_new = max(a - lr*grad - λ, 0)`.

```python
def subgradient_step(a, lr):
    n = len(a)
    c = np.convolve(a, a)
    M = np.max(c)
    # Get the argmax set (with some tolerance)
    S = np.where(c >= M - 1e-8)[0]
    
    # Compute subgradient
    grad = np.zeros(n)
    for k in S:
        for j in range(n):
            # a[k-j] term
            idx = k - j
            if 0 <= idx < n:
                grad[j] += a[idx]
            # a[j] term
            grad[j] += a[j]
    grad /= len(S)
    
    # Update
    a_new = a - lr * grad
    a_new = np.maximum(a_new, 0)
    s = np.sum(a_new)
    if s > 0:
        a_new = a_new / s
    else:
        a_new = np.ones(n) / n
    return a_new, M
```

This is O(n * |S|) per step. If |S| is small (just the peak), it's O(n²) per step.

The learning rate is important. Too large and we oscillate; too small and convergence is slow. We can use a decreasing learning rate schedule: `lr = lr0 / sqrt(it)`.
