Note that conv(a, b) is linear in b. We can write this as A @ b <= M * ones, where A is the (2n-1) x n convolution matrix.

Instead of building A explicitly, we can use the following trick:
- A @ b = conv(a, b)
- We can compute this using FFT: ifft(fft(a, 2n-1) * fft(b, 2n-1))

But the LP solver needs the matrix in explicit form. Unless we use a solver that accepts a matrix-vector product callback, which is possible with some solvers (like SCS or PDLP) but not all.

Actually, CVXPY does support problem formulations where you can define the constraints using operations on variables, without explicitly building matrices. The DCP (Disciplined Convex Programming) framework handles the conversion to standard form.

    # Actually, the most efficient way for a Toeplitz-like matrix:
    # Each column j is a[j] * [0...0, 1, 1, ..., 1, 0...0]^T
    # where the 1s are in positions j to j+n-1 (clipped to [0, 2n-2])

    rows_list = []
    cols_list = []
    data_list = []
    
    for j in range(n):
        r_start = j
        r_end = min(2*n - 2, j + n - 1)

    data = np.concatenate(data_list)
