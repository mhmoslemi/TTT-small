"""
Minimizes J(a) = 2*n*max(conv(a,a))/(sum(a))^2 using:
1. Adam optimizer with smooth-max gradient (much faster than LP-based approach)
2. Progressive tau annealing (sharpens max approximation over time)
3. Variance-aware objective (encourages flat auto-correlation)
4. Multi-scale initialization and length exploration
5. Coordinate descent polishing for final refinement

import numpy as np
import time

def fast_conv(a):
    n = len(a)
    size = 1
    while size < 2 * n - 1:
        size <<= 1
    fa = np.fft.rfft(a, size)
    result = np.fft.irfft(fa * fa, size)[:2 * n - 1]
    # Clamp tiny negatives from FFT
    result = np.maximum(result, 0.0)
    return result

def compute_J(a):
    a = np.maximum(a, 0)
    s = a.sum()
    if s < 0.01:
        return float('inf')
    b = fast_conv(a)
    return float(2 * len(a) * b.max() / (s * s))

def smooth_max_grad(a, tau):
    """
    Compute gradient of (1/tau) * log(sum exp(tau * conv(a,a))) with respect to a.
    Returns (grad, b, p) where p is the softmax weights.
    """
    n = len(a)
    b = fast_conv(a)
    b_max = b.max()
    exponents = tau * (b - b_max)
    # For numerical stability
    exponents -= exponents.max()
    exp_vals = np.exp(exponents)
    p = exp_vals / exp_vals.sum()
    
    # grad[j] = 2 * sum_k p[k] * a[k-j] for valid k-j
    # This is 2 * correlate(p, a, 'full')[:n]
    grad = 2.0 * np.correlate(p, a, 'full')[:n]
    return grad, b, p

    a is kept normalized (sum = 1) throughout.

    if s < 1e-10:
        return a_init, float('inf')

        b_max = b.max()

        v_hat = v / (1.0 - beta2**t)

Let me replace the coordinate descent with a smarter approach: **block coordinate descent** or **pairwise optimization**.

Actually, let me think about what's really the bottleneck. The main benefit of Adam over the parent's LP approach is speed: each Adam iteration is O(n log n) (for the FFT) while each LP iteration is much slower. So in the same time, Adam can do 100-1000x more iterations.

The question is whether Adam can find a better solution than LP mirror descent. LP finds the exact "best direction" in a certain sense, while Adam is an approximate method. However, Adam's advantage is that it can do many more iterations and explore the landscape more thoroughly.

I think the key improvements over the parent are:
1. **Much more iterations** (Adam is faster per iteration)
2. **Progressive tau** (start with smooth approximation, sharpen over time)
3. **Better escape from local minima** (adaptive lr reduction + restarts)
4. **Variance encouragement** (using sum-of-exponentials instead of just max)

Let me also add a **restart mechanism**: if no improvement for a while, reset the Adam state and try a different tau or a slightly perturbed starting point.

Let me also think about whether I should use the **sum-of-exponentials** objective instead of the smooth max. The sum-of-exponentials:
Psi(a) = sum_k exp(tau * b[k])

has the property that it's sensitive to ALL peaks, not just the single max. This should help equalize the peaks. The gradient is:
d Psi / d a[j] = 2*tau * sum_k exp(tau * b[k]) * a[k-j]

This is the same direction as the smooth max gradient (just scaled differently), but the effective "tau" is automatically adapted based on the spread of b values.

Actually, I realize the gradient direction IS the same. The gradient of the smooth max is:
grad_smoothmax[j] = 2 * sum_k p[k] * a[k-j] where p[k] = exp(tau*(b[k]-M)) / sum_l exp(tau*(b[l]-M))

The gradient of the sum of exponentials is:
grad_sumexp[j] = 2*tau * sum_k exp(tau*b[k]) * a[k-j] = 2*tau * sum(exp) * sum_k p[k] * a[k-j]

So grad_sumexp = 2*tau * sum(exp) * grad_smoothmax

They're in the same direction! So using one or the other doesn't matter for the direction of steepest descent. The difference is only in the magnitude, which Adam normalizes away.

So the smooth max gradient is fine. Let me stick with it.
