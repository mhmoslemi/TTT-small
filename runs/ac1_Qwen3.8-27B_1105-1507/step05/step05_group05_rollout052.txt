def coordinate_update_fast(a, b, i, x_cur):
    """Fast 1D optimization for coordinate i, given current a and convolution b."""
    n = len(a)
    S = a.sum()
    
    # Affected range
    k_lo = i
    k_hi = min(2*n-2, i+n-1)
    
    # Unaffected max
    if k_lo > 0:
        base_max_left = b[:k_lo].max() if k_lo > 0 else 0
    else:
        base_max_left = 0
    if k_hi < 2*n-2:
        base_max_right = b[k_hi+1:].max() if k_hi+1 < 2*n-1 else 0
    else:
        base_max_right = 0
    base_max = max(base_max_left, base_max_right)
    
    # Affected positions
    ks = np.arange(k_lo, k_hi+1)
    # j = k - i, range [0, n-1]
    js = ks - i  # these are the indices j such that a[j] pairs with a[i]
    
    # A_k = 2 * a[k-i] = 2 * a[j]
    A = 2 * a[js]
    
    # C_k = b[k] - A_k * x_cur (for k != 2i)
    # For k = 2i: C = b[2i] - 2*a[i]*x_cur - x_cur^2, and there's x^2 term
    C = b[ks] - A * x_cur
    
    # Mark the quadratic term (k = 2i)
    quad_mask = (ks == 2*i)
    if quad_mask.any():
        # For k = 2i, the actual b_new = C + A*x + x^2 (since (x-x_cur)^2 + 2*x_cur*x... let me recheck)
        # b_new[2i] = b[2i] + 2*(x-x_cur)*a[i] + (x^2 - x_cur^2)
        # = b[2i] - 2*x_cur*a[i] - x_cur^2 + 2*a[i]*x + x^2
        # = C_2i + A_2i * x + x^2
        # where C_2i = b[2i] - 2*x_cur*a[i] - x_cur^2, A_2i = 2*a[i]
        # But I set C = b[ks] - A * x_cur, so for k=2i: C[quad] = b[2i] - 2*a[i]*x_cur
        # And the actual formula has an extra -x_cur^2. So:
        C[quad_mask] -= x_cur * x_cur
    
    # Now b_new[k] = C + A*x + (x^2 if quad else 0)
    
    def obj(x):
        vals = C + A * x
        if quad_mask.any():
            vals[quad_mask] += x * x
        m = max(base_max, vals.max())
        new_sum = S - x_cur + x
        if new_sum <= 0:
            return 1e10
        return m / (new_sum * new_sum)
    
    # Golden section search
    lo = 0.0
    hi = max(x_cur * 2 + 0.5, 0.1)
    
    # Check if expanding hi helps
    if obj(hi) < obj(hi * 0.5):
        hi *= 2
    
    gr = (np.sqrt(5) - 1) / 2
    a_pt = hi - gr * (hi - lo)
    b_pt = lo + gr * (hi - lo)
    fa = obj(a_pt)
    fb = obj(b_pt)
    
    for _ in range(40):
        if fa < fb:
            hi = b_pt
            b_pt = a_pt
            fb = fa
            a_pt = hi - gr * (hi - lo)
            fa = obj(a_pt)
        else:
            lo = a_pt
            a_pt = b_pt
            fa = fb
            b_pt = lo + gr * (hi - lo)
            fb = obj(b_pt)
    
    x_opt = (lo + hi) / 2.0
    if obj(0.0) < obj(x_opt):
        x_opt = 0.0
    
    return x_opt

    a[0] = np.sqrt(c)
    for k in range(1, n):

        for i in range(1, k):

        a[k] = (c - s) / (2 * a[0])
    return a / a.sum()  # normalize

One more thought: the previous code's coordinate_update function recomputes the full convolution at the start of each call. I can avoid this by maintaining the convolution incrementally: when I update a[i] from x_old to x_new, I update b[k] for all affected k.

This gives an O(n) update per coordinate change (instead of O(n log n) for FFT recomputation). Over a full sweep, this saves a factor of ~log n.

Let me implement this:

```python
def update_convolution(b, a, i, x_old, x_new):
    """Update convolution b in-place when a[i] changes from x_old to x_new."""
    n = len(a)
    k_lo = i
    k_hi = min(2*n-2, i+n-1)
    delta = x_new - x_old
    for k in range(k_lo, k_hi+1):
        j = k - i
        if 0 <= j < n:
            if k == 2*i:
                b[k] += (x_new*x_new - x_old*x_old)
            else:
                b[k] += 2 * delta * a[j]
```

Wait, this is O(n) per update, which is the same as the FFT approach for small n. For n=512, FFT is O(n log n) ≈ 4600 operations, while direct update is O(n) = 512 operations. So direct update is faster!

But I need to be careful: the direct update formula is:
When a[i] changes by delta = x_new - x_old:
- For k = 2i: b[k] changes by (x_new^2 - x_old^2) = delta * (x_new + x_old)
- For k != 2i, k in [i, i+n-1] (clamped): b[k] changes by 2 * delta * a[k-i]

Let me verify: (a*a)[k] = sum_j a[j]*a[k-j]. The terms involving a[i] are:
- j = i: a[i]*a[k-i]
- j = k-i: a[k-i]*a[i] (same term if k-i = i, i.e., k = 2i)

So the contribution of a[i] to b[k] is:
- 2*a[i]*a[k-i] if k-i != i (i.e., k != 2i)
- a[i]^2 if k = 2i

When a[i] changes to a[i] + delta:
- New contribution: 2*(a[i]+delta)*a[k-i] = 2*a[i]*a[k-i] + 2*delta*a[k-i] (for k != 2i)
  Or: (a[i]+delta)^2 = a[i]^2 + 2*delta*a[i] + delta^2 (for k = 2i)
- Change: 2*delta*a[k-i] (for k != 2i) or 2*delta*a[i] + delta^2 (for k = 2i)

So:
- For k != 2i: b[k] += 2*delta*a[k-i]
- For k = 2i: b[k] += 2*delta*a[i] + delta^2

This is correct. And it's O(n) per update (n affected k values).

obj(x) = max(base_max, max_k (C_k + A_k*x + q_k*x^2)) / (S - x_cur + x)^2

where:
- base_max = max of b[k] for unaffected k
- C_k, A_k, q_k are as defined before

I can precompute C, A for the current state of a and b, and then the objective evaluation is just a few vector operations.
