```python
        size <<= 1

    conv = np.fft.irfft(fa*fa, size)

            a = a / S
            conv = compute_conv(a)
            obj = 2.0*n*np.max(conv)
            if obj < best_obj - 1e-12:
                best_obj = obj
                best_a = a.copy()
                improved = True
        if not improved and sweep > 5:
            break
    
    return best_a
```

Wait, there's a problem. After I update a[i] and renormalize, the conv changes for ALL coordinates (because normalization scales all of them). So I need to recompute conv after each coordinate update. That's O(n log n) per update, and O(n^2 * 

log n) per sweep. For n=330, that's about 330*20*330*9 ≈ 24.5M per sweep (with 20 evaluations per coordinate). With 100 sweeps: ~2.4B. In Python with numpy, each FFT of size 512 is maybe ~1μs, so 24.5M FFTs would be too slow.

Wait, 330 coordinates × 20 evaluations = 6600 FFTs per sweep. Each FFT is O(n log n) ≈ 330*9 = 2970 operations. So 6600 * 2970 ≈ 19.6M operations per sweep. In numpy, an FFT of size 512 takes about 1-5μs. So 6600 * 3μs ≈ 20ms per sweep. With 100 sweeps: 2 seconds. That's fine!

But wait, I also need to recompute conv after each coordinate update (to get the correct conv for the next coordinate). That's 330 extra FFTs per sweep, which is negligible.

Actually, I realize I can avoid the FFT entirely in the 1D subproblem. Since I have conv_no_i and d precomputed, I just need to do:
`new_conv = conv_no_i + new_v * d`
`new_conv[i] = conv_no_i[i] + new_v**2`
`return max(new_conv) / S_new**2`

This is O(n) per evaluation (just a vector addition and max). So 20 evaluations = O(20n) = O(6600) per coordinate. Per sweep: O(n^2 * 20) = O(330^2 * 20) = O(2.18M). Very fast!

The only O(n log n) part is recomputing conv after each coordinate update (330 times per sweep). That's 330 * O(n log n) = 330 * 2970 ≈ 1M per sweep. Total per 100 sweeps: 100M. Fine.

Actually, I can also update conv incrementally! When a[i] changes by δ:
- conv[k] += 2*δ*a[k-i] (for k≠i, 0<=k-i<n)
- conv[i] += 2*v*δ + δ^2

This is O(n) per update. So per sweep: 330 * O(n) = O(n^2) = O(109K). Very fast!
