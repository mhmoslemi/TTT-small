def solve_1d_minimax(x_old, quad_c, lines_m, lines_b):
    """
    Find x >= 0 minimizing max(x^2 + quad_c, max_j(m_j*x + b_j), 0)
    using binary search on the value.
    quad_c: constant term of quadratic (C_old[2i] - x_old^2)
    lines_m: array of slopes (2*a[n_l-i])
    lines_b: array of intercepts (C_old[n_l] - 2*x_old*a[n_l-i])

    lo = 0.0

        mid = (lo + hi) / 2
        # Check feasibility
        x_low = 0.0

        if mid < quad_c:

            elif m < -1e-15:

                x_low = max(x_low, (mid - b) / m)
            else:
                # b <= mid
                if b > mid:
                    return float('inf')  # infeasible
        
        if x_low <= x_high + 1e-15:
            hi = mid
        else:
            lo = mid
    
    # Optimal x is in [x_low, x_high] at V = hi
    # Return the midpoint for stability
    x_high = np.sqrt(max(0, hi - quad_c))
    for j in range(len(lines_m)):

However, we're dealing with LINEAR convolution, not circular. The linear convolution has the "edge effects" that make the problem different.

For n=512 and 512 coordinates per sweep, that's 512 * O(n log n) = O(n^2 log n) per sweep, which is about 512^2 * 10 ≈ 2.6M ops per sweep. With 1000 sweeps, that's 2.6B ops. **Key insight**: Computing the full convolution for each 1D evaluation is wasteful. I only need to update the convolution values that change when a[i] changes. Those are at lags [i, i+n-1].

For a change in a[i] from x_old to x_new:
- C_new[k] for k in [i, i+n-1]: C_old[k] + 2*(x_new - x_old)*a[k-i] (for k ≠ 2i)
  or C_old[k] + (x_new^2 - x_old^2) for k = 2i
- C_new[k] for k not in [i, i+n-1]: C_old[k] (unchanged)

So I can update C in O(n) time (only the relevant lags change). Then the max is O(n) to compute. Total per coordinate evaluation: O(n). Total per sweep: O(n^2). With FFT for the initial computation and O(n) updates per coordinate, this is much faster.
