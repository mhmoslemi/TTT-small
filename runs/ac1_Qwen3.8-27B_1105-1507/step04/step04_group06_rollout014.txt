(a) Use the stale b (computed at the start of the sweep) for all updates (Jacobi-style). This is fast but might not converge as well.
(b) Update b incrementally after each coordinate change (Gauss-Seidel-style). This is more accurate but requires O(n) work per update (to update the affected entries of b).

For option (b): when we change a[i] by delta, the convolution changes as:
b_new[k] = b[k] + delta * a[k-i] (for k in [i, i+n-1])

This is an O(n) update (we add delta * a[k-i] to b[k] for k in [i, i+n-1]).

So the total cost per sweep is O(n^2) (n coordinates × O(n) per coordinate for the update and the max computation).

For n = 1024, that's about 1M operations per sweep, which should be fast.

Let me implement both options and see which works better.

Actually, for option (b), we need to compute B_fix = max of b[k] for k outside [i, i+n-1]. This is the max of b[0:i] and b[i+n:2n-1] (using Python slicing). If we maintain a data structure for range maximum queries, this could be O(log n) per query. But for simplicity, O(n) per query is fine.

Wait, I realize there's an even simpler observation. In Case 4 (B_peak <= B_fix), we're trying to increase a[i] to saturate the constraint. So coordinate descent only makes progress when B_peak < B_fix (strictly), meaning the peak is outside the range [i, i+n-1].

This suggests that coordinate descent will drive the sequence toward a state where the convolution peak is "balanced" - no single region has a significantly lower peak than the rest.

def coordinate_descent_sweep(a, b, n_passes=1):

    Perform coordinate descent sweeps. b is the current convolution.
    Uses Gauss-Seidel style: update b after each coordinate change.
    """
    n = len(a)
    a = a.copy().astype(np.float64)
    b = b.copy().astype(np.float64)
    
    for _ in range(n_passes):
        for i in range(n):
            # Compute B_fix = max of b[k] for k outside [i, i+n-1]
            # k ranges from 0 to 2n-2
            lo = i
            hi = i + n - 1  # inclusive
            # Outside: [0, lo-1] and [hi+1, 2n-2]
            if lo > 0:
                B_fix_left = b[:lo].max()
            else:
                B_fix_left = 0.0
            if hi + 1 < 2 * n - 1:
                B_fix_right = b[hi+1:].max()
            else:
                B_fix_right = 0.0
            B_fix = max(B_fix_left, B_fix_right)
            
            # B_peak = max of b[k] for k in [lo, hi]
            B_peak = b[lo:hi+1].max()
            
            if B_peak > B_fix + 1e-15:
                # Peak is in our range, can't reduce without increasing elsewhere
                continue
            
            # Try to increase a[i]
            # d* = min over k in [lo,hi] with a[k-i] > 0 of (B_fix - b[k]) / a[k-i]
            # k-i ranges from 0 to n-1
            # b[k] for k in [lo,hi] has indices lo to hi
            # a[k-i] for k in [lo,hi] is a[0] to a[n-1]

            d_star = candidates.min()

                # Update a[i]
                delta = d_star
                a[i] += delta
                # Update b
                b[lo:hi+1] += delta * a_slice
    
    return a, b
