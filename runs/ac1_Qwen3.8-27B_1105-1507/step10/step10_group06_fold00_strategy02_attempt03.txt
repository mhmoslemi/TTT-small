2.  **Smoothing Constraint (Element-Sum)**: Each coefficient cannot be arbitrarily large (bounded by 1000) to prevent singular behavior (divide-by-zero error and inf/surrounding) that might confuse optimization.

We differ from the previous strategy mainly by enhancing the gradient polishing phase, incorporating combinatorial ideas through the `compose_sequence` helper, and using Fourier perturbations specifically to optimize the structure of the sequence (not just to escape). We maintain the same evaluation criteria as the evaluator.

Mathematical specification:

*   We represent candidate step function coefficients in a normalized way, but maintain the underlying sequence that defines the simplex via `np.maximum(0, x)/s`.
*   The goal is to minimize the objective: `2 * n * max(convolve(seq, mode='full')) / (s)**2`, where `convolve` is the linear convolution (mode 'full') of the sequence.
*   The `compute_convolve_full` function will be used to compute the convolution profile (2*n-1 points) for the Linfinity constraint.
*   We re-formulate the optimization problem into two parts: simplex projection and gradient update. The projected gradient steps consider adjusted gradients based on the simplex constraint and element-sum bounds at each iteration.
*   For gradient descent, we use analytic gradient coefficients (unlike the current `smoothed_gradient` which computes using exponential smoothing) or rely on a fast, user-friendly gradient approximation from the `smoothed_gradient` function, but in a way that informs function-level behavioral changes.
