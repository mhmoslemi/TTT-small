But in the linear cross-correlation computed via FFT with zero-padding, the output is indexed from 0 to N-1. The "negative lags" wrap around to the end of the array.

So if we compute cross_corr(a, p) via ifft(FFT(a)*conj(FFT(p))) with N >= 3n-2 zero padding:
- The first n elements (indices 0 to n-1) correspond to lags 0 to n-1
- The last n-1 elements (indices N-n+1 to N-1) correspond to lags -(n-1) to -1

So cross_corr(a, p)[k] for k=0,...,n-1 gives us lags 0 to n-1 of cross_corr(a, p).
And cross_corr(p, a)[k] = cross_corr(a, p)[-k] means:
- cross_corr(p, a)[0] = cross_corr(a, p)[0]
- cross_corr(p, a)[1] = cross_corr(a, p)[-1]
- cross_corr(p, a)[k] = cross_corr(a, p)[-k]

In the FFT output, cross_corr(a, p)[-k] is at index N-k (circular).

So the correct gradient would be:
g[0] = cross_corr_a_p[0]
g[1] = cross_corr_a_p[N-1]
g[k] = cross_corr_a_p[N-k]

Or equivalently, we should compute cross_corr(p, a) directly:
g = ifft(conj(FFT(p)) * FFT(a))[:n]

Let me verify with my example:
a = [1, 2, 3], p = [0.1, 0.1, 0.3, 0.3, 0.2]
N = 8 (>= 3n-2 = 7)

g[0] = sum_n p[n]*a[n] = 0.1*1 + 0.1*2 + 0.3*3 = 1.2
g[1] = sum_n p[n+1]*a[n] = p[1]*a[0] + p[2]*a[1] + p[3]*a[2] = 0.1+0.6+0.9 = 1.6
