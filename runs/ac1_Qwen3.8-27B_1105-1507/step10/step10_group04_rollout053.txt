- Given a: solve min M s.t. A(a)g <= M*1, 1'g=1, g>=0. Call the solution g*(a).
- Given g: solve min M s.t. A(g)a <= M*1, 1'a=1, a>=0. Call the solution a*(g).

The mapping T(a) = a*(g*(a)) is a contraction (hopefully), and iterating T should converge.

At a fixed point a* = T(a*), we have a* = a*(g*(a*)) and g*(a*) = g*(a*) (trivially). The key property is that at the fixed point, a* minimizes max_k (a* * a*)[k] over the polytope {g >= 0, sum(g)=1} when a* is fixed in the first argument. But since a* = g*(a*), this means a* is a "best response" to itself.

By the theory of best-response dynamics, this converges to a Nash equilibrium of the two-player game where player 1 chooses a and player 2 chooses g, and the payoff is max_k (a*g)[k]. At the Nash equilibrium, neither player can improve by unilaterally changing their strategy.

For our problem, the Nash equilibrium (a*, g*) satisfies:
- a* = argmin_{a>=0, sum=1} max_k (g* * a)[k]
- g* = argmin_{g>=0, sum=1} max_k (a* * g)[k]

At this point, a* = g* (by symmetry of the game) and a* is a "self-best-response."

The objective at this point is f(a*) = max_k (a* * a*)[k].

This is a valid local minimum of the original problem (in the sense that no single coordinate update can improve it, since the LP gives the best possible single-block update).

Actually, you know what, let me just use the direct computation. For n=800, the O(n^2) gradient is 640K operations, which is nothing. Even for n=4000, it's 16M which is fine. And it's much simpler to get right.

```python
def compute_grad_direct(a, p):
    """grad[j] = 2 * sum_k p[k] * a[k-j] where a[x]=0 outside [0,n-1]."""
    n = len(a)
    grad = np.zeros(n)
    for j in range(n):
        # sum_k p[k] * a[k-j] where 0 <= k-j < n => j <= k <= j+n-1
        k_start = max(0, j)  # k >= 0
        k_end = min(2*n-2, j+n-1)  # k <= 2n-2 and k-j <= n-1
        if k_start <= k_end:
            grad[j] = 2.0 * np.dot(p[k_start:k_end+1], a[k_start-j:k_end-j+1])
    return grad
```

Wait, that's still O(n^2) in Python loops which would be slow. Let me vectorize it.

Actually, I can use the FFT approach and just be careful about the indexing. Let me test it:

```python
def compute_grad_fft(a, p):
    n = len(a)
    N = 1
    while N < 3 * n:
        N <<= 1
    A = fft(a, N)
    P = fft(p, N)
    corr = ifft(A * np.conj(P)).real
    # grad[0] = 2 * corr[0]
    # grad[j] = 2 * corr[N-j] for j=1,...,n-1
    grad = np.zeros(n)
    grad[0] = 2.0 * corr[0]
    if n > 1:
        grad[1:] = 2.0 * corr[N-n+1:N][::-1]
    return grad
```
