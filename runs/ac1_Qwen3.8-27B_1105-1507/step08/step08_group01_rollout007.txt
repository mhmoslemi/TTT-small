    Let me think about a different approach entirely: **Power iteration / Multiplicative Weights**

    The idea from multiplicative weight algorithms in game theory:
    
    1. Initialize `a` (e.g., uniform).
    2. Compute `conv = a*a`.
    3. Find `k* = argmax conv`.
    4. Update: `a_j <- a_j / (1 + η * a_{k*-j})` (or some variant)
    5. Renormalize.
    6. Repeat.

    This is like a no-regret algorithm where "nature" picks the worst peak `k*` and the player (us) updates to minimize future regret.

    Actually, a cleaner version:

    **Algorithm: Iterative Peak Reduction (IPR)**
    1. Normalize `a` to sum 1.
    2. Compute `conv = a*a`.
    3. For the top `p` peaks `k_1, ..., k_p`:
       - For each peak `k_i`, compute the "pressure" on coordinate `j`: `p_j = a_{k_i - j}`
       - Update: `a_j <- a_j * (1 - η * sum_i w_i * p_j / max_p)`
       - Clip to non-negative, renormalize.
    4. Repeat with decreasing `η`.

    This is essentially a multiplicative version of projected subgradient descent.

    Let me also think about **proximal gradient** with a non-Euclidean proximal term (like KL divergence for the simplex). This gives:
    
    `a_j^{new} ∝ a_j * exp(-η * grad_j)`
    
    where `grad_j = 2 * sum_{k in active} w_k * a_{k-j}`.

    This is the mirror descent update, which is natural for the simplex constraint.
