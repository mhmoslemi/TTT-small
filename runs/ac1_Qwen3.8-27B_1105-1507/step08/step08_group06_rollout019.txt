Let me also think about **what makes a good active set**. The active peaks should be:
- At the max of the convolution
- "Well-spread" (not all clustered together)
- The corresponding dual multipliers should be non-negative

For the quadratic QP with active set A:
min a^T Q_A a s.t. sum(a) = 1, a >= 0
where Q_A[i,j] = 1/|A| if i+j in A, else 0

The KKT conditions give: for i in support(a):
(2 Q_A a)_i = λ (constant)

This means: for i in support(a):
(2/|A|) * sum_j a[j] * 1_{i+j in A} = λ

This is a system of |S| equations in |S| unknowns (where S is the support), plus the normalization sum(a_S) = 1.

I can solve this linear system directly! The matrix is:
M[i,j] = (2/|A|) * 1_{i+j in A} for i, j in S

And M @ a_S = λ * 1, with sum(a_S) = 1.

This is (|S| + 1) equations in (|S| + 1) unknowns (a_S and λ).

If the solution has a_S >= 0, it's the QP solution. If some a_i = 0, we remove i from S and re-solve.

This is the **active set method for QP**! It's a finite algorithm (at most n iterations).

```python
def solve_qp_active_set(a_init, active_set, n):
    """
    Solve min a^T Q_A a s.t. sum(a) = 1, a >= 0
    using the active set method.
    
    Q_A[i,j] = 1/|A| if i+j in A, else 0
    """
    A_set = set(int(k) for k in active_set)
    S = set(range(n))  # Start with all variables active
    
    for iteration in range(n * 2):  # At most 2n iterations
        # Solve the linear system on current active set S
        S_list = sorted(S)
        m = len(S_list)
        if m == 0:
            break
        
        # Build the (m+1) x (m+1) system:
        # M[i,j] = (2/|A|) * 1_{(S_list[i]+S_list[j]) in A}
        # last row: 1^T a = 1
        # last col: M @ a = λ * 1
        
        M = np.zeros((m + 1, m + 1))
        A_size = len(A_set)
        for ii in range(m):
            for jj in range(m):
                if (S_list[ii] + S_list[jj]) in A_set:
                    M[ii, jj] += 2.0 / A_size
            M[ii, m] = 1.0
            M[m, ii] = 1.0
        M[m, m] = 0.0
        
        rhs = np.zeros(m + 1)
        rhs[m] = 1.0
        
        try:
            sol = np.linalg.solve(M, rhs)
        except np.linalg.LinAlgError:
            try:
                sol = np.linalg.lstsq(M, rhs, rcond=None)[0]
            except:
                break
        
        a_S = sol[:m]
        lambda_val = sol[m]
        
        # Check non-negativity
        if np.all(a_S >= -1e-10):
            # Check if we can add any variable
            # For j not in S: (2 Q_A a)_j should be >= λ for feasibility
            # (2 Q_A a)_j = (2/|A|) * sum_{i in S} a_S[i] * 1_{(i+j) in A}
            can_add = False
            for j in range(n):
                if j not in S:
                    val = 0.0
                    for i in S_list:
                        if (i + j) in A_set:
                            val += 2.0 * a_S[S_list.index(i)] / A_size
                    if val < lambda_val - 1e-10:
                        # This variable should be in S
                        S.add(j)
                        can_add = True
                        break
            
            if not can_add:
                # Optimal!
                a = np.zeros(n)
                for idx, si in enumerate(S_list):
                    a[si] = max(0, a_S[idx])
                s = float(np.sum(a))
                if s > 1e-10:
                    a /= s
                return a
        
        # If some a_S is negative, remove the most negative
        min_idx = int(np.argmin(a_S))
        # Remove S_list[min_idx] from S, but we need to be careful
        # Actually, we should remove it and re-solve
        S.remove(S_list[min_idx])
    
    # Fallback: return the last feasible solution or the initial
    return a_init
```

Wait, this is O(n^2) per iteration (checking all j not in S), and the matrix build is O(m^2). For n=800, this might be slow if the active set is large.

But in practice, the active set A should be relatively small (maybe 20-100 peaks), and the support S should also be relatively small (maybe 100-300 variables). So the matrix sizes are manageable.

Let me optimize the inner loop:

For the check "can we add j to S":
(2/|A|) * sum_{i in S, i+j in A} a[i] < λ

I can precompute: for each j, which i in S have (i+j) in A.
This is: i in S and i in (A - j) = S ∩ (A - j)

If A is small (say |A| = 30), then for each j, I check at most |A| values of i.
Total: n * |A| = 800 * 30 = 24000 per iteration. Fine.

For the matrix build: M[i,j] = (2/|A|) * 1_{(S_i + S_j) in A}
This is O(|S|^2) but each entry is O(1) (just a set lookup).
For |S| = 300, that's 90000 entries. Fine.

Solving the linear system: O(|S|^3) = 300^3 = 27 million. This might be slow if done many times.

**Key insight**: The LP alternation is essentially a **block coordinate descent** on the pair (a, g) where:
- Given a, optimize g: min M s.t. conv(a,g) <= M, sum(g)=1, g>=0
- Given g, set a = g (or blend)

**Faster alternative**: Instead of solving the LP exactly, use **one step of projected gradient** on the LP. This gives a direction that's approximately correct but much faster to compute.

The LP: min M s.t. A@g <= M * 1, sum(g) = 1, g >= 0

The "surrogate" objective (from the dual perspective) is:
max_g sum_k min(M, (A@g)_k) ... not quite right.

Let me use a different approach. The **Dantzig-Wolfe** or **Benders decomposition** idea:

The LP dual is: max 1^T y s.t. B^T @ y <= 1, y >= 0
where B is the convolution matrix (2n-1 x n), so B^T is n x (2n-1).

B^T @ y = [sum_k y_k * a[k-j] for j = 0, ..., n-1]

This is the cross-correlation of y with a (reversed)! So I can evaluate the dual constraints via FFT.

I can solve the dual LP with a **cutting plane** or **column generation** method:
1. Start with a small set of dual constraints
2. Solve the restricted dual
3. Find the most violated constraint
4. Add it
5. Repeat

Let me also try a completely different approach: **direct search on the active set**.

The idea:
1. Start with some active set A (subsets of {0, ..., 2n-2})
2. Solve the QP: min a^T Q_A a s.t. sum(a)=1, a>=0
3. Check if the solution is "valid": conv(a,a) has its max at the active peaks (not elsewhere)
4. If valid, we have a local optimum
5. If not valid, add the new peak to A and re-solve
6. Randomly perturb A to explore different local optima

This is essentially the **Dantzig's selection rule** or **active set method** for the original problem.

The key advantage over LP alternation: it directly solves the QP for a given active set, which gives the exact best solution for that active set. No need for iterative blending.

        return a

```python
def solve_qp_for_active_set(a_init, active_set, n):
    """
    Solve min (1/|A|) sum_{k in A} (a*a)[k] s.t. sum(a)=1, a>=0
    using active set method on the QP.
    """
    A_set = frozenset(int(k) for k in active_set)
    A_size = len(A_set)
    
    # Start with the support of a_init
    support = set(np.where(a_init > 1e-10)[0])
    if len(support) == 0:
        support = set(range(n))
    
    a = a_init.copy()
    
    for iter in range(n * 3):  # Max iterations
        S_list = sorted(support)
        m = len(S_list)
        if m == 0:
            break
        if m > n:
            S_list = list(range(n))
            m = n
        
        # Build the KKT system:
        # For i in S: sum_j a[j] * (2/|A|) * 1_{(i+j) in A} = λ
        # sum_{j in S} a[j] = 1
        # 
        # Matrix M (m+1) x (m+1):
        # M[i,j] = (2/|A|) * 1_{(S_list[i]+S_list[j]) in A} for i,j < m
        # M[i,m] = 1, M[m,i] = 1, M[m,m] = 0
        # rhs = [0, ..., 0, 1]
        
        M = np.zeros((m + 1, m + 1))
        for ii in range(m):
            ii_val = S_list[ii]
            for jj in range(ii, m):  # Symmetric
                jj_val = S_list[jj]
                if (ii_val + jj_val) in A_set:
                    M[ii, jj] = 2.0 / A_size
                    if ii != jj:
                        M[jj, ii] = 2.0 / A_size
            M[ii, m] = 1.0
            M[m, ii]
