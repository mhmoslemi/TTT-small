def spectral_flatten(a, num_steps=10, alpha=0.1):

    Try to flatten the spectrum to reduce peak autocorrelation.
    The idea: if we can make |A(f)|^2 more uniform in frequency,
    the autocorrelation (IDFT of |A(f)|^2) will be flatter in time.
    """
    n = len(a)
    a = a.copy()
    N = 2 * n  # Use a larger FFT for more frequency resolution
    
    for step in range(num_steps):
        A = fft(a, N)

        # We want to make |A(f)|^2 more uniform
        # Use a soft threshold: reduce peaks in |A|^2
        power = np.abs(A) ** 2
        avg_power = np.sum(power) / N
        
        # Soft compression: reduce high-power bins
        threshold = avg_power * 1.5
        compression = np.where(power > threshold, 
                              np.sqrt(power / threshold),  # reduce magnitude
                              1.0)

        a_new = a_new / s

    return a

This is essentially the "Golay complementary sequence" problem or "low PAPR" sequence design, adapted to real non-negative sequences.

If a has DFT A(f), then the autocorrelation of a (which is conv(a, reverse(a)) for proper autocorrelation, but conv(a,a) is slightly different) is related to |A(f)|^2.

So conv(a,a) = ifft(A(f)^2) where A(f) = DFT(a).

To minimize the peak of ifft(A(f)^2), we want A(f)^2 to be as "flat" as possible (close to a constant) in the frequency domain. But A(f) is the DFT of a non-negative sequence, so it has constraints.

This is a different optimization problem than the standard PAPR problem. In standard PAPR, we minimize the peak of ifft(|A(f)|^2), which is the autocorrelation. Here we minimize the peak of ifft(A(f)^2), which is the "pseudo-autocorrelation" or "chirp autocorrelation."

Interesting. So the spectral approach should target making A(f)^2 flat, not |A(f)|^2 flat.

def solve_lp_minpeak(a):
    n = len(a)
    a_norm = a / float(np.sum(a))
    
    # Build constraint matrix
    # conv(a_norm, g)[k] = sum_j a_norm[j] * g[k-j] for valid k,j
    # We want: for all k, sum_j a_norm[j] * g[k-j] <= M
    # subject to g >= 0, sum(g) = 1
    
    # The constraint matrix B has B[k,j] = a_norm[j] if 0 <= k-j < n, else 0
    # i.e., B[k,j] = a_norm[j] * 1{0 <= k-j < n}
    
    # This is a (2n-1) x n matrix
    # Let's build it sparsely using the structure
    # B[k,j] = a_norm[j] for k in [j, j+n-1]
    
    # For cvxpy, we can build this as a dense matrix for n <= 2000
    B = np.zeros((2*n-1, n))
    for j in range(n):
        B[j:j+n, j] = a_norm
    
    g = cp.Variable(n, nonneg=True)
    M = cp.Variable()
    constraints = [B @ g <= M, cp.sum(g) == 1]
    prob = cp.Problem(cp.Minimize(M), constraints)
    
    for solver in [cp.MOSEK, cp.CLARABEL, cp.ECOS, cp.SCS, cp.PDLP]:
        try:
            prob.solve(solver=solver)
            if g.value is not None and prob.status in ('optimal', 'optimal_inaccurate'):
                g_val = np.maximum(g.value, 0)
                s = float(np.sum(g_val))
                if s > 1e-10:
                    return g_val / s, float(M.value)
        except Exception:
            continue
    return None, None

The objective `2*n*max(conv(a,a))/(sum(a))^2` is scale-invariant, so we can fix `sum(a) = 1` and minimize `2*n*max(conv(a,a))`. The constraint set is the simplex.

Let me stick with the LP approach but make it more effective:

**Key improvement idea**: Instead of blending `a` with `g_lp` at a fixed rate, solve for the optimal blend analytically.

Given current `a` and LP solution `g`, we want to find `t* = argmin_t f((1-t)*a + t*g)` where `f(x) = max_k (x*x)[k]`.

Since `f` is piecewise quadratic, we can:
1. For each k, compute `f_k(t) = ((1-t)*a + t*g * ((1-t)*a + t*g))[k]` (a quadratic in t)
2. The max `f(t) = max_k f_k(t)` is a piecewise quadratic function
3. Find the minimum of this piecewise quadratic

This is a 1D optimization that can be done efficiently!

Let me implement this:

This is a good improvement! The ternary search with 50 iterations gives very precise t values, and each evaluation is O(n log n) via FFT. So finding the optimal t costs 50 * O(n log n) ≈ 50 * 800 * 10 = 400000 operations, which is fast.

But wait, is f(t) = max_k f_k(t) unimodal? Not necessarily. Each f_k(t) is a parabola (could be opening up or down depending on the sign of quad[k]). The max of parabolas is not necessarily unimodal.

However, in practice, near the optimum, the function should be fairly smooth and the ternary search should work well. If it doesn't, we can fall back to a grid search.

```python
def find_best_t(a, g, n_grid=100):
    # Grid search
    ts = np.linspace(0, 1, n_grid)
    best_t = 0
    best_val = np.inf
    for t in ts:
        x = np.maximum((1-t)*a + t*g, 0)
        s = x.sum()
        if s < 1e-10:
            continue
        x = x / s
        val = np.max(compute_conv(x))
        if val < best_val:
            best_val = val
            best_t = t
    
    # Local refinement around best_t
    lo = max(0, best_t - 2/n_grid)
    hi = min(1, best_t + 2/n_grid)
    for _ in range(30):
        m1 = lo + (hi-lo)/3
        m2 = hi - (hi-lo)/3
        x1 = np.maximum((1-m1)*a + m1*g, 0)
        x1 = x1 / x1.sum()
        v1 = np.max(compute_conv(x1))
        x2 = np.maximum((1-m2)*a + m2*g, 0)
        x2 = x2 / x2.sum()
        v2 = np.max(compute_conv(x2))
        if v1 < v2:
            hi = m2
        else:
            lo = m1
    
    t_star = (lo + hi) / 2
    return t_star
```
