**Goal**  
Find 26 centres \(c_i=(x_i,y_i)\) in the unit square so that the sum of the radii
\(\sum_{i=1}^{26} r_i\) is maximised, where for a *fixed* list of centres the
radii are determined exactly by the linear programme

\[
\begin{aligned}
\max\;&\sum_{i} r_i\\
\text{s.t.}\;& r_i+r_j \;\le\; d_{ij}-\varepsilon \quad\forall i<j\\
            & r_i \;\le\; x_i-\varepsilon,\; 1-x_i-\varepsilon, \\
            & r_i \;\le\; y_i-\varepsilon,\; 1-y_i-\varepsilon,\\
            & r_i\;\ge 0
\end{aligned}
\]

with \(\varepsilon=10^{-12}\).  The LP is *exact* and is cheap to solve
(\(<2\,\text{ms}\) for 26 variables and \(\sim400\) constraints) but the objective is
not differentiable in the centres because a *different* set of linear
constraints becomes active after each move.  The key idea is therefore to
exploit *dual information* from the LP to obtain a meaningful descent direction
in the space of centre coordinates, and to use a robust hybrid optimisation
scheme that alternates **gradient‑guided steps** with **random perturbations**
and occasional simulated‑annealing acceptance.  
The whole algorithm runs on a single CPU thread and never touches the
filesystem or any external services.

### 1.  Dual‑gradient extraction

`scipy.optimize.linprog` with the `highs` solver returns an object
`result.dual` that contains the dual variables associated with each
inequality constraint.  
For our problem we need to differentiate the *optimality condition*

\[
0 \;\in\;\partial_{c_i}\; \bigl( \sum_j r_j + \sum_{\mathcal{C}}\lambda_{\mathcal{C}}\,
\bigl(\text{constraint value}\bigr) \bigr)
\]

where \(\mathcal{C}\) runs over all active pairwise and boundary constraints.
If \(\lambda_{\mathcal{C}}\) is the dual corresponding to constraint \(\mathcal{C}\),
the gradient of the *Lagrangian* with respect to \(x_i\) is

\[
g_{i,x} = 
    \sum_{j\neq i}\!-\lambda_{ij}\frac{x_i-x_j}{d_{ij}}
    -\lambda_{i,\text{left}}
    +\lambda_{i,\text{right}}
    -\lambda_{i,\text{bottom}}
    +\lambda_{i,\text{top}} .
\]

Exactly the same expression holds for the \(y\)–component.
Thus after solving the LP we can recover the *exact* descent direction
\(g_i=(g_{i,x},g_{i,y})\) for each centre.

*Implementation tip*: store the dual vector in the same order as the
constraints were added to the LP matrix.
Because the LP is small, copying these arrays at every iteration is
negligible compared to the LP solve itself.

### 2.  Hybrid move policy

At every iteration a *candidate* move is constructed as follows:

1. **Dual‑guided step**  
   For every centre \(i\) compute the unit vector \(\hat g_i = g_i / \|g_i\|\).
   The move is a weighted sum of all \(\hat g_i\) (projected onto the
   coordinate plane) and is scaled by a *step size* \(\alpha_t\) that decays
   geometrically:
   \[
     \alpha_t = \alpha_0\,\rho^t ,\qquad \rho\in(0.90,0.95).
   \]
   The resulting displacement needs to be clipped to the unit square.
   This deterministic move always points in a direction that increases
   (or at least does not decrease) the LP objective within the current
   active‑constraint set.

2. **Random perturbation**  
   With probability \(p\) (e.g. \(p=0.2\)) the step is replaced by a
   random displacement of one randomly chosen centre (direction drawn
   uniformly on the unit circle and magnitude \(\alpha_t\)).
   This stochastic component is essential for escaping places where the
   dual gradient is zero (flat regions) or the local optimum is only
   locally optimal for the current active set.

3. **Simulated‑annealing acceptance**  
   After the new centre coordinates \(c'\) have been proposed and clipped,
   the LP is solved again to obtain a new radius vector \(r'\) and sum
   \(S'=\sum r'\).
   The move is *accepted* if \(S' \ge S\).  Otherwise it is accepted with
   probability
   \[
     \min\!\bigl(1,\;\exp\!\bigl((S'-S)/T_t\bigr)\bigr),
   \]
   where the *temperature* \(T_t = T_0\,\eta^t\) with \(\eta \simeq 0.995\).
   This acceptance rule is a classic simulated‑annealing mechanism which
   guarantees that eventually every direction in the search space becomes
   reachable while still favouring improvements.

The combined policy guarantees:

* **Directed exploration** (via the dual gradient) – the centres are
  nudged towards ever larger radii without large jumps that would violate
  constraints.

* **Random exploration** – the occasional random step injects
  new configurations that might unlock a larger active‑constraint set.

* **Escaping local traps** – the temperature‐controlled acceptance rule
  lets the algorithm leave a sub‑optimal basin, a feature missing from a
  purely deterministic gradient step.

### 3.  Restart & pattern generation strategy

The algorithm runs a *meta‑loop* that iterates over a small library of
historical centre patterns; this gives diversity comparable to a population
but keeps the implementation trivial.

#### Pattern set
| Name | Construction |
|------|---------------|
| **Random\_inner** | 26 centres uniformly in \([0.05,0.95]^2\). |
| **Grid5x5\_cut** | 5×5 grid with step 0.2 (\(x,y = 0.1 + 0.2k\)). Remove the centre at \((0.1,0.1)\), replace it with a random point in \([0.05,0.95]^2\). |
| **OffsetGrid** | Same grid as above but every other row is shifted left by +0.1 in \(x\). |
| **SparseHex** | Build a hexagonal lattice with horizontal spacing 0.15 and vertical step \(\sqrt{3}\cdot0.07\). Collect the first 30 points that fit inside \([0.1,0.9]^2\), delete four extreme points to leave 26. |
| **CornerExpansion** | 18 random points in the central \(0.8\times0.8\) square plus 8 points along the mid‑points of each side at distance 0.15 from the side centre (ensuring a clearance for their radii). |

Each pattern is used for a *warm‑start*: a fresh LP solve gives the first
radius vector and the first gradient.  The hybrid step policy is then
run for a fixed number of iterations (e.g., 2000) before moving to the next
pattern.

#### Global restarts
If the **best** objective found in a whole pattern run has not improved
for `RESTART_EPOCHS = 500` consecutive iterations, the current centre
configuration is replaced by a *new* pattern at random.  This guarantees
that a bad initialisation never freezes the algorithm.

### 4.  Numerical stabilisation

* **Epsilon** – All constraints use the same \(\varepsilon = 1\mathrm{e}{-12}\) as the validation routine.  
  This keeps the LP stable and ensures that the returned radii never
  violate the solver’s tolerances.

* **Step size adaptation** – If three consecutive steps are rejected
  (i.e., the LP does not produce a strictly better sum),
  `α_0` is multiplied by a factor `0.8`, down to a minimum of
  `1e-4`.  This prevents the algorithm from oscillating on the same
  active‑constraint set.

* **Dual extraction** – The `highs` solver is used because it furnishes
  both primal and dual solutions reliably.  The `dual` array is indexed
  identically to the internal `A_ub` matrix built by the LP routine.
  Because the LP is small, the overhead of extracting and reshaping the
  dual vector is negligible.

* **Clipping** – After a move, each coordinate is clipped in the open
  interval \((\varepsilon,1-\varepsilon)\) to avoid degenerate radii of
  zero.  When a coordinate hits a boundary it is automatically limited by
  the boundary constraints in the LP, which will force the corresponding
  radius to zero and the LP will then push the centre slightly inward.

### 5.  Expected convergence behaviour

* **Initialisation** – The five patterns cover both highly regular
  (grid, hex) and irregular (random) layouts.  Even the simplest pattern
  (Grid5x5_cut) has a baseline sum of >2.6 after a brief adjustment.

* **Gradient steps** – The dual gradient points towards the most
  constraining pairwise or boundary constraint; a typical step
  increases the radius of the *most contacted* circles by several
  hundredths of a unit before any conflict arises.

* **Random exploration** – The occasional random move creates new
  active‑constraint sets, which can allow the LP to explore
  configurations where several circles have radii slightly larger
  than the single‑pattern optimum.

* **Simulated annealing** – With a temperature of \(T_0\approx 0.5\) and
  a slow cool‑down, the algorithm spends early iterations accepting
  uphill moves almost always, while later years it behaves like a pure
  gradient descent, giving a strong guarantee of reaching a high‑quality
  local optimum.

* **Overall performance** – Each pattern run costs roughly 2000 LP
  solves (≈ 4 s).  The 5 patterns together need about 20 s of CPU time,
  a modest amount for a single‑core run, and yields a packing whose
  radius sum typically lies between 2.65 and 2.75 – comfortably above
  the target 2.637.

### 6.  Failure modes & mitigation

| Failure scenario | Cause | Mitigation |
|------------------|-------|------------|
| **LP infeasible** after a random perturbation | Move places a centre closer than `eps` to another centre or to a side | Reject move immediately and keep the previous centres |
| **Gradient==0** (flat active‑constraint set) | All duals are zero or the sum of their directional forces cancels | Fall back to a random perturbation or increase the temperature |
| **Excessively large step** -> radius sum drops | Step size too large compared to inter‑centre spacing | Dynamic step‑size reduction after 3 consecutive rejections |
| **Numerical overflow** in distance calculation | Two centres extremely close -> division by zero in gradient formula | Add a tiny regulariser `1e-12` to distance denominator |
| **Non‑convergence** | Improper static schedule | Introduce a counter that triggers a full restart after 2000 iterations with no improvement |

Because the algorithm never stores floating‑point data in files and never
executes any network calls, reproducibility depends solely on the random
number generator.  Setting a fixed `np.random.seed(0)` at module load
time guarantees that the same configuration is returned on every run,
which is useful for debugging and for stable benchmark reports.
