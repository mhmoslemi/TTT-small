**Objective**  
Design an algorithm that searches for a packing of 26 circles in the unit square whose sum of radii exceeds 2.637.  The objective is maximised by a linear program once the centre positions are fixed.  Consequently the optimisation problem is a *parameter* optimisation over the centres, with the radii and their total computed exactly by a linear program.  The key is to give the optimisation a rich enough set of initial centre configurations and a robust local search that can escape local optima.

---

### 1.  Mathematical background

* **Boundary constraints** – for circle \(i\) with radius \(r_i\) and centre \((x_i,y_i)\)  
  \(0 \le r_i \le \min(x_i,\,1-x_i,\,y_i,\,1-y_i)\).

* **Non‑overlap constraints** – for every pair \(i\neq j\)  
  \(r_i+r_j \le d_{ij}\), where \(d_{ij} = \sqrt{(x_i-x_j)^2+(y_i-y_j)^2}\).

* **Linear programme** – with variables \(r_i\) (all non‑negative).  
  Objective: maximise \(\sum_i r_i\).  
  The constraints are linear, so the problem is a standard LP that can be solved by `scipy.optimize.linprog` in a few milliseconds for 26 variables and \(\approx 400\) constraints.

**Important numerical note** – the puzzle’s validation code subtracts a tiny amount \(10^{-12}\) from every upper bound.  Therefore all optimal radii are strictly smaller than the geometric limit; we must respect these tolerances in every calculation.

* **Simulated annealing acceptance** gives the search a chance to move uphill (improve radii sum) and, with small probability, downhill (to escape a local optimum).

* **Temperature (`T`)** decays slower than step size so that early iterations are more permissive.  
* **Global restarts** keep the algorithm away from stagnation.

### 3.  Linear programme construction

For a centre array `c` of shape `(26,2)`:

1. Compute pairwise Euclidean distances once (fast with broadcasting).  
2. Build constraint matrix `A_ub` and vector `b_ub`:
   * For each unordered pair `(i,j)` add the row `[0,…,1,…,1,…,0]` with the bound `d_ij - EPS`.  
   * For each circle add four boundary rows:  
     `r_i <= x_i - EPS`, `r_i <= 1 - x_i - EPS`,  
     `r_i <= y_i - EPS`, `r_i <= 1 - y_i - EPS`.  
3. Use `c = -np.ones(26)` as objective vector (maximisation).  
4. Call `scipy.optimize.linprog` with `highs` method; extract solution `x` (the radii) and compute `sum(x)`.

All arithmetic uses double precision; the tiny `EPS=1e‑12` guarantees that the validation will treat touching as non‑overlap.

### 5.  Local move proposal

```
def propose_move(centers, step):
    idx   = np.random.randint(26)
    dir   = np.random.randn(2)
    dir   /= np.linalg.norm(dir)          # unit direction
    Δ     = dir * step
    return idx, Δ
```

After clipping, the new position is passed to the LP.  If the LP reports an infeasible problem (which can happen if the new centre is too close to another), the move is automatically rejected and the algorithm continues with the next iteration.

### 7.  Global restart strategy

If the best sum does not improve for `MAX_NO_IMPROV` consecutive iterations, the algorithm discards the current centre set and re‑initialises it using a randomly chosen pattern from §4.  This guarantees that a single bad start does not kill the whole optimisation.
