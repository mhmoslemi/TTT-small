**Goal**  
Pack 26 non‑overlapping circles inside the unit square \([0,1]^2\) such that the objective  
\[
S=\sum_{i=1}^{26} r_i
\]
is maximised.  
All centres \(c_i=(x_i,y_i)\) and radii \(r_i\ge0\) must satisfy

* Boundary constraints: \(0\le x_i-r_i,\;x_i+r_i\le1\) and \(0\le y_i-r_i,\;y_i+r_i\le1\).
* Non‑overlap: \(\|c_i-c_j\|\ge r_i+r_j\;\;\forall i<j\).

The problem is a non‑convex quadratic inequality program.  
We reduce it to a *two‑stage* optimisation:

1. **Fix the 52 position variables, solve a linear programme (LP) to obtain the maximum admissible radii.**  
   For fixed \(c_i\) the constraints become linear in \(r_i\):
   \[
   r_i+r_j \le d_{ij},\qquad r_i \le B_i,
   \]
   where \(d_{ij}=\|c_i-c_j\|\) and \(B_i=\min\{x_i,1-x_i,y_i,1-y_i\}\).  
   The LP has 26 variables, 26 upper‑bound constraints (one per circle) and
   \(\binom{26}{2}=325\) pairwise constraints.  
   The LP is inexpensive to solve (few µs with the modern
   `highs` backend of `scipy.optimize.linprog`).

2. **Search over the 52‑dimensional centre space** using a stochastic global optimiser that receives the LP objective value for any proposed layout.  
   The PT of the search is the *sum of radii* given by the LP.

### 1. Initial seed geometry

A good starting point is a low‑density hexagonal lattice because it places circles far apart, giving the LP leeway to raise radii close to the boundary limits.

* Build 23 centres on a hexagonal grid:
  - 5 rows. Rows 0, 2, 4 contain 5 points; rows 1 and 3 contain 4 points.
  - Horizontal spacing \(2s\), vertical spacing \(\sqrt3\,s\).  
    The largest \(s\) that keeps all points in \([0,1]^2\) is \(s=0.099\) (just below 0.1).
  - Coordinates: for row \(i\) (0‑based) and column \(j\)
    \[
    \begin{array}{ll}
    y_i = s + i\,\sqrt3\,s, & \\
    x_{i,j} = s + \bigl(j + (i \bmod 2)\bigr)\,2s. &
    \end{array}
    \]

* Add three side‑midpoints that sit on distinct sides of the square:
  \[
  (0.5,\,0.05),\;(0.95,\,0.5),\;(0.05,\,0.5).
  \]
  These can reach radii up to 0.05–0.1 depending on neighbor distances,

The LP run on this 26‑point set yields a moderate sum (\(\approx 2.4\)–\(2.5\)),

### 2. Linear‑programme routine (function `solve_radii(centres)`)

1. Compute \(B_i\) for every centre \(c_i\).  
2. Compute all pairwise distances \(d_{ij}\).  
3. Set up the LP:
   * Variables: \(r_i\), \(i=1,\dots,26\).  
   * Constraints:
     - \(0 \le r_i \le B_i\).
     - \(r_i + r_j \le d_{ij}\) for all \(i<j\).
   * Objective: maximise \(\sum r_i\).
4. Solve with `highs` LP solver.  
5. Return the radii vector and the objective value \(S\).

If the LP fails (no feasible solution), treat \(S=-\infty\) so the
proposed layout is rejected by the optimiser.

---------------------------------------------------------------------

### 3. Simulated Annealing over centres

The SA algorithm explores the 52‑dimensional configuration space
while always keeping the radii optimal (via the LP).

**State** – a vector of 52 coordinates \((x_1,y_1,\dots,x_{26},y_{26})\).

**Temperature schedule**  
* \(T_0 = 0.1\) (allows large exploratory moves).  
* Cool geometrically: \(T \gets 0.9999\,T\) after every iteration.  
* Stop when \(T < 10^{-6}\) or after a fixed number of iterations (≈ 20 000).

**Neighbour generation**  
Select a random circle \(i\).  
Propose displacement
\[
(x_i',y_i') = (x_i,y_i) + \mathcal N\!\left(0,\;\sigma^2\right),
\quad \sigma = \tfrac{T}{2}.
\]
Clip \((x_i',y_i')\) to \([0,1]^2\).

**Quick infeasibility filter**  
If \(\min_{j\neq i}\|(x_i',y_i')-(x_j,y_j)\| < \epsilon\) (take \(\epsilon=10^{-4}\)),
discard the move (LP would be infeasible).

**Evaluation**  
Call the LP routine with the updated centre set; obtain \(S_{\text{new}}\).

**Acceptance**  
* If \(S_{\text{new}} > S_{\text{curr}}\) accept.  
* Else accept with probability
  \[
  \min\!\bigl(1,\;\exp((S_{\text{new}}-S_{\text{curr}})/T)\bigr).
  \]
Track the best state seen so far.

---------------------------------------------------------------------

### 4. Deterministic polishing (finite‑difference hill‑climb)

SA finishes with a near‑optimal geometry but often leaves a tiny amount of slack:

1. For each circle \(i\) in turn, evaluate the objective after moving its centre by \(\pm\delta\) in each coordinate separately (\(\delta = 10^{-4}\)).  
2. Choose the direction that yields the largest \(S\); if none improves \(S\) beyond \(10^{-6}\), keep the current position.  
3. Repeat until no improvement on any arm.

Because the LP is recomputed at each test, the gradient is exact.

---------------------------------------------------------------------

### 5. Implementation details

* **LP solver**: `scipy.optimize.linprog` with `method='highs'` – highly efficient for small‑to‑moderate problems.  
* **Precision**: set `tol=1e-12` when calling the LP to avoid numerical slop in constraint satisfaction.  
* **Radiuses**: initial guess for the LP can be \(r_i = B_i/2\); the LP will adjust this internally.  
* **Data structures**: store centres as a 26×2 NumPy array; the LP routine will pre‑compute distance matrices once per call to avoid redundant work.  
* **Parallelism**: not required; all operations are cheap and execute in < 0.5 s.
