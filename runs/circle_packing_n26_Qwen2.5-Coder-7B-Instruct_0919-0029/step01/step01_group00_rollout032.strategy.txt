The problem is to choose 26 circle centres \(c_i=(x_i,y_i)\) and radii \(r_i\ge0\) that maximise  
\(\displaystyle\sum_{i=1}^{26} r_i\) under the constraints

* \(c_i+r_i\) lies in the unit square,
* \(\|c_i-c_j\|\ge r_i+r_j\) for every \(i<j\).

For any fixed set of centres the optimisation over radii is a *linear program*
(see the helper `lp_optimum` in the starter code).  
Thus the *hard* part is the *geometric* optimisation over the 52 position
variables.  The goal of the strategy is to generate centre configurations that
produce a *large* feasible radius-sum, by exploring the high‑dimensional
search space with a combination of deterministic and stochastic
methods, and by exploiting geometric intuition about optimal packings.

### 1.  Why the current approach can be improved

* The random walk used in the starter code has a fixed step size that is
  gradually decreased.  The walk is *pure hill‑climbing* – it never
  accepts a worse move – so it easily becomes trapped in a local optimum.
* The step size is decreased through a simple exponential decay which is
  unrelated to the current objective.  As a result, once the walk reaches a
  shallow plateau it will keep stepping in essentially useless directions.
* The initial configurations are purely random; many are very poor (e.g.
  many circles already overlap at the start of the optimiser), which forces
  the LP to shrink almost all radii to zero.
* The algorithm does not make use of any *geometric knowledge*: it does not
  try to start from a dense “hexagonal” pattern, nor does it attempt to
  purposely inflate a few corner circles, which are usually the bottleneck
  in dense packings.

Because the LP is cheap (≈0.001–0.002 s per call on our test machine), the
bottleneck is purely the exploration of positions.  A search that can
escape local optima and starts from a reasonably good configuration
can hit the target sum (≈2.637) or even surpass it.

### 2.  High‑level optimisation plan

1. **Hybrid geometric initialization**  
   *Generate three families of starting positions:*  
   - pure random (as before).  
   - *Hexagonal grid* inside the unit square, scaled and shifted so that all
     circles are inside the square.  
   - *Packed‑border* configuration that places a few (2–4) large circles in
     the corners and distributes the rest on an inner lattice.  

   Each family gives a diverse set of starting points that are already
   relatively dense.

2. **Simulated Annealing (SA) on centres**  
   *Walk*:
   * pick a random circle \(i\),
   * propose a new centre \(c_i' = \text{clip}(c_i+\Delta,\;0,1)\) with
     \(\Delta\) drawn from a normal distribution \(N(0,\sigma^2)\).
   * Compute the LP (using `lp_optimum`) to obtain a new radius‑sum \(S'\).
   * Accept the move if \(S'\ge S_{\text{current}}\), otherwise accept it with
     probability \(\exp((S'-S_{\text{current}})/T)\).  
   The temperature \(T\) starts high (≈1.0) and slowly cools
   (e.g. \(T \leftarrow 0.999\,T\) each iteration).  The step standard
   deviation \(\sigma\) is adapted in a *cooling schedule*:
   \(\sigma = \sigma_0 \times T\) with \(\sigma_0=0.1\).  
   This keeps the exploration large in the beginning and tightens as the
   algorithm progresses.

3. **Restarts and best‑improvement**  
   Perform `NUM_RESTARTS` independent SA runs for each of the three
   families.  Keep the best centre configuration found so far.  
   The total number of objective evaluations is thus
   \(\text{NUM_RESTARTS}\times\text{NUM_ITER}\times3\).  
   With ~1 000 iterations per run this stays well‑below the 1 CPU time
   limit (~30 s on a typical laptop).

4. **Final LP refinement**  
   After the SA terminates, run `lp_optimum` one last time on the best
   centre set to obtain the radii.  These radii are guaranteed to be
   optimal for the fixed positions – the LP solver already implements an
   optimality check, so no further tuning is required.

5. **Post‑processing sanity checks**  
   * Clipping of all centres to \([0,1]^2\) guarantees feasibility.  
   * The LP returns zero or very small radii only if the centres are
     mutually overlapping.  The annealing acceptance rule and
     temperature schedule make this situation unlikely.  
   * Use the `validate_packing` function (provided by the judge) after the
     construction to double‑check.  Any failure aborts the programme
     (as required by the prompt).

### 4.  Implementation details

1. **Data structures**  
   *centres*: 2‑D NumPy array of shape (26,2).  
   *ranges*: vectorised bounds for clipping.  
   All operations use vectorised NumPy to reduce Python overhead.

2. **LP helper (`lp_optimum`)**  
   Re‑use the starter implementation: build `A_ub` on the fly from the
   distance matrix of the current centres.  
   Since only the distances change, we can pre‑allocate the matrix
   shape and fill it row‑by‑row for each call.  
   The LP uses the `highs` method which is robust and fast.

3. **Annealing loop**  
   ```python
   for it in range(NUM_ITER):
       i = random integer in [0,25]
       delta = np.random.normal(scale=step, size=2)
       new_c = np.clip(centres[i] + delta, 0, 1)
       new_centres = centres.copy()
       new_centres[i] = new_c
       radii, S = lp_optimum(new_centres)
       if S > best_S or random.random() < exp((S-best_S)/temp):
           centres = new_centres
           best_S = S
       step *= STEP_DECAY
       temp *= TEMP_DECAY
   ```

4. **Initial configurations**  
   *Random*: `np.random.rand(26,2)` .  
   *Hexagonal*: compute grid spacing `s` so that `max(corners)-min(corners) <= 1`,
   shift to centre of the square.  
   *Border*: place 2–4 large circles in opposite corners (`r≈0.3`) and seed the
   rest uniformly in the remaining region.

5. **Choice of best solution**  
   Keep variables `global_best_centres` and `global_best_radii`.  
   After all restarts, run `lp_optimum` on `global_best_centres` once more to
   guarantee consistency.

6. **Safety checks**  
   After the final LP call compute `validate_packing` and raise if
   `not ok`.  This guarantees the function never returns a degenerate
   packing silently.

### 5.  Potential pitfalls and how the strategy mitigates them

| Pitfall | Mitigation |
|---------|------------|
| **Local optimum trapping** | SA with temperature allows uphill moves early; restart from varied starts. |
| **Very small radii due to poor initial positions** | Hexagonal/boundary starts are already dense; the LP can still “shrink” circles but the annealing will drive them outward. |
| **Numerical instability in LP** | `highs` solver is numerically robust; we keep `b_ub` values with a small epsilon to avoid 0‑length constraints. |
| **Excessive runtime** | Number of inner LP evaluations is controlled; warm‑start behaviour of `highs` (re‑using basis) gives speed‑ups. |
| **Incorrect boundary handling** | Centers are clipped to \([0,1]^2\) before the LP; LP constraints prevent circles from expanding beyond the boundary. |
