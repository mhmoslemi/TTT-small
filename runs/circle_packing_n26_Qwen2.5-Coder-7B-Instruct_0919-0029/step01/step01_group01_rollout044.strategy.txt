**Goal** – Find a configuration of 26 circle centres in the unit square that *maximises the total radius*, while keeping every circle inside the square and keeping all pairs non‑overlapping.  
The optimisation is a *bilevel* problem:  

*Upper‑level*: choose the 52 real variables (26 centres – 2 coordinates each).  
*Lower‑level*: for any fixed set of centres solve a linear program that gives the
maximum possible radii vector \(\mathbf r\) that satisfies all linear
inequalities  
\[
\begin{aligned}
r_i &\leq x_i ,\quad r_i \leq 1-x_i ,\quad r_i \leq y_i ,\quad r_i \leq 1-y_i ,\\
r_i+r_j &\leq \|\,c_i-c_j\,\| .
\end{aligned}
\]

Because the lower level is a linear program, the *value function*  
\(f(\mathbf c)=\max_{\mathbf r}\sum_i r_i\) is concave in \(\mathbf c\); hence local
optimisation methods that explore the centre space and re‑run the LP at each
step can acquire high‑quality solutions.

### 2.  Initialisation of centres  
The success of local search hinges on a good starting point.

1. **“Corner‑favourable” distribution**  
   Most of the total radius is obtained when a circle touches two or three
   sides of the square (e.g. a circle centred at \((r,r)\) can reach r≈0.29,
   whereas a circle in the interior is limited by inter‑circle distances).
    
   We sample each coordinate separately from a mixture  
   \[
   \text{PDF}(x) = 0.25\,\mathbf 1_{\{x\in[0,0.1]\}}+
                    0.25\,\mathbf 1_{\{x\in[0.9,1]\}}+
                    0.5\,\text{Uniform}(0,1).
   \]
   This puts roughly 25 % of the samples near the left/right edge, 25 %
   near the top/bottom edge, and the remainder uniformly distributed.
   The same mixture is used for the y‑coordinate.  
   The result is a set of 26 centres that are already biased towards
   producing relatively large radii.

2. **Grid‑seed variant**  
   As a safety net we also start from a *hexagonal grid* with 5 rows:
   rows contain 5, 4, 5, 4, 5 circles respectively (total 23).  
   The remaining 3 circles are placed in the centre of the three widest
   gaps.  The grid is scaled so that the first and last row touch the
   top/bottom borders (i.e. the corresponding y‑coordinates are
   \(r\) and \(1-r\)).  The radius \(r\) is chosen such that the horizontal
   spacing is \(2r\).  Exact values can be computed analytically or by a
   quick trial run of the LP; for the search it suffices to use a
   pre‑computed radius (≈0.12) that fits the screen.

We perform a *first‑pass* of the local search from the corner‑favourable
initialiser and a *second pass* from the grid‑seed (optional).  
If the latter produces a higher objective early, we keep it as the
current best.

### 3.  Local‑search framework

#### 3.1  Parameters

| Parameter | Recommended value | Rationale |
|-----------|-------------------|-----------|
| `num_starts` | 80 | Enough trials to escape local optima without exhausting the CPU. |
| `iterations_per_start` | 4000 | Balances depth of exploration versus runtime. |
| `initial_step` | 0.10 | Large enough to move substantial distances in the first few

| `decay_factor` | 0.995 | Mild cooling keeps the step size above `step_min` for a long

| `no_improve_limit` | 500 | Stop a start if 500 consecutive steps produce no

#### 3.2  Core loop

```
best_centres = None
best_radii   = None
best_sum     = -∞

for start in range(num_starts):
    centres = initialise_centres()       # mixture + grid‑seed mix
    step   = initial_step
    no_improve = 0
    
    for it in range(iterations_per_start):
        # 1. Pick a random circle
        i = rng.integers(26)

        # 2. Propose a random displacement
        delta = rng.normal(scale=step, size=2)                 # Gaussian move
        new_c = centres[i] + delta

        # 3.  Clip to the unit square
        new_c = np.clip(new_c, 0.0, 1.0)

        # 4.  Try full LP for the new configuration
        tmp_centres = centres.copy()
        tmp_centres[i] = new_c

        radii, sum_radii = lp_optimum(tmp_centres)

        # 5.  Accept the move if it improves the objective
        if sum_radii > best_sum:
            centres  = tmp_centres
            best_sum = sum_radii
            best_centres = centres.copy()
            best_radii   = radii.copy()
            no_improve   = 0
        else:
            no_improve += 1

        # 6.  Decrease step size
        step = max(step_min, step * decay_factor)

        # 7.  Early exit from a stuck start
        if no_improve >= no_improve_limit:
            break
```

**Why this works**

* The Gaussian jitter allows large, medium and tiny step sizes automatically
  as the `step` decays.  
* Clipping keeps all centres inside the unit square.  
* The LP is called after each proposal so every move is evaluated
  against the true objective, not a surrogate.  
* The “no‑improve” counter prevents spending hours in a flat basin
  where all proposals reduce the total radius.
