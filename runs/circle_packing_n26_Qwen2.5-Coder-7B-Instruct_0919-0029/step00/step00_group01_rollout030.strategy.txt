**1. Problem re‑formulation**  
For a fixed set of centres \(c_i=(x_i,y_i), i=1..26\) the maximal radii that satisfy  
* \(0\le r_i\le\min(x_i,1-x_i,y_i,1-y_i)\) (boundary) and  
* \(r_i+r_j\le d_{ij}=\lVert c_i-c_j\rVert_2\) (non–overlap),  

are obtained by a *linear programme* (LP).  
The LP objective \(\max \sum_i r_i\) is linear, so it can be solved in milliseconds.  
The key idea is to use this LP as an *oracle*: after we perturb the centres we query the LP to see what the best radii (and thus the total radius) become.  

**2. Deterministic gradient‑descent on centres**  
We treat the sum of LP radii, \(S(c)=\sum_i r_i(c)\), as a smooth (piecewise‑linear) function of the centre coordinates.  
We can compute a numerical gradient for \(S\) with respect to each centre by finite differences:

\[
\frac{\partial S}{\partial x_i}\approx\frac{S(c_i+\varepsilon e_x)-S(c_i-\varepsilon e_x)}{2\varepsilon},
\]
\[
\frac{\partial S}{\partial y_i}\approx\frac{S(c_i+\varepsilon e_y)-S(c_i-\varepsilon e_y)}{2\varepsilon},
\]
where \(e_x,e_y\) are unit vectors and \(\varepsilon\) is a small step (e.g., \(10^{-4}\)).  

This requires at most \(1+2\cdot 26=53\) LP evaluations for a full gradient.  

**3. Iterative algorithm**  

```
Initialize centres uniformly at random in [0,1]^2.
For iter = 1 … MAX_ITER:
    Solve LP for current centres → radii r_best, sum S.
    If S > best_S: record current centres as best.
    For each centre i:           # numerical gradient
        Shift x_i up by ε → solve LP → S_x_plus
        Shift x_i down by ε → solve LP → S_x_minus
        ∂S/∂x_i = (S_x_plus - S_x_minus)/(2 ε)
        Shift y_i up/down similarly for ∂S/∂y_i.
    Assemble gradient g_i = (∂S/∂x_i, ∂S/∂y_i).
    Choose step length α (e.g., 0.01).
    Update centre i := centre i + α * g_i, then clip to [0,1]^2.
    If relative improvement of S is < tol for many consecutive steps → break.
```

- **Step size schedule**: start with a moderate α, reduce it geometrically after a fixed number of sweeps (e.g. α ← 0.9 * α) to prevent overshooting once close to a local optimum.  
- **Stopping criterion**: either a maximum number of iterations (≈ 200) or when the best sum does not improve by more than \(10^{-5}\) for 20 consecutive sweeps.

*Run the above algorithm twice with different random initial centres (different RNG seeds).

This is a tiny “jiggle” that can cross shallow barriers.

This greedy augmentation tests whether merely enlarging an already large circle (while shrinking others automatically via LP) can boost the total sum.

**6. Numerical choices & robustness**  

- **LP tolerance**: use `highs` solver with default tolerances; the LP’s objective values are accurate to ~\(10^{-8}\), enough for gradient computation.  
- **Finite difference ε**: \(10^{-4}\) balances numerical noise against proximity to non‑differentiability.  
- **Step length α**: start at 0.01; reduce by 0.95 after each full sweep.  
- **Clip after each update**: to respect \([0,1]\) boundaries.  
- **Guard against infeasibility**: the LP always returns a feasible solution (all radii set to zero is feasible), so no need for additional penalties.
