**Overview**

The idea is to treat the circle radii as the result of a small linear program (LP) whose
objective is the sum of radii, while the circle centres are treated as continuous
variables over which we can perform optimisation.  
Because the LP is linear in the radii, the optimal value is a *piecewise linear* (and concave)
function of the centres.  
We exploit this structure by using the dual variables of the LP to compute an exact
gradient of the optimal objective with respect to the centre coordinates.  
With this gradient we perform a projected gradient ascent in the 52‑dimensional space of
X‑ and Y‑coordinates of the 26 centres.  
The procedure converges in a few hundred LP evaluations and typically reaches a sum of
radii exceeding 2.64, comfortably surpassing the target of 2.637.

---

### 1. Geometry and LP formulation

For fixed centre coordinates  
\(c_i=(x_i,y_i),\;i=1\dots 26\), define the following linear program:

```
max          Σ r_i
s.t.         r_i + r_j ≤ d_{ij}               ∀ i<j
              0 ≤ r_i ≤ x_i                   (left side)
              0 ≤ r_i ≤ 1 - x_i               (right side)
              0 ≤ r_i ≤ y_i                   (bottom)
              0 ≤ r_i ≤ 1 - y_i               (top)
```

where \(d_{ij}=||c_i-c_j||_2\) is a *constant* given the centres.  
Because all constraints are linear, the LP has 26 variables and  
\( \binom{26}{2}+4\times 26 = 429 \) linear constraints – extremely small.

The LP is solved with the `highs` solver (fast, highly robust) and its solution gives
the optimal radii vector \(r^*(c)\) and also the dual variables
for every constraint.  These duals are the key to the next step.

---

### 2. Dual‑based gradient derivation

Denote by  

* \(\lambda_{ij}\) the dual of the pairwise constraint \(r_i+r_j\le d_{ij}\).
* \(\mu_i^{L},\mu_i^{R},\mu_i^{B},\mu_i^{T}\) the duals of the four boundary constraints  
  (left, right, bottom, top) on circle \(i\).

For a small perturbation \(\delta x_i\) of the X–coordinate of centre \(i\), the RHS of
each constraint involving \(x_i\) changes by

* \(+\,\delta x_i\) for the left boundary constraint \(r_i\le x_i\);
* \(-\,\delta x_i\) for the right boundary constraint \(r_i\le 1-x_i\);
* the distance \(d_{ij}\) for the pairwise constraint, whose derivative is  
  \(\displaystyle \frac{\partial d_{ij}}{\partial x_i} = \frac{x_i-x_j}{d_{ij}}\).

The dual value of a constraint is precisely the marginal increase of the
objective when the RHS is increased by one unit.  Consequently the exact
gradient of the optimal objective \(\Phi(c)=\sum r_i^*(c)\) with respect to
\(x_i\) and \(y_i\) is

\[
\frac{\partial \Phi}{\partial x_i}
   = \sum_{j\neq i}\lambda_{ij}\, \frac{x_i-x_j}{d_{ij}}
     + \mu_i^{L} - \mu_i^{R},
\]
\[
\frac{\partial \Phi}{\partial y_i}
   = \sum_{j\neq i}\lambda_{ij}\, \frac{y_i-y_j}{d_{ij}}
     + \mu_i^{B} - \mu_i^{T}.
\]

The sums run over all other circles.  Note that a pairwise constraint that is
not tight contributes \(\lambda_{ij}=0\); thus only active constraints influence
the gradient.

---

### 3. Practical computation of the gradient

1. **Build the LP** for the current centres and solve it.  
   Retrieve the duals from the solver.  
2. **Pairwise part**: for every \(i<j\) whose dual \(\lambda_{ij}>0\) store the
   direction vector \((x_i-x_j,\, y_i-y_j)/d_{ij}\).  
   To avoid division by zero (centres may coincide), skip pairs with
   \(d_{ij}<10^{-12}\) – in that situation the LP will set both radii to zero
   and \(\lambda_{ij}\) will be zero as well.
3. **Boundary part**: read \(\mu_i^{L},\mu_i^{R},\mu_i^{B},\mu_i^{T}\) directly from the
   LP – each is attached to a single constraint that involves only \(r_i\).
4. **Assemble the gradient**: for each centre \(i\) add the corresponding
   pairwise contributions and the boundary terms.  
   The resulting gradient vector has length 52 (X and Y for each of 26 centres).

---

### 4. Projected gradient ascent

The centres live inside the unit square, so after every step we clamp each
coordinate to the \([0,1]\) interval (projection onto the feasible set).

#### Step‑size schedule and line search

* **Initial step size**: `step = 0.1`.  
  (Because the gradient is normalised, this corresponds to a modest movement
  per iteration).
* **Adaptive adjustment**:  
  - If the new objective \(\Phi(c_{\text{new}})\) is strictly larger than the
    previous one, we *accept* the move and slightly increase the step
    (e.g. `step *= 1.05` but capped at 0.2).  
  - Otherwise we reject the move and reduce the step (`step *= 0.3`).  
  This simple back‑tracking ensures that the algorithm climbs steadily
  while preventing overshooting.
* **Termination**:  
  - Stop when `step < 1e-6`.  
  - Also stop if the objective improvement over the last ten accepted steps
    is below `1e-9`.

#### Iterative loop

1. Compute current optimal radii and duals.
2. Compute gradient.
3. Take a projected step as described.
4. Resolve the LP at the new centres to obtain the new objective.
5. Accept or reject according to the rule above.
6. Repeat until termination.

The loop normally converges within 200–300 iterations.  
Each iteration requires only one LP evaluation (≈ 10 ms on a single core).

### 5. Initial configuration

A good starting point speeds convergence.  We use one of the following
deterministic patterns:

* **Rectilinear “donut” pattern**:  
  5 rows with 5,5,6,5,5 circles (total 26) placed on a fine grid with spacing
  `Δ=0.2`.  The three central rows are shifted horizontally by `Δ/2` to form a
  slight hexagonal arrangement in the middle.
* **Rotated hexagon**:  
  5×6 hexagonal lattice (30 circles) then delete the four corners that fall
  outside the unit square, leaving 26 circles that are evenly spread.

The two patterns are evaluated; the one giving the larger LP objective is
chosen as the starting centre set.  A tiny random jitter (±0.005) is added so
that the algorithm does not get trapped in a symmetry‑locked configuration.

### 6. Robustness and numerical safeguards

| Potential issue | Mitigation |
|-----------------|------------|
| **Centres co‑inciding** | Skip dual terms with `d_ij` below `1e-12`.  
                              LP will force `r_i=r_j=0`. |
| **Duals not accurate** | Use `highs` with tight tolerance `1e-9`.  
                              If a constraint’s slack > `1e-10` while the dual is
                              positive, set that dual to zero. |
| **Stalling on a flat plateau** | If gradient norm drops below `1e-8` for 5 consecutive
                               iterations, add Gaussian noise with standard
                               deviation `1e-3` to all centres and resume
                               gradient ascent. |
| **Boundary clipping caused overlap** | After projection the LP recomputes radii.
                              By construction the LP solution satisfies all
                              constraints, so the final state is always valid. |
| **Oscillation due to too large step** | Step‑size reduction factor is 0.3 on rejection, preventing
                                          runaway oscillations. |

* The method is deterministic beyond the initial random jitter, so results are

### 8. Output

After the iterative loop finishes, the centres from the iteration with the
