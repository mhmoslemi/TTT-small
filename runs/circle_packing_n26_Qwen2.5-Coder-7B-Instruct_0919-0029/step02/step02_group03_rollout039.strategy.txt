**A Convex‑Optimization–Only Methodology for a 26‑Circle Packing**

---

### 1.  Mathematical Formulation

The entire problem can be cast as a single convex optimisation task.

*Variables*  
\(x_i,\; y_i\) – centre coordinates of circle \(i\) (for \(i=1,\dots,26\)).  
\(r_i\) – radius of circle \(i\).

*Objective*  
\[
\text{maximise }\;\;\; \sum_{i=1}^{26} r_i
\]

*Constraints*  

1. **Boundary containment** (linear, affine in the variables)  
\[
\begin{aligned}
r_i &\le x_i  && (i=1,\dots,26)\\
r_i &\le 1-x_i\\
r_i &\le y_i\\
r_i &\le 1-y_i\\
r_i &\ge 0
\end{aligned}
\]

2. **Non‑overlap** (second‑order cone constraints)  
For every unordered pair \(i<j\)
\[
\sqrt{(x_i-x_j)^2+(y_i-y_j)^2} \;\ge\; r_i + r_j .
\]
The left‑hand side is a convex quadratic norm; the right‐hand side is affine, so the inequality defines a convex *second‑order cone* (SOC).

All constraints are convex; the objective is linear → the whole problem is a **convex second‑order cone program (SOCP)**.  
Thus a *global optimum* can be found in polynomial time with a reliable solver (ECOS, SCS, or MOSEK).

### 2.  Algorithmic Workflow

1. **Set up the SOCP**  
   - Create 26‐dimensional variable vectors `x`, `y`, `r` in `cvxpy`.  
   - Encode the 104 boundary constraints and the 325 pairwise SOC constraints.  
   - Set the objective to `cp.Maximize(cp.sum(r))`.

2. **Solve**  
   - Call `prob.solve(solver=cp.ECOS, verbose=False, abstol=1e-7, reltol=1e-7)` (ECOS is fast for moderate‑size SOCPs).  
   - If ECOS fails, retry with SCS as a backup (`solver=cp.SCS`).  
   - If both fail, fallback to a heuristic (differential evolution as described in the previous solution).

3. **Post‑processing**  
   - Extract `centers` and `radii` from the solver values.  
   - Clip radii to `max(0, r_i)` to eliminate tiny negative values caused by numerical noise.  
   - Clip centre coordinates to `[0,1]` if any exceed the boundary marginally.  
   - Re‑run the LP (`compute_sum_radii`) on the final centres to recompute the true sum and guarantee feasibility; adjust the radii with the LP solution if they differ by more than `1e-6`.

4. **Return**  
   The function returns `(centers, radii, sum_radii)` where  
   - `centers` has shape `(26,2)`;  
   - `radii` has shape `(26,)`;

### 4.  Failure Modes and Mitigations

1. **Solver Infeasibility** – Extremely rare; the convex problem always has at least one feasible point (e.g., all radii zero). If infeasible, fall back to the previously published evolutionary routine.  
2. **Solver Numerical Instability** – Sometimes ECOS may refuse to converge; using SCS as a backup ensures we still get a high‑quality solution.  
3. **Tight Tolerance vs Runtime** – Setting extremely tight tolerances can increase runtime; the chosen `1e-7` balances speed (≈ 0.5 – 1 s) with required precision.  
4. **Rounding Errors on Validation** – The final verification step re‑solves the LP, so any tiny overlaps or boundary violations due to rounding are automatically corrected to satisfy the validator’s `1e-12` tolerance.
