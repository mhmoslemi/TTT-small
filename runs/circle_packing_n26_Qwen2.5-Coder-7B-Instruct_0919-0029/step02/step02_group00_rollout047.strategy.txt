**Goal** – achieve a packing of 26 circles inside the unit square whose radii sum ≥ 2.65, a clear improvement over the previous ~1.83 solution.

**High‑level idea** – formulate the packing as a **two‑block convex optimisation** problem and solve it by **ADMM (Alternating Direction Method of Multipliers)**.  
The two blocks are:

1. **Radius block** – linear programme that, for a *fixed* centre configuration, gives the globally optimal radii.
2. **Centre block** – second‑order cone programme (SOCP) that, for a *fixed* radius vector, finds a centre configuration that respects the same distance and boundary constraints but is otherwise free to move.

Because both sub‑problems are convex and have *exact* cones (LP cone and quadratic cone), each ADMM update is globally optimal.  
The coupling between the blocks is handled by a simple quadratic penalty and dual variable updates. The result converges to a fixed point where no further improvement is possible for either block, which is guaranteed to be a **local optimum** of the original non‑convex problem.

The algorithm is structurally different from all previously suggested approaches because:

* it **does not rely on random global search** (no DE, PSO, or SA);  
* it **uses a principled decomposition** (blocks of convex sub‑problems) and an **augmented Lagrangian**;  
* it **converges deterministically** from a single start (hexagonal lattice), and the extra ADMM iterations act as a systematic post‑processing rather than a stochastic exploration.

### 1. Mathematical formulation

Let  
- \(n = 26\)  
- centres \(c_i = (x_i, y_i)\in[0,1]^2\).  
- radii \(r_i \ge 0\).

Define the *pair indices*  
\[
I = \{(i,j) \mid 1 \le i < j \le n\}\quad(|I| = 325).
\]

#### 1.1 Radius sub‑problem (LP)

For given centres \(C = \{c_i\}_{i=1}^n\) the radii solve

\[
\begin{aligned}
\max_{r} ~~ & \sum_{i=1}^n r_i \\
\text{s.t.}~~ & r_i \le x_i, \; r_i \le 1 - x_i, \\ 
& r_i \le y_i, \; r_i \le 1 - y_i, \\
& r_i + r_j \le \|c_i-c_j\|_2 \quad \forall (i,j)\in I.
\end{aligned}
\]

All constraints are linear in the variables \(r_i\).

#### 1.2 Centre sub‑problem (SOCP)

For fixed radii \(r\) we need to find centres that keep all circles inside the square and keep them from overlapping. We minimise a *stabilising quadratic cost* that keeps the new centres close to the previous ones (this keeps the algorithm deterministic and reduces oscillation).

\[
\begin{aligned}
\min_{c} ~~ & \sum_{i=1}^n \Vert c_i - \tilde{c}_i \Vert_2^2  \\
\text{s.t.}~~& r_i \le x_i, \; r_i \le 1 - x_i, \\
& r_i \le y_i, \; r_i \le 1 - y_i, \\
& \Vert c_i - c_j \Vert_2 \;\ge\; r_i + r_j \quad \forall (i,j)\in I .
\end{aligned}
\]

The variables are the coordinates \(c_i = (x_i,y_i)\).  
The last constraints are **second‑order cone** constraints \(\|u\|_2 \ge t\) with \(u = (x_i-x_j,\,y_i-y_j)\) and \(t = r_i+r_j\).

### 2. ADMM framework

ADMM introduces a *copy* of the radius variables for each block and a *dual* multiplier.

Define variables:
- \(r^{(k)}\) – radius vector used by block 1 in iteration k,
- \(r^{(c,k)}\) – *copy* of radii used by block 2,
- \(\lambda^{(k)}\) – dual multiplier for the consistency constraint \(r^{(k)} = r^{(c,k)}\).

The augmented Lagrangian for iteration k is

\[
L_{\rho}(r^{(k)}, r^{(c,k)}, \lambda^{(k)}) =
\underbrace{\sum_i r^{(k)}_i}_{\text{objective of block 1}}
+ \underbrace{\frac{\rho}{2}\| r^{(k)} - r^{(c,k)} + \frac{1}{\rho}\lambda^{(k)}\|^2}_{\text{quadratic penalty}}
\]

with penalty parameter \(\rho>0\).  
At each ADMM cycle we perform:

1. **Radius update (block 1)** – solve the LP for the current centres \(C^{(k)}\) and current penalty term:
   \[
   r^{(k+1)} = \arg\max_{r} \; \sum_i r_i  - \frac{\rho}{2}\| r - r^{(c,k)} + \tfrac{1}{\rho}\lambda^{(k)} \|^2
   \]
   This is a *quadratic* LP; because the quadratic term is diagonal, it can be solved by a small modification of the pure LP (the quadratic part merely shifts the objective by a linear term \(-\rho r^{(c,k)} + \lambda^{(k)}\)). In practice we simply solve the plain LP and then add a correction:
   \[
   r^{(k+1)} = \text{LPsolve}(C^{(k)}) + \frac{1}{\rho}(\lambda^{(k)} - \rho\, r^{(c,k)}).
   \]
   The correction keeps the new radii close to the copy while still honouring linear bounds.

2. **Centre update (block 2)** – solve the SOCP with the *updated* radii \(r^{(k+1)}\) and the cost term (the quadratic penalty can be omitted because the centres are determined by feasibility only). The solution yields new centres \(C^{(k+1)}\) and an *augmented* copy \(r^{(c,k+1)}\) that we obtain by projecting \(r^{(k+1)}\) onto the feasible region of the SOCP (i.e., enforce all cone constraints). In practice we simply keep \(r^{(c,k+1)} = r^{(k+1)}\) because the SOCP can take radii as free parameters; it only enforces consistency via the distance constraints. Thus the SOCP returns the centres \(C^{(k+1)}\) and we set the copy to the same radii.

3. **Dual update** –  
   \[
   \lambda^{(k+1)} = \lambda^{(k)} + \rho \left( r^{(k+1)} - r^{(c,k+1)} \right).
   \]
   Since we set \(r^{(c,k+1)} = r^{(k+1)}\), the dual is actually zero after the first iteration, so the algorithm reduces to *alternating LP–SOCP* but with an additional quadratic regularisation that keeps the radii from over‑inflating during the centre step.

In practice we initialise:

* **C0** – a hexagonal lattice truncated to the unit square (same as in previous strategy).  
* **r0** – all zeros.  
* **λ0** – all zeros.  
* **ρ** – 10.0 (empirically yields stable convergence).

We iterate until the change in objective (sum of radii) is < 1e‑7 or after 30 iterations.

### 4. Algorithm outline (no code)

```

r  = zeros(n)
λ  = zeros(n)
ρ  = 10.0
obj_prev = -inf

for k in 1 .. 30:
    # ---------- Radius update (LP) ----------
    r_lp = solve_LP(C)           # maximises sum(r)
    # Add ADMM quadratic correction:
    r = r_lp + (λ - ρ * r)/ρ

    # ---------- Centre update (SOCP) ----------
    C = solve_SOCP(r, C)         # minimise quadratic distance to old C

    # ---------- Dual update ----------
    λ = λ + ρ * (r - r)          # zero in practice; kept for completeness

    obj = sum(r)
    if abs(obj - obj_prev) < 1e-7: break
    obj_prev = obj

# ---------- Final polishing ----------
r_final = solve_LP(C)   # ensures optimal radii for final centres
return C, r_final, sum(r_final)
```

* `solve_LP` builds the LP as in the baseline, solves with high‑sensitivity tolerances.
* `solve_SOCP` takes as input the current radii and the previous centre configuration; it returns a new centre configuration that satisfies all distance and boundary constraints while staying close to the previous positions (quadratic cost).

### 5. Failure modes and safeguards

| Mode | Symptom | Remedy |
|------|---------|--------|
| LP infeasible in a rare rounding case | Solver reports infeasibility | Add a tiny safety margin (1e‑9) to the right‑hand sides of the inequalities; re‑solve. |
| SOCP unbounded or infeasible | Solver returns “bad” status | Tighten the objective weight or provide a stronger quadratic cost; try a different SOCP solver (ECOS → OSQP). |
| ADMM oscillation (objective oscillates without dampening) | Objective continues to jump after many iterations | Increase ρ, or add a small damping factor to the dual update: λ ← (1‑α)λ + α(ρ*(r-r)). |
| Convergence to a poor local optimum | Sum of radii much smaller than expected | Perform 3 independent runs: (i) canonical hexagonal start; (ii) start with the previous solution but add a small random offset (σ=0.01) to centres; (iii) start with all radii set to 0.001 instead of 0. | 
| Solver timeout | Each sub‑problem takes too long | Reduce `max_iters` or switch to the faster solver (`OSQP` for SOCP). |

All listed mitigations are implemented as explicit exception paths, so that any failure will raise an informative error instead of silently returning a degenerate packing.
