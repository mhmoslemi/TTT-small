The key observation: for the score to be small, the convolution needs to be "flat" (all values close to the mean). The mean of the convolution is (sum_a)^2 / (2n-1).

For a "flat" convolution, we need:
(a*a)[k] ≈ (sum_a)^2 / (2n-1) for all k.

In particular:
- (a*a)[0] = sum a_j^2 ≈ (sum_a)^2 / (2n-1)
- (a*a)[n-1] = sum a_j * a_{n-1-j} ≈ (sum_a)^2 / (2n-1)

The first condition says sum a_j^2 ≈ (sum_a)^2 / (2n-1). By Cauchy-Schwarz, sum a_j^2 >= (sum_a)^2 / n. So we need (sum_a)^2 / n <= (sum_a)^2 / (2n-1), which means 1/n <= 1/(2n-1), i.e., 2n-1 <= n, i.e., n <= 1. Contradiction for n > 1!

So it's impossible to have a perfectly flat convolution. The best we can do is minimize the "excess" of the maximum over the mean.

Let me define the "excess" as: excess = max_k (a*a)[k] - (sum_a)^2 / (2n-1).

The score = 2n * max_k (a*a)[k] / (sum_a)^2 = 2n * (mean + excess) / (sum_a)^2 = 2n/(2n-1) + 2n * excess / (sum_a)^2.

So minimizing the score is equivalent to minimizing the excess. The first term 2n/(2n-1) is a constant (for fixed n).

For n=2000: 2n/(2n-1) = 4000/3999 ≈ 1.00025.
Current score: 1.519.

def _fft_convolve(a):
    """Fast linear convolution using FFT."""
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    fa = np.fft.rfft(a, fft_size)
    ca = np.fft.irfft(fa * fa, fft_size)
    return ca[:size]

def _compute_score(a):
    """Compute the score for a sequence."""
    n = len(a)
    s = a.sum()
    if s < 1e-15:
        return np.inf
    c = _fft_convolve(a)
    return float(2.0 * n * np.max(c) / (s * s))

def _coord_descent(a0, time_budget, rng):

    cur_score = float(2.0 * n * c.max() / (s * s))
