**Heuristic LP solver**:

The LP is:
maximize sum(b)
subject to: (a*b)[k] <= M for all k = 0,...,2n-2

A simple heuristic: start with b = ones(n), then iteratively reduce b to satisfy the constraints.

For each constraint k:
  (a*b)[k] = sum_{m: valid} a[m] * b[k-m] <= M

If this is violated, we need to reduce some b[k-m] values. A natural choice: reduce all of them proportionally.

Specifically, if s_k = (a*b)[k] > M, then for each m with valid (m, k-m):
  b[k-m] *= sqrt(M / s_k)

This reduces (a*b)[k] from s_k to approximately M (since each cross term is reduced by M/s_k, and there are two factors... actually it's more complex because reducing b[k-m] also affects other constraints).

Let me think about this more carefully. If we set b[k-m] -> b[k-m] * alpha for all m (for a fixed k), then:
(a*b)[k] -> alpha * (a*b)[k] (approximately, if we only change the b values that appear in constraint k)

Wait, no. (a*b)[k] = sum_m a[m]*b[k-m]. If we multiply all b[k-m] by alpha (for all valid m), then (a*b)[k] becomes alpha * (a*b)[k]. So to bring it to M, we set alpha = M / (a*b)[k].

But this also affects other constraints! For a constraint k', the value (a*b)[k'] = sum_m a[m]*b[k'-m]. If k'-m equals some k-m' (i.e., if b[k-m] appears in constraint k'), then that constraint is also affected.

This is the fundamental challenge. But as a heuristic, we can do:
1. Initialize b = ones(n)
2. Repeat until convergence:
   a. For k = 0, 1, ..., 2n-2 (or in random order):
      i. Compute s_k = (a*b)[k]
      ii. If s_k > M: for all valid m, b[k-m] *= sqrt(M/s_k)
   b. After a full sweep, check if all constraints are satisfied.

The sqrt is important: if we use alpha = M/s_k for all b[k-m], then (a*b)[k] becomes alpha * s_k = M. But if we use alpha = sqrt(M/s_k), then each product a[m]*b[k-m] is reduced by sqrt(M/s_k), and the sum is reduced by... hmm, it's more complex.

Actually, let's think of it differently. (a*b)[k] = sum_m a[m]*b[k-m]. If we replace b[k-m] with b[k-m]*t for all m, then (a*b)[k] becomes t*(a*b)[k]. To get M, we need t = M/(a*b)[k].

So the update is: b[k-m] *= M/(a*b)[k] for all valid m.

But this over-corrects because the same b value appears in multiple constraints. The sqrt version is a compromise: b[k-m] *= sqrt(M/(a*b)[k]) means each pairwise product a[m]*b[k-m] is reduced by sqrt(M/(a*b)[k]), and if there were only one such product, the total would be reduced by sqrt(M/(a*b)[k]) rather than M/(a*b)[k]).

I think the correct approach is:
- For each violated constraint k, compute the ratio r = M / (a*b)[k] < 1
- Scale all b[k-m] (for valid m) by r

This is like a coordinate descent on the constraints. It's not guaranteed to converge, but in practice it should work well.

So for each i, the relevant k range is [max(0, i), min(2n-2, i+n-1)] = [i, i+n-1] (since i is in [0, n-1] and i+n-1 <= 2n-2).

So for b[i], the most restrictive ratio is:
min over k in [i, i+n-1] of (M / ab[k]) for those k where ab[k] > M.

This can be written as:
M / max(ab[i:i+n])  (taking the max over the relevant window)

Wait, min(M/ab[k]) = M / max(ab[k]). Yes!

So: ratios[i] = M / max(ab[i:i+n]) (if the max is > M, else 1)

This is a sliding window maximum! We can compute it efficiently.

```python
def solve_lp_heuristic_v3(a, M, n):
    b = np.ones(n, dtype=np.float64)
    L = 1
    while L < 2*n - 1:
        L *= 2
    A = np.fft.rfft(a, L)
    
    for sweep in range(30):
        B = np.fft.rfft(b, L)
        ab = np.fft.irfft(A * B, L)[:2*n-1]
        
        # For each i, find max of ab[i:i+n]
        # ab has length 2n-1, and for i in [0, n-1], ab[i:i+n] is a window of size n
        # The max over this window:
        window_max = np.zeros(n)
        for i in range(n):
            window_max[i] = np.max(ab[i:i+n])
        
        ratios = np.minimum(1.0, M / window_max)
        b *= ratios
        
        if np.min(ratios) > 1.0 - 1e-10:
            break
    
    return b
```
