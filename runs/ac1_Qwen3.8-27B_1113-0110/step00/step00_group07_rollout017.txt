So `grad[j] = 2 * sum_d f[d] * I(j+d in A)`.

This can be computed efficiently! If we define `A_ind[d] = I(d in A)` (an array of length 2n-1), then:
`grad[j] / 2 = sum_d f[d] * A_ind[j+d]` = `(f * A_ind)[j]` (cross-correlation).

Wait, that's the convolution of `f` with `A_ind` evaluated at position `j`. Specifically:
`(f * A_ind)[j] = sum_d f[d] * A_ind[j-d]`... hmm, the indexing is tricky.

Let me use the FFT approach:
- `F = fft(f, 2*n-1)` (zero-padded to length 2n-1)
- `A_fft = fft(A_ind, 2*n-1)`
- `grad_fft = F * A_fft` (element-wise, but we need correlation not convolution)

Actually, let me just use the direct computation. For n=6733, computing `grad` directly is O(n * |A|). If |A| is small (say 1-10 active positions), this is fast.

If |A| is large (say 100), it's O(n * 100) = O(673300) which is still fast.

```python
import numpy as np
import time

def compute_gradient(f, A):
    """Compute the subgradient of max(S) where S = f*f.
    A is the set of active indices (where S is near max).
    Returns grad array of length n.
    """
    n = len(f)
    grad = np.zeros(n)
    for k in A:
        # grad[j] += 2*f[k-j] for j where 0 <= k-j < n
        # i.e., j ranges from max(0, k-n+1) to min(k, n-1)
        j_start = max(0, k - n + 1)
        j_end = min(k, n - 1)
        if j_start <= j_end:
            # For j in [j_start, j_end], k-j is in [0, n-1]
            # grad[j] += 2 * f[k-j]
            # Let d = k-j, so d ranges from k-j_end to k-j_start
            # f[d] where d = k-j
            # When j = j_start, d = k - j_start
            # When j = j_end, d = k - j_end
            d_start = k - j_end
            d_end = k - j_start
            grad[j_start:j_end+1] += 2 * f[d_start:d_end+1][::-1]
    return grad
```

Wait, let me check: when `j` goes from `j_start` to `j_end`, `d = k-j` goes from `k-j_start` down to `k-j_end`. So `f[d]` goes from `f[k-j_start]` down to `f[k-j_end]`. So we need to reverse.

`grad[j_start:j_end+1] += 2 * f[k-j_end : k-j_start+1][::-1]`

Let me verify: `d_start = k - j_end`, `d_end = k - j_start`. The slice `f[d_start:d_end+1]` has length `d_end - d_start + 1 = j_end - j_start + 1`. Reversing it gives the correct order.

OK, now for the update:
- We want to decrease `max(S)`. The subgradient points in the direction of increase.
- So the descent direction is `-grad`.
- But we need to maintain `f >= 0` and some reasonable sum.
- Update: `f_new = f - t * grad`, clip to 0, then don't renormalize (the objective is scale-invariant anyway).

Actually, since the objective is scale-invariant, we don't need to maintain a specific sum. We just need `sum(f) > 0.01`.

But the subgradient step might make some coordinates negative. We handle this by clipping.

The step size `t` is crucial. We can use a simple line search: try `t = 1, 0.5, 0.25, ...` until the objective decreases.

But evaluating the objective requires computing the full convolution, which is O(n^2) = O(n * (2n)) for the direct method, or O(n log n) with FFT.

For n=6733, `np.convolve` takes about 5-10ms. So we can do maybe 100-200 evaluations per second. In 1800 seconds, that's 180,000-360,000 evaluations. That's plenty.

```python
import numpy as np
import time

def fast_convolve(f):
    """Compute full linear convolution using FFT."""
    n = len(f)
    size = 2 * n - 1
    # Use next power of 2 for FFT efficiency
    fft_size = 1
    while fft_size < size:
        fft_size *= 2
    F = np.fft.rfft(f, fft_size)
    S = np.fft.irfft(F * F, fft_size)[:size]
    return S

def get_active_set(S, M, frac=0.999):
    """Get indices where S is near the maximum."""
    return np.where(S >= M * frac)[0]

def compute_subgradient(f, active_indices):
    """Compute subgradient of max(f*f) at f."""
    n = len(f)
    grad = np.zeros(n)
    for k in active_indices:
        j_start = max(0, k - n + 1)
        j_end = min(k, n - 1)
        if j_start <= j_end:
            d_start = k - j_end
            d_end = k - j_start
            grad[j_start:j_end+1] += 2.0 * f[d_start:d_end+1][::-1]
    return grad
```
