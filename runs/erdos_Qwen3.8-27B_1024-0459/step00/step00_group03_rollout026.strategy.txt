## Approach and Rationale

The fundamental challenge is minimizing the maximum overlap integral \(C_5\) for a step function \(h(x)\) over \(x \in [0, 2]\) subject to \(h(x) \in [0, 1]\) and \(\int_0^2 h(x) \, dx = 1\).

### Central Idea

I will employ a **multi-resolution multi-start optimization strategy** combined with **coordinate-wise updates** to distort the parent solution's oscillatory pattern effectively. The key insight is that minimal overlap occurs with a function that either (a) is concentrated in a small region, reducing the number of possible overlapping shifts, or (b) distributes support to minimize the height products \(h(x)h(x+k)\). Though concentrated distributions initially seem promising, adjacent peaks inevitably cause overlap, so the optimal lies in carefully weighting peak separation versus height.

### Non-Convex Optimization Challenges

The objective involves:

1. A max operation over all possible shifts \(k\)
2. A nonlinear integral constraint
3. Product terms \(h(x)h(x+k)\)

Together, these create a non-convex optimization landscape. I cannot rely on simple gradient-based methods. Instead, I use:

- **Resolution hopping**: Test multiple grid sizes (40, 60, 80, 100)
- **Starting diversity**: Initialize from parent solution and random checks
- **Adaptive constraints**: Use probability-based weighting of the integral constraint
- **Orthonormal basis projection**: Projects/repair immediately maintains integrals
- **Entropy-based exploration**: To segment local ridges

The algorithm anticipates long execution times, so resource-efficient interpolation and smart grid selection are critical.

### Time/Budget Considerations

Optimization scale with \(O(n_{\text{points}}^2)\) correlation. I plan:

- Early tests with small grids (\(n_{\text{points}}\)=40, dày 60) to identify promising patterns
- Then iterate with escalating grid sizes
- Up to \(n_{\text{points}}\)=100 as the failure point given 1300 seconds

This balances exploration and computation.

### Fallback Strategy

If time runs short, the algorithm falls back to projecting the parent solution to available grid sizes, then refining via short optimization runs derived from numerical differentiation.

## Mathematical Specification

### Representation

Functions are represented as samples \(h_i\) at uniform grid points over \([0, 2]\) with spacing \(dx = 2.0/n_{\text{points}}\).

### Variables

Define \(n_{\text{points}}\) as grid size. Each \(h_i \in [0, 1]\), subject to:
\[
\sum_{i=1}^{n_{\text{points}}} h_i = \frac{n_{\text{points}}}{2}
\]

### Objective
Minimize \(C_5\) defined by:
\[
\lambda = \max_{k \in [-n_{\text{points}}+1, n_{\text{points}}-1]} \left( \operatorname{np.correlate}(h, 1-h, \text{mode}=\text{'full'})[k] \times dx \right)
\]

The losses are computed via upscaled correlation, ensuring exactness.

### Constraints
- **Step function range**: \(0 \leq h_i \leq 1\)
- **Integral constraint**: \(\sum_i h_i = \frac{n_{\text{points}}}{2}\)

### Recoverability

In case of failures, the projection operation recovers from divergence:
\[
h_{\text{proj}} = \text{clip}(h \times \frac{s}{\sum_i h_i}, 0, 1)
\]
where \(s = \frac{n_{\text{points}}}{2}\) adjusts integrals.

### Rationale Summary
This mathematical setup rigorously defines the optimization space. The orthonormal basis projection layer ensures constraints are maintained at all steps, while multi-start configures explorations without accumulating local minima.

def project(h, nxi):
