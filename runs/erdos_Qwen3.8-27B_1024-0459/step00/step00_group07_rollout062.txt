To speed up: vectorize the swap evaluation.

For swap (a→0, b→1), the change in C[k] for all k simultaneously:
ΔC[k] = [-(1-h[a+k]) + h[a-k]] + [(1-h[b+k]) - h[b-k]] (with validity)

This is a sum of two "stick functions" (nonzero only for specific k values). Specifically:
- The "remove a" part: -(1-h[a+k]) for k in valid range, +h[a-k] for k in valid range
  This is nonzero for k in [-(n-1-a), a] roughly.
- The "add b" part: similar

The total ΔC is a vector of length 2n-1.

For the objective max_k C[k], after the swap:
new_max = max_k (C[k] + ΔC[k])

To find the best swap, I need to minimize this over all (a, b) pairs.

For fixed a: ΔC[k] = ΔC_remove_a[k] + ΔC_add_b[k]
The "remove_a" part is fixed (depends only on a and the current h).
The "add_b" part depends on b.

new_max = max_k (C[k] + ΔC_remove_a[k] + ΔC_add_b[k])

For a fixed a, this is: max_k (D_a[k] + ΔC_add_b[k]) where D_a[k] = C[k] + ΔC_remove_a[k]

And ΔC_add_b[k] is a "stick" pattern (nonzero only near k related to b).

This is hard to vectorize over all (a,b) pairs simultaneously in a simple way.

Alternative: for each a (one-position), compute D_a[k] for all k. Then for each b (zero-position), check if max(D_a + ΔC_add_b) < current_max. The best (a,b) is the one that most reduces the max.

For n=2000: 1000 a-values × 1000 b-values = 1M pairs. Each pair requires O(n) to evaluate max. Total: 2B operations. Too slow.

Better approach: for the current max value M = max_k C[k], a swap (a,b) "helps" if:
- For all k where C[k] is close to M, C[k] + ΔC[k] < M (or at least the max of (C[k]+ΔC[k]) < M)

A necessary (not sufficient) condition: for the specific worst lag k*, C[k*] + ΔC[k*] < M.

So I can first filter by the worst lag, then verify with the full max.

This gives:
1. For the worst lag k*, compute ΔC[k*] for all (a,b) pairs
2. Pick the pair with minimum ΔC[k*] (most negative)
3. Verify with full C evaluation
4. If it helps (reduces max), apply it
5. Repeat

Step 2 is O(n²) but vectorizable:
ΔC[k*] for swap (a→0, b→1) = f(a, k*) + g(b, k*)
where f(a, k*) = -(1-h[a+k*])*[valid] + h[a-k*]*[valid]
and g(b, k*) = (1-h[b+k*])*[valid] - h[b-k*]*[valid]

So for fixed k*, f(a) and g(b) are separable! The best pair (a,b) with a≠b is:
- If argmin_a f(a) ≠ argmin_b g(b): use those
- If they're the same: use (argmin_a f(a), second_min_b g(b)) or (second_min_a f(a), argmin_b g(b)), whichever is better

This makes each iteration O(n) after the O(n) correlate computation. Very fast!
