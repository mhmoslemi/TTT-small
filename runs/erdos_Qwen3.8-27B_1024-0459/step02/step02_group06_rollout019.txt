To address this, I should focus the search on swaps that affect the CURRENTLY MAXIMAL lags. Specifically:
1. Find which lag k* achieves the max
2. Only consider swaps that would reduce corr[k*]
3. For a swap (i: 1→0, j: 0→1) to reduce corr[k*]:
   - We need h[i]*(1-h[i+k*]) = 1 (i.e., i is a 1-position and i+k* is a 0-position) AND after the swap, this pair no longer contributes
   - OR h[j]*(1-h[j+k*]) = 0 before (j was 0, so no contribution) but after swap j becomes 1, so it might add a contribution... wait that makes it worse.
   
   Actually, flipping i from 1 to 0 removes the contribution h[i]*(1-h[i+k*]) from lag k* (which was 1 if i+k* is 0).
   Flipping j from 0 to 1 adds the contribution h[j]*(1-h[j+k*]) to lag k* (which is 1 if j+k* is 0).
   
   So the net change to corr at lag k* is: -(1 if h[i+k*]=0 else 0) + (1 if h[j+k*]=0 else 0)
   
   To DECREASE corr at lag k*: we want h[i+k*]=0 (so removing i helps) and h[j+k*]=1 (so adding j doesn't hurt).

This gives us a directional heuristic: prioritize swaps where i is a "problem" 1-position (has a 0-neighbor at the critical lag) and j is a "safe" 0-position (has a 1-neighbor at the critical lag).

The convention is: output[j] = sum_m h[m] * (1-h[m + j - (n-1)]) where the product is nonzero only when both indices are in [0, n-1].

Actually, numpy's correlate(a, v) computes: c[k] = sum_n a[n+k] * conj(v[n])

- For output index j: c[j] involves h[i] when i is in the range of the sum
- Specifically, c[j] = sum_m h[m] * (1-h[m + j - (n-1)])

For a "well-spread" pattern, #{i ∈ [0, n-1-k] : h[i]=1} ≈ (n-k)/2 (half the valid positions are 1)
