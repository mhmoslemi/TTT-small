The key difference is L-BFGS-B vs SLSQP. L-BFGS-B is much faster per iteration (especially for n=160) and can handle the problem without equality constraints (using a penalty). This means I can do more optimization iterations in the same time.

However, the penalty approach might not converge as precisely as SLSQP with the equality constraint. Let me use both: L-BFGS-B for the bulk of the work, then SLSQP for final polish.

Actually, I just realized there might be an issue with L-BFGS-B and the penalty. The penalty term lam * (sum(x) - n/2)^2 might cause issues if lam is too large (it makes the problem ill-conditioned) or too small (the constraint isn't satisfied).

A better approach: use L-BFGS-B without the penalty, but project onto the feasible set after each function evaluation. This is the "projected L-BFGS-B" approach.

But scipy's L-BFGS-B doesn't support projection callbacks. So I'll stick with the penalty approach but tune it carefully.

Alternatively, I can eliminate one variable: set h[n-1] = n/2 - sum(h[0:n-2]) and optimize only over h[0:n-2]. But then I need to check that h[n-1] ∈ [0,1].

Let me try yet another approach: **Use scipy.optimize.minimize with method='SLSQP' but with a better objective function**.

The key insight: instead of smoothing the max over ALL 2n-1 shifts, smooth it only over the top few (active set). This makes the problem much easier for the optimizer.

Here's my refined strategy:
1. Use SLSQP (exact constraint handling)
2. Smooth only the top-m shifts (m=10-30)
3. Iterate: optimize → re-identify active set → optimize
4. Use adaptive beta (start low, increase)
5. At the end, do a full max optimization with high beta

This should be more effective than the previous approach because:
- Focusing on the active set makes the objective smoother
- SLSQP handles the constraint exactly (no penalty issues)
- Iterative re-identification of the active set adapts to changing maxima

Let me also add: **random restarts from perturbed versions of the best solution**. This helps escape local optima.

One more idea: **use the fact that the problem has symmetry**. If h is a solution, then 1-h shifted by 1 (and projected) might also be a good solution. Also, reversing the sequence.

        sme = m + np.log(np.sum(exps)) / b

def project_h(h, n):
    h = np.array(h, dtype=float).copy()
    h = np.clip(h, 0.0, 1.0)
    target = n / 2.0
    for _ in range(100):
        diff = target - np.sum(h)
        if abs(diff) < 1e-15:
            break
        mask = (h > 1e-12) & (h < 1.0 - 1e-12)
        cnt = np.sum(mask)
        if cnt > 0:
            h[mask] += diff / cnt
        else:
            h[:] += diff / n
        h = np.clip(h, 0.0, 1.0)
    return h


def interp_h(src, src_n, dst_n):
    if src_n == dst_n:
        return src.copy()
    xp = (np.arange(src_n) + 0.5) * 2.0 / src_n
    xq = (np.arange(dst_n) + 0.5) * 2.0 / dst_n
    return np.interp(xq, xp, src)


def time_left(t0, budget):
    return max(0.0, budget - (time.time() - t0))


def find_active(corr, top_m=20, gap=0.5):
    mx = np.max(corr)
    thresh = mx - gap
    act = np.where(corr >= thresh)[0]
    if len(act) > top_m:
        order = np.argsort(corr[act])
        act = act[order[-top_m:]]
    if len(act) < 5:
        act = np.argsort(corr)[-top_m:]
    return act


def make_binary_random(n, rng):
    h = np.zeros(n)
    idx = rng.permutation(n)
    h[idx[:n // 2]] = 1.0
    return h


def make_thue_morse(n):
    h = np.zeros(n)
    for i in range(n):
        cnt = 0
        v = i
        while v:
            cnt ^= (v & 1)
            v >>= 1
        h[i] = 1.0 if cnt == 1 else 0.0
    return h


def make_golden(n):
    h = np.zeros(n)
    gr = (1.0 + np.sqrt(5.0)) / 2.0
    for i in range(n):
        frac = (i * gr) % 1.0
        h[i] = 1.0 if abs(frac - 0.5) < 0.25 else 0.0
    return h
