Let me think more carefully about the directed search. The key idea:

Given the current correlation vector corr[0..2n-2], the worst lag is at index k* where corr[k*] is maximum. The corresponding shift is m* = k* - (n-1).

For m* > 0: the contributing positions are i in [0, n-1-m*] where h[i]=1 and h[i+m*]=0.
For m* < 0: the contributing positions are i in [0, n-1+m*] where h[i+m*]=1 and h[i]=0. (Or equivalently, j = i+m* in [0, n-1] where h[j]=1 and h[j-m*]=0, so positions j where h[j]=1 and h[j-|m*|]=0.)

To reduce the worst lag, I want to:
- Flip a 1 at a contributing position to 0 (removes a contribution)
- Flip a 0 at a non-critical position to 1 (adds few new contributions)

The "non-critical" position j should be one where:
- Flipping h[j] to 1 adds few new (1,0) pairs at currently-high lags
- Ideally, h[j+m] = 1 for most m where corr[m] is high (so no new bad pairs)

def make_feasible(h, n):

            cnt = np.count_nonzero(mask)

    for i in range(n):

    # Fix sum to be exactly n/2
    ones = np.sum(h)

    elif ones < target:

        idx_zeros = np.where(h == 0)[0]
        h[idx_zeros[:deficit]] = 1
    return h
