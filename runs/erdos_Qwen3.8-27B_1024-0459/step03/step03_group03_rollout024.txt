def _smax_grad(h, beta):
    n = len(h)
    c = np.correlate(h, 1.0 - h, mode='full')
    mx = float(np.max(c))
    w = np.exp(beta * (c - mx))
    sw = float(np.sum(w))
    w /= sw
    g = np.zeros(n)
    for k in range(len(c)):
        if w[k] > 1e-12:
            g += w[k] * _grad_lag(h, k)
    return g

Let me also add a **binary local search** that's more systematic:

For binary h (0s and 1s), the objective is:
C₅ = dx * max_k ∑_i h[i](1-h[i+k])

A "swap" move: change h[i] from 1 to 0 and h[j] from 0 to 1 (preserving the sum constraint).
The change in c[k] for this swap:
Δc[k] = (change from h[i]:1→0) + (change from h[j]:0→1)

For h[i]: 1→0:
  c[k] changes by: -[(1-h[k-i]) * 1[lo_k<=i<=hi_k]] + h[k-i] * 1[lo_k<=k-i<=hi_k]
  (removing the contribution of h[i]=1)

For h[j]: 0→1:
  c[k] changes by: +[(1-h[k-j]) * 1[lo_k<=j<=hi_k]] - h[k-j] * 1[lo_k<=k-j<=hi_k]
  (adding the contribution of h[j]=1)

This can be computed efficiently for all k simultaneously, giving us the change in the entire correlation vector.

Actually, this is O(n) per swap (to update the correlation), which is much cheaper than O(n²) for a full correlation computation. Let me think about this...

Actually, for the "full" correlation, changing h[i] affects c[k] for k in [i, i+n-1] (the lags where h[i] participates). That's n values out of 2n-1. So updating is O(n) per single change.

For a swap (two changes), it's still O(n).
