4. If it improves, accept; otherwise, reject (or do a few δ values)

But step 2 requires recomputing the full corr, which is O(n) for the affected entries + O(1) for the rest. Actually, np.correlate is O(n²) but with a very small constant for n=160. Let me benchmark in my head: 160*160 = 25,600 multiply-adds, at ~10 ops/sec in C, that's ~3μs. Plus Python overhead of ~5μs. So ~10μs per call.

5000 calls per second → 50ms. Fine.

But I want to be more efficient. Instead of recomputing the full corr, I can update only the affected entries.

For a move (i, +δ) and (j, -δ):
The only entries that change are those where i or j appears. For a fixed i, the affected entries are:
- As first factor: entries m where k = i - n for some valid n (i.e., n = i-k, 0 ≤ n < n)
  → k ranges from i-(n-1) to i, but clamped to [-(n-1), n-1]
  → In m: from max(0, i-(n-1)) to min(2n-2, i+(n-1))
  → About min(2i+1, 2(n-1-i)+1, 2n-1) entries, roughly n on average

Similarly for j.

So about 2n entries change per pair. Updating these is O(n) per pair.

Let me implement this:

```python
def update_corr(corr, h, i, delta_i, j, delta_j, n):
    """Update corr in-place after h[i] += delta_i and h[j] += delta_j."""
    # For each entry m where i or j appears, recompute
    # Or: compute the change analytically
    
    # For pair (i, i-k) where h[i] is first: corr[m] += delta_i * (1-h[i-k])
    # For pair (i+k, i) where h[i] is second: corr[m] += delta_i * (-h[i+k])
    # etc.
    
    for k in range(-(n-1), n):
        m = k + (n-1)
        dc = 0.0
        # h[i] as first: pair is (i, i-k), valid if 0 <= i-k < n
        if 0 <= i - k < n:
            dc += delta_i * (1.0 - h[i-k])
        # h[i] as second: pair is (i+k, i), valid if 0 <= i+k < n
        if 0 <= i + k < n:
            dc += delta_i * (-h[i+k])
        # h[j] as first: pair is (j, j-k), valid if 0 <= j-k < n
        if 0 <= j - k < n:
            dc += delta_j * (1.0 - h[j-k])
        # h[j] as second: pair is (j+k, j), valid if 0 <= j+k < n
        if 0 <= j + k < n:
            dc += delta_j * (-h[j+k])
        if dc != 0:
            corr[m] += dc
```

Wait, but this is O(n) per pair (looping over all 2n-1 shifts). And for each shift, we do O(1) work. So it's O(n) per pair, O(n²) per full sweep. For n=160, that's 25,600 * 160 = 4M per sweep. In Python with the inner loop, maybe 50-100ms per sweep. 13000 sweeps possible in 1300s.

But I can vectorize the inner loop! For a fixed pair (i, j):
- The shifts where i appears as first: k ∈ [i-(n-1), i] ∩ [-(n-1), n-1]
- The shifts where i appears as second: k ∈ [-i, n-1-i] ∩ [-(n-1), n-1]
- Similarly for j

The total set of affected shifts is the union of these 4 ranges, which is at most 2n-1 but typically about n.

For the vectorized update:
```python
def update_corr_vectorized(corr, h, i, di, j, dj, n):
    """Vectorized update of corr after h[i]+=di, h[j]+=dj."""
    # Precompute the affected shifts
    # For i as first: k from max(-(n-1), i-(n-1)) to min(n-1, i)
    # For i as second: k from max(-(n-1), -i) to min(n-1, n-1-i)
    # etc.
    
    k_range = np.arange(-(n-1), n)
    m_range = k_range + (n-1)  # 0 to 2n-2
    
    # i as first: k where 0 <= i-k < n → i-n < k <= i
    mask_i_first = (0 <= i - k_range) & (i - k_range < n)
    # i as second: k where 0 <= i+k < n → -i <= k < n-i
    mask_i_second = (0 <= i + k_range) & (i + k_range < n)
    # j as first
    mask_j_first = (0 <= j - k_range) & (j - k_range < n)
    # j as second
    mask_j_second = (0 <= j + k_range) & (j + k_range < n)
    
    delta = np.zeros(2*n-1)
    idx = i - k_range  # for i as first: partner index
    delta[mask_i_first] += di * (1 - h[idx[mask_i_first]])
    idx = i + k_range  # for i as second: partner index
    delta[mask_i_second] += di * (-h[idx[mask_i_second]])
    idx = j - k_range
    delta[mask_j_first] += dj * (1 - h[idx[mask_j_first]])
    idx = j + k_range
    delta[mask_j_second] += dj * (-h[idx[mask_j_second]])
    
    corr += delta
    h[i] += di
    h[j] += dj
```

This is O(n) numpy operations per pair, which is very fast (a few μs).

Now, for the optimization of δ for a given pair (i, j):
- h[i] → h[i] + δ, h[j] → h[j] - δ
- Feasible: max(-h[i], h[j]-1) ≤ δ ≤ min(1-h[i], h[j])
- Minimize: max_m (corr[m] + δ * g[m]) where g[m] = S[m,i] - S[m,j]

I can compute g[m] efficiently:
- g[m] = (contribution of h[i] to c_m) - (contribution of h[j] to c_m)
- For each m: g[m] = sum of (1-h[partner]) for i-as-first + sum of (-h[partner]) for i-as-second - (same for j)

This is O(n) to compute.

Then I need to minimize max_m (c_m + δ*g[m]) over the feasible δ range.

Since this is a convex 1D problem, I can:
1. Evaluate at δ_min, δ_max, and 0
2. If the minimum is at a boundary, done
3. Otherwise, the minimum is where the "active" set changes

A practical approach: evaluate at 30 evenly-spaced points in [δ_min, δ_max], pick the best, done. 30 * O(n) = O(30n) per pair.

For 5000 pairs per sweep: 5000 * 30 * 160 = 24M numpy ops → ~0.1 sec per sweep.
13000 sweeps in 1300s. More than enough.
