    delta = np.zeros(2*n-1)
    # For k >= 0 (m = n-1+k, k = 0..n-1)
    k = np.arange(n)  # 0 to n-1
    m = n-1+k  # index in full corr

    idx = m[valid]
    k_v = k[valid]
    delta[idx] += (h[i-k_v] - 1)  # h[i-k]-1 = -(1-h[i-k])

    k_v = k[valid]

```python
def compute_swap_delta(h, i, j, n):
    delta = np.zeros(2*n-1)
    
    # Positive lags k = 0, 1, ..., n-1; index m = n-1+k
    k = np.arange(n)
    m = n - 1 + k
    
    # i as h[a+k] (a=i-k): valid if k <= i (and i <= n-1, which is true)
    v = k <= i
    delta[m[v]] += (h[i - k[v]] - 1)  # -(1-h[i-k])
    
    # i as h[a] (a=i): valid if i+k < n
    v = (i + k) < n
    delta[m[v]] += h[i + k[v]]
    
    # j as h[a+k] (a=j-k): valid if k <= j
    v = k <= j
    delta[m[v]] += (1 - h[j - k[v]])
    
    # j as h[a] (a=j): valid if j+k < n
    v = (j + k) < n
    delta[m[v]] -= h[j + k[v]]
    
    # Negative lags k' = 1, 2, ..., n-1; index m = n-1-k'
    kp = np.arange(1, n)
    m_neg = n - 1 - kp
    
    # i as h[a] (a=i): valid if i+kp < n
    v = (i + kp) < n
    delta[m_neg[v]] += (h[i + kp[v]] - 1)  # -(1-h[i+k'])
    
    # i as h[a+k'] (a=i-k'): valid if kp <= i
    v = kp <= i
    delta[m_neg[v]] += h[i - kp[v]]
    
    # j as h[a] (a=j): valid if j+kp < n
    v = (j + kp) < n
    delta[m_neg[v]] += (1 - h[j + kp[v]])
    
    # j as h[a+k'] (a=j-k'): valid if kp <= j
    v = kp <= j
    delta[m_neg[v]] -= h[j - kp[v]]
    
    return delta
```

Let me also think about the continuous refinement more carefully. The key idea is:

After finding a good binary solution, the "smoothing" step can reduce C5 slightly because:
- The max correlation might be at lag k with value M (an integer for binary)
- By making some values slightly fractional, we can bring it below M
- But we need to maintain sum = n/2

A simple approach: identify the positions that contribute to the worst correlation, and nudge them.

For lag k* (worst): corr_{k*} = sum (1-h[a])*h[a+k*]
Positions where (1-h[a])*h[a+k*] > 0 are contributing. For binary h, these are where h[a]=0 and h[a+k*]=1.

To reduce corr_{k*}, we can:
- Increase h[a] slightly (from 0 to ε) for some of these positions
- Decrease h[a+k*] slightly (from 1 to 1-ε) for some of these positions
- But we need to maintain sum! So we can do both (increase some, decrease others) or just do one and compensate elsewhere.

The effect on other lags is complex, but for small ε, the change is:
- For each contribution we reduce by δε, the change at other lags is also O(δε)
- So the net effect is: worst lag reduces by sum of δε, other lags change by O(δε)

This is essentially what SLSQP with the smooth-max objective does, but maybe I can do it more directly.

**My "nudge" algorithm:**
1. Find worst lag k*
2. Find all positions a where h[a]=0 and h[a+k*]=1 (for k*>0) - these are the "bad" positions
3. For a subset S of these positions, increase h[a] by ε and decrease h[a+k*] by ε
   - This reduces corr_{k*} by 2ε*|S| (each pair contributes ε less)
   - Wait: (1-(0+ε))*(1-ε) ≈ (1-ε)*(1-ε) ≈ 1-2ε. Original was 1*1=1. Reduction is 2ε.
   - Actually: (1-ε)*(1-ε) = 1-2ε+ε². Original: (1-0)*1 = 1. Reduction: 2ε-ε².
4. But this changes other correlations!
5. Use a small ε (like 0.01-0.1) and check if the max actually decreases
