SLSQP with the smooth max objective: The issue is that when beta is large, the smooth max is very sharp, and SLSQP might have convergence issues. When beta is small, the objective is too smooth and doesn't capture the max well.

A better approach might be to use a **sequence of linear programs**:
1. Start with an estimated active set A
2. Solve: minimize C s.t. for k in A: corr[k] <= C - ε, for all k: corr[k] <= C, sum h = n/2, 0 <= h <= 1
   But this is non-convex (bilinear corr[k])

Alternatively, use the **alternating direction method**:
1. Given h, compute active set A
2. Given A, solve a subproblem to minimize max_{k in A} corr[k]
   This can be done by: minimize C s.t. corr[k] <= C for k in A, sum h = n/2, 0 <= h <= 1
   The corr[k] = sum_i h[i](1-h[i+k]) is bilinear in h
   Linearize: corr[k] ≈ sum_i h[i](1-h[i+k]^0) + sum_i h[i]^0(1-h[i+k]) - sum_i h[i]^0(1-h[i+k]^0)
   where superscript 0 denotes the previous iterate
   This gives a linear constraint!

So the alternating approach is:
1. h^{0} = initial
2. Repeat:
   a. Compute active set A from h^m
   b. Solve LP: minimize C s.t. for k in A: sum_i [h[i](1-h^m[i+k]) + h^m[i](1-h[i+k])] - sum_i h^m[i](1-h^m[i+k]) <= C
                                                        sum h = n/2, 0 <= h <= 1
      This is a linear program in (h, C)!
   c. h^{m+1} = LP solution
   d. Update active set
3. Return h

This is a "linearization of the bilinear term" approach, similar to the method of linearizing at the current point. It should converge to a local minimum of the original problem.
