def project_feasible(h, n):
    h = np.array(h, dtype=float).copy()
    h = np.clip(h, 0.0, 1.0)
    target = n / 2.0
    for _ in range(100):
        diff = target - np.sum(h)
        if abs(diff) < 1e-12:
            break
        # Distribute diff to elements not at bounds
        interior = (h > 1e-8) & (h < 1.0 - 1e-8)
        if np.sum(interior) > 0:
            h[interior] += diff / np.sum(interior)
        else:
            # All at bounds, adjust the one closest to 0.5
            idx = np.argmin(np.abs(h - 0.5))
            h[idx] = np.clip(h[idx] + diff, 0.0, 1.0)
        h = np.clip(h, 0.0, 1.0)
    return h

def remaining_time():
    return max(0.0, _BUDGET_S - (time.time() - _START_TIME) - 5.0)

def smooth_objective_grad(h, n, beta):
    """Compute smoothed objective and gradient using log-sum-exp."""
    dx = 2.0 / n
    corr = compute_corr(h)
    m = np.max(corr)
    shifted = beta * (corr - m)
    shifted = np.minimum(shifted, 0.0)  # numerical stability
    exp_vals = np.exp(shifted)
    wsum = np.sum(exp_vals)
    weights = exp_vals / wsum
    val = (m + np.log(wsum) / beta) * dx
    
    # Gradient
    grad = np.zeros(n)

                grad[:npairs] -= w * h[offset:offset + npairs]
        else:

            if npairs > 0:
                grad[:npairs] += w * (1.0 - h[aoff:aoff + npairs])
                grad[aoff:aoff + npairs] -= w * h[:npairs]

def adam_optimize(h, n, beta_schedule, max_iters, lr=0.001):

    _best = h.copy()
    _best_c5 = compute_c5(_best)

    v_hat = np.zeros(n)

        m_hat = beta1 * m_hat + (1-beta1) * grad

Now, for the coordinate descent, let me make it more efficient:
- Only optimize variables that appear in active correlations
- Use a direct formula for the optimal value (since the objective is piecewise linear in each variable)

For a fixed variable h[j], the objective as a function of t = h[j] is:
C(t) = max_k (base_k + a_k * t) * dx

where base_k and a_k are constants (for fixed other variables). The minimum of a max of linear functions is at a "kink" point, which occurs where two lines cross. We can find this by:
1. Computing all the lines (base_k, a_k)
2. Finding the minimax point (lower envelope of the max)

This is a 1D piecewise-linear optimization, which can be solved exactly!

The minimum of max_k (a_k * t + b_k) over t ∈ [0,1] is:
- At t = 0, t = 1, or at a point where two lines cross and the max is minimized

This can be found by:
1. Evaluating at t=0 and t=1
2. For each pair (i,j), finding the crossing point t* = (b_i - b_j)/(a_j - a_i) if 0 < t* < 1
3. At t*, the value is (a_i*t* + b_i) = (a_j*t* + b_j)
4. Taking the minimum over all candidates

But this is O(n²) in the number of correlations, which is O(n²) total. For n=640, that's 640² = 409K operations per variable, times 640 variables = 262M per sweep. Too slow.

A better approach: since we only care about the active constraints (those with value close to the max), we can:
1. Identify the top-K active correlations
2. For each variable, only compute the lines for those K correlations
3. Find the minimax point considering only K lines

With K=10, this is O(K * n) per variable, O(K * n²) total = 10 * 640² = 4.1M per sweep. Much better.

Actually, even simpler: for a given variable j and a set of active correlations, the objective is max of K linear functions. The minimum is at one of the K+1 "break points" (including t=0 and t=1). We can just evaluate at all K(K-1)/2 + 2 points and take the minimum. With K=10, that's 47 evaluations per variable.

Let me implement this.

Wait, actually I realize there's a subtlety. When t changes, the set of active correlations might change (a different correlation might become the max). But if we fix the set of active correlations, the problem is exactly the minimax of linear functions, which is solvable in O(K log K) time.

For the coordinate descent, I'll use this approach:
1. Identify top-K active correlations (K=5 or 10)
2. For each variable in the support of those correlations:
   a. Precompute (a_k, b_k) for each active correlation k
   b. Find the minimax point in [0,1]
   c. Update h[j] to that point
3. Repeat for several sweeps

This should be much faster than the golden section approach.

Let me reconsider. `compute_c5` calls `np.correlate` which is O(n²) for mode='full' with n outputs... actually, `np.correlate` for two arrays of length n in 'full' mode gives 2n-1 outputs and takes O(n²) time (or O(n log n) with FFT, but numpy uses direct method for small n).
