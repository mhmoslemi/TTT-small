This counts pairs (i, i+k) where h[i]=1 and h[i+k]=0. The total across ALL positive lags k is:
∑_k ∑_{i=0}^{n-1-k} h[i](1-h[i+k]) = (number of pairs (i,j) with i<j, h[i]=1, h[j]=0)

This is the number of "inversions" if we think of 1s before 0s.

For a random binary sequence with 128 ones and 128 zeros, the expected number of inversions is 128*128/2 = 8192.

The maximum number of inversions at a SINGLE lag k is at most n-1-k (if all positions 0..n-1-k are 1s and all n-k..n-1 are 0s).

So we want to spread the inversions evenly across lags. The "ideal" would be:
INV/k ≈ 8192/256 ≈ 32 for each lag k.

Then C5 ≤ 32 * dx = 32 * 2/256 = 0.25.

But wait, that's not achievable because the correlation structure is constrained. The Thue-Morse sequence gets close to this ideal at small scales.

Actually, let me recalculate. The total number of "1→0" pairs across ALL positive lags:
∑_{k=1}^{n-1} ∑_{i=0}^{n-1-k} h[i](1-h[i+k])

For each pair (i,j) with i < j and h[i]=1, h[j]=0, this contributes exactly once (to lag j-i).

So total = (# of (i,j) with i<j, h[i]=1, h[j]=0)

For a random arrangement: E = 128*128/2 = 8192.

The lags that are problematic are likely:

For the Thue-Morse sequence, the correlation at each scale is balanced, but the maximum is still well above the average.

Actually, let me reconsider the problem. The gap is only 0.00005 (from 0.380899 to 0.38085). At n=256, dx = 2/256 = 0.0078125. So we need to reduce the max correlation by about 0.00005/0.0078125 ≈ 0.0064 in the discrete sum. Since the correlation values are integers (for binary), we'd need to change at least 1 element. Wait, for non-binary h values, the correlation can be non-integer. So we can make small continuous adjustments.

The key question is: what's the gradient of the max correlation with respect to h? If we can compute it accurately and take a small step, we should be able to reduce C5 by the needed amount.

Let me think about this more carefully. If the max is at lag k*, then:
∂C5/∂h[i] = dx * ∂corr(k*)/∂h[i]

For lag k* (assume k* > 0, so offset = k*):
corr(k*) = ∑_{i=0}^{n-1-k*} h[i]*(1-h[i+k*])
∂corr(k*)/∂h[i] = (1-h[i+k*]) - h[i-k*] (if both terms exist)

So the gradient is:
∂C5/∂h[i] = dx * [(1-h[i+k*]) - h[i-k*]] (for valid i)

If multiple lags are at the max, we take the sum of their gradients (or the subgradient of the max, which is any convex combination).

The issue with the subgradient method is that it's slow near the optimum. A better approach might be to:
1. Identify the active lags
2. Solve a small QP: minimize max_j (a_j^T h + b_j) subject to sum(h) = n/2, 0 ≤ h ≤ 1
   where a_j is the gradient of correlation at lag j.

Actually, this is a linear program! Each correlation at a fixed lag is linear in h:
corr(k) = ∑ h[i]*(1-h[i+k]) = ∑ h[i] - ∑ h[i]*h[i+k]

Wait, that's NOT linear because of h[i]*h[i+k]. 

Hmm, so it's actually quadratic (bilinear). This makes it harder.

But for a FIXED shift k, corr(k) = ∑_{i} h[i] - h[i]*h[i+k] is a sum of bilinear terms, which is a quadratic form in h.

So the problem is: min_h max_k q_k(h) subject to linear constraints, where q_k is a quadratic (concave? convex?).

q_k(h) = ∑_{i} h[i]*(1-h[i+k]) = ∑ h[i] - ∑ h[i]*h[i+k]

The Hessian of q_k with respect to h is:
∂²q_k/∂h[i]∂h[j] = -1 if j = i+k, -1 if j = i-k, 0 otherwise (diagonal is 0)

This Hessian has eigenvalues in [-2, 2], so q_k is neither convex nor concave in general. This makes the problem non-convex.

However, for BINARY h (h[i] ∈ {0,1}), q_k(h) = number of "1→0" transitions at distance k, which is an integer. The problem becomes combinatorial.

Given the non-convexity, gradient-based methods with good heuristics are the way to go. Let me focus on making the gradient method as effective as possible.

**Key improvement idea**: Instead of using the subgradient of the max (which picks only the top lag), use a weighted average of the top K lags' gradients, with weights proportional to how close they are to the maximum. This gives a smoother descent direction.

**Another idea**: Use "mirror descent" or "exponential weighting" to handle the 0-1 constraints more naturally.

**Yet another idea**: Since the problem is close to a binary optimization, use a **local search** that:
1. Projects to binary
2. Tries all single-bit flips
3. Tries all pair-swaps (flip two 1s to 0s and two 0s to 1s)
4. Accepts if C5 improves
5. Uses simulated annealing for stuck states

def compute_grad_topk(h, n, top_k=5, weights=None):
    """Compute weighted gradient of top-k correlations"""
    corr = np.correlate(h, 1.0 - h, mode='full')
    sorted_idx = np.argsort(corr)[::-1][:top_k]
    if weights is None:
        # Exponential weighting based on closeness to max
        max_val = corr[sorted_idx[0]]
        weights = np.exp(-10 * (max_val - corr[sorted_idx]))
        weights /= np.sum(weights)
    grad = np.zeros(n)
    for wk, k_idx in zip(weights, sorted_idx):
        offset = int(k_idx) - (n - 1)
        if offset >= 0:
            n_valid = n - offset

            grad[offset:offset + n_valid] += wk * (1.0 - h[:n_valid])
            grad[:n_valid] -= wk * h[offset:offset + n_valid]
        else:
            m = -offset
            n_valid = n - m
            if n_valid <= 0:
                continue
            grad[:n_valid] += wk * (1.0 - h[m:m + n_valid])
            grad[m:m + n_valid] -= wk * h[:n_valid]
    return grad
