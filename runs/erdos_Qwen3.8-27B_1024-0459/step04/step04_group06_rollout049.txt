_G_BUDGET = 1300.0

def power_sum_obj(h, n, p=20):
    """Power-sum smooth max approximation."""
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    # Scale for numerical stability
    c_max = np.max(corr)
    if c_max < 1e-10:
        return 0.0
    shifted = corr / c_max - 1.0
    exps = np.exp(p * np.clip(shifted, -100, 0))
    return c_max * (1.0 + np.log(np.sum(exps)) / p) * dx

def softmax_obj(h, n, beta=500):
    """Softmax/LogSumExp smooth max approximation."""
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    c_max = np.max(corr)
    shifted = corr - c_max
    exps = np.exp(beta * np.clip(shifted, -600, 0))
    return (c_max + np.log(np.sum(exps)) / beta) * dx

def slsqp_optimize(h, n, beta=500, maxiter=300):
    """SLSQP with softmax objective."""
    target = n / 2.0
    dx = 2.0 / n
    
    def obj(x):
        corr = np.correlate(x, 1.0 - x, mode='full')
        c_max = np.max(corr)
        shifted = corr - c_max
        exps = np.exp(beta * np.clip(shifted, -600, 0))
        return (c_max + np.log(np.sum(exps)) / beta) * dx
    
    def con_sum(x):
        return np.sum(x) - target
    
    bounds = [(0.0, 1.0)] * n
    cons = [{'type': 'eq', 'fun': con_sum}]
    
    try:

                       options={'maxiter': maxiter, 'ftol': 1e-14, 'iprint': 0})
        h_new = project_feasible(res.x, n)
        return h_new, compute_c5(h_new)

        return h, compute_c5(h)

Wait, the problem is: minimize f(h) = max_k g_k(h) subject to h ∈ [0,1]^n, ∑h = n/2.

If we use the LogSumExp approximation: f_β(h) = (1/β) log ∑ exp(β g_k(h)), this is smooth (C∞) and convex (since each g_k is... wait, is g_k convex?).

g_k(h) = dx * ∑_i h[i](1-h[i+k]) = dx * (∑_i h[i] - ∑_i h[i]h[i+k])

The term ∑_i h[i]h[i+k] is NOT convex (it's bilinear). So g_k is not convex, and f_β is not convex.

However, g_k IS concave in each individual h[i] (since h[i] - h[i]h[i+k] = h[i](1-h[i+k]) is concave in h[i] when h[i+k] is fixed... wait, it's linear in h[i]). Actually, h[i](1-h[i+k]) is linear in h[i] for fixed h[i+k]. So g_k is linear in each h[i] individually!

This means the problem is DC (difference of convex) and also amenable to coordinate descent (where each coordinate minimization is a 1D problem of minimizing the max of linear functions, which is piecewise linear).

So the right algorithm is: **Coordinate descent with exact 1D minimization, using a Lagrange multiplier for the sum constraint.**

For the Lagrangian: L(h) = max_k g_k(h) + λ(∑h[i] - n/2) + ∑_i μ_i(1-h[i]) + ∑_i ν_i(-h[i])

For fixed h[j≠i], L as a function of h[i] is:
L(h[i]) = max_k (a_k * h[i] + b_k) + λ*h[i] + μ_i(1-h[i]) + ν_i*(-h[i])

where a_k is the coefficient of h[i] in g_k (plus the correlation terms where h[i] is the "second" element).

This is max of linear functions + linear = piecewise linear. The minimum is at a breakpoint or endpoint.

The subgradient of max_k(a_k*x + b_k) at x is the convex hull of {a_k : k is active}. The minimum of the piecewise linear function is where 0 is in the subgradient (or at a boundary).

So the coordinate update is:
1. For coordinate i, determine all a_k values (coefficients of h[i] in each constraint)
2. The subgradient of the objective w.r.t. h[i] is in [min_{k active} a_k, max_{k active} a_k] + λ
3. Set h[i] where this contains 0, or at boundary if not

This is O(n²) per coordinate (to evaluate all a_k), and O(n) coordinates, so O(n³) per sweep. For n=256, that's about 16M operations, which is fast.

But the sum constraint makes this tricky. If I change h[i], I need to adjust another variable to maintain the sum. Options:
a) Use a Lagrange multiplier λ and ignore the sum constraint during coordinate updates, then project at the end.
b) Pair updates: change h[i] + δ and h[j] - δ simultaneously.

Let me go with option (a) for simplicity:
- Maintain a running estimate of λ (dual variable)
- For each coordinate, minimize L(h[i]) = max_k(a_k*h[i] + b_k) + λ*h[i] over [0,1]
- Update λ based on the constraint violation: λ += η * (∑h - n/2)
- This is a primal-dual method

def project_feasible(h, n):

def slsqp_smooth(h, n, beta, maxiter):
    target = n / 2.0
    dx = 2.0 / n
    
    def obj(x):
        corr = np.correlate(x, 1.0 - x, mode='full')
        c_max = np.max(corr)
        shifted = corr - c_max
        exps = np.exp(np.clip(beta * shifted, -600.0, 0.0))
        return (c_max + np.log(np.sum(exps)) / beta) * dx
    
    def con_sum(x):
        return np.sum(x) - target
    
    bounds = [(0.0, 1.0)] * n
    cons = [{'type': 'eq', 'fun': con_sum}]
    
    try:
        res = minimize(obj, h, method='SLSQP', bounds=bounds, constraints=cons,
                       options={'maxiter': maxiter, 'ftol': 1e-14, 'iprint': 0})
        h_new = project_feasible(res.x, n)
        c5 = compute_c5(h_new)
        return h_new, c5

        corr = np.correlate(h, 1.0 - h, mode='full')
        n_corr = len(corr)
        
        # Get top-k shifts
        top_idx = np.argsort(corr)[-top_k:]
        
        # Compute subgradient
        grad = np.zeros(n)
        for k_idx in top_idx:
            offset = int(k_idx) - (n - 1)
            if offset >= 0:
                n_valid = n - offset
                if n_valid <= 0:
                    continue
                grad[offset:offset + n_valid] += (1.0 - h[:n_valid])
                grad[:n_valid] -= h[offset:offset + n_valid]
            else:
                m = -offset
                n_valid = n - m
                if n_valid <= 0:
                    continue
                grad[:n_valid] += (1.0 - h[m:m + n_valid])
                grad[m:m + n_valid] -= h[:n_valid]
        
        gn = np.linalg.norm(grad)
        if gn < 1e-14:
            break
        grad /= gn
        
        # Line search with momentum
        alpha = step
        improved = False
        for _ in range(10):

                h = h_trial.copy()
                improved = True

            step = min(alpha * 1.3, 0.3)
        else:
            patience += 1
            step *= 0.6
            v *= 0.4
