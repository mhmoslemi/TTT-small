    """Gradient of corr_k with respect to x for shift index k in full mode."""
    g = np.zeros(n)
    off = k - (n - 1)
    if off >= 0:
        npairs = n - off
        # corr_k = sum_{i=0}^{npairs-1} x[i] * (1 - x[i + off])
        g[:npairs] += (1.0 - x[off:off + npairs])
        g[off:off + npairs] -= x[:npairs]
    else:
        ao = -off
        npairs = n - ao
        # corr_k = sum_{i=0}^{npairs-1} x[ao + i] * (1 - x[i])
        g[ao:ao + npairs] += (1.0 - x[:npairs])
        g[:npairs] -= x[ao:ao + npairs]
    return g

OK, let me also think about a completely different approach: **coordinate descent on the binary solution**.

For a binary solution, the objective is max_k corr_k. If I know which shift achieves the max, I can try to reduce that specific correlation by flipping bits.

Specifically:
- Find k* = argmax corr_k
- For the shift k*, the correlation is sum_i h[i] * (1-h[i+off]) where off = k* - (n-1)
- To reduce this, I want to either:
  - Change h[i] from 1 to 0 where (1-h[i+off]) = 1 (i.e., h[i+off] = 0)
  - Or change h[i+off] from 0 to 1 where h[i] = 1

But I need to maintain balance, so I'd swap: pick i where h[i]=1, h[i+off]=0, and find j where h[j]=0, h[j+off']=1 for some off', and swap h[i] and h[j].

This is essentially what SA does, but targeted at the worst shift.

Let me implement a "targeted local search":
1. Find the worst shift k*
2. Find all "bad pairs" at this shift
3. Try to fix them by swapping
4. Repeat

This could be much more efficient than random SA.
