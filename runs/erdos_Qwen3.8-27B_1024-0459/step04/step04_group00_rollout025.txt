where effect_on_P[i] is the effect of h[i]: 1→0, and effect_on_P_inv[j] is the effect of h[j]: 0→1.

For h[p]: 1→0:
- ΔP(d) = [p+d<n and h[p+d]==1] - [p-d>=0 and h[p-d]==0] for d=1,...,n-1
- ΔQ(d) = [p-d>=0 and h[p-d]==1] - [p+d<n and h[p+d]==0] for d=1,...,n-1

For h[p]: 0→1:
- ΔP(d) = [p-d>=0 and h[p-d]==0] - [p+d<n and h[p+d]==1] for d=1,...,n-1
- ΔQ(d) = [p+d<n and h[p+d]==0] - [p-d>=0 and h[p-d]==1] for d=1,...,n-1

Note: the effect of 0→1 is the negative of 1→0! Because:
- 1→0: ΔP(d) = [p+d<n, h[p+d]=1] - [p-d>=0, h[p-d]=0]
- 0→1: ΔP(d) = [p-d>=0, h[p-d]=0] - [p+d<n, h[p+d]=1] = -(1→0 effect)

Wait, that's only true if h hasn't changed. But since we're computing the effect independently (linear superposition), and the effects are computed based on the CURRENT h, the 0→1 effect at position j is indeed the negative of what the 1→0 effect would be at position j.

So: ΔP(d) for swap (i: 1→0, j: 0→1) = effect_1to0_P[i][d] - effect_1to0_P[j][d]

This is great! We can precompute effect_1to0_P[p] for all p, and then for each swap, the delta is just a difference of two precomputed vectors.

But we still need to compute the max of (P(d) + ΔP(d), Q(d) + ΔQ(d)) over all d for each swap, which is O(n) per swap.

With 36,864 swaps and O(n=384) per swap, that's 14M operations. In numpy, we can vectorize over the swaps:

That's 192*192*383 ≈ 14M elements. Might be too much memory (14M * 8 bytes = 112 MB). Feasible but tight.

- For all d with Q(d) = M: ΔQ(d) < 0

So we only need to check a subset of d values (the "critical" ones plus those close to M).

Let me implement a two-phase approach:
1. Identify critical d values (where P(d) or Q(d) is within 1 of M)
2. For each swap, check if it reduces the objective on critical d values
3. Only for promising swaps, verify the full condition
