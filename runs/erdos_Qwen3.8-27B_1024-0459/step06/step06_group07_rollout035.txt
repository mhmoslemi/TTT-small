from scipy.optimize import minimize

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(corr)) * dx

def compute_corr(h):
    return np.correlate(h, 1.0 - h, mode='full')

def project_feasible(h, n):
    h = np.array(h, dtype=float).copy()
    h = np.clip(h, 0.0, 1.0)
    target = n / 2.0
    for _ in range(300):
        diff = target - np.sum(h)
        if abs(diff) < 1e-14:
            break
        at_low = h <= 1e-12
        at_high = h >= 1.0 - 1e-12
        mid = ~(at_low | at_high)
        cnt = int(np.count_nonzero(mid))
        if cnt > 0:
            h[mid] += diff / cnt
        else:
            h[:] += diff / n
        h = np.clip(h, 0.0, 1.0)
    return h

def make_binary(h, n):
    """Convert to binary while maintaining sum = n/2"""
    n_ones = n // 2
    # Sort by value, keep top n_ones as 1
    idx = np.argsort(-h)
    b = np.zeros(n)
    b[idx[:n_ones]] = 1.0
    return b

def thue_morse(n):
    """Generate Thue-Morse sequence of length n"""
    t = np.zeros(n, dtype=np.int32)
    for i in range(1, n):
        t[i] = t[i >> 1] ^ (i & 1)
    return 1.0 - t  # Flip to get 256 ones (or not, depending on convention)

    idx = rng.permutation(n)

    b[idx[:n//2]] = 1.0
    return b

    rng = np.random.RandomState(seed)
    h = h.copy()
    best_c5 = compute_c5(h)
    best_h = h.copy()
    start = time.time()
    
    ones_idx = np.where(h > 0.5)[0]
    zeros_idx = np.where(h < 0.5)[0]
    
    no_improve = 0
    max_no_improve = 10000
    
    while time.time() - start < max_time:
        # Pick random pair
        i = ones_idx[rng.randint(len(ones_idx))]
        j = zeros_idx[rng.randint(len(zeros_idx))]
        if i == j:

        # Try flip

        h[j] = 1.0
        c5_new = compute_c5(h)

            best_h = h.copy()
            no_improve = 0
        else:
            # Revert
            h[i] = 1.0
            h[j] = 0.0
            no_improve += 1
            if no_improve > max_no_improve:

Actually, I realize this local search might be too slow because each flip requires a full correlation computation. For n=512, np.correlate is fast (~2μs), so 1M flips would take ~2 seconds. That's fine.

But the issue is that random pair flips are unlikely to improve a near-optimal solution. We need a more directed approach.

Let me think about a better move generation:

**Key idea**: For the lag k* that achieves the maximum, we want to reduce corr[k*]. The way to do this is:
- Change h[i] from 1 to 0 where h[i+k*]=0 (directly reduces corr[k*] by 1)
- But we must also change some h[j] from 0 to 1 (to maintain the sum)
- The j flip might increase other correlations

So the optimal j is one that minimizes the increase in other correlations. This is a secondary optimization.

**Efficient implementation**:
For a fixed i (the 1→0 flip), the change in correlation at all lags can be computed:
- Removing h[i]=1: for lag k, the change is -(1-h[i+k]) if i+k is valid, and -h[i-k] if i-k is valid (from the other side of the correlation)
- This gives a "delta" vector of length 2n-1

For each candidate j (0→1 flip), the change is:
- Adding h[j]=1: for lag k, the change is +(1-h[j+k]) if j+k valid, +h[j-k] if j-k valid

So the total change is delta_i + delta_j, and we want to minimize max(corr + delta_i + delta_j).

If we precompute delta_i for the current h and the chosen i, then for each j, we just need to compute max(corr + delta_i + delta_j).

The question is: how expensive is this?
- Computing delta_i: O(n)
- Computing delta_j for all j: O(n²) if done naively
- But we can precompute a "delta table" for all possible j: O(n²)

Then for each i, we find the best j by computing max(corr + delta_i + delta_j) for all j. This is O(n) per i (if we can compute the max quickly).

This is getting complicated. Let me just use a simpler approach.

For n=512, the correlation computation is fast enough that we can just try many flips and keep the best. The bottleneck is not the computation but the search strategy.

Let me use a **simulated annealing** approach with a good move generator:

1. State: binary sequence h with n/2 ones
2. Move: pick two random positions i (with h[i]=1) and j (with h[j]=0), swap them
3. Cost: current C₅ (max correlation * dx)
4. Acceptance: accept if cost decreases, or with probability exp(-(new_cost - old_cost)/T)

The temperature T starts high and decreases geometrically.

Key parameters:
- n = 512 (start with parent resolution)
- Initial T: large enough to accept many moves (e.g., T = 0.1 * C₅)
- Cooling rate: 0.999 per step
- Steps: as many as possible within time budget
- Restart: if stuck, restart from best with higher T

Let me also add a "chunk" move: instead of swapping two individual positions, swap two blocks of equal length. This can escape deeper local minima.
