"C₅ = max_k ∫ h(x)(1 - h(x+k)) dx"

The integral is ∫₀² h(x)(1-h(x+k)) dx. But h is defined on [0,2], so h(x+k) is only defined when x+k ∈ [0,2], i.e., x ∈ [-k, 2-k]. So the integral is actually over [0, min(2, 2-k)] = [0, 2-k] for k ≥ 0, and [0, 2] for k ≤ 0... 

Wait, the problem says h: [0,2] → [0,1]. What is h(x+k) when x+k > 2? It's not defined. The implicit assumption is that h is extended by 0 outside [0,2]. So:

∫₀² h(x)(1-h(x+k)) dx = ∫₀^{2-k} h(x)(1-h(x+k)) dx for k ≥ 0
= ∫₀² h(x) dx - ∫_{2-k}² h(x) dx - ∫₀^{2-k} h(x)h(x+k) dx + ∫_{2-k}² h(x) dx

Wait, that's not right. If h(x+k) = 0 for x+k > 2 (i.e., x > 2-k), then:
1-h(x+k) = 1 for x > 2-k

So the integral becomes:
∫₀^{2-k} h(x)(1-h(x+k)) dx + ∫_{2-k}² h(x) * 1 dx
= ∫₀^{2-k} h(x)(1-h(x+k)) dx + ∫_{2-k}² h(x) dx

For the discrete version, this is exactly what np.correlate(h, 1-h, mode="full") computes (with appropriate indexing), because the "full" mode zero-pads.

Wait, actually np.correlate with mode="full" doesn't zero-pad in the way I described. Let me check:

np.correlate(h, 1-h, mode="full") computes:
result[m] = ∑_i h[i] * (1-h)[i + m - n + 1]

where the sum is over all valid i (0 ≤ i < n and 0 ≤ i + m - n + 1 < n).

This is NOT the same as zero-padding. It's a "full" convolution-like operation.

For h of length n, 1-h of length n:
- m ranges from 0 to 2n-2
- offset = m - n + 1 ranges from -(n-1) to (n-1)
- For offset > 0: result = ∑_{i=0}^{n-1-offset} h[i] * (1-h[i+offset])
- For offset = 0: result = ∑_{i=0}^{n-1} h[i] * (1-h[i]) = ∑ h[i](1-h[i])
- For offset < 0: result = ∑_{i=-offset}^{n-1} h[i] * (1-h[i+offset]) = ∑_{i=0}^{n-1+offset} h[i-offset] * (1-h[i])

This is the "linear correlation" (not circular). It matches the integral with zero extension.

So the C₅ = max of this full correlation * dx. And for the 0-1 case, the offset=0 term is 0 (since h(1-h)=0), and the other terms are counts of (1,0) or (0,1) pairs.
