How many i's are active at k*? The set of i such that effect_i[k*] = 1 is:

Let s* = k* - (n-1). Then we need i + s* to be in [0, n-1] and h[i+s*] = 0.

The number of such i's is the number of zeros in a window of length n, which is n/2.

Similarly, effect_j[k*] = 0 means h[j+s*] = 1 (or j is out of range, but if j+s* is out of range, effect_j[k*] = 0 by definition).

The number of j's with effect_j[k*] = 0 is: (n/2) [ones in the window] + (n - n) [out of range, which is 0 since the window is always length n] = n/2.

def project_binary(h, n, rng):
    """Project h to binary with exactly n/2 ones."""
    n_half = n // 2
    b = (h >= 0.5).astype(float)
    ones_count = int(b.sum())
    if ones_count == n_half:

    if ones_count > n_half:
        one_idx = np.where(b == 1)[0]
        # Flip the ones with smallest h values
        order = np.argsort(h[one_idx])
        to_flip = one_idx[order[:ones_count - n_half]]
        b[to_flip] = 0
    else:

        order = np.argsort(-h[zero_idx])
        to_flip = zero_idx[order[:n_half - ones_count]]
        b[to_flip] = 1
    return b

        T *= cooling
        if T < T_min:
            T = T_min
    
    return best_h, best_max

Hmm, the SA approach recomputes corr every iteration, which is O(n²) per step (for np.correlate). For n=512, that's about 262K operations per step. At maybe 1000 steps/second, that's 262M ops/second, which is fine.

Actually, np.correlate for n=512 should be very fast (maybe 10-50μs). So we can do 20000-100000 steps in 60 seconds. That's plenty.

But the issue is that SA with random single-pair moves might be too slow to make progress. Let me think about a better approach.

**Better idea: SA with "smart" moves**

Instead of purely random moves, use the local search structure to guide the SA:
- At each step, consider only moves that pass the "critical shift filter" (i.e., moves where the flipped one "covers" the argmax shift)
- This focuses the search on potentially useful moves

Or even better: use the local search as a "restart" mechanism within SA:
1. Do a few steps of random perturbation
2. Run local search to convergence
3. Compare with best, accept/reject based on SA criterion
4. Cool down

This is essentially iterated local search (ILS) with SA-style acceptance.
