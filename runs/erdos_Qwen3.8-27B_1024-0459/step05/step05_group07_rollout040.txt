For a more efficient approach:
- Precompute the current corr array
- For a candidate swap, compute the new values of corr at the affected offsets
- Check if the max decreases

The affected offsets are those m where (i+m) mod something or (j+m) mod something gives a difference. In the worst case, all 2n-1 offsets are affected.

For n=640, checking one swap takes O(n) ≈ 640 operations. With 102,400 possible swaps, that's ~65M operations per full scan, which is too slow.

Alternative: Only check a subset of swaps. For example:
- Only check swaps where |i-j| is small (local swaps)
- Or only check swaps that target the worst offset

For targeting the worst offset k*:
- Δcorr[k*] = (h[j+k*] - h[i+k*]) + (h[i-k*] - h[j-k*])
- We want this < 0
- For binary h: we want h[j+k*] + h[i-k*] < h[i+k*] + h[j-k*]
- This means the "pattern" around j is "better" than around i for offset k*

We can pre-compute, for each position i, the "score" S[i] = h[i+k*] + h[i-k*] (the contribution to the "bad" side).
Then a swap (i,j) helps if S[j] < S[i] (i.e., j has a "better" pattern for offset k*).

So the algorithm is:
1. Find worst offset k*
2. Compute S[i] = h[i+k*] + h[i-k*] for all i (with out-of-bounds = 0)
3. Find i with h[i]=1 and maximum S[i] (worst "1" position)
4. Find j with h[j]=0 and minimum S[j] (best "0" position)
5. Swap i and j
6. Check if max correlation decreased
7. If yes, accept; if no, try next best candidate

This is O(n) per candidate, and we only need to check a few candidates per iteration. Much faster!

The soft-max approach: min_h (max(corr) + log(sum(exp(beta*(corr - max))))/beta) * dx
This smoothly approximates the max and is differentiable everywhere.

The excess L2 approach: min_h sum_k max(0, corr[k]*dx - T)²
This directly penalizes violations of a threshold T and is piecewise quadratic.

The excess L2 has the advantage that:
- It directly targets the constraint corr[k]*dx ≤ T
- The gradient is zero when all correlations are below T (so it "stabilizes" at the target)
- By decreasing T, we can drive the max down

The disadvantage:
- It's not smooth at the kink points (where corr[k]*dx = T)
- The gradient can be zero if no correlations exceed T (stuck in a local minimum)

To handle the non-smoothness, I can use a smoothed version:
f_ε(h) = sum_k (max(0, corr[k]*dx - T + ε/2)² - (ε/2)²) / ε
This is the "smooth hinge" loss, which is C¹ continuous.

Or I can just use the non-smooth version with a subgradient (take the subdifferential and use a fixed subgradient, e.g., the one corresponding to the "right" side of the kink).

In practice, the non-smooth version works fine with gradient descent because the kink points are measure zero and the method still makes progress.
