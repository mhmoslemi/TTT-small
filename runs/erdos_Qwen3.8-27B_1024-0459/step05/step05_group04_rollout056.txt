```python
        g[:np_] += (1.0 - h[ao:ao + np_])
        g[ao:ao + np_] -= h[:np_]
    return g

        _, g = logsumexp_objective_and_grad(x, n, beta)
        return g

        result = project_feasible(res.x, n)
        if compute_c5(result) < compute_c5(h):
```

```python
    hi3 = min(2*nm1 - j, corr_len - 1)
    if lo3 <= hi3:
        idx3 = np.arange(j + lo3 - nm1, j + hi3 - nm1 + 1)
        dr[lo3:hi3+1] += (1.0 - h[idx3])
    
    # h[j]: 0 -> 1, second factor: k in [j, j+nm1]
    lo4 = max(j, 0)
    hi4 = min(j + nm1, corr_len - 1)
    if lo4 <= hi4:
        idx4 = j - np.arange(lo4, hi4+1) + nm1
        dr[lo4:hi4+1] -= h[idx4]
    
    # Corrections
    dr[nm1] -= 2.0
    d = j - i
    if 0 < abs(d) < n:
        k_cross = nm1 + d
        if 0 <= k_cross < corr_len:
            dr[k_cross] += 1.0
    
    return dr
```

This is vectorized and should be fast. Each vectorized operation is O(n) but done in C under the hood.

Now for the gradient of the log-sum-exp objective, I also need vectorization. Let me precompute the gradient contributions:

For the full correlation gradient:
dcorr[k]/dh[j] = (1-h[j+shift]) * [valid1] - h[j-shift] * [valid2]

where shift = k-(n-1).

I can compute this as a matrix, but for n=384, the matrix would be 384 x 767, which is about 295K entries. That's fine memory-wise but computing it each iteration might be slow.

Alternative: for the weighted sum gradient, I can iterate over k (767 iterations) and for each, add w[k] * gradient_contribution_k. Each contribution is a vector of length n computed in O(n). Total: O(n * (2n-1)) = O(n²) per gradient evaluation. For n=384, that's about 300K operations. In numpy, this should take a few milliseconds.

Let me write the gradient:

```python
def lse_gradient(h, n, beta):
    corr = compute_corr(h)
    shifted = beta * corr
    max_s = np.max(shifted)
    exp_s = np.exp(shifted - max_s)
    w = exp_s / np.sum(exp_s)
    dx = 2.0 / n
    
    g = np.zeros(n)
    for k in range(2 * n - 1):
        wk = w[k] * dx
        if wk < 1e-15:
            continue
        shift = k - (n - 1)
        if shift >= 0:
            np_ = n - shift
            g[shift:shift+np_] += wk * (1.0 - h[:np_])
            g[:np_] -= wk * h[shift:shift+np_]
        else:
            ao = -shift
            np_ = n - ao
            g[:np_] += wk * (1.0 - h[ao:ao+np_])
            g[ao:ao+np_] -= wk * h[:np_]
    return g
```

This loops over 2n-1 = 767 values, each doing O(n) numpy operations. Should be fast enough.
