But wait, I also need to handle the case where pa and pb "interact" (i.e., when pa+m = pb or pb+m = pa for some lag m). In that case, the simple formula breaks down because changing h[pa] affects h[pb+m] or vice versa.

Let me check: f_pa[m] uses h[pa-m] and h[pa+m]. If pa+m = pb, then h[pa+m] = h[pb] which is being changed. Similarly if pb+m = pa, h[pb+m] = h[pa] which is being changed.

When pa + m = pb: m = pb - pa. At this lag, the formula gives:
f_pa[m] = h[pa-m] + h[pa+m] - 1 = h[2pa-pb] + h[pb] - 1 = h[2pa-pb] + 0 - 1 = h[2pa-pb] - 1

But after the swap, h[pb] = 1, so the "true" f should use h[pb]=1:
Actually, the issue is that in the original correlation, the term involving h[pb] when it's 0 doesn't contribute (since h[pb]=0), but after setting h[pb]=1, it does.

Let me re-derive more carefully for the case where pa + m = pb (i.e., the "h[n+m]" term for n=pa gives h[pa+m] = h[pb]):

Original corr[m] includes: h[pa+m]*(1-h[pa]) = h[pb]*1 = 0 (since h[pb]=0)
After swap: h_new[pa+m]*(1-h_new[pa]) = h_new[pb]*0 = 0 (since h_new[pa]=0)
So this term doesn't change! Good.

And the "(1-h[n])" term for n=pb: 
Original: h[pb+m]*(1-h[pb]) = h[pb+m]*1 = h[pb+m]
After: h[pb+m]*(1-h_new[pb]) = h[pb+m]*0 = 0
Change: -h[pb+m]

And for n=pa in the "(1-h[n])" term:
Original: h[pa+m]*(1-h[pa]) = h[pb]*0 = 0
After: h_new[pa+m]*(1-h_new[pa]) = 1*1 = 1 (since h_new[pa+m] = h_new[pb] = 1, h_new[pa] = 0)
Change: +1

And for n such that n+m = pa (i.e., n = pa-m):
Original: h[pa]*(1-h[pa-m]) = 1*(1-h[pa-m])
After: h_new[pa]*(1-h[pa-m]) = 0
Change: -(1-h[pa-m])

And for n such that n+m = pb (i.e., n = pb-m):
Original: h[pb]*(1-h[pb-m]) = 0
After: h_new[pb]*(1-h[pb-m]) = 1*(1-h[pb-m])
Change: +(1-h[pb-m])

So total change when pa+m = pb:
= -(1-h[pa-m]) + 1 + (1-h[pb-m]) - h[pb+m]
= -1 + h[pa-m] + 1 + 1 - h[pb-m] - h[pb+m]
= h[pa-m] + 1 - h[pb-m] - h[pb+m]

Versus the general formula: f_pa[m] - f_pb[m] = (h[pa-m] + h[pa+m] - 1) - (h[pb-m] + h[pb+m] - 1)
= h[pa-m] + h[pa+m] - h[pb-m] - h[pb+m]
= h[pa-m] + h[pb] - h[pb-m] - h[pb+m]  (since pa+m=pb)
= h[pa-m] + 0 - h[pb-m] - h[pb+m] (since h[pb]=0)

So the general formula gives: h[pa-m] - h[pb-m] - h[pb+m]
The correct answer is: h[pa-m] + 1 - h[pb-m] - h[pb+m]

Difference: the general formula is off by 1 (missing the +1).

This happens because when pa+m = pb, the term "h[pa+m]*(1-h[pa])" changes from 0 to 1 (not 0 to 0 as the formula assumes). The formula assumes h[pa+m] doesn't change, but it does (it equals h[pb] which changes from 0 to 1).

Similarly, if pb+m = pa (i.e., m = pa-pb), there's an analogous issue.

So for the general formula to be exact, we need pa+m ≠ pb and pb+m ≠ pa, i.e., m ≠ pb-pa and m ≠ pa-pb.

For a given pair (pa, pb), there are at most 2 lags where this correction is needed. I can handle these as special cases.

Actually, for the purpose of finding the best swap, this off-by-1 at 2 out of 2N-1 lags probably won't change the argmax much. I'll use the approximate formula and handle corrections if needed.

    zeros = np.where(h == 0.0)[0]
    
    if len(ones) == 0 or len(zeros) == 0:
        return h, 0

    # For each pb in zeros, compute max_j(A[j] - F[pb, j])
