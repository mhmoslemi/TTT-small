This is the fundamental problem: when computing the delta for a swap, the two position changes interact. The simple linear formula doesn't capture the second-order interaction.

The correct approach: compute the change as:
Δcorr[k] = corr_new[k] - corr_old[k]

For a swap (i: 1→0, j: 0→1), the change at each k is:
= [terms involving h[i] or h[j] in new] - [terms involving h[i] or h[j] in old]

The terms that change are those where either the "first" or "second" factor is at position i or j.

For a given k (with d = k-(n-1)):
- h[i+d] appears as first factor at position i (if 0 ≤ i+d < n)
- h[i] appears as second factor at position i-d (if 0 ≤ i-d < n)
- Similarly for j

But if i+d = j or j+d = i or i = j-d or j = i-d, there's an interaction.

The interaction happens when:
- i + d = j (the first factor at position i is at position j, which is also changing)
  This means d = j - i
- j + d = i (the first factor at position j is at position i, which is also changing)
  This means d = i - j
- i = j - d (the second factor at position j-d is at position i, which is also changing)
  This means d = j - i (same as first)
- j = i - d (the second factor at position i-d is at position j, which is also changing)
  This means d = i - j (same as second)

So the interaction happens at d = j-i and d = i-j (i.e., k = n-1+j-i and k = n-1+i-j).

At these lags, the simple formula is incorrect and we need to add a correction.

At d = j-i (so k = n-1+j-i):
The term at position i (first factor is h[i+d] = h[j]) interacts with the change at j.
The term at position j-d = i (second factor is h[i]) interacts with the change at i.

  Change: +1

  The term at position i is h[i+d]*(1-h[i]) = h[j]*(1-h[i]) (same as above)

Hmm, this is getting complicated. The interaction correction depends on the specific configuration.

Actually, I think the simplest and most robust approach is to just compute the delta directly by evaluating the affected terms, rather than using a formula. For a swap (i, j), the correlation values that change are only at lags k where the window [i, i+n-1] or [j, j+n-1] (for the first factor) or [i-(n-1), i] or [j-(n-1), j] (for the second factor) is non-empty.

The affected lags are:
- k such that 0 ≤ i+k-(n-1) ≤ n-1, i.e., n-1-i ≤ k ≤ 2(n-1)-i
- k such that 0 ≤ j+k-(n-1) ≤ n-1, i.e., n-1-j ≤ k ≤ 2(n-1)-j
- k such that 0 ≤ i-(k-(n-1)) ≤ n-1, i.e., i ≤ k ≤ i+n-1
- k such that 0 ≤ j-(k-(n-1)) ≤ n-1, i.e., j ≤ k ≤ j+n-1

The union of these ranges is at most 4n long, but typically about 2n.

For each affected k, I can compute the exact change by looking at which terms are affected. But this is still O(n) per k, giving O(n²) total, which is too slow.

The O(n) approach in the original code must handle the interaction somehow. Let me look at the original code again:

```python
def make_swap_delta(h, i, j, n):
    r = 2 * n - 1
    dr = np.zeros(r)
    # Effect of h[i] -> h[i]-1 (delta=-1)
    # First factor: -(1-h[i+n-1-k]) for k in [i, i+n-1]
    lo = max(i, 0)
    hi = min(i + n - 1, r - 1)
    if lo <= hi:
        ks = np.arange(lo, hi + 1)
        dr[lo:hi+1] += -(1.0 - h[i + n - 1 - ks])
    # Second factor: +h[i+k-(n-1)] for k in [n-1-i, 2n-2-i]
    lo2 = max(n - 1 - i, 0)
    hi2 = min(2 * (n - 1) - i, r - 1)
    if lo2 <= hi2:
        ks = np.arange(lo2, hi2 + 1)
        dr[lo2:hi2+1] += h[i + ks - (n - 1)]
    # Effect of h[j] -> h[j]+1 (delta=+1)
    # First factor: +(1-h[j+n-1-k]) for k in [j, j+n-1]
    lo3 = max(j, 0)
    hi3 = min(j + n - 1, r - 1)
    if lo3 <= hi3:
        ks = np.arange(lo3, hi3 + 1)
        dr[lo3:hi3+1] += (1.0 - h[j + n - 1 - ks])
    # Second factor: -h[j+k-(n-1)] for k in [n-1-j, 2n-2-j]
    lo4 = max(n - 1 - j, 0)
    hi4 = min(2 * (n - 1) - j, r - 1)
    if lo4 <= hi4:
        ks = np.arange(lo4, hi4 + 1)
        dr[lo4:hi4+1] -= h[j + ks - (n - 1)]
    # Correction at k=n-1 (double counting)
    dr[n - 1] -= 2.0
    return dr
```
