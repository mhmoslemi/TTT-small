    if rng is None:

        h[best_b] = 1.0
        new_c5 = compute_c5(h)
        if new_c5 < best_c5:
            best_c5 = new_c5

Wait, the binary steepest descent with exhaustive 1-swap check is O(n^2 * n) = O(n^3) per round (n^2 swaps, each requiring O(n) correlate). For n=384, that's about 56 million operations per round. With numpy, each correlate takes maybe 5μs, so n^2 = 147456 swaps * 5μs = 0.7s per round. That's too slow for many rounds.

Let me optimize: instead of checking all n^2/4 pairs, I can check a subset (e.g., only pairs within a certain distance, or use random sampling mixed with exhaustive).

Actually, for n=384, n^2/4 ≈ 37000 pairs. Each correlate is O(n) = O(384). So total is 37000 * 384 ≈ 14 million multiply-adds per round. In numpy, this should take maybe 50-100ms per round. That's manageable for 20-50 rounds.

But wait, 37000 correlate calls of length 384... each might take ~2μs, so 74ms total. OK that's fine.

Let me also think about the simulated annealing more carefully.

For SA, I need to be careful about the temperature. The "energy" is C₅ ≈ 0.38. A single swap changes C₅ by at most... well, swapping one position changes at most 2*(n-1) terms in the correlation (one for each shift), and each term changes by at most 1. So the max correlation can change by at most 2*(n-1) in absolute value, giving a C₅ change of at most 2*(n-1)*2/n ≈ 4. But in practice, the change is much smaller, maybe 0 to 0.05.

So T_start ≈ 0.02, T_end ≈ 0.001 seems reasonable.

Number of iterations: For n=384, each iteration involves one correlate (O(n)) and one random pair selection. At 5μs per correlate, 100000 iterations would take 0.5s. I can afford a few million iterations in the time budget.
