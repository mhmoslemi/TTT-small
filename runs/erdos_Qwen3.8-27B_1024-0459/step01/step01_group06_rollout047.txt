Let me also add a "bisection on t" approach:
- Binary search on t: is there a feasible h with max c_k <= t and sum(h) = n/2, 0<=h<=1?
- This feasibility check is: find h such that for all k, sum_i h[i]*(1-h[i+k]) <= t, 0<=h<=1, sum(h)=n/2
- This is a quadratic feasibility problem (the constraints are quadratic in h)
- Not directly solvable by LP, but could use CVXPY (QCP)

Actually wait, h[i]*(1-h[i+k]) = h[i] - h[i]*h[i+k]. The constraint is:
sum_i h[i] - sum_i h[i]*h[i+k] <= t

The first term is linear, the second is a product. This makes it a QCP (quadratic constraint program). CVXPY can handle this if the quadratic terms are "convex" in the right direction.

sum_i h[i]*h[i+k] is a quadratic form: h^T A_k h where A_k is a shift matrix. The constraint is:
sum(h) - h^T A_k h <= t, which is:
-1 * (h^T A_k h) [+ linear] <= t - linear

For this to be a convex constraint, we need -h^T A_k h to be convex, i.e., A_k to be negative semidefinite. But A_k (a shift matrix) is not PSD or NSD in general.

So direct CVXPY formulation won't work for the general case. We'd need to linearize.

Alternative: For a fixed iteration, linearize h[i]*h[i+k] ≈ h[i]*h_old[i+k] + h_old[i]*h[i+k] - h_old[i]*h_old[i+k] (first-order Taylor). Then the constraint becomes linear, and we can solve an LP. This is the "successive linearization" or "Dinkelbach" approach.
