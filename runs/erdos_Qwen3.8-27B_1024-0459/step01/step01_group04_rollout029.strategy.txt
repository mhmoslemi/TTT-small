The central idea is to use a **hierarchical Bayesian optimization** approach combined with **resolution adaptation**. Unlike gradient-based methods, this strategy leverages Bayesian inference to balance exploration and exploitation across multiple scales. It assumes global optima lie in structured periodic or near-periodic functions (e.g., sinusoidal, sawtooth) that minimize overlap by maintaining symmetric high-low transitions. The key limitation of current gradient-based methods is local entrapment, addressed by introducing two phases: (1) top-down Bayesian optimization with Gaussian process surrogates, and (2) bottoms-up fine-tuning on sparse grid resolutions. We use the provided parent as a temperate (secondary) initialization and dynamically up/downsample solutions for proof-of-concept.

2. **Mathematical Specification**  
Variables:  
- `h ∈ [0,1]^n` represents discrete time samples over `[0,2]`.  
- `n = 2^k * base_n` (even, optimally chosen) for multi-resolution embedding.  
- **Objective**: Minimize `C_max = \| \text{conv}(h, 1-h) \|_∞ / (2/n)`.  
Constraints:  
- Integral: `∑h_i * (2/n) = 1`.  
- Box: `0 ≤ h_i ≤ 1` for all `i`.  

Representation:  
- **Multi-scale**: Use `h` and its upscaled/downscaled variants to explore periodic patterns.  
- **Surrogate**: Gaussian process learns `C`-objective vs. `h` features (e.g., percentile moments, smoothness).  

3. **Implementation Procedure**  
   **Step 1: Initialization**  
   - If `initial_h_values` provided, generate hierarchies of upsamples/vary-resolution (`n=70*2/4`) bootstrapped by `initial_h_values`.  
   - Optionally use `synthetic_h` for missing candidate surfaces.  
   **Step 2: Bayesian Optimization (Phase 1)**  
   - Use proxy kernels: `Kernel('rbf')` for local refinement, `Kernel('matern')` for robustness.  
   - Objective: Minimize `-expected_improvement` under integral constraint.  
   - Constraints enforced via probabilistic projection: `h ~ truncated_normal(0,1,0,1)` + integral penalty.  
   **Step 3: Resolution Chaining**  
   - Query `compute_c5` for sampled `n ∈ {50, 100, 200}` assuming `n=2*k`. Persist best `@n=70` child via upscaling.  
   **Step 4: Local Refinement (Phase 2)**  
   - Apply SLSQP to fine-tune `h` with fixed constraints: `integral=0.5`, `clip(0,1)`.  
   **Step 5: Outcome Handling**  
   - Accept any candidate achieving `C < 0.38` if gradient-based refinement fails.  
   - Preserve initialization if budget under-runs.  

4. **Search Choices**  
   Base parameters:  
   - **GP Hyper**: `alpha=0.01`, `epsilon=1e-4`.  
   - **Resolution**: Ascending: `n ∈ [50,100,200]` (even, powers-of-2).  
   - **Pareto Prior**: Penalize slow update: maximize improvement rate vs. stagnation.  
   Variations: Inject learned sinusoidal modulation if parent-function detected.  

5. **Budget and Robustness**  
   Time allocation:  
   - Train GP: ~`0.2 * budget_s` seconds for initial kernel learning.  
   - Phase 1: `budget_s * 0.5` for 100 evaluations.  
   - Phase 2: Strictly <`budget_s * 0.3` per resolution step.  
   Fallback: Linear interpolate best `h` from previous n-levels if perturbation fails.  

6. **Validation and Return Contract**  
   - **Feasibility**: Check invariants: `sorted(h) has no -1 or >1`, `abs(∑h-(n/2))<1e-5`.  
   - **Objective**: Rerun `compute_c5(h)` to confirm.  
   - **Output**: Return first `h` with `C < 0.38`, even via upscale of `initial_h_values`.
