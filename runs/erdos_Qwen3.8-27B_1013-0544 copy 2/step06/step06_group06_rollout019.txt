Let me also think about another approach: **use the continuous relaxation more effectively**.

The problem with continuous h:
- min max_k corr_k(h) * dx
- s.t. 0 ≤ h[i] ≤ 1, sum(h) = n/2

The correlation is corr_k = sum_i h[i](1-h[i+k]) which is bilinear (non-convex).

But here's a trick: if we define x = h and y = 1-h, then corr_k = sum_i x_i * y_{i+k}, and we have x + y = 1, x ≥ 0, y ≥ 0.

The problem becomes:
- min max_k sum_i x_i * y_{i+k} * dx
- s.t. x_i + y_i = 1, x_i ≥ 0, y_i ≥ 0, sum x_i = n/2

This is still non-convex due to the product x_i * y_{i+k}.

However, we can use a **semidefinite relaxation** or **linearization** approach. For the product x_i * y_{i+k}, we can introduce a variable z_{i,k} ≤ x_i, z_{i,k} ≤ y_{i+k}, z_{i,k} ≥ x_i + y_{i+k} - 1 (standard bilinear relaxation). But this gives a convex relaxation that might be too loose.

Actually, for our specific case where x_i + y_i = 1 (so y_i = 1 - x_i), the product is x_i * (1 - x_{i+k}) which is a concave function of each variable (but bilinear overall). The maximum of a concave function over a polytope is achieved at extreme points, which are the binary solutions! So the continuous relaxation doesn't help - the optimal solution is always binary.

Wait, that's not quite right. The objective is max_k corr_k, which is the maximum of bilinear functions. The maximum of bilinear functions is not concave. So the continuous relaxation could potentially give a better (lower) value than the best binary solution, but we can't use it directly since we need a valid h.

However, we can use the continuous relaxation to get a UPPER BOUND on the binary optimum (by solving the relaxed problem), and use the relaxed solution to guide the binary search.

def build_g(h, n):
    g = np.zeros((n, 2 * n - 1))
    for p in range(n):
        ks = p
        ke = min(2 * n - 2, p + n - 1)
        k_range = np.arange(ks, ke + 1)

        idx = k_range[valid]
        g[p, idx] = 1.0 - 2.0 * h[idx - p]

def do_swap(g, h, corr, n, zeros, ones, ii, jj):
    """Perform swap: zeros[ii] -> 1, ones[jj] -> 0. Returns updated state."""

    j = ones[jj]
