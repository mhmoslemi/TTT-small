```python
    # Similarly if a-s=b (i.e., b=a-s, so s=a-b):
    #   h[a-s]*(1-h[a]) = h[b]*(1-h[a]): before = 1*(1-0)=1, after = 0*(1-1)=0. Delta = -1
    #   From h[a]: i=a-s term: -h[a-s] = -h[b] using OLD h[b]=1 → -1 ✓
    #   From h[b]: i=b term: -(1-h[b+s]) = -(1-h[a]) using old h[a]=0 → -1
    #   DOUBLE COUNTED! The -1 appears in both.
    #   Actually wait: the "from h[a]" change at i=a-s is: the term h[a-s]*(1-h[a]) changes
    #     because (1-h[a]) changes. The change is h[a-s]*(1-1) - h[a-s]*(1-0) = 0 - h[a-s] = -h[a-s]
    #   The "from h[b]" change at i=b is: h[b]*(1-h[b+s]) changes because h[b] changes.
    #     The change is 0*(1-h[b+s]) - 1*(1-h[b+s]) = -(1-h[b+s])
    #   These are TWO DIFFERENT terms in the sum (different i values: i=a-s=b and i=b).
    #   Wait, i=a-s=b and i=b are the SAME i! So it's the same term h[b]*(1-h[a]).
    #   I'm double counting.
    
    # OK this is getting really messy. Let me just use a simpler approach:
    # After making the swap, recompute corr directly. For n=400, np.correlate is fast.
    # Or better: compute the change using the formula but handle edge cases.
    
    # Actually, the safest approach for correctness:
    # 1. Make the swap
    # 2. Recompute corr = np.correlate(h, 1-h, 'full')  [O(n^2) but fast in C]
    # 3. Check if M decreased
    
    # For n=400, np.correlate takes about 20-50 μs. So we can do ~20K-50K iterations per second.
    # With 500s budget, that's 10M-25M iterations. More than enough.
    
    # Let me just go with the direct approach for simplicity and correctness.
    
    T = 0.1  # initial temperature
    for it in range(max_iter):
        if time.time() > deadline:
            break
        if it % 10000 == 0:
            T *= 0.99  # slow cooling
        
        zeros = np.nonzero(h == 0)[0]
        ones = np.nonzero(h == 1)[0]
        if zeros.size == 0 or ones.size == 0:
            break
        
        a = zeros[rng.randint(zeros.size)]
        b = ones[rng.randint(ones.size)]
        
        h[a] = 1.0
        h[b] = 0.0
        new_corr = np.correlate(h, 1.0-h, mode="full")
        new_M = int(np.round(new_corr.max()))
        delta = new_M - M
        
        if delta <= 0 or rng.random() < np.exp(-float(delta) / T):
            M = new_M
            corr = new_corr
            if M < best_M:
                best_M = M
                best_h = h.copy()
            zeros = np.nonzero(h == 0)[0]
            ones = np.nonzero(h == 1)[0]
        else:
            h[a] = 0.0
            h[b] = 1.0
    
    return best_h, best_M * dx
```

This is simple but might be too slow for finding M=76 from M=77 (the improvement is tiny). Let me add a "directed" component:

**Directed local search:**
- When stuck, identify the k values where c[k] = M
- Among zero positions, find the one whose addition most reduces c at the hot k values
- Among one positions, find the one whose removal most helps
- Try that specific swap

This is more targeted and should find the M=77→76 transition faster.

Let me also add: **try ALL swaps** (not just random) when M is close to the target. For n=400, there are 200*200 = 40000 possible swaps. Each takes O(n) to evaluate with the profile approach, so 40000*400 = 16M operations per full sweep. That's fast.

For position p, the "add profile" (change in corr when h[p] goes 0→1) is:
add[p, m] for m in [0, 2n-2]:

  contribution = 0
  if 0 <= p+s < n: contribution += (1-h[p+s])  [p as first index]

rem[p, m]:

  if 0 <= p-s < n: contribution += h[p-s]       [p as second index, (1-h[p]) goes 0→1]
