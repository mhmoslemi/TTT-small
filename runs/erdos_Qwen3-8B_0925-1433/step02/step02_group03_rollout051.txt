But let's say that the maximum occurs at index max_idx in the correlation array. Then, the lag (number of samples) is shift = max_idx - (n_points -1). However, this shift can be negative. For example, if max_idx is 0, then shift = -n_points +1.

But in the integral, the lag k can be any real number. However, for the purpose of analytical gradient, we need to know the shift in terms of the number of samples. Let's call it k_samples = shift. 

But to compute the gradient for h[i], we need to know for each i, whether i +k_samples is within the array, and similarly i -k_samples is within.

So, for each i in 0..n_points-1:

if i +k_samples is within [0, n_points-1], then term1 = (1 - h[i +k_samples]).

Else, term1 = 0.

if i -k_samples is within [0, n_points-1], then term2 = h[i -k_samples].

Else, term2 = 0.

gradient[i] = term1 - term2.

Thus, the gradient for the overlap at lag k_samples is computed in O(n_points) time.

This seems feasible.

So the steps are:

1. Compute the correlation array, find the max and its index.

2. Compute k_samples = max_idx - (n_points -1).

3. For each i, compute term1 and term2 based on k_samples.

4. The gradient is [term1 - term2 for all i].

Once the gradient is computed, update h using gradient descent.

But what about the constraint that sum(h) == n_points / 2? During gradient descent, after updating h, we need to clip to [0,1] and then rescale.

So, during each iteration:

- Compute the gradient for the maximum lag.

- Update h using h_new = h - alpha * gradient.

- Clip h to [0,1], then rescale to meet the sum constraint.

Now, this seems manageable.
