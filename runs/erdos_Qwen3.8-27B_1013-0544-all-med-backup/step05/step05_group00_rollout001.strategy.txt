def explore_neighbor(h, n, rate, mode):
    """
    Create a neighbor by modifying a random index or set
    Modes: 0=partial, 1=full, 2=random
    """
    h_new = h.copy()
    if rate > 0.6:
        # reset a few elements
        num = 5
        positions = np.random.choice(n, num, replace=False)
        for i in positions:
            h_new[i] = np.random.rand() * 0.5  # full change to test new patterns
    elif mode == 0:
        # add/subtract uniformly distributed noise
        i = np.random.randint(0, n)
        change = rate * (np.random.rand() - 0.5)
        h_new[i] += change
    elif mode == 1:
        # slight changes on multiple points
        i = np.random.randint(0, n)
        h_new[i] += rate * (np.random.rand() - 0.5)
    return h_new

### Search choices and useful variations

This implementation supports several adaptive features:

1. **Multi-resolution exploration**: 
   - Explores 6 distinct resolutions (target numbers of samples)
   - Starts from parent (250 samples) and progressitively refines larger-sample solutions

2. **Configurable search modes**:
   - `explore_neighbor` function allows 3 modes:
     0=partial change, 1=full change short-term, 2=random
   - The chosen mode depends on a random factor proportional to perturbation size
   - Benefits from incomplete information on optimal start

3. **Adaptive cooling rate**:
   - Reduces temperature every 100 steps to 99% of current rate
   - Stops cooling early if significant cost reduction is not found

4. **Progressive refinement**:
   - Designed to work even if full time budget is exhausted
   - Retains memory across resolutions
   - Maintains archive of top performers for later expansion

### Compute budget and robustness

The program follows these time management policies:

1. **Time considerations for different sizes (estimated)**:
   - n=250: ~0.1-0.2 seconds per 100 steps
   - n=500: ~0.5-0.7 seconds per 100 steps
   - Larger n: Computation scales as O(n^2) but typically
   - with careful scheduling, the program should not time out at 1100s

   - Handles `KeyError`, `ValueError`, `TimeOutError` gracefully

3. **Progressive reduction**:
