However, if h is binary, then g_k is linear in h (since h[i]*(1-h[i+k]) is linear when h is binary). But for continuous h, it's bilinear.

So the LP approach only works for binary h. For continuous h, we need a different approach.

Alternative: Use the bilinear structure. The constraint sum h[i]*(1-h[i+k]) ≤ λ/dx can be rewritten as:
sum h[i] - sum h[i]*h[i+k] ≤ λ/dx

This is a quadratic constraint (specifically, a Bilinear Matrix Inequality). This can be solved as a QCQP (quadratic constraint quadratic program), which is NP-hard in general but can be approximated.

Actually, let me think about this differently. The objective is:
max_k sum_i h[i]*(1-h[i+k])

This is a max of bilinear functions. At the optimum, the KKT conditions say that the gradient of the active constraints should be in the span of the gradients of the other constraints.

For a practical approach, let me try:
1. Start from the parent (continuous)
2. Use a "minimax" style optimization:
   - Maintain a weight vector w over the lags (initially uniform, or concentrated on the worst lag)
   - Minimize sum_k w_k * g_k (a weighted sum)
   - Update w to emphasize the worst lags
   This is related to the "multiplicative weights" or "follow-the-regularized-leader" approach.

Actually, this is essentially what the smooth-max approach does (with softmax weights). The previous solution already uses this with SLSQP.

    """Compute gradient of g_lag with respect to h, scaled by dx."""
    dx = 2.0 / n
    grad = np.zeros(n)
    if lag >= 0:
        grad[:n-lag] += dx * (1.0 - h[lag:])
        grad[lag:] -= dx * h[:n-lag]
    else:
        to = -lag
        grad[:n-to] += dx * (1.0 - h[to:])
        grad[to:] -= dx * h[:n-to]
    return grad
