def generate_initial(n, init_type, rng):
    if init_type == 'const':
        return np.ones(n)
    elif init_type == 'geo':
        r = rng.uniform(0.95, 0.999)
        return r ** np.arange(n)
    elif init_type == 'ramp':
        return np.linspace(0.5, 1.5, n)
    elif init_type == 'sin':

        eps = rng.uniform(0.1, 0.8)
        freq = rng.uniform(1, 10)
        phase = rng.uniform(0, 2*np.pi)
        x = eps * np.cos(2*np.pi*freq*np.arange(n)/n + phase)
        return np.maximum(base + x, 0)
    elif init_type == 'rand':
        return np.abs(rng.normal(1, 0.5, n))
    elif init_type == 'exp':
        # Exponential decay from center
        center = n//2
        d = np.abs(np.arange(n) - center)
        rate = rng.uniform(0.001, 0.02)
        return np.exp(-rate * d)

def compute_score(a):
    """Fast score computation without calling evaluate_sequence."""
    n = len(a)
    conv = np.convolve(a, a, 'full')
    max_b = conv.max()
    sum_a = a.sum()
    if sum_a < 0.01:
        return np.inf
    return 2.0 * n * max_b / (sum_a ** 2)

OK so for a monotonically varying sequence, the convolution peak is at one end and is large. We need a different approach.

What if the sequence goes up and then down? Like a "bump":
a[i] = exp(-(i-n/2)^2/σ^2) (Gaussian)

For a Gaussian, the convolution is also a Gaussian (wider). The peak is at the center.
c[k] ≈ ∫ e^{-(x-n/2)^2/σ^2} * e^{-(k-x-n/2)^2/σ^2} dx
= (σ√π/2) * e^{-(k-n/2+... )^2 / (2σ^2)} (broadened Gaussian)

The peak is at k=n-1 (center) with value proportional to 1/σ.
As σ → n (wider), the Gaussian becomes more like a constant, and the peak approaches the triangle peak.
As σ → 0 (narrower), the sequence becomes a delta, and the convolution is a delta too (peak = 1, sum = 1, score = 2n).

For the Gaussian, the score is always >= 2 (since it's symmetric, the center is sum of squares >= sum^2/n).

So symmetric sequences are bounded below by 2! We NEED asymmetry.

This is the key insight: **the sequence must be asymmetric to beat 2.**

For an asymmetric sequence, the center of the convolution is sum a[i]*a[n-1-i], which can be less than sum a[i]^2 (by rearrangement inequality, the minimum of sum a[i]*b[i] over permutations of b is when a and b are oppositely sorted).

So if a is sorted in increasing order: a[0] < a[1] < ... < a[n-1].
Then a[n-1-i] is in decreasing order.
sum a[i]*a[n-1-i] is the "anti-sorted" product sum, which is minimized when one is increasing and the other is decreasing.

The minimum of sum a[i]*a[n-1-i] (over all permutations of a[n-1-i], which is fixed as the reverse) is achieved by the reverse pairing.

But a[n-1-i] IS the reverse of a[i]. So sum a[i]*a[n-1-i] is the "anti-sorted" sum.

By rearrangement: sum a[i]*a[i] >= sum a[i]*a[n-1-i] (for sorted a).
So the center of the convolution for a sorted sequence is <= sum a[i]^2.

How much less? For a[i] = i (sorted, n=100):
sum a[i]*a[n-1-i] = sum_{i=0}^{99} i*(99-i) = 99*sum i - sum i^2 = 99*4950 - 328350 = 490050 - 328350 = 161700
sum a[i]^2 = 328350
sum a = 4950, sum^2 = 24502500

So center = 161700, sum^2/n = 245025. Center < sum^2/n ✓ (161700 < 245025)
