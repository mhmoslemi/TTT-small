   Uses simplex projection and adaptive step sizes to find sequences with flat autocorrelation.
   """
   import numpy as np

   def project_simplex(v):
       """Project vector v onto the probability simplex."""
       n = v.size
       if n == 0:
           return v
       u = np.sort(v)[::-1]
       cssv = np.cumsum(u)
       rho_candidates = np.arange(1, n + 1)
       cond = u * rho_candidates > (cssv - 1.0)
       if not np.any(cond):
           return np.ones(n) / n
       rho = np.nonzero(cond)[0][-1]
       theta = (cssv[rho] - 1.0) / (rho + 1.0)
       return np.maximum(v - theta, 0.0)

       """Compute 2*n*max(conv(a)) assuming sum(a)=1."""
       n = a.size
       conv = np.convolve(a, a)

   It seems like the [0.25, 0.1, 0.05, 0.1, 0.25] pattern is special because the edges aren't too large (so conv[0] = 0.0625 is small) AND the middle is small enough to reduce the center peak.

   The key constraint is: we need `2*a[0]*a[n-1]` (the dominant term in the center convolution for a symmetric sequence) to be small. This means at least one of a[0] or a[n-1] should be small.

   But we also need a[0]^2 to be below the max (which is at the center). So a[0]^2 <= center value.

   For a symmetric sequence: center = sum_i a[i]^2 (when n is odd, the exact center). Wait no, for a symmetric sequence of length n, conv[n-1] = sum_i a[i]*a[n-1-i] = sum_i a[i]^2 (by symmetry).

   So for a symmetric sequence, the center IS sum(a^2). And we want to minimize sum(a^2) subject to sum(a) = 1, a >= 0. This is minimized by the uniform distribution! (By Cauchy-Schwarz or Jensen's inequality.)

   So for symmetric sequences, the best we can do is uniform, giving objective 2. To beat 2, we need an ASYMMETRIC sequence.

   This is a crucial insight! The sequence must be asymmetric to beat 2.

   Let me think about what asymmetry helps. For an asymmetric sequence, conv[n-1] = sum_i a[i]*a[n-1-i] (the reversal correlation). This can be small if a[i] is high where a[n-1-i] is low (and vice versa).

   For example, if a is increasing (a[0] < a[1] < ... < a[n-1]), then a[i]*a[n-1-i] pairs small values with large values, reducing the sum.

   But as I showed earlier, for n=5 with a ramp [0.05, 0.1, 0.25, 0.3, 0.3], the max was not at the center but at index 6 (off-center), and it was large.

   The issue is that for an increasing sequence, the convolution at lags near the right side (where both factors are large) is large. Specifically, conv[2n-2-1] = a[n-2]*a[n-1] + a[n-1]*a[n-2] = 2*a[n-2]*a[n-1], which is large if the last two elements are large.

   So we need a more careful design. We want:
   1. The reversal correlation (center) to be small → asymmetry
   2. The "same-side" correlations (edges of the convolution) to be small → no large adjacent values

   These two goals are in tension. Let me think about how to balance them.
