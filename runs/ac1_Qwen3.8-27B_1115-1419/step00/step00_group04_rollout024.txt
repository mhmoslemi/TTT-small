def simplex_projection(v, sum_target=1.0):
    """Project v onto the simplex {x >= 0, sum(x) = sum_target}"""
    n = len(v)
    # Scale to make the problem standard: project v/sum_target onto {x >= 0, sum(x) = 1}, then scale back
    v = v / sum_target
    # Standard simplex projection
    mu = 0
    v_sorted = np.sort(v)[::-1]
    cssv = np.cumsum(v_sorted)
    rho = np.arange(1, n+1)
    cond = v_sorted - (cssv - 1) / rho > 0
    rho_star = np.max(rho[cond])
    theta = (cssv[rho_star-1] - 1) / rho_star
    result = np.maximum(v - theta, 0)
    return result * sum_target

For `k = 1`: `c[1] = 2r` (two terms: `i=0,1`)
...
For `k = n-1`: `c[n-1] = n * r^{n-1}` (n terms)
For `k = n`: `c[n] = (n-1) * r^n` (n-1 terms)
...

So the max of `c[k]` is at `k=0` with value 1 (for `r < 1`), assuming `2r < 1` (i.e., `r < 1/2`).

If `r < 1/2`: `max = 1`, `sum ≈ 1/(1-r)`, `objective = 2n/(1/(1-r))^2 = 2n(1-r)^2`.
As `r -> 0`, `objective -> 2n`. As `r -> 1/2`, `objective = 2n/4 = n/2`.

Hmm, for large n this is still large. Not good.

If `r > 1/2`: The max might be at a different k. Let's check `k=1`: `c[1] = 2r`. If `2r > 1`, then `max >= 2r`. This happens when `r > 1/2`.

So for `r` slightly above 1/2, the max transitions from `c[0]=1` to `c[1]=2r`. At the transition point `r=1/2`, both are 1.

This doesn't seem to lead to good solutions for large n.
