Actually, the KKT conditions for minimizing max_k q_k subject to p >= 0, sum(p) = 1, where q_k = (p*p)[k]:

- j = i: a[i] * a[k-i] → (a[i]+Δ) * a[k-i], change = Δ*a[k-i] (valid if 0<=k-i<n)
- k-j = i, i.e., j = k-i: a[k-i] * a[i] → a[k-i] * (a[i]+Δ), change = a[k-i]*Δ (valid if 0<=k-i<n)

These are the SAME term if i = k-i, i.e., k = 2i. In that case, the change is Δ*a[i] + a[i]*Δ = 2Δ*a[i]... no wait, if k = 2i, then j = k-j means j = i, so it's the same term a[i]*a[i], and the change is 2Δ*a[i] + Δ².

For k ≠ 2i: the two terms are distinct (j=i and j=k-i are different), so the total change is 2Δ*a[k-i].

So:
- If 0 <= k-i < n and k ≠ 2i: Δconv[k] = 2Δ*a[k-i]
- If k = 2i (and 0 <= i < n): Δconv[k] = 2Δ*a[i] + Δ²
- Otherwise: Δconv[k] = 0

This means changing a single element a[i] by Δ affects conv[k] for k = 2i (quadratically) and for k = i + j where j is in [0, n-1] (linearly, with coefficient 2Δ*a[j]).

The set of affected k values: k = i + j for j = 0, ..., n-1, i.e., k = i, i+1, ..., i+n-1. That's n consecutive values of k.

So changing a[i] affects n values of the convolution. The max of the convolution can change at any of these n positions.

For coordinate descent: given the current sequence and the current conv, if I change a[i] by Δ, the new conv at position k (for k in [i, i+n-1]) is:
conv_new[k] = conv[k] + 2Δ*a[k-i] (for k ≠ 2i)
conv_new[2i] = conv[2i] + 2Δ*a[i] + Δ²

And conv_new[k] = conv[k] for k not in [i, i+n-1].

The new max is: max(max_{k not in [i,i+n-1]} conv[k], max_{k in [i,i+n-1]} conv_new[k])
= max(conv_max_others, max_{k in [i,i+n-1]} conv_new[k])

where conv_max_others is the max of conv over all k NOT in [i, i+n-1].

If I know conv_max_others and the values of conv in [i, i+n-1], I can efficiently compute the new max for any Δ.

This is the key to an efficient coordinate descent! I can:
1. Precompute conv_max_others for each i (expensive: O(n²) total, but I can update incrementally).
2. For each i, find the optimal Δ (the one that minimizes the resulting max).
3. Update a and conv.

Step 2: The optimal Δ for element i is the one that minimizes:
max(conv_max_others[i], max_{k in [i,i+n-1]} (conv[k] + 2Δ*a[k-i] + [k==2i]*Δ²))

This is a 1D optimization problem. The function is the max of linear (and one quadratic) functions, so it's piecewise linear (with one quadratic piece). The minimum is at a "kink" where two of the pieces cross, or at a boundary.

In the worst case, there are O(n) kinks, so finding the exact minimum takes O(n) per element. With n elements, the total is O(n²) per "pass", which for n=5582 is about 31 million operations. That's fast!

But I also need to track conv_max_others[i] for each i. Initially, I can compute this in O(n²) (for each i, find the max of conv outside [i, i+n-1]). After each update of a[i], I need to update conv_max_others for all j such that i is in [j, j+n-1], i.e., for j in [i-n+1, i]. That's up to n other j values, and updating each takes O(1) if I maintain a data structure.

This is getting complex. Let me simplify:

Simpler approach: For each element i, try a few candidate Δ values (e.g., ±ε, ±2ε, ±4ε for small ε) and pick the best one based on the computed new max. This avoids the exact 1D optimization but is still efficient.

Even simpler: just do random coordinate updates. Pick a random i, change a[i] by a random Δ, evaluate the score, keep if improved.

But evaluating the score from scratch each time is O(n²) (for the convolution). With the incremental update (only n positions change), I can compute the new max in O(n) per evaluation. So each evaluation is O(n) instead of O(n²).

With O(n) per evaluation and n=5582, I can do 2400*10^6 / 5582 ≈ 430,000 evaluations in 2400 seconds. That should be enough for a thorough coordinate descent.
