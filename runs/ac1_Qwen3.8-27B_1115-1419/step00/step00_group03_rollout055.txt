Let me think about what optimization to use. The objective function is:
f(a) = 2n * max_k (convolve(a,a))_k / (sum a)^2

This is a ratio of a max of linear functions (the convolution terms are linear in a... wait, no, they're quadratic! (f*f)[k] = sum a_i * a_j is quadratic in a).

So the objective is a ratio of a quadratic (the max of quadratics) to a quadratic (sum^2). This is a fractional programming problem, which is non-convex in general.

However, we can use the Dinkelbach algorithm or bisection: to check if f(a) <= t, we need max_k (f*f)[k] <= t*(sum a)^2/(2n). But (sum a)^2 is quadratic, so this isn't a simple constraint.

Alternatively, since the objective is scale-invariant, we can fix sum(a) = 1 and minimize max_k (f*f)[k]. Then the objective is 2n * min_max.

With sum(a) = 1: minimize max_k sum_{i+j=k} a_i * a_j.

This is still non-convex (max of quadratics), but we can use general-purpose optimization.

For the LP approach: with fixed a (the current sequence), we solve for x that maximizes sum(x) subject to convolve(a, x) <= M and x >= 0. This IS a linear program (the constraints are linear in x since a is fixed).

Let me implement the LP approach carefully.

The LP:
- Variables: x_0, ..., x_{n-1} (all >= 0)
- Objective: maximize sum(x)
- Constraints: for each k = 0, ..., 2n-2: sum_j A[k,j] * x_j <= M
  where A[k,j] = a_{k-j} if 0 <= k-j < n, else 0.

This gives a (2n-1) x n constraint matrix A.

For n = 1000: 1999 x 1000 matrix = ~2 million entries. Should be fine.
For n = 10000: 19999 x 10000 = ~200 million entries. Might be too slow.
