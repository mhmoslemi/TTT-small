One more thought: the repair function. When we clip and then add diff/n, we might oscillate. A better approach:
- Clip to [0,1]
- If sum > target: sort by value descending, subtract from largest first
- If sum < target: sort by value ascending, add to smallest first

This "water-filling" approach converges in one pass.

```python
def repair_h(h, n):
    h = np.clip(h.astype(float), 0.0, 1.0)
    target = n / 2.0
    diff = target - np.sum(h)
    if abs(diff) < 1e-14:
        return h
    if diff > 0:
        # Need to increase sum: add to values that are < 1, starting with smallest
        order = np.argsort(h)
        remaining = diff
        for i in order:
            add = min(1.0 - h[i], remaining)
            h[i] += add
            remaining -= add
            if remaining < 1e-14:
                break
    else:
        # Need to decrease sum: subtract from values that are > 0, starting with largest
        order = np.argsort(h)[::-1]
        remaining = -diff
        for i in order:
            sub = min(h[i], remaining)
            h[i] -= sub
            remaining -= sub
            if remaining < 1e-14:
                break
    return h
```

This is O(n log n) per call but converges exactly in one pass. Much better than iterative clipping.
