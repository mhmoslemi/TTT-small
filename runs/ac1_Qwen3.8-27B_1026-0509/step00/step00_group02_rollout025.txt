def project_simplex(v, s=1.0):
    n = len(v)
    u = np.sort(v)[::-1]
    cv = np.cumsum(u) - s
    rho = np.nonzero(u * np.arange(1, n + 1) > cv)[0]
    if len(rho) == 0:
        return np.full(n, s / n)
    theta = (cv[rho[-1]] + s) / (rho[-1] + 1)
    return np.maximum(v - theta, 0)

Hmm wait, I realize there might be a performance issue with `np.correlate(w, a, mode='valid')`. Let me check: w has length 2n-1 = 13923, a has length n = 6962. The 'valid' mode gives output of length 13923 - 6962 + 1 = 6962. The computation is 6962 * 6962 ≈ 48.5M multiply-adds. In C, this takes about 10-25ms.

Over 20000 iterations per restart, that's 200-500 seconds per restart. With 30 restarts, that's way too much!

I need to use FFT for the correlation. Let me implement that.

The cross-correlation (w ⋆ a)[j] = sum_{k} w[k] * a[k-j] can be computed as:
- Reverse a: a_rev = a[::-1]
- Compute convolution: conv = convolve(w, a_rev)
- Then (w ⋆ a)[j] = conv[j + n - 1]

Let me verify: (w * a_rev)[m] = sum_k w[k] * a_rev[m-k] = sum_k w[k] * a[n-1-(m-k)] = sum_k w[k] * a[n-1-m+k]

We want (w ⋆ a)[j] = sum_k w[k] * a[k-j].

Setting n-1-m+k = k-j → n-1-m = -j → m = n-1+j.

So (w ⋆ a)[j] = (w * a_rev)[n-1+j].

The convolution w * a_rev has length (2n-1) + n - 1 = 3n-2. We need indices n-1 to n-1+(n-1) = 2n-2.

Using FFT:
```python
def fft_correlate_valid(w, a):
    """Compute (w cross-correlate a) for the valid region, using FFT."""
    n = len(a)
    a_rev = a[::-1]
    conv_len = len(w) + n - 1  # = 3n - 2
    fft_size = 1
    while fft_size < conv_len:
        fft_size *= 2
    W = np.fft.rfft(w, fft_size)
    A = np.fft.rfft(a_rev, fft_size)
    conv = np.fft.irfft(W * A, fft_size)
    return conv[n-1:n-1+n]  # indices n-1 to 2n-2
```

This is O(n log n) per call. Much faster!
