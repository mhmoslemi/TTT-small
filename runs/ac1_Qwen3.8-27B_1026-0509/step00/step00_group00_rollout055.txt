If a_i > a_j, reducing a_i by δ reduces the product by a_j*δ, while reducing a_j by δ reduces it by a_i*δ. Since a_i > a_j, reducing a_j is more effective per unit δ.

Wait, that's the opposite. If a_i > a_j:
- Reducing a_i by δ: product decreases by a_j * δ
- Reducing a_j by δ: product decreases by a_i * δ

Since a_i > a_j, reducing a_j is more effective! This is counterintuitive but correct: the "cross" derivative says the sensitivity of the product to a_j is a_i (the other element), which is larger.

So the strategy is: for each pair contributing to the peak, reduce the smaller element more (or proportionally to the larger element).

Actually, the gradient of (a*a)_k* w.r.t. a_i is a_{k*-i} (times 2 for the symmetric contribution). So the "pressure" on a_i is proportional to a_{k*-i}. The descent direction is:
a_i -= lr * a_{k*-i} (for each i where k*-i is in [0,n-1])

This is like a "flip and subtract" operation: the update direction is the flipped version of a, shifted.

def gradient_step(a, lr):
    """One gradient descent step on max autocorrelation."""
    n = len(a)
    conv = convolve_fft(a)
    k_star = np.argmax(conv)
    # Gradient: 2 * a flipped and shifted by k_star
    # grad[i] = 2 * a[k_star - i] if 0 <= k_star-i < n, else 0
    grad = np.zeros(n)
    lo = max(0, k_star - n + 1)
    hi = min(n, k_star + 1)
    for i in range(lo, hi):
        j = k_star - i
        if 0 <= j < n:
            grad[i] = 2 * a[j]
    # Projected gradient step
    a_new = a - lr * grad
    a_new = np.maximum(a_new, 0)
    # Renormalize
    S = a_new.sum()
    if S < 1e-10:
        return a
    return a_new / S
```

        k_star = np.argmax(conv)
        grad = np.zeros(n)
        lo = max(0, k_star - n + 1)
        hi = min(n, k_star + 1)
        idx = np.arange(lo, hi)
        partners = k_star - idx
        grad[idx] = 2.0 * a[partners]
        
        # Momentum update
        momentum = mu * momentum + (1 - mu) * grad
        a_new = a - lr * momentum
        a_new = np.maximum(a_new, 0)
        S = a_new.sum()
        if S < 1e-6:
            lr *= 0.5
            continue
        a_new /= S

        conv_new = _fft_conv(a_new)
        if conv_new.max() < M * 1.001:  # accept if not much worse

        if it % 500 == 0:
            lr *= 0.92
            beta *= 1.2  # sharpen the peak focus

        if it % 200 == 100:
            n_pert = int(rng.integers(n // 20, n // 3))
            start = int(rng.integers(0, n - n_pert))
            a[start:start+n_pert] *= float(np.exp(rng.normal(0, 0.1)))
            a = np.maximum(a, 0)
            a /= a.sum()
        
        # Evaluate with exact evaluator periodically
        if it % 200 == 0:
            s = evaluate_sequence(a.astype(float).tolist())
            if s < best_score:
                best_score = s
                best_a = a.copy()
    
    # Phase 2: Fine-tuning with block perturbations on best_a
    a = best_a.copy()
    while time.monotonic() < deadline:
        trial = a.copy()
        for _ in range(int(rng.integers(1, 4))):
            width = int(rng.integers(max(2, n // 100), n // 10))
            start = int(rng.integers(0, n - width))
            trial[start:start+width] *= float(np.exp(rng.normal(0, 0.05)))
        trial = np.maximum(trial, 0)
        trial /= trial.sum()
        s = evaluate_sequence(trial.astype(float).tolist())
        if np.isfinite(s) and s < best_score:
            best_score = s
            best_a = trial.copy()
            a = trial.copy()
    
    final = evaluate_sequence(best_a.astype(float).tolist())
    if not np.isfinite(final):
        return [1.0 / n] * n
    return [float(x) for x in best_a]

Each iteration takes about (2n log n + n) ≈ 2 * 4806 * 13 ≈ 125K operations. In numpy, this should be very fast (< 1ms per iteration). So I can do hundreds of thousands of iterations in 1500s.

The key question is: does the single-peak subgradient actually converge to a good solution when started from a non-uniform initial point?

Let me think about it. The "butterfly" subtraction a[i] -= lr * a[k*-i] has the effect of:
- If k* = n-1 (center): a[i] -= lr * a[n-1-i]. This is like a "left-right averaging" that reduces differences between left and right halves.
- If k* = 2r-1 (some other lag): a mixed pairing.

The effect is to reduce the products a[i]*a[k*-i] that contribute to the peak. Over many iterations, this should flatten the autocorrelation.

But there's a subtlety: reducing a[i] to lower the peak at k* might create a new peak at some other lag. The momentum and periodic perturbations should help navigate this.

Let me also consider using the "top-K peaks" approach instead of single peak. I can compute the top-K lags and average their contributions:

- If it makes things much better, keep or slightly increase lr

Starting from a non-uniform sequence, the peak autocorrelation might be above 1/n (the uniform value). The subgradient reduces the peak by "unbalancing" the products. But it also changes the sum (normalized away). The question is whether the iterations reduce the peak below 1/n.

I think the answer is yes, but it requires careful tuning. The key is that the subgradient method is a form of "load balancing" for the autocorrelation: it reduces the products at the hot lags, which flattens the overall autocorrelation profile.

Let me add one more trick: after the subgradient iterations, do a "flattening" step where I directly attack the top peaks by scaling down specific elements.

Actually, I just realized something important. The subgradient direction a[i] -= lr * a[k*-i] can make a[i] go negative (which we clip to 0). This is problematic because it can destroy a lot of the sequence's mass.

A better update: instead of subtracting, use a multiplicative (exponential) update:
a[i] *= exp(-lr * a[k*-i] / a[i]) or something like that.

a_new[i] = a[i] * exp(-lr * grad[i]) / sum_j a[j] * exp(-lr * grad[j])

This is the multiplicative weights / exponential family update. It's always positive and has good convergence properties for constrained optimization.
