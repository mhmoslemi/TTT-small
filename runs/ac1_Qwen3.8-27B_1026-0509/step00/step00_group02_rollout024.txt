To minimize the peak, we want all convolution values to be as equal as possible. The "ideal" would be a convolution that's uniform: each value = (sum a)^2/(2n-1) = 1/(2n-1).

For n=4: ideal max = 1/7 ≈ 0.143. AC1 = 2*4/7 ≈ 1.14.

So a perfectly flat convolution is impossible. But we can get closer than the uniform sequence.

OK so now I have a clearer picture. The problem is to find a nonnegative sequence whose full convolution has minimum peak. This is a non-convex optimization problem, but there are good heuristics.

**Strategy for n=6962:**

1. Start with a random or structured initialization.
2. Use gradient-based local search to reduce the peak.
3. The key gradient information: if the peak is at lag k*, the "coupling" is between a[i] and a[k*-i]. We should reduce the products in high-coupling pairs.

Let me think about the most effective search:

**Approach 1: Multiplicative gradient descent**

For the active peak k*, define the "coupling matrix" C where C[i,j] = 1 if i+j = k* (mod something). Then:
- conv[k*] = sum_{i+j=k*} a[i]*a[j] (for valid i,j)
- Gradient w.r.t. a[m]: 2*a[k*-m] (if valid)

Multiplicative update: a[m] <- a[m] * exp(-eta * (2*a[k*-m] - mean_coupling))

This reduces the elements that are strongly coupled to large partners.

**Approach 2: Iterative peak shaving**

1. Find the peak lag k*.
2. For each pair (i, k*-i) contributing to the peak:
   - If a[i] > a[k*-i]: reduce a[i] and increase a[k*-i] (makes the product smaller by AM-GM)
   - Wait, that increases the product! a[i]*a[k*-i] increases if we make them more equal.
   - To DECREASE the product, we should make them MORE unequal: reduce the smaller one, increase the larger one. But that might increase other convolution values.

Actually, for a fixed sum s = a[i] + a[k*-i], the product a[i]*a[k*-i] is maximized when a[i] = a[k*-i] = s/2, and minimized when one of them is 0 (or as close to 0 as possible).

So to reduce the peak at lag k*, we should make the pairs (i, k*-i) as "unequal" as possible. This suggests concentrating the mass in a few elements.

But if we concentrate mass, the peak at k = 2*index (where the large element pairs with itself) becomes large!

This is the fundamental tension: we want to reduce peak at k* by making pairs unequal, but this creates new peaks at other lags.

The optimal solution balances all lags. This is like a wavelength-balancing problem.

I'll implement a combination of:
1. FFT-based convolution for fast evaluation
2. Gradient-informed moves (reduce the dominant peak by adjusting the contributing elements)
3. Random exploration (to escape local minima)
