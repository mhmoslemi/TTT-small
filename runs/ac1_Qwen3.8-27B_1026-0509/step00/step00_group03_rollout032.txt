Actually, I just realized something important. The subgradient direction depends on `k_star` (the position of the max in the convolution). As we update `f`, `k_star` might change. This makes the optimization non-smooth and potentially chaotic.

One approach to handle this: use a "smoothed" version where we take a weighted average of the subgradients from all positions near the max. This makes the optimization smoother and more stable.

Let me define: `weight[k] = max(0, 1 - ((conv[k] - B) / epsilon)^2)` for some small epsilon, normalized so `sum(weights) = 1`. Then the "smoothed subgradient" is:
`sg_smooth[i] = 4n/A^2 * (sum_k weight[k] * f[k-i] - B/A)`

This is a convex combination of the subgradients from different max positions, giving a smoother direction.

But this adds O(n * |K|) cost per iteration, where |K| is the number of "near-max" positions. If I limit |K| to, say, 10, it's O(10n) which is fine.

Let me implement this:

```python
def smoothed_subgrad(f, epsilon=0.01):
    A = np.sum(f)
    conv = np.convolve(f, f)
    B = conv.max()
    
    # Find positions within epsilon*B of the max
    mask = conv >= B * (1 - epsilon)
    positions = np.where(mask)[0]
    if len(positions) > 20:
        # Take top 20
        idx = np.argsort(conv[positions])[::-1][:20]
        positions = positions[idx]
    
    # Weighted subgradient
    weights = (conv[positions] - B * (1 - epsilon)) / max(1e-15, B * epsilon)
    weights = np.clip(weights, 0, 1)
    if weights.sum() > 0:
        weights = weights / weights.sum()
    else:
        weights = np.ones(len(positions)) / len(positions)
    
    # Compute weighted average of f[k-i] for each i
    weighted_f = np.zeros(n)
    for w, k in zip(weights, positions):
        j = k - np.arange(n)
        valid = (j >= 0) & (j < n)
        weighted_f[valid] += w * f[j[valid]]
    
    sg = 4.0 * n / A**2 * (weighted_f - B/A)
    return sg, B, A
```
