OK I realize the coordinate descent approach with the full score function is more complex than I initially thought. Let me use a simpler but effective approach.

Key insight: the score is 2n * max_c / S^2. Since it's scale-invariant, I can fix S = 1 (normalize after each step) and minimize max_c.

With S fixed to 1:
- When I change a[j] from v to x, the new sum is S' = 1 - v + x.
- To maintain S = 1, I'd need to rescale all other coordinates. That's complex.

Alternative: don't fix S. Instead, minimize the full score function.

Let me use a different approach entirely. Let me use the LP-based method from the problem description, which is known to converge:

1. Start with binomial sequence a
2. Compute M = max(convolve(a, a))
3. Solve LP: max sum(g) s.t. convolve(a, g) ≤ M, g ≥ 0
4. Rescale g: g = g * S_a / S_g (so sum(g) = sum(a))
5. Update: a ← (1-t)*a + t*g
6. Repeat

This is a "multiplicative weight" type update and should converge.

The key advantage is that step 3 is a LINEAR program (fix a, vary g). The constraint convolve(a, g) ≤ M is linear in g.

Let me implement this properly.

For the LP:
- Variables: g[0], ..., g[n-1] (n = 2535 variables)
- Objective: maximize sum(g)
- Constraints:
  - For k = 0, ..., 2n-2: sum_{j: valid} a[k-j] * g[j] ≤ M (2n-1 = 5069 constraints)
  - g[j] ≥ 0 for j = 0, ..., n-1 (2535 constraints, handled by nonnegativity)

Total: 2535 variables, 5069 inequality constraints.

The constraint matrix A (5069 × 2535) has:
- A[k, j] = a[k-j] if 0 ≤ k-j < n, else 0
- Nonzeros: for each j, the valid k range is j to j+n-1, so n nonzeros per column, total n^2 = ~6.4M nonzeros.

For n=2535, the dense matrix would be 5069*2535*8 ≈ 103 MB. That's fine.
The sparse matrix would be ~6.4M nonzeros × (row + col + value) = ~6.4M × 20 bytes ≈ 128 MB. Also fine.
