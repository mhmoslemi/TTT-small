**Alternative: Use the dual LP**

The dual of:
maximize `sum(g)` s.t. `A @ g <= M * ones`, `g >= 0`

is:
minimize `M * sum(y)` s.t. `A^T @ y >= ones`, `y >= 0`

where `y` has `2n-1` components.

The constraint `A^T @ y >= ones` means:
For each `j`: `sum_{k: A[k,j] != 0} A[k,j] * y[k] >= 1`
= `f_norm[j] * sum_{k=j}^{j+n-1} y[k] >= 1`
= `sum_{k=j}^{j+n-1} y[k] >= 1/f_norm[j]`

So the dual is:
minimize `M_norm * sum(y)` s.t. `sum_{k=j}^{j+n-1} y[k] >= 1/f_norm[j]` for `j=0,...,n-1`, `y >= 0`

The constraint matrix for the dual is a "sliding window" matrix:
- Variables: `y[0], ..., y[2n-2]` (2n-1 variables)
- Constraint j: `y[j] + y[j+1] + ... + y[j+n-1] >= 1/f_norm[j]`

This is a matrix with `n` rows and `2n-1` columns, where row `j` has 1's in columns `j` to `j+n-1` and 0's elsewhere.

The total number of non-zeros is `n * n = n^2` (same as before!). So the memory is the same.

But the dual has fewer constraints (n vs 2n-1) and more variables (2n-1 vs n). For LP solvers, having more constraints than variables is usually preferred (since the basis is determined by the active constraints). So the primal (n variables, 2n-1 constraints) is actually better for the solver.
