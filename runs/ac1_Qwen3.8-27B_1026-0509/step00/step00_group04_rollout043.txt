```python
def project_simplex(v):
    """Project v onto {x >= 0, sum(x) = 1}."""
    # Sort-based projection
    n = len(v)
    u = np.sort(v)[::-1]
    cssv = np.cumsum(u)
    rho = np.where(u * np.arange(1, n+1) > (cssv - 1))[0][-1]
    theta = (cssv[rho] - 1) / (rho + 1)
    return np.maximum(v - theta, 0)
```

Let me try a different approach: instead of gradient descent on max(b), use a "level set" method.

Algorithm:
1. Set a target level t (initially t = max(b) for the current a).
2. Find the minimum of b[k*] - t subject to sum(a) = 1, a >= 0, and b[k] <= t for all k ≠ k* (or for all k).
3. Update a.
4. Decrease t.

This is essentially bisection on t: for a given t, check if there exists a >= 0, sum(a) = 1, b[k] <= t for all k. If yes, decrease t; if no, increase t.

The feasibility check "b[k] <= t for all k" is a system of quadratic inequalities, which is hard to check exactly.

Alternatively, I can use the following heuristic:
1. Start with a (e.g., ramp, normalized).
2. Compute b, find k*.
3. Solve: minimize b[k*] subject to sum(a) = 1, a >= 0, and b[k] <= M_current for all k ≠ k*.
   (Only constrain the active constraint b[k*] <= M, and keep the others at their current level.)
4. This is a quadratic program (QP): minimize a^T Q a subject to 1^T a = 1, a >= 0, a^T R_k a <= M for k ≠ k*.
   Where Q = R_{k*} (the matrix for b[k*]).

But this QP has O(n^2) constraints (one for each k ≠ k*), which is too many.

Simpler: just minimize b[k*] subject to sum(a) = 1, a >= 0. (Ignore the other constraints.)
This is: minimize sum_i a[i]*a[k*-i] subject to sum(a) = 1, a >= 0.

The solution to this is: put all mass on the "least contributing" elements. Specifically, if k* is in the "middle" (k* ≈ n), then b[k*] = sum a[i]*a[k*-i], and the minimum is achieved by putting mass on a[0] and a[n-1] (the endpoints, which don't overlap at lag k*).

But if we put all mass at a[0] and a[n-1], then b[0] = a[0]^2 and b[2n-2] = a[n-1]^2 become the new peaks!

So the "minimize the current peak" approach leads to oscillation: we reduce b[k*], but create new peaks elsewhere.

The correct approach is to minimize the MAX of all b[k] simultaneously, which is the original problem. And that's what the gradient descent on max(b) does (approximately, since we only use the gradient of the current max).

I think the practical solution is:
1. Use gradient descent with the multiplicative weights update
2. Use a "running average" of the gradient to smooth out oscillations
3. Periodically re-evaluate and keep the best

Let me also consider: what if I use a "top-k" approach? Instead of just the argmax, use the top k elements of b in the gradient. This gives a "soft max" that's smoother:

grad[j] = (1/k) * sum_{k in top_k} 2*a[k-j] (for valid j)

This is smoother and might avoid oscillation. Let me use k = 5 or 10.

Actually, an even better approach: use the "softmax" of b:
w_k = exp(b[k] / tau) / sum exp(b[j] / tau) for a small tau > 0.
Then the "smooth max" is tau * log(sum exp(b/tau)), and its gradient is:
d/d a[j] [tau * log(sum exp(b/tau))] = sum_k w_k * db[k]/da[j]

This is a convex function of a (since it's a sum of convex functions... wait, b[k] = a^T R_k a is not convex in a as we showed). So the softmax approach doesn't make the problem convex either.

But it does make the gradient smoother, which might help convergence.

Let me implement the softmax approach:

```python
# Softmax of b
tau = 0.1  # Temperature
b_shifted = b - b.max()  # For numerical stability
w = np.exp(b_shifted / tau)
w /= w.sum()

# Gradient of smooth max
grad = np.zeros(n)
for k in range(len(b)):
    if w[k] < 1e-10:
        continue
    j_min = max(0, k - n + 1)
    j_max = min(n - 1, k)
    js = np.arange(j_min, j_max + 1)
    kjs = k - js
    grad[js] += w[k] * 2.0 * a[kjs]
```
