**Alternative: Direct coordinate descent with line search**

At each step:
1. Find k* = argmax conv_k
2. Pick a coordinate i to modify
3. Determine the direction (increase or decrease a_i)
4. Do a line search along that coordinate to minimize the max conv

For a single coordinate change a_i -> a_i + delta:
- conv_k changes by: 2*delta*a_{k-i} + delta^2 (if k-i == i)
  More precisely: conv_k = sum_j a_j * a_{k-j}. If we change a_i by delta:
  Δconv_k = delta * (a_{k-i} + a_{k-i}) = 2*delta*a_{k-i} (for k != 2i)
  Δconv_k = 2*delta*a_i + delta^2 (for k = 2i)
  
  Wait, more carefully: conv_k = sum_j a_j * a_{k-j}. Changing a_i by delta:
  The terms involving a_i are: a_i * a_{k-i} and a_{k-i} * a_i (if k-i != i), or a_i^2 (if k-i = i).
  So Δconv_k = delta * a_{k-i} + a_{k-i} * delta = 2*delta*a_{k-i} (for k-i != i)
  And Δconv_k = 2*delta*a_i + delta^2 (for k-i = i, i.e., k = 2i)
  
  But we also need k-i to be valid (0 <= k-i < n).

So for a given coordinate i and direction (increase/decrease), the new conv_k values are:
new_conv_k = conv_k + 2*delta*a_{k-i} (for valid k-i, k != 2i)
new_conv_k = conv_k + 2*delta*a_i + delta^2 (for k = 2i)

We want to choose delta to minimize max(new_conv_k). This is a 1D optimization problem!

The function g(delta) = max_k (conv_k + 2*delta*a_{k-i}) (ignoring the quadratic term for simplicity) is a convex piecewise-linear function of delta. Its minimum can be found by bisection or by finding the crossing point.

This gives us an efficient coordinate descent algorithm:
- Each coordinate update is O(n) (compute the new max)
- We cycle through all n coordinates: O(n^2) per full sweep
- For n = 2535, that's about 6.4M per sweep, which is fine

But we need to be smarter about which coordinates to update. Updating a_i affects conv_k for k in [i, i+n-1] (all k where k-i is valid). So we only need to check those lags.
