**Approach: Iterative flattening**

The idea is to iteratively modify the sequence to make its autocorrelation flatter. At each step:
1. Compute the autocorrelation `b[k]`
2. Identify the lags where `b[k]` is above the mean
3. Modify the sequence to reduce `b[k]` at those lags

The modification that reduces `b[k]` at a specific lag is to decrease the product `a[j]*a[k-j]` for the pairs that make up `b[k]`. The most effective way is to decrease the larger of the two values.

This is similar to the "water-filling" approach: pour water (reduce values) into the positions that contribute most to the peaks.

The objective is to minimize `max(b)`. This is a min-max problem. A standard approach is to use the "barrier" or "log-sum-exp" method:

Minimize `log(sum exp(b[k]/tau))` for small `tau`. This approximates `max(b[k])` as `tau -> 0`.

The gradient of `log(sum exp(b[k]/tau))` w.r.t. `a[i]` is:
`(1/tau) * sum_k p_k * db[k]/da[i]`
where `p_k = exp(b[k]/tau) / sum_j exp(b[j]/tau)` is the softmax.

So the gradient is `(2/tau) * sum_k p_k * a[k-i]`.

For small `tau`, the softmax is concentrated on the peak, and this reduces to the single-peak gradient.

For larger `tau`, it spreads the gradient over multiple peaks, which helps avoid getting stuck on a single peak.

So: `db[k]/da[i] = 2*a[k-i]` when `k-i` is in [0, n-1], else 0.
(Special case i = k/2: `2*a[k/2] = 2*a[i]`, consistent.)

Now, the gradient of `(1/K) * sum_{k in topK} b[k]` w.r.t. `a[i]`:
`= (1/K) * sum_{k in topK} 2*a[k-i]` (where k-i in [0,n-1])
`= (2/K) * sum_{k in topK} a[k-i] * 1[k-i in [0,n-1]]`

For a fixed `i`, the sum is over all `k in topK` such that `0 <= k-i < n`, i.e., `i <= k < i+n`.
So: `= (2/K) * sum_{k in topK, i <= k < i+n} a[k-i]`

Let `j = k - i`: `= (2/K) * sum_{j=0}^{n-1} a[j] * 1[k=j+i in topK and 0 <= j+i < half]`
`= (2/K) * sum_{j=0}^{n-1} a[j] * ind[j+i]`

where `ind` is the indicator of topK lags (padded to length `half`).

This is exactly `(2/K) * (ind ⋆ a)[i]` where `⋆` is cross-correlation.

And the cross-correlation via FFT: `ifft(fft(ind, N) * conj(fft(a, N)))[:n]`

Let me verify: `ifft(fft(ind) * conj(fft(a)))` gives the circular cross-correlation.
For our case with N >= n + half - 1 = n + 2n - 2 = 3n - 2, there's no circular aliasing.
With N = 16384 and 3n-2 = 14416, we're fine.

So the gradient computation is correct.

- `grad[i] ≈ (2/K) * K = 2`
- So `grad_mag ≈ 2` and `lr ≈ 0.01/2 = 0.005`

This gives an update of `lr * v ≈ 0.005 * 2 = 0.01` per step, which is small relative to `a ≈ 1`. That's reasonable.

An alternative approach that might work better: **Alternating direction method**.

1. Fix the peak lag `k*` (the one with maximum autocorrelation)
2. Solve: minimize `b[k*]` subject to `sum(a) = n` and `a >= 0`
   - This is: minimize `sum_j a[j]*a[k*-j]` subject to constraints
   - The optimal solution (ignoring nonnegativity) is found by eigendecomposition
   - With nonnegativity, it's a QP (quadratic program)
3. After updating, recompute the peak and go to step 1

But solving a QP at each step is expensive for n=4806.

Actually, the problem `minimize sum_j a[j]*a[k*-j] subject to sum(a)=n, a>=0` has a special structure. The objective is `a^T Q_{k*} a` where `Q_{k*}` is a symmetric matrix (the "shift" matrix). The unconstrained minimum is at `a = 0`, so the constraint `sum(a) = n` is active.

Using Lagrange multipliers: minimize `a^T Q a - lambda * sum(a)` subject to `a >= 0`.
KKT conditions: `2*Q*a - lambda*1 + mu = 0` where `mu >= 0`, `mu*a = 0`.

This is a linear system! `2*Q*a = lambda*1 - mu`. For the active set where `a > 0`, `mu = 0`, so `2*Q*a = lambda*1`.

The solution depends on the active set, which is determined by the complementarity condition. This is essentially a linear complementarity problem (LCP), which can be solved efficiently.

But for n=4806, even a single LCP solve might take a few seconds. And we'd need many iterations.

Let me stick with the gradient approach but make it more effective.

**Key insight for a better gradient**: Instead of using a hard "top-K" selection (which is noisy), I should use a smooth softmax weighting over ALL lags. This gives a differentiable, smooth gradient.

`F_smooth = tau * log(sum_k exp(b[k]/tau))`

`dF_smooth/da[i] = (2/tau) * sum_k p_k * a[k-i]` where `p_k = exp(b[k]/tau) / sum_j exp(b[j]/tau)`

This is smooth and well-defined for all `a`. The gradient can be computed efficiently via FFT.

The only concern is the computational cost of computing the softmax. For `2n-1 = 9611` lags, this is O(n) per iteration, which is fine.

Let me use this approach with an adaptive temperature `tau`:
- Start with large `tau` (all lags contribute equally, gradient is smooth)
- Gradually decrease `tau` (gradient focuses on the peaks)
- This is like simulated annealing
