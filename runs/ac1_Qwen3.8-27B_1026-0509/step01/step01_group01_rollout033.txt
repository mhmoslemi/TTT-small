**Alternative approach: Spectral method**

The auto-convolution `c[k] = sum_j a[j] a[k-j]` can be written in the frequency domain as `C(ω) = A(ω)^2` where `A(ω) = FFT(a)`. We want to minimize `max_k c[k]`.

By Parseval: `sum_k c[k]^2 = (1/L) sum_ω |C(ω)|^2 = (1/L) sum_ω |A(ω)|^4` (where L is the FFT length).

Also: `c[k] = (1/L) sum_ω C(ω) e^{iωk} = (1/L) sum_ω A(ω)^2 e^{iωk}`.

So `c[k]` is the inverse FFT of `A(ω)^2`. We want to choose `A(ω)` (with the constraint that its inverse FFT is nonnegative and sums to 1) to minimize `max_k c[k]`.

This is a complex optimization problem. But we can use the following heuristic:
- If `|A(ω)|` is flat (white spectrum), then `|A(ω)^2|` is also flat, and `c[k]` is a delta at k=0. That gives a peaked convolution - bad.
- If `|A(ω)|` is concentrated at ω=0 (low-pass), then `c[k]` is spread out - better, but the peak at k=0 is still `sum a[j]^2`.
- If `|A(ω)|` has a specific shape, we can control the shape of `c[k]`.

The key is: `A(ω)^2` (not `|A(ω)|^2`) determines `c[k]`. The PHASE of `A(ω)` matters! For a real nonnegative sequence, `A(ω)` has a specific phase relationship (Hermitian symmetry), but the phase is not zero in general.

This is the key difference between auto-convolution and autocorrelation. For autocorrelation, only `|A(ω)|^2` matters (the phase cancels). For auto-convolution, `A(ω)^2` matters, which depends on both magnitude and phase.

So the problem is: find a nonnegative sequence `a` whose DFT `A(ω)` has `A(ω)^2` as "flat" (in the sense of having small peak in the time domain) as possible.

One approach: start with a candidate `a`, compute `A(ω)`, modify `A(ω)` to flatten `A(ω)^2`, then take the inverse FFT and project back to nonnegative.

The "flattening" step: we want `c[k] = IFFT(A(ω)^2)` to be as flat as possible. So we want `A(ω)^2 ≈ constant` (in the frequency domain of `c`). This means `A(ω) ≈ sqrt(constant)` in magnitude, with some phase.

But `A(ω) = sqrt(c_target(ω))` where `c_target(ω) = FFT(c_target)`. If we want `c_target` to be flat, then `c_target(ω)` is concentrated at ω=0, which means `A(ω)` should be a narrow pulse. But that corresponds to a broad `a`, which brings us back to the all-ones sequence.

- Invert `A A^T`: O(m^3)
- Compute `Δa`: O(m * n)

```python
def newton_step(a, active, max_iter=10):
    n = len(a)
    m = len(active)
    # Form A: m x n matrix where A[i,j] = a[active[i] - j]
    # Compute A @ A^T (m x m)
    ATA = np.zeros((m, m))
    for i in range(m):
        pos_i = active[i]
        lo_i = max(0, pos_i - n + 1)
        hi_i = min(n, pos_i + 1)
        a_i = a[pos_i - hi_i + 1:pos_i - lo_i + 1][::-1]
        for j in range(i, m):
            pos_j = active[j]
            lo_j = max(0, pos_j - n + 1)
            hi_j = min(n, pos_j + 1)
            a_j = a[pos_j - hi_j + 1:pos_j - lo_j + 1][::-1]
            # Dot product of a_i with a_j (padded to length n)
            # a_i is at positions [lo_i, hi_i) in the n-dim space
            # a_j is at positions [lo_j, hi_j) in the n-dim space
            # Overlap: [max(lo_i, lo_j), min(hi_i, hi_j))
            lo = max(lo_i, lo_j)
            hi = min(hi_i, hi_j)
            if hi > lo:
                ATA[i,j] = np.dot(a_i[lo-lo_i:hi-lo_i], a_j[lo-lo_j:hi-lo_j])
            ATA[j,i] = ATA[i,j]
    
    # Solve (ATA) * alpha_vec = ones(m)
    try:
        alpha_vec = np.linalg.solve(ATA + 1e-10 * np.eye(m), np.ones(m))
    except np.linalg.LinAlgError:
        alpha_vec = np.linalg.lstsq(ATA, np.ones(m), rcond=None)[0]
    
    # Compute grad = A^T @ alpha_vec
    grad = np.zeros(n)
    for i in range(m):
        if abs(alpha_vec[i]) < 1e-15:
            continue
        pos_i = active[i]
        lo_i = max(0, pos_i - n + 1)
        hi_i = min(n, pos_i + 1)
        a_i = a[pos_i - hi_i + 1:pos_i - lo_i + 1][::-1]
        grad[lo_i:hi_i] += alpha_vec[i] * a_i
    
    return grad
```
