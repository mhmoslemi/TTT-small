The problem is that for any "smooth" profile that's high on one side and low on the other, the autocorrelation will have a peak at an intermediate lag where the "overlap" of the high and low parts creates a large product sum.

Let me think about what profile actually minimizes the peak autocorrelation.

Going back to basics: we want to minimize max_k b[k] subject to sum a = 1, a >= 0.

The Lagrangian approach (for the smooth case, ignoring the max):
minimize b[k*] (for the binding k*)
subject to sum a = 1, a >= 0.

∂b[k*]/∂a[j] = 2*a[k*-j] (if 0<=k*-j<n).

Setting the gradient proportional to 1 (for the sum constraint):
2*a[k*-j] = λ for all j with 0<=k*-j<n.

This means a[j] is constant for j in the range [0, min(n-1, k*)] (the range where k*-j is in [0,n-1]). Specifically, a[j] = λ/2 for j in [max(0, k*-n+1), min(n-1, k*)] and a[j] = 0 elsewhere (to satisfy a >= 0 and minimize).

Wait, that's not quite right. The KKT conditions are:
∂b[k*]/∂a[j] - λ + μ[j] = 0 where μ[j] >= 0 and μ[j]*a[j] = 0.

If a[j] > 0: ∂b[k*]/∂a[j] = λ, i.e., 2*a[k*-j] = λ (a constant).
If a[j] = 0: ∂b[k*]/∂a[j] <= λ.

So for a[j] > 0, we need a[k*-j] to be constant. This means a is constant on the "reflected" set.

If k* = n-1 (center): a[j] > 0 implies a[n-1-j] = constant. So a is symmetric and constant where positive. That gives the "block" solution, which we've seen gives T = 2n/m >= 2.

If k* < n-1 (off-center): a[j] > 0 implies a[k*-j] = constant. This is a more complex constraint.

For example, if k* = 1: a[j] > 0 implies a[1-j] = constant. So a[0] and a[1] are both positive and a[1] = a[0] = constant. And a[j] = 0 for j >= 2 (since for j >= 2, k*-j = 1-j < 0, so ∂b[1]/∂a[j] = 0 <= λ).

So the solution is a = [c, c, 0, 0, ...]. b[0] = c^2, b[1] = 2c^2, b[2] = c^2. max = 2c^2. sum = 2c. T = 2n*2c^2/4c^2 = n. Terrible.

OK so single-lag optimization doesn't work well. The issue is that we need to balance ALL lags simultaneously.

Let me think about this differently. The optimal solution should have the autocorrelation "as flat as possible." This is like the "Burckardt" or "Golomb" sequence problem, but for nonnegative sequences.

For complex sequences, the ideal is a "perfect" autocorrelation (impulse at lag 0, zero elsewhere). For nonnegative sequences, this is impossible, but we can get a "low" autocorrelation.

I think the practical approach is:
1. Use a good initialization (not uniform, but something that already gives T < 2).
2. Use iterative optimization to reduce T further.
