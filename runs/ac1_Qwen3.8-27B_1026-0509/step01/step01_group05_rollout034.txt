Actually, let me think more carefully about the optimization. The key challenge is that the max is non-smooth. A common technique is to use a "smooth max" approximation:

soft_max(c, τ) = τ * log(sum(exp(c/τ)))

As τ → 0, this approaches max(c). For finite τ, it's smooth and its gradient is:
∂soft_max/∂c[k] = exp(c[k]/τ) / sum(exp(c[j]/τ))

This gives a weighted average of the individual gradients, where the weights are proportional to exp(c[k]/τ). This effectively considers all "near-max" lags, not just the single max.

For the optimization:
F(a) ≈ 2n * soft_max(c, τ) / S^2

The gradient with respect to a is:
∂F/∂a[m] = 2n/S^3 * (S * ∂soft_max/∂a[m] - 2*soft_max)

where ∂soft_max/∂a[m] = sum_k w[k] * ∂c[k]/∂a[m] = sum_k w[k] * 2*a[k-m]

w[k] = exp(c[k]/τ) / sum_j exp(c[j]/τ)

This is a weighted sum of the individual lag gradients. For small τ, it's dominated by the max lag. For larger τ, it's a smoother approximation.

This is essentially a "trust region" style approach that considers multiple lags simultaneously.

Let me implement this with adaptive τ:
- Start with a moderate τ (e.g., τ = 0.1 * max(c))
- Decrease τ over time for sharper optimization
- Use Nesterov momentum for acceleration

Let me also consider the "dual" approach more carefully. The LP from the SOTA:
maximize sum(b)
subject to: (f*b)[k] <= M for all k
            b >= 0

where M = max(f*f). This finds the "best response" b to f. Then we update f toward b.

The intuition is: if f is the current "chaser" signal, b is the "target" signal that would be hardest to detect (maximizing sum while keeping the cross-correlation bounded). By moving f toward b, we make f harder to correlate with itself, reducing the peak.

This LP has:
- n = 4806 variables (b[0], ..., b[n-1])
- 2n-1 = 9611 constraints (f*b)[k] <= M for k = 0, ..., 2n-2
- n = 4806 constraints b[i] >= 0

Total: 14417 constraints. This is a large LP but solvable.

Using scipy.optimize.linprog with method='highs' (HiGHS solver), this should be fast. But I need to be careful about the formulation.

(f*b)[k] = sum_j f[j]*b[k-j] <= M

This is a linear constraint in b. The constraint matrix A has rows corresponding to k=0,...,2n-2 and columns corresponding to b[0],...,b[n-1]. Entry A[k, j] = f[j] if 0 <= k-j <= n-1, else 0.

This matrix is banded (bandwidth n), so it's sparse. For n=4806, the matrix has 9611*4806 ≈ 46M entries, but only about 2*4806*4806/2 ≈ 23M are nonzero (each row has at most n nonzeros, and there are 2n-1 rows).
