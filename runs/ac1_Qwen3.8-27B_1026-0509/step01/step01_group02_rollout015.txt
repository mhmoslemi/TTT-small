One key insight: if we make the sequence "ramped" (increasing or decreasing), the self-convolution will have its peak away from the center, and we might be able to flatten it more.

Let me think about a specific example. Take `a[i] = c*(i+1)` for i=0,...,n-1 (linearly increasing). Then:
`(a*a)[k] = c^2 * sum_{i} (i+1)(k-i+1)` (with valid range)

This is a well-known calculation. For a linear ramp, the self-convolution is a cubic polynomial. The peak is at the center for a symmetric ramp, but for a one-sided ramp, the peak shifts.

Actually, I think the best approach is to just do a good optimization. Let me think about what makes this problem hard:

1. High dimensionality (4806)
2. Non-smoothness (the max in the objective)
3. Non-negativity constraint

For the non-smoothness, the subgradient approach works but can be slow. An alternative is to use a smooth approximation of the max (e.g., soft-max) and then optimize that.

Let me try a different approach: use the "LogSumExp" trick to approximate the max, then use gradient descent on the smooth approximation.

`max_k c[k] ≈ (1/beta) * log(sum exp(beta * c[k]))`

For large beta, this is close to the max. We can increase beta over time.

The gradient of `log(sum exp(beta*c[k]))` wrt `a[j]` is:
`beta * sum_k (exp(beta*c[k])/sum exp(beta*c[k])) * d c[k]/d a[j]`

And `d c[k]/d a[j] = 2*a[k-j]` (as computed before).

So the gradient is:
`beta * sum_k p_k * 2*a[k-j]` where `p_k = exp(beta*c[k])/sum exp(beta*c[k])`

This is a weighted average of the "shifted and reversed" versions of `a`, weighted by the softmax of the convolution values.

This can be computed efficiently: if we define `w[k] = 2*p[k]`, then the gradient is the cross-correlation of `a` with `w`, which can be computed via FFT!

Specifically: `grad[j] = sum_k w[k] * a[k-j]` (with appropriate boundary handling).

This is essentially a convolution/cross-correlation, computable in O(n log n).

This is much smoother than the pure subgradient and should converge faster.

Let me also think about the denominator. If we normalize `sum a = 1`, the denominator is 1 and we just minimize `max_k c[k]`. The gradient of the smooth approximation is just the cross-correlation above.

But we also need to handle the constraint `sum a = 1`. We can do this by:
1. Computing the unconstrained gradient step
2. Projecting onto `a >= 0`
3. Normalizing to `sum a = 1`

Or we can use a Lagrange multiplier approach.

Let me also consider: instead of normalizing at each step, we can work in the unnormalized space and let the optimizer figure out the scaling. Since the objective is scale-invariant, the optimizer will naturally find a direction that improves the shape.

Actually, for a scale-invariant objective, the gradient is orthogonal to the scaling direction. So the gradient automatically preserves the sum (up to numerical error). Let me verify:

`f(a) = 2n * max_k (a*a)[k] / (sum a)^2`

`d f / d a[j] = 2n * [2*a[k*-j] * (sum a)^2 - max_c * 2*(sum a)*a[j]] / (sum a)^4`
`= 4n * [a[k*-j] * (sum a) - max_c * a[j]] / (sum a)^3`

`= 4n / (sum a)^3 * [(sum a)*(sum a) - max_c * (sum a)]`
`= 4n * (sum a) * (sum a - max_c) / (sum a)^3`
`= 4n * (sum a - max_c) / (sum a)^2`

This is not zero in general, so the gradient is NOT orthogonal to the uniform direction. This means the objective is not truly scale-invariant in the sense that the gradient doesn't point in the scaling direction... wait, that contradicts scale invariance.

Let me verify: `f(c*a) = 2n * max_k ((ca)*(ca))[k] / (sum ca)^2 = 2n * c^2 * max_k (a*a)[k] / (c*sum a)^2 = f(a)`. Yes, it's scale-invariant.

So `sum_j a[j] * d f / d a[j]` should be 0. Let me check my gradient formula.

`d f / d a[j] = 4n * [a[k*-j] * S - max_c * a[j]] / S^3` where S = sum a.

`sum_j a[j] * d f / d a[j] = 4n/S^3 * [S * sum_j a[j]*a[k*-j] - max_c * sum_j a[j]^2]`

Now `sum_j a[j]*a[k*-j]` is the self-convolution at lag k*, which is `max_c` (by definition).

So: `= 4n/S^3 * [S * max_c - max_c * sum_j a[j]^2]`
`= 4n * max_c / S^3 * [S - sum_j a[j]^2]`

This is zero only if `sum_j a[j]^2 = S`, which is not true in general. So I must have made an error.

Let me recompute the gradient more carefully.

Let `g(a) = max_k (a*a)[k]` and `h(a) = (sum a)^2`.

`f = 2n * g / h`.

`d f / d a = 2n * (g' * h - g * h') / h^2`

where `g' = grad g` and `h' = grad h = 2*(sum a) * 1` (the vector of all 2*(sum a)).

At the point where the max is at k*: `g'[j] = 2*a[k*-j]` (as before).

So: `d f / d a[j] = 2n * [2*a[k*-j] * S^2 - max_c * 2*S] / S^4`
`= 4n * [a[k*-j] * S - max_c] / S^3`

Wait, I had an error before. Let me redo:

`h = S^2` where `S = sum a`.
`h'[j] = 2S` (same for all j).

`d f / d a[j] = 2n * (g'[j] * h - g * h'[j]) / h^2`
`= 2n * (2*a[k*-j] * S^2 - max_c * 2*S) / S^4`
`= 2n * 2*S * (a[k*-j]*S - max_c) / S^4`
`= 4n * (a[k*-j]*S - max_c) / S^3`

OK so the correct gradient is `4n * (a[k*-j]*S - max_c) / S^3`.

`d f / d x[i] = sum_j (d f / d a[j]) * (d a[j] / d x[i])`
`= sum_j (d f / d a[j]) * a[j] * (delta(j,i) - a[i])`
`= a[i] * (d f / d a[i]) - a[i] * sum_j a[j] * (d f / d a[j])`

`d f / d x[i] = a[i] * (d f / d a[i])`

This is just the gradient element-wise scaled by `a[i]`. This is nice!

And since `a = softmax(x)`, we have `a[i] * (d f / d a[i])` which is well-defined and smooth (as long as `a[i] > 0`).
