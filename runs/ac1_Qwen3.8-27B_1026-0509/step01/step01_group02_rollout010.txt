Now, for the actual optimization, let me think about the strategy:

1. The max-based subgradient is the true subgradient of the objective. It's non-smooth and can cause oscillations.
2. The smooth gradient (sum of squares) is smooth and easy to compute via FFT, but it's a surrogate.
3. A good approach: use the smooth gradient for most iterations (fast, smooth), and occasionally check the actual max to track the true objective.

Here's my refined plan:

```
For each iteration:
  1. Compute c = autocorrelation of p (FFT, O(n log n))
  2. Compute smooth gradient g_s = 4 * crosscorr(c, p) (FFT, O(n log n))
  3. Update momentum: mom = beta * mom + (1-beta) * g_s
  4. Step: p = project(p - alpha * mom)
  5. Every M iterations: compute true score, update best
```

Total per iteration: 2 FFT operations of size 16384 ≈ 0.5 ms.
In 1400 seconds: ~2,800,000 iterations. That should be enough.

Actually, let me think about this differently. Instead of gradient descent on the smooth objective, let me use a "power iteration" style approach:

At each step, compute c = p*p (autocorrelation). The "direction" to update is related to c: if c is peaked at some k, we want to reduce p at the positions that contribute to c_k.

For the max objective, the descent direction is -2 * R_{k*}(p) where k* = argmax c.

The smooth direction is a weighted average of the max direction, with weights c_k. So it's a "smoothed" version of the max direction. This should work well.

The key insight is: the autocorrelation c = p*p has 2n-1 entries. The "peak" of c (the maximum) is what we want to minimize. The smooth gradient approach (minimizing sum c^2) will tend to flatten c, which helps, but it also spends effort reducing the already-small values of c.

A better approach: focus on reducing the peak. The subgradient of max(c) at the current point is the gradient of the active constraint(s). This directly targets the peak.

The problem with pure subgradient is that it's non-smooth and can oscillate. The solution is to:
1. Use momentum to smooth the direction
2. Use the top-K active constraints (not just the argmax) for a more stable direction
3. Use a diminishing step size
