**Speeding up the LP:**

The LP is:
`min t`
s.t. `T @ b <= t * 1` (2n-1 constraints)
`1^T b = 1`
`b >= 0`

where T is the (2n-1) × n convolution matrix for the fixed sequence `a`.

For n=1200, T has 2399 × 1200 = 2,878,800 entries. Most are zero (banded structure with bandwidth n). The nonzero entries are `a[j]` at position (k, k-j) for valid j.

We can use a sparse representation. In cvxpy, we can build this as a sparse matrix.

Actually, the structure is: row k has nonzeros at positions j where 0 <= k-j < n, i.e., j is in [max(0, k-n+1), min(k, n-1)]. The value at position (k, j) is a[k-j].

This is a Toeplitz-like matrix (each row is a shifted version of a). We can build it efficiently.

**Even better: Use the dual LP!**

The dual is:
`max 1^T y` (i.e., sum of y_k)
s.t. `T^T @ y <= 1` (n constraints)
`y >= 0`

where `(T^T @ y)[j] = sum_k y[k] * T[k,j] = sum_k y[k] * a[k-j]` (for valid k).

This is: `conv(y, a_rev)[j] <= 1` for all j, i.e., the cross-correlation of y with the reversed a is bounded by 1.

The dual has 2n-1 variables (y_0, ..., y_{2n-2}) and n + 2n-1 = 3n-1 constraints. For n=1200, that's 2399 variables and 3599 constraints. Similar size to the primal.

But the dual has a nicer structure: the constraints are `conv(y, a_rev) <= 1`, which is a set of "sliding window" constraints. This structure might be exploitable.

Actually, for LP solvers, the primal and dual should be about equally fast. Let me just focus on using cvxpy efficiently.

```python
from scipy.optimize import linprog
from scipy.sparse import csr_matrix

def solve_lp_sparse(a, n):
    """Solve min t s.t. T@b <= t, sum(b)=1, b>=0."""
    # T is (2n-1) x n, T[k,j] = a[k-j] if valid
    rows = []
    cols = []
    vals = []
    for k in range(2*n-1):
        j_start = max(0, k-n+1)
        j_end = min(k, n-1)
        for j in range(j_start, j_end+1):
            rows.append(k)
            cols.append(j)
            vals.append(a[k-j])
    T = csr_matrix((vals, (rows, cols)), shape=(2*n-1, n))
    
    # Full constraint matrix: [T, -1; 1^T, 0] with RHS [t_max; 1]
    # Actually: T@b - t <= 0, 1^T b = 1, b >= 0
    # In linprog form: A_ub @ x <= b_ub, A_eq @ x = b_eq
    # x = [b; t], A_ub = [T, -I_{2n-1}], b_ub = 0
    # A_eq = [1^T, 0], b_eq = [1]
    
    # This is large. Let me use a different approach.
    # Actually for n=1200, this is 2399 rows for A_ub and 1200+1 variables.
    # That's manageable.
    
    m = 2*n-1
    A_ub = scipy.sparse.hstack([T, -scipy.sparse.eye(m)], format='csr')
    b_ub = np.zeros(m)
    A_eq = np.hstack([np.ones(n), [0]])
    b_eq = np.array([1.0])
    
    res = linprog(c=np.r_[np.zeros(n), 1.0], A_ub=A_ub, b_ub=b_ub, 
                  A_eq=A_eq.reshape(1,-1), b_eq=b_eq,
                  bounds=[(0, None)]*n + [(-np.inf, None)], method='highs')
    
    if res.success:
        b_opt = res.x[:n]
        t_opt = res.x[n]
        return b_opt, t_opt
    return None, None
```

This should be fast with HiGHS solver (which is what scipy uses by default now).

   Let me also consider: **can we avoid the LP entirely and use a purely gradient-based method?**

   The objective `f(a) = max_k R[k]` (where R = conv(a,a)) is differentiable almost everywhere. At points where the max is achieved at a unique index k*, the gradient is:
   `∇f(a)[i] = a[k*-i] + a[i-k*]` (with boundary handling)

   This can be computed in O(n) time! (Just two shifted copies of a.)

   For the subgradient (when multiple peaks are active), we average over the active set.

   **Subgradient method with line search:**
   1. Compute R = conv(a,a), find active set I = {k : R[k] >= max - ε}
   2. Compute g[i] = (1/|I|) * sum_{k in I} (a[k-i] + a[i-k])
   3. Update: a_new = a - η * g, project to {sum=1, a>=0}
   4. Adjust η by line search (backtracking)

   This is O(n * |I|) per step (for computing g) + O(n log n) for the convolution. If |I| is small (say 5-20), this is very fast!

   The projection onto {sum=1, a>=0} is the Euclidean projection onto the probability simplex, which can be done in O(n log n) using the "water-filling" algorithm.

   **This is much faster than the LP!** Each step is O(n log n) vs O(n^2) for the LP. And we can do millions of steps in the time it takes to do thousands of LPs.

   The convergence might be slower (subgradient methods have O(1/sqrt(T)) convergence vs O(1/T) for the LP alternating), but the constant factor is much better.

   **Combined strategy:**
   1. Phase 1: Fast subgradient (100k+ steps) - get close to optimum
   2. Phase 2: LP alternating (thousands of steps) - fine polish
   3. Phase 3: Subgradient again with smaller step - final polish

```python
import numpy as np
from scipy.fft import rfft, irfft
from scipy.optimize import linprog
from scipy.sparse import csr_matrix, eye as sp_eye, hstack as sp_hstack
import time

def fast_convolve(a):
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    A = rfft(a, fft_size)
    return irfft(A * A, fft_size)[:size]

def simple_projection(a):
    """Project a onto the probability simplex {x: sum(x)=1, x>=0}."""
    n = len(a)
    if a.sum() <= 0:
        return np.ones(n) / n
    # Water-filling algorithm
    u = np.sort(a)[::-1]
    cssv = np.cumsum(u)
    rho = np.where(u * np.arange(1, n+1) > (cssv - 1))[0][-1]
    theta = (cssv[rho] - 1) / (rho + 1.0)
    return np.maximum(a - theta, 0)

def subgradient_step(a, eta, active_threshold=1e-4):
    """One subgradient step for minimizing max(conv(a,a))."""
    n = len(a)
    R = fast_convolve(a)
    max_R = R.max()
    
    # Find active set
    threshold = max_R * (1 - active_threshold)
    active = np.where(R >= threshold)[0]
    if len(active) == 0:
        active = np.array([np.argmax(R)])
    
    # Compute subgradient: g[i] = (1/|I|) * sum_{k in I} (a[k-i] + a[i-k])
    g = np.zeros(n)
    for k in active:
        # a[k-i] is valid when 0 <= k-i < n, i.e., k-n+1 <= i <= k
        # a[i-k] is valid when 0 <= i-k < n, i.e., k <= i <= k+n-1
        # Combined: i in [max(0, k-n+1), min(n-1, k+n-1)]
        # But more precisely:
        # Term 1: a[k-i] for i such that 0 <= k-i < n -> i in [k-n+1, k]
        # Term 2: a[i-k] for i such that 0 <= i-k < n -> i in [k, k+n-1]
        
        # For term 1: g[i] += a[k-i] for i in [max(0,k-n+1), min(n-1,k)]
        i_start1 = max(0, k - n + 1)
        i_end1 = min(n - 1, k)
        if i_start1 <= i_end1:
            indices = np.arange(i_start1, i_end1 + 1)
            g[indices] += a[k - indices]
        
        # For term 2: g[i] += a[i-k] for i in [max(0,k), min(n-1, k+n-1)]
        i_start2 = max(0, k)
        i_end2 = min(n - 1, k + n - 1)
        if i_start2 <= i_end2:
            indices = np.arange(i_start2, i_end2 + 1)
            g[indices] += a[indices - k]
    
    g /= len(active)
    
    # Update
    a_new = a - eta * g
    a_new = simple_projection(a_new)
    return a_new, max_R, len(active)
```
