Actually, since a >= 0, C_k >= 0 for all k. But the quadratic form a^T M_k a where M_k has entries (M_k)_{ij} = 1 if i+j=k... this matrix is not positive semidefinite in general. For example, if n=3 and k=2: C_2 = a_0*a_2 + a_1*a_1 + a_2*a_0 = 2*a_0*a_2 + a_1^2. The matrix is [[0,0,1],[0,1,0],[1,0,0]] and its eigenvalues are 1, 1, -1. So it's INDEFINITE.

This means the problem is genuinely non-convex, and we need numerical methods.

For the coordinate descent, here's the key insight:
- For fixed a_{-j}, the function f(a_j) = max_k C_k(a_j) is convex in a_j
- We can find its minimum efficiently

Let me code this up:

For coordinate descent on coordinate j:
1. Compute C_k for all k
2. Identify the "near-max" k values (within some tolerance of the max)
3. For each such k, C_k is a function of a_j:
   - If k = 2j: C_k = a_j^2 + B_k (where B_k = sum_{i != j} a_i * a_{k-i})
   - If k != 2j: C_k = 2 * a_{k-j} * a_j + B_k (where B_k = sum_{i != j, i != k-j} a_i * a_{k-i})
4. The function max_k C_k(a_j) is piecewise: each piece is either linear or quadratic
5. Find the minimum by checking all breakpoints

Let me redo: C_k = sum_i a_i * a_{k-i}. If I change a_j to x:
- The terms involving a_j are: a_j * a_{k-j} (when i=j) and a_{k-j} * a_j (when i=k-j)
- If j != k-j: C_k(x) = x * a_{k-j} + a_{k-j} * x + (C_k - 2*a_j*a_{k-j}) = 2*a_{k-j}*x + (C_k - 2*a_j*a_{k-j})
- If j = k-j (k=2j): C_k(x) = x * x + (C_k - a_j^2) = x^2 + (C_k - a_j^2)

So:
- For k = 2j: C_k(x) = x^2 + (C_k_current - a_j^2)  [quadratic]
- For k != 2j, 0 <= k-j < n: C_k(x) = 2*a_{k-j}*x + (C_k_current - 2*a_j*a_{k-j})  [linear]
- Otherwise: C_k(x) = C_k_current  [constant]

To find the minimum of max_k C_k(x) over x >= 0 (and x <= 1 since sum = 1):
- The function is convex (max of convex functions)
- I can use ternary search or binary search on the derivative

The "derivative" (subgradient) at x is:
- From the active k values (those achieving the max)
- For active k with k=2j: derivative = 2x
- For active k with k!=2j: derivative = 2*a_{k-j}
- The subgradient is the convex hull of these values

The minimum is where 0 is in the subgradient, i.e., where the subgradient contains 0.

Algorithm for finding optimal x:
1. Evaluate the function and subgradient at x=0
2. If min subgradient at 0 > 0, optimal x = 0
3. Otherwise, use bisection:
   - At each step, evaluate f(x) and the subgradient
   - The "left derivative" is the min of {2x, 2*a_{k-j} for active k}
   - The "right derivative" is the max of {2x, 2*a_{k-j} for active k}
   - If left derivative > 0, move x down
   - If right derivative < 0, move x up
   - Otherwise, we've found the minimum

This is efficient! Each evaluation is O(n) (compute all C_k(x) values), and we need O(log(1/eps)) evaluations.

    A = np.fft.rfft(a, fft_size)
    return np.fft.irfft(A * A, fft_size)[:size]

def project_simplex(v, target_sum=1.0):
    """Euclidean projection onto {x>=0, sum(x)=target_sum}."""
    n = len(v)
    if n == 0:
        return v.copy()
    if target_sum <= 0:
        return np.zeros(n)
    u = np.sort(v)[::-1]
    cssv = np.cumsum(u)
    cond = (u - (cssv - target_sum) / np.arange(1, n + 1)) > 0
    if not cond.any():
        return np.full(n, target_sum / n)
    rho = np.nonzero(cond)[0][-1]
    theta = (cssv[rho] - target_sum) / (rho + 1)
    return np.maximum(v - theta, 0.0)

def compute_smooth_obj_and_grad(params, alpha, beta):
    """
    Compute the smooth objective and gradient.
    params: array of length n-1 (the first n-1 elements of a)
    alpha: fixed last element parameter (we'll use sum constraint instead)
    beta: temperature for log-sum-exp
    Returns: (objective_value, gradient)
    """
    n = len(params) + 1
    a = np.empty(n)
    a[:n-1] = params
    a[n-1] = np.maximum(1.0 - np.sum(params), 0.0)
    
    # If a[n-1] would be negative, we're infeasible
    # L-BFGS-B handles bounds, so we set bounds to prevent this
    
    conv = fast_convolve(a)
    # Smooth max
    shifted = conv - conv.max()
    log_sum_exp = conv.max() + np.log(np.sum(np.exp(beta * shifted))) / beta
    
    # Gradient
    weights = np.exp(beta * shifted)
    weights /= weights.sum()
    # grad_a[j] = 2 * sum_k weights[k] * a[k-j]
    grad_a = 2.0 * np.correlate(weights, a, 'full')[n-1:n-1+n]
    
    # Gradient w.r.t. params (first n-1 elements)
    grad_params = grad_a[:n-1] - grad_a[n-1]
    
    return log_sum_exp, grad_params

Wait, I realize there's an issue with my approach. When I drop the last variable and use L-BFGS-B, the constraint sum(a[:n-1]) <= 1 is not directly handled. If sum(params) > 1, then a[n-1] < 0 which is infeasible.

A better approach: Use the softmax parameterization.

Let x be an unconstrained vector in R^n, and define:
a_i = exp(x_i) / sum_j exp(x_j)

This automatically ensures a_i > 0 and sum(a) = 1. Then I optimize f(softmax(x)) over x.

The gradient:
df/dx_i = a_i * (df/da_i - sum_j a_j * df/da_j)
         = a_i * (grad_a_i - dot(a, grad_a))

This is clean and handles all constraints automatically.

Let me rewrite:

```python
def softmax_obj_grad(x, beta):
    """Objective and gradient using softmax parameterization."""
    n = len(x)
    # Compute softmax
    x_shifted = x - x.max()
    exp_x = np.exp(x_shifted)
    a = exp_x / exp_x.sum()
    
    # Compute convolution
    conv = fast_convolve(a)
    
    # Smooth max (log-sum-exp)
    conv_max = conv.max()
    shifted = conv - conv_max
    lse = conv_max + np.log(np.sum(np.exp(beta * shifted))) / beta
    
    # Gradient
    weights = np.exp(beta * shifted)
    weights /= weights.sum()
    grad_a = 2.0 * np.correlate(weights, a, 'full')[n-1:n-1+n]
    
    # Chain rule for softmax
    mean_grad = np.dot(a, grad_a)
    grad_x = a * (grad_a - mean_grad)
    
    return lse, grad_x
```

This is much cleaner! And L-BFGS-B can optimize over x directly with no constraints.

The downside is that the softmax parameterization can make the optimization ill-conditioned (if some a_i are very small, the corresponding x_i is very negative, and small changes in x_i can cause large relative changes in a_i). But in practice, L-BFGS handles this fine.

Let me now think about the coordinate descent. For exact coordinate descent on a_j (with the sum constraint):

Given a with sum = 1, I want to find the optimal a_j by:
1. Setting a_j = t (variable)
2. Scaling all other a_i by factor (1-t)/(1-a_j) to maintain sum = 1
3. Finding t that minimizes max_k C_k

Step 2 means: a_new[j] = t, a_new[i] = a[i] * (1-t)/(1-a[j]) for i != j.

The convolution C_k(a_new) as a function of t:
C_k = sum_i a_new[i] * a_new[k-i]

This involves t in a more complex way than before (since ALL other elements are scaled). Let me write it out:

Let s = 1 - a[j] (sum of all elements except j), and scale = (1-t)/s.
a_new[j] = t
a_new[i] = a[i] * scale for i != j

C_k(a_new) = sum_i a_new[i] * a_new[k-i]
= a_new[j] * a_new[k-j] + a_new[k-j] * a_new[j] + sum_{i != j, i != k-j} a_new[i] * a_new[k-i]
(special case when j = k-j: a_new[j]^2 + sum_{i != j} a_new[i] * a_new[k-i])

For j != k-j:
= t * (a[k-j] * scale) + (a[k-j] * scale) * t + sum_{i != j, i != k-j} (a[i]*scale) * (a[k-i]*scale)
= 2 * t * a[k-j] * scale + scale^2 * sum_{i != j, i != k-j} a[i] * a[k-i]
= 2 * t * a[k-j] * (1-t)/s + ((1-t)/s)^2 * (C_k - 2*a[j]*a[k-j])

For j = k-j (k = 2j):
= t^2 + sum_{i != j} (a[i]*scale) * (a[k-i]*scale)
= t^2 + ((1-t)/s)^2 * (C_k - a[j]^2)

So C_k(t) is a quadratic function of t in all cases! (The scale factor (1-t)/s is linear in t, and when squared, gives a quadratic; when multiplied by t, also gives quadratic.)

So the objective max_k C_k(t) is a piecewise quadratic function of t, and I can find its minimum using:
- Ternary search on [0, 1] (since t must be in [0, 1])
- Or evaluate at all breakpoints

Ternary search is simplest and should converge in ~50-100 evaluations, each of which is O(n) (compute all C_k(t) values).

Wait, computing all C_k(t) for a given t:
C_k(t) for all k = 0, ..., 2n-2. This is the full convolution of a_new with itself.
I can compute this via FFT in O(n log n).

So each ternary search iteration costs O(n log n), and I need ~50 iterations, giving O(n log n * 50) per coordinate. For n=768, that's about 768 * 10 * 50 = 384K operations per coordinate, and 768 coordinates = 300M per pass. That might be too slow.

Alternative: Instead of ternary search, use the fact that the function is convex and find the minimum analytically.

The function f(t) = max_k C_k(t) where each C_k(t) is quadratic in t. The minimum of f is where the subgradient contains 0.

The subgradient of f at t is the convex hull of {C_k'(t) : C_k(t) = f(t)}.

I can find the minimum by:
1. Start at t = current a[j]
2. Compute f(t) and identify the active set (k values where C_k = f(t))
3. Compute the subgradient: S = convex hull of {C_k'(t) : k in active set}
4. If 0 in S, we're at the minimum
5. Otherwise, move t in the direction that reduces f (towards the side where the subgradient points)
6. Repeat (essentially bisection)

Each iteration is O(n) (compute C_k for all k and find the max). With O(log(1/eps)) iterations, total is O(n * log(1/eps)) per coordinate.

For n=768 and 50 iterations: 768 * 50 = 38K per coordinate, 768 coordinates = 30M per pass. That's very fast!
