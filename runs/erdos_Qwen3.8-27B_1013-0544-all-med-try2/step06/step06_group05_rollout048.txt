```python
                        best_raw = actual
    
    h = project_feasible(h, n)
    return h, compute_c5(h, n)
```

This is O(n) per pass (the argmin/argmax are O(n), and the correlation is O(n log n)). With 20000 passes per delta and 7 deltas, that's 140000 passes total, each O(n log n) ≈ O(2000) for n=250. Total: ~280 million operations. In numpy, this should take maybe 30-60 seconds.

But wait, the correlation computation is the bottleneck at O(n log n) per pass. For n=250, that's fast. Let me estimate: np.correlate for n=250 takes about 10-20 microseconds. 140000 * 20μs = 2.8 seconds. The rest (argmax, argmin, indexing) is also fast. Total maybe 5-10 seconds. 

But we have 1100 seconds budget, so we can afford many more passes and multiple resolutions.

Let me now think about the overall structure:

1. Start from initial_h_values (n=250)
2. Run L-BFGS-B optimization (maybe 100-200 seconds)
3. Run vectorized pair search (maybe 100-200 seconds)
4. Try n=200, n=300 (interpolate and re-optimize) (maybe 200-400 seconds)
5. Try random restarts (maybe 100-200 seconds)
6. Final pair search refinement

Let me also add a "multi-peak" variant where instead of just looking at the single peak, I look at the top K peaks and try to reduce all of them.

Actually, for the multi-peak approach, I can modify the objective to be a weighted sum of the top K peaks, or use the smooth max with a specific alpha.

Let me keep it simple: use the smooth max objective for the L-BFGS-B phase, and the single-peak approach for the pair search.

def project_feasible(h, n):
    target_sum = n / 2.0
