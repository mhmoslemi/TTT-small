For the targeted pair search, here's my improved algorithm:
- Find the worst shift k*
- For this shift, the overlap is O(k*) = sum_{i=0}^{n-1-k*} h[i]*(1-h[i+k*])*dx
- To reduce O(k*), we want to either:
  a) Decrease h[i] where h[i] is large and h[i+k*] is small (the "conflict" pairs)
  b) Increase h[i+k*] where h[i] is large and h[i+k*] is small
- A pair move (i, j, d) changes O(k*) by:
  ΔO(k*) = d*dx * [effect of h[i] change + effect of h[j] change]

For shift k > 0, h[i] appears in O(k) as:
- First factor in term i (if i ≤ n-1-k): contribution h[i]*(1-h[i+k])
- Second factor in term i-k (if i-k ≥ 0): contribution h[i-k]*(1-h[i])

So dO(k)/dh[i] = dx * [(1-h[i+k]) if i ≤ n-1-k else 0] + dx * [-h[i-k] if i-k ≥ 0 and i-k ≤ n-1-k else 0]

For the pair search, the key insight is:
- We want to find (i, j, direction) that minimizes the maximum of (O(k) + d*ΔO(k))
- For the worst shifts, we want ΔO(k) < 0
- ΔO(k) = d * (dO(k)/dh[i] - dO(k)/dh[j]) for the move h[i]+=d, h[j]-=d

So for each pair (i,j), we can compute the vector of changes for the worst shifts and choose the direction (which of i,j gets the mass) that reduces the worst.

                              options={'maxiter': 300, 'ftol': 1e-16, 'gtol': 1e-13})
                h_interp = project_feasible(res.x, 200)
                c_interp = compute_c5(h_interp, 200)
            except Exception:
                pass
            h_interp, c_interp = targeted_pair_search(h_interp, 200, deadline - 5)
            if c_interp < best_c:
                best_c = c_interp; best_h = h_interp; n = 200

    best_h = project_feasible(best_h, len(best_h))
    best_c = compute_c5(best_h, len(best_h))
    return best_h, best_c, len(best_h)
