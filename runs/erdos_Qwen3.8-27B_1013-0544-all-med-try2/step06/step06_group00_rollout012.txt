def project_feasible_fast(h, n):
    """Project h onto {x: 0<=x<=1, sum(x)=n/2}"""
    target = n / 2.0
    # Bisection on lambda
    lo, hi = -1.0, 2.0
    for _ in range(60):
        mid = (lo + hi) / 2
        s = np.sum(np.clip(h - mid, 0, 1))
        if s > target:
            lo = mid
        else:
            hi = mid
    return np.clip(h - (lo + hi) / 2, 0, 1)

- The term h[c]*(1-h[c+k]) becomes 1*(1-h'[c+k])
- If a+k = c, then h'[c] = 1, so 1-h'[c+k] depends on h'[c+k] which might have changed

So it's NOT simply additive. We need to compute the full delta.

For a 2-swap (a,b → 0, c,d → 1):
The positions that change are a, b (go to 0) and c, d (go to 1).
The correlation at shift k (index m = k + n - 1 in the full correlation) is:
g_m = sum_{i: valid} h[i] * (1-h[i+k])

The change in g_m when we swap:
- Terms involving h[a] or h[b] as the "first" factor: they go from 1 to 0, so we lose h[a]*(1-h[a+k]) and h[b]*(1-h[b+k])
- Terms involving h[a] or h[b] as the "second" factor (i+k = a or b): the (1-h) term changes
- Terms involving h[c] or h[d] as the "first" factor: they go from 0 to 1, so we gain 1*(1-h'[c+k]) and 1*(1-h'[d+k])
- Terms involving h[c] or h[d] as the "second" factor: the (1-h) term changes

This is getting complex. Let me just compute the full delta by evaluating the new correlation at the affected positions.

Actually, for the binary case, there's a simpler way to think about it. The correlation at shift k is:
g_k = #{i: h[i]=1 and h[i+k]=0} (times dx)

When we do a 2-swap (turn off a, b; turn on c, d):
- For each k, the new count = old count + (changes due to a going off) + (changes due to b going off) + (changes due to c going on) + (changes due to d going on) + (cross terms)

The cross terms arise when, e.g., turning on c affects the count for shift k = a-c (because h[c+k] = h[a] changes from 1 to 0).

        t = t_new
