Actually, for n=70, np.correlate of two length-70 arrays is extremely fast (it's essentially a convolution). Let me estimate: each call is maybe 5-10 microseconds. So 500000 iterations would take about 2.5-5 seconds. That's very feasible.

But I realize the issue: recomputing the full correlation at each step is wasteful. When I swap positions i and j, only the correlations at lags involving i or j change. Specifically, corr changes at lags i-j, j-i, and all lags where the index range includes i or j.

Actually, for a swap of positions i and j in a binary sequence:
- At position i: h changes from 1 to 0
- At position j: h changes from 0 to 1

The correlation at lag k is Σ valid_i h[i]*(1-h[i+k]).

When h[i] changes from 1 to 0:
- corr[k] decreases by (1-h[i+k]) for all k where i is in the valid range and i+k is also valid
- i.e., for k from -(i) to (n-1-i) (approximately)

When h[j] changes from 0 to 1:
- corr[k] increases by (1-h[j+k]) for all k where j is in the valid range
- But wait, it's more subtle because h[j] appears in both the "h" and "1-h" positions

Let me think more carefully. corr[k] = Σ_i h[i] * (1-h[i+k]).

If I change h[i] from 1 to 0:
- For the term where the first index is i: h[i]*(1-h[i+k]) changes from (1-h[i+k]) to 0, so corr[k] decreases by (1-h[i+k])
- For the term where the second index is i (i.e., first index is i-k): h[i-k]*(1-h[i]) changes from h[i-k]*0 to h[i-k]*1, so corr[k] increases by h[i-k]
- Net change in corr[k] = h[i-k] - (1-h[i+k]) = h[i-k] + h[i+k] - 1

Similarly for changing h[j] from 0 to 1:
- First index j: h[j]*(1-h[j+k]) changes from 0 to (1-h[j+k]), so corr[k] increases by (1-h[j+k])
- Second index j (first index is j-k): h[j-k]*(1-h[j]) changes from h[j-k]*1 to h[j-k]*0, so corr[k] decreases by h[j-k]
- Net change = (1-h[j+k]) - h[j-k] = 1 - h[j+k] - h[j-k]

Total change in corr[k] from swapping i and j:
= [h[i-k] + h[i+k] - 1] + [1 - h[j+k] - h[j-k]]
= h[i-k] + h[i+k] - h[j+k] - h[j-k]

This is only non-zero for k values where both i and j are in the valid range. For most k values, this is 0.

So I can maintain the full correlation array and update it incrementally! This would be much faster.

import numpy as np
from scipy.optimize import minimize, Bounds

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode="full")
    return float(np.max(corr) * dx)


def binary_max_corr(h):
    corr = np.correlate(h, 1 - h, mode="full")
    return int(np.max(corr))


def project_feasible(h, target_sum):
    h = np.clip(h, 0.0, 1.0)
    for _ in range(100):
        s = h.sum()
        if abs(s - target_sum) < 1e-12:
            break
        diff = target_sum - s
        if diff > 0:
            mask = h < 1.0
        else:
            mask = h > 0.0
        cnt = mask.sum()
        if cnt == 0:
            break
        h[mask] += diff / cnt
        h = np.clip(h, 0.0, 1.0)
    return h


def smooth_max(x, beta):
    m = np.max(x)
    shifted = np.clip(beta * (x - m), -700.0, 700.0)
    return m + np.log(np.sum(np.exp(shifted))) / beta


def obj_smooth(h, dx, beta):
    corr = np.correlate(h, 1.0 - h, mode='full')
    return smooth_max(corr, beta) * dx


def con_fun(h, target_sum):
    return h.sum() - target_sum

    return np.ones(len(h))

    x_old = np.linspace(0, 2, len(h_old), endpoint=False)
