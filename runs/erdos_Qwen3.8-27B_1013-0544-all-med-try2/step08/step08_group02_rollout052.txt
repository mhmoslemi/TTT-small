def fast_flip(c, h, p, n):
    """Flip h[p] and update correlation array c in-place. Returns new h value."""
    old = h[p]
    delta = 1.0 - 2.0 * old  # +1 for 0->1, -1 for 1->0
    
    # Case 1: p is in first factor, k = m-(n-1), need 0<=p+k<n
    # m range: max(0, n-1-p) to min(2n-2, n-1+p)
    m_start1 = max(0, n - 1 - p)
    m_end1 = min(2 * n - 2, n - 1 + p)
    for m in range(m_start1, m_end1 + 1):
        k = m - (n - 1)
        if k == 0:
            continue  # binary: h[p]*(1-h[p]) = 0
        jp = p + k
        c[m] += delta * (1.0 - h[jp])
    
    # Case 2: p is in second factor, i = p-k, need 0<=i<n
    # m range: max(0, p) to min(2n-2, n-1+p)
    m_start2 = max(0, p)
    m_end2 = min(2 * n - 2, n - 1 + p)
    for m in range(m_start2, m_end2 + 1):
        k = m - (n - 1)
        if k == 0:
            continue
        ip = p - k
        c[m] -= delta * h[ip]
    
    h[p] = 1.0 - old
    return c

Case 1: c[m] += +1 * (1 - h[i+k]) for valid k
Case 2: c[m] -= +1 * h[i-k] for valid k

But h[i] is now 0 (after forward flip), and the other h values are in their post-flip state. Since i and j are different positions, and we're using h[m] values other than i and j, the state is correct.

Actually wait, there's a subtle issue. When I flip i from 1 to 0 in the forward direction, I use h[i+k] and h[i-k] values. These values haven't changed (they're not i or j). Then I flip j from 0 to 1, using h[j+k] and h[j-k]. Again, these are fine.

For the revert: I flip i from 0 to 1. I use h[i+k] and h[i-k]. These are the same values as before (none of them are i or j). Good. Then I flip j from 1 to 0, using h[j+k] and h[j-k]. Same values. Good.

So the revert is correct. But I need to make sure I'm using the right delta signs.

Forward flip i (1->0): delta = -1
  Case 1: c[m] += delta * (1-h[i+k]) = -(1-h[i+k])
  Case 2: c[m] -= delta * h[i-k] = +h[i-k]

Forward flip j (0->1): delta = +1
  Case 1: c[m] += delta * (1-h[j+k]) = +(1-h[j+k])
  Case 2: c[m] -= delta * h[j-k] = -h[j-k]

Revert flip i (0->1): delta = +1
  Case 1: c[m] += delta * (1-h[i+k]) = +(1-h[i+k])
  Case 2: c[m] -= delta * h[i-k] = -h[i-k]

Revert flip j (1->0): delta = -1
  Case 1: c[m] += delta * (1-h[j+k]) = -(1-h[j+k])
  Case 2: c[m] -= delta * h[j-k] = +h[j-k]

So the revert is exactly the negative of the forward. Good.

But in my code above, I have:
Forward i (1->0):

The logic is correct.

Now, there's a performance concern: the np.arange, np.where, and vectorized operations create temporary arrays each iteration. For n=500, these are small (at most 500 elements), but the overhead of creating them adds up.

A faster approach: precompute the index arrays for each position p.

For each position p (0 to n-1):
- Case 1 indices: m in [max(0, n-1-p), min(2n-2, 2n-2-p)], excluding m=n-1
  k values: m-(n-1) for each m
  j values: p+k for each valid k
- Case 2 indices: m in [max(0, p), min(2n-2, n-1+p)], excluding m=n-1
  k values: m-(n-1) for each m
  i values: p-k for each valid k

I can precompute these for all p and store them in arrays. Then each flip just does:
c[precomputed_idx_1[p]] += delta * (1 - h[precomputed_j_1[p]])
c[precomputed_idx_2[p]] -= delta * h[precomputed_i_2[p]]

This would be very fast.

Let me redesign:

```python
def precompute_flip_indices(n):
    """Precompute for each position p, the indices and partner positions needed for correlation update."""
    idx1 = []  # m indices for Case 1
    j1 = []    # partner positions for Case 1
    idx2 = []  # m indices for Case 2
    i2 = []    # partner positions for Case 2
    
    for p in range(n):
        # Case 1: m in [max(0, n-1-p), min(2n-2, 2n-2-p)], k != 0
        m_vals = []
        for m in range(max(0, n-1-p), min(2*n-2, 2*n-2-p) + 1):
            k = m - (n-1)
            if k != 0:
                m_vals.append(m)
        k_vals = np.array(m_vals) - (n-1)
        idx1.append(np.array(m_vals, dtype=np.int32))
        j1.append(np.array(p + k_vals, dtype=np.int32))
        
        # Case 2: m in [max(0, p), min(2n-2, n-1+p)], k != 0
        m_vals2 = []
        for m in range(max(0, p), min(2*n-2, n-1+p) + 1):
            k = m - (n-1)
            if k != 0:
                m_vals2.append(m)
        k_vals2 = np.array(m_vals2) - (n-1)
        idx2.append(np.array(m_vals2, dtype=np.int32))
        i2.append(np.array(p - k_vals2, dtype=np.int32))
    
    return idx1, j1, idx2, i2
```

Then the flip becomes:
```python
def do_flip(c, h, p, delta, idx1, j1, idx2, i2):
    c[idx1[p]] += delta * (1.0 - h[j1[p]])
    c[idx2[p]] -= delta * h[i2[p]]
    h[p] += delta
```

This is very clean and fast! Each flip is just two vectorized numpy operations on precomputed index arrays.

Let me estimate the speed: for n=500, each position has ~n entries in the precomputed arrays. So each flip does two vectorized operations on ~500-element arrays. In numpy, this should take maybe 5-10μs per operation. So each SA iteration (2 flips + max) would be ~20-30μs. That gives ~30,000-50,000 iterations per second. In 60 seconds, that's 2-3 million iterations.
