    # This is a 1D convex piecewise linear minimization
    # Evaluate at boundaries and at crossing points
    
    def max_val(hi):
        return np.max(a_vals * hi + b_vals)
    
    # Evaluate at 0 and 1
    v0 = max_val(0.0)
    v1 = max_val(1.0)
    
    # Find crossing points of pairs of active lines
    # Active lines are those that are on the upper envelope
    # For efficiency, just check all pairs
    best_hi = 0.0 if v0 <= v1 else 1.0
    best_val = min(v0, v1)

                continue

            if 0.0 <= xc <= 1.0:

                if vc < best_val:
                    best_val = vc
                    best_hi = xc
    
    return best_hi

Actually, I want to reconsider the coordinate descent more carefully. The issue is that when I change h[i], the projection to maintain the sum constraint will change other coordinates, which might undo the improvement.

A better approach: **paired coordinate descent**. Pick two coordinates (i, j) and change them simultaneously:
- h[i] += δ
- h[j] -= δ
- This maintains the sum constraint exactly!

The subproblem becomes: find δ that minimizes max_k f_k(h + δ*e_i - δ*e_j)

For each k, f_k changes by:
Δf_k = δ * (∂f_k/∂h_i - ∂f_k/∂h_j)

So f_k(δ) = f_k(0) + δ * g_k where g_k = ∂f_k/∂h_i - ∂f_k/∂h_j

This is a max of linear functions in δ! The minimum is found the same way as before (find the vertex of the upper envelope).

And the constraint 0 ≤ h_i + δ ≤ 1 and 0 ≤ h_j - δ ≤ 1 gives:
δ ∈ [max(0, h_j - 1), min(1 - h_i, h_j)] = [max(0, h_j-1), min(1-h_i, h_j)]

Since h_j ≤ 1, h_j - 1 ≤ 0, so the lower bound is 0 if h_j < 1, or h_j-1 if h_j = 1.
Actually: 0 ≤ h_j - δ ≤ 1 means h_j - 1 ≤ δ ≤ h_j.
And 0 ≤ h_i + δ ≤ 1 means -h_i ≤ δ ≤ 1 - h_i.
So δ ∈ [max(0, h_j-1), min(1-h_i, h_j)].
Since 0 ≤ h_j ≤ 1, h_j-1 ≤ 0, so lower bound = 0 (assuming h_j < 1) or h_j-1 (if h_j = 1, then δ ≥ h_j-1 = 0, same thing).
So δ ∈ [0, min(1-h_i, h_j)].

This is clean! And we can use the same "find minimum of max of lines" algorithm.

The advantage: no projection needed! The sum is automatically maintained.

The disadvantage: we need to choose which pairs (i,j) to try. We can't try all n²/2 pairs.

Strategy: for each i, choose j that gives the most improvement. This is still O(n²) per sweep, but with the early termination and top-k, it should be fast.

            for direction in [1, -1]:
