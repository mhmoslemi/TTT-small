```python
    grad = np.zeros(n)
    for m in range(2*n - 1):
        lag = m - (n - 1)
        pm = p[m]
        if pm < 1e-15:
            continue
```

Let me also think about the **gradient-guided pair swap** more carefully:

Given gradient g[i], if I increase h[i] by δ and decrease h[j] by δ:
- Change in smooth objective ≈ δ * (g[i] - g[j])
- We want this to be negative, so g[i] < g[j]

But this is only a first-order approximation. For small δ, it should be good.

Algorithm:
1. Compute gradient g
2. Find i* = argmin(g) and j* = argmax(g)
3. Try swapping δ from j* to i*
4. If it improves, accept; otherwise try smaller δ or different pairs
5. Repeat

This is O(n) per iteration (after the O(n²) gradient computation), much faster than O(n²) pair search.

```python
import numpy as np
from scipy.optimize import minimize
import time

def compute_c5(h, n):
    dx = 2.0 / n
    return float(np.max(np.correlate(h, 1 - h, mode='full')) * dx)

def compute_corr(h, n):
    dx = 2.0 / n
    return np.correlate(h, 1 - h, mode='full') * dx

def project_feasible(h, n):
    target = n / 2.0
    h = np.clip(h, 0.0, 1.0)
    lo, hi = -1.5, 1.5
    for _ in range(60):
        mid = (lo + hi) / 2.0
        s = np.clip(h - mid, 0.0, 1.0).sum()
        if s > target:
            lo = mid
        else:
            hi = mid
    return np.clip(h - (lo + hi) / 2.0, 0.0, 1.0)

def smooth_obj(h, n, alpha):
    c = compute_corr(h, n)
    c_max = c.max()
    shifted = alpha * (c - c_max)
    return float(c_max + np.log(np.sum(np.exp(shifted))) / alpha)

def compute_smooth_grad(h, alpha):
    n = len(h)
    dx = 2.0 / n
    c = np.correlate(h, 1 - h, mode='full') * dx
    c_max = c.max()
    shifted = alpha * (c - c_max)
    shifted -= shifted.max()  # extra stability
    exp_c = np.exp(shifted)
    p = exp_c / exp_c.sum()
    
    grad = np.zeros(n)
    for m in range(2 * n - 1):
        if p[m] < 1e-14:
            continue
        lag = m - (n - 1)
        pm = p[m] * dx
        lo1 = max(0, lag)
        hi1 = min(n - 1, lag + n - 1)
        if lo1 <= hi1:
            idx = np.arange(lo1, hi1 + 1)
            grad[lo1:hi1 + 1] += pm * (1.0 - h[idx - lag])
        lo2 = max(0, -lag)
        hi2 = min(n - 1, n - 1 - lag)
        if lo2 <= hi2:
            idx2 = np.arange(lo2, hi2 + 1)
            grad[lo2:hi2 + 1] -= pm * h[idx2 + lag]
    return grad

def proj_grad_step(h, n, alpha, deadline, max_iter=5000):
    h = project_feasible(h.copy(), n)
    best_c = compute_c5(h, n)
    best_h = h.copy()
    best_f = smooth_obj(h, n, alpha)
    
    for it in range(max_iter):
        if time.time() > deadline:
            break
        g = compute_smooth_grad(h, alpha)
        
        # Backtracking line search
        step = 1.0 / (alpha * 0.5)
        f_cur = best_f
        for _ in range(20):
            h_new = project_feasible(h - step * g, n)
            f_new = smooth_obj(h_new, n, alpha)
            if f_new < f_cur - 1e-14 * max(1, abs(f_cur)):
                break
            step *= 0.5
        else:
            break  # no improvement possible
        
        h = h_new
        best_f = f_new
        c = compute_c5(h, n)
        if c < best_c - 1e-15:
            best_c = c
            best_h = h.copy()
    
    return best_h, best_c

def gradient_pair_swap(h, n, deadline, max_iter=50000):
    h = project_feasible(h.copy(), n)
    best_c = compute_c5(h, n)
    
    deltas = [0.01, 0.005, 0.002, 0.001, 0.0005, 0.0002, 0.0001]
    
    for delta in deltas:
        for it in range(max_iter):
            if time.time() > deadline:
                return h, best_c
            
            # Compute which direction helps
            c = compute_corr(h, n)
            # Gradient of max (use active set)
            active = c >= c.max() - 1e-6
            g = np.zeros(n)
            for m in np.where(active)[0]:
                lag = m - (n - 1)
                lo1 = max(0, lag)
                hi1 = min(n - 1, lag + n - 1)
                if lo1 <= hi1:
                    idx = np.arange(lo1, hi1 + 1)
                    g[lo1:hi1 + 1] += (1.0 - h[idx - lag])
                lo2 = max(0, -lag)
                hi2 = min(n - 1, n - 1 - lag)
                if lo2 <= hi2:
                    idx2 = np.arange(lo2, hi2 + 1)
                    g[lo2:hi2 + 1] -= h[idx2 + lag]
            
            # Find best swap: minimize g[i] - g[j] (want g[i] < g[j])
            # i gets +delta, j gets -delta
            # Change ≈ delta * (g[i] - g[j])
            # We want g[i] - g[j] < 0, i.e., g[i] < g[j]
            
            min_idx = np.argmin(g)
            max_idx = np.argmax(g)
            
            if g[min_idx] >= g[max_idx]:
                break  # no improving swap in gradient direction
            
            improved = False
            # Try the best pair
            if h[min_idx] + delta <= 1.0 and h[max_idx] - delta >= 0.0:
                h[min_idx] += delta
                h[max_idx] -= delta
                h = project_feasible(h, n)
                c_new = compute_c5(h, n)
                if c_new < best_c - 1e-14:
                    best_c = c_new
                    improved = True
                else:
                    h[min_idx] -= delta
                    h[max_idx] += delta
                    h = project_feasible(h, n)
            
            if not improved:
                # Try a few more pairs
                sorted_idx = np.argsort(g)
                tried = 0
                for ii in range(min(10, n)):
                    for jj in range(max(1, n-10), n):
                        i, j = sorted_idx[ii], sorted_idx[jj]
                        if i == j:
                            continue
                        tried += 1
                        if tried > 50:
                            break
                        if h[i] + delta <= 1.0 and h[j] - delta >= 0.0:
                            h[i] += delta
                            h[j] -= delta
                            h = project_feasible(h, n)
                            c_new = compute_c5(h, n)
                            if c_new < best_c - 1e-14:
                                best_c = c_new
                                improved = True
                                break
                            else:
                                h[i] -= delta
                                h[j] += delta
                                h = project_feasible(h, n)
                    if improved or tried > 50:
                        break
                if not improved:
                    break
    
    return h, best_c
```

3. Solve: min max_k [c[k](h) + ∇c[k](h) · (h' - h)] s.t. 0≤h'≤1, sum(h')=n/2
4. Update h = h', repeat

This is the **cutting plane / linearization** approach. Step 3 is a linear program (minimize t subject to linear constraints), which can be solved efficiently with scipy or cvxpy.

The LP in step 3:
min t

     0 ≤ h' ≤ 1
     sum(h') = n/2

This has 2n-1 + 1 = 2n constraints (plus bounds and equality). For n=250, that's 501 variables and about 1250 constraints. Very fast to solve!

Wait, this is essentially the **cutting plane method** for bilinear optimization. At each iteration, we linearize the objective around the current point and solve the resulting LP. The LP solution gives a direction to move.

But there's a subtlety: the LP minimizes a LOWER BOUND on the objective (since we're using the tangent plane, which underestimates the bilinear function... actually no, the bilinear function is neither convex nor concave, so the tangent plane is not necessarily a bound).

Hmm, actually for bilinear functions, the tangent plane at a point gives:
c[k](h') = c[k](h) + ∇c[k](h)·(h'-h) + (h'-h)^T H_k (h'-h) / 2 ... no, bilinear means the Hessian is constant.

Actually, c[k] = sum_j h[j](1-h[j-lag]) is bilinear in h. The exact expression is:
c[k](h') = c[k](h) + ∇c[k](h)·(h'-h) + (correction term)

The correction term for a bilinear function is: the cross term. Specifically, if c = f·g where f and g are linear in h, then:
c(h') = f(h')·g(h') = (f(h) + ∇f·(h'-h))·(g(h) + ∇g·(h'-h))
= f(h)g(h) + f(h)∇g·(h'-h) + g(h)∇f·(h'-h) + (∇f·(h'-h))(∇g·(h'-h))

So the linear approximation misses the last term (∇f·δ)(∇g·δ) which is quadratic. This means the LP solution might not actually decrease the objective.

The correct approach is to use the LP solution as a DIRECTION and then do a line search along that direction. This is the **Frank-Wolfe** or **conditional gradient** approach.

Let me reformulate:
1. At current h, compute theLP: min ∇f(h) · h' s.t. h' ∈ P (feasible set)
   where f(h) = max_k c[k] (or the smooth approximation)
   and P = {h' : 0≤h'≤1, sum(h')=n/2}

2. The LP solution h_LP gives the Frank-Wolfe direction: d = h_LP - h

3. Take a step: h_new = (1-γ)h + γ*h_LP for some γ ∈ [0,1]

4. Use backtracking line search to find the best γ

This is the standard Frank-Wolfe algorithm! And it's guaranteed to converge (albeit slowly, O(1/t) rate).

But for our problem, the "LP oracle" is:
min ∇f(h) · h' s.t. 0≤h'≤1, sum(h')=n/2

The solution to this LP is: h'_LP[i] = 1 if ∇f(h)[i] < τ, h'_LP[i] = 0 if ∇f(h)[i] > τ, and fractional at the threshold, where τ is chosen so that sum = n/2.

This is just a thresholding operation! No need for an LP solver!

Wait, that's the solution to min c·x s.t. 0≤x≤1, sum(x)=S. The optimal is:
- Sort c in increasing order
- Set x[i] = 1 for the smallest indices, x[i] = 0 for the largest
- One index might be fractional

So the Frank-Wolfe direction is:
d[i] = 1 - h[i] if c[i] < τ (we want to increase h[i])
d[i] = -h[i] if c[i] > τ (we want to decrease h[i])
d[i] = (n/2 - sum of 1s) - h[i] for the fractional index

This is O(n log n) per iteration! Very fast.

But wait, this is for the gradient of a CONVEX function. Our function f(h) = max_k c[k] is not convex (it's the max of bilinear functions). The Frank-Wolfe method is typically for convex objectives.

However, we can still use it as a heuristic: compute the subgradient of f at h (which is the average of gradients of active c[k]), then use the thresholding to get a direction, then do a line search.

Actually, for the smooth approximation f_α(h) = (1/α)log(sum exp(αc[k])), the gradient IS well-defined and we can use projected gradient (which is what I was planning earlier).
