```python
            if tot < 1e-15:

            h += (diff / tot) * h
```

```python
                    # f_0 = sum h[j]*(1-h[j]), term for j=i: h[i]*(1-h[i]) = h[i] - h[i]^2
                    # This is NOT linear in h[i]! It's quadratic.
                    # So for m=0, we can't use the linear approach.
                    # Skip m=0 for now, or handle separately.
                    a = 1.0 - 2.0 * old_val  # This would be the derivative, not the coefficient
                    # Actually for m=0, f_0 = sum h[j] - h[j]^2
                    # The term for j=i is h[i] - h[i]^2
                    # This is quadratic, so we handle it differently
                    a_vals.append(1.0)  # h[i] coefficient
                    b_vals.append(-h[i]*old_val + old_val)  # hmm this is getting messy
                    # Let me just skip m=0
                    continue
                elif m > 0:
                    a = 0.0
                    b = 0.0
                    if 0 <= i <= n-1-m:
                        b += (1.0 - h[i+m])  # h[i] * (1-h[i+m]), coefficient of h[i]
                        a = 1.0 - h[i+m]
                        b = 0.0  # no constant term from this part
                        # Actually: h[i]*(1-h[i+m]) = (1-h[i+m]) * h[i]
                        # So a = (1-h[i+m]), b = 0
                        a = 1.0 - h[i+m]
                    if m <= i <= n-1:
                        # h[i-m]*(1-h[i]) = h[i-m] - h[i-m]*h[i]
                        # a += -h[i-m], b += h[i-m]
                        a += -h[i-m]
                        b += h[i-m]
                    a_vals.append(a)
                    b_vals.append(b)
                else:
                    am = -m
                    # Overlap at lag -am: sum_{j=0}^{n-am-1} h[j+am]*(1-h[j])
                    # Terms involving h[i]:
                    # j+am = i => j = i-am: h[i]*(1-h[i-am]) if 0 <= i-am <= n-am-1
                    # j = i: h[i+am]*(1-h[i]) if 0 <= i <= n-am-1 and i+am < n
                    a = 0.0
                    b = 0.0
                    if 0 <= i-am <= n-am-1:
                        a += (1.0 - h[i-am])
                    if 0 <= i <= n-am-1 and i+am < n:
                        a += -h[i+am]
                        b += h[i+am]
                    a_vals.append(a)
                    b_vals.append(b)
            
            a_vals = np.array(a_vals)
            b_vals = np.array(b_vals)
            
            if len(a_vals) == 0:
                continue
            
            # Minimize max_m (a_m * x + b_m) over x in [0, 1]
            # The minimum is at the point where the maximum is minimized
            # This is a 1D convex problem
            # We can use binary search or find the intersection points
            
            # Quick approach: try x=0, x=1, and the "balanced" point
            # The balanced point satisfies a_max * x + b_max = a_min * x + b_min
            # where a_max and a_min are the lines with highest and lowest slopes
            # Actually, the minimum of max of lines is at the point where
            # two lines cross and all others are below.
            
            # Simple approach: ternary search on [0, 1]
            def obj_1d(x):
                return float(np.max(a_vals * x + b_vals))
            
            # Ternary search
            lo, hi = 0.0, 1.0
            for _ in range(30):
                m1 = lo + (hi - lo) / 3
                m2 = hi - (hi - lo) / 3
                if obj_1d(m1) < obj_1d(m2):
                    hi = m2
                else:
                    lo = m1
            x_new = (lo + hi) / 2
            
            # Also check boundaries
            candidates = [0.0, 1.0, x_new]
            best_x = min(candidates, key=obj_1d)
            
            if obj_1d(best_x) < obj_1d(old_val) - 1e-12:
                h[i] = best_x
                improved = True
        
        # Check if improvement
        c_new = compute_c5(h, n)
        if c_new < best_c - 1e-14:
            best_c = c_new
            best_h = h.copy()
        elif not improved:
            break
    
    return best_h, best_c
```

This coordinate descent is O(n * |active| * n_active) per round, where n_active is the number of active lags. For n=300 and ~10 active lags, each round is about 300 * 10 * 30 = 90000 operations, which is very fast.

The ternary search adds a factor of 30, so each round is about 2.7 million operations. For 50 rounds, that's about 135 million operations, which should take a few seconds.

This is a fundamentally different approach from the gradient-based methods and might find a different local optimum!
