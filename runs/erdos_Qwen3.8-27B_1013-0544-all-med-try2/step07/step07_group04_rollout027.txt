def compute_c5(h, n):
    dx = 2.0 / n
    c = np.correlate(h, 1 - h, mode='full')
    return float(np.max(c) * dx)

def project_feasible(h, n):
    target = n / 2.0
    h = np.clip(h, 0.0, 1.0)
    for _ in range(100):

            break
        if diff > 0:
            room = 1.0 - h
            s = room.sum()
            if s < 1e-14:
                break
            h = h + diff / s * room
        else:
            s = h.sum()
            if s < 1e-14:
                break
            h = h + diff / s * h
    return np.clip(h, 0.0, 1.0)

    n_ones = n // 2
    idx = np.argsort(h)[::-1]
    b = np.zeros(n)
    b[idx[:n_ones]] = 1.0
    return b

        i = zeros[rng.randint(len(zeros))]

        b[i] = 1.0

            b[i] = 0.0

        m = g.max()

Actually, let me try a fundamentally different approach: **use the fact that the problem is equivalent to a game/linear programming problem**.

Consider: C₅ = max_k ∫h(x)(1-h(x+k))dx

We want to minimize this. Note that:
∫h(x)(1-h(x+k))dx = ∫h(x)dx - ∫h(x)h(x+k)dx = 1 - ∫h(x)h(x+k)dx

So C₅ = max_k (1 - ∫h(x)h(x+k)dx) = 1 - min_k ∫h(x)h(x+k)dx

We want to minimize C₅, which is equivalent to maximizing min_k ∫h(x)h(x+k)dx.

So the problem is: find h ≥ 0, ∫h = 1, 0 ≤ h ≤ 1, to maximize min_k ∫h(x)h(x+k)dx.

This is a max-min problem. By minimax, this equals:
min_t max_h [t - min_k R_k(h)] where R_k(h) = ∫h(x)h(x+k)dx

Or equivalently, find the largest t such that there exists h with R_k(h) ≥ t for all k.

This is a feasibility problem for a given t:
Does there exist h ∈ [0,1]^n, ∑h = n/2, such that ∑_i h[i]h[i+k] ≥ t for all k?

This is a system of quadratic inequalities, which is non-convex.

However, we can use a **bisection + SOCP relaxation** approach:
- For a given t, check feasibility
- Use a relaxed version (e.g., drop the quadratic constraints and use linear approximations)

Actually, let me try a different angle. What if I use **iterated linearization** (like the Cutting Plane method)?

1. Start with a feasible h
2. Compute all R_k(h) = ∑_i h[i]h[i+k]
3. Find the minimum: R_min = min_k R_k(h), achieved at k*
4. Linearize R_{k*}(h) at current h: R_{k*}(h') ≈ R_{k*}(h) + ∇R_{k*}(h)·(h'-h)
5. Solve: max t subject to t ≤ R_{k*}(h') (linearized), ∑h'=n/2, 0≤h'≤1
6. Update h, go to 2

This is essentially a **cutting plane / Benders decomposition** approach.

Step 5 is a linear program (LP) since R_{k*} linearized is linear in h'.

The gradient of R_k(h) = ∑_i h[i]h[i+k] with respect to h[j]:
= h[j+k] (if j+k valid) + h[j-k] (if j-k valid)
= ∂/∂h[j] ∑_i h[i]h[i+k]

So the linearized constraint is:
t ≤ R_k(h_0) + ∑_j (h_0[j+k] + h_0[j-k])(h[j] - h_0[j])

This is linear in h! So step 5 is an LP.

We can use scipy.optimize.linprog or cvxpy for this.

def cutting_plane_multi(h0, n, deadline, max_iter=200):
    from scipy.optimize import linprog
    dx = 2.0 / n
    h = h0.copy()
    n_ones = n // 2
    cuts = []  # List of (grad, r_val) pairs
    
    for it in range(max_iter):
        if time.time() > deadline:
            break
        
        # Compute all R_k and find the worst
        corr = np.correlate(h, h, mode='full')
        # c5 = max_k correlate(h, 1-h, full) * dx
        # Let me just use the direct computation
        c5_direct = compute_c5(h, n)
        
        # Find all k that are near-maximizing for C5
        c_vals = np.correlate(h, 1-h, mode='full') * dx
        k_max = np.argmax(c_vals)
        
        # For the maximizing shift, we want to decrease c_{k_max}
        # c_k = sum_n h[n+k](1-h[n]) = sum_n h[n+k] - R_k(h)
        # To decrease c_k, we can either decrease sum_n h[n+k] or increase R_k(h)
        # The gradient of c_k w.r.t. h[j]:
        # dc_k/dh[j] = (1-h[j-k])*1(j-k valid) - h[j+k]*1(j+k valid)
        
        k = k_max - (n - 1)  # Convert index to shift
        idx = np.arange(n)
        grad_c = np.zeros(n)
        # (1-h[j-k]) for j-k valid
        mask1 = (idx - k >= 0) & (idx - k < n)
        grad_c[mask1] += (1 - h[idx[mask1] - k])
        # -h[j+k] for j+k valid
        mask2 = (idx + k >= 0) & (idx + k < n)
        grad_c[mask2] -= h[idx[mask2] + k]
        
        # Add cut: c_k(h') ≤ c_k(h) (linearized)
        # c_k(h') ≈ c_k(h) + grad_c · (h' - h)
        # grad_c · h' ≤ c_k(h) - grad_c · h
        
        cuts.append((grad_c.copy(), c_vals[k_max] - grad_c.dot(h)))
        
        # Solve LP with all cuts
        # Variables: h[0..n-1], t
        # Minimize t
        # Subject to: for each cut (g, b): g · h - t ≤ b  => -g·h + t ≥ -b... 
        # Hmm, let me reformulate.
        # We want: c_k(h') ≤ t for all k (cuts)
        # Linearized: grad_c · h' + const ≤ t
        # i.e., grad_c · h' - t ≤ -const
        
        # Actually, let me use a different LP formulation:
        # Minimize t
        # Subject to: for each cut j: grad_j · h ≤ t - const_j
        #   i.e., grad_j · h - t ≤ -const_j
        #         sum(h) = n/2
        #         0 ≤ h ≤ 1
        #         t ≥ 0
        
        n_cuts = len(cuts)
        c_obj = np.zeros(n + 1)
        c_obj[n] = 1.0  # Minimize t
        
        A_ub = np.zeros((n_cuts, n + 1))
        b_ub = np.zeros(n_cuts)
        for ci, (g, b_val) in enumerate(cuts):
            A_ub[ci, :n] = g
            A_ub[ci, n] = -1.0
            b_ub[ci] = -b_val
        
        A_eq = np.zeros((1, n + 1))
        A_eq[0, :n] = 1.0
        b_eq = np.array([float(n_ones)])
        
        bounds_lp = [(0, 1)] * n + [(0, None)]
        
        res = linprog(c_obj, A_ub=A_ub, b_ub=b_ub, A_eq=A_eq, b_eq=b_eq,
                      bounds=bounds_lp, method='highs')
        
        if res.status != 0:
            break
        
        h_new = project_feasible(res.x[:n], n)
        c5_new = compute_c5(h_new, n)
        
        if c5_new < c5_direct - 1e-10:
            h = h_new
        else:
            break
    
    return h, compute_c5(h, n)

This is a proper cutting plane method! Each iteration:
1. Find the worst shift k
2. Linearize c_k at current h
3. Add the linear constraint to the LP
4. Solve the LP to get a new h
5. Repeat

This is a valid approach for min-max problems. The LP grows by one constraint per iteration, but with n=250 and maybe 50-100 iterations, the LP has at most 100 constraints on 251 variables, which is very fast.

The key advantage: this is a GLOBAL method (not local), as it adds valid constraints. It's similar to the ellipsoid method or Benders decomposition.

Fix all but one coordinate, optimize that coordinate, repeat. For the max-min structure:

2. Finding all intersection points of the lines in [0,1]
3. Evaluating the max at each breakpoint
4. Taking the minimum
