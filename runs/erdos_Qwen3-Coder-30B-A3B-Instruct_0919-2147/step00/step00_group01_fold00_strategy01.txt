**Goal** – Produce a step function `h` on `[0,2]` (discretised with `n_points` samples) satisfying  

* `0 ≤ h[i] ≤ 1` for every sample,  
* `∑ h[i]·dx = 1`  (equivalently `∑ h[i] = n_points/2`),  

that minimises  

```
C5 = max_k  ∫_0^2 h(x)·(1 – h(x+k)) dx
     = 1 – min_k  ∫_0^2 h(x)·h(x+k) dx .
```

Thus we **maximise** the *minimum* auto‑correlation value over all integer shifts of the discrete vector.

The optimisation is non‑convex because the auto‑correlation is quadratic in `h`.  
The plan below combines a **projected sub‑gradient ascent** on a smooth approximation of the min‑correlation with a **focused binary local search** that exploits exact incremental updates.  The two phases are run sequentially within the 600 s wall‑clock budget, repeatedly restarting from different initialisations and discretisations.

--------------------------------------------------------------------
### 1. Common building blocks

| Block | Description |
|-------|-------------|
| **Correlation (`corr`)** | For a vector `h` (length `N`) we need the linear correlation `c[k] = ∑_i h[i]·h[i+k]` for `k = -(N‑1)…(N‑1)`.  It is computed efficiently by FFT:  `H = rfft(h, n = P)` where `P` is the next power‑of‑two ≥ `2·N‑1`; `c = irfft(H·conj(H), n=P)[:2·N‑1] * dx`. |
| **Projection onto the box + sum hyper‑plane** | Given a provisional vector `x`, we must find the closest `z` (in Euclidean norm) such that `0 ≤ z[i] ≤ 1` and `∑ z[i] = target = N/2`.  The solution is `z[i] = clip(x[i] + λ, 0, 1)` where the scalar `λ` is the unique root of `φ(λ) = ∑ clip(x[i] + λ,0,1) – target`.  `φ` is monotone, so a binary search (≈60 iterations) yields `λ` to machine precision. |
| **Soft‑minimum weighting** | To obtain a differentiable surrogate for `min_k c[k]` we use a temperature‑controlled “soft‑min”:  

```
w[k] = exp( -α·(c[k] – c_min) ),   w ← w / ∑ w .
```

`α` starts small (≈1) and is increased slowly (≈×1.1 every few hundred iterations) so that early steps see a smooth landscape while later steps focus on the true worst shift. |
| **Sub‑gradient for the smoothed min** | For each shift `s = k – (N‑1)` the contribution of `c[k]` to `∑ w·c` has derivative `∂c/∂h[i] = h[i+s] + h[i‑s]` (out‑of‑range indices are treated as zero).  Hence the gradient of the surrogate (which we maximise) is  

```
g[i] = Σ_s w[s]·(h[i+s] + h[i‑s]) .
```

A naïve double loop (`O(N²)`) is cheap for `N ≤ 512`.  The gradient is symmetrised automatically because `w` is symmetric. |
| **Direction normalisation** | To keep step‑sizes comparable across iterations we use the unit direction `d = g / ‖g‖₂` (unless ‖g‖₂ = 0). |
| **Line‑search with projection** | For a candidate step length `η` we form `h′ = project( h + η·d )`.  If `C5(h′) < C5(h)` we accept; otherwise we try a reduced `η` (multiply by 0.5) up to a few trials.  If none improve, we keep the current `h` and optionally shrink the base `η`. |

### 3. Phase B – Binary local optimisation with exact incremental updates

The best vector from Phase A is usually fractional.  To possibly push the bound further we convert it to a **binary** configuration (a set of `N/2` “selected” indices) and then run a specialised hill‑climbing / simulated‑annealing search that works directly with the exact auto‑correlation values.

#### 3.1. Binaryisation
* Sort the entries of the Phase A best `h` in descending order.
* Take the `N/2` largest indices and set them to `1`; all others become `0`.  This yields a feasible binary vector `b`.

#### 3.2. Data structures
* Keep the current correlation array `c` (full length `2·N‑1`) updated after each move.  Instead of recomputing by FFT after every single swap, we employ an **incremental delta** formula:

```
Δc[k] =  ( h[i1+k] + h[i1‑k] ) – ( h[i0+k] + h[i0‑k] )
        + extra terms when i0+k = i1 or i1+k = i0 (handled automatically by the same expression)
```

Because the vector is binary (`h[i] ∈ {0,1}`) the terms are just 0/1 checks.  Computing `Δc` for all shifts costs `O(N)` per swap.

* Maintain the current value `C5 = 1 – min(c)` and the index set `K_min = { k | c[k] = min(c) }`.

#### 3.3. Move generation
* **Targeted swap** – Choose a `1`‑position `i0` that *currently* contributes to the worst shift(s) (i.e., for some `k ∈ K_min`, either `b[i0] = 1` and `b[i0+k] = 0` or `b[i0‑k] = 0`).  Choose a `0`‑position `i1` that would *increase* the overlap for those shifts (i.e., `b[i1+k] = 1` or `b[i1‑k] = 1`).  Swapping `i0` ↔ `i1` tends to raise the minimum correlation.

* **Random swap** – Occasionally (e.g., 10 % of attempts) pick a completely random `1` and a random `0`.  This injects diversity and helps escape plateaus.

#### 3.4. Acceptance rule (Simulated Annealing)
* Define a temperature schedule `T(t)` that linearly decays from `T₀ = 0.01` to `0` over the allotted Phase B time.
* After computing the new correlation `c′ = c + Δc` and the new `C5′ = 1 – min(c′)`, accept the swap with probability  

```
p = 1               if C5′ < C5   (improvement)
p = exp( -(C5′‑C5)/T )   otherwise.
```

* If accepted, replace `b←b′`, `c←c′`, update `C5`, and adjust `K_min`.  If rejected, keep the state unchanged.

#### 3.5. Loop control
* Run swaps until the remaining time drops below about `budget_s·0.1`.  Typical swap rate with `N = 256` is ≈ 10 000 → 30 000 swaps per second, so even a few seconds afford many attempts.

* Periodically (every 1 000 accepted swaps) recompute the full correlation via FFT to eliminate accumulated numeric drift.

* Keep the best binary vector encountered (lowest `C5`) in a separate variable.
