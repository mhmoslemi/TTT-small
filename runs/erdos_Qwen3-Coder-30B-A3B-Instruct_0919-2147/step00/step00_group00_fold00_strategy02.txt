**I.  Problem reformulation**

1. **Discrete representation**  
   - Choose an odd number `N` (e.g. 401 – 801) of equally spaced points `x_i = (i+½)·dx` on `[0,2]` with `dx = 2/N`.  
   - The vector `h ∈ ℝ^N` stores the step‑function values: `h_i = h(x_i)`.  

2. **Constraints**  
   - Box: `0 ≤ h_i ≤ 1` for all `i`.  
   - Integral: `∑_i h_i·dx = 1`.  Equivalently `∑_i h_i = N/2`.  
   - The search space is the intersection of a hyperplane with the unit cube.

3. **Objective**  
   - For a shift of `k = m·dx` (integer `m` ranging `-(N‑1)…N‑1`) the discrete overlap is  
     `C(m) = dx·∑_{i=0}^{N‑1} h_i·(1‑h_{i+m})` where out‑of‑range indices give value 0.  
   - Using `np.correlate` this is exactly the “full” cross‑correlation `conv = correlate(h, 1‑h)·dx`.  
   - Desired cost: `C₅(h) = max_m C(m)`.  
   - Since `dx·∑ h_i = 1` is constant, `C(m) = 1 - dx·∑ h_i·h_{i+m}`.  
     Hence minimizing `C₅` is equivalent to **maximizing the minimal auto‑correlation**  
     `ρ(m) = dx·∑ h_i·h_{i+m}` over all shifts `m`.

### 2. Fast evaluation of the objective

- Compute the full correlation via FFT (linear‑convolution with zero padding):  
  *Zero‑pad both vectors to length `L = 2·N`, take real FFT (`rfft`), multiply `H·conj(G)`, inverse FFT, keep the first `2·N‑1` samples, then multiply by `dx`.*  
- This yields `conv[m] = C(m)` for all `m` in `O(N log N)` time, far faster than naïve `O(N²)` for `N≈800`.

Result needed per iteration:  
  - `c_max = max(conv)`

Both are available from the FFT output without extra work.

### 3. Projection onto the feasible set

**Box projection** – clamp each component: `h ← clip(h,0,1)`.

**Hyperplane projection (sum = N/2)** – perform a *water‑filling* (a.k.a. Euclidean projection onto a simplex with upper bound 1):
```
while True:
    current_sum = h.sum()
    deficit   = target_sum - current_sum
    if |deficit| < 1e‑12: break
    free = indices where 0 < h_i < 1
    if free is empty: break
    delta = deficit / len(free)
    h[free] += delta
    clip again (some may hit 0 or 1)
```
Iterates at most a couple of times because the initial vector is already close to the hyperplane after a gradient step.

A combined routine `project_feasible(h)` returns a vector satisfying both constraints exactly (up to floating‑point tolerance).

### 4. Parametric families for the *coarse* search

The optimal shape is known to be roughly “high in the middle, low on the sides”. Two simple families capture this:

#### A. Triangular / Trapezoidal shape (one free parameter)

- Let `w ∈ [0,1]` be the width of a central flat plateau at value 1.
- The remaining mass `1-w` must be placed in two symmetric linear slopes of total area `1-w`.  
  If `s = 1 - w` (the slope length on each side), the continuous function is:
  ```
  h(x) = 1                           for |x‑1| ≤ w/2
         1 - (|x‑1| - w/2)/s         for w/2 < |x‑1| ≤ w/2 + s
         0                           otherwise
  ```
- For each `w` (grid step 0.001) build the discrete vector, apply `project_feasible`, evaluate `C₅`. Store the best pair `(w, h)`.

#### B. Three‑level “plateau‑mid‑low’’ shape (two free parameters)

- Central plateau width `w₁` with height 1.
- Symmetric side blocks of constant height `c ∈ (0,1]` and total side width `w₂`.  
  The area constraint `w₁·1 + w₂·c = 1` gives `w₂ = (1‑w₁)/c`.  
  Feasibility requires `w₁ + w₂ ≤ 2` (the shape must fit inside `[0,2]`).  
- Build the discrete vector:
  ```
  h = 1      if |x‑1| ≤ w₁/2

  ```
- Scan `w₁` on a coarse grid (e.g. step 0.02) and `c` on a grid (step 0.02).  
- After each construction, run `project_feasible` (to correct the tiny discretisation error) and evaluate `C₅`. Keep the best candidate.

Both families are cheap to evaluate (≈ 10 k designs) and normally produce `C₅` already below 0.38 for a reasonable `N`.

### 5. Local refinement – projected sub‑gradient descent

Given a feasible vector `h`:

1. **Identify worst shift**  
   - Use the FFT routine → get `m*` where `C(m*) = C₅(h)`.

2. **Compute sub‑gradient of `C₅` at `h`**  
   - For a fixed shift `m*`, the derivative of `C(m*)` w.r.t. `h_i` is  
     `∂C/∂h_i = -dx·(h_{i+m*} + h_{i‑m*})` (zero outside range).  
   - The sub‑gradient `g` is this vector (the max is attained uniquely or we can pick any one of the ties).

3. **Gradient step** (descent direction = `‑g`)  
   - Choose a step size `α`.  A practical schedule: start `α₀ = 0.8`, then multiply by `β = 0.999` each iteration, never letting `α` drop below `1e‑4`.  
   - Update: `h ← h - α·g`  (equivalently `h ← h + α·dx·(h shifted by ±m*)`).  
   - This move increases the overlap of `h` with its worst‑shifted copy, thereby lowering `C₅`.

4. **Projection** – call `project_feasible(h)` to re‑impose `[0,1]` and the sum constraint.

5. **Acceptance & bookkeeping**  
   - Compute the new `C₅`.  
   - If it improves the best recorded value, store a copy of `h`.  
   - Optionally implement a simple *backtracking*: if `C₅` increases, reject the step (or halve `α` and retry).

6. **Stopping criteria**  
   - Fixed number of iterations (e.g. 2000) **or** stop early when the improvement over the last 100 iterations is < 1e‑6.  
   - Always respect the global time budget.
