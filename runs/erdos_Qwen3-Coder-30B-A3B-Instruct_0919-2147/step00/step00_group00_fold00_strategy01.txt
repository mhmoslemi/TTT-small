### 1.  Overall Goal  
Find a discretised step‑function  

\[
h\;:\;[0,2]\rightarrow[0,1],\qquad 
\sum_{i=0}^{N-1} h_i\,dx = 1\;(dx=2/N)
\]

that minimizes  

\[
C_5(h)=\max_{k}\int_0^{2}h(x)\bigl(1-h(x+k)\bigr)\,dx .
\]

The discrete analogue is  

\[
C_5(h)=\max_{s\in\{-N+1,\dots,N-1\}} 
\bigl(h\star(1-h)\bigr)_s\,dx ,
\]

where “\(\star\)” is the linear (zero‑padded) cross‑correlation.  
The task is a **non‑convex minimax** problem with simple box and equality constraints.

The strategy below departs completely from the local gradient‑descent approach previously discussed.  
It employs a **global stochastic optimizer (simulated annealing)** that explores the feasible space while respecting the constraints, and uses a **fast FFT‑based evaluation** of the objective at each step.  The method is robust to many local minima and needs only a modest number of parameters.

### 2.  Discretisation & Pre‑computations  

1. **Choose the grid size**  
   *Pick a moderate size that balances resolution and speed, e.g. `N = 256` (any even number < 1000).  
   `dx = 2.0 / N`.  
   The target sum is `S_target = N/2`.

2. **FFT length**  
   For fast correlation we zero‑pad to length `L = 2*N` (nearest power of two is optional).  
   All FFTs will be performed with `np.fft.rfft`/`irfft` to keep them real‑valued and cheap.

3. **Pre‑compute indices**  
   Store the index of the “zero‑shift” element: `shift0 = N-1`.  
   This allows conversion from a correlation index `idx` to an integer shift `s = idx - shift0`.

### 3.  Feasibility Projection  

Every candidate vector must satisfy

* Box constraints: `0 ≤ h_i ≤ 1`.  
* Equality constraint: `∑ h_i = S_target`.

A fast **water‑filling / projection** routine is used after every proposal:

1. Clip the vector to `[0,1]`.  
2. Compute the current sum `S = ∑ h_i`.  
3. If `S ≠ S_target`, distribute the deficit/excess uniformly over the *free* coordinates (those strictly between 0 and 1).  
   Iterate: after each redistribution, clip again, recompute the free set and the remaining deficit.  
   Because the starting point is close to feasible, the loop converges in at most a handful of passes.

The projector returns a feasible `h` with negligible numerical error (‖∑h - S_target‖ < 1e‑12).

---

### 4.  Objective Evaluation (FFT‑based)

Given a feasible `h`:

1. Compute the FFT of `h` and of `1‑h` (both padded to length `L`).  
   ```
   H = rfft(h, n=L)
   G = rfft(1 - h, n=L)
   ```
2. Compute the inverse FFT of the product `H * conj(G)`.  
   The real part yields the linear correlation vector `c` of length `L`.  
3. Truncate to the usable part `c[:2*N‑1]` and multiply by `dx`.  
4. The maximum entry `c_max` is the current value of `C_5`.  
   The index `idx_max` gives the worst shift `s_max = idx_max - shift0` (used later for gradient‑free proposals).

All steps are vectorised and executed in compiled code, so a single evaluation costs `O(N log N)` and is negligible even for thousands of iterations.

### 5.  Simulated Annealing Framework  

#### 5.1.  State Representation  

The state is the feasible vector `h`.  
We keep a *current* state `h_cur` and the *best* ever seen `h_best` together with their objective values `C_cur` and `C_best`.

#### 5.2.  Proposal Mechanism  

To preserve the sum constraint **exactly** we modify *pairs* of entries:

1. Randomly pick two distinct indices `i` and `j`.  
2. Draw a signed perturbation `Δ` from a uniform distribution  
   `Δ ∈ [‑δ, +δ]`, where `δ` is a scale parameter that adapts with temperature.  
3. Propose  

   ```
   h'_i = h_i + Δ
   h'_j = h_j - Δ
   ```

   All other entries stay unchanged.  

4. If either `h'_i` or `h'_j` falls outside `[0,1]`, the proposal is rejected immediately.  
   (Alternatively, clamp and reject only when the required Δ cannot be realised.)

This move **keeps the total sum unchanged** and never violates the box constraints when accepted.

#### 5.3.  Temperature Schedule  

*Initial temperature* `T₀` is chosen from a short pilot run: sample 50 random feasible vectors, record the standard deviation `σ₀` of their `C_5` values, and set  
`T₀ = α·σ₀` with `α ≈ 0.8`.  

*Cooling* follows a **geometric schedule**  

```
T_{k+1} = γ·T_k   with   γ = 0.9995   (or tuned for the allotted time)
```

The perturbation scale `δ` is tied to the temperature, e.g.  

`δ = δ_max·(T / T₀)` where `δ_max` is a fixed upper bound (e.g. 0.2).  
Thus, early in the run large moves are possible, later only fine adjustments survive.

#### 5.4.  Acceptance Rule  

Let `ΔC = C_new – C_cur`.  

* If `ΔC ≤ 0` (the move improves or ties) → **accept**.  
* Else accept with probability `p = exp(‑ΔC / T)`.  

A **Metropolis‑Hastings** step produces a controlled random walk that can escape local minima while gradually focusing on improvement as the temperature drops.

#### 5.5.  Recording the Best  

After each accepted move (or even after each trial, regardless of acceptance) compute the objective; if it is **strictly lower** than `C_best`, store the new vector as `h_best`.  

Optionally keep a short history (e.g., last 20 best values) to monitor convergence and to allow early termination if improvement stalls.

### 6.  Additional Enhancements  

1. **Symmetry enforcement** – The optimal solution is known to be symmetric around the midpoint `x=1`.  
   Impose `h_i = h_{N‑1‑i}` after each projection. This halves the effective dimensionality and reduces the search space dramatically.  

2. **Hybrid Restarts** – After the temperature reaches a low value (e.g., 1 % of `T₀`) perform a *restart*: keep the current best `h_best`, add a small random perturbation to all entries (followed by projection) and resume annealing. This helps to explore neighborhoods that may have been missed.

3. **Periodic “big jumps”** – Every `K` iterations (e.g. `K = 2000`) propose a *global* move: pick 5–10 indices and redistribute a random amount among them while preserving the sum. Accept only if the Metropolis criterion holds. This injects additional diversity without breaking the box constraints.

4. **Parallel‑tempering (optional)** – If the CPU permits, run two annealers at different temperatures simultaneously and periodically attempt to swap their states (always accept when the higher‑temperature state is better). This classic technique reduces the probability of getting trapped.

5. **Early‑stop on time** – Continuously monitor `time.time()`. As soon as the elapsed time exceeds `budget_s * 0.95` stop the loop, return the best vector found so far. This guarantees compliance with the 600 s limit.
