### Overview
The task is to construct a step‑function  
\(h:[0,2]\to[0,1]\) with \(\int_0^2h=1\) that minimises  

\[
C_5(h)=\max_{k\in\mathbb R}\int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx .
\]

Because the evaluator works on a uniform grid, we discretise the interval into \(n\) points (the “grid size”).  
Instead of using local descent, smooth approximations, or stochastic heuristics, the new approach **recasts the problem as a sequence of linear (or mixed‑integer) programs** that converge to the global optimum of the discretised problem. The core idea is:

1. **Linearise each quadratic term \(h_i\,h_j\) by McCormick envelopes** (exact when \(h\) is binary, a tight convex hull when \(h\in[0,1]\)).
2. **Introduce a scalar variable \(t\)** to bound the maximum overlap.  
3. **Add constraints \(t\ge\sum_i\bigl(h_i - y_{i,k}\bigr)\) for each shift \(k\)**, where \(y_{i,k}\) approximates the product \(h_i\,h_{i+k}\).
4. **Solve the resulting linear program** (LP).  
5. **Evaluate the true max‑overlap** for the computed \(h\).  
6. **If the true overlap exceeds the bound \(t\)**, add the offending shift \(k^\*\) to the constraint set and resolve.  
7. **Iterate (cutting‑plane loop)** until the LP bound equals the true objective (within a tiny tolerance).

This **cutting‑plane LP/MILP scheme** is fundamentally different from gradient descent or simulated annealing: it guarantees global optimality for a given grid size, uses only linear constraints, and converges via a finite number of added shift constraints.

### 1. Discretisation and variables

* Choose a grid size \(n\) (odd numbers like 45, 61, 81 are convenient).  
* Grid step \(dx = 2/n\).  
* Decision variables:  
  * \(h_i\in[0,1]\) for \(i=0,\dots,n-1\).  
  * For each active shift \(k\) we introduce auxiliary variables \(y_{i,k}\) intended to model \(h_i h_{i+k}\) (indices out of range are interpreted as 0).  
* Mass constraint: \(\sum_{i=0}^{n-1} h_i = n/2\) (ensures \(\int h =1\)).  

If we want an *exact* integer formulation we can restrict each \(h_i\) to be binary (0/1). The binary case makes the product exact without relaxation and yields a pure MILP. For a mixed‑continuous formulation we retain \(h_i\in[0,1]\) and use McCormick envelopes.

---

### 2. Linearisation of the product

For any two variables bounded in \([0,1]\),

\[
y_{i,k}=h_i h_{i+k}\quad\Longrightarrow\quad 
\begin{aligned}
y_{i,k}&\le h_i,\\
y_{i,k}&\le h_{i+k},\\
y_{i,k}&\ge h_i+h_{i+k}-1,\\
y_{i,k}&\ge 0.
\end{aligned}
\]

These four linear inequalities describe the convex hull of the bilinear term over the unit box (the McCormick envelope). When both arguments are binary the envelope collapses to the exact product.

---

### 3. Bounding the max‑overlap with a single variable \(t\)

For a fixed shift \(k\),

\[
\sum_{i} h_i\bigl(1-h_{i+k}\bigr)=\sum_i h_i - \sum_i h_i h_{i+k}
   = \underbrace{\sum_i h_i}_{=n/2} - \sum_i y_{i,k}.
\]

Because \(\sum_i h_i\) is constant, the term we need to bound for each shift is simply \(-\sum_i y_{i,k}\). Introducing a scalar \(t\) that dominates **all** such expressions yields the linear constraints

\[
t \;\ge\; \sum_i h_i - \sum_i y_{i,k}
\quad\text{for every shift }k\text{ currently in the active set}.
\]

The objective is to **minimise \(t\)**.

---

### 4. Cutting‑plane algorithm (LP version)

1. **Initial active set**  
   Start with a small set of shifts, e.g. \(\mathcal K=\{0\}\) (trivial constraint) and optionally the shift that is halfway across the interval (\(k=n/2\)).  

2. **Build the LP**  
   * Variables: \(h\), all \(y_{i,k}\) for \(k\in\mathcal K\), and \(t\).  
   * Constraints: box on \(h\), mass constraint, McCormick constraints for each \(y_{i,k}\), and the bound constraints \(t\ge\sum_i h_i - \sum_i y_{i,k}\).  

3. **Solve** the LP using a fast linear‑programming solver accessible from CVXPY (e.g. ECOS, OSQP, or, if available, CBC/Gurobi). The solution provides an **upper bound** \(t^\*\) on the true max‑overlap.

4. **Exact evaluation**  
   * Compute the real correlation vector \(c = \operatorname{corr}(h,1-h)\).  
   * Obtain the actual max overlap \(C = dx\cdot\max(c)\).  

5. **Optimality test**  
   * If \(C \le t^\* + \varepsilon\) (with \(\varepsilon\) e.g. \(10^{-7}\)), the LP solution is feasible for the original non‑linear problem; stop – we have the optimal discretised bound.  
   * Otherwise, identify the offending shift \(k^\* = \arg\max C_k\). Add \(k^\*\) to \(\mathcal K\) and **re‑solve**.  

6. **Iterate** steps 3–5. Because each iteration adds at least one new shift, the algorithm terminates after at most \(2n-1\) iterations, but in practice convergence occurs after a handful (often < 10) of cuts.

---

### 5. MILP alternative (binary \(h\))

If the solver supports mixed‑integer programming, force each \(h_i\) to be binary:

* Replace the continuous box constraints with \(h_i\in\{0,1\}\).  
* The McCormick constraints become exact equalities: \(y_{i,k}=h_i h_{i+k}\) is equivalent to the logical AND \({y_{i,k} = 1}\iff{h_i = h_{i+k}=1}\).  
* The problem is then a **pure MILP**: minimise \(t\) subject to linear constraints and 0‑1 variables.  
* Modern MILP solvers (CBC, GLPK, or commercial ones if present) can solve the binary formulation for \(n\le 80\) within seconds, providing a provably optimal binary step‑function.  

The binary solution often yields a tighter bound than a naïve continuous relaxation because the objective (a max of linear forms) is piecewise linear and attains its minimum at an extreme point of the feasible polytope.

### 6. Multi‑scale refinement

The LP/MILP approach works reliably for moderate grid sizes (e.g., \(n=45, 61, 81\)). To obtain a finer discretisation without blowing up the problem size:

1. **Solve** the problem for a coarse grid \(n_0\) (e.g., 45).  
2. **Interpolate** the optimal \(h^{(0)}\) onto a finer grid \(n_1=2n_0\) using linear interpolation, then **project** onto the capped simplex to satisfy the mass constraint exactly.  
3. **Warm‑start** the LP for \(n_1\) with the interpolated values (initial values for \(h\), initialise \(y_{i,k}\) from the product of interpolated entries).  
4. **Run the cutting‑plane loop** again.  

Because the finer problem starts close to a good solution, only a few additional cuts are needed, keeping the total runtime well within the 600 s budget.
