**Goal:**  Produce a step‑function `h` on `[0,2]` (discretised with `n` points) that satisfies  
`0 ≤ h[i] ≤ 1`, `∑ h[i]·dx = 1` (`dx = 2/n`) and minimises  

```
C5 = max_k  ∫0^2 h(x)·(1‑h(x+k)) dx
```

In the discrete setting  

```
C(k) = dx * Σ_i h[i]·(1‑h[i+k])   (correlation, out‑of‑range indices are ignored)
C5 = max_k C(k)
```

The problem is a **max‑min quadratic programme** because `C(k)=dx·( Σ h[i] – Σ h[i]h[i+k] )`.  
If `h` is binary (`h[i]∈{0,1}`) then `Σh[i]=n/2` is fixed and  

```
C(k) = 1 – dx * Σ_i h[i]·h[i+k] .
```

Thus minimising `C5` is equivalent to **maximising the minimal self‑overlap**  
`Σ_i h[i]·h[i+k]` over all integer shifts `k`.  The binary restriction is natural:
the optimal continuous solution is known to be an indicator of a “fat Cantor” set, i.e. a
0–1 function.  Therefore we focus on a binary search space and solve the exact
combinatorial formulation with mixed‑integer linear programming (MILP).  The MILP
provides a proven upper bound on the constant and can be refined by a fast
local‑search post‑processor.

### 1.  MILP formulation

For a fixed even `n` (e.g. `n = 52, 60, 66`) define binary variables  

```
x_i ∈ {0,1}    , i = 0,…,n‑1                (h[i] = x_i)
```

Weight constraint (integral = 1):

```
Σ_i x_i = n/2 .
```

For each shift `s ∈ {‑(n‑1), …, n‑1}` introduce auxiliary variables  
`y_{i,s}` that linearise the product `x_i·x_{i+s}` (only when both indices are
in range, otherwise the term is omitted).  Use the classic McCormick (big‑M) 
linearisation:

```
y_{i,s} ≤ x_i
y_{i,s} ≤ x_{i+s}
y_{i,s} ≥ x_i + x_{i+s} – 1
y_{i,s} ≥ 0      (redundant because of binary x’s)
```

The overlap for shift `s` is

```
overlap_s = dx * Σ_{i} y_{i,s} .
```

Introduce a scalar variable `t` that bounds the worst overlap:

```
t ≥ 1 – overlap_s        for every shift s .
```

The objective is to **minimise t** (i.e. minimise the maximal C‑value).  

All constraints are linear, the only integer variables are the `x_i`.  The
MILP size is O(n²) (≈ 2 000–5 000 binary variables for `n≈60`) which is
tractable for modern open‑source solvers (CBC, GLPK) inside the 600 s budget.
