```python
def lse_grad(h, n, alpha):
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    max_c = corr.max()
    shifted = alpha * (corr - max_c)
    max_shifted = shifted.max()
    exps = np.exp(shifted - max_shifted)
    w = exps / exps.sum()
    
    grad = np.zeros(n)
    
    for k in range(1, n):
        wp = w[n-1+k]  # weight for positive lag k
        wn = w[n-1-k]  # weight for negative lag k
        
        if wp > 1e-14:
            # ∂g_k/∂h[j] = I(j>=k)*(1-h[j-k]) - I(j<=n-1-k)*h[j+k]
            grad[k:] += wp * (1.0 - h[:n-k])
            grad[:n-k] -= wp * h[k:]
        
        if wn > 1e-14:
            # ∂g_{-k}/∂h[j] = I(j<=n-1-k)*(1-h[j+k]) - I(j>=k)*h[j-k]
            grad[:n-k] += wn * (1.0 - h[k:])
            grad[k:] -= wn * h[:n-k]
    
    # k=0 term
    grad += w[n-1] * (1.0 - 2.0 * h)
    
    return grad * dx, max_c * dx
```

So yes, g_k is linear in h[j]! The coefficient of h[j] is:
a_k(j) = (1-h[j-k])*I(k≤j≤n-1) - h[j+k]*I(0≤j≤n-1-k)

And the constant term is:
b_k(j) = C_k + h[j+k]*I(0≤j≤n-1-k)

where C_k = g_k - (terms involving h[j]).

Now, the objective is f(h) = max_k g_k(h) = max_k (b_k + a_k * h[j])

This is the maximum of linear functions of h[j], which is a convex piecewise-linear function. Its minimum over h[j] ∈ [0,1] occurs at a "breakpoint" or at a boundary.

The breakpoints are where two lines intersect: b_k + a_k * t = b_m + a_m * t, i.e., t = (b_m - b_k)/(a_k - a_m).

So the optimal h[j] is the median-like value that minimizes the max of these lines, constrained to [0,1].

This gives us an exact coordinate descent step! Let me implement this.

For each coordinate j:
1. Compute a_k(j) and b_k(j) for all k
2. Find the value of h[j] ∈ [0,1] that minimizes max_k (b_k + a_k * h[j])
3. Update h[j]

The minimum of max_k (b_k + a_k * t) over t ∈ [0,1] can be found by:
- Evaluating at t = 0 and t = 1
- Finding all breakpoints in (0,1)
- Evaluating at each breakpoint
- Taking the minimum

But finding all breakpoints is O(n²) in the worst case (O(n) lines, O(n²) intersections). For n=400, that's 160K intersections to check, which is feasible but might be slow if done for each of the 400 coordinates.

A faster approach: use binary search on the value of the max.
- For a given threshold T, check if there exists t ∈ [0,1] such that b_k + a_k * t ≤ T for all k.
- This is a system of linear inequalities in t: t ≤ (T-b_k)/a_k (if a_k > 0) or t ≥ (T-b_k)/a_k (if a_k < 0).
- Feasible iff the lower bound ≤ upper bound and both are in [0,1].

Then binary search on T to find the minimum feasible T.

This is O(n log n) per coordinate update (O(n) to check feasibility, O(log precision) iterations).

For n=400 coordinates, one full sweep is O(n² log n) ≈ 400² × 9 ≈ 1.4M operations. Very fast!
