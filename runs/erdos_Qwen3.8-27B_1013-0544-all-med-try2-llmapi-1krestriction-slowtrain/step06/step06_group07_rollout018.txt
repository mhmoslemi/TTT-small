def coord_obj_1d(h, j, n, t, old_corr=None):
    """Compute max corr when h[j] is changed to t, efficiently."""
    if old_corr is None:
        old_corr = np.correlate(h, 1.0 - h, mode='full')
    delta = np.zeros(2*n-1)
    old = h[j]
    if t == old:
        return np.max(old_corr)
    
    for m in range(2*n-1):
        k = m - (n-1)
        if k == 0:
            delta[m] = t*(1-t) - old*(1-old)
        else:
            coeff = 0.0
            if 0 <= j-k < n:
                coeff += (1 - h[j-k])
            if 0 <= j+k < n:
                coeff -= h[j+k]
            delta[m] = coeff * (t - old)
    
    new_corr = old_corr + delta

1. Start from initial_h_values

3. After each sweep, project to maintain the sum constraint
4. Alternate with SLSQP for the joint optimization
5. Try multiple resolutions

Wait, there's a subtlety with the sum constraint. If I change h[j] to the optimal t, the sum changes. I need to either:
a) Handle the sum constraint in the 1D subproblem (more complex)
b) Project after each coordinate update (simpler but might not be exact)

Option (b) is simpler and should work fine in practice. The projection redistributes the sum error across all other coordinates with room (h[i] < 1 or h[i] > 0).

Actually, a better approach: after changing h[j], distribute the sum error to one other coordinate k (the one with the most room). This is a "pair swap" style update.

Or even better: use a "free" coordinate. Fix all coordinates except h[j] and one "free" coordinate h[f]. Then optimize both simultaneously to maintain the sum constraint. But this makes the 1D problem 2D.

I think the simplest approach is:
1. Optimize h[j] ignoring the sum constraint
2. Project the result to maintain the sum constraint (distribute the error)
3. Move to the next j

The projection will slightly undo the improvement, but over many sweeps it should converge.
