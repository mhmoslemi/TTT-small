Actually, for n=300, the direct computation is 2n-1 = 599 lags, each requiring up to n=300 multiplications. So about 599*300/2 ≈ 90K multiply-adds per correlate. That's very fast.

In numpy, np.correlate(h, 1-h, 'full') for n=300 should take about 10-50μs. Let me estimate: 22500 swaps * 30μs = 0.675s per full sweep. So in 1000s, we can do about 1500 full sweeps. That should be more than enough.

```python
import numpy as np
from scipy.optimize import minimize
import time

def compute_c5(h, n):
    dx = 2.0 / n
    return float(np.max(np.correlate(h, 1 - h, mode='full')) * dx)

def compute_c5_all(h, n):
    dx = 2.0 / n
    return np.correlate(h, 1 - h, mode='full') * dx

def project_feasible(h, n):
    target = n / 2.0
    h = np.clip(h.copy(), 0.0, 1.0)
    for _ in range(500):
        diff = target - h.sum()
        if abs(diff) < 1e-15:
            break
        if diff > 0:
            room = 1.0 - h
            tot = room.sum()
            if tot < 1e-15:
                break
            h += (diff / tot) * room
        else:
            tot = h.sum()
            if tot < 1e-15:
                break
            h += (diff / tot) * h
    return np.clip(h, 0.0, 1.0)

def binarize(h, n):
    target = n // 2
    order = np.argsort(h)[::-1]
    h_bin = np.zeros(n)
    h_bin[order[:target]] = 1.0
    return h_bin

def binary_local_search(h, n, deadline):
    """Best-improvement binary local search"""
    best_c = compute_c5(h, n)
    ones = np.where(h == 1.0)[0]
    zeros = np.where(h == 0.0)[0]
    
    while time.time() < deadline:
        best_improve = 0
        best_swap = None
        c_arr = compute_c5_all(h, n)
        max_c = c_arr.max()
        
        for i in ones:
            for j in zeros:
                # Compute change in correlation
                # h[i]: 1->0, h[j]: 0->1
                for m in range(n):
                    # Effect on lag m (shift by m)
                    # Position i as first index: was h[i]*(1-h[i+m]) = 1*(1-h[i+m])
                    # Position i as second index: was h[i-m]*(1-h[i]) = h[i-m]*1
                    # Position j as first index: was 0, now 1*(1-h[j+m])
                    # Position j as second index: was h[j-m]*1, now h[j-m]*0
                    pass
                # This inner loop is too slow. Let me just recompute.
                h[i] = 0.0
                h[j] = 1.0
                c_new = compute_c5(h, n)
                h[i] = 1.0
                h[j] = 0.0
                if c_new < best_c - best_improve:
                    best_improve = best_c - c_new
                    best_swap = (i, j)
        
        if best_swap is None:
            break
        i, j = best_swap
        h[i] = 0.0
        h[j] = 1.0
        best_c = compute_c5(h, n)
        ones = np.where(h == 1.0)[0]
        zeros = np.where(h == 0.0)[0]
    
    return h, best_c
```

Wait, this is O(n²/4 * n) per iteration = O(n³/4) = 6.75M for n=300. But each "compute_c5" call involves np.correlate which is O(n²) = 90K operations. So total per iteration is 22500 * 90K = 2B operations. That's too slow!

I need to be smarter. Let me use the incremental update approach.

For a swap of h[i]:1→0 and h[j]:0→1, the change in the p-th element of the full correlation (where p=0,...,2n-2) can be computed as:

The full correlation result[p] corresponds to a specific overlap pattern. Let me define it more carefully.

np.correlate(h, 1-h, 'full')[p] = sum_k h[k] * (1-h[k - (p - (n-1))])

where the sum is over valid k.

So for a given p, the shift is s = p - (n-1).
result[p] = sum_k h[k] * (1-h[k-s]) (summing over k where both k and k-s are in [0, n-1])

When h[i] changes from 1 to 0:
- If i is used as k: term h[i]*(1-h[i-s]) = 1*(1-h[i-s]) is removed
- If i is used as k-s (i.e., k = i+s): term h[i+s]*(1-h[i]) = h[i+s]*1 is removed

When h[j] changes from 0 to 1:
- If j is used as k: term h[j]*(1-h[j-s]) = 1*(1-h[j-s]) is added
- If j is used as k-s (i.e., k = j+s): term h[j+s]*(1-h[j]) = h[j+s]*0 = 0 was there, now h[j+s]*(1-1) = 0... wait no.
  Before: h[j+s]*(1-h[j]) = h[j+s]*1 = h[j+s]
  After: h[j+s]*(1-h[j]) = h[j+s]*0 = 0
  So we remove h[j+s].

Wait, I'm getting confused. Let me be very precise.

Let g = 1-h. Then result[p] = sum_k h[k] * g[k-s] where s = p-(n-1).

When h[i]: 1→0, we have g[i]: 0→1.
When h[j]: 0→1, we have g[j]: 1→0.

Change in result[p]:
- From h[i]: 1→0:
  - If i appears as k: contribution changes from h[i]*g[i-s] = 1*g[i-s] = g[i-s] to 0
    → change: -g[i-s] (if i-s is valid, i.e., 0 ≤ i-s ≤ n-1)
  - If i appears as k-s (k = i+s): contribution changes from h[i+s]*g[i] = h[i+s]*0 = 0 to h[i+s]*1 = h[i+s]
    → change: +h[i+s] (if i+s is valid)

- From h[j]: 0→1:
  - If j appears as k: contribution changes from 0*g[j-s] = 0 to 1*g[j-s] = g[j-s]
    → change: +g[j-s] (if j-s is valid)
  - If j appears as k-s (k = j+s): contribution changes from h[j+s]*g[j] = h[j+s]*1 = h[j+s] to h[j+s]*g[j] = h[j+s]*0 = 0
    → change: -h[j+s] (if j+s is valid)

Total change in result[p]:
Δresult[p] = -g[i-s] + h[i+s] + g[j-s] - h[j+s]

where terms are 0 if the index is out of [0, n-1].

In terms of h (since g = 1-h):
Δresult[p] = -(1-h[i-s]) + h[i+s] + (1-h[j-s]) - h[j+s]
            = h[i-s] - 1 + h[i+s] + 1 - h[j-s] - h[j+s]
            = h[i-s] + h[i+s] - h[j-s] - h[j+s]

where s = p - (n-1), and out-of-range indices contribute 0.

So for each swap (i,j), I need to compute:
Δresult[p] = h[i-s_p] + h[i+s_p] - h[j-s_p] - h[j+s_p] for p = 0, ..., 2n-2

where s_p = p - (n-1) ranges from -(n-1) to n-1.

This is a vectorized operation! I can precompute the "profile" for each index:
profile[i][s] = h[i-s] + h[i+s] (with out-of-range = 0)

This is a convolution-like operation. For all i and all s, this is O(n²) to precompute, but then each swap is just a vector subtraction of two precomputed profiles, which is O(n).

Even better: I can precompute all profiles in a (n, 2n-1) matrix, where row i and column p gives h[i-s_p] + h[i+s_p].

Let me define:
P[i, p] = h[i - s_p] + h[i + s_p] (with out-of-range = 0)

where s_p = p - (n-1) for p = 0, ..., 2n-2.

Then for a swap (i,j):
Δresult[p] = P[i, p] - P[j, p] for all p

And new result = old result + P[i] - P[j]
New max = max(old result + P[i] - P[j])

So I can compute the new max in O(n) after precomputing P in O(n²).

This means each swap evaluation is O(n), and a full sweep is O(n²/4 * n) = O(n³/4). For n=300: 6.75M simple operations (just additions, subtractions, and a max). In numpy, this would be very fast if vectorized.

But 22500 swaps * 599 elements = 13.5M operations per sweep. In pure Python, this might take a second or two. In numpy (vectorized over p), each swap is one vector operation of length 599, so 22500 * 599 * ~1ns = ~13ms per sweep! That's very fast.

Let me implement this:

```python
def binary_local_search_fast(h, n, deadline):
    best_c = compute_c5(h, n)
    ones = np.where(h == 1.0)[0]
    zeros = np.where(h == 0.0)[0]
    
    while time.time() < deadline:
        # Precompute correlation
        result = np.correlate(h, 1 - h, mode='full').astype(float)
        
        # Precompute profiles
        # P[i, p] = h[i-s_p] + h[i+s_p] where s_p = p - (n-1)
        s = np.arange(-(n-1), n)  # length 2n-1
        P = np.zeros((n, 2*n-1))
        for i in range(n):
            idx1 = i - s  # i - s_p for each p
            mask1 = (idx1 >= 0) & (idx1 < n)
            P[i, mask1] += h[idx1[mask1]]
            idx2 = i + s  # i + s_p for each p
            mask2 = (idx2 >= 0) & (idx2 < n)
            P[i, mask2] += h[idx2[mask2]]
        
        best_improve = 0
        best_swap = None
        
        for i in ones:
            for j in zeros:
                new_result = result + P[i] - P[j]
                new_max = new_result.max()
                improve = result.max() - new_max
                if improve > best_improve:
                    best_improve = improve
                    best_swap = (i, j)
        
        if best_swap is None:
            break
        i, j = best_swap
        h[i] = 0.0
        h[j] = 1.0
        best_c = compute_c5(h, n)
        ones = np.where(h == 1.0)[0]
        zeros = np.where(h == 0.0)[0]
    
    return h, best_c
```
