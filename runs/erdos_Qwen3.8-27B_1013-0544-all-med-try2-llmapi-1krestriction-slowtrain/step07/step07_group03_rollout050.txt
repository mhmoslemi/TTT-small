For a binary sequence, when we swap h[i]=0 to 1 and h[j]=1 to 0, the change in c at lag m is:
Δc[m] = (1-h[i+m]) - h[i-m] - (1-h[j+m]) + h[j-m]

This can be written as:
Δc[m] = (1-h[i+m]) + h[j-m] - (1-h[j+m]) - h[i-m]
       = [(1-h[i+m]) - h[i-m]] - [(1-h[j+m]) - h[j-m]]

Let d_i[m] = (1-h[i+m]) - h[i-m] (with boundary handling)
Then Δc[m] = d_i[m] - d_j[m]

So if I precompute d_i[m] for all i and m, I can evaluate any swap in O(1) (just checking if max(c + d_i - d_j) < current_max).

But checking max(c + d_i - d_j) is still O(N) in the worst case (need to check all m).

However, I can use the following trick: after a swap, c_new[m] = c[m] + d_i[m] - d_j[m] for all m. The new max is max_m c_new[m]. If I maintain a data structure for the maximum, I can update it in O(log N) per changed element.
