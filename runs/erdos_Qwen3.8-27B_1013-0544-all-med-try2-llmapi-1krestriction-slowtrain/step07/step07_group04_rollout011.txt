But wait, the projection is the tricky part. Let me think about it.

Projection onto {h: 0 ≤ h[i] ≤ 1 for all i, sum(h) = n/2}:

Algorithm:
1. Start with v (the point to project)
2. We need to find λ such that sum(clip(v[i] - λ, 0, 1)) = n/2
3. clip(v[i] - λ, 0, 1) = min(max(v[i] - λ, 0), 1)
   - If v[i] - λ > 1: contributes 1
   - If v[i] - λ < 0: contributes 0
   - Otherwise: contributes v[i] - λ

So: sum = count(v[i] > 1+λ) * 1 + sum_{0≤v[i]-λ≤1} (v[i]-λ) + count(v[i] < λ) * 0

This is a piecewise linear function of λ. We can find the right λ by:
1. Sort v
2. The breakpoints are at λ = v[i] and λ = v[i] - 1
3. Binary search for the right interval, then solve linear equation

Simpler approach: just binary search on λ directly.
- λ range: [min(v) - 1, max(v)]
- At each step, compute sum(clip(v - λ, 0, 1)) and check if it's > or < n/2
- Convergence in ~50 iterations (each O(n))

Total projection cost: O(n * 50) = O(12500) for n=250. That's fine.

Actually, there's a more efficient O(n log n) method:
1. Sort v: v[0] ≤ v[1] ≤ ... ≤ v[n-1]
2. We need sum(clip(v[i]-λ, 0, 1)) = target = n/2
3. For a given λ, the sum is:
   - # {i: v[i] > 1+λ} + sum_{i: λ ≤ v[i] ≤ 1+λ} (v[i] - λ)
4. As λ decreases, more terms become active
5. We can use the sorted order to find the threshold

But for simplicity, binary search is fine.

```python
import numpy as np
from scipy.optimize import minimize
import time

def compute_c5(h, n):
    dx = 2.0 / n
    c = np.correlate(h, 1 - h, mode='full')
    return float(np.max(c) * dx)

def project_feasible(h, n, tol=1e-12):
    """Project h onto {0<=h<=1, sum(h)=n/2}"""
    h = np.clip(h, 0.0, 1.0)
    target = n / 2.0
    for _ in range(100):
        s = h.sum()
        diff = target - s
        if abs(diff) < tol:
            break
        # Binary search for lambda
        # We need sum(clip(h - lambda, 0, 1)) = target
        # If diff > 0, we need to increase sum, so decrease lambda (or add)
        # Simpler: iterative proportional adjustment
        if diff > 0:
            room = 1.0 - h
            sroom = room.sum()
            if sroom < tol:
                break
            h = h + diff / sroom * room
        else:
            s = h.sum()
            if s < tol:
                break
            h = h + diff / s * h
    return np.clip(h, 0.0, 1.0)

# Better projection using binary search on lambda
def project_simplex(h, target_sum):
    """Project h onto {h: 0<=h[i]<=1, sum(h)=target_sum}"""
    n = len(h)
    lo = h.min() - 1.0
    hi = h.max()
    for _ in range(100):
        mid = (lo + hi) / 2
        s = np.clip(h - mid, 0, 1).sum()
        if abs(s - target_sum) < 1e-12:
            break
        if s > target_sum:
            lo = mid
        else:
            hi = mid
    return np.clip(h - (lo+hi)/2, 0, 1)

def fista_step(h, n, alpha, eta=None, deadline=None, max_iter=100000):
    """FISTA optimization step."""
    dx = 2.0 / n
    h = h.copy()
    h = project_simplex(h, n/2.0)
    
    t = 1.0
    h_prev = h.copy()
    
    # Estimate Lipschitz constant
    L = alpha * dx * (2 * n)  # rough upper bound
    
    best_c = compute_c5(h, n)
    best_h = h.copy()
    
    for it in range(max_iter):
        if deadline is not None and time.time() > deadline:
            break
        
        y = h + (t - 1) / (t + 1) * (h - h_prev)
        
        # Compute objective and gradient at y
        c_raw = np.correlate(y, 1 - y, mode='full')
        c = c_raw * dx
        z = alpha * c
        z_max = z.max()
        exp_z = np.exp(z - z_max)
        Z = exp_z.sum()
        p = exp_z / Z  # softmax weights
        obj = z_max / alpha + np.log(Z) / alpha
        
        # Gradient
        grad = np.zeros(n)
        for k in range(2 * n - 1):
            d = k - (n - 1)
            j_lo = max(0, -d)
            j_hi = min(n - 1, n - 1 - d)
            if j_lo > j_hi or p[k] < 1e-15:
                continue
            idx = np.arange(j_lo, j_hi + 1)
            term1 = 1.0 - y[idx + d]
            jd = idx - d
            valid2 = (jd >= j_lo) & (jd <= j_hi)
            term2 = np.zeros(len(idx))
            if valid2.any():
                term2[valid2] = -y[jd[valid2]]
            grad[idx] += p[k] * (term1 + term2)
        
        # Backtracking line search
        if eta is None:
            eta = 1.0 / L
        while True:
            h_new = y - eta * grad
            h_new = project_simplex(h_new, n/2.0)
            # Check decrease (simplified)
            c_new = np.correlate(h_new, 1 - h_new, mode='full') * dx
            if np.max(c_new) <= np.max(c) + 0.5 * eta * np.dot(grad, h_new - y) + 1e-12:
                break
            eta *= 0.5
            if eta < 1e-10:
                h_new = h
                break
        
        h_prev = h
        h = h_new
        t_new = (1 + np.sqrt(1 + 4 * t * t)) / 2
        
        c_curr = compute_c5(h, n)
        if c_curr < best_c - 1e-10:
            best_c = c_curr
            best_h = h.copy()
        
        t = t_new
    
    return best_h, best_c
```

Let me also think about an alternative: **coordinate descent**. 

For the problem min_h max_k c[k], we can do:
- Fix all variables except one, optimize that one
- Cycle through variables
- For each variable h[i], the objective as a function of h[i] is:
  max_k (c[k] without h[i] + contribution of h[i] to c[k])
  
The contribution of h[i] to c[k]:
- h[i] appears in c[k] with coefficient (1-h[j]) where j = i+k-n+1, and -(h[j]) where j = i-k+n-1
- So c[k] = c_without_h[i][k] + h[i]*((1-h[i+k-n+1]) - h[i-k+n+1]) (if indices valid)
- This is linear in h[i]!

So for fixed h[i], the objective max_k c[k] is max_k (a[k] + h[i]*b[k]) where a[k] = c[k] - h[i]*b[k] and b[k] is the coefficient.

This is the maximum of linear functions of h[i], which is a piecewise linear convex function of h[i]!

So we can find the optimal h[i] in [0,1] by checking the breakpoints. This is a 1D convex minimization problem, solvable in O(n) time (evaluate at the n + 2 candidate points: 0, 1, and the n intersection points).

**Coordinate descent with exact 1D optimization!**

For each coordinate i:
1. Compute b[k] = coefficient of h[i] in c[k] for all k
   - b[k] = (1-h[i+k-n+1]) - h[i-k+n+1] (with appropriate validity checks)
   - Note: when we set h[i]=0, c[k] = c_without[k]
   - When we set h[i]=t, c[k] = c_without[k] + t*b[k]
   
2. The objective is max_k (c_without[k] + t*b[k]) for t ∈ [0,1]
3. Find t* that minimizes this. This is a 1D convex piecewise linear minimization.
4. The minimum is at t=0, t=1, or at a breakpoint where two lines cross.
5. Breakpoints: for each pair (k1, k2), the intersection is at t = (c_without[k2] - c_without[k1]) / (b[k1] - b[k2])
6. But we only need to check O(n) candidate values: 0, 1, and the values where the "active" set changes.

Actually, the minimum of max of linear functions over [0,1] occurs at:
- t = 0
- t = 1
- Or at a point where the maximum is achieved by at least two functions (a "kink")

The kinks are at the intersection points of pairs of lines, but there are O(n²) such points. However, we can be smarter:
- Sort the lines by their value at t=0
- The upper envelope changes at most n-1 times as t goes from 0 to 1
- We can find the minimum of the upper envelope by binary search or by walking the upper envelope

Actually, for a practical implementation, since n=250 and we have 499 lines, we can just:
1. Evaluate max_k (c_without[k] + t*b[k]) at t = 0, 1, and at a few quantiles
2. Use ternary search on [0,1] (since the function is convex, it's unimodal)
3. Or: use the analytical solution

For the analytical solution:
- We want min_t max_k (a[k] + b[k]*t) over t ∈ [0,1]
- This is a linear programming problem in 1D
- The optimal t* satisfies: there exist k1 ≠ k2 such that a[k1]+b[k1]*t* = a[k2]+b[k2]*t* = max, and for all k, a[k]+b[k]*t* ≤ this value
- Equivalently: t* = (a[k2]-a[k1])/(b[k1]-b[k2]) for the pair that determines the optimum

So that term changes from h[i-k+n-1]*(1-a) to h[i-k+n-1]*(1-a-Δ).

So: Δc[k] = Δ*(1-h[i+k-n+1]) + h[i-k+n-1]*(-Δ) [if i-k+n-1 ≠ i and is valid]
          = Δ*(1-h[i+k-n+1] - h[i-k+n+1]) [with validity checks]

Wait, if i-k+n-1 = i, that means k = n-1, and the term is h[i]*(1-h[i]) which changes by Δ*(1-2a-Δ). But in the bilinear case (ignoring the Δ² term):
Δc[n-1] = Δ*(1-2a) = Δ*(1-h[i]-h[i]) = Δ*(1-2*h[i])

And from the formula: Δ*(1-h[i+(n-1)-n+1] - h[i-(n-1)+n+1])... wait that doesn't work because i+k-n+1 = i+n-1-n+1 = i, so we'd be double-counting.

The issue is when i+k-n+1 = i (i.e., k=n-1) AND i-k+n-1 = i (same condition). In that case, the two corrections are the same term.

For k ≠ n-1:
Δc[k] = Δ*(1-h[i+k-n+1]) - Δ*h[i-k+n+1] (if i-k+n+1 is valid)
       = Δ*(1 - h[i+k-n+1] - h[i-k+n+1]) (with validity)

For k = n-1:
Δc[n-1] = Δ*(1-2*h[i]) (since h[i+k-n+1] = h[i] = h[i-k+n+1])

This is getting complicated. For simplicity, let me just recompute the full correlation after each coordinate change. It's O(n²) per change, O(n³) per sweep, but for n=250, that's about 15M operations per sweep, which takes about 0.1 seconds. In 900 seconds, we can do about 9000 sweeps. That's plenty.

Actually wait, np.correlate for n=250 arrays takes about 0.02ms (it's implemented in C). So O(n) correlations take O(n*0.02ms) = 5ms per sweep. That's extremely fast! 900 seconds / 5ms = 180,000 sweeps!

OK so coordinate descent with full correlation recomputation is extremely fast. Let me go with this approach.

Now, for the 1D optimization at each coordinate:
- I compute c0 (with h[i]=0) and c1 (with h[i]=1)
- The objective is f(t) = max(c0 + t*(c1-c0)) for t ∈ [0,1]
- This is a convex piecewise linear function
- I can find its minimum efficiently

For the minimum of a convex piecewise linear function on [0,1]:
- The minimum is at a kink point (where the active set changes) or at 0 or 1
- I can use the fact that f(t) = max_k (a_k + b_k*t) where a_k = c0[k], b_k = c1[k]-c0[k]
- The subgradient at t is {b_k : k ∈ argmax_k (a_k + b_k*t)}
- The minimum is where 0 is in the subgradient (or at the boundary)

Practical approach: 
1. Evaluate f at t=0 and t=1
2. If f(0) ≤ f(1), the minimum is at t ≤ 0.5 (roughly)
3. Use bisection: 
   - At the current t, find k* = argmax(a_k + b_k*t)
   - The subgradient is b_{k*}
   - If b_{k*} > 0, decrease t; if b_{k*} < 0, increase t
4. Converge in O(log(1/ε)) steps, each O(n)

Let me code this up properly:

```python
def min_1d_convex(a, b, n_evals=50):
    """Find min of max_k(a[k] + b[k]*t) over t in [0,1].
    a, b are arrays of length m."""
    lo, hi = 0.0, 1.0
    for _ in range(n_evals):
        t = (lo + hi) / 2
        vals = a + t * b
        k_star = np.argmax(vals)
        if b[k_star] > 0:
            hi = t
        elif b[k_star] < 0:
            lo = t
        else:
            break
    t_opt = (lo + hi) / 2
    # Also check endpoints
    f_lo = np.max(a)
    f_hi = np.max(a + b)
    f_mid = np.max(a + t_opt * b)
    if f_lo <= f_mid and f_lo <= f_hi:
        return 0.0
    elif f_hi <= f_mid and f_hi <= f_lo:
        return 1.0
    return t_opt
```

This is O(n * n_evals) = O(n²) per coordinate, O(n³) per sweep. For n=250, that's 250 * 250 * 50 = 3.1M operations per sweep. Each operation is simple (add, multiply, compare), so maybe 0.01-0.05 seconds per sweep in numpy. 

In 900 seconds: 18,000 - 90,000 sweeps. Way more than enough.

Now, the constraint issue. After each coordinate update, the sum might not be exactly n/2. I have two options:
1. Project after each full sweep (simpler, might lose a tiny bit)
2. Pair updates: update h[i] and h[j] simultaneously (maintains sum exactly)

For option 1: After coordinate descent, project. The projection changes values slightly, which might undo some progress, but over many sweeps, the net effect should be positive.

For option 2: Update h[i] by +δ and h[j] by -δ. The 1D optimization becomes:
min_δ max_k (c[k] + δ*(contribution_i[k] - contribution_j[k]))

This is still a 1D convex problem, solvable the same way. But we need to choose j. Natural choices:
- j = argmax of h (the "most over" variable)
- j = some random variable
- j = the variable that would benefit most from receiving mass

Let me start with option 1 (simpler) and see if it works well enough.

Actually, wait. There's a subtlety. When I update h[i] independently (without maintaining the sum), I'm effectively allowing the integral to vary. The projection back will change all values slightly. This might prevent convergence.

A better approach: **Do pair updates.** Pick a random pair (i, j) and move mass between them. This maintains the sum exactly.

But actually, for coordinate descent to work well, I want to update one variable at a time and let the projection handle the rest. The key insight is that if I do enough sweeps, the projection error averages out.

Let me just go with the simple approach and see.

    dx = 2.0 / n
    return float(np.max(np.correlate(h, 1 - h, mode='full')) * dx)

def project_feasible(h, n):
    h = np.clip(h, 0.0, 1.0)
    target = n / 2.0
    for _ in range(100):
        diff = target - h.sum()
        if abs(diff) < 1e-12:
            break
        if diff > 0:
            room = 1.0 - h
            s = room.sum()
            if s < 1e-14:
                break
            h += diff / s * room
        else:
            s = h.sum()
            if s < 1e-14:
                break
            h += diff / s * h
    return np.clip(h, 0.0, 1.0)

def min_1d_convex(a, b):
    """Min of max_k(a[k]+b[k]*t) over t in [0,1]"""
    lo, hi = 0.0, 1.0
    for _ in range(40):
        t = (lo + hi) / 2
        idx = np.argmax(a + t * b)
        if b[idx] > 1e-15:
            hi = t
        elif b[idx] < -1e-15:
            lo = t
        else:
            break

    f0 = np.max(a)
    f1 = np.max(a + b)
    fm = np.max(a + t_mid * b)
    if f0 <= fm and f0 <= f1:
        return 0.0
    if f1 <= fm and f1 <= f0:
        return 1.0
    return t_mid

def coordinate_descent(h, n, max_sweeps, deadline, order='sequential'):
    h = h.copy()
    dx = 2.0 / n
    best_c = compute_c5(h, n)
    
    for sweep in range(max_sweeps):
        if time.time() > deadline:
            break
        if order == 'sequential':
            idxs = range(n)
        else:
            idxs = np.random.permutation(n)
        
        for i in idxs:
            if time.time() > deadline:
                break
            old_val = h[i]
            h[i] = 0.0
            c0 = np.correlate(h, 1-h, mode='full')
            h[i] = 1.0
            c1 = np.correlate(h, 1-h, mode='full')
            
            delta = c1 - c0
            t_opt = min_1d_convex(c0, delta)
            h[i] = t_opt
        
        h = project_feasible(h, n)
        c_curr = compute_c5(h, n)
        if c_curr < best_c:
            best_c = c_curr
    
    return h, best_c
