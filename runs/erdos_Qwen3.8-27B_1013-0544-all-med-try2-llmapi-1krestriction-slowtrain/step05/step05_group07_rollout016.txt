Let s = m - (n-1) be the shift. Then:
r[m] = ∑_{k: 0≤k<n, 0≤k+s<n} h[k]·(1-h[k+s])

When we change h[i] from 0 to 1 and h[j] from 1 to 0:

Effect on r[m] from changing h[i]:
- h[i] appears in the sum when k=i (if i+s is valid) or k=i-s (if i-s is valid and h[i-s]≠0... wait no, h[i] is in the (1-h[...]) term)

Let me denote the contribution to r[m] from position p in h:
- As the "first" factor: h[p]·(1-h[p+s]) if p+s < n
- As the "second" factor: h[p-s]·(1-h[p]) if p-s ≥ 0

So the total contribution of h[p] to r[m] is:
- h[p]·(1-h[p+s]) [if p+s < n] + h[p-s]·(1-h[p]) [if p-s ≥ 0]

When h[p] changes by δ (0→1 means δ=+1, 1→0 means δ=-1):
- The "first" factor changes by: δ·(1-h[p+s]) [if p+s < n]
- The "second" factor changes by: h[p-s]·(-δ) [if p-s ≥ 0]

So Δr[m] = δ·(1-h[p+s])·[p+s<n] - δ·h[p-s]·[p-s≥0]

For a swap (i goes 0→1 with δ_i=+1, j goes 1→0 with δ_j=-1):
Δr[m] = (1-h[i+s])·[i+s<n] - h[i-s]·[i-s≥0] - (1-h[j+s])·[j+s<n] + h[j-s]·[j-s≥0]

This is O(1) per m, so O(n) per swap. And we need to check if max(r + Δr) < current_max.

But checking if max(r + Δr) < current_max requires computing the max of r + Δr, which is O(n). So total per swap is O(n), and total for all swaps is O(n³).

For n=250: 250³ = 15.6M operations. In pure Python this would be slow, but if we vectorize the Δr computation, it should be fast.

- i-s ranges from i-(n-1) to i, so s from -(n-1) to -i, meaning m from 0 to n-1-i
