Hmm, this coordinate descent is O(n²) per round (computing c each time is O(n²)). For n=250, that's about 62,500 operations per evaluated point, times 250 points times maybe 50 rounds = ~780 million operations. That's too slow.

Let me optimize: instead of recomputing the full correlation each time, I can update it incrementally.

When h[i] changes by delta:
c_new[k] = c_old[k] + delta * g_i[k]

where g_i[k] is the gradient vector computed once per i. So after computing g_i, I can update c in O(n) instead of O(n²).

But I need to recompute c from scratch at the start of each round. That's O(n²) per round, and with 250 coordinates per round, the total is still O(n³) per round if I recompute c for each coordinate.

Wait, no. If I update c incrementally:
- Start of round: compute c = correlate(h, 1-h, 'full') * dx [O(n²)]
- For each i: compute g_i [O(n)], find best delta [O(n)], update c += delta * g_i [O(n)]
- Total per round: O(n²) + n * O(n) = O(n²)

That's much better! O(n²) per round, with maybe 100 rounds = O(n²) * 100. For n=250, that's about 6.25 million operations. Very fast.

Let me reconsider the approach. But there's a subtlety: after updating h[i], the gradient g for a later coordinate j is affected. However, if the updates are small, the gradient doesn't change much, so we can use a "stale" gradient. This is like Gauss-Seidel vs Jacobi.

Actually, the issue is more fundamental: c depends on ALL h values, so when I update h[i], c changes, and then the gradient for h[j] (j≠i) also changes. But if I use the updated c (which I can do since I'm updating c incrementally), then the gradient g_j for the next coordinate is computed from the current h (which has h[i] already updated). So I need to recompute g_j from the current h, which is O(n) per coordinate. That's fine.

Wait, but g_j depends on h values at positions j±k for various k. After updating h[i], if i = j±k for some k, then g_j changes. But since I compute g_j fresh each time (O(n) operation), this is handled correctly.

So the algorithm is:
1. c = correlate(h, 1-h, 'full') * dx  [O(n²)]
2. For i = 0 to n-1:
   a. Compute g_i = gradient of c w.r.t. h[i]  [O(n)]
   b. Find optimal delta_i that minimizes max(c + delta_i * g_i)  [O(n)]
   c. h[i] += delta_i  [O(1)]
   d. c += delta_i * g_i  [O(n)]
3. Repeat steps 1-2 for multiple rounds

Total per round: O(n²) (dominated by step 1 and the n * O(n) in the loop)
This is very efficient!

Now, for step 2b (finding optimal delta), I need to solve:
min_δ max_k (c[k] + δ * g[k])
subject to: -h[i] ≤ δ ≤ 1 - h[i]

This is a 1D convex optimization (max of linear functions is convex). I can solve it by:
- Binary search: O(n log(1/ε))
- Or: find the breakpoint where the max transitions

Actually, the simplest approach: the optimal δ is where the "active" constraints (those achieving the max) are balanced. A practical approach:

1. Find k* = argmax c (the current worst)
2. If g[k*] < 0, we want δ > 0 (increase h[i] to decrease c[k*])
   - The limiting constraint is: for all k with g[k] > g[k*], we need c[k] + δ*g[k] ≤ c[k*] + δ*g[k*]
   - i.e., δ ≤ (c[k*] - c[k]) / (g[k] - g[k*]) for such k
   - Take the minimum of these upper bounds, intersect with [0, 1-h[i]]
3. Similarly if g[k*] > 0, we want δ < 0

But this only considers the current argmax. A better approach considers the top few k values.

Let me just use binary search on δ in the range [δ_min, δ_max] and evaluate max(c + δ*g) at each step. Since the function is piecewise linear convex, binary search converges in log steps.

Actually, even simpler: since we're doing this n times per round and the total budget is large, let me just try a few candidate δ values:
- δ = 0 (no change)
- δ = ±0.01, ±0.005, ±0.001 (small steps in both directions)
- δ that equalizes the top 2 c values

And pick the best. This is O(n) per coordinate with a small constant.

The derivative w.r.t. h[i] is (1-h[i+k])*dx - h[i-k]*dx (the second term is from the product h[i-k]*h[i]).

But this derivative is only valid at the current point. After changing h[i], the derivative changes (because h[i+k] and h[i-k] are fixed, but the cross term h[i-k]*h[i] changes the derivative for OTHER shifts).

c_full[m] = dx * sum_j h[j] * (1 - h[j + k_m]) where k_m = m - (n-1) and the sum is over valid j.

The terms involving h[i] are:
1. j = i: h[i] * (1 - h[i + k_m]) * dx, valid if 0 <= i+k_m < n
2. j + k_m = i, i.e., j = i - k_m: h[i-k_m] * (1 - h[i]) * dx, valid if 0 <= i-k_m < n

So c_full[m] = A_m + h[i] * (1-h[i+k_m]) * dx * [valid1] - h[i-k_m] * h[i] * dx * [valid2]

where A_m is everything else.

This is NOT linear in h[i]! The first term is linear in h[i], but the second term has h[i-k_m] * h[i] which is also linear in h[i] (since h[i-k_m] is fixed when we're varying h[i]).

Wait, h[i-k_m] * h[i] IS linear in h[i] (it's h[i-k_m] * h[i] = (constant) * h[i]). So the total dependence of c_full[m] on h[i] IS linear!

c_full[m] = A_m + h[i] * dx * (1-h[i+k_m]) * [valid1] - h[i-k_m] * dx * h[i] * [valid2]
           = A_m + h[i] * dx * [(1-h[i+k_m])*[valid1] - h[i-k_m]*[valid2]]

So the derivative is:
dc_full[m]/dh[i] = dx * [(1-h[i+k_m])*[valid1] - h[i-k_m]*[valid2]]

This is indeed constant (doesn't depend on h[i])! So c_full[m] is a LINEAR function of h[i] (for fixed other h values).

This means my incremental update c += delta * g is EXACT, not approximate! Great.

One idea: **Use the fact that the problem is equivalent to finding a function with "flat" correlation (in a certain sense).** In signal processing, this is related to "low autocorrelation sequences" or "Zadoff-Chu sequences." The ideal would be a function whose autocorrelation is as flat as possible (equal for all lags), which would minimize the maximum overlap.

For discrete sequences, the "ideal" is a sequence with zero autocorrelation at all non-zero lags. But that's impossible for real-valued sequences with fixed energy. The best we can do is minimize the peak sidelobe level (PSL).

This suggests that the optimal h might have a "pseudo-random" or "chirp-like" structure.

Another idea: **Use the Lagrangian dual.** The problem is:
min_h max_k F_k(h)
s.t. ∫h = 1, 0 ≤ h ≤ 1

where F_k(h) = ∫h(x)(1-h(x+k))dx.

The Lagrangian dual (for the max) gives:
min_h max_{λ≥0, Σλ_k=1} Σ_k λ_k F_k(h)
s.t. ∫h = 1, 0 ≤ h ≤ 1

For a fixed λ (a probability distribution over k), the inner problem is:
min_h Σ_k λ_k ∫h(x)(1-h(x+k))dx
= min_h ∫h(x)dx - ∫h(x) [Σ_k λ_k h(x+k)] dx
= 1 - ∫h(x) [Σ_k λ_k h(x+k)] dx

= 1 - ∫h(x) (λ * h)(x) dx

where (λ*h)(x) = Σ_k λ_k h(x+k) is a weighted average of shifts of h.

So we want to maximize ∫h(x)(λ*h)(x)dx, which is like maximizing the "self-similarity" of h under the weighted shift.

For λ uniform over all k, this becomes:
max_h ∫h(x) [average of h(x+k) over all k] dx

The average of h(x+k) over k∈[-(n-1), n-1] (with appropriate weighting) is a "blurred" version of h. We want h to have high correlation with its own blur, which means h should be smooth (low frequency). But h should also be "peaky" (close to 0 or 1) to minimize ∫h(1-h).

This is a contradiction, suggesting the optimal solution is a balance between smoothness and peakiness.

import numpy as np
from scipy.optimize import minimize
import time

def compute_c5(h, n):
    dx = 2.0 / n
    return float(np.max(np.correlate(h, 1 - h, mode='full')) * dx)

def compute_corr(h, n):
    dx = 2.0 / n
    return np.correlate(h, 1 - h, mode='full') * dx

def project_feasible(h, n):
    target = n / 2.0
    h = np.clip(h, 0.0, 1.0).copy()
    for _ in range(200):
        diff = target - h.sum()
        if abs(diff) < 1e-13:
            break
        if diff > 0:
            room = 1.0 - h
            tot = room.sum()
            if tot < 1e-14:
                break
            h += (diff / tot) * room
        else:
            tot = h.sum()
            if tot < 1e-14:
                break
            h += (diff / tot) * h
        h = np.clip(h, 0.0, 1.0)
    return h

def smooth_obj(x, n, alpha):
    dx = 2.0 / n
    c = np.correlate(x, 1 - x, mode='full') * dx
    shifted = alpha * (c - c.max())
    mx = shifted.max()
    return float(c.max() + (mx + np.log(np.sum(np.exp(shifted - mx)))) / alpha)

def _con_fun(x, n):
    return float(np.sum(x)) - n / 2.0

def _con_jac(x, n):
    return np.ones(n)

def slsqp_opt(h, n, alpha, maxiter=3000):
    bounds = [(0.0, 1.0)] * n
    cons = [{'type': 'eq', 'fun': _con_fun, 'jac': _con_jac, 'args': (n,)}]
    try:
        res = minimize(smooth_obj, h, args=(n, alpha), method='SLSQP',
                       bounds=bounds, constraints=cons,
                       options={'maxiter': maxiter, 'ftol': 1e-15})
        return project_feasible(res.x, n)
    except Exception:
        return h.copy()

def find_best_delta(c, g, dlo, dhi):
    """Ternary search for delta minimizing max(c + delta*g)."""
    for _ in range(35):
        m1 = dlo + (dhi - dlo) / 3.0
        m2 = dhi - (dhi - dlo) / 3.0
        if float(np.max(c + m1 * g)) < float(np.max(c + m2 * g)):
            dhi = m2
        else:
            dlo = m1
    return (dlo + dhi) / 2.0

def coord_descent(h, n, deadline, max_rounds=200):
    h = h.copy()
    c = compute_corr(h, n)
    best_c = float(c.max())
    n_corr = 2 * n - 1
    k_range = np.arange(-(n - 1), n)

    for rnd in range(max_rounds):
        if time.time() > deadline:
            break
        improved = False
        for i in range(n):
            if time.time() > deadline:
                return h, best_c
            idx1 = i + k_range
            idx2 = i - k_range
            v1 = (idx1 >= 0) & (idx1 < n)
            v2 = (idx2 >= 0) & (idx2 < n)
            g = np.zeros(n_corr)
            g[v1] += (1.0 - h[idx1[v1]])
            g[v2] -= h[idx2[v2]]

            dlo = -h[i]
            dhi = 1.0 - h[i]
            # Quick check: if no improvement possible, skip
            cmax = float(c.max())
            obj_at_0 = cmax
            # Try the ternary-search optimum
            d_opt = find_best_delta(c, g, dlo, dhi)
            obj_opt = float(np.max(c + d_opt * g))
            if obj_opt < obj_at_0 - 1e-14:
                h[i] = float(np.clip(h[i] + d_opt, 0, 1))
                c += d_opt * g
                cm = float(c.max())
                if cm < best_c - 1e-14:
                    best_c = cm
                    improved = True

        h = project_feasible(h, n)
        c = compute_corr(h, n)
        cm = float(c.max())
        if cm < best_c:
            best_c = cm
        if not improved:
            break

    best_c = compute_c5(h, n)
    return h, best_c

def pair_local_search(h, n, deadline, delta=0.005):

    h = h.copy()
    c = compute_corr(h, n)
    best_c = float(c.max())

    k_range = np.arange(-(n - 1), n)

                idx2i = i - k_range
                g_i = np.zeros(n_corr)
                v1i = (idx1i >= 0) & (idx1i < n)
                v2i = (idx2i >= 0) & (idx2i < n)
                g_i[v1i] += (1.0 - h[idx1i[v1i]])

                idx2j = j - k_range
                g_j = np.zeros(n_corr)

                gc = delta * (g_j - g_i)

                    h[j] += delta
                    c += gc
                    best_c = new_max
                    improved = True

        if not improved:

    best_c = compute_c5(h, n)
    return h, best_c
