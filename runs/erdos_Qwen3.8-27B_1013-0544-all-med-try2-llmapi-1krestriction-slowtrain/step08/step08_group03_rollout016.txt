def pgd_optimize(h, n, deadline, alpha=1000.0, top_k=80):

        if prev_h is not None:
            sv = best_h - prev_h
            yv = g - prev_g
            ss = sv @ sv
            sy = sv @ yv
            if sy > 1e-18:
                step = float(np.clip(ss / sy, 0.0001, 0.05))
            else:
                step *= 0.6
        prev_h = best_h.copy()
        prev_g = g.copy()
        accepted = False
        for _ in range(20):
            h_new = project_feasible(best_h - step * g, n)
            c_new = compute_c5(h_new, n)
            if c_new <= best_c + 1e-14:
                best_h = h_new
                if c_new < best_c - 1e-16:
                    best_c = c_new
                    stall = 0
                else:
                    stall += 1
                accepted = True
                break
            step *= 0.4
        if not accepted:
            break
        if stall > 150:
            break
    return best_h, best_c

                        best_c = c_new
                        improved = True
                    else:
                        best_h[i] += d
                        best_h[j] -= d

Actually, here's a better idea: **coordinate descent with exact line search**. For each coordinate i, find the optimal value of h[i] (given all other coordinates fixed) that minimizes the max overlap. This is a 1D optimization problem that can be solved exactly.

For a fixed h with only h[i] free, the overlap for shift k is:
f_k(h) = sum_j h[j] * (1-h[j+k]) * dx

If k = 0: f_0 = sum_j h[j] * (1-h[j]) * dx - h[i]*(1-h[i])*dx + h[i]*(1-h[i])*dx = sum_j h[j]*(1-h[j])*dx (no change from varying h[i] in a single term... wait)

Actually, f_0 = sum_j h[j] * (1-h[j]) * dx. If I change h[i], then:
f_0 = (sum_{j≠i} h[j]*(1-h[j]) + h_i*(1-h_i)) * dx
= (C + h_i - h_i²) * dx where C = sum_{j≠i} h[j]*(1-h[j])

This is a quadratic in h_i: -h_i² + h_i + C, which is maximized at h_i = 0.5. So to minimize f_0, we want h_i = 0 or h_i = 1.

For k ≠ 0: f_k = sum_j h[j] * (1-h[j+k]) * dx
Changing h[i] affects terms where j = i (h[i]*(1-h[i+k])) and where j+k = i, i.e., j = i-k (h[i-k]*(1-h[i])).

So: f_k = (sum_{j≠j1,j2} ... + h[i]*(1-h[i+k]) + h[i-k]*(1-h[i])) * dx
= (C_k + h[i] - h[i]*h[i+k] + h[i-k] - h[i]*h[i-k]) * dx
= (C_k + h[i] - h[i]*(h[i+k] + h[i-k]) + h[i-k]) * dx
= (C_k + h[i-k] + h[i]*(1 - h[i+k] - h[i-k])) * dx

This is linear in h[i]! So to minimize f_k, we set h[i] = 0 if (1 - h[i+k] - h[i-k]) > 0, and h[i] = 1 if (1 - h[i+k] - h[i-k]) < 0.

But we want to minimize the MAX over all k, not a single k. So the optimal h[i] is the one that minimizes the maximum of all f_k as functions of h[i].

Each f_k is linear in h[i] (for k ≠ 0) or quadratic (for k = 0). The max of linear functions is convex, so we're minimizing a convex function of h[i] over [0,1]. This can be done with binary search!

This is a great insight! For each coordinate i, the optimal value of h[i] (given all other coordinates fixed) can be found by:
1. For each k, compute the coefficient of h[i] in f_k (and the constant term)
2. The function max_k f_k(h[i]) is convex in h[i] (max of linear/quadratic functions)
3. Use ternary search or binary search on the derivative to find the minimum

This is essentially **cyclic coordinate descent** with exact line search, which is guaranteed to converge (for the smooth case) and often works very well in practice.
