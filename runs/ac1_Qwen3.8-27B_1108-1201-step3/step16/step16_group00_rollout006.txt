Now, the question is: can we do even better than the linear ramp?

The key insight is that for non-negative sequences, the convolution peak is NOT necessarily at lag 0 of the autocorrelation. It's at the "center" of the linear convolution, which for asymmetric sequences can be much smaller.

So the strategy should be:
1. Use a monotonically increasing (or decreasing) sequence to minimize the "center" of the convolution.
2. The optimal shape might not be linear - it could be exponential or some other function.

Let me think about what shape minimizes the peak. For a sequence a_0, a_1, ..., a_{n-1}, the "center" convolution value is:
conv[n-1] = sum_{i=0}^{n-1} a_i * a_{n-1-i}
conv[n] = sum_{i=1}^{n-1} a_i * a_{n-i}

For a monotonically increasing sequence, a_i < a_{n-1-i} for i < n/2, so the products a_i * a_{n-1-i} are "balanced" - small*large.

The optimal shape might be to make the sequence as "peaked at one end" as possible, which would concentrate the mass where the products are smallest.

An exponential ramp: a_i = r^i for r > 1.
sum = (r^n - 1)/(r-1) (for r ≠ 1)

conv[n] = sum_{i=1}^{n-1} r^i * r^{n-i} = sum_{i=1}^{n-1} r^n = (n-1) * r^n

J = 2n * (n-1) * r^n / ((r^n-1)/(r-1))^2
= 2n(n-1) * r^n * (r-1)^2 / (r^n-1)^2

For large n (r^n >> 1):
J ≈ 2n(n-1) * r^n * (r-1)^2 / r^{2n}
= 2n(n-1) * (r-1)^2 / r^n

For r=2, n=3200: J ≈ 2*3200*3199 * 1 / 2^3200 which is essentially 0!

But wait, we need to check all convolution values, not just conv[n]. For an exponential, the convolution might peak elsewhere.

For a_i = r^i:
conv[k] = sum_{valid i} r^i * r^{k-i} = sum_{valid i} r^k = r^k * (number of valid terms)

The number of valid terms for position k in the convolution of two length-n sequences:
- For k = 0, 1, ..., n-1: k+1 terms
- For k = n, n+1, ..., 2n-2: 2n-1-k terms

So conv[k] = r^k * (k+1) for 0 <= k <= n-1
conv[k] = r^k * (2n-1-k) for n <= k <= 2n-2

For r > 1, r^k is increasing, but (k+1) increases only linearly while r^k increases exponentially. So for k < n, conv[k] is dominated by r^k and is increasing.

For k >= n, r^k continues to increase but (2n-1-k) decreases. The peak in this region is where r^k * (2n-1-k) is maximized.

d/dk [r^k * (2n-1-k)] = r^k * ln(r) * (2n-1-k) - r^k = r^k * [ln(r)*(2n-1-k) - 1]
= 0 when k = 2n-1 - 1/ln(r)

For r = e (ln r = 1): peak at k = 2n-2, value = e^{2n-2} * 1
For r = 2 (ln r ≈ 0.693): peak at k = 2n-1-1.44 ≈ 2n-2.44, so at k = 2n-2 or 2n-3.

Actually, for k = 2n-2: conv[2n-2] = r^{2n-2} * 1 = r^{2n-2}
For k = 2n-3: conv[2n-3] = r^{2n-3} * 2 = 2r^{2n-3}

Compare: r^{2n-2} vs 2r^{2n-3}. Ratio = r/2. So for r > 2, peak is at 2n-2; for r < 2, peak is at 2n-3 or earlier.

For r = 2: conv[2n-2] = 2^{2n-2}, conv[2n-3] = 2*2^{2n-3} = 2^{2n-2}. They're equal!

So for r=2, the peak is at both k=2n-2 and k=2n-3, with value 2^{2n-2}.

sum = (2^n - 1)/(2-1) = 2^n - 1 ≈ 2^n for large n.

J = 2n * 2^{2n-2} / (2^n - 1)^2 ≈ 2n * 2^{2n-2} / 2^{2n} = 2n/4 = n/2

For n=3200: J ≈ 1600. That's terrible!

So exponential is bad because the peak at the far end (k=2n-2) is huge.

What about a sequence that's concentrated in the middle? Like a_i = exp(-c(i - n/2)^2)?

For a Gaussian centered at n/2:
conv[n-1] = sum a_i * a_{n-1-i} = sum exp(-c(i-n/2)^2) * exp(-c(n-1-i-n/2)^2)
= sum exp(-c(i-n/2)^2) * exp(-c(n/2-1-i)^2)
≈ sum exp(-2c(i-n/2+0.5)^2) (approximately, for large n)

This is like a narrower Gaussian, with value proportional to 1/sqrt(c) * exp(0) = 1/sqrt(c) * constant.

Actually, the convolution of two Gaussians is a Gaussian with variance = sum of variances. So if a_i ∝ exp(-i^2/(2σ^2)), then (a*a)_k ∝ exp(-k^2/(4σ^2)) * sqrt(2)σ * sqrt(2π).

The peak is at k=0 (or k=n-1 for the centered version), and max conv ∝ σ.

sum a ∝ σ * sqrt(2π)

J = 2n * max_conv / sum^2 ∝ 2n * σ / (σ^2 * 2π) = n/(πσ)

To minimize J, we want σ as large as possible. But σ can't be larger than n/2 (the sequence is only n elements long). So the best Gaussian would have σ ≈ n/2, which is essentially uniform, giving J ≈ 2.

So Gaussians don't help.

OK so what about a sequence that increases very steeply at the end? Like a step function that's 0 for most of the length and then jumps up?

Actually, let me think about this differently. The convolution at position k involves pairs (i, k-i). For the peak to be small, we want all these products to be small.

For a monotonically increasing sequence a_0 < a_1 < ... < a_{n-1}:
- At position k < n/2: products a_i * a_{k-i} where both indices are small → small products
- At position k ≈ n/2: products include a_i * a_{k-i} where one index is small and the other is large → medium products
- At position k ≈ n: products include a_i * a_{n-i} where i is small and n-i is large → these are the "cross" terms
- At position k > n: similar to k < n by the structure

The overall structure for an increasing sequence is that the convolution increases from k=0 to some peak and then decreases. The peak location depends on the shape.
