Actually, the gradient of the LogSumExp-smoothed objective can be computed using the FFT:
- a = softmax(z) (or just exp(z) / sum(exp(z))).
- r = a * a (via FFT).
- w = exp(r/T) / sum(exp(r/T)) (softmax of r).
- grad_a = T^T w (cross-correlation of w with a, which is (w * a_reversed) via FFT).
- grad_z = a * (grad_a - <grad_a, a>) (for the softmax parameterization).

The cross-correlation T^T w can be computed via FFT: it's the inverse FFT of FFT(w) * conj(FFT(a)) (with appropriate padding).

Wait, actually T^T w[j] = sum_k T[k,j] w[k] = sum_k a[k-j] w[k] (with boundary handling).
This is the cross-correlation of a and w: (a ⊛ w)[j] = sum_k a[k] w[k+j] = sum_k w[k] a[k-j].

Yes! So T^T w = a ⊛ w (cross-correlation), which can be computed via FFT:
FFT(a ⊛ w) = FFT(a) * conj(FFT(w)).

So the gradient computation is:
1. a = softmax(z).
2. r = a * a (FFT).
3. w = softmax(r/T) (elementwise).
4. grad_a = a ⊛ w (FFT cross-correlation).
5. grad_z = a * (grad_a / T - <grad_a, a> / T).

This is O(n log n) per gradient evaluation, which is much faster than the O(n^2) loop.

Let me also think about a completely different approach: **simulated annealing** on the sequence space.

The idea:
- Start with a good initial sequence.
- In each step, randomly perturb one or a few elements.
- Accept the perturbation with probability exp(-Δscore / T_sa) where T_sa is the SA temperature.
- Gradually decrease T_sa.

This is simple but can be effective for escaping local minima. The challenge is that evaluating the score requires an FFT (O(n log n)), so each step is fast.

For n = 1200, each FFT takes about 1200 * log2(1200) ≈ 1200 * 11 ≈ 13,200 operations. At 100 MHz (conservative for a single Python thread), that's about 0.1 μs per FFT, so we can do about 10 million steps per second. In 1800 seconds, that's 18 billion steps. More than enough.
