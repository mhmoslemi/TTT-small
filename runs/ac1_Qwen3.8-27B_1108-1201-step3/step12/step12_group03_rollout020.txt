Wait: (2n-2) - i for i=0,1,...,n-1 gives 2n-2, 2n-3, ..., n-1.
So we want conv[(2n-2), (2n-3), ..., (n-1)] which is conv[n-1 : 2n-1][::-1].

Let me verify: conv has length 3n-2 (indices 0 to 3n-3).
We need indices 2n-2, 2n-3, ..., n-1. That's n elements: from n-1 to 2n-2.
conv[n-1 : 2n-1] gives indices n-1, n, ..., 2n-2. Reversed: 2n-2, 2n-3, ..., n-1. ✓

So: grad = 2.0 * conv_result[n-1 : 2*n-1][::-1]

Now let me code this up properly.

For the FFT computation:
- a has length n, p has length 2n-1
- p_flipped has length 2n-1
- conv(a, p_flipped) has length n + (2n-1) - 1 = 3n-2
- We need FFT size >= 3n-2

Let me now think about the overall algorithm:

1. Start with the parent sequence (or a good initialization)
2. Run gradient-based optimization with:
   - Log-sum-exp smoothing (annealed temperature)
   - Nesterov acceleration
   - Simplex projection
   - Adaptive learning rate
3. Periodically evaluate and keep the best
4. Try different lengths
5. Use LP refinement at the end for final polish

The gradient method should be much faster per iteration than the LP method, allowing many more iterations in the same time.

Let me also think about the learning rate schedule. The objective is Lipschitz (with constant depending on n and the parameters), so we can use a standard Lipschitz gradient descent rate. But with Nesterov acceleration, we get O(1/t^2) convergence for the smooth part.

The Lipschitz constant of the smooth objective (log-sum-exp of c) is roughly tau * (max eigenvalue of the Hessian of c). The Hessian of c = a*a is related to the structure of a. For simplicity, I'll use an adaptive learning rate (backtracking or diminishing).

Actually, for the constrained problem (simplex), the standard approach is:
1. Compute gradient
2. Take a step: a_new = a - lr * grad
3. Project onto simplex

The projection onto the simplex {x >= 0, sum(x) = 1} is:
- Sort x in decreasing order
- Find the threshold tau such that the projected values are non-negative
- Project: x_proj[i] = max(x[i] - tau, 0) where tau is chosen so sum(x_proj) = 1

This is O(n log n) per iteration (for sorting).

Let me also think about whether to use the smooth approximation or directly work with the max. The log-sum-exp approximation is smooth and has a well-defined gradient, so it's good for gradient methods. As tau → ∞, it approaches the max.

The issue is: for very large tau, the gradient is concentrated on the peak, and the method becomes like "peak shaving" (move mass away from the peak). For small tau, it's more like "flatten the whole convolution" which might be less effective.

A good strategy: start with small tau (to get a rough shape) and gradually increase tau (to focus on the peak).

Let me also consider using the "proximal gradient" method with a Bregman divergence (mirror descent). Instead of Euclidean projection, use the entropy projection (Kullback-Leibler). This gives multiplicative updates:

a_new[i] = a[i] * exp(-lr * grad[i]) / Z

where Z = sum a[i] * exp(-lr * grad[i]).

This is the "exponential weighting" or "Hedge" algorithm applied to our problem. It naturally keeps a >= 0 and we just need to normalize.

The mirror descent step is:
a_new = argmin_{x in simplex} <grad, x> + (1/lr) * D(x, a)

where D is the KL divergence (relative entropy). The solution is:
x[i] = a[i] * exp(-lr * grad[i]) / sum_j a[j] * exp(-lr * grad[j])

This is always non-negative and sums to 1, so no projection needed!

The convergence rate of mirror descent with entropy on the simplex is O((R/d^2) * (1/T)) where R is the initial KL divergence and d is the minimum component (which can be very small, making this slow in theory). In practice, it works well.

Let me combine both approaches:
- Use mirror descent (multiplicative updates) as the main workhorse
- Use Euclidean projection as a backup
- Use Nesterov acceleration
- Anneal the temperature tau

Now, let me also think about the LP approach. The LP gives the exact best response, which is valuable for:
1. Verification: at the Nash equilibrium, the LP best response to a* should be a* itself (or very close)
2. Final polish: after gradient methods converge, use LP to fine-tune

The LP is slower per iteration but each iteration gives a "perfect" response. So a hybrid approach:
- Use fast gradient methods for the bulk of the optimization (90% of time)
- Use LP for final verification and polish (10% of time)

def fast_autocorr(a):
    """Full convolution a*a using FFT."""
    n = len(a)
    size = 2 * n - 1

    A = rfft(np.asarray(a, dtype=np.float64), fft_size)
    return irfft(A * A, fft_size)[:size]

def simplex_project(x):
    """Project onto the probability simplex {x >= 0, sum(x) = 1}."""
    n = len(x)
    # Euclidean projection onto simplex
    if n == 1:
        return np.array([1.0])
    u = np.sort(x)[::-1]
    cssv = np.cumsum(u)
    rho = np.nonzero(u * np.arange(1, n + 1) > (cssv - 1))[0][-1]
    theta = (cssv[rho] - 1) / (rho + 1.0)
    return np.maximum(x - theta, 0)

def compute_gradient(a, p):
    """
    Compute grad[i] = 2 * sum_j a[j] * p[i+j]
    where p has length 2n-1 (same as the convolution).
    Using FFT: grad = 2 * conv(a, p_flipped)[n-1:2n-1][::-1]
    """
    n = len(a)
    p_flipped = p[::-1]
    conv_len = n + len(p_flipped) - 1  # = 3n-2
    N = 1 << (conv_len - 1).bit_length()
    A = rfft(a, N)
    P = rfft(p_flipped, N)
    conv = irfft(A * P, N)[:conv_len]
    grad = 2.0 * conv[n-1:2*n-1][::-1]
    return grad
