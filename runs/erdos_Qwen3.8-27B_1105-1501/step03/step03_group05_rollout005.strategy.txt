1. Approach and rationale

1.1 Central idea

The proposed method is an exact one-dimensional polynomial line-descent algorithm in the full coordinate space, wrapped in a validated basin-hopping / population search.

At a feasible point `h`, choose any feasible direction `v` satisfying approximate zero sum `sum(v)=0`. Move along the exact line

```
h(alpha) = h + alpha v
```

and evaluate the authoritative evaluator exactly, not a smoothed surrogate and not only linearized quantities. The key mathematical fact is that every lag score is quadratic in `alpha` and the linear/quadratic coefficients can be obtained from just three correlations:

```
raw_score(alpha) = raw_score(0)
                  + alpha * (correlate(v, 1-h) - correlate(h, v))
                  - alpha^2 * correlate(v, v)
```

with exactly the same `mode="full"` indexing as the evaluator. Therefore, for any chosen direction, the globally best feasible `alpha` along that exact line can be found by minimizing the maximum of a known set of quadratics over a known feasible `alpha` interval. Candidate stationary points and all pairwise envelope intersections are enumerated. This gives a genuine exact line minimization for every sampled full-dimensional direction, rather than a local gradient or pairwise-only move.

The direquality advantage over the previous construction and prior proposed methods:

- It uses the maximum of many exact quadratic functions in the direction variable, preserving the non-smooth max structure exactly.
- It can move all coordinates jointly along one feasible zero-sum line, not only two coordinates.
- It can land on exact envelope cusps, not only stationary points of a smoothed maximum.
- It accepts only candidates whose direct `np.correlate(h, 1-h)` objective improves the incumbent.

Because the original problem is nonconvex in `h`, local line steps cannot guarantee global optimality. The algorithm therefore combines this exact line primitive with:

- multi-resolution transfer,
- feasible transformations of the incumbent,
- population diversification,
- random feasible restarts,
- exact acceptance and exact re-evaluation,
- a safe parent fallback.

1.2 Why this can improve the supplied parent

The supplied parent is a known local point, typically with several active correlated lags at or near the maximum. A small final improvement usually requires a coordinated redistribution across many nearby coordinates because active lag constraints are coupled. Single-coordinate, smooth-gradient or LP-distance directions often miss fine movements where two opposing active lags become simultaneously balanced.

Full-dimensional exact lines address this bottleneck: when a direction is chosen well, the algorithm can jump along the entire feasible line and stop precisely at the best maximum-quadratic point, including the best envelope cusp, without project-loop drift or step-size smoothing errors. Random directions and feasibility transformations provide an escape from local stationary subgradients. The high-resolution variants help because the best true sample value can be represented more finely, while the exact evaluator still judges each actual returned discretization.

1.3 Limitations and distinctions between facts and heuristics

Justified exact facts:

- For any fixed line direction `v`, each finite-support correlation score is an exact quadratic polynomial in the line parameter `alpha`.
- `np.correlate` is bilinear in its two arguments, cond the expansion above is algebraically exact (up to floating-point rounding).
- Any accepted move is finally checked by the authoritative evaluator and feasibility constraints; the objective is never estimated at acceptance.
- Pairwise intersections and stationary points give a complete candidate list for the exact global minimum of a finite max-of-quadratives on a closed interval, modulo numerical tolerance and high-resolution pruning heuristics.

Heuristics:

- Direction sampling, population updates, transformations, and resolution search are local and not globally complete.
- The algorithm does not claim a minimizing or ast.
- High-resolution transformed vectors are different discretizations, not exact maps of the original continuous problem; each is accepted only after direct evaluation of its own evaluator score.
- Waterfilling is numerical; final returned vectors satisfy feasibility within a strict floating-point tolerance and are checked with the actual metric.

1.4 Selected default strategy

Execute the following pipeline:

1. Validate and repair the supplied parent. Store it as an always-available fallback.
2. Intensify the parent with a large budget of exact full-dimensional line steps at the parent resolution.
3. Generate candidates from feasible transformations of good points: reflection, mixing, cyclic rolls, random zero-sum perturbations, thresholded / binary snapshots, and population crossover.
4. Do exact line descent on new candidates at the same resolution.
5. Map good candidates to nearby resolutions and perform resolution-aware line descent.
6. Keep a small validated population of candidates. Continue line descent and transformation from them, preferring lower exact objective values and, on near ties, smaller vectors.
7. Use remaining budget for a tiny final pair-coordinate line polish, because the same full line machinery covers two-coordinate directions and can squeeze local fine moves.
8. Return the best exact-valid candidate found; if something crashes, return the validated parent or a deterministic feasible fallback.

2. Mathematical specification

2.1 Discretization and exact objective

Let `n = len(h)` and `dx = 2.0 / n`.

The evaluator uses

```
raw_scores = np.correlate(h, 1 - h, mode="full")
C5 = float(np.max(raw_scores) * dx)
```

Indexing convention:

- Lag offset `d` ranges from `-(n-1)` to `n-1`.
- Raw score rank `r = n - 1 + d`.
- For nonzero lag, only the finite-support overlapping range is included.

The raw score at offset `d` can be written exactly as:

```
S_d(h) = sum_{p=low(d)}^{high(d)-1} h[p+d] * (1 - h[p])
```

where

```
low(d)  = max(0, -d)
high(d) = min(n, n - d)
```

Use raw score `S_d` internally for line minimization. Multiply by `dx` only when computing or comparing the final reported bound. This avoids repetitive scaling and keeps line coefficients compatible with one output evaluator call.

2.2 Lipsche constraints

For every coordinate:

```
0 <= h[i] <= 1
```

and over samples:

```
sum(h) = n / 2
```

equivalently `sum(h) * dx = 1`.

The parent can be repaired to exact `sum(h) = n/2` and box intervals using the helper described below. All candidates and the final returned vector must pass a feasibility check. Because computations are floating-point, use a strict but tolerable check, for example:

```
0 <= h[i] <= 1 + 1e-12        (and clip final answer back where outside)
abs(sum(h) - n/2) <= 5e-12
```

A separate evaluator recompute always confirms the objective.

2.3 Exact line-subproblem formulation

For a feasible point `h` and feasible zero-sum direction `v`, define:

```
h_alpha = h + alpha v
```

The authoritative raw score vector along this line is:

```
A(alpha) = np.correlate(h_alpha, 1 - h_alpha, mode="full")
```

Using bilinearity:

```
A(alpha) = A + alpha*B + alpha^2*C
```

where:

```
A = np.correlate(h, 1 - h, mode="full").astype(float)
B = np.correlate(v, 1 - h, mode="full") - np.correlate(h, v, mode="full")
C = -np.correlate(v, v, mode="full")
```

The line objective in raw score units is:

```
f_raw(alpha) = max_r (A[r] + alpha*B[r] + alpha^2*C[r])
```

The final C5 on the line is `f_raw(alpha) * dx`.

2.4 Feasible line interval for alpha

The direction should be normalized and zero-sum. Box constraints imply:

For every coordinate with `v[i] > 0`:

```
alpha >= -h[i] / v[i]
alpha <= (1 - h[i]) / v[i]
```

For every coordinate with `v[i] < 0`:

```
alpha >= (1 - h[i]) / v[i]
alpha <= -h[i] / v[i]
```

The feasible interval is the intersection:

```
alpha_low  = max of all lower constraints and -large_finite if none
alpha_high = min of all upper constraints and +large_finite if none
alpha_low  = min(alpha_low, 0)
alpha_high = max(alpha_high, 0)
```

If `alpha_low > alpha_high`, the direction is infeasible; skip. If interval is infinite, choose a conservative cap based on alpha scale. Because nonzero zero-sum normalized directions usually bound both sides, cap only to avoid numerical runaway, for example:

```
if not finite interval side:
    set side to +/-(4 + norm(h, inf) / max(norm(v, inf), 1e-12))
```

At the end of interval arithmetic, shrink by `1e-14` on both ends when selecting an interior candidate. Using the endpoint candidate itself is allowed; at direct evaluation any boundary coordinate must be clamped and mass repaired if needed.
