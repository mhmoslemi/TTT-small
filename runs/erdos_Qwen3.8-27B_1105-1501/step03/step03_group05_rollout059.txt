Now, let me think about potential issues:
1. The LP might be infeasible if rho is too small (the box constraints and trust region might conflict). But since we start with a feasible point and the delta bounds include 0, the LP is always feasible (delta=0, t=max(scores) is always a feasible solution).

2. The LP might give a direction that doesn't improve the true objective (due to linearization error). The line search handles this.

3. The LP solution might have many nonzero delta components, representing a coordinated move. This is the key advantage over single-coordinate methods.

Let me also add a "top-k" variant: instead of minimizing the maximum, minimize the sum of the top-k scores. This might give better directions when only a few lags are near the maximum.

Actually, let me think about this more. The LP with the maximum constraint is:
minimize t
subject to: scores + G@delta <= t for all lags

This is equivalent to:
minimize t
subject to: scores[r] + G[r]@delta <= t for r = 0, ..., 2n-2

The optimal t will be the maximum of {scores[r] + G[r]@delta} at the optimum. The binding constraints are those where the linearized score equals t.

If I instead minimize the sum of the top-k linearized scores, I get a different (possibly better) direction. But this is harder to formulate as an LP.

Alternative: I can weight the constraints. For each lag r, use a weight w_r that's higher for lags near the maximum. Then:
minimize sum_r w_r * (scores[r] + G[r]@delta)
subject to: box, sum, trust region

This is a simpler LP (no t variable) and gives a weighted sum descent direction.

Let me now think about the multi-resolution aspect. For different n values, I need to:
1. Resample the current best solution to the new n
2. Optimize at the new n
3. Compare C₅ values

The resampling should be done carefully to preserve the integral. I'll use piecewise constant interpolation (the step function interpretation).

For converting from n_old to n_new:
- The old step function has n_old cells of width 2/n_old
- The new step function has n_new cells of width 2/n_new
- For each new cell, compute the average of the old function over that cell's interval

This is the integral-average (or boxcar) resampling.

```python
def _resample_fractional(h_old, n_new):
    n_old = len(h_old)
    dx_old = 2.0 / n_old
    dx_new = 2.0 / n_new
    h_new = np.zeros(n_new)
    for j in range(n_new):
        x_start = j * dx_new
        x_end = (j + 1) * dx_new
        # Find which old cells overlap [x_start, x_end)
        i_start = int(x_start / dx_old)
        i_end = int(np.ceil(x_end / dx_old))
        total_weight = 0.0
        weighted_sum = 0.0
        for i in range(max(0, i_start), min(n_old, i_end)):
            old_start = i * dx_old
            old_end = (i + 1) * dx_old
            overlap_start = max(x_start, old_start)
            overlap_end = min(x_end, old_end)
            if overlap_end > overlap_start:
                w = overlap_end - overlap_start
                weighted_sum += w * h_old[i]
                total_weight += w
        if total_weight > 0:
            h_new[j] = weighted_sum / total_weight
    return _project_box_sum(h_new, n_new / 2.0)
```

This is O(n_old * n_new) in the worst case, but for small n values it's fine.

def _resample_fractional(h_old, n_new):
    n_old = len(h_old)
    x_old = np.linspace(0, 2, n_old + 1)  # old cell boundaries
    x_new = np.linspace(0, 2, n_new + 1)  # new cell boundaries
    h_new = np.zeros(n_new)
    for j in range(n_new):
        # New cell [x_new[j], x_new[j+1])
        # Find overlapping old cells
        mask = (x_old[:-1] < x_new[j+1]) & (x_old[1:] > x_new[j])
        if mask.any():
            overlap_lens = np.minimum(x_old[1:][mask], x_new[j+1]) - np.maximum(x_old[:-1][mask], x_new[j])
            h_new[j] = np.dot(overlap_lens, h_old[mask]) / overlap_lens.sum()
    return _project_box_sum(h_new, n_new / 2.0)
