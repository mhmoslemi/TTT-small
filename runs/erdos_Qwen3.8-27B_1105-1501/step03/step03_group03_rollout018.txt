def _deriv_matrix(h):
    n = len(h)
    L = 2*n - 1
    A = np.zeros((n, L))
    # For each lag d, compute the derivative for all i at once
    for d in range(-(n-1), n):
        r = n - 1 + d
        if d >= 0:
            # ∂s_d/∂h[i] = (1-h[i-d]) for i >= d, minus h[i+d] for i+d < n
            i_range = np.arange(0, n)
            # First term: (1-h[i-d]) for i >= d
            mask1 = i_range >= d
            if np.any(mask1):
                idx = i_range[mask1]
                A[idx, r] += (1.0 - h[idx - d])
            # Second term: -h[i+d] for i+d < n
            mask2 = i_range + d < n
            if np.any(mask2):
                idx = i_range[mask2]
                A[idx, r] -= h[idx + d]
        else:
            g = -d
            i_range = np.arange(0, n)
            # First term: (1-h[i+g]) for i+g < n
            mask1 = i_range + g < n
            if np.any(mask1):
                idx = i_range[mask1]
                A[idx, r] += (1.0 - h[idx + g])

            mask2 = i_range - g >= 0
            if np.any(mask2):
                idx = i_range[mask2]
                A[idx, r] -= h[idx - g]
    return A

    best_t = t_candidates[np.arange(n)[:, None], np.arange(n)[None, :], best_k]
    
    f = np.where(valid, best_f, np.inf)
    cur_max = np.max(s)
    
    best_pos = np.unravel_index(np.argmin(f), (n, n))
    improve = cur_max - f[best_pos]
    
    if improve < 1e-12:
        return -1, -1, 0.0, 0.0
    
    return best_pos[0], best_pos[1], best_t[best_pos], improve

Now, one important consideration: after each greedy step, I update h. But the optimization of h[i] and h[j] was done assuming all other coordinates were fixed. The next step will reoptimize with the new values. This is a standard coordinate descent / cyclic method.

The issue is that greedy coordinate descent can cycle or get stuck. To prevent cycling:
- Use a small tolerance: only accept if improvement > 1e-14
- Keep a "recently used" mask and avoid re-using the same pair too quickly
- Use the annealing temperature to escape

Let me also think about what happens at the boundary. If h[i] is close to 0 or 1, the feasible range for transfer is very small, limiting the improvement. This is where the problem gets hard - the optimal solution might have many coordinates at the boundary (0 or 1), making it essentially a binary problem.

For binary solutions (h[i] ∈ {0,1}), the transfer t is either 0 or 1-h[j]+h[i] (to flip i to 1 and j to 0, or vice versa). The optimization becomes: which pair to flip minimizes the max score?

This is a combinatorial optimization problem (related to the minimum maximum autocorrelation of a binary sequence). For n=64, there are C(64,32) ≈ 10^18 possible binary sequences, so we can't enumerate. But we can use local search: try all possible flips (n² = 4096 possibilities) and pick the best one.

Actually, this is exactly what the greedy pair search does when the solution is binary! The transfer t = 1 (flip j from 1 to 0) and t = -1 (flip i from 0 to 1) or t = 0.25, 0.5, 0.75 for non-binary.

So my algorithm naturally handles both binary and non-binary solutions.
