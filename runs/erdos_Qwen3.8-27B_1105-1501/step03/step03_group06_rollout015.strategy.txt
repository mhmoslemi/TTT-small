1. Approach and rationale

1.1 Central idea

The supplied parent construction is already close to a high-quality incumbent, but the previous program relied mainly on a smoothed log-sum-exp surrogate plus a sequence of heuristic local moves. That approach can be blind to the exact bottleneck because it minimizes an aggregated approximation of the maximum rather than the exact set of constraints which define the official score.

The proposed program takes the opposite point of view: it treats the maximum over all lags as an explicit set of constraints and solves a sequence of local nonlinear programming subproblems. For a fixed resolution n, solve approximately

    minimize T
    subject to T >= dx * C_r(h),  r = 0,...,2n-2,
               sum_i h_i = n/2,
               0 <= h_i <= 1.

Here C_r(h) is one full-correlation contribution used by the evaluator and dx = 2/n. This epigraph formulation is algebraically exactly the original approximate feasibility problem except for the accuracy of the nonlinear local solver. To improve numerical locality without abandoning the exact bottleneck, also solve variants with a tiny smoothed-max term in the objective while retaining the hard epigraph constraints. Candidates are judged only by the exact task evaluator.

This is materially different from the previous algorithm:

- The previous main engine minimized a soft aggregate of all correlations and used smoothing/linearizations.
- This plan makes every max constraint explicit in the subproblem and optimizes the bottleneck itself with the true active and near-active constraints.
- It uses local constrained nonlinear optimization with analytic residuals, variable shifts, and warm starts, followed afterward by exact finite-sample post-processing and resolution variation.
- It aims to make a small deterministic improvement over the incumbent by exploiting curvature and active-set structure of the exact min-max problem, rather than randomly perturbing an approximate smoother.

1.2 Why it can improve the parent

At a near-optimal point, the score is often dominated by a few lags, but the log-sum-exp gradient is a weighted average over many lags. It can allocate reductions in a way that decreases the aggregate while the true maximum decreases slowly or stalls. The exact epigraph subproblem lets the local solver move h to reduce the actual max constraint and use second-order or quasi-Newton effects around the active maxima. Even if the global problem remains nonconvex and no finite solver proves global optimality, a direct constrained local model is often more effective than solving a biased surrogate once a close local optimum has been reached.

Two further global mechanisms are included:

- Low-dimensional transforms and binary-like valid descendants of the parent produce new basins not reachable by a Gaussian perturbation alone.
- Resolution transfer creates slight different finite discretizations where the same continuous idea corresponds to a different discrete active set, often unlocking an exact improvement.

No candidate is accepted as valid unless it satisfies box and sum constraints by a dedicated exact feasibility repair, and unless it is re-scored with the exact evaluator `max(np.correlate(h, 1.0 - h, mode="full")) * dx`. The returned value is therefore always an honest upper bound for the parent if no exact improvement is found.

1.3 Limitations, classifying facts and hypotheses

Justified facts:

- The final metric is exact. Every returned candidate is recomputed with the required np.correlate-centered objective.
- Feasibility of the box and sum constraints is enforced by a monotone feasible projection and repair that does not simply apply clipping and rescaling independently.
- The program retains the parent (or a deterministic valid fallback) and never returns worse than its initial valid fallback, provided the exact evaluation of initial inputs is kept.

Not true / limitations:

- The epigraph problem is nonconvex: constraints contain products h_i h_j. A local optimizer can find a local minimizer, not a global optimizer.
- Analytic gradients are verified empirically, not trusted unconditionally, because finite differences or scalar/factor conventions can expose bugs.
- The target C5 <= 0.38085 is not guaranteed in a fixed wall-clock budget. The program seeks to improve below the incumbent safely.
- Binary or heuristic variants are heuristic. They can provide better starts but are not complete search methods unless capped and terminated exactly.

2. Mathematical specification

2.1 Representation and exact objective

For any current dimension n, let

    dx = 2.0 / n
    target = n / 2.0.

A candidate h = h[0],...,h[n-1] represents samples over the uniform cell-centered grid on [0,2]. Feasibility demands

    0 <= h_i <= 1,
    sum_i h_i = target.

The exact evaluator is

    R(h) = np.correlate(h, 1.0 - h, mode="full")
    C(h) = dx * max(R(h)).

The length of R is K = 2n - 1. The internal formulation may arrange the lags in any order because the objective is the maximum of all rows, but final validation always uses exact R in the exact np convention. The internal gradient and constraints must include the complete full-correlation terms and not a circular convolution or an omitted direction.

Important: the overlap term at a nonzero shift does not have a fixed support length. Therefore do not replace the problem by reinterpretations using autocorrelation alone, Fourier norms, or a minimum, unless an exact identity for the discrete full correlation has been derived. This plan keeps the exact full correlation rows.

2.2 Variable shift and epigraph formulation

To improve conditioning, optimize a centered variable

    y = h - 0.5,

so that

    -0.5 <= y_i <= 0.5,
    sum_i y_i = 0,
    h_i = y_i + 0.5.

For optimization variables, define

    x = [T; y]

with length n+1. Unit T is exactly the final scaled C value constraint bound.

Define the correlation vector under an internal row correspondence as c(x), where internal c_r(x) is exactly one full-correlation term (as a maximum set this is equivalent to using np order; in the final measure rows are not reordered). Use correlation based on the full finite support without circular wrap:

For a lag index r corresponding to integer displacement s, define overlap index set

    I_s = {i: 0 <= i < n, 0 <= i+s < n},

and the term

    C_s(y) = sum_{i in I_s} (y_i + 0.5) * (1 - (y_{i+s} + 0.5)).

The implementation should generate all rows needed for the full correlation. If the generated lag mapping is reversed or permuted relative to `np.correlate`, the maximum is unchanged, but a small sanity test should be done: random y, compute the internal maximum and the exact maximum, and require equality. Use either vector exactly for constraints, and keep all final evaluations via exact evaluator.

For r = 0,...,K-1, define scaled correlation

    G_r(y) = dx * C_r(y).

Epigraph problem:

    minimize T
    subject to T - G_r(y) >= 0, for all r,
               sum_i y_i = 0,
               -0.5 <= y_i <= 0.5.

2.3 Softly regularized epigraph subproblem

If the pure epigraph minimization stalls because T has a trivial objective and nonlinear constraints are numerically difficult, solve the same constrained problem with a tiny regularized objective that also depends on h:

    F_delta,alpha(T,y) = T + delta * L_alpha(G(y)).

The weighted log-sum-exp is

    m = max_r G_r(y),
    v_r = alpha * (G_r(y) - m),
    w_r = exp(v_r) / sum_s exp(v_s),
    L_alpha(y) = m + (log(sum_r exp(v_r)) - log K) / alpha,

where subtracting log K keeps the surrogate less dependent on K after subtracting the max. d form an invariant to first order? The subtraction is a constant; gradient is unaffected.

Use small regularization constants and choose only one per solve:

- delta 0 for the hard epigraph,
- delta 1e-3, 3e-3, 1e-2, with alpha in {10, 30}.

The correlation inequality constraints remain hard during the subproblem, so the objective term is only a direction and curvature provider. The accepted solution comes from exact evaluation after projection.

2.4 Analytic gradients

Need gradient of G_r(y) with respect to y. Since variables are centered, derivative w.r.t. y equals derivative w.r.t. h.

For a row at displacement s:

    derivative w.r.t. y_i for a term active in I_s:
    d/dy_i (h_i (1 - h_j)) = 1 - h_j
    d/dy_j (h_i (1 - h_j)) = -h_i,
    where j = i+s.

Define a sparse dense gradient matrix Grad(y) with shape (K,n) whose row r has those coefficients. With y = h-0.5, substitute values h_i = y_i+.5 into coefficients. When multiple same indices receive contributions, accumulate them. Implementation detail: compute internal correlation rows and gradient rows simultaneously in a loop over all lags; this is trivially small and avoids substitutions/order mistakes.

Weighted LSE gradient:

    dF(T,y)/dT = 1
    dF/dy = d sum+
    = sum_r w_r * Grad[r,:].

The full objective Jacobian row has a scalar constant on the general objective objective orientation and variant adjust only for T term if there is appends. For soft regularize, add `delta * LSE_grad`.

Constraint Jacobian:

For each inequality residual function r_r(T,y) = T - dx*C_r(y), the row is

    d r_r / dT = 1
    d r_r / dy_j = - dx * Grad[r,j]

Equality residual:

    e(T,y) = sum_j y_j
    d e / dT = 0, d e/dy_j = 1.

Bounds are supplied separately to solver as x[0] in [0, 1.0] and each y_i in [-0.5,0.5]. If using raw h variables directly, bounds are [0,1], equality sum(h)-n/2. Prefer y variables because sum target zero with order-one coefficients provides much better scaling.

A solver-independent gradient validation must be implemented: with a random y, compute analytic positive variables and compare to centered finite differences on random rows and objectives for random small states; for implementation reasoning, if difference > 1e-6 absolute/relative at a prep debug stage, don't trust that solver path and use finite difference for constraints or turn fallback off; in production code use deterministic checks to pick internal correlation orientation. Reject candidate from assumptions product by exact acceptance.

2.5 Feasibility, projection, and repair

A naive sequence "clip then scale" may violate the integer target after clipping. Use a bisection clip projection:

    Project(v, target):                     # v length n, target in [0,n]
    1. if target <= 0, return zeros
       if target >= n, return ones
    2. Define f(lambda) = sum(clip(v_i - lambda, 0, 1))
       f is nonincreasing in lambda.
       low = min(v)-2, high = max(v)+2.
       For up to 75 iterations, choose mid. If f(mid) > target, low = mid;
       else high = mid. Stop when interval < 1e-13.
    3. h = clip(v - (low+high)/2, 0, 1)
       Compute residual s = sum(h) - target.
    4. Feasibility mass repair:
       if abs(s) < 1e-10, accept.
       If s > 0, subtract s from entries. Prefer entries that are fractional/gentle, then interior entries. For each chosen entry, reduce by at most min(remaining, h_i); if remaining remains after reducing positive interior entries, reduce entries that correspond to h_i > 0. maintain trunc within bounds.
       If s < 0, increase entries preferring fractional/max<1 interior. After repair, clip to [0,1] and repeat max twice.
       A choice that violates the tolerance of 1e-10 is rejected rather than used in exact improve comparison.

For square: if original y is centered and exact sum zero, a degenerate initial should work. The final repair always converts to h and can be reused. Keep claims of constraint satisfaction robust by checking final min, max, sum.

2.6 Resolution transfer

Sample centers when changing resolution retain interval [0,2]:

    x_old = (linspace-like centers (i+0.5)/n_old for i=0..n_old-1)
    x_new = (j+0.5)/n_new for j=0..n_new-1
    h_new = linearly interpolate h_old at x_old to x_new
    h_new = Project(h_new, n_new/2)

If n_new odd, the right-hand target is a half integer exactly representable if even/float values. Parent-n interpolation re-expresses finite support and creates new maximum. Formatting for resolution candidates is in exact scaling, not drop by number of coefficients.

2.7 Binary and rounding transformations (heuristic global moves)

Even though continuous value variables are optimized, binary states are easier for gradients and interesting local basin candidates.

Generate binary-like candidates:

- if n even, select exact n/2 indices whose internal soft h-values have highest value, set binary and validate score;
- exclude n where half target is not exact;
- perturb smoothing `eps * (binary - binary_mean)`; the center variable is binary -(sum/n), so sum y=0 before projection and if projection with binary eps is assigned to the nearest target, preserve baseline.
- Alternatively: threshold at exact `bin_channel_sum` and corrective steps add EPS to differences. Exact round ensures sum only if lower matching. A chosen fractional exact amount can be set along thresholds.

No hardcoded binary vectors are generated. Everything algorithmically from current values and RNG seed.

1. Approach and rationale

1.1 Central idea
The supplied parent construction is near a local minimum but the previous algorithm mostly optimizes a smoothed aggregate of all correlation values. That aggregate is not maximally sensitive to the small active set that actually determines the exact evaluator maximum, and it can stall while the true bottleneck is slowly reduced. The proposed plan attacks the exact bottleneck directly.

For each resolution n it solves local nonlinear epigraph subproblems:

  minimize T
  subject to T >= dx * C_r(h) for every full-correlation row r=0,...,2n-2,
             sum_i h_i = n/2,
             0 <= h_i <= 1,

where C_r(h) is one full finite-support correlation term and dx=2/n. The hard constraints make the solver move only when it can reduce or balance the actual constraints, not merely reduce an approximate log-sum-exp surrogate.

To avoid tight numerical stalls in the pure epigraph problem, use two objective modes with the same hard constraints:

- pure epigraph objective, minimizing T alone;
- lightly regularized objective, minimizing T plus a small smoothing term over exact scaled correlations.

Candidates are generated from the parent, global transforms, smoothed/relaxed states, and nearby resolutions. Every candidate is projected by an explicit bisection feasibility repair and finally scored with the exact evaluator `max(np.correlate(h,1-h,mode="full"))*dx`.

The key methodological difference from the parent is that the exact `max` inequalities are retained as a constraint system. The key difference from generic smoothing is that the smoothing regularizer cannot declare success on its own; the hard epigraph constraint remains enforced in the subproblem and every noun of output is judged by exact `np.correlate`.

1.2 Why this addresses the parent bottleneck
At tight bounds, normal directions in h also mostly affect the few active correlation rows. The log-sum-exp gradient weights all lags. An epigraph trust-region subproblem can use the analytic Jacobians of active and near-active rows, reducing actual maxima or improving KKT conditions in ways a fixed surrogate gradient may request. The nonconvex problem is handled locally; no global optimality is claimed. Exact acceptance prevents a weak solver from returning an invalid bound.

Resolved differences from earlier plans: this specification does not rely on a direct CVXPQRS relaxation, circular correlation substitution, or a 0/1 completion filter that may throw away a feasible half-integer solution. It specifies compact compact plan robustly readable by another coder and preserves the raw evaluator.

1.3 Limitations
This is local nonconvex optimization. It may find a local but not the global optimum. The code must:
- validate gradients,
- retain only feasible final h with acceptable numerical tolerance,
- keep the parent/fallback and never return a worse invalid object,
- make all local computations constrained by the time deadline.
