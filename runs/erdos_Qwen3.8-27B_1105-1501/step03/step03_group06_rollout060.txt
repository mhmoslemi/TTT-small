One more thought: the `_pairwise_min` function does a binary search on v. But I can make it more efficient by noting that v_star is the minimum value of a convex piecewise linear function. The minimum occurs at a "kink" point, which is where two of the lines (corr[r] + b[r]*t) intersect and are both on the upper envelope. 

An alternative to binary search: find the t where the subgradient of the max contains 0. The subgradient at t is {sum of b[r] : r in active(t)} where active(t) = {r : corr[r] + b[r]*t = max_s (corr[s] + b[s]*t)}.

As t increases, the active set changes at "critical values" where two lines cross. The minimum is at the critical value where the subgradient changes from negative to positive.

To find this:
1. Compute all critical values t_c where two lines cross: t_c(r,s) = (corr[s] - corr[r]) / (b[r] - b[s]) for b[r] ≠ b[s]
2. At each critical value, check if it's feasible (within [t_lo, t_hi]) and if the subgradient contains 0
3. The answer is the first such t_c (in order of increasing "activeness")

But this is O(m²) to enumerate all critical values, and O(m) to check each, giving O(m³) total. With m=127, that's about 2M operations per pair. Too slow.

Binary search is O(m * log(range)) which is much better. Let me stick with binary search.
