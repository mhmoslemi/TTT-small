def soft_grad(h, tau):
    """Compute gradient of soft-max approximation."""
    n = len(h)
    dx = 2.0 / n
    scores = np.correlate(h, 1.0 - h, mode='full') * dx
    max_s = np.max(scores)
    exp_s = np.exp((scores - max_s) / tau)
    Z = np.sum(exp_s)
    w = exp_s / Z
    
    G = grad_matrix(h)
    grad = G.T @ w * dx
    return grad

def grad_descent(h, deadline, tau_init=0.5, lr_init=0.01):

            cur_c5 = c5_new

def resample(h, n_new):
    n = len(h)
    if n_new == n:
        return h.copy()
    x_old = (np.arange(n) + 0.5) / n
    x_new = (np.arange(n_new) + 0.5) / n_new
    h_new = np.interp(x_new, x_old, h)
    return project(h_new, n_new / 2.0)

Actually, I just realized something. The previous code's LP formulation minimizes s = max_k (score_k + G[k,:] @ p). But this is the LINEARIZED max. The actual max after taking step alpha*p might be much larger or smaller depending on the bilinear terms.

The key issue: the bilinear term h[i]*h[i+k] changes when we change h. The linearization approximates this change as:
(h[i]+p[i]) * (1-h[i+k]-p[i+k]) ≈ h[i]*(1-h[i+k]) + p[i]*(1-h[i+k]) + h[i]*(-p[i+k])
= score_k + G[k,:] @ p

The second-order term is -p[i]*p[i+k] which is O(p²). If the step size is small, this is negligible. But if the step is large, the linearization is poor.

The line search handles this by finding the actual best alpha, but the DIRECTION from the LP might be suboptimal for the actual (nonlinear) problem.

To improve, I could:
1. Use a smaller radius (more accurate linearization, but smaller steps)
