Here's the idea:
- Fix all h_j for j ≠ m.
- For each lag k, corr_k is a linear function of h_m: corr_k = a_k * h_m + b_k.
- The objective is max_k (dx * (a_k * h_m + b_k)).
- We want to minimize this over h_m ∈ [0,1], subject to the sum constraint.

The sum constraint means: sum_j h_j = n/2, so h_m = n/2 - sum_{j≠m} h_j. This means h_m is actually fixed! We can't vary it independently.

So coordinate descent doesn't directly work with the sum constraint. We need to either:
1. Vary two coordinates simultaneously (h_m and h_p).
2. Use a different approach.

For (1), the 2D problem is: minimize max_k (dx * (a_k * h_m + a'_k * h_p + b_k)) subject to h_m + h_p = constant, 0 ≤ h_m, h_p ≤ 1.

This is a 1D problem (parameterize by h_m, with h_p determined by the constraint). The objective is max of linear functions of h_m (since h_p = constant - h_m, so a'_k * h_p = a'_k * constant - a'_k * h_m, which is still linear). So it's the same 1D problem.

This is promising! Let me implement a 2-coordinate descent:

For a pair (m, p):
- Let s = h_m + h_p (fixed by the sum constraint).
- h_m = x, h_p = s - x, where x ∈ [max(0, s-1), min(1, s)].
- For each lag k: corr_k(x) = a_k * x + b_k (linear in x).
- Minimize max_k (a_k * x + b_k) over x in the feasible range.

The minimum of the max of linear functions over an interval occurs at:
- A point where two lines intersect (and is below all other lines)
- Or at a boundary of the interval.

To find it efficiently:
1. Evaluate the max at the two boundaries.
2. For each pair of lines (i, j), find their intersection x*. If x* is in the feasible range and at x*, line i and j are both above all other lines, then x* is a candidate.
3. Take the best candidate.

But checking "above all other lines" for each pair is O(n) per pair, and there are O(n^2) pairs, so total O(n^3) per pair of coordinates. For n=84, that's about 600k operations per coordinate pair, and there are about 84*83/2 ≈ 3500 pairs, so total about 2 billion operations. That's too slow.

Actually, the function f(x) = max of linear functions is convex (it's the pointwise maximum of affine functions). So we can use a convex 1D optimization method. The minimum of a convex piecewise linear function occurs at a "kink" point or at a boundary.

For a convex piecewise linear function, we can find the minimum by:
1. Binary search on the subgradient. At the minimum, 0 is in the subdifferential.
2. The subdifferential at x is the convex hull of the slopes of the lines that are active (achieve the maximum) at x.
3. So we're looking for a point where the subdifferential contains 0, i.e., there's at least one line with negative slope and at least one with positive slope that are both active.

This is equivalent to finding a "crossing point" where the maximum switches from one line to another.
