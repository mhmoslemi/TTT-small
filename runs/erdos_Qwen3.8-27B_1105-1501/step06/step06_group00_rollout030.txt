```python
    overlaps = np.correlate(h, 1-h, mode='full')
    # Shift to make values smaller for numerical stability
    m = overlaps.max()
    log_sum = m + np.log(np.sum(np.exp(overlaps - m)))
    return log_sum / beta

def softmax_gradient(h, beta):
    n = len(h)
    overlaps = np.correlate(h, 1-h, mode='full')
    m = overlaps.max()
    weights = np.exp(overlaps - m) / np.sum(np.exp(overlaps - m))
    # Gradient of each overlap_k w.r.t. h
    # For shift s (k = s + n - 1):
    # overlap_s = sum_i h[i]*(1-h[i+s]) (for s >= 0)
    # d(overlap_s)/d(h[j]) = (1-h[j+s]) - h[j-s] (with bounds)
    grad = np.zeros(n)
    for k in range(2*n-1):
        s = k - (n-1)
        if weights[k] < 1e-10:
            continue
        if s >= 0:
            # overlap = sum_{i=0}^{n-1-s} h[i]*(1-h[i+s])
            # d/dh[j] = (1-h[j+s]) for j <= n-1-s, minus h[j-s] for j >= s
            if s == 0:
                grad[:n] += weights[k] * (1 - 2*h)
            else:
                grad[:n-s] += weights[k] * (1 - h[s:])
                grad[s:] -= weights[k] * h[:n-s]
        else:
            g = -s
            # overlap = sum_{i=0}^{n-1-g} h[i+g]*(1-h[i])
            # d/dh[j] = (1-h[j-g]) for j >= g, minus h[j+g] for j <= n-1-g

            else:
                grad[g:] += weights[k] * (1 - h[:n-g])
                grad[:n-g] -= weights[k] * h[g:]
    return grad / beta
```

```python
            h[i], h[j] = 0, 1
            new_c = np.correlate(h, 1-h, mode='full')
            new_max = new_c.max()
            delta = cur_max - new_max
            h[i], h[j] = 1, 0
            if delta > best_delta:
                best_delta = delta
                best_pair = (i, j)
        
        if best_pair is not None:
            i, j = best_pair
            h[i], h[j] = 0, 1
            c = np.correlate(h, 1-h, mode='full')
            cur_max = c.max()
            ones = np.where(h > 0.5)[0]
            zeros = np.where(h <= 0.5)[0]
            if cur_max < best_max:
                best_max = cur_max
                best_h = h.copy()
            stall = 0
        else:
            stall += 1
    
    return best_h, best_max
```

This is simple but might be slow because we're calling np.correlate 200 times per iteration. Each call is O(n²) = O(32400). 200 calls = 6.5M operations per iteration. At ~1 ns per operation (vectorized), that's ~6.5 μs per iteration. So we can do ~100,000 iterations per 0.65 seconds. Over 400 seconds, that's ~60 million iterations. Each iteration that succeeds reduces the max by 1 (in the binary case), so we can reduce by up to 60 million... but realistically we'll hit a local optimum quickly.

The issue is that random sampling of 200 pairs out of 8100 possible pairs might miss the best swap. Let me try a different approach: instead of random sampling, use a structured search.

**Structured binary local search**:
1. Find the worst shift k* (where c is maximum)
2. For each i with h[i]=1, compute the effect of removing h[i] on c[k*]
3. For each j with h[j]=0, compute the effect of adding h[j] on c[k*]
4. The pair (i, j) that reduces c[k*] the most is the best candidate
5. Check that this swap doesn't increase any other c[k] above the current max
6. If it does, try the next best pair

The effect of removing h[i] on c[k] (for a specific k):
c[k] = ∑_n h[n+k]*(1-h[n])
Change due to h[i] going from 1 to 0:
- If i = n+k for some n (i.e., n = i-k is valid): the term h[i]*(1-h[i-k]) = 1-h[i-k] is removed. Change: -(1-h[i-k]) = h[i-k]-1 ≤ 0.
- If n = i: the term h[i+k]*(1-h[i]) = h[i+k]*0 = 0. No change.

So the change in c[k] from removing h[i] is:
δ_remove(k, i) = (h[i-k] - 1) if 0 ≤ i-k ≤ n-1, else 0

The effect of adding h[j] on c[k]:
- If j = n+k for some n (i.e., n = j-k is valid): the term was h[j]*(1-h[j-k]) = 0, now is 1-h[j-k]. Change: +(1-h[j-k]).
- If n = j: the term was h[j+k]*(1-h[j]) = h[j+k], now is 0. Change: -h[j+k].

δ_add(k, j) = (1-h[j-k]) * [0 ≤ j-k ≤ n-1] - h[j+k] * [0 ≤ j+k ≤ n-1]

Total: δ(k; i, j) = δ_remove(k, i) + δ_add(k, j)

For a fixed k*, we want to minimize c[k*] + δ(k*; i, j) = c[k*] + δ_remove(k*, i) + δ_add(k*, j).

Since δ_remove(k*, i) = h[i-k*] - 1 (if valid) is independent of j, and δ_add(k*, j) is independent of i, we can separate:
- Best i: minimize h[i-k*] - 1 (i.e., minimize h[i-k*])
- Best j: minimize (1-h[j-k*]) - h[j+k*] (i.e., maximize h[j-k*] - ... wait)

Actually: δ_add(k*, j) = (1-h[j-k*]) - h[j+k*] (with validity checks)
We want to minimize δ_add, so we want to minimize (1-h[j-k*]) - h[j+k*] = 1 - h[j-k*] - h[j+k*].
This is minimized when h[j-k*] is large and h[j+k*] is large.

So the best pair (i, j) for reducing c[k*] is:
- i: h[i]=1 and h[i-k*] is as small as possible (preferably 0)
- j: h[j]=0 and h[j-k*] + h[j+k*] is as large as possible (preferably both 1)

This gives a very fast O(n) procedure to find the best pair for a given k*!

But we also need to check that the swap doesn't increase other c[k] values. This check is O(n) (comparing the new c[k] for the affected k values against the current max).

So each iteration of the structured local search is O(n) to find the best pair + O(n) to verify = O(n) total!

That's much faster. Let me implement this.

But wait, there's a catch. The "best pair for k*" might not be the "best pair overall" (it might increase some other c[k] above the max). So we might need to try multiple candidates.

Strategy:
1. For the worst k*, find the top K candidates (i, j) that reduce c[k*] the most
2. For each candidate, check if the swap is valid (doesn't increase max)
3. Accept the first valid one
4. If none are valid, try the second-worst k*, etc.

With K = 10-20 candidates, this should be efficient.

Let me also think about the "verify" step more carefully. When we do the swap (i, j), the c[k] values change only for k where δ(k; i, j) ≠ 0. As I computed earlier, these are the k values where:
- i-k is in [0, n-1] (i.e., k in [i-(n-1), i])
- j-k is in [0, n-1] (i.e., k in [j-(n-1), j])
- j+k is in [0, n-1] (i.e., k in [-(j), n-1-j]... wait, k in [-(n-1-j), -j])

Wait, let me re-index. The correlation c is indexed 0 to 2n-2. Let shift s = k - (n-1), ranging from -(n-1) to n-1.

δ_remove(s, i): nonzero when 0 ≤ i-k ≤ n-1 where k = s + (n-1).
So 0 ≤ i - s - (n-1) ≤ n-1
i - (n-1) ≤ s ≤ i
and we need s in [-(n-1), n-1].

δ_add(s, j): 
- (1-h[j-k]) term: nonzero when 0 ≤ j-k ≤ n-1, i.e., j-(n-1) ≤ s ≤ j
- -h[j+k] term: nonzero when 0 ≤ j+k ≤ n-1, i.e., -(j) ≤ s ≤ n-1-j

So the affected shifts are s in:
[i-(n-1), i] ∪ [j-(n-1), j] ∪ [-j, n-1-j]

Each of these is an interval of length n. The union has at most 3n elements. For n=180, that's 540 shifts to check.

But we can do better: we only need to check if c[s] + δ(s) > current_max for the affected s values. If we maintain c as an array, we just need to check the max over the affected indices.

Actually, for the "first improvement" strategy, we can just:
1. Tentatively apply the swap to c (add δ)
2. Check if max(c) has decreased
3. If yes, accept; if no, revert

Since c has 2n-1 = 359 entries, checking the max is O(n) = O(359). And updating c (adding δ) is O(n) as well (only ~3n entries change, but we can just recompute c from scratch using np.correlate, which is also O(n²) but fast in practice).

For simplicity and speed, let me just recompute c using np.correlate after each swap. For n=180, this takes about 1-2 microseconds (numpy's correlate is highly optimized).
