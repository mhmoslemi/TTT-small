1. Find the worst lag k*.
2. Find the pair (j, m) and the value h[j] that most reduces c[k*].
3. Apply the move if it doesn't increase other lags too much.

For step 2:
c[k*] = sum_i h[i+k*]*(1-h[i])
The coefficient of h[j] in c[k*] is:
a_k*[j] = (1-h[j-k*])_valid - h[j+k*]_valid

To reduce c[k*], we want to decrease h[j] where a_k*[j] > 0, or increase h[j] where a_k*[j] < 0.

If we transfer mass from j to m (h[j] -= δ, h[m] += δ):
Δc[k*] = δ * (a_k*[m] - a_k*[j])

We want this to be negative, so we want a_k*[m] < a_k*[j].

So the best move for lag k* is:
- j = argmax_m a_k*[m] (coordinate with largest positive coefficient)
- m = argmin_j a_k*[j] (coordinate with smallest/most negative coefficient)
- Transfer mass from j to m

This is a single O(n) computation per lag! And we can do it for the top few lags.
