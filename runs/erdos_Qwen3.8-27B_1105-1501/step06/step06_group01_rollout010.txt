**Gradient-guided pair optimization:**
The idea is to use the subgradient to guide which pairs to try. If S[k*] is the maximum, then moving mass from a position where h contributes a lot to S[k*] to a position where it contributes less (or negatively) should reduce the maximum.

For the active lag k* (with shift r*), the contribution of h[i] to S[k*] is:
- dx*(1-h[i+r*]) if shifting h[i] up increases S[k*] (when i+r* < n)
- -dx*h[i-r*] if shifting h[i] down... 

Actually, the gradient tells us: increasing h[i] changes S[k*] by dx*(1-h[i+r*]) - dx*h[i-r*]. So if this is negative, increasing h[i] decreases the active constraint, which is good.

So the strategy is:
1. Find the active lag k*
2. Compute the gradient g[i] = ∂S[k*]/∂h[i]
3. Find pairs (i, j) where g[i] < 0 and g[j] > 0 (moving mass from i to j decreases S[k*])
   Wait, we want to decrease the MAX. If we decrease S[k*] but increase some other S[k'], that might not help.
   
   Actually, the right approach is: the direction that decreases the max the most is the one that has the most negative component in the direction of the subgradient. The subgradient of max at the active set is the average of the gradients of active constraints.

Let me simplify: use the subgradient to compute a "descent direction" p = -subgradient (projected to sum(p)=0), then do a line search along this direction. This is essentially what the LSE smooth descent does, but using the exact subgradient.

But the subgradient is only valid at the current point and the feasible set is non-smooth. So I'll combine:
- Use the subgradient direction for a few steps (smooth descent)
- Then switch to pair moves for fine-tuning

        return np.zeros(n)
    if target >= n:
        return np.ones(n)

        else:

But actually, I can compute the gradient more efficiently using convolutions:

g[i] = sum_k w[k] * dS[k]/dh[i]

For the term where h[i] appears as the "first" factor:
sum_k w[k] * dx * (1-h[i+r_k]) where r_k = k-(n-1)
= dx * sum_r w[n-1+r] * (1-h[i+r]) * [0<=i+r<n]
= dx * (w_shifted * (1-h))[i] (some kind of convolution)

For the term where h[i] appears as the "second" factor:
-sum_k w[k] * dx * h[i-r_k] * [0<=i-r<n]
= -dx * sum_r w[n-1+r] * h[i-r] * [0<=i-r<n]
= -dx * (w_shifted * h)[i] (reversed convolution)

So g = dx * (w_fwd * (1-h)) - dx * (w_rev * h) where w_fwd and w_rev are appropriately shifted versions of w.

This can be computed with np.convolve or scipy.signal.convolve in O(n log n) time.

def _compute_grad(h, w):

    n = len(h)

    # w[k] corresponds to shift r = k - (n-1)

    # w_neg = w[:n-1] (for r < 0, length n-1)

    # Actually: sum_{r} w[n-1+r] * (1-h[i+r]) = sum_r w_pos[r] * (1-h[i+r])

    # = cross-correlation of (1-h) with w_pos at lag i
    # In terms of convolution: if we flip w_pos, then convolve with (1-h):
    # conv(flip(w_pos), (1-h))[n-1-i + ...]

    # np.correlate(1-h, w_pos, mode='valid') gives (1-h) cross-correlated with w_pos
    # result[i] = sum_j (1-h)[i+j] * w_pos[j] = sum_j (1-h[i+j]) * w_pos[j]
    # That's exactly what we want for term1!

    # = (w_pos * (1-h))[i] in the "valid" sense of the convolution? No...

    # term1[i] = w_pos @ (1-h[i:])  (dot product of w_pos with the tail of (1-h) starting at i)

    # term1[i] = sum_{j=i}^{n-1} w_pos[j-i] * (1-h[j])
    # Let j' = j - i: term1[i] = sum_{j'=0}^{n-1-i} w_pos[j'] * (1-h[i+j'])
    # This IS the cross-correlation! np.correlate(1-h, w_pos, 'full')[n-1] ... no.
