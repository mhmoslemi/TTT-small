1. Approach and rationale

The supplied parent construction is already a strong local point (around C5 = 0.380891), but the dominant limiting behavior is local optimality under mostly low-dimensional moves. The objective is a nonsmooth maximum of many finite-lag overlap terms, and each lag contains products h_i h_j. Pairwise coordinate moves and small active-set gradient polish are excellent for climbing out of sharp nonsmooth kinks, but they tend to remain in the same cluster because they only move two coordinates at a time and only react to the current record lags with a somewhat delayed temperature schedule.

The proposed primary algorithmic change is a multi-start, full-vector, soft-max minimization of the exact discrete objective, followed by exact validation and an improved exact pair-line polish. The main operator is:
- minimize a smooth surrogate Φ_β(h) = logsumexp_β(T_1(h),...,T_L(h)) / β, where T(h) are exactly the evaluator's lag values scaled by dx = 2/n;
- keep the constraints h ∈ [0,1]^n and ∑ h_i = n/2 exactly enforced or repaired after every solver call;
- use one-hot or active-set exact scores for acceptance;
- ramp the soft-max hardness β so that first many lags are influenced and later only the peak lags are equalized;
- start from the parent and from several independently constructed feasible vectors, including low-frequency smooth families and balanced random kicks;
- after a promising soft-max result, use a more robust exact pair-line search with grid-plus-bracketing (not only a blind golden section over the full interval) and a bounded stochastic exact pair polish.

Why this may improve the parent:
- Soft-max supplies a dense gradient field, not just the subgradient at the argmax, so coordinates that are second, third, ... largest can be reduced in a coordinated way.
- The full-dimension constrained optimizer changes many coordinates consistently through a projected/quasi-Newton linearization, overcoming barriers from restrictive pair moves.
- Exact validation still guarantees the returned value is truly max_np_correlate(h,1-h)*dx, not a surrogate value.
- Multi-start low-dimensional starts may enter a different local basin than the parent; the exact polish can then make them valid record-setters.

Important limitations:
- Φ_β is nonconvex, and the original problem is nonconvex. The method is local/multistart and gives no global optimality guarantee.
- Soft-max minimization is only a surrogate; final acceptance is always the task evaluator's exact objective.
- If a solver or an exact candidate is infeasible or nonfinite, it is rejected. The parent construction is always retained as a fallback once validated and projected.
- The method is heuristic; claims of improvement are testable only by the exact returned score and the exact constraints.

2. Mathematical specification

2.1 Discrete decision variables and feasible set

Let n be even in the main search, preferably n = 122 initially and several candidate resolutions. Define x_i = (i + 0.5)/n for i = 0,...,n-1 as a normalized midpoint coordinate on [0,1]. The decision vector is h ∈ R^n.

Constraints:
- 0 ≤ h_i ≤ 1 for all i.
- ∑_{i=0}^{n-1} h_i = n/2.
  Since dx = 2/n, then ∫_0^2 h = (∑ h_i) * dx = 1.

The exact objective is the same as the evaluator:

C5(h) = max_{r=0}^{2n-2} T_r(h), where
T_r(h) = ((np.correlate(h, 1 - h, mode="full"))[r]) * dx.

This represents, for lag r-(n-1), the finite-support overlap ∑ overlap-products h_j(1 - h_i). At reduced lags the overlap contains fewer terms; the implementation does not replace the objective by an autocorrelation lower bound.

For a lag offset ℓ = r - (n-1):
- If ℓ ≥ 0, pairs are (j + ℓ, j), j = 0,..., n-ℓ-1, term = h_{j+ℓ}(1 - h_j).
- If ℓ < 0 with s = -ℓ, pairs are (j, j + s), j = 0,..., n-s-1, term = h_j(1 - h_{j+s}).

This orientation and the full mode result are exactly equivalent to np.correlate(h, 1 - h, "full").

2.2 Exact-score helper definition

Define eval_exact(h). Required outputs:
- c = max(np.correlate(h, 1 - h, mode="full")) * (2.0 / n)
- return float c. If h_i not finite or any h_i smaller than 0 or greater than 1 by more than 1e-9 tolerance, set c = +inf.

The programmer must not compute C5 from the smooth approximation. Every stored best uses eval_exact.

2.3 Joint feasibility projection

After any interpolation, solver callback, or pair update, enforce feasibility jointly:

project_to_box_and_sum(v, tau), tau = len(v)/2.

Input v finite; output z finite with 0 ≤ z_i ≤ 1 and ∑ z_i = tau.

Algorithm:
1. If tau ≤ 0: return zeros. If tau ≥ n: return ones.
2. Minimize ||z - v||_2 under z ∈ [0,1], ∑ z_i = tau.
   By separability, z_i(θ) = clip(v_i - θ, 0, 1) for an appropriate threshold θ; s(θ) = ∑ z_i(θ) is monotone decreasing.
3. Initialize lo = min(v)-2, hi = max(v)+2.
4. Run 80 bisection steps on s(mid) > tau or not to find θ. Use the final θ for initial z.
5. Let residual = tau - ∑ z.
6. For absolute residual above 1e-12, repeatedly repair:
   If residual > 0, mask = z < 1. Let capacity slack choose a step delta = residual/sum_i(1 - z_i)_pos, update only variables with positive capacity, track realized sum, recompute residual; at most 40 hand bridges. Then slack/shrink.
   If residual < 0, same with mask z > 0.
   Stop at residual ≤ 1e-12.
7. Clip again. If residual remains > 1e-8, mark invalid and fall back on the original feasible best.

This mechanism enforces both objective constraints. A simple clip followed by sum division would not be adequate.

2.4 Lag values and their exact gradients

Let T(h) be length L = 2n-1. For a weights vector w in R^L, define weighted_grad(h,w):∇(∑_r w_r T_r)(h). Scaling by dx is included.

Exact vectorized gradient of a weighted sum, using numpy slice additions:
- Create grad array shape (n) full of float.
- Loop over r=0,...,L-1. But total O(n^2), acceptable (n≤~240).
- weight wr = w_r * dx.
- lag ℓ = r - (n-1); if ℓ≥0 with len m=n-ℓ:
   grad_lag_front = wr * (1 - h[0:m]) to grad[ℓ:n];
   grad_lag_back = wr * (-h[ℓ:n]) to grad[0:m];
- otherwise s=-ℓ; len m=n-s:
   grad_lag_front = wr * (1 - h[s:s+m]) to grad[0:m];
