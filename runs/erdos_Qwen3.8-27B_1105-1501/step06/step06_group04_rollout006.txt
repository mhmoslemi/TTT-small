  S0[n-1+j-i] + t·T[n-1+j-i] + t²·Q[n-1+j-i],
  S0[n-1+i-j] + t·T[n-1+i-j] + t²·Q[n-1+i-j]
)

The "max of linear functions" part can be computed at any t in O(n) (just take the max over all k of S0[k] + t·T[k]).

So evaluating f(t) is O(n). A golden section search with 30 iterations would be O(30n) per pair, which is 30*122 = 3660 operations per pair. With 7381 pairs, that's 27M operations per full pass. At ~100M ops/sec, that's 0.27 seconds per pass. We can do ~4000 passes.

But we can be smarter: we don't need to do a full golden section for every pair. Most pairs won't improve the objective. We can:
1. First, quickly check if t=0 is already optimal (i.e., the derivative at t=0 is pointing in the wrong direction for all nearby t). If not, do a quick line search.
2. Use a coarse grid first (10 points), then refine only if the best grid point is better than current.

Let me also think about which pairs to try first. The most promising pairs are:
- Pairs (i, j) where h[i] is high and h[j] is low (transfer mass from high to low)
- Pairs where moving mass from i to j reduces the active constraints

For the active constraint approach:
- The active constraints are the lags r where corr[h,1-h][r] is near the max
- For an active lag r with d = r-(n-1) > 0, the constraint is:

- To reduce this, we want to either decrease h[i] where (1-h[i+d]) is large, or increase h[i+d] where h[i] is large
- This suggests specific pairs to try

    Returns (best_t, best_val) where best_val is the C5 at h+t*d."""

    # T[r] = (1-h)[i+r-n+1] - (1-h)[j+r-n+1] - h[i-r+n-1] + h[j-r+n-1]
    # (where indices are valid)

    one_minus_h = 1.0 - h

    for r in range(2*n-1):

        val_dc = 0.0

        b = j + s

        val_hd = 0.0
        c = i - s

        d_ = j - s
        if 0 <= d_ < n:
            val_hd -= h[d_]  # d[j]=-1

        Q[n-1 + (i-j)] = 1.0

    # h[j]-t >= 0, h[j]-t <= 1 => t <= h[j], t >= h[j]-1

    # Golden section
    g = (np.sqrt(5.0) - 1.0) / 2.0

    c2 = a + g*(b-a)

            f1 = float(np.max(S0 + c1*T + c1*c1*Q)) * dx
        else:
            a, c1, f1 = c1, c2, f2
            c2 = a + g*(b-a)
            f2 = float(np.max(S0 + c2*T + c2*c2*Q)) * dx
    opt_t = (a+b)/2.0
    opt_val = float(np.max(S0 + opt_t*T + opt_t*opt_t*Q)) * dx
    return opt_t, opt_val

Actually, let me reconsider the approach. The key insight is:

For the pair (i, j) with d[i]=1, d[j]=-1:
- The line objective f(t) = max_k [S0[k] + t*T[k] + t²*Q[k]] * dx
- Q is extremely sparse (only 3 non-zero entries)
- So f(t) ≈ max_k [S0[k] + t*T[k]] for most k, with 3 exceptions

The "max of linear functions" part has a well-known structure: it's a piecewise-linear convex function of t, and its minimum is at a "kink" point (where two lines cross) or at a boundary.

To find the minimum of max_k [S0[k] + t*T[k]]:
- This is equivalent to: minimize α subject to S0[k] + t*T[k] ≤ α for all k
- For T[k] > 0: t ≤ (α - S0[k]) / T[k]
- For T[k] < 0: t ≥ (α - S0[k]) / T[k]  (note: dividing by negative flips)
- For T[k] = 0: need α ≥ S0[k]

The optimal (t*, α*) satisfies:
- α* = max_k [S0[k] + t*·T[k]]
- t* is where the "upper envelope" of lines {S0[k] + t·T[k]} is minimized

A practical approach: 
1. Find t+ = argmin over t≥0 of max_k [S0[k] + t*T[k]]
   This is the smallest t≥0 such that for all k with T[k]>0: S0[k]+t*T[k] ≤ max_{k':T[k']≤0} [S0[k']+t*T[k']]
   
2. Similarly for t- ≤ 0.

But this is still O(n) per evaluation and we need to find the minimum...

1. For each pair, evaluate f(t) at t = 0, t = ±0.01, t = ±0.02, t = ±0.05
2. If any of these beats the current best, do a golden section search between the two best grid points
3. This way, most pairs are quickly rejected (6 evaluations * O(n) = 6*243 = 1458 ops per pair)
