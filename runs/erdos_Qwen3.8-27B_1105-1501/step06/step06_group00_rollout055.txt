- h[j] changes by dj (new - old)

The change in c[lag] for the correlation of h with (1-h):

Let me think more carefully. c[lag] = sum_n h[n] * (1-h[n+lag]) (using our convention where lag ≥ 0 means we shift h to the right).

OK this is getting too complicated for a clean formula. Let me just use the approach of recomputing the affected correlations directly.

For a swap at positions i and j (binary case: h[i] was 1, h[j] was 0, after swap h[i]=0, h[j]=1):

The affected correlations are those where either i or j appears in the product h[r]*(1-h[r+k]).

For lag k ≥ 0: corr[k] = sum_{r=0}^{n-1-k} h[r]*(1-h[r+k])
Position i appears as r (first factor) if 0 ≤ i ≤ n-1-k, or as r+k (second factor) if 0 ≤ i-k ≤ n-1-k (i.e., k ≤ i ≤ n-1).
Position j appears similarly.

So for each lag k, the delta is at most 4 terms. Computing the delta for all lags is O(n) total (since for each position, it affects O(n) lags, and we have 2 positions).

OK this is getting too complex for a clean derivation in my head. Let me just use a practical approach:

**Key realization**: For the optimization, I don't need to compute the exact delta formula. I can just:
1. Maintain the current h and its full correlation vector.
2. For a proposed swap (i, j), create a copy h_new = h.copy(); h_new[i], h_new[j] = h_new[j], h_new[i].
3. Compute the new full correlation: O(n²) using np.correlate.
4. Compare max.

The cost is O(n²) per swap evaluation. For n=180, that's about 32400 operations, which is fast (~0.1ms in numpy). The bottleneck is the number of swaps to evaluate.

But if I evaluate, say, 10,000 swaps per iteration, that's 10,000 * 0.1ms = 1 second. In 1100 seconds, I can do about 1100 iterations. That might be enough.

But I can do better: for a swap, I only need to recompute the correlations that are affected. As I analyzed above, only O(n) correlations are affected (those where i or j appears in the product). So I can update the correlation vector in O(n) time per swap.

Let me implement this properly:

```python
def _swap_corr_update(h, i, j, corr, n):
    """Update correlation vector after swapping h[i] and h[j].
    Returns new correlation vector (copy).
    corr is the current full correlation (numpy 'full' mode, length 2n-1).
    """
    # numpy correlate full mode: corr[m] = sum_n a[n] * b[n+m-(n-1)]
    # Actually: np.correlate(a, v, 'full')[n] = sum_m a[m] * v[m-n + (len(v)-1)]
    # Let me just use the definition: corr_full[k] corresponds to shift (k - n + 1)
    # corr_full[k] = sum over valid r: h[r] * (1-h[r + k - (n-1)])
    
    new_corr = corr.copy()
    di = h[j] - h[i]  # change at position i
    dj = h[i] - h[j]  # change at position j (= -di)
    
    # For each output index k (0 to 2n-2), the lag is L = k - (n-1)
    # corr[k] = sum_r h[r] * (1-h[r+L]) where max(0,-L) <= r <= min(n-1, n-1-L)
    
    # Position i affects corr[k] if:
    #   (a) i is in [max(0,-L), min(n-1, n-1-L)] as first factor
    #   (b) i-L is in [max(0,-L), min(n-1, n-1-L)] as second factor (r = i-L, so r+L = i)
    
    # Let's iterate over the affected k values:
    # For (a): L = k-(n-1), need max(0,-L) <= i <= min(n-1, n-1-L)
    #   i >= max(0, -(k-n+1)) and i <= min(n-1, n-1-(k-n+1)) = min(n-1, 2n-2-k)
    #   For i >= 0: -(k-n+1) <= i means k >= n-1-i
    #   For i <= n-1: always true (since i < n)
    #   For i <= 2n-2-k: k <= 2n-2-i
    #   So: n-1-i <= k <= 2n-2-i for the first factor contribution
    #   But also need the second factor to be valid: r+L = i+L = i+k-(n-1) must be in [0, n-1]
    #   0 <= i+k-(n-1) <= n-1, i.e., n-1-i <= k <= 2n-2-i
    #   So the range is k from n-1-i to 2n-2-i (inclusive). That's n values.
    #   Wait, but we also need r=i to be in the valid range: max(0,-L) <= i <= min(n-1, n-1-L)
    #   -L <= i means -(k-n+1) <= i, i.e., k >= n-1-i (same as above)
    #   i <= n-1-L = n-1-(k-n+1) = 2n-2-k, i.e., k <= 2n-2-i (same)
    #   AND 0 <= i (always true) and i <= n-1 (always true)
    #   So yes, k ranges from n-1-i to 2n-2-i.
    
    # For (b): r = i-L = i-(k-n+1) = n-1+i-k must be in [max(0,-L), min(n-1, n-1-L)]
    #   Also need 0 <= r <= n-1: 0 <= n-1+i-k <= n-1
    #   n-1+i-k >= 0 means k <= n-1+i
    #   n-1+i-k <= n-1 means k >= i
    #   And r+L = i must be in [0, n-1]: always true.
    #   And max(0,-L) <= r: same as above (covered by r >= 0)
    #   And r <= min(n-1, n-1-L): r <= n-1 covered; r <= n-1-L means n-1+i-k <= n-1-(k-n+1) = 2n-2-k
    #   n-1+i-k <= 2n-2-k means n-1+i <= 2n-2, i.e., i <= n-1 (always true)
    #   So k ranges from i to n-1+i.
    
    # Combining (a) and (b) for position i: k ranges from min(n-1-i, i) to max(2n-2-i, n-1+i)
    # = min(i, n-1-i) to max(i, n-1-i) + (n-1)
    # Actually the union is k from min(i, n-1-i) to max(2n-2-i, n-1+i)
    # Hmm, let me just handle it differently.
    
    # For each k where position i or j is involved, compute the delta.
    # The affected k values for position i are in [n-1-i, 2n-2-i] ∪ [i, n-1+i]
    # = [min(n-1-i, i), max(2n-2-i, n-1+i)]
    # For i=0: [n-1, 2n-2] ∪ [0, n-1] = [0, 2n-2] (all!)
    # For i=n/2: [n-1-n/2, 2n-2-n/2] ∪ [n/2, n-1+n/2] = [n/2-1, n+2-n/2] roughly
    
    # This is O(n) range for each position, so O(n) total affected k values.
    # For each affected k, the delta computation is O(1) (at most 4 terms).
    
    # Let me just iterate over all k and check if affected:
    # Actually for efficiency, let me compute the delta directly for each k in the affected range.
    
    # For position i (change di = h[j]-h[i]):
    # As first factor (r=i): valid for k in [n-1-i, 2n-2-i]
    #   delta = di * (1 - h[i + k - (n-1)])
    #   But if i + k - (n-1) = j, then h at that position also changed!
    #   h_new[i+k-(n-1)] = h[i+k-(n-1)] + (dj if i+k-(n-1)==j else 0)
    #   So delta = di * (1 - h_new[i+k-(n-1)]) - di * (1 - h_old[i+k-(n-1)])... 
    #   Wait, the delta in corr[k] from position i being first factor:
    #   old term: h_old[i] * (1 - h_old[i+k-(n-1)])
    #   new term: h_new[i] * (1 - h_new[i+k-(n-1)])

    #   If p == j: 
    #     old: h_old[i]*(1-h_old[j]) = h_old[i]*1 (since h_old[j]=0)
    #     new: h_new[i]*(1-h_new[j]) = h_new[i]*0 = 0
    #     delta = -h_old[i]
    #   If p != i and p != j:
    #     old: h_old[i]*(1-h[p])
    #     new: h_new[i]*(1-h[p])
    #     delta = (h_new[i]-h_old[i])*(1-h[p]) = di*(1-h[p])
    
    # This is getting very case-by-case. Let me just use the brute force approach for correctness:
    # For each affected k, compute old and new contribution of terms involving i or j.
    
    # Actually, the simplest correct approach that's still O(n) per swap:
    # Just recompute the correlations that are affected.
    
    # Let me identify the affected k values and recompute those correlations directly.
    
    affected = set()
    # Position i affects k where i or i+L is in the valid range
    # Simplify: just mark all k from 0 to 2n-2 that could be affected
    # For position i: k where max(0,-L) <= i <= min(n-1, n-1-L) OR max(0,-L) <= i+L <= min(n-1, n-1-L)
    # L = k-(n-1)
    # This is equivalent to: the term h[i]*(1-h[i+L]) or h[i-L]*(1-h[i]) is in the sum
    # First: 0<=i<=n-1 and 0<=i+L<=n-1, i.e., -i<=L<=n-1-i, i.e., k from n-1-i to 2n-2-i
    # Second: 0<=i-L<=n-1 and 0<=i<=n-1, i.e., 0<=L<=i (wait, i-L>=0 means L<=i, and i-L<=n-1 means L>=i-(n-1))
    #   So L from i-(n-1) to i, i.e., k from i to n-1+i
    
    k_lo_i = min(n-1-i, i)
    k_hi_i = max(2*n-2-i, n-1+i)
    k_lo_j = min(n-1-j, j)
    k_hi_j = max(2*n-2-j, n-1+j)
    
    k_start = max(0, min(k_lo_i, k_lo_j))
    k_end = min(2*n-2, max(k_hi_i, k_hi_j))
    
    # For each k in [k_start, k_end], recompute corr[k] directly
    # But that's O(n) per k, giving O(n²) total. Not ideal.
    
    # Better: compute the delta analytically for each k.
    # Let me just do it with the direct formula, handling edge cases.
    
    new_h = h.copy()
    new_h[i], new_h[j] = new_h[j], new_h[i]
    
    for k in range(k_start, k_end + 1):
        L = k - (n - 1)
        # corr[k] = sum_r h[r] * (1-h[r+L]) for max(0,-L) <= r <= min(n-1, n-1-L)
        r_lo = max(0, -L)
        r_hi = min(n-1, n-1-L)
        # Only terms where r == i or r+L == i or r == j or r+L == j changed
        old_val = 0.0
        new_val = 0.0
        for r in [i, j, i-L, j-L]:
            if r_lo <= r <= r_hi:
                old_val += h[r] * (1 - h[r+L])
                new_val += new_h[r] * (1 - new_h[r+L])
        # But we might double-count if i == j or i-L == j-L etc.
        # For distinct i, j, the four values i, j, i-L, j-L could have overlaps
        # Let's use a set to avoid double-counting
        rs = set()
        for r in [i, j, i-L, j-L]:
            if r_lo <= r <= r_hi:
                rs.add(r)
        old_val = sum(h[r] * (1 - h[r+L]) for r in rs)
        new_val = sum(new_h[r] * (1 - new_h[r+L]) for r in rs)
        new_corr[k] = corr[k] + (new_val - old_val)
    
    return new_corr
```

This is O(n) per swap (the loop over k is O(n), and for each k we do O(1) work). Good.

But wait, there's a subtlety: the "affected" range [k_start, k_end] might be all of [0, 2n-2] for some positions (like i=0 or i=n-1). In that case, we're doing O(n) work per swap, which is fine.

Actually, I realize there's an even simpler approach: since n is at most ~256, and np.correlate is very fast in numpy (it's essentially a convolution computed with FFT or direct method), I can just recompute the full correlation for each candidate swap. For n=180, np.correlate takes about 5-10 microseconds. So evaluating 100,000 swaps takes about 0.5-1 second. That's fast enough!

Let me design the algorithm around this:

**Algorithm: Exhaustive pair swap optimization with simulated annealing**

1. Start with a binary solution (n/2 ones, n/2 zeros)
2. At each iteration:
   a. Identify the "active" lags (those at or near the maximum)
   b. Generate candidate swaps: for each active lag, find pairs (i,j) that would most reduce it
   c. Evaluate all candidates using fast correlation recomputation
   d. Accept the best (or accept worse with probability per SA)
3. Repeat with different n values and restarts

Actually, for step (b), the most impactful swaps are those where:
- i is a position where h[i]=1 and is "surrounded by" zeros at the active lags
- j is a position where h[j]=0 and is "surrounded by" ones at the active lags

But computing this exactly requires knowing the structure. A simpler approach: just try all pairs (i,j) with h[i]=1, h[j]=0. There are (n/2)² = 8100 such pairs for n=180. Evaluating all of them takes 8100 * 10μs ≈ 80ms per iteration. In 1100 seconds, that's about 13,000 iterations. That should be more than enough to converge.

But actually, I don't need to try ALL pairs every iteration. I can be smarter:

**Steepest descent approach**: 
- Compute the current correlation vector
- Find the max lag(s)
- For each position i with h[i]=1, compute how much removing it (and adding j) would reduce the max correlation
- Pick the best (i,j) pair

This is still O(n²) per iteration but with a better constant.

Let me implement a clean version:

```python
def _steepest_swap(h, corr, n, max_swaps_to_try):

    Returns (best_i, best_j, best_c5, improved).
    """
    cur_c5 = float(np.max(corr))
    ones = np.where(h > 0.5)[0]
    zeros = np.where(h <= 0.5)[0]
    best_c5 = cur_c5
    best_i, best_j = -1, -1
    
    for i in ones:
        for j in zeros:
            # Try swap
            h[i], h[j] = h[j], h
