1. Approach and rationale

1.1 Central idea
Use the supplied parent construction only as one initial feasible point, then search the feasible set with an explicit epigraph local optimizer plus several diversified starts at the parent resolution and at nearby resolutions. The main improvement over the previous method is to stop relying only on a linearized/max-control local model. Instead, directly impose the actual finite-support overlap inequalities:

    maximize-over-all-output-lags <= t,
    sum(h) = n/2,
    0 <= h_i <= 1.

This gives the local nonlinear solver exact first-order curvature information for the objective rather than only a first-order linear surrogate. Because the problem is nonconvex, the solver is a local method and cannot be claimed global. Every accepted candidate is therefore reevaluated using the authoritative discrete evaluator, not by trusting the epigraph variable or the constraint residuals.

1.2 Why this can improve the parent
The previous method is strong but mixes:
- a linearized local LP direction,
- a quadratic line search that is actually exact for a fixed direction,
- heuristic perturbations and resamplings.

The bottleneck is that the local direction is generated from a linearization, so near a true solution it can become nearly stationary due to linearization error and curvature cancellation. A direct epigraph nonlinear nonlinear optimization can use the reciprocal accuracy of the constraints and objective and can reveal finer accretion improvements by moving positive positions slightly differently than linearized step prescriptions allow.

1.3 Auxiliary mechanisms
Two auxiliary methods are included only after the epigraph phase:
- a multiplier/smooth-weight gradient-driven exact line neighborhood search using two-, three-, and four-coordinate moves;
- a resolution-transfer/local-bootstrap mechanism which can deliver better discrete scores at nearby sample lengths.

These are supplementing, not replacing, the epigraph search. Because every proposal is evaluated exactly, they cannot damage the returned upper bound.

1.4 Limitations and honest status
The principal optimizer has nonconvex inequality constraints and a bilinear objective hidden in the epigraph. Therefore:
- It should be treated as a local search, not a proof of global optimality.
- If it returns a raw vector that nearly satisfies constraints but whose projected/repaired exact score is better, it can still be accepted.
- Every proposal must pass the exact evaluator before it is stored as a candidate.

The plan does not use CVXPY for the nonconvex max-of-bilinear terms, because that would not be a supported convex formulation.

2. Mathematical specification

2.1 Variables and constraints
For a chosen length `n` (integer), define `dx = 2.0 / n`. The return vector is

    h = (h_0, ..., h_{n-1}) in [0,1]^n

with

    sum_i h_i = n / 2.

The reason for n/2 is the discretized integral constraint:

    integral_0^2 h(x) dx = 1
    approximated by dx * sum_i h_i = 1.

The exact objective required by the evaluator is

    C_5(h) = max_{q in 0,...,2n-2} dx * corr_o_q,
    corr_o = np.correlate(h, 1-h, mode="full").

This is a one-sided, finite-support linear overlap functional, not circular convolution and not a simplification using full-interval integrals. Boundary terms are naturally handled because the sum for output lag `d`, with |d| = k, contains exactly n-k terms.

2.2 Explicit overlap values and gradient formulas
The edge and complex numerical formulas must align with `np.correlate` or else the solver could optimize a different functional. The representation that matches the usual numpy correlation output order is:

For q = 0,...,2n-2, define integer lag

    k = q - (n - 1),    k in {-(n-1), ..., n-1}.

For each q the overlap value is

    S_q(h) = dx * sum_{valid x} h[a(x)] * (1 - h[b(x)]),

where the valid x and indices are:

    If k >= 0:
        x = 0,...,n-k-1
        a = x + k
        b = x
    If k < 0:
        d = -k
        x = 0,...,n-d-1
        a = x
        b = x + d

This generates the correct boundary truncation: for |k| = d there are n-d terms. The full objective is exactly max_q S_q.

For use in epigraph constraints and gradient-driven local moves, define derived pair derivatives. For a single q, the gradient row r of S_q with respect to h consists of only two nonzero families, but when all pair terms are accumulated:

Differentiating `h_a * (1 - h_b) * dx`:

    dS/dh_a = dx * (1 - h_b)
    dS/dh_b = -dx * h_a

If a coordinate appears in multiple overlap terms, the gradients are summed. Hence, after accumulating S over all pairs for fixed q,

    r_i = sum_{pairs(j,j+k)}/valid h_i = dx * (1 - h_b - sum of h_a where i is a negative side)

with exact accumulation for each q. More compactly:

    initialize r = zeros(n)
    for S pairs over h,1-h:
        do r[a] += dx * (1 - h[b])
        and r[b] -= dx * h[a].

This direct formula is simple enough for any n in the planned range (about 60 to 200) and avoids relying on a potentially nonzero constant baseline trick, which is tempting but dangerous because one should optimize the original objective with its integral term.

One should be careful not to combine all lags into the scalar `dx*sum(h_i*(1-h_i)) + ...` without retaining each individual lag. Some multi-lag transformations only produce a lower bound when restrictions hold, and they do not replace boundary-laged terms. A direct constraint for each q avoids substituting an incorrect surrogate.

2.3 Epigraph nonlinear program
Let the optimizer vector be `y = [h_0,...,h_{n-1}, t]`, dimension `n+1`:

    minimize    t

subject to       sum_i y_i = n/2
                   y_i ∈ [0,1] for i = 0..n-1
                   t - S_q(y[:n]) >= 0, q = 0..2n-2.

The objective gradient is:

    d/dy = [0,...,0,1]

For each inequality constraint `c_q(y)= t - S_q(y[:n])`, its Jacobian row is:

    d(c_q)/dy = [-grad_h S_q, 1].

In scipy SCP and objective constraints convention for moderate or smaller steps, gradients are treated consistently. Upper/lower bounds on t for feasibility domains may be restricted using:

    0 <= t <= min(1.000001, initial_exact_value + small margin).
