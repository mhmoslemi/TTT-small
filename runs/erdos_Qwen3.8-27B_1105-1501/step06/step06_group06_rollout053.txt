The key insight for the line search: since c_k(h) is a quadratic function of h (bilinear in the components), c_k(h + α·d) is a quadratic in α. So f(α) = max_k c_k(h + α·d) is the max of quadratics, which is piecewise smooth.

For a small trust region, the linear approximation is good, and f(α) is approximately piecewise linear. The golden section search should work well.

But I realize there's a simpler and more efficient approach: precompute the quadratic coefficients.

c_k(h + α·d) = c_k(h) + α·A_k + α²·B_k

where:
A_k = sum of d[i]*(1-h[i+k]) + h[i]*(-d[i+k]) over valid i
    = sum of d[i]*(1-h[i+k]) - h[i]*d[i+k]

B_k = -sum of d[i]*d[i+k] over valid i

Then f(α) = max_k [c_k(h) + α·A_k + α²·B_k]

I can evaluate this for any α in O(n²) time (to compute the max over k). But I can also precompute A and B once (in O(n²)) and then evaluate f(α) in O(n) time for each α.

This makes the line search much faster!

    """Line search using precomputed quadratic model."""
    n = len(h)
    dx = 2.0 / n
    
    # Ensure sum(d) = 0
    d = d - d.mean()
    
    # Compute feasible range
    pos = d > 1e-14
    neg = d < -1e-14
    t_lo = -radius
    t_hi = radius
    if np.any(pos):
        t_hi = min(t_hi, float(np.min((1.0 - h[pos]) / d[pos])))
        t_lo = max(t_lo, float(np.max(-h[pos] / d[pos])))
    if np.any(neg):
        t_hi = min(t_hi, float(np.min(h[neg] / (-d[neg]))))
        t_lo = max(t_lo, float(np.max((1.0 - h[neg]) / d[neg])))
    
    if t_hi - t_lo < 1e-14:
        return 0.0, _exact_c5(h)

    # Actually: A_k = sum_i d[i]*(1-h[i+k]) - sum_i h[i]*d[i+k]
    # The first sum is correlate(d, 1-h) at the appropriate offset
    # The second sum is correlate(h, d) at the appropriate offset

    fm = f_alpha(mid)
    if fm < best_v:
        best_a, best_v = mid, fm
