Wait, the coordinate descent as written doesn't maintain the sum constraint properly. When I change h[i] from old to new, the sum changes by (new - old). I need to either:
1. Only allow moves that preserve the sum (pair moves)
2. Allow the sum to drift and project at the end of each sweep

Option 1 is more principled. Let me use pair moves: change h[i] by +δ and h[j] by -δ.

Actually, for the coordinate descent, the simplest approach is:
- For each pair (i, j), try moving mass from i to j: h[i] -= δ, h[j] += δ
- The sum is preserved
- Try several values of δ

But this is O(n²) pairs per sweep, which is the same as the binary search. And each evaluation is O(n). So it's O(n³) per sweep, which for n=122 is about 1.8M operations. That's fine.

But actually, I think a simpler approach works: just do the coordinate descent with projection at the end. The projection is fast (O(n) with the water-filling). So:
1. For each coordinate i, try setting it to various values
2. After all coordinates are updated, project to feasibility
3. Repeat

This might not be optimal but should work in practice.

Alternatively, I can use the "balanced move" approach:
- Pick two coordinates i, j
- Move mass from the one with higher value to the one with lower value
- Try several amounts

Let me simplify and just use the approach from the previous program (LP-based) but with a different twist. Actually, let me try a different approach entirely:

**Approach: Direct subgradient with projection**

The objective f(h) = max_k corr_k(h) * dx is convex in h (it's the max of linear functions). Wait, is it? corr_k(h) = sum_a h[a]*(1-h[a+s]) is bilinear in h, not linear. So f(h) is NOT convex. It's a max of bilinear functions, which is non-convex.

So gradient methods don't apply directly. The non-convexity is the fundamental challenge.

Given this, I think the best approach is:
1. Binary local search (exploiting the discrete structure)
2. Simulated annealing (to escape local minima)
3. Non-binary refinement (to squeeze out the last bit)

Let me finalize my code. I'll make the binary search efficient with the O(n) swap evaluation, and use simulated annealing for exploration.

For the non-binary refinement, I'll use a different approach: instead of coordinate descent, I'll use the "line search along random directions" approach:
- Generate a random zero-sum direction d
- Do a line search along h + t*d
- Accept if it improves
