import numpy as np
import time

def score_exact(h):
    n = len(h)
    dx = 2.0 / n
    r = np.correlate(h, 1.0 - h, mode="full")
    return float(np.max(r) * dx)

def repair_feasible(h, target_sum):
    """Repair h to satisfy 0<=h<=1 and sum(h)=target_sum"""
    h = np.array(h, dtype=float).copy()
    h[~np.isfinite(h)] = 0.5
    h = np.clip(h, 0.0, 1.0)
    diff = target_sum - np.sum(h)
    if abs(diff) < 1e-12:
        return h
    # Deterministic repair
    n = len(h)
    max_iter = 2 * n
    for _ in range(max_iter):
        diff = target_sum - np.sum(h)
        if abs(diff) < 1e-12:
            break
        if diff > 0:
            # Need to add mass - add to positions with most room (largest 1-h)
            order = np.argsort(1.0 - h)[::-1]
            for i in order:
                room = 1.0 - h[i]
                add = min(room, diff)
                h[i] += add
                diff -= add
                if abs(diff) < 1e-14:
                    break
        else:
            # Need to remove mass - remove from positions with most mass
            order = np.argsort(h)[::-1]
            for i in order:
                rem = h[i]
                take = min(rem, -diff)
                h[i] -= take
                diff += take
                if abs(diff) < 1e-14:
                    break
    return h

def resample_to(h, n_new):
    """Resample h from its current length to n_new using midpoint interpolation"""
    n_old = len(h)
    x_old = np.linspace(0, 2, n_old, endpoint=False) + 1.0/n_old
    x_new = np.linspace(0, 2, n_new, endpoint=False) + 1.0/n_new
    y = np.interp(x_new, x_old, h, left=h[0], right=h[-1])
    return y

Actually, let me reconsider the approach. The key insight is:

The objective C(h) = max_k [sum_i h[i] * (1-h[i-k])] * dx (for valid i)

For a random-looking h with h_i ∈ [0,1] and mean 0.5, each term h[i]*(1-h[i-k]) has expected value 0.25. The sum over ~n terms gives ~n/4, and multiplied by dx=2/n gives ~0.5. This matches the constant function analysis.

To get below 0.5, we need the correlation to be negative on average for each lag, meaning h[i] and h[i-k] should be anti-correlated (when one is high, the other is low). This is like a checkerboard pattern in 1D, which is just alternating 0 and 1.

But we can't have perfect anti-correlation at ALL lags simultaneously! At lag 0, h[i]*(1-h[i]) is always ≥ 0 (it's 0 only when h[i] ∈ {0,1}). So the lag-0 contribution is always non-negative.

The minimum possible lag-0 value is 0 (achieved when all h_i ∈ {0,1}), giving C ≥ 0 from lag 0. But other lags will be positive.

For a binary sequence (h_i ∈ {0,1}), correlate(h, 1-h) at lag k is:
- Number of positions where h[i]=1 and h[i+k]=0 (or the appropriate shifted version)

For a "balanced" binary sequence (half 1s, half 0s), the best we can do is to make the autocorrelation as close to -1/2 as possible (i.e., as anti-correlated as possible). But at lag 0, it's 0 (since h[i]*(1-h[i]) = 0 for binary).

So for binary sequences, C = max_k [count of "10" pairs at lag k] * dx.

The minimum possible value of max_k [count of "10" pairs at lag k] for a binary sequence of length n with n/2 ones is determined by the "crossover count" which relates to the autocorrelation.

This is a well-studied problem! It's related to the "Golay ruler" or "Sidon set" type problems.
