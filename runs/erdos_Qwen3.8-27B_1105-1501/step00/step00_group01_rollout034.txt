So if I precompute A_k for coordinate j, I can quickly evaluate the new c for any new value of h[j].

Better yet, I can precompute A_k and B_k = c[k] - A_k * h[j] once, and then for any new x, c_new[k] = A_k * x + B_k.

The cost of computing A_k for all k is O(n) (just looking at h[j+m] and h[j-m] for each m).

So the full coordinate descent step is:
1. Compute c = correlate(h, 1-h) [O(n^2) or O(n) with FFT]
2. For each j:
   a. Compute A_k for all k [O(n)]
   b. Compute B_k = c[k] - A_k * h[j] [O(n)]
   c. Find x* minimizing max_k (A_k x + B_k) [O(n * log(1/eps))]
   d. Update h[j] = x* and update c [O(n)]
3. Fix the sum [O(n)]

Total per sweep: O(n^2 + n^2 * log(1/eps)) ≈ O(n^2) for the initial compute + O(n^2) for the coordinate updates.

For n=63, this is very fast.

Actually, let me use a smarter approach. Since f(x) is piecewise linear and convex, the minimum is at a "kink" point or at the boundary. The kink points are where two lines cross: A_i * x + B_i = A_j * x + B_j, i.e., x = (B_j - B_i) / (A_i - A_j).

But there are O(n^2) such points. For n=63, that's ~7800 points, which is manageable but might be slow in Python.

Let me use a hybrid: coarse grid search + local refinement.

Or even simpler: since the function is convex and piecewise linear, I can use the following:
1. Evaluate at x=0 and x=1
2. Find the k that achieves the max at x=0 (call it k0)
3. If A_k0 >= 0, the minimum is at x=0
4. Otherwise, follow the line k0: f(x) = A_k0 * x + B_k0 until another line takes over
5. At the crossing point, check the new active k
6. Repeat

This is the "walking" algorithm for piecewise linear convex functions. It's O(n) in the worst case (each step moves to a new active k, and there are at most n distinct active k's).

def find_min_x_walk(A, B):
    n = len(A)
    # Evaluate at x=0
    vals_0 = B  # A*0 + B
    k0 = np.argmax(vals_0)
    
    if A[k0] >= 0:
        return 0.0
    
    # Follow line k0 to the right
    x = 0.0
    f_x = B[k0]
    k_active = k0
    
    for _ in range(n):  # At most n steps
        # Find where line k_active crosses another line
        # A_k_active * x + B_k_active = A_k * x + B_k
        # x = (B_k - B_k_active) / (A_k_active - A_k)
        denom = A[k_active] - A
        # We want x > current_x and denom > 0 (since we're moving right and A[k_active] < 0)
        # Actually: A[k_active] * x + B[k_active] = A[k] * x + B[k]
        # (A[k_active] - A[k]) * x = B[k] - B[k_active]
        # x = (B[k] - B[k_active]) / (A[k_active] - A[k])
        
        # Find the smallest x > 0 where another line becomes active
        # We need A[k] > A[k_active] (so that the other line has steeper slope)
        # and x_cross > 0
        valid = (A > A[k_active] + 1e-15) & (denom > 1e-15)
        if not np.any(valid):
            # Line k_active is the top everywhere to the right
            return 1.0
        
        x_cross = (B[valid] - B[k_active]) / (A[k_active] - A[valid])
        # We want the smallest positive x_cross
        x_cross = x_cross[x_cross > 1e-15]
        if len(x_cross) == 0:
            return 1.0
        
        x_next = x_cross.min()
        x_next = min(x_next, 1.0)
        
        # Evaluate at x_next
        vals_next = A * x_next + B
        k_new = np.argmax(vals_next)
        
        if A[k_new] >= 0:
            # The minimum is at or before x_next
            # Actually, the minimum is where the active k's A crosses 0
            # At x_next, k_new is active with A >= 0
            # The minimum is at x_next (the kink point)
            return x_next
        
        k_active = k_new
    
    return 1.0

def _fix_sum(h, target):
    h = np.array(h, dtype=float, copy=True)
    deficit = target - h.sum()
    if abs(deficit) < 1e-13:
        return h

    if deficit > 0:
        room = 1.0 - h
    else:

C₅ = (3n/4) * 2/n = 3/2. That's way worse than 0.38!

So a pure sine wave is terrible. The issue is that it has strong correlation at all lags.

What we want is a sequence with LOW correlation at ALL lags simultaneously. This is the "low-autocorrelation sequence" problem, which is well-studied in signal processing.

Barker sequences have the property that their aperiodic autocorrelation is bounded by a small constant. But they're very short (max length 13 for ±1 sequences).

def _lfsr_sequence(n_bits, poly, seed_val=1):
    """Generate an m-sequence using a linear feedback shift register."""
    # poly is an integer where bit i represents x^i
    # Feedback is XOR of the bits specified by poly
    n = (1 << n_bits) - 1
    state = seed_val
    seq = []
    for _ in range(n):
        seq.append(state & 1)
        # Feedback
        fb = 0
        for i in range(n_bits):
            if (poly >> i) & 1:
                fb ^= (state >> i) & 1
        state = (state >> 1) | (fb << (n_bits - 1))
    return np.array(seq, dtype=float)
```

def _gen_mseq(m, taps, length=None):
    """Generate m-sequence. taps is the set of bit positions to XOR for feedback.
    State is m bits. Feedback = XOR of bits at positions in taps.
    Output = bit 0. Shift right, put feedback at bit m-1.
    """
    if length is None:
        length = (1 << m) - 1
    state = 1  # Non-zero initial state
    seq = []
    for _ in range(length):
        seq.append(state & 1)
        # Compute feedback
        fb = 0
        for t in taps:
            fb ^= (state >> t) & 1
        state = (state >> 1) | (fb << (m - 1))
    return np.array(seq, dtype=float)
```
