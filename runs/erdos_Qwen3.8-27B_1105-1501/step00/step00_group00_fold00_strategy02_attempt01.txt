1. Approach and rationale

The task is to minimize the nonsmooth, finite-support, nonconvex discrete overlap
objective

- `h_i in [0,1]`,
- `sum_i h_i = n/2`,
- `C5(h) = max over all lags of correlation(h, 1-h, lag) * (2/n)`.

The returned scalar must match the evaluator exactly. The method below does not
use a circular/periodic surrogate, does not replace the objective by a minimum
autocorrelation, and does not claim global optimality. It uses a deterministic
local/global-review pipeline that is built around the actual evaluator:

1. The exact objective is always evaluated with `np.correlate(h, 1-h, "full")`
   (or an equivalent directly checked manual implementation equivalent in max
   value). Internal candidate selection is based only on this objective.

2. A dimension is accepted only after a joint feasibility repair. Feasibility
   means exact `sum(h) ≈ n/2`, within a very strict numeric tolerance, and exact
   intervals; the returned representative is placed on a dyadic power-of-two
   grid by integer rounding, which makes the sum condition reproducible and
   removes clipping+rescaling inconsistencies.

3. The nonconvex problem is attacked by several distinctly different engines:
   - exact finite-support projected smoothing descent,
   - epigraph local nonlinear programming with an adjustable bound `t` and
     analytic constraints,
   - exact symmetric/mirror complement variableness, which sizes a natural
     smaller subspace and automatically enforces the mass with no final repair
     drift,
   - vertex-form transforms and exact energy multistarts to reduce the
     parent-parent lock-in that is common for local NLP only.

Most attempts at this problem fail because the local Euclidean unconstrained
gradient violates the exact mass or because the actual maximum is approximated
too coarsely. The design reduces these failure modes by using a feasible return
projection every time a proposal enters the best pool, and by adding a full
epigraph signature that admits all actual available lags, not a bath of
inactive constraints. The objective can be slightly deteriorated by numerical
final rounding, so a final `quantize -> verify -> local polish -> re-quantize`
loop is reserved at the end.

2. Mathematical specification

2.1 Discrete representation and exact evaluator

Let `h` be a 1D array with `n_points = n`. The official score is

`C5math(h) = dx * max_j np.correlate(h, 1-h, mode="full")(j)`

with `dx = 2.0/n`. Valid h check uses `0 <= h_i <= 1` and mass
`sum h_i = n/2`. For `n`, the correlation has `2n-1` components. Let unsigned
scaled `C_k` be the correlation at lag `k`, where `k` belongs to the finite
set `{-(n-1), -(n-2), ..., 0, ..., (n-2), (n-1)}`. The formula is deliberately
linear correlation exactly corresponding to finite support:

For lag `l`:

- For `l > 0`:
  `C_l = dx * dot(h[0:n-l], 1 - h[l:n])`.
- For `l = 0`:
  `C_0 = dx * dot(h, 1-h)`.
- For `l < 0`, with `p=-l`:
  `C_l = dx * dot(h[p:n], 1 - h[0:n-p])`.

This is not circular, and the partial support is correctly included:

- The length of the changed integral is `n - abs(l)` samples, times `dx`.
- The zero-lag derivative for a simple h is `dx*(1-2h_j)` as expected from
  `h(h-1)`.

The boundary-lag cases with `abs(l)=n-1` contain one term:
  - `l = n-1`: `C = dx * h[0] * (1 - h[n-1])`.
  - `l = -(n-1)`: `C = dx * h[n-1] * (1 - h[0])`.

An internal implementation should define its own correlation index using
`lag = index - (n-1)` or any fixed permutation of this set. It need not have
the same numerical order as `np.correlate`; it needs the same set of values.
A mandatory sanity check is that for multiple random small h arrays, the sorted
internal scaled vector and the sorted official `np.correlate` scaled vector are
close to 1e-12 relative. If the supplied coder's manual order is permuted but
produces same set, exact evaluation and max remain correct.

2.2 Full-variable gradient of each scaled correlation

For a scaled correlation `C_l(h)` in 2.1, the gradient in full h is:

For `l >= 0`:
  - For all `i in [0, n-l-1]`: add `(1 - h[i+l])` to component `i`.
  - For all `j in [l,n-1]`: add `-h[j-l]` to component `j`.
  - multiply the resulting full vector by `dx`.
For `l = 0`, this reduces to `dx*(1-2h)`.
For `l < 0`, with `p=-l`:
  - For all `i in [p,n-1]`: add `(1 - h[i-p])` to component `i`.
  - For all `j in [0,n-p-1]`: add `-h[j+p]` to component `j`.
  - multiply by `dx`.

These formulas are exact for scalar constraints and for the exact max smoothing
weighted sum over a vector of lag values.
