Key optimization: Instead of full projected gradient with line search, use **pair moves** which only change 2 coordinates. This is:
1. Faster to evaluate (only 1 evaluation per candidate)
2. Easier to maintain feasibility

For a pair move from b to a (h_a += α, h_b -= α), the change in the objective is:
ΔC = dx * (max_p (Y_p + ΔY_p) - max_p Y_p)

where ΔY_p = g_p[a]*α - g_p[b]*α + (quadratic term if a and b are coupled at lag p)

The quadratic term is at most ±α², which is small for small α.

So as a first approximation, ΔC ≈ dx * α * (G[a] - G[b]) where G is the composite gradient.
We want G[a] - G[b] < 0, i.e., G[b] > G[a], and we transfer from b to a.

This is O(n²) to find the best pair (or O(n log n) if we just take min and max of G).

But we need to verify with the actual evaluation. So the algorithm is:
1. Compute G (composite gradient)
2. Find (a, b) with G[b] - G[a] maximized (subject to feasibility)
3. Try α values: 0.1, 0.25, 0.5, 0.75, 1.0 times max feasible
4. Accept the best α that improves

This is O(n) for gradient computation + O(n) for finding best pair + O(5) evaluations = O(n) per iteration.
