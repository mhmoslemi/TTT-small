1. Approach and rationale

1.1 Central idea

The evaluator is completely discrete and deterministic for any returned vector h: with n columns, dx=2/n, the exact score is

    S(h) = max over all 2n-1 finite-support correlation entries of [np.correlate(h, 1-h, mode="full")*dx}_index.

The problem is therefore not directly convex. The proposed method is an exact-metric, candidate-based nonlinear local/global hybrid:

- Preserve the supplied parent construction as a validated source candidate whenever `initial_h_values` is available. Repair it jointly for bounds and mass, but immediately store the parent as a guaranteed feasible fallback.
- Search continuously in the original box constraint 0<=h_i<=1 and exact mass constraint sum(h)=n/2, because fractional components are useful for smoothing discrete wells and finding small improvements that binary decisions cannot represent.
- Optimize smooth surrogate objectives that approximate the exact max-over-correlations objective, but never return a candidate accepted by a surrogate alone. Every return candidate is re-scored with the authoritative evaluator formula and accepted only through that exact value.
- Reinforce the smooth local minimizer by an exact objective coordinate-pair search, randomized pair-transfer searches, and several restarts from the parent and perturbed parents. This is intended to address the primary nonconvex-bottleneck: local exact minima are often flat because only a few correlation entries are active. Smooth active-lag weighting changes the effective gradient weights and can escape nominally stationary points; exact pair transfers restore/protect the actual discrete objective.
- The plan does not claim global optimality. It provides a coherent, locally searched, validated fallback even if no candidate below the parent is found.

1.2 Why this can improve the parent or solve the task

The supplied best known construction length appears to be around 70 finite samples. The current parent is already feasible and on or very close to the historical optimum, so a fresh stochastic search over many resolutions is unnecessary and potentially slower. The main value can be obtained from:

- fine continuous perturbation of the parent, because record constructions often have fractional components whose ratios are not exactly discrete;
- a multi-scale soft-max objective, which balances multiple active correlation entries rather than moving along the direction determined by an arbitrary rule selected by the exact max at one iteration;
- exact pair moves that always obey sum and bounds because mass is shifted between coordinates instead of rescaled after clipping;
- keeping all old-score candidates and sorting them with the exact evaluator once per validation.

If `initial_h_values` is not supplied or fails validation, a compact seeded balanced-random and deterministic candidate bank plus the same local machinery provides a valid search; if that fails, the method returns a concretely feasible constant vector with a valid bound, though that bound will not be below the target.

1.3 Primary limitations

- The objective is nonconvex; smooth surrogate minima may be invalid or have a poor exact score. The proposal only asserts acceptance by exact rescoring, not optimality.
- Soft-max blowups can be numerically tricky; the implementation must use max-shifted exponentials and stable softplus.
- Due to nonconvexity, no solver’s success flag proves the exact global optimum. Success flags are only progress signals.
- Reducing resolution can make evaluation faster, but it changes the discrete problem and does not necessarily lower the actual discrete objective. Any resolution reduction is an optional, validated heuristic, not a monotone transformation of improvement.

2. Mathematical specification

2.1 Variables, dimensions, and feasible set

The construction always has one vector with n columns. If `initial_h_values` is valid, the main resolution uses the parent length n0. If none exists, choose n0=70, because the problem statement points at that size and n0 is small enough for fast finite-support correlation.

Definitions for any candidate vector y∈R^n:

    dx = 2.0/n
    target_sum = n/2.0
    q_i = 1 - y_i
    z_k = dx * sum_{p,m: k = p-m + (n-1)} y_p * q_m
    S(y) = max_k z_k

The discrete autotuple/evaluator checked is:

    np.correlate(y, 1-y, mode='full') * dx

and returned as the score. This must not be approximated by a circular correlation or by a formula of the type 1 - min autocorr unless separately proven. The correlation array has length 2n-1 and includes both lag directions. A pair of coordinates (p,m) contributes to lag/order array index

    k = p - m + (n-1).

This is the orientation used for all gradient derivations below.

The feasible set is:

    h_i ∈ [0,1] for i=0,...,n-1
    sum_i h_i = target_sum

2.2 Exact objective formulas and gradient context

For a candidate h and row vector labelled weights w indexed by 2n-1 correlation lags, one exact correlation-entry gradient structure is:

    g_i = dx * [ sum_m w_{p-m+n-1} q_m  - sum_p w_{p-m+n-1} h_p ]

with p in the first term replaced by i. Equivalently, construct the pair matrix

    W_pair[p,m] = weights[p-m+n-1]

then

    A = W_pair @ q
    B = W_pair.T @ h
    grad = dx * (A - B)

Derivation: each full-support correlation bin contains pairs y_p q_m. Derivative with respect to y_i when it appears as first factor is q_m, with the corresponding lag weight. Derivative with respect to y_i when it appears as the complement second factor q_i=1-y_i is -y_p, with the same bin weight. The pair index mapping above exactly follows `np.correlate`; the sum over bins matches `np.correlate`, not circular convolution.

The `IndexMatrix` can be built as an integer array

    IDX[p,m] = p - m + n-1

The helper then computes the pair matrix for a supplied `weights` vector as

    W_pair = take(weights, IDX).

The adjoint structure described above must be used in gradient helpers; for final objectively, use only the correlation evaluation.

2.3 Smooth surrogate soft-max objective

For h and parameter beta > 0, let c = exact `np.correlate(h, 1-h, full)*dx`, and

    u = beta * (c - max_c)
    w_c = exp(u) / sum(exp(u))
    logweight = log(sum(exp(u)))

The smooth surrogate score is

    phi_beta(h) = max_c + logweight/beta.

This objective is between max_c and max_c + log(2n-1)/beta. As beta increases it becomes closer to the exact objective. Its gradient is computed using g_i for the correlation bin weights w_c:

    grad_phi_beta = dx * (W_pair(beta) @ (1-h) - W_pair.T @ h).

The same weights are softmaxed; no reweighting by scores after this.

The objective is not necessarily nonsmooth but it is usually smooth. Decreasing it does not guarantee decreasing exact max, hence exact acceptance is all required.

1.1 Central idea

The evaluation is deterministic, discrete, and finite. A returned vector h of length n with dx=2/n is scored by

    C(h) = max_{lag=0,...,2n-2} [np.correlate(h, 1-h, mode="full") * dx]_lag.

This is linear correlation of h and 1-h over finite support, with both shifted overlap directions included. The problem is nonconvex because each active correlation bin contains products h[p]*(1-h[m]). The proposed algorithm therefore treats the evaluator as the only authoritative acceptance test and uses several local surrogate objectives to generate feasible candidate vectors. It preserves any feasible sup convergence by validating `initial_h_values` whenever it is supplied, maps its length dynamically into the vector dimension, and uses that parent as a guaranteed fallback.

The main heuristic paradigm is:

1. Keep one or more feasible source candidates.
2. Try to decrease their exact score using smooth surrogate objectives for the max of correlation entries.
3. Repair exact mass and box constraints using formulas that always satisfy both requirements.

5. Add local pair-transfer searches and randomized perturbations to escape flat surrogate/stationary regimes.

The method is mindful that a decrease in a smooth surrogate can worsen the exact objective, so no solver success flag or surrogate value is used to correct or prove the returned bound. No global optimality is claimed.
