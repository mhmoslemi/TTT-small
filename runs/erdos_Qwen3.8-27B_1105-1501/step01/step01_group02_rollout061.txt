Now let me also think about a potential issue: the "active" set in the bisection. When multiple lags achieve the max simultaneously, the subgradient is the convex hull of their dc values. The right derivative is max(dc[active]) and left derivative is min(dc[active]). For the bisection, I use the right derivative to decide which way to go. This is correct for finding the minimum of a convex function.

Let me now write the final code:

```python
import numpy as np
import time


def project_box_sum(h, target_sum):
    """Project h onto {0 <= x_i <= 1, sum(x) = target_sum}."""
    lo, hi = -1.0, 1.0
    for _ in range(50):
        mid = (lo + hi) / 2.0
        if np.sum(np.clip(h - mid, 0.0, 1.0)) > target_sum:
            lo = mid
        else:
            hi = mid
    return np.clip(h - (lo + hi) / 2.0, 0.0, 1.0)


def compute_corr(h):
    return np.correlate(h, 1.0 - h, mode='full')


def compute_c5(h):
    n = len(h)
    return float(np.max(compute_corr(h))) * 2.0 / n


def compute_dc(h, i, j, n):
    """Compute the dc vector for pair (i,j). dc[k] = d(corr[k])/dt for unit transfer i->j."""
    off = n - 1
    dc = np.zeros(2 * n - 1)
    for k in range(2 * n - 1):
        L = k - off
        c = 0.0
        m = i - L
        if 0 <= m < n:
            c -= (1.0 - h[m])
        m = j - L
        if 0 <= m < n:
            c += (1.0 - h[m])
        m = i + L
        if 0 <= m < n:
            c += h[m]
        m = j + L
        if 0 <= m < n:
            c -= h[m]
        dc[k] = c
    return dc


def find_optimal_t(corr, dc, h_i, h_j):
    """Find optimal t for pair (i,j). Returns (t, improvement)."""
    t_lo = max(h_i - 1.0, -h_j)
    t_hi = min(h_i, 1.0 - h_j)
    if t_hi - t_lo < 1e-12:
        return 0.0, 0.0
    
    # Check if t=0 is optimal
    max_0 = np.max(corr)
    active = np.where(corr >= max_0 - 1e-10)[0]
    rd = np.max(dc[active])
    ld = np.min(dc[active])
    
    if rd <= 1e-10 and ld >= -1e-10:
        return 0.0, 0.0
    
    if rd > 1e-10:
        lo, hi = t_lo, 0.0
    else:
        lo, hi = 0.0, t_hi
    
    if hi - lo < 1e-12:
        return 0.0, 0.0
    
    # Bisection
    for _ in range(35):
        mid = (lo + hi) / 2.0
        vals = corr + dc * mid
        mv = np.max(vals)
        act = np.where(vals >= mv - 1e-10)[0]
        r = np.max(dc[act])
        if r > 1e-10:
            hi = mid
        else:
            lo = mid
    
    best_t = (lo + hi) / 2.0
    improvement = max_0 - np.max(corr + dc * best_t)
    return best_t, improvement


def full_sweep(h, n, max_sweeps=100):
    """Perform full pair sweeps until convergence."""
    corr = compute_corr(h)
    total_improvement = 0.0
    num_sweeps = 0
    
    for sweep in range(max_sweeps):
        sweep_improvement = 0.0
        for i in range(n):
            for j in range(i + 1, n):
                dc = compute_dc(h, i, j, n)
                t, imp = find_optimal_t(corr, dc, h[i], h[j])
                if abs(t) > 1e-10 and imp > 1e-10:
                    h[i] -= t
                    h[j] += t
                    corr = compute_corr(h)
                    sweep_improvement += imp
        total_improvement += sweep_improvement
        num_sweeps += 1
        if sweep_improvement < 1e-10:
            break
    
    return h, num_sweeps, total_improvement
```

Wait, I realize the full sweep is O(n³) because for each of the O(n²) pairs, I do an O(n) computation for dc and an O(n * 35) bisection. Total: O(n²) * O(n * 35) = O(n³ * 35).

For n=70: 70² * 70 * 35 ≈ 12 million operations per sweep. In Python, with the inner loop being scalar operations, this might take 5-20 seconds per sweep. So in 1100 seconds, I can do about 50-200 sweeps. That should be sufficient for convergence.

But wait, there's a subtlety: after each pair update, I recompute corr (O(n²) using np.correlate). So the total per sweep is actually O(n²) updates * (O(n) dc + O(n*35) bisection + O(n²) correlate) = O(n²) * O(n²) = O(n⁴) per sweep.

For n=70: 70⁴ ≈ 24 million * 35 ≈ 840 million. That's too slow!

Let me optimize. The key issue is recomputing corr after every pair update. Instead, I can:
1. Only update corr incrementally (I know how it changes when I modify two coordinates).
2. Or, do a "batch" approach: compute all optimal t's first, then apply them.

Option 1: Incremental corr update.
When we change h[i] -= t and h[j] += t, the change in corr is exactly dc * t (by definition). So I can update as:
corr_new = corr + dc * t

This is O(n) instead of O(n²)! Great.

But there's a subtlety: after updating h, the dc for the NEXT pair will be different (because h has changed). So I can't precompute all dc's; I need to recompute for each pair. But the dc computation is O(n), and I can update corr in O(n) after each pair. So the total per sweep is O(n²) * O(n) = O(n³).

For n=70: 70³ * 35 ≈ 12 million. In Python, this is maybe 1-5 seconds per sweep. OK, that's better.

Wait, but the bisection is 35 iterations of O(n) each, so O(n*35) per pair. And the dc computation is O(n). So per pair: O(n + n*35) = O(36n). Total per sweep: O(n² * 36n) = O(36n³). For n=70: 36 * 343000 ≈ 12.3M. In Python with simple operations, this is maybe 2-10 seconds per sweep. Let's say 5 seconds. In 1100 seconds, that's about 200 sweeps. Should be enough.

Let me revise the code to use incremental corr updates:

```python
def full_sweep(h, n, corr):
    """One full sweep. Updates h and corr in place. Returns total improvement."""
    total_imp = 0.0
    for i in range(n):
        for j in range(i + 1, n):
            dc = compute_dc(h, i, j, n)
            t, imp = find_optimal_t(corr, dc, h[i], h[j])
            if abs(t) > 1e-10 and imp > 1e-10:
                h[i] -= t
                h[j] += t
                corr += dc * t  # Incremental update!
                total_imp += imp
    return total_imp
```

This is much better. The incremental update `corr += dc * t` is exactly correct because corr changes linearly with t for a pair move.

Now, one concern: numerical accumulated error. After many incremental updates, corr might drift from the true value. I should periodically recompute corr from scratch:

if sweep_count % 10 == 0:
