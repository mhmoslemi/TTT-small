1. Approach and rationale

1.1 Central idea

The task is a constrained finite-support quadratic minimax problem.  The previous idea-space relied heavily on a smoothed maximum surrogate projected-gradient path, random perturbations, or an LP/SQP tangent construction whose main effect is to choose a single step direction.  The proposed method is materially different: it repeatedly performs **global exact one-dimensional minimization of the exact evaluator along active-subgradient, local-pair, and random feasible directions**.  A candidate parameter value is found by solving/constructing the global minimum of the maximum of the exact quadratic one-dimensional functions along a full feasible line segment.  Every step is accepted by the original evaluator, not by a surrogate.  If a line contains any feasible point with lower `C5`, the method can find it; if all Sekarang feasible line minima do not improve the current point, the search perturbs or changes the working dimension.  The parent construction is retained and can be returned exactly when no better valid candidate is found.

The method targets the microsecond improvement needed here, from around `0.38085` toward below `0.3808`, because it is able to:
- move several coordinates at once along a direction z并对” metabolic necessaryの新 mass;
- search the entire feasible interval on a chosen direction as a one-dimensional exact minimax objective rather than taking fixed small steps;
- handle the nondifferentiable active-set kinks exactly (inside the line) by considering minima where two or more correlations intersect;
- combine that with pair-transfer line searches that perform reallocation of mass, which are important because the feasible set is a unit-mass box and directions with positive and negative components are usually more beneficial than random unconstrained lines;
- interrogate nearby dimensions from the parent solution with faithful resampling and exact reevaluation.

1.2 Bottleneck addressed

A direct projected-gradient/local method can fail when the exact objective has multiple active maxima, and a projection or fixed-size step cannot move smoothly over a kink in the `max` surface.  This plan removes the surrogate valley problem on the chosen line: after the one-dimensional objective being maximized by quadratic correlations is specified, a global line minimization uses the exact quadratic structure rather than an approximate smoothed maximum.  The method is still not a global optimizer because the line directions are generated locally and in a biased mass-transport way; but each successful update is justified by exact improvement.

1.3 Limitations

- The problem is nonconvex; no global optimality is claimed.
- Direction selection uses an active correlation/cone approximation.  If that approximation is misleading, the exact line search may fail to improve; random lines and perturbations provide escape.
- Exact line optimization is done over already feasible line segments; general feasible line with box constraints is exact but candidates may get slightly damaged by final mass/box repair if numerical drift is present.
- High-dimensional exact-pair-intersection line search costs some CPU time; the line limit and stop conditions keep it under 1100 seconds on a single CPU.

2. Mathematical specification

2.1 Discrete state and constraints

Let the returned vector be `h` of length `n`, cell centers `x_i = (i+0.5)*2/n`.

Feasibility:
- `0 <= h[i] <= 1`
- `sum(h) = n/2`.

The exact returned objective is:
`C5(h) = max_k np.correlate(h, 1-h, mode="full")[k] * (2.0/n)`, with `k=0,...,2*n-2`.  Both lag signs are in the full vector; no logical circularization or boundary reconstruction must be substituted for this.

2.2 Exact correlation convention and useful formula

For `n=len(h)` and `m=2*n-1`, define an explicit matching formula that a correct implementation can check against NumPy.  With lag attached to output position `k = lag + n - 1`:

For `L >= 0`, `c_{n-1+L} = sum_{i=0}^{n-1-L} h[i+L] * (1-h[i])`.

For `M > 0`, `c_{n-1-M} = sum_{i=0}^{n-1-M} h[i] * (1-h[i+M])`.

For `L=0`, `c_{n-1} = sum_i h[i]*(1-h[i])`.

Scaled correlations are `c_scaled = c * dx`, `dx=2/n`.  All core optimizer calculations use this scaled correlation so objective-inc changes are directly in `C5` units.  An implementation should include a tiny dimensional consistency sanity check on the full array of length `2*n-1`, but this is for developer correctness, not for final numerical behavior.

2.3 Feasibility repair

Define a box/simplex-feasible operator `make_feasible(v)`:
1. Clip to `[0,1]`.
2. If the mass is within very tight bounds, clip only tiny negative/above-one tolerance not causing large change, then repair mass exactly by subtracting the residual from a selected interior coordinate of largest slack-from-bound.  This preserves candidate microstructure.
3. If residual is not tiny, use the scalar water-filling algorithm: find, by bisection, `mu` such that `sum(clip(h - mu, 0, 1)) = target`.  Use 60 to 80 bisection iterations and then small exact residual cleanup.

All starting points and final outputs pass through this.  Line segment updates preserve sum because direction sums are zero and are finalized with the tiny method above rather than a large projection that would ruin the line-found point.

2.4 Objective active weighting and approximate gradient

At feasible `h`:
- compute `wcorr = c_scaled`
- `c_max = max(wcorr)`

Define active weights `q` for approximating a subgradient of the exact max:
- Choose a rank-turn active set: select the top `r` entries of `c_scaled`, where `r = max(6, min(32, (2*n + 20)//14))`.
- Correlations with `c_scaled >= c_max - top_tol` use weight `1`.  The rest use a decaying weight `exp((c_scaled - c_max)/tauActive)` to avoid an entirely zero active gradient rare-but-noisy case.  `tauActive = max(3e-5, 1e-3*c_max)`.
- Normalize `q` to sum `1`.

The weighted smooth scalar is `F(h) = sum_j q[j] * c_scaled[j]`.  Analytically compute its gradient `g` with respect to `h` using the same exact lag formulas:
For each output row `j` with lag `lag = j - (n-1)` and weight `q[j]`:

- lag `L>0`:
  - indices `i=0..n-1-L`
  - h-gradient contribution at `i+L`: `q[j] * (1 - h[i])`
  - contribution at `i`: `-q[j] * h[i+L]`

- lag `-M<0`:
  - indices `i=0..n-M-1`
  - contribution at `i`: `q[j] * (1 - h[i+M])`
  - contribution at `i+M`: `-q[j] * h[i]`

- lag `0`:
  - contribution at `i`: `q[j] * (1 - 2*h[i])`

Multiply the final accumulated gradient by `dx`.  This gradient is a checkable derivative of a top-active linear surrogate of the exact max.  Invariant check rule for implementation (a one-time compelled check in startup test code or self-contained code if it is not too costly): for at least two coordinates the one-dimensional finite difference from directly forming scalar `sum q*c` against `np.correlate` should match the accumulated gradient within expected error; mismatch behavior should fall back to finite-difference weighted gradient for that dimension.  Acceptance of any step remains strictly with the original `C5`, so the possible convention issue only affects search quality not constraint validity.

2.5 Feasible direction intervals

For `||` any direction `d` satisfying `sum(d)=0`, construct `h(t) = h + t*d`.  It keeps mass preserved.  Feasibility imposes:

- if `d_i > 0`: `t <= (1-h_i)/d_i`
- if `d_i < 0`: `t >= -(h_i)/|d_i|`
- if `d_i = 0`: no restriction directly.

`[t_low,t_high]` is intersection of these one-sided limits.  If `t_low > t_high` due numerical pathological normalization, discard direction.  If interval width is tiny, discard direction.  Optionally cap the interval to `±10.0/candidate_slack` to avoid giant scales; since max absolute direction is normalized to order one, boundaries are usually lower.

2.6 Exact line objective and global quadratic minimization

Along `h(t)`:
- `wcorr_k(t)` is a quadratic polynomial `A_k t^2 + B_k t + C_k`, because all products are products of affine functions.  This is exact across `[t_low,t_high]`.
- Fit `A_k,B_k,C_k` numerically with three well-separated parameter samples, e.g. `t=0` and two feasible points inside `[t_low,t_high]`. The constructed central value `C_k` is the scaled correlation vector at `t=0`; solve a two-equation quadratic fit for `A,B`. Check residuals at another point.  If fit is bad, use only dense exact-line sampling and judge by exact demands, or skip the line if it degenerates.
- Define `phi(t)=max_j (A_j t^2 + B_j t + C_j)`.

The exact global minimum of a finite piecewise quadratic upper envelope occurs:
- at interval endpoints,
- at vertices of one quadratic where `A_j > 0` and `t_v = -B_j/(2A_j)` is inside the interval,
- at intersections where two constraint polynomials are equal:
  `(A_j-A_k)t^2 + (B_j-B_k)t + (C_j-C_k) = 0`.

The returned parameter(s) form a candidate list.  Evaluate `phi` along roots with absence membership by linear intervals.  The most-critical few root candidates are then mapped through the feasible formula `h + t*d`, concretely repaired to exact constraints, and scored by the original evaluator.  A dense grid fallback is used across the interval (for example 81 points) to catch numerical envelope-root mistakes.  This is global for that feasible line according to the principle above and exact for the obtained mapped candidate.

2.7 No convexity claims

Products `h_i h_j` and majorization by `max` spoil convexity. 3. Implementation procedure

3.1 Global programming style constraints

All helper routines are top-level Python functions and the required top-level function is `run(seed=42, budget_s=1100, **kwargs)`.  Do not create closures, lambdas, or inline full objects.  The entire program should consist only of compact NumPy/SciPy operations, not hard-coded tables.  Optional `evaluate_erdos_solution` may be used for validation, but final scoring uses the actual NumPy correlation formula to keep interface transparent.

3.2 Interface elements and hierarchy

Required top-level helpers (by design):

3.2.1 Objective helpers
- `compute_c_scaled(h)`:
  - input: length-`n` array; output: length `2*n-1` array
  - operation: multiply `dx=2.0/n` by `np.correlate(h, 1.0-h, mode="full")`.
- `compute_c5(h)`:
  - input: array; output: `float(max(compute_c_scaled(h)))`.

3.2.2 Feasibility helpers
- `make_feasible(v)` detailed in 2.3.  This helper must accept bad clipped starting arrays and always return finite `0<=out<=1`, `sum(out)=len(out)/2` to machine accuracy, using an exact-damage branch for sum residual and full waterfill for gross violation.
- `line_make_feasible(h_bar_h, d, t)`:
  - output `h_new=h + t*d`;
  - clip tiny numerical catastrophic remains to `[0,1]`;
  - compute mass error; if small, adjust exactly by one interior/free coordinate from the `error`; if not small return `None` so the line candidate is not accepted.
  - return `(h_new, exact_score,feasible_flag)`.

3.2.3 Direction helpers

3.2.3.1 Weighted active gradient `weighted_active_grad(h)` always:
- compute by formula in section 2.4 for weights whose largest entries correspond with `np.correlate` order.
- return: a length-`n` gradient array.

3.2.3.2 normalization logic in `clean_scaled_direction(raw)`
- subtract its mean to ensure sum zero;
- if `max(abs(raw)) < 1e-14` return `None`;
- divide by `scale = max(1.0, max(abs(raw)))` so the direction has maximum coordinate change of order one at optimal scalar size.  For gradient descent direction: initially use `raw=-g`; for a second-type direction use reversed gradient, for robustness. Box step intervals become bounded, and fit coefficients are stable.

3.2.4 Line directions helpers

- `gradient_line_direction(h)` returns `[d,-d]` derived from active gradient.
- `pair_directions(h,g,pairs_limit)`:
  - sort coordinates by gradient value ascending/descending.
  - approximate low group `P1` near coordinates most favorable to increase (`low g`) and high group `P2` most favorable to decrease.  also fill using random feasible `i/j` if minimum `g` fails due bounds.
  - filters: `h_i < 1-1e-8` and `h_j > 1e-8` for pair direction `e_i-e_j`. Because the global line search will choose an endpoint/root over negative and positive feasible portions, brute check is robust.
  - limit `pairs_limit` from budget control (default `10` per pass).
- `random_directions(n,k,rng)` for U-shaped Gaussian normal direction with exact center mass zero and normalized.
- `cyclic_shifted_gradient_direction(h)` can shift parent or best vector in index via `np.roll(h, s)` and random sign both useful.
