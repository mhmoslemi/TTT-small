Now let me think about the efficiency of the pair search. For each pair (a,b):
- slope = grad[a] - grad[b] (vector of length 2n-1)
- new_V(t) = V + t * slope
- f(t) = max(new_V(t))
- Minimize f(t) over [t_lo, t_hi]

To minimize f(t) = max_lag(V[lag] + t*slope[lag]) over [t_lo, t_hi]:
This is a convex piecewise linear function. The minimum is at:
- An endpoint, OR
- A point where two (or more) lines cross and the maximum switches

A practical approach: 
1. Evaluate f at t_lo, t_hi
2. If f(0) is already the max, check if moving helps
3. Try a binary-search-like approach: 
   - The subgradient at t is the set of slopes of active (maximizing) functions
   - If all active slopes > 0, minimum is to the left → try t_lo
   - If all active slopes < 0, minimum is to the right → try t_hi
   - If mixed, we're near the minimum

Even simpler: just try a handful of t values and pick the best:
- t_candidates = [t_lo, t_hi, 0, (t_lo+t_hi)/2, t_lo + 0.25*(t_hi-t_lo), t_lo + 0.75*(t_hi-t_lo)]
- Plus: the t that minimizes the sum of squares (least squares): t_ls = -sum(V*slope)/sum(slope^2), clamped to [t_lo, t_hi]
- Plus: the t that equalizes the top 2 active constraints

For speed, I'll just use 5-7 candidate t values per pair. With ~1800 pairs per sweep, that's ~12000 evaluations of f(t). Each evaluation is O(n) (just a max over 2n-1 values). So ~12000 * 120 = 1.4M ops per sweep. Very fast!

            resid -= add
            if resid < 1e-14:

    else:

        for idx in order:
            sub = min(-resid, z[idx])
            z[idx] -= sub
            resid += sub
            if -resid < 1e-14:

    n = len(h)

                if a <= n - 1 - lag:
                    g += (1.0 - h[a + lag])

                    g += -h[a - lag]

                    g += (1.0 - h[a - t])
                if a <= n - 1 - t:
                    g += -h[a + t]
            grad[a, s] = g * dx

Hmm, this is getting long. Let me think about a cleaner structure.

Actually, I realize the gradient recomputation after each accepted move is O(n) per move (for the two changed indices, each affecting 2n-1 lags). That's fine.

But the main loop structure: for each pair, I do O(n) work to evaluate candidates. With n^2/2 pairs, each sweep is O(n^3). For n=60, that's 216K ops per sweep. I can do thousands of sweeps in the time budget.

Let me also think about a better t search strategy. Instead of fixed quantiles, I can do a proper 1D minimization of the convex piecewise linear function:

The minimum of max_i(a_i * t + b_i) over [lo, hi]:
- This is a convex piecewise linear function
- The minimum occurs where 0 is in the subgradient
- Subgradient at t = {a_i : i in active(t)} where active(t) = {i : a_i*t + b_i = max_j(a_j*t + b_j)}
- 0 in subgradient means: min_{i in active} a_i <= 0 <= max_{i in active} a_i

Algorithm:
1. At t=lo, find active set. If all active slopes > 0, minimum is at lo. If all < 0, move right.
2. If mixed, we're at the minimum (or very close).
3. Otherwise, binary search for the switching point.

Actually, a simpler approach that's nearly as good: the minimum of max of linear functions can be found by the "gift wrapping" / rotating calipers method, but that's overkill.

Let me just use: evaluate at the intersection point of the two lines with the most positive and most negative slopes (among active lines), plus endpoints. That should find the minimum in O(n log n) time.

Actually, the simplest effective approach: 
1. Find which lag gives the max at t=lo: call it i_lo
2. Find which lag gives the max at t=hi: call it i_hi  
3. If i_lo == i_hi, the max is achieved by the same line throughout, so the function is linear on [lo,hi] (or the same line is always on top). Minimum is at the endpoint where it's smaller.
4. If i_lo != i_hi, find their intersection: t* = (V[i_hi] - V[i_lo]) / (slope[i_lo] - slope[i_hi]) (if denominator != 0)
5. Evaluate at t*, lo, hi, and pick the best.

This is O(n) per pair and finds the exact minimum in most cases!

Wait, that's not quite right. The max could switch through multiple lines. But in practice, checking the intersection of the two "extreme" active lines plus endpoints usually finds the minimum or very close to it.

Let me refine: 
- At t=lo, the active set is A_lo = {i : V[i] + lo*slope[i] = max_j(V[j] + lo*slope[j])}
- At t=hi, the active set is A_hi
- The minimum is at:
  - lo, if all slopes in A_lo > 0 (moving right increases the max)
  - hi, if all slopes in A_hi < 0 (moving left increases the max)
  - Otherwise, somewhere in between

                    h_sr, max_sweeps=150, n_pairs_per_sweep=None,
                    rng=rng, time_limit=min(remaining * 0.35, 35), t_start=t_sweep)
                if sc_sr < best_score - 1e-13:
                    try_update(h_sr, sc_sr)
    
    # Phase 5: Fine polishing on best
    if not check_deadline():
        remaining = deadline - time.time()
        if remaining > 15:
            h_fin = best_h.copy()
            t_sweep = time.time()
            h_fin, sc_fin, _ = pair_sweep(
                h_fin, max_sweeps=1000, n_pairs_per_sweep=None,
                rng=rng, time_limit=remaining * 0.6, t_start=t_sweep)
            if sc_fin < best_score - 1e-13:
                try_update(h_fin, sc_fin)
    
    # Phase 6: One more direction + pair cycle
    if not check_deadline():
        remaining = deadline - time.time()
        if remaining > 20:
            h_w6 = best_h.copy()
            V6 = np.correlate(h_w6, 1.0 - h_w6, mode='full') * (2.0 / len(h_w6))
            grad6 = compute_grad(h_w6)
            for K in [5, 8, 15]:
                if check_deadline():
                    break
                h_w6, sc6, ok = direction_move(h_w6, V6, grad6, len(h_w6), K=K)
                if ok:
                    V6 = np.correlate(h_w6, 1.0 - h_w6, mode='full') * (2.0 / len(h_w6))
                    grad6 = compute_grad(h_w6)
                if sc6 < best_score - 1e-13:
                    try_update(h_w6, sc6)
            remaining = deadline - time.time()
            if remaining > 10:
                t_sweep = time.time()
                h_w6, sc6b, _ = pair_sweep(
                    h_w6, max_sweeps=200, n_pairs_per_sweep=None,
                    rng=rng, time_limit=min(remaining * 0.7, 30), t_start=t_sweep)
                if sc6b < best_score - 1e-13:
                    try_update(h_w6, sc6b)
    
    # Final validation
    final_h = make_feasible(best_h)
    final_score = score_fn(final_h)
    final_n = len(final_h)
    
    # Safety fallback
    if not np.all(np.isfinite(final_h)) or final_h.min() < -1e-9 or final_h.max() > 1 + 1e-9:
        final_h = np.full(max(20, final_n), 0.5)
        final_score = score_fn(final_h)
        final_n = len(final_h)
    
    final_bound = final_score + 1e-12
    
    return final_h, final_bound, final_n
