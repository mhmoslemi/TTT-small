```python
def compute_effects(h, n):
    """Compute the effect of h[p]+=1 on the full correlation vector, for each p."""
    # effect[p, m] = change in c[m] when h[p] increases by 1
    # c[m] corresponds to lag k = m - (n-1)
    # Delta c_k = (1-h[p-k])*[0<=p-k<n] - h[p+k]*[0<=p+k<n]
    effects = np.zeros((n, 2*n-1))

                val += (1.0 - h[pk])
            pk2 = p + k
            if 0 <= pk2 < n:

    return effects

            best_val = new_maxes[best_idx]
            
            if best_val < current_c5 - 1e-15:
                i = ones[best_idx[0]]
                j = zeros[best_idx[1]]
                h[i] = 0.0
                h[j] = 1.0
                old_corr = np.correlate(h, 1.0 - h, mode='full')
                current_c5 = best_val
            else:
                break
        else:
            # Too many swaps, use random subset
            break
        
        if verbose and sweep % 100 == 0:
            print(f"Sweep {sweep}: C5 = {current_c5:.6f}")
    
    return h, current_c5
```

Wait, there's an issue. The effects depend on the current h, and after a swap, h changes. So I need to recompute effects after each accepted swap. But the vectorized computation gives me the best swap given the CURRENT effects, which is correct for one step. After applying that swap, I recompute everything.

The issue is: after one swap, the "best next swap" might be different. So I do a full sweep (try all swaps, apply the best one), then repeat. This is "steepest descent" or "best improvement" local search.

Each sweep costs:
- compute_effects: O(n²) = 4096 (with Python loop, maybe 1ms)
- Vectorized max computation: O(n_o * n_z * n) in memory/time
  For n=64: 32*32*127 = 131K elements, which numpy handles in < 1ms
- One correlate: ~10μs

So each sweep takes maybe 2-3ms (dominated by the Python loop in compute_effects).
10000 sweeps: 20-30 seconds. That's fine!

But wait, I can vectorize compute_effects too! Let me think...

effects[p, m] = (1-h[p-k])*[0≤p-k<n] - h[p+k]*[0≤p+k<n] where k = m-(n-1)

This is essentially a "shifted" version of h. I can compute it with vectorized operations:

For each p, the first term (1-h[p-k]) is a shifted version of (1-h) centered at p-k.
The second term h[p+k] is a shifted version of h centered at p+k.

Using the "full" correlation structure:
effects[p, :] is like the "correlation" of a unit pulse at position p with (1-h) and -h.

Actually, I realize I can compute all effects at once using a matrix operation or by exploiting the Toeplitz structure.

Let me define:
For k from -(n-1) to n-1 (total 2n-1 values):
effects[p, k+(n-1)] = (1-h[p-k])*[0≤p-k<n] - h[p+k]*[0≤p+k<n]

The first term: (1-h[p-k]) where p-k is in [0,n). This is (1-h) "shifted" by k.
If I create a matrix A where A[p, m] = (1-h[(p-(m-(n-1))) mod n])... no, it's not mod, it's with boundary conditions (0 outside).

Let me think of it as: for fixed k, the vector over p is:
first_term[p] = (1-h[p-k]) if 0≤p-k<n, else 0
= (1-h) shifted right by k, with 0-padding.

Similarly, second_term[p] = h[p+k] if 0≤p+k<n, else 0
= h shifted left by k, with 0-padding.

I can compute these using np.roll with zero-padding, or more directly:

For each k (or m = k + n-1):
first_term = np.zeros(n)
valid_p = np.arange(max(0, k), min(n, n+k))  # p such that 0 ≤ p-k < n
first_term[valid_p] = 1 - h[valid_p - k]

second_term = np.zeros(n)
valid_p2 = np.arange(max(0, -k), min(n, n-k))  # p such that 0 ≤ p+k < n
second_term[valid_p2] = h[valid_p2 + k]

effects[:, m] = first_term - second_term
