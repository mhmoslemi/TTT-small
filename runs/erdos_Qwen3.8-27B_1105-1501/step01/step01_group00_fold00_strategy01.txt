1. Approach and rationale
  1.1 Central idea
  The primary new method is an exact feasible-set line-search engine built around two-point sum-preserving moves, supplemented by an active-constraint composite direction and random feasibility-aware restarts. The current construction is first evaluated exactly with the official evaluator. The full value vector and the active lag set are then used to generate low-dimensional descent attempts. Each attempt is accepted only if the official full objective strictly improves. The search is carried out in several allowed resolutions, with validation whenever dimension changes.

  This differs from a generic smoothing/SLSQP ladder in three substantive ways:
  - Every accepted update is judged by the true non-smooth objective `max(pair-correlation)`, not a smoothed surrogate.
  - Moves preserve the exact constraint `sum(h) = n/2` by construction instead of relying on an equality constraint solver or iterative repair. Specifically, pair moves change one coordinate by +delta and another by -delta within bounds. Composite active directions are projected to zero mean, and any candidate entering the active pool is validated exactly.
  - The active constraints are the 2n-1 lag-direction functionals themselves. The method may use tangent or smooth-max gradients only to propose directions. No convexity is claimed. The exact evaluator rejects nonimproving proposals.

  1.2 Bottleneck addressed
  A direct smooth-max optimizer used in the parent process can create bias toward the currently dominant lags and can miss adjacent lag labels that rise. The proposed method repeatedly uses the official full overlap vector and all lag labels. It alternates the exact objective landscape and line-sample curve along specific sum-preserving directions. Random pair updates add curiosity, while active-direction sampling uses the local balance structure to coordinate moves unavailable to coordinate-greedy methods.

  1.3 Honest limitations and claims
  This is a stochastic local-search method. It is not a global optimizer, and it does not assert that a common minimal fixed point or global C5 value has been found. Claims such as tangent global upper bounds are not made because products `h_i h_j` make the objective non-convex. The only determinant of accepted progress is the exact evaluator: 0 <= h[i] <= 1 and sum(h) = n/2.

  Candidate acceptance is improvement for exact full exact objective on returned vector. The parent construction is retained as the fallback(best proven candidate). A higher resolution candidate is always included, then mapped to the requested final resolution. The returned candidate and bound are both compared with the original evaluator before returning.
