∂F_k/∂h[j] = (1-h_0[j+k]) if j+k is valid + (-h_0[j-k]) if j-k is valid (for the two terms where j appears in F_k)

Wait, let me be more careful. F_k = sum_i h[i](1-h[i+k]) (over valid i).

∂F_k/∂h[j]:
- Term i=j: h[j](1-h[j+k]) → ∂/∂h[j] = (1-h[j+k])
- Term i=j-k: h[j-k](1-h[j]) → ∂/∂h[j] = -h[j-k]
- All other terms: 0

So ∂F_k/∂h[j] = (1-h[j+k]) - h[j-k] (where both terms are included only if the indices are valid).

This matches the `compute_lag_gradient` function in the previous code.

So the linearization approach would be:
1. At current h_0, compute F_k(h_0) and ∇F_k(h_0) for all k.
2. Solve: min t s.t. F_k(h_0) + ∇F_k(h_0)·(h - h_0) ≤ t for all k, sum(h) = n/2, 0 ≤ h ≤ 1.
   This is a linear program! (The constraints are linear in (h, t).)
3. Update h to the LP solution.
4. Repeat.

This is essentially the "piecewise linear approximation" method (like in the simplex method for nonlinear optimization). It should converge to a local optimum.

The LP can be solved with scipy's linprog or with cvxpy.

Let me think about the size: we have n variables (h[0], ..., h[n-1]) + 1 variable (t) = n+1 variables. We have 2n-1 inequality constraints (one for each k) + 1 equality (sum) + 2n bounds. For n=61, that's 62 variables and ~181 constraints. Very manageable.

This is a good approach! Let me code it up.

Actually, I realize there's a subtlety: the linearization is a first-order approximation, so it overestimates F_k (since F_k is not convex, the tangent plane doesn't necessarily give an upper bound). But it should still work as a local optimization method: at each step, we move to a point that decreases all the linearized F_k, which should (locally) decrease the actual F_k.

Let me also think about convergence: this is essentially the "method of conditional gradients" (Frank-Wolfe) applied to a piecewise-smooth function, or more precisely, it's similar to the "successive linear programming" (SLP) method used in chemical engineering.

The key advantage over SLSQP is:
- Each subproblem is a linear program (exactly solvable).
- No smooth approximation needed.
- Can handle the non-differentiability of the max exactly (by including all linearized constraints).

import numpy as np

def slp_step(h, n, dx):
    """One successive linear programming step."""
    # Compute F_k and gradients at current h
    F = np.zeros(2*n - 1)
    grad = np.zeros((2*n-1, n))  # grad[k, j] = ∂F_k/∂h[j]

        start = max(0, -k)
        end = min(n, n - k)
        F[idx] = np.sum(h[start:end] * (1 - h[start+k:end+k]))

def compute_grad_all(h, n):
    """Compute gradient of all F_k w.r.t. all h[j]. Returns (2n-1, n) array."""
    grad = np.zeros((2*n-1, n))
    for k in range(-(n-1), n):
        idx = k + n - 1
        start = max(0, -k)
        end = min(n, n - k)
        # First part: j in [start, end), contributes (1 - h[j+k])
        grad[idx, start:end] += (1 - h[start+k:end+k])
        # Second part: j in [start+k, end+k), contributes -h[j-k]
        p_start = max(0, start + k)
        p_end = min(n, end + k)
        grad[idx, p_start:p_end] += -h[p_start-k:p_end-k]
    return grad

**Alternative: Direct non-smooth optimization with subgradient**

Even though f(h) = max_k C_k(h) is not convex, we can still define a "subgradient" at h as any convex combination of the gradients of the active (maximizing) C_k. This gives us a direction to move.

The issue is that C_k is not convex, so the "subgradient" doesn't have the usual properties. But in practice, moving in the -subgradient direction (i.e., the direction that decreases all active C_k simultaneously) should work locally.

Algorithm:
1. Compute C = F_raw * dx, find active set K* = {k: C_k = max C}.
2. Compute subgradient: g = dx * (1/|K*|) * sum_{k ∈ K*} grad_k (averaged gradient of active terms).
3. Take a step: h_new = h - α * g, where α is chosen by line search.
4. Project h_new back to the feasible set (0 ≤ h ≤ 1, sum = n/2).
5. Repeat.

The projection is the tricky part. We need to find the closest point to h - α*g in the set {h: 0 ≤ h ≤ 1, sum(h) = n/2}.

This is a quadratic program: min ||h - p||² s.t. 0 ≤ h ≤ 1, sum(h) = n/2, where p = h - α*g.

This can be solved by bisection on the Lagrange multiplier for the sum constraint:
h[i] = clip(p[i] - λ, 0, 1) for some λ, chosen so that sum(h) = n/2.

This is exactly what `make_feasible` does! (It's the Euclidean projection onto the intersection of the box and the hyperplane.)

So the algorithm is:
1. Compute active set and subgradient.
2. h_candidate = h - α * subgradient.
3. h_new = make_feasible(h_candidate).
4. Check if C_5(h_new) < C_5(h). If yes, accept. If no, reduce α and retry.

This is essentially a projected subgradient method (or projected gradient method, since we're using the actual gradient of active terms).

For the active-set method, the key computation is: given the active set K*, find the direction d that minimizes the maximum increase in C_k for k ∈ K*, subject to the constraints.

This is: min_d max_{k ∈ K*} ∇C_k · d
subject to: ∇(sum) · d = 0 (sum constraint), and d points into the feasible region.

This is a small LP (with |K*| + 1 constraints and n variables). It's essentially the same as the SLP but only using active constraints.

def make_feasible(z):

            elif err < 0 and h[i] > 0.0:

                h[i] -= d
                err += d
