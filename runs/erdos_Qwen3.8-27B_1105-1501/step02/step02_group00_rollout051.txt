        f2 = float(np.max(v * m2 + c))
        if f1 < f2:
            hi = m2
        else:
            lo = m1
    return (lo + hi) / 2.0

def _two_coord_pass(h, order, deadline):

This is equivalent to: minimize max_d |{i : x[i]=1, x[i+d]=0}| over all non-zero d (and d=0 gives the number of 1s, which is 32).

Wait, for d=0: corr_0 = sum_i h[i]*(1-h[i]) = 0 for binary h (since h[i]*(1-h[i]) = 0 when h[i] ∈ {0,1}). So lag 0 is always 0 for binary h!

For d ≠ 0: corr_d = |{i : h[i]=1, h[i+d]=0}| (counting only valid i).

The total over all non-zero d is 32*32 = 1024 (each 1 can pair with each 0 at exactly one non-zero lag).

We have 126 non-zero lags (d = -63, ..., -1, 1, ..., 63).
Average count per lag = 1024/126 ≈ 8.13.

So we want all lag counts to be ≤ 9 (ideally) or at most 10-12.

This is a well-studied combinatorial problem! It's related to "optimal binary sequences" or "low autocorrelation" sequences.

Let me implement a greedy + swap algorithm for this:

1. Start with a random binary sequence (32 ones, 32 zeros)
2. Compute all lag counts
3. Find the lag with the maximum count
4. Try swaps (move a 1 from position a to position b) that reduce the max count
5. Accept the best swap
6. Repeat until no improvement

The problem is that the O(n³) per iteration (trying all n²/4 swaps, each taking O(n) to evaluate) might be too slow if we need many iterations.

For n=64: 1024 swaps × 127 lag evaluations = 130K operations per iteration. In Python, maybe 50ms per iteration. With 5000 iterations, that's 250 seconds. Should be fine.

But actually, we can optimize by only evaluating the lags that are near the maximum. If the current max is at lag r with value M, then we only need to check if the swap reduces corr_r (and doesn't increase any other lag above M).

Even better: we can precompute the "effect" of each position on each lag, and then the effect of a swap (a,b) is just the sum of two precomputed vectors.

Let me precompute: for each position p, the vector of its contribution to each lag. Then the effect of swap (a,b) is effect[b] - effect[a], where effect[p] is the vector of changes when we toggle h[p] from 0 to 1 (or 1 to 0).

Wait, that's exactly the g_col! The g_col(h, p) gives d(corr)/d(h[p]), which is the effect of changing h[p] by a small amount. For a binary swap (h[a]: 1→0, h[b]: 0→1), the effect on corr is:
Δcorr = -g_col(a) + g_col(b)

where g_col is computed at the current h (before the swap). This is exact for binary h because the correlation is linear in each coordinate when the others are fixed (for binary h, the bilinear terms h[i]*h[i+d] are just 0 or 1, and changing one coordinate only affects the terms involving that coordinate).
