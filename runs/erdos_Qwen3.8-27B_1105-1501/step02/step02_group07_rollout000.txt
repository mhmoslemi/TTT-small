Let me also think about a more principled approach. The key insight is that at the optimum, the KKT conditions must hold. For the active set LP, the KKT conditions are:
- For active constraints: the gradient of the constraint is a non-negative combination of the gradients of the box constraints and the sum constraint
- For inactive constraints: the constraint value is below t

The LP finds a direction d such that:
- For active k: ∇V_k · d ≤ 0 (the constraint is satisfied)
- ||d||_∞ ≤ trust (trust region)
- Σ d = 0 (sum constraint)
- Minimize t (the new maximum)

This is exactly what the active_set_lp function does. The question is whether it's finding the right direction.

One issue: the LP might find a direction that reduces the linearized active constraints but doesn't actually reduce the true objective. This happens when the trust region is too large. The solution is to use a small trust region and many iterations.

But with a very small trust region, each LP only makes a tiny improvement, and it takes many iterations. The total time might be too long.

A better approach: **use a quadratic trust region**. Instead of |d|_∞ ≤ trust, use ||d||₂ ≤ trust. This is a quadratic constraint, making the problem a QP (or SOCP). But scipy's linprog only handles LPs.

I could use scipy.optimize.minimize with the trust-constr method, which handles QP-like problems. But it might be slow.

Alternatively, I can use the LP with a slightly larger trust region and then verify the improvement. If the true improvement is less than the predicted improvement, reduce the trust region.

        else:
