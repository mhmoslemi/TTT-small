But the step size is critical. If it's too large, we oscillate. If too small, we make no progress. The diminishing step size alpha_t = alpha_init / (1 + c*t) is a standard choice.

Actually, for the max function, a better approach might be the **mirror descent** or **follow-the-regularized-leader** method. But for simplicity, let's stick with projected subgradient.

Let me also think about a **key insight for the step size**: the function values f_k(h) are bounded. The maximum possible value of f_k is at most sum(h) = n/2 (when h is 0/1 and the shifted version is all 0s in the overlap region). Actually, max f_k <= sum of h over the overlap region <= n/2. And the minimum is 0. So the range is at most n/2.

For the subgradient method, the theoretical step size for convergence to epsilon-optimal is alpha = D / sqrt(T * L^2) where D is the diameter of the feasible set and L is the Lipschitz constant of the subgradient.

L is bounded by the maximum norm of any gradient. Each gradient g_k has ||g_k|| <= sqrt(n) (roughly). So L ~ sqrt(n).

D (diameter in L2) is at most sqrt(n) (since h is in [0,1]^n).

So alpha ~ sqrt(n) / sqrt(T * n) = 1/sqrt(T). With alpha_init = 1/sqrt(500) ≈ 0.045.

Let me use alpha_init = 0.05 and decay slowly.

Now, one important thing: the subgradient method converges to the optimum only in the limit (infinite iterations). In practice, with finite iterations, we get an approximate solution. The averaged iterate often performs better than the last iterate.

Let me now think about the **structured perturbation** idea:

Instead of random perturbations, try specific structured moves:
1. **Block shift**: Take a contiguous block of h and shift it by 1 position (wrapping around or not)
2. **Block flip**: Complement a contiguous block (h[i:i+k] -> 1-h[i:i+k])
3. **Block swap**: Swap two blocks
4. **Edge modification**: Adjust the boundary between high and low regions

These moves preserve the sum constraint (or easily fix it) and might escape local optima.

Actually, for the block flip: if we flip h[i:i+k], the sum changes by k - 2*sum(h[i:i+k]). To maintain the sum, we'd need to adjust other entries. This is more complex.

A simpler structured move: **exchange**. Pick two indices i, j where h[i] > h[j], and swap their values (or partially swap: h[i] -= eps, h[j] += eps). This preserves the sum exactly.

    if abs(r) > 1e-12:

                h[idx] += d; r -= d
                if abs(r) < 1e-15: break
        else:

                d = min(-r, h[idx])
