1. Approach and rationale

1.1 Central idea

The supplied parent is already close to the target, but the previous local-search program primarily explores the parent's own basin using linearized max-constraint subproblems and smooth-max projections. If the target value is separated from the parent by a numerical barrier, further slope-based movement from the same configuration can stall even when a slightly different ordering or level pattern exists.

This plan uses a different global/local architecture:

1. Global coarse exploration: optimize a low-dimensional decoded shape rather than all fine-grid variables at once. Parameters live in a smooth hidden grid of size roughly 10–26 and are decoded to the target grid by interpolation plus an exact mean/box repair. This lets the search communicate between different shape patterns with fewer interacting variables.

2. Global acceptance and scoring: all coarse candidates are immediately converted into a genuinely feasible full-resolution vector using the exact official constraints and objective. No smoothed objective is ever trusted.

3. Exact objective-preserving descent: after basin generation, use coordinate-pair descent. One move changes two unrelated variables along the mass-preserving line
   h_i += α, h_j -= α,
   with α searched by exact evaluations of the original correlation objective. The mass and box bounds are enforced analytically along each line.

4. Discrete-metric transformation diversity: include exact mass-preserving transformations such as anti-symmetric/complementary reflection, segment reversal, value swapping, and translations/free reversals followed by validation. These transformations do not claim any guarantee but are evaluated with the same original objective, allowing structural jumps.

The main difference from the previous program is replacing active-set linearization / smooth-max local smoothing as the primary method with:
- an actual global stochastic search in a compact decoded shape space, and
- direct exact one-dimensional coordinate-pair search on the FE grid, so accepted updates are validated by the original evaluator on the actual array.

1.2 Why this addresses the observed bottleneck

At a near-optimal local point, the active overlap constraints may be numerically balanced in several ways. Linearizing only the currently dominant lags can become insensitive to very small changes that require coordinated rearrangements. A hidden-shape evolution can discover analogs with different topology. Exact pair descent can then make detailed corrections even if the final solution has frequencies higher than the initial coarse shape.

1.3 Important limitations and honest status

- There is no global-optimality claim. The discrete problem is nonconvex because products h_i(1-h_j) appear in every overlap.
- The decoder can distort coarse parameters because feasibility repair chooses a vertical shift needed to match the required mass.
- Pair descent along two variables is not a full Newton step and does not guarantee escape from all local minima. It intentionally samples a different subspace form than linearized all-variable QP.
- Every candidate accepted for title status must be generated by exact vector building and exact score recomputation. Projections and transformations are heuristics, not proofs.

2. Mathematical specification

2.1 Discrete state and exact objective

For a vector h = [h_0,...,h_{n-1}], define

dx = 2.0 / n
F(h) = np.correlate(h, 1.0 - h, mode="full") * dx
C(h) = max(F(h)).

Equivalently, with lag

L = p - (n-1),  p = 0,...,2n-2

the unnormalized overlap corresponding to full-correlation position p is

F_L^raw(h) =
sum over all valid i of
h_i * (1 - h_{i+L}),

where valid means 0 <= i < n and 0 <= i + L < n. It may contain less than n terms at any nonzero lag. The inclusion of boundary terms is mandatory. No periodic/circular or full-correlation normalization should substitute for this exact expression at a nonzero lag.

Constraints for every returned vector:

1. 0 <= h_i <= 1 for all indices.
2. The sum must match the supplied evaluator convention

 sum_i h_i = n / 2.

Since the evaluator's integral condition is sum(h) * dx = 1, using dx=2/n makes the required raw sum exactly n/2.

All figures in bytes are merely evaluated numerically; retain the formula and all boundary terms. Keep lengths exact when returned unless an outside fallback physically has vmin/rint issues.
