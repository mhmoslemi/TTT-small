def _grad_matrix(h):
    n = len(h)
    G = np.zeros((2 * n - 1, n))
    for d in range(-(n - 1), n):
        r = n - 1 + d
        if d == 0:
            G[r, :] = 1.0 - 2.0 * h
        elif d > 0:
            m = n - d
            G[r, d:d+m] += (1.0 - h[:m])
            G[r, :m] += -h[d:]
        else:
            g = -d
            m = n - g
            G[r, :m] += (1.0 - h[g:])
            G[r, g:] += -h[:m]
    return G

Now for the SLSQP solver, I need to be careful. Let me think about the constraint structure more carefully.

For SLSQP, the constraints are:
- Equality: sum(h) = n/2
- Inequality: z - score_k(h) >= 0 for k in active set

The objective is to minimize z.

The key insight is that at the optimum, z = max_k score_k(h), and the active constraints are exactly those with score_k = z.

For the gradient, I need:
- d(f)/d(h) = 0 (f = z, so independent of h)
- d(f)/d(z) = 1
- d(constraint_k)/d(h) = -grad(score_k)/d(h)
- d(constraint_k)/d(z) = 1

This is correct.

Now, one issue: SLSQP might struggle if the initial z is too tight. Let me add a small slack.

Another issue: the problem is non-convex (bilinear), so SLSQP finds a local optimum. Multi-restart is important.

Let me also think about what "top_k" to use. If I use all 2n-1 constraints, the QP subproblem in SLSQP will be large. Let me use top-30 or so, and adaptively increase if needed.

Actually, for n=64, 2n-1=127 constraints. SLSQP should be able to handle this. The QP at each iteration has 65 variables and up to 128 constraints (127 + 1 equality). This is small.

Let me just use all constraints and see if it's fast enough. If not, I'll reduce.

Let me also add a line search after SLSQP to fine-tune.

Here's my refined plan:

Phase 1 (40% budget): SLSQP from initial point + a few neighbor points
Phase 2 (30% budget): Multi-restart SLSQP with random perturbations
Phase 3 (15% budget): Try different n values (resample + SLSQP)
Phase 4 (10% budget): Final polish (SLSQP + subgradient)
Phase 5 (5% budget): Binary search

One more thought: I should also try a "softer" constraint approach. Instead of hard epigraph constraints (z >= score_k), I can use a log-sum-exp penalty:

minimize z + mu * log(sum_k exp((score_k - z)/mu))

This is smooth and can be optimized with standard gradient methods. The parameter mu controls how closely we approximate the max.

Actually, this is equivalent to a Bregman-smoothed version of the max function. Let me use this as an alternative to SLSQP.

The gradient of the smoothed objective with respect to h_i is:
(mu * sum_k exp((score_k - z)/mu) * grad(score_k)_i) / (sum_k exp((score_k - z)/mu))

Which is a weighted average of the active gradients, weighted by exp((score_k - z)/mu).

This is actually a very natural approach! Let me implement it:

```python
def _smoothed_grad_step(h, z, mu, alpha):
    """Take a gradient step using the smoothed max."""
    n = len(h)
    scores = _scores(h)
    # Compute weights: w_k = exp((score_k - z) / mu)
    shifted = (scores - z) / mu
    # Clip to avoid overflow
    shifted = np.clip(shifted, -50, 50)
    w = np.exp(shifted)
    w /= np.sum(w)
    # Weighted gradient
    G = _grad_matrix(h)
    g = G.T @ w
    # Gradient descent step
    h_new = h - alpha * g
    return _project(h_new, n / 2.0)
```

This is essentially a "soft" version of the subgradient method. The scale parameter mu controls how many constraints are effectively active:
- Small mu: only the top constraint matters (like the LP approach)
- Large mu: all constraints are weighted equally

I can anneal mu from large to small to first balance all constraints, then focus on the max.

This is a different and potentially more effective approach! Let me combine it with SLSQP.

def _slsqp_solve(h, deadline, top_k=50, maxiter=60, ftol=1e-12):
    n = len(h)
    target = n / 2.0
    h = _project(h.copy(), target)
    scores0 = _scores(h)
    z0 = float(np.max(scores0)) + 0.5
    n_var = n + 1
    total_lags = 2 * n - 1
    if top_k > total_lags:
        top_k = total_lags
    
    # Select top constraints
    idx = np.argsort(scores0)[::-1][:top_k]
    
    x0 = np.concatenate([h, [z0]])

        return x[-1]

        g = np.zeros(n_var)

        return float(np.sum(x[:n]) - target)

        g = np.zeros(n_var)
        g[:n] = 1.0

        z = x[-1]
        s = _scores(h_x)
        return z - s[idx]

def _binary_init(n, h_guide):
    target = n // 2
    sorted_h = np.sort(h_guide)[::-1]
    if target > 0 and target < n:
        threshold = sorted_h[target - 1]
    else:
        threshold = 0.5

    if cnt > target:
        idx = np.where(b > 0)[0]
        order = np.argsort(h_guide[idx])
        for i in range(cnt - target):
            b[idx[order[i]]] = 0.0

        order = np.argsort(h_guide[idx])[::-1]
        for i in range(target - cnt):
