One optimization: instead of building the full G matrix every time, I can compute it more efficiently.

For G[p, k] where m = p - (n-1):

This can be computed as:
- First term: for each k, (1-h[k-m]) if k-m is in range
  This is a shifted version of (1-h)
- Second term: for each k, -h[k+m] if k+m is in range
  This is a shifted version of -h

So G[p, :] = shift(1-h, m) - shift(h, -m) where shift is a circular... no, non-circular shift with zero padding.

```python
def compute_gradient_matrix(h):
    n = len(h)
    n_lags = 2 * n - 1
    G = np.zeros((n_lags, n))
    one_minus_h = 1.0 - h
    for p in range(n_lags):
        m = p - (n - 1)
        # First term: (1-h[k-m]) for valid k
        if m >= 0:
            # k-m in [0, n-1] => k in [m, n-1]
            G[p, m:] = one_minus_h[:n-m]
        else:
            # k-m in [0, n-1] => k in [0, n-1+m]
            G[p, :n+m] = one_minus_h[-m:]
        # Second term: -h[k+m] for valid k
        if m >= 0:
            # k+m in [0, n-1] => k in [0, n-1-m]
            G[p, :n-m] -= h[m:]
        else:
            # k+m in [0, n-1] => k in [-m, n-1]
            G[p, -m:] -= h[:n+m]
    return G
```

    n = len(h)
    dx = 2.0 / n
    return float(np.correlate(h, 1.0 - h, mode='full').max() * dx)

def make_feasible(z):
    n = len(z)
    target = n / 2.0
    z = np.asarray(z, dtype=float).copy()
    z = np.clip(z, 0.0, 1.0)
    lo, hi = -2.0, 2.0
    for _ in range(80):
        mid = (lo + hi) / 2.0
        s = np.sum(np.clip(z + mid, 0.0, 1.0))
        if s < target:
            lo = mid
        else:
            hi = mid
    h = np.clip(z + (lo + hi) / 2.0, 0.0, 1.0)
    residual = target - np.sum(h)
    if abs(residual) > 1e-13:
        if residual > 0:
            order = np.argsort(1.0 - h)
        else:
            order = np.argsort(h)
        for idx in order:
            if residual > 0:
                add = min(residual, 1.0 - h[idx])
                if add <= 1e-15:
                    continue
                h[idx] += add
                residual -= add
            else:
                sub = min(-residual, h[idx])
                if sub <= 1e-15:
                    continue
                h[idx] -= sub
                residual += sub
            if abs(residual) < 1e-14:
                break

    h_int = np.interp(tgt_c, src_c, h_src)

def compute_grad(h):
    n = len(h)
    n_lags = 2 * n - 1

        else:

    return G

    G = compute_grad(h)
    
    d = cp.Variable(n)
    t = cp.Variable()
    
    d_lo = np.maximum(-h, -eps)
    d_hi = np.minimum(1.0 - h, eps)
    
    cons = [
        cp.sum(d) == 0,
        d >= d_lo,
        d <= d_hi,
    ]
    # Lag constraints: corr[p] + dx * G[p,:] @ d <= t
    # Vectorized: corr + dx * (G @ d) <= t
    cons.append(corr + dx * (G @ d) <= t)
    
    prob = cp.Problem(cp.Minimize(t), cons)
    
    try:
        prob.solve(solver=solver)
    except Exception:
        try:
            prob.solve(solver='SCS')
        except Exception:
            return None, None

        if np.all(np.isfinite(d_val)):
            h_new = make_feasible(h + d_val)
            sc = official_score(h_new)
            return h_new, sc
    return None, None

Hmm, the linearized prediction says O(0) stays at 0.5, but the actual value drops to 0.48. This is because the linearization of h*(1-h) at h=0.5 gives (1-2*0.5)*d = 0*d = 0, which is correct (the derivative of h(1-h) at h=0.5 is 1-2*0.5 = 0).

So the linearization is exact at the first order, and the quadratic term (which is -d^2) provides the actual improvement. This means the LP might not detect this improvement because the linearized model doesn't see it!

This is a fundamental limitation of the LP approach: it can't detect improvements that come from the quadratic (curvature) of the objective.

However, for the max function, the situation is different. If multiple lags are close to the maximum, the LP can find a direction that reduces all of them simultaneously, even if the individual lags have zero gradient in that direction. The "max" structure creates a non-differentiable point where the subdifferential is larger than the individual gradients.

Let me think about this more carefully. The subdifferential of max(f1, f2, ..., fm) at a point where f1 = f2 = ... = fk = max is the convex hull of the gradients of f1, ..., fk. The LP is essentially finding a direction that is in the "polar" of this subdifferential (i.e., a direction that decreases all active functions).

If the subdifferential doesn't contain 0 (i.e., there's a direction that decreases all active functions), the LP will find it. If 0 is in the subdifferential, the LP will conclude that no improvement is possible in the linear model.

In the example above (n=2, h=[0.5, 0.5]), the max is achieved at lag 1 (value 0.5). The subdifferential of the max at this point is just {G[1,:]} = {[0,0]}. So 0 is in the subdifferential, and the LP correctly concludes that no linear improvement is possible. The actual improvement comes from the curvature, which the LP can't see.

But in a more complex example with n=60, the max might be achieved at multiple lags, and the subdifferential might not contain 0. In that case, the LP can find an improvement direction.

So the LP approach is most useful when:
1. Multiple lags are close to the maximum (flat max)
2. The gradients of these active lags span a subspace that doesn't contain 0 in its "polar"

This is a good condition for the LP to be useful, and it's likely to occur in practice for the Erdős problem.

        else:

def compute_grad(h):
    n = len(h)
    n_lags = 2 * n - 1
    G = np.zeros((n_lags, n))
    omh = 1.0 - h
    for p in range(n_lags):
        m = p - (n - 1)
        if m >= 0:
            G[p, m:] = omh[:n - m]
            G[p, :n - m] -= h[m:]
        else:
            t = -m
            G[p, :n - t] = omh[t:]
            G[p, t:] -= h[:n - t]
    return G
