1. Approach and rationale

1.1 Central idea

The supplied parent construction is already in a narrow basin near the current best known numerical bound. The earlier style of search is dominated by scalar smoothed objectives, random two-coordinate exchanges, and opportunistic interpolation. Those methods can escape weak local minima but they do not directly attack the real bottleneck of the last one or two decimal places: several different lags in `np.correlate(h, 1 - h)` are typically blocked at almost the same value. To reduce the maximum below `0.3809`, one needs a move that simultaneously gives small signed linear reductions to the whole group of currently active lags while keeping the equality and box constraints feasible.

The proposed algorithm is therefore based on two new primary mechanisms:

1. Exact active-lag linearized minimax local solver.
   - At the current feasible vector `h`, compute all official lag values exactly using `np.correlate(h, 1 - h, mode="full") * dx`.
   - Select the currently maximum and near-maximum lags.
   - Build exact gradients of those lag functions.
   - Solve a convex linear programming subproblem: minimize a linearized upper bound `t` subject to linearized active-lag constraints, exact zero-sum direction constraints, current box directions, and a trust-region cap.
   - Try the resulting direction at several smaller step fractions and keep only points whose exact, authoritative objective strictly improves.

   This is materially different from the previous SLSQP/log-sum-exp or two-point-search approaches because the direction is not chosen by scalar smoothing of all lags or random pairwise swaps. It is chosen by an exact linear model evaluated on all active blocking lags simultaneously, then certified by the true objective.

2. Balanced binary search as a separate extreme relaxation.
   - Discrete step functions in `{0, 1}` with exactly `n/2` ones are feasible. They are subset endpoints of the continuum and often enable moves that the smooth log-sum-exp flow cannot reach.
   - Run a constrained simulated-annealing/binary local-search over balanced binary strings, initialized from the parent thresholding, deterministic patterns, and random balanced permutations.
   - Let binary discoveries enter the continuous pool as exact `0/1` arrays and as binary-averaged transformed arrays. Then continuous LP polishing can convert a kırık binary basin into a lower continuous feasible value.

The overall method is local and heuristic. It is not claimed to be globally optimal. Every returned value is valid only after being certified with the original evaluator. If it improves the incumbent, it is a valid new numerical upper bound for the discrete problem.

1.2 What bottlenecks the new method addresses

- Bottleneck A: active blocking set.
  When the score is near zero, the maximum over `2n-1` lags is held by many lags. Reducing a strict global maximum therefore requires directions that make every currently restrictive linearized constraint decrease. Random two-point coordinate movements do not enforce this. The LP solves a minimax linear convex relaxation and enforces it explicitly for a chosen active set.

- Bottleneck B: poor boundary and family slip sinelerini from ultimate temperature.
  Binary states can make the entire score distribution even and sometimes find configurations unavailable to the parent's continuous basin. This gives independent starts for the nonconvex continuous method.

- Bottleneck C: reliability of surrogate.
  The LP never uses its exact-objective acceptance. The linearized solution itself can violate thresholds due to nonconvex quadratic interactions. A candidate is accepted only if exact `max(np.correlate(...)) * dx` is smaller. If the LP direction is bad, it is not allowed into the continuous path.

- Bottleneck D: infeasible joint bounds and mass sum.
  Simple projection followed by scalar rescaling is not used. A single joint feasibility routine performs shape-preserving monotone shifting followed by a greedy exact residual repair, always respecting both `0 <= h_i <= 1` and sum equality up to machine precision.

1.3 Distinctness from previous proposals

Earlier programs emphasized smoothed max (log-sum-exp) plus two-point random exchanges, active two-coordinate jumps, or generic local descent. The proposed main solver is a deterministic LP minimax step on exact active-lag gradients with a trust-region capped step, combined with a balanced binary extreme search that uses the constraints exactly by bit swaps. This changes the search space structure and the local step formulation rather than simply tuning hyperparameters or adding a surrogate/preconditioner.

The LP subproblem is convex because it contains only linear equality constraints, variable bound constraints, and linear inequalities. The underlying full problem remains nonconvex because the exact lag functions are quadratic and the objective is max over them. Convexity is claimed only for the linearized trust-region subproblem. No global optimality is claimed.

1.4 Hypotheses versus established facts

Established:
- The objective values used for final score must be exact discrete evaluates using `np.correlate(h, 1-h, mode="full") * dx`.
- If a returned vector is feasible and its score is smaller, then it proves a smaller discrete upper bound.
- The active-lag LP step direction is computed from valid analytic gradients and is constructed to satisfy linearized constraints by formulation, though exact feasibility is enforced afterward.

Hypotheses:
- Active-lag LP directions will reduce the exact maximum more than random or pairwise coordinates near the incumbent.
- Binary balanced states often reveal better basins for the discrete relaxation, and LP polishing of binary-derived starts can produce continuous improvements.
- Resolution changes can translate a good continuous function from one grid into a better legal sequence with the exact official objective; this is checked only empirically and accepted only when exact score improves.

2. Mathematical specification

2.1 Discrete representation and official objective

Let `n` be the number of returned samples.

Let
```
dx = 2.0 / n
```
and let `h` be a real array of shape `(n,)`.

Constraints, to be enforced numerically:
```
0 <= h[i] <= 1 for every i
sum_i h[i] = n / 2
```
The sum equality is continuous. For final floating-point vectors, require `abs(sum(h)-n/2) <= 1e-9` or tighter; the helper repair maker should make it as close to machine precision as reliably possible.

Official objective, repeated verbatim:
```
C(h) = max_k [ correlate(h, 1-h, mode="full")[k] * dx ]
```
where the full correlation result has length `2n-1`. The return value of the implementation must equal the maximum of these values. No other formula may be used for scoring, even for diagnostics.

2.2 Lag indexing and orientation validation

For each full correlation index `p = 0, ..., 2n-2`, define the center lag index
```
q = p - (n - 1)
```
for a root convention. Because of possible numpy indexing convention differences between `correlate` and a manually implemented term, the implementation must use a manually validated gradient convention.

Define one root lag convention A: for integer shift `s = q_A`, for `s >= 0` the raw sum is
```
R_A(h, s) = Σ_{i=0}^{n-1-s} h[i] * (1 - h[i + s])
```
and for `s < 0`
```
R_A(h, -t) = Σ_{j=0}^{n-1-t} h[j + t] * (1 - h[j])
```
with `t = -s > 0`. This subpair convention is exactly the one whose derivative is easy to write.

Then define the full root-A raw array as the array length `2n-1` ranging over all `s = -(n-1), ..., n-1` and stored at corresponding `p = s + n - 1`.

At runtime, test against numpy:
```
truth = np.correlate(sample_h, 1 - sample_h, mode="full")
rootA = root_A_raw(sample_h)
```
and compare using official scale tolerance. If rootA equals truth (or equals truth divided by `dx`; choose a convention once), use gradient orientation `identity`:
```
if corr index p is selected, s = p - (n - 1)
```
If reversed comparison
```
truth[p] = rootA[2n - 2 - p]
```
holds, use orientation `reversed_full`:
```
if corr index p is selected, s = (2n - 2 - p) - (n - 1)
```
If neither matches within tolerance, compute gradients of selected lags by central finite differences for that selected p. This fallback is acceptable because it uses the truth function itself. The algorithm may oscillate slightly, but all exact scores remain authoritative.

2.3 Gradient formulas

Let official lag values include `dx`:
```
V_p(h) = dx * raw_p(h)
```

For root-A raw value with shift `s`:

For `s >= 0`, for all valid `i = 0, ..., n-1-s`
```
term = h[i] * (1 - h[i + s])
```
Derivative with respect to `h[i]` is
```
dx * (1 - h[i + s])
```
Derivative with respect to `h[i + s]` is
```
dx * (- h[i])
```
Accumulate all contributions by summing several raw loops into one length-`n` gradient. For `s = 0`, adding both contributions gives the correct derivative `dx * (1 - 2h[i])` for diagonal pairs.

For `s < 0`, let `t = -s`, and valid raw terms are
```
term = h[j + t] * (1 - h[j]), j = 0, ..., n-1-t
```
Derivative at `h[j + t]` is
```
dx * (1 - h[j])
```
Derivative at `h[j]` is
```
dx * (- h[j + t])
```
Again accumulate.

With the orientation mapping described above, each selected official p maps to a root shift `s` and a derivative row `g_p`.

Urgent variables and LP objective are in values of `V_p`, which already include `dx`. Consequently the direction `u_i` remains in raw step units of `h`, not correlation-scaled units.

2.4 LP local subproblem

At a current feasible iterate `h` let
```
V = official_values(h)
C = max(V)
```
Select a finite active or near-active set `A` of correlation indices. For algorithm efficiency and robustness, `A` is not necessarily all p. At most a set top-K plus values above a user-defined threshold. The set will contain the current max and recently blocking lags.

Let
```
g_p ∈ R^n
c_p = V[p]
```
for each `p ∈ A`.

Variables in LP:
```
u_i, i=0..n-1          step in h
t                      linearized maximum bound
```
Variable bounds:
For each coordinate `i`:
```
u_i ∈ [max(-h_i, -rho), min(1-h_i, rho)]
```
where `rho` is a positive trust radius in original `h` units. This choice ensures an alpha=1 step cannot exit the `[0,1]` bounds, except numerical tolerance. The final repair clip/mean correction can still enforce official feasibility.

Equality:
```
Σ_i u_i = 0
```
This keeps the sum relative infinitesimal when `sum h = n/2`.

Linearized lag constraints for selected A:
For each selected p:
```
g_pᵀ u + c_p <= t
```
or equivalently
```
g_pᵀ u - t <= -c_p
```

Objective:
```
minimize t
```
The alarm theory issue is preventing arbitrary movement after strict upstream constraints. Minimizing `t` alone increases the best possible linear maximum. If there is no predicted decrease `t < C`, feasibility still exists because `u=0, t=C` but `t` is the objective; a strict feasible solution of lesser value is a predicted direction.

Formulator of subproblem:
```
min_{u,t} t
subject to:
g_pᵀ u - t <= -c_p,  p in A
Σ_i u_i = 0
max(-h_i, -rho) <= u_i <= min(1-h_i, rho)
```
This subproblem is convex. It may be infeasible if a predicted improvement under active constraints is not possible due bounds, but the zero vector is always feasible at worst if constraints are satisfied in the lightly, since `0 <= rho` and `t=C` satisfies inequalities when active values `c_p<=C`. `t` should be set up with upper bound `<= C` to prevent candidate pollution parameters. But algorithmic implementation can include variable t bound also `(None or -inf, C, rho)`. If using a simplified bounds API, equality matters say an objective with a penalty for absolute movement is possible as specified variation; default no penalty is easier.

The full nonlinear objective still has `V` max over all lags, not selected A. Therefore any point `h + alpha u` is accepted after exact `C(h + alpha u)` if it exactly lowers the objective.

2.5 Zero-sum and joint feasibility repair

Before proposing a direction in LP solve and after line search, use a single robust routine `make_feasible(z)`.

Inputs: arbitrary real array length `n`.

Steps:
1. Convert to a float64 1-D array.
2. For values that are NaN or infinite, replace with 0.5. If the whole array is non-finite, fill the entire array with 0.5.
3. Clip to `[0, 1]`.
4. Define target sum `target = float(n)/2.0`.
5. First perform monotone shift bisection to preserve shape:
   - Comfort mapping `Phi(a)=np.sum(np.clip(z+a,0,1))`.
   - Bisection search `a` in `[-2.0,2.0]` for `Phi(a)=target`, 80 iterations.
   - Set intermediate `h = clip(z + r, 0, 1)`.
6. Recompute residual:
```
residual = target - np.sum(h)
```
7. Repair residual exactly with greedy methods respecting bounds.
   - If residual > 0, sort indices by largest remaining slack `1-h_i` descending. Add `min(residual, slack_i)` to heaviest indices until residual close to zero within `1e-12` or more; skip tiny increments below double threshold.
   - If residual < 0, sort by largest `h_i` descending and subtract `min(-residual,h_i)` until zero.
8. Repeat residual repair if clipping residual occurs. Guarantee point length remains in `[0,1]` because updates are capped by slack/cap听众 and final `np.clip` with small tolerance. Enforce bounds by adding tiny machine uniforms if numeric clipping produces very small above 1.

This is a joint feasible repair. It is not clipping followed by a separate scalar rescaling of a clipped array; two-constraint enforcement remains bracket by monotone bisection with final massing. It is a projection on both constraints but based on shape-preserving conversion; acceptable because the exact optimum is not required for failed candidates.

Use `make_feasible()` for every candidate before exact score evaluation, including random perturbed states, interpolated candidates, binary continuous states, and final vector.

2.6 Binary representation target

For binary sequences, feasible constraints can be guaranteed exactly without repair by the construction property.

State: integer array `b` length `n` with values 0 or 1 and
```
np.sum(b) == n // 2
```
Use only even `n` for binary states. The parent n=60 is consistent. If an operation gives odd length, do not make a binary string. Convert or discard; continuous methods can continue with even and odd lengths.

Score for binary state is simply `score_exact(1.0 * b)`; no LP gradient is necessary.
