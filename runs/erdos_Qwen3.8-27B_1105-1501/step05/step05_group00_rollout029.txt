Let me also think about what makes a good binary sequence for this problem.

For a sequence with n/2 ones, the ideal would be to have the ones as "spread out" as possible, so that at every shift k, approximately half of the n-k overlapping pairs have matching values. The "stretch" of the sequence (how spread out the 1s are) determines the correlation.

A roughly uniform distribution of 1s (alternating 010101...) would give:
- At even shifts: all pairs match → c_k = 0
- At odd shifts: all pairs differ → c_k = (n-k)/2 approximately

Wait, for alternating 0101...:
- At shift 1: every adjacent pair differs, so count_10(1) = (n-1)/2 and count_01(1) = (n-1)/2 (approximately)
- At shift 2: every pair matches, so count_10(2) = 0, count_01(2) = 0
- At shift 3: same as shift 1

So the max would be at odd shifts, giving C5 ≈ (n-1)/2 * 2/n ≈ 1. That's terrible!

What about a more structured sequence? Let's think about what minimizes the max.

For a random binary sequence with n/2 ones:
- E[count_10(k)] ≈ (n-k)/4 (since for each pair, P(h[i]=1, h[i+k]=0) = 1/2 * 1/2 = 1/4 in the random case, but with the constraint of exactly n/2 ones it's slightly different)
- Actually with exactly n/2 ones: P(h[i]=1) = 1/2, P(h[i+k]=0) = 1/2, and they're not independent but approximately so for large n.
- So E[count_10(k)] ≈ (n-k)/4
- max over k of (n-k)/4 is at k=1, giving (n-1)/4
- C5 ≈ (n-1)/4 * 2/n ≈ 1/2

So random gives about 0.5, and we're at 0.38, which is significantly better.

The optimal structure is something like a "difference set" or "Bose-Chowla" type construction where the autocorrelation is as flat as possible.

```python
def project_to_sum(v, target):
    """Project v to [0,1]^n with sum = target (water filling)."""
    n = len(v)
    if target <= 0:
        return np.zeros(n)
    if target >= n:
        return np.ones(n)
    lo, hi = -1.0, 2.0

        if s > target:
            lo = mid
        else:

    sorted_idx = np.argsort(-h)
    b = np.zeros(n)
    b[sorted_idx[:target]] = 1.0
    return b

def compute_F(h):

    n = len(h)

    p_idx = np.arange(2*n-1)[None, :]
    F = hp[x_idx - p_idx + 2*(n-1)] + hp[x_idx + p_idx]
    return F

            new_maxes = np.max(c[None, :] + F_i[None, :] - F_j, axis=1)

            best_val = float(new_maxes[np.argmin(new_maxes)])
            if best_val < best_delta:

                best_i = int(i)
                best_j = int(best_j_local)

            h[best_j] = 1.0

            cur_c5 = float(np.max(c))
            if cur_c5 < best_c5:

                best_h = h.copy()
            no_improve = 0
        else:

                flip_zeros = rng.choice(zeros_idx, size=min(n_flips, len(zeros_idx)), replace=False)

                zeros_idx = np.where(zeros_mask)[0]
```

```python
def compute_delta(F, i, j, n):
    """Compute delta to correlation for flipping h[i]:1->0, h[j]:0->1."""
    delta = F[i] - F[j]  # shape (2n-1,)
    # Add corrections for diagonal lags
    p1 = n - 1 + (i - j)
    p2 = n - 1 + (j - i)
    if 0 <= p1 < 2*n - 1:
        delta[p1] += 1.0
    if 0 <= p2 < 2*n - 1 and p2 != p1:
        delta[p2] += 1.0
    return delta
```

Since i ≠ j, p1 ≠ p2 always (p1 - p2 = 2(i-j) ≠ 0). And both are in range [0, 2n-2] since |i-j| ≤ n-1 (because i,j ∈ [0,n-1]).

So the correction is always valid: both p1 and p2 are in range.
