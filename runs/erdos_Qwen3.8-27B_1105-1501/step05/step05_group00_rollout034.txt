Wait, I realize I'm overcomplicating this. Let me look at the gradient more carefully.

For corr at lag d ≥ 0: corr_d = ∑_{i=0}^{n-d-1} h[i] * (1 - h[i+d])

∂corr_d/∂h[j] = (1-h[j+d]) if j ≤ n-d-1, PLUS (-h[j-d]) if j ≥ d

These are not mutually exclusive! If j is in [d, n-d-1], both terms contribute:
∂corr_d/∂h[j] = (1-h[j+d]) - h[j-d]

For binary h, the exact change in corr_d when h[j] changes by δ (from 0 to 1 or 1 to 0) is:
δ * [(1-h[j+d]) * I(j ≤ n-d-1) - h[j-d] * I(j ≥ d)]

This is because corr_d is linear in h[j] when we fix all other h values (it's a product h[a]*h[b] type, and j appears in at most two such products).

Wait, actually h[j]*(1-h[j+d]) = h[j] - h[j]*h[j+d]. This is quadratic in the vector h but linear in h[j] alone (treating h[j+d] as constant). Similarly h[j-d]*(1-h[j]) = h[j-d] - h[j-d]*h[j], also linear in h[j].

So yes, the partial derivative gives the exact change for a unit flip. 

So for a binary sequence, the change in corr[q] from flipping h[i] is:
- If h[i] was 1 (flip to 0): Δcorr[q] = -∂corr[q]/∂h[i] = -(grad[q,i])
- If h[i] was 0 (flip to 1): Δcorr[q] = +∂corr[q]/∂h[i] = +(grad[q,i])

And for a swap (h[i]: 1→0, h[j]: 0→1):
Δcorr[q] = -grad[q,i] + grad[q,j]

This is EXACT for binary h! No second-order terms because the function is multilinear.

This is great. So I can precompute the gradient matrix for a binary h, and then the change in any corr[q] from a swap is just grad[q,j] - grad[q,i].

Now, for the objective C₅ = max(q) corr[q] * dx, the change from a swap is not simply the max of the changes (since different lags might be the active one). But I can use the gradient to rank moves:
- Let M = max(q) corr[q] (the current max, before dx scaling)
- The "worst" lags are those with corr[q] ≈ M
- A good move reduces the active lags without increasing others too much
- A simple heuristic: minimize the max of (corr[q] - grad[q,i] + grad[q,j]) over q

This is equivalent to: for each swap (i,j), compute the new max correlation, and pick the swap that minimizes it.

For n=122, there are about 61*61 ≈ 3721 possible swaps. Computing the new max for each is O(2n-1) = O(243). Total: 3721 * 243 ≈ 900K operations per iteration. That's very fast! We can do thousands of iterations per second.

Actually, we can vectorize: for all i (ones) and all j (zeros), compute the new corr vector:
new_corr = corr - grad[:, i] + grad[:, j]

For all pairs at once:
new_corr[i,j,:] = corr[None,None,:] - grad[:,:,None,i]... 

Hmm, this would be 61*61*243 ≈ 900K floats ≈ 7MB. That's fine!

So the algorithm for one tabu iteration:
1. Compute grad matrix (O(n²) or so)
2. For all (i,j) pairs (i in ones, j in zeros): compute new_corr_max[i,j] = max_q (corr_q - grad_qi + grad_qj)
3. Pick the (i,j) that minimizes new_corr_max (with tabu constraints)
4. If the new max < current max (or aspiration), perform the swap
5. Update

This is a full best-improvement tabu search, which should be very effective.

def _project(v, target):

        else:

def _grad_matrix(h):
    n = len(h)
    G = np.zeros((2*n-1, n))
    for d in range(-(n-1), n):
        r = n - 1 + d
        if d >= 0:
            m = n - d
            G[r, :m] += (1.0 - h[d:d+m])
            if m > d: G[r, d:m] += -h[:m-d]
        else:
            g = -d; m = n - g
            G[r, :m] += -h[g:g+m]
            if m > g: G[r, g:m] += (1.0 - h[:m-g])
    return G
