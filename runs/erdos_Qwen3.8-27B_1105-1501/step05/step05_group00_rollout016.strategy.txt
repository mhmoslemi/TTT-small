   `dx = 2.0/n`, under `0 <= h_i <= 1` and `sum_i h_i = n/2`. The parent has

   active part of the max-over-lags objective.

   The primary algorithmic idea is materially different from the previous large
   LP/SA/line-search pipeline. The core of the proposed method is an exact
   epigraph nonlinear-programming (NLP) stage: introduce the objective value as
   an auxiliary scalar variable `t`, and solve a local problem of the form

   `minimize t + flex regularizer`,
   subject to `t - F_r(h) >= 0` for every lag row `r`,
   `sum_i h_i = n/2`, and `0 <= h_i <= 1`,

   where `F_r(h) = dx * correlation row r`. The rows are exact differentiable
   quadratic constraints. The auxiliary `t` is allowed to start slightly above
   the exact `C5` of the current vector and is then driven downward by SLSQP.
   Any solution is accepted only after projecting back to exact feasibility and
   re-evaluating with the real evaluator. This directly addresses the L-∞
   bottleneck (`t >= F_r(h)` active constraints) instead of repeatedly testing
   heuristic pairwise moves or bilinear LP linearizations.

   To make the method robust, the NLP stage is complemented by two exact local
   modules:

   1. An active-ridge steepest direction derived from the first-order
      derivatives of the currently active or near-active covariance rows.
      This direction is obtained by a small ridge least-squares solve in the
      sum-zero tangent space. It is a coherent descent proposal, not a pair of
      arbitrary coordinates, and it is accepted only if an exact safe directional
      line search lowers the true `np.correlate` score.

   2. Multi-resolution transfer support. The supplied parent is always retained
      as a valid fallback. If a separately optimized shorter vector has a
      strictly better exact value, it is returned; otherwise the parent or the
      best accepted continuous file is returned.

   The method remains heuristic and nonconvex. No global optimality is claimed;
   the improvement is produced by exact acceptance under the task's own evaluator.
