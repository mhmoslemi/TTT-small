def _binary_local_search(h, deadline):
    n = len(h)
    dx = 2.0 / n
    S = np.correlate(h, 1 - h, mode='full').astype(float)
    cur_max = S.max()
    best_h = h.copy()
    best_S = S.copy()
    best_max = cur_max
    
    while time.time() < deadline:
        dc, ds = _compute_deltas(h, n)
        ones = np.where(h == 1)[0]
        zeros = np.where(h == 0)[0]
        
        improved = False
        best_delta = 0
        best_a, best_b = -1, -1
        
        for a in ones:
            base = S + dc[a]
            # For all b in zeros:
            candidates = base[None, :] + ds[zeros, :, None]  # shape (n_zeros, 2n-1)
            new_maxes = candidates.max(axis=1)
            idx = new_maxes.argmin()
            if new_maxes[idx] < cur_max - 1e-10:
                b = zeros[idx]
                if new_maxes[idx] < cur_max - best_delta:
                    best_delta = cur_max - new_maxes[idx]
                    best_a, best_b = a, b
                    best_new_S = S + dc[a] + ds[b]
        
        if best_a >= 0:
            h[best_a] = 0
            h[best_b] = 1
            S = best_new_S
            cur_max = best_new_S.max()
            improved = True
            if cur_max < best_max:
                best_max = cur_max
                best_h = h.copy()
                best_S = S.copy()
        
        if not improved:
            break
    
    return best_h, best_max * dx, best_S

So yes, the global minimum is at a vertex of the hypersimplex, which is a 0-1 vector with n/2 ones.

This is a crucial insight. The problem is purely combinatorial!

Now, the question is: what n to use? The problem says "smaller sequences with less than 2k samples are preferred." So I should try various n values and pick the one with the best C5.

For a binary vector h of length n with n/2 ones:
C5 = (2/n) * max_d S_d

where S_d is an integer count. So C5 = 2 * max_d S_d / n.

To minimize C5, I want to minimize max_d S_d relative to n.

Let me think about what's achievable. For a "random" binary vector with n/2 ones, the expected S_d for lag d is approximately (n-d)/4 (since each pair independently has probability 1/4 of being (1,0)). So the max over d would be around (n/4) + O(sqrt(n)). Then C5 ≈ 2*(n/4)/n = 1/2. That's not great.

For a better construction, we want to minimize the maximum overlap. This is related to the problem of finding a binary sequence that minimizes the maximum autocorrelation (or cross-correlation with its complement).

The Erdős problem is about finding a binary sequence of length N with low maximum overlap. The constant C is the infimum over all sequences of (1/N) * max_overlap. Here we have a slightly different setup (length 2, n points, the correlation is over the given length), but the ideas are similar.

For the specific case of length n with n/2 ones, the minimum possible max S_d is at least n/8 (by averaging argument: sum of all S_d = sum over all pairs (i,j) with i≠j of h[i]*(1-h[j]) = (n/2)*(n/2) = n^2/4. There are 2n-1 lags, so average S_d ≈ n^2/4 / (2n) = n/8). So C5 >= 2*(n/8)/n = 1/4 = 0.25.

But the actual minimum is higher due to the constraint that consecutive lags are correlated. The best known constructions give C ≈ 1/3 or so for long sequences.

def _resample_binary(h_old, n_new):
    n_old = len(h_old)
    x_old = (np.arange(n_old) + 0.5) / n_old
    x_new = (np.arange(n_new) + 0.5) / n_new
    h_cont = np.interp(x_new, x_old, h_old)
    target = n_new // 2
    idx = np.argsort(-h_cont)
    h_new = np.zeros(n_new)
    h_new[idx[:target]] = 1
    return h_new
