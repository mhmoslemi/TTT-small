def _project(v, target):
    """Project v onto {x : 0 <= x_i <= 1, sum(x) = target} using bisection on threshold."""
    n = len(v)
    if target <= 0:
        return np.zeros(n)
    if target >= n:
        return np.ones(n)
    lo = float(v.min()) - 2.0
    hi = float(v.max()) + 2.0

        s = float(np.sum(np.clip(v - mid, 0.0, 1.0)))

        else:

    x = np.clip(v - (lo + hi) / 2.0, 0.0, 1.0)

            x = np.clip(x, 0.0, 1.0)

Let me also think about a different kind of move for the binary search: **block moves**. Instead of swapping individual bits, swap contiguous blocks. This can lead to larger jumps in the landscape.

For a block move: swap a block of length L starting at position i with a block of length L starting at position j. This changes 2L positions. The effect on the scores can be computed similarly.

But for now, let me stick with 2-swaps and see if that's enough.

Let me also add a **softmax-based continuous optimizer** as a separate phase:

The smoothed objective is:
f_β(h) = (1/β) * log(sum_k exp(β * s_k(h)))

For large β, this approximates max_k s_k. The gradient is:
∇f_β = (1/sum exp(β s_k)) * sum_k β * exp(β s_k) * ∇s_k

This is a weighted average of the gradients of the individual s_k, with weights proportional to exp(β s_k) / sum exp(β s_k). These weights concentrate on the lags near the maximum.

The projected gradient step is:
h_new = project(h - α * ∇f_β)

where project maps to {0 ≤ h ≤ 1, sum h = n/2}.

This is smooth and can be optimized with line search. For β → ∞, it converges to the subgradient of the max.
