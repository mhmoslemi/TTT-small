```python
    # F[i,d] = -(1-h[i+d]) + h[i-d] (with validity)
    # G[i,d] = (1-h[i+d]) - h[i-d] (with validity)
    # So F[i,d] + G[i,d] = 0
    
    # Wait, that means delta(i,j) = F[i] + G[j] = F[i] - F[j]!
    # Because G[j] = -F[j].
    
    # Let me verify: 
    # delta(i,j,d) = -(1-h[i+d]) + h[i-d] + (1-h[j+d]) - h[j-d]
    # = [-(1-h[i+d]) + h[i-d]] + [(1-h[j+d]) - h[j-d]]
    # = F[i,d] + G[j,d]
    # And G[j,d] = -(F[j,d]) only if the validity conditions are the same
    # But they're not: F[i,d] has i+d and i-d, while F[j,d] has j+d and j-d
    # So G[j,d] ≠ -F[j,d] in general (the validity masks differ)
    
    # Actually wait:
    # F[i,d] = -(1-h[i+d])*[0≤i+d<n] + h[i-d]*[0≤i-d<n]
    # G[j,d] = (1-h[j+d])*[0≤j+d<n] - h[j-d]*[0≤j-d<n]
    # -F[j,d] = (1-h[j+d])*[0≤j+d<n] - h[j-d]*[0≤j-d<n] = G[j,d]
    
    # YES! G[j,d] = -F[j,d]!
    # So delta(i,j,d) = F[i,d] - F[j,d]
    
    # This means: new_c[d] = c[d] + F[i,d] - F[j,d]
    # And I only need to compute F, not G!
```

Let me now think about the vectorized computation of F:

```python
def compute_F(h):
    n = len(h)
    lags = np.arange(-(n-1), n)  # (2n-1,)
    F = np.zeros((n, 2*n-1))
    for i in range(n):
        # Term 1: -(1-h[i+lag]) for 0 <= i+lag < n
        idx1 = i + lags
        v1 = (idx1 >= 0) & (idx1 < n)
        F[i, v1] -= (1.0 - h[idx1[v1]])
        # Term 2: +h[i-lag] for 0 <= i-lag < n
        idx2 = i - lags
        v2 = (idx2 >= 0) & (idx2 < n)
        F[i, v2] += h[idx2[v2]]
    return F
```

This is O(n * 2n) = O(2n²) in a Python loop, but each iteration is vectorized over 2n elements. For n=122, that's 122 iterations of vectorized ops on arrays of length 243. Very fast.

Can I fully vectorize it? Let me think...

For all i and all lags:
idx1[i, m] = i + lags[m]
v1[i, m] = (idx1[i,m] >= 0) & (idx1[i,m] < n)
F[i, m] = -(1-h[idx1[i,m]]) * v1[i,m] + h[idx2[i,m]] * v2[i,m]

where idx2[i,m] = i - lags[m], v2[i,m] = (idx2[i,m] >= 0) & (idx2[i,m] < n).

I can build idx1 as an (n, 2n-1) matrix using broadcasting:
idx1 = np.arange(n)[:, None] + lags[None, :]
idx2 = np.arange(n)[:, None] - lags[None, :]

Then:
v1 = (idx1 >= 0) & (idx1 < n)
v2 = (idx2 >= 0) & (idx2 < n)
F = np.where(v1, -(1.0 - h[idx1]), 0.0) + np.where(v2, h[idx2], 0.0)

Wait, but h[idx1] where idx1 might be out of bounds... I need to handle that.

Actually, np.where evaluates both branches, so I can't directly use h[idx1] where idx1 might be out of bounds. I need to use a safe indexing:

safe_idx1 = np.clip(idx1, 0, n-1)
F = -(1.0 - h[safe_idx1]) * v1 + h[safe_idx2] * v2

where safe_idx2 = np.clip(idx2, 0, n-1).

This works! Let me verify:
- When v1[i,m] = True: F[i,m] includes -(1-h[idx1[i,m]])
- When v1[i,m] = False: the term is 0 (multiplied by v1)
- The safe indexing ensures we don't go out of bounds

This fully vectorizes the computation of F in O(n * 2n) = O(2n²) numpy operations, all at once. For n=122, this is a (122, 243) matrix operation, which is very fast.

```python
def greedy_pass(h, corr, max_corr, F, ones_idx, zeros_idx):
    # new_maxs[i,j] = max_m (corr[m] + F[ones_i, m] - F[zeros_j, m])
    F_ones = F[ones_idx]  # (n_ones, 2n-1)
    F_zeros = F[zeros_idx]  # (n_zeros, 2n-1)
    
    # temp[i,j,m] = corr[m] + F_ones[i,m] - F_zeros[j,m]
    temp = corr[None, None, :] + F_ones[:, None, :] - F_zeros[None, :, :]
    new_maxs = temp.max(axis=2)
    
    best_idx = np.unravel_index(np.argmin(new_maxs), new_maxs.shape)
    best_val = new_maxs[best_idx]
    
    if best_val < max_corr - 1e-15:
        i = ones_idx[best_idx[0]]
        j = zeros_idx[best_idx[1]]
        h[i] = 0.0
        h[j] = 1.0
        corr = corr + F[i] - F[j]
        max_corr = np.max(corr)
        return h, corr, max_corr, True, i, j
    else:
        return h, corr, max_corr, False, -1, -1
```

Wait, but after the swap, F changes! Because h[i] and h[j] changed. So I need to recompute F.

But the change in F is local: only F[i] and F[j] change (and the entries of F[k] where k is related to i or j through the lag).

Actually, F[k, m] depends on h[k+lag_m] and h[k-lag_m]. So if h[i] changes, it affects:
- F[k, m] where k+lag_m = i, i.e., k = i - lag_m for each m
- F[k, m] where k-lag_m = i, i.e., k = i + lag_m for each m

For a given m (lag d = m - n + 1):
- k = i - d: F[k, m] has the term h[k+d] = h[i], which changed
- k = i + d: F[k, m] has the term h[k-d] = h[i], which changed

So for each m, two entries of F change (at rows i-d and i+d).

In total, changing h[i] affects O(2n) entries of F (2 entries per each of the 2n-1 lags).
