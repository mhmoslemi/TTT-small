1. Approach and rationale
- Central idea: instead of relying only on local derivative or linearization steps around the supplied parent, search the feasible set with exact two-coordinate transfer moves that always preserve `sum(h)=n/2` and the box bounds, then polish the best exact candidates with multi-resolution interpolation and a conservative active-lag descent phase. The exact evaluator is used for every proposal that may change global `C5`, so surrogate speeds are never needed for correctness. The nonconvex quadratic nature is accepted directly.
- Why this could improve the supplied parent: the parent optimization appears close to a local optimum of a derivative-trust-region method. Exact pair-transfer annealing can move by finite amounts across the full interval, can flip near-binary h values, can cross flat regions where no small first-order descent direction is found, and can generate continuous candidates of different resolutions. Any candidate is accepted globally only if its exact evaluator score is smaller than the best seen score.
- Primary method: a global pair-transfer simulated annealing layer, seeded in many ways from the parent and from exact randomized or quantized initializations, followed by deterministic polish layers (pair line search, grouped coordinate transfer, multi-resolution resampling, and optional active-lag linearization if implemented). This addresses the bottleneck that the previous program over-relies on incremental LP or gradient fields within a small trust region, and it maintains exact feasibility by transfer rather than by clipping-and-renormalizing, which can both spoil box constraints and increase the objective.
- Limitations and plausible corrections: the search is only locally/global meta-heuristic; no convex relaxation should be treated as a proof of global optimality. If no exact candidate improves the parent due to time overhead, the exact parent, after a conservative projection or a previously accepted exact candidate, is returned. All mathematical recommendation levels are heuristic unless explicitly marked as exact facts.

2. Mathematical specification
2.1 Exact representation
- For a vector `h` of length `n`, define `dx = 2.0 / n`.
- Store values on cell centers by interpretation, but for the objective, just apply the evaluator operation:
  `C5(h) = max_k np.correlate(h, 1.0 - h, mode="full") * dx`.
- Feasible domain:
  - `0 <= h[i] <= 1` for every `i`.
  - `sum(h) = n / 2.0` exactly within a strict numerical tolerance.
- `n` may differ between candidates; compare only after evaluating the evaluator exactly for that particular `n`.
- `np.correlate` is full linear correlation over finite support, `-n+1` through `n-1` conceptual shifts. Both directions are included, and boundary handling must come from `np.correlate`, not from a periodic wrap.

2.2 Dollar exact objective computation
- `_exact_c5(h)` must:
  1. Convert h to a float array and ensure no NaN values.
  2. compute `scores = np.correlate(h, 1.0 - h, mode="full")`.
  3. return `float(np.max(scores)) * (2.0 / len(h))`.
- The function is always authoritative. If any surrogate smooth max, linearization, or coupling-weight model is used, it is allowed only for generating proposals, never to accept a solution without re-checking `_exact_c5`.

2.3 Exact feasible coordinate transfers
- A two-coordinate transfer is a move `(delta_i, delta_j)` where
  - `h[i] = h[i] + delta_i`,
  - `h[j] = h[j] + delta_j`,
  - `delta_i + delta_j = 0`,
  - `0 <= new h[i] <= 1` and `0 <= new h[j] <= 1`.
- This forms an exact feasible move if the current h is feasible, because the total sum changes by `delta_i + delta_j = 0`. Bounds are acceptable when `delta_i` is chosen within both tight-room constraints.
- Generic transfer formula to lower i and raise j:
  - Let `cap = min(h[i], 1.0 - h[j])`.
  - Pick `delta = cap * q` with `0 < q <= 1`.
  - Apply `h[i] -= delta`, `h[j] += delta`.
- If `cap` is nonpositive or too small, the proposal is rejected without evaluation. This move is exact and avoids any projection via construction.

2.4 Exact feasibility repair / clip projection
- For an arbitrary candidate vector `v` imported by interpolation or perturbation, implement a feasible projection to `{x in [0,1]^n : sum(x) = target}`.
- Solve for scalar `theta` such that `x = clip(v - theta, 0, 1)` has sum approximates `target`. Use bisection; the monotone decreasing sum of clipped v - theta is exhaustive. Then do a joint correction on coordinates not clamped at 0 or 1 by distributing the sum residual. Return exact feasible candidate after that projection. This method sets both bounds and sum jointly.
- Use it on parent validation and resolution changes. If applying projection worsens exact C5, do not commit the projection; if the candidate's native exact sum is already within tolerance `1e-8` and bounds are valid, keep the native candidate.
