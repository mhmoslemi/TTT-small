1. Approach and rationale

The supplied parent is already down near the current numerical record, so a direct restart of the same projected-linear LP is unlikely to move much. The bottleneck is that the parent appears to sit in a very flat, constraint-dominated local optimum: many correlations are nearly tied at the peak, the zero and nonzero boundary terms are structurally coupled, and ordinary line-search directions become weak because the maximum is determined by a small set of hard constraints. We therefore combine three complementary ideas:

1. Exact epigraph / active-set nonlinear refinement.  The evaluator uses the true non-smooth objective
   max_l corr_l(h) * dx.  We formulate the local epigraph problem
   minimize t subject to corr_l(h) <= t and the parent constraints, and trim it to
   only the most active current constraints so that a local unconstrained
   non-linear inequality solver can be used.  If a local optimizer of this
   epigraph problem is tried, there is no ambiguity and the reported value can
   be compared with the actual metric.

2. Smooth log-sum-exp search directions.  Direct LP directions ignore which
   constraints are slightly non-active and can stall as soon as the quadratic cross-
   terms of the function vanish. Instead we derive the gradient of the smoothed
   function
   f_rho(h) = rho^{-1} log sum_{lags} exp(rho corr_l(h))
   using the explicit finite-support derivative. Smooth direction steps are
   evaluated by exact interior search to avoid evaluating the wrong surrogate
   and only accepted if exact objective decreases. This will:
   - increase the number of effective directions near optimum, the log sum, and
   - not erroneously accept false steps.

3. Expanded local-global branching/pool-based strategy.  The refining core is
   applied to a small pool of candidate strings, including a range of resolution
   transfers of the parent and source candidates. From that pool we repeatedly
   create new points, evolve candidates directly to a range, discard candidates
   that are clearly untrue, ensure feasibility exactly, and accept only exact
   candidate values that are new terms. Multi-scale uniformly prevents local
   optimum dimensional overshoot. This is correct for generating targets
   that are close representative representations. However, each accepted parent
   transfer must be immediately evaluated using exact score.

None of these should be described as global optimality. All are definitions.
Like the previous routines, the true design remains randomized and heuristic. It
should be understood as a more capable local-plus-branching combination with
strong exact validation and nondirectional regularization, and a definitive
definition of "try or use the previous demo solutions" decision threshold:
always retain that parent as a feasible output, and retain all previous best
