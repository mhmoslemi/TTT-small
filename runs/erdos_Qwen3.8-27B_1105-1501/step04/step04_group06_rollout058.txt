    if target >= n:
        return np.ones(n)
    
    # Binary search for the threshold
    lo, hi = v.min() - 1.0, v.max() + 1.0
    for _ in range(80):
        mid = (lo + hi) / 2.0
        s = np.sum(np.clip(v - mid, 0.0, 1.0))
        if s > target:
            lo = mid
        else:
            hi = mid
    
    x = np.clip(v - (lo + hi) / 2.0, 0.0, 1.0)
    # Fixup
    diff = target - x.sum()
    if abs(diff) > 1e-10:
        idx = np.argsort(-x if diff < 0 else x)
        for i in idx:
            if diff > 0:
                a = min(1.0 - x[i], diff)
                x[i] += a
                diff -= a
            else:
                a = min(x[i], -diff)
                x[i] += a
                diff -= a
            if abs(diff) < 1e-10:
                break
    return x

    corr = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(corr) * 2.0 / n)

Wait, but each call to np.correlate involves modifying h (setting h[j]=t, h[k]=c-t), computing the correlation, and then restoring h. That's a lot of overhead.

Let me use a smarter approach: compute the correlation change analytically.

For a given pair (j,k) and value t (with c = h[j]+h[k] fixed):
- The old values are h[j] = a, h[k] = b (where a+b = c)
- The new values are h[j] = t, h[k] = c-t

The change in correlation at shift S (0-indexed, S = 0 to 2n-2):
The shift amount is s = S - (n-1), ranging from -(n-1) to n-1.

The correlation at shift S is:
c_S = Σ_{valid i} h[i+s] * (1-h[i])

where "valid" means 0 ≤ i < n and 0 ≤ i+s < n.

The terms that change are those where i ∈ {j, k} or i+s ∈ {j, k}.

Let me define for a given S (shift s = S - (n-1)):
- i1 = j: valid if 0 ≤ j < n and 0 ≤ j+s < n
- i2 = j-s: valid if 0 ≤ j-s < n (which means 0 ≤ j-s < n and j-s+s = j, always valid if j valid)
  Actually: i2 = j-s is valid if 0 ≤ j-s < n and 0 ≤ (j-s)+s = j < n. The second condition is always true.
  So i2 valid iff 0 ≤ j-s < n, i.e., -j < s ... wait: 0 ≤ j-s means s ≤ j, and j-s < n means s > j-n.
  So: j-n < s ≤ j, or equivalently: s ∈ (j-n, j].
  
- i3 = k: valid if 0 ≤ k < n and 0 ≤ k+s < n → s ∈ (-k, n-1-k]
  Wait: 0 ≤ k+s < n means -k ≤ s < n-k.
  
- i4 = k-s: valid if 0 ≤ k-s < n → k-n < s ≤ k, i.e., s ∈ (k-n, k].

So the affected shifts for a pair (j,k) are:
s ∈ [-(n-1), n-1] ∩ ([0-extending range for j] ∪ [range for j-s] ∪ [range for k] ∪ [range for k-s])

Specifically:
- i1 = j contributes to shifts s where 0 ≤ j+s < n: s ∈ [-j, n-1-j]
- i2 = j-s contributes to shifts s where 0 ≤ j-s < n: s ∈ [j-n+1, j]
- i3 = k contributes to shifts s where 0 ≤ k+s < n: s ∈ [-k, n-1-k]
- i4 = k-s contributes to shifts s where 0 ≤ k-s < n: s ∈ [k-n+1, k]

The union of these ranges gives the affected shifts.

For each affected shift s, the change is:
Δc_S = [new_i1 + new_i2 + new_i3 + new_i4] - [old_i1 + old_i2 + old_i3 + old_i4]

where new_iX is the contribution of index iX with the new h values, and old_iX with the old values.

But I need to handle the case where iX values overlap (e.g., i1 = i4 when j = k-s, i.e., s = k-j).

Let me define the set of unique valid indices:
V = {i : i ∈ {j, j-s, k, k-s} and 0 ≤ i < n and 0 ≤ i+s < n}

For each i in V:
- old_contrib = h_old[i+s] * (1 - h_old[i])
- new_contrib = h_new[i+s] * (1 - h_new[i])

where h_new differs from h_old only at positions j and k.

So:
- If i ∈ {j,k} and (i+s) ∈ {j,k}: both factors change
- If i ∈ {j,k} and (i+s) ∉ {j,k}: first factor changes
- If i ∉ {j,k} and (i+s) ∈ {j,k}: second factor changes
- If i ∉ {j,k} and (i+s) ∉ {j,k}: no change (but then i wouldn't be in V)
