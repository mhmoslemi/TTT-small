1. Approach and rationale

1.1 Central idea
The previous parent-centered program relied heavily on deterministic local linearizations, gradient smoothing, and paired coordinate line searches. That is a single-basin optimization method: if the initial construction is already near a narrow active-set plateau, the descent moves repeatedly trying to solve a linearized active problem from close to the parent are no longer able to leave it. The new approach changes the primary search pattern to an exact-state, exact-objective stochastic annealing procedure over the actual feasible polytope, combined with two additional components that are absent from the previous program:

- A fast exact binary count-neighborhood simulated annealing module. This searches over binary finite-step functions while preserving the discrete integral exactly by swapping a 1 with a 0. For binary vectors, every full-correlation score is an integer count, and the objective becomes an inexpensive maximum of two orientation-count arrays. Because each proposed swap is feasibility-preserving by construction, the simulator can perform many more exact-objective there-and-accept moves than the previous smooth-max gradient program.
- A continuous projected exact annealing module. Starting from continuous parent and resampled/rescaled candidates, it proposes random zero-sum coordinate displacements whose feasibility is ensured by step size chosen before evaluation. It accepts all non-increasing exact-objective moves and accepts uphill moves with a decreasing temperature schedule. This lets it jump over the plateau that pure descent, LPz directions, and line searches have difficulty escaping. After uphill excursions it returns exact local pair/gradient line polishing.
- Multi-resolution and diversified seed generation, but the full score always uses the authoritative exact evaluator, not the linearization. Any xi transformation between n-values must be followed by feasibility restoration and exact re-evaluation. If a accepted pattern is infeasible by more than a tolerance, it is rejected. The validated parent is saved as the no-worse fallback unless a better verified candidate was found.

This directly addresses the bottleneck that the parent appears to be a narrow local optimum: deterministic descent directions become inexact after local linearization or line search, while the exact evaluator changes by only tiny amounts. The new methods either explore exactly feasible uphill states (continuous) or minimize a count equivalent exactly on the coarser binary search space (binary). If either finds an exact candidate with a lower value, the returned bound improves; otherwise the program returns the best parent or best verified fallback.

1.2 Differentiation from the old methods
The program should not become one minor tweak to the old SLSQP/LP pair-polish loop. The four substantive additions are:

1. Binary count-system SA maintaining both orientation arrays and using swap potentials for exact preservation of mass. Since the swap uses only the swapped entries and the bit balance, feasibility is guaranteed exactly independent of numerical projection.
2. Exact-state probabilistic acceptance on continuous h states with random zero-sum vectors and internal capacity-limited step size. The solver can deliberately traverse the plateau rather than being forced onto a linearized descent branch.
3. Major structured seed collection at multiple n points with exact comparisons, but capped resolution/bounded randomized smoother initializations.
4. Only degenerate exact evaluators/acceptance parameters, not numerical objective solves, to return the exact c5 calculator and final reported evaluation before returning. This en/downloads final validation.

The overall method is independent of any previously run program and uses only initial_h_values if available, never hardcoded. If no parent is received, it constructs the algorithmically defined fallback seeds on the fly.

2. Mathematical specification

2.1 representation and exact evaluator
A candidate vector is a 1-dimensional NumPy array h of length n, with dx = 2.0/n. The exact evaluator is

score(h) = dx * max(np.correlate(h, 1.0 - h, mode='full'))

using np.correlate exactly as specified. This is not circular correlation; full mode contains both negative and positive lag directions. Feasibility constraints are:

0 <= h_i <= 1 for every i,
sum h_i * dx = 1, equivalently sum h_i = n/2,
n must be even for an exactly feasible minimum sample. Only even n should be generated/submitted.

Use dx for every return value. Since the exact objective is nonlinear, no convex reformulation can be claimed. Every numerical method gives a candidate/filter; its final reported bound must be the actual selected exact score after exact evaluator calls.

2.2 Feasibility projection for continuous vectors
Define a top-level helper called project_unit_interval_feasibility(v, target=None).

Given v in R^n, return the Euclidean projected array x onto the intersection:
{ x in R^n : 0 <= x_i <= 1, sum(x) = target }

For this problem target is n/2. Pseudocode:
