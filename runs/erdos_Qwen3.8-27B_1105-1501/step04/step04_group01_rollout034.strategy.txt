1. Approach and rationale

The supplied parent is already close to the current numerical record, so the useful scientific move is not to run one more copy of a single deterministic local LP loop. The bottleneck is narrow basins and plateaued active overlap coordinates: a local direction can reduce one active peak after another but often merely circulates mass around an almost-flat upper envelope. The proposed construction therefore keeps and protects the parent, then alternates three capabilities that were not all fully combined in the previous program:

- exact, accepted-only-if-exact line-search searches along many cheaply generated feasible directions;
- a smooth log-sum-exp surrogate for gradient/information generation, but not for acceptance, so the supplied evaluator remains authoritative;
- a small population maintained entirely in the feasible box/mean manifold, with crossover/interval moves and resolution transfer. This lets distinct plateau-shaped profiles exchange the parts that reduce different active lags.

This addresses the previous stagnation because it actively searches directions generated by: smoothed active-gradient descent, pair transfers suggested by marginal gradients, random harmonic/Fourier directions, and random neighbors in the feasible manifold. It also adds explicit symmetry/variance motion and candidates at modestly different resolutions (`n` values). It does not claim global optimality or that the smooth surrogate is sufficient; those are only proposal generators. Every returned number is always the exact evaluator

`C5(h) = max(np.correlate(h, 1-h, mode="full")) * (2.0/n)`.

If no candidate is strictly better, the parent is returned. The scheme is intentionally conservative: only exact objective decreases, or ties with a smaller `n` within a small tolerance, replace the best candidate.

2. Mathematical specification

Let `h ∈ R^n`. For `dx = 2/n`, define raw overlap vector

`R(h) = np.correlate(h, 1-h, mode="full")`, length `2n-1`.

The evaluator constant is

`C(h) = dx * max_j R(h)_j`.

Feasibility is:

`0 <= h_i <= 1 for all i`,
`sum_i h_i = n/2`.

This is equivalent to `int_0^2 h(x)dx = 1` under the rectangle convention used by the evaluator. Do not optimize `1 - autocorrelation` or circular autocorrelation. Boundary-overlap behavior is part of the objective.

For feasible perturbation directions, require

`sum_i d_i = 0`,

and the usable interval

`t_min = max_i for d_i < 0, { h_i / d_i }`,
`t_max = min_i for d_i > 0, { (1-h_i) / d_i }`,

starting at `t=0`. Direction normalization does not affect acceptance because the line search tries both signs and the feasibility interval adapts to magnitude.

The exact one-dimensional value along `d` can be written exactly using correlation algebra:

`R(h + t d, 1 - h - t d) = R(h,1-h) + t T - t^2 Q`,

with

`T = np.correlate(d, 1-h, mode="full") - np.correlate(h, d, mode="full")`,
`Q = np.correlate(d, d, mode="full")`.

The callable line-search objective is therefore

`g(t) = dx * max_r(R_0[r] + t*T[r] - t*t*Q[r])`.

This uses the same algebraic construction as the evaluator, assuming the sign/orientation is rooted from the supplied `np.correlate` pipeline. Line search must test two signs of a proposed direction before rejecting it; this prevents a sign convention issue from completely disabling a useful direction family.

For proposal generation, use smoothed objective

`J_r(h) = dx*R(h)_r`,
`F_beta(h) = (1/beta) log(sum_r exp(beta*(J_r(h)-max_s J_s(h))))`.

It is a smooth surrogate over the interior and approximates the maximum from below plus `log(2n-1)/beta`; it provides weighted marginals. Define `w_r = exp(-beta*(max_sJ - J_r))/sum_s()` after subtracting the max. The weighted gradient for proposal use is the linear combination of the raw overlap gradients associated with the actual rows. The correct adjacent/raw direction can be verified numerically at runtime by a small centered finite difference `(F_beta(h+eps*p)-F_beta(h-eps*p))/(2eps)` versus `g·p`; if the orientation is reversed, reorder weights or reverse both the formula and candidate vector. Direction proposal only; no acceptance is based on `F_beta`.

Feasibility repair is a single-projected waterfill operation:

Given arbitrary `v` and target `tau = n/2`, find scalar theta such that

`sum_i clip(v_i - theta, 0, 1) = tau`.

The function `f(theta)` is nonincreasing, continuous, and range covers target. Find by 70 binary-search iterations after definite bracketing; set

`h_i = clip(v_i - theta, 0, 1)`.

If floating error remains, fix by adding the final residual equally to coordinates that remain strictly inside `(0,1)`. This simultaneously enforces bounds and mean, unlike clip-then-rescale operations that can violate bounds.

For variable resolution transfer from length `n_old` to `n_new`, the centers in normalized `[0,1]` are

`x_old区委_i = (i + 0.5)/n_old`,
`x_new_i = (i + 0.5)/n_new`.

Use `h_interp_i = interp(x_new, x_old, h_old)`, then waterfill to `target=n_new/2`. The final objective must always be recomputed exactly in the new length. This is only candidate transport, not a certificate; the parent with `n=initial_h_values` length remains a fallback if no cross-resolution improvement occurs.
