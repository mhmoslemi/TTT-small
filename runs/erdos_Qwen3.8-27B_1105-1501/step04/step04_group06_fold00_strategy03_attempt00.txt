1. Approach and rationale

1.1 Central idea

The supplied parent construction is a continuous n=64 local optimum or near-optimum from smooth local minimizers. The previous reported value 0.380915 is very close to the record 0.38085, so the remaining work is mostly to find a tiny additional reduction or an independent basin that produces a value below 0.3808. The algorithm in this plan is materially different from pure SLSQP/LSE/LP polishing because it first creates exact 0/1 balanced sequences by combinatorial local annealing, then uses those binary sequences and the supplied parent as seeds for a constrained global stochastic search and a low-dimensional exact local search. The final returned value is always validated with the authoritative evaluator.

The key new ingredients are:

1. Exact binary subspace search. We require the sequence to have exactly n/2 entries equal to 1 and n/2 entries equal to 0. This gives exact feasibility without projection and searches basins that a smooth local method may never reach. For binary h, every raw correlation is an integer count of ordered 1-zero pairs across the shifted overlap, so the score is exactly comparable with the evaluator and is theoretically very inexpensive.

2. Exact finite-difference/fuzz-safe active local polishing. Local polishing is not a single black-box optimizer. After any proposal, the vector is repaired to the box and mass constraint without clipping plus rescaling. The current objective is always the evaluator score, never a surrogate score. A candidate is accepted only when the exact evaluator improves the incumbent solution.

3. Targeted pairwise mass-transfer local moves. Instead of treating each coordinate independently, we preserve ∑h by transferring mass between two coordinates. These exact 2-coordinate moves allow one-dimensional line searches that can improve nonsmooth local optima missed by a gradient method. Movement is performed between coordinate pairs chosen from active correlation constraints.

4. Independent global stochastic exploration. A custom differential-evolution/mutation search over feasible projected vectors explores beyond the parent basin before local polishing. It is not used as the final solution; it only supplies high-quality feasible seeds.

This plan is deliberately a hybrid stochastic/exact local optimizer. It will not claim global optimality. It will return the best exact evaluator value found among all valid feasible candidates, with the initial parent construction as a valid fallback.

1.2 Why this may improve the parent

The parent was found by continuous local algorithms. Such algorithms are vulnerable to:

- Getting stuck at a nonsmooth local minimum.
- Using inactive constraints that prevent tiny exact reductions.
- Smoothing the maximum too much.
- Missing integer-like event basins because perturbations are tied to the initial curve.

Binary search jumps directly into 0/1 event basins. The objective in this subspace is often close to the continuous optimum because the product h_i(1-h_j) is largest when one coordinate is interior and smallest around 0/1, and many known extremal constructions are near 0/1. If the binary search finds a better exact raw count, continuous pair-move polishing may reduce the maximum further by slightly shifting mass. Even if no binary sequence is below the target, its best candidates can seed a different continuous basin.

The pairwise mass-transfer moves are exact feasibility-preserving primitives. At a false local optimum for gradient methods, a nonsmooth kink may be softened by moving just enough mass from donor coordinates to receiver coordinates in two or three selected directions. This is complementary to SLSQP and can be independently executed for the supplied parent, for binary candidates, and for all seeds found by stochastic search.

2. Mathematical specification

2.1 Discrete representation and authoritative objective

For a return vector h of length n:

- dx = 2.0 / n.
- Constraint: 0.0 ≤ h[i] ≤ 1.0 for every i.
- Mass constraint: ∑ h[i] = n/2.0.
- Authoritative raw correlation vector:

  c = np.correlate(h, 1.0 - h, mode="full")

  length(c) = 2n - 1.

- Authoritative C5 value:

  C5(h) = max(c) * dx.

All internal minimization can minimize raw_max = max(c), because dx is fixed within a fixed n. If n changes, compare only after multiplying by 2/n so the objective is the official C5. The binary case keeps raw exact as an integer count before scaling.

2.2 Finite-support correlation indexing

For implementation, the exact correlation identities that correlate with np.correlate can be checked numerically. Use the following template and verify orientation:

For each allowed shift ℓ, define an output order variant. A safe implementation should derive the matching order using a runtime finite-difference/introspection function rather than manually assuming orientation.

Candidate form:

  corr_q(h) = ∑_{i in I_q} h_i * (1.0 - h_{i+ℓ}), where I_q padded.

If the array from your formula does not match np.correlate in order, use the reversed order orientation. This matters for gradient matrix rows, not for the final maximum.

A canonical gradient formula, assuming the above and I_q:

I_q = { i: 0 ≤ i < n and 0 ≤ i+ℓ < n }

and

  corr_q(h) = ∑_{i in I_q} h_i * (1 - h_{i+ℓ}).

The partial derivative wrt h_k is the sum of:

- from direct i=k term, if k ∈ I_q: + (1 - h_{k+ℓ})
- from indirect j=k where j=i+ℓ, so i=k-ℓ: if k-ℓ ∈ I_q, then - h_{k-ℓ}

Boundary conditions in those inequalities follow the discrete zero-padded evaluator.

Runtime orientation validation procedure:

1. For small n such as n=8, construct three independent feasible random continuous vectors.
2. Compute corr_np = np.correlate(h, 1-h, "full").
3. Compute corr_formula(A) by filling the formula exactly as described for every lag.
4. Compare corr_formula to corr_np directly and to corr_np[::-1]. Use as orientation whichever has default derivative equals np-max position error. If neither, use forward finite differences to construct matrices only for local moves or use numerical gradient for the epigraph objective. This validation is before long optimization.

2.3 Feasible joint projection

Do not normalize and then clip separately. Use one offset projection.

Given vector v of length n and target T = n/2.0:
Find a scalar α such that

  S(α) = ∑_i clip(v_i + α, 0.0, 1.0) = T.

S is continuous, nondecreasing, convex in the upper quantile but search bracket yields binary search feasible. Bracket endpoints:

  low = min(v) - 1.0 - 2.0
  high = max(v) + 1.0 + 2.0

Then binary search α about 80 times. Then h = clip(v + α, 0, 1). If residual abs(sum(h)-T) > tolerance, correct by distributing excess/deficit over coordinates with the least crowding:

- If sum is low, sort ascending and add from coordinates below 1.0 until exact.
- If sum is high, sort descending and subtract from coordinates above 0.0 until exact.

Tolerances for final feasibility:
  abs(max(h)-1) ≤ 1e-10
  min(h) ≥ -1e-10
  abs(sum(h)-n/2) ≤ 1e-9 (for n up to 256; use 1e-7 for binary because count exact)

The final repaired vector is always reconstructed using this same projection before evaluation.

2.4 Exact 0/1 subspace feasibility

A binary candidate has bits y∈{0,1}^n and exactly ∑ y_i = n/2. It satisfies box/mass exactly.

Binary raw correlation is:

  c_s(y) = ∑_{i ∈ I_s} y_i * (1 - y_{i+s}).

These are nonnegative integer counts. The exact C5 is max_s c_s * (2/n).

Binary feasibility does not require projection. If a candidate generated from continuous values needs to be binarized to exact half-length, use the deterministic balanced ranker described later.

2.5 Derived gradient of the exact correlation vector

Let C(h) be vector length 2n-1; G(h) the Jacobian, G[r, :] shape (2n-1, n). For any feasible step p and linearization:

  C(h + p) ≈ C(h) + G(h) dot p.

The gradient of a reduced pairwise transfer is simply G[:, donor] - G[:, receiver]. In mechanisms that do not rely exactly on gradients, exact one-dimensional clamp searches evaluate the original objective. This direction infrastructure always supports the active-move saacc algorithm.

2.6 Pairwise move model preserving mass

Select coordinates j, k. Feasible movement parameter a changes

  h' = clone(h)
  h'[j] = h[j] - a
  h'[k] = h[k] + a

mass and box mean require

  a ∈ [ max(-h[k], h[j]-1), min(h[j], 1-h[k]) ]

The padded upper bound is 1-h[k]. If a negative winner parameter is allowed, reverse directions. For each candidate move, exact h' is used:

  raw(a) = max(colorate(h', 1 - h'))

The best a found over sampled plus extrapolated interval must produce exact C lower than incumbent. The search interval default length 0.01 for maturity, 0.05 step, long early. If h[j] or h[k] are integers, maximum kernel length is 0.01 or nonzero. In multiple coordinate mass tray, make moves limited by derivative ranks to productive coordinates even where only using the full max shift hard and guarantee directions are around continuous faults and can produce binary phenomenon.

2.7 Objective equivalence and limits

No relaxation or surrogate value is returned. Surrogates can be used only to reduce complexity during sampling. The incumbent store is built only from vectors with the exact evaluator applied after feasibility repair. The method is not a valve: if no candidate is a global optimum, not depends, we are a lower practical bound. Even if no improvement exists in the returned financial graph ring.
