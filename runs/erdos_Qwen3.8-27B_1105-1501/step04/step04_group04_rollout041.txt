Let me think about a more efficient approach:

For each pair (i,j), compute the vector of coefficients c_d (the linear change in M_d) and the quadratic coefficient (0 or -1 for the one lag where they interact). Then:
- The new M_d(τ) = M_d + c_d * τ + q_d * τ² where q_d is 0 for all but at most 2 lags
- We want to minimize max_d (M_d + c_d * τ + q_d * τ²) over τ ∈ [τ_min, τ_max]
- Since the max of linear/quadratic functions is convex, we can ternary search

The cost per pair evaluation is O(L) for computing the max, and ternary search takes O(log(1/ε)) iterations. So O(L * log(1/ε)) per pair.

With n=128, number of pairs is ~n²/2 ≈ 8000. Each evaluation is ~255 * 30 ≈ 7500 ops. Total: ~60 million ops. That's feasible.

1. Focus on pairs that are likely to help (e.g., where one coordinate is high and the other is low, or where they're at "active" lags)
2. Use a priority queue or greedy selection

1. **Exact 1D pair exchange**: For pair (i,j), the exchange h_i+τ, h_j-τ preserves the sum. The objective max_d M_d(τ) is convex in τ. Find the optimal τ by ternary search.

3. **Smart pair selection**: Prioritize pairs where the exchange is likely to reduce the max. E.g., pairs where one index is at a "peak" position (high h) and the other at a "valley" (low h), or pairs that appear in the active lags.

4. **Multiple strategies**: Combine the pair exchange with:
   - Random restarts
   - Local perturbations
   - Different n (resolution changes)

    d_pt = a + invphi * (b - a)
    fc = np.max(M + c*c_pt + q*c_pt*c_pt)

            fc = fd
            d_pt = a + invphi * (b - a)
            fd = np.max(M + c*d_pt + q*d_pt*d_pt)

    f_opt = np.max(M + c*tau_opt + q*tau_opt*tau_opt)

  i+d ranges from 0 to n-1.
  c indices: n-1+d ranges from n-1-i to n-1+n-1-i = 2n-2-i.
  Number of c elements: (2n-2-i) - (n-1-i) + 1 = n. ✓
  h values: h[0], h[1], ..., h[n-1]. So it's the full h vector!
  
  c[n-1-i : n-1-i+n] += (1-h)
  i.e., c[n-1-i : 2n-1-i] += (1-h)

Let me verify: when i=0, d ranges from 0 to n-1. c[n-1+d] += 1-h[d] for d=0,...,n-1.
  c[n-1 : 2n-1] += (1-h). That's the second half of c. ✓

When i=n-1, d ranges from -(n-1) to 0. c[n-1+d] += 1-h[n-1+d] for d=-(n-1),...,0.
  c[0 : n] += (1-h). That's the first half. ✓

OK so Term A is simply: c[n-1-i : 2n-1-i] += (1-h)

Term B: for d from i-n+1 to i (inclusive), c[n-1+d] += -h[i-d].
  - i-d ranges from i-(i-n+1)=n-1 down to i-i=0.
  - So h[i-d] ranges from h[n-1] down to h[0], i.e., h reversed.
  - c indices: n-1+d ranges from n-1+i-n+1=i to n-1+i.
  - Number of elements: (n-1+i) - i + 1 = n. ✓
  
  c[i : i+n] += -h[::-1]

Let me verify: when i=0, d ranges from -(n-1) to 0. c[n-1+d] += -h[0-d] = -h[-d] for d=-(n-1),...,0.
  That's -h[n-1], -h[n-2], ..., -h[0]. c[0:n] += [-h[n-1], ..., -h[0]] = -h[::-1]. ✓

When i=n-1, d ranges from 0 to n-1. c[n-1+d] += -h[n-1-d] for d=0,...,n-1.
  That's -h[n-1], -h[n-2], ..., -h[0]. c[n-1:2n-1] += -h[::-1]. ✓



Term C: for d from -j to n-1-j (inclusive), c[n-1+d] += -(1-h[j+d]).
  Same structure as Term A but with j instead of i and a negative sign.
  c[n-1-j : 2n-1-j] -= (1-h)

Term D: for d from j-n+1 to j (inclusive), c[n-1+d] += h[j-d].
  Same structure as Term B but with j instead of i and positive sign.
  c[j : j+n] += h[::-1]

So:
```python
def pair_coeffs(h, i, j):
    n = len(h)
    L = 2*n - 1
    c = np.zeros(L)
    c[n-1-i : 2*n-1-i] += (1.0 - h)
    c[i : i+n] += -h[::-1]
    c[n-1-j : 2*n-1-j] -= (1.0 - h)
    c[j : j+n] += h[::-1]
    
    q = np.zeros(L)
    q[n-1] = -2.0
    q[n-1 + j - i] += 1.0
    q[n-1 + i - j] += 1.0
    
    return c, q
```

This is O(n) per pair (the slice operations are O(n) each). And it's very clean!
