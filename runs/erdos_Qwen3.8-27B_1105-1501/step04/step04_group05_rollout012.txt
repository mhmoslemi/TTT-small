Actually, let me redefine. In the full correlation of length 2n-1:

where k ranges from -(n-1) to n-1, and c_full is stored at index k + n - 1.

Let me use a different parameterization. Let the lag be L (where L = k, ranging from -(n-1) to n-1).

When we swap h[i] and h[j] (i has 1, j has 0):
- h[i] changes 1→0, h[j] changes 0→1
- For a given lag L, the terms affected are those involving index i or j:
  1. Term where n = i: h[i]*(1-h[i-L]) → changes from (1-h[i-L]) to 0. Δ = -(1-h[i-L]) if i-L is in range.
  2. Term where n-L = i, i.e., n = i+L: h[i+L]*(1-h[i]) → changes from 0 to h[i+L]. Δ = h[i+L] if i+L is in range.
  3. Term where n = j: h[j]*(1-h[j-L]) → changes from 0 to (1-h[j-L]). Δ = (1-h[j-L]) if j-L is in range.
  4. Term where n-L = j, i.e., n = j+L: h[j+L]*(1-h[j]) → changes from h[j+L] to 0. Δ = -h[j+L] if j+L is in range.

So Δc[L] = -(1-h[i-L]) + h[i+L] + (1-h[j-L]) - h[j+L]
     = h[i+L] - h[j+L] - 1 + h[i-L] + 1 - h[j-L]
     = (h[i+L] - h[j+L]) + (h[i-L] - h[j-L])

(Where h[x] = 0 if x < 0 or x ≥ n, since out-of-range terms don't contribute.)

This is a nice formula! For each swap (i,j), we can compute the change in c[L] for all L in O(n) time (or O(1) per L).

But since we're minimizing the MAX of c[L], a single swap can affect the maximum in complex ways. The standard approach is:
1. Compute c[L] for all L (O(n²) using FFT or direct computation)
2. For each candidate swap, compute Δc[L] for all L
3. Check if the new max is lower

This is O(n³) per iteration (n² swaps × n lags), which for n=64 is 64³ = 262144 operations per iteration. With millions of iterations, this might be tight but feasible.

Actually, a smarter approach: we only need to check if the swap improves the maximum. The current maximum is M. After the swap, the new c'[L] = c[L] + Δc[L]. The new maximum is max_L (c[L] + Δc[L]). We accept if this is < M.

For a swap to be accepted, we need: for all L, c[L] + Δc[L] < M (or at least the max is reduced). A necessary condition is that for the L where c[L] = M (the active lags), we need Δc[L] < 0.

So a quick filter: check the active lags first. If Δc[L] ≥ 0 for all active L, the swap can't help. Only then do the full check.

Let me code this up. The key data structures:
- h: binary array of length n
- c: array of length 2n-1 (the full correlation)
- active: set of lags where c[L] = max(c)

For each swap (i, j) where h[i]=1, h[j]=0:
- Compute Δc[L] for all L (or just active L first)
- If max(c[L] + Δc[L] for all L) < current max: accept

Even better: define for each position p and lag L:

- g[p, L] = h[p-L] (0 if out of range)

Then Δc_{i,j}[L] = f[i,L] - f[j,L] + g[i,L] - g[j,L]

We can precompute f and g as 64×127 matrices (with out-of-range = 0).

Then for each swap (i,j), Δc is just f[i] - f[j] + g[i] - g[j] (vector operation on 127-element vectors).

For all 1024 swaps, we can compute all Δc values at once using broadcasting:
Δc_all = f[ones_indices][:, None, :] - f[zero_indices][None, :, :] + g[ones][:, None, :] - g[zeros][None, :, :]

This gives a 32×32×127 array. Then the new c for each swap is:
c_new = c[None, None, :] + Δc_all  (32×32×127)
max_new = c_new.max(axis=2)  (32×32)

And we pick the swap with the minimum max_new. If it's < current max, we apply it.

This is very vectorizable! Let me estimate the cost:
- 32×32×127 array = 130,048 floats = ~1 MB. Very manageable.
- The computation is a few vectorized numpy operations.
- Total per full evaluation: maybe 1-2 ms.

So we can do ~500,000 full evaluations per second, which is way more than enough.
