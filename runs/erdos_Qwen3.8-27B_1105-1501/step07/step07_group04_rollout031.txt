  If b-k ≠ a: New = 1*(1-h[b-k]) = 1-h[b-k]. Delta: 1-h[b-k].
  
- Term at index n where n = b (valid if 0 <= b <= n-1-k):
  Old: h_old[b+k]*(1-h_old[b]) = h[b+k]*1 = h[b+k]
  New: h_new[b+k]*(1-h_new[b]) = h_new[b+k]*0 = 0
  If b+k = a: New = 0. Delta: -h_old[a] = -1.
  If b+k ≠ a: New = 0. Delta: -h[b+k].

So the total delta F_k for swap (a:1→0, b:0→1) is the sum of the deltas from up to 4 terms (some may overlap or be invalid).

Let me define:
T1: exists if 0 <= a-k and a-k <= n-1-k (i.e., k <= a <= n-1)
  Delta T1 = -(1 - h_new[a-k])
  If a-k == b: h_new[a-k] = h_new[b] = 1, so Delta T1 = -(1-1) = 0
  Else: h_new[a-k] = h[a-k] (unchanged), so Delta T1 = -(1-h[a-k])

T2: exists if 0 <= a <= n-1-k (i.e., a <= n-1-k, i.e., k <= n-1-a)
  Delta T2 = h_new[a+k] - 0 = h_new[a+k]
  If a+k == b: h_new[a+k] = 1, Delta T2 = 1
  Else: h_new[a+k] = h[a+k], Delta T2 = h[a+k]

T3: exists if 0 <= b-k and b-k <= n-1-k (i.e., k <= b <= n-1)
  Delta T3 = h_new[b] - 0 = 1 - ... wait.
  Old: 0. New: 1*(1-h_new[b-k]) = 1-h_new[b-k].
  If b-k == a: h_new[b-k] = 0, Delta T3 = 1
  Else: h_new[b-k] = h[b-k], Delta T3 = 1-h[b-k]

T4: exists if 0 <= b <= n-1-k (i.e., b <= n-1-k, i.e., k <= n-1-b)
  Old: h[b+k]. New: h_new[b+k]*0 = 0.
  Delta T4 = -h_new[b+k]
  If b+k == a: h_new[b+k] = 0, Delta T4 = 0
  Else: h_new[b+k] = h[b+k], Delta T4 = -h[b+k]

Note: T1 and T3 can be the same term if a-k = b-k, i.e., a = b, which is impossible. T1 and T4 can be the same if a-k = b, i.e., a-b = k. In that case, T1 is the term at n = a-k = b, and T4 is the term at n = b. They're the same term!

Wait no. T1 is the term where h[n+k] = h[a], i.e., n+k = a, so n = a-k. T4 is the term where (1-h[n]) = (1-h[b]), i.e., n = b. These are the same term when a-k = b, i.e., a - b = k. In that case, the term is h[a]*(1-h[b]) (since n = b = a-k, so h[n+k] = h[a] and h[n] = h[b]).

Similarly, T2 is the term where (1-h[n]) = (1-h[a]), so n = a. T3 is the term where h[n+k] = h[b], so n+k = b, n = b-k. These are the same term when a = b-k, i.e., b - a = k. In that case, the term is h[b]*(1-h[a]).

So there can be overlap between T1&T4 (when a-b=k) and T2&T3 (when b-a=k). In those cases, we should only count the term once.

Let me handle this by computing the delta of each unique term:

The terms in F_k that involve position a or b are:
1. Term at n = a-k (if valid): involves h[a] and h[a-k]
2. Term at n = a (if valid): involves h[a+k] and h[a]
3. Term at n = b-k (if valid): involves h[b] and h[b-k]
4. Term at n = b (if valid): involves h[b+k] and h[b]

Some of these may be the same n:
- n = a-k = a → k = 0 (center, ignore for binary)
- n = a-k = b-k → a = b (impossible)
- n = a-k = b → a - b = k → terms 1 and 4 are the same
- n = a = b-k → b - a = k → terms 2 and 3 are the same
- n = a = b → impossible
- n = a-k = b+k → a - b = 2k → terms 1 and... wait, n = b+k means the term at n = b+k, which involves h[b+k+k] and h[b+k]. That's not one of our terms unless b+k = a or b+k = b-k etc. This is getting complicated.

Let me simplify: I'll just compute F_k(new) - F_k(old) directly for the swap by computing the change in each of the at most 4 relevant terms, being careful about overlaps.

Actually, for implementation purposes, the easiest thing is:
1. Compute the old F_k (we already have it from the correlation)
2. Compute the change: for each of the up to 4 affected terms, compute old_value - new_value
3. Sum them up (being careful about double-counting if two "terms" are actually the same position in the sum)

For efficiency in the code, I'll precompute the affected indices.

Actually, for a practical implementation with n=180, I can just:
1. Copy h
2. Perform the swap
3. Compute the new correlation (or at least the affected lags)
4. Compare max

Since np.correlate is very fast (O(n^2) but with small constant), and n=180 means ~32400 operations per correlate call, this is negligible. A full pass over all 8100 swaps would be 8100 * 32400 ≈ 262M operations, which might take a second or two. That's fine for a few iterations.
