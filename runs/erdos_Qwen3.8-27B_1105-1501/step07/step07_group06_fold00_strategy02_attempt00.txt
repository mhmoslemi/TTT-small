1. Approach and rationale

The parent construction is already close to the best known discrete evaluation, so small changes along the same surrogate-smooth-gradient path are likely to stall. The new plan treats the task as an exact nonsmooth minimax problem instead of converting it into a smooth surrogate, a long binary annealing trail, or a single structural symmetry. Its central engine is an active-constraint local descent method that uses the actual maximizing lags, computes a structured direction in the constraint tangent space, and accepts moves only after evaluating the exact finite-support cross-correlation objective.

The bottleneck it addresses is that the objective is the maximum over roughly twice the dimension. Once a plateau with several simultaneously active intersections exists, small multidimensional steps are hard to find with generic smooth-gradient directions because nonactive lags dilute the direction and many lags must be lowered together. The algorithm therefore concentrates on a small active set of the largest lags, uses their gradients to synthesize candidate descent directions, and then performs exact minimization along those directions. This is materially different from the previous proposals: the search is not primarily smoothed objective descent, not primarily binary simulated-annealing, and not restricted to a custom symmetry; it is direct nonsmooth minimax simplification via known active constraints and exact one-dimensional polynomial line search.

The method is heuristic. It does not prove global optimality or guarantee improvement. However, every candidate returned carries an exact validated upper bound from the required finite-sample evaluator, and the best valid parent remains a fallback. It can run without the parent supplied only as a generic valid construction, not as a guaranteed record bound.

2. Mathematical specification

2.1 Exact discrete problem and objective

Let `n = len(h)` be the number of grid samples on `[0, 2]`; therefore `dx = 2.0 / n`. The task evaluator is

`C5(h) = max(np.correlate(h, 1 - h, mode="full")) * (2.0 / n)`.

All optimization decisions, rankings, and acceptance tests use exactly this quantity. Internally, for a fixed grid length, define the unscaled finite vector

`raw(h) = np.correlate(h, 1.0 - h, mode="full")`,

and the raw maximum `R = max(raw)`. Then `C5 = dx * R`. Since `dx` is constant for a fixed `n`, minimizing raw is equivalent to minimizing `C5`; if comparing different sizes, always compare exact task-scale scores. This retains boundary effects of linear correlations rather than treating the evaluator as circular correlation or converting it to a positive-definite autocorrelation condition.

2.2 Feasible set

For a feasible vector `h`, dimensions and constraints:

- `h_i in [0, 1]` for every i.
- `sum(h) = n / 2` exactly, or within a container tolerance after explicit repair.
- The `raw` vector length is `2n - 1`, covering all active lags in both directions.

The joint box-and-sum constraint is enforced by a reversible exact-sum projection and by moves in sum-zero directions. The returned solution is checked using the real objective.

Exact-sum projective repair:

Given any array v containing finite numbers, target `t = n/2`.

1. If target is at or below zero return zeros; if at or above n, return ones.
2. Use continuous thresholded water-filling definition: choose lambda such that
   `sum(clip(v - lambda, 0, 1))` is as close to target as possible. This can be computed by 60-to-80 bisection over `[min(v)-2, max(v)+2]`, then final repair below.
3. Let δ be `target - sum(clipped result)`. If positive, distribute a small additional mass among entries with slack `1 - value`; if negative, remove mass from entries currently greater than zero. The goal is not to independently clip and rescale; it is a small exact repair after the projection has fixed the limit. A valid construction repeats the mass repair, and final returned candidates have `abs(sum(h)-n/2)*dx <= 1e-11` within rounding tolerance.

A valid binary vector also satisfies it because choosing exactly `n/2` ones and `n/2` zeros is exact. However, binary vectors are not the main player; continuous vectors are used because the mixed objective need not have pure integral optima.

2.3 Active lag gradient formula

Let raw index `r = 0, ..., 2n-2`, and lag identifier `tau = r - (n - 1)`. A consensus implementation should use the following derivative of the raw component corresponding to the signed lag.

For positive `tau`, valid overlap length is `m = n - tau`, over indices where the first array is shifted ahead:

- `G[tau : n] += 1 - h[0 : m]`
- `G[0 : m] -= h[tau : n]`

For negative `tau`, let `d = -tau` and `m = n - d`:

- `G[0 : m] += 1 - h[d : n]`
- `G[d : n] -= h[0 : m]`

For zero lag the formula gives the derivative of `sum_i h_i(1 - h_i)`, which is `1 - 2 h_i`. These formulas are the raw correl derivative of the component selected by a standard signed full correlation indexing convention. Because exact casing of NumPy full output convention can differ in signatures, the code must include a compact self-calibration step. At init, take a tiny 2- or 3-sample array and compare a finite difference of the entire raw array to a direction `D`; compute predicted coefficients from the positive formula, negative formula, or the sign-flipped signed-lag transform. If a tiny directional discrepancy exceeds 1e-6, adapt sign internally. All subsequent raw and gradient routines should use the same active representation. More important is active set and exact raw values. If the gradient test fails, fallback to numerical finite-difference gradients chosen by a small set of top lags rather than risky analytic gradients. This self-check protects orientation correctness.

2.4 Feasible tangent directions

Any direction vector `D` must have zero sum as far as possible so `h + alpha D` keeps the mass constraint exactly in exact arithmetic. Operationally, after generation:

- `D = D - sum(D)/n`
- normalize for consistent directions.

Feasibility interval along direction:

`h_i + alpha D_i` must stay in `[0,1]`. For entries with positive D_i, the allowable lower and upper α satisfy `-h_i/D_i <= alpha <= (1-h_i)/D_i`. For negative D_i, equivalent constraints reduce to `h_i/(-D_i)` boundary values. Start with symmetric trust interval `[-radius, radius]`, intersect with all coordinate boundary constraints, and handle the common case of a zero interval by returning α = 0 and the score at current `h`. The resulting line contains the feasible line segment.

2.5 Exact line search along a direction

Along a feasible ray `h(alpha) = h + alpha D`, the raw array is exactly

`raw(alpha) = S + alpha T - alpha^2 Q`,

where

- `S = np.correlate(h, 1-h, "full")`
- `T = np.correlate(D, 1-h, "full") - np.correlate(h, D, "full")`
- `Q = np.correlate(D, D, "full")`

The objective is `max(raw(alpha)) * dx`. A robust line search does:

1. Evaluate a compact grid, such as 40 to 80 equally spaced points, over the interval.
2. Identify the best grid interval.
3. Refine with a golden-section search around the minimum of the exact nonlinear maximum.
4. Also test `alpha = 0`, endpoint values, and the analytically stationary point of every quadratic lag currently in top raw positions and large curvature (`Q_r >= tiny`): `alpha = T_r/(2 Q_r)`.

Because `max` of many parabolas is not necessarily unimodal, the multi-start grid plus golden refinement plus stationary-point evaluation catches many nonunimodal minima. If numerical bounded failure, use best grid-sampled high evaluated exact value and do not accept unless the fully updated vector lowered exact score.

2.6 Active set construction

At an iterate `h`, compute raw. Let `Rmax` be raw max. Construct candidate active directions dynamically:

- A top collection of the largest indices, typically the 8 to 30 indices with largest raw value. The range widens and narrows with stagnation.
- Include all raw indices within a tolerance of Rmax. The absolute raw tolerance corresponds to an actual task-scale tolerance; for example, once the user-scale current best value is c, include raw entries if `r >= Rmax - max(0.5*abs(dx*1e-3), relative_raw_tol)`. A practical switch is: early tolerance is broader to find directions, final is 0.001 or less raw.
- In addition to the true peaks top, include candidate active lag weights based on a top-K local smoothing, e.g. top 16, to prevent a lag just below the current maximum from getting cut off by ranking dust.
- Remove the mean component of weighted gradient information so tangent directions remain sum-zero.

The algorithm does not require stable active membership. It resets directions when stiffness occurs.

1. Approach and rationale

The supplied parent is close to the current discrete record, so repeating the same smooth surrogate or a purely binary annealing search is likely to produce only marginal movement. This plan uses a different main engine: a direct active-set minimax engine operating in the original sampled variables. The objective is the maximum over all finite-support cross-correlation lags. At a good point, several lags are simultaneously active or nearly active, and a direction must reduce the whole active envelope at once. Generic smoothed-gradient directions usually contain too much information from nonactive lags, while random directions are inefficient in a high-dimensional nonconvex class.

The proposed method therefore:

1. Uses exact evaluations only. Every stored competitor is recorded by the actual evaluator score.
2. Builds candidate feasible directions from the currently largest correlation terms, not from the fully smoothed objective alone.
3. Uses a second-level smoothing/relaxation tolerance around the active maximum to reduce noise from artificial kinks.
4. Minimizes along those directions by exactly exploiting that, for each direction, the entire correlation vector is a quadratic function of the step along that direction.
5. Refuses any move unless the complete candidate vector exactly improves the task's score.
6. Runs this engine over multiple sampled lengths and starts, because the sampled discrete optimum is not guaranteed to be exactly identical at every mesh length. Parent and other good candidates remain as strict valid fallbacks.

This is materially different from relying only on a smoothed maximum, binary simulated annealing, or a fixed anti-palindromic subspace. It also does not attempt to support a convexity or optimality claim. It is a constructive global-search plus structured-local-refinement upper-bound generator. The direct nonsmooth active-set directions are its central distinctive algorithmic idea.

The heuristic hypotheses are:
- Keeping many near-maximal lags active is closer to a true minimax gradient than using fully smoothed maximum weights.
- Combining several exact top-lags and minimizing the exact piecewise-quadratic envelope along combinations of their gradients can lower several active lags more effectively than arbitrary tangent directions.
- Multi-length exploration may exploit grid effects or find a shorter sequence whose stricter targeted resolution yields a lower exact discrete score.

These are hypotheses, not proven guarantees. The only claims of the plan are that a valid candidate, or at least the valid parent fallback, is returned within the time budget and scored using the original objective.

2. Mathematical specification

2.1 Exact sampled objective

For a vector `h` of length `n`, the exact evaluator is:

`raw(h) = np.correlate(h, 1.0 - h, mode="full")`, length `2n - 1`.

`dx = 2.0 / n`.

`C5(h) = dx * max(raw(h))`.

The optimization sign direction is minimization: `bound_score = C5(h)`.

Internal comparison on a fixed grid may use raw values because the raw value and the task value differ only by positive constant `dx`. All cross-grid comparisons and final accepted score must use the actual `dx * max(raw)` form.

The sampled representation and objective include boundary effects from linear correlation. There is no conversion to circular autocorrelation, no replacement with `1 - autocorrelation`, and no using only positive lags.

2.2 Exact feasibility

A valid candidate satisfies:

- `0 <= h[i] <= 1` for all `i`.
- `sum(h) == n / 2` up to the intended numerical tolerance after joint feasible repair.

The feasible direction step property used in the core:

For any direction `D` with `sum(D) = 0`, `h + alpha * D` preserves the mass constraint exactly in exact arithmetic. Feasible alpha interval along `D` intersects with the coordinate box:

- For `D[i] > 0`:
  lower bound `-h[i] / D[i]`, upper bound `(1 - h[i]) / D[i]`.
- For `D[i] < 0`:
  equivalent scaled interval endpoints represented by evaluating `h[i] / (-D[i])` and `(1 - h[i]) / (-D[i])`.
- Intervals are built from the intersection of all coordinate intervals with a safe search radius.

A final feasible normalization is required regardless of line search because accumulated floating-point error or interpolated points can move the sum. The allowed joint mechanism is a threshold water-filling projection followed by tiny residual repair, not unrelated clipping followed by simple rescaling.

Threshold water-filling normalization from vector `v` to target `T = n / 2`:

1. Define nonincreasing scalar feasibility equation `lambda -> sum(clip(v[i] - lambda, 0, 1))`.
2. Solve by bisection for a lambda whose induced sum is closest to `T`.
3. Let the remaining signed mass defect be `delta = T - sum(projected(h))`.
4. If `delta > 0`, add `delta / k` to `k` selected entries currently below 1, or add enough to several entries as their capacity permits, maintaining box until done.
5. If `delta < 0`, subtract mass from entries above 0 analogously.
6. If the result becomes feasible within about `1e-11 * dx`, accept. Otherwise call another repair construction rather than returning an invalid candidate.

For known binary vectors, converting by selecting the top `n/2` values and setting exactly those entries to 1 and others to 0 guarantees both constraints without repair. However, binary moves are auxiliary in this plan; continuous variables remain because mixed continuous optima can be useful.

2.3 Lag derivative used for active gradients

Let correlation vector index be `r = 0, ..., 2n-2`, and corresponding signed lag `tau = r - (n - 1)`. Let `m = n - |tau|`.

After a consistency calibration (discussed below), for a positive signed lag `tau > 0`:

`G[tau : n] += 1 - h[0 : m]`.

`G[0 : m] -= h[tau : n]`.

For negative signed lag `tau = -d < 0`:

`G[0 : m] += 1 - h[d : n]`.

`G[d : n] -= h[0 : m]`.

For zero lag `tau = 0`:

`G[i] = 1 - 2 h[i]`.

Because NumPy's full correlation convention must not be assumed in a handoff, a tiny calibration must be present. It may compare raw finite differences with the analytic gradient to determine whether signed lag uses direct `tau` or `-tau`. Internally store that calibration choice and reuse it everywhere. If calibration fails, use finite differences for active gradients when time permits.

A selected raw gradient is constrained to the feasible tangent by subtracting its average so its sum is zero. These gradients are used only to form directions and cannot by themselves justify acceptance.

2.4 Exact line-segment objective exact reduction

For a fixed feasible vector `h` and direction `D`, define:

`h(alpha) = h + alpha D`.

`u = 1 - h`.

Using real cross-correlation orientation independently in coefficients:

`raw(alpha) = S + alpha T - alpha^2 Q`.

where:

`S = correlate(h, u, "full")`.

`T = correlate(D, u, "full") - correlate(h, D, "full")`. Note coefficients depend on exact orientation chosen; final line value is directly evaluated from `np.correlate(h+alpha D, 1-(h+alpha D), "full")` as a double-check on selected final alpha if desired.

`Q = correlate(D, D, "full")`.

The line objective on positive dx is:

`g(alpha) = dx * max(S + alpha T - alpha^2 Q)` over feasible alpha values and coordinate constraints.

This is exactly correct for the normalized-to-relevant-correlation evaluation. To avoid not physically selecting alpha solely from a model near optimum or near non-smoothness, compare selected exact vector by actual score.

The exact line envelope may have multiple local minima because it is the maximum of many quadratics. Plan line search for practical not exact unimodality. A rough grid plus a guaranteed-line golden plus stationary points of raw-aware lags provides a rich candidate set and no wrong storage. Normanged impossible or NaN is rejected from metrics for best candidate searching itself.

Feasible bounds should never be lost to policy. Choose last exact best from `grid` points and numbers explicitly. Do not try alpha blindly adding any entry outside rule. Cached feasible interval join returned alpha0x endpoint vertices.
