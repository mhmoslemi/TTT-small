1. Approach and rationale

1.1 Central idea

The proposed method is not a linearized active-set/trust-region LP, not a graph-cut construction, and not a simple accept-if-lower random search. Its primary search engine is a sequence of smooth, full-lag, max-like surrogate objectives solved with constrained local nonlinear optimization, followed by exact line polishing and pair-transfer polishing. The essential mathematical choice is:

- Keep the exact discrete evaluator as the only decision criterion.
- Interrupt the non-smooth discrete maximization by replacing it with a smooth full-lag log-sum-exp surrogate whose temperature decreases from a broad, stable regime to a near-exact maximum regime.
- For a given temperature, solve a bound-constrained smooth-max approximation using an equality-preserving constrained nonlinear optimizer. At the end of each temperature stage, every proposed vector is restored to exact feasible form and compared against the task metric `max(np.correlate(h, 1-h, mode="full")) * dx`.
- Use diverse starting points, not only a gradient path from the supplied construction.
- After smooth annealing, refine with exact midpoint and coordinate-pair line searches. Every accepted increment, if any, is computed from the actual evaluator. If the method cannot beat the supplied construction, the supplied construction is retained as the unique fallback.

1.2 Why this addresses the likely bottleneck

A locally optimal endpoint is typically characterized by a number of lag-score rows being nearly equal at the maximum. The supplied construction is close to such a point. A 한-dimensional linearized direction that only enforces the current few constraints can stall because it is unaware of cooperative changes that lower many inactive rows while slightly changing the active plateau. A log-sum-exp target sees all finite-support rows with exponentially biased weights, so during each optimization call it can propagate small cancellations through the lag set, rather than only through the row set satisfying an active constraint. The temperature continuum then makes the final stages reproduce the actual `max` closely, while earlier stages escape sharp local maxima.

This plan is a practical heuristic local/global explorer, not a global optimality proof. It is accepted because its candidate acceptance uses the exact task metric and every returned bound is recomputed directly from the evaluator. No convexity of the original problem is assumed or claimed.

1.3 Structural difference from the supplied code

The earlier supplied optimizer creates full trust-region LP directions based mainly on currently high score rows. The proposed optimizer treats the smooth maximum as its primary objective and uses constrained local smooth optimization over all rows. Invariance transformations, dimension-transfer candidates, basin-exploration starting points, and exact line polishing are used only to search diverse basins; every non-bound improvement remains exact.

2. Mathematical specification

2.1 Representation and exact objective

For a returned vector `h` of length `n`, define:

- `dx = 2.0 / n`.
- `target = n / 2.0`.
- The feasible set `{h : 0 <= h_i <= 1 AND sum_i h_i = target}`.
- The raw score vector is the exact evaluator vector:
  `raw(h) = np.correlate(h, 1.0 - h, mode="full")`.
- The exact bound is
  `exact_C5(h) = max(raw(h)) * dx`.
The vector row convention, including notion of positive/negative lags at a row index, must be established from this exact evaluator, not re-invented. All rows `0..2*n-2` are included without cyclic wrap-around. The plan includes an explicit runtime orientation test for rows/nonzero-lag gradients to remove ambiguity.

2.2 Row derivatives

Let `R = raw(h)` and `mid = n-1`. A correct gradient matrix `G` has shape `(2*n-1, n)` and is defined for row `r` by
`G[r, k] = partial raw(h)[r] / partial h[k]`.
The explicit formula is implemented through an orientation test. Two candidate orientation builders are defined for `m = n-d` and `d=1..n-1`:

Candidate orientation I:

- For `row = mid + d`:
  `G[row, d:d+m] += 1.0 - h[0:m]`
  `G[row, 0:m] -= h[d:d+m]`

Candidate orientation II:

- For `row = mid + d`:
  `G[row, 0:m] += 1.0 - h[d:d+m]`
  `G[row, d:d+m] -= h[0:m]`

For the corresponding `row = mid - d`, mirrored assignments are
Candidate I:
  `G[row, 0:m] += 1.0 - h[d:d+m]`
  `G[row, d:d+m] -= h[0:m]`

Candidate II:
  `G[row, d:d+m] += 1.0 - h[0:m]`
  `G[row, 0:m] -= h[d:d+m]`

The zero-lag row always receives
`G[mid,:] += 1.0 - h`
`G[mid,:] -= h`
which produces the row derivative
`1.0 - 2.0*h`. This gives
`raw[mid] = sum_i h_i * (1-h_i)`.

Before smoothing begins, use the evaluator `np.correlate` to test the orientation for one or a few candidate builder matrices. Choose a column test vector `e_k`, evaluate approximate finite differences of raw scores at a perturbed point within bounds, and compare with `G[:, k]`. Choose the formula whose maximum mismatch is within tolerance. If a question remains, apply forward/reverse transformations to test symmetry; the finite-difference verification serves as a correctness gate. The exact later line searches use the true evaluator regardless of auxiliary formula correctness.

2.3 Smooth surrogate and gradient

For a temperature `tau` expressed in the same units as the scaled exact objective used by the evaluator:

- Determine scaled raw row vector
  `s = raw(h) * dx`.
- Use the stable identity
  `mval = max(s)`
  `u = (s - mval) / tau`
  `z = exp(u)`
  `LSE = mval + tau * log(sum(z))`.
- Every `LSE` equals the mathematical
  `tau * log(sum_r exp(s[r] / tau))`;
  no numerical term `mval` enters the gradient because it is a constant shift in the log-sum-exp identity for a fixed `h`.
- The optimizer has full `i` dependency in predicted gradient vector weights and evaluation:
  `probs = z / sum(z)`
  gradient wrt `h` = `G.T @ probs * dx`.
- The returned smooth objective is equal to `LSE`, minimized.

Since the underlying lag function is bilinear, the objective `LSE(h)` is generally nonconvex. Constrained local nonlinear optimization can find only local attempts, but a decreasing smooth-max annealing schedule gives opportunity to escape or balance multiple rows.

For computational robustness, if `exp(u)` underflows completely, distribute weight equally among the rows that realize `s == mval`. If `tau` becomes below a floor (recommended `max(1e-8, 1e-4 * max(1e-8, current_exact_c5))`), stop smoothing and finish by an exact coordinate polish. The exact metric then mediates acceptance.
