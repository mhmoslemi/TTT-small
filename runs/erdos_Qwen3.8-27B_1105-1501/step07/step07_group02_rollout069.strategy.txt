1. Approach and rationale

The problem is to minimize the maximum finite-support directed overlap
C(h) = (2/n) max_m corr_m(h, 1-h)
subject to 0 <= h_i <= 1 and sum_i h_i = n/2.  For n on the order of 150–350,
the objective is already a finite maximum of about 2n-1 quadratic functions.
The previous program relied mainly on pairwise coordinate moves.  Those moves
are exact one-dimensional searches, but the allowed direction vectors are very
sparse: only one sink and one source are changed at a time.  That makes the
local basin narrow and can get stuck when improving one peak increases another
peak, requiring a coherent simultaneous motion of many coordinates.

The proposed primary method is a multi-coordinate continuous local optimizer:

* construct feasible descent directions from a linear program on the active or
  nearly active correlation peaks;
* optimize each proposed direction by an exact one-dimensional search over the
  true quadratic slice of the evaluator;
* solve LP directions occasionally while using exact coordinate moves as a
  fallback and receiver;
* intensify and diversify this loop over different resolutions around the
  supplied parent, with a final binary/diversified promotion stage.

The central advantage is that the LP direction can move an entire set of
coordinates so that many active peak constraints decrease simultaneously.
The subsequent exact line search retains complete fidelity to the evaluator and
never accepts a candidate based on a surrogate.  The method remains local and
nonconvex: no global optimality is claimed.

This is materially different from the previous algorithm because the main local
update is no longer only sparse pair transfers.  It combines:
- LP-approximating tangent directions on the peak set;
- exact one-dimensional quadratic minimization along arbitrary directions;
- resolution transfer among neighboring grids;
- a short binary promotion stage to escape step/complement-structure local
  optima;
- a final exact polishing and feasibility repair stage.

2. Mathematical specification

2.1 Variables, objective, and scales

Let n be even.  The final returned vector h has length n, with spacing
dx = 2/n.  The evaluator computes

  c5(h) = max(np.correlate(h, 1 - h, mode="full")) * dx.

Use dx = 2.0 / n exactly.  The internal optimizations are best done on the
unscaled correlation vector R(h):

  R_m(h) = np.correlate(h, 1 - h, mode="full")[m], m = 0,...,2n-2,
  C5(h) = max_m R_m(h) * dx.

The acceptance and final output must use the scaled evaluator, while internal
LP active thresholds can be specified in units of R_m.  Strict feasibility
requires exactly sum_i h_i = n/2, not merely approximately.

2.2 Finite support and all lags

np.correlate(..., mode="full") has length L=2n-1.  If lag ell = m - (n-1),
the overlap has only n - |ell| valid pairs, and both directions ell>0 and
ell<0 are present.  The exact discrete overlap at lag ell is one of the two
directed forms
  sum_{i valid} h_i (1 - h_{i+ell})
with the valid boundary depending on ell.  Do not replace this objective by
1 minus a circular autocorrelation or by an average autocorrelation.  Use the
actual np.correlate vector for line-search comparisons and final checks.

2.3 Exact quadratic slice along any direction

For a direction d with sum_i d_i = 0, and h current feasible, let o = 1 - h.
Because np.correlate is bilinear in its two arguments:

  h(t) = h + t d,
  o(t) = 1 - h(t) = o - t d,
  R(t) = corr(h(t), o(t))
       = R(0) + t A - t^2 B,

where

  R(0) = np.correlate(h, o, mode="full")
  A    = np.correlate(d, o, mode="full") - np.correlate(h, d, mode="full")
  B    = np.correlate(d, d, mode="full")

The true scaled objective along this direction is max_m [R(0)_m + t A_m - t^2
B_m] * dx.  This formula should be used by the line-search helper.  Always
verify the best h(t) afterwards with the actual _exact_c5(h_new).  If the
actual score is worse, treat the direction as unsuccessful.

2.4 Gradient/password for LP active constraints

For LP directions, use an actual gradient matrix G of shape L x n.  Do not
use only pair movements and do not rely on a manually signed formula.  Compute
G by the exact derivative

  R(h + eps e_i) - R(h) = eps * (corr(e_i, 1-h) - corr(h, e_i)) + O(eps^2).

Concretely, for each i:
  e_i = vector with component 1 at i, zeros elsewhere;
  G[:, i] = np.correlate(e_i, 1 - h, mode="full")
            - np.correlate(h, e_i, mode="full").

This is robust with respect to np.correlate index/sign conventions.  The loop
cost is O(n^2) with very small constants for n <= 350.

2.5 Feasibility and projection

A feasible vector must satisfy both the box and the sum simultaneously.  Use a
joint projection.

Define _project_joint(v, target_sum=n/2) as follows:
1. Clip v to [0,1].
2. If the sum is already within 1e-13 of target_sum, pass to scalar repair.
3. Otherwise find theta so that sum_i clip(v_i - theta, 0, 1) = target_sum
   using bisection on theta in [min(v)-1, max(v)+1]. After 100 iterations, set
   y = clip(v - theta, 0, 1).
4. Let residual = target_sum - y.sum(). If |residual| < 1e-12, apply the final
   repair in step 6.
5. While |residual| > 1e-11:
   - If residual > 0, find indices with y_i < 1, increase them by
     min(residual / q, (1-y_i)) where q is the explicitly chosen number of
     most-loose open components (or a single index if sufficient room exists).
   - If residual < 0, find indices with y_i > 0, decrease them by
     min(-residual / q, y_i).
   Simplification: choose q = number of open components; each pass adds or
   subtracts residual / q but never exceeds bounds; recompute residual.  At
   least one pass should be enough numerically; if not, run bisection again on
   current y.
6. If residual <= 4e-13 or if there is an open component with room at least
   |residual|, adjust only that component so sum == target_sum exactly.  If no
   such component remains but target is mean-zero, there must exist a component
   with the needed room due to the mean half condition.

Use this projection before every objective computation and after every operation
that may introduce sum drift.  A continuous line-search along a zero-sum d need
not be projected except for safety; enforce zero sum numerically if the residual
grows past 1e-10.

2.6 Active-set LP tangent

Let R = corr(h,1-h), M = max R.  Let A be a short list of peak row indices, for
example the largest 4–20 rows, with more rows adaptive during runtime.  For
these rows the local first-order reduction condition of correlation values
R_m is

  G[m,:] dot u + beta <= 0.

Here beta is the amount of first-order peak reduction along a directional
step.  We maximize beta subject to a normalized direction.

Use split variables sp_i >= 0 and sn_i >= 0 with u_i = sp_i - sn_i.  The unit
direction scale is

  sum_i (sp_i + sn_i) = 1.

Also require balance

  sum_i sp_i - sum_i sn_i = 0.

Bounds:
  0 <= sp_i <= 1,
  0 <= sn_i <= 1,
  beta free but bounded sufficiently (e.g. [-1e6, 1e6] only because SciPy is
  numerically happier with bounds; the LP objective will keep it meaningful).

For each active row r in A:
  sum_i G[r,i] sp_i - sum_i G[r,i] sn_i + beta <= 0.

Solve
  minimize -beta
subject to those linear constraints, the equality constraints, and bounds.

Important details:
- Do not impose h_i + u_i bounds on the LP; they make the LP overly conservative.
  The exact line-search interval enforces feasibility of the chosen scalar t.
- Start with a moderate peak count, e.g. top 6.  If the LP fails to produce an
  accepted line-search improvement, later try top counts 10, 18, 30, then 4.
- If the LP fails but an approximate direction would improve a subset, retry LP
  with top rows only (not thresholding by difference from max) rather than rows
  below a razor geo-threshold.
- If the LP is not solvable with SciPy's HiGHS, retry with the default SciPy
  high-level method and finally fall back to coordinate exact moves.

Extract direction u = sp - sn.  If the optimizer returns tiny u, reject it.
If it returns u with finite values and directional sum near 0, normalize to
unit L1 exactly or rely on the equality.  Use this u only as a proposed
direction; exact c5 decides.

2.7 Exact one-dimensional line-search along a direction

Given h and unit stored vector u:
1. Build A and B from section 2.3.
2. Determine t_min and t_max such that 0 <= h_i + t u_i <= 1. Initialize

   - if u_i < 0:

6. Choose best_t.  Construct h_new = h + best_t u.  Project only for numerical
