Hmm, the CD with the direct approach is getting complex. Let me use a simpler but effective CD:

For each coordinate j, I'll try a few candidate values and pick the one that minimizes C5. The candidates are:
1. Current value
2. 0
3. 1
4. Current ± 0.01, ± 0.05, ± 0.1 (clipped to [0,1])
5. Values that make the top 3 correlations equal to each other

After trying all candidates for coordinate j, I pick the best one. Then I project to maintain the sum constraint.

Actually, this is still O(n * k * n) per sweep where k is the number of candidates. Let me think of a faster way.

The fastest approach: for each j, compute the derivative of C5 w.r.t. h_j (treating other coordinates as fixed). Since C5 = max_d R_d, the derivative is:
dC5/dh_j = max_{d in active} s_d,j

where s_d,j = dR_d/dh_j and "active" means R_d is near the maximum.

If the derivative is positive, decreasing h_j helps. If negative, increasing h_j helps. The optimal h_j is where the derivative changes sign (or at a boundary).

But this is a 1D problem where the objective is the max of linear functions (approximately, for small changes). I can find the optimal by:
1. Computing all s_d,j
2. The function f(delta) = max_d (R_d + delta * s_d,j)
3. Finding delta that minimizes f, subject to delta in [-h_j, 1-h_j]

The minimum of the upper envelope of lines occurs at a point where two lines cross (or at a boundary). I can find it by:
- Sorting the lines by slope
- Sweeping and tracking the upper envelope
- Finding where the minimum of the envelope is

This is O(n log n) per coordinate, O(n^2 log n) per sweep. For n=180, that's about 180 * 180 * 8 = 260K per sweep. Very fast!

But implementing the upper envelope efficiently in numpy is tricky. Let me just use a simpler approach:

For each j:
1. Compute s = s_d,j for all d (O(n))
2. The new R would be R + delta * s
3. I want to find delta in [lo, hi] that minimizes max(R + delta * s)
4. Use golden section on interval [lo, hi] (since max of lines is convex)

Wait! The max of linear functions IS convex! So golden section works!

f(delta) = max_d (R_d + delta * s_d) is convex in delta (max of affine functions is convex).

So I can use golden section to find the minimum in O(log(1/eps)) evaluations, each O(n). Total O(n log(1/eps)) per coordinate.

With 50 iterations of golden section (more than enough for 1e-10 precision), that's O(n * 50) = O(9000) per coordinate. For all n coordinates: O(n^2 * 50) = O(1.6M) per sweep.

At 100M operations per second (conservative), that's about 0.016s per sweep. We can do ~60000 sweeps in 1100s. Way more than enough.

But in practice, Python overhead means maybe 100-500 sweeps. Still fine.
