            dc[ci+t] -= h[j+t]  # (1-h[j]) was 1, now 0. Term goes from h[j+t]*1 to h[j+t]*0

            dc[ci-s] -= h[j-s]  # (1-h[j]) was 1, now 0
    
    return dc

The main bottleneck is the inner loop: for each (i,j) pair, we compute np.correlate. That's a Python function call each time. For 8100 pairs, that's 8100 Python function calls per sweep.

Alternative: vectorize the swap evaluation.

For a given i (fixed), the effect of swapping h[i] (1→0) with h[j] (0→1) for all j can be computed more efficiently:

Start with h, set h[i] = 0. Then for each j in zeros:
  set h[j] = 1, compute max correlation, set h[j] = 0.

The first step (h[i]=0) changes the correlation from C0 to C0 + Δi where Δi is the effect of setting h[i] from 1 to 0.

Then for each j, the additional effect of setting h[j] from 0 to 1 is Δj (computed with h[i] already at 0).

So: new_corr = C0 + Δi + Δj
new_max = max(new_corr)

We can precompute Δi once, then for each j, compute Δj and take the max.

But computing Δj still requires O(n) work per j (to find the max of C0 + Δi + Δj). Unless we maintain a data structure.

Actually, the max of (C0 + Δi + Δj) over all positions p is:
max_p (C0[p] + Δi[p] + Δj[p])

If we precompute A = C0 + Δi, then for each j we need max_p (A[p] + Δj[p]).

Δj is nonzero at O(n) positions (all positions that involve index j). So we need to check O(n) positions per j. Total: O(n) per j, O(n²) for all j at a fixed i. Plus the initial O(n²) for C0. Total per sweep: O(n³).

For n=180: 180³ = 5.8 million operations. In Python, that's maybe 1-2 seconds per sweep. Too slow!

The numpy correlate approach (O(n²) per evaluation, but in C) is actually faster for the full sweep:
