```python
        return np.zeros(n)
    if target >= n:
        return np.ones(n)
```

```python
        A[m, i] += delta
```

This is O(n) per change. Since we have 2 changes per swap (u[oi] += 1, u[oz] -= 1), the total update is O(n).

With this, each swap evaluation is O(n) (to compute max of new_c = c - A[:,oi] + A[:,oz]), and each accepted swap has O(n) update cost. The total per round is O(n³) for evaluation + O(n) per accepted swap.

For n=180: one round is about 180 * 180 * 360 ≈ 11.7M operations. That's fast.

```python
def _solve_lp(A, n):
    h_var = cp.Variable(n)
    t_var = cp.Variable()
    constraints = [
        h_var >= 0,
        h_var <= 1,
        cp.sum(h_var) == n / 2.0,
        A @ h_var <= t_var
    ]
    prob = cp.Problem(cp.Minimize(t_var), constraints)
    
    for solver in [cp.GLOP, cp.ECOS, cp.PDLP]:
        try:
            prob.solve(solver=solver)
            if h_var.value is not None:
                return h_var.value.copy()
        except:
            continue
    return None
```

One more thought: the LP approach gives binary solutions. But what if I add a small regularization to the LP to encourage non-binary solutions? For example:

min t - ε * ∑ h_i (1 - h_i)

The second term is a concave function of h_i (it's maximized at h_i = 1/2). Minimizing t - ε * ∑ h_i(1-h_i) is equivalent to minimizing t + ε * ∑ (h_i - 1/2)² (since ∑ h_i(1-h_i) = ∑ (1/4 - (h_i-1/2)²) = n/4 - ∑(h_i-1/2)²). Wait, that's not right.
