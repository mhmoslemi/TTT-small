    """Compute change in correlation at lag L after swapping h[p]:1->0, h[q]:0->1."""
    # Affected i values (where the term h[i]*(1-h[i+L]) might change)
    candidates = set()
    if 0 <= p < n and 0 <= p+L < n:

    if 0 <= p-L < n:  # p-L >= 0 and p < n (p is the second index)

```python
def _swap_delta_vec(h, p, q, n):
    """
    Compute the change vector Δ[k] for k=0..2n-2 after swapping h[p]:1→0, h[q]:0→1.
    Returns the delta array of length 2n-1.
    """
    delta = np.zeros(2*n-1)
    for L in range(-(n-1), n):
        if L == 0:
            continue
        k = n - 1 + L
        # Affected i values
        affected = []
        if 0 <= p < n and 0 <= p+L < n:
            affected.append(p)
        ip = p - L
        if 0 <= ip < n:
            affected.append(ip)
        if 0 <= q < n and 0 <= q+L < n:
            affected.append(q)
        iq = q - L
        if 0 <= iq < n:
            affected.append(iq)
        # Remove duplicates
        if len(affected) > 1:
            affected = list(set(affected))  # or manual dedup
        for i in affected:
            j = i + L
            if 0 <= i < n and 0 <= j < n:
                hi_old = h[i]
                hj_old = h[j]
                hi_new = 0.0 if i == p else (1.0 if i == q else h[i])
                hj_new = 0.0 if j == p else (1.0 if j == q else h[j])
                delta[k] += hi_new * (1.0 - hj_new) - hi_old * (1.0 - hj_old)
    return delta
```

- At lag -d: the pair is (q, p): h[q]*(1-h[p]) = 0*0 = 0 → 1*1 = 1. c(-d) changes by +1.
  
  Wait, that's interesting. Swapping a (1,0) pair at distance d INCREASES c(-d) by 1!

  Hmm, but c(L) and c(-L) are not the same in general (the correlation function isn't necessarily symmetric for non-reversible sequences).
  
  Actually: c(L) = sum h[i]*(1-h[i+L]), c(-L) = sum h[i]*(1-h[i-L]).
  These are different in general.
  
  For binary h: c(L) + c(-L) at a specific pair (i, i+L):
  c(L) contribution: h[i]*(1-h[i+L])
  c(-L) contribution: h[i+L]*(1-h[i])
  Sum: h[i]*(1-h[i+L]) + h[i+L]*(1-h[i])
  For binary: if (h[i], h[i+L]) = (1,0): sum = 1*1 + 0*0 = 1
  If (h[i], h[i+L]) = (0,1): sum = 0*0 + 1*1 = 1
  If (h[i], h[i+L]) = (1,1): sum = 1*0 + 1*0 = 0
  If (h[i], h[i+L]) = (0,0): sum = 0*1 + 0*1 = 0
  
  So c(L) + c(-L) = number of (1,0) pairs + number of (0,1) pairs at distance L = number of "different" pairs at distance L.
  This is invariant under swapping! So c(L) + c(-L) is preserved.
  
  Therefore, swapping a (1,0) pair to (0,1) at distance d decreases c(d) by 1 and increases c(-d) by 1. The max might go either way.
  
  This means that simply swapping to reduce one lag might increase the other. The optimization is non-trivial.

OK, I think the fastest approach is to just implement the O(n) swap update and do a large number of SA iterations with targeted proposals. Let me code this up.

One more optimization: instead of computing the full delta vector (length 2n-1) and then adding it to raw, I can directly update raw. And for the acceptance criterion, I just need to check if max(raw) decreased. I can maintain the max efficiently by noting that only the changed entries can affect the max.

def _compute_swap_delta(h, p, q, n):
    """Vectorized computation of swap delta."""
    # L ranges from -(n-1) to (n-1), excluding 0
    Ls = np.arange(-(n-1), n)
    Ls = Ls[Ls != 0]
    k_idx = n - 1 + Ls  # indices into the 2n-1 raw array
    
    # For each i in {p, p-L, q, q-L}, compute contribution
    # This is tricky to fully vectorize due to the "valid range" conditions
    # and the deduplication requirement.
    
    delta = np.zeros(2*n-1)
    
    # Term at i=p (p is first index): valid where 0 <= p+L < n
    valid = (p + Ls >= 0) & (p + Ls < n)
    if np.any(valid):
        Ls_v = Ls[valid]
        partners = p + Ls_v  # = p+L, the partner index
        # Old: h[p]*(1-h[partner]) = 1*(1-h[partner])
        # New: 0*(1-h_new[partner]) = 0
        # Delta: 0 - (1-h[partner]) = h[partner] - 1
        h_partner = h[partners]
        h_partner_new = h_partner.copy()
        h_partner_new[partners == q] = 1.0  # if partner is q, its new value is 1
        h_partner_new[partners == p] = 0.0   # can't happen since partner = p+L != p (L!=0)
        # Wait, the new value of partner:
        # If partner == q: new value is 1, old was 0
        # If partner == p: impossible (L!=0)
        # Otherwise: unchanged
        # Delta = new_term - old_term = 0 - (1 - h_old[partner])
        # But h_old[partner] might be different from h_new[partner] if partner==q
        # old_term = 1 * (1 - h_old[partner])
        # new_term = 0 * (1 - h_new[partner]) = 0
        # delta = -(1 - h_old[partner])
        d = -(1.0 - h_partner)
        delta[k_idx[valid]] += d
    
    # Term at i=p-L (p is second index, i=p-L is first): valid where 0 <= p-L < n
    ip = p - Ls
    valid = (ip >= 0) & (ip < n) & (p >= 0) & (p < n)  # p is always valid as second
    # Actually: i = p-L must be in [0,n-1], and i+L = p must be in [0,n-1] (which it is since 0<=p<n)
    valid = (ip >= 0) & (ip < n)
    if np.any(valid):
        first_idx = ip[valid]
        Ls_v = Ls[valid]
        # Old: h[first_idx]*(1-h[p]) = h[first_idx]*0 = 0
        # New: h_new[first_idx]*(1-h_new[p]) = h_new[first_idx]*1 = h_new[first_idx]
        # h_new[first_idx] = 1 if first_idx==q, else h[first_idx]
        h_first = h[first_idx]
        h_first_new = h_first.copy()
        h_first_new[first_idx == q] = 1.0
        h_first_new[first_idx == p] = 0.0  # impossible since first_idx = p-L != p
        d = h_first_new - 0.0
        delta[k_idx[valid]] += d
    
    # Term at i=q (q is first index): valid where 0 <= q+L < n
    valid = (q + Ls >= 0) & (q + Ls < n)
    if np.any(valid):
        partners = q + Ls[valid]
        # Old: h[q]*(1-h[partner]) = 0
        # New: 1*(1-h_new[partner])
        h_partner = h[partners]
        h_partner_new = h_partner.copy()
        h_partner_new[partners == p] = 0.0
        d = 1.0 - h_partner_new
        delta[k_idx[valid]] += d
    
    # Term at i=q-L (q is second index, i=q-L is first): valid where 0 <= q-L < n
    iq = q - Ls
    valid = (iq >= 0) & (iq < n)
    if np.any(valid):
        first_idx = iq[valid]
        # Old: h[first_idx]*(1-h[q]) = h[first_idx]*1 = h[first_idx]
        # New: h_new[first_idx]*(1-h_new[q]) = h_new[first_idx]*0 = 0
        h_first = h[first_idx]
        h_first_new = h_first.copy()
        h_first_new[first_idx == p] = 0.0
        d = 0.0 - h_first  # Wait, this is wrong.
        # Actually: new_term - old_term = 0 - h[first_idx] (old)
        # But if first_idx == p, then old h[first_idx] = 1 and new h_new[first_idx] = 0
        # old_term = 1*(1-0) = 1, new_term = 0*0 = 0, delta = -1
        # My formula gives: 0 - h[p] = 0 - 1 = -1 ✓
        # If first_idx != p: old_term = h[first_idx]*(1-0) = h[first_idx], new_term = h[first_idx]*0 = 0
        # delta = -h[first_idx]. My formula gives 0 - h[first_idx] ✓
        # But wait, if first_idx == q? Impossible since first_idx = q-L != q (L!=0)
        d = -h_first
        delta[k_idx[valid]] += d
    
    return delta

Wait, but this has the double-counting problem! When p+L = q (i.e., L = q-p > 0), the "i=p" term and the "i=q-L" term refer to the SAME term (i=p, partner=q). Let me check:
- "i=p" with L=q-p: partner = p+L = q. Term = h[p]*(1-h[q]).
- "i=q-L" = "i=q-(q-p)" = "i=p": first_idx = p. Term = h[p]*(1-h[q]).

Yes, same term! In my vectorized code:
- "i=p" contribution: -(1-h[q]) = -(1-0) = -1
- "i=q-L" contribution: -h[p] = -1
Total from these two: -2. But the true delta is: new - old = 0 - 1 = -1.

So I'm overcounting by 1 in this case. Similarly for L = p-q:
- "i=p-L" = "i=q": contribution = h_new[q] - 0 = 1
- "i=q" with L=p-q: partner = q+L = p. contribution = 1 - h_new[p] = 1 - 0 = 1
Total: 2. True delta: new - old = 1 - 0 = 1. Overcounted by 1.

To fix this, I need to subtract the correction when |p-q| = |L| and the specific overlap condition holds.

The correction cases:
1. L = q - p > 0: overlap between "i=p" and "i=q-L". 
   - The "i=p" term computed delta = -(1-h[q]) = -1 (since h[q]=0)
   - The "i=q-L" term computed delta = -h[p] = -1 (since h[p]=1)
   - True delta for this term: new - old = 0 - (1*1) = -1
   - Overcount: -2 - (-1) = -1. So I need to ADD 1.
   
2. L = p - q > 0: overlap between "i=p-L" and "i=q".
   - The "i=p-L" = "i=q" term: delta = h_new[q] - 0 = 1
   - The "i=q" term with partner p: delta = 1 - h_new[p] = 1
   - True delta: new - old = 1 - 0 = 1
   - Overcount: 2 - 1 = 1. So I need to SUBTRACT 1.

3. L = q - p < 0 (i.e., L = -(p-q), same as case with distance d = p-q):
   This is the same as case 2 with L negative. Let me re-examine.
   
   If L < 0, let d = -L = p-q > 0 (assuming p > q):
   - "i=p" with L=-d: partner = p+L = p-d = q. Term = h[p]*(1-h[q]) = 1*1 = 1 → new: 0*0 = 0. Delta = -1.
   - "i=q-L" = "i=q+d" = "i=p": first_idx = p. Term = h[p]*(1-h[q]) = same term!
     delta = -h[p] = -1.
   - Overcount again: -2 vs true -1. Add 1.
   
   - "i=p-L" = "i=p+d": if p+d < n, first_idx = p+d. This is a different term.
   - "i=q" with L=-d: partner = q+L = q-d. Different from p in general.
   
   So case 3 (L = q-p < 0, i.e., q < p and L = q-p) has the same overlap as case 1.

Let me summarize: the overlap occurs when |L| = |q-p|, i.e., L = q-p or L = p-q.

Case A: L = q-p (which could be positive or negative):
- Overlap between "i=p" (partner = p+L = q) and "i=q-L" (first_idx = q-L = p)
- Correction: the computed delta is -1 (from i=p) + (-1) (from i=q-L) = -2
- True delta: -1
- Add +1 to delta at this L

Case B: L = p-q:
- Overlap between "i=p-L" (first_idx = p-L = q) and "i=q" (partner = q+L = p)
- Computed delta: +1 (from i=p-L) + 1 (from i=q) = 2
- True delta: +1
- Subtract 1 from delta at this L

So the correction is:
- At L = q-p: add +1
- At L = p-q: subtract 1
(where these L values are in the valid range [-n+1, n-1] and ≠ 0)
