Let me also think about a completely different angle: **semidefinite programming (SDP) relaxation**.

The bilinear term h[i]*h[i+m] can be relaxed using a moment matrix. Define X as an n×n matrix with X[i,j] = h[i]*h[j]. Then:
- X[i,i] = h[i] (since h[i]^2 = h[i] for binary, but for continuous h[i]^2 ≤ h[i])
- X is PSD (it's a Gram matrix: X[i,j] = h[i]*h[j], so X = h*h^T which is rank-1 and PSD)
- X[i,j] ≤ h[i] (from h[i]*h[j] ≤ min(h[i],h[j]))
- X[i,j] ≤ h[j]
- X[i,j] ≥ 0

The SDP relaxation would be:
minimize t
subject to: ∑_{valid i} h[i] - X[i, i+m] ≤ t for all k
           X = h*h^T (relaxed to X ⪰ 0)
           X[i,j] ≤ h[i], X[i,j] ≤ h[j], X[i,j] ≥ 0
           ∑h = n/2, 0≤h≤1

But this SDP is very large (n×n matrix variable = 180×180 = 32400 entries). For n=180, this might be too large for practical solving, especially with the rank-1 constraint.

However, we can use the fact that X = h*h^T is rank-1, and instead work with the vector h directly. The issue is that the bilinear terms make it non-convex.

Let me also think about the "n" parameter. The problem says "smaller sequences with less than 2k samples are preferred." The initial is n=180. We might be able to do better with a different n.

For the LP approach, the key insight is that the LP solution is a vertex of the feasible polytope (since we're minimizing a linear function over a polytope). The vertices of the polytope {h : ∑h = n/2, 0≤h≤1} are the binary vectors with exactly n/2 ones. So the LP solution will always be binary (or close to binary) if the constraints are tight!

Wait, that's not quite right. The LP has additional constraints (M@h ≤ t), so the feasible region is smaller. The optimal solution of the LP will be at a vertex of this smaller polytope, which may be fractional.

But if the M@h ≤ t constraints are not active at the optimum, then the LP reduces to min t (with t free), which is unbounded below. So the M@h ≤ t constraints must be active.

Actually, the LP is:
min t
s.t. M[k,:] @ h ≤ t for all k
     ∑h = n/2
     0 ≤ h ≤ 1

The objective is just t, and we're minimizing it. The constraint M[k,:] @ h ≤ t means t ≥ max_k M[k,:] @ h. So we're minimizing max_k M[k,:] @ h.

This is a linear programming formulation of a min-max problem. The optimal solution will generally be fractional (not binary), because the min-max of linear functions over a polytope typically has a fractional optimum.

For example, min max(x, 1-x) over [0,1] has optimum at x=0.5 (fractional).

So the LP will give a fractional h, which is good for the continuous problem.

Now, will the LP-based BCD make progress? Let me think about it differently.

The true objective is F(h) = max_k g_k(h) where g_k(h) = M_k(1-h) @ h = ∑_{valid} (1-h[j])*h[i] (bilinear).

At point h, the LP solves: min_{h'} max_k M_k(1-h) @ h'

This is a linear objective (in h') that matches F(h) at h (since M_k(1-h) @ h = g_k(h) = raw_k). So the LP gives the best h' in terms of the linearized objective.
