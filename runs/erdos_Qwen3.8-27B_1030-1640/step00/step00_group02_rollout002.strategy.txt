1. Approach and rationale

Central idea

The search is carried out directly in the feasible set by moving along one-dimensional affine directions that preserve the integral constraint and respect the box bounds. A direction is accepted or rejected only by evaluation with the exact objective. The core improvement method is an exact feasible linear-path minimizer: given a feasible vector `h` and a sum-zero direction `d`, the vector path `h(t)=h+t*d` is feasible for `t` in a interval that can be computed from the current bounds. Along this path every discrete overlap value is a quadratic polynomial in `t`; therefore, after using a few exact evaluations to recover those polynomials, candidate local minima can be found almost exactly from stationary points and intersections of all large overlap components. Each candidate is rebuilt, repaired for floating-point feasibility, and evaluated by the original evaluator before acceptance. Because the move remains in the sum-zero subspace at every iteration, no nontrivial projection is needed during most of the search. The most important number of enforcement stays in the exact evaluator.

Why this addresses the task

The supplied parent may be a very good local construction: only a tiny decrease from the current value is needed to reach the target. A general nonlinear programming epigraph can do this, but it is limited by constraint tolerance and the mass of active constraints. The proposed method is strongly specialized: every policy iteration preserves the constraint by construction, the active overlap model has a small finite structure, and candidate points on the best line are obtained analytically rather than through a generic solver.Directional descent can use hard active-set gradients, smoothed gradients, random directions, and all coordinate transfer directions. This gives a richer family of feasible movements than fixed point relay or direct projection. A local scalar path is minimized sufficiently accurately to push a flat active group below its current maximum, but solutions are always exact-order-recorded.

Substantive distinction

The plan's substantive core is not a CVXPY epigraph, not a log-sum-exp surrogate continuation, and not raw black-box evolution. It is feasible affine direction + exact quadratic path minimization + acceptance by the original discrete evaluator. Pairwise exchange operations are recovered as special directions `e_i-e_j`, but the main tools include generalized active-gradient projection directions and brute random directions that simultaneously move many coordinates while remaining integral. This concentrated mathematical structure attempts to extract the required small improvement from the supplied parent and still has different fallback constructions when no parent exists.

Key facts

For any feasible sum-zero discrete vector `h`, integer integral and finite bounds make `h` valid. For any output lag index `m` in the evaluator's linear-correlation array, the value is a sum over valid pairs of terms `h_i(1-h_j)`. Along an arbitrary direction path `h_i(t)=h_i+t*d_i`, each term is a polynomial of degree at most two in `t`, so each overlap output is quadratic in `t`. Therefore the exact one-dimensional restricted problem is the minimization of a maximum of known quadratics over a finite interval. Stationary points and roots of differences between quadratics, together with interval endpoints, form a finite candidate superset.

Key heuristics and limits

Candidate paths are generated from Gram hard/soft relations and random callback. There is no Claim global minimization across all paths. The full overlap-basis exact path minimization is valid for a chosen line, assuming retained coefficients are high. For dimension levels larger than moderate sizes, restricting intersection generation to large interval components is heuristic; only strict final evaluation protects from wrong acceptance. The method can get stuck at coordinate/path optimum; randomized feasible walks and multi-start mechanisms search around parents. Numerical errors from papers evaluate step results using repositories emulate algorithm. no untested local optimum values are asserted.
