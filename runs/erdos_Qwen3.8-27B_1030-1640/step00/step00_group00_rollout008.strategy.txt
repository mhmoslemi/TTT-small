1. Approach and rationale

The evaluator defines the objective as

C(h) = max over all lags in np.correlate(h, 1-h, mode="full") * dx,  dx = 2/n,

with h in R^n, 0 <= h_i <= 1, and sum(h) * dx = 1, equivalently sum(h) = n/2. This is a finite-support, nonconvex minimax problem. A direct general-purpose convex program is not available because the objective contains products h_i h_j. The proposed method therefore does not claim a global optimum from a convex solver. It obtains a valid upper bound by continuous multistart local improvement, exact local two-coordinate line minimization, and final exact re-evaluation.

The supplied `initial_h_values` array, when available, is used as the incumbent fallback and as one or more starting points. Its objective value is taken from the evaluator, not from an assumption. If no parent is available, deterministic and randomly generated feasible constructions are used. If `initial_h_values` is unavailable, a uniform half-mass feasible array or other algorithmic noncopying constructions are used.

The main bottleneck of direct evaluation is the max/minimax structure: gradient information is concentrated on only the few active lags. The method addresses this with:

- A smooth soft-max objective with annealing. This forms stable gradients over a weighted set of high lags rather than a single top constraint.
- Projection onto the exact feasible set: the same projection treats the box constraints and the linear mass sum simultaneously.
- Accelerated/projected steepest descent with line search during a descending annealing schedule.
- After each smoothed descent, an exact one-dimensional penalized local search along two-coordinate transfers. A two-coordinate transfer preserves sum and bounds exactly; the exact overlap objective along that segment is the maximum of affine and convex quadratic functions and is therefore convex/unimodal. This is optimized directly by bounded ternary/golden search, using the original evaluator, not by the smoothed surrogate.
- Small optional resolution changes and exact dyadic repair, used only in ways that are validated by the real evaluator.

This design deliberately separates candidate generation from objective acceptance. Every returned candidate is re-evaluated using the authoritative evaluator. Any solver-based or heuristic step that is not convex in the full space is only a proposal mechanism; acceptance is exact. The only claimed properties are: returned arrays satisfy the constraints to a stated numerical tolerance; the exact objective value is computed from the returned array; and improvements over existing incumbents are accepted only if exact.

2. Mathematical specification

Notation and shapes

- n = number of grid points.
- dx = 2.0 / n.
- target_mass = n / 2.
- h is an ndarray of shape (n,), dtype float64.
- Feasible set is F = {h : 0 <= h_i <= 1 for all i, sum_i h_i = target_mass}. The target mass may be integral or half-integral. For n=45 it is 22.5.
- The authoritative objective function used for acceptance is exactly:
  C(h) = max(np.correlate(h, 1-h, mode="full")) * dx.
  The returned objective value must be this exact scalar, recomputed after any projection, transformation, perturbation, pair move, dyadic repair, or final return.

Exact finite-support overlap set

For clarity, define the exact overlap terms for all relevant lag directions:

For l = 0,
  A_0 = B_0 = dx * sum_{i=0}^{n-1} h_i * (1 - h_i).

For l = 1, ..., n-1,
  A_l = dx * sum_{i=0}^{n-1-l} h_i * (1 - h_{i+l}),
  B_l = dx * sum_{i=0}^{n-1-l} h_{i+l} * (1 - h_i).

Let G(h) = [A_0, A_1, ..., A_{n-1}, B_1, ..., B_{n-1}], of shape (2n-1,). The set of real terms in np.correlate(h, 1-h, "full") * dx is the same values arranged in a correlation-order permutation, with a repeated or permuted zero-lag term depending on convention. Therefore

C(h) = max(h, G(h)).

This formulation avoids relying on the exact orientation of positive and negative lags and explicitly includes both directions, preserving boundary terms.

Feasibility projection

Given y in R^n and m = n/2, compute

P(y) = argmin_z 1/2 ||z-y||_2^2 subject to 0 <= z_i <= 1, sum_i z_i = m.

The solution is

P(y)_i = clip(y_i + lambda, 0, 1),

where lambda is chosen so that sum_i clip(y_i + lambda, 0, 1) = m. Since this sum is monotone nondecreasing in lambda, find lambda by bisection:

1. If sum(clip(y,0,1)) is already within tolerance of m, return clip(y,0,1).
2. Expand a lower/upper bracket: lower sufficiently negative so sum clip(y+lower) <= m, upper sufficiently positive so sum clip(y+upper) >= m. A practical initial cheap bracket is lower = -max(y)-n, upper = max(1-y)+n, and expand by doubling until bracket signs are correct.
3. Bisection for around 60 iterations, computing sum(clip(y + mid, 0, 1)) each iteration.
4. Return the clipped midpoint.

This projection is feasible jointly and nonexpansive. Each update that must remain feasible projects the whole vector, rather than clipping and rescaling independently.

Smoothed surrogate objective

For temperature theta > 0 define

S_theta(h) = theta * log(sum_G exp(G_h_lag / theta)),

where G_h_lag denotes the components of G(h). Gradient:

grad S_theta(h) = sum_k w_k(h) grad G_k(h),
w_k(h) = exp(G_k(h) - max(G(h))) / sum_j exp(G_j(h) - max(G(h))).

This is computed in numerically stable software: temporarily subtract max(G), exponentiate, normalize weights exactly sum to 1. If all weights are zero due to variance or nans, use uniform weights over active components and abort the step. The temperature is only a surrogate device; acceptance uses C(h).

Gradient of correlation terms

For each positive lag l:

For A_l = dx * sum_{i=0}^{n-1-l} h_i (1-h_{i+l}), gradient contributions multiplied by a lag weight u_l:

- Linear part: add u_l * dx to indices 0 through n-1-l.
- Derivative as first multiplier h_i: subtract u_l * dx * h[l:n] from indices 0 through n-1-l.
- Derivative as shifted coordinate h_{i+l}: subtract u_l * dx * h[0:n-1-l] from indices l through n-1.

For B_l = dx * sum_{i=0}^{n-1-l} h_{i+l} (1-h_i), gradient contributions:

- Linear part: add u_l * dx to indices l through n-1.
- Derivative as first multiplier h_{i+l}: subtract u_l * dx * h[0:n-1-l] from indices l through n-1.
- Derivative as shifted coordinate h_i: subtract u_l * dx * h[l:n] from indices 0 through n-1-l.

For l=0 this reduces to derivative of dx * sum_i (h_i - h_i^2): add dx to all coordinates and subtract 2*dx*h from all coordinates, when the l=0 term has weight.

The full gradient of S_theta is the weighted sum of these contributions. The product is important: each gradient is multiplied by the corresponding softmax weight. Include both positive and negative lag families in the sum. Every candidate line search uses the smoothed objective only to choose directions and directions; the exact evaluator computes acceptance.

Two-coordinate exact line search

For a chosen pair of distinct source and target indices (s,t), define a transfer amount tau moving mass from s to t:

h_s(tau) = h_s - tau,
h_t(tau) = h_t + tau,
0 <= tau <= T = min(h_s, 1-h_t).

All sums and bounds remain feasible for every tau in [0,T]. For any lag term, expressions h_i(1-h_j) whose indices are not exactly the pair remain affine in tau. If a pair appears in both positions for the same term, the product coefficient is positive:

- For h_s * (1-h_t) under source decrease and target increase: (h_s - tau)(1-h_t - tau) has dependence plus tau^2.
- For h_t * (1-h_s): (h_t + tau)(1-h_s + tau) also has plus tau^2.

Therefore each correlation-coordinate component of G(h(tau)) is affine or a convex quadratic in tau. The maximum of affine and convex quadratic functions is convex on the interval. Thus C(h(tau)) is a bounded unimodal scalar function that can be minimized by standard ternary/golden section. The returned tau and the actual line value matter; they are evaluated by the exact evaluator.

Implementation note: the incidental floating-point tau value need not make sum exactly bitwise integer; after accepting pair moves, return a vector that has been feasibility-repaired or sum-projected. Final acceptance criteria still include projection if needed.

Nonconvexity and convex-solver boundary

The full problem contains h_i(1-h_j), not generally convex or concave over the box. Avoid claiming direct CVXPY/QP feasibility for it. Do not formulate h_i*(1-h_j) <= tau as a DCP constraint unless the solver explicitly supports nonconvex quadratics with certified treatment. This plan uses no such exact convex reformulation. It may optionally use generic nonlinear optimizer with simple linear range constraints, but only with exact acceptance; custom projected gradient and line search are preferred.

3. Implementation procedure

Helper responsibilities

All helpers are top-level and nondynamic. Recommended names:

- evaluate_C(h): implements exact np.correlate objective with dx. Returns a float.
- objective_G(h): returns the vector G using A_l/B_l formulas. Used for diagnostics, surrogate weights, and validation. Compare max(max(G), max(evaluate_C(h))) for small sanity checks; they should agree up to implementation roundoff. The return contract still uses evaluate_C.
- is_feasible(h): checks bounds within a tolerance and mass tolerance. It should be used for diagnostics but final answer applies direct projection/repair.
- project_h(y): projection to F using lambda bisection described above. Passes lower to reduce arbitrary vector y.
- random_projected_vector(n, rng, mode): samples an unconstrained vector from mode and projects. Modes:
  - "uniform": all 0.5 plus tiny noise.
  - "softparent": around a base h with Gaussian perturbation and sign-preserving wave.

- smoothed_objective_and_grad(h, theta): returns F_theta(h), its gradient, components G, theta, active weights, and exact max. If numerical failure occurs (nan, overflow, degenerate weights), return nan objective and zero gradient; the caller aborts the line step or temperature jump.
- weighted_grad_from_components(h, g, theta): high-leverage subhelper if the objective helper is split. It computes G, softmax values, and incremental weighted gradient.
- projected_gradient_step(h, theta, max_inner_iters, time_stop): returns an improved feasible h and exact best seen along inner path.
- exact_pair_line_search(h, source, target, max_evals): returns best feasible line update and its objective, if strictly better.
- multiplier_two_coord_repair(h, rng, max_trials, time_stop): stochastic pair-descent policy. Returns improved feasible h and evaluation log.
- dyadic_feasible_repair(h, itr): rounds to a power-of-two grid (1/16 or smaller) and adjusts a list of coordinates by one grid unit to satisfy target sum exactly, then returns changed h if valid. Better: use this only for final safety, recompute exact objective and retain whichever among continuous, parent, quantized, etc.
