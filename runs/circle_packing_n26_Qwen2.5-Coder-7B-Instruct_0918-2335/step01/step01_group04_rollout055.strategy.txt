**A new, geometry‑driven, two‑stage optimisation**  

The previous approach solved the full 52‑dimensional problem with a nonlinear optimizer that had to discover *in one shot* a set of centres and radii.  That optimisation often got trapped in local minima and could not exploit the fact that, **once the centres are fixed, the radii form an exactly solvable linear program**.  

The strategy below separates the problem into *position optimisation* (guided by the geometry that actually constrains the circles) and *radius optimisation* (implemented as a fast LP).  By iterating the two steps, the algorithm can make large, directed moves in the position space, while always keeping a feasible set of radii.  Quick convergence and high quality solutions are obtained, and the final solution is polished by a short nonlinear SLSQP run.

---

### 1.  Overall pipeline

```
for each restart (≈8 total):
    initialise centres (lattice or random)
    run the iterative position‑radius loop
    store the best centres/radii pair of this restart

pick the overall best pair from the restarts
refine with SLSQP (non‑linear)
validate and return
```

The key pieces are:

| Piece | What it does | How it is implemented |
|-------|--------------|-----------------------|
| **LP for radii** | Finds the maximum‑radius set for a fixed centre configuration | `scipy.optimize.linprog` (Highs) with 26 variables and ~354 linear constraints |
| **Active‑constraint gradient** | Moves each circle just as far as its most restrictive neighbour or wall would allow | For each circle, identify the constraint that attains the minimum of all inequalities; the derivative is simply the unit vector pointing away from the constraining object |
| **Iterative loop** | Repeats: LP → active‑constraint detection → position update → LP → accept or revert | Simple `for` loop with decreasing step size |
| **Bidirectional neighbour motion** | Keeps touching pairs from pushing each other away unnecessarily | If the active constraint of circle `i` is a neighbour `j`, we update both `i` and `j` simultaneously in opposite directions |
| **Random perturbation escape** | Avoids shallow local optima without a full SA sweep | After a fixed number of iterations, add small Gaussian noise (variance proportional to current step size) to all centres |
| **SLSQP polish** | Lifts the final solution from the linear regime into the fully constrained nonlinear regime | `minimize` with objective `-sum(r)` and the same inequalities, starting from the best LP‑generated point |

### 2.  LP formulation for a given set of centres

Let \(C=\{(x_i,y_i)\}_{i=1}^{26}\).

**Variables**: \(r_i \ge 0\).

**Constraints**:

| Constraint | Mathematical form |
|------------|-------------------|
| Left wall | \(r_i \le x_i\) |
| Right wall | \(r_i \le 1 - x_i\) |
| Bottom wall | \(r_i \le y_i\) |
| Top wall | \(r_i \le 1 - y_i\) |
| Pairwise contact | \(r_i + r_j \le d_{ij}\),  \(d_{ij} = \sqrt{(x_i-x_j)^2+(y_i-y_j)^2}\) |

All inequalities are linear in the \(r_i\).  
Objective: \(\max \sum_{i=1}^{26} r_i\) (equivalently, minimise \(-\sum r_i\)).

The LP is tiny: 26 variables, 152 boundary inequalities, 325 pairwise inequalities → 477 constraints at most.  Solving it takes ≈ 1 ms with the `highs` solver.

---

### 3.  Determining the most restrictive (active) constraint per circle

After solving the LP we examine the *slack* of every inequality that involves a fixed circle \(i\).

- If a wall inequality is active (within \(10^{-9}\) of equality), we note which wall it is.
- Otherwise, the active pair is the neighbour \(j\) that yields the smallest value of \(d_{ij}-r_i-r_j\).

The **direction** in which circle \(i\) should move to increase that slack is:

- **Left wall**: \((+\alpha, 0)\)
- **Right wall**: \((-\alpha, 0)\)
- **Bottom wall**: \((0, +\alpha)\)
- **Top wall**: \((0, -\alpha)\)
- **Neighbour \(j\)**: \(\alpha \cdot \frac{(x_i-x_j,\;y_i-y_j)}{d_{ij}}\)

Here \(\alpha\) is the current step size.  By construction, moving the circle in that direction increases at least one active slack (and may increase the radii).

### 4.  Iterative position‑radius loop

**Parameters**

| Symbol | Value | Reason |
|--------|-------|--------|
| \(\alpha_0\) | 0.01 | Reasonable initial step relative to unit square |
| \(\text{cooling}\) | every 20 iterations, halve \(\alpha\) | Gradual convergence |
| \(\epsilon_{\text{sum}}\) | \(1\times10^{-7}\) | Threshold for accepting a move |
| \(\text{patience}\) | 10 | If no improvement for 10 successive iterations, break |
| \(\text{max_iter}\) | 200 | Ensures bounded runtime |

**Algorithm**

1. **Initial LP** → obtain initial radii and sum.  
2. **Iteration** (while `iter < max_iter`):
   - Identify active constraints for all circles using the current LP solution.
   - Compute tentative new centres using the direction rules above (with current \(\alpha\)).
   - **Clip** any coordinate that would leave \([0,1]\) to the boundary.
   - **Bidirectional update**: if circle \(i\) and \(j\) are mutual active neighbours, move both simultaneously in opposite directions (same step size).
   - Solve LP again for the new centres → new radii and sum.
   - **Accept** the new configuration if the sum increased by at least \(\epsilon_{\text{sum}}\); otherwise revert the positions to the previous ones.
   - If accepted, record the new best sum for this restart.
   - Every `cooling` iterations halve \(\alpha\).
   - If no improvement for `patience` consecutive iterations, break (local optimum reached).
3. Return the best centres/radii pair found in this restart.

The SA‑style *random perturbation* (small Gaussian noise added to all centres after every 50 iterations) can optionally be enabled to escape very shallow local optima.

### 6.  Final SLSQP polishing

Once the best configuration across all restarts is identified, we launch a nonlinear optimisation with:

- **Variables**: 54 (52 for centres + 2 for radii).
- **Objective**: \(-\sum r_i\).
- **Constraints**: same 104 boundary inequalities and the 325 pairwise non‑overlap inequalities (type `ineq`).
- **Bounds**: \(0 \le x_i, y_i \le 1\); \(0 \le r_i \le 0.5\).
- **Method**: SLSQP, `maxiter=2000`, `ftol=1e-9`, `disp=False`.

Because our starting point is already feasible up to machine precision, the SLSQP run typically converges in a few hundred iterations and may achieve a modest increase (~\(10^{-4}\)) in the sum of radii.

### 9.  Anticipated failure modes and mitigations

1. **Stagnation before local optimum** – mitigated by bidirectional neighbour updates and occasional random perturbations.  
2. **Boundary clipping causing zero radii** – impossible because the LP would set the radius to zero only if the centre ends up exactly on the wall; this is unlikely after an accepted move.  
3. **Oscillations between two walls** – step direction always pointing *away* from the active wall, so oscillation can only happen if the wall becomes inactive; then the next active wall pulls the circle back, creating a damped oscillation that is naturally stopped by the acceptance rule.  
4. **Very small step sizes leading to premature termination** – the `patience` counter allows the algorithm to continue exploring until the improvement stalls; if the step is too small we simply finish earlier, but the LP then guarantees a feasible configuration.  
5. **Numerical overflow when computing \(\sqrt{(x_i-x_j)^2+(y_i-y_j)^2}\)** – avoided because all coordinates lie in \([0,1]\).
