**High‑level idea**

Instead of relying on a single global search (DE or random starts), we treat the center coordinates as a search space that is explored by a *genetic algorithm* (GA).  
For every individual (a complete set of 26 2‑D coordinates) the *optimal* radii are computed **exactly** by solving a small linear program (LP).  
Thus the GA optimises a *piecewise linear concave* function (the optimal sum of radii for the current positions) without ever having to resort to a penalty or penalty‑gradient scheme.  
After a few hundred generations the population converges to an excellent local optimum; the best individual is then polished by a conventional SLSQP local optimiser that now optimises positions **and** radii together.  

The GA is simple to implement, fully deterministic (kept reproducible by a fixed seed), and runs comfortably within a second on a single CPU because the LP is tiny (≤ 351 inequalities, 26 variables).  

**Why GA is different and effective**

| Previous approach | New approach | What changes |
|-------------------|--------------|--------------|
| Differential Evolution (population‑based search over all 78 variables) | GA over *positions only* (52 variables) | Radii are computed analytically by LP → no need to search radial space |
| Uses SLSQP for after‑touch | GA uses same SLSQP only for final polishing | GA supplies a well‑structured starting point |
| Inequality constraints all handled by SLSQP | Radii constraints are handled **exactly** by LP, boundary constraints in GA are trivial | Guarantees that every fitness evaluation corresponds to a feasible radius vector |
| Random restarts in each trial | A homogeneous GA population explores many distinct regions simultaneously | Faster, more systematic exploration |

### 1.  Linear program for radii (given positions)

For a position vector `pos` of shape `(26,2)`:

```
A_ub = []
b_ub = []

# Boundary constraints:
for each i:
    A_ub.append([1 at i, 0 elsewhere])          => r[i] ≤ x[i]
    A_ub.append([1 at i] ... )                  => r[i] ≤ 1−x[i]
    A_ub.append([...])                          => r[i] ≤ y[i]
    A_ub.append([...])                          => r[i] ≤ 1−y[i]

# Pairwise constraints:
for each i<j:
    d = Euclidean distance between centers
    A_ub.append([1 at i, 1 at j, 0 elsewhere]) => r[i]+r[j] ≤ d
```

Objective: `c = -np.ones(26)` (minimise negative sum).

Call `scipy.optimize.linprog(method='highs')`.  
Return `r_opt` and `sum_r = r_opt.sum()`.

The LP is guaranteed to be feasible (radius zero is always allowed) and cheap to solve (< 1 ms per call).

### 2.  Fitness evaluation

```
def fitness(pos):

    return -s_r                         # GA minimises, so negative of sum
```

The fitness is the negative of the optimal sum of radii obtained from the LP.

### 3.  GA main loop

1. **Initialization**  
   Randomly sample `popsize` parents uniformly in `[0,1]^52` (i.e., coordinates independently in `[0,1]`).  
   Evaluate fitness for each.

2. **Generations** (repeat `generations` times)

   a. **Elitism**: keep the `elite_size` best individuals unchanged.

   b. **Parent selection**: *tournament* (size 3).  
      For each new child, select two parents by tournament.

   c. **Crossover**: uniform crossover with probability `crossover_rate`.  
      A child inherits each gene from either parent with 0.5 chance.

   d. **Mutation**: each gene is perturbed by Gaussian noise `N(0, sigma)`  
      with probability `mutation_rate`.  Afterwards clamp to `[0,1]`.

   e. **Replacement**: fill the rest of the population with newly generated children.

3. **Termination**  
   After the final generation, the elite contains the best individuals.  
   Take the very best one (`best_pos`) as the starting point for a local polish.
