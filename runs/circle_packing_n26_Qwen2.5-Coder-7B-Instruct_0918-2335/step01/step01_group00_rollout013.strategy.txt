**Goal**  
Pack 26 circles inside a unit square so that the sum of their radii is maximised.  
The solver must output integer‑style arrays `centers` (26 × 2) and `radii` (26‑element) that satisfy the geometric constraints and obtain a sum of radii significantly better than the previous 2.6097 (target > 2.636).  

**Key idea** – *hierarchical decomposition*.  
Instead of optimising both centre coordinates and radii together (a 78‑dimensional non‑convex problem), we:  

1. **Fix** the 52 centre coordinates.  
2. **Solve a small LP** that gives the largest possible radii for that particular configuration.  
3. **Use the LP optimum** as the objective value for the outer optimiser (only the centres are variables).  

Because the LP always returns the best radii for the current centres, the outer search is guided by the true objective.  
The outer problem is smooth‑enough for stochastic gradient‑free search and its dimension is reduced to 52, making it far easier to explore globally.

--------------------------------------------------------------------
### 1.  Inner optimisation – linear programme for the radii

For a fixed matrix of centre coordinates `C ∈ ℝ^{26×2}` let  

```
d_ij = ||C[i] - C[j]||  (pairwise Euclidean distance)
w_i  = min( C[i,0], 1-C[i,0], C[i,1], 1-C[i,1] )   # distance to the nearest wall
```

The radii vector `r ∈ ℝ^{26}` must satisfy

```
r_i + r_j ≤ d_ij          for all i < j                 (pairwise separation)
0 ≤ r_i ≤ w_i              for all i                     (stay inside the square)
```

The LP to solve for fixed `C` is

```
maximise   1ᵀ r
subject to r_i + r_j ≤ d_ij          (pairwise constraints)
           0 ≤ r_i ≤ w_i
```

*Implementation notes*  

- Bounds are handled directly by the LP routine (`(0, w_i)` for each variable).  
- Pairwise constraints are linear, one row per unordered pair.  
- All data (matrix of distances) can be reused; only RHS changes when `C` changes.  
- Use SciPy’s `linprog(..., method='highs')`, which is fast and robust for a 26‑variable LP with ~250 constraints.  
- Return two values: the optimal radii `r*` and the objective value `S(C) = ∑ r_i*`.  
  If the LP reports *infeasible*, return `S(C) = -∞` and a zero radii vector.

### 2.  Outer optimiser – stochastic global search on the centres

The outer optimisation is a 52‑dimensional search (26 × ( x , y )), bounded by [0,1] on each coordinate.

#### 2.1  Initial layout
Generate a *structured* starting point that is almost certainly feasible:

1. **Hexagonal lattice** with 5 columns and 6 rows (5+5+5+5+5+5 = 30, then remove 4 circles randomly to obtain 26).  
2. Apply a small random jitter (≤ 0.01) to each coordinate to avoid symmetry.  
3. The lattice guarantees that every pairwise distance is at least 0.15, so the initial LP is feasible (radiuses can be as large as the minimal distance to the walls).

#### 2.2  Simulated Annealing (SA) engine

```
state = current centre vector (52 entries)
temperature T = T0 (e.g. 0.1)
cooling factor α = 0.97
iteration limit per restart = 2000
```

*Move generation*  
- Randomly pick an index `k` (0 ≤ k < 26).  
- Propose new coordinates for circle k:
  - Δx, Δy ~ N(0, (σ·T)²) where σ = 0.02 (controls step size).  
  - Replace old coordinates with new, clip to [0,1] (rough bound keeping the move valid).  

*Evaluation*  
- Call the LP routine to compute `S(new_state)`.  
- If LP infeasible → reject move.  
- Acceptance rule:
  - If `S(new_state) > S(old_state)`: accept.  
  - Else: accept with probability exp((S(new_state) - S(old_state)) / T).  

*Temperature schedule*  
`T ← α·T` after each iteration.  

*Restarts*  
Perform `R = 150` independent SA runs, each starting from the same structured layout but with a different seed.  
Keep the best configuration seen across all runs (`best_state` and its `best_sum`).

*Why SA*  
- Global search capability (exploration via uphill moves).  
- No derivative information needed for the LP objective.  
- Simple to implement, easily parallelisable on a single core.

### 3.  Local refinement – deterministic descent on the centres

After SA, the configuration is already fairly good but can still be improved by a precise local optimiser.

#### 3.1  Objective function for local optimiser

Define `f(state)` that:

- Runs the LP routine on the given centre vector.  
- Returns `-S(state)` (negative of sum of radii) as the scalar objective to minimise.  
- If LP infeasible, return a large penalty (e.g. 1e6) – the optimiser will avoid such points.

#### 3.2  Optimisation method

Use SciPy’s `minimize` with:

- `method='BFGS'` (quasi‑Newton, needs only finite‑difference gradients).  
- `bounds=[(0,1)]*52` to keep coordinates inside the square.  
- `options={'gtol': 1e-10, 'maxiter': 200}`.

Because the objective is computed by an independent LP call at each evaluation, the gradient is automatically approximated by back‑propagation over this black‑box.  BFGS converges quickly for moderately smooth functions of about 50 variables.

After `minimize` finishes, compute the final LP once more to obtain the optimal radii vector for the refined centres.

### 6.  Likely failure modes and mitigations

* **LP infeasible during SA** – handled by rejecting the move.  
  Since the initial lattice is heavily separated, infeasibilities will not arise unless a circle moves too close to another. The penalty on acceptance automatically discourages such moves.  
* **Numeric underflow in acceptance probability** – the numerator (`S_new - S_old`) is bounded because each radius ≤ 0.5, so differences are below 0.5. The exponential will never underflow for the chosen temperature range.  
* **Local optimiser stuck in basin of attraction** – already mitigated by SA; BFGS only fine‑tunes.  
* **Very flat terrain** – the LP objective can have flat regions (e.g., when many circles touch walls). BFGS handles this gracefully with its finite‑difference gradient approximation.  
* **Runtime** – each LP resolves with ~300 inequality constraints; thanks to `highs`, a single solve costs < 0.5 ms on a modern CPU. Even 150 × 2000 = 300 000 solves finish in ~150 s, well within typical limits.
