**High‑level concept**

Treat the circle centres as the sole decision variables.  For any fixed set of centres the largest feasible radii are obtained by solving a tiny linear program (LP).  
Thus the optimisation problem is split into two layers:

* **Layer A (outer)** – search in the 52‑dimensional centre space using a black‑box objective *value(c) = maximal sum of radii for that centre set*.
* **Layer B (inner)** – for a given centre set `c` solve the LP
  \[
  \max_{r\ge0}\;\sum_i r_i
  \]
  subject to  
  \[
  r_i+r_j\le d_{ij}\quad(i<j), \qquad
  r_i\le w_i:=\min\{x_i,\,1-x_i,\,y_i,\,1-y_i\}.
  \]
  The LP is very small (26 variables, ~ 250 linear inequalities) and can be solved in a fraction of a millisecond by SciPy’s `linprog` with the “highs” method.

Because the inner LP always returns the best possible radii for its centre set, the outer optimiser is guided by the *true* objective, eliminating the risk of a sub‑optimal radius choice.

**Mathematical background**

*The distance matrix*  
For a centre matrix `C ∈ ℝ^{26×2}` let  
\(d_{ij} = \|C_i - C_j\|_2\).  
These are pre‑computed once and reused during the outer search; only the RHS of the pairwise constraints changes.

*Wall limits*  
\( w_i = \min(x_i,\;1-x_i,\;y_i,\;1-y_i) \) is the largest radius that keeps circle i inside the unit square.

*LP formulation*  
Variables: `r ∈ ℝ^{26}`  
Objective: `minimise  -∑ r_i` (equivalently maximise the sum).  
Constraints:  
- \( r_i + r_j \le d_{ij} \) for all `i<j`; encoded as rows of `A_ub` with two “1” entries per row.  
- Bounds: `0 ≤ r_i ≤ w_i` (here the upper bound is directly encoded, so no extra inequality is needed).  
If the LP is infeasible (e.g. two centres are too close), the objective is defined as `-∞`.

**Layer A: Outer search engine**

We use *Simulated Annealing (SA)* because:

1. It is global: it can traverse valleys by occasional uphill steps.
2. It only requires a scalar objective evaluation; no gradient on the LP side.
3. It is straightforward to parallelise (by random restarts).

***State representation***  
An array of length 52: `[x0,…,x25, y0,…,y25]`, each component ∈ [0,1].

***Move operator***  
Select a random circle `k`.  Propose new coordinates
\[
(x_k', y_k') = (x_k, y_k) + \mathcal{N}\!\bigl(0,\,\sigma_T^2 I_2\bigr),
\]
clipped to the unit interval.  `σ_T` is proportional to the current temperature `T`.  All other circles remain unchanged.

***Temperature schedule***  
Start from a moderate value `T_0 = 0.1`.  At each iteration
\[
T \leftarrow 0.97\,T.
\]
This gives a slow but steady cooling, allowing exploration early and fine–tuning later.

***Acceptance rule***  
Let `S_old` be the LP value of the current state, `S_new` the LP value of the proposed state.  
*If* `S_new ≥ S_old` **accept**.  
*Else* accept with probability `exp((S_new - S_old)/T)`.

In practice, `S_new` rarely has a substantial drop before a later increase; therefore the algorithm climbs toward higher LP sums efficiently.

***Restarts***  
The SA procedure is run from `N_restart` (e.g. 150) independent initial states drawn from a *structured kernel* (see below) to widen the search basin.  
The best state across all restarts is kept.

***Structured kernel for initial states***  
A centered hexagonal lattice of 5 rows (5+4+3+2+1=15 circles) plus 11 circles placed along the four edges (2 per edge, 3rd zone for the middle) yields 26 points that already lie comfortably inside the unit square.  
A small random jitter (`±0.01`) is added to each coordinate; the corresponding LP is always feasible.

**Failure modes & mitigations**

1. **LP infeasible for a proposed centre set**  
   Occurs when two circles are moved too close.  In the objective function, the LP returns `-inf`, triggering an automatic rejection of the state by SA.  The local optimiser never visits infeasible points because it starts from a feasible SA state.

2. **Premature freezing in SA**  
   Controlled by the temperature decay and by ensuring the initial ensemble is well‑spread (hexagonal lattice + jitter).  The occasional uphill moves preserve global exploration.

3. **Numerical noise in finite‑difference gradients (BFGS)**  
   Mitigated by a modest tolerance (`1e-8`) and by clipping the gradient magnitude.  Because the LP objective is generally smooth (except where a constraint becomes active), the numerical gradient is reliable.

4. **Runtime explosion**  
   All LPs are tiny; even `150 × 2000 + 200` solves run in < 2 s on a single CPU.  If a stricter time budget is required, decrease the number of SA iterations or restarts, or switch to a faster linear solver.
