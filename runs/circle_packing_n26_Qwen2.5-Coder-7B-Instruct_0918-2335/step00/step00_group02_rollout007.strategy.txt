**Overview**

We solve the packing problem *exactly as a constrained nonlinear optimisation* rather than through a black‑box penalty search.  
The decision variables are the coordinates and radii of the 26 circles:

\[
\mathbf{z}= \bigl(x_1,y_1,r_1,\ldots ,x_{26},y_{26},r_{26}\bigr)^\top \in\mathbb{R}^{78}.
\]

The objective is to **maximize the sum of radii**  
\(f(\mathbf{z})=\sum_{i=1}^{26} r_i\).  
We formulate the constraints in *inequality form*, so that the solver can use its
in‑built Jacobian for a fast, reliable Newton–type iterate.  
The core idea is to replace the “big‑M” penalty used in differential evolution
with exact, differentiable constraints that the solver can enforce.

**Mathematical model**

1. **Variables**  
   \(x_i,\,y_i\) – centre of circle *i*  
   \(r_i\) – radius of circle *i*  
   All \(i=1,\dots,26\).

2. **Objective (to be maximised)**  

\[
f(\mathbf{z})=\sum_{i} r_i
\]

   In the minimiser we use the negative: \(J(\mathbf{z})=-f(\mathbf{z})\).

3. **Linear bounds (easy to encode)**  

\[
0\le x_i\le1,\;\;0\le y_i\le1,\;\;0\le r_i\le0.5.
\]

4. **Boundary constraints (touching, but never crossing)**  

For each circle *i*:
\[
\begin{aligned}
c_{1,i}(\mathbf{z}) &= x_i-r_i \ge 0, \quad &(\text{left side})\\
c_{2,i}(\mathbf{z}) &= 1-x_i-r_i \ge 0, \quad &(\text{right side})\\
c_{3,i}(\mathbf{z}) &= y_i-r_i \ge 0, \quad &(\text{bottom side})\\
c_{4,i}(\mathbf{z}) &= 1-y_i-r_i \ge 0. \quad &(\text{top side})
\end{aligned}
\]

5. **Non‑overlap (pairwise) constraints**  

For every unordered pair \(i<j\):

\[
c_{ij}(\mathbf{z})=
    (x_i-x_j)^2+(y_i-y_j)^2-(r_i+r_j)^2 \ge 0.
\]

The right hand side can be zero (touching allowed).

These 325 quadratic constraints together with the 104 linear ones
ensure a perfectly feasible solution once the solver finishes.

**Chosen solver**

`scipy.optimize.minimize` with method **trust-constr** is an interior‑point solver designed for large-scale nonlinear constrained problems.  
Why it is a genuine departure from the earlier DE approach:

| Feature | DE (penalty) | trust‑constr (constraint) |
|---------|--------------|---------------------------|
| Representation of feasibility | Implicit penalty | Explicit inequalities |
| Use of analytic Jacobian | No (if penalty); numeric | Full analytic Jacobian |
| Local refinement built‑in | Requires separate local run | Already performs interior Newton steps |
| Exploits problem sparsity | Flat objective, nothing special | Returns the underlying problem structure |

**Gradient Computation**

Analytic gradients speed up the solver dramatically.  
All Jacobians are straightforward:

* For linear constraints \(c_{k,i}\) the Jacobian has a single entry 1 or –1.
* For a pair constraint
  \[
  c_{ij} = (x_i-x_j)^2+(y_i-y_j)^2-(r_i+r_j)^2,
  \]
  we have
  \[
  \begin{aligned}
  \frac{\partial c_{ij}}{\partial x_i}&= 2(x_i-x_j), &
  \frac{\partial c_{ij}}{\partial x_j}&= -2(x_i-x_j),\\
  \frac{\partial c_{ij}}{\partial y_i}&= 2(y_i-y_j), &
  \frac{\partial c_{ij}}{\partial y_j}&= -2(y_i-y_j),\\
  \frac{\partial c_{ij}}{\partial r_i}&= -2(r_i+r_j), &
  \frac{\partial c_{ij}}{\partial r_j}&= -2(r_i+r_j).
  \end{aligned}
  \]
All other partial derivatives are zero.

Because the sparse pattern is highly repetitive we can build the whole Jacobian
with simple broadcasting operations.

**Multiple random starts**

The packing problem is highly multimodal, so a single run may land in a poor local optimum.  
We therefore initialise the optimiser from *N* (e.g. 6) random initial guesses:

1. **Generate \(x_i,y_i\)** uniformly in \([0,1]\).
2. **Assign initial radius** \(r_i = \min\bigl(x_i,1-x_i,y_i,1-y_i\bigr)/2\), i.e. the maximum radius that fits at that point.  
   Then shrink it a random factor \(0.3\le \alpha \le 0.8\) to give the optimiser room to grow.

Each start is passed to `trust-constr`.  
The solver returns the best solution (largest sum of radii) among them.

**Termination and validation**

*The solver can fail*: if it reaches a point where all constraints are satisfied but the gradient is zero, it will stop with a status code.  
We check the status and if it’s not *success*, raise an exception – any silent failure defeats the purpose.

After obtaining the candidate \(\mathbf{z}\) we:

1. Extract centers and radii from the vector.
2. Re‑compute all constraints directly (to guard against numerical issues).
3. Call the supplied `validate_packing`; if it fails we try the next best candidate.

If all candidates fail (highly unlikely), we return the exact zero solution so the system knows the pack is infeasible (this would trigger a crash, not a silent degradation).
