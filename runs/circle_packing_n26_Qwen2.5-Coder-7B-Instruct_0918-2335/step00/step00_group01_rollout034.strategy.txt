**Overall idea**

We treat the radii and the positions as two inter‑linked optimisation problems.  
1. **Fix positions → find the best radii**: for any set of circle centres the maximisation of the sum of radii is a *linear program* (LP).  
2. **Improve positions → re‑solve the LP**: the dual values from the LP give a set of “contact pressures” that exactly describe how the radii would change if we moved the circles.  We use these pressures to create a simple force‑directed movement of the centres.  
3. **Iterate**: keep moving the centres in the direction of the forces and repeatedly solve the LP until the objective stops improving.  
4. **Restart / perturb**: after a stagnation phase we add a small random jitter to the centres and continue; after a few restarts we take the best packing found.

Because the LP for fixed positions is very small (26 variables, 429 constraints) it solves in a few milliseconds.  The physics‑based position update is *only* based on the LP duals, so it stays completely deterministic and stable.

This approach is fundamentally different from a full nonlinear optimisation: the radius part is solved exactly and efficiently in each iteration, while the only non‑linear part (moving the centres) is a lightweight physics simulation guided by exact dual information.

--------------------------------------------------------------------

### 1.  Mathematics of the radius LP

For a given list of centre coordinates  
\(c_i = (x_i, y_i)\)  with  \(i=0\dots 25\)  :

Variables:  \(r_i \ge 0\).

Constraints
* **Boundary**  
  \[
  r_i \le x_i,\;\; r_i \le 1-x_i,\;\; r_i \le y_i,\;\; r_i \le 1-y_i .
  \]
* **Pairwise non‑overlap**  
  \[
  r_i + r_j \le d_{ij}\quad \text{for all } i<j,
  \]
  where \(d_{ij}= \|c_i-c_j\|\).

All inequalities are affine in the \(r_i\); thus the LP
\[
\max \sum_{i} r_i \quad \text{s.t. the constraints above.}
\]

The dual variables (Lagrange multipliers) of the active pairwise constraints are exactly the *contact pressures* between circles: if two circles touch, the multiplier tells us how strongly their radii combined are limited by their distance.  These pressures will drive the centre moves.

--------------------------------------------------------------------

### 2.  Force‑directed position update

After solving the LP we obtain:
* radii vector \(r\),
* for each pair \(i<j\) the dual `λ_{ij}`,
* for each boundary inequality the dual `λ_{i,lim}` (one per side; zero if the inequality is not tight).

Define a small *step size*  \( \alpha >0\).

**For each circle \(i\) compute a net force vector \(F_i\):**

1. **Pairwise contacts**  
   For every \(j\neq i\):  
   *If  \(λ_{ij}>0\) (the pairwise constraint is active)*  
   add  
   \[
   F_i \mathrel{+=} λ_{ij}\;\frac{c_i-c_j}{d_{ij}}\; .
   \]
   (The term points from \(j\) to \(i\), i.e. pushes them apart.)
2. **Boundary pushes**  
   For each boundary side that is active \(λ_{i,lim}>0\):  
   * if \(x_i\) is limited by left side (\(r_i\le x_i\)) add  
     \(F_i \mathrel{+=} λ_{i,lim}\,(1,0)\);  
   * if limited by right side (\(r_i\le 1-x_i\)) add  
     \(F_i \mathrel{+=} λ_{i,lim}\,(-1,0)\);  
   * similarly for bottom and top y–bounds.

3. **Normalise (optional)**  
   To avoid very large forces when radii are large we can
   normalise \(F_i\) to unit length or keep a cap (e.g. \(|F_i|\le 1\)).

**Move centres**

\( c_i \mathrel{+=} \alpha\, F_i \).

Because the forces are computed from the LP duals, the step size \(\alpha\) can be kept quite large (e.g. 0.01–0.05) and still remain stable; the LP in the next iteration will immediately readjust the radii to accommodate the new distances.

--------------------------------------------------------------------

### 3.  Iterative procedure

```
centres ← initial pattern
best_obj ← -∞
best_centres, best_radii ← None

repeat up to MAX_RESTARTS:
    centres ← initial pattern  (possibly rotated or jittered)
    for iter in 1 … MAX_ITERS:
        solve LP for current centres → radii, obj
        if obj > best_obj:
            best_obj ← obj
            best_centres, best_radii ← centres.copy(), radii.copy()
        compute forces from duals
        update centres ← centres + α * forces
        if convergence criterion satisfied (obj change < tol):
            break
    optionally add small random jitter to centres and continue
```

*Convergence criterion*: relative improvement in the objective < 1e‑6 over the last 5 iterations, or maximum iterations 200 are reached.  
*MAX_RESTARTS*: 3–5 (each restart can use a different initial jitter or a rotated/mirrored pattern).

### 5.  Linear‑programming details

`scipy.optimize.linprog` is sufficient.

*Objective* vector `c = -np.ones(n)` (since `linprog` minimises, we give negative sum).

*Constraints*:

- **Pairwise**: For each \(i<j\) add one row  
  `A_ub[k, i] = 1`, `A_ub[k, j] = 1`, `b_ub[k] = dist_ij`.

- **Boundary**: For each circle \(i\) add four rows  
  `A_ub[4*i  , i] = 1`  with `b_ub[4*i  ] = x_i` (left)  
  `A_ub[4*i+1, i] = 1`  with `b_ub[4*i+1] = 1 - x_i` (right)  
  `A_ub[4*i+2, i] = 1`  with `b_ub[4*i+2] = y_i` (bottom)  
  `A_ub[4*i+3, i] = 1`  with `b_ub[4*i+3] = 1 - y_i` (top)

The dual values `res.dual_ub` have the same ordering as the constraint rows; we use them directly to compute forces.

The LP is always feasible (all r_i = 0 is a trivial feasible solution). The solver terminates in a few milliseconds.

### 8.  Potential failure modes and mitigations

| Failure                         | Detection                          | Mitigation                                 |
|--------------------------------|-------------------------------------|--------------------------------------------|
| LP infeasible (due to extreme positions) | `res.success==False` | Re‑initialize positions (jitter / rotate) |
| Radii become zero for many circles | Sum radii < ε after several restarts | Adjust step size α downward; increase jitter |
| Runaway positions (centres leave square) | Any coordinate < 0 or > 1 | Clip positions after each update; enforce bounds |
| Very slow convergence | Objective improvement < 1e‑8 over many iterations | Reduce α, restart, or swap to a higher level heuristic |

Because the LP always has a feasible solution, the only real risk is stagnation; the random jitter and restarts give us robust escape routes.
