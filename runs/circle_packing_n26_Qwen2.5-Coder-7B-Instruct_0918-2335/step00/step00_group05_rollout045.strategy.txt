**Overall objective**  
We want 26 disjoint unit‑square‑confined circles whose radii sum to as large a value as possible.  
Mathematically we are looking for  

```
maximize    Σ r_i
subject to  0 ≤ x_i − r_i ,  x_i + r_i ≤ 1
            0 ≤ y_i − r_i ,  y_i + r_i ≤ 1
            ||(x_i,y_i)−(x_j,y_j)||  ≥ r_i + r_j   for i≠j
            r_i ≥ 0
```

The feasible set is highly non‑convex because of the quadratic distance
constraints.  Nevertheless we can solve it numerically with a
decent initial guess and a robust constrained optimizer (SciPy’s SLSQP
or NLopt).  The key to *good* results is a **high‑quality starting point**  
followed by a **fine‑tuned search** that respects all constraints
accidentally.

Below is a detailed, implementable plan that exploits eight core ideas:

1. **Canonical seed packings** – start from a relatively compact, well‑studied packing of equal circles in the unit square and then let radii grow.  
2. **Local packing lattice** – use a rectangular/hexagonal lattice so that circles sit in a “grid’’ that makes the constraints easier to satisfy.  
3. **Boundary‑aware radius assignment** – initialise each circle with a radius that touches at least one side of the square; this guarantees legality.  
4. **Feasibility enforcement by a simple penalty** – if during optimisation a constraint is violated, add a large penalty to the objective so that the optimizer learns to avoid that region.  
5. **Iterative blues (ball‑inflation) routine** – after every optimisation step, forcibly inflate every circle as far as possible in its current local environment, then re‑project onto feasibility.  
6. **Random perturbations + restarts** – the search is made robust to local optima by injecting small random moves and restarting from the best found configuration.  
7. **Gradual constraint tightening** – start with a relaxed distance threshold, then tighten it in stages, letting the system settle each time.  
8. **Validation and numerical safety** – use high‑precision `float64`, relative tolerances of `1e-12`, and explicit “inside‑square” checks after every update.

### Step‑by‑step construction

1. **Consistent ice‑cube packing (26 circles)**  
   • We take a *hexagonal lattice* inside the square.  
   • Specify a lattice spacing `s` such that a circle of radius `s/2` will not overlap its neighbours.  
   • Alternate rows are shifted by `s/2` horizontally, and successive rows are moved up by `s * √3/2`.  
   • Choose `s` so that 26 nodes fall inside the square but we are still well below the maximal packing density of a hexagonal layer so that we reserve room to enlarge radii.  
   • Compute the exact coordinates `(x_i, y_i)` of the lattice points that lie inside `[s/2, 1−s/2] × [s/2, 1−s/2]`.  
   • At this point the radii are all `r_i = s/2`.  
   • Count the nodes; if it is less than 26, decrease `s` slightly (this will increase the number of lattice points without exceeding the square).  
   • If it is more than 26, pick the 26 points that maximise the sum of distances to the existing neighbours – this keeps the configuration as “tight’’ as possible.  

   This gives us an *initial feasible* configuration with 26 circles and a known sum of radii, `S0`.

2. **Boundary‑greedy radius augment**  
   For each circle, compute the minimal clearance to the four square sides:
   ```
   down  = y_i
   right = 1 - x_i
   up    = 1 - y_i
   left  = x_i
   ```
   Choose the minimal clearance `c_i` and set
   ```
   r_i := min(r_i, c_i)
   ```
   This step guarantees that all circles touch at least one side and hence satisfy the boundary constraints.

3. **Define the optimisation problem**  
   - Decision variables `z = [x_0,…,x_25, y_0,…,y_25, r_0,…,r_25]`.  
   - Objective: `f(z) = - Σ r_i` (negative to turn maximisation into minimisation).  
   - Constraints:  
     * `x_i - r_i ≥ 0 + ε`  
     * `x_i + r_i ≤ 1 - ε`  
     * `y_i - r_i ≥ 0 + ε`  
     * `y_i + r_i ≤ 1 - ε`  
     * `((x_i - x_j)^2 + (y_i - y_j)^2) - (r_i + r_j)^2 ≥ ε` for i<j  
     * `r_i ≥ ε`  

   Here `ε = 1e-12` (or a small multiple of machine precision) keeps the constraints strictly satisfied.

4. **Sequential constraint tightening**  
   *Stage 0* – set ε to a relaxed value (e.g. `1e-8`) so that SLSQP can explore the region without getting stuck at absolute tangency.  
   *Stage 1* – reform the distance constraints to include a slack parameter `δ`. We solve for the optimum with `δ = 5e-4`.  
   *Stage 2* – reduce δ linearly over iterations until it hits `1e-12`. After each reduction we re‑run SLSQP starting from the previous solution.  
   This gradually forces the circles to touch neighbours without violating the constraints.

5. **Penalised objective**  
   During optimisation we add a penalty term  
   ```
   penalty = K * Σ max(0, -a_i)  (over all linear & quadratic constraints)
   ```
   where `a_i` are the constraint functions and `K = 1e6`.  
   This keeps the optimizer away from infeasible regions and guarantees that the returned solution is robust.

6. **Blue‑ball inflation subroutine**  
   After each optimisation stage we run a simple “ball‑inflation” loop:  
   - For each circle, compute the minimal distance to the square sides and to all other circles.  
   - Increase `r_i` to that minimum without exceeding the square.  
   - Project the resulting position back to its nearest feasible location if a small overlap is detected (by moving the centre a fraction `(r_i - r_j)/(distance)` along the line connecting the two centres).  
   - Stop when the change in `Σ r_i` falls below `1e-10`.  

   This routine tends to push the circles to tangency with neighbours or borders, increasing the objective.

7. **Mutation & restart strategy**  
   - After finishing Stage 2, we perform `M = 5` restarts.  
   - Each restart starts from the best solution so far but perturbates every centre by `± 1e-3` and every radius by `± 1e-3` (uniform random).  
   - Run SLSQP again with the small δ toolbox.  
   - Keep the best final solution across all restarts.

8. **Post‑processing safety checks**  
   - Verify all constraints have residual ≤ `1e-10`.  
   - Compute the exact pairwise distances to confirm all overlaps are below `1e-12`.  
   - Clamp any tiny numerical negative radii to zero (should not happen).  
   - Compute `sum_radii = Σ r_i` and return along with the arrays.

9. **Implementation details**  
   - Use `numpy` arrays of dtype `float64`.  
   - Wrap the optimisation in a helper function `solve_stage(z0, δ)` that returns the final `z`.  
   - Only one CPU thread is used – SciPy’s SLSQP defaults to single‑threaded Python loops.

   - No reads/writes to disk or network.  
   - The function `run_packing` simply calls the entire pipeline and returns `(centers, radii, sum_radii)`.

10. **Why this works**
