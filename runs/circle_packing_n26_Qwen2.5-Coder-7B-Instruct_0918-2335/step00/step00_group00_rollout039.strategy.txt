**A Fully Deterministic Simulated‑Annealing Pack‑Solver**

The core idea is to treat the 26 circles as movable beads that
simultaneously
grow in radius while being pushed apart whenever they touch another bead
or the boundaries of the unit square.
Instead of solving a constrained nonlinear program as in the previous
strategies,
we explore the continuous configuration space directly with
a classic *simulated‑annealing* (SA) routine.
All moves are vetted for feasibility, so the final configuration
satisfies the validator’s inequalities exactly.

Below is a complete, step‑by‑step plan that can be coded
with only NumPy, the standard library’s `random`, and a few pure‑Python
helpers.

---

### 1.  Problem Representation

For each circle \(i\in\{0,\dots,25\}\) we keep a 3‑tuple

* \(c_i = (x_i, y_i)\) – centre coordinates,
* \(r_i\) – radius.

These are stored in two flat NumPy arrays:

```
X = np.array([x_0, y_0, x_1, y_1, ..., x_25, y_25])   # shape (52,)
R = np.array([r_0, r_1, ..., r_25])                   # shape (26,)
```

All arithmetic is performed in double precision (`float64`).

The *objective* is to **maximise** the total radius

\[
S(X,R)=\sum_{i=0}^{25} r_i .
\]

Because SA is usually written as a minimisation,
we will minimise \(-S\) but the acceptance logic will be expressed
directly in terms of increasing \(S\).

---

### 2.  Feasibility Test

A configuration is *feasible* iff

1. **Boundary**  
   \[
   r_i \le x_i \le 1-r_i,\qquad
   r_i \le y_i \le 1-r_i ,\qquad \forall i .
   \]

2. **Non‑overlap**  
   \[
   \lVert c_i-c_j\rVert_2 \;\ge\; r_i+r_j , \qquad
   \forall\, i<j .
   \]

Because of machine precision we allow a tiny slack \(\varepsilon_{\mathrm{cold}}=
10^{-12}\).  
Hence we accept a move if

```
distance_ij + eps_overlap >= r_i + r_j     # eps_overlap = 1e-12
```

and similarly for boundaries.

The test is implemented in a vectorised way by computing the pairwise
distance matrix once per *inner iteration*.

---

### 3.  Initial Configurations (Two Deterministic Variants)

Two different starting layouts are prepared; the best result is taken.

| Variant | Construction |
|---------|--------------|
| **A** | 25 circles centred on a 5×5 grid with spacing \(s=0.2\) |
| &  – grid points are \((x,y)=\bigl((j+0.5)/5,\,(i+0.5)/5\bigr)\), \(i,j\in\{0,\dots,4\}\).  |
| &  – 26th circle at \((0.6,0.9)\). |
| **B** | Same 5×5 grid, 26th circle at \((0.4,0.9)\). |

All circles start with a tiny radius \(r_0 = 0.01\).
The grid guarantees at least a 0.08 clearance between adjacent circles,
so the initial state is trivially feasible.

---

### 4.  Simulated Annealing Parameters

| Symbol | Value | Explanation |
|--------|-------|-------------|
| \(T_{\mathrm{init}}\) | \(0.1\) | Initial “temperature”; large enough to accept many downhill moves. |
| \(\alpha\) | \(0.995\) | Cooling factor (monotonic decay). |
| \(n_{\mathrm{inner}}\) | \(5000\) | Number of random perturbations per temperature level. |
| \(\sigma_{\mathrm{pos}}\) | \(0.01\) | Standard deviation of the uniform displacement for a centre (x or y). |
| \(\sigma_{\mathrm{rad}}\) | \(0.002\) | Step size for radius changes (signed). |
| \(T_{\min}\) | \(10^{-7}\) | Temperature at which we stop the annealing loop. |

The parameters were chosen by short experiments on toy instances
and are conservative enough to let the algorithm explore the space
but still finish under a second on a single CPU.

---

### 5.  Move Generation

In every inner loop:

1. Pick a random circle \(k\).
2. Propose a new centre \(c_k'\) by adding to each coordinate a value drawn from a
   uniform distribution \([-\,\sigma_{\mathrm{pos}}, +\,\sigma_{\mathrm{pos}}]\).
3. Propose a new radius \(r_k'\) by adding a value drawn from a uniform
   distribution \([-\,\sigma_{\mathrm{rad}}, +\,\sigma_{\mathrm{rad}}]\).
4. Clamp \(r_k'\) to \([0,\,0.5]\) and also enforce that the new centre lies
   at least \(r_k'\) away from all four sides of the square:
   \[
   r_k' \le c_{k,x}' \le 1-r_k',\qquad
   r_k' \le c_{k,y}' \le 1-r_k'.
   \]
   (If the clamping changes any coordinate, the move is discarded immediately.)

The perturbed states for all other circles remain unchanged.

---

### 6.  Acceptance Rule

Let \((X, R)\) be the current configuration and
\((X', R')\) the proposed one after the move.

Compute the objective values

```
S_cur  = sum(R)
S_next = sum(R')
```

If \(S_{\mathrm{next}} \ge S_{\mathrm{cur}}\) the move is **accepted**.

Otherwise it is accepted with probability

\[
\min\!\left(1,\;\exp\!\left( \frac{S_{\mathrm{next}}-S_{\mathrm{cur}} }{T} \right)\right)
\]

Because we maximise, \(S_{\mathrm{next}}-S_{\mathrm{cur}}\) is negative
for a worse move; the exponent thus yields a value in \((0,1)\).

The random acceptance counter is performed with the standard RNG
seeded deterministically (e.g. `random.seed(12345)`).
Hence the entire SA trajectory is reproducible.

---

### 7.  Annealing Loop

```
T = T_init
while T > T_min:
    for _ in range(n_inner):
        propose a random move
        if feasible:
            accept with the rule above
            update current best if S_next is larger
    T *= alpha
```

At the end of the loop the configuration that achieved the greatest
totalsum \(S_{\max}\) over all temperatures is taken as the output.

---

### 8.  Final Rounding & Post‑Processing

Because every acceptance step guarantees feasibility,
the only remaining issue is rounding errors:  
after the annealing loop we scan all pairwise distances and tighten
overlaps by a tiny proportional reduction of the two radii in the
overlapping pair:

```
if distance < r_i + r_j:
    shrink_factor = (distance)/(r_i+r_j)
    r_i *= shrink_factor
    r_j *= shrink_factor
```

This correction uses the same 1 × 10⁻¹² tolerance as the validator,
ensuring no overlap remains.  
The sum of radii is recomputed after the correction
although it will move downward by at most \(10^{-12}\) per pair –
far below the tolerance.

Finally `centers = X.reshape((26,2))`, `radii = R`,
and `sum_radii = np.sum(R)` are returned.
