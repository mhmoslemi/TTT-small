**Overall Goal**

We must find a feasible packing of 26 circles inside the unit square that maximises the sum of their radii.  
The solution has to be produced by a single function
```python
def run_packing() -> Tuple[np.ndarray, np.ndarray, float]
```
where the first two return values are the centres and radii of the circles, and the third one is the sum of the radii.  
The packing must satisfy

* each radius ≥ 0,
* each circle is completely inside the square,
* no two circles overlap (touching is allowed).

The evaluation will automatically check the packing with the supplied validator.  
The only optimisation we can influence is the *algorithm* inside `run_packing`.

---

### 1. Modelling the problem

We choose the most direct real‑valued formulation:

```
variables:
    Xi, Yi, Ri   (i = 1 … 26)

bounds (allocation step 1 of the algorithm):
    0 ≤ Xi ≤ 1
    0 ≤ Yi ≤ 1
    0 ≤ Ri ≤ 0.5
```

The *true* feasibility constraints are encoded as *penalties* that are
added to a **negative sum of radii objective**:

```
objective(x) = - Σ Ri + λ * Penalties(x)
```

where `λ` is a large positive constant.  
If the variables violate any geometric constraint, the penalty becomes
strictly positive and slows the optimisation down – the optimizer will
therefore try to keep the configuration feasible.

The penalties are:

| Constraint | Penalty term |
|------------|--------------|
| Boundary on left | `max(0, Ri - Xi)²` |
| Boundary on right| `max(0, Xi + Ri - 1)²` |
| Bottom            | `max(0, Ri - Yi)²` |
| Top               | `max(0, Yi + Ri - 1)²` |
| Overlap `i–j`    | `max(0, Ri + Rj - dist(i,j))²` |

`dist(i,j)` is the Euclidean distance between the two centres.

All these penalties are smooth (except at the kink, which is not a problem
for the optimisation techniques we use).  
They also provide the optimizer with a gradient‑style signal, even though
the underlying problem is highly non‑convex.

---

### 2. Choice of Optimiser

We need a *global* optimisation method capable of handling a moderately high
dimensional, highly non‑convex problem (78 variables).  
The most reliable off‑the‑shelf choice that satisfies the constraints of
this contest is:

* **differential evolution** (`scipy.optimize.differential_evolution`)  
  - Purely derivative‑free  
  - Handles bounds automatically  
  - Works well with large penalty terms  
  - Parallelisation can be enabled, but we restrict to 1 thread as the
    contest allows only “up to 1 CPU”.

After the DE run we refine the best solution locally with
`scipy.optimize.minimize` using the L‑BFGS‑B algorithm:

* **L‑BFGS‑B** (`scipy.optimize.minimize(method='L-BFGS-B')`)  
  - Uses the same bounds  
  - Very fast in the neighbourhood of a good solution  
  - No penalty on the objective – we keep the penalty to enforce
    feasibility.

The combination of a global DE for *exploration* followed by a local L‑BFGS
refinement is known to produce state‑of‑the‑art results for packing
problems.

### 3. Algorithmic Steps

1. **Set constants**
   * `N = 26`
   * `dim = 3 * N` (78)
   * `lambda_penalty = 1e5`  (tunes how strongly the constraints are enforced)
   * `DE_popsize = 12`  (≈ 2×dim – good trade‑off between exploration and CPU)
   * `DE_maxiter = 400` (assures the routine finishes quickly)

2. **Bound specification**

   For each variable we provide simple bounds:
   ```
   bounds = [(0, 1)] * (2*N)   # for all Xi and Yi
   bounds += [(0, 0.5)] * N    # for all Ri
   ```

3. **Objective function**
   
   Input: a flat vector `x ∈ ℝ⁷⁸`.

   * Split into arrays `xs, ys, rs`.
   * Compute sum of radii: `-rs.sum()`.
   * Compute all penalties:

     ```
     # boundary margins:
     p_boundary = (
          np.maximum(0, rs - xs)**2 +
          np.maximum(0, xs + rs - 1)**2 +
          np.maximum(0, rs - ys)**2 +
          np.maximum(0, ys + rs - 1)**2
     ).sum()
     
     # pairwise overlaps (avoids heavy loops with broadcasting)
     dx = xs[:, None] - xs[None, :]
     dy = ys[:, None] - ys[None, :]
     dist = np.hypot(dx, dy)
     rr = rs[:, None] + rs[None, :]
     overlap = rr - dist
     p_overlap = np.sum(np.maximum(0, overlap[np.triu_indices(N, 1)])**2)
     ```

   * Total cost: `-sum_r + lambda_penalty * (p_boundary + p_overlap)`.

4. **Differential Evolution**

   * Randomly initialise the DE with a fixed seed (we run *four* seeds
     sequentially to escape poor local minima).
   * In each run, store `result.x` and `result.fun`.
   * Keep the best finishing vector (`best_x`).

5. **Local refinement**

   * Call `minimize` on `best_x` with L‑BFGS‑B, same `bounds`.
   * Use the same objective (with penalty) – this prevents the method
     from stepping outside the feasible region.

6. **Post‑processing**

   * Extract centres and radii from the final vector:
     ```
     centres = np.column_stack([x[0:N*2:2], x[1:N*2:2]])
     radii   = x[2*N:]
     ```
   * Compute the actual sum of radii `sum_radii = radii.sum()`.
   * Verify feasibility once more with the provided `validate_packing`
     (this is optional, but guarantees the result is accepted).

7. **Return**

   ```
   return centres, radii, sum_radii
   ```

### 5. Robustness & Edge Cases

* **Feasibility** – All radii are bounded by 0.5; the penalty makes any
  escape from the square extremely expensive, so the final solution will
  never violate boundaries.
* **Overlap** – The squared penalty ensures that a very slight overlap
  is heavily penalised; the optimiser will keep any touching circles
  exactly at the equality threshold.
* **Degenerate solutions** – Because the objective explicitly promotes
  larger radii, the optimiser will not return many circles with near‑zero
  radius unless it is geometrically necessary.
* **Numerical stability** – All operations are performed with `np.float64`;
  the penalty terms use `np.maximum` to avoid NaN from negative numbers.
* **Optional multi‑start** – Running several DE sweeps guarantees that
  a single unlucky random initialisation does not cause the algorithm
  to get stuck.
