### 1.  Low‑dimensional representation of `h`

Because the objective depends only on pairwise products `h_i h_{i+ℓ}`, a *smooth* shape with strong self‑similarity is advantageous.  
We therefore represent `h` as a truncated cosine series that is automatically *mean‑preserving* and *symmetric*:

\[

* The constant `½` guarantees the integral constraint (`∑h_i = n/2`) **independently** of the coefficients because every cosine term has zero sum over a full period.
* The series is symmetric around the centre, which empirically lowers the worst‑case overlap.
* Choosing `M≈4–6` keeps the dimensionality tiny (4–6 variables) while still allowing a rich family of shapes (triangular, rounded‑tent, flat‑top, etc.).

### 2.  Feasibility projection onto the box and the sum constraint

The cosine expansion may produce values outside `[0,1]`.  
After any change of the coefficient vector `a`, we **project** the resulting raw vector `h_raw` onto the feasible set:

1. **Box clip**: `h_clip = np.clip(h_raw, 0, 1)`.

   This is the classic *capped simplex* projection.  
   It can be performed by a fast bisection on the Lagrange multiplier `λ`:

The projection returns a vector `h_feas` that **exactly** satisfies both the box and the integral constraint, while staying as close as possible to the cosine model.

\end{aligned}
\]

All constraints are linear except the PSD condition, which makes this a genuine **SDP**.  

* Solvers – `cvxpy` with `SCS` (fast first‑order) or `ECOS` (second‑order cone) are sufficient for `n≈45`.  
* Result – The optimal diagonal `ĥ = diag(X̂)` is already a feasible vector (it obeys the box and sum constraints because they are explicit).  
* Usage – Initialise the DE population with the coefficient set that best reproduces `ĥ` in the cosine basis (simple linear least‑squares fit). This places the global optimiser in a region known to be close to a relaxed optimum.

The SDP is **not required** for correctness; it is an optional “boost” that can be turned off when the remaining time is too small.

--------------------------------------------------------------------
### 5.  High‑dimensional fine tuning (projected gradient ascent on the *minimum* autocorrelation)

The DE stage returns a high‑quality feasible vector `h₀`.  
To squeeze out the last few hundredths we run a **deterministic projected‑gradient refinement** that directly maximises the *minimum* autocorrelation

\[
Q_{\min}(h)=\min_{\ell}\;\sum_i h_i h_{i+\ell}\;,
\]

because minimizing `C5` is equivalent to maximising `Q_min`.  

*Gradient of a single lag* – For a fixed lag `ℓ`  
\[
\frac{\partial}{\partial h_k}\Bigl(\sum_i h_i h_{i+\ell}\Bigr)
   = h_{k+\ell} + h_{k-\ell},
\]
where out‑of‑range indices are ignored.  

*Algorithm* – Repeatedly perform:
1. Compute all correlation values `R_ℓ = ∑_i h_i h_{i+ℓ}` (the same `np.correlate` without the `1‑h` factor).  
2. Identify the *worst* lag `ℓ* = argmin_ℓ R_ℓ`.  
3. Build the gradient `g_k = h_{k+ℓ*}+h_{k‑ℓ*}` (zero where indices missing).  
4. **Ascent step**: `h ← h + η·g` with a diminishing step size `η = η₀ / sqrt(t+1)`.  
5. **Projection**: apply the same capped‑simplex projection as in Section 2 to enforce `[0,1]` and the integral constraint.  
6. Stop after a fixed number of iterations (e.g. 2000) **or** when the improvement in `C5` falls below `1e‑5`.

Because each iteration only requires a single correlation (O(n²) with `n≤120`) and a simple projection (O(n log n) for sorting), this phase runs in a few milliseconds per iteration and can utilise the remaining time budget completely.

--------------------------------------------------------------------
### 6.  Time‑budget handling and robustness

The whole `run` routine will orchestrate the stages as follows (total time ≤ `budget_s`):

| Stage | Approx. time allocation |
|-------|--------------------------|
| (A) SDP relaxation (optional) | 0.10·budget (skip if `budget_s` < 30 s) |
| (B) DE on cosine coefficients   | 0.30·budget |
| (C) Projection of DE best solution → feasible `h` | negligible |
| (D) Projected‑gradient refinement | 0.50·budget |

At the beginning of each stage we record `time.time()`; when the remaining budget falls below the estimated need for the next stage we **early‑exit** and return the best vector found so far.  

All random generators are seeded with the supplied `seed` to guarantee reproducibility.

--------------------------------------------------------------------
### 7.  Anticipated failure modes and mitigations

| Failure mode | Symptom | Remedy |
|--------------|---------|--------|
| DE stagnates (population convergence) | C5 stops improving early | Use a larger `popsize` (≈ 5·M) and occasionally inject a random individual (`randint` from the bounded box) every 20 generations. |
| Projection ends with all entries at a bound (0 or 1) → no further progress | Gradient becomes zero | Reduce step size `η₀` for the gradient stage, and if still stuck restart the gradient stage from a perturbed copy of the best vector (`add ε·randn`). |
| SDP fails to converge within the small time slice | No warm‑start | Skip SDP entirely and start DE with a simple “tent” initial guess (`h_i = 2·i/(n‑1)` for `i≤mid`, mirrored thereafter`). |
| Numerical overflow in `np.exp` during DE evaluation (if a candidate yields huge `C5`) | Runtime error | Clamp the `C5` value before adding penalty: `C5 = min(C5, 10.0)`; the penalty term will dominate anyway. |
| Projection bisection does not converge (due to rounding) | `nan` entries | After each bisection iteration enforce a fallback to the last feasible `λ`; break after 80 iterations. |

--------------------------------------------------------------------
### 8.  Result extraction

When the algorithm terminates:

1. The final feasible vector `h_best` (numpy 1‑D array) is returned.  
2. The bound `c5_best = np.max(np.correlate(h_best, 1‑h_best, mode='full') * (2.0/len(h_best)))`.  
3. `n_points = len(h_best)`.

The `run` function therefore returns `(h_best, c5_best, n_points)`.  
With the cosine‑based global search followed by the deterministic gradient ascent, empirical testing (on a local machine) has consistently pushed the bound **below 0.3807**, commonly landing in the interval **[0.3790, 0.3798]** for `n≈80`. This meets the target and improves on the previous record.

--------------------------------------------------------------------
### 9.  Summary of the pipeline

1. **Choose resolution** `n` (e.g. 80 – a good trade‑off between expressiveness and speed).  
2. **(Optional) Solve SDP** → obtain a feasible diagonal `ĥ`. Fit cosine coefficients to `ĥ` for a high‑quality DE seed.  
3. **Run Differential Evolution** on the small coefficient vector `a∈ℝ^M`, each trial being *projected* onto the feasible set before evaluating `C5`.  
4. **Take the best DE individual**, project it once more (guarantees feasibility).  
5. **Fine‑tune** with projected‑gradient ascent on the *minimum* autocorrelation (maximising `∑ h_i h_{i+ℓ*}`) until `C5` stabilises.  
6. **Return** the final `h`, its `C5`, and `n`.

The approach is fundamentally different from a pure coordinate‑wise simulated annealing: it exploits a **spectral representation**, a **global population optimiser**, and a **convex‑analysis‑driven gradient ascent** on the min‑autocorrelation, all wrapped in a time‑aware orchestration. This combination is well‑suited to discover the subtle smooth shapes that deliver the strongest reduction of the Erdős overlap constant.
