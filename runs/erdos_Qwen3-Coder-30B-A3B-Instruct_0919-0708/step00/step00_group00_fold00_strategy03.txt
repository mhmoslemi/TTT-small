### Overview

The proposed pipeline solves the Erdős minimum‑overlap problem by **linearising the bilinear products with McCormick envelopes, solving a global linear program (LP) to obtain a tight lower bound, turning the LP solution into a feasible step‑function by a systematic rounding+local‑swap phase, and finally polishing the result with a small projected‑gradient refinement**.  

All steps are fundamentally different from the previously described smooth‑max + SLSQP or block‑CMA‑ES approaches: the core optimisation is a *pure linear programme* that exploits convex envelopes of the non‑convex terms, followed by a *combinatorial rounding* rather than continuous stochastic search. The method works with the original discretisation (e.g. n = 45) and fits comfortably inside the 600 s time budget.

--------------------------------------------------------------------
### 1.  Re‑formulation of the objective

For a discretised vector `h ∈ ℝⁿ` (spacing `dx = 2/n`) define the full‑mode correlation

```
S_ℓ(h) = ∑_{i} h_i·(1 – h_{i+ℓ})      (ℓ = -(n‑1)…(n‑1), out‑of‑range indices are omitted)
```

The quantity to be minimised is  

```
C5(h) = max_ℓ  dx·S_ℓ(h) .
```

Because `∑_i h_i = n/2` is fixed,  

```
S_ℓ(h) = 1 – ∑_i h_i·h_{i+ℓ} .
```

Hence minimising `C5` is equivalent to **maximising the minimal autocorrelation**  
`A_ℓ(h) = ∑_i h_i·h_{i+ℓ}` over all shifts ℓ.  
The non‑convexity lies entirely in the bilinear terms `h_i·h_j`.

--------------------------------------------------------------------
### 2.  Linearisation via McCormick envelopes

For every pair of indices that can appear in a product (`i` and `j = i+ℓ` with `0≤i,j<n`) introduce an auxiliary variable  

```
y_{i,ℓ}  ≈  h_i·h_{i+ℓ} .
```

On the unit box `[0,1]` the exact product satisfies the **McCormick convex envelope**:

```
y ≥ 0
y ≥ h_i + h_{i+ℓ} – 1
y ≤ h_i
y ≤ h_{i+ℓ}
```

All four inequalities are linear.  Collecting them for every admissible `(i,ℓ)` yields a polyhedral relaxation that **contains the true bilinear graph**.  Consequently any feasible `(h,y)` of the linear system respects the original bounds, while allowing `y` to be *larger* than the true product – this gives a **relaxed lower bound** on the achievable `C5`.

--------------------------------------------------------------------
### 3.  LP model

Variables  

* `h_i`   – continuous, `0 ≤ h_i ≤ 1` for `i=0,…,n‑1`.  
* `y_{i,ℓ}` – continuous auxiliary variables for each admissible product.  
* `t` – scalar representing the (relaxed) maximal overlap.

Constraints  

1. **Mass constraint**  
   `∑_{i=0}^{n‑1} h_i = n/2`.  

2. **McCormick envelope** for every `(i,ℓ)` (as listed above).  

3. **Overlap upper bound** for each shift ℓ  

   ```
   t ≥ 1 – Σ_{i} y_{i,ℓ}          (because S_ℓ = 1 – Σ h_i·h_{i+ℓ})
   ```

   The constant “1” is exact because `dx·∑ h_i = 1`.

Objective  

```
minimise   t .
```

All constraints and the objective are linear → a **pure LP**.

--------------------------------------------------------------------
### 4.  Solving the LP

* Build the LP once (the sparsity pattern is fixed for a given `n`).  
* Use `cvxpy` with a fast free LP solver (e.g. **ECOS**, **SCS**, or the built‑in **CBC** for MILP).  
* The problem size for `n = 45` is modest:  
  * `h` – 45 variables,  
  * `y` – at most `∑_{ℓ} (n‑|ℓ|) ≈ n·(2n‑1) ≈ 4000` variables,  
  * Constraints – ≈ 4·|y| + (2n‑1) + 1 ≈ 16 000 linear constraints, still trivial for modern LP solvers.  

The LP solve typically finishes in **under a second**; we allocate up to **150 s** to allow multiple restarts with different seeds (to avoid solver‑specific numerical artefacts) and to experiment with a few `n` values (e.g., 35, 45, 55) to see which yields the best feasible bound.

The optimal LP value `t*` is a **theoretical lower bound** on the true `C5` (because the envelope may over‑estimate the products).  The associated `h*` will almost never be binary; it is a good *guide* for where the mass should be placed.

--------------------------------------------------------------------
### 5.  Rounding the LP solution to a feasible step‑function

#### 5.1  Simple deterministic rounding

1. Sort indices by the LP values `h*_i` in descending order.  
2. Set the first `⌊n/2⌋` entries to `1`, the rest to `0`.  
3. If `n` is odd, the required sum `n/2` is half‑integer.  After the binary assignment the total mass will be `⌊n/2⌋`.  Choose one additional index (the next largest `h*_i`) and set it to `0.5`.  
4. The resulting vector `ĥ` satisfies exactly the box constraints and the mass constraint.

#### 5.2  Probabilistic rounding (optional)

Interpret each `h*_i` as a probability, draw several independent binary samples respecting the total mass (e.g., by **dependent Bernoulli sampling** using a “balanced” procedure), and keep the sampled vector with the smallest exact `C5`.  This stochastic stage can discover a better integer pattern than the deterministic rule.

Both rounding schemes are extremely cheap (linear in `n`) and guarantee feasibility.

--------------------------------------------------------------------
### 6.  Combinatorial local improvement

The rounded vector is typically close to optimal but can be refined by low‑cost swaps:

* **Swap move** – pick a location `p` where `ĥ_p = 1` and a location `q` where `ĥ_q = 0`.  
  * Exchange the values (`1↔0`) while preserving the total number of ones (and the optional `0.5` stays untouched).  
  * Compute the exact overlap `C5_exact` (via `np.correlate`).  
  * Accept the swap if `C5` decreases.

* **Fractional move** – if a `0.5` entry is present, allow moving the 0.5 to a neighbouring index, or swapping it with a `1`/`0` while keeping the sum unchanged.

* **Simulated‑annealing overlay** – to escape shallow plateaus, occasionally accept a worsening swap with probability `exp(-(Δ)/T)`, where the temperature `T` decays geometrically (e.g., multiply by `0.98` each 100 accepted moves).  

Iterate until no improvement is observed for a few thousand attempts or until the remaining time budget falls below a safety margin (≈ 30 s).  Because each evaluation of `C5` costs only a tiny `O(n²)` convolution, millions of swaps can be examined well within the total time limit.

--------------------------------------------------------------------
### 7.  Continuous polishing (optional)

After the combinatorial phase we may still have *slack* in the box constraints (some entries are strictly between 0 and 1).  A few steps of **projected gradient descent** can exploit this remaining freedom:

1. Identify the *worst shift* ℓ* that actually attains the current maximum `C5`.  
2. The sub‑gradient of `S_ℓ*(h)` w.r.t. `h` is  

   ```
   g_i = – ( h_{i+ℓ*}  +  h_{i‑ℓ*} )          (indices out of range are omitted)
   ```

   (the constant part `+1` cancels because we are minimizing the max and use a Lagrange multiplier for the equality constraint).

3. Update `h ← h – α·g` with a small step size `α` (e.g., `α = 0.01`).  
4. **Project** back onto the feasible set:  
   * Clip to `[0,1]`.  
   * Adjust the sum to exactly `n/2` using the **capped‑simplex projection** (bisection on a scalar λ so that `h_i ← clamp(h_i – λ, 0, 1)` yields the required total).  

5. Repeat for a limited number of iterations (≤ 200) or until `C5` stops improving.

Because the gradient is cheap to compute (two shifted copies of `h`), this polishing stage finishes in a few seconds.
