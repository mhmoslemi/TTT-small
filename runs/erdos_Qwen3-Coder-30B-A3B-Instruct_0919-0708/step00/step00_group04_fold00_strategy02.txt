**Mathematical reformulation**

For a discrete step‑function `h` with `n` samples on `[0,2]` and spacing `dx = 2/n`

```
C5(h) = max_k   ∑_{i : 0 ≤ i,i+k < n} h[i] * (1‑h[i+k]) * dx .
```

Let  

* `w = ∑_i h[i] = n/2`  (the integral constraint)  
* `O_k = ∑_{i : 0 ≤ i,i+k < n} h[i] * h[i+k]`  (overlap of 1‑entries for shift `k`)  

and define the prefix sum  

```
pref[t] = ∑_{i < t} h[i]          (pref[0] = 0, pref[n] = w)
```

For a *positive* shift `k (1≤k≤n‑1)` the uncovered weight is  

```
U_k⁺ = w – O_k – (w – pref[n‑k])        # tail on the right side
```

and for the *negative* shift `‑k`

```
U_k⁻ = w – O_k – pref[k]                # tail on the left side
```

Hence  

```
C5(h) = (2/n) * max( max_{k>0} U_k⁺ , max_{k>0} U_k⁻ ) .
```

Thus the optimisation problem is **maximise the minimum overlap O_k** while also keeping the “tail” terms (prefix / suffix sums) small.  All quantities are integers for binary `h`, which makes a fast *O(n)* update possible when a single 1↔0 swap is performed.

### Overview of the algorithm

1. **Time management** – the total wall‑clock budget `budget_s` is divided
   into three phases:
   * *Phase A* (≈ 30 %): try several problem sizes `n` (small‑to‑medium, e.g. 42, 84, 126, 168, 210) with a cheap random‑restart hill‑climber to locate the most promising size.
   * *Phase B* (≈ 60 %): devote the bulk of the time to a simulated‑annealing search on the best `n` found in Phase A.  The annealer uses the *exact* discrete objective `C5`.
   * *Phase C* (≈ 10 %): polish the best binary vector with a short projected gradient descent on a smooth surrogate (log‑sum‑exp) that allows fractional entries; finally clip to `[0,1]` and renormalise to respect the integral constraint.

2. **Data structures kept for a single `n`**
   * `h` – `np.int8` vector of length `n`, exactly `w = n/2` ones.
   * `O` – integer array `O[k]` for `k = 0..n‑1` (auto‑correlation).  
     `O[0] = w` and for `k>0`  `O[k] = np.dot(h[:n‑k], h[k:])`.
   * `pref` – integer prefix sums `pref[t] = h[:t].sum()`.
   * From `pref` we obtain the right‑tail size for any shift  
     `tail_right(k) = w – pref[n‑k]` and the left‑tail `tail_left(k) = pref[k]`.

   All three arrays are updated in *O(n)* after a proposed swap.

3. **Exact objective evaluation**
   ```
   def max_uncovered(O, pref):
       maxU = 0
       for k in 1 .. n‑1:
           tailR = w - pref[n‑k]                # right tail
           tailL = pref[k]                      # left tail
           U_pos = w - O[k] - tailR
           U_neg = w - O[k] - tailL
           maxU = max(maxU, U_pos, U_neg)
       return maxU
   ```
   `C5 = (2.0/n) * maxU`.

4. **Swap proposal**
   * Pick a random index `i1` with `h[i1]==1` and a random index `i0` with `h[i0]==0` (simple rejection sampling on a uniform integer draw; expected 2 draws per index because density is ½).
   * The swap keeps `w` invariant.

5. **Fast Δ‑update for a swap**
   * For each shift `k=1..n‑1` compute the change in `O[k]`:

        ```
        loss  = (i1+k < n and i1+k != i0 and h[i1+k]==1) +
                (i1-k >= 0 and i1-k != i0 and h[i1-k]==1)

        gain  = (i0+k < n and i0+k != i1 and h[i0+k]==1) +
                (i0-k >= 0 and i0-k != i1 and h[i0-k]==1)

        ΔO[k] = gain - loss
        ```

   * Update `O_new[k] = O[k] + ΔO[k]`.

   * Update prefix contributions for the two indices:

        # new prefix for any t is: pref[t] - (i1 < t) + (i0 < t)

### Why this strategy works

* **Exact objective handling** – By keeping the exact `O_k` and prefix sums we evaluate the true `C5` after every trial without any approximation.
* **O(n) per move** – Even for `n≈300` a full iteration costs only a few hundred integer operations; millions of swaps easily fit into the 600 s budget.
* **Annealing** – The temperature schedule lets the search escape local plateaus that are common in max‑min autocorrelation problems.
* **Size selection** – Smaller `n` is cheap to explore, larger `n` can approach the asymptotic constant; Phase A guarantees we spend most time on the most promising size.
* **Continuous refinement** – The log‑sum‑exp surrogate gives a smooth gradient that can slightly improve the bound beyond what pure binary swaps can achieve; the projection step respects both box and integral constraints.
* **Robustness** – Random restarts, a clear time budget split, and a final verification step ensure that even if one phase under‑performs we still return a valid solution.
