### Stage 2 – Exact overlap calculation for a given configuration

For a shift τ (real number 0 ≤ τ ≤ 2), the overlap integral of h with its shifted complement is:

C(τ) = ∫ h(x) (1 - h(x+τ)) dx = 1 - ∫ h(x) h(x+τ) dx.

The product integral can be expressed as sum over block pairs:

∫ h(x) h(x+τ) dx = Σ_{i,j} a_i a_j * length ( intersection of block i with block j shifted by τ).

Intersection length of interval [x_i, x_i+ℓ_i) with interval [x_j+τ, x_j+τ+ℓ_j) equals max(0, ℓ_i + ℓ_j - |Δ_{ij} - τ|) where Δ_{ij}=x_j - x_i (distance of the left endpoints). However it’s easier to pre‑compute start positions s_i = Σ_{k< i} ℓ_k.

Given τ, the intersection length between block i and shifted j is max(0, min(s_i+ℓ_i, s_j+τ+ℓ_j) - max(s_i, s_j+τ)). This can be computed quickly with a few comparisons. ### 1.  Piece‑wise constant parametrisation

1. **Choose a small block count** `M` (e.g. 4 or 5).  
   An `M`‑block step function is completely described by  

   * lengths `ℓ = (ℓ₁,…,ℓ_M)   ,  ℓ_i > 0 ,  Σ ℓ_i = 2`,  
   * heights `a = (a₁,…,a_M)   ,  0 ≤ a_i ≤ 1`.

2. **Linear constraints**  
   * Mass: `Σ a_i ℓ_i = 1`.  
   * Bounds: `ℓ_i > 0` and `0 ≤ a_i ≤ 1`.  
   The two linear equalities can be **eliminated**:
   * keep the first `M‑1` lengths free, set `ℓ_M = 2 – Σ_{i<M} ℓ_i`,
   * keep the first `M‑1` heights free, compute `a_M` from the mass equation:
     ```
     a_M = (1 – Σ_{i<M} a_i ℓ_i) / ℓ_M .
     ```
   After this elimination the decision vector has exactly `2M‑2` free real numbers.

3. **Feasibility projection** (applied to every CMA‑ES candidate)

   * **Lengths** – given any vector `z ∈ ℝ^{M‑1}` apply `ℓ_i = max(ε, z_i)` (ε≈1e‑9), then rescale:
     ```
     ℓ_i ← ℓ_i / Σ ℓ_i * 2 .
     ```
   * **Heights** – given raw heights `y ∈ ℝ^{M‑1}` we must satisfy `0≤a_i≤1` and the mass equation.
     Use a **capped‑simplex projection**:
     * Define a scalar `λ` and solve for `a_i(λ) = clamp(y_i – λ, 0, 1)`.
     * Compute `a_M(λ) = (1 – Σ_{i<M} a_i(λ) ℓ_i) / ℓ_M`.

### 2.  Exact overlap computation for a block configuration

The overlap integral simplifies to  

```
C5(h) = max_τ  ( 1 – Σ_{i,j} a_i a_j · |B_i ∩ (B_j+τ)| )
```

where `B_i = [s_i, s_i+ℓ_i)` are the blocks and `s_i = Σ_{k<i} ℓ_k` are block start positions.

**Intersection length** for a given shift `τ` is

```
|B_i ∩ (B_j+τ)| = max( 0,
                       min(s_i+ℓ_i, s_j+τ+ℓ_j) –
                       max(s_i    , s_j+τ      ) )
```

Because the expression is *piecewise linear* in `τ`, the maximum of `C5(τ)` on `[0,2]` occurs only at values of `τ` where an endpoint of one block aligns with an endpoint of another block, i.e.

```
τ ∈ { |s_i     – (s_j+ℓ_j)| ,
      |(s_i+ℓ_i) –  s_j    | }   for all i,j
      ∪ {0, 2} .
```

Thus the exact `C5` for a given `(ℓ,a)` can be obtained by

1. building the list `T` of all candidate shifts (at most `2·M²+2` values),
2. for each `τ ∈ T` compute the autocorrelation `A(τ) = Σ_{i,j} a_i a_j · |B_i ∩ (B_j+τ)|`,
3. take `C5 = max_τ (1 – A(τ))`.

All operations are `O(M³)` (tiny for `M≤5`). No numerical integration or FFT is needed, and the result is **exact** for the chosen block model.

### 3.  Global optimisation of the low‑dimensional parameters

Because the decision space now has only `d = 2M‑2` dimensions (e.g. `d = 6` for `M = 4`), a **derivative‑free global optimiser** works extremely well. The recommended choice is **CMA‑ES** (Covariance Matrix Adaptation Evolution Strategy) because:

**CMA‑ES workflow**

1. **Initial population** – draw `d`‑dimensional vectors uniformly from a modest interval (e.g. `[0,2]` for lengths, `[0,1]` for heights) and project each to the feasible `(ℓ,a)` as described in Section 1.3.

3. **Selection & recombination** – standard CMA‑ES steps (μ best individuals determine the new mean, covariance matrix updated).
4. **Offspring generation** – sample new individuals from the multivariate normal `N(mean, σ²·C)`, project them, evaluate them.
5. **Termination** – stop when either  
   * the allotted time (`budget_s`) minus a 5 s safety margin is exhausted, **or**

Because each fitness evaluation costs only a few microseconds (the analytic `C5` uses ≤ 25 intersection calculations), we can afford **tens of thousands** of evaluations well within the 600 s budget.

### 4.  Fine‑grained local refinement on a dense grid

2. **Local hill‑climbing** (projected coordinate descent)  

   * **Move definition** – pick two distinct indices `(p,q)`.  
     Compute the admissible interval for a transfer `δ`:
     ```
     δ_min = max(-h[p],  h[q]-1)      # keep both inside [0,1]
     δ_max = min( 1-h[p],  h[q]  )
     ```
     Choose `δ` uniformly in `[δ_min, δ_max]` (or a few deterministic candidates: ±step, ±step/2).  
     Apply `h'[p] = h[p] + δ`, `h'[q] = h[q] – δ`. The sum stays unchanged.
   * **Acceptance rule** – evaluate `C5_exact(h')`.  
     If it is lower, accept; otherwise accept with probability `exp(-(C5'‑C5)/T)` (simulated‑annealing).

| **CMA‑ES stagnates in a poor region**   | Low diversity or too small population.            | Increase population size (`λ = 4+d`) for the first few generations, or restart with a larger `σ`. Run multiple independent CMA‑ES runs per `M`. |
| **Analytic C5 evaluation missing the true maximum** | The candidate shift set `T` omitted a critical τ due to floating‑point equality. | After computing `C5` on the reduced set, optionally evaluate a fine uniform grid (e.g., 200 points) and take the larger of the two results – this guarantees the bound is not underestimated. |
| **Local refinement gets stuck**           | Small step size leads to no further improvements. | Dynamically adapt the step size: if no improvement for 500 attempts, increase the allowed `δ_max` (capped at 0.2) and reset temperature. |
| **Time budget overrun**                  | Too many CMA‑ES generations or excessive refinement. | Continuously monitor `time.time()`. When remaining time < 30 s, skip further restarts and jump directly to the final refinement with a reduced number of annealing steps. |

### 7.  Summary of the full pipeline (no code)

1. **Set random seed**; read `initial_h_values` (only to know `n`).  
2. **Choose block count `M`** (try 3 – 5).  
3. **Define projection routines** for lengths and heights (Section 1.3).  
4. **Implement exact `C5` evaluator** for a block configuration (Section 2).  
5. **Run CMA‑ES** on the `2M‑2` free variables, feeding each offspring through the projection and exact evaluator. Record the best `(ℓ,a)` found.  
6. **Discretise** the best configuration to `n = 45` points → `h_dense`.  
7. **Perform stochastic hill‑climbing** on `h_dense` with pairwise transfers, simulated‑annealing acceptance, temperature decay, and a 5 s termination guard.  
8. **Optional gradient polishing** (projected gradient descent).  
9. **Compute final bound** with `evaluate_erdos_solution`.  
10. **Return** the final `h_values`, the bound, and `n_points`.

This approach explores the solution space **qualitatively differently** from gradient‑based smoothing: it works on a *structured low‑dimensional model*, evaluates the objective **exactly** (no log‑sum‑exp approximation), uses a **global stochastic optimiser (CMA‑ES)**, and finishes with a simple, constraint‑preserving local search. The reduction to a handful of block parameters makes the global search cheap and allows many restarts, giving a strong chance of beating the previous record (`C5 ≤ 0.38092`) within the allotted 600 seconds.
