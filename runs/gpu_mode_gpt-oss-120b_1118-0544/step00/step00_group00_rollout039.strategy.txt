- 0 <= b < batch_size
- 0 <= i_block < ceil(seq_len/BLOCK_N)   -> tiled indices
- 0 <= j < N:
  j = j_block * BLOCK_N + j_offset
- 0 <= d < hidden_dim: split into multiple tiles with BLOCK_H

4. Tiling parameters and variations:
The blocking parameters should be set based on device capabilities. We'll use:
- BLOCK_N = 64  (sequence dimension blocking, requires tuning)
- BLOCK_H = 8   (hidden dimension blocking)

Adjustments:
- For very large hidden_dim, use larger BLOCK_H (but minimum 8)
- For large sequence length, use larger BLOCK_N (up to 128 or 256, but 64 is common)

5. Compute budget and robustness:
The core operation is a matrix multiplication-like reduction. For worst-case N=1024, batch_size=1, hidden_dim=128:
- Each kernel tile (BLOCK_N x BLOCK_H) processes 64*8=512 elements per thread
- The grid size is ceil(1024/64)=16 in the sequence dimension and ceil(128/8)=16 in the hidden dimension
- Total threads: 16x16 = 256 threads

Memory access pattern:
- Matrix multiplication over sequence indices (with tiling) uses global memory access most of the time but with good locality within tiles
- The output is computed as tiled local accumulator (BLOCK_H windows)

6. Validation and output:
- Check output is [B, N, N, hidden_dim] -> [B, N, N, dim] via final projection
- Ensure masked and gated operations are correctly applied
- Compare with a reference PyTorch implementation
- Check exponent range for potential overflow (with Cauchy distribution, but normal is common)

Fallback plan:
If kernel launch fails due to invalid parameters, use a default BLOCK_N=32, BLOCK_H=8 configuration.

7. Return contract:
The output must be [B, N, N, dim], computed by:
- Epsilon: small value for stability
- Masking: enforced by mask_ptr (if provided)
- Gating: applied element-wise and by mean/std for normalization
