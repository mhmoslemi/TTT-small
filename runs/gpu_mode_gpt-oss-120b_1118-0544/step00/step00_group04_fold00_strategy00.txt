 2. Project the normalized input into two separate hidden dimensions using linear transformations (left_proj and right_proj).
    This gives two tensors of shape [B, N, N, hidden_dim] each.
 3. Apply a mask (if provided) to the projected tensors. The mask is broadcasted to match the dimensions.

    Then multiply the projections by their respective gates.

        out[b, i, j, :] = sum_{k=0}^{N-1} (left[b, i, k, :] * right[b, j, k, :])

1. Approach and Rationale

The core challenge in implementing the TriMul operator is to perform an N^3 operation efficiently without explicitly iterating over every element. The operator takes a tensor of shape [B, N, N, dim], mask, and several weight matrices, normalizing the input and output, applying projections and gating mechanisms, and finally multiplying pairwise over the k (shared sequence) dimension. This operation is memory-bandwidth intensive due to its O(N^3) nature and must be optimized for very large sequence lengths (up to 1024) while maintaining precision in float32 output.

The AlphaFold paper's TriMul is similar to sparse attention but with an additional projection mechanism. The key parts are:
- Normalization using LayerNorm
- Projection into a hidden dimension
- Element-wise multiplication with gating
- Pair-wise reduction over the sequence dimension (k)
- Second normalization and gating

Our approach will be to orthogonally decompose the operation:
  • Batch normalization (LayerNorm) for input and output
  • Efficient tensor reshaping to split the operation into scalable kernel calls
  • Large-block matrix multiplication approach for the inner dimension reduction

This addresses the challenge by separating concerns while reducing explicit inner-loop iteration. The blocked matrix handling improves reuse patterns and enables GPU-level parallelization.

2. Mathematical Specification

Let all tensors be of dimension 0-indexed splits:
- Input: x ∈ ℝ^{B, N, N, dim}
- Mask: m ∈ {0,1}^{B, N, N}

The operation is three-part:

Stage 1: First normalization and projection
  • x_normalized = LayerNorm(x)[B, N, N, dim]
  • left_proj = Linear(x_normalized, hidden_dim)[B, N, N, hidden_dim]
  • right_proj = Linear(x_normalized, hidden_dim)[B, N, N, hidden_dim]
  • left_gate = Sigmoid(Linear(x, hidden_dim))[B, N, N, hidden_dim]
  • right_gate = Sigmoid(Linear(x, hidden_dim))[B, N, N, hidden_dim]
  • left_processed = left_proj * left_gate[B, N, N, hidden_dim]
  • right_processed = right_proj * right_gate[B, N, N, hidden_dim]
  • set scope: For each batch and channel pair, we work on two matrices: A = left_processed and B = right_processed, both of shape [N, N, hidden_dim] (flattened to scope [B*hidden_dim])

Stage 2: The tri- attention kernel:
  • We aim for: out_stage = sum_{k=0}^{N-1} (A[i,k,:] * B[j,k,:]) [for all i,j]
  • This can be interpreted as a blocked matrix multiplication between two views of our data:

    Let C be defined as:
    - We permute A and B to [hidden_dim, B, N, N] and [N, B, N, hidden_dim]
    - Then split between sequence dimensions into smaller blocks

    However, note: the operation requires element-wise multiplication along the k dimension and summation over it.

Stage 3: Second normalization and final gating:
  • out = LayerNorm(out_stage)[B, N, N, hidden_dim]
  • out_post_gate = out * Sigmoid(Linear(x_normalized, hidden_dim)) [B, N, N, hidden_dim]
  • Final projection: Linear(out_post_gate, dim)[B, N, N, dim]

3. Implementation Procedure

We'll break the operation into discrete kernel launches:

Phase 1: Initial Normalization
  • Use standard matrix multiplication: operation string '…i j d → …i j d' for the first norm, but for the hidden_dim projection
  • However, we are to keep batch dimensions separate.

The kernel design:

A. Input Decomposition:
  • Input tensor x: [B, N, N, dim]
  • We must normalize along the dim dimension.

B. Projection Kernels:
  • We need to split the tensor into batches of B*dim and perform: gemm(B*dim, N*N) -> but that doesn't align
  • Better: flatten all batch and dim into one large tensor to use blocked matrix multiplication for both LayerNorm and Linear.

But given the complexity, we cautiously note:

  while the operation is not explicitly given, the intended design consists of LayerNorm, Linear projections, Sigmoid gates, and then a summed einsum operation. Due to the high dimensionality and large sequence length, we must avoid naive loop unfolding.

4. Search Choices and Parameter Tuning

We'll use fixed kernel launch size (BLOCK = 32*1024) to work in bulk, but this might not be optimal. Since hardware hidden_dim=128 and sequence=N=1024 might be too large for our kernel blocks, we consider:

  • BLOCK sizes typically used
  • We might need to split the hidden_dim dimension if available

However, the problem doesn't allow us to assume hidden_dim can be split.

We have B in {1,2}, N in {256,512,1024}, hidden_dim typically 128, so operation size can be up to 2*1024^2*128 = 268 million elements, and we are summing over N, so we must find a way to compute with large blocks.
