We are going to implement the TriMul forward pass as a Triton kernel. The goal is to improve performance by fusion and efficient use of shared memory.
 The main steps as in the PyTorch code are:
  1. Apply LayerNorm on the input channel dimension.
  2. Project the input to hidden_dim with two linear projections (left_proj and right_proj) and two gated projections (left_gate and right_gate).
  3. Apply the gating functions (sigmoid) and multiply by the mask if present.
  4. Perform the core reduction (TriMul operation) which is: 
        out[b, i, j, h] = sum_{k=0}^{N-1} left[b, i, k, h] * right[b, j, k, h]
     Note: The reduction is over the sequence index k for each triangle (i, j) and for the hidden dimension h.
  5. Apply an output gate and then the final linear projection.

 Since the operation is computationally intensive (N^2 elements and hidden_dim inner dimension) we will try to fuse as much as possible.

 We have two configurations for the input distribution: normal or Cauchy. We don't need to change the kernel for that, but we should cast appropriately.

 We have a mask option. We can try to integrate the mask into the kernel if possible.

1. Approach and rationale
   The Triangle Multiplicative Update (TriMul) operator from AlphaFold3 performs pairwise operations by projecting inputs through multiple linear layers, applying gating mechanisms and optional masks, and finally reducing the results over a shared sequence dimension. The core challenge is optimizing the reduction step, which is O(N^3) for the given tensor shape.

   Our approach leverages Triton's block scheduling and shared memory to:
   - Split the reduction dimension (N) into manageable blocks
   - Use in-thread operations for gating and masking
   - Perform matrix multiplication for each hidden index h
