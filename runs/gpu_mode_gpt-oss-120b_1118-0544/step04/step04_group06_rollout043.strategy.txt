    The central idea is to implement the core operation of TriMul (Triangle Multiplicative Update) as a fast library primitive. The operation involves a triple summation over the sequence dimensions (often called reduction in the context of tensor operations), and our goal is to optimize it using Triton. The rationale is based on the following key points:

    We have a tensor `x` of shape [B, N, N, C] that undergoes linear projections (left_proj, right_proj) followed by sigmoid gate activations (left_gate, right_gate). The core operation reduces the last two sequence dimensions (k) to compute `out[b,i,j,d]`.

    The bottlenecks addressed are:
    1. Explicit Python loops would be inefficient for large N (512-1024). 
    2. Unstructured memory access patterns without tiling.
    3. High overhead from coordination across N^3 operations.

    Our primary method is to convert the reduction into an efficient linear algebra kernel. Triton provides atomic adds and barrier synchronization that allow us to optimize concurrent writes on different (`i`, `j`) positions while avoiding race conditions. The operation is separable by channel dimension (d), so we'll group reductions for each d concurrently. This grouping is possible because intermediate computations for different d are independent.

    Aggressive blocking is crucial. The reduction size N (sequence dimension) is large, so we can divide the entire reduction by a BLOCK size (≥64) and process multiple blocks at once. This allows us to hide memory latency and keep computation busy, reducing total runtime.

    - We must handle invalid computations explicitly.
