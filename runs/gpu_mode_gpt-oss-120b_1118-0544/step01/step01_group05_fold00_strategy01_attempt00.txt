The approach is to use a batched matrix multiplication kernel to compute the contraction defined by the TriMul operator.

The core idea is to reshape the input and output tensors to simplify the computation and to use efficient memory access patterns. Specifically, for the input tensors `left` and `right` (both from shape [B, N, N, hidden_dim] to [B*hidden_dim, N, N]), the contraction for each element in the batch (now B * hidden_dim elements) is to compute a matrix multiplication of two matrices: one `N` x `hidden_dim` and the other `hidden_dim` x `N` (with the inner dimension being `hidden_dim`). 

This is motivated by the fact that the contraction is defined as:
`out[b, i, j, d] = sum_{k} (left[b, i, k, d] * right[b, j, k, d])`
Which can be interpreted as a matrix multiplication between two matrices (`left` and `right`) for each `d` and each `b`.

The Mathematical specification:
We have two tensors:
- `left` of shape [B, N, N, hidden_dim]
- `right` of shape [B, N, N, hidden_dim]

We wish to compute a new tensor `out` of shape [B, hidden_dim, N, N] (or equivalently (B*hidden_dim, N, N)) where:
`out_block[b*d+i, j, k] = sum_{l} (left[b, i, l, d] * right[b, j, l, d])`

But note that the indices in `out` are not independent. We wish to compute for each (b, i, j, d) the sum over k.

However, after reshaping:
- We view `left` as [B*hidden_dim, N, N] and `right` as [B*hidden_dim, N, N]
- Then, for each batch index `block_id` in [0, batch_size-1] where batch_size = B * hidden_dim, we perform:
    `C[block_id, i, j] = dot_product(left[block_id, i, :] * right[block_id, j, :])`

    `C[i, j] = (left[block_id, i, :] * right[block_id, j, :]) but then summed? No.`

Actually, the operation is:
    `C[i, j] = (left[block_id, i, k] * right[block_id, j, k]) summed over k.`
