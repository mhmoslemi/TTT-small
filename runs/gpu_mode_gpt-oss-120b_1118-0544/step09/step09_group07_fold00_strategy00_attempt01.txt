<problem-description>
We are implementing the "outgoing" version of the Triangle Multiplicative Update (TriMul) operator from AlphaFold3, which operates on a 4D tensor of shape [B, N, N, C]. The core operation is a pairwise multiplication conditioned on a mask, followed by a reduction. The reference implementation uses a series of PyTorch operations including LayerNorm and einsum for the spatial dimensions, but the reduction part has been offloaded to a batched matrix multiplication (BMM) kernel which is slower.

Our previous implementation used a hybrid approach: a custom Triton kernel for the LayerNorm and projection/gating stages (when a mask is present), but it relied on `torch.bmm` for the core reduction, which resulted in a runtime of 3220 microseconds for the worst-case scenario. This is too slow, and our goal is to implement a fully optimized Triton kernel for the core operation that can meet the target runtime of 550 microseconds.

The core operation is:

out[b, i, j, :] = matrix multiplication of the row i of the [N, N] matrix and the column j of the [N, N] matrix from the same "channel" segment. However, note that the operation is defined per channel index:
out[b, i, j, h] = sum_{k} left[b, i, k, h] * right[b, j, k, h]

This means for each hidden dimension (h), we need to perform a small matrix multiplication between a [N, 1] vector (row i, all channels h) and a [1, N] vector (column j, all channels h). But wait, the original einsum expression:

out = einsum('...ikd,...jkd->...ijd', left, right)

performs the operation (N=128) [B*N*N*H] points.

Given the large N dimensions (up to 1024), we cannot iterate over N^3 in Python. We must use Triton's block-major processing to hide the reduction.

The new plan:

1. We will launch a kernel for each batch element, and within the kernel, process the hidden dimensions using block-major.
2. For fixed (b, i), we will have access to the row in left, which is [N, H].
3. For each j and h in the grid, we will load the corresponding column from right and the channel index h from left, then compute the dot product (sum over k) if the (i,j) element is active.

The key is to structure the kernel so that for each (b, i) pair, we do a block-major reduction over j and k. This means:

- We define a BLOCK_SIZE for the j-k space.
- We use async loading to fetch tiling blocks for right (when j varies) and left.
- We'll need to handle the mask appropriately if provided.

However, note that the operation out[b,i,j,h] requires that we multiply by left[b,i,k,h] and right[b,j,k,h]. This is not a standard matrix multiplication (like BMM) but a tensor contraction along k. But observe:

In the example einsum, it's:

 left[b,i,k,h] and right[b,j,k,h] -> [B, N, N, H] form matrix multiplication along k for each (b,i,j,h).

But note: left[b,i,k,h] is the k-th element of the i-th row (index i) for batch b and channel h, and right[b,j,k,h] is the k-th element of the j-th row for batch b and channel h.

The operation for fixed h is:
