**1. Approach and Rationale**

The previous implementation used a simple bmm (batched matrix multiplication) with FP16 and was sequential. It activated cache-friendly kernels only for the core operation, but the input linear layers and gating were still done in a naive way. We believe this design could reduce runtime by mitigating the large sequential memory footprint, especially for large seqlen and hidden layers, by better utilizing the specialized memory management features of triton.cuda.Device.
