The input is a 4D tensor [B, N, N, C] and an optional mask [B, N, N]. The outputs are computed by a series of linear projections and multiplicative operations, with a specific reduction operation over the diagonal index (k) for each pair (i, j) and hidden unit.

The previous implementation tried to use a kernel for the mask and gate fusion, and then used torch.bmm for the core reduction. However, the goal is to achieve lower runtime (target: 550 microseconds, down from 3229) by re-implementing the core reduction with a more optimized kernel.

### Approach and Rationale
The core operation of the TriMul module can be broken down as follows:
1. Layer normalization of the input tensor (x).
2. Projection of x to the hidden dimension using left_proj and right_proj linear layers.
3. Applying sigmoid activations to the gate projections (left_gate, right_gate, out_gate).
4. If a mask is provided, element-wise multiply the activations and projections by the mask (which is of shape [B, N, N]).
5. Perform a reduction over the sequence dimension (k) for each (i, j) to compute the output for the hidden dimension. This reduction is:
   out[b, i, j, d] = sum_{k=0}^{N-1} (left_proj[b, i, k, d] * right_proj[b, j, k, d])
6. Second layer normalization on the output hidden dimension.
7. Apply the output gate (out_gate) element-wise, then linear projection to restore the original channel dimension.

The bottleneck is the reduction step (step 5) which is O(N^3) per hidden unit. Since N can be up to 1024 (which is 2^10) and we have multiple batches and channels, a naive implementation would be too slow.

We propose to rewrite the core reduction using a fused kernel that also incorporates the mask and gates if present. However, note that the mask and gates might have been done in a separate kernel in the previous version.
