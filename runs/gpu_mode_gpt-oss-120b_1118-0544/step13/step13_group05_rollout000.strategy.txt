We are implementing the Triangle Multiplicative Update (TriMul) operator for the outgoing version from the AlphaFold3 paper.
 The input is a 4D tensor of shape [B, N, N, C] and a mask tensor of shape [B, N, N] (if present). The output is [B, N, N, C].

 Steps:
 1. LayerNorm on the input tensor over the channel dimension.
 2. If a mask is present and we are not in nomask mode, apply the mask (we'll handle masking in the kernel).
 3. Linear projections for left and right (both without bias and then gating with sigmoid).
 4. Core reduction: out[b,i,j,c_z] = sum_{k} x[b,i,k,c_z] * mask[b,i,k] * x[b,j,k,c_z] * right_gate[b,i,k,c_z] * right_gate[b,j,k,c_z]
    But note: the original operation uses two separate projections (left_proj, right_proj) and then gating. We are to compute:
        out[b,i,j,h] = (left_proj[b,i,k,h] * right_proj[b,j,k,h] * left_gate[b,i,k,h] * right_gate[b,j,k,h]) summed over k.

    However, the original code does:
        left_proj = left_proj(x) * mask * left_gate(x).sigmoid()   [and similarly for right]
        Then, out is computed by: out[b,i,j,d] = sum_{k} left_proj[b,i,k,d] * right_proj[b,j,k,d]

    So the core reduction is: (left_proj * right_proj) summed over k.

 5. Then, output_layer_norm and multiplication by out_gate, and final projection.

 Important: We are not computing gradients (so forward only).

 We are told to use Triton 3.3.1 and the kernels will run on a B200. We must achieve good performance (target 550 us, lower is better).

 Since we are dealing with a 4D tensor and the core reduction is over N (which is large) and also hidden_dim, and the operation is highly irregular (each output element at (i,j) is a sum over k of the product of two hidden_dim-sized vectors at (i,k) and (j,k)), we have to design a kernel that does this.

 Observation: The reduction can be viewed as a matrix multiplication between two matrices of shape [N, hidden_dim] but for each (i, j) we have:

        out_i[j, :] = left_proj[i, :, :] @ right_proj[j, :, :][:, 0], ... 

    However, note that the core operation is:

        out[b,i,j,d] = sum_{k=0}^{N-1} left[b,i,k,d] * right[b,j,k,d]

    But the dimensions of the tensors are [B, N, N, hidden_dim] for left_proj and right_proj after the initial linear projection.

    We are actually computing a batched version of a 3D tensor convolution, but without any convolutional strides, it's a full matrix multiplication style.

    Another way: We can rewrite the reduction with Einsum (as in the original code):

        out = einsum('...ikd,...jkd->...ijd', left_proj, right_proj)

    We cannot use PyTorch's Einsum because that might not be fused and could be slow for large N.

    We must write a Triton kernel for this.
