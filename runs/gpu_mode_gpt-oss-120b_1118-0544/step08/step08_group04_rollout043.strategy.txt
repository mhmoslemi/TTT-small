   1. LayerNorm on the input (using float32 for stability).
   2. Linear projections to hidden_dim (left_proj and right_proj, done via F.linear).
   3. Sigmoid gates are applied to the projected tensors (left_gate and right_gate).
   4. Fuse mask and gates (optional mask is applied, then multiplied by left_gate and right_gate).

   7. Apply output_gate (element-wise multiplication by a sigmoid output gate).
   8. Final linear projection back to original channels.

# Approach and rationale
The outgoing Triangle Multiplicative Update (TriMul) operator is a key component in protein structure prediction models, requiring efficient fissionover operations. The previous implementations used separate PyTorch operations for the reductions, leading to high L3 cache pressure and poor arithmetic intensity. We will implement a single fused kernel that handles all the dense operations: LayerNorm, projections, gating, and the core reduction. The kernel will be optimized with shared memory caches and proper blocking to maximize arithmetic intensity.

Our primary goals are:
1. Through-layer normalization: Use FP32 for stability then convert to FP16
2. Two-layer projection: Convert input to hidden_dim using FP16 linear operations
3. Masking and gating: Apply optional mask and gated operations within the reduction
4. Outgoing reduction: Perform the O(N^3) reduction efficiently with blocking
5. Post-processing: Second LayerNorm and final projection in FP16

The reduction step will be implemented in a nested loop fashion with three distinct kernels managed by two program IDs (batch and hidden_dim) to ensure proper tiling and reuse. We'll use a grid of configur`,constexpr size for spatial dimensions and the top-level BLAS gemm call for the reduction (which is highly optimized given the tensor core support).

# Mathematical specification
Let the input tensor `x` have shape `[B, N, N, C]`. After normalization and projection, we have two tensors `left` and `right` of shape `[B, N, N, H]`. 

The reduction step is:
$$
out[b,i,j,h] = \sum_{k=0}^{N-1} left[b,i,k,h] * right[b,j,k,h]
$$

But note that we also need to apply:
- Masking: `mask[b,i,j]` could be zero or one depending on the mask configuration
- Gating: Apply `left_gate[b,i,k,h]` and `right_gate[b,j,k,h]` to the left and right projections respectively

The combined operation is:
$$
out[b,i,j,h] = \sum_{k=0}^{N-1} mask[b,i,k] * left[b,i,k,h] * left_gate[b,i,k,h] * right[b,j,k,h] * right_gate[b,j,k,h]
$$

# Implementation procedure
1. **Input layout**: Maintain the original `[B, N, N, C]` layout but rearrange projections properly
2. **Kernel definition**: Use 2D program IDs (batch_id, hidden_id) to cover all batches and hidden channels
3. **Blocking strategy**:

   - Hidden_dim H is an outer dimension (we process all hidden channels separately)
4. **Memory management**:
