   ## 1. Approach and rationale
   The TriMul operation is defined as:
     - First, normalize the input using LayerNorm in PyTorch
     - Then, project via two linear layers and apply gating with sigmoid
     - Finally, compute an output tensor using a pairwise reduction over the sequence dimensions and hidden dimension

   However, the core reduction operation `out[b,i,j,h] = sum_{k} left[b,i,k,h] * right[b,j,k,h]` is expensive and requires optimization. This implementation breaks the computation into two separate stages in the kernel:
     a) Compute the intermediate `left` and `right` tensors via projections and gating
     b) Perform the reduction using matrix multiplication

   The key bottleneck is the pairwise reduction over N x N elements with H depth. The naive implementation would use nested loops with complexity O(N^3 x H) which would be slow for large N (up to 1024).

   WeInstead, transpose the input tensor to [B, H, N] and view it as B*H matrices of size [N, N], then multiply them pairwise and transpose to recover the desired output shape B, N, N, H.

   This reduces the pairwise operation to a double-loop over the batch-major dimension (B*H) and the inner matrix multiplication.
