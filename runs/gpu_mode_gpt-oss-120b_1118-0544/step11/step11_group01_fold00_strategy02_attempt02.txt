<strategy>Approach and rationale
The core operation of TriMul is a 3D reduction: given gate-in tensors of shape (B, N, N, H), compute for each (b, i, j, h) the scalar:
    out[b, i, j, h] = ∑ₖ left_gated[b, i, k, h] * right_gated[b, j, k, h]
where left_gated = left_proj * left_gate and similarly right_gated = right_proj * right_gate.

This is analogous to performing a batched matrix multiplication (BMM) where each 'matrix' is of shape (N, N) and the batch size is effectively (B * H). The two matrices for each 'batch element' are (i,k) and (j,k) with fixed H. 

The key insight is to treat this as a special case of BMM with timers, sharing spatial dimensions across the kernel. While block-strided reduction is conceptually similar, we use a single reduction kernel optimized for the 4D input structure.

For performance, we use:
- Activation to fp16 for tensor cores
- Blocked reduction across k (sequence dimension)
- Argument shapes<0,3,1,2> for efficient interleaving

Choose block size as max_N * max_H * 32 (minimum around 512, maximum around 2048) considering modern hardware timing affordances.

Implementation steps:
1. Apply LayerNorm (sequential, uses standard PyTorch) and load weights
2. Project with linear transformations using einsum fastpaths
3. Gate and mask using PyTorch
4. Transpose view ftensor to (B, H, N, N)
5. Compute reduction kernel with three loop dimensions: BLOCK=batch*H, BLOCK_H=H, BLOCK_K=N
6. View resulting tensor as (B, H, N, N)
7. Apply output gate and projection

This plan relies on triton's fused reduction capabilities and works across all shapes by dynamic kernel launch.
