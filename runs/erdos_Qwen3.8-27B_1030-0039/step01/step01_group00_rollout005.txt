Let me also think about the coordinate descent more carefully. The key insight is:
- A pairwise transfer (increase h[i] by t, decrease h[j] by t) preserves the mass constraint.
- The effect on each corr_k can be computed incrementally.
- We can do exact line search on the max corr.

For efficiency, I'll:
1. Precompute the current corrs.
2. For each pair (i,j) in priority order (based on active gradient difference):
   a. Compute how each corr_k changes as a function of t.
   b. Find the t that minimizes max_k corr_k(t).
   c. Accept if improvement > threshold.

The change in corr_k due to a transfer (i += t, j -= t):
- corr_k depends on h[i] and h[j] (and their partners).
- The change is linear in t for each corr_k (since corr_k is bilinear in h, and we're changing two coordinates, the change is linear).

Wait, corr_k is a sum of products h[a]*h[b]. If we change h[i] by t, the terms involving h[i] change linearly in t. So corr_k(t) = corr_k(0) + t * (partial_k) where partial_k is the partial derivative of corr_k at (i,j).

Actually, since we're changing BOTH h[i] and h[j], the change is:
Δcorr_k = t * (∂corr_k/∂h[i] - ∂corr_k/∂h[j])

So corr_k(t) = corr_k(0) + t * (g_k[i] - g_k[j]) where g = gradient of corr_k.

Since we want to minimize max_k (corr_k(0) + t * (g_k[i] - g_k[j])), and this is a max of linear functions of t, the minimum is at a point where two (or more) of the linear functions are equal and maximal.

This can be solved efficiently: for each k, the linear function is a_k + t * b_k where a_k = corr_k(0) and b_k = g_k[i] - g_k[j]. We want to minimize max_k (a_k + t * b_k) over t in [t_lo, t_hi].

The minimum of a convex piecewise-linear function can be found by checking the "breakpoints" where pairs of linear functions cross. But with 2n-1 = 89 functions, this is O(n^2) per pair, which might be too slow.

A simpler approach: binary search or ternary search on t. Since the max of linear functions is convex, ternary search works. Or I can just evaluate at a few points (like the previous code did with 7 points, but I'll use more).

Actually, for a convex piecewise-linear function, the minimum is either at t_lo, t_hi, or at a breakpoint. The breakpoints are where a_k + t*b_k = a_l + t*b_l for some pair (k,l), i.e., t = (a_l - a_k)/(b_k - b_l). There are O(n^2) breakpoints, but the minimum must be at one of them.

For n=45, that's 89*88/2 = 3916 breakpoints per pair. Too many.

Simpler: I'll use a grid of t values plus the endpoints. With 20-30 grid points, I should be able to find a good t.

Actually, an even simpler approach: since the function is convex, I can use scipy's brentq on the subgradient (which changes sign at the minimum). The subgradient at the minimum is 0, meaning the set {b_k : k in active} must straddle 0 (i.e., some b_k > 0 and some b_k < 0, and the weighted average is 0).

But for simplicity, I'll just use a grid of t values (say 20 points) plus endpoints, and take the best. This is O(20 * n) per pair, which is fine.

    dx = 2.0 / n
    return float(np.max(np.correlate(h, 1.0 - h, mode="full")) * dx)

    tgt = n / 2.0

        return float(np.sum(np.clip(h_raw + t, 0.0, 1.0))) - tgt
    lo = float(np.min(h_raw)) - 2.0
