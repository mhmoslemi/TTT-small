1. Approach and rationale
**Central objective and representation.** We search for a sampled step profile `h ∈ R^n` satisfying `0 ≤ h_i ≤ 1` and `(2/n) sum_i h_i = 1`, and we score it with the exact evaluator

`E_n(h) = dx * max_l corr_l(h, 1-h)`, `dx = 2/n`,

where `corr` is the full, non-circular correlation used by the supplied task. The goal is to minimize `E_n(h)` and, expectedly, to move from the supplied parent and prior heuristic optimum (about 0.381652 in the previous program) toward `0.3808`. This is nonconvex because the objective contains products `h_i h_j`. We do not claim a global optimum. The improvement mechanism is a direct minimax method that: (i) uses exact objective and exact candidate acceptance; (ii) targets only the active near-maximal lags; and (iii) augments high-dimensional linearized trust-region steps with exact pairwise coordinate descent and diversified restarts.

**Why this could improve the supplied construction.** Prior behavior relied on smoothed maximum log-sum-exp optimization followed by fixed-angle coordinate transfers. The new plan:
- avoids chasing all lags or a soft average of all constraints; it solves a convex QP on only the active constraints, allowing a direction that is individually favorable to every currently active/nearly active lag;
- explores a direction in full `n`-dimensional space rather than only tangent to two coordinates, then performs full nonlinear line search along that radically nonlinear direction;
- preserves or improves exactness by repeatedly re-evaluating exact objective after each high-dimensional step and using exact pairwise refinement for local unimodal neighborhoods;
- uses the supplied parent but treats it as one seed among parent-preserving/diversified seeds rather than allowing the entire budget to be tied to a single escalated continuous path;
- uses multi-resolution transfers to let a better continuous construction emerge at finer sample counts and then returns whichever resolution/window produced the exact minimum found.

**Distinguishing justified facts from heuristics.** The following are mathematical facts given the evaluator: total mass, exact objective, gradient, reflected complementary transform preserving the bound, exact affine linearization around a candidate, feasibility projection, and continuous transfer with exact re-evaluation. The following are heuristics: the size of active sets, trust radius schedule, the addition of thresholding/binarization, multi-resolution scaling factors, multistart count, and QP penalties. These choices are chosen for robustness and coverage; they do not prove optimality. Every significant move is still accepted only by its exact score.

2. Mathematical specification
2.1 Exact sampled objective
For one-dimensional vector `h` of floating length `n`, set

`dx = 2/n`.
Define a distinct derivative distance `d = 1 - h` (an array length n) and
`Cyl_array_lg = np.correlate(h, d, mode="full") * dx`.
Return

`C = max(Cyl_array_lg).`

`shape(Cyl_array_lg) = (2n - 1,)`.
For a lag sign index `ell = i - (n-1)`, expression paired as
`Cyl_array_lg[i] = dx * sum over valid first index s of h[s] * (1 - h[s+ell])`, where valid indices are一つ `s ∈ [0, n-1]`, `s+ell ∈ [0, n-1]`.

2.2 Objective transformation under reflected complement
Define

`T(h) = 1 - h[::-1]`.
Then `sum_i T(h)_i = n - sum_i h_i`; if `sum_i h_i = n/2`, then same.
The correlation formula gives maximum equality: `E(T(h)) = E(h)` because `T(h)` precisely interchanges correlation sequence and non-computed order reversal.
This preserves measurability/bounds and mass; useful as an evaluation sanity check/seed only, and it should always be evaluated exactly.

2.3 Mean-zero box-projected models
If a candidate or proposed direction `d` has sum `0`, then `h + alpha d` preserves the mass exactly up to numerical tolerance. If a solver directly changes variables `x`, impose equality `sum(x) = n/2` to enforce line load bounds for candidate mean.

2.4 Gradient of exact objective segments
For defining the constant vector gradient `G_ell ∈ R^n` of `Cyl_array_lg[ell]`:

For `ell = 0`:
`(G_ell)_i = dx * (1 - 2 h_i)`.

For `ell > 0`:
`G_ell` has derivative contributions
for valid first coordinates `i = 0, ..., n-ell-1`:
`+(dx)*(1 - h_{i+ell})` applied at index `i`;
for valid second-coordinate positions `[j=i+ell]`, using entry `j`:
`-(dx)*h_{j-ell}` as derivative at `j`.
Consequently any index `i` that appears in both categories, if both valid, has combined expression
`(G_ell)_i = dx * (1 - h_{i+ell}) - dx * h_{i-ell}` over the intersection; or if `i` is first only it is just first term; if only second, it is just `-(dx)h_{i-ell}` using `j=i` shifted range translated carefully.

For `ell < 0`, write `p = -ell`, then valid original-index pairs are
`i = p, ..., n-1`.
Derivative derivatives:
at first term variable `i`: `dx * (1 - h_{i-p})`;
at the underlying shifted parameter `r = i-p`, derivative is `-dx * h_i`.

Do not replace exact linear-correlation objective by a fixed-mass autocorrelation formula. The mass of h on a partial overlap `sum_{overlap} h` is lag-dependent. All logic compares to exactly computed standard result.

2.5 Feasibility projection
Every candidate vector/X after interpolation/optimization/line search needs a valid joint feasibility repair mechanism. Allowed and required:

For `x` finite, unless `n=0`, let `T = n/2`. Iterate stage:
(i) sanitize: if nonfinite, set NaN to constant `0.5`; then `x = np.clip(x,0,1)`.
(ii) Monotonic clipping root for exact equality:
Find an integer offset `theta` such that
`sum_i clip(x_i + theta, 0, 1) = T`. This exists because the clip sum is continuous and monotone; at `theta = -max(x)-1` gives near zero and at `theta=1-min(x)` gives near `n`. Solve via bisection/Brent until absolute difference `<1e-13`. Then set `x = np.clip(x+theta,0,1)`.
(iii) micro-repair finite errors: let `diff = T - sum(x)`. Use only variables strictly in `1e-12 < x_i < 1-1e-12`. If `diff >0`, add proportional amount only limited by the remaining headroom; if `diff <0`, confine inside common positions. While using `abs(diff) > 1e-10` and enough interior/output, split difference over thousands and redo bounds via maximum slack. This is exact mathematical feasibility with respect to linear constraints and within double precision tolerance. If it fails, revert to a valid verified vector.

The returned vector must satisfy numerical range and `sum(h) * 2/n` near `1`, and one should validate it with different absolute tolerance.
