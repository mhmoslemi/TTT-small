**Objective** – Find 26 circles inside the unit square that maximise the sum of their radii while satisfying non‑overlap and containment constraints.  
**Idea** – Treat the problem as a *max‑sum* variant of the classic “circle packing” but solve it by **sequential linear programming (SLP) on a reformulated convex subproblem**. The key insight is that for any fixed set of centre positions the optimal radii are given by a simple linear program, and conversely for any fixed radii the feasible centre locations form a convex region that can be approximated by linear constraints. By alternating between these two convex sub‑problems we obtain a monotone improvement of the objective and escape many local minima that trap a monolithic non‑linear optimizer.

The whole pipeline consists of the following stages:

---

### 1. Geometry‑first layout (deterministic seed)

1.1 **Choose a dense template** – Start from a *triangular lattice* (hexagonal packing) scaled to fit roughly 0.8 of the unit square. Compute lattice spacing `s = 0.8 / floor(sqrt(26))`. Generate points  
 `(i*s + (j mod 2)*s/2 , j* s*sqrt(3)/2)` for integer `i, j` until at least 26 points lie inside `[0,1]^2`.  
Select the first 26 points by row‑major order.

1.2 **Margin addition** – Translate the whole pattern so that the minimal x‑ and y‑coordinates become `m = 0.05`. This guarantees a starting feasible radius of at least `m`.

1.3 **Initial radii** – Set every radius to a tiny uniform value `r0 = 0.01`. At this stage the configuration is trivially feasible.

Result: a feasible seed `(C⁰, r⁰)` with `C⁰ ∈ ℝ^{26×2}` and `r⁰ ∈ ℝ^{26}`.

---

### 2. Convex sub‑problem: optimal radii for fixed centres

Given a centre set `C = {c_i}` the radii must satisfy linear inequalities:

* **Wall constraints**  
 `r_i ≤ c_i.x`  (left)  
 `r_i ≤ 1 - c_i.x`  (right)  
 `r_i ≤ c_i.y`  (bottom)  
 `r_i ≤ 1 - c_i.y`  (top)

* **Separation constraints**  
 `r_i + r_j ≤ d_{ij}` where `d_{ij} = ‖c_i - c_j‖₂` (pre‑computed Euclidean distance).

All constraints are of the form `A r ≤ b` with `r ≥ 0`.  
The **objective** is to maximise `1ᵀ r`. This is a **linear program (LP)**.

**Solution method** – Use `scipy.optimize.linprog` (high‑speed dual simplex). Because the LP has only 26 variables and at most `4·26 + 26·25/2 ≈ 400` constraints, it solves in microseconds.

Output: `r* = argmax 1ᵀr  s.t.  A r ≤ b`. By construction `r*` is the *largest* radii compatible with the current centre set, therefore the sum of radii never decreases when we solve this LP.

---

### 3. Convex sub‑problem: feasible centre motion for fixed radii

Now treat radii `r` as constants and move the centres to increase the objective indirectly (by allowing larger radii in the next LP). For each circle we define a *safe region* where its centre may move without violating any constraint:

* **Wall strip** – `c_i.x ∈ [r_i, 1 - r_i]`, `c_i.y ∈ [r_i, 1 - r_i]`.
* **Pairwise strip** – For every neighbour `j` we need `‖c_i - c_j‖₂ ≥ r_i + r_j`. This is a *non‑convex* disc exclusion region.  
  Approximate each disc by a **polygonal outer linearisation**: Replace the Euclidean norm by a set of linear constraints that bound a regular `k`‑gon (e.g., `k = 8`) inscribed in the forbidden disc. For direction vectors `u_l = (cos θ_l, sin θ_l)`, the constraint becomes  
 `u_l·(c_i - c_j) ≤ - (r_i + r_j) * cos(π/k)`  (or the appropriate support function).  
  The collection of `k` half‑spaces yields a conservative convex approximation of the non‑overlap region.

With these linearised constraints the feasible set for all centres is a **convex polytope** `P(C; r)`.  

**Movement objective** – We cannot directly maximise the sum of radii (they are fixed), but we can **push centres away from walls and neighbours** to increase the slack in the LP of step 2. A simple proxy is to maximise the *minimum distance* from each centre to its active constraints, which can be expressed as a linear objective using slack variables:

Introduce slack `s_i ≥ 0` for each circle, impose  
 `c_i.x - r_i ≥ s_i`  (left)  
 `1 - c_i.x - r_i ≥ s_i`  (right)  
 `c_i.y - r_i ≥ s_i`  (bottom)  
 `1 - c_i.y - r_i ≥ s_i`  (top)

and for each polygonal side `l` between i and j:  
 `u_l·(c_i - c_j) + (r_i + r_j) * cos(π/k) ≥ s_i + s_j`.

Then **maximise** `Σ s_i`. This linear program encourages each centre to move toward the centre of its feasible region, producing a more “relaxed” packing.

**Solution method** – Again a small LP, solved with `linprog`.

Result: a new centre set `C⁺` that respects all constraints (by construction) and provides larger slack for the next radius LP.

### 5. Refinement via “local inflation”

After the alternating SLP converges, many constraints will be tight but some circles may still have unused margin (e.g., a circle far from walls but blocked by a polygonal approximation). Perform a **local non‑linear inflation**:

* For each circle `i` compute the exact Euclidean distances to all neighbours and walls.
* If the exact gap `g = min_j d_{ij} - (r_i + r_j)` is noticeably larger than the polygonal gap used in the centre LP, increase `r_i` by a fraction of `g` (e.g., `0.4·g`) and re‑solve a *small* radius LP limited to the affected circles (only those with changed radii).  
* Repeat a few passes (≤5) until no further increase ≥ 1e‑5 is possible.

Because we only enlarge radii within the true feasible region, the final configuration remains valid.

### 7. Implementation details

* **Data structures** – Store centres as `np.ndarray` of shape (26,2); radii as 1‑D array length 26.
* **Polygonal approximation** – Use 8‑gon (θ = 0, π/4, …, 7π/4). Pre‑compute direction vectors `u_l`. The factor `cos(π/8) ≈ 0.9239` scales the disc radius into the half‑space offset.
* **LP formulation** – Build coefficient matrix `A_ub` and vector `b_ub` for each LP directly using NumPy broadcasting for speed; no loops over pairs needed beyond constructing the list of constraints.
* **Numerical tolerances** – Set `linprog` option `tol=1e-10`. After each LP, clip radii to `[0, 0.5]` and centre coordinates to `[0,1]` to avoid drift.
* **Termination criteria** – `ε = 1e-6` on the improvement of the sum of radii; maximum 30 alternating iterations; each LP solves in < 0.01 s, so total runtime well below the 1‑CPU limit.
* **Failure modes** –  
   * *Degenerate LP* – If a centre is exactly on a wall, some constraints become redundant; `linprog` still handles it.  
   * *Polygonal under‑approximation* – May prevent slight improvements; the final local inflation step recovers the missing slack.  
   * *Numerical overflow* – Not an issue because variable magnitudes stay ≤ 1.
