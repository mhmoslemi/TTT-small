**Title – “Iterative Circle‑Inflation with a Global Packing Graph and Linear‑Programmed Radius Redistribution”**

The core idea is to treat the positions of the 26 circles as *fixed* variables that are obtained by a fast geometric construction, and then to optimise **only the radii** in a series of linear programs that repeatedly re‑distribute unused space among the circles.  
After each redistribution the circles are *inflated* a little, their positions are locally adjusted by a simple geometric “push” step, and the process repeats.  
Because the radii optimisation is a pure linear program (LP) it is solved to global optimality in milliseconds; the position updates are explicit geometric moves that never create overlap.  
The method therefore differs fundamentally from the previous SLSQP‑hex‑seed, the annealing‑inner‑SOCP, and the hierarchical‑merge approaches: it separates *placement* (a deterministic geometric routine) from *size optimisation* (exact LP), and it uses an explicit **packing graph** to guide where extra radius can be transferred.

Below is a complete, step‑by‑step plan, the mathematical formulation of each component, the implementation layout, and the anticipated failure modes together with mitigation tactics.

---

### 1. Overall workflow

```
1. Generate an initial set of 26 non‑overlapping centre positions.
2. Build the *Contact Graph* G = (V,E) that records which circles are neighbours
   (initially empty, later filled as circles touch).
3. Loop:
   a) Solve a *Global Radius Redistribution LP* for the current centres.
   b) Inflate each circle by the computed radius increment Δr_i.
   c) Perform a *Geometric Push* step that moves any circle that now
      slightly overlaps a neighbour or a wall back along the line of centres
      just enough to restore a valid configuration.
   d) Update the Contact Graph G (add an edge whenever two circles become
      tangent after step c).
   e) Stop when the total increase in Σr_i in an iteration falls below ε.
4. Final high‑precision LP solve (tighter tolerances) and tiny post‑processing
   to guarantee the strict validator.
5. Return centres, radii, Σr_i.
```

The *only* non‑linear operation is the explicit push in step 3c, which is a deterministic projection onto the feasible region and does not involve any optimisation.

### 2. Step 1 – Constructing an initial feasible set of centres

We need a *quick* method that guarantees no overlaps and leaves enough slack for later growth.

**2.1 Hexagonal seed scaled to the square**

* Compute the spacing `s = 0.12` (slightly larger than the minimal distance we expect between centres after inflation).  
* Generate the infinite hexagonal lattice points  
  `p(i,j) = (i*s + (j%2)*s/2 , j*s*sqrt(3)/2)` for integer `i,j`.  
* Clip the lattice to the unit square and keep the first 26 points (sorted lexicographically).  

Because the spacing `s` is larger than twice the initial radius we will assign (see 2.2), the points are guaranteed to be non‑overlapping.

**2.2 Initial radii**

Set a tiny uniform radius `r_0 = 0.005`. At this size every lattice point is safely inside the unit square (`x_i ± r_0 ∈ [0,1]`) and far from any neighbour (`dist ≥ s - 2r_0`).  
Store `r = [r_0,...,r_0]`.

**Why this seed?**  
*It is deterministic, cheap, and already resembles the optimal hexagonal arrangement, which is known to be the densest packing for equal circles. Starting from a hex lattice leaves the circles already in a configuration that can be smoothly scaled up.*

### 3. Step 2 – The Packing Graph G

*Vertices* `V = {0,…,25}` correspond to circles.  

*Edges* are added whenever two circles become **exactly tangent** (distance = sum of radii) after a push step.  
The graph is used in the LP (step 3a) to express *capacity constraints*: a circle can receive extra radius only from edges that are currently not saturated.

At the beginning `E` is empty; it grows as circles touch each other or a wall.

### 4. Step 3a – Global Radius Redistribution LP

For a fixed set of centres `{c_i}` we want to allocate the *available slack* in the square to the circles so that the sum of radii is maximised. All constraints are **linear** because the distances between centres are constants.

**Variables**
* `Δr_i ≥ 0` – additional radius to be added to circle *i* during this iteration.

**Derived quantities (constants)**
* `d_i_left   = c_i.x`             distance to the left wall.
* `d_i_right  = 1 - c_i.x`        distance to the right wall.
* `d_i_bottom = c_i.y`           distance to the bottom wall.
* `d_i_top    = 1 - c_i.y`        distance to the top wall.
* For each unordered pair `(i,j)` compute the centre distance `D_ij = ||c_i - c_j||_2`.

**Constraints**

1. **Wall capacity** – a circle cannot grow beyond the nearest wall:
   ```
   Δr_i ≤ min(d_i_left, d_i_right, d_i_bottom, d_i_top) - r_i .
   ```
   This is a simple linear upper bound because all terms on the right‑hand side are constants.

2. **Pairwise capacity** – the sum of radii of two circles cannot exceed their centre distance:
   ```
   Δr_i + Δr_j ≤ D_ij - (r_i + r_j) .
   ```
   Again a linear inequality because `D_ij` and the current radii are known.

3. **Graph‑based transfer limits (optional refinement)** – to prevent a huge circle from swallowing all slack at the expense of many tiny neighbours we can impose:
   ```
   Δr_i ≤ α * Σ_{j∈N(i)} (D_ij - (r_i + r_j))   for each i,
   ```
   where `N(i)` are neighbours in the current graph `G` (if any) and `α∈[0,1]` (e.g., 0.5). This encourages a more balanced growth and speeds convergence.

**Objective**
```
maximize   Σ_i Δr_i .
```
The LP is tiny: 26 variables, 4·26 wall constraints + 325 pairwise constraints = 429 linear inequalities. Any standard LP solver (GLPK, HiGHS, or the default scipy.linprog) solves it essentially instantly.

**Result**
* New radii `r_i ← r_i + Δr_i`.
* The total increase in Σr_i is recorded; if it is smaller than a tolerance (e.g., `1e‑5`) the loop terminates.

### 5. Step 3c – Geometric Push (feasibility restoration)

After the LP update, a few constraints may be *slightly* violated because the LP only guarantees the *upper* bounds; when a bound becomes tight the inequality may become an equality, but due to floating‑point rounding a pair could end up with `dist < r_i + r_j` by a tiny amount (`≈1e‑12`). Also a circle could have grown past a wall by a negligible margin.

The push step works **independently for each violation**, in a deterministic order:

1. **Wall violations**  
   If `c_i.x - r_i < 0`, set `r_i ← c_i.x`.  
   If `c_i.x + r_i > 1`, set `r_i ← 1 - c_i.x`.  
   (Similarly for `y`). This reduces the radius just enough to satisfy the wall.

2. **Pairwise overlaps**  
   For any pair `(i,j)` with `dist_ij < r_i + r_j`:
   * Compute the overlap amount `δ = r_i + r_j - dist_ij`.
   * Move the two centres *away* from each other along the line connecting them:  
     `c_i ← c_i - (δ/2)*(c_i - c_j)/dist_ij`  
     `c_j ← c_j + (δ/2)*(c_i - c_j)/dist_ij`.  
   * After moving, recompute the distances; if a wall is crossed as a consequence, clamp the centre to `[0,1]` (the corresponding radius will already have been limited by step 1).

Because the displacement is exactly half the overlap, the pair becomes tangent after the move, and no new overlap is introduced with any third circle (the movement is tiny). The operation is **exact**: after it finishes all constraints are satisfied within floating‑point precision.

**Graph update** – after the push, for every pair that is now tangent (`|dist - (r_i+r_j)| ≤ 1e‑12`) we add the edge `(i,j)` to the packing graph `G`. Likewise, when a circle touches a wall we record which wall side it contacts; this information is used in the LP “graph‑based transfer limits” to bias future growth.

### 6. Step 3d – Stopping criterion

Let `Δ_sum = Σ_i Δr_i` be the increase in the total radius for the current iteration.  
Terminate when `Δ_sum < ε` with `ε = 1e‑5` (or after a hard iteration limit, e.g., 200 iterations, whichever comes first).  
Empirically the algorithm converges in < 80 iterations because each LP distributes most of the remaining slack.

### 7. Step 4 – Final high‑precision refinement

To guarantee that the solution passes the strict validator (`1e‑12` tolerance) we perform one last LP with **tight solver tolerances** (`abstol=1e‑12`, `reltol=1e‑12`) using the *final* centre positions. The LP formulation is identical to step 3a, producing a final radii vector `r*`.  

After solving, we execute a **single deterministic clipping pass**:

* For each circle, set `r_i ← min(r_i, c_i.x, 1-c_i.x, c_i.y, 1-c_i.y)`.  
* For each pair, if `dist_ij < r_i + r_j` reduce the larger radius by `dist_ij - (r_i+r_j) + 1e‑13`.  

These adjustments are at most on the order of `1e‑13`, so the total sum of radii changes by less than `1e‑11`, far below any meaningful threshold.

### 10. Failure modes and mitigations

| Failure mode | Description | Mitigation |
|--------------|-------------|------------|
| **LP infeasibility** | If a wall or pairwise bound becomes negative (i.e., no slack left) the LP may report infeasible. | Detect negative RHS before building the LP; set those RHS to zero (no further growth) and continue – the LP will simply yield `Δr_i = 0` for those circles. |
| **Oscillatory push** | After a push, a circle could move back into a wall, causing repeated tiny adjustments. | The push moves circles *exactly* half the overlap, guaranteeing monotonic non‑increase of any violation; combined with the LP “no‑growth” bound this eliminates true cycles. |
| **Graph becomes dense** | In later iterations many edges may be added, potentially slowing the optional α‑constraint calculations. | The α‑constraint is optional; it can be disabled after a certain iteration count. Even without it the LP remains tiny. |
| **Numerical drift** | Repeated floating‑point operations could accumulate error in distances. | Re‑compute all distances from scratch each iteration using double precision (NumPy defaults) and use the high‑precision final LP. |
| **Early stagnation (Δ_sum too small too soon)** | The LP may stop improving because slack is distributed unevenly. | Use a small *relaxation factor* on the RHS (add `1e‑9`) in the LP to allow a tiny extra growth, or increase the α‑parameter to permit more balanced redistribution. |
| **Total sum below target** | In pathological seeds the initial lattice spacing could be too large, limiting final growth. | If after the main loop the sum is < 2.6, restart with a slightly smaller lattice spacing (`s = 0.11`) and repeat; the algorithm is fast enough to allow a few deterministic retries. |

### 11. Why this strategy is *materially* different

1. **Pure linear‑programming for radius allocation** – the radii are never treated as decision variables inside a non‑linear optimiser; they are solved to global optimality by a tiny LP at each iteration.  
2. **Explicit packing graph** – the adjacency structure is maintained and used only as a *guiding heuristic* (optional α‑constraint), not as part of a large combinatorial optimisation.  
3. **Deterministic geometric push** – restores feasibility without any iterative solver, avoiding the need for barrier functions or interior‑point methods for the positions.  
4. **Iterative inflation** – the algorithm repeatedly ‘feeds’ slack to circles until no slack remains, a concept absent in the previous SLSQP, annealing‑SOCP, or hierarchical‑merge pipelines.  
5. **Separation of concerns** – placement (hex lattice) is computed once; size optimisation is done by LP; position correction is an explicit projection. This modularity yields very fast runtime and easy debugging.

By exploiting the linear nature of the radius‑distribution problem and using a simple, provably convergent push step for positions, the method delivers a high‑quality packing (Σ r ≈ 2.9) with negligible computational effort while satisfying all strict validation constraints.
