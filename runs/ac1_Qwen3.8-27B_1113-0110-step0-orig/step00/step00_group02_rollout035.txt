Now the pattern I'm seeing: for small n, we can get below 2 by making the sequence non-uniform (decreasing or having a specific shape). The key is that the convolution peak (at the center) gets reduced relative to the sum.

For large n, the question is what's the optimal shape. Let me think about this more generally.

For a sequence x of length n, the center of the convolution is:
b[n-1] = sum_i x[i]*x[n-1-i]

If the sequence is decreasing (x[0] > x[1] > ... > x[n-1]), then the products x[i]*x[n-1-i] pair large with small, potentially reducing the sum compared to a uniform sequence.

For a geometric sequence x[i] = r^i (for i = 0, ..., n-1) with r < 1:
- sum = (1-r^n)/(1-r)
- b[n-1] = sum_i r^i * r^{n-1-i} = n * r^{n-1}

Wait, that's interesting! b[n-1] = sum_i r^{i + (n-1-i)} = sum_i r^{n-1} = n * r^{n-1}

And sum = (1-r^n)/(1-r)

score = 2*n * max_b / sum^2

If max_b is at the center: score = 2*n * n * r^{n-1} / ((1-r^n)/(1-r))^2 = 2*n^2 * r^{n-1} * (1-r)^2 / (1-r^n)^2

For large n and r < 1, r^n → 0, so 1-r^n → 1:
score ≈ 2*n^2 * r^{n-1} * (1-r)^2

To minimize this, we need r^{n-1} to be small, which means r should be small. But if r is too small, the sequence is concentrated at one end and other parts of the convolution might be large.

Actually, for a geometric sequence, the convolution at position k is:
b[k] = sum_{i=max(0,k-n+1)}^{min(n-1,k)} r^i * r^{k-i} = sum of r^{k} for each valid i
= (number of valid i) * r^k

The number of valid i for position k is:
- For k < n: k+1 (since i ranges from 0 to k)
- For k >= n: 2n-1-k (since i ranges from k-n+1 to n-1)

So b[k] = (k+1)*r^k for k = 0, ..., n-1
b[k] = (2n-1-k)*r^k for k = n, ..., 2n-2

The maximum is at some position. For k < n, b[k] = (k+1)*r^k. The maximum of (k+1)*r^k as a function of k is at k ≈ 1/r - 1 (for continuous k).

If r is close to 1, the peak is at large k (near n-1), and b[n-1] ≈ n*r^{n-1}.
If r is close to 0, the peak is at small k, and b[0] = 1 (approximately).
