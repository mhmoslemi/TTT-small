```python
    """Compute a * a using FFT."""
    n = len(a)
    size = 2 * n - 1

def simplex_project(v):
    """Project v onto the probability simplex {x >= 0, sum(x) = 1}."""
    n = len(v)
    u = np.sort(v)[::-1]
    cssv = np.cumsum(u)
    cond = u * np.arange(1, n + 1) > (cssv - 1)
    rho = np.nonzero(cond)[0][-1]
    theta = (cssv[rho] - 1) / (rho + 1.0)
    return np.maximum(v - theta, 0)

    """Compute subgradient of (a*a)_{k_star} w.r.t. a."""
    n = len(a)
    g = np.zeros(n)
    lo = max(0, k_star - n + 1)
    hi = min(n - 1, k_star)
    idx = np.arange(lo, hi + 1)
    g[idx] = 2.0 * a[k_star - idx]
    return g
```

$\text{softmax}_\tau(a, k) = \tau \log \sum_k \exp((a*a)_k / \tau)$

As $\tau \to 0$, this approaches $\max_k (a*a)_k$. For finite $\tau$, it's smooth and can be optimized with gradient-based methods.

The gradient is:
$\frac{\partial \text{softmax}_\tau}{\partial a_i} = \sum_k p_k \cdot \frac{\partial (a*a)_k}{\partial a_i}$

where $p_k = \exp((a*a)_k / \tau) / \sum_j \exp((a*a)_j / \tau)$ is a probability distribution over $k$.

This is a "weighted average" of the subgradients at different $k$ values, with weights proportional to the softmax distribution. This is exactly the "smoothed subgradient" and should work well with standard optimization methods.

```python
    # In FFT terms: cross_corr = IFFT(conj(FFT(p)) * FFT(a))
    # (with appropriate length)
    
    fft_size2 = 1 << (3*n).bit_length()
    P_full = fft(p, fft_size2)  # need complex FFT for cross-correlation
    A_full = fft(a, fft_size2)
    cross_corr = ifft(np.conj(P_full) * A_full)
    # cross_corr[i] = sum_k p[k] * a[k-i] (circular correlation)
    # For linear correlation, we need to take the first n elements (or appropriate range)
    # Actually, cross_corr[i] = sum_k p[k] * a[(k-i) mod fft_size2]
    # For i = 0, ..., n-1 and k = 0, ..., 2n-2:
    #   (k-i) mod fft_size2 = k-i (if k >= i) or k-i+fft_size2 (if k < i)
    # Since fft_size2 >= 3n > 2n-2, and k < 2n, k-i > -n, so:
    #   If k >= i: cross_corr gets p[k] * a[k-i] (correct)
    #   If k < i: cross_corr gets p[k] * a[k-i+fft_size2] = 0 (since k-i+fft_size2 >= fft_size2 - n > 2n-2 >= len(a))
    # So cross_corr[i] = sum_{k=i}^{2n-2} p[k] * a[k-i] = sum_{d=0}^{2n-2-i} p[d+i] * a[d]
    # But we also need d < n, so: cross_corr[i] = sum_{d=0}^{min(n-1, 2n-2-i)} p[d+i] * a[d]
    # This is exactly what we want!
    
    grad_a = 2.0 * np.real(cross_corr[:n])
    
    # Gradient w.r.t. z:
    # dz_i = a_i * (grad_a_i - sum_j a_j * grad_a_j)
    mean_grad = np.dot(a, grad_a)
    grad_z = a * (grad_a - mean_grad)
    
    return obj, grad_z
```

Actually, I realize I can use `np.correlate` or just FFT to compute the gradient. Let me use `scipy.signal.fftconvolve` or `numpy.fft` directly.

Let me reconsider. The gradient is:
$\text{grad}_a[i] = 2 \sum_k p_k \cdot a_{k-i}$

where the sum is over valid $k$ (i.e., $0 \leq k < 2n-1$ and $0 \leq k-i < n$).

This is the "cross-correlation" of $p$ and $a$ at lag $i$ (with $p$ as the "template").

Using FFT:
$\text{cross\_corr} = \text{IFFT}(\text{FFT}(p, N) \cdot \overline{\text{FFT}(a, N)})$

where $N$ is the FFT size (padded to avoid circular effects).

The length of $p$ is $2n-1$ and the length of $a$ is $n$, so the linear cross-correlation has length $3n-2$. I need $N \geq 3n-1$.

For $n = 5000$, $N \geq 14999$, so I'd use $N = 16384$ (next power of 2).

The FFT of size 16384 takes about $16384 \cdot 14 \approx 230000$ operations. That's fast.

Let me implement this properly:

```python
def smooth_obj_grad(z, tau):
    n = len(z)
    # Softmax parameterization
    z_shifted = z - np.max(z)
    a = np.exp(z_shifted)
    a = a / a.sum()
    
    # Auto-convolution
    fft_size_conv = 1 << (2*n - 1 - 1).bit_length()
    fa = rfft(a, fft_size_conv)
    b = irfft(fa * fa, fft_size_conv)[:2*n-1]
    
    # Smooth max
    b_max = np.max(b)
    exp_b = np.exp((b - b_max) / tau)
    p = exp_b / exp_b.sum()
    obj = b_max + tau * np.log(exp_b.sum())
    
    # Gradient w.r.t. a: grad_a[i] = 2 * sum_k p_k * a_{k-i}
    # Use FFT for cross-correlation
    fft_size_xc = 1 << (3*n).bit_length()
    P = np.fft.fft(p, fft_size_xc)
    A = np.fft.fft(a, fft_size_xc)
    cross_corr = np.fft.ifft(np.conj(P) * A).real[:n]
    grad_a = 2.0 * cross_corr
    
    # Gradient w.r.t. z
    mean_grad = np.dot(a, grad_a)
    grad_z = a * (grad_a - mean_grad)
    
    return obj, grad_z
```

The issue with L-BFGS-B is that it stores a history of gradients (memory), which can be expensive for large $n$. The default memory is 10, which stores 10 pairs of $(s_i, y_i)$, each of length $n$. For $n = 5000$, that's $10 \cdot 5000 \cdot 8 = 400KB$, which is fine.

Each function evaluation involves:
1. Softmax: $O(n)$.
2. Auto-convolution: $O(n \log n)$.
3. Smooth max: $O(n)$.
4. Cross-correlation (FFT): $O(n \log n)$.
5. Gradient computation: $O(n)$.

Total: $O(n \log n)$ per evaluation. For $n = 5000$, that's about $5000 \cdot 13 = 65000$ operations, which is very fast.

L-BFGS-B typically converges in 50-200 iterations for smooth problems. So the total time should be a few seconds.

The key question is: **will L-BFGS-B on the smooth approximation actually find a solution with score < 2?**

I think the answer depends on the value of $\tau$:
- For large $\tau$, the smooth max is close to the mean of the auto-convolution, and the optimum is the uniform distribution (score 2).
- For small $\tau$, the smooth max is close to the actual max, and the optimization might find a non-uniform solution with score < 2.

But for small $\tau$, the function is "spiky" and L-BFGS-B might struggle. I'll use a "continuation" approach: start with large $\tau$ and gradually decrease it.

Let me implement this:

```python
def optimize_with_continuation(n, tau_start, tau_end, n_steps, rng):
    z = np.zeros(n)  # uniform
    for i in range(n_steps):
        tau = tau_start * (tau_end / tau_start) ** (i / n_steps)
        result = minimize(
            fun=lambda z, tau=tau: smooth_obj_grad(z, tau)[0],
            x0=z,
            jac=lambda z, tau=tau: smooth_obj_grad(z, tau)[1],
            method='L-BFGS-B',
            options={'maxiter': 100, 'ftol': 1e-12, 'gtol': 1e-10}
        )
        z = result.x
    
    a = np.exp(z - np.max(z))
    a = a / a.sum()
    return a
```

This is a "homotopy" or "continuation" method. Start with a smooth approximation (large $\tau$) and gradually make it sharper (small $\tau$).

The challenge is choosing the right $\tau$ values and the number of steps.

Let me think about the range of $\tau$. The auto-convolution values are of order $1/n$ (for a uniform distribution). The "interesting" scale for $\tau$ is comparable to the typical fluctuation of $b_k$ around its mean. For a uniform distribution, $b_k$ ranges from $0$ to $1/n$, with most values around $1/(2n)$. The fluctuation is of order $1/n$. So $\tau$ should be of order $1/n$ to $1/n^2$.

For $n = 5000$: $\tau$ should be in the range $[10^{-5}, 2 \times 10^{-4}]$.
