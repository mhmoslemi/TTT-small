    target = n / 2.0

    h = h * (target / s)
    h = np.clip(h, 0.0, 1.0)
    diff = target - h.sum()

        order = np.argsort(1.0 - h) if diff > 0 else np.argsort(h)
        for idx in order:
            if diff > 0:
                add = min(diff, 1.0 - h[idx])
                h[idx] += add
                diff -= add
            else:
                sub = min(-diff, h[idx])
                h[idx] -= sub
                diff += sub
            if abs(diff) < 1e-12:
                break
    return h

    corr = np.correlate(x, 1.0 - x, mode='full')
    m = np.max(corr)
    s = alpha * (corr - m)
    s = np.clip(s, -500, 500)

Actually, I realize I should double-check: does the problem use periodic or non-periodic correlation? Looking at the formula:

C₅ = max_k ∫ h(x)(1-h(x+k)) dx

And the discretization: C₅ = max(np.correlate(h, 1-h, mode="full") * dx)

np.correlate with mode="full" gives the linear (non-periodic) correlation. So it's NOT periodic. The lags go from -(n-1) to (n-1), and the correlation at each lag is a partial sum.

This is important: at extreme lags (|k| close to n), the overlap is small (few terms), so the correlation is naturally small. The maximum is likely achieved at intermediate lags.

This means the "correlation" is really measuring: for each shift k, how much of h overlaps with the complement of shifted h. For small k, there's lots of overlap potential. For large k, the overlap region is small.

    target = n / 2.0

    h = h * (target / s)
    h = np.clip(h, 0.0, 1.0)
    diff = target - h.sum()
    if abs(diff) > 1e-10:
        order = np.argsort(1.0 - h) if diff > 0 else np.argsort(h)
        for idx in order:
            if diff > 0:
                add = min(diff, 1.0 - h[idx])
                h[idx] += add
                diff -= add
            else:
                sub = min(-diff, h[idx])
                h[idx] -= sub
                diff += sub

    best_c5 = compute_c5(best_h, 2.0 / best_n)
    return (best_h, best_c5, best_n)
