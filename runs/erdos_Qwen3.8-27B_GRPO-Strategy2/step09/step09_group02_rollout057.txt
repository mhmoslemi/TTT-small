Wait, that's not quite right. h[i](1-h[i+L]) is:
- 0 when h[i]=0 (regardless of h[i+L])
- 0 when h[i+L]=1 (regardless of h[i])
- h[i] when h[i+L]=0
- h[i](1-h[i+L]) in general

So to minimize, we want: either h[i] is small, or h[i+L] is close to 1.

For ALL L simultaneously, this suggests h should be close to 1 almost everywhere. But sum(h) = n/2 prevents this.

Alternatively: h should be structured so that for every L, the set {i: h[i] is large} and {i+L: h[i+L] is small} have minimal overlap.

This is like a "code" problem: find a subset S of {0,...,n-1} of size n/2 such that for every shift L, |S ∩ (S+L)^c| is minimized.

This is related to "difference sets" in combinatorial design theory.

For a perfect difference set, every difference s_i - s_j (mod n) for s_i ≠ s_j in S occurs exactly once. This gives a very uniform distribution of differences.

If such a set exists for n=560 (it might not), then |S ∩ (S+L)^c| would be constant for all L.

v = 560, k = 280, λ = 280*279/559 ≈ 140.27... Not an integer, so no perfect difference set exists.

    dx = 2.0 / n
    g = np.zeros(n)
    for ii, k in enumerate(top_idx):

def _smooth_grad(h, alpha, mlags):

    c = _corr(h)
    m = c.max()
    top_idx = np.argpartition(c, -mlags)[-mlags:]

    w = np.exp(s)
