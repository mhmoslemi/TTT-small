= (1-h[p-s]) * [0 ≤ p-s < n and 0 ≤ p < n] + (-h[p+s]) * [0 ≤ p < n and 0 ≤ p+s < n]

So: ∂c[k]/∂h[p] = (1-h[p-s]) if p-s ∈ [0,n-1] else 0, minus h[p+s] if p+s ∈ [0,n-1] else 0.

For a pair move h[i] += d, h[j] -= d:
Δc[k] = d * (∂c[k]/∂h[i] - ∂c[k]/∂h[j])

This is O(1) to compute per k, so O(n) total per pair evaluation. But we need to check if c5 decreases, which requires knowing max(c). We can maintain the current c array and update it:
c_new[k] = c_old[k] + d * (∂c[k]/∂h[i] - ∂c[k]/∂h[j])

Then max(c_new) can be computed. But that's still O(n) per evaluation (139 values for n=70).

Actually, this is the same cost as just computing _c5(h_new, dx) which is also O(n²) = O(4900) for n=70. The incremental approach saves a factor of ~n but the constant is higher due to the complexity of computing partials. For n=70, the direct approach is probably fine.
