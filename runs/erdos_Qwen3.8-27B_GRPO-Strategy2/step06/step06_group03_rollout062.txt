def _repair(h, n):
    h = np.clip(h, 0.0, 1.0).copy()
    target = n / 2.0
    s = h.sum()
    if s < 1e-15:
        return np.full(n, 0.5)
    if abs(s - target) > 1e-9:
        h *= target / s
        h = np.clip(h, 0.0, 1.0)
        diff = target - h.sum()
        if abs(diff) > 1e-12:
            order = np.argsort(1.0 - h) if diff > 0 else np.argsort(h)
            for idx in order:
                if diff > 0:
                    a = min(diff, 1.0 - h[idx]); h[idx] += a; diff -= a
                else:
                    a = min(-diff, h[idx]); h[idx] -= a; diff += a
                if abs(diff) < 1e-12:
                    break
    return h

    n = len(h)
    return float(np.max(np.correlate(h, 1.0 - h, mode='full')) * 2.0 / n)

    c = np.correlate(h, 1.0 - h, mode='full')

Instead of optimizing h directly, think of it as: we want to minimize t subject to:

min 0
s.t. c_lin[k] <= t*n/2 for all k
     sum(h) = n/2
     0 <= h <= 1

If feasible, we can decrease t. If not, increase t.

But wait, the linearization of a bilinear term is only a valid upper or lower bound depending on the sign. For h∈[0,1] and g=1-h∈[0,1], the bilinear term h[i]*g[i+k] is bounded:
- h[i]*g[i+k] ≤ h[i] * 1 = h[i] (trivial)
- h[i]*g[i+k] ≤ 1 * g[i+k] = g[i+k] (trivial)
- h[i]*g[i+k] ≤ (h[i] + g[i+k])/2 (JP bound)

The JP (Jensen-Penalty) bound gives a convex upper bound:
h[i]*g[i+k] ≤ (h[i] + g[i+k])² / 4

But that's still quadratic. The McCormick envelope for x*y with x∈[0,1], y∈[0,1]:
x*y ≤ max(x,y) (upper bound)
x*y ≤ x, x*y ≤ y (tighter upper bounds)
x*y ≥ x + y - 1 (lower bound)

For our purpose (upper bounding c[k]), we can use:
h[i] * g[i+k] ≤ h[i]  (always, since g ≤ 1)
h[i] * g[i+k] ≤ g[i+k] (always, since h ≤ 1)
h[i] * g[i+k] ≤ (h[i] + g[i+k]) / 2 (JP, tighter when both are in (0,1))

The tightest upper bound is min(h[i], g[i+k], (h[i]+g[i+k])/2). But this is piecewise linear, not a single linear function.

Actually, for the SCA approach, the linearization (first-order Taylor) is the standard approach. At the current point h0:
h[i]*g[i+k] ≈ h0[i]*g0[i+k] + g0[i+k]*(h[i]-h0[i]) + h0[i]*(g[i+k]-g0[i+k])
= h[i]*g0[i+k] + h0[i]*g[i+k] - h0[i]*g0[i+k]

Since g = 1-h, this becomes:
= h[i]*(1-h0[i+k]) + h0[i]*(1-h[i+k]) - h0[i]*(1-h0[i+k])

This is linear in h! (The terms h[i] and h[i+k] appear linearly.)

So the linearized constraint c[k] ≤ T becomes:
sum_i [h[i]*(1-h0[i+k]) + h0[i]*(1-h[i+k]) - h0[i]*(1-h0[i+k])] ≤ T

This is linear in h.

But the key question: is this a valid UPPER bound? In general, the first-order Taylor approximation of a bilinear function is NOT an upper bound. For x*y with x,y ∈ [0,1]:
xy ≈ x0*y + x*y0 - x0*y0
The error is (x-x0)(y-y0), which can be positive or negative.

So the Taylor linearization is not a valid relaxation. We'd need to add a penalty or use the McCormick envelope.

McCormick for x*y, x∈[0,1], y∈[0,1]:
Lower: xy ≥ 0, xy ≥ x + y - 1
Upper: xy ≤ x, xy ≤ y

For c[k] = sum_i h[i]*g[i+k], an upper bound is:
c[k] ≤ sum_i min(h[i], g[i+k])
But min is not linear. Using xy ≤ x: c[k] ≤ sum_i h[i] = n/2 (trivial)
Using xy ≤ y: c[k] ≤ sum_i g[i+k] = 2n - n/2 = 3n/2 (trivial)

The McCormick upper bound for the sum:
c[k] ≤ min(sum_i h[i], sum_i g[i+k]) = n/2 (still trivial)

So the McCormick LP approach gives trivial bounds for this problem. Not useful.

One key improvement: **compute the gradient more efficiently using FFT**.

The gradient for the weighted correlation:
g[j] = sum_k w[k] * (∂c[s_k]/∂h[j])

where s_k = (n-1) - k is the shift for correlation index k.

For shift s ≥ 0:
∂c[s]/∂h[j] = (1-h[j+s]) for j ≤ n-1-s  (from the h[j]*(1-h[j+s]) term)
              - h[j-s] for j ≥ s  (from the h[j-s]*(1-h[j]) term)
              (0 otherwise)

So: g[j] = sum_{k: s_k ≥ 0, j ≤ n-1-s_k} w[k]*(1-h[j+s_k]) - sum_{k: s_k > 0, j ≥ s_k} w[k]*h[j-s_k]
         + sum_{k: s_k < 0, j+s_k ≥ 0} w[k]*(1-h[j+s_k]) - sum_{k: s_k < 0, j-s_k ≤ n-1} w[k]*h[j-s_k]

This can be written as:
g = sum_k w[k] * ((1-h) shifted by s_k - h shifted by -s_k)

Which is a convolution! Specifically:
g = conv(w, 1-h) - conv(w_flip, h) (with appropriate indexing)

Wait, let me be more precise. If I define:
A[j] = sum_k w[k] * (1-h[j + s_k])  (first term: shift by +s_k)
B[j] = sum_k w[k] * h[j - s_k]      (second term: shift by -s_k)
g = A - B

A is a convolution of w with (1-h) where w is indexed by shift.
B is a convolution of w with h where w is indexed by -shift.

The shifts s_k = (n-1) - k range from n-1 down to -(n-1).

So: A = correlate(w, 1-h) (circular, with appropriate zero-padding)
    B = correlate(w_flip, h)

Where w is indexed by shift s = n-1-k, so w[s] for s = -(n-1), ..., n-1.

This can be computed via FFT in O(n log n) instead of O(n²)!
