For coordinate descent:
- Pick a random pair (i, j)
- Let s = h[i] + h[j]
- The objective as a function of t = h[i] (with h[j] = s-t) is:
  f(t) = max_k c_k(t)
  
  where c_k(t) = a_k + b_k * t (linear in t, as we showed)
  
- To find min_t f(t) over [max(0,s-1), min(1,s)]:
  - f is convex (max of lines)
  - Use bisection on the subgradient: find t where the subgradient crosses 0
  
The subgradient of f at t is:
  ∂f(t) = convex hull of {b_k : a_k + b_k*t >= f(t) - eps}
  
f is minimized where 0 ∈ ∂f(t), i.e., where there exist active k with b_k > 0 and b_k < 0 (or b_k = 0 for an active k).

Algorithm:
1. Compute a_k and b_k for all k
2. Find f* = min_t max_k (a_k + b_k*t)
3. This can be done by:
   a. Finding all intersection points t_jk where a_j + b_j*t = a_k + b_k*t
   b. Evaluating f at each intersection point and at boundaries
   c. Taking the minimum

But computing all intersection points is O(K²) where K = 2n-1 ≈ 1119. That's about 1.2M points, each needing O(K) evaluation. Total: 1.4B operations per pair update. Way too slow.

Faster: Use bisection.
1. Compute f'(t-) and f'(t+) (min and max slopes of active lines)
2. If f'(t) > 0 for all active lines (all slopes positive), decrease t
3. If f'(t) < 0 for all active lines (all slopes negative), increase t
4. Otherwise, t is optimal

This is essentially bisection + activation check. Each iteration is O(K) to find active lines. With 30 iterations, that's 30*1119 ≈ 34K operations per pair update. For 560 pairs, that's 19M operations per sweep. Very fast!
