- From h[j] changing: the term p=j in c[m] was h[j]*(1-h[j-shift_k]) = 0, now 1*(1-h[j-shift_k]). Change: +(1-h[j-shift_k]).
- From h[i] in second factor: when p-shift_k = i, i.e., p = i+shift_k. The term was h[p]*(1-h[i]) = h[p]*0 = 0, now h[p]*1 = h[p]. Change: +h[p] for p = i+shift_k (if valid).
- From h[j] in second factor: when p-shift_k = j, i.e., p = j+shift_k. The term was h[p]*(1-h[j]) = h[p]*1 = h[p], now h[p]*0 = 0. Change: -h[p] for p = j+shift_k (if valid).

So the total change in c[m] for shift_k = m-(n-1):
delta_c[m] = -(1-h[i-shift_k]) + (1-h[j-shift_k]) + h[i+shift_k] - h[j+shift_k]
(where we only include terms for valid indices)

This is O(1) per shift_k! So the total change is O(n) to compute all deltas, and we need to check if the max changes.

But actually, for the max to change, we need to check:
- If the new max (at the previously-max position) equals the old max, or
- If some other position becomes the new max

The previously-max positions are the ones with c[m] = old_max. After the swap, their value changes by delta_c[m]. If any of them decreases below old_max, then we need to find the new max among all positions.

This is a bit complex but doable. Let me implement it:

```python
def _swap_delta(h, i, j, n):
    """Compute the change in all c[m] values when we swap h[i]:1->0, h[j]:0->1."""
    # c[m] = sum_p h[p] * (1-h[p - (m-(n-1))])
    # shift_k = m - (n-1), ranges from -(n-1) to (n-1)
    # delta_c at shift_k = m-(n-1):
    #   -(1-h[i-shift_k]) + (1-h[j-shift_k]) + h[i+shift_k] - h[j+shift_k]
    #   (each term only if index is in [0, n-1])
    
    delta = np.zeros(2*n - 1)
    for sk in range(-(n-1), n):
        d = 0.0
        # Term 1: -(1-h[i-sk]) if 0 <= i-sk < n
        idx1 = i - sk
        if 0 <= idx1 < n:
            d -= (1.0 - h[idx1])
        # Term 2: +(1-h[j-sk]) if 0 <= j-sk < n
        idx2 = j - sk
        if 0 <= idx2 < n:
            d += (1.0 - h[idx2])
        # Term 3: +h[i+sk] if 0 <= i+sk < n
        idx3 = i + sk
        if 0 <= idx3 < n:
            d += h[idx3]
        # Term 4: -h[j+sk] if 0 <= j+sk < n
        idx4 = j + sk
        if 0 <= idx4 < n:
            d -= h[idx4]
        delta[sk + n - 1] = d
    return delta
```

This is O(n) per swap. For n=560, that's 560 operations. In Python, this loop would take about 50-100μs. That's slower than just recomputing the correlation (10μs). So for binary solutions, just recomputing might be faster!

Let me also think about the "targeted continuous optimization" more carefully. The idea is:
- Find the top T shifts with highest c[k]
- For each of these shifts, identify the positions that contribute most
- Adjust those positions to reduce the overlap

For shift k (0-indexed in the correlation output, corresponding to shift_k = k - (n-1)):
c[k] = sum_i h[i] * (1-h[i-shift_k]) for valid i

The "contributing" pairs are (i, i-shift_k) where h[i]=1 and h[i-shift_k]=0.
To reduce c[k], we want to either:
- Set h[i] closer to 0 (reduce the first factor), or
- Set h[i-shift_k] closer to 1 (reduce the second factor)

But changing h[i] affects other shifts too. So we need to be careful.

A simple heuristic: for the worst shift, find a random pair (i, i-shift_k) that contributes, and move h[i] down by ε and h[i-shift_k] up by ε (preserving the sum). Then check if the overall max decreased.

This is essentially a 2-point local search guided by the worst shifts.

Let me implement this:

```python
def _targeted_opt(h, n, rng, deadline, top_k=5):
    best_h = h.copy()
    best_c = _eval(h)
    dx = 2.0 / n
    
    while time.time() < deadline:
        c = np.correlate(h, 1.0 - h, mode='full') * dx
        # Find top k shifts
        top = np.argsort(c)[-top_k:]
        worst_shift = top[np.argmax(c[top])]
        shift_k = (n - 1) - worst_shift  # actual shift
        
        # Find contributing pairs
        if shift_k >= 0:
            # c = sum_i h[i] * (1-h[i-shift_k]) for i = shift_k..n-1
            i_vals = np.arange(shift_k, n)
            pairs = (h[i_vals] > 0.5) & (h[i_vals - shift_k] < 0.5)
        else:
            sp = -shift_k
            i_vals = np.arange(sp)
            pairs = (h[i_vals + sp] > 0.5) & (h[i_vals] < 0.5)
        
        if pairs.sum() == 0:
            # No clear conflict, try random 2-point move
            i = rng.randint(n)
            j = (i + 1) % n
            eps = 0.01 * rng.randn()
            h[i] += eps
            h[j] -= eps
            if h[i] < 0 or h[i] > 1 or h[j] < 0 or h[j] > 1:
                h[i] -= eps
                h[j] += eps
                continue
            c_new = _eval(h)
            if c_new < best_c:
                best_c = c_new
                best_h = h.copy()
            else:
                h[i] -= eps
                h[j] += eps
            continue
        
        # Pick a random contributing pair
        pidx = np.where(pairs)[0][rng.randint(pairs.sum())]
        if shift_k >= 0:
            i1 = i_vals[pidx]  # h[i1] = 1, h[i1-shift_k] = 0
            i2 = i1 - shift_k
        else:
            sp = -shift_k
            i1 = i_vals[pidx] + sp  # h[i1] = 1, h[i1-sp] = 0
            i2 = i_vals[pidx]
        
        # Move: decrease h[i1], increase h[i2]
        eps = 0.005 * rng.uniform(0.5, 1.5)
        if h[i1] - eps < 0: eps = h[i1] * 0.5
        if h[i2] + eps > 1: eps = (1 - h[i2]) * 0.5
        if eps < 1e-8: continue
        
        h[i1] -= eps
        h[i2] += eps
        c_new = _eval(h)
        if c_new < best_c:
            best_c = c_new
            best_h = h.copy()
        else:
            h[i1] += eps
            h[i2] -= eps
    
    return _repair(best_h, n), best_c
```

**New idea: Use a "penalty" approach instead of log-sum-exp**

Instead of approximating max_k c_k with log-sum-exp, use a large-M penalty:
f(h) = mean(c) + M * max(0, max_k c_k - target)^2

This directly pushes max_k c_k below a target value. We can iteratively decrease the target.

**Another new idea: Use the "bottleneck" structure**

At the optimum, multiple shifts achieve (close to) the maximum. The solution is "balanced" across shifts. We can exploit this by:
1. Computing c[k] for all k
2. Identifying the "active" set (shifts within ε of the max)
3. Optimize only to reduce the max of the active set
4. As the max decreases, more shifts become active

For step 3, the "direction" approach:
- At the current point, the active constraints are the top few c[k] values
- The gradient of each c[k] with respect to h is:
  dc_k/dh[i] = (1-h[i-shift_k]) - h[i+shift_k] (for valid indices)
  (where shift_k = k-(n-1))
- To reduce max_k c_k, we want to move in a direction that decreases all active c_k simultaneously
- This is a linear programming problem: find direction d that minimizes max_k (c_k + d·∇c_k) subject to ||d||_infty ≤ 1
- The optimal d is given by the negative of the weighted sum of gradients, where weights are the softmax of the active c_k values
