from scipy.optimize import minimize
import time

def compute_c5(h, dx):
    corr = np.correlate(h, 1.0 - h, mode='full')
    return np.max(corr) * dx

def repair(h, n):
    h = np.clip(h, 0, 1)
    target = n / 2.0
    s = h.sum()
    if s < 1e-12:
        return np.full(n, target / n)
    h *= target / s
    h = np.clip(h, 0, 1)
    diff = target - h.sum()
    if abs(diff) > 1e-12:
        if diff > 0:
            order = np.argsort(1.0 - h)
        else:
            order = np.argsort(h)
        for idx in order:
            if diff > 0:
                add = min(diff, 1.0 - h[idx])
                h[idx] += add
                diff -= add
            else:
                sub = min(-diff, h[idx])
                h[idx] -= sub
                diff += sub
            if abs(diff) < 1e-12:
                break
    return h

def smooth_obj(x, dx, alpha):
    corr = np.correlate(x, 1.0 - x, mode='full')
    m = np.max(corr)
    s = alpha * (corr - m)
    s = np.clip(s, -200, 200)
    return (m + np.log(np.sum(np.exp(s))) / alpha) * dx

def smooth_grad(x, dx, alpha):
    n = len(x)
    corr = np.correlate(x, 1.0 - x, mode='full')
    m = np.max(corr)
    s = alpha * (corr - m)
    s = np.clip(s, -200, 200)
    e = np.exp(s)
    w = e / np.sum(e)
    grad = np.zeros(n)
    for m_idx in range(2 * n - 1):
        sh = m_idx - n + 1
        wm = w[m_idx]
        for k in range(n):
            if 0 <= k + sh < n:
                grad[k] += wm * (1.0 - x[k + sh])
            if 0 <= k - sh < n:
                grad[k] -= wm * x[k - sh]
    return grad * dx

def lbbq_optimize(h, n, dx, alpha, maxiter, deadline):
    if time.time() >= deadline:
        return h, compute_c5(h, dx)
    try:
        def obj(x):
            return smooth_obj(x, dx, alpha)
        def grad(x):
            return smooth_grad(x, dx, alpha)
        def sum_con(x):
            return np.sum(x) - n / 2.0
        
        res = minimize(
            obj, h, jac=grad, method='L-BFGS-B',
            bounds=[(0, 1)] * n,
            constraints=[{'type': 'eq', 'fun': sum_con, 'jac': lambda x: np.ones(n)}],
            options={'maxiter': maxiter, 'gtol': 1e-12, 'ftol': 1e-14}

def repair(h, n):
    h = np.clip(h, 0.0, 1.0)
    target = n / 2.0
    s = h.sum()
    if s < 1e-12:
        return np.full(n, target / n)
    h *= target / s
    h = np.clip(h, 0.0, 1.0)
    diff = target - h.sum()
    if abs(diff) > 1e-12:
        if diff > 0:
            order = np.argsort(1.0 - h)
        else:
            order = np.argsort(h)
        for idx in order:
            if diff > 0:
                add = min(diff, 1.0 - h[idx])
                h[idx] += add
                diff -= add
            else:
                sub = min(-diff, h[idx])
                h[idx] -= sub
                diff += sub
            if abs(diff) < 1e-12:
                break
    return h

def smooth_obj(x, dx, alpha):
    corr = np.correlate(x, 1.0 - x, mode='full')
    m = np.max(corr)
    s = alpha * (corr - m)
    s = np.clip(s, -200, 200)
    return (m + np.log(np.sum(np.exp(s))) / alpha) * dx

def smooth_grad(x, dx, alpha):
    n = len(x)

        grad[k] = np.sum(w[m1] * (1.0 - x[k + sh[m1]])) - np.sum(w[m2] * x[k - sh[m2]])
    return grad * dx

Also, I realize the vectorized local search might have a bug. When I do `corr = corr + scale * (C[i] - C[j])`, I need to make sure this is correct. Let me verify:

If h[i] increases by scale and h[j] decreases by scale:
- Δcorr[m] = scale * (C[i,m] - C[j,m]) where C[i,m] = ∂corr[m]/∂h[i] (approximately, for small scale)

Wait, C[i,m] as I defined it is NOT the partial derivative. Let me recheck.

C[i,m] = (1-h[i+sh[m]])_{valid} - h[i-sh[m]]_{valid}

This IS ∂corr[m]/∂h[i]! Because:
corr[m] = Σ_k h[k] * (1-h[k+sh[m]])
∂corr[m]/∂h[i] = (1-h[i+sh[m]])_{i+sh valid} - h[i-sh[m]]_{i-sh valid}

So C[i,m] = ∂corr[m]/∂h[i]. And for a small change δ at i:
corr_new[m] ≈ corr[m] + δ * C[i,m]

For a pair move (h[i]+=d, h[j]-=d):
corr_new[m] ≈ corr[m] + d*C[i,m] - d*C[j,m] = corr[m] + d*(C[i,m] - C[j,m])

This is correct! It's a first-order approximation. For small d, this should be accurate.

But wait - the correlation is bilinear, not linear! So the first-order approximation isn't exact. The exact change is:
corr_new[m] = Σ_k h'[k] * (1-h'[k+sh[m]])

where h'[i] = h[i]+d, h'[j] = h[j]-d, h'[k] = h[k] otherwise.

The exact change in corr[m] from changing h[i]→h[i]+d:
= (h[i]+d)*(1-h'[i+sh]) - h[i]*(1-h[i+sh])
= d*(1-h'[i+sh]) = d*(1-h[i+sh])  [since i+sh ≠ i,j for most m]

Actually, it's more complex if i+sh = j (the change at j affects the value at i+sh). But for most (i,j,m) triples, i+sh[m] ∉ {i,j}, so the first-order approximation is exact!

The cases where it's not exact:
- i + sh[m] = j: then h'[i+sh[m]] = h[j]-d, so the change is d*(1-(h[j]-d)) = d*(1-h[j]+d) ≠ d*(1-h[j])
- i - sh[m] = j: then h'[i-sh[m]] = h[j]-d, change = -h'[i-sh[m]] = -(h[j]-d) ≠ -h[j]
- j + sh[m] = i: similar
- j - sh[m] = i: similar

These are O(1) cases per (i,j) pair (at most 4 values of m where this happens). For n=70, the correlation has 139 values, so at most 4 out of 139 are affected. This means the first-order approximation is exact for at least 135 out of 139 values. The max might be slightly off for those 4 values, but for a good solution, the max is unlikely to be at those specific positions.
