1. Approach and rationale

Central idea. The discretized problem has state variables h ∈ [0,1]^n with an exact-measure constraint Σ h_i = n/2. The true objective is

    C(h) = max_s T_s(h),  T_s(h) = dx · Σ_i h_i (1 - h_{i-s}), dx = 2/n,

where s runs over all discrete lags -(n-1),…,(n-1). The pointwise maximum over 2n-1 shifted overlap terms is discontinuous. The proposed approach is a nonconvex, multi-start gradient method: replace the max only inside the optimization core by a smooth log-sum-exp surrogate, use an analytic gradient, retain feasibility with an exact box + sum projection or with an equality-constrained local optimizer, evaluate every candidate by the original metric, and keep only candidates whose exact original objective improves.

Why this addresses the bottleneck. The main difficulty is the nonsmooth maximum over many boundaries and lag directions. A direct threshold or coordinate construction cannot adapt continuously to the active set of supporting lags. The log-sum-exp objective makes all near-term lags contribute, but in the final beta steps it heavily concentrates weight on active near-maximal lags. Feasible gradient directions can lower the worst overlap in a continuous way. Multiple starts, including quantized binary starts and random perturbations, are used because the problem is generally nonconvex. Exact reevaluation ensures that surrogate distortions and small equality-constraint violations do not turn into an invalid final answer.

Primary method. Use a warm-started smooth local solver initialized at validated current constructions and diverse alternatives. There are two local modes:

1. Exact-mode: use scipy.optimize.minimize with method="trust-constr", bounds [0,1], and a LinearConstraint enforcing sum(x)=n/2. This is the preferred mode when time permits. It avoids any penalty-driven constraint drift.

2. Penalty-mode fallback: use scipy.optimize.minimize with method="L-BFGS-B", bounds [0,1], objective F_beta(h) + λ(Σ h - n/2)^2. Every fallback return is repaired with the exact-feasibility projection and evaluated by the true objective.

Use deterministic functions, top-level objective helpers, and no lambda/closure scanning hooks because constraints/objectives must be top level. For search initialization, use the supplied initial_h_values as the parent construction, then continuing improvement tabs are kept only if exact feasibility check passes.
