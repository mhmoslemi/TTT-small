<strategy>
1. Approach and rationale

Central idea: the parent construction is already close to the record, and the dominant bottleneck is that the discrete objective
`F(h)=max_r dx*corr(h,1-h)[r]` is finite-dimensional but globally nonconvex and nonsmooth: each lag value contains products `h_i(1-h_j)`. A direct nonlinear-programming minimization cannot be treated as a standard convex epigraph because products `h_i h_j` are nonconvex, while a direct exact local search over only continuous variables is weak on nonsmooth plateaus. The proposed method therefore combines:

1. Exact validation of the supplied parent and a robust joint repair mechanism enforcing `0<=h_i<=1` and `sum_i h_i=N/2` together.
2. Multiple annealed smooth-minimax reductions `F_tau(h)=tau*logsumexp(C(h)/tau)`, minimized by local trust-region/sequential quadratic programming methods under simple bounds and one equality constraint. The annealing reduces the smooth approximation error, while multiple starts and updated best candidates allow escape from local regions.
3. A continuous coordinate-pair exact line-search phase. Because each objective value changes along a feasible sum-preserving line as a quadratic function of the scalar parameter, local optimum escape is attempted along discrete finite directions selected from active-gradient scores. The exact evaluator with finite support is used for acceptance, so the original lag-direction boundary terms are never replaced.
4. Randomized local perturbations and optional coarse representation transfers to avoid becoming trapped by the parent representation. The runner always keeps the best exact feasible one-seed solution and returns it before the deadline; parent or a clean fallback is retained when nothing is improved.

This approach targets the tiny record gap `~5e-5`: small changes are pursued by exact local descent after smoothing. The smooth surrogate guides the high-dimensional manifold toward lower-max regions, while exact pair line searches make Newton-like gradients unnecessary and handle the nonconvex nonsmooth exact objective. Correctness is strictly tied to the supplied `np.correlate` evaluator. No solution is accepted unless evaluated with the exact evaluator and repair.

Limitations and facts distinguished:
- Global optimality is not claimed; this is a local启发式 plus sampling of many nearby feasible manifolds.
- The convex solver path is deliberately not claimed as global: nonconvex bilinear products require accepted lower bound only if the subproblem is convex; elsewhere smooth surrogates are used as search methods only.
- Random variations improve the chance of beating the parent but do not guarantee improvement; the exact evaluator is always used to falsify bad surrogate approximations.
- The finite support of linear correlation and nonzero lag boundary effects are included by using `np.correlate(h,1-h, mode="full")` themselves, not a circular or autocorrelation shorthand.

2. Mathematical specification

2.1 Discrete variables, dimension, and normalization
Let `N = h_points`. Indexing is `i=0,...,N-1`. Define
```
dx = 2.0/N
S_target = N/2
```
Feasibility requires:
`0 <= h_i <= 1` for every `i`, and `sum(h_i)=S_target`, equivalently `dx*sum(h_i)=1`.

2.2 Exact objective
The authoritative objective is:
`C_vec(h) = dx * np.correlate(h, 1-h, mode='full')`
whose length is `2N-1`. Indexing: all lags in the entire vector are considered. Then:
`C5(h) = max(C_vec(h))`.
This combines lag directions and finite-support truncation. The optimizer must implement exactly the returned `dx` and mode `full`. For every final candidate, recompute this from the actual arrays.

2.3 Edge/matrix representation matching np.correlate
For gradient and optional exact diagonal operations, define pairs `(a,b)`, `a,b in 0..N-1`, such that: the product `h_a*(1-h_b)` contributes to output lag `r` determined by the actual `np.correlate` pairing. Build this relation without assuming formula:
- Build exact generated pairs `E = {(a,b,lag(a,b))}`.
- `e_a` has 1 at `a`, others 0; `e_b` similarly. Compute `t = np.correlate(e_a, e_b, 'full')`.
- The lag index `r` where `t` is the nonzero/maximum is recorded for pair `(a,b)`. Usually there is one such index for exact unit arrays. If multiple entries by numerical error, choose any index with `t > 0.5`, and confirm unique basis count; otherwise fall back to evaluating finite differences.
- For each lag `r`, the derivative of `h_i` appears in the linear term exactly by the number of second coordinates paired to first `i`. Precompute:
```
D[r,i] = # { j : (i,j) in E_r }
E_r = { (a,b) : lag_of_pair[a,b] == r }
```
Then the numerical expression used for objective may be written:
```
C_r(h) = dx * ( sum_i D[r,i]*h[i] - sum_{(a,b) in E_r} h[a]*h[b] )
```
This pharmacist must be verified during setup against `np.correlate(h,1-h,'full')*dx` for several random feasible vectors with approximate tolerance on large-scale, sparse, and boundary cases (including components exactly `0`, `1`, `0.5`). If the numerical relation fails, mark gradients finite-difference only; parent fallback phase remains.

2.4 Objective gradient from the edge relation
For each lag `r`, C_r gradient is:
```
∂C_r/∂h_m = dx * (D[r,m]
                  - sum_{(m,j) in E_r} h[j]
                  - sum_{(i,m) in E_r} h[i])
```
The diagonal pair `(m,m)` contributes `-2*h[m]` correctly because it appears twice in the second and third sums.

For surrogate minimization, choose a stabilizing scalar reference inside one evaluation but define mathematically:
```
F_tau(h) = tau * log sum_r exp( C_r(h) / tau )
```
stabilized by `m = max_r(C_r(h)/tau)`, `w_r = exp(C_r(h)/tau - m)/sum_r exp(...)`, and value `F_tau = tau*(m + log(sum exp(...)))`. Correct gradient with respect to h is independent of the constant `m`:
```
∇F_tau(h) = sum_r w_r * ∇C_r
```
Compute using the edge formula and `np.add.at` or two-scaled scatter operations with duplicate first/second index arrays.

Equality constraint derivative:
```
g_eq(h)=sum(h)-S_target=0
J_eq = ones(N)
```
No extra penalty terms added. The smooth surrogate still governs only search. Acceptance always uses exact `C5(h)` before return.

2.5 Joint feasibility projection mechanism
For a candidate vector `y`, project to the projection of the box intersection hyperplane:
```
min_x ||x-y||^2 subject to sum(x)=S_target, 0<=x_i<=1
```
Because objective Euclidean is convex. Solve by bisection for scalar `lambda`. For candidate `lambda`, set:
```
p(lmbd)=np.clip(y - lambda, 0, 1), S(p)=sum(p)
```

- ub = max(y)+1, lb = min(y)-1 maybe adjusted; in exact boundary require `S(lb) >= S_target`, `S(ub) <= S_target`. Then perform 100 binary steps finding lambda where `S(p)` crosses S_target. Choose nearest feasible lambda from small tolerance. Then repair sum mismatch:
