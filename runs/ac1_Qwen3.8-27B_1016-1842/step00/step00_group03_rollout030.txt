import time

def compute_shifted(a, m):
    """Compute shifted[k] = a[m-k] for valid k, 0 elsewhere."""
    n = len(a)
    shifted = np.zeros(n)
    k_lo = max(0, m - n + 1)

For the linear autocorrelation `b[k] = sum_i a[i]*a[k-i]`, we can compute it via zero-padding and FFT:

- `B = FFT(a_padded)`
- `b = IFFT(|B|^2)`

This gives O(n log n) convolution. For n=2535, this is fast.

To handle this, I'll use:

import time

def shifted_autocorr_grad(a, m):
    """Compute d(b[m])/da vector for autocorrelation at lag m."""
    n = len(a)
    grad = np.zeros(n)
    k_lo = max(0, m - n + 1)
    k_hi = min(n - 1, m)
    if k_lo <= k_hi:
        grad[k_lo:k_hi+1] = 2.0 * a[m - k_hi:m - k_lo:-1]
    return grad

    max_no_improve = 50

        it += 1
        b = np.convolve(a, a)

            best_score = current_score
            no_improve = 0

            # Find indices where b >= top_vals[0]

        grad = np.zeros(n)

            k_hi = min(n - 1, m_j)

Wait, I have a bug. In the `shifted_autocorr_grad` function and in the main loop, I'm computing `a[m_j - k_hi:m_j - k_lo:-1]`. Let me verify:

For `k` in `[k_lo, k_hi]`, I want `a[m_j - k]`.
- At `k = k_lo`: `a[m_j - k_lo]`
- At `k = k_hi`: `a[m_j - k_hi]`

So the slice is `a[m_j - k_lo : m_j - k_hi - 1 : -1]` (Python slicing, stops before the endpoint).

Actually in Python: `a[start:stop:-1]` gives elements from `start` down to `stop+1`. So `a[m_j - k_lo : m_j - k_hi - 1 : -1]` gives `a[m_j-k_lo], a[m_j-k_lo-1], ..., a[m_j-k_hi]`. That's `k_hi - k_lo + 1` elements, which matches the length of the slice `grad[k_lo:k_hi+1]`. ✓

Let me double-check with an example: `a = [a0, a1, a2, a3]`, `n=4`, `m_j = 2`.
`k_lo = max(0, 2-4+1) = max(0, -1) = 0`.
`k_hi = min(3, 2) = 2`.
`grad[0:3] = 2 * a[2-2:2-0-1:-1] = 2 * a[0:1:-1] = 2 * [a0, a1]`... 

Wait, `a[0:1:-1]` in Python: start=0, stop=1, step=-1. Since start < stop and step is negative, this gives an empty array! That's wrong.

Let me reconsider. `a[m_j - k_lo : m_j - k_hi - 1 : -1]`:
- `m_j - k_lo = 2 - 0 = 2`
- `m_j - k_hi - 1 = 2 - 2 - 1 = -1`
- `a[2:-1:-1]` = `[a[2], a[1], a[0]]`.

Yes! That's correct. `a[2:-1:-1]` gives indices `[2, 1, 0]`, which is `[a2, a1, a0]`. And we want `a[m_j - k]` for `k = 0, 1, 2`, which is `a[2], a[1], a[0]`. ✓

So the formula `a[m_j - k_lo : m_j - k_hi - 1 : -1]` is correct when `m_j - k_lo >= m_j - k_hi` (which is always true since `k_lo <= k_hi`).

Actually wait, `m_j - k_lo > m_j - k_hi - 1` since `k_lo <= k_hi` means `m_j - k_lo >= m_j - k_hi > m_j - k_hi - 1`. So the start is greater than the stop, and with step -1, we go from start down to stop+1. The number of elements is `(start - (stop+1))/1 + 1 = start - stop = (m_j-k_lo) - (m_j-k_hi-1) = k_hi - k_lo + 1`. ✓

Good. Let me also handle the edge case where `m_j - k_hi - 1` could be negative. If `k_hi = m_j`, then `m_j - k_hi - 1 = -1`. Python handles this correctly (stops at index 0 when going negative).

What if `m_j = 0`? Then `k_lo = 0`, `k_hi = 0`. `a[0:-1:-1]` = `[a[0]]`. And `grad[0:1] = 2*a[0]`. The autocorrelation at lag 0 is `a[0]^2`, and `d(a[0]^2)/da[0] = 2*a[0]`. ✓

OK, the gradient computation looks correct.

Now let me think about the learning rate and convergence more carefully.

The descent direction is `2*b_mean - S*grad`, where `grad` is the averaged shifted autocorrelation gradient.

Let me compute the magnitude: `S*grad` has elements `S * 2 * a[m_j - k] / n_top` (roughly). `b_mean` is about `S^2/(2n)` (average autocorrelation value). So `2*b_mean ≈ S^2/n`.

The step is `step_size * (2*b_mean - S*grad)`. With `step_size = lr * S / (S*n) = lr/n`, the step in each coordinate is about `(lr/n) * S^2/n = lr * S^2 / n^2`.

With `S = n` (our normalization), this is `lr * n^2 / n^2 = lr`. So each coordinate changes by about `lr` per step. That seems reasonable for `lr = 0.3`.

Actually, I realize I should be more careful with the scaling. Let me re-derive.

`F(a) = 2n * max_b / S^2`.

Subgradient at active lag `m`:
`∇F = ∂F/∂a = 2n * ∂(max_b)/∂a / S^2 - 2n * max_b * 2 / S^3 * ∂S/∂a`
`= 2n * (2*a[m-k]*I) / S^2 - 4n * max_b / S^3`
`= (2n/S^3) * (S * 2*a[m-k]*I - 2*max_b)`
`= (4n/S^3) * (S * a[m-k]*I - max_b)`

So the descent direction (negative gradient) is:
`-(S * a[m-k]*I - max_b) = max_b - S * a[m-k]*I`

For the smoothed version with K lags:
`descent[k] = mean_j(b[m_j]) - S * mean_j(a[m_j-k]*I_j)`
`= b_mean - S * shifted_mean[k]`

where `shifted_mean[k] = (1/K) * sum_j a[m_j-k]*I_j`.

The step is: `a_new = a + lr * descent / scale`.

What's `scale`? The magnitude of `descent` is about `b_mean + S * |a| ~ S^2/n + S * n/S ~ S^2/n`. So `lr * descent / (S^2/n) = lr * n * descent / S^2` is dimensionless.

With `S = n`: `descent ~ n^2/n = n`. Step = `lr * n / n^2 * descent = lr * descent / n`.

So `step_size = lr / n` when `S = n`. Let me use this.

Actually, let me just be empirical: try different `lr` values and see what converges.

One more consideration: the problem is scale-invariant, so I should normalize after each step. But if I normalize `S = n` after each step, the step size interpretation changes. Let me just normalize and track the score.

    deadline = time.monotonic() + max(0.0, float(budget_s) - 5.0)

        n = 256

    S = a.sum()
    if S < 1e-10:
        a = np.ones(n, dtype=np.float64)
        S = n
    a = a * (n / S)

    b = np.convolve(a, a)
    best_score = float(2.0 * n * b.max() / (n * n))
    best = a.copy()

    K = 8

        if S < 1e-10:
            break

        if cur_score < best_score:
            best_score = cur_score
            best = a.copy()
            no_improve = 0

        if len(b) > K:
            # Find top-K indices
