This is getting complicated. Let me think about what the LP approach actually does.

The LP is: given f, find g >= 0 maximizing sum(g) subject to (f*g)[k] <= M for all k.

The key insight: this is a LINEAR program in g. The constraint matrix is the Toeplitz matrix formed by f. For n=6962, this matrix is 13923 × 6962. It's too dense to store explicitly (97 million entries ≈ 776 MB).

But we can use a matrix-free approach! The matrix-vector product A@g is just a convolution: (f*g). We can compute this with FFT in O(n log n).

scipy.optimize.linprog doesn't support matrix-free, but we can use the dual or a custom implementation.

Actually, let me think about this differently. The LP:
max sum(g)
s.t. (f*g)[k] <= M for k=0,...,2n-2
g >= 0

The dual is:
min M * sum(lambda_k) + 0
s.t. sum_k lambda_k * f[k-i] >= 1 for all i (the "reduced cost" constraints)
lambda_k >= 0

Where f[k-i] means the coefficient of g[i] in constraint k, which is f[k-i] (with f[j]=0 for j outside [0,n-1]).

The dual has 2n-1 variables (lambda_k) and n constraints. We want to minimize M*sum(lambda).

This dual is much smaller! 13923 variables, 6962 constraints. And the constraint matrix is the same Toeplitz (transposed).

But it's still dense. However, we can use scipy.optimize.linprog with method='highs' and provide the constraint matrix in a structured way... but HiGHS still needs the matrix.
