1. Start with parent (or uniform)
2. At each step:

   b. Identify which elements of a contribute most to the peak

Or better: use the LP direction as described in the problem statement. The LP is:
max sum(b) s.t. b >= 0, conv(a,b) <= M

where M = max(conv(a,a)) and a is the current sequence (fixed).

The key insight: at the optimum, b is an extreme point of the polytope. The update direction is g = normalize(b). Then blend: a_new = (1-t)*a + t*g.

For solving the LP efficiently, since the constraint matrix is banded Toeplitz, we can use a specialized approach. But for now, let me try a simpler multiplicative approximation:

The LP can be approximated by iterative reweighting:
- Start with b = 1 (all ones)
- For each iteration: for each k, if conv(a,b)[k] > M, reduce b[j] for all j that contribute to row k
- This is similar to simulated annealing or the "water-filling" algorithm

Actually, a cleaner approach: the dual of the LP is:
min M * sum(y) s.t. sum_k y_k * C[k,j] >= 1 for all j, y >= 0

where C[k,j] = a[k-j] (if valid).

The KKT conditions suggest: at optimum, y_k > 0 only for binding constraints (conv(a,b)[k] = M), and b_j > 0 only for binding dual constraints.

For a practical algorithm, let me use the following:

Algorithm (LP-direction heuristic):
1. Given a (current), compute M = max(conv(a,a))
2. Initialize b = ones/n
3. Iterate (multiplicative weight):
   - Compute c = conv(a, b)
   - For each k: if c[k] > M, multiply b[j] by (M/c[k]) for all j with a[k-j] > 0
   - For each k: if c[k] < M, optionally increase b[j] slightly
   - Repeat until convergence
4. Normalize b, use as direction

This is O(n^2) per LP iteration in the worst case, but with the banded structure, each row k only touches n elements, so it's O(n^2) per LP iteration. For n=6733, that's 45M per LP iteration. Might be too slow.
