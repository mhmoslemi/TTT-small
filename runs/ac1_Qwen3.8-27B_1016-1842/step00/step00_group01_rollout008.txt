            if score_new < float(evaluate_sequence(a.tolist())):

            alpha = min(alpha * 1.01, 10.0)  # slight increase

                a = a / np.sum(a) * S_target
                no_improve = 0
                alpha = 0.5

        if iters % 500 == 0:

                best_score = exact_sc
                best = a.copy()

    if time.monotonic() < deadline - 30:

        final_sc = float(evaluate_sequence(best.tolist()))

            final_sc = cur_sc

    if result.size == 0 or np.sum(result) < 0.01:
        result = np.ones(64)
    
    return [float(x) for x in result]

Hmm wait, I'm not calling evaluate_sequence frequently enough. The problem says the evaluator clamps to [0, 1000] and takes max(0, x). Since I'm already clipping, the exact and fast scores should agree.

Let me also reconsider the gradient step. The issue is that the gradient depends on k_star (the max lag), which changes as a changes. This makes the optimization non-smooth.

A better approach: use the "top-K lags" approach. Instead of a single k_star, use the K lags with highest convolution values, and compute the gradient as the max (or weighted sum) of their individual gradients.

Actually, the subgradient of max_k C_k is the gradient of C_{k*} where k* is any argmax. So using a single argmax is correct from a subgradient perspective. The issue is just that the subgradient might not point in the "right" direction when there are near-ties.

Let me use a smoothed objective: f_smooth(a) = 2n * logsumexp(c/τ) / S^2 where τ is a small temperature. This is smooth and its gradient is a weighted average of the individual lag gradients.

But computing logsumexp of a length-2n-1 vector is O(n), and the gradient would be:
∂f_smooth/∂a_j = 2n/S^2 * sum_k exp(c_k/τ)/τ * exp(-logsumexp/τ) * ∂c_k/
