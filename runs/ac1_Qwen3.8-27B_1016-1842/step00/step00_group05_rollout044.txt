Instead of just the argmax, use a weighted sum of the top K convolution values. This gives a smoother objective.

**Even better: Use the "water-filling" perspective**

The LP approach from the LaTeX is essentially:
- Given current a, compute M = max(conv(a,a)).
- Find the direction d that maximizes sum(d) subject to (conv(a + t*d)) <= M for all lags (for small t, this is linear: (a*d + d*a)[k] <= (M - conv(a,a)[k]) for the tight lags, and (a*d+d*a)[k] <= M for non-tight lags).

For small t, the constraint is approximately: for each k, sum_i (a[i]*d[k-i] + d[i]*a[k-i]) <= M - conv(a,a)[k] (if conv[k] < M) or <= 0 (if conv[k] = M).

Actually for the tight lags (conv[k] = M), we need (a*d + d*a)[k] <= 0, i.e., the "perturbation" of the convolution at that lag must be non-positive.

This is a linear program with 2n-1 constraints and n variables. We could solve it with scipy's linprog (sparse), but it might be slow.

**Simpler approach: Proximal gradient with power iteration**

Actually, let me just go with the simple subgradient approach and tune it well. Given that n=4498 and each convolution is fast (FFT-based), we can do many iterations.

Let me estimate: np.convolve for two length-4498 arrays. NumPy uses a direct method for small arrays. Let me check: for 1D arrays, NumPy uses `np.correlate` internally or a C loop. For n=4498, the direct convolution is O(n^2) ≈ 20M operations. In compiled C, this is maybe 5-20ms.

With 1100 seconds and 10ms per eval, we can do about 50,000 evaluations. That's plenty.
