### 1. Approach and Rationale

The Erdős minimum overlap problem requires finding a step function \( h: [0,2] \to [0,1] \) with integral 1 that minimizes the maximum overlap integral \( C_5 = \max_k \int h(x)(1-h(x+k))  dx \). The current best bound is approximately 0.38085, and the goal is to find a construction that improves this to below 0.380876.

The proposed approach combines **simulated annealing** with **gradient-based optimization** and **population-based exploration** to escape local optima. Unlike gradient descent, which can get stuck in local minima, simulated annealing allows occasional uphill moves to explore the global solution space. The gradient provides targeted updates, while the annealing schedule balances exploration and exploitation.

Key innovations:
- **Hybrid optimization**: Uses gradient information for targeted updates but accepts worse solutions probabilistically to avoid local optima.
- **Adaptive cooling**: Adjusts the temperature schedule based on progress to balance exploration and convergence.
- **Population-based repair**: Maintains a population of candidate solutions with repair mechanisms to ensure feasibility.
- **Efficient gradient computation**: Computes gradients for the worst shift without recomputing the entire correlation.

The approach addresses the non-convex nature of the problem by:
- Using gradient descent for exploitation
- Using simulated annealing for exploration
- Repairing infeasible solutions
- Starting from the parent solution to leverage existing knowledge

Limitations:
- Requires careful tuning of temperature and mutation parameters
- Computationally intensive due to repeated correlation calculations
- May still find local optima if the temperature schedule is not optimal

- \( h \): Step function represented as NumPy array of length \( n_{\text{points}} \) with values in [0,1]
- \( n_{\text{points}} \): Number of grid points (default 80)
- \( dx \): Grid spacing, \( dx = 2.0 / n_{\text{points}} \)
- \( C_5 \): Objective to minimize, \( C_5 = \max_k \left( \text{np.correlate}(h, 1-h, \text{mode}="full") \times dx \right) \)

#### Objective

#### Constraints

\[

   ```python

   best_c = compute_C5(h, n_points)
   T_start = 10.0
   cooling_rate = 0.95
   ```

#### Iteration Loop
For each iteration until budget exceeded:
1. **Compute worst shift and gradient**:
   ```python
   corr = np.correlate(h, 1-h, mode="full")
   max_idx = np.argmax(corr)
   s = max_idx - (n_points-1)
   
   # Compute gradient for worst shift s
   g = np.zeros(n_points)
   for i in range(n_points):
       j_forward = i + s
       j_backward = i - s
       term1 = 0.0
       if 0 <= j_forward < n_points:
           term1 = 1 - h[j_forward]
       term2 = 0.0
       if 0 <= j_backward < n_points:
           term2 = h[j_backward]
       g[i] = term1 - term2
   ```

2. **Gradient descent step**:
   ```python
   h_candidate = h + 0.01 * g
   h_candidate = clip_and_scale(h_candidate)
   c_candidate = compute_C5(h_candidate, n_points)
   ```

3. **Random mutation**:
   ```python
   h_candidate = h + 0.01 * np.random.randn(n_points)
   h_candidate = clip_and_scale(h_candidate)
   c_candidate = compute_C5(h_candidate, n_points)
   ```

4. **Simulated annealing acceptance**:
   ```python
   T = T_start * (cooling_rate ** iteration)
   if c_candidate < best_c:
       best_c = c_candidate
       best_h = h_candidate.copy()
   elif np.random.rand() < np.exp((best_c - c_candidate) / T):
       h = h_candidate.copy()
   ```

5. **Restart mechanism**:
   ```python
   if np.random.rand() < 0.01:
       h = generate_feasible_solution(n_points)
   ```

6. **Termination check**:
   ```python
   elapsed = time.time() - start_time
   if elapsed > budget_s:
       break
   ```

#### Helper Functions
```python
def compute_C5(h, n_points):
    corr = np.correlate(h, 1-h, mode="full")
    max_corr = np.max(corr)
    return max_corr * (2.0 / n_points)

def clip_and_scale(h):
    h_clip = np.clip(h, 0, 1)
    total = np.sum(h_clip)
    return h_clip * (n_points/2) / total
```

### 4. Search Choices and Variations

#### Default Configuration
- Population size: 1 (single candidate)
- Temperature start: 10.0
- Cooling rate: 0.95
- Iterations: 10000
- Mutation probability: 0.3
- Restart probability: 0.01
- Step size: 0.01

#### Adaptive Rules
- **Temperature adaptation**: If progress stalls, increase temperature to encourage more exploration.
- **Mutation adaptation**: If stuck in local optimum, increase mutation variance.
- **Restart adaptation**: Increase restart probability if diversity drops below 0.2.

#### Variations
1. **Population-based approach**: Maintain a population of 5 candidates with crossover.
2. **Line search**: Replace fixed step size with adaptive step size based on gradient magnitude.
3. **Multi-start**: Run multiple independent processes with different initializations.
4. **Hybrid cooling**: Combine exponential cooling with linear cooling based on progress.

### 5. Compute Budget and Robustness

#### Time Estimation
- Each iteration: O(n_points^2) for correlation, O(n_points) for gradient.
- For n_points=80: ~1000 operations per iteration.
- 10000 iterations: ~10^7 operations, estimated runtime 600-800 seconds on single CPU.

#### Stopping Conditions
- Time budget exceeded (1100 seconds)
- No improvement in 1000 iterations
- Temperature below T_end (0.1)

#### Edge Cases
- **NaN/Inf**: Ensure finite values by clipping and scaling.
- **Gradient explosion**: Clip gradient to [-1,1] before update.
- **Zero sum**: Handle cases where sum becomes zero by small perturbation.

#### Fallback
```python
def get_fallback_solution(n_points):

    return generate_feasible_solution(n_points)
```
