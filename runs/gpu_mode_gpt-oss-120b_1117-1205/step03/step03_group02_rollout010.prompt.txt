```python
class TriMul(nn.Module):
    def __init__(
        self,
        dim: int,
        hidden_dim: int,
    ):
        super().__init__()

        self.norm = nn.LayerNorm(dim)

        self.left_proj = nn.Linear(dim, hidden_dim, bias=False)
        self.right_proj = nn.Linear(dim, hidden_dim, bias=False)

        self.left_gate = nn.Linear(dim, hidden_dim, bias=False)
        self.right_gate = nn.Linear(dim, hidden_dim, bias=False)
        self.out_gate = nn.Linear(dim, hidden_dim, bias=False)

        self.to_out_norm = nn.LayerNorm(hidden_dim)
        self.to_out = nn.Linear(hidden_dim, dim, bias=False)

    def forward(self, x: torch.Tensor, mask: torch.Tensor) -> torch.Tensor:
        """
        x: [bs, seq_len, seq_len, dim]
        mask: [bs, seq_len, seq_len]

        Returns:
            output: [bs, seq_len, seq_len, dim]
        """
        batch_size, seq_len, _, dim = x.shape

        x = self.norm(x)

        left = self.left_proj(x)
        right = self.right_proj(x)

        mask = mask.unsqueeze(-1)
        left = left * mask
        right = right * mask

        left_gate = self.left_gate(x).sigmoid()
        right_gate = self.right_gate(x).sigmoid()
        out_gate = self.out_gate(x).sigmoid()

        left = left * left_gate
        right = right * right_gate

        out = einsum('... i k d, ... j k d -> ... i j d', left, right)
        # This einsum is the same as the following:
        # out = torch.zeros(batch_size, seq_len, seq_len, dim, device=x.device)
        
        # # Compute using nested loops
        # for b in range(batch_size):
        #     for i in range(seq_len):
        #         for j in range(seq_len):
        #             # Compute each output element
        #             for k in range(seq_len):
        #                 out[b, i, j] += left[b, i, k, :] * right[b, j, k, :]

        out = self.to_out_norm(out)
        out = out * out_gate
```

A `@triton.jit` function is NOT a Python function. It is launched with a grid
subscript, and its `tl.constexpr` parameters exist only inside it:

```python
@triton.jit
def my_kernel(x_ptr, y_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    m = offs < n
    tl.store(y_ptr + offs, tl.load(x_ptr + offs, mask=m, other=0.0), mask=m)

def custom_kernel(data):
    ...
    BLOCK = 128                                   # a host variable YOU define
```

```python
Algorithm
---------
1. Layer‑norm the input tensor (float32 → half).
2. Linear projections to the hidden dimension for the left/right tensors.

5. Apply output LayerNorm, multiply by the output gate and a final linear

6. Return a float32 tensor.

    right_ptr,              # [total] half

        right = right * right_gate

    right_mat = right_perm.view(B * H, N, N)

    out_mat = torch.bmm(left_mat, right_mat)   # (B*H, N, N), half

    # Restore original layout: (B, N, N, H)
    out = out_mat.view(B, H, N, N).permute(0, 2, 3, 1).contiguous()
```

# Approach and Rationale

The Triangle Multiplicative Update (TriMul) operator is a core operation used in protein structure prediction models like AlphaFold3 and Chex RFC. It needs to efficiently handle large-sequence batched matrix multiplications (O(N³) operations) over a small hidden feature dimension. The main challenge is to reduce the memory footprint and optimize the performance for large sequences (up to 1024) by minimizing the number of redundant operations and leveraging tiling in Triton kernels.

The previous implementation used PyTorch's `torch.bmm` for the core contraction step, which broke the tensor into a view of size [B*hidden, N, N] and performed a batched matrix multiplication. This approach, while natural to PyTorch, suffers from inefficiency in the element-wise reduction across the hidden dimension. We will replace this with a custom Triton kernel that performs a blocked GEMM-like operation, but crucially, we will use a grouped sparse kernel that allows for more efficient processing over large sequences.

The key idea is to transpose the left and right tensors appropriately and then handle the contraction by iterating over the tiles defined by the first, last, and sequence dimensions. This way, we avoid storing intermediate arrays and optimize the use of shared memory and register space.

# Mathematical Specification

We have input tensor `x` of shape `(B, N, N, C)` and gate values (left_gate, right_gate) also of shape `(B, N, N, H)`, where H is the hidden dimension. We also have a mask tensor `(B, N, N)` if provided.

The core operation is:

$\text{out}[b,i,j,d] = \sum_{k=0}^{N-1} \text{left}[b,i,k,d] \cdot \text{right}[b,j,k,d]$

where the left and right tensors are computed as:

$\text{left}[b,i,k,d] = \text{proj}_L[b,i,k,d] \cdot \text{mask}[b,i,k] \cdot \text{left_gate}[b,i,k,d]$

$\text{right}[b,i,k,d] = \text{proj}_R[b,i,k,d] \cdot \text{mask}[b,i,k] \cdot \text{right_gate}[b,i,k,d]$

and if no mask is provided, we simply use:

$\text{left}[b,i,k,d] = \text{proj}_L[b,i,k,d] \cdot \text{left_gate}[b,i,k,d]$

$\text{right}[b,i,k,d] = \text{proj}_R[b,i,k,d] \cdot \text{right_gate}[b,i,k,d]$

where proj_L and proj_R are linear projections of the input matrix from channels `C` to `H`.

After the contraction, we apply the output gate and the final layer normalization.

# Implementation Procedure

We will implement the entire forward pass using multiple Triton kernels for efficiency:

1. **LayerNorm on Input**: Compute in host code (using float32 for computation but downcast to float16 for storage in the linear layer).

2. **Linear Projections**: Apply left_proj and right_proj to the layer-normalized input in host code, converting to float16 for the next operations.

3. **Gate Computation**: Apply left_gate, right_gate, and out_gate activation (sigmoid) operations in host code, producing float16 tensors.

4. **Mask Application**: Fuse mask application with gates in a deterministic way using element-wise operations if no mask is provided. If mask is present, apply it conditionally.

5. **Core Contraction**: Use a custom Triton kernel `tri_mul_contraction` to perform the contraction using blocked sparse matrix multiplication.

6. **Output Gate and LayerNorm**: Apply output gate (element-wise multiplication) and output layer normalization (final projection).
