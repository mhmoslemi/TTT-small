The operator, as described in the PyTorch code, works as follows:

Input:

  2. Linear projections (left_proj and right_proj) from dim C to hidden_dim (H)

Approach and rationale
The Triangle Multiplicative Update (TriMul) operator requires efficiently performing O(N^3) operations without memory bottlenecks. The previous implementation using torch.bmm was found to be suboptimal due to the kernel's overhead on large N dimensions. My approach leverages a blocked 2D semi-sparse matrix multiplication via TRMM (triangular matrix multiplication) to parallelize the computation across batches and hidden channels. The kernel is designed to handle both masked and unmasked cases simultaneously, reducing host-offloading overhead. This differs from the previous strategy's extensive use of torch.bmm by focusing on a segmented reduction approach that minimizes element-wise operations and maximizes arithmetic intensity.

Mathematical specification
We have two tensors: 
  left: [B, N, N, H] (output from linear projection)
  right: [B, N, N, H] (output from linear projection)

The core operation is:
  out[b,i,j,d] = sum_{k} left[b,i,k,d] * right[b,j,k,d]

We transform the tensor to a semi-sparse structure by grouping across batches and channels. For given (b, d), we compute out[b,i,j,d] as the dot product between two vectors (left and right). The output is then layer-normalized and gated.
