# Approach and rationale for TriMul implementation with Triton
**Core idea:**  
We implement a highly optimized Triton kernel to accelerate the TriMul operation. The key steps are:
1. **Normalizing input** with LayerNorm (implemented entirely in PyTorch for simplicity)
2. **Projecting normalized input** using multiple linear transformations (computed in float16 for speed)
3. **Applying gating operations** (sigmoid activations) to control the update direction
4. **Performing the core operation** via a custom Triton kernel that efficiently computes:
   `out[b,i,j,d] = sum_{k=0}^{N-1} left_proj[b,i,k,d] * right_proj[b,j,k,d]`
   ```python
   out = left_proj @ right_proj  # Not an actual matrix multiplication
   ```
   but specifically the dot product between fixed hidden dimension vectors. This is crucial because the standard spmm kernel cannot handle this pattern efficiently.
5. **Applying output transformation** (LayerNorm and gating) to produce final output.

**Bottleneck addressed:**  
The `out = einsum('...ikd,...jkd->...ijd', left, right)` operation is computationally heavy (O(N^3) per tensor element) in PyTorch. Our Triton kernel reduces this by casting the operation as multiple independent matrix multiplications in contiguous blocks, leveraging the fact that the contraction is separable across the hidden dimension.

**Mathematical specification:**  
Input tensor `x` of shape [B, N, N, C] undergoes normalization:

`x_normalized[b,i,j,c] = (x[b,i,j,c] - mean[b,:,:,c]) / (std[b,:,:,c] + eps)`

Then, three sets of linear transformations are applied:

- **Input linear transformations:**
  `left_proj[b,i,j,h] = Wlh^T x_normalized[b,i,j,:] + b_lh`
  `right_proj[b,i,j,h] = Wrh^T x_normalized[b,i,j,:] + breh`

- **Gating linear transformations:**
  `left_gate[b,i,j,h] = sgm(Wgh^T x_normalized[b,i,j,:] + b_gh)`
  `right_gate[b,i,j,h] = sgm(Wrh^T x_normalized[b,i,j,:] + breh)`
  `out_gate[b,i,j,h] = sgm(Woh^T x_normalized[b,i,j,:] + boh)`

The core operation combines `left_proj` and `right_proj`:

`out[b,i,j,h] = sum_{k=0}^{N-1} left_proj[b,i,k,h] * right_proj[b,j,k,h]`

This can be viewed as:

`out[b,:] = Wlh^T @ R.reshape(?, -1)`, but not applicable.
