import torch
from torch import nn, einsum
import math

# Reference code in PyTorch
class TriMul(nn.Module):
    def __init__(
        self,
        dim: int,
        hidden_dim: int,
    ):
        super().__init__()

        self.norm = nn.LayerNorm(dim)

        self.left_proj = nn.Linear(dim, hidden_dim, bias=False)
        self.right_proj = nn.Linear(dim, hidden_dim, bias=False)

        self.left_gate = nn.Linear(dim, hidden_dim, bias=False)
        self.right_gate = nn.Linear(dim, hidden_dim, bias=False)
        self.out_gate = nn.Linear(dim, hidden_dim, bias=False)

        self.to_out_norm = nn.LayerNorm(hidden_dim)
        self.to_out = nn.Linear(hidden_dim, dim, bias=False)

    def forward(self, x: torch.Tensor, mask: torch.Tensor) -> torch.Tensor:
        """
        x: [bs, seq_len, seq_len, dim]
        mask: [bs, seq_len, seq_len]

        Returns:
            output: [bs, seq_len, seq_len, dim]
        """
        batch_size, seq_len, _, dim = x.shape

        x = self.norm(x)

        left = self.left_proj(x)
        right = self.right_proj(x)

        mask = mask.unsqueeze(-1)
        left = left * mask
        right = right * mask

        left_gate = self.left_gate(x).sigmoid()
        right_gate = self.right_gate(x).sigmoid()
        out_gate = self.out_gate(x).sigmoid()

        left = left * left_gate
        right = right * right_gate

        out = einsum('... i k d, ... j k d -> ... i j d', left, right)
        # This einsum is the same as the following:
        # out = torch.zeros(batch_size, seq_len, seq_len, dim, device=x.device)
        
        # # Compute using nested loops
        # for b in range(batch_size):
        #     for i in range(seq_len):
        #         for j in range(seq_len):
        #             # Compute each output element
        #             for k in range(seq_len):
        #                 out[b, i, j] += left[b, i, k, :] * right[b, j, k, :]

        out = self.to_out_norm(out)
        out = out * out_gate
        return self.to_out(out)

## Triton launch convention

Every failure mode below has appeared in this search. Read this before writing.

A `@triton.jit` function is NOT a Python function. It is launched with a grid
subscript, and its `tl.constexpr` parameters exist only inside it:

```python
@triton.jit
def my_kernel(x_ptr, y_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    m = offs < n
    tl.store(y_ptr + offs, tl.load(x_ptr + offs, mask=m, other=0.0), mask=m)

def custom_kernel(data):
    ...
    BLOCK = 128                                   # a host variable YOU define
    grid = (triton.cdiv(n, BLOCK),)               # host-side, use triton.cdiv
    my_kernel[grid](x, y, n, BLOCK=BLOCK)         # note the [grid] subscript
```

- `my_kernel(...)` without `[grid]` raises "Cannot call @triton.jit'd outside
  the scope of a kernel".
- `BLOCK`, `BLOCK_M`, `BLOCK_N` are not defined on the host unless you define
  them there. Referencing one you only declared as a `tl.constexpr` parameter
  raises NameError.
- `tl.cdiv` is device-side. On the host use `triton.cdiv`.
- Define the kernel at module top level, never nested inside `custom_kernel`.

You do not have to move everything into Triton. A correct submission that keeps
most of the computation in PyTorch and moves one hot region into a kernel scores;
one that fails to launch scores zero.

import torch
import torch.nn.functional as F
import triton
import triton.language as tl


@triton.jit
def _gate_mask_fuse_kernel(
    left_ptr,          # half*  (flattened left tensor)
    right_ptr,         # half*  (flattened right tensor)
    left_gate_ptr,     # half*  (flattened left gate)
    right_gate_ptr,    # half*  (flattened right gate)
    mask_ptr,          # half*  (flattened mask, broadcasted over hidden dim)
    total_elements: tl.int32,
    BLOCK: tl.constexpr,
    HAS_MASK: tl.constexpr,   # 1 -> mask present, 0 -> no mask
    H: tl.constexpr,          # hidden dimension size
):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    mask = offs < total_elements

    # Load data
    left = tl.load(left_ptr + offs, mask=mask, other=0.0)
    right = tl.load(right_ptr + offs, mask=mask, other=0.0)
    left_gate = tl.load(left_gate_ptr + offs, mask=mask, other=0.0)
    right_gate = tl.load(right_gate_ptr + offs, mask=mask, other=0.0)

    if HAS_MASK:
        # Each hidden channel shares a mask entry: mask index = offset // H
        mask_idx = offs // H
        mask_val = tl.load(mask_ptr + mask_idx, mask=mask, other=0.0)
        left = left * left_gate * mask_val
        right = right * right_gate * mask_val
    else:
        left = left * left_gate
        right = right * right_gate

    # Store results back in‑place
    tl.store(left_ptr + offs, left, mask=mask)
    tl.store(right_ptr + offs, right, mask=mask)

    # --------------------------------------------------------------

        weights["left_proj.weight"].to(torch.float16),

    right = F.linear(

        bias=None,

        weights["out_gate.weight"].to(torch.float16),

        right_gate_f = right_gate.contiguous().view(-1)

    left_mat = left_perm.view(B * H, N, N)   # (B*H, N, N)
    right_mat = right_perm.view(B * H, N, N)  # (B*H, N, N)

    out_mat = torch.bmm(left_mat, right_mat.transpose(1, 2))  # (B*H, N, N)

    # Restore original layout: (B, N, N, H)
    out = out_mat.view(B, H, N, N).permute(0, 2, 3, 1).contiguous()

    # --------------------------------------------------------------
    # 6. Output LayerNorm, out‑gate scaling and final linear projection
    # --------------------------------------------------------------

        out,
        weights["to_out.weight"].to(torch.float16),
        bias=None,
    )

### Approach and Rationale

We are going to implement the "outgoing" version of the TriMul operator from AlphaFold3's paper. The goal is to optimize the core contraction operation, which is O(N³) when N is large (e.g., 1024), by using a sufficiently parallelized and blocked Triton kernel. The key observation here is that the operation 'sum_k left[b,i,k,d] * right[b,j,k,d]' can be viewed as a grouped matrix multiplication, which provides high levels of parallelism and caching efficiency.
 
We will split the problem into smaller tiles along the sequence dimension (N), and within each batch and channel context, we will compute the contraction efficiently. The LayerNorm and gate activations benefit from GPU acceleration and can be implemented with minimal overhead (convert weights to half precision). Finally, the output projection is a straightforward linear layer.

### 3. Kernel Implementation Plan

#### Key Steps in the Kernel:
1. **Permute and Reshape**: Convert the input tensors to a layout that allows grouped matrix multiplication.
2. **Reduce Dimensions**: Treat the problem as a batched matrix multiplication between matrices implicitly built from the input sequences.
3. **Blocking**: Use the sequence dimension (N) as the major blocking axis. This allows the kernel to operate on subsets of the sequence length, maximizing parallelism and coalesced memory access.
4. **Mixed Precision**: Perform the kernel computation in half precision to leverage speed and memory savings.

The kernel kernel will be structured with the following: for each batch and channel, determine the range of sequences it handles, load and compute the appropriate tensor blocks, and store the results. This minimizes memory pressure and allows Efficient reuse of cache lines.

#### Output Shape:
The output will be [batch_size, sequence_length, sequence_length, hidden_dim]. We will permute the input again to restore the original spatial dimensions.

### Detailed Solution Outline

1. **LayerNorm Operation**:
   - Apply LayerNorm to the input tensor `x` (this can stay in PyTorch).
   - Convert the normalized tensor to half precision for efficient kernel computation.

2. **Hidden-Dimensional Projection**:
   - The 4D tensor [B, N, N, C] is projected to [B, N, N, hidden_dim] using a linear layer.
   - This operation is done in half precision, but the weights for the linear layers must be provided as half tensors.

3. **Gate Activation**:
   - Compute three gates (left_gate, right_gate, out_gate) on the input's spatial dimensions.
   - These gates are converted to half precision and then activated using the sigmoid operator.

4. **Mask Application**:
   - If a mask exists, apply it to the projected tensor `left` and `right`. This means masking out specific spatial positions based on the mask's configuration.

5. **Core Contraction**:
   - Use a Triton kernel to compute the nested operations 'for each d in hidden_dim, for each i, j in [0, N-1], sum_k left[b,i,k,d] * right[b,j,k,d]'.
   - Implement this via grouped matrix multiplication, grouping by (b, d) and using the spatial sequence indices (i, j) as output axes.

6. **Finishing Operations**:
   - Apply a second LayerNorm to the result of the contraction.
   - Multiply by the out_gate and perform the final linear projection to return to the original dimension.
