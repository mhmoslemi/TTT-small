import math

# Reference code in PyTorch
class TriMul(nn.Module):
    def __init__(
        self,
        dim: int,
        hidden_dim: int,
    ):
        super().__init__()

        self.norm = nn.LayerNorm(dim)

        self.left_proj = nn.Linear(dim, hidden_dim, bias=False)
        self.right_proj = nn.Linear(dim, hidden_dim, bias=False)

        self.left_gate = nn.Linear(dim, hidden_dim, bias=False)
        self.right_gate = nn.Linear(dim, hidden_dim, bias=False)
        self.out_gate = nn.Linear(dim, hidden_dim, bias=False)

        self.to_out_norm = nn.LayerNorm(hidden_dim)
        self.to_out = nn.Linear(hidden_dim, dim, bias=False)

    def forward(self, x: torch.Tensor, mask: torch.Tensor) -> torch.Tensor:
        """
        x: [bs, seq_len, seq_len, dim]
        mask: [bs, seq_len, seq_len]

        Returns:
            output: [bs, seq_len, seq_len, dim]
        """
        batch_size, seq_len, _, dim = x.shape

        x = self.norm(x)

        left = self.left_proj(x)
        right = self.right_proj(x)

        mask = mask.unsqueeze(-1)
        left = left * mask
        right = right * mask

        left_gate = self.left_gate(x).sigmoid()
        right_gate = self.right_gate(x).sigmoid()
        out_gate = self.out_gate(x).sigmoid()

        left = left * left_gate
        right = right * right_gate

        out = einsum('... i k d, ... j k d -> ... i j d', left, right)
        # This einsum is the same as the following:
        # out = torch.zeros(batch_size, seq_len, seq_len, dim, device=x.device)
        
        # # Compute using nested loops
        # for b in range(batch_size):
        #     for i in range(seq_len):
        #         for j in range(seq_len):
        #             # Compute each output element
        #             for k in range(seq_len):
        #                 out[b, i, j] += left[b, i, k, :] * right[b, j, k, :]

        out = self.to_out_norm(out)
        out = out * out_gate
        return self.to_out(out)

## Triton launch convention

Every failure mode below has appeared in this search. Read this before writing.

A `@triton.jit` function is NOT a Python function. It is launched with a grid
subscript, and its `tl.constexpr` parameters exist only inside it:

```python
@triton.jit
def my_kernel(x_ptr, y_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    m = offs < n
    tl.store(y_ptr + offs, tl.load(x_ptr + offs, mask=m, other=0.0), mask=m)

def custom_kernel(data):
    ...
    BLOCK = 128                                   # a host variable YOU define
    grid = (triton.cdiv(n, BLOCK),)               # host-side, use triton.cdiv
    my_kernel[grid](x, y, n, BLOCK=BLOCK)         # note the [grid] subscript
```

- `my_kernel(...)` without `[grid]` raises "Cannot call @triton.jit'd outside
  the scope of a kernel".
- `BLOCK`, `BLOCK_M`, `BLOCK_N` are not defined on the host unless you define
  them there. Referencing one you only declared as a `tl.constexpr` parameter
  raises NameError.
- `tl.cdiv` is device-side. On the host use `triton.cdiv`.
- Define the kernel at module top level, never nested inside `custom_kernel`.

You do not have to move everything into Triton. A correct submission that keeps

half‑precision tensors to reduce memory traffic while accumulating in
single‑precision for numerical stability.

import torch.nn.functional as F

import triton.language as tl

# Triton kernel: batched matrix multiplication C = A @ B
#   A: (P, M, K)   (float16)
#   B: (P, K, N)   (float16)   (here B is already transposed)
#   C: (P, M, N)   (float16)   (output)

    A, B, C,
    M, N, K,
    stride_a_batch, stride_am, stride_ak,
    stride_b_batch, stride_bk, stride_bn,
    stride_c_batch, stride_cm, stride_cn,

):

    pid_m = tl.program_id(0)                # tile row
    pid_n = tl.program_id(1)                # tile column

    # tile offsets
    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    offs_n = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)

    # accumulator in fp32
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # loop over k dimension
    for k in range(0, tl.cdiv(K, BLOCK_K)):

                   + offs_k[None, :] * stride_ak

        b = tl.load(b_ptrs, mask=mask_b, other=0.0)   # fp16

        acc += tl.dot(a, b)

## Strategy from the reasoning-model planning stage

<strategy>
We are implementing the "outgoing" version of the TriMul operator from AlphaFold3. The operation involves several steps including layer normalization, linear projections, gate activations, optional masking, and a batched matrix multiplication which sums over a sequence dimension. The matrix multiplication part is the most time-consuming and will be implemented using a Triton kernel.

Approach and rationale:
The bottleneck is the matrix multiplication step which involves summing over a third sequence dimension. The naive approach would require O(N^3) operations per element, which is too slow for large N (up to 1024). We'll use a block-sparse matrix multiplication approach to reduce memory traffic and reuse. The key idea is to treat the sequence dimensions in a block-sparse manner, allowing us to perform the multiplication efficiently.

Mathematical specification:
We have an input tensor `x` of shape [B, N, N, D] (sequence length N, batch size B, hidden dimension D). The TriMul operation is defined by:
out[b, i, j, d] = sum_{k=0}^{N-1} left[b, i, k, d] * right[b, j, k, d]

Where `left` and `right` are the projected input tensors. The operation is performed for every hidden dimension d.

Implementation procedure:
1. LayerNorm: Apply LayerNorm on the input tensor using GPU operations.
2. Projection: Compute linear projections for left and right using GPU operations.
3. Masking: If provided, apply the mask (broadcasted over hidden dimensions) to left and right.
4. Gates: Compute gate activations using linear projections and then multiply left/right by the gates.
5. Matrix multiplication kernel: Implement a Triton kernel for the triangular multiplication. The kernel will be launched with a grid size that covers the entire (batch, sequence, sequence, hidden) dimension.
6. Output gate: Apply the output gate and Project back using CPU operations.

Search choices and useful variations:
- We'll use a block size (BLOCK_SIZE) that is 128. This is chosen because it provides good hardware utilization and fits well within the constraints of the given problem.
- The sequence dimension index is treated as the primary index for the loops, with each block corresponding to a segment of the sequence.

Compute budget and robustness:
The dominant operation is the matrix multiplication kernel. We'll use mixed precision (fp16 for accumulates) to improve performance. The grid launch size will be calculated based on the sequence length.

Validation and return contract:
- Input validation: Ensure dimensions match expected ranges.
- Output: Convert from mixed precision to float32.

We implement a kernel that takes two matrices `A` and `B`, each representing the input for a given (batch, hidden) pair in their respective sequence dimensions. The kernel then computes the matrix multiplication of `A` and `B` as defined by the TriMul operation.
