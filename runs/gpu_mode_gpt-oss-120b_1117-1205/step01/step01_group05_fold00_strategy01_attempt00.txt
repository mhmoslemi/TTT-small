1. **Approach and Rationale**

The core operation of TriMul involves a tensor contraction over the sequence dimension N (up to 1024) with a hidden_dim (up to 128). The naive implementation O(N^3 * hidden_dim) would be prohibitively slow. The goal is to implement this contraction using a blocked computation approach similar to matrix multiplication, reducing the per-thread launch overhead.

The key idea is to reinterpret the contraction as a sequence of matrix multiplications. For each pair `(b, d)` (batch and channel) and for each sequence index `i`, we need to compute:

```
out[b,i,j,d] = sum_{k=0}^{N-1} | left[b,i,k,d] * right[b,j,k,d] |
```

However, this is not a standard matrix multiplication problem. Notice that `left` and `right` both have the same shape `[B, N, N, hidden_dim]`, so we can view them as containing `N * N` smaller vectors (size `hidden_dim`) for each `b`.
