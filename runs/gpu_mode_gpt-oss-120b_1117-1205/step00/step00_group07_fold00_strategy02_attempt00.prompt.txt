```python
import torch
from torch import nn, einsum
import math

# Reference code in PyTorch
class TriMul(nn.Module):
    def __init__(
        self,
        dim: int,
        hidden_dim: int,
    ):
        super().__init__()

        self.norm = nn.LayerNorm(dim)

        self.left_proj = nn.Linear(dim, hidden_dim, bias=False)
        self.right_proj = nn.Linear(dim, hidden_dim, bias=False)

        self.left_gate = nn.Linear(dim, hidden_dim, bias=False)
        self.right_gate = nn.Linear(dim, hidden_dim, bias=False)
        self.out_gate = nn.Linear(dim, hidden_dim, bias=False)

        self.to_out_norm = nn.LayerNorm(hidden_dim)
        self.to_out = nn.Linear(hidden_dim, dim, bias=False)

    def forward(self, x: torch.Tensor, mask: torch.Tensor) -> torch.Tensor:
        """
        x: [bs, seq_len, seq_len, dim]
        mask: [bs, seq_len, seq_len]

        Returns:
            output: [bs, seq_len, seq_len, dim]
        """
        batch_size, seq_len, _, dim = x.shape

        x = self.norm(x)

        left = self.left_proj(x)
        right = self.right_proj(x)

        mask = mask.unsqueeze(-1)
        left = left * mask
        right = right * mask

        left_gate = self.left_gate(x).sigmoid()
        right_gate = self.right_gate(x).sigmoid()
        out_gate = self.out_gate(x).sigmoid()

        left = left * left_gate
        right = right * right_gate

        out = einsum('... i k d, ... j k d -> ... i j d', left, right)
        # This einsum is the same as the following:
        # out = torch.zeros(batch_size, seq_len, seq_len, dim, device=x.device)
        
        # # Compute using nested loops
        # for b in range(batch_size):
        #     for i in range(seq_len):
        #         for j in range(seq_len):
        #             # Compute each output element
        #             for k in range(seq_len):
        #                 out[b, i, j] += left[b, i, k, :] * right[b, j, k, :]

        out = self.to_out_norm(out)
        out = out * out_gate
        return self.to_out(out)
```

A `@triton.jit` function is NOT a Python function. It is launched with a grid
subscript, and its `tl.constexpr` parameters exist only inside it:

```python
@triton.jit
def my_kernel(x_ptr, y_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    m = offs < n
    tl.store(y_ptr + offs, tl.load(x_ptr + offs, mask=m, other=0.0), mask=m)

def custom_kernel(data):
    ...
    BLOCK = 128                                   # a host variable YOU define
    grid = (triton.cdiv(n, BLOCK),)               # host-side, use triton.cdiv
    my_kernel[grid](x, y, n, BLOCK=BLOCK)         # note the [grid] subscript
```

- `my_kernel(...)` without `[grid]` raises "Cannot call @triton.jit'd outside
  the scope of a kernel".
- `BLOCK`, `BLOCK_M`, `BLOCK_N` are not defined on the host unless you define
  them there. Referencing one you only declared as a `tl.constexpr` parameter
  raises NameError.
- `tl.cdiv` is device-side. On the host use `triton.cdiv`.
- Define the kernel at module top level, never nested inside `custom_kernel`.

# Approach and Rationale

The TriangleMultiplicativeUpdate (TriMul) operator, used in protein structure prediction models like AlphaFold, performs a constrained pairwise multiplicative update. Its complexity (O(N^3)) arises from the nested loops iterating over potentially all indices. We tackle this by:

- Using `tlcsrnf` to manage state without gradients, enabling optimizations like kernel fusion.
- Mapping parameters to tensors using `torch.compile.setup`.
- Applying a cache-oblivious tiled k loop to automatically block access patterns.
- Optimizing dot product via parallel casting to avoid prolonged L2 access.

This scalable approach adapts to various tensor feature dimensions (dim) and hidden dimensions (hidden_dim), crucial for handling large protein sequences effectively.

- **`mask`**: Mask tensor of shape [B, N, N]

We are to implement the "outgoing" version of the Triangle Multiplicative Update (TriMul) operator from AlphaFold3.
 The input tensor shape is [B, N, N, C], and there's an optional mask [B, N, N].

 Steps:
 1. Normalize the input along the feature dimension.
 2. Project the normalized input using two linear layers (left_proj, right_proj) to dimension `hidden_dim`.
 3. Compute gate activations (sigmoid) for left_gate, right_gate, and out_gate.
 4. Apply element-wise multiplication using the gate activations and the mask.
 5. Compute the contracted representation (the core operation) using Einstein summation.
 6. Apply a second normalization rule (to_out_norm) and an element-wise multiplication with the out_gate (another gate).
 7. Project back to the original dimension using to_out.

 However, note that the core operation (step 5) is the expensive part with complexity O(N^3). We will implement this core operation using a Triton kernel.

 Approach:
 - We will first normalize the input and apply the linear projections (steps 1, 2) in host PyTorch unless specified otherwise.
 - Then, we compute the gate activations (steps 3) and apply element-wise masking (step 4) using host PyTorch to avoid gradient tracking.
 - For the core contraction (step 5), we use a Triton kernel that is a modified version of the matrix multiplication example provided. We will adjust it to handle the [B, N, N, hidden_dim] shape and the necessary masking.

 Mathematical specification:
   Let `x` be the input tensor, shape [B, N, N, C].
   after normalization and projection via left_proj, we have left_proj(x): B, N, N, hidden_dim.
   Similarly for right_proj(x).

   We then let:
     left_gate: [B, N, N, hidden_dim] (activation = sigmoid)
     right_gate: [B, N, N, hidden_dim] (activation = sigmoid)

   left = left_proj(x) * left_gate * mask
   right = right_proj(x) * right_gate * mask

   Then, the einsum operation: 
     output[i, j, d] = sum_{k} (left[i, k, d] * right[j, k, d])

   We can view this as a batched matrix multiplication for each feature dimension d, where 
     matrices_left[d] is a matrix of shape [N, N] (from the selected d-th channel)
     matrices_right[d] is similarly shaped.

   Then, output = einsum of matrices formed by left and right.

   However, note the mask requirement: If there's a mask, then for some (i, j, d) entries, we might want to avoid computing if i or j is masked.

   Let's denote the core operation as a function:
     def contract(x: torch.Tensor, y: torch.Tensor, d: int, mask: Optional[torch.Tensor]):
         # x, y are not masked here, but might have masking in the main code.
         return torch.tensor([ sum_k (x[i, k, d] * y[j, k, d]) for i in range(N) for j in range(N)])

 Implementation procedure:

 We will split the operation into:
   1. Host part: normalization and projection.
   2. Host part: gates and masking (avoid gradient).
   3. Triton kernel: the contraction.

 However, note that the problem constraints: 
   dim: [128, 384, 768]
   hidden_dim: ... and the sequence length N can be up to 1024.

 We cannot compute and store an [N, N, hidden_dim] tensor fully in host if N is 1024 because that would be 1e9 * hidden_dim elements which is too large for GPUs.

 Therefore, we must implement the projections and the contraction entirely within a Triton kernel, without any host memory to store intermediate results.

 Revised plan:

   We are going to implement the entire forward pass including the LayerNorms in the same Triton kernel to avoid host memory allocation. However, mixing precision and formats must be carefully handled.

   Steps in the kernel:

   a. Define grid sizes. The grid will cover all elements in the sequence dimensions [N, N] and for each d in hidden_dim and batch.
   b. Load parameters (norm_weight, norm_bias, to_out_norm_weight, to_out_norm_bias, to_out_weight) from host.
   c. Normalize the input in the kernel for each batch and each hidden feature channel (we cannot rely on host LayerNorm for Memory efficiency).
   d. Project the normalized input using left_proj and right_proj weights in the kernel.

   But how to do linear projection in a kernel? The operation is a matrix multiplication.

   We can use the matmul_persistent_ws_kernel as a reference for how to do matrix multiplication. However, note the input is 4D and the weights are 4D (influent_dims) [hidden_dim, dim] for each linear layer?
