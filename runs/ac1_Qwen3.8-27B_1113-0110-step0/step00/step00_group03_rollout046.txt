The score function is:
```

```

where `convolve(a, a)` is the full convolution (length 2n-1).

For a uniform sequence of length n with value c, the score is always 2.0 (as derived in the strategy).

To get a score below 2, we need a sequence where the maximum autocorrelation is relatively small compared to (sum(a))^2 / n.

Key insight: For a sequence with sum S, the score is:
```
score = 2 * n * max_b / S^2
```

To minimize this, we want to minimize `max_b / S^2` or equivalently minimize `max_b / S` (since increasing S helps).

Wait, actually S is the sum of the sequence. If we scale all elements by a constant factor k, then max_b scales by k^2 and S scales by k, so max_b / S^2 is invariant to scaling. So the score is scale-invariant (as long as S >= 0.01).

So we can normalize S = 1 WLOG, and minimize max_b * n (since score = 2n * max_b when S=1).

The key mathematical insight is that we want to minimize the peak of the autocorrelation. This is similar to designing sequences with low peak autocorrelation (like Barker sequences, Zadoff-Chu sequences, etc.).

For the autocorrelation of a sequence a = (a_0, ..., a_{n-1}):
- The full autocorrelation at lag k is: sum_{i} a_i * a_{i+k} (with appropriate bounds)
- We want all these to be as small as possible relative to the energy.

This is related to the "peak-to-average power ratio" (PAPR) minimization, or equivalently, designing sequences with flat autocorrelation.

= 2n/S^2 * g[m] - 4n*max_b/S^3

def fast_convolve(a):
    """Compute linear convolution using FFT."""
    n = len(a)

        fft_size *= 2
    A = np.fft.rfft(a, fft_size)
    result = np.fft.irfft(A * A, fft_size)
    return result[:size]

**Key insight**: The problem has a specific structure. The autocorrelation b[k] = sum_i a[i]*a[i+k] is a sum of products. To minimize the maximum of all these sums, we want the "mass" of a to be distributed in a way that no single lag accumulates too much product.

This is similar to the problem of "low cross-correlation" sequences in radar/communications. Known good sequences include:
- Barker sequences (binary, optimal for certain lengths)
- Zadoff-Chu sequences (complex, perfect autocorrelation)
- m-sequences (binary, good autocorrelation properties)

For non-negative real sequences, one idea is to use the absolute value (or some transform) of these sequences, scaled to be non-negative.

Another idea: use a "mutilook" approach where we simultaneously try to flatten multiple lags.

Let me also consider the following: the score function is 2n*max_b/S^2. If I can make max_b = c * S^2 / n for some c < 2, then score = 2c < 4. Wait, that's not right.

If max_b = c * S^2 / (2n), then score = 2n * c * S^2/(2n) / S^2 = c. So if max_b = S^2/(2n), score = 1 (the theoretical minimum).

For a uniform sequence: max_b = n * (S/n)^2 = S^2/n. Score = 2n * S^2/n / S^2 = 2. ✓

So we need max_b < S^2/n to get score < 2. The uniform sequence has max_b = S^2/n (achieved at lag 0 and lag 2n-2 for the edges, and at lag n-1 for the center).

Wait, for uniform: max_b is at lag n-1 (the center), where b[n-1] = n*(S/n)^2 = S^2/n. And b[0] = (S/n)^2 which is much smaller.

So the "bottleneck" lag for a uniform sequence is the center (lag n-1). To reduce the score, we need to reduce b[n-1] = sum_i a[i]*a[n-1-i].

One way: make a[i] and a[n-1-i] "disagree". Since both are non-negative, we can make a[i] large where a[n-1-i] is small, and vice versa.

For example, if we make the sequence "anti-symmetric" (a[i] large for i < n/2, a[i] small for i >= n/2), then b[n-1] = sum_i a[i]*a[n-1-i] would be small (since the large values are paired with small values).

But this increases b[k] for small k (within the "large" block), which might increase the max.

This is the fundamental trade-off: you can't reduce one lag without potentially increasing others.

The optimal solution balances all lags. For non-negative sequences, this is a hard problem.

Let me try a different approach: **coordinate descent on the sequence elements**.

For each element a[i], I can compute the "marginal" effect of changing a[i] on the score. If I increase a[i] by dt, how does each b[k] change?

db[k]/da[i] = 2*a[k-i] (if 0 <= k-i <= n-1) + 2*a[i-k] (if 0 <= i-k <= n-1)

Wait, that's the same as before: db[k]/da[i] = 2*a[k-i] if k-i in [0,n-1], else 0. (The formula already accounts for both terms since the convolution is symmetric.)

Actually, I derived earlier that db[k]/da[m] = 2*a[k-m] if 0 <= k-m <= n-1, else 0. This is correct.

So changing a[i] by dt changes b[k] by 2*dt*a[k-i] for each k.

The score change is: d(score) = 2n/S^2 * sum_{k: b[k]=max} 2*a[k-i]*dt - 4n*max_b/S^3 * dt

(Using the subgradient at the argmax lags.)

For coordinate descent, at each step I pick the element i that gives the most negative d(score)/da[i], and adjust it.

d(score)/da[i] = 2n/S^2 * 2*a[k*-i] - 4n*max_b/S^3 (for k* in argmax)
= 4n/S^2 * (a[k*-i] - max_b/S)

So the "best" element to increase is the one where a[k*-i] is smallest (most negative gradient), and the best to decrease is where a[k*-i] is largest.

This gives a greedy algorithm:
1. Find k* = argmax(b).
2. Find i where a[k*-i] is smallest (preferably 0): increase a[i].
3. Find i' where a[k*-i'] is largest: decrease a[i'].
4. Transfer mass from i' to i (or just adjust).

Minimizes the score 2n*max(convolve(a,a))/sum(a)^2 using a combination of
FFT-based subgradient descent, greedy mass transfer, and random restarts.

import numpy as np
import time


def fast_self_convolve(a):
    """Compute linear self-convolution of a using FFT."""
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    A = np.fft.rfft(a, fft_size)
    result = np.fft.irfft(A * A, fft_size)
    return result[:size]

    Subgradient + greedy transfer optimization for peak autocorrelation minimization.
    Uses FFT for fast convolution, top-K lag weighting, momentum, and random restarts.

        parent = np.ones(1024, dtype=np.float64)

    n = len(parent)
    best = parent.copy()
    best_score = float(evaluate_sequence(best.tolist()))
    print(f"Initial: n={n}, score={best_score:.8f}")

        """Run subgradient descent phase."""
        nf = len(y)
        s = y.sum()
        if s < 1e-15:
            y = np.ones(nf) / nf
        else:
            y = y / s
        y = y.copy()
        momentum = np.zeros(nf)
        
        for it in range(num_iters):
            if time.monotonic() > deadline:
                break
            
            b = fast_self_convolve(y)

                top_idx = np.arange(len(b))
                top_vals = b
            else:
                top_idx = np.argpartition(b, -K)[-K:]
                top_vals = b[top_idx]

            shifted = top_vals - top_vals.max()
            w = np.exp(shifted / T)
            w_sum = w.sum()
            if w_sum < 1e-30:
                w = np.ones(len(top_vals)) / len(top_vals)
            else:
                w = w / w_sum

            h = np.zeros(nf)
            for idx in range(len(top_idx)):

                wv = w[idx]
                if wv < 1e-10:
                    continue

                hi = min(k, nf - 1)
                if lo <= hi:
                    h[lo:hi+1] += wv * y[k-lo::-1][:hi-lo+1]

            target = float(np.dot(w, top_vals))

            momentum = mu * momentum + (1.0 - mu) * grad

            y = np.maximum(y, 0.0)

            s = y.sum()
