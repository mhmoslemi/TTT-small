    return float(np.max(np.correlate(h, 1.0 - h, mode='full')) * (2.0 / n))

    for _ in range(50):

        np.clip(x, 0.0, 1.0, out=x)
        if abs(x.sum() - S) < 1e-12:

        for i in order:

            a = min(abs(d), abs(1.0 - x[i]) if d > 0 else x[i])
            x[i] += a * (1 if d > 0 else -1)

            if abs(d) < 1e-13: break
            a = min(abs(d), 1.0 - h[i] if d > 0 else h[i])
            h[i] += a * (1 if d > 0 else -1)

    dx = 2.0/n

    bc = cur
    bh = h.copy()
    t0 = time.time()

Actually, reversing a segment of a binary array DOES change it. For example, [0,0,1,1] reversed is [1,1,0,0]. So it's a valid move. But it might not be as useful as swapping two segments.

Let me think of better moves:
1. **Swap two 1s with two 0s**: Pick positions i,j (both 1) and p,q (both 0), set h[i]=h[j]=0, h[p]=h[q]=1
2. **Move a block**: Take a contiguous block of 1s and move it elsewhere (replacing 0s)
3. **Complement a segment**: Flip all bits in a segment (but this changes the count!)

For move 1 (2-for-2 swap), the effect on correlation at lag k is:
ΔC_k = h[i+k]+h[i-k]+h[j+k]+h[j-k] - h[p+k]+h[p-k]+h[q+k]+h[q-k]... 

Wait, it's: removing 1s at i,j and adding 1s at p,q:
ΔC_k = (h[i+k]+h[i-k]) + (h[j+k]+h[j-k]) - (h[p+k]+h[p-k]) - (h[q+k]+h[q-k])

This is still O(1) per lag. But finding the best (i,j,p,q) combination is harder.

Let me stick with single swaps (which are fast) and add a few block reversal moves for diversity.
