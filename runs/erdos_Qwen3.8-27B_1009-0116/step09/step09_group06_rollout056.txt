**Idea: Use the structure of the problem more**

The objective C_k = dx * ∑ h[i]*(1-h[i+k]) can be written as:
C_k = dx * (∑_{valid i} h[i] - ∑_{valid i} h[i]*h[i+k])

The second term is like a cross-correlation. If h is "binary-like" (close to 0 or 1), then h[i]*h[i+k] ≈ 1 only when both are 1. So C_k ≈ dx * (number of 1s in valid range - number of overlapping 1 pairs).

For a truly binary h, this is a combinatorial problem. The continuous relaxation might be close to binary.

**Idea: Exploit the fact that the optimal h might have a specific structure**

For the autocorrelation problem, the optimal binary sequence tends to be "balanced" - roughly half 0s and half 1s, with a specific pattern. The m-sequences and Barker sequences minimize peak sidelobe.

But our problem is different: we minimize the MAX over all lags of ∑ h[i](1-h[i+k]). This is NOT the same as minimizing peak sidelobe. It's minimizing the maximum "disagreement" between h and its shifts.

If h is binary: C_k = (number of positions where h=1 and h[k]=0) * dx = (num_1s - num_11_pairs_at_lag_k) * dx

To minimize the max: we want the minimum over k of (num_1s - num_11_pairs_at_lag_k) to be as small as possible... wait, we want to MINIMIZE the max. So we want ALL lags to have small disagreement.

For binary h with n/2 ones: C_k = (n/2 - A_k) * dx where A_k is the autocorrelation at lag k.
To minimize max C_k, we want to MAXIMIZE min A_k.

This is related to the "minimum autocorrelation" problem! The best sequences for this are related to Legendre sequences, m-sequences, etc.

But we're in continuous [0,1], not binary. The continuous relaxation might allow better values.

Let me try a different approach: instead of gradient-based optimization, use an **iterative water-filling** approach:

1. Initialize h
2. Find the lag k* that maximizes C_k
3. Try to reduce C_{k*} specifically by adjusting h
4. Repeat

This is a "coordinate descent on lags" rather than on coordinates.

For a fixed lag k*, C_{k*} = dx * ∑_{i} h[i]*(1-h[i+k*]) (over valid i).
To reduce this, we want to make h[i] and h[i+k*] more similar. We can do this by:
- Where h[i] > h[i+k*]: decrease h[i] or increase h[i+k*]
- Where h[i] < h[i+k*]: increase h[i] or decrease h[i+k*]

This is a "diffusion" along the lag-k* direction.

**Algorithm: Multi-lag diffusion**

1. Compute all C_k, find top m lags
2. For each top lag k*, apply a "smoothing" step: h[i] += ε*(h[i+k*] - h[i]) (and h[i+k*] += ε*(h[i] - h[i+k*]))
   This reduces disagreement at lag k*
3. Project to feasible set
4. Repeat, cycling through lags

This is like a Gauss-Seidel / Jacobi method for the min-max problem!

def _repair(h, n):

    target = n * 0.5
    s = h.sum()

        return np.full(n, 0.5)
    for _ in range(300):
        h *= target / s
        h = np.clip(h, 0.0, 1.0)
        s = h.sum()
        if abs(s - target) < 1e-14:
            break
    diff = target - h.sum()
    if abs(diff) > 1e-14:
        order = np.argsort(1.0 - h) if diff > 0 else np.argsort(h)
        for idx in order:
            if abs(diff) < 1e-14:
                break
            if diff > 0:
                a = min(diff, 1.0 - h[idx])
                h[idx] += a
                diff -= a
            else:
                a = min(-diff, h[idx])
                h[idx] -= a
                diff += a
    return h

            lo = mid
        else:
            hi = mid

            g[L:] -= h[:n - L]
        else:
            M = -L

    c5c = _eval(h2)
    while time.time() - t0 < budget_s - 2:
        i = rng.randint(n)
        j = (i + 1 + rng.randint(0, 6)) % n
        d = 5e-6 * rng.randn()
        ni, nj = h2[i] + d, h2[j] - d
        if 0 <= ni <= 1 and 0 <= nj <= 1:
            h2[i], h2[j] = ni, nj
            c5n = _eval(h2)
            if c5n < c5c:
                c5c = c5n
                if c5n < best_c5:
                    best_c5 = c5n
                    best_h = h2.copy()
            else:
                h2[i], h2[j] = ni - d, nj + d

    best_h = _repair(best_h, n)
    best_c5 = _eval(best_h)
    return (best_h, best_c5, n)
