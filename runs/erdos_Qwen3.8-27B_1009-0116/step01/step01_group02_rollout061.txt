Key question: Is the bottleneck the quality of the local optimization, or are we stuck in a bad local optimum?

Given that the previous code used SLSQP with various perturbations and still got stuck at 0.380973, I suspect we might be in a local optimum. The active set (which correlations are at the max) might form a degenerate configuration.

To escape:
1. Try very different initializations
2. Use global optimization (DE, basin hopping)
3. Try different n values
4. Use a different parameterization

Let me also think about the problem structure. With n=70, we have 69 degrees of freedom (one constraint: sum = 35). The objective is the max of 139 correlation values. At a local optimum, typically 69 or more of these are "active" (at the max). If exactly 69 are active, the solution is determined (it's a system of 69 equations in 69 unknowns). If more are active, the solution might not be unique.

The key to improvement might be to find a different "active set configuration" - a different set of lags that are simultaneously at the maximum.

Let me try a different approach: **simulated annealing on the h vector**.

At each step:
1. Generate a perturbation: pick 2-5 random coordinates and add Gaussian noise
2. Repair to feasible set
3. Accept if C5 decreases, or accept with probability exp(-ΔC5 / T) if T > 0
4. Cool T over time

This is simple and effective for escaping local optima.

    h = np.array(h, dtype=float).copy()

    s = np.sum(h)
    if s < 1e-15:

        # Random
        cands.append(repair(rng.random(n_try), n_try))

        h = np.where(np.arange(n_try) % 2 == 0, 0.8, 0.2) + rng.normal(0, 0.1, n_try)
        cands.append(repair(h, n_try))

            c_pol = compute_c5(h_pol, n_c)

        except Exception:
            pass

    best_c5 = compute_c5(best_h, n)
    return (best_h, best_c5, n)
