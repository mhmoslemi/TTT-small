def _repair(h, n):
    h = np.clip(h, 0.0, 1.0).copy()
    target = n / 2.0
    for _ in range(10):
        s = h.sum()
        if abs(s - target) < 1e-12:
            break
        diff = target - s
        if diff > 0:
            cap = 1.0 - h
            tot = cap.sum()
            if tot < 1e-15:

        else:
            floor = h.copy()
            tot = floor.sum()
            if tot < 1e-15:

                diff -= a
            else:

                h[idx] -= a
                diff += a

                h[idx] += a; diff -= a
            else:

    s -= s.max()

The objective is: f(t) = max_k (A[k] + B[k]*t) + μ*(t-h[i])²

For large μ, this is close to t = h[i] (no change), which defeats the purpose. I need to balance: use a moderate μ that allows t to deviate but not too much.

Actually, a better approach: instead of a penalty, I can find the range of t that keeps the sum constraint satisfiable:
- After changing h[i] to t, I need to distribute the remaining sum = n/2 - t among the other n-1 elements.
- This is possible iff 0 ≤ n/2 - t ≤ n-1, i.e., n/2 - (n-1) ≤ t ≤ n/2.
- Since each element is in [0,1], we also need 0 ≤ t ≤ 1.
- So t ∈ [max(0, n/2-(n-1)), min(1, n/2)] = [0, min(1, n/2)]

For n=560: t ∈ [0, 1]. So the constraint doesn't really restrict t beyond [0,1].

After finding the optimal t, I update h[i] = t, and then I need to fix the sum. The sum was n/2, now it's n/2 + (t - h[i]). I need to redistribute -(t-h[i]) among the other elements.
