So we're finding g_0 (length n) that maximizes sum(g_0) subject to:
- g_0 >= 0
- For all k in [0, 2n-2]: sum_{i: valid} f[i] * g_0[k-i] <= M

where M = ||f*f||_inf (the current max autocorrelation).

This is a linear program with n variables and 2n-1 + n = 3n-1 constraints. The constraint matrix is sparse (Toeplitz-like).

After finding g_0, we rescale to have the same normalization as f, then take a convex combination.

This is essentially a projected gradient / dual ascent step. The LP finds the best direction to move in.

However, solving an LP with 2535 variables and ~7600 constraints might take a while. With scipy's linprog (HiGHS solver), it should be fast for this size. Let me estimate: for a problem of this size, HiGHS should solve it in well under a second.

1. Start with parent sequence, normalize
2. Compute M = max(conv(f,f))
3. Solve LP to get g_0
4. Rescale g_0 to match normalization
5. Update: f = (1-t)*f + t*g_0
6. Repeat

With a decreasing step size t.

But wait, the LP constraint is ||f*g_0||_inf <= M. After we update f, M changes, so we need to recompute M and solve the LP again.

Actually, this is similar to the "alternating" approach in optimization. Let me think about whether this converges.

The key property: the LP finds the g that maximizes sum(g) subject to the autocorrelation constraint. After rescaling to the same normalization, the new sequence g has the same L1 norm as f but potentially lower max autocorrelation (since it was optimized to have low autocorrelation relative to the "budget" M).

The convex combination (1-t)f + tg should have max autocorrelation <= M (by convexity of the max of a convex function... wait, max of a linear function is convex, so max_convolutions((1-t)f+tg) <= (1-t)*max_conv(f) + t*max_conv(g) <= (1-t)*M + t*M = M). So the max autocorrelation doesn't increase!

Wait, that's not quite right. max(conv(a,a)) is not a convex function of a (it's the max of quadratic functions). Let me reconsider.

conv((1-t)f + t*g, (1-t)f + t*g)[k] = (1-t)^2 conv(f,f)[k] + t(1-t)(conv(f,g)[k] + conv(g,f)[k]) + t^2 conv(g,g)[k]

This is not simply bounded by M. The cross terms complicate things.

However, the LP ensures conv(f,g)[k] <= M for all k. And conv(g,g) might have a different max. So the simple monotonicity argument doesn't directly apply.

def _fft_conv(x, y):
    m = len(x) + len(y) - 1
    sz = 1
    while sz < m:
        sz <<= 1
    fx = np.fft.rfft(x, sz)
    fy = np.fft.rfft(y, sz)
    return np.fft.irfft(fx * fy, sz)[:m]

    z = x / tau
    z -= z.max()
    e = np.exp(z)
    s = e.sum()
    if s < 1e-300:
        return np.full(len(x), 1.0 / len(x))
    return e / s

    n = len(a)

    max_b = conv.max()

    if sa < 0.01:
        return np.inf
    return 2.0 * n * max_b / (sa * sa)

    """Build the sparse constraint matrix for the LP.
    Returns A_ub (2n-1 x n) sparse, b_ub = M * ones(2n-1).
    Row k: conv(f, g)[k] = sum_i f[i]*g[k-i] (valid i)

    n = len(f)
    rows = []
    cols = []
    vals = []

            rows.append(k)
            cols.append(k - i)
            vals.append(f[i])
    A = csr_matrix((vals, (rows, cols)), shape=(2*n-1, n))
    return A
