Actually, I realize there might be a smarter approach. Let me think about the problem as a convex optimization:

Minimize `max_k b(k)` subject to `sum a = c`, `a >= 0`.

This is a convex problem! (convex objective, convex constraints). We can solve it with:
- Subgradient methods
- Interior point methods (via CVXPY)
- Custom projected gradient

The subgradient of `max_k b(k)` at `a` is `convex hull of {∇b(k) : k ∈ argmax b}`.

For the projected gradient:
1. Compute b = conv(a, a).
2. Find active set K = {k : b(k) ≈ max b}.
3. Gradient: g = (1/|K|) * sum_{k in K} ∇b(k) (average of active gradients).
4. Update: a = a - lr * g, then project onto {sum a = c, a >= 0}.

The projection onto {sum a = c, a >= 0} is the Euclidean projection, which can be done in O(n log n) using the "water-filling" algorithm.

But we also need to handle the normalization. Since the objective is scale-invariant, we can fix sum a = 1 (or any constant) and minimize max b(k).

Let me think about the step size. The objective `max_k b(k)` has Lipschitz constant related to the matrix norm of the "autocorrelation operator". For a uniform step, we'd need `lr < 2/L` where L is the Lipschitz constant.

The Hessian of b(k) (for a fixed k) is `4 * S_k^T * S_k` (where S_k is the shift-reverse operator). The eigenvalues of S_k^T * S_k are bounded by n (roughly). So L ≈ 4n per active k. With |K| active constraints, the overall Lipschitz constant is ≈ 4n * |K| (roughly).

For n = 7000 and |K| = 32: L ≈ 4 * 7000 * 32 ≈ 900K. So lr < 2/900000 ≈ 2.2e-6. Very small step!

This means projected gradient would be extremely slow. We need a better method.
