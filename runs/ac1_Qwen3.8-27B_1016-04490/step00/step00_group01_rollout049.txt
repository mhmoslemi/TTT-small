**Iterative reweighting / multiplicative update:**

The idea: if the convolution peak is at lag k*, we want to reduce contributions at that lag. The gradient of (f*f)[k*] w.r.t. f[i] is f[k*-i] (for valid indices). So to reduce the peak, we should decrease f[i] where f[k*-i] is large.

A multiplicative update: f[i] *= exp(-eta * (f * 1_{active_lags})[i] / sum(f))

Or more simply: identify the top few lags (those where (f*f)[k] is close to max), compute the "pressure" on each coordinate, and adjust.

1. Initialize f (parent or something better).
2. For each iteration:

The "A_weighted" computation: for each k, A[k,j] = 1 if k-n+1 <= j <= k (clamped to [0, n-1]). So A_weighted[j] = sum_k weights[k] * 1[max(0,k-n+1) <= j <= min(n-1, k)].

This can be computed as a "cumulative sum" operation:
For a fixed j, A_weighted[j] = sum_{k: max(0,n-1) >= j >= max(0,k-n+1) and j <= k} weights[k]
= sum_{k: k >= j and k <= j+n-1} weights[k] (clamped to [0, 2n-2])
= sum of weights[k] for k in [j, min(2n-2, j+n-1)]

This is a sliding window sum! It can be computed in O(n) with a prefix sum.

So the algorithm is:
1. Compute conv (O(n log n) via FFT)
2. Compute weights = some function of conv (e.g., softmax, or top-K uniform)
3. Compute A_weighted via prefix sum (O(n))
4. Update f: f = max(0, f - eta * A_weighted); f /= sum(f)
5. Check score

This is O(n log n) per iteration (dominated by the FFT), and each iteration is very fast for n=6121.
