Suppose a is a linear ramp, increasing from left to right. The max of a*a is slightly to the right of center (as I computed for n=10, max was at k=13 out of 0..18). The values contributing to the max are large*a_largish.

To reduce the max, we should reduce the largest values (right end) or increase the smallest values (left end) to balance things out.

It's a tradeoff. The optimal solution balances all the convolution values.

**Let me implement a practical approach:**

1. Try several parameterized families of sequences.
2. For the best one, do a gradient-based refinement.
3. Use FFT for convolution (O(n log n) per iteration).
4. Keep track of the best score found.

For the gradient-based refinement, I'll use a projected gradient method:
- Compute the subgradient of the objective.
- Take a step in the negative gradient direction.
- Project back to the feasible set (a >= 0, sum(a) = target).

The objective is F(a) = 2n * max(a*a) / (sum a)^2.

Let me normalize so that sum(a) = sqrt(2n) (as in the problem description). Then:
F(a) = max(a*a) / n (since 2n * max_b / (2n) = max_b).

Wait: if sum_a = sqrt(2n), then sum_a^2 = 2n. So F = 2n * max_b / 2n = max_b.

So minimizing F is the same as minimizing max(a*a) with the constraint sum(a) = sqrt(2n) and a >= 0.

The subgradient of max(a*a) at k* is: for each m, sg[m] = 2*a[k*-m] (if 0<=k*-m<n) [approximately, ignoring the middle-term correction].

For the projected gradient:
a_new = a - lr * sg
a_new = max(a_new, 0)
a_new = a_new * (sqrt(2n) / sum(a_new))  [re-normalize]

def convolve_fft(a):
    """Compute np.convolve(a,a) using FFT for O(n log n) speed."""
    n = len(a)
    size = 1
    while size < 2*n - 1:
        size *= 2
    fa = np.fft.rfft(a, size)
    return np.fft.irfft(fa * fa)[:2*n-1]

def score_of(a):
    """Compute the score 2*n*max_b/sum_a^2."""

    if sa < 0.01:

    b = convolve_fft(a)
