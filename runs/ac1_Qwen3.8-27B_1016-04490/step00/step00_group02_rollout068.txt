Let me also think about what the optimal sequence looks like. For the problem min max(b) s.t. sum(a)=1, a>=0, the optimal solution should have b as flat as possible. By the Karush-Kuhn-Tucker conditions, at the optimum:
- All a[i] >= 0, with complementary slackness
- The "active" b[k] values (the ones equal to max) determine the gradient
- The gradient of max(b) (weighted average of active b gradients) should be proportional to 1 (the constraint gradient)

This means: sum_{k in argmax} ∇b[k] = λ * 1 (vector of ones)
For a given k: ∇b[k][j] = 2*a[k-j]*I(0<=k-j<n)
So: sum_{k in argmax} 2*a[k-j]*I(0<=k-j<n) = λ for all j

This is a system of equations that determines the optimal a. It's complex but suggests that the optimal a has a specific structure.

One more thought: the "LP approach" from the state-of-the-art is actually more principled. At each step:
1. Fix a, compute M = max(b).
2. Solve: max sum(b') s.t. conv(a, b') <= M, b' >= 0.
3. Update: a_new = (1-t)*a + t*b'/sum(b').

Step 2 is the key. The constraint conv(a, b') <= M is a system of 2n-1 linear inequalities in n variables. The matrix is the banded Toeplitz matrix T.

I can solve this LP using scipy.optimize.linprog with method='highs' and a sparse matrix. But building the sparse matrix takes O(n^2) memory.

Alternatively, I can use projected gradient for the LP:
b'_{new} = max(0, b' - α * max(0, T*b' - M))

where T*b' = conv(a, b') is computed via np.convolve (O(n log n) or O(n^2)).

This is a simple iteration that should converge to the LP optimum. Let me implement this.

Actually, for the projected gradient to work well, I need a good step size. The Lipschitz constant of the projection is related to the largest eigenvalue of T^T T. For the Toeplitz matrix T, this is related to the maximum of |A(f)|^2 where A is the DFT of a. For a uniform a, this is O(n^2). So the step size should be O(1/n^2), which means O(n^2) iterations for convergence. That's too slow.

Alternative: use the dual of the LP.
Dual: min M * sum(y) s.t. T^T y >= 1, y >= 0.
