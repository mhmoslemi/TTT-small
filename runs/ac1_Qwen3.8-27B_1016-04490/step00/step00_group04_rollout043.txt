a_i = (λ - δ_{2i,k*}a_i) / a_{k-i}

This is implicit. But I can iterate: given current a, compute the gradient of C_{k*} - λ(sum-1), do a projected gradient step.

Actually, let me just do a simpler approach:
1. Normalize a to sum=1
2. Find k* = argmax of conv(a,a)
3. Compute gradient g_i = ∂C_{k*}/∂a_i (with the constraint handled by subtracting the mean)
4. Update a_i = max(0, a_i - step * (g_i - mean(g)))
5. Renormalize
6. Repeat

The gradient computation is O(n) for a single k*. The convolution to find k* is O(n²) but can be done with FFT in O(n log n) or just with np.convolve (which uses direct method for small arrays and FFT for large).

For n=3809, np.convolve is fast. Let me estimate: each convolution is ~14.5M multiply-adds, which is < 1ms in numpy. So I can do thousands of iterations.

But wait, the max might jump between different k values. After reducing C_{k*}, a new k might become the max. I need to handle that.

Simple strategy:
- Each iteration: compute full conv, find max, compute gradient for that max lag, step.
- This is O(n²) per iteration (for the convolution), but with numpy it's fast.

Let me code this up.

Actually, for n=3809, the convolution has 7617 elements. Computing it with np.convolve is O(n²) ≈ 14.5M ops. In numpy, this should take about 1-5ms. So in 1100 seconds, I can do about 200,000-1,000,000 iterations. That's plenty.

import numpy as np
import time

def compute_score(a):
    """Compute the objective for a nonnegative array a."""
    n = len(a)
    sa = a.sum()
    if sa < 0.01:
        return np.inf
    conv = np.convolve(a, a)
    max_b = conv.max()
    return 2.0 * n * max_b / (sa * sa)

    for j in range(n):
        kj = k - j
        if 0 <= kj < n:
            g[j] += a[kj]
            if j != kj:
