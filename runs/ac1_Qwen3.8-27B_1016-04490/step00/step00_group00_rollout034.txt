```python
from scipy.sparse import csc_matrix
from scipy.optimize import linprog

def solve_lp(a, M):
    n = len(a)
    # Build constraint matrix: (a * x)[k] <= M for k=0..2n-2
    # (a * x)[k] = sum_j a[max(0,k-n+1)..min(k,n-1)] * x[j] shifted
    
    # Row k has nonzeros at columns j where 0 <= k-j < n, i.e., max(0, k-n+1) <= j <= min(k, n-1)
    # Value at row k, col j is a[k-j]
    
    rows = []
    cols = []
    vals = []
    
    for k in range(2*n - 1):
        j_lo = max(0, k - n + 1)
        j_hi = min(k, n - 1)
        for j in range(j_lo, j_hi + 1):
            rows.append(k)
            cols.append(j)
            vals.append(a[k - j])
    
    A_ub = csc_matrix((vals, (rows, cols)), shape=(2*n-1, n))
    
    # Maximize sum(x) s.t. A_ub @ x <= M, x >= 0
    c = -np.ones(n)  # minimize -sum(x)
    
    res = linprog(c, A_ub=A_ub, b_ub=np.full(2*n-1, M), 
                  bounds=[(0, None)]*n, method='hihps')
    
    return res.x if res.success else None
```

6. Redistribute the removed mass to positions with low responsibility
7. Repeat

```python
def project_simplex(v, S):
    """Project v onto {x >= 0, sum(x) = S}."""
    # Find tau such that sum(max(0, v - tau)) = S
    # Sort v in descending order
    sv = np.sort(v)[::-1]
    # Find the right number of non-zero components
    cumulative = np.cumsum(sv)
    # The optimal tau satisfies: sum_{i: sv[i] > tau} (sv[i] - tau) = S
    # n_active * sv values > tau, sum = S
    # tau = (sum_active - S) / n_active
    n = len(sv)
    idx = np.arange(1, n + 1)
    tau_candidates = (cumulative - S) / idx
    # Find where sv[idx] > tau_candidates[idx] (approximately)

            lo = mid
```

Actually, the standard algorithm for Euclidean projection onto the simplex {x >= 0, sum(x) = S} is:
1. Sort x in descending order: x_(1) >= x_(2) >= ... >= x_(n)
2. Find the largest rho such that sum_{i=1}^{rho} (x_(i) - S/rho) > 0, i.e., sum_{i=1}^{rho} x_(i) > S
3. tau = (sum_{i=1}^{rho} x_(i) - S) / rho
4. x_proj[i] = max(0, x[i] - tau)

This is O(n log n) per projection due to the sort.

The constant sequence is the unique point where a[j] = a[(n-1)-j] for all j (symmetric) AND a is constant. At this point, all lags of the convolution achieve the same max value... wait, no. For the constant sequence, c[k] is triangular: peaks at the center. Only the center lag achieves the max.

So the active set is {n-1} (the center lag). The subgradient points in the direction of ∇c[n-1], which for a constant sequence is proportional to a (by symmetry). So the gradient of the objective points in the "a" direction, which is the direction of increasing the sum (but we're on a fixed-sum manifold). The projected gradient is... let me think.

If a is constant: a[j] = c for all j. Then ∇c[n-1][j] = 2*a[n-1-j] = 2c. So the gradient is constant: ∇c[n-1] = 2c * ones(n).

The projected gradient step: a_new = a - step * 2c * ones(n). After projection onto the simplex, this is the same as subtracting a constant from all entries and then projecting. Since all entries are equal, subtracting a constant keeps them equal (or makes some zero). The projection would keep them equal. So the step doesn't change the direction relative to the constant.

This means the constant sequence IS a fixed point of the algorithm! We need perturbations to escape.

This is a critical insight. The algorithm will get stuck at the constant sequence (or any point where the gradient is "symmetric" in a way that the projection doesn't change things).

Solution: Use the full softmax over all lags (not just the max). This gives a non-symmetric gradient even at the constant sequence, because the convolution is triangular (not flat), so the softmax weights give different values to different lags.

Wait, for the constant sequence, c[k] is triangular. The softmax weights w[k] = exp(beta * c[k] / max_c) / Z. The lags near the center get weight ~1, lags near the edges get weight ~exp(-beta). So the gradient is:

grad[j] = 2 * sum_k w[k] * a[k-j] (valid)

For a constant sequence a[k-j] = c, so grad[j] = 2c * sum_{k: 0<=k-j<n} w[k] = 2c * (sum of w over the valid range of k for each j).

For j near the center: the valid range of k is large (almost all k), so grad[j] ≈ 2c * sum(w) = 2c.
For j near the edges: the valid range is smaller, so grad[j] < 2c.

So the gradient is LARGER in the middle and SMALLER at the edges! This means the step will REDUCE the middle and INCREASE the edges (relative to the mean, after projection). This breaks the symmetry and moves away from the constant sequence.

So the softmax with finite beta DOES break the symmetry. The gradient pushed a from being constant towards being "U-shaped" (higher at edges, lower in middle). This makes sense: reducing the center values reduces the center convolution peak, while the edge values (which contribute to the tails of the convolution) are less penalized.
