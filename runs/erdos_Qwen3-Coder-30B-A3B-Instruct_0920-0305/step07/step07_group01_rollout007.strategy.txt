**Goal** – Produce a step‑function `h` (discretised on a uniform grid on [0,2]) with a smaller overlap constant  

\[
C_{5}(h)=\max_{k\in\{-N+1,\dots ,N-1\}} 
\Bigl(\Delta x\sum_{i}h_i\bigl(1-h_{i+k}\bigr)\Bigr) ,
\qquad 
\Delta x=\frac{2}{N},
\]

subject to  

* box constraints `0 ≤ h_i ≤ 1`,
* linear equality `\sum_i h_i = N/2`.

The new algorithm is **population based (Differential Evolution)** with a **feasibility‑repair** step, combined with **periodic deterministic local refinement** and a **multi‑resolution schedule**.  It is deliberately different from the previous gradient‑guided hill‑climbing approaches.

--------------------------------------------------------------------
### 1.  Mathematical building blocks

| Symbol | Meaning |
|--------|---------|
| `N` | Number of sample points (grid size). |
| `dx` | Grid spacing `2/N`. |
| `target` | Required sum `N/2`. |
| `h` | Candidate vector in `[0,1]^N`. |
| `corr(h)` | Full correlation vector `np.correlate(h,1-h,'full')*dx`. |
| `Cmax(h)` | `max(corr(h))` – the objective to minimise. |
| `proj_sum_box(v)` | Projection of any real vector `v` onto the intersection of the box `[0,1]^N` and the hyperplane `∑v = target`.  It works by a binary search for the scalar `λ` such that `∑clip(v+λ,0,1)=target` and then returns `clip(v+λ,0,1)`.  This operation is **exact**, cheap (`O(N log precision)`) and is applied after every genotype modification. |

--------------------------------------------------------------------
### 2.  Population representation

A *population* `P = {h^{(1)},…,h^{(M)}}` of size `M` (typical `M≈40‑60`) is maintained.  
All individuals are **always feasible**: each one has already been passed through `proj_sum_box`.  

Each individual also carries **self‑adaptive control parameters** `F` (mutation factor) and `CR` (crossover rate) – a standard DE technique that lets the algorithm discover a good balance between exploration and exploitation automatically.

--------------------------------------------------------------------
### 3.  Initialisation (Phase 0)

1. **Choose an initial grid size** `N₀`.  
   A good value is `N₀ = 120` (the size of the supplied `initial_h_values`), because the existing construction already lives on this grid.

2. **Create a diverse seed set** (size `M`):
   * **Seed A** – the provided `initial_h_values` interpolated to `N₀` and projected.
   * **Seed B** – the uniform vector `h_i = 0.5` (projected trivially).
   * **Seed C** – a binary half‑interval (first `N/2` entries = 1, rest = 0) projected (it already satisfies the sum).
   * **Seed D** – a *checkerboard* pattern (alternating 0/1) projected onto the sum hyperplane.
   * **Seeds E…M** – random vectors: draw `u_i ∼ Uniform(0,1)`, then apply `proj_sum_box(u)`.
   * For each seed initialise `F ∼ Uniform(0.4,0.9)` and `CR ∼ Uniform(0.5,0.9)`.

3. **Evaluate** `Cmax` for every individual and store the current global best `h_best`.

--------------------------------------------------------------------
### 4.  Evolution loop (Differential Evolution)

The main loop runs until the wall‑clock reaches the allocated budget (or a sub‑budget if later phases need time).  Each iteration corresponds to **one generation**:

For each individual `h^{(i)}` in the population (random order):

1. **Mutation** – draw three *distinct* indices `a,b,c` ≠ i (uniformly without replacement).  
   Compute a *mutant* vector  

   \[
   v = h^{(a)}\;+\;F_i\,(h^{(b)}-h^{(c)}).
   \]

   If a random number `r < p_best` (e.g., `p_best = 0.2`) we replace the base vector `h^{(a)}` by the *current global best* `h_best` – this yields the “DE/best/1” variant for a fraction of the population and accelerates convergence.

2. **Repair after mutation** –  
   * Clip `v` to `[0,1]`.  
   * Apply `proj_sum_box(v)` to restore the equality constraint.  
   The resulting vector is still denoted `v`.

3. **Crossover** – produce the *trial* vector `u` dimension‑wise:

   ```
   for j = 0 … N‑1:
       if random() < CR_i or j == j_rand:   # guarantee at least one component from v
           u_j = v_j
       else:
           u_j = h^{(i)}_j
   ```

   After crossover, **repair again** (clip + sum‑projection) to guarantee feasibility.

4. **Selection** – evaluate `Cmax(u)`.  
   If `Cmax(u) ≤ Cmax(h^{(i)})` replace the parent: `h^{(i)} ← u` and keep the parent’s `F_i,CR_i`.  
   Otherwise keep the parent unchanged.

5. **Self‑adaptation** – with probability `τ₁≈0.1` replace `F_i` by a new value drawn from `Normal(F_i,0.1)` and clipped to `[0.4,0.9]`.  
   With probability `τ₂≈0.1` replace `CR_i` by a new value drawn from `Normal(CR_i,0.1)` and clipped to `[0.5,0.9]`.

6. **Update global best** – after every successful replacement, recompute `Cmax` for the new individual; if it beats the current `h_best`, store it.

All operations are `O(N)` per individual, so a whole generation costs `O(M·N)` plus the `O(N²)` correlation needed for the `Cmax` evaluations.  With `N≈120‑200` and `M≈50` this is comfortably below a millisecond per generation in compiled NumPy code, allowing **tens of thousands of generations** inside the 600 s budget.

--------------------------------------------------------------------
### 5.  Periodic deterministic refinement (Hybridisation)

Every `G` generations (e.g. `G = 200`) the **best individual** undergoes a short *local optimisation* that is deterministic and gradient‑based:

1. Compute the correlation vector `c = corr(h_best)`.  
2. Identify the *worst lag* `k* = argmax c`.  
3. Build the **exact sub‑gradient** of `Cmax` at `k*`:

   ```
   grad = zeros(N)
   if k* >= 0:
       grad[0:N‑k*] += (1 - h_best[k*:]) * dx
       grad[k*:  ] += -h_best[0:N‑k*] * dx
   else:
       t = -k*
       grad[t:   ] += (1 - h_best[0:N‑t]) * dx
       grad[0:N‑t] += -h_best[t:   ] * dx
   ```

4. **Projected back‑tracking line search**: start with step `α = 0.2`; while `α > α_min`:
   * `h_trial = proj_sum_box(h_best - α*grad)`.
   * Evaluate `Cmax(h_trial)`.  
   * If the trial improves the objective, accept and break; otherwise halve `α`.

5. If the line search fails to improve after `α` falls below `α_min` (≈ 1e‑4), perform a **greedy mass‑transfer** move:
   * Sort indices with positive `‑grad` (sources) by decreasing magnitude, and those with negative `‑grad` (sinks) by increasing magnitude.
   * Transfer a small quantum `ε = 0.01` of mass from each source to the most promising sink while respecting the box bounds.
   * Re‑project and keep the improvement if any.

The refined vector replaces `h_best` (and also the copy inside the population) if it yields a lower `Cmax`.  This hybrid step injects a **deterministic descent direction** that the stochastic DE may otherwise miss, yet it is used sparingly to keep the overall algorithm stochastic.

--------------------------------------------------------------------
### 6.  Multi‑resolution schedule

The search proceeds on a **coarse grid first**, then **refines** the discretisation:

| Phase | Time window (fraction of total) | Grid size `N` | Reason |
|------|-----------------------------------|--------------|--------|
| 0  (initial) | `[0, 0.30·budget]` | `N₀ = 120` | Uses the known construction, cheap to explore. |
| 1  (medium) | `[0.30·budget, 0.70·budget]` | `N₁ = 240` (≈ 2·N₀) | After a decent basin is found, extra degrees of freedom allow the overlap to be reduced further. |
| 2  (fine, optional) | `[0.70·budget, budget]` | `N₂ = 360` (if time permits) | Final polishing on a finer mesh. |

Transition from phase p to p+1:

1. **Interpolation** – each feasible individual `h` is linearly interpolated onto the finer grid (`np.interp`).  
2. **Projection** – immediately apply `proj_sum_box` on the new grid (the total mass is automatically preserved by interpolation but rounding errors are removed).  
3. **Population enlargement** – increase `M` proportionally to `N` (e.g. `M = 0.3·N`) to keep diversity; fill the new slots with freshly random feasible vectors.

The **mutation factor `F`** is reset to a slightly larger range (`[0.6,0.95]`) after refinement, because the higher dimensional space benefits from larger exploratory steps.

--------------------------------------------------------------------
### 7.  Diversity preservation & stagnation handling

* **Diversity metric** – every `D` generations (e.g. `D = 100`) compute the average pairwise `L₂` distance in the population.  If the diversity falls below a threshold (`0.1·√N`), **re‑inject** a fraction (`≈ 20 %`) of the population with fresh random feasible individuals (projected from uniform draws).  
* **Stagnation trigger** – if the global best has not improved for `S` generations (`S = 500`), temporarily **inflate the mutation factor** (`F ← min(F·1.5, 0.95)`) for all individuals for the next `G` generations, then restore the usual range.  This mimics a temperature‑rise in simulated annealing.

--------------------------------------------------------------------
### 8.  Numerical safeguards

* **Exponentially stable correlation** – the correlation routine uses `np.correlate` on `float64`; no overflow occurs because values are bounded in `[0,1]`.
* **Projection robustness** – binary search for λ stops when the absolute difference of the summed projection to `target` is ≤ 1e‑12, guaranteeing the equality to machine precision.
* **Floating‑point clipping** – after any arithmetic operation, `np.clip(...,0.0,1.0)` is applied before the sum‑projection to avoid tiny negative numbers or values > 1 caused by round‑off.
* **Time guard** – the outermost loop checks `time.time() - start_time` before starting a new generation; if the remaining budget is insufficient for a full generation (including evaluation of `M` individuals) the loop breaks and the current best is returned.
