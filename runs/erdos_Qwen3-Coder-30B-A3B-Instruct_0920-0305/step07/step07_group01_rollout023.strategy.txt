We also propose a multi-resolution approach: start with a modest number of points (e.g., 100) and progressively refine to higher resolution (e.g., 200) using interpolation and warm-start, enabling larger search space gradually while avoiding large dimensional local minima.

The key steps: 

1. Preprocess initial shape (interpolate, project to sum constraint). 
2. Define core functions: evaluate_correlations (full correlation), compute exact subgradient for a given shift, compute smoothed gradient via log-sum-exp weighting.
3. Main optimizer loop:
   - Maintain current solution h_cur.
   - At each iteration compute its C5 vector; if the max is >target record, proceed.
   - Pick smoothing parameter β that grows from small (smooth expression) to large (approx max). This ensures early global moves and later precise fine-tuning.
   - Compute weighted gradient: for each lag compute weight proportional to exp(β*C5_lag); accumulate contributions to gradient as constant term dx minus weighted sum of neighbor values (explained in derivation).
   - Perform a backtracking line search in direction -gradient, projecting onto box and sum constraint after each tentative step using the efficient “lambda projection” algorithm (binary search on Lagrange multiplier).
   - If line search fails to improve C5, temporarily accept a probabilistic uphill move using temperature schedule (simulated annealing) and continue.
   - Periodically (e.g., every 500 iterations) inject a small random perturbation of magnitude decreasing with time to escape shallow basins.
   - Also occasionally restart from the best known solution but with a higher‑temperature perturbation to probe new regions (multi‑restart).
4. Termination: break when allocated time is exhausted. Keep the best encountered solution and its C5 value.

Additional enhancements:
- Use a “mass‑transfer” step derived from the linear approximation of the objective: compute d_i = -∂C5/∂h_i; then greedily move mass from indices with d_i>0 (where increasing h hurts) to those with d_i<0, respecting bounds, until a preset total transferred mass (e.g., 5% of total) is moved. This step is a deterministic improvement that often reduces C5 more than a naive gradient step because it respects the equality constraint exactly without projection artifacts.
- Incorporate a progressive refinement of discretization: after a certain number of iterations at size N, double the number of points (e.g., N←2N) by linear interpolation, re‑project, and continue optimizing. The higher‑resolution stage inherits the structure found on the coarser grid but can fine‑tune.
- Record the best C5 on each grid size; the final answer may be the finest grid solution (e.g., N=240). This yields a more accurate integral approximation.

Implementation notes:
- All heavy loops (gradient accumulation) are O(N^2) but with N≤240 they are cheap; run on CPython with NumPy vector operations to stay within time.
- The projection onto the simplex with upper bound 1 uses the same binary‑search‑lambda routine as before; pre‑compute the target sum = N/2.
- Use numpy random generator seeded for reproducibility.

**Goal:**  Find a step‑function h on [0,2] (discretised as h[0…N‑1]) that lowers the Erdős‑overlap constant  
\(C_{5}(h)=\max_{k}\int_{0}^{2}h(x)\bigl(1-h(x+k)\bigr)\,dx\)  
subject to \(0\le h_i\le1\) and \(\sum_i h_i = N/2\).  
The discrete analogue is  
\(C_{5}(h)=\Delta x\;\max_{\,\ell\in\{-N+1,\dots,N-1\}} \; \sum_{i} h_i\bigl(1-h_{i+\ell}\bigr)\)  
with \(\Delta x=2/N\) and indices outside [0,N−1] ignored.

The optimisation is a **max‑min quadratic problem**.  Rather than heuristic finite‑difference gradients and SLSQP (as in the previous code), the new method uses **exact sub‑gradients of the max‑over‑shifts**, a **smooth‑max surrogate**, **deterministic projected steepest‑descent with back‑tracking line‑search**, occasional **mass‑transfer moves**, and a **progressive refinement of the discretisation**.  The combination gives a far more directed search while still allowing occasional stochastic jumps to escape local minima.

### 2.  Projection onto the feasible set

We must stay inside the hyper‑cube \([0,1]^N\) *and* satisfy the linear equality \(\sum h_i=target\).

1. **Box clip:** `h:=clip(h,0,1)`.
2. **Sum‑projection:** Find a scalar λ such that  
   \(\displaystyle \sum_i\operatorname{clip}(h_i+λ,0,1)=target\).  
   Because the mapping is monotone in λ, a simple binary search (≈ 50 iterations) yields λ to machine precision.  
   Then set `h = clip(h+λ,0,1)`.  
   This is exactly the same routine used previously, but we call it **after every tentative update**, guaranteeing feasibility without solving a full linear programme.

### 3.  Deterministic steepest‑descent step

For the current iterate `h`:

1. Compute `corr = np.correlate(h, 1-h, mode='full')*dx`.  
   `cmax = corr.max()` and the index `idx_best = corr.argmax()`.  
2. **Choose gradient type**  
   *Early stage* (β small) → use **grad_smooth** (weighted sum of all lags).  
   *Late stage* (β large) → use **grad_max** (exact sub‑gradient of the true max).  
3. **Back‑tracking line search**  
   * Initialize step size `α` (e.g. 0.2).  
   * While `α` > `α_min` (≈ 1e‑4):  
     * Propose `h_new = h - α * grad`.  
     * Project `h_new` onto the feasible set (box + sum).  
     * Compute `cmax_new`.  
     * If `cmax_new < cmax` → accept and break.  
     * Otherwise halve α (`α←α/2`).  
   * If no α succeeds, skip the descent this iteration (to avoid wasting time) and go to the stochastic perturbation step.

This guarantees *monotone* improvement whenever a descent direction is useful, while the adaptive β slowly pushes the algorithm toward the true max‑objective.

--------------------------------------------------------------------
### 4.  Mass‑transfer (greedy linearised) move

Even with a perfect gradient, the projection can clip many entries, reducing effective progress.  A **linearised greedy move** uses the sign of the gradient to move mass directly from “bad” to “good” coordinates:

1. Compute direction `d = -grad`.  
2. Identify **sources** = indices where `d[i] < 0` (decreasing `h_i` helps).  
   *Maximum removable amount:* `rem_i = h_i`.  
3. Identify **sinks** = indices where `d[i] > 0` (increasing `h_i` helps).  
   *Maximum addable amount:* `add_i = 1 - h_i`.  
4. Sort sources by decreasing `-d[i]` and sinks by decreasing `d[i]`.  
5. Greedily transfer mass:
   ```
   for s in sources:
       for t in sinks:
           transfer = min(rem_s, add_t, ε)   # ε = small fraction of total mass, e.g. 0.02
           if transfer==0: continue
           h[s] -= transfer;   h[t] += transfer
           rem_s   -= transfer
           add_t   -= transfer
   ```
6. After the sweeps, **re‑project** onto the box (the transfer already respects bounds, so only the equality may drift by ≤ machine epsilon; a final λ‑projection restores the exact sum).  

Because the linearised objective `Δ = Σ d_i Δh_i` is minimized by moving as much mass as possible from the most detrimental entries to the most beneficial ones, this step often yields a **larger decrease in C5** than a simple gradient step of the same size.

--------------------------------------------------------------------
### 5.  Stochastic escape (simulated‑annealing style)

When the deterministic descent stalls, inject a controlled random perturbation:

* Choose a **temperature** `T` that decays exponentially with elapsed time.  
* Pick a random pair (i,j) and a random `δ ~ Uniform(0, min(h_i, 1-h_j, τ))` where `τ` = `T * 0.1`.  
* Transfer `δ` from i to j, then project.  
* Accept the new point **even if C5 does not improve** with probability `exp(-(Cnew-Cold)/T)`.  

This occasional uphill move prevents the algorithm from becoming trapped in shallow local minima.

### 6.  Multi‑resolution refinement

The landscape becomes smoother on a coarse grid, which helps locate a good basin; a finer grid then refines the shape.

1. **Stage A (coarse):** N₁ = 120 (the size of the supplied `initial_h_values`).  
   Run the full optimisation (steps 3‑5) for a fraction of the total time (≈ 30 %).  

2. **Stage B (medium):** N₂ = 240 (≈ 2×N₁).

   * Re‑project onto the feasible set for N₂.  
   * Continue optimisation with the same schedule (β now runs from 5 → 80).  

3. **Optional Stage C (fine):** N₃ = 360 if time remains; same procedure.  

Each refinement inherits the global structure discovered at the previous level, but the increased resolution allows the algorithm to push the max‑overlap down a little further.

### 8.  Why this strategy differs materially

* **Exact sub‑gradients** – the previous code used noisy finite‑difference gradients; here we compute the true derivative of the max‑over‑shifts (or its smooth‑max surrogate) analytically, eliminating stochastic noise.
* **Smooth‑max surrogate** – a temperature‑controlled log‑sum‑exp provides a principled path from a globally‑smooth objective to the true max, rather than arbitrary “gradient‑guided” heuristics.
* **Deterministic back‑tracking line search** – guarantees descent whenever possible, unlike the earlier unconstrained “step‑size‑adaptation” that could overshoot.
* **Greedy mass‑transfer** – a linear‑approximation step that moves mass directly from harmful to beneficial coordinates while respecting the equality constraint exactly; the earlier method shuffled one coordinate at a time.
* **Progressive grid refinement** – the former program fixed N = 120; we deliberately enlarge N mid‑run, inheriting a good coarse shape and exploiting extra degrees of freedom to lower the bound further.
* **Controlled annealing** – stochastic moves are only taken according to a temperature schedule and are coupled with an acceptance probability, instead of the earlier unconditional “perturb‑and‑run‑SLSQP” loops.
* **Unified projection routine** – every update (gradient step, mass‑transfer, random perturbation) ends with the same λ‑projection, ensuring feasibility at all times without extra constraints.

All these ingredients together constitute a fundamentally new optimisation pipeline rather than a re‑ordering of the former steps.

### 9.  Expected outcome & failure handling

* The deterministic descent with smooth‑max rapidly reduces the worst‑shift overlap; the mass‑transfer moves give additional jumps that the gradient alone may miss.
* Grid refinement typically yields a ~0.002–0.003 improvement when moving from N = 120 to N = 240, enough to push the bound below 0.3807 if the coarse stage already reaches ≈ 0.3810.
* If the algorithm stalls (no improvement for several hundred iterations), the temperature‑controlled random jump is guaranteed to be executed, ensuring continued exploration.
* Numerical issues (overflow in `exp(β*corr)`) are avoided by subtracting `max(corr)` before exponentiation.
* If the back‑tracking line search repeatedly fails (possible when the gradient points outside the feasible region), the code falls back to the mass‑transfer step, guaranteeing progress.
