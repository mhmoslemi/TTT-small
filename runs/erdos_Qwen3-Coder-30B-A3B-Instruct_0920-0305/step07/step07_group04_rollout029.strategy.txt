### 2. Linear‑programming relaxation

#### Variables
* `h_i ∈ [0,1]` – the step‑function values.  
* `p_{ij} ∈ [0,1]` for each unordered pair `i ≤ j` – a surrogate for the product `h_i·h_j`.  
  (Store only the upper‑triangular part; the total number of `p`‑variables is `n(n+1)/2` ≈ 11 250 for `n=150`.)

#### Constraints
1. **Mass**: `∑_i h_i = n/2`.  
2. **McCormick envelope** (convex hull of the bilinear term) for every pair `(i,j)`:
   ```
   p_ij ≥ 0
   p_ij ≥ h_i + h_j – 1
   p_ij ≤ h_i
   p_ij ≤ h_j
   ```
3. **Shift (overlap) constraints** – for each integer shift `k ∈ {-(n‑1), …, n‑1}` define the overlap
   ```
   O_k = Σ_{i=0}^{n‑1‑|k|} p_{i, i+|k|}
   ```
   The original correlation for that shift is
   ```
   R_k = (Σ_i h_i) – O_k = n/2 – O_k .
   ```
   Introduce a scalar `T ≥ 0` that bounds the max‑overlap and add for every `k`:
   ```
   n/2 – O_k ≤ T    ⇔    O_k ≥ n/2 – T .
   ```

#### Objective
* Minimise `T`. The LP returns the smallest *relaxed* upper bound on the true max‑overlap.

All constraints are linear; the problem is a pure LP and can be handed to any solver supported by `cvxpy` (CBC, ECOS, GLOP).  
Set a modest solver time limit (e.g. 180 s) to guarantee termination inside the overall budget.

### 3. Binary search on the true objective

The LP relaxation yields a *lower* bound on the minimal feasible `T`, but because the McCormick hull may over‑estimate products, a solution that satisfies the LP can still violate the original max‑overlap when evaluated exactly. To obtain a certified bound:

1. Initialise a search interval `[T_low, T_high]` where `T_low = 0` and `T_high = n/2` (the trivial bound).  
2. Repeat:
   * Set `T_mid = (T_low + T_high) / 2`.  
   * Solve the LP **with `T` fixed to `T_mid`** (i.e. replace the minimisation by a feasibility test).  
   * If the LP is feasible, **evaluate the true C₅** of the returned `h` with the exact correlation (FFT‑based, as in the original evaluator).  
       * If the true value `C5(h) ≤ T_mid·dx`, accept the candidate: store `h_best = h`, set `T_high = T_mid`.  
       * Otherwise treat the LP solution as a *false positive* (relaxation too loose) and set `T_low = T_mid`.  
   * If the LP is infeasible, set `T_low = T_mid`.  
   * Stop when `T_high – T_low` falls below a prescribed tolerance (e.g. `1e‑4·dx`).

At termination `T_high·dx` is a **certified upper bound** on the original problem, and `h_best` is a feasible step‑function achieving (or very close to) that bound.

### 4. Deterministic sub‑gradient polishing

The `h_best` from the binary‑search phase is already good, but the LP relaxation may have left slack that can be exploited. Polish it by directly minimising the original max‑overlap:

1. **Identify the active shift**  
   Compute the correlation vector `c_k = Σ_i h_i·(1 – h_{i+k})` for all `k`.  
   Let `k* = argmax_k c_k`. (If several shifts tie, average their gradients.)

2. **Sub‑gradient of the active term**  
   For each index `i`:
   ```
   g_i = (1 – h_{i+k*})            # contribution from the forward term
        – h_{i‑k*}  (if i‑k* is in range, otherwise 0)
   ```
   This follows from differentiating `h_i·(1 – h_{i+k*})`.

3. **Projective step**  
   * Choose a step size `α_t = α0 / sqrt(t+1)` (or use a simple geometric decay).  
   * Update `h ← h – α_t·g`.  
   * **Projection onto the feasible set**:
     - Clip `h` to `[0,1]`.  
     - Enforce the mass constraint by adding a constant `λ` to all components and re‑clipping:
       Find `λ` such that `Σ_i clip(h_i + λ, 0, 1) = n/2`.  
       A short bisection (≈ 30 iterations) gives `λ` to machine precision.

4. **Loop** – repeat the identification‑gradient‑projection cycle for a fixed budget of iterations (e.g. 2000) or until the max‑overlap stops decreasing.

Because the step uses the exact sub‑gradient of the true objective, it can only improve (or keep) the bound, never worsen it.

### 5. Local exchange refinement (optional)

After sub‑gradient polishing, perform a deterministic “mass‑exchange” sweep:

* Randomly shuffle all unordered index pairs `(i, j)`.  
* For each pair, compute the maximal safe transfer `δ_max = min( h_j, 1 – h_i )`.  
* Try a small transfer `δ = η·δ_max` (with `η ∈ {0.1, 0.5, 0.9}`) from `j` to `i`.  
* Evaluate the new `C5`. If it improves, keep the change; otherwise revert.  

Scanning the full set of pairs a few times (each full pass costs O(n²) but with early‑exit heuristics can be limited to O(n·log n) by only considering neighbours) tightens the bound a few additional thousandths, especially when the solution is already near‑optimal.
