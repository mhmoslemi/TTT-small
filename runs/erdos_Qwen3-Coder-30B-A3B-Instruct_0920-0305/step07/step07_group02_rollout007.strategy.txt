**Why this is materially different?**  

- It formulates the problem as a mixed‑integer linear program solving for the exact worst‑case correlation lower bound rather than purely heuristic local moves.  
- It employs product linearisation with auxiliary binary variables and a global λ variable, a classic combinatorial optimisation approach.  
- The MILP can provide a proven upper bound (incumbent) even if optimality not reached, which is fundamentally distinct from the gradient‐based continuous optimisation used earlier.  

**Mathematical reasoning**  

- With binary h, each term `h_i * h_{i+k}` is exactly the AND of two bits; linearisation preserves exactness, no relaxation.  
- The objective `max λ` guarantees the minimum correlation across all shifts is as large as possible; because the sum of h is fixed, this directly minimizes the maximal overlap via the relation `C5 = 1 - 2 λ / N`.  
- Adding symmetry‑breaking reduces the solution space without affecting optimality (the problem is symmetric under global complement and reversal; fixing one variable removes redundant equivalents).

### 1. Exact MILP formulation

*Variables*  

* `h[i] ∈ {0,1}` for `i = 0,…,N‑1`.  
* For each admissible shift `k ∈ {-(N‑1),…,N‑1}` and each index `i` such that
  `0 ≤ i < N` and `0 ≤ i+k < N`, introduce an auxiliary binary variable  

  ```
  w[i,k] = h[i]·h[i+k]      (AND of the two bits)
  ```

* `λ ∈ ℤ , 0 ≤ λ ≤ N/2` – the **minimum correlation** (in unit‑count, not yet
  multiplied by `dx`).

*Constraints*  

1. **Mass constraint**  
   `Σ_i h[i] = N/2` (the integral equals 1).

2. **Linearisation of the product** (McCormick for binaries) for every
   `(i,k)` pair:  

   ```
   w[i,k] ≤ h[i]
   w[i,k] ≤ h[i+k]
   w[i,k] ≥ h[i] + h[i+k] – 1
   ```

   These three inequalities force `w[i,k] = 1` iff both bits are 1,
   otherwise `w[i,k] = 0`.

3. **Minimum‑correlation definition** – for each shift `k` the correlation
   sum must be at least `λ`:  

   ```
   Σ_{i : 0≤i,i+k<N} w[i,k] ≥ λ .
   ```

4. **Symmetry breaking** (optional, but dramatically reduces the search space)  

   *Fix one bit*, e.g. `h[0] = 1`.  The problem is invariant under global
   complement and reversal; fixing a single entry removes the twofold
   symmetry without discarding any optimal solution.

*Objective* – **maximize** `λ`.  
Since `dx = 2/N`, the resulting bound on the overlap is  

```
C5 = 1 – (2·λ)/N .
```

Thus a larger `λ` directly yields a smaller `C5`.

* `N = 120` (the same size as the previous best record).

### 3. Solving the MILP

1. **Build the model with CVXPY** – all variables are declared with
   `boolean=True` (or `integer=True` for `λ`).  
   The constraints listed above are added in a double loop over `k` and the
   valid `i`‑range for that shift.

2. **Solver selection & time budget** – use the strongest free MILP solver
   available (order of preference: `SCIP`, `CBC`, `GLPK_MI`).  
   Pass a time limit, e.g. `solver_opts = {"max_seconds": budget*0.55}`.
   CVXPY will terminate when the limit is reached, returning the *incumbent*
   (best feasible solution found so far).

3. **Extract the solution** – read the values of `h[i]`.  Because of numerical
   tolerance, round each to the nearest integer (0 or 1).  If rounding
   destroys the exact sum, repair it by swapping a few bits (swap a `1` with a
   `0`) until `Σ h = N/2` again.

4. **Compute the bound** – evaluate  

   ```
   C5 = 1 - (2·λ)/N
   ```

   where `λ` is the integer value obtained from the model (or recompute
   `C5` via a fast FFT‑based convolution to avoid rounding artefacts).

At this stage we already have a **provably feasible binary construction**,
often with `C5` well below the previous record because the MILP optimises the
global minimum‑correlation directly.

--------------------------------------------------------------------
### 4. Post‑MILP polishing (optional, uses remaining time)

The MILP may stop before proven optimality, leaving room for improvement.
Two cheap, complementary refinements are applied while time remains.

#### 4.1 Greedy worst‑shift descent (deterministic)

* Input: binary `h` from the MILP.  
* Repeatedly:
  1. Compute the full discrete correlation `corr = np.correlate(h, h, mode='full')`.  
     The worst shift `s = argmax( N/2 – corr )` is the one that yields the
     current `C5`.  
  2. Identify positions forming a mismatched pair for this shift:
     - `A = { i | h[i]=1  and h[i+s]=0 }` (contribute +dx to `C5`).  
     - `B = { i | h[i]=0  and h[i+s]=1 }`.
  3. If both sets are non‑empty, pick a random `i∈A` and `j∈B` and swap the
     bits (`h[i]=0`, `h[j]=1`). This **strictly reduces** the overlap for the
     worst shift by exactly `dx`.  
  4. Re‑compute `corr`.  
* Stop when no improving swap exists for the current worst shift.  
Because each successful swap lowers the worst overlap, the loop finishes in
≤ `N/2` swaps and typically yields a noticeable reduction (≈ 10⁻³).

#### 4.2 Light‑weight simulated annealing on binary vectors

If time is still available, run a brief Metropolis annealing that can
cross local barriers:

* Temperature schedule: `T(t) = T0·(1 – t/Tmax)` with `T0 ≈ 0.02`.  
* Move: choose a random `1`‑position `i` and a random `0`‑position `j`,
  swap them (preserves the sum).  
* Evaluate `C5` via the FFT routine.  
* Accept if the new value is lower; otherwise accept with probability
  `exp(-(ΔC5)/T)`.  
* Every few hundred accepted moves invoke a short greedy sweep (as in 4.1) to
  accelerate descent.

Both polishing stages are **purely local** and add negligible overhead
compared with the MILP; they merely tighten the incumbent bound.
