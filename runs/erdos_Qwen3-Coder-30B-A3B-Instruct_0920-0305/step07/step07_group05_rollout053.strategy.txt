The goal is to produce a step‑function `h` (discretised as an array) that satisfies  

*   \(0\le h_i\le 1\) for every index,  
*   \(\sum_i h_i = n/2\)   (the integral constraint, because the interval length is 2),  

and that minimises  

\[
C_5(h)=\max_k\int_0^2 h(x)(1-h(x+k))dx .
\]

In the discrete setting the integral is approximated by  

\[
C_5(h)=\Delta x\;\max_{\ell\in\{-n+1,\dots ,n-1\}}
\; \sum_{i=0}^{n-1} h_i\bigl(1-h_{i+\ell}\bigr),
\]

where out‑of‑range indices give \(h=0\) and \(\Delta x=2/n\).

Because \(\sum_i h_i\) is fixed,  

\[
\sum_i h_i\bigl(1-h_{i+\ell}\bigr)=\frac{n}{2}-\sum_i h_i h_{i+\ell}.
\]

Thus  

\[
C_5(h)=\frac{n}{2}\,\Delta x \;-\;\Delta x\;\min_{\ell}\Bigl(\sum_i h_i h_{i+\ell}\Bigr)
      = 1\;-\;\Delta x\;\min_{\ell} s_\ell ,
\]

where  

\[
s_\ell = \sum_i h_i h_{i+\ell}= \bigl(h\star h \bigr)_\ell
\]

is the (full) autocorrelation of `h`.  
**Minimising \(C_5\) is equivalent to maximising the smallest autocorrelation value \(s_\ell\).**

The exact objective is a *max‑of‑linear* (or *min‑of‑quadratic*) function, which is non‑smooth.  
Instead we smooth the *minimum* with a **log‑sum‑exp** (soft‑min) :

\[
\operatorname{softmin}_\alpha(s)=
-\frac{1}{\alpha}\log\!\Bigl(\sum_{\ell}e^{-\alpha s_\ell}\Bigr)
\;\xrightarrow{\;\alpha\to\infty\;}\; \min_\ell s_\ell .
\]

For a given smoothing parameter \(\alpha>0\) we maximise  

\[
F_\alpha(h)=\operatorname{softmin}_\alpha\!\bigl(s(h)\bigr)
\quad\Longleftrightarrow\quad
\text{minimise } \; -F_\alpha(h).
\]

The smooth objective is **differentiable**, and its gradient can be written in closed form, which allows efficient *projected gradient ascent*.

---

### 2.  Gradient of the smooth objective

* Autocorrelation vector: `s = correlate(h, h, mode='full')` (length \(2n-1\)).
* Soft‑min weights  

\[
w_\ell = \frac{e^{-\alpha s_\ell}}{\sum_{m}e^{-\alpha s_m}} .
\]

* Derivative of a single autocorrelation component  

\[
\frac{\partial s_\ell}{\partial h_i}= 
\begin{cases}
h_{i+\ell}+h_{i-\ell}, & \text{if both indices exist},\\[4pt]
h_{i+\ell},            & \text{if only }i+\ell\text{ exists},\\[4pt]
h_{i-\ell},            & \text{if only }i-\ell\text{ exists},\\[4pt]
0,                     & \text{otherwise}.
\end{cases}
\]

* Gradient of the soft‑min  

\[
\nabla_h F_\alpha = \sum_{\ell} w_\ell \,\nabla_h s_\ell .
\]

Thus the gradient can be built by looping over all lags; each lag contributes two *shifted copies* of `h` multiplied by its weight `w_\ell`.  
Because `n` is modest (≤ 500), an explicit O(n²) loop is fast enough and avoids any FFT bookkeeping.

---

### 3.  Projected gradient ascent with a *pairwise mass‑transfer* representation  

The equality constraint \(\sum_i h_i = n/2\) is linear, and the box constraints are simple.  
Instead of applying a generic projection after every gradient step, we keep the sum **exactly** by transferring a small amount of mass from an “source” index to a “target” index:

* Choose a source index `i_src` where the gradient is *most negative* (decreasing `h_i` would increase the objective) and a target index `i_tgt` where the gradient is *most positive*.
* Transfer a quantity \(\delta = \min(\Delta,\,h_{i_{\text{src}}},\,1-h_{i_{\text{tgt}}})\) with a controllable step‑size parameter `Δ`.
* The move automatically preserves the total sum; only the box limits need to be checked.

To avoid getting stuck, the algorithm is **annealed**:

| Phase | α (smoothness) | Δ (step size) | Temperature T | Behaviour |
|-------|----------------|---------------|---------------|-----------|
| Early (exploration) | 10‑30 | 0.4‑0.2 | 5·10⁻³ – 1·10⁻³ | Accept uphill moves with probability \(e^{-(\Delta C)/T}\). |
| Middle | 30‑80 | 0.2‑0.05 | 1·10⁻³ – 5·10⁻⁴ | Mostly downhill moves, occasional escapes. |
| Late (refinement) | 80‑200 | 0.05‑0.005 | 5·10⁻⁴ – 1·10⁻⁴ | Strict descent; temperature approaches zero. |

The parameters are updated *every few hundred iterations* (α multiplied by a factor ≈ 1.2, Δ multiplied by ≈ 0.9995, T multiplied by ≈ 0.9995).  

If a proposed transfer does **not** improve the true objective `C5`, it may still be accepted according to the Metropolis rule using the current temperature; otherwise it is reverted.

---

### 4.  Global search framework

1. **Discretisation choice** – use `n = 240` (Δx ≈ 0.00833).  
   This gives enough resolution to shape the function while keeping each correlation evaluation cheap (≈ 5·10⁻⁴ s).

2. **Initial solution** – interpolate the supplied `initial_h_values` to length `n` and project onto the capped simplex (box + sum) using a simple binary‑search for the Lagrange multiplier.  

3. **Main optimisation phase** – run the annealed projected gradient ascent described above on the interpolated start for **≈ 0.6 · budget** seconds. Keep the best vector seen (`best_h`, `best_c5`).

4. **Exploratory restarts** – while time remains (> ~15 s):
   * Generate a *binary* start: pick exactly `n/2` indices uniformly at random and set them to 1, the rest to 0.
   * Optionally perturb the binary start with a tiny uniform noise (±0.05) and re‑project.
   * Run a *short* gradient‑ascent session (≈ 20 s) on this start.
   * Update the global best if a better `C5` is found.

5. **Fine‑tuning** – take the current global best and perform a **pure projected gradient ascent** on the *exact* max‑over‑shifts objective (no smoothing) with a very small step (Δ ≈ 1·10⁻⁴) for a few thousand iterations. Because the step is tiny, the max‑operator is effectively constant and the loop converges quickly to a locally optimal point.

6. **Optional L‑BFGS‑B polish** – formulate a smooth surrogate objective  

   \[
   J(h)= -\operatorname{softmin}_\alpha(s(h)) + \lambda\bigl(\sum_i h_i - n/2\bigr)^2 ,
   \]

   with a large penalty weight \(\lambda\) (e.g. 10⁴).  
   Initialise the optimiser at `best_h`, use bounds \([0,1]\), and run `scipy.optimize.minimize` (method `L-BFGS-B`) for a few hundred iterations. This step exploits the built‑in line‑search and typically removes the last few hundredths of the bound.

7. **Return** – output  

   * `best_h.tolist()` (Python list of floats),  
   * `float(best_c5)` (the value of `C5` obtained with the correlation routine used by the grader),  
   * `n` (the number of discretisation points).

All steps respect the 600 s wall‑clock limit: the longest phase (global gradient ascent) consumes at most 80 % of the budget, the restart loop uses the remaining time, and the final polishing is negligible.

### 5.  Helper routines (top‑level, no closures)

| Name | Purpose |
|------|---------|

### 6.  Expected advantage over the previous code

* **Soft‑min weighting** replaces the “single worst lag” gradient with a *global* weighted gradient that simultaneously improves *all* low autocorrelation lags.  
* **Annealing of the smoothing parameter α** lets the algorithm first explore a smoother landscape (large basin of attraction) and later focus on the true max‑operator, reducing the chance of getting stuck in a shallow local optimum.  
* **Pairwise mass‑transfer moves** maintain the equality constraint exactly without repeated projections, making each iteration cheap and numerically stable.  
* **Structured time allocation** guarantees a feasible answer regardless of how the search proceeds, while still dedicating the majority of the budget to a sophisticated global optimiser.  
* **Optional L‑BFGS‑B polish** gives a deterministic final push that was absent in the original heuristic.

Together these ingredients form a fundamentally different optimisation pipeline and are expected to push the reported bound below the target 0.3807 (e.g. ≈ 0.3804 or better).
