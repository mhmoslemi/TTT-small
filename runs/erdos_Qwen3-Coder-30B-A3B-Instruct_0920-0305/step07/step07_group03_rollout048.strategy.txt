`∫₀²h=1` and a minimal value of  

\[
C_5(h)=\max_{k}\;\int_0^2 h(x)\bigl(1-h(x+k)\bigr)dx .
\]

The discrete version (grid size `n`, step `dx=2/n`) is  

\[
C_5(h)=dx\;\max_{\ell\in\{-n+1,\dots ,n-1\}} 
\sum_{i=0}^{n-1} h_i\bigl(1-h_{i+\ell}\bigr) ,
\qquad
h_i\in[0,1],\;\sum_i h_i=n/2 .
\]

(Indices outside `[0,n‑1]` are treated as 0.)

It combines three ideas that are mathematically distinct:

1. **A global combinatorial search on the binary space** (simulated annealing on

### 1. Mathematical reformulation used by the optimizer

*Write the overlap for a fixed shift ℓ as*

\[
\Phi_\ell(h)=\sum_{i=0}^{n-1} h_i - \sum_{i=0}^{n-1}h_i\,h_{i+\ell}
\qquad(\text{out‑of‑range indices give }h_{i+\ell}=0).
\]

Then  `C₅(h)=dx·max_ℓ Φ_ℓ(h)`.  
For binary variables (`h_i∈{0,1}`) the second term is an integer count of
overlapping pairs of ones.  The problem is a **max‑min quadratic program**.

### 2. MILP seed for short lengths

For a small even length `m` (e.g. `m∈{60,62,64,68,70,72,76,78,80}`) we build the
following linear model:

* Variables  
  * `h_i ∈ {0,1}` for `i=0…m‑1`.  
  * For every lag `ℓ=1…m‑1` and every admissible pair `(i,i+ℓ)` a binary
    auxiliary variable `p_{i,ℓ}` intended to represent the product  
    `h_i·h_{i+ℓ}`.

* Linearisation constraints (standard “big‑M” formulation)

```
p_{i,ℓ} ≤ h_i
p_{i,ℓ} ≤ h_{i+ℓ}
p_{i,ℓ} ≥ h_i + h_{i+ℓ} – 1 .
```

* Overlap expression for a lag ℓ (with out‑of‑range tail `t_ℓ = Σ_{i=m-ℓ}^{m-1} h_i`)

```
Φ_ℓ = Σ_{i=0}^{m-ℓ-1} h_i – Σ_{i=0}^{m-ℓ-1} p_{i,ℓ} .
```

* Objective: minimise a new scalar variable `t` subject to  
  `Φ_ℓ ≤ t` for **all** ℓ (including ℓ=0).  

* Additional constraints: `Σ_i h_i = m/2`.

The model is a pure integer linear program (≈ m·(m‑1)/2 ≈ 3000 binary
variables for `m=80`).  It is solved **once** with the open‑source CBC
solver (available through CVXPY).  The solver returns an optimal binary
vector `h^{(seed)}` for that short length.  

**Tiling to the target length**

adding a short “transition block’’ to keep the exact number of ones
(`n/2`).  The tiled vector is a high‑quality *binary* starting point for
the later stages.

### 3. Global stochastic search on the binary space (Simulated Annealing)

**Representation** – a binary vector `b∈{0,1}ⁿ` with `Σ b = n/2`.  

**Neighbourhood moves** (each preserves the sum):
* **Swap** – pick a `1`‑position `i` and a `0`‑position `j` uniformly at random
  and exchange the bits.
* **Block‑swap** – choose a block length `L∈{2,3,4,5}` and two non‑overlapping
  intervals `[a,a+L)` and `[c,c+L)`.  Exchange the whole blocks.
* **Rotation** – cyclically shift a randomly chosen interval of length `L`
  by one step (equivalent to a series of swaps but cheaper to generate).

All moves are generated in O(1) time.

**Energy** – `E(b)=C₅(b)`.  It is computed by a fast FFT‑based correlation:

```
b_rev = b[::-1]                # reverse for correlation
c = ifft( fft(b_rev,2n-1) * fft(1-b,2n-1) ).real
E = dx * max(c)
```

The FFT length `2n‑1` is a power of two (zero‑padded) → O(n log n) ≈ 10⁴
flops for `n=120`, negligible.

**Annealing schedule**  
* Initial temperature `T₀ = 0.5·E(b₀)` (half the initial energy).  
* Final temperature `T_f = 1e‑5`.  
* Exponential cooling: after each iteration
  `T ← T·α` with `α = (T_f/T₀)^{1/N_iter}` where `N_iter` is the number of
  iterations allocated to this phase (≈ 2 × 10⁶ for a 6‑minute budget).

**Acceptance rule** – standard Metropolis:
`accept  ⇐  ΔE ≤ 0  or  rand() < exp(-ΔE/T)`.

**Execution plan** – launch several independent annealing runs in
sequence (not parallel, because only a single CPU is available):
* 0 s – 30 s : generate 10 distinct seeds (random balanced, Legendre‑derived,
  MILP‑seed, alternating block, low‑discrepancy Sobol‐sampled pattern, …)
  and run each for ≈ 2 s to obtain a hot start.
* 30 s – 180 s : for each seed run the full SA loop for a fixed number of
  iterations (≈ 200 k moves).  Keep the best binary vector `b*` and its
  energy `E*`.

The SA stage explores the combinatorial landscape far more aggressively
than the SLSQP‑based local search that previously suffered from tiny

### 4. Continuous refinement – projected sub‑gradient descent

The binary optimum `b*` is taken as a **continuous** starting point
(`h⁰ = b*` cast to `float64`).  We now minimise the *max‑overlap* directly
in the continuous cube `[0,1]ⁿ` while preserving the linear constraint
`Σ h = n/2`.

#### 4.1. Sub‑gradient of the max‑overlap

Let `c = corr(h)` be the vector of un‑scaled overlaps `Φ_ℓ(h)` (the same
FFT routine as above, **without** the factor `dx`).  
Let `Λ = { ℓ : c_ℓ = max(c) }` be the set of worst shifts (normally 1 or a few
indices).

For a fixed lag `ℓ` the gradient of `Φ_ℓ` w.r.t. `h` can be written
explicitly (derived from the definition of `Φ_ℓ`):

```
g_i(ℓ) =  1 - h_{i+ℓ}          if i+ℓ < n
          1                    otherwise
       -  h_{i-ℓ}              if i-ℓ ≥ 0
```

(Indices outside `[0,n‑1]` are ignored.)  
The sub‑gradient of `max_ℓ Φ_ℓ` is the average of `g(ℓ)` over all
`ℓ∈Λ` :

```
g = (1/|Λ|) Σ_{ℓ∈Λ} g(ℓ) .
```

All operations are vectorised with a few NumPy slices; the cost is O(n).

#### 4.2. Projection onto the feasible set

After a step `h' = h – η·g` we must enforce

* box constraints `0 ≤ h'_i ≤ 1`,
* the affine sum `Σ h'_i = n/2`.

The Euclidean projection onto the intersection of a box and a hyperplane can
be performed by the classic “water‑filling’’ algorithm:

1. Sort the shifted vector `u = h' + λ` where `λ` is an unknown scalar.
2. Find `λ` such that after clipping `x_i = min(1, max(0, u_i))` we have
   `Σ x_i = n/2`.  
   Because the left‑hand side is monotone in `λ`, a short binary search
   (≈ 30 iterations) yields `λ` to machine precision.

A helper routine `project_to_sum_box(x, target_sum)` implements this.

#### 4.3. Step‑size schedule

We use a diminishing step size of the form  

\[
\eta_t = \frac{\eta_0}{\sqrt{t}} ,
\qquad \eta_0 = 0.2 .
\]

If a trial step does **not** improve the objective, we halve `η` and retry
(at most three halvings per iteration).

#### 4.4. Loop

```
h ← binary_best
best ← C₅(h)
for t = 1 … T_max   (T_max ≈ 5000 or until time runs out)
    compute c, Λ, g
    η ← η₀ / sqrt(t)
    try η, η/2, η/4 → h_new (project after each trial)
    if C₅(h_new) < best:
         h ← h_new ; best ← C₅(h_new)
    else:
         keep h (no update)
```

Because the sub‑gradient targets exactly the lag(s) responsible for the
current maximum, the method quickly flattens the peak(s) and often pushes
`C₅` below the best binary value by a few `dx`‑units (the fractional improvement

### 5. Randomised rounding + final greedy fine‑tuning

Even after sub‑gradient descent the solution may contain many entries close
to 0 or 1.  To explore nearby binary neighbourhoods we perform:

1. **Probabilistic rounding** – generate a binary vector `b̂` by setting
   `b̂_i = 1` with probability `h_i` (independently) and then correcting the
   total number of ones to exactly `n/2` by swapping the smallest‑probability
   `1`s with the largest‑probability `0`s.
2. Evaluate `C₅(b̂)`.  Keep the best of, say, 200 such samples.
3. **Greedy swap refinement** – starting from the best rounded vector,
   repeatedly examine a *sample* of `O(√n)` random `(i,j)` swaps and accept any
   swap that reduces `C₅`.  Continue until no improvement is found in a full
   sweep.

This stage is very cheap (each evaluation uses the same FFT routine) and
can shave off the last few `dx`‑steps that separate 0.38098 from 0.38070.

* **Targeted sub‑gradient** – instead of a generic SLSQP which tries to

* **Rounding‑plus‑greedy** – after the continuous phase we deliberately
