**1.  Reformulate the continuous problem as a finite 0/1 optimisation**

*Discretisation*  
Choose an even number of lattice points `N` (e.g. 120 – 160).  
Let `dx = 2/N`.  
A step‑function `h` is represented by a vector  

```
x = (x0,…,xN‑1)  with  xi ∈ {0,1}   and   Σ xi = N/2 .
```

(The integral condition is exactly the half‑ones constraint.)

*Overlap in binary form*  
For an integer shift `k∈{1,…,N‑1}` the discrete overlap used by the evaluator is  

```
Ok(x) = Σ_{i=0}^{N‑1‑k}  xi·(1‑x_{i+k}) .
```

Writing `yi,k = xi·x_{i+k}` we have  

```
Ok = Σ_{i=0}^{N‑1‑k} xi  –  Σ_{i=0}^{N‑1‑k} yi,k .
```

Thus each `Ok` is an affine function of the variables `xi` **and** the quadratic terms `yi,k`.  

**2.  Linearise the quadratic terms with auxiliary binary variables**

Introduce a new binary variable  

```
wij,k  ∈ {0,1}   (i = 0,…,N‑1‑k) .
```

which is forced to be the logical AND of `xi` and `x_{i+k}` by the three classic “big‑M” constraints

```
wij,k ≤ xi,
wij,k ≤ x_{i+k},
wij,k ≥ xi + x_{i+k} - 1 .
```

With these variables  

```
Ok = Σ_{i=0}^{N‑1‑k} xi  –  Σ_{i=0}^{N‑1‑k} wij,k .
```

All expressions are now linear.

**3.  Introduce a single variable that bounds the worst overlap**

Add an integer variable `t ≥ 0` and enforce for every shift `k`

```
Ok ≤ t .
```

Because `dx` is a constant, minimising `t` is exactly equivalent to minimising the returned `C5 = t·dx`.

**4.  Symmetry‑breaking constraints (optional but very effective)**  

* Complementarity: the solution `x` and its complement `1‑x` give the same `t`.  
  Fix the first entry, e.g. `x0 = 1`.  

* Reversal symmetry: a reversed sequence yields identical overlaps.  
  Force a lexicographic ordering on the first three bits, e.g.  
  `x0 ≥ xN‑1`, `x1 ≥ xN‑2`.  

These linear constraints cut the feasible region roughly by a factor of four without affecting optimality.

**5.  Build a *cutting‑plane* mixed‑integer model (incremental constraints)**  

Creating `wij,k` for **all** pairs would give O(N²) auxiliary binaries (≈ 7 000 for N=120) and a comparable number of constraints, which is already tractable for modern MILP solvers, but we can do much better:

*Start with a small set `K₀` of shifts (e.g. `K₀ = {1,2,3,4,5}`) and create the corresponding `wij,k` variables only for those shifts.*  

All other shifts are ignored initially.  The mixed‑integer programme (MIP) is:

```
minimise   t
subject to
    Σ xi = N/2
    x0 = 1                     (symmetry break)
    0 ≤ xi ≤ 1 ,  xi integer
    for every (i,k) with k∈K₀:
         wij,k ≤ xi
         wij,k ≤ x_{i+k}
         wij,k ≥ xi + x_{i+k} - 1
    for every k∈K₀:
         Σ_{i=0}^{N‑1‑k} xi  -  Σ_{i=0}^{N‑1‑k} wij,k  ≤  t .
```

**6.  Solve the reduced MIP, then iteratively add the *real* worst shift**

1. **Solve** the current MIP with a time limit (e.g. 30 s) using any MILP engine available through CVXPY (`CBC`, `GLPK`, `SCIP`, …).  
2. **Recover** the binary vector `x*` and the objective value `t*`.  
3. **Evaluate** the full set of overlaps `Ok(x*)` (via `np.correlate`).  
4. **If** `max_k Ok(x*) ≤ t*` then the current solution is feasible for **all** shifts – we have a provably optimal bound for the chosen `N`.  
5. **Otherwise** let `k̂ = argmax_k Ok(x*)`.  Add `k̂` to the active shift set `K` and create the new auxiliary variables `wij,k̂` together with their three linking constraints and the overlap bound `Ok̂ ≤ t`.  
6. **Re‑solve** the enlarged MIP (warm‑starting the `x` variables with `x*`).  
7. **Repeat** steps 2‑6 until the full‑overlap check succeeds or the global time budget expires.

Because the worst overlap is almost always caused by a *few* small shifts, the algorithm typically adds only a handful of new shift constraints (often < 20).  Consequently the total number of auxiliary binaries stays modest (≤ ~15 000) and the solver finishes far faster than a monolithic model that contains every shift from the outset.

**7.  Tighten the bound by a feasibility binary search (optional but cheap)**  

When the algorithm terminates with a feasible pair `(x*,t*)`, we can try to improve `t` by solving *feasibility* MIPs:

* For a candidate integer `B = t* – 1, t* – 2, …` add the constraints `Ok ≤ B` for all already‑active shifts (no objective).  
* Solve the feasibility problem (again with a few seconds limit).  
* If feasible, replace `t* ← B` and continue the search; otherwise stop.  

Since `Ok` is integer, this binary search finishes in at most `log₂(t*)` additional solves (typically ≤ 6) and often lowers the bound by 1–2 integer units, i.e. by roughly `dx = 2/N`.
