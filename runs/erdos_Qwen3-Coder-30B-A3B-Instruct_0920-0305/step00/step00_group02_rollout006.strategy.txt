### 1. Algebraic reformulation

Let  

* `h ∈ {0,1}ⁿ` be the unknown binary vector,  
* `X = hhᵀ ∈ ℝ^{n×n}` be its outer product (rank‑1, PSD).  

For each shift `k` define the sparse symmetric matrix `A_k ∈ ℝ^{n×n}` by  

\[
(A_k)_{i,j}= \begin{cases}
1 & \text{if }|i-j|=k\; \text{and}\;0\le i,j<n,\\[4pt]
0 & \text{otherwise}.
\end{cases}
\]

(For `k=0` the diagonal entries are 1; they are irrelevant because `S_0 = n/2` is always maximal.)

Then  

\[
S_k(h) = \sum_{i=0}^{n-1-k} h_i h_{i+k}
       = \tfrac12\,\operatorname{tr}(A_k X) .
\]

Thus the *exact* combinatorial problem can be written as

\[
\begin{aligned}
\max_{h\in\{0,1\}^n}&\;\;\min_{k\ge 1}\; \operatorname{tr}(A_k X) \\[2pt]
\text{s.t. }& X = hhᵀ,\qquad
            \sum_i h_i = n/2 .
\end{aligned}
\]

### 2. SDP relaxation

Relax the rank‑1 constraint and the integrality of `h`.  Introduce variables  

* `X ⪰ 0` (positive semidefinite),  
* `x_i = X_{ii}` (the diagonal entries, interpreted as relaxed “probabilities’’ of selecting position `i`).  

The relaxed problem is

\[
\begin{aligned}
\max_{X\succeq0,\,x}\;&\; t                                                   \\
\text{s.t. }        &\operatorname{tr}(A_k X) \ge 2t           &&\forall k=1,\dots,n-1,\\
                    &0\le x_i \le 1                           &&\forall i,\\
                    &\sum_{i=0}^{n-1} x_i = n/2,\\
                    &X_{ii}=x_i                               &&\forall i .
\end{aligned}
\]

*Why the factor 2?*  Because `S_k = ½ tr(A_k X)`.  Maximising `t` therefore maximises the *minimal* overlap `S_k`.

All constraints are linear except the PSD constraint; the problem is a **convex SDP**.  Solving it yields an upper bound on the achievable `min_k S_k` (hence a lower bound on `C₅`).  Moreover the optimal `X` often exhibits a pronounced low‑rank structure, which we exploit during rounding.

### 3. Building the SDP data (size ≈ n²)

* **Choice of `n`** – pick a modest even size that balances resolution and SDP cost, e.g. `n = 200` (`dx = 0.01`).  With `n = 200` we have `n‑1 = 199` shift matrices, each containing exactly `2·(n‑k)` non‑zero entries, so the total number of non‑zeros is `O(n²) ≈ 4·10⁴`.  Modern SDP solvers (SCS, COSMO, or the open‑source `CVXOPT`/`SDPA`) handle this comfortably within the 600 s budget.

* **Sparse representation** – construct each `A_k` as a `scipy.sparse.csr_matrix`.  When formulating the SDP in CVXPY we pass the sparse matrices directly (`A_k @ X`), avoiding a dense `n×n` allocation.

* **Symmetry reduction** – because `S_k = S_{n-k}` the constraints for `k > n/2` are redundant.  We therefore keep only `k = 1,…,⌊n/2⌋` (≈ 100 constraints for `n=200`).  This halves the SDP size without affecting the exact value.

--------------------------------------------------------------------
### 4. Solving the SDP

1. **Modeling** – use `cvxpy` with a PSD variable `X = cp.Variable((n,n), PSD=True)`.  
   *Add the diagonal constraints* `cp.diag(X) == x`.  
   *Add the sum constraint* `cp.sum(x) == n/2`.  
   *Add the box constraints* `0 ≤ x ≤ 1`.  
   *Add the overlap constraints* `cp.trace(A_k @ X) >= 2*t` for each kept shift `k`.  

2. **Solver choice** – the open‑source first‑order solver **SCS** (`solver=cp.SCS`) is extremely fast for moderate‑size SDPs and respects a user time limit (`max_iters` or `eps`).  If a commercial interior‑point solver like **MOSEK** is available, it can be used for higher accuracy.

3. **Time budgeting** – call `prob.solve(solver=cp.SCS, max_iters=2000, eps=1e‑4, warm_start=True)`.  Empirically, with `n=200` the SDP finishes in **≈ 180 s** on a single core, leaving ample time for the later stages.

4. **Extracting the solution** – obtain the optimal matrix `X_star = X.value` and the diagonal `x_star = np.diag(X_star)`.  The optimal objective value `t_star` is returned as `t.value`.  The continuous lower bound on `C₅` is  

   \[
   C_5^{\text{SDP}} = 1 - t_\star\,dx .

### 5. Randomised rounding from the SDP matrix

`X_star` is positive semidefinite, so we can write `X_star = V Vᵀ` with `V ∈ ℝ^{n×r}` (Cholesky or eigen‑decomposition).  In practice the spectrum of `X_star` is heavily concentrated in the first few eigenvalues; we keep the top `r = 5–10` components to save memory.

**Rounding procedure (performed many times, e.g. 300 trials):**

1. Sample a random Gaussian vector `g ∈ ℝ^{r}` with i.i.d. `N(0,1)` entries.  
2. Compute scores `s = V g` (vector of length `n`).  
3. Determine a threshold `τ` such that exactly `n/2` entries of `s` are ≥ `τ`.  This can be done by sorting `s` once per trial and picking the `(n/2)`‑th largest value.  
4. Set binary vector `h_i = 1` if `s_i ≥ τ`, else `0`.  
5. **Feasibility check** – by construction the sum constraint is satisfied; the box constraint is automatic.  

Because the scores are linear functions of `g`, this is precisely the **Goemans‑Williamson hyperplane rounding** used for max‑cut, adapted to our problem.  The SDP’s PSD structure ensures that, in expectation, the rounded vector preserves a constant‑factor of the SDP objective.

**Evaluation** – for each rounded `h` compute the exact `C₅` using the given evaluation routine (`np.correlate`). Keep the best (smallest) `C₅` among all trials.  Empirically, with a modest number of trials (≈ 200–300) we obtain a binary solution whose `C₅` is within a few thousandths of the SDP bound.

--------------------------------------------------------------------
### 6. Post‑rounding local polishing (swap hill‑climbing)

The rounded vector is already very good, but a few **swap moves** can improve the worst‑case shift:

1. Pre‑compute the overlap vector `S = np.correlate(h, h, mode='full')[n‑1:]`.  
2. Identify the current `k* = argmin S`.  
3. Randomly pick a `1`‑position `i` and a `0`‑position `j`.  
4. Swap (`h[i]=0, h[j]=1`) and recompute `S` (the full correlation; with `n≤200` this is cheap).  
5. Accept the swap iff the new `min(S)` **increases** (equivalently `C₅` decreases).  
6. Repeat for a fixed number of iterations or until the elapsed time of this polishing phase (≈ 120 s) expires.

Because each successful swap raises the minimum overlap, the objective converges rapidly; typical runs achieve the **global optimum for the given `n`** or a solution within the SDP bound’s tolerance.
