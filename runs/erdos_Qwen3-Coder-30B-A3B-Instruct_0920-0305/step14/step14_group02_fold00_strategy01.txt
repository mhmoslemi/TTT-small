### 1.  Problem reformulation

For a discretised step function  
\(h=(h_0,\dots ,h_{N-1})\) on \([0,2]\) with step \(\Delta x = 2/N\) we have  

\[
C_5(h)=\Delta x\;\max_{s\in\{-N+1,\dots ,N-1\}}   
\underbrace{\sum_{i=0}^{N-1-s} h_i\bigl(1-h_{i+s}\bigr)}_{\displaystyle\text{corr}_s(h)} .
\tag{1}
\]

Because \(\sum_i h_i = N/2\) (the integral constraint),
\[
\text{corr}_s(h)=\frac{N}{2}-\sum_{i}h_i h_{i+s}.
\]
Thus minimising \(C_5\) is equivalent to **maximising the smallest auto‑correlation**  
\(\displaystyle \min_{s}\sum_i h_i h_{i+s}\) (the “overlap” between \(h\) and a shifted copy of itself).

The feasible set is the **capped simplex**
\[
\mathcal F=\Bigl\{h\in[0,1]^N\;:\;\sum_i h_i = N/2\Bigr\}.
\]

The objective is a non‑convex max of quadratic forms.  Direct global optimisation is out of reach, but a *smooth continuation* combined with a projected gradient method works well in practice.

--------------------------------------------------------------------
### 2.  Smooth approximation of the max

Replace the hard max in (1) by a **log‑sum‑exp** (soft‑max) with temperature \(T>0\):

\[
f_T(h)=T\log\Bigl(\sum_{s} \exp\bigl(\text{corr}_s(h)/T\bigr)\Bigr)
      \;\approx\;\max_s \text{corr}_s(h)\quad (T\downarrow0).               \tag{2}
\]

While \(T\) is positive the objective is **smooth** and has a well‑defined gradient that can be used for first‑order optimisation.  We will start with a moderate temperature (e.g. \(T_0=10^{-1}\)) and **anneal** it geometrically to a tiny value (\(T_{\text{final}}\approx10^{-5}\)).  The annealing schedule provides a continuation from a “soft” landscape (easy to move) to the true problem.

--------------------------------------------------------------------
### 3.  Gradient of the smooth objective

Define  
\[
w_s(T,h)=\frac{\exp\bigl(\text{corr}_s(h)/T\bigr)}{\sum_t \exp\bigl(\text{corr}_t(h)/T\bigr)} .      \tag{3}
\]

Then by the chain rule

\[
\nabla f_T(h)=\sum_{s} w_s(T,h)\,\nabla\text{corr}_s(h).               \tag{4}
\]

The gradient of a *single* shift \(s\) follows directly from (1):

\[
\boxed{\;
\bigl[\nabla\text{corr}_s(h)\bigr]_j
=
\begin{cases}
1-h_{j+s} & \text{if }0\le j\le N-1-s,\\[1mm]
0           & \text{otherwise}
\end{cases}
-
\begin{cases}
h_{j-s} & \text{if }s\le j\le N-1,\\[1mm]
0       & \text{otherwise}
\end{cases}
\;}.                                                \tag{5}
\]

Expression (5) is *exactly* a pair of shifted, zero‑padded arrays; it can be evaluated in \(O(N)\) time.

Computing (4) for *all* \(2N-1\) shifts would be \(O(N^2)\).  In practice the soft‑max weight vector is *highly peaked*: almost all mass sits on the **K** largest shifts (with \(K\) between 5 and 15).  Therefore we:

1. Compute the full correlation vector once per iteration (via an FFT, \(O(N\log N)\)).
2. Select the indices of the top‑\(K\) values.
3. Build the weighted sum (4) **only** over those top‑\(K\) shifts.

This reduces the per‑iteration cost to  
\(O(N\log N + K N)\) – negligible for \(N\le200\).

--------------------------------------------------------------------
### 4.  Projection onto the capped simplex

After a gradient step the iterate will generally violate the box or sum constraints.
We project onto \(\mathcal F\) in two stages:

* **Box clipping:**  \(y_i = \operatorname{clip}(x_i,0,1)\).
* **Sum correction:**  Find a scalar \(\lambda\) such that  
  \(\displaystyle\sum_i \operatorname{clip}(x_i+\lambda,0,1)=N/2\).

The second step is a *water‑filling* problem with a single unknown \(\lambda\).  
A robust implementation uses a **bisection** on \(\lambda\) (initial interval \([-1,1]\), 40–50 iterations are enough for double‑precision tolerance).  The whole projection runs in \(O(N\log\epsilon)\) and is cheap compared with the FFT.

### 5.  Optimisation loop (continuation)

For a fixed resolution \(N\) we run the following loop:

```
h ← initial feasible vector (see §6)
T ← T0
α ← α0               # initial step size
v ← 0                # momentum vector (optional)

for t = 1 … MaxIter while time left:
    # 1. correlation (FFT)
    corr ← FFT‐correlation of h with (1−h)

    # 2. top‑K shifts & soft‑max weights
    idx_top ← indices of the K largest entries of corr
    w_s ← soft‑max weights restricted to idx_top (temperature T)

    # 3. gradient (weighted sum of (5))
    g ← weighted sum of sub‑gradients for each s∈idx_top

    # 4. momentum (optional)
    v ← β·v + (1−β)·g                     (β≈0.9)
    step ← α / √t                        # diminishing step size
    h ← h − step·v

    # 5. feasibility projection
    h ← project_onto_capped_simplex(h, N/2)

    # 6. temperature & step schedule
    T ← τ_T·T      (τ_T≈0.9995 per iteration)
    α ← α0·τ_α     (τ_α≈0.999 per iteration, optional)

    # 7. occasional exact evaluation
    if t % 20 == 0:
        C5 ← Δx·max(corr)
        keep best (h, C5) seen so far
```

Key points:

* **Continuation** – The temperature starts large (the landscape is almost convex) and slowly contracts; the algorithm automatically follows the moving optimum.
* **Momentum** – Reduces zig‑zagging caused by the non‑smooth max.
* **Diminishing step** – Guarantees convergence of the projected sub‑gradient method.
* **Top‑K** – Keeps the cost linear while still following the true max.

### 6.  Initialisation & symmetry handling

Multiple independent restarts drastically increase the chance of finding the global optimum.

| Type | How to build the seed | Symmetry |
|------|-----------------------|----------|
| **Random** | Draw i.i.d. \(U[0,1]\) and project onto \(\mathcal F\). | No |
| **Symmetric random** | Same as Random, then enforce mirror symmetry:  \(h←(h+h^{\text{rev}})/2\). | Yes |
| **Triangular (deterministic)** | Continuous triangle \(h(x)=\max\bigl(0,1-|x-1|\bigr)\). Sample on the grid, then project. | Yes |
| **Piecewise‑constant blocks** | Create several blocks of height 1 separated by gaps, adjust lengths so that the integral is 1, finally project. | Optional |

For every *symmetric* run we keep the vector exactly symmetric after each projection:
`h ← (h + h[::-1]) / 2`.  Because the average of two feasible points stays inside the box, only the sum constraint needs checking (the averaging does not change the total sum).

### 7.  Multi‑scale (coarse‑to‑fine) strategy

1. **Coarse phase** – Set \(N_{\text{coarse}} = 60\). Run a short continuation (≈ 2 000 iterations) from the triangular seed.  
2. **Interpolation** – Interpolate the best coarse vector onto a finer grid (e.g. \(N=120\) or \(150\)) using linear interpolation on the domain \([0,2]\).  
3. **Fine phase** – Initialise the fine‑resolution optimiser with the interpolated vector and run the full continuation (≈ 10 000 iterations distributed across restarts).

The coarse phase is only a few seconds but supplies a high‑quality basin that the fine phase inherits, helping the algorithm avoid shallow local minima that would trap a direct high‑resolution run.

### 8.  Local combinatorial polishing (post‑processing)

After the continuation has converged (temperature ≈ 10⁻⁶), the objective is essentially the true max.  At this stage we switch to a **pair‑swap hill‑climber** that respects the constraints *exactly* (no projection needed).

```
repeat until time out or no improvement for 5000 trials:
    pick distinct i,j uniformly at random
    # feasible interval for a transfer Δ from i → j
    Δ_low  = max(-h_i,       h_j-1)
    Δ_high = min( 1-h_i,      h_j )
    if Δ_low >= Δ_high: continue
    Δ ← Uniform(Δ_low, Δ_high)
    h_i ← h_i + Δ
    h_j ← h_j - Δ
    C5_new ← exact C5 (FFT)
    if C5_new < C5_current:
        accept; C5_current ← C5_new
    else:
        # tiny simulated‑annealing acceptance to escape plateaus
        p ← exp( -(C5_new-C5_current)/τ )
        τ ← max(0.001, τ0·(1 - elapsed/total_budget))
        accept with prob p
```

Because the move conserves the total sum and stays in \([0,1]\) by construction, the expensive projection is avoided, allowing millions of cheap trials in the remaining time budget.  The occasional acceptance of worse states (temperature τ slowly decays) prevents the search from getting stuck in a flat region.

### 9.  Numerical ingredients (fast building blocks)

* **Correlation via FFT** – For a vector `h`, compute  
  `corr = irfft( rfft(h[::-1]) * rfft(1−h) , n=2*N-1 )`.  
  The maximum of `corr` multiplied by `Δx` is the exact `C5`.
* **Top‑K extraction** – `np.argpartition(corr, -K)[-K:]` gives the indices of the largest `K` shifts in linear time.
* **Soft‑max stability** – Subtract the global maximum of `corr` before exponentiation:  
  `w = np.exp((corr - corr.max())/T)`; then normalise.
* **Projection** – Bisection on a scalar λ; each evaluation requires a cheap `np.clip` and a sum, both vectorised.

All operations are vectorised NumPy calls; a single iteration on \(N=150\) costs < 0.5 ms on a modern CPU, leaving ample margin for the 600 s total budget.

### 11.  Anticipated failure modes & mitigations

| Failure mode | Why it could happen | Countermeasure |
|--------------|--------------------|----------------|
| **Stagnation at a poor local minimum** | The continuation may lock onto a sub‑optimal basin if the temperature is reduced too quickly. | Use a *slow* geometric decay (`τ_T≈0.9995`) and keep the K‑top‑shift set dynamic (re‑evaluate each iteration). |
| **Overshooting due to large steps** | Early iterations with high step size may leave the feasible region or increase the max correlation. | The projection step guarantees feasibility; additionally cap the step size by the maximum absolute entry of the gradient (`step = min(step, 0.5/‖g‖_∞)`). |
| **Numerical overflow in soft‑max** | For very large `corr/T` the exponentials can overflow. | Always subtract the global max before exponentiation as described in §9. |
| **Projection bottleneck** | Repeated bisections could dominate runtime if called too often. | Project only **once per iteration** (after the gradient step). The bisection converges in ≤ 40 iterations, each O(N). |
| **Insufficient exploration** | A small number of restarts may miss the global optimum. | The schedule explicitly runs many cheap restarts (≈ 12–15) plus the deterministic triangular start. |
| **Symmetry breaking** | For a symmetric optimum a non‑symmetric initialisation may converge slowly. | Include dedicated symmetric restarts (mirror‑averaging after each update). |
| **Local search plateau** | Pair‑swap hill‑climber may stop improving long before the theoretical optimum. | Add a tiny simulated‑annealing temperature that decays slowly, allowing occasional uphill moves. |
