def smooth_gradient(h, T, top_k=10):
    corr = corr_fft(h)
    # compute weights
    if T < 1e-12:
        # just subgradient of max shift
        idx = np.argmax(corr)
        shift = idx - (len(h)-1)
        return subgradient_for_shift(h, shift)
    else:
        # Convert to exponentials
        max_corr = np.max(corr)
        # shift to improve numeric
        exp_vals = np.exp((corr - max_corr) / T)
        weights = exp_vals / np.sum(exp_vals)
        # Use only top_k weights for efficiency
        top_idx = np.argpartition(weights, -top_k)[-top_k:]
        g = np.zeros_like(h)
        N = len(h)
        for idx in top_idx:
            w = weights[idx]
            s = idx - (N-1)
            # compute grad for shift s
            grad_s = subgradient_for_shift(h, s)
            g += w * grad_s
        return g
```

def evaluate_c5_fast(h):
    n = len(h)
    L = 2*n - 1
    # use real FFT for speed
    h_rev = h[::-1]
    b = 1 - h
    H = np.fft.rfft(h_rev, n=L)
    B = np.fft.rfft(b, n=L)
    corr = np.fft.irfft(H * B, n=L)
    max_corr = np.max(corr)
    return max_corr * (2.0 / n)
```

**Goal** – Find a step function  
\(h:[0,2]\rightarrow[0,1]\) with \(\int_0^2h=1\) that minimises

On a uniform grid of `n` points (`dx = 2/n`) the problem becomes

C_5(h)=dx\;\max_{s\in\{-n+1,\dots ,n-1\}}\;

\tag{1}
\]

The constraints are  

* box: \(0\le h_i\le1\)   
* sum: \(\sum_i h_i = n/2\)    (because \(\int h=1\)).

### 1.  Mathematical reformulation

From (1)

\[
\int h(x)(1-h(x+k))dx
= \int h - \int h(x)h(x+k)\,dx
\;=\;1-\int h(x)h(x+k)\,dx .
\]

Hence minimising \(C_5\) is **equivalent** to maximising the *minimum* auto‑correlation  

\[
\min_{k} \int h(x)h(x+k)dx .
\tag{2}
\]

In the discrete setting each shift \(s\) contributes  

\[
\text{corr}_s(h)=\sum_{i}h_i\bigl(1-h_{i+s}\bigr)
    =\underbrace{\sum_i h_i}_{=n/2}
      -\sum_i h_i h_{i+s}.
\]

Thus the only non‑linear term is the quadratic inner product \(\sum_i h_i h_{i+s}\).

--------------------------------------------------------------------
### 2.  Optimisation framework

Because the objective is a **max of linear‑quadratic forms**, it is non‑convex and non‑smooth.  
A practical approach is a *continuation* (homotopy) method:

1. **Smooth the max** with a log‑sum‑exp (soft‑max) at temperature \(T>0\):

   \[
   f_T(h)=T\log\Bigl(\sum_{s} e^{\text{corr}_s(h)/T}\Bigr)
   \quad\Longrightarrow\quad
   \max_s\text{corr}_s(h)\approx f_T(h).
   \]

   As \(T\downarrow0\) the smooth objective converges to the true max.

2. **Compute a gradient** of the smooth objective.  
   For a *fixed* shift \(s\),

   \[
   \frac{\partial\text{corr}_s}{\partial h_j}
   =\begin{cases}
        (1-h_{j+s}) & \text{if }j+s<n,\\[2mm]
        0            & \text{otherwise}
      \end{cases}
     -\begin{cases}
        h_{j-s} & \text{if }j-s\ge0,\\[2mm]
        0       & \text{otherwise}
      \end{cases}.
   \tag{3}
   \]

   The gradient of the soft‑max is a **convex combination** of the per‑shift gradients:

   \[
   \nabla f_T(h)=\sum_{s} w_s\,\nabla\text{corr}_s(h),
   \qquad
   w_s=\frac{e^{\text{corr}_s/T}}{\sum_{t}e^{\text{corr}_t/T}} .
   \tag{4}
   \]

   Computing (3) for *all* shifts costs \(O(n^2)\).  Instead we keep only the
   **top‑K** shifts (e.g. K = 10) – their weights dominate the soft‑max – and sum the
   corresponding gradients.  This reduces the per‑iteration work to  
   \(O(Kn)\) ≈ a few thousand elementary operations for \(n\le200\).

3. **Projected gradient descent** on the *smooth* objective:  

   \[
   h^{\text{new}} = \Pi_{\mathcal{F}}\bigl(h - \alpha\,\nabla f_T(h)\bigr) .
   \]

   \(\Pi_{\mathcal{F}}\) projects onto the feasible set  
   \(\mathcal{F}=\{h\in[0,1]^n:\sum h=n/2\}\) (a “capped simplex”).  
   The projection is implemented by a **scalar‑shift + clipping**:
   find a λ such that \(\sum_i\text{clip}(h_i+\lambda,0,1)=n/2\).  
   A fast bisection on λ (≈ 40 iterations) is sufficient.

4. **Continuation schedule** – start with a relatively large temperature
   (`T₀≈0.1`) and a moderate step size (`α₀≈0.5`).  After each iteration
   multiply the temperature by a factor `τ_T≈0.9995` and shrink the step
   like \(\alpha_t = \alpha_0 / \sqrt{t+1}\).  After ~1500–2500 iterations the
   temperature falls below 10⁻⁴, at which point the soft‑max has become the exact
   max and the algorithm behaves as a sub‑gradient method on the original
   problem.

5. **Momentum** – optional Nesterov/Heavy‑ball momentum improves convergence
   without extra cost.  Keep a velocity vector `v←βv+(1-β)∇f_T`, then update
   \(h←h-αv\).  Use β≈0.9.

### 5.  Local combinatorial polishing (post‑processing)

When the global phase ends we have a promising vector `h*`.  A cheap,
yet powerful, **pair‑swap hill‑climber** is applied for the remaining time:

*Pick two distinct indices* `i, j`.  
*Choose a feasible delta* `Δ` in the interval  

\[
\Delta\in\bigl[\max(-h_i,\;h_j-1),\;\min(1-h_i,\;h_j)\bigr],
\]

so that `h_i←h_i+Δ`, `h_j←h_j-Δ` preserves both the box constraints and the
total sum exactly (no projection needed).  

If the new configuration yields a smaller exact `C_5`, accept it
(unconditionally).  Otherwise accept with a *tiny* simulated‑annealing
probability that decays linearly to zero, to allow occasional escapes.

We run this loop until the allocated budget (≈ 10 % of total time) expires,
or until no improvement occurs for several thousand trials.

| `smooth_gradient(h, T, top_k=10)` | Compute (4) using only the `top_k` largest soft‑max weights. |
| `gradient_descent_restart(n, target, max_iter, step0, T0, top_k, sym=False)` | Runs one continuation‑gradient run (with optional symmetry). Returns the best `(h, C5)` seen. |
| `local_swap_search(h, c5, time_limit)` | Pair‑swap hill‑climber described in §5. |
| `run(seed=42, budget_s=600, **_)` | Orchestrates the whole pipeline: coarse → up‑sample → many restarts → local polishing → return best vector, its bound, and `n`. |

All FFT‑based work uses `np.fft.rfft`/`irfft` for speed; the correlation length is
`L = 2*n-1`.  The cost of a single `corr_fft` call on `n=120` is < 0.001 s,
so even 30 000 gradient iterations fit comfortably inside the 600 s budget.

### 8.  Expected outcome & failure handling

*Why should this beat the previous bound?*

* The **smooth‑max continuation** supplies a directed descent direction that
  simultaneously reduces *all* large correlation peaks, whereas the previous
  evolutionary code could only improve one candidate at a time.
* **Top‑K gradient aggregation** focuses effort on the dominant shifts while
  remaining cheap.
* **Symmetry enforcement** halves the search space and aligns with the
  conjectured shape of the optimal solution (empirically the best known
  constructions are symmetric).
* **Multi‑scale start** supplies a high‑quality basin for the fine‑grid optimiser,
  avoiding many poor local minima.
* **Pair‑swap local search** exploits the linear equality constraint exactly,
  allowing rapid fine‑tuning beyond what continuous gradient steps can achieve
  (they are limited by the projection step).

If, despite all this, the algorithm stalls at \(C_5\approx0.3810\), the
fallback is simply to return the *best* vector obtained (the code always
stores it).  The projected gradient/D‑continuation method is robust; even a
single run usually reaches a bound < 0.3810 within a few seconds, leaving ample
budget for extra restarts and polishing.

--------------------------------------------------------------------
### 9.  Summary of the workflow (what `run` will do)

1. **Initialisation** – set random seed, compute `dx`, `target_sum = n/2`.
2. **Coarse phase** (`n=60`) – a short gradient‑descent run from a random start.
3. **Upsample** the coarse best vector to the main resolution (`n=120` or `150`).
4. **Global optimisation** – launch 10‑15 independent gradient‑descent restarts
   (mix of fully random, symmetric random, and the triangular seed).  Each restart
   performs the continuation schedule described above, records the best exact `C_5`.
5. **Local refinement** – run the pair‑swap hill‑climber on the globally best
   candidate for the remaining time.
6. **Final projection & evaluation** – enforce feasibility one last time,
   compute the exact `C_5` with `evaluate_c5_fast`, and return  
   `(h.tolist(), float(C_5), n)`.

All steps are pure NumPy/FFT operations, respect the 600 s limit, and require
only a single CPU core.  The algorithm’s design (smooth‑max gradient,
top‑K focus, symmetry, multiscale seeding, and swap polishing) is substantially
different from the earlier evolutionary approach, giving a strong chance of
producing a tighter upper bound (target ≤ 0.3807).
