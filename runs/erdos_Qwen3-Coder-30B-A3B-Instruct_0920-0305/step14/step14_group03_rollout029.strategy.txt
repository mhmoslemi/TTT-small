**1. Problem reformulation**

For a uniform grid of `n` points on [0,2] with spacing `Δ = 2/n` let  

* `h ∈ ℝⁿ` be the step heights, 0 ≤ hᵢ ≤ 1, and  
* `t = Σᵢ hᵢ = 1/Δ = n/2` (the integral constraint).

Define the auto‑correlation for shift `s∈{-(n‑1),…,n‑1}`

```
C_s(h) = Σ_i h_i · h_{i+s}                     (indices outside [0,n‑1] are ignored)
```

The overlap for the same shift is  

```
O_s(h) = Δ·( t – C_s(h) )
```

so the objective is  

```
C₅ = max_s O_s(h) = Δ·( t – min_s C_s(h) ).
```

Thus *minimising* `C₅` is *maximising* the minimal auto‑correlation `min_s C_s`.  
This gives a natural **min–max feasibility formulation**:

```
find h            s.t.   0 ≤ h ≤ 1,   Σ h = t,
                     C_s(h) ≥ τ   for every shift s,
```

where `τ = t – C₅/Δ`.  For a trial value `C`, the feasibility condition becomes  

```
C_s(h) ≥ t – C/Δ   (∀ s).
```


---

**2. Linearisation of the bilinear terms**

Introduce a new variable `w_{i,j}` for each product `h_i·h_j` that actually appears in some correlation (i.e. for each admissible pair `(i,i+s)`).  
Use *McCormick envelope* linear constraints (exact for binary variables, a tight relaxation for `[0,1]` variables):

```
w_{i,j} ≥ 0,
w_{i,j} ≤ h_i,
w_{i,j} ≤ h_j,
w_{i,j} ≥ h_i + h_j – 1.
```

Now each correlation is a **linear** expression:

```
C_s(h) = Σ_i w_{i,i+s}.
```

Hence the whole problem is a **pure linear feasibility system** once a candidate `C` is fixed.

---

**3. Bisection on the unknown bound**

The optimal value `C*` lies between 0 and 1.  
Perform a binary search on `C`:

```
low  = 0.30                # known to be infeasible
high = 0.40                # known feasible (previous record)
while high – low > ε:      # ε = 1e‑4 for the target precision
    Cmid = (low + high)/2
    solve linear feasibility problem with RHS = t – Cmid/Δ
    if feasible:
        high = Cmid;       # we have found a valid upper bound
        store the corresponding h as a candidate
    else:
        low = Cmid
```

Because the constraints are linear, any LP solver can be used (`cvxpy` with CBC/GLPK/ECOS).  
The problem size is modest for `n≈80`:
* Variables: `n` for `h` plus ≈ `n·(2n‑1)/2` for the products `w`.  
  For `n=80` this is ~3 200 `h`‑`w` pairs, well within memory limits.  
* Constraints: a few per `w` (the 4 McCormick inequalities) plus one sum constraint,
  one box per `h`, and one for each shift (`2n‑1`).

The LP solves in a fraction of a second; a full bisection (≈ 12 iterations) comfortably fits into the 600 s budget.

During bisection only `rhs.value` changes, so the solver can reuse the problem structure and warm‑start, dramatically reducing total runtime.

**5. Extracting a feasible step function**

When a feasible LP is found for a given `Cmid`, the solver returns concrete values for `h`.  
These are already within `[0,1]` and satisfy `Σ h = t` up to numerical tolerance.  
Apply a *final Euclidean projection* (`clip` + binary search for the Lagrange multiplier) to enforce the sum exactly and eliminate any tiny drift.

The obtained `h` is guaranteed (modulo the McCormick relaxation) to realise an overlap no larger than `Cmid`.

**6. Tightening the relaxation (optional SDP)**  

The McCormick relaxation may be loose. A tighter convex relaxation is obtained by lifting `h` to a matrix `X = h·hᵀ` and imposing `X ≽ 0`.  
The constraints become:

```
X_{ii} = h_i,
0 ≤ X_{ij} ≤ min(h_i, h_j),
X_{ij} ≥ h_i + h_j – 1,
Σ_i X_{i,i+s} ≥ t – C/Δ    (∀ s).
```

This is a **semidefinite program** (SDP).  
Solve it with `cvxpy` + `SCS` or `PDLP`.  
If the SDP is feasible, extract a rank‑1 approximation of `X` (eigenvector of the largest eigenvalue) to obtain a high‑quality `h`.  
The SDP provides a *tighter* lower bound on the optimum; the resulting `h` is an excellent seed for the next stage.

---

**7. Refinement with a deterministic sub‑gradient step**

Take the LP (or SDP‑derived) `h` as a starting point and perform a *few* iterations of a **projected sub‑gradient method** that works directly on the original non‑convex objective:

1. Compute all correlations `C_s` via FFT (cost `O(n log n)`).
2. Identify the **worst shift(s)** `S = {s | O_s = max O}`.
3. The sub‑gradient of `max_s O_s` at `h` is the average of the gradients of the active constraints:

```
g_i = –Δ· (1/|S|)· Σ_{s∈S} ( h_{i+s} + h_{i–s} ).
```

4. Update `h ← h – η·g` with a small step size `η` (e.g. 1e‑3), then project onto the capped simplex (same binary‑search projection as before).
5. Repeat for a few hundred iterations (the “few” is enough because we start already near a stationary point).

Because the sub‑gradient uses the **exact** derivative of the *true* max (no soft‑max smoothing), this fine‑tunes the solution without the approximation error of the earlier algorithm.

*Fine level:* Upsample the resulting `h` to a larger grid (e.g. `n = 200`) by linear interpolation, clip, and re‑project.

| Possible issue                                 | Mitigation                                                                                              |
|-------------------------------------------------|----------------------------------------------------------------------------------------------------------|
| **Too many product variables** (n > 120)        | Keep the LP stage at `n ≤ 80`. Use the coarse solution only as a seed for finer grids where only the sub‑gradient step is needed. |
| **LP infeasibility due to relaxation gap**      | After an infeasible LP, increase the candidate `C` by a tiny margin (e.g. +1e‑4) and retry; or switch to the SDP relaxation which is tighter. |
| **Numerical tolerance causing slight violation**| Add a marginal safety slack (`+1e‑6`) to the RHS of the correlation constraints before solving the LP. |
| **Solver time‑out**                             | Use CBC/GLPK (fast for modest sizes) or, if available, a commercial MILP solver (Gurobi, MOSEK). Reduce `n` for the LP stage. |
| **Stagnation in sub‑gradient phase**           | Reduce the step size `η` geometrically, inject a small random jitter (Gaussian, σ≈1e‑4) and re‑project to escape flat regions. |

All heavy steps (FFT, gradient assembly, projection) are `O(n log n)` or `O(n²)` with very small constants; the total runtime stays well below the 600 s budget.
