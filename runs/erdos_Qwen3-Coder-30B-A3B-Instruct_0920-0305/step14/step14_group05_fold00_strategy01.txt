**Goal** – Produce a step‑function `h` (discretised on a uniform grid) whose
overlap constant  

\[
C_5(h)=\max_{k}\int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx
      =\frac{2}{n}\max_{s\in\{-n+1,\dots,n-1\}}
        \sum_{i=0}^{n-1}h_i\bigl(1-h_{i+s}\bigr)
\]

is as small as possible, while  
\(0\le h_i\le1\) and \(\sum_i h_i=n/2\) (the integral‑constraint).

The previous code used a *soft‑max* gradient and a few hand‑crafted
re‑allocation tricks.  To obtain a genuinely different optimisation
strategy we replace this deterministic sub‑gradient descent by a **global
stochastic search (simulated annealing)** that directly respects the
linear constraints, and we refine the result with a short *exact*
sub‑gradient descent.  The algorithm works on a **multi‑resolution
schedule** (coarse → fine grid) so that the search space is explored
first with few degrees of freedom and then refined.

### 2. Simulated annealing on a fixed grid size

**Overview** – The state is a vector `h` that already satisfies both constraints
(`0≤h≤1` and sum = `target`).  A *move* transfers a small amount of mass
δ from one coordinate `i` to another coordinate `j`.  Because the transfer
preserves the total sum, no projection is required after the move; we only
clip the two entries to stay inside `[0,1]`.  This guarantees that every
candidate automatically satisfies the constraints.

**Move generation**
1. **Random transfer** – pick two distinct indices `i, j` uniformly.
   Choose a maximal allowed transfer `Δ` (initially ~0.1).  
   Draw `δ = uniform(0, Δ)`.  
   If `h_i ≥ δ` and `h_j ≤ 1‑δ` accept the proposal `h_i←h_i‑δ`, `h_j←h_j+δ`.  
   Otherwise reject the proposal and draw new `i,j,δ`.
2. **Targeted transfer (30 % of moves)** – compute the *worst shift* `s*`
   (using `corr_fft`).  For each index compute a *desirability*
   `d_i = h_{i+s*}+h_{i‑s*}` (the larger `d_i`, the more the neighbour sum
   exceeds 1).  Pick `i` among the **lowest 20 %** of the `d`‑values
   (those that currently hinder the overlap) and pick `j` among the **highest
   20 %**.  Transfer a random `δ` (still bounded by the box limits).
   This bias pushes mass toward positions that improve the worst overlap.

**Acceptance rule (Metropolis)**
* Let `C_old = C5_value(h)`.
* Compute `C_new` for the proposed state (fast FFT – O(n log n)).
* If `C_new ≤ C_old` → accept.
* Else accept with probability `exp( -(C_new‑C_old) / T )`,
  where `T` is the current temperature.

**Cooling schedule**
* Initialise temperature `T₀ = 0.02` (a few % of the typical `C` value).
* After each *accepted* move (or after a fixed number of trials) update  
  `T ← α·T` with `α = 0.9997`.  This yields ≈ 3000‑4000 temperature steps
  before `T` becomes ≈ 10⁻⁶, after which only improving moves survive.
* Simultaneously shrink the transfer limit: `Δ ← Δ·β` with `β = 0.9999`.
  This makes later moves fine‑grained, helping the algorithm settle.

**Restart & time management**
* The annealing loop runs until either a pre‑allocated iteration budget
  (e.g. 80 % · budget / stage) is exhausted, **or** the wall‑clock time
  reaches its stage limit.
* Keep the best ever seen vector `best_h_stage` and its `best_C_stage`.
* When the loop ends, perform a *short deterministic polishing* (see §3)
  starting from `best_h_stage`.  The polished result becomes the candidate
  that is handed to the next resolution stage.

### 3. Deterministic polishing – exact sub‑gradient descent

After the stochastic phase the current vector is already good but may
still be off the local optimum because the annealer accepts occasional
worsening moves.  A **few hundred** iterations of a plain projected
sub‑gradient descent quickly clean the remaining slack.

**Iteration**
1. Compute the correlation vector `c = corr_fft(h)`.  
   Determine the set `S = {s | c_s ≥ max(c)‑ε}` with a tiny tolerance
   `ε = 1e‑12`.  (Usually `|S| = 1`.)
2. For each `s∈S` compute the sub‑gradient `g_s = gradient_worst(h, s)`.  
   Average them: `g = (1/|S|) Σ g_s`.
3. Choose a diminishing step size, e.g. `η = η₀ / sqrt(k+1)`, with
   `η₀ = 0.5`.
4. Update `h ← h – η·g`.
5. Project onto the box‑sum intersection with `project_to_sum_box`.
6. If the new objective improves the global best, store the copy.

Run this loop for at most `N_polish = 2000` iterations or until the wall‑clock
budget for the current stage is exhausted.  The method is cheap (one FFT
per iteration, O(n log n)) and converges quickly because the worst shift
is usually the same for many successive steps.

### 4. Multi‑resolution schedule

The problem is smoother when the grid is coarse; a good coarse solution
guides the finer search.  The schedule uses three stages:

| Stage | Grid points `n` | Time‑fraction of total budget |
|-------|-----------------|------------------------------|
| 1 (coarse) | 80 | 0.30 |
| 2 (medium) | 160 | 0.35 |
| 3 (fine)   | 240 | 0.35 |

**Procedure for a stage**

1. **Initial vector**  
   *Stage 1*: Random uniform `[0,1]` → project.  
   *Later stages*: `interpolate(best_h_previous, n)` → project.

2. **Simulated annealing** – run as described in §2, using the stage‑specific
   `T₀`, `Δ`, and iteration budget (chosen so that the total wall‑clock time
   respects the allocated fraction).

3. **Polishing** – execute the sub‑gradient loop (§3) for a few thousand
   iterations.

4. **Record** – keep the best vector of the stage (`best_h_stage`,
   `best_C_stage`).  This becomes the seed for the next higher‑resolution
   stage after interpolation.

If during any stage the wall‑clock time exceeds its allocated budget,
the algorithm aborts the remaining inner loops, returns the best vector
found so far, and proceeds to the next stage (or to final output).

### 7. Failure‑mode mitigations

| Potential problem | Mitigation |
|-------------------|------------|
| **Too many rejected moves** (temperature too low) | Start with a relatively high `T₀`, reduce `α` slowly; also keep a fallback random restart if acceptance ratio falls below 1 % for a large window. |
| **Numerical drift out of `[0,1]`** | After every accepted move clip the two modified entries; after polishing, always re‑project with `project_to_sum_box`. |
| **FFT overhead** | Grid sizes are ≤ 240 → FFT length ≤ 479, negligible (< 0.2 ms). |
| **Running out of wall‑clock time** | Each stage monitors `time.time()` and aborts inner loops as soon as the allocated fraction is exhausted. |
| **Stuck in a poor local optimum after annealing** | The targeted mass‑transfer moves deliberately focus on the worst shift, forcing progress; additionally, a final polishing run guarantees descent from the current point. |
| **Interpolation artefacts** | After interpolation immediately re‑project onto the box‑sum set, removing any small violations. |

### 8. Summary of the algorithmic pipeline (pseudo‑code outline)

```
run(seed, budget_s):
    set RNG seed
    start = time()
    define make_stage(n, time_fraction):
        # 1. initialise
        if first stage:
            h = random_uniform(0,1,n) -> project
        else:
            h = interpolate(prev_best_h, n) -> project
        best_h_stage = h; best_val = C5_value(h)

        # 2. simulated annealing
        T = 0.02; Δ = 0.1
        while time() < start + allocated_time and iter < max_iter:
            if random()<0.3:   # targeted move
                s = worst_shift(corr_fft(h))
                d = h_plus(s)+h_minus(s)
                i = random_low_desirability(d)
                j = random_high_desirability(d)
            else:               # pure random move
                i,j = two distinct random indices
                Δ = min(Δ, h[i], 1-h[j])
            δ = uniform(0, Δ)
            propose h' by moving δ from i to j
            val' = C5_value(h')
            if val' < current or rand()<exp(-(val'-current)/T):
                h = h'; current = val'
                if val' < best_val: store best_h_stage
            update T and Δ
        # 3. polishing
        for k in range(N_polish):
            compute worst shift set, gradient, step η
            h = project_to_sum_box(h - η*grad, target_sum)
            update best_h_stage if improved
        return best_h_stage, best_val

    # run three stages with n = 80, 160, 240
    best_h, best_val = make_stage(80, 0.30)
    best_h, best_val = make_stage(160, 0.35)
    best_h, best_val = make_stage(240, 0.35)

    return best_h.tolist(), float(best_val), len(best_h)
```
