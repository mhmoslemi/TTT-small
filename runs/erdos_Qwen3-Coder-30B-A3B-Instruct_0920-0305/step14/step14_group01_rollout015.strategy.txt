`0 ≤ 0.5 + Ĉ·a ≤ 1`.  

These are `2·G` linear inequalities in `a`.  
Because `M≈15` and `G≈1000`, they can be processed instantly.

**Penalty formulation** (used during L‑BFGS‑B):  
`pen(a)=ρ·∑_j max(0, -ĥ_j)² + ρ·∑_j max(0, ĥ_j‑1)²` with a large `ρ` (e.g. `10⁴`).  
The penalty is differentiable and its gradient is `2ρ·Cᵀ·r`, where `r` holds the violated amounts.

**Projection (post‑optimisation)**:  
If after optimisation `a` violates any inequality, solve a small QP  
`min ‖a−â‖₂  s.t. 0 ≤ 0.5+Ĉ·a ≤ 1`  
using `cvxpy` with the `ECOS` solver (tiny problem, negligible time).  
The projected `a` yields a feasible `h`.

---

### 3. Smooth max‑overlap objective

For any `a` we compute the discretised `h = 0.5 + C·a`.  
Define `b = 1 - h`.  
Let `L = 2·n−1`.  
Using FFT:
```
h_rev = h[::-1]
corr = ifft( fft(h_rev, L) * fft(b, L) ).real
I = dx * corr                # vector of overlap integrals for all shifts
```

The true objective is `max(I)`.  
We replace it by the **log‑sum‑exp** smooth max:
```
f_ε(a) = ε * log( Σ_j exp( I_j / ε ) )
```
When `ε → 0` we recover `max(I)`; moderate `ε` gives a smooth landscape amenable to gradient‑based optimisation.

---

### 4. Gradient of the smooth objective

Let `w_j = exp( I_j / ε ) / Σ_k exp( I_k / ε )`.  
Then `∂f_ε/∂a = Σ_j w_j ∂I_j/∂a`.

*Derivative of a single overlap* `I_j` w.r.t. `a`:
```
I_j = dx Σ_i h_i (1 - h_{i+j})                     (indices out‑of‑range are ignored)
∂I_j/∂a = dx [ Σ_i (∂h_i/∂a) (1 - h_{i+j})  -  Σ_i h_i (∂h_{i+j}/∂a) ]
```
Because `∂h/∂a = C`, the two sums are *convolutions* of the cosine matrix with `b` and `h`.  

Efficiently compute:
* `g1 = Cᵀ· (b shifted by +j)`   → use FFT convolution of `C` columns with `b`.
* `g2 = Cᵀ· (h shifted by -j)`   → similar.

Implement a vectorised routine:
```
# full convolution of each column of C with b and with h
conv_b = fft_convolve_columns(C, b)   # shape (M, L)
conv_h = fft_convolve_columns(C, h)   # shape (M, L)
# For shift j (index j0 = j + n-1) take column j0 from each
grad_Ij = dx * ( conv_b[:, j0] - conv_h[:, j0] )
```
Thus the weighted sum `∂f_ε/∂a = Σ_j w_j grad_Ij` is obtained by a single matrix‑vector product:
```
grad_f = dx * ( Cᵀ * ( w * b_convolved ) - Cᵀ * ( w * h_convolved ) )
```
All operations are `O(M·L·log L)`, negligible for `M≈15`, `L≈400`.

Add the gradient of the penalty term (straightforward linear expression) to obtain the total gradient used by L‑BFGS‑B.

### 5. Optimisation workflow

1. **Choose parameters**:  
   * `n = 200` (grid size).  
   * `M = 12` cosine terms (enough flexibility).  
   * `G = 5·n = 1000` validation points.  
   * Penalty weight `ρ = 10⁴`.  

2. **Initial guesses** (run several independent trials):  
   * **Zero start** (`a = 0` → `h ≡ 0.5`).  
   * **Cosine‑square start**: the known optimal shape `h(x) = (1+cos(π(x‑1)))/2` corresponds to a single coefficient `a₁ = -0.5`.  
   * **Randomised start**: draw `a_m ∼ N(0, σ²)` with `σ = 0.2` and project onto the feasible polytope via the QP described in §2.  
   * **Projection of the previous discrete best**: solve a least‑squares fit `min‖0.5 + C·a − h_prev‖₂` subject to the box constraints, obtain a feasible `a`.  

3. **Continuation on ε**:  
   * Stage 1: `ε₁ = 0.1`.  
   * Stage 2: `ε₂ = 0.05`.  
   * Stage 3: `ε₃ = 0.02`.  
   * Stage 4: `ε₄ = 0.01`.  
   * Stage 5: `ε₅ = 0.005`.  
   * Stage 6: `ε₆ = 0.001`.  

   For each stage, run L‑BFGS‑B starting from the solution of the previous stage (warm start).  
   L‑BFGS‑B settings:  
   * `maxiter = 400` (per stage).  
   * `gtol = 1e‑8`.  
   * Bounds on each coefficient: `[-1, 1]` (sufficiently wide).  

4. **Feasibility enforcement**: after each L‑BFGS‑B call, project `a` onto the linear box constraints (solve the tiny QP).  This guarantees that the final `h` respects `0 ≤ h ≤ 1` on the dense grid; the final `h` on the actual `n` points will automatically satisfy the integral constraint (constant term already ensures it).

5. **Evaluation of true C₅**: once a stage finishes, compute the *exact* max overlap using the original non‑smoothed correlation (full FFT) on the `n`‑point vector and store the best `h` found so far.

6. **Multiple restarts**: repeat the whole ε‑continuation **five times** with the different initial guesses.  Keep the globally best `h`.

7. **Final discrete polishing** (optional, ≤ 30 s):  
   * Start from the best `h` (full `n`‑point vector).  
   * Perform a **pairwise mass‑swap Simulated Annealing**:
        - Choose two indices `i, j`.  
        - Propose `δ ∈ [‑δ_max, δ_max]` (e.g. `δ_max = 0.02`).  
        - Set `h_i' = clip(h_i+δ,0,1)`, `h_j' = clip(h_j−δ,0,1)`.  
        - Adjust the whole vector by the projection onto the sum‑box (fast binary‑search λ).  
        - Accept if `C₅` decreases, otherwise accept with probability `exp(-(Δ)/T)` where temperature `T` decays geometrically.  
   * Run for a fixed number of iterations (e.g. `10 000`) or until the time budget is exhausted.

8. **Return** the final vector `h` (as a Python list), the exact `C₅` value, and `n`.

### 6. Numerical choices & implementation notes

| Item | Choice | Rationale |
|------|--------|-----------|
| `n` (grid points) | 200 (dx = 0.01) | Small enough for fast FFT, fine enough to capture smooth cosine shapes and to reduce discretisation error. |
| `M` (cosine terms) | 12–15 | Provides enough degrees of freedom to approximate the optimal shape while keeping the optimisation low‑dimensional. |
| Validation grid `G` | 5·n = 1000 | Guarantees that box constraints are respected everywhere (linear constraints dense enough). |
| Penalty weight `ρ` | 10⁴ – 10⁵ | Sufficient to push iterates into the feasible region without overwhelming the smooth objective. |
| ε‑schedule | 0.1 → 0.05 → 0.02 → 0.01 → 0.005 → 0.001 | Larger ε smooths the landscape; decreasing ε gradually refines the max while staying in the basin of a good solution. |
| L‑BFGS‑B maxiter per ε | 300–400 | Empirically enough for convergence on a 12‑dimensional problem; total cost negligible. |
| Restarts | 5 (including deterministic cos‑square start) | Provides diversity and avoids being trapped in local minima. |
| Time allocation | 70 % for Fourier‑L‑BFGS‑B (including all ε‑stages and restarts), 30 % for final discrete annealing. | Guarantees that the heavy‑lifting part finishes well before the deadline, leaving room for polishing. |

**Potential failure modes & safeguards**

* *Infeasible intermediate `a`*: the penalty may not be strong enough; after each L‑BFGS‑B iteration we check feasibility on the dense grid and, if violations exceed a tiny tolerance (`1e‑8`), we immediately project using the QP. This keeps the optimizer inside the feasible region.

* *Gradient explosion for very small ε*: we never let ε go below `0.001`. If the algorithm stalls, we fall back to a larger ε for a few extra iterations and then retry the smaller ε.

* *Numerical drift of the integral*: the constant term guarantees the continuous integral, but discretisation error may cause a tiny sum mismatch. After the final projection onto the sum‑box (binary‑search for λ), the discrete sum is forced to the exact target `n/2`.

* *Local minima*: the continuation on ε and the assortment of starting points (including the analytically derived cosine‑square shape) greatly reduce this risk. The final annealing stage can escape shallow basins.

* *CPU time*: All heavy operations are `O(n log n)` (FFT) or `O(M·L)` (gradient assembly). With `n=200`, `M=15` the total runtime per L‑BFGS‑B call is < 0.02 s, leaving ample time for the prescribed number of restarts and ε‑stages.

### 7. Expected outcome

The cosine series is capable of reproducing the known near‑optimal “cosine‑square” shape and, thanks to the additional higher‑frequency terms, can fine‑tune the function to flatten the overlap profile across all shifts.  Empirically, similar low‑dimensional spectral optimisations for related min‑max problems have reduced the worst‑case value by a few × 10⁻⁴, which is enough to push `C₅` below the target `0.3807`.  

Because the optimisation works directly on the smooth surrogate of the max, it converges to a point where the *raw* max (computed after projection) is already very close to the smooth value, so the final polishing step typically yields only marginal improvements.
