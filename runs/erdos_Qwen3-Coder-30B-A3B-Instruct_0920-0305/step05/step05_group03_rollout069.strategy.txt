    - Use solver `GLOP` (Google's LP solver) for speed; fallback to `CBC` if not available.

    - Keep track of best feasible solution (lowest C5) discovered; after each iteration if the LP lower bound exceeds best feasible, we can prune.

13. *Time management*:

    - Allocate ~80 % of the budget to the cutting‑plane loop (LP solves + evaluation). Each LP resolution is cheap; we can afford up to 200 iterations.
    - The remaining ~20 % for the final projected gradient descent (or simple local swaps) to polish.

14. *Failure modes and mitigations*:

    - **LP relaxation too weak**: The O_k constraints may be far from actual; if the candidate h yields a C5 far larger than τ, many iterations may be needed. To accelerate, we can *tighten* McCormick envelopes by adding *binary partitions*: split each variable's domain into two intervals (e.g., [0,0.5] and [0.5,1]), add corresponding McCormick constraints per partition, which yields tighter relaxations at cost of extra binary variables (branch‑and‑bound). However for our moderate n we might not need this; the cutting‑plane will eventually include hard constraints for all worst shifts, effectively making the relaxation exact for those shifts.

    - **Solver time blow‑up**: As K grows, variable count increases linearly; but with n=44 and K≤20, total variables ≈ 44 + 20*44 = 924, constraints ≈ 44 (sum) + K (τ constraints) + 4 per y (McCormick) ≈ 44 + 20 + 4*44*20= 44+20+3520 = ~3584 – still manageable for LP solvers. If time gets high, we cap K at 30.

    - **Local refinement diverges**: Use backtracking line search and enforce step-size reduction; ensure projection onto feasible set after each step.

    - **Memory**: negligible.

15. *Why this will likely improve the bound*:

    - The cutting‑plane method directly enforces the *most violating* shift constraints, leading to a solution where the maximum overlap is *balanced* across many shifts. This is analogous to the optimal Chebyshev approximation principle (equioscillation), which often yields near‑optimal solutions for minimax problems. 

    - By solving the LP relaxation with exact linear constraints derived from McCormick envelopes, we guarantee that the eventual solution respects the *tightest possible* linear outer approximation of the product, narrowing the feasible region more aggressively than generic gradient descent.

    - The LP provides a *global lower bound* (τ) that can be used to gauge progress; we stop only when the feasible solution's true C5 is within a tiny gap of this bound.

    - The symmetry constraints reduce degrees of freedom, further improving the objective.

    - Empirically, analogous column‑generation approaches for aperiodic autocorrelation problems (e.g., designing low‑sidelobe sequences) have yielded bounds that beat naïve local optimisation.

Thus, this strategy is materially different: it leverages a **cutting‑plane / column generation linear programming relaxation using McCormick envelopes**, combined with symmetry reduction and a final projected gradient polish, rather than relying on smooth surrogate gradients or binary MILP alone.

**Goal** – Produce a step function `h` on `[0,2]` (discretised to `n` equally‑spaced points, `dx=2/n`) satisfying  

* `0 ≤ h[i] ≤ 1` for every `i`  
* `∑ h[i]·dx = 1`  (equivalently `∑ h[i] = n/2`)  

that minimises  

`C₅(h) = max_k  ∫ h(x)(1‑h(x+k))dx = max_k  (h ⋆ (1‑h))_k·dx`.

The previous attempts used smooth surrogates and plain local optimisation.  
The new plan attacks the problem from a **global linear‑programming relaxation with column generation**, followed by a brief **projected gradient polish**.  This is a completely different algorithmic paradigm: we iteratively enforce the most‑violated max‑overlap constraints using *McCormick linear envelopes* for the bilinear products, solve a pure LP at each step, and only after the LP has converged we perform a local refinement on the true (non‑smoothed) objective.

--------------------------------------------------------------------
### 1.  Reformulation as a MINLP with bilinear terms

For a fixed shift `k` (integer index `k∈{-(n‑1),…,n‑1}`) the overlap can be written discretely as  

```
O_k(h) = Σ_i h_i  –  Σ_i h_i·h_{i+k}      (zero‑pad out‑of‑range indices)
```

Hence the minimisation problem is  

```
minimise τ
subject to   O_k(h) ≤ τ      ∀k
             0 ≤ h_i ≤ 1    ∀i
             Σ_i h_i = n/2 .
```

The difficulty is the quadratic term `h_i·h_{i+k}`.  Introduce an auxiliary variable  

```
y_{i,k} ≈ h_i·h_{i+k}      (for every i,k with i+k in range)
```

and replace each product by its **McCormick convex envelope**, which is exact when `h_i, h_{i+k}` are binary and otherwise yields a tight linear over‑approximation:

```
y_{i,k} ≥ 0
y_{i,k} ≤ h_i
y_{i,k} ≤ h_{i+k}
y_{i,k} ≥ h_i + h_{i+k} – 1 .
```

With these linear constraints the problem becomes a **linear programme (LP)** in the variables `{h_i, y_{i,k}, τ}`; the LP is a *convex relaxation* of the original non‑convex problem.  Solving the LP provides a lower bound on the attainable `τ`.  The true objective for a candidate `h` is obtained later by evaluating the exact overlaps (using `np.correlate`) – this gives an *upper bound*.

--------------------------------------------------------------------
### 2.  Column‑generation / cutting‑plane loop

The LP contains a constraint `τ ≥ O_k(h)` for **every** shift `k`.  Adding all `2n‑1` constraints at once would blow up the model (≈ n² auxiliary `y` variables).  Instead we start with a tiny *active set* `K` of shifts (e.g. `{0, ±1}`) and **grow it only when necessary**:

1. **Initial model** – build the LP with the current active shift set `K`.  
   *Variables*: `h[0…n‑1]`, `τ`, and for each `k∈K` a vector `y_{:,k}`.  
   *Constraints*: box on `h`, sum constraint, symmetry `h_i = h_{n‑1‑i}` (optional but helpful), McCormick constraints for the current `y`, and `τ ≥ Σ_i h_i – Σ_i y_{i,k}` for each `k∈K`.

2. **Solve** the LP with a fast LP solver (`GLOP`, `CBC`, or `GLPK`).  The solution yields a feasible vector `ĥ` and a lower bound `τ̂`.

3. **Evaluate the true overlaps** for `ĥ`:
   - Compute `O_k(ĥ)` for **all** shifts `k` (via discrete correlation).
   - Find the worst shift `k* = argmax_k O_k(ĥ)` and the corresponding value `O_max`.

4. **Termination test** – if `O_max ≤ τ̂ + ε` (tiny tolerance, e.g. `ε=1e‑6`) then `ĥ` already satisfies all original max‑overlap constraints; we have a globally optimal solution for the current relaxation and can stop.

5. **Otherwise** – the LP has *under‑estimated* the true maximum.  Add the offending shift `k*` to the active set `K` (if not already present) and go back to step 1.  Adding a new shift introduces `n‑|k*|` new `y` variables and one more linear constraint `τ ≥ Σ_i h_i – Σ_i y_{i,k*}`.

Because each iteration adds only O(n) variables, the model stays modest (even after 20–30 iterations we have < 1 000 variables).  LP solves are a few milliseconds each, so thousands of iterations comfortably fit into the 600 s budget.

The loop implements the classic **cutting‑plane / column‑generation** scheme for minimax problems: we only enforce the constraints that are currently active (the worst overlaps).  This drives the solution toward the *equioscillation* pattern known to be optimal for Chebyshev‑type minimax problems.

--------------------------------------------------------------------
### 3.  Symmetry reduction

The objective and all constraints are invariant under the reflection `i ↔ n‑1‑i`.  Enforcing `h_i = h_{n‑1‑i}` reduces the number of decision variables by roughly a factor of two and sharply improves the bound because the optimum is known to be symmetric.  In the LP this is a simple set of linear equalities; after every LP solve we can also symmetrise the floating‑point `ĥ` by averaging with its reverse and re‑projecting (the projection step is described in Section 5).

--------------------------------------------------------------------
### 4.  Projection onto the capped simplex (used later)

When we later polish the solution we must maintain both box bounds and the sum constraint.  The Euclidean projection of a vector `v` onto  

```
S = { h | 0 ≤ h_i ≤ 1 ,  Σ h_i = n/2 }
```

is obtained by a one‑dimensional water‑filling search for a multiplier `λ`:

```
p_i(λ) = clip(v_i + λ , 0 , 1) .
```

Because `Σ p_i(λ)` is monotone in `λ`, a simple binary search (≈ 60 iterations) finds `λ` such that the sum equals `n/2`.  The resulting `p = clip(v+λ,0,1)` is the projected vector.  This operation is `O(n)` and will be called after every gradient step in the polishing stage.

--------------------------------------------------------------------
### 5.  Polishing stage – projected sub‑gradient descent on the true max

After the cutting‑plane loop terminates we have a **feasible** `h₀` whose true `C₅` is already low, but we can usually shave a few 10⁻⁴ more by a short local optimisation that works directly on the original nonsmooth objective.

Because `C₅(h) = max_k O_k(h)` is the pointwise maximum of a finite set of smooth functions, a sub‑gradient at `h` can be obtained by **averaging the gradients of the active shifts**:

* Let `A = {k | O_k(h) = C₅(h)}` be the set of maximising shifts.  
* For a fixed shift `k`, the gradient of `O_k` w.r.t. `h_i` is  

```
∂O_k/∂h_i = 1  –  ( h_{i+k} + h_{i−k} )   (out‑of‑range indices give 0)
```

* The sub‑gradient of `C₅` is  

```
g_i = (1/|A|) * Σ_{k∈A} ∂O_k/∂h_i .
```

All three terms are **convolutions**, so we compute them efficiently with `np.correlate` (cost `O(n²)`, negligible for n≈44).

**Descent step**:  

```
h_new = project( h – η·g )
```

with step size `η` chosen adaptively (initial `η = 0.5·dx`).  After each step we optionally **symmetrise** (`h_new ← (h_new + h_new[::-1])/2`) and re‑project.  If the true `C₅` does not improve for a few iterations we halve `η`.  The loop stops when the remaining time is < 5 % of the budget or when `η` becomes tiny.

Because we start from a point that already satisfies the worst‑shift constraints (up to the LP relaxation gap), only a modest number of gradient steps (≤ 2000) are required to reach the final bound.

--------------------------------------------------------------------
### 6.  Optional binary‑rounding and local swap improvement

Binary masks often achieve slightly better maxima because the objective favours extreme values (0 or 1).  From the polished continuous `h*` we can obtain a high‑quality binary candidate:

1. **Thresholding** – set the `n/2` largest components of `h*` to 1, the rest to 0.  
2. **Swap‑hill‑climbing** – repeatedly examine a pair `(i,j)` with `h_i=1, h_j=0`; compute the change in `C₅` if they are exchanged (the change can be evaluated by updating the correlation in `O(n²)`); accept the swap if it lowers `C₅`.  Continue until no improving swap exists.  

The binary solution is then evaluated; if it beats the continuous one we return it, otherwise we keep the continuous optimum.

   - Perform swap‑hill‑climbing until no improvement.  
   - Evaluate the binary `C₅`; if it improves the current best, replace `h_best`.

5. **Return**  
   - Output `(h_best.tolist(), C5_best, n)`.

### 8.  Expected performance and why it should beat the previous record

*The cutting‑plane LP* enforces exactly the worst overlap constraints and does so with a **global linear relaxation**; each iteration eliminates the most severe violation, driving the solution toward the *equi‑oscillating* pattern that is optimal for minimax problems.  This contrasts with the previous approach that relied on smoothing the max and local gradient descent, which can get stuck in a local basin.

*The McCormick envelope* provides the tightest possible linear over‑approximation of each bilinear term without introducing integer variables, keeping each sub‑problem an LP that solves in milliseconds.  Because the active set grows only as needed, the model remains small regardless of `n`.

*Symmetry reduction* halves the number of variables and forces the solution to live in the natural sub‑space, a property that earlier methods only applied heuristically.

*The final projected sub‑gradient polish* guarantees that any residual slack in the LP relaxation is removed, usually shaving a few 10⁻⁴ from the bound.  The optional binary swap phase can capture the occasional advantage of extreme values.

Overall, the algorithm explores the problem **globally** (through the LP lower bound) and **locally** (through gradient polishing), a combination not used in the earlier code.  The column‑generation strategy is well‑suited to minimax objectives and has been shown in related aperiodic autocorrelation problems to reach bounds tighter than those obtained by pure local search.  With `n≈44` the LPs are tiny; thousands of iterations fit comfortably within 600 seconds, giving ample opportunity to converge to a solution with `C₅ ≤ 0.3807` (and, with luck, below `0.3805`).  

Thus the proposed plan offers a mathematically grounded, computationally efficient, and fundamentally new route to a better upper bound for the Erdős constant `C₅`.
