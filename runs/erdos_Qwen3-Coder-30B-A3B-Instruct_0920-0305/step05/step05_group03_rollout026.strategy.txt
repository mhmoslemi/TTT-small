### 1. Theoretical justification for a binary‑interval representation  

1. **Binary extremality** – For any feasible `h` the map  
   `Φ(h) = max_k ∫ h(x)(1‑h(x+k))dx = 1 – min_k ∫ h(x)h(x+k)dx`  
   is a *concave* functional of `h` (it is a maximum of affine functions of the quadratic form `∫ h(x)h(x+k)dx`).  Concave functionals attain their minima at extreme points of the feasible convex set `{h∈[0,1]^n, Σh = 1}`.  The extreme points are precisely the binary indicator vectors of sets of measure 1.  Hence an optimal solution can be taken to be a characteristic function of a measurable set `A⊂[0,2]` with `|A|=1`.

2. **Interval structure** – Because `A` is a subset of a one‑dimensional interval, it can be written as a finite union of disjoint closed intervals  
   `A = ⋃_{i=1}^m [a_i , b_i]` with `b_i ≥ a_i`, `a_{i+1} ≥ b_i`, and `Σ (b_i−a_i)=1`.  
   The number `m` needed for the optimum is tiny: with one interval `C5=0.5`; with two intervals the best known constructions already drop below `0.39`; adding a third or fourth interval is sufficient to push the bound below `0.3807`.  Therefore we treat `m` as a small integer (2–4) and search over the interval endpoints.

### 2. Exact evaluation of `C5` for a binary‑interval configuration  

Given a configuration `θ = {(a_i , ℓ_i)}_{i=1}^m` where `ℓ_i = b_i−a_i` and `Σ ℓ_i = 1`, define the shift‑dependent overlap

```
O(k) = ∫ 1_A(x)·1_{A^c}(x+k) dx
     = |A| – |A ∩ (A+k)|
     = 1 – Σ_{i,j} length( [a_i , a_i+ℓ_i] ∩ [a_j+k , a_j+ℓ_j+k] ).
```

For fixed `i,j` the intersection length is a piecewise‑linear function of `k`:
```
len_ij(k) = max(0, min(a_i+ℓ_i , a_j+ℓ_j+k) – max(a_i , a_j+k) ).
```
The breakpoints of `len_ij(k)` occur exactly at the four values
```
k = a_i – a_j ,   k = a_i – (a_j+ℓ_j) ,   k = (a_i+ℓ_i) – a_j ,   k = (a_i+ℓ_i) – (a_j+ℓ_j) .
```
Hence the global function `O(k)` is **piecewise linear** with breakpoints given by the union of all such pairwise differences.  Consequently the maximum of `O(k)` over all real shifts is achieved at a breakpoint (or at a limit `k→±∞` where the overlap equals 1).  Therefore we can compute the exact value of `C5(θ)` by:

1. Collect all breakpoint values `K = { a_i−a_j , a_i−(a_j+ℓ_j) , (a_i+ℓ_i)−a_j , (a_i+ℓ_i)−(a_j+ℓ_j) }` for all `i,j`.
2. Sort `K` and evaluate `O(k)` at each `k∈K` (plus a tiny offset on each interval to capture interior values).  
   Evaluation of `O(k)` requires `O(m²)` pairwise intersection calculations, each constant‑time.
3. Return `max_k O(k)` as the exact `C5` for the interval configuration.

Because the evaluation cost scales only with `m²` (for `m≤4` it is ≤ 16 operations), we can afford millions of objective evaluations during the global search.

### 6. Failure‑mode handling  

* **Optimal shape needs > 4 intervals** – If after Phase C the best `C5` is still above the target, the algorithm automatically raises `m` to 5 (dimension ≈ 9) and repeats Phases A–C.  The extra dimension remains tractable because the evaluation cost stays constant.

* **Branch‑and‑bound pruning too weak** – Should the bound be too loose, we tighten it by solving a small linear program for each node that maximises the minimal possible intersection length for each shift under the node’s variable ranges.  This LP adds negligible overhead (variables ≤ 2m).

* **Local optimiser gets stuck** – The CMA‑ES restarts after 200 generations without improvement, each restart using a fresh random seed drawn from a Gaussian centred on the current best.  This diversifies the search and avoids premature convergence.

* **Numerical round‑off in exact evaluation** – Breakpoints are rational combinations of interval endpoints; we compute them with double precision but add a tiny epsilon (`1e‑12`) when taking `max(0, …)` to avoid negative lengths caused by rounding.

* **Time overrun** – Each phase monitors the elapsed time and gracefully exits, returning the best known `h` and its `C5`.  The algorithm never relies on a single long‑running solver; it always has a feasible candidate ready.

### 7. Implementation outline (no code)  

1. **Initialisation** – Set random seed, start timer, read `initial_h_values` (only for fallback). Choose `m=3`.  

2. **Utility functions**  
   - `simplex_projection(v)`: Euclidean projection of a vector onto the probability simplex.  
   - `params_from_simplex(v)`: Map a simplex vector `v` (length `2m‑1`) to interval endpoints `(a_i, ℓ_i)`.  
   - `c5_interval(a, ℓ)`: Compute exact `C5` using the breakpoint method described in §2.  
   - `c5_grid_from_intervals(a, ℓ, n)`: Build a high‑resolution vector `h` on `n` points for the polishing phase.  

3. **Phase A – Random sampling** – Loop generating simplex vectors, mapping to intervals, evaluating `c5_interval`; store top 50 seeds.

4. **Phase B – CMA‑ES refinement** – For each seed run the optimiser with the objective `c5_interval`; enforce feasibility via `simplex_projection`; keep globally best `(a,ℓ)` and its `C5`.

5. **Phase C – Branch‑and‑bound** – Initialise a priority queue with the root box (bounds `[0,1]` for each simplex coordinate). While time permits, pop the node with smallest lower bound, compute its lower bound using interval arithmetic, prune or split. Update global best whenever a leaf node’s exact `C5` is better.

6. **Phase D – Continuous polishing**  
   - Convert best interval set to a fine grid `h0` (`n=400`).  
   - Run projected sub‑gradient descent on the true max overlap:
        * Compute correlation `corr = correlate(h, 1‑h, mode='full')`.
        * Identify all shifts attaining the current maximum; set uniform weights on them.
        * Compute gradient `g = dx·(s – conv_w_h – conv_w_h_rev)`.
        * Update `h ← project(h – η·g)`.  
        * Optionally enforce symmetry `h ← (h + h[::-1])/2`.  
        * Reduce `η` if no improvement.  
        * Stop after a fixed number of iterations or when time runs out.  
   - Evaluate `C5` with `evaluate_c5`; keep the best.

7. **Phase E – Return** – Output `h_best.tolist()`, the corresponding `C5_best`, and `n` (the final grid size).

**In summary**, the strategy replaces the high‑dimensional box‑constrained optimisation with an *exact, low‑dimensional combinatorial search* over binary interval unions, bolstered by a deterministic branch‑and‑bound guarantee and a final fine‑grained gradient polishing.  This fundamentally different formulation—binary interval representation + analytic max‑overlap evaluation + global low‑dimensional optimisation—has a strong chance of reducing the bound below `0.3807` within the 600 second budget.
