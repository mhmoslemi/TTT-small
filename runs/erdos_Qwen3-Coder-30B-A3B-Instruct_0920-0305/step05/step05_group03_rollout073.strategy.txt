  By construction \(s^{(t+1)} \le s^{(t)}\); the algorithm is monotone.

### 5. Iteration & Convergence

Repeat the linearisation‑LP cycle:

```
t = 0
h = initial feasible vector (see §6)
s = +∞
while time < budget and improvement > tol:
    compute gradients g_r = 2 B_r h
    build affine lower bounds ℓ_r
    solve LP → (h_new, s_new)
    if s_new < s - tol:
        accept h = h_new, s = s_new, t += 1
    else:
        break
```

* **Stopping tolerance** `tol = 1e-7` (in the original objective scale).  
* **Maximum iterations** per run ≈ 2000 (far below the time limit).  
* The algorithm usually converges within a few dozen iterations; extra
  iterations simply confirm optimality.

---

### 6. Generating *Diverse* Starting Points

Because the LP is convex after linearisation, the only source of non‑convexity
is the linearisation itself.  Different initial vectors lead to different
tangent planes and thus to distinct local minima.  We therefore launch several
independent runs, each with a different seed:

1. **Uniform start** – `h_i = 0.5` (after projection onto the capped simplex).
2. **Random start** – draw `h_i` uniformly in `[0,1]`, then project to satisfy
   the sum constraint and symmetry.
3. **Binary start** – create a balanced binary sequence (e.g., from a Gold code
   of length `n` or a simple alternating pattern) and treat it as the initial
   `h`.
4. **Upsampled previous best** – take the `initial_h_values` (length 42),
   interpolate linearly to length `n`, project onto the feasible set.
5. **Spiked start** – concentrate mass in a narrow region (a “spike”) while
   keeping the rest near zero; enforce symmetry.

For each start we run the CCP‑LP procedure described in §5.  The best `(h,s)`
found across all runs is kept as the current global best.

---

### 7. Post‑Processing Refinement (Optional)

The linearised model may be slightly conservative because each iteration uses a
first‑order lower bound of the quadratic term.  After the CCP loop terminates we
can perform a *local polishing* step:

* Run a few iterations of the **smooth‑max gradient descent** from §4 of the
  previous solution (or a brief `SLSQP` call) using the final `h` as start.
* Enforce the constraints by projection onto the capped simplex (as in the
  previous algorithm) after each gradient step.
* This polishing often yields a modest reduction (≈ 0.0001–0.0003) in the true
  `C5` value.

Because the polishing phase consumes only a few hundred milliseconds, it safely
fits within the remaining budget.

---

### 8. Evaluation & Return

* The objective value reported to the competition is the **true max overlap**
  `C5 = evaluate_c5(h)` (the unsmoothed max).  
* Throughout the search we keep the smallest `C5` ever observed.
* When the time budget (`budget_s`) is about to expire (e.g. 97 % elapsed) we
  stop any ongoing optimisation round, return the best candidate found so far,
  and exit gracefully.

The returned tuple is `(h.tolist(), C5_best, n)` as required.

### 11. Failure Modes & Mitigations

| Failure mode | Symptom | Mitigation |
|--------------|---------|------------|
| LP becomes ill‑conditioned (very flat gradients) | Solver stalls, returns status “optimal_inaccurate”. | Add a tiny regularisation term `ε·∑h_i` to the objective (does not affect the bound) or increase solver tolerance. |
| Linearisation stalls prematurely (no improvement) | `s` stops decreasing after a few iterations. | Restart from a different random seed; increase `max_iter` per run; optionally switch to a *second‑order* linearisation (add a quadratic term using the Hessian of the concave part). |
| Symmetry enforcement causes infeasibility for odd `n`. | No feasible solution satisfying both sum and symmetry. | Use an *odd* `n` only when the symmetry condition is relaxed (drop symmetry for that run). |
| Time budget exhausted before any run finishes | Early exit with no feasible candidate. | Ensure a **fallback**: if no CCP run completes, return the *uniform* feasible vector (`h_i = 0.5`) – its `C5` is ≈ 0.5, which is a valid (though weak) bound. |
| Random rounding after LP relaxation yields worse `C5`. | Post‑processing produces higher overlap. | Do not rely on rounding for the final bound; the LP solution itself is already feasible (it satisfies all original constraints) because the affine lower bound is exact at the current point. Rounding is only used for generating diverse starts, not for the final answer. |

### 12. Summary of the Workflow

1. **Initialisation** – choose `n`, build symmetric Toeplitz matrices `B_r`, decide on symmetry.
2. **Generate** a batch of diverse feasible starting vectors (uniform, random,
   binary, upsampled, spiked) and project each onto the capped simplex while
   enforcing symmetry.
3. For each start:
   * Run the **concave‑convex linearisation loop** (LP at every iteration) until
     convergence or time out.
   * Record the best `(h,s)` obtained (note: `s` is a certified upper bound on
     the true max‑overlap).
4. **Optional polishing** – from the best `h` feed a few gradient‑descent or
   SLSQP steps with projection.
5. **Evaluation** – compute the exact `C5` using `evaluate_c5`.
6. **Return** the `h` with the smallest observed `C5`, together with the bound
   and the chosen `n`.

By exploiting a convex outer approximation, solving only linear programs, and
systematically varying the linearisation point, this strategy explores the
solution space far more thoroughly than the earlier heuristic local‑search
method.  It is therefore a materially different approach that is well‑suited
to the 600‑second computational budget and is expected to achieve a tighter
upper bound (target ≤ 0.3805, ideally ≤ 0.379).
