But we could simply treat the constraint as:

`c_s = ∑_{i} h_i h_{i+s}`.

Let `v_s` be the vector of entries `h_{i+s}` for each i (with zeros where out of range). Then `c_s = hᵀ v_s`. This is bilinear but can be linearized in one argument if we treat the other as fixed (current estimate).

Thus we could use **alternating optimization**: hold h fixed in the “partner” term to compute each correlation, then solve a linear program to update h.

Specifically, given current h^{(k)}, define for each shift s a partner vector p_s = shift(h^{(k)}, s) (size n). Then `c_s ≈ hᵀ p_s` for the next iterate (since we evaluate with old vector for one side). This yields a **linear objective** for each shift.

Now the problem of maximizing the minimal linear correlation across shifts becomes a linear fractional programming:

max τ
s.t.   hᵀ p_s ≥ τ   ∀ s>0,
      0 ≤ h ≤ 1,
      ∑ h = n/2.

Because p_s are known (based on previous iterate), this is a linear program (LP). We can solve it efficiently with e.g. `scipy.optimize.linprog` or a linear programming solver in cvxpy.

Then we update h, recompute p_s, and iterate. This is a **successive linear programming** method (a variant of CCP). It may converge to a local optimum.

We can also add a damping factor: new h = α h^{new} + (1-α) h^{old} to avoid large jumps.

Potential variation: propagate momentum or use a bisection on τ: For a fixed τ, check feasibility of linear constraints; then binary search on τ to find the maximal feasible τ.

Thus the iteration reduces to a series of feasibility linear programs.

### 15.  Summary of the novel approach  

1. **Exploit bilinearity** of the autocorrelation: express each shift correlation as a linear functional of `h` when the partner side is frozen.

### 1.  Problem restatement  

For a discretised step function `h ∈ [0,1]^n` (with `dx = 2/n`)

```
C5(h) = max_{k≠0} ∫_0^2 h(x) (1‑h(x+k)) dx
       = 1 − min_{k>0} c_k,
c_k = ∫_0^2 h(x) h(x+k) dx .
```

Thus minimising `C5` is equivalent to **maximising** the worst self‑correlation  

```
τ = min_{k>0} c_k .
```

The constraints are  

```
0 ≤ h_i ≤ 1   for all i,
∑_i h_i = n/2   (∫ h = 1).
```

`c_k` is a bilinear form:  

```
c_k = ∑_{i=0}^{n‑1‑k} h_i h_{i+k}.
```

### 2.  Core idea – successive linearisation via linear programmes  

Fix a current iterate `h^{(t)}`.  
For each shift `k` define the **partner vector**

```
p_k^{(t)} = (h^{(t)}_{i+k} if i+k < n else 0)   i = 0,…,n‑1 .
```

Then  

```
c_k(h) = hᵀ p_k^{(t)}          (linear in h, because p_k^{(t)} is frozen)
```

Hence, for the *fixed* partners the constraint “τ ≤ c_k” becomes a **linear inequality**.  

We therefore solve the following LP at every outer iteration:

*Variables*: `h ∈ ℝ^n`, scalar `τ`.  
*Objective*: maximise `τ`.  
*Constraints*  

```
hᵀ p_k^{(t)} ≥ τ      for all k = 1,…,n‑1,
∑_i h_i = n/2,
0 ≤ h_i ≤ 1           for all i.
```

The LP yields the largest τ compatible with the current partners.  
After solving, we update the partners using the new `h` and repeat.  
Because each LP gives the maximal τ for the current partners, the sequence `τ^{(t)}` is monotone non‑decreasing and converges to a fixed point – a local optimum of the original non‑convex problem.

### 3.  Projection onto the bounded simplex  

All constraints are already enforced inside the LP (box + sum).  
Nevertheless, after the LP solution we may blend the new vector with the old one:

```
ĥ = λ h_new + (1‑λ) h_old   (λ ∈ (0,1]; typical λ = 1)
```

To guard against numerical drift we apply a *bounded‑simplex projection*:

1. Clip to `[0,1]`.
2. Find a scalar `γ` (by bisection) such that `∑_i clip(h_i + γ,0,1) = n/2`.  
   This is the standard projection onto `{h | 0≤h≤1, ∑h = n/2}`.

The projection is O(n) and guarantees feasibility for the next LP.

### 4.  Algorithmic pipeline  

1. **Discretisation** – Choose a grid size `n`.  
   * Start from the provided 42‑point seed, up‑sample to `n = 2·42 = 84` (or 126 if time permits) by linear interpolation.  
   * Project the up‑sampled seed onto the bounded simplex → `h⁰`.

2. **Random restarts** – Perform `R` independent runs (e.g. `R = 30`).

   a. Generate a random feasible `h⁰` (draw uniform numbers, project).  
   b. Initialise `τ = 0`.  

3. **Successive linear programme** – Iterate up to `K` times (e.g. `K = 200`) or until `|τ^{(t+1)}‑τ^{(t)}| < ε` (`ε = 1e‑8`):  

   a. Build partner vectors `p_k` from the current `h`.  
   b. Solve the LP described in §2 (use `scipy.optimize.linprog` with the `'highs'` method, or `cvxpy` with ECOS/SCS).  
   c. Retrieve `(h_new, τ_new)`.  
   d. Optionally blend: `h ← λ h_new + (1‑λ) h_old`.  
   e. Project the blended vector onto the bounded simplex.

4. **Record the best result** – After each restart store the final `(h, τ)`.  
   Keep the restart with the largest τ (hence the smallest `C5 = 1‑τ`).

5. **Polishing (optional)** – Starting from the best `h` run a short **projected gradient ascent** on the true non‑smooth objective:  

   * Compute the full correlation `c_k = hᵀ p_k`.  
   * Identify the worst shift `k* = argmin c_k`.  
   * Gradient of `c_{k*}` w.r.t. `h` is `g_i = h_{i‑k*}` (if `i‑k*≥0`) + `h_{i+k*}` (if `i+k*<n`).

   * Repeat for ≤ 500 iterations or until improvement < 1e‑12.  

   This usually refines τ by a few 10⁻⁶, giving a tighter bound.

6. **Final evaluation** – Compute the exact `C5` using the original definition:

   ```
   C5 = max_k np.correlate(h, 1‑h, mode='full') * dx .
   ```

7. **Return** `(h.tolist(), C5, n)`.

### 8.  Why this approach is materially different  

1. **Exploits bilinearity** – Instead of treating the max‑overlap as a black‑box objective, each shift’s correlation is linearised by fixing one side.  
2. **Deterministic convex sub‑problems** – The outer non‑convex problem is tackled by a sequence of **linear programmes**, not by stochastic evolutionary or smoothing heuristics.  
3. **Exact handling of constraints** – Box constraints and the integral constraint are embedded directly in each LP, so feasibility is guaranteed at every iteration.  
4. **Scalable and fast** – Solving an LP of size `≈ n` is orders of magnitude cheaper than evaluating the non‑smooth objective many times, enabling many restarts and rapid convergence.  
5. **Conceptually distinct** – Prior solutions relied on differential evolution, SLSQP, or smooth log‑sum‑exp. This method uses a *successive linearisation* (majorisation–minimisation) framework, a classic technique for non‑convex QCQPs that has not been applied in the earlier strategies.
