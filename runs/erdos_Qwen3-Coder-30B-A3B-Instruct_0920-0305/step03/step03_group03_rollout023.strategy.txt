### 2. Exact binary optimisation for small grids (MILP)

For a chosen even size `n` (start with `n = 42`, later try 44, 48, 52,
56, 60) we solve the following mixed‑integer linear program.

*Variables*  
- `b_i ∈ {0,1}` – the binary step function.  
- `y_{i,j} ∈ {0,1}` for all ordered pairs `0≤i≤j<n` – product
  `b_i·b_j` (McCormick linearisation).  
- `t ≥ 0` – lower bound on every shift overlap.

*Constraints*  

1. **Weight** `Σ_i b_i = m = n/2`.  
2. **Product linearisation** (for all `i ≤ j`):  

   ```
   y_{i,j} ≤ b_i
   y_{i,j} ≤ b_j
   y_{i,j} ≥ b_i + b_j – 1
   ```

3. **Overlap for each shift** `s = 0,…,n‑1` :

   ```
   overlap_s = Σ_{i=0}^{n‑1‑s} y_{i,i+s}
   overlap_s ≥ t
   ```

*Objective* `maximise t`.

*Solution* – Build the model with **CVXPY** using a MILP solver that
handles binary variables (CBC, GLPK_MI, or ECOS_BB).  Impose a wall‑time
limit for the solve (e.g. `time_limit = 0.6·budget_s` for the first
grid, then proportionally less for later grids).  When the solver finishes
(successfully or on timeout) read the integer value `t*` and compute the
corresponding bound

```
C5_binary = (m – t*)·dx = 1 – (2·t*)/n .
```

If `C5_binary` improves the global best, store the binary vector
`b*` (converted to `float`) as the incumbent.

*Why this works* – The MILP finds the optimum among all binary step
functions, guaranteeing the smallest possible `C5` for the chosen
resolution.  For `n=42` the optimal `t` is 13, giving `C5≈0.381`.  The
same machinery on a slightly larger grid can produce a better ratio
`(m‑t)/m` because the averaging effect changes with `n`.

--------------------------------------------------------------------
### 3. Continuous refinement of a binary incumbent (projected sub‑gradient)

Binary optima lie on the corners of the feasible polytope; allowing
fractional values may lower the maximum correlation.  Starting from a
binary incumbent `h⁰`:

3.1 **Gradient of the max‑correlation**  
Let `S = {s : C_s = max_k C_k}` be the set of shifts attaining the
current maximum `C = max_s C_s`.  For a shift `s` the correlation is  

```
C_s(h) = Σ_i h_i·(1 – h_{i+s}) .
```

The gradient w.r.t. component `i` (treating out‑of‑range indices as 0) is  

```
∂C_s/∂h_i = 1 – h_{i+s} – h_{i‑s} .
```

A sub‑gradient of `C(h)=max_s C_s(h)` is the average of the gradients
over all active shifts `s∈S`.

3.2 **Projected sub‑gradient step**  

```
h ← h – α·g                (α = step‑size, e.g. α_k = α₀/√k)
clip to [0,1]             (h_i ← min(max(h_i,0),1))
project onto the simplex  Σ h_i = 1   (standard ℓ₁‑simplex projection)
```

3.3 **Loop** – repeat for a fixed number of iterations (e.g. 2000) or
until the improvement in `C5` falls below `1e‑8`.  Keep the best vector
seen during the run.

3.4 **Multiple restarts** – run the above descent from several
different seeds: the binary optimum, a random uniform vector, and a
smooth sigmoid shape (`h_i = sigmoid(a·(i‑n/2))`).  Keep the best result.

Because each evaluation of `C_s` uses `np.correlate` (or an FFT‑based
convolution) the cost per iteration is `O(n log n)` and negligible for
`n ≤ 80`.

--------------------------------------------------------------------
### 4. Stochastic combinatorial search on larger grids (Simulated Annealing)

To beat the binary optimum we must explore richer lengths `n` where the
discrete combinatorial optimum may already be lower.  Simulated
annealing on the **binary** space is fast and works well for the
constant‑weight constraint.

For each target size `n ∈ {44,48,52,56,60}`:

4.1 **Initial state** – generate a random binary vector with exactly `n/2`
ones.

4.2 **Neighbourhood** – a move consists of swapping the values of a
random `1`‑position `i` and a random `0`‑position `j`.  This preserves the
weight exactly.

4.3 **Energy** – the current `C5` evaluated with `evaluate_c5`.

4.4 **Acceptance** – if the new energy `E'` is lower, accept; otherwise
accept with probability `exp( -(E'‑E)/T )` where temperature `T`
follows a simple schedule, e.g. `T = T0·(1‑t/τ)` with `τ` the total
number of annealing steps allotted to this `n`.

4.5 **Schedule** – run a sufficient number of swaps (e.g. `10·n²`) or
until the wall‑clock time allotted for this length is exhausted (roughly
`budget_s / (#lengths)` seconds).  Periodically recompute the full
correlation (cheap for our sizes) and keep the best vector found.

4.6 **Post‑processing** – take the best binary string for this `n`,
convert it to a float vector, and run the **continuous refinement** of
Section 3 for a short burst (e.g. 300 iterations) to exploit possible
fractional improvements.

--------------------------------------------------------------------
### 5. Optional Genetic Evolution (diversification)

If time remains after the annealing passes, run a lightweight genetic
algorithm on the *best* length discovered:

- Population size ≈ 30 binary strings of the chosen `n`.  
- Evaluate `C5` for all.  
- Keep the top 10 % as parents.  
- Produce offspring by uniform crossover (take each bit from parent A
  with probability ½) and immediately **repair** the weight by flipping
  random bits until exactly `n/2` ones remain.  
- Mutate each offspring by a low‑probability random swap.  
- Iterate 10–15 generations, retaining the overall best individual.  

Again finish with a brief continuous refinement.

--------------------------------------------------------------------
### 6. Time management & early exit

- Record `start = time.time()`.  
- Allocate roughly:
  * 30 % of the budget to the exact MILP on `n=42` (guarantees the known
    bound 0.381).  
  * 30 % to binary annealing on the larger lengths (split equally).  
  * 30 % to continuous refinements (gradient descents).  
  * 10 % reserved for a safety fallback (the original differential‑
    evolution routine) if none of the above reaches the target.
- After each improvement, check whether `best_C5 ≤ 0.3807`.  If so,
  abort all further work and return immediately.

### 7. Return format

When the search ends (either because the budget is exhausted or the target
has been met) output  

```
(best_h.tolist(), best_C5, n_best)
```

where `best_h` is the final `numpy` array (float values in `[0,1]`),
`best_C5` is the value returned by `evaluate_c5(best_h)`, and `n_best`
