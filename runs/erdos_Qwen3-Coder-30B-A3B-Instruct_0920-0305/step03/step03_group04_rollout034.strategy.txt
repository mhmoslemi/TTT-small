The new method is **fundamentally different** from the previous SLSQP + annealing / binary hill‑climb pipeline: it treats the max‑over‑shifts as an explicit linear constraint, linearises the bilinear part of the objective, and solves a *sequence of linear (or small quadratic) programs* via a **Convex‑Concave (DC) Procedure**. ### 1. Reformulation as a DC (difference‑of‑convex) programme
For a fixed shift `k` define

\[
C_k(h)=\underbrace{\sum_{i=0}^{n-1-k} h_i}_{\displaystyle S_k}
        \;-\;
        \underbrace{\sum_{i=0}^{n-1-k} h_i\,h_{i+k}}_{\displaystyle Q_k}.
\]

`S_k` is linear in `h`; `Q_k` is *bilinear* and can be written as a difference of two convex functions:

\[
h_i h_{i+k}
= \tfrac12\bigl[(h_i+h_{i+k})^2 - h_i^2 - h_{i+k}^2\bigr].
\]

Hence each `C_k` is a **difference of convex (DC)** function:
\[
C_k(h)=S_k(h) \;-\; Q_k(h)=\bigl[S_k(h)-\tfrac12(h_i+h_{i+k})^2\bigr]
        \;+\; \tfrac12\bigl(h_i^2+h_{i+k}^2\bigr).
\]

The overall objective is the **maximum** of the `C_k`.  Introducing an auxiliary scalar `t` we obtain the equivalent convex programme

\[
\min_{h,t}\; t\qquad\text{s.t.}\qquad C_k(h)\le t\;\; \forall k,
\;0\le h_i\le 1,\;
\sum_i h_i = n/2 .
\]

Because each `C_k` is DC we can apply the **convex–concave procedure (CCCP)**: at iteration `r` we linearise the *concave* part of every `C_k` around the current iterate `h^{(r)}` and solve the resulting convex (actually linear) sub‑problem.

--------------------------------------------------------------------
### 2. Linearisation of the concave part
For a given `k` let  

\[
\mathcal{I}_k =\{i\mid 0\le i\le n-1-k\}.
\]

The gradient of the bilinear term at `h^{(r)}` is
\[
\frac{\partial Q_k}{\partial h_i}\Big|_{h^{(r)}}=
\begin{cases}
h^{(r)}_{i+k} & i\in\mathcal{I}_k, \\
h^{(r)}_{i-k} & i\ge k,\\
0 & \text{otherwise}.
\end{cases}
\]

Using the DC decomposition we keep the *convex* part untouched (`\tfrac12\,h_i^2` and `\tfrac12\,h_{i+k}^2`) and replace the concave part `-\tfrac12 (h_i+h_{i+k})^2` by its first‑order Taylor approximation:

\[
-\tfrac12 (h_i+h_{i+k})^2
\approx
-\tfrac12 (h^{(r)}_i+h^{(r)}_{i+k})^2
-\;(h^{(r)}_i+h^{(r)}_{i+k})\bigl( h_i-h^{(r)}_i+h_{i+k}-h^{(r)}_{i+k}\bigr).
\]

Collecting the linear terms for a fixed `k` yields a **linear function** in `h`.  Denote it by  

\[
\tilde C_k^{(r)}(h) = a_k^{(r)} + b_k^{(r)}\!\cdot\!h ,
\]

where `b_k^{(r)}` contains the coefficients `1` from `S_k` and the negative gradient contributions coming from the linearised `Q_k`.

--------------------------------------------------------------------
### 3. Sub‑problem solved at each CCCP iteration
Given the current iterate `h^{(r)}`, solve

```
variables:  h ∈ ℝⁿ ,  t ∈ ℝ
minimise   t
subject to  b_k^{(r)}·h  ≤  t - a_k^{(r)}   for all k = 0,…,n-1
            0 ≤ h_i ≤ 1               for all i
            Σ_i h_i = n/2 .
```

All constraints are linear, therefore the sub‑problem is a **linear programme** (LP).  
A tiny quadratic regulariser `μ‖h‑h^{(r)}‖²` can be added to stabilise the updates (making it a QP), but for modest `μ` most LP solvers handle it as a second‑order cone constraint without appreciable overhead.

--------------------------------------------------------------------
### 4. Overall algorithm (deterministic core)

1. **Choose a modest even grid size** `n` (e.g. 40, 60, 80 – any even number ≤ 120 keeps the LP tiny).  
2. **Initial feasible point**  
   * Set `h_i = 0.5` for all `i`.  
   * Project onto the hyperplane `Σh = n/2` (already satisfied) and clip to `[0,1]`.  
   * Add a tiny random perturbation (`±0.01`) to break symmetry; re‑project onto the hyperplane.  

3. **CCCP loop** (max 200 iterations or until time‑budget is exhausted)  

   a. Compute for every shift `k` the exact values `S_k`, `Q_k`, and the current objective `C_k`.  
   b. Identify the **active set** `K_active` = { `k` | `C_k` is within `ε` of the current maximum, `ε≈10⁻⁶` }.  
      Using only the active shifts (usually 1–3) keeps the LP tiny while still enforcing the true max.  
   c. Build the linear coefficients `a_k^{(r)}`, `b_k^{(r)}` for all `k∈K_active` using the gradient formulas above.  
   d. Solve the LP (or QP) with any off‑the‑shelf solver (`scipy.optimize.linprog` with method “highs”, or `cvxpy` with ECOS/OSQP).  
   e. Set `h ← solution`.  
   f. Evaluate the *exact* `C_5` (full correlation) and keep the best `h` seen so far.  
   g. If `C_5` has not improved for, say, 20 consecutive iterations, stop early.  

4. **Multi‑scale continuation**  
   * After convergence at a coarse grid `n₁`, generate a finer grid `n₂ > n₁` by linear interpolation of the current `h`.  
   * Initialise the finer `h` with the interpolated values (they automatically satisfy the integral constraint after a final projection).  
   * Resume the CCCP loop on the finer grid.  
   * Typical schedule: `n = 40 → 60 → 80`.  Each refinement needs only a few dozen iterations because the interpolated start is already close to optimal at the finer resolution.

5. **Random restarts**  
   * Perform the whole continuation (steps 1‑4) from several different random seeds (e.g., 10).  
   * Keep the solution with the smallest exact `C_5`.  The deterministic core guarantees that each run explores a well‑defined descent path, but different seeds avoid the few remaining local minima of the DC method.

--------------------------------------------------------------------
### 5. Final polishing (optional but cheap)

The LP‑based CCCP converges to a point that satisfies all linearised constraints; the true max constraint may still be slightly violated due to linearisation error.  A short **smooth‑max refinement** finishes the job:

* Define `F_s(h)=\mathrm{softmax}_α\bigl\{ C_k(h)\bigr\}` with a large `α` (≈30).  
* Minimise `F_s(h) + λ( Σh – n/2 )²` with box bounds using **L‑BFGS‑B** (max 300 iterations).  
* Initialise from the best CCCP solution; after convergence project onto `Σh=n/2` and clip to `[0,1]`.  

Because the starting point is already very close to optimal, this stage typically changes `C_5` by < 10⁻⁴.

--------------------------------------------------------------------
### 6. Exact final local optimisation (to guarantee feasibility)

Run a single **SLSQP** (or `trust-constr`) optimisation on the true nondifferentiable objective:

* Objective: `evaluate(h) = dx * max(np.correlate(h,1‑h,'full'))`.  
* Equality: `Σh*dx = 1`.  
* Bounds: `0≤h_i≤1`.  

Start from the polished `h`.  With only a few hundred iterations the solver converges to a stationary point that satisfies the integral exactly; the resulting `C_5` is the final bound to be reported.

### 8. Failure‑mode analysis & safeguards

| Failure | Why it may happen | Fix |
|---------|-------------------|-----|
| **Oscillation** (CCCP cycles without improvement) | Linearisation too aggressive; step jumps far from the current point. | Add the proximal ‑‖h‑h_prev‖² term (turn LP into a small QP) or damp the update: `h ← (1‑β) h_prev + β h_new` with β ≈ 0.5. |
| **Infeasibility of the LP** | The linearised constraints can become contradictory when the active set is mis‑identified. | If LP returns infeasible, relax the active set: add a slack variable `s≥0` to each active constraint and penalise `Σs` heavily in the objective (e.g., weight = 10⁶). |

| **Numerical drift of the sum constraint** | Repeated LP solves may produce `Σh` ≈ n/2 ± 1e‑8. | Enforce the equality exactly in the LP (add a row `Σh = n/2`). After solving, apply a final projection onto the hyperplane (simple scaling) before the next iteration. |

1. **Initialisation** – set random seed, pick the first grid size `n₁ = 40`.  
2. **Run CCCP** on `n₁` until convergence (or time limit).  
3. **Upsample** to `n₂ = 60`, re‑project onto the feasible simplex, run CCCP again.  
4. **Upsample** to `n₃ = 80`, run CCCP again – keep the best `h` found at any stage.  
5. **Repeat** steps 1‑4 from several seeds (≈ 10 total runs).  
6. **Select** the vector with smallest exact `C_5`.  
7. **Polish** this vector with a few L‑BFGS‑B steps on the smooth‑max surrogate.  
8. **Finalize** with a short SLSQP optimisation on the true max objective.  
9. **Return** `list(h)`, the final `C_5` value, and the grid size `n` that achieved it.

### 11. Why this strategy is **materially different**

* It **replaces stochastic perturbations** (annealing, random swaps) with a **deterministic convex programme** per iteration.  
* It **linearises the bilinear overlap term** and treats the max via an auxiliary variable, turning a non‑smooth, non‑convex problem into a **sequence of LP/QP solves**.  
* It uses a **multi‑scale continuation** (coarse → fine grid) to obtain high‑resolution solutions without exploding the problem size.  
* The only randomness lies in the initial seeds; the optimisation path itself is fully governed by the DC algorithm, unlike previous hill‑climbing or generic SLSQP runs.

Consequently, the method explores the feasible region in a principled way that is orthogonal to the earlier approaches, giving a strong chance of improving the current record bound on `C_5`.
