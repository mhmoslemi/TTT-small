### 1. Mathematical reformulation

For any shift `k` (0 ≤ k ≤ n‑1)  

\[
C(k)=\sum_{i=0}^{n-1-k}h_i-\sum_{i=0}^{n-1-k}h_i\,h_{i+k}
      =S_k-P_k ,
\]

where `S_k` is the weight of the prefix of length `n‑k` and `P_k` is the number of **overlapping ones** at lag `k`.  
Since `∑h_i` is fixed, minimising `max_k C(k)` is equivalent to **maximising the minimal overlap**  
\(\displaystyle \min_k P_k\).  For binary vectors this is a purely combinatorial problem; for general vectors the quadratic term is still present but the problem is smoother if we replace the hard max by a differentiable approximation.

### 4. Stage 2.1 – Structured interval family

**Motivation** – Many extremal sets for overlap problems consist of a small number of intervals of equal length placed periodically.  Optimising the *gap* between intervals is a low‑dimensional problem that can be scanned exhaustively.

**Parameterisation**

- Choose an integer `m ≥ 2` (number of intervals).  
- Let each interval have length `ℓ = 1/m` (so total measure = 1).  
- Let the common gap length be `g ≥ 0`. The domain constraint is `m·ℓ + (m‑1)·g ≤ 2`.  
- Choose an offset `δ ∈ [0,g]` (the distance from the left boundary to the first interval).

The vector `h` is 1 on the intervals, 0 elsewhere.  For a given triple `(m,g,δ)` we can build `h` analytically (the interval endpoints are rational multiples of `dx`; we fill the nearest grid points).  

**Search strategy**

- Loop over `m = 2…8`.  
- For each `m`, solve `g = (2 - m·ℓ) / (m-1)` (the *maximally spread* configuration) and also a few smaller `g` values (e.g. `0.5·g`, `0.75·g`).  
- For each `g`, sweep `δ` over `0 … g` with a step of `dx/2`.  

All candidate vectors are evaluated with `evaluate`.  The best candidate for each `n` (we try `n = 46, 48, 50, 60`) is stored.  This stage finishes in seconds and often yields a bound around 0.39, providing a solid starting point for later stages.

### 5. Stage 2.2 – Binary hill‑climbing (the core combinatorial improvement)

**Why binary?**  
If the optimal `h` is close to a characteristic function, the binary neighbourhood provides a powerful discrete landscape that SLSQP cannot see because of flat gradients.  Swapping a `1` with a `0` changes *exactly* the two positions that influence the correlation, allowing us to exploit greedy improvements.

**Algorithm (per even `n`)**

1. **Initialisation** – Generate `R` random binary vectors (`R≈5`).  Keep the one with smallest `C5`.  
2. **Greedy swaps** – Repeatedly pick a random `1`‑index `i` and a random `0`‑index `j`, swap them, compute the new `C5`.  
   *If* the new cost is **strictly smaller**, accept the swap and update the two index lists; otherwise reject.  
3. **Stagnation handling** – After `S = 5·n` unsuccessful attempts, re‑initialise the vector (or keep the best and perform a *large* perturbation: randomly re‑assign `p·n` bits).  
4. **Multiple restarts** – Run the above hill‑climb for several distinct `n` values (e.g. `n ∈ {50, 60, 70, 80}`).  Each run receives a time slice (≈ budget × 0.5 / #n).  The best binary solution across all `n` is retained.

Because the evaluation cost is tiny (full correlation via `np.correlate`), we can afford **≈ 30 000–50 000** swap attempts per `n` within the allocated time.  Empirically this produces binary vectors whose raw mismatch count `M = C5/dx` falls to ≈ 0.19 n (≈ 9 – 12 mismatches for `n≈50‑80`), already near the target bound.
