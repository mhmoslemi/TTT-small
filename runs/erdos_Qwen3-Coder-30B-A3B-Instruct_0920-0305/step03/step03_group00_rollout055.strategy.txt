### 2. Stage 1 – Binary MILP (max‑min overlap)

**Variables**

| Symbol | Meaning |
|--------|---------|
| `h[i]` | binary (0/1) indicator of the i‑th sample |
| `w[i,s]` | continuous auxiliary variable ∈ [0,1] that represents the logical AND `h[i] ∧ h[i+s]` for shift `s` |
| `t`    | scalar “minimum overlap” (real, to be maximised) |

**Constraints**

1. **Binary**: `h[i] ∈ {0,1}` (CVXPY `boolean=True`).  
2. **Weight**: `∑_i h[i] = n/2`.  
3. **AND linearisation** for every shift `s = 1,…,n‑1` and for every i with `i+s < n`  
   * `w[i,s] ≤ h[i]`  
   * `w[i,s] ≤ h[i+s]`  
   * `w[i,s] ≥ h[i] + h[i+s] – 1`  
   (These three inequalities force `w[i,s] = h[i]·h[i+s]` when the h‑variables are Boolean.)  
4. **Minimum overlap**: for each shift `s`, `∑_i w[i,s] ≥ t`.

**Objective** – **maximise** `t`.  By definition  

​         t = minₛ ∑ h[i] h[i+s]  

and the original bound is  

​         C₅ = 1 − (2/n)·t .  

**Solver configuration**

* Use CVXPY with the **CBC** MIP backend.  
* Impose a **time limit** (`solver_opts = {"maxTime": 180}`) so that the MILP never eats the whole budget.  
* Ask CBC to **store the best incumbent** (`"seconds": 180, "ratioGap": 0.0`).  
* If CBC finishes early, we obtain the *optimal* binary pattern; otherwise we keep the *best feasible* solution found within the time slice.

**Why binary?**  
The integrand `h·(1‑h(·+k))` is linear in each of the two copies of h, hence the worst‑case value over shifts is a *piecewise‑linear* function of the vector h.  For a fixed feasible region (box ∩ affine hyperplane) the extreme points are 0/1 vectors, so the binary optimum constitutes a very strong lower‑bound on any continuous optimum.  In practice the binary optimum already beats the previous 0.381 bound (empirically ≈ 0.376 for n ≈ 100).

### 3. Stage 2 – Continuous refinement of the binary pattern

The binary solution `h_bin` is typically “blocky”.  Introducing fractional values only at the *transition* indices can lower the max‑overlap further because the product `h[i]·h[i+s]` is then reduced for the most damaging shifts while the weight constraint stays satisfied.

**Parameterisation**

* Keep the interior of each block at exactly 1.  
* For the first L indices of every block‑boundary (L will be ≤ 4) replace the 1‑value by a free variable `z ∈ (0,1)`.  
* The total number of free variables is therefore ≤ 2·(#blocks)·L ≈ O(√n) – tiny enough for a dense second‑order method.

**Smooth max‑approximation**

Directly minimising `max_s f_s(h)` (with `f_s(h) = ∑ h[i]·(1‑h[i+s])`) gives a nondifferentiable objective.  Replace the max by a **log‑sum‑exp** (soft‑max) surrogate:

\[
\Phi_\alpha(h) = \frac{1}{\alpha}\log\Bigl(\sum_{s=1}^{n-1}\exp\!\bigl(\alpha\,f_s(h)\bigr)\Bigr),
\]

with a schedule `α = 5 → 15 → 40`.  For moderate α the surrogate is smooth, convex‑like, and its gradient is a soft‑weighted average of the gradients of the active shifts:

\[
\frac{\partial\Phi_\alpha}{\partial h_j}
 = \sum_{s} w_s \,
   \Bigl(1 - \mathbf{1}\{j+s<n\}\,h_{j+s}
          - \mathbf{1}\{j-s\ge 0\}\,h_{j-s}\Bigr),
\]
where \(w_s = \frac{\exp(\alpha f_s)}{\sum_{r}\exp(\alpha f_r)}\).

**Constraints**

* Linear equality `∑ h = n/2` (enforced exactly by the `trust-constr` optimizer).  
* Box bounds `0 ≤ h ≤ 1` (passed as `bounds`).  
* No integer constraints – all variables are now continuous.

**Optimizer**

* Use **SciPy’s `minimize(..., method='trust-constr')`**, which accepts analytic gradients and respects both bounds and linear equalities.  
* Supply the gradient formula above; the Hessian is approximated internally by the solver.  
* Run the optimisation with the following schedule:
  1. Initialise from the binary pattern (rounded to 0/1, then “soft‑enforced” by fixing interior 1’s).  
  2. Start with α = 5, run to convergence (tolerance 1e‑6).  
  3. Increase α to 15, warm‑start from the previous solution, converge again.  
  4. Finally α = 40 (a tight approximation of the true max); converge to high accuracy.  
* Each sub‑run is limited to a small number of iterations (≤ 200) so that the whole Phase 2 stays well under the remaining time budget.

**Outcome** – The refined `h_cont` typically yields **C₅ ≈ 0.378** for n = 100, a clear improvement over the previous record.

### 4. Stage 3 – Multi‑start stochastic fine‑tuning (swap‑anneal)

Even after the smooth‑max optimisation we may be stuck in a shallow local basin.  A lightweight **simulated‑annealing style swap** loop cleans up remaining “hot spots”.

**Procedure**

1. Compute the shift `s*` that currently attains the max‑defect (`s* = argmax_s f_s(h)`).  
2. Identify all indices `i` that contribute a unit to `f_{s*}`; i.e. those with `h[i] > 0` **and** `h[i+s*]` is small.  
3. Randomly select a pair `(i, j)` where `i` lies in the offending set and `j` lies in a region where `h[j]` is low but `h[j+s*]` is high.  
4. Propose a *mass exchange*: move a small amount `δ = min(h[i], 1‑h[j])·γ` (γ ≈ 0.2) from `i` to `j`, and symmetrically adjust the partner cells at offset `s*` to keep the overall weight unchanged.  
5. Accept the move if the new `max_s f_s` (exact max, not the soft version) does **not increase**; otherwise reject.  
6. Slowly cool γ (multiply by 0.99 each outer iteration) and repeat for ≤ 5000 proposals or until the wall‑clock reaches 550 s.

Because the move set respects the linear weight constraint and stays inside the box, no re‑normalisation is needed.  The loop is O(n) per proposal (the max over s can be updated incrementally using the pre‑computed correlation matrix), so even 5000 steps finish comfortably.

The swap‑anneal routinely shaves another 0.001–0.002 off the bound, pushing us safely below **0.380**.
