### 1.  Re‑formulation of the objective  

For a discretisation with `n` points (`dx = 2/n`) define the vector  
`h = (h₀,…,hₙ₋₁)`,   `0≤h_i≤1`,   `∑ h_i·dx = 1`.  
Set `m = ∑ h_i = n/2` (because `dx·m = 1`).  
The overlap integral used in the evaluation routine is

```
C₅(h) = max_k  Σ_i  h_i·(1 – h_{i+k})·dx
      = (m – min_k Σ_i h_i·h_{i+k})·dx     (full convolution, zero padding)
```

Hence minimising `C₅` is equivalent to **maximising the smallest aperiodic
autocorrelation**  

```
t_min  =  min_k Σ_i h_i·h_{i+k}      (k∈{-(n‑1),…,(n‑1)})
C₅     =  (m – t_min)·dx = 1 – (2·t_min)/n .
```

The quantity `t_min` is an integer when `h` is binary (0/1).  For a fixed
grid size the problem is therefore a **max‑min integer quadratic
program**.



### 2.  Exact binary optimisation via a mixed‑integer linear programme  

#### 2.1 Decision to work with binary step functions  

To obtain a provably optimal bound for a given `n` we restrict the search
to vectors `b∈{0,1}ⁿ` with `∑ b_i = m`.  Any feasible binary vector is a
feasible `h` (just interpreted as a step function) and gives a valid
upper bound for the original continuous problem.  If the binary optimum
already beats the target `0.3807` we are done; otherwise we can try a
fractional polishing step (Section 4).

#### 2.2 Linearisation of the quadratic terms  

Introduce auxiliary binary variables  

```
y_{i,j}  =  b_i * b_j          for 0 ≤ i ≤ j < n .
```

The product is enforced by the classic McCormick (or RLT) constraints

```
y_{i,j} ≤ b_i,
y_{i,j} ≤ b_j,
y_{i,j} ≥ b_i + b_j – 1,
y_{i,j} ≥ 0                     (implicit by binary type)
```

For a shift `s ≥ 0` the aperiodic autocorrelation is

```
R(s) = Σ_{i=0}^{n-1-s} b_i * b_{i+s} = Σ_{i=0}^{n-1-s} y_{i,i+s}.
```

(The case `s<0` yields the same values because the sum is over ordered
pairs; therefore it is sufficient to enforce the constraints for
`s = 0,…,n‑1`.)

#### 2.3 Feasibility model for a prescribed lower bound `t`

For a candidate integer `t` we ask whether there exists a binary vector
with `R(s) ≥ t` for **every** shift `s`.  This is a pure feasibility MILP:

```
variables:    b_i ∈ {0,1}   (i=0,…,n‑1)
              y_{i,j} ∈ {0,1}   (0≤i≤j<n)
constraints:
   Σ_i b_i = m                                              (weight)
   y‑product constraints (3 per pair)                       (linear)
   Σ_{i=0}^{n‑1‑s} y_{i,i+s} ≥ t   for all s = 0,…,n‑1     (overlap)
```

If the model is feasible, `t` can be achieved; otherwise it is impossible.

#### 2.4 Binary search on `t`

The feasible `t` is bounded by `0 ≤ t ≤ m`.  We perform a **binary search**
on `t`:

```
t_low  = floor(m/4)          // random expectation, safe lower bound
t_high = m                    // trivial upper bound
while t_high – t_low > 1:
    t_mid = ceil((t_low + t_high)/2)
    solve the feasibility MILP for t = t_mid (with a short time‑limit)
    if feasible:   t_low  = t_mid ; store the associated b
    else:          t_high = t_mid – 1
```

At termination `t_low` is the largest achievable lower bound and the
corresponding binary vector `b*` is the exact optimum for this grid size.

The resulting constant is  

```
C₅ = 1 – (2·t_low)/n .
```

#### 2.5 Solver and time‑budget handling  

* Use **CVXPY** with the MILP backend `CBC` (or `GLPK_MI` if faster on the
platform).  
* For each feasibility call set a per‑solve time limit (e.g. 5 % of the
overall remaining budget).  If the solver exceeds the limit, treat the
instance as *infeasible* for the current `t` (conservative decision).  
* Record the wall‑clock time after each MILP; stop the binary search as
soon as the remaining budget is insufficient for another feasibility test.

The MILP size is `O(n²)` variables (`≈ n(n+1)/2` `y`‑variables) and `O(n²)`
constraints, which is trivial for `n≈50–70` on a modern CPU.  The binary
search needs at most `⌈log₂(m)⌉` feasibility solves (≤ 6 for the sizes we
care about).

### 4.  Fractional polishing of a binary optimum (optional but powerful)

The exact binary optimum may not be globally optimal for the original
continuous problem because allowing `0<h_i<1` can sometimes increase the
minimal overlap.  To exploit this possibility:

1. **Initialisation** – take the best binary vector `b*` and treat it as a
   real vector `h⁰ = b*`.  
2. **Smooth surrogate for the max** – replace the nondifferentiable
   `max_s C_s(h)` by a log‑sum‑exp with a temperature parameter `τ`:

   ```
   Φ_τ(h) = τ·log( Σ_s exp( C_s(h)/τ ) ),   C_s(h) = Σ_i h_i·(1−h_{i+s})·dx .
   ```

   As `τ → 0` the surrogate converges to the exact maximum.  
3. **Projected gradient descent** (or Adam) on `Φ_τ`:

   * Gradient of each `C_s` is available analytically:  
     `∂C_s/∂h_i = (1−h_{i+s})·dx − h_{i−s}·dx` (zero if the index is out of
     range).  
   * The gradient of `Φ_τ` is a convex combination of the gradients of the
     active shifts, weighted by the soft‑max probabilities.  
   * After each step, **project** back onto the feasible set: clip to
     `[0,1]` and then apply the Euclidean projection onto the simplex
     `Σ h_i = 1` (the well‑known `O(n)` algorithm that first projects onto
     the simplex `Σ h_i = 1, h_i≥0` and then enforces the upper bound `≤1`
     by a second pass).  
4. **Continuation on τ** – start with a relatively large temperature
   (e.g. `τ₀ = 0.1`) to obtain a smooth landscape, run a few hundred
   iterations, then halve `τ` and repeat, using the previous iterate as
   warm‑start.  This *homotopy* strategy helps avoid shallow local minima.  
5. **Termination** – stop when the reduction in `Φ_τ` over a full τ‑cycle
   falls below `1e‑8` or the global time budget is exhausted.  Compute the
   true `C₅` (using `evaluate_c5`) for the final `h`.  If it improves upon
   the binary bound, replace the stored best solution.

### 5.  Final fallback (guaranteed return within the budget)

If, for every `n` in the list, the MILP feasibility tests repeatedly hit
the per‑solve timeout (unlikely for `n≤64`) **or** the polishing phase
fails to improve the bound, we revert to a lightweight stochastic
procedure that is guaranteed to produce a result:

1. Generate `K = 200` random feasible vectors (simplex projection).  
2. Keep the `K₁ = 20` best candidates (by exact `evaluate_c5`).  
3. From each of those, perform a short projected Adam run (e.g. 200
   iterations, fixed `τ = 0.01`).  
4. Return the best vector obtained.

This fallback uses only gradient information and no integer programming,
so it finishes well within a few seconds and will never return a worse
value than the initial seed.
