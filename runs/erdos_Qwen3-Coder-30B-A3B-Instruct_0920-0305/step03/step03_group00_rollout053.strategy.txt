**Goal** – Produce a step‑function `h` (discretised on a uniform grid) that satisfies  

*   `0 ≤ h[i] ≤ 1` for every grid point,  
*   `∑ h[i]·dx = 1`  (i.e. `∑ h[i] = n/2` with `dx = 2/n`),

and minimises  

\[
C_5(h)=\max_{k}\;\int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx
      =\frac{2}{n}\;\max_{s\in\{0,\dots,n-1\}}
          \sum_{i=0}^{n-1-s}h_i\bigl(1-h_{i+s}\bigr).
\]

The new method is a **two‑phase combinatorial–continuous optimisation** that is fundamentally different from the previous differential‑evolution / SLSQP pipeline.

--------------------------------------------------------------------
### 1.  Choose a modest but sufficiently fine grid  

*Pick an even `n` in the range 80 – 300 (the exact value is decided at run‑time depending on the time left; a default of `n = 200` gives a good trade‑off).  
`dx = 2.0 / n`.  
All subsequent steps work with this fixed grid size.*

--------------------------------------------------------------------
### 2.  Initialise with a *balanced binary* pattern  

The binary constraint (`h[i] ∈ {0,1}`) is natural for the original problem (indicator of a set of measure ½).  
A good start is to distribute the `n/2` ones as uniformly as possible:

```
positions = round(i * n / (n/2))  for i = 0 … (n/2‑1)
h[i] = 1 if i is in positions else 0
```

Optionally, add a few random swaps to break symmetry.  
The initial `h` already respects the integral constraint.

--------------------------------------------------------------------
### 3.  Efficient evaluation of the objective  

For a binary vector the quantity  

\[
f_s(h)=\sum_{i=0}^{n-1-s}h_i\,(1-h_{i+s})
\]

is computed for every shift `s` by a **single FFT‑based correlation**:

```
corr = np.fft.ifft( fft(h) * fft(1‑h) ).real
f    = corr[:n]                     # shifts 0 … n‑1
C5   = 2.0/n * np.max(f)
```

FFT of length `2*n` is used, so the cost per evaluation is O(n log n) – negligible for `n ≤ 300`.

--------------------------------------------------------------------
### 4.  Phase I – *Targeted combinatorial hill‑climbing*  

The current worst shift is  

```
s* = argmax_s f_s(h)
```

All contributions to `f_{s*}` are of the form `h_i * (1‑h_{i+s*})`.  
A term contributes **1** exactly when `h_i = 1` **and** `h_{i+s*}=0`.  
These are the *mismatched* indices that make the objective large.

**Swap move** – exchange a mismatched `1` with a `0` that is *matched* for the same shift:

```
M = { i | h_i = 1 and i+s* < n and h_{i+s*}=0 }      # mismatches
Z = { j | h_j = 0 and j+s* < n and h_{j+s*}=1 }      # opposite side
choose (i,j) ∈ M×Z (heuristically the pair giving biggest Δ)
swap h_i ↔ h_j
```

A single swap can reduce `f_{s*}` by **2** (removing the mismatched 1 and creating a matching 1).  
After the swap we recompute all `f_s` (via FFT) and repeat while an improving swap exists.

Because the swap preserves the exact number of ones, the integral constraint stays satisfied.
The loop stops when no `(i,j)` pair reduces the current maximum, i.e. a **local optimum for the binary problem** has been reached.

--------------------------------------------------------------------
### 5.  Phase II – *Global stochastic escape* (Simulated Annealing)

The binary hill‑climber may be stuck in a local optimum.  
We therefore run a **simulated‑annealing** wrapper:

* **State** – a binary vector with exactly `n/2` ones.  
* **Neighbour move** – pick a random `1` and a random `0` and swap them (single‑swap).  
* **Energy** – the current `C5` value.  
* **Temperature schedule** – exponential cooling  
  `T_k = T_0 * decay^k` with `T_0 ≈ 0.05`, `decay ≈ 0.9995`.  
* **Acceptance** – always accept a move that lowers `C5`; otherwise accept with probability `exp(-(ΔC5)/T_k)`.

The annealing runs for a pre‑determined number of iterations (e.g. `4·10⁴` swaps) or until the elapsed time reaches ~ 70 % of the budget.  
Every `1000` iterations we invoke the **targeted hill‑climber** of Phase I to polish the current state; this hybridisation dramatically accelerates convergence.

The best binary vector seen during the whole run is stored (`best_bin`).

--------------------------------------------------------------------
### 6.  Phase III – *Continuous fine‑tuning*  

Binary vectors are often close to optimal, but allowing *fractional* values near the block boundaries can lower the max overlap further (the original continuous formulation permits this).

1. **Lift** – start from `best_bin` and treat it as a real vector `h ∈ [0,1]^n`.  
2. **Project to the simplex** – enforce the integral constraint by scaling:

   ```
   h = h * ( (n/2) / np.sum(h) )
   ```

   (this keeps the total exactly `n/2`).  
3. **Smooth‑max objective** – replace `max_s f_s` by a differentiable upper bound

   \[
   \Phi_\alpha (h)=\frac{1}{\alpha}\log\Bigl(\sum_{s=0}^{n-1}\exp\bigl(\alpha\,f_s(h)\bigr)\Bigr),
   \qquad \alpha>0 .
   \]

   For large `α` the function approaches the true maximum; we start with a modest `α=5` and increase it geometrically (`α←1.5·α`) after each optimisation stage.

4. **Gradient** – each `f_s` has a simple analytic gradient:

   \[
   \frac{\partial f_s}{\partial h_i}=1 -\mathbf 1_{i+s<n}\,h_{i+s}
                                 -\mathbf 1_{i-s\ge0}\,h_{i-s}.
   \]

   Consequently  

   \[
   \nabla\Phi_\alpha = \sum_{s} w_s\,\nabla f_s, \quad
   w_s = \frac{\exp(\alpha f_s)}{\sum_{t}\exp(\alpha f_t)} .
   \]

5. **Projected L‑BFGS‑B** – minimise `Φ_α(h)` using SciPy’s `minimize` with method=`L‑BFGS‑B`, bounds `[0,1]`, and a linear equality constraint `∑h = n/2`.  
   The optimiser is called repeatedly with increasing `α` (continuation), each time using the solution of the previous stage as the start point.

6. **Termination** – stop when the improvement in `C5` over the last two `α`‑stages is < 1e‑5 or when the overall time budget is exhausted.

The final vector `h*` is the continuous refinement of the best binary pattern and respects all constraints.
