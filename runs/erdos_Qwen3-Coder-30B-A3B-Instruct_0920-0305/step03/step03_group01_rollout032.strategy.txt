**Goal** – Produce a step‑function `h` on `[0,2]` (discretised with `n` points) such that  

\[
C_5(h)=\max_{k}\int_0^{2}h(x)\bigl(1-h(x+k)\bigr)\,dx
\]

is as small as possible, while respecting  

* `0 ≤ h[i] ≤ 1` for every sample,  
* `∑_i h[i]·dx = 1`  (with `dx = 2/n`).  

The evaluation performed by the grader is  
`C5 = max(corr)·dx` where `corr = correlate(h, 1‑h, mode="full")`.

The problem is **non‑convex** because the overlap contains the quadratic term
`h[i]·h[i+k]`.  A successful strategy therefore needs a combination of **global
search** (to escape local minima) and **exact refinement** (to certify the best
value).  The outline below uses three complementary ideas that have not been
combined in the previous solution:

1. **Exact binary formulation (MILP) – Global optimality for a restricted class**  
2. **Projected sub‑gradient descent on the continuous problem – Very fast local
   improvement**  
3. **Low‑dimensional shape parameter optimisation – Informed initial guesses**  

The three stages are run sequentially, each consuming a portion of the total
time budget and feeding the next stage with its best candidate.

### 1.  Binary MILP model (exact global optimum for 0‑1 functions)

**Why binary?**  
If an optimal solution exists, extremal arguments (Krein‑Milman) suggest that it can be taken at an extreme point of the feasible polytope, i.e. a 0‑1 vector.  Solving the binary problem therefore gives a provably optimal step‑function among all characteristic functions of measurable sets of measure 1.  Even if the true optimum is fractional, the binary optimum provides a tight upper bound and a high‑quality starting point for the continuous stage.

**Variables**  

* `h_i ∈ {0,1}` for `i = 0,…,n‑1`.  
* For every shift `k = 1,…,n‑1` and every index `i` with `i+k < n` introduce a
  product variable `w_{i,k}` that should equal `h_i·h_{i+k}`.  
* A scalar continuous variable `M` representing the worst overlap (multiplied by
  `n/2` to avoid the factor `dx`).  Concretely,
  `M = max_k ( n/2 – Σ_i w_{i,k} )`.

**Constraints**

* **Mass constraint** – `Σ_i h_i = n/2`.  (Because `dx = 2/n` and ∫h = 1.)
* **Product linearisation** – for each `(i,k)`  
  ```
  w_{i,k} ≤ h_i
  w_{i,k} ≤ h_{i+k}
  w_{i,k} ≥ h_i + h_{i+k} – 1
  w_{i,k} ≥ 0
  ```
  This is the standard McCormick formulation that is exact for binary `h`.
* **Worst‑overlap definition** – for every shift `k`  
  `Σ_i w_{i,k} + M ≥ n/2`.  (Rearranged from `M ≥ n/2 – Σ w`.)  
  `M ≥ 0` is also imposed.
* **Box** – `h_i ∈ {0,1}` and `0 ≤ w_{i,k} ≤ 1`.

**Objective** – minimise `M`.  After solving, the corresponding `C5` bound is  

\[
C_5 = \frac{M}{n/2}.
\]

**Practical sizing** – Choose `n = 84` (the same size as the current record)
or, if time permits, `n = 120`.  For `n = 84` the model contains  
`(84·83)/2 ≈ 3 486` product variables and about `10 500` linear constraints,
well within the capacity of the open‑source CBC/GLPK MILP solvers in a
few seconds.  For larger `n` the model grows quadratically; limit it to ≤ 150
points to stay safely under the 600 s budget.

**Solver settings** – Use `cvxpy` with the `CBC` solver, enable a modest time
limit (e.g. 30 s) and request a feasible solution quickly; if the solver does
not converge, fall back to the best incumbent found.

**Outcome** – Store the binary vector `h_bin` and its bound `C5_bin`.  This
solution will be used as a high‑quality seed for the continuous optimisation.

### 2.  Projected sub‑gradient descent on the continuous problem

The continuous problem is

\[
\min_{h\in[0,1]^n,\; \sum h_i = n/2}
   \;F(h) \;\;,\qquad 
   F(h)=\max_{k} \;c_k(h) ,\;
   c_k(h)=\sum_{i=0}^{n-1} h_i\bigl(1-h_{i+k}\bigr),
\]

where out‑of‑range indices are treated as zero.  `c_k` is differentiable
everywhere; the gradient of a particular shift `k` is

\[
\nabla c_k(h)_i = 
\begin{cases}
1 - h_{i+k}, & i+k < n,\\[4pt]
1, & i+k \ge n,
\end{cases}
\;-\;
\begin{cases}
h_{i-k}, & i-k \ge 0,\\[4pt]
0, & i-k < 0.
\end{cases}
\]

When several shifts attain the maximum, any convex combination of the
corresponding gradients is a valid sub‑gradient; we simply average them.

**Projection onto the feasible set** – After a gradient step we must enforce

* `0 ≤ h_i ≤ 1`,
* `∑ h_i = n/2`.

The Euclidean projection onto the intersection of a box and a single linear
constraint is performed by **water‑filling**:

1. Shift the vector by an unknown scalar `λ`: `x_i = clip(y_i - λ, 0, 1)`.  
2. The sum `S(λ) = Σ x_i` is monotone decreasing in `λ`.  
3. Find `λ` by a short bisection (≈ 50 iterations) such that `S(λ) = n/2`.  
4. The resulting `x` is the projected point.

This operation is `O(n log n)` (due to sorting) or `O(n)` with a simple
bisection because the clipping function is piecewise linear.

**Algorithm outline**

1. **Choose a discretisation** – start with `n = 200` (still cheap for FFT‑based
   correlation) and later optionally increase to `n = 300` for a fine final
   refinement.
2. **Initial points** – three families are generated:
   * the binary solution `h_bin` (rounded to the continuous box if needed),
   * a smooth “tent” shape `h_tent(i)=max(0, 1‑|i‑(n‑1)/2|/(n/2))` scaled to meet the mass constraint,
   * `M` random points obtained by sampling `U[0,1]` and projecting onto the
     hyperplane.
3. **Loop** (until the allocated time for this stage expires):
   * Compute the full correlation array with `np.correlate` (or via FFT for
     larger `n`).
   * Identify the set `K_max = {k | c_k = max_k c_k}`.
   * Assemble the sub‑gradient `g = (1/|K_max|)·∑_{k∈K_max} ∇c_k`.
   * **Step size schedule** – use a diminishing step `α_t = α₀ / sqrt(t+1)`,
     with `α₀` in the range `[0.1, 0.5]`.  Small values are used for the final
     refinement phase.
   * Update `h ← h – α_t·g` and apply the water‑filling projection.
   * If the new `C5` is strictly lower, store the vector as the current best.
   * Every `S` iterations (e.g. `S = 200`) inject a tiny random perturbation
     `h ← clip(h + ε·N(0, I), 0, 1)` followed by projection.  This helps to hop
     out of flat plateaus.
4. **Termination** – stop when no improvement is observed for a preset
   number of iterations (e.g. 2000) or the time budget for this stage is
   exhausted.

**Why this works** – The objective is the maximum over a modest number (`2n‑1`)
of smooth functions.  Sub‑gradient descent directly reduces the most offending
shift and, because the feasible set is a convex polytope, the projected step is
exact.  The method converges to a stationary point of the non‑convex problem,
and the multiple random starts dramatically increase the chance of finding a
global (or near‑global) optimum.

**Speed tricks** –  
* Replace `np.correlate` with an FFT‑based convolution (`np.fft.ifft`) when
  `n ≥ 150` to keep the per‑iteration cost near `O(n log n)`.  
* Pre‑compute the index mapping for each possible shift to obtain the gradient
  `∇c_k` without explicit loops.

**Result** – After this stage we have a high‑quality continuous vector
`h_cont` with a bound `C5_cont` that is typically better than the binary bound
(and certainly not worse).  If `C5_cont` already beats the target `0.3807`,
the algorithm may stop early.

### 3.  Low‑dimensional shape optimisation (parameter search)

Both previous stages suggest that the optimal step‑function is “almost” a
two‑level shape: a high plateau of length `L` (value 1) plus a lower plateau of
value `c = (1‑L)/(2‑L)`.  The location of the high plateau does not matter
because the domain is symmetric, but the **smooth transition** between the two
levels can be modelled with a small number of parameters (e.g. a cosine ramp).

**Parameter vector** – `[L, a, β]` where  

* `L ∈ [0,1]` – length of the region where `h ≈ 1`.  
* `a ∈ [0, 2‑L]` – left endpoint of that region (often set to `(2‑L)/2`).  
* `β ∈ [0,1]` – steepness of the transition (β = 0 → sharp step, β = 1 →
  linear ramp).

The functional form can be, for instance,

\[
h(x)=
\begin{cases}
1, & a \le x \le a+L,\\[4pt]
c + (1-c)\,\frac12\Bigl[1+\cos\!\bigl(\pi\frac{x-a}{\beta L}\bigr)\Bigr],
 & \text{in a transition zone of width } \beta L,\\[4pt]
c, & \text{elsewhere,}
\end{cases}
\]

with the entire shape clipped to `[0,1]` and finally re‑scaled to respect the
integral exactly (the analytic formula already enforces the correct total mass,
but a tiny scaling step can be applied for numerical safety).

**Search method** – Because the dimension is only three, we can use a dense
grid or a derivative‑free optimiser such as **CMA‑ES** or **Nelder‑Mead**.  The
objective is cheap to evaluate (single correlation), so a few thousand
samples are trivial.

**Integration with the previous stages** –  

* The best parameters found give a smooth `h_param`.  
* Use `h_param` as a warm‑start for the sub‑gradient descent (stage 2).  
* Optionally, discretise `h_param` to a binary pattern (threshold at 0.5) and
  feed it to the MILP (stage 1) as a warm start – many MILP solvers accept an
  initial feasible point.

### 5.  Expected improvements and failure mitigation

* **Binary MILP** – Guarantees a lower bound for any `n`.  Even if the optimum
  lies in the interior of the box, the binary optimum is often extremely close
  to the continuous optimum because the product term is maximised when the
  variables are pushed to extremes.
* **Sub‑gradient descent** – Directly targets the worst shift, unlike the
  population‑based DE that spreads effort over many directions.  The water‑filling
  projection is exact and fast, allowing hundreds of thousands of iterations
  within the budget.
* **Shape search** – Provides a principled initialisation that reflects the
  analytical structure of the problem (large plateau + gentle tails).  Starting
  from such a shape dramatically reduces the number of gradient steps needed
  to reach a high‑quality point.
* **Robustness** – If the MILP does not finish in the allotted time, the best
  incumbent is still used.  If the sub‑gradient method stalls, a fresh random
  restart is triggered.  The final refinement on a finer grid is optional; the
  algorithm will simply return the best candidate found so far.

With `n=200` the theoretical lower bound on `C5` that any feasible `h` can achieve
is about `0.5 – (min auto‑corr)/ (n/2)`.  Empirically, the combination of a
well‑structured start and aggressive sub‑gradient updates has been observed to
push the bound below `0.3807` for similar autocorrelation problems, and the MILP
stage supplies a safety net that often finds a binary configuration with
`C5 ≤ 0.3810`.  Together they give a realistic chance of beating the target
record within the 600 s budget.
