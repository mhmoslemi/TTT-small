**Goal** – produce a step function \(h:[0,2]\to[0,1]\) (represented by an array of samples) that satisfies  

* \(0\le h_i\le 1\) for all samples,  
* \(\displaystyle\sum_{i=0}^{n-1} h_i\,\Delta x = 1\)  with \(\Delta x = 2/n\),

and **minimises**  

\[
C_5(h)=\max_{k}\;\int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx
      =\max_{k}\;\Delta x\sum_{i=0}^{n-1} h_i\bigl(1-h_{i+k}\bigr),
\]

where out‑of‑range indices are treated as zero.  
The current best bound is ≈ 0.38106; we aim for ≤ 0.3807.

The proposed pipeline is **structurally different** from the DE+SLSQP approach that produced the current record. It combines three complementary ideas that have not been used together before:

1. **A low‑dimensional global search on a smooth parametric family** (CMA‑ES on block heights).  
2. **A deterministic projected sub‑gradient descent on the full‑resolution vector**, exploiting the explicit analytic sub‑gradient of the worst‑shift overlap.  
3. **An exact combinatorial refinement** – binary rounding, swap‑based hill‑climbing, and, if time permits, a *mixed‑integer linear programme* (MILP) that solves the binary version to optimality for the chosen discretisation.

The stages are executed sequentially, each feeding the best result to the next. The total wall‑clock budget (≤ 600 s) is divided adaptively among the stages; if a later stage finishes early the leftover time is passed to the following one.

### 1.  Discretisation choice

* **Resolution** – fix \(n = 200\) sample points (Δx = 0.01).  
  *‑Rationale‑*: 200 points give a fine enough description to capture the shape of the optimal continuous function while keeping all subsequent linear‑algebraic and integer‑programming steps comfortably small (≈ 20 000 binary variables for the MILP).
* **Indexing** – shift \(k\) in the correlation corresponds to array offset `k_idx = k + n - 1`. Positive \(k\) means “h shifted right”.

All later formulas assume this discretisation.

### 2.  Stage A – Global optimisation on a **block‑height** parametrisation

#### 2.1  Parametric model
Divide the interval into \(m\) equal blocks (e.g. \(m=10\)).  
All points inside block \(j\) share the same height \(u_j\in[0,1]\).  

The full‑resolution vector is obtained by repeating each \(u_j\) `n/m` times (or by nearest‑neighbour interpolation if `n` is not a multiple of `m`).

#### 2.2  Constraint handling
The integral constraint becomes a single linear equality

\[
\frac{2}{m}\sum_{j=1}^{m} u_j \;=\;1\quad\Longleftrightarrow\quad
\sum_{j=1}^{m} u_j = \frac{m}{2}.
\]

During optimisation we keep the first \(m-1\) heights free and set

\[
u_m = \frac{m}{2} - \sum_{j=1}^{m-1} u_j,
\]

rejecting any candidate that pushes \(u_m\) outside \([0,1]\).

#### 2.3  Optimiser
Use **CMA‑ES** (Covariance Matrix Adaptation Evolution Strategy) because

* it needs only function evaluations,
* it copes well with non‑convex, flat landscapes,
* it converges quickly in ≤ 10 dimensions.

Configuration (all deterministic with a fixed seed):

* Population size ≈ 4 + m (≈ 14 for \(m=10\)).  
* Initial step‑size = 0.2.  
* Maximum number of function evaluations ≈ 1500 (≈ 1 min on a single core).

Each evaluation expands the block heights to a 200‑point vector and computes  

\[
C_5 = \Delta x\;\max_k \text{corr}(h,1-h)
\]

via `np.correlate`. The best block‑height vector \(\mathbf u^\*\) and its expanded \(h^{(A)}\) are stored.

### 3.  Stage B – **Projected sub‑gradient descent** on the full vector

The objective is a pointwise maximum of smooth functions  

\[
c_k(h)=\sum_i h_i\bigl(1-h_{i+k}\bigr).
\]

Let  

\[
k^\* = \arg\max_k c_k(h) .
\]

For a fixed shift \(s=k^\*\) (zero‑padding assumed) the partial derivative of the active term is

\[
\frac{\partial c_s}{\partial h_i}
   = \bigl(1-h_{i+s}\bigr)-h_{i-s},
\]
where out‑of‑range indices contribute zero.

Hence a **sub‑gradient** of \(C_5\) at the current iterate is the vector \(g\) whose entries are given by the formula above.

#### 3.1  Update step
With a step‑size schedule \(\alpha_t = \alpha_0/\sqrt{t+1}\) (e.g. \(\alpha_0 = 0.5\)) we compute

\[
\tilde h = h^{(t)} - \alpha_t g .
\]

#### 3.2  Projection onto the feasible set
The feasible set is the intersection of a hyperplane and a box:

\[
\mathcal F = \{\,h\in[0,1]^n \mid \mathbf 1^\top h = n/2 \,\}.
\]

Projecting onto \(\mathcal F\) can be done by a **water‑filling** (bisection on a Lagrange multiplier):

* Find λ such that  

  \[
  x_i = \operatorname{clip}\bigl(\tilde h_i - λ,\;0,\;1\bigr)
  \]
  satisfies \(\sum_i x_i = n/2\).

* Because the sum is monotone decreasing in λ, a simple bisection (≈ 50 iterations) yields λ to machine precision; the resulting \(x\) is the projected point.

Set \(h^{(t+1)} = x\).

#### 3.3  Stopping / early‑exit criteria
* Maximum iterations = 3000 (≈ 0.8 min).  
* If the best \(C_5\) has not decreased by more than \(10^{-6}\) over the last 200 iterations, abort early.

The best vector encountered during the whole descent (call it \(h^{(B)}\)) is saved.

### 4.  Stage C – **Binary rounding and combinatorial local improvement**

The continuous optimum is often close to a 0/1 function, and the true integer optimum can be strictly better for the max‑overlap objective. This stage converts the best continuous vector into a high‑quality binary step function.

#### 4.1  Probabilistic rounding
* Sort indices by decreasing value of \(h\).  
* Set the top \(n/2\) indices to 1, the rest to 0 → binary vector \(b^{(0)}\).  
* Repeat the above **K = 30** times, each time applying a tiny random perturbation (e.g. add i.i.d. Gaussian noise σ = 0.02 before sorting) to explore nearby combinatorial selections.  
* Keep the binary vector with the smallest \(C_5\) (evaluated via correlation). Call it \(b^{(0)}\).

#### 4.2  Fast evaluation of swaps
For a binary vector define the overlap counts  

\[
S_k = \sum_{i} b_i b_{i+k},\qquad k=1,\dots,n-1 .
\]

The worst‑case overlap is  

\[
C_5(b) = \Delta x\;\max_k\bigl(\tfrac{n}{2} - S_k\bigr).
\]

When swapping a 1 at position \(p\) with a 0 at position \(q\) the only affected terms are those shifts that involve either \(p\) or \(q\). The delta for a single shift \(k\) can be computed in O(1) by checking whether the shifted partners \(p\pm k\) and \(q\pm k\) are 1. Hence a full swap evaluation costs O(n) → acceptable for the modest n=200.

#### 4.3  Hill‑climbing loop
```
repeat
    best_improvement = 0
    randomly sample a modest fraction (≈0.2 %) of all (p,q) pairs
    for each sampled pair (p,q) with b_p=1, b_q=0:
        compute ΔC5 if we swap p↔q
        if ΔC5 < best_improvement:
            store pair as best_swap
    if best_improvement < 0:
        execute best_swap
        update all S_k incrementally (O(n))
        continue
    else
        break   # local optimum reached
```

The outer repeat is performed up to 10 times (or until no improvement in a full pass). The result is a binary vector \(b^\*\) that is locally optimal with respect to all single swaps.

#### 4.4  Output conversion
Return \(h^{(C)} = b^\*\) as a float array (values 0.0 or 1.0). Its \(C_5\) value is recorded as `c5_C`.

### 5.  Stage D – **Exact MILP refinement** (optional, time‑limited)

If after Stage C there are ≥ 30 s remaining, we launch a mixed‑integer linear programme that finds the *globally optimal binary* vector for the chosen discretisation. The MILP is built as follows.

#### 5.1  Decision variables
* \(h_i \in \{0,1\}\) for each sample \(i\).  
* \(w_{i,k}\in\{0,1\}\) for every feasible ordered pair \((i,i+k)\) (i.e. for \(k=1,\dots,n-1\) and \(i=0,\dots,n-1-k\)).  
* Continuous scalar \(C\ge0\) representing the worst‑case overlap *in sample‑units*.

#### 5.2  Linearisation of the product
For each \((i,k)\) add the classic “AND” constraints

```
w_{i,k} ≤ h_i
w_{i,k} ≤ h_{i+k}
w_{i,k} ≥ h_i + h_{i+k} – 1
```

These enforce \(w_{i,k}=h_i·h_{i+k}\).

#### 5.3  Overlap constraints
Recall that with binary variables \(\sum_i h_i = n/2\).  
For each shift \(k\) the overlap count in sample units equals

\[
\text{ov}_k = \frac{n}{2} - \sum_i w_{i,k}.
\]

Impose

\[
\text{ov}_k \le C \quad\Longleftrightarrow\quad
\sum_i w_{i,k} + C \ge \frac{n}{2},\qquad \forall k=1,\dots,n-1 .
\]

#### 5.4  Additional constraints
* Exact weight: \(\sum_i h_i = n/2\).  
* Box constraints on \(h_i\) are implicit in the binary domain.

#### 5.5  Objective
\[
\min\; C .
\]

The resulting linear programme (with integer variables) yields the smallest possible worst‑case overlap for binary step functions of the chosen discretisation. The continuous bound is then \(C_5 = C\cdot\Delta x\).

#### 5.6  Solver configuration
* Use **CVXPY** with the `CBC` (or `GLPK_MI`) solver.  
* Pass a hard wall‑clock limit (`maximumSeconds = remaining_time`).  
* Warm‑start: set the binary variables to the pattern \(b^\*\) from Stage C (most solvers accept initial values).  

If the solver terminates with optimality, we obtain the *provably best* binary bound for that \(n\). If it stops early, the best feasible solution found (and its objective value) is still a valid upper bound and supersedes the Stage C result.

### 7.  Expected failure modes & mitigations

| Failure mode | Why it occurs | Mitigation |
|--------------|---------------|------------|
| **CMA‑ES generates infeasible block vectors** (last block outside \([0,1]\)) | Linear reduction may push \(u_m\) beyond bounds. | Reject the individual candidate and ask CMA‑ES to sample a new one; keep the population size unchanged. |
| **Sub‑gradient descent stalls or oscillates** | Step‑size too large or the active shift changes erratically. | Use the decaying schedule \(\alpha_t = \alpha_0/\sqrt{t+1}\); after every 500 iterations recompute the worst shift and, if it changed, reset a modest momentum term (Nesterov‑type) to stabilise. |
| **Projection bisection fails to reach exact mass** | Numerical round‑off after many iterations. | After the bisection, perform a cheap corrective scaling: compute the residual mass error and distribute it uniformly over non‑saturated entries (those not at 0 or 1). |
| **Swap‑hill‑climber gets trapped in a local optimum** | The neighbourhood of single swaps may be insufficient. | Periodically (every 5 passes) perform a **random perturbation**: flip 2–3 random bits (while preserving total weight) and resume the hill‑climb; additionally allow a small probability (≈ 5 %) of accepting a *worsening* swap (simulated‑annealing style) with a cooling schedule. |
| **MILP exceeds memory or time** | Number of product variables grows as \(O(n^2)\). | Use a smaller discretisation (e.g. \(n=180\)) if the solver reports “out of memory”; alternatively, drop the product variables for shifts that are not among the current worst 30 % (the omitted constraints can only increase the objective, so the bound remains valid albeit weaker). |
| **Numerical discrepancy between our correlation and the evaluator** | Off‑by‑one handling of zero‑padding. | Validate early by computing `C5` for a simple known vector (e.g. all 0.5) and checking that both our routine and the hidden `evaluate_erdos_solution` give the same value; adjust indexing if needed. |
