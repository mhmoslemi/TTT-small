### 2.  Discretisation choice

* **Resolution** – Use \(n=200\) samples (Δx = 0.01).  
  * This gives a good trade‑off: the correlation matrix is only \(200\times200\) (≈ 40 k entries) so each evaluation is cheap; the MILP will have ≈ 19 500 binary/product variables – still tractable for CBC in a minute.  
* **Indexing** – Correlation index `k_idx = shift + n - 1`.

  * The zero shift is ignored (its overlap is identically zero for binary vectors, but non‑zero for continuous; the algorithm treats it like any other shift).

### 3.  Stage A – Low‑dim global optimisation

#### 3.1  Parametrisation
Represent \(h\) by **m equal‑width blocks** (e.g. \(m=10\)).  
Each block \(b_j\) carries a constant height \(u_j\in[0,1]\).  
The discretised vector is obtained by repeating each height `n/m` times (or by linear interpolation if `n` not divisible by `m`).  

**Constraint** – total mass 1 gives a single linear equality  

\[
\frac{2}{m}\sum_{j=1}^{m}u_j = 1\qquad\Longleftrightarrow\qquad\sum_{j=1}^{m}u_j = \frac{m}{2}.
\]

During optimisation we enforce this equality by **affine reduction**: keep the first \(m-1\) heights free, set  

\[
u_m = \frac{m}{2}-\sum_{j=1}^{m-1}u_j,
\]

clipping \(u_m\) to \([0,1]\) (reject infeasible samples).

#### 3.2  Optimiser
Use **CMA‑ES** (Covariance Matrix Adaptation Evolution Strategy) because:

* It works well on low‑dim smooth but non‑convex landscapes.
* It needs only function evaluations (no gradients).
* With a modest population (e.g. `popsize = 4+m`) it converges quickly.

**Settings**

* Max evaluations: 1500 (≈ 120 s for \(m=10\)).
* Initial step‑size: 0.2.
* Random seed fixed for reproducibility.

Each candidate is expanded to the full 200‑point vector, evaluated with `np.correlate`, and the resulting \(C_5\) value is returned to CMA‑ES.

#### 3.3  Output
After the allotted budget the best block‑height vector \(\mathbf{u}^\*\) and the corresponding full‑resolution \(h^{(A)}\) are kept for the next stage.

### 4.  Stage B – Projected sub‑gradient descent on the full vector

The objective \(C_5(h)=\max_k c_k(h)\) is a **max of smooth functions**.  
At any point the worst shift(s) \(k^\*\) can be identified, and a sub‑gradient of the active term is easily computed:

*Define*  

\[
c_k(h)=\sum_{i=0}^{n-1}h_i\bigl(1-h_{i+k}\bigr),\qquad
\text{with }h_{j}=0\text{ for }j\notin[0,n-1].
\]

For a chosen shift \(s\) (the index of a maximal overlap) the partial derivative w.r.t. component \(h_i\) is  

\[
\frac{\partial c_s}{\partial h_i}= \bigl(1-h_{i+s}\bigr)-h_{i-s},
\]

where out‑of‑range terms are taken as zero.

#### 4.1  Gradient step
Given the current vector \(h\) and the worst shift \(s\),

```
g_i = (1 - h[i+s]) - h[i-s]   (zero‑padding at the ends)
h' = h - α * g                (α > 0)
```

The step size α is **decreased slowly** (e.g. α = α0 / sqrt(t+1)) to guarantee stability.

#### 4.2  Projection onto the feasible set
After the update we must enforce:

* Box constraints \(0\le h_i\le1\).
* Equality \(\sum_i h_i = n/2\).

The projection onto the intersection of a hyperplane and a box is the **water‑filling** operation:

1. Start from \(y = h'\) (unconstrained).
2. Find a scalar λ such that  

   \[
   x_i = \operatorname{clip}(y_i - λ,\;0,\;1)
   \]

   satisfies \(\sum_i x_i = n/2\).  
   Because the sum is a monotone decreasing function of λ, a simple **bisection** (≈ 50 iterations) yields λ to machine precision.

The resulting \(x\) is the projected vector and becomes the next iterate.

#### 4.3  Stopping criteria
* Stop after a fixed number of iterations (e.g. 3000) **or**
* Stop early if the improvement in \(C_5\) over the last 200 iterations is < 1e‑6.

All intermediate best vectors (and their \(C_5\) values) are stored. The best found \(h^{(B)}\) proceeds to Stage C.

### 5.  Stage C – Binary rounding & combinatorial local optimisation

The continuous solution is often close to a binary one, yet the exact optimum may involve fractional values. We therefore:

#### 5.1  Probabilistic rounding
Interpret each component \(h_i\) as a probability of selecting a “1”.  
Generate a **binary vector** \(b\) of length \(n\) with exactly \(n/2\) ones by:

1. Sample a random permutation of the indices.
2. Walk through the permutation, setting \(b_i=1\) with probability proportional to \(h_i\) while keeping the total count exactly \(n/2\).  
   (A simple way: sort indices by decreasing \(h_i\) and take the top \(n/2\) as ones.)

Do this **K = 30** times, evaluate the exact \(C_5\) for each binary candidate using correlation, and keep the best (call it \(b^{(0)}\)).

#### 5.2  Swap‑based local search
Define a **swap move**: pick a pair \((i,j)\) with \(b_i=1, b_j=0\) and exchange their values.  
The effect on each overlap sum \(S_k=\sum_i b_i b_{i+k}\) can be updated *in O(1)* per shift using pre‑computed contribution tables:

*Before swap:*  
Contribution of index i to shift k: \(b_i b_{i+k}\) (if in range).  
Similarly for index j.

*After swap:*  
Replace \(b_i\) by 0 and \(b_j\) by 1, recompute contributions for the same set of shifts.

The **delta** in the worst‑overlap value is the maximum over all shifts of the change in \(1 - S_k\Delta x\).  

**Local‑search loop**

```
repeat
    best_improvement = 0
    for each (i,j) with b_i=1, b_j=0 (sample a random subset ≈ 0.1% of all pairs)
        compute ΔC5 for swapping i↔j
        if ΔC5 < best_improvement:
            store (i,j) as best_swap
    if best_improvement < 0:
        perform best_swap
        update all S_k incrementally
    else
        break   # local optimum reached
```

The loop stops when no improving swap is found among the sampled pairs. Because we only sample a fraction of all possible pairs each iteration, a full pass costs very little; we repeat the outer loop a few times (≈ 10) to exhaust improvements.

The resulting binary vector \(b^{*}\) (converted to floating point for the return) is a **high‑quality 0/1 step function**.

### 6.  Stage D – Exact MILP refinement (optional, time‑limited)

If the budget still has ≥ 30 s, we launch a **mixed‑integer linear program** that solves the original max‑overlap problem **exactly** for the chosen discretisation **under the binary restriction**.

#### 6.1  Variables
* \(h_i\in\{0,1\}\) – the binary step function (size n).  
* \(w_{i,k}\in\{0,1\}\) – auxiliary product variables,
  \(w_{i,k}=h_i\,h_{i+k}\) for all feasible pairs \((i,k)\) (i.e. \(0\le i,i+k<n\)).  
* \(C\ge0\) – a scalar representing the worst overlap *in sample‑units* (i.e. `C = max_k Σ_i h_i (1‑h_{i+k})`).

#### 6.2  Linearisation of the product
For each pair \((i,k)\) we add the classic **AND constraints**

```
w_{i,k} ≤ h_i
w_{i,k} ≤ h_{i+k}
w_{i,k} ≥ h_i + h_{i+k} – 1
```

These force \(w_{i,k}=1\) iff both endpoints are 1, otherwise 0.

#### 6.3  Overlap constraints
The overlap for shift \(k\) equals  

\[
\text{ov}_k = \sum_i h_i - \sum_i w_{i,k}
            = \frac{n}{2} - \sum_i w_{i,k}\qquad(\because\sum_i h_i=n/2).
\]

Impose  

\[
\text{ov}_k \le C\quad\forall k\in\{1,\dots,n-1\}.
\]

Equivalently  

\[
\sum_i w_{i,k} + C \ge \frac{n}{2}\quad\forall k.
\]

#### 6.4  Additional constraints
* Exact weight: \(\displaystyle\sum_i h_i = n/2\).
* Box constraints on \(h_i\) are implicit in binary domain.

#### 6.5  Objective
Minimize \(C\).

#### 6.6  Solver configuration
* Use **CVXPY** with the `CBC` (or `GLPK_MI`) solver.  
* Pass a time limit (e.g. `solver_kwargs={'maximumSeconds': 30}`) so the solver returns the best feasible bound within the remaining budget.  
* Warm‑start the binary variables with the vector \(b^{*}\) obtained in Stage C (CVXPY supports `parameter` values or one can set initial values via the solver’s `warm_start` flag).

The solver yields a *guaranteed* upper bound \(C_{\text{MILP}}\) on the binary problem for the chosen discretisation, which we translate back to the continuous integral by multiplying with Δx.

If the MILP finishes to optimality the binary solution is *globally optimal* for the given \(n\); otherwise we keep the best feasible solution found.

### 8.  Anticipated failure modes & mitigations

| Failure mode | Why it happens | Counter‑measure |
|--------------|----------------|-----------------|
| Gradient step overshoots → oscillation or violation of bounds | Large α or steep sub‑gradient for early iterations | Use a **decaying step‑size schedule** (α₀/√t) and enforce projection after every step. |
| Water‑filling projection stalls (λ bounds exhausted) | Numerical rounding may push sum slightly out of feasible interval | Expand the bisection interval a little (e.g. `[-2, 3]`) and stop after a fixed number of iterations, then renormalise by scaling the whole vector. |
| CMA‑ES repeatedly generates infeasible block vectors (last block out of [0,1]) | Linear reduction may push `u_m` outside bounds | Reject and resample any candidate whose derived `u_m` violates `[0,1]`. |
| Binary local search gets stuck in a poor local optimum | Swap neighbourhood may be too limited | Periodically **randomly shuffle** a small fraction (≈ 5 %) of the bits and restart the swap loop; also try **simulated‑annealing acceptance** for worsening swaps with a cooling schedule. |
| MILP too large → no solution within time | For n=200 the number of product variables is ≈ 20 k, which may be heavy for some solver builds | Keep n at 180 (≈ 16 k product vars) if the solver reports “out of memory”; also limit the MILP to a **subset of shifts** (e.g. only the worst 30 % of shifts identified from the binary candidate) – this yields a valid upper bound (since we are minimizing C). |
| Numerical discrepancy between discrete correlation and the continuous definition | Edge handling (zero‑padding) may be interpreted differently | Always use the exact same `np.correlate` call that the evaluator uses; verify early on that a known vector (e.g. all 0.5) gives the expected C5. |

### 9.  Why this strategy is “materially different”

* **Low‑dim evolutionary search on block heights** – reduces the search space dramatically compared with the 42‑dim DE used previously.
* **Explicit projected sub‑gradient descent** on the *max‑overlap* objective – a deterministic descent method absent from the original pipeline.
* **Binary combinatorial refinement** – a focused swap‑based hill‑climber that operates on the exact 0/1 problem, rather than continuous SLSQP refinements.
* **Optional exact MILP** – solves the binary version to provable optimality for the chosen discretisation; the original code never attempted a formal integer programming formulation.
* **Clear time‑budget partitioning** – guarantees that each stage gets sufficient work while keeping the total runtime under control.

By tackling the problem from three complementary angles (coarse global, fine deterministic, discrete exact), the approach is far more likely to escape the local minima that limited the previous DE+SLSQP result and to push the bound below the target 0.3807.
