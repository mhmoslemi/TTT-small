**Overview**  
The Erdős minimum overlap problem is a *max‑min* quadratic optimisation:

\[
C_5=\max_{k}\int_0^2 h(x)\bigl(1-h(x+k)\bigr)dx
    =1-\min_{k}\int_0^2h(x)h(x+k)dx .
\]

For a discretisation with \(n\) points,
\(h\in[0,1]^n,\;\sum_i h_i=n/2\), and the linear autocorrelation
\(\rho_k=dx\sum_{i}h_i h_{i+k}\) (full mode of np.correlate).  
Thus we want to **maximise the smallest autocorrelation** \(\rho_k\) while
respecting the box and sum constraints.

Instead of the gradient‑based heuristics used previously, we formulate the
problem as a **mixed‑integer linear program (MILP)** that exactly captures the
quadratic products by linearising them with McCormick envelopes.  
A MIP solver (CBC, GLPK_MI, Gurobi, SCIP, …) then performs a systematic
branch‑and‑bound search, guaranteeing a feasible solution and often the
global optimum for moderate \(n\) (the budget allows up to a few‑seconds of
solver time).  A tiny deterministic local‑search polish is added afterwards
to squeeze out any remaining improvement.

The whole pipeline consists of **four stages**:
1. Discretisation choice.  
2. Exact MILP model construction (binary variables for a step function).  
3. Solving the MILP under the time budget.  
4. Optional greedy swap‑local‑search refinement.

Because the MILP directly encodes the definition of the overlap integral,
the method is mathematically orthogonal to the previous L‑BFGS‑B/simulated‑annealing
approach.

### 2. MILP model (exact “binary” step function)

**Decision variables**

* `h[i]    ∈ {0,1}`   – the step function (binary is natural for a “step”).
* `y[i,k]  ≥ 0`       – auxiliary variable representing the product  
  `h[i] * h[i+k]` for every overlapping pair `(i,i+k)`.
* `z       ≥ 0`       – scalar upper bound on the maximal overlap integral.

**Constraints**

1. **Sum constraint**  
   ` Σ_i h[i] = target_sum`.

2. **Box constraints** (implicit in binary declaration).

3. **McCormick linearisation** for each admissible shift `k` (‑(n‑1)…(n‑1))
   and each index `i` with `j = i + k` inside `[0,n)`:

```
y[i,k] ≤ h[i]
y[i,k] ≤ h[j]
y[i,k] ≥ h[i] + h[j] - 1
y[i,k] ≥ 0                # already implied by the previous line
```

   For binary `h` these four inequalities force `y[i,k] = h[i]·h[j]`.

4. **Correlation ≥ t** (equivalently `z ≥ 1 – ρ_k`).  
   For each shift `k` compute the (unnormalised) correlation

```
rho_k = dx * Σ_{i where i+k valid} y[i,k]
```

   Add the linear constraint

```
z  ≥  1 - rho_k .
```

   (Because `C5 = max_k (1 - rho_k)`, minimising `z` drives the worst
    overlap down.)

**Objective**

```
minimise   z .
```

All constraints are linear; the model is a pure MILP.

**Why this works**

* The product `h_i h_j` appears only inside the overlap integral, so the
  McCormick formulation introduces no approximation error for binary
  variables – the model is exact.
* Optimising `z` enforces the worst‑case shift to be as small as possible,
  i.e. it implements the original max‑over‑k definition directly.
* Branch‑and‑bound explores the combinatorial space systematically, avoiding
  the local‑optimum traps common to gradient methods.

### 4. Greedy swap‑local‑search polish (optional, very fast)

The MILP solution is binary, but a few deterministic swaps can sometimes
lower the worst overlap further.

**Procedure**

1. Compute the full correlation vector `rho = dx * correlate(h_opt, h_opt, 'full')`.
2. Identify the *worst shift* `k* = argmin(rho)`.
3. For every index `i` with `h[i]=0` compute  
   `gain_i = (h[i+k*] if i+k*∈range else 0) + (h[i-k*] if i-k*∈range else 0)`.
4. For every index `j` with `h[j]=1` compute  
   `loss_j = (h[j+k*] if j+k*∈range else 0) + (h[j-k*] if j-k*∈range else 0)`.
5. Choose the pair `(i,j)` that maximises `gain_i - loss_j`.  
   If this quantity is positive, swap `h[i]←1, h[j]←0`.
6. Update `rho` incrementally (only the entries affected by the swap) and
   repeat from step 2.
7. Stop when no improving swap exists or when the remaining time budget is
   exhausted (typically after a few dozen swaps).

Because each swap strictly reduces the maximal overlap, the process is
monotone and finishes quickly (≤ 0.1 s for n = 100).
