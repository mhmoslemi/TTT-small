### 1.  Reformulate the design space as a **low‑dimensional interval problem**

The admissible step functions are exactly the indicator functions of measurable
subsets S ⊂ [0,2] of Lebesgue measure 1.  
Instead of a pointwise vector *h*∈[0,1]^{n}, describe *S* by a **small collection of
disjoint intervals**  

```
S = ⋃_{j=1}^{M} [a_j , a_j + ℓ_j]        (M  =  number of “on” blocks)
```

with  

*   ℓ_j > 0   (length of interval j)  
*   a_j ≥ 0, a_j+ℓ_j ≤ 2   (interval stays inside the domain)  
*   intervals are ordered and non‑overlapping:
    a_{j+1} ≥ a_j+ℓ_j for all j.  

The “half‑area” constraint becomes simply  

```
∑_{j=1}^{M} ℓ_j  =  1 .
```

All admissible *h* are obtained from a feasible tuple  

```
θ = (a_1,…,a_M, ℓ_1,…,ℓ_M)  ∈  ℝ^{2M} .
```

Choosing a modest *M* (4 ≤ M ≤ 8) reduces the problem from a 100‑dimensional
binary search to a 8‑12 dimensional continuous optimisation.

### 2.  Exact evaluation of the **max‑overlap** functional for a given tuple

For a fixed shift k ∈ [−2,2] the overlap integral is  

\[
A(k)=\int_0^2 h(x)\bigl(1-h(x+k)\bigr)dx
    = 1 - \rho(k) ,
\qquad
\rho(k)=\int_0^2 h(x)h(x+k)dx .
\]

When *h* is a union of intervals, ρ(k) is simply the total length of
pairwise intersections of the intervals with their **k‑shifted copies**.
Because each interval is convex, the intersection length of two intervals
is a piecewise‑linear function of k; the whole ρ(k) is therefore a
piecewise‑linear function whose breakpoints occur exactly when an endpoint of
one interval aligns with an endpoint of another (including the domain borders).

Consequences:

*Only finitely many candidate shifts need to be examined.*  
Let  

```
E = {0} ∪ { (a_i) – (a_j) , (a_i+ℓ_i) – (a_j) , (a_i) – (a_j+ℓ_j) , (a_i+ℓ_i) – (a_j+ℓ_j)
        | 1≤i,j≤M } .
```

All elements of E lie in [−2,2]; for any k not in E the value of ρ(k) (hence A(k))
lies on a linear segment and cannot be larger than the values at the
segment’s endpoints. Therefore  

```
C5(θ) = max_{k∈E} A(k)
```

can be computed in **O(M²)** time by:

1. Enumerating all pairwise endpoint differences (O(M²) numbers).  
2. For each candidate shift k, compute the sum of intersection lengths:
   for every interval j, intersect [a_j , a_j+ℓ_j] with its translate
   [a_j−k , a_j+ℓ_j−k] (or the symmetric version for negative k) and add the
   resulting length (a trivial O(1) operation per interval).  
3. Take the maximal value of 1‑ρ(k).

All calculations are done with double precision; the result is the exact
value of the objective for the continuous model (no FFT, no discretisation
error).

### 3.  Optimisation framework – **global population‑based search** on the
continuous variables

Because the objective is non‑convex but cheap to evaluate, a **black‑box
global optimiser** works extremely well.  The recommended choice is
*Differential Evolution* (DE) or *CMA‑ES* from SciPy; both accept bound
constraints and can be combined with a **projection onto the feasible set**
after each offspring is generated.

**Parameterisation and projection**

* Decision vector: `x = (a_1,…,a_M, ℓ_1,…,ℓ_M)`.
* Box bounds: `0 ≤ a_j ≤ 2‑ℓ_j`, `0 ≤ ℓ_j ≤ 1`.
* After any mutation/crossover step, perform a **simple feasibility projection**:
  1. Clip all ℓ_j to `[0,1]`.
  2. Enforce the total‑length constraint by scaling:
     `ℓ ← ℓ * (1/ Σℓ)` (the scaling preserves ordering of intervals).
  3. Sort the intervals by the current a_j values, then enforce non‑overlap by
     `a_1 ← max(0, a_1)`,
     `a_{j+1} ← max(a_{j+1}, a_j + ℓ_j)` for j=1…M‑1,
     and finally clip any interval that would exceed the right border:
     `if a_M + ℓ_M > 2: a_M ← 2‑ℓ_M`.
  This projection is O(M log M) and guarantees a feasible tuple on every
  iteration.

**DE configuration (tuned empirically for the 600 s budget)**

| Parameter                | Value (typical)                              |
|--------------------------|----------------------------------------------|
| Population size (`popsize`) | `10 × (2 M)`  (e.g. 80 for M=4, 120 for M=6) |
| Mutation factor `F`      | 0.8                                          |
| Crossover probability `CR` | 0.9                                        |
| Maximum generations      | as many as fit in the remaining time (≈ 2000‑3000) |
| Stopping criterion       | no improvement of the best C5 for 200 generations |

The optimiser is run **independently for each chosen M** (e.g. M = 4,5,6,7,8).  
Each run starts from a fresh random population; the best tuple of all runs is
kept.

### 4.  Local refinement after the global search

When a high‑quality tuple θ\* has been obtained, a **deterministic hill‑climb**
may still improve it:

1. Identify the worst shift `k* = argmax_{k∈E} A(k)`.
2. For each interval *j* compute the **marginal gain** in ρ(k*) if its length
   is increased by ε (while respecting total‑length and non‑overlap) and the
   marginal loss if decreased by ε.
3. Perform a **line search** along the direction that most improves ρ(k*) (i.e.
   reduces A(k*)). Because the objective is piecewise linear, the optimal step
   size is either limited by a neighbouring endpoint becoming aligned or by the
   total‑length bound; both are easy to compute.
4. Update the tuple, recompute the candidate shift set E (new breakpoints may
   appear) and repeat until no improvement is possible.

The local phase usually converges in a handful of iterations because the
global DE already positions the solution near a vertex of the feasible polytope.

| **Discretisation error inflates C5**             | Use a slightly larger `n_points` (e.g. 128) for the final conversion; the evaluation routine works for any even n≤1000. |
| **Numerical instability at breakpoints**        | When evaluating intersections, add a tiny epsilon (1e‑12) to avoid “touching” cases that can flip the max‑shift. |
| **Solver time‑out** (unlikely for DE)           | The algorithm is embarrassingly parallel – if a single‑process run is too slow, reduce the number of generations or population size. |
