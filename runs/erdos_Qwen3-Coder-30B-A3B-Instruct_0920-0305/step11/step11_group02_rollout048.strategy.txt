**1.  Problem reformulation**

For a discretisation with `n` points (`dx = 2/n`) the constraints are  

* `0 ≤ h[i] ≤ 1` for all `i`  
* `∑ h[i] = n/2`   (because `∫₀² h = 1`).

Denote  

```
S = n/2                                 # total mass
O_j = ∑_{i} h[i]·h[i+j]                # ordered autocorrelation,
                                        #   j = –(n‑1)…(n‑1)  (out‑of‑range terms are omitted)
```

Then  

```
g_j = ∑_{i} h[i]·(1‑h[i+j]) = S – O_j
C5(h) = dx·max_j g_j = 1 – min_j (O_j / S)
```

Hence **minimising C5 is equivalent to maximising the minimal autocorrelation**
`m = min_{j≠0} O_j`.  The objective is a *max‑of‑smooth functions* (the `g_j`).

**3.  Smooth‑max surrogate**

The non‑smooth objective  

```
F(h) = max_j g_j
```

is replaced by a differentiable surrogate

```
F_α(h) = (1/α)·log( Σ_j exp(α·g_j) )          (α > 0)
```

When `α → ∞`, `F_α → F`.  
For a given `α` the gradient is a soft‑max weighted sum of the gradients
of the individual `g_j`:

```
w_j = exp(α·g_j) / Σ_k exp(α·g_k)            (soft‑max weights, Σ w_j = 1)

∂g_j/∂h_i = – (h[i+j] + h[i‑j])               (indices out of bounds give 0)
∇F_α = Σ_j w_j·∂g_j/∂h = – Σ_j w_j·(h shifted by +j  +  h shifted by –j)
```

Thus the gradient is a **convolution** of `h` with the weight vector `w`
and with its reversal.

**4.  Fast evaluation of correlations and gradients**

All needed convolutions are performed with the FFT (complexity `O(n log n)`).

* Autocorrelation `O_j`:

```
h_rev = h[::-1]
O = ifft( fft(h_rev, L) * fft(h, L) ).real   # L = next power of two ≥ 2·n
```

* Soft‑max weights `w` are computed from `g_j = S – O_j`.

* Gradient:

```
w_rev = w[::-1]

conv_plus  = ifft( fft(w, L)      * fft(h, L) ).real   # Σ_j w_j·h[i‑j]
conv_rev   = ifft( fft(w_rev, L)  * fft(h, L) ).real   # Σ_j w_j·h[i+j]

grad[i] = -(1/S) * ( conv_plus[i+(n‑1)] + conv_rev[i+(n‑1)] )
```

Only the `n` entries centred at `i+(n‑1)` are required.

--------------------------------------------------------------------
**5.  Projection onto the feasible set (box + linear sum)**

After a gradient step we obtain an unconstrained vector `y`.
We must enforce  

```
0 ≤ y[i] ≤ 1,      Σ y[i] = S .
```

This is a classic “water‑filling’’ projection:

1. Clip `y` to `[0,1]`.
2. Find a scalar λ such that  

   ```
   Σ_i clip(y[i] - λ, 0, 1) = S .
   ```

   λ is found by a short bisection (≈30 iterations, tolerance 1e‑10).  
   The final projected vector `h_proj` is `clip(y - λ, 0, 1)`.

The routine is deterministic, cheap, and guarantees the exact sum.

```
    # 2) smooth‑max and weights
    shift  ← g - max_g                  # for numerical stability
    w_raw  ← exp(α * shift)
    w      ← w_raw / w_raw.sum()

    # 3) gradient (FFT based)
    grad   ← gradient_from_weights(h, w)   # as described in §4

    # 4) projected gradient step
    y      ← h - η * grad
    h      ← project_to_sum_box(y, S)

    # 5) evaluate true objective
    C5_now ← dx * max(g)               # exact max, not the smooth surrogate
    if C5_now < best_C5:
        best_C5 ← C5_now
        best_h  ← h.copy()

    # 6) schedule
    if iteration % 200 == 0:
        α = min(α * 1.3, α_max = 100)    # increase smoothing gradually
        η = η * 0.9                     # slowly taper the step size

    # 7) occasional random shake‑up (to escape flat regions)
    if iteration % 500 == 0 and no improvement in last 200 iters:
        h ← h + 0.02·randn(n)           # Gaussian noise, then project
        h ← project_to_sum_box(np.clip(h,0,1), S)
```

All FFTs reuse the same length `L`; only three transforms per iteration
(autocorrelation, two convolutions for the gradient).  On a modern CPU
with `n = 300` this loop easily runs >10 000 iterations within the
600 s budget, far more than the previous code’s few hundred DE generations.

--------------------------------------------------------------------
**7.  Initialisation**

Two complementary starts are used (both executed within the total time
budget; the better result is kept).

* **Upsampled known solution** – the supplied `initial_h_values`
  (length 120) are linearly interpolated to the current `n`.  
  The interpolated vector is clipped to `[0,1]` and projected onto the
  exact sum `S`.  This provides a good “warm‑start’’ close to the best
  known region of the search space.

* **Random binary start** – generate a binary vector with exactly `S`
  ones placed uniformly at random, then treat it as the continuous
  variable (binary values are admissible).  This gives a diverse
  exploration point.

Each start runs the full gradient‑descent loop independently; the best
solution among them is retained.

--------------------------------------------------------------------
**8.  Final polishing (local nonlinear optimisation)**

Although the projected gradient scheme already respects the constraints,
a few extra Newton‑type steps can sometimes shave off the last few
10⁻⁴ of the objective.

```
def obj_full(x):
    O = autocorrelation(x)
    return dx * np.max(S - O)          # exact C5

constraints = ({'type':'eq', 'fun': lambda x: np.sum(x) - S},)
bounds      = [(0.0,1.0)] * n

res = minimize(obj_full,
               x0 = best_h,
               method = 'SLSQP',
               bounds  = bounds,
               constraints = constraints,
               options = {'maxiter':200, 'ftol':1e-12})
if res.success and obj_full(res.x) < best_C5:
    best_h, best_C5 = res.x, obj_full(res.x)
```

The polishing step is called only once, after the gradient phase,
and its cost is negligible compared with the whole budget.

**10.  Failure‑mode analysis & mitigations**

| Failure mode                               | Symptom                               | Mitigation |
|--------------------------------------------|---------------------------------------|------------|
| **α becomes too large too early**          | Gradient collapses to a single shift → oscillations. | Increase α gradually (e.g. multiply by 1.3 every 200 iterations). |
| **Step size η too aggressive**             | Projection repeatedly hits bounds, making no progress. | Reduce η by 0.9 after each α‑increase; if no improvement for 100 iters, halve η. |
| **Stagnation in a flat region**           | No improvement for many iterations.   | Inject Gaussian noise (as described) and re‑project. |
| **Numerical overflow in `exp(α·g)`**       | `inf`/`nan` in weights.               | Subtract `max(g)` before exponentiation; use `np.exp` on the shifted values. |
| **Projection precision loss**              | Sum deviates from `S` by >1e‑9.       | Perform the bisection until `|Σ‑S| < 1e‑12`. |
| **Boundary effects (out‑of‑range indices)**| Wrong gradient contributions.        | Convolutions are performed with zero‑padding; the FFT formulation automatically treats missing indices as zero. |
| **Time budget exhausted before convergence**| Returned solution still far from optimum.| Reduce `n` (e.g. 240) or limit the number of restarts; the gradient loop is cheap enough that 10 000+ iterations fit easily. |

**11.  Summary of the implementation flow**

1. **Set `n`, `dx`, `S`.**  
2. **Prepare the projection routine** (binary‑search water‑filling).  
3. **Build two initial vectors** – up‑sampled known solution and random binary – and project each to the feasible set.  
4. **For each start**, run the projected‑gradient loop:
   * compute autocorrelation via FFT,
   * build `g`, smooth‑max weights `w`,
   * obtain gradient by two FFT‑based convolutions,
   * take a step `h ← project(h – η·grad)`,
   * adapt `α` and `η`,
   * keep the best `(h, C5)` seen.
5. **After the loop**, apply a short SLSQP refinement with the exact max‑overlap objective.  
6. **Return** the best `h` (as a Python list), the corresponding `C5` value, and `n`.

All operations rely only on `numpy` and `scipy`, respect the 1‑CPU limitation,
and run comfortably within the 600 s budget while exploring a richer
search space than the previous program.  The method is fundamentally
different (smooth‑max gradient ascent with FFT‑based convolutions) and
has a strong chance of beating the current record `C5 ≤ 0.38092`,
targeting a bound below `0.3807`.  </strategy>
