1. **Global exploration with a population‑based evolutionary algorithm** (Differential Evolution).  
2. **Deterministic refinement by projected gradient descent on a smooth approximation of the max‑overlap**.

Each phase respects the two constraints  

* 0 ≤ h[i] ≤ 1 for all i,

The phases are run sequentially, occupying roughly 60 % – 30 % – 10 % of the total time budget (default 600 s).  All heavy numerical work (correlation, convolutions) uses FFT‑based O(n log n) kernels; for n = 120 this is negligible compared with the optimisation loops.

### 1. Global search – Differential Evolution (DE)

| Component | Choice | Rationale |
|-----------|--------|-----------|
| **Population size** | 30 – 40 individuals | Provides sufficient diversity while keeping per‑generation cost low (30 × 2 FFTs). |
| **Initialisation** | Draw each vector from a uniform [0, 1] distribution, then project onto the feasible set. Include the supplied `initial_h_values` as one individual. | Guarantees a mix of random and informed starting points. |
| **Mutation operator** | “DE/rand/1”:  v = x_r1 + F·(x_r2 – x_r3) with base scaling F = 0.5.  Every generation independently perturb F for each trial by sampling F ~ Uniform(0.4, 0.7). | Classic robust DE scheme; the adaptive F reduces stagnation. |
| **Crossover** | Binomial crossover with probability CR = 0.9 (CR also jittered by ±0.1 each trial). | High CR preserves most of the mutant while keeping at least one component from the target. |

### 2. Deterministic refinement – Projected gradient descent on a smooth max

The raw objective `max_k f_k` is non‑differentiable.  Replace it by the **log‑sum‑exp** (soft‑max) surrogate  

\[
S_{\alpha}(h)=\frac{1}{\alpha}\log\!\Bigl(\sum_{k} e^{\alpha\,f_k(h)}\Bigr),\qquad 
f_k(h)=\sum_{i}h_i\bigl(1-h_{i+k}\bigr).
\]

For any shift `k` (including negative indices, padded with zeros)  

\[
\frac{\partial f_k}{\partial h_j}= \bigl(1-h_{j+k}\bigr)-h_{j-k}.
\]

If `w_k = e^{\alpha f_k}/\sum_j e^{\alpha f_j}` are the soft‑max weights, the gradient of `S_α` is  

\[
\frac{\partial S_{\alpha}}{\partial h_j}= 1-\sum_{k}w_k h_{j+k} -\sum_{k}w_k h_{j-k}.
\]

Both sums are discrete convolutions of the weight vector `w` (length 2n‑1) with `h`.  Using FFT they are computed in O(n log n).  The gradient is therefore available *exactly* without automatic‑differentiation.

**Gradient‑descent loop**

1. **Start** from the best DE individual (`h`).  
2. **Set** a modest smoothing parameter `α = 4`.  The soft‑max is still smooth but already reflects the dominating shifts.  
3. **Repeat** until the allotted 30 % of time expires:
   * Compute correlation `f = correlation_fft(h)`.  
   * Build the weight vector `w = exp(α·f)` and normalise it.  
   * Compute the two convolutions `conv1 = w * h` and `conv2 = w_rev * h` via FFT (`w_rev` is `w` reversed).  
   * Form the gradient `g = 1.0 - conv1 - conv2`.  
   * **Line search**: try step sizes `η` from a geometric series (e.g. 0.5, 0.25, 0.125, …) and propose `h_new = project_to_sum_box(h - η·g)`.  Accept the first `η` that yields a *strictly lower true* C₅ (computed with the exact max‑correlation).  If none succeed, shrink `η` down to `1e‑5` and break.  
   * Update `h ← h_new`; if its C₅ beats the global best, store it.  
   * Every 30 iterations increase `α ← min(α·1.5, 200)`.  Raising `α` sharpens the surrogate, gradually turning the smooth optimisation into true max‑min optimisation.  
4. Keep the best vector seen during this phase as `h_refined`.

Because the gradient is analytically exact, each iteration makes a principled move toward reducing the *worst* overlap while staying inside the feasible polytope.  The line‑search guarantees monotone improvement of the true objective, preventing the occasional overshoot that can happen with a pure fixed‑step scheme.

### 3. Binary polishing – rounding + swap‑based simulated annealing

Empirically the optimal configuration for the Erdős problem often lies near a binary pattern (values 0 or 1).  After the continuous refinement we therefore attempt to extract a high‑quality binary vector.

**Rounding**
* Compute the median `m` of the refined `h`.  
* Form a binary vector `b` by setting `b_i = 1` if `h_i ≥ m`, else `0`.  
* If the number of ones differs from `n/2`, adjust by flipping the smallest (or largest) entries around the median until exactly `n/2` ones remain.  This yields a feasible binary candidate without altering the total mass.

**Swap‑based hill‑climb (simulated annealing)**
* **State** = current binary vector `b`.  
* **Neighbour generation**: pick uniformly at random a position `i` with `b_i=1` and a position `j` with `b_j=0`; propose the swap `b'` that flips these two bits (so the sum constraint is automatically satisfied).  
* **Energy** = C₅(b) = `dx * max(correlation_fft(b))`.  
* **Delta evaluation**: recompute the full correlation after a tentative swap (the cost is O(n log n) with FFT, cheap for n = 120).  The new C₅ is compared to the current energy.  
* **Acceptance rule**: if the new C₅ is lower, accept the swap.  If it is higher, accept with probability `exp(-(Δ)/T)`, where `Δ = C₅(b') – C₅(b)` and `T` is a temperature that decays geometrically (e.g. `T ← 0.95·T` each 500 accepted moves).  
* **Restarts**: run the annealing from several independent perturbations of `b` (flip 5 % of bits randomly, re‑project to the right count) to explore different basins.  
* **Budget**: allocate the final 10 % of the overall time (≈ 60 s) to this stage, performing a few hundred thousand swap attempts in total.

During annealing we maintain the best binary vector ever seen.  At the end, compare its C₅ with the best continuous value obtained from phase 2; return whichever is lower.
