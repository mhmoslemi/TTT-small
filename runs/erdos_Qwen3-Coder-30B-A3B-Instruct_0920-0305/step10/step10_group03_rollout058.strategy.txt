**Objective** – Construct a step‑function `h` on the uniform grid of length `n_points` (normally 120) with values in `[0,1]`, total area 1, that minimizes  

```
C5(h) = max_k ∫ h(x)·(1‑h(x+k)) dx .
```

The new methodology diverges completely from the previous gradient‑descent / local‑perturbation pipeline. It proceeds in several orthogonal phases:

---

### 1. Reformulate as a max‑min combinatorial problem  

For a discrete vector `h_i` the overlap at shift `k` is  

```
C_k = dx·∑_{i=0}^{n‑k‑1} h_i·(1‑h_{i+k})
     = 1 – dx·∑_{i=0}^{n‑k‑1} h_i·h_{i+k} .
```

Therefore  

```
C5 = max_k C_k = 1 – min_k ρ(k) ,
```

where `ρ(k) = dx·∑ h_i·h_{i+k}` is the (non‑periodic) autocorrelation.  
If `h` is forced to be binary (`0`/`1`) then `ρ(k)` counts the number of overlapping “1‑positions’’ at shift `k`.  
Consequently the problem becomes: **choose a binary vector of weight `n/2` that maximises the smallest overlap** over all shifts. This is a classic max‑min integer program.

---

### 2. Phase A – Exact binary skeleton via a small‑scale MILP  

1. **Select a reduced grid** `N = 60` (or any even number ≤ 80).  With `dx = 2/N` the mass constraint becomes `∑ x_i = N/2`.  
2. **Variables**  
   - Binary `x_i ∈ {0,1}` (the step‑function).  
   - For each shift `k = 1,…,N‑1` and each admissible pair `(i,i+k)` introduce an auxiliary binary `y_{i,k}` meant to represent `x_i·x_{i+k}`.  
3. **Linearisation (McCormick)**  
   ```
   y_{i,k} ≤ x_i ,          y_{i,k} ≤ x_{i+k}
   y_{i,k} ≥ x_i + x_{i+k} – 1 .
   ```
   With binary `x` these constraints force `y_{i,k}=x_i·x_{i+k}`.  
4. **Worst‑case variable** `t ≥ 0` representing the maximal uncovered count:  
   ```
   ∑_{i} y_{i,k} ≥ N/2 – t   for every shift k .
   ```
5. **Constraints**  
   - Mass: `∑ x_i = N/2`.  
   - `t` bounds all shifts as above.  
6. **Objective** – minimise `t`.  
7. **Solve** with `cvxpy` using the free MILP solver (GLPK_MI or CBC). Impose a modest solver time limit (≈ 30 s). If the solver finishes with a feasible incumbent, retrieve the binary vector `x*` and the associated `t*`.  
   *Even a sub‑optimal feasible solution gives a strong combinatorial skeleton.*

---

### 3. Phase B – Lift to the required resolution  

1. **Upsample** the binary skeleton to the final length `n_points` (e.g. `n_points = 120`).  
   Use an integer factor `s = n_points / N` and repeat each entry `s` times: `h0[i] = x*_{⌊i/s⌋}`.  
2. The upsampled vector automatically satisfies the integral constraint because the total number of ones scales with `s`.

---

### 4. Phase C – Direct worst‑shift‑focused binary swap search  

If the MILP solution is still far from the target bound, improve it by a deterministic local optimisation that *explicitly* reduces the Chebyshev norm:

1. **Maintain** the integer autocorrelation array `ρ[k] = ∑ x_i·x_{i+k}`.  
2. **Loop** (up to a few ten‑thousand swaps or until time expires):  
   - Find the **worst shift** `k* = argmax (N/2 – ρ[k])`.  
   - Build two candidate sets  
     - `A = { i | x_i = 1, i+k* < N, x_{i+k*} = 0 }` (a “lonely 1’’ at the worst shift).  
     - `B = { j | x_j = 0, j+k* < N, x_{j+k*} = 1 }` (a “missing 1’’ counterpart).  
   - If both sets are non‑empty, pick a random pair `(a∈A, b∈B)` and **swap** the bits (`x_a←0`, `x_b←1`).  
   - Update `ρ` **incrementally** in O(N) by adding/removing the contributions of the two swapped indices.  
   - Accept the swap if the new worst‑case value `t_new ≤ t_current`; otherwise revert.  
   - If no improving pair exists, allow a random swap with a small acceptance probability (simulated‑annealing flavour) to escape plateaus.  
3. **Result** – a binary vector with a strictly reduced `t`. Upsample again if the swap search was performed on a smaller `N`.

This routine is fundamentally different from generic gradient steps because it targets the *maximum* overlap directly and works on the combinatorial level.

---

### 5. Phase D – Continuous global optimisation (DE + SA)

After obtaining a binary skeleton, allow fractional values to possibly lower the bound further.

#### 5.1 Differential Evolution (DE)

1. **Population** – e.g. 30 candidates of length `n_points`.  
2. **Initialisation** – each individual = binary skeleton + a tiny random jitter (±0.02).  
3. **Projection onto feasibility** after every mutation/crossover:  
   - Find a scalar `λ` such that `clip(v+λ,0,1)` has the exact required sum (`n_points/2`).  
   - This can be done by a short binary search (water‑filling) – O(`n_points log n_points`).  
4. **Mutation / Crossover** – standard DE/rand/1/bin with scaling factor `F≈0.8` and crossover probability `CR≈0.9`.  
5. **Evaluation** – compute `C5` with a fast FFT‑based convolution (`np.fft.ifft(np.fft.fft(h)·np.fft.fft(1‑h))`).  
6. **Selection** – keep the trial if its `C5` is not larger than the parent’s.  
7. **Termination** – run until the remaining wall‑clock time drops below a safety margin (≈ 5 s). The best individual found is stored as `h_DE`.

#### 5.2 Simulated Annealing (fallback / polishing)

If DE stalls, launch a quick SA from the best DE individual:

1. At each step pick two indices `i,j`; move a random amount `δ` from `i` to `j` while clipping to `[0,1]`.  
2. The sum is automatically preserved; no projection is needed.  
3. Accept worsening moves with probability `exp(−Δ/T)`, where `Δ` is the increase in `C5` and `T` follows a geometric cooling schedule (`T←α·T`, `α≈0.99`).  
4. Stop when the time budget is exhausted.

Both DE and SA explore the continuous landscape globally, something the previous gradient‑based approach never does.

### 6. Phase E – Deterministic local polishing (gradient‑free hill‑climb)

Finish with a short, deterministic hill climb:

1. Repeatedly pick a modest random subset of coordinates (≈ 5 % of the points).  
2. Add independent Gaussian perturbations `δ∼N(0,σ²)` where `σ` is proportional to `h_i·(1‑h_i)`.  
3. Project back onto the box and the sum constraint (water‑filling).  
4. Keep the new vector if `C5` improves; otherwise discard.  
5. Run for a few thousand iterations – negligible time compared with the earlier phases.
