**Goal** – Produce a step‑function `h` on the uniform grid `x_i = i·dx` (`dx = 2/n_points`) with  
 • `0 ≤ h_i ≤ 1` for every `i`  
 • `∑ h_i·dx = 1` (i.e. `∑ h_i = n_points/2`)  
that minimises  

```
C5(h) = max_{k = 0,…,n_points‑1}  dx·∑_{i=0}^{n_points‑k‑1} h_i·(1‑h_{i+k})
```

The previous solution relied on gradient descent and generic local search.  
Below is a **different, multi‑phase strategy** that combines (a) a **binary integer‐programming** formulation to obtain a high‑quality combinatorial skeleton, (b) a **worst‑shift‑focused swap search** that directly reduces the Chebyshev norm, (c) a **parameterised piecewise‑constant model** that can be explored exhaustively, and (d) a **continuous refinement** (DE / simulated‑annealing) that exploits the binary skeleton as a warm‑start.  
All phases respect the 600 s time budget and require only `numpy`, `scipy`, and `cvxpy` (with the free MILP solver).

### 1. Core mathematical insight
For any shift `k`

```
Ck = ∫ h(x)(1‑h(x+k))dx = 1 − ∫ h(x)h(x+k)dx .
```

Thus  

```
C5 = max_k Ck = 1 − min_k ρ(k) ,
```

where `ρ(k) = ∫ h(x)h(x+k)dx` is the (non‑periodic) auto‑correlation.  
*Minimising* `C5` ⇔ *maximising* the *minimum* auto‑correlation over all shifts.  
If `h` is binary (`h∈{0,1}`) the correlation at shift `k` equals the number of overlapping “1‑positions’’ between the original vector and its `k`‑step right‑shift, i.e.

```
ρ(k) = dx·∑_{i} x_i·x_{i+k}  ,   x_i∈{0,1}.
```

Hence the problem becomes a **max‑min integer‑program** on the binary vector `x`.

### 2. Phase A – Binary MILP skeleton (small N)

1. **Choose a modest grid size** `N = 60` (so `dx = 2/60`).  
   This size yields ≈ 1 800 auxiliary product variables, well within the ability of CBC/GLPK‑MI.

2. **Decision variables**  
   * `x[i] ∈ {0,1}` for `i = 0,…,N‑1`.  
   * For each shift `k = 1,…,N‑1` and each admissible pair `(i,i+k)` introduce a *product* variable `y[i,k] ∈ {0,1}` with the standard McCormick constraints that force `y[i,k] = x[i]·x[i+k]` when `x` is binary:
   ```
   y[i,k] ≤ x[i] ,   y[i,k] ≤ x[i+k] ,
   y[i,k] ≥ x[i] + x[i+k] – 1 .
   ```

3. **Auxiliary scalar** `t ≥ 0` representing the worst‑case uncovered count  
   (i.e. `t = max_k (N/2 – Σ_i y[i,k])`).

4. **Constraints**  
   * **Mass constraint**: Σ_i x[i] = N/2.  
   * **Worst‑case bound** for each shift:
     ```
     Σ_i y[i,k] ≥ N/2 – t   for all k = 1,…,N‑1 .
     ```
   * **Box constraints** are already enforced by binary nature of `x` and `y`.

5. **Objective** – minimise `t`.  
   The model is a pure linear MILP (no quadratic terms) because the product is replaced by `y`.

6. **Solve** with `cvxpy` + `GLPK_MI` (or `CBC`).  
   *Set a modest solver time limit (e.g. 30 s) – the problem size is tiny, and an optimal or near‑optimal feasible solution is usually returned quickly.*  
   *If the solver finishes with status `optimal` or `feasible`, extract the binary vector `x*`.  
   *If the solver times out, keep the best incumbent it reported.*

7. **Result** – a binary skeleton `x*` with a provable bound  
   `C5_bin = dx·t*`.  
   Even if `C5_bin` is still above the target, this skeleton is an excellent starting point for later phases because it already maximises the minimum auto‑correlation under a combinatorial restriction.

### 3. Phase B – Upsampling to the final resolution

1. **Target resolution** – the evaluation routine expects a length `n_points` that may be larger (the problem statement currently uses `n_points = 120`).  
2. **Upsample** `x*` by integer factor `s = n_points / N` (e.g. `s = 2`).  
   ```
   h0[i] = x*[i//s]   for i = 0,…,n_points‑1 .
   ```
   The upsampled vector remains binary, automatically satisfies the integral constraint (`∑ h0 = n_points/2`), and serves as a warm start for the continuous phases.

### 4. Phase C – Worst‑shift‑focused binary swap search (optional refinement of the skeleton)

If Phase A produced a binary vector with a relatively large `t`, a cheap deterministic improvement can be obtained without any continuous optimisation:

1. **Maintain** the full auto‑correlation array `ρ[k] = Σ_i x_i·x_{i+k}` (integer counts).  
2. **Iteratively**:
   * Identify the *worst shift* `k* = argmax (N/2 – ρ[k])`.  
   * Gather the sets  
     ```
     A = { i | x_i = 1  and  i+k* < N  and  x_{i+k*} = 0 }
     B = { j | x_j = 0  and  j+k* < N  and  x_{j+k*} = 1 } .
     ```
     Swapping any pair `(a∈A, b∈B)` reduces the uncovered count at `k*` by at least 1 while preserving the total number of ones.
   * Choose a random pair `(a,b)` from `A×B`, perform the swap (`x_a←0, x_b←1`) and update `ρ` **incrementally** (O(N) work per swap).
   * Accept the swap if the new worst‑case value `t_new ≤ t_current`.  
   * If no improving pair exists, fall back to a *random* swap (simulated‑annealing style) with a small probability of acceptance to escape local plateaus.
3. **Terminate** when a preset iteration budget (e.g. 10 000 swaps) is exhausted or when no improvement occurs for a long streak.

This swap search is *directly* minimising the Chebyshev norm and is far more targeted than a generic gradient descent.

After the swap search, upsample the improved binary vector again (if the swap was performed on a smaller `N`) and proceed to Phase D.

### 5. Phase D – Continuous refinement (global stochastic optimisation)

Even after binary optimisation, allowing fractional values can lower `C5` (the optimal step‑function need not be purely 0/1).  
We therefore run a **population‑based global optimiser** on the *full* resolution `n_points` (e.g. 120 or 140) initialized from the upsampled binary skeleton.

#### 5.1 Differential Evolution (DE)

1. **Population** – `P = 30` vectors `h^{(p)}` of length `n_points`.  
   * Initialise each individual by copying `h0` and adding a tiny uniform jitter (`±0.02`), then **project** onto the feasible set (box `[0,1]` and exact sum `n_points/2`).  
2. **Projection onto the affine‑box**  
   * Use the classic *water‑filling* algorithm: find a scalar `λ` such that `∑ clip(h+λ,0,1) = target_sum`. This is a monotone 1‑D root‑finding problem solvable by a short binary search (≈ 50 iterations, negligible cost).
3. **Mutation & Crossover** (standard DE/rand/1/bin):  
   * For each target vector `h^{(t)}` select three distinct donors `a,b,c`.  
   * Form mutant `m = a + F·(b‑c)` (with `F≈0.8`).  
   * Crossover each coordinate with probability `CR≈0.9` (guaranteeing at least one mutated component).  
   * Project the trial vector back onto the feasible set.  
4. **Selection** – evaluate `C5` via a **fast FFT‑based correlation** (zero‑padding, multiply `h` with `1‑h` and take the max).  
   * Keep the trial if its `C5` is ≤ the parent’s; otherwise retain the parent.
5. **Termination** – run DE until the remaining time budget falls below a small safety margin (≈ 5 s).  
   * Keep the best individual seen so far (`h_DE`, `c5_DE`).

#### 5.2 Simulated Annealing (fallback / refinement)

If DE exhausts the budget without a clear improvement, launch a quick **simulated‑annealing** (SA) routine:

1. Start from the current best `h_cur`.  
2. At each iteration, pick two indices `i,j` (preferably one with `h_i > 0` and one with `h_j < 1`) and transfer a random amount `δ ∈ [‑ε, ε]` (`ε≈0.05`) from `i` to `j` while clipping to `[0,1]`.  
3. Re‑project only if necessary (the transfer already preserves the sum).  
4. Compute Δ = `C5_new – C5_cur`.  
   * Accept unconditionally if Δ ≤ 0.  
   * Otherwise accept with probability `exp(‑Δ / T)`, where the temperature `T` follows a geometric cooling schedule (`T←α·T` with `α≈0.99`).  
5. Stop when the time budget is reached.

SA is cheap (single‑pair updates) and can polish the DE result, especially when the landscape has narrow ridges.

### 6. Phase E – Deterministic local polishing (gradient‑free hill climbing)

After stochastic phases, apply a *short deterministic hill‑climbing*:

1. **Current vector** `h_cur`.  
2. For a fixed number of iterations (e.g. 2 000) do:
   * Randomly pick a *small* subset of indices (e.g. 5% of the points).  
   * For each selected index, propose a perturbation `δ ∼ N(0, σ²)` with `σ` proportional to `h_i·(1‑h_i)` (larger near the middle of the interval).  
   * Apply all perturbations, then **project** onto feasibility.  
   * Keep the new vector if it reduces `C5`; otherwise discard (or accept with a tiny probability to avoid stagnation).  
3. Record the best vector encountered.

Because the projection step is O(n log n) and the evaluation is O(n log n) via FFT, this phase fits comfortably within the remaining seconds.
