### 1.  Reformulation of the problem  

For a discretisation with `n` equally‑spaced points (`dx = 2/n`) let  

*`h ∈ ℝⁿ`*  with `0 ≤ h_i ≤ 1` and the exact integral constraint  

\[
\frac{2}{n}\sum_{i=0}^{n-1} h_i = 1\qquad\Longleftrightarrow\qquad 
\sum_{i=0}^{n-1} h_i = n/2 .
\]

For a shift `s = -(n-1)…(n-1)` define  

\[
f_s(h)=\sum_{i=0}^{n-1} h_i\bigl(1-h_{i+s}\bigr) ,
\]

where out‑of‑range indices are taken as zero (this is exactly the full‑mode correlation used in the evaluator).  
The quantity we must minimise is  

\[
C_5(h)=dx\;\max_{s}|f_s(h)|.
\]

The max‑operator is non‑smooth.  The key idea of the new approach is to **replace the max by a smooth p‑norm**, solve a sequence of smooth problems with increasing `p`, and enforce the two constraints (box and exact sum) by a *projected gradient* method.  This gives a genuinely different optimisation pipeline from the previous pure differential‑evolution scheme.

### 2.  Smooth approximation of the max  

For any `p≥1`

\[
\Phi_p(h)=\Bigl(\sum_{s} f_s(h)^p\Bigr)^{1/p}
\]

converges to `max_s|f_s(h)|` as `p → ∞`.  For moderate `p` (e.g. 4, 8, 12) the function is still very smooth, its gradient is analytic, yet it strongly penalises large `f_s`.  The optimisation target will be  

\[
J_p(h)=\Phi_p(h) + \lambda\Bigl(\sum_i h_i- n/2\Bigr)^{2},
\]

where `λ` is a large penalty (≈1 e³) that forces the equality constraint without needing an external optimiser.  The box constraints are handled by a **projection** after each gradient step.

### 3.  Analytic gradient  

Write `c = h` and `c̅ = 1 – h`.  For a fixed shift `s` we have  

\[
f_s(h)=c^\top ( \,c̅\; \text{shifted by } s \, ).
\]

The derivative of a single term is  

\[
\frac{\partial f_s}{\partial h_k}
= 1 - h_{k+s} - h_{k-s},
\]

where `h_{k±s}` is taken as zero when the index falls outside `[0,n-1]`.  
Define the weight  

\[
w_s = f_s(h)^{\,p-1}.
\]

The gradient of the smooth part is  

\[
\frac{\partial \Phi_p}{\partial h_k}
= \frac{1}{\Phi_p(h)^{\,p-1}}\;\sum_{s} w_s\,\bigl(1 - h_{k+s} - h_{k-s}\bigr).
\]

The penalty term contributes `2λ(∑h_i - n/2)` uniformly to all components, which is trivial to add.

All required shifted vectors can be obtained with **zero‑padded rolls** (`np.concatenate([h[s:], np.zeros(s)])` for a right shift, and the opposite for a left shift).  With vectorised NumPy this costs `O(n·|S|)` where `|S| = 2n-1` – well within the budget for `n ≤ 200`.

### 4.  Projection onto the feasible set  

After a gradient step we have a vector `y`.  We must find the Euclidean projection onto  

\[
\mathcal{F}= \{\,x\in[0,1]^n \mid \mathbf{1}^\top x = n/2 \,\}.
\]

This is a classic *box‑constrained simplex* projection.  It can be performed in two stages:

1. **Shift**: subtract a scalar `α` from every component of `y` and then **clip** to `[0,1]`.  
2. Choose `α` such that the resulting vector satisfies the sum constraint.  

The scalar `α` can be found by a simple 1‑D root‑find (e.g. bisection) because the sum after clipping is a monotone decreasing function of `α`.  The algorithm converges in a handful of iterations and is negligible compared with the gradient evaluation.

The result of the projection is the next iterate `h^{(t+1)}` and automatically respects both constraints.

### 7.  Global‑local hybrid fallback (binary hill‑climbing)

If the projected‑gradient continuation fails to push the bound below the current record (≈ 0.381), we fall back to a **binary optimisation** that can exploit the discretised nature of the problem:

1. **Rounding** – take the continuous `h` from the finest stage, sort its entries, set the largest `n/2` to `1` and the rest to `0`.  This automatically respects the integral constraint.  
2. **Local swaps** – perform a hill‑climbing on the binary vector: repeatedly pick a `1` that participates in the worst shift (`s* = argmax |f_s|`) and a `0` elsewhere, swap them, and accept the move only if the maximal overlap decreases.  Stop after a fixed number of unsuccessful attempts or when the allocated time for this fallback expires.  

Because the objective for a binary vector is integer‑multiple of `dx`, the final bound can be **slightly finer** than what a pure binary search would give, thanks to the prior smoothing and the possibility of re‑introducing fractional values in the final scaling step.
