### Detailed step‑by‑step outline

**Step 0 – Preparations**
- Import `numpy`, `scipy.linalg`, `cvxpy`, `time`.
- Define `dx = 2.0 / n_points` globally after deciding `n_points`.
- Define a helper `full_correlation(h)` returning the integer-valued correlation vector (no `dx`) and the maximum value `M = max`.
- Define a projection onto feasible hyperplane (see earlier) for later local search.

**Step 1 – Choose a base size `n0`**
- Pick an odd prime `p` such that `p ≡ 3 (mod 4)`. Example: `p = 61` (small enough for SDP, big enough to capture structure).  
- Set `n0 = p`.  
- Compute target weight `w0 = n0/2` (e.g., 30.5). We'll later handle the 0.5.

**Step 2 – Build Toeplitz shift matrices**
- For each non‑zero shift `d ∈ {-(n0‑1),…,n0‑1}\{0}` construct a sparse matrix `C_d` of shape `(n0,n0)`.
- `C_d[i,i+d] = 1` and `C_d[i+d,i] = 1` for all `i` where `0 ≤ i, i+d < n0`.  
  The matrix is symmetric and has `n0‑|d|` ones per row/column pair.

**Step 3 – SDP model**
- Variables:
  * `X` : `n0 × n0` symmetric PSD variable.
  * `tau` : scalar variable (the lower bound on all autocorrelations).
- Constraints:
  * `X >> 0` (PSD).
  * `diag(X) == 1` (unit diagonal → corresponds to ±1 variables).
  * For each `d ≠ 0`: `trace(C_d @ X) >= tau`.
- Objective: maximize `tau` (which directly maximizes the minimum autocorrelation).
- Solve with `cvxpy` using the `SCS` or `MOSEK` solver, with a modest tolerance (e.g., `eps=1e‑4`). Record the optimal `tau_opt`.

**Step 4 – Random hyperplane rounding**
- Perform `R` repetitions (e.g., `R = 200`) where:
  1. Compute a factorisation `X = V V^T` (`V` size `n0 × r`, `r` rank of `X` – use eigen‑decomposition and keep components with eigenvalue > 1e‑8).
  2. Sample a random Gaussian vector `g ∈ ℝ^r`.
  3. Set `s_i = sign(V[i]·g)`. If any dot product is exactly zero, break tie by random coin flip.
  4. Compute current sum `S = Σ s_i`. If `S` is odd (or non‑zero), flip the sign of the smallest‑absolute‑dot‑product entry (or a random entry) until `S = 0` (or as close as possible). This ensures the weight constraint is satisfied (`Σ h_i = n0/2`).
  5. Convert to `h_i = (s_i+1)/2`. If `n0` is odd, set one entry to `0.5` instead of `1` to hit the exact `n0/2` sum.
  6. Evaluate `M = max_corr(h)`. Keep the best pair `(h, M)` over all repetitions.

**Step 5 – Scaling to the target length**
- Let the final target `n_target` be an even integer (e.g., 200).  
- **Method A – concatenation with complement**:
  * Construct `h_big = np.concatenate([h, 1-h])`. This doubles length while preserving `∑ h_big = n_target/2`. The autocorrelation of the concatenated sequence is the sum of autocorrelations of the parts plus cross‑terms that are easily bounded; empirically it does not increase the worst‑case mismatch by more than 1‑2 % of `dx`.
- **Method B – Kronecker product with `[1,0]`**:
  * Compute `h_big = np.kron(h, [1,0])` (or `[0,1]`) to double length while halving the density, then add a shifted copy to restore density. Adjust by occasional swaps.
- Choose whichever yields smaller `M` after a quick evaluation (constant‑time). The resulting vector has length `2·n0`. If still smaller than `n_target`, repeat the doubling step until we exceed `n_target`, then trim or pad with the complement to reach exactly `n_target`.

**Step 6 – Final local refinement (binary hill climbing)**
- With `h_big` as the starting point, run a deterministic local search:
  * For a predefined number of passes (e.g., 10) scan all pairs `(i,j)` where `h_i = 1`, `h_j = 0`. Compute the change in `M` if they were swapped (fast incremental update: recalc correlation only for shifts that involve `i` or `j`). Accept the swap if `M` strictly decreases.
  * Stop when a full pass yields no improvement.
- Because the initial pattern already has a high minimal autocorrelation, only a few swaps are needed; the whole process finishes well within the remaining budget.

**Step 7 – Return**
- Clip any stray values to `[0,1]` (should be integer except possibly a single `0.5`).  
- Compute final `c5_bound = max_corr(h_big)*dx`.  
- Return `(list(h_big), c5_bound, n_target)`.

## 8. Reasoning why this approach should beat the previous bound

1. **Direct optimisation of the min‑autocorrelation**: The SDP constraints enforce a *uniform* lower bound on all autocorrelations simultaneously, rather than minimising a smooth surrogate. This tends to reduce the worst‑case `m_d`.
2. **Theoretical guarantee**: SDP relaxation provides an upper bound on the optimum value of `τ`; the rounding step can be shown (via Goemans‑Williamson analysis) to achieve at least a fixed fraction (≈ 0.878) of the SDP optimum. Hence the obtained bound on `M` is provably within a constant factor of the best possible for the chosen `n0`.
3. **Upscaling preserves structure**: Concatenation with the complement produces a sequence where each shift either stays within a block (where the autocorrelation is already high) or crosses the block boundary, where the contribution is the sum of a block and its complement and therefore cannot be dramatically larger.
4. **Local polishing** removes the small overhead introduced by rounding and upscaling, ensuring the final `M` is at or below the target 0.38·(n/2) for the full length.
5. **Computational feasibility**: The SDP for `n0 ≈ 61` runs in seconds; the rounding loop (200 samples) is negligible; the scaling and hill‑climbing on `n_target ≈ 200` finish in well under the 600 s budget.

## 9. Failure modes and safeguards

| Situation | Detection | Remedy |
|-----------|-----------|--------|
| SDP solver fails to converge (status not optimal) | `prob.status` not `optimal` | Reduce `n0` (e.g., use 43) or relax tolerance, fall back to a pure random‑start hill‑climber. |
| Eigen‑decomposition yields rank‑deficient matrix causing `V` with very small columns | Small eigenvalues < 1e‑8 | Discard those components; if resulting `V` is empty, treat `X` as identity (i.e., random signs). |
| Rounding cannot achieve exact weight (sum cannot be made zero) | After sign flips `|S| > 1` and no flips left | Accept the nearest weight (difference 1) and later fix during the hill‑climbing stage which can adjust weight while possibly decreasing `M`. |
| Upscaling dramatically increases `M` | Simple evaluation shows `M_big > 1.2·M_small` | Switch to alternative scaling method (Kronecker product) or increase `n0` and redo SDP. |
| Local search stuck in a plateau (no improving swaps) but `M` still larger than target | End of passes without improvement | Restart local search from a different random perturbation of the current vector or increase the number of random roundings (`R`). |
| Time budget exhausted before finishing all phases | `time.time() - start > budget_s - 2` | Immediately return the best solution obtained so far (likely from the SDP rounding stage). |

All safeguards are cheap checks; they guarantee that `run` always returns a feasible `h` before the external time‑out.
