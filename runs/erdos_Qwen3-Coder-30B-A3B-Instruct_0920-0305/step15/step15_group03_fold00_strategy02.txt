```
t ≥ Σ_i h_i – Σ_i y_{i,k}   for every shift k
```

Minimising `t` therefore minimises the maximum of the `F_k`’s, i.e. directly minimises `C5`.  

The **objective** is simply  

```
minimise   t
```

All constraints are linear; the only integer variables are the `h_i` (and the `y_{i,k}` if we keep them binary; they may be relaxed to continuous because the “AND” constraints already force them to be integral when `h_i` are binary).

--------------------------------------------------------------------
### 3.  Model size and choice of `n`

The number of product variables is  

```
|Y| = Σ_{k=0}^{n‑1} (n‑k) = n·(n+1)/2 .
```

For `n = 120` this gives 7 260 binary `y`‑variables plus 120 binary `h`‑variables – well within the capacity of the open‑source CBC / GLPK MILP solvers in a few seconds to a few minutes.  
If the solver proves too slow, we can reduce `n` to a divisor of 120 (e.g. 96, 108, 112) or even to 80; the resulting binary pattern can later be up‑sampled without changing the value of `C5`.

--------------------------------------------------------------------
### 4.  Building the MILP with CVXPY

*Variables*  

```
h   : Boolean   (size n)
y   : Boolean   (size |Y|)   – one per admissible (i,k) pair
t   : Continuous
```

*Constraints*  

1. **Sum constraint** – `sum(h) == n/2`.  
2. **Product constraints** – for each `(i,k)` add the three “AND” inequalities shown above.  
3. **Maximum‑overlap constraints** – for each shift `k`  

   ```
   t >= n/2 - sum( y_{i,k} over i )
   ```

   (the `sum(h_i)` term is replaced by its constant `n/2`).  

4. **Box constraints** – automatically satisfied by binary type.

*Objective* – `Minimise t`.

The model can be written directly in CVXPY and solved with the CBC solver:

```python
prob = cp.Problem(cp.Minimize(t), constraints)
prob.solve(solver=cp.CBC, maxTime=budget_s-5)
```

`maxTime` guarantees we never exceed the overall time budget.

--------------------------------------------------------------------
### 5.  Extracting the step‑function and the C5 bound

After the solver finishes:

* `h_opt = np.array(h.value, dtype=float)` – already `0` or `1`.  
* The optimal integer `t_opt` gives the exact discrete overlap sum:  

  ```
  C5_opt = t_opt * dx          # because each F_k = dx·( … )
  ```

* Verify feasibility (sum, bounds) and compute the correlation with `np.correlate` as a sanity check.

--------------------------------------------------------------------
### 6.  If the MILP does not finish in time – LP relaxation fallback

*Relax the binary restriction on `h`* (allow `0 ≤ h_i ≤ 1`) **and** keep the `y`‑variables continuous, retaining the McCormick envelope constraints:

```
0 ≤ h_i ≤ 1
0 ≤ y_{i,k} ≤ 1
y_{i,k} ≤ h_i
y_{i,k} ≤ h_{i+k}
y_{i,k} ≥ h_i + h_{i+k} – 1
```

The problem becomes a pure **linear program**; it solves in milliseconds.  

From the LP solution we obtain a fractional vector `h_frac`.  
To obtain a feasible step‑function we **round**:

* sort indices by `h_frac` descending,
* set the first `n/2` entries to `1`, the rest to `0`,
* project the resulting binary vector onto the sum constraint (trivial because we forced exactly `n/2` ones).

This rounded vector is a legitimate candidate. Its `C5` is computed and stored as the current best bound.

--------------------------------------------------------------------
### 7.  Iterative cut‑generation to tighten the LP/MILP

After we have a concrete binary (or rounded) candidate `h_cur` with overlap value `t_cur`:

1. **Identify the worst shift** `k* = argmax_k F_k(h_cur)`.  
2. **Add a cut** that forces any future solution to beat this value:  

   ```
   t <= t_cur - ε                (ε = 1e‑4)
   ```

   or equivalently  

   ```
   Σ_i y_{i,k*} >= n/2 - (t_cur - ε) .
   ```

3. **Re‑solve** the (still linear) model with the new cut.  
4. If the solver finds a strictly smaller `t`, replace `h_cur` and repeat from step 1.  
5. Continue until no improvement is achievable or the remaining time drops below a small safety margin.

Because each added cut eliminates the currently worst shift, the process converges quickly to a provably optimal (or near‑optimal) bound for the chosen `n`.

--------------------------------------------------------------------
### 8.  Post‑processing local improvement (optional but cheap)

Starting from the best binary vector found:

* Perform a **pairwise swap hill‑climb**:  
  - Let `I₁` be indices with `h_i = 1` and `I₀` those with `h_i = 0`.  
  - For every `(i ∈ I₁, j ∈ I₀)` compute the change in each `F_k` if we flip `h_i←0` and `h_j←1`.  
  - Keep the swap that yields the largest reduction of the current maximum `F_k`.  
  - Apply it, update the overlap values incrementally (only the shifts that involve `i` or `j` change), and repeat until no improving swap exists.  

The swap search is `O(n³)` in the naïve implementation, but for `n≤120` the inner updates are cheap and the whole local search finishes well within the remaining time.

--------------------------------------------------------------------
### 9.  Upsampling (if a smaller `n` was used)

If the MILP was solved for a reduced grid (e.g. `n=96`), produce the final answer with a larger `n_target` (e.g. `200`) by **replicating each entry**:

```
h_up = np.repeat(h_opt, n_target // n)          # integer multiple only
```

Because the function is piecewise constant, the integral and all discrete correlations scale linearly with `dx`, so the bound `C5 = t_opt * (2/n_target)` remains exactly the same.  This gives a finer‑grained step‑function without any loss of quality.

--------------------------------------------------------------------
### 10.  Time‑management & fallback logic

* Record `start = time.time()`.  
* Allocate the bulk of the budget (≈ 80 %) to the MILP/LP solve (including cut‑generation).  
* After each solve, check `elapsed = time.time()-start`.  
* If `elapsed > budget_s-5` jump to the **final evaluation** and return the best bound obtained so far.  
* If the MILP never finishes, automatically switch to the LP‑relaxation+rounding branch (which is guaranteed to finish instantly).

### 11.  Why this method is fundamentally different

| Aspect | Previous DE / smooth‑gradient pipelines | This MILP‑cut approach |
|--------|------------------------------------------|------------------------|
| **Problem type** | Heuristic, continuous, nonsmooth optimisation | Exact (or near‑exact) combinatorial optimisation via linearisation |
| **Decision variables** | Real values in `[0,1]` (gradient‑based) | Binary `h_i` (0/1) – the natural extremal class for the overlap problem |
| **Non‑linearity handling** | Smoothing of the max, sub‑gradient descent | Linearisation of products with auxiliary binary variables (`y_{i,k}`) – the model becomes linear |
| **Global guarantee** | No guarantee, relies on stochastic search | MILP solver provides provable optimality for the given `n`; cut‑generation systematically tightens the bound |
| **Scalability** | Works for any `n` but improvement plateaus | Quadratic growth of variables, so we deliberately keep `n` modest (≤ 120) – still enough to beat the current record |
| **Outcome** | A possibly fractional step‑function | A clean 0/1 step‑function that can be up‑sampled, often giving a lower `C5` |

Because the exact binary model directly minimises the worst overlap, it often yields a *strictly* smaller `C5` than any continuous relaxation produced by DE.  Moreover, the cut‑generation loop actively drives the solution away from the current worst shift, something gradient descent only approximates.

1. **Choose** an even `n` (e.g. 120) and compute `dx = 2/n`.
