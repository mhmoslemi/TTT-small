**1.  What we really have to optimise**  
For a discretisation with *n* equally spaced samples (`dx = 2/n`) let  

```
h = (h0,…,h{n‑1}),      0 ≤ hi ≤ 1 ,      Σi hi = n/2 .
```

Define for every shift `k = 0,…,n‑1`

```
Fk(h) = dx· Σ_{i=0}^{n‑1‑k} hi·(1 – h_{i+k}) .
```

The objective is  

```
C5(h) = max_k Fk(h) .
```

Because `Σi hi·dx = 1`, each `Fk` can be written as  

```
Fk = 1 – dx· Σ_{i} hi·h_{i+k} .
```

Hence minimising the maximum overlap is *equivalent* to **maximising the minimum autocorrelation** and, more importantly for us, the quadratic term `hi·h_{i+k}` appears only as a product of two variables that are naturally binary at the optimum (the known extremal solutions of the Erdős problem are 0/1 step‑functions).  This observation allows a **exact linearisation** of the problem.

--------------------------------------------------------------------
**2.  Binary decision variables and linearisation of the product**  

Introduce binary variables  

```
hi ∈ {0,1}   for i=0,…,n‑1 .
```

To linearise the product `hi·h_{i+k}` create an auxiliary binary variable  

```
y_{i,k} ∈ {0,1}   for every admissible pair (i,k) with i+k < n .
```

The classic “AND’’ formulation enforces `y_{i,k}=hi·h_{i+k}` using three linear constraints:

```
y_{i,k} ≤ hi
y_{i,k} ≤ h_{i+k}
y_{i,k} ≥ hi + h_{i+k} – 1 .
```

No other constraints are needed; the binary nature of `hi` and `h_{i+k}` forces `y_{i,k}` to be exactly the product.

--------------------------------------------------------------------
**3.  Linear model for the max‑overlap**  

For a fixed shift `k`

```
Fk = dx· Σ_i hi  –  dx· Σ_i y_{i,k}
    = 1          –  dx· Σ_i y_{i,k}       (because Σ_i hi·dx = 1 ).
```

Introduce a continuous scalar variable `t` that upper‑bounds every `Fk`:

```
t ≥ 1 – dx· Σ_i y_{i,k}      for all k .
```

The optimisation problem is now **purely linear**:

```
minimise   t
subject to
    t ≥ 1 – dx· Σ_i y_{i,k}          (k = 0,…,n‑1)
    Σ_i hi = n/2                     (equality, exactly half of the points are 1)
    y_{i,k} constraints (the three AND inequalities)
    hi ∈ {0,1} ,   y_{i,k} ∈ {0,1} .
```

The objective value `t*` obtained by the solver equals the exact discrete overlap `C5` because `t` already incorporates the factor `dx`.  After solving we will have a concrete binary pattern `h*`.

**7.  LP‑relaxation fallback (guaranteed fast solution)**  

If the MILP does not finish in time, relax the binary restrictions:

```
0 ≤ hi ≤ 1 ,   0 ≤ y_{i,k} ≤ 1 .
```

The same linear constraints (the three “AND’’ inequalities) become a **McCormick envelope**, which is a valid convex hull for the product of two variables bounded in `[0,1]`.  The resulting linear program solves in milliseconds and yields a *fractional* solution `h_frac`.

**Rounding** – sort the entries of `h_frac` descending and set the largest `n/2` of them to 1, the rest to 0.  This respects the sum constraint exactly and produces a binary candidate `h_round`.  Because the MILP model is linear, `h_round` is a feasible point for the original integer problem; we compute its true `C5` (using the exact correlation) and keep it as the current best bound.

**8.  Cutting‑plane / iterative improvement loop**  

Even after a feasible integer solution has been obtained (either from MILP or from rounding), we can **push the bound down** by adding a simple cut that forces any future solution to beat the current worst shift.

* Compute the exact overlap values `Fk(h_cur)` for the current binary pattern `h_cur`.

  ```
  t ≥ 1 – dx· Σ_i y_{i,k*} .

Because each iteration eliminates at least one previously worst shift, the loop converges quickly (usually within a handful of cuts). **9.  Local combinatorial polishing (pairwise swaps)**  

After the cutting‑plane phase we have a binary vector `h_best`.  A cheap deterministic improvement is a **pairwise swap hill‑climb**:

1. Build the vector of current overlaps `Fk`.  
2. Maintain the set `I₁` of indices where `h=1` and `I₀` where `h=0`.  
3. For each candidate swap `(i∈I₁ , j∈I₀)` compute the change in every `Fk` that involves `i` or `j`.  The change can be evaluated in O(1) per shift because only the terms containing `i` or `j` are affected.  
4. Determine the swap that reduces the current maximum `max_k Fk` the most (or eliminates it).  
5. If the best swap yields a **strict decrease**, perform it, update the affected `Fk` values incrementally, and repeat from step 2.  
6. Stop when no improving swap exists.

Because `n` is modest (≤ 120) the whole hill‑climb finishes in a fraction of a second.  It guarantees a locally optimal pattern with respect to the exchange neighbourhood, often shaving a few 10⁻⁴ off the `C5` bound.
