**Goal** – Find a step function `h` (represented by `n` samples on `[0,2]`) with  
`∑h_i = n/2` and `0 ≤ h_i ≤ 1` that minimizes  

\[
C_5 = \max_{k\ge 0}\int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx .
\]

The discretised version is  

\[
C_5 = \frac{2}{n}\,\max_{t=0,\dots ,n-1}
      \Bigl(\;w -  O(t)\Bigr),\qquad
      w=\frac{n}{2},
\]
where  

\[
O(t)=\sum_{i=0}^{n-1-t} h_i\,h_{i+t}
\]

is the a‑periodic autocorrelation of the binary vector `h`.  
Thus **minimising** `C_5` ⇔ **maximising**  

\[
O_{\min}= \min_{t>0} O(t) .
\]

The bound that we will report is  

\[
C_5 = 1 - \frac{2\,O_{\min}}{n}=1-\frac{O_{\min}}{w}.
\]

The search will be performed on **binary** vectors (`h_i∈{0,1}`); continuous values never improve the integer optimum for this problem.

#### 2.1. Exact Mixed‑Integer Linear Programme (MILP)

**Variables**

| Symbol | Meaning |
|--------|----------|
| `h_i` (binary) | indicator of the set at sample `i` |
| `w_{i,t}` (binary) | product `h_i ∧ h_{i+t}` for every shift `t = 1…T` (`T = n‑1`) |
| `M` (continuous) | the objective “worst complement”  `M ≥ w – Σ_i w_{i,t}` for all `t` |

**Constraints**

1. **Cardinality** – `∑_i h_i = w`.
2. **Product linearisation** (McCormick for binaries) for all feasible pairs `(i,t)`:
   * `w_{i,t} ≤ h_i`
   * `w_{i,t} ≤ h_{i+t}`
   * `w_{i,t} ≥ h_i + h_{i+t} – 1`
3. **Upper‑bound definition** – for each shift `t`:
   * `M ≥ w - Σ_i w_{i,t}`

**Objective** – minimise `M`.

**Implementation notes**

* Only shifts `t = 1 … n/2` need to be kept because `O(t) = O(n‑t)` by symmetry; this halves the number of auxiliary variables.
* The total number of `w`‑variables is at most `n·(n/2) ≈ 12 000` for `n = 120`, well within the capability of open‑source MILP solvers (CBC, GLPK, SCIP).
* Provide a **warm start**: use a high‑quality binary solution produced by the stochastic engine (see §2.2) and set the corresponding `h_i` values before invoking the solver. Most solvers accept a partial initialisation and use it for branching.
* Solver parameters:
  * Time limit = remaining budget (e.g. `budget_s – elapsed`).
  * `mip_gap` = `1e‑4` to stop early once we are within 0.01 % of optimal.
* After the solver stops (optimal, cut‑off, or time‑out) read the binary `h` and compute `C_5`.

#### 2.2. Stochastic Simulated‑Annealing (SA) + focused greedy repair  

Because the MILP may not finish for the larger `n`, a very fast heuristic is needed.

**2.2.1. State representation** – binary vector `h` with exactly `w` ones.

**2.2.2. Fast evaluation of the objective**  

* Compute the whole autocorrelation `O(t)` using a **single FFT** on the padded vector:
  * Pad `h` with `n` zeros → length `L = 2^⌈log2(2n)⌉`.
  * `conv = ifft(fft(h, L) * conj(fft(h, L))).real`
  * Then `O[t] = round(conv[t])` for `t = 0 … n‑1` (the rounding removes numerical noise).
* `O_min = min_{t>0} O[t]`.  
* `M = w – O_min` and `C_5 = M * (2/n)`.

The FFT costs `O(L log L)` (≈ 1 µs for `n ≤ 200`), so the objective can be recomputed **from scratch** each iteration if needed.

**2.2.3. Neighbour move** – swap a `1` and a `0`.  
Choosing the pair uniformly at random guarantees that the cardinality constraint stays satisfied.

**2.2.4. Incremental update (optional)** – to speed up the inner loop we can keep `O[t]` and update it in `O(n)` when a swap is performed:

```
for each shift t:
    Δ = Δh_i * (h_{i+t} + h_{i‑t}) + Δh_j * (h_{j+t} + h_{j‑t})
    O[t] += Δ
```

where `Δh_i` = –1 for the leaving‑1 position, `+1` for the entering‑1 position.  
If the incremental code becomes a source of bugs we fall back to the full FFT recomputation (still fast enough).

**2.2.5. Temperature schedule**

* Initialise `T0 = 0.5 * w` (large enough to accept many uphill moves).
* Geometric cooling: `T ← α·T` every `Lcool` iterations (e.g. `α = 0.995`, `Lcool = 1000`).
* Stop when `T` falls below `1e‑4` *or* the elapsed time reaches a fixed fraction (≈ 40 % of the total budget).

**2.2.6. Acceptance rule**

* Compute `ΔM = M_new – M_old`.
* If `ΔM ≤ 0` accept (improvement).
* Else accept with probability `exp(‑ΔM / T)`.

**2.2.7. Focused greedy repair (post‑processing)**  

After the SA loop finishes, we improve the best solution by repeatedly attacking the **worst shift** `t* = argmin O[t]`:

1. Identify all mismatched pairs for this shift:
   * `U = {i | h_i = 1 and h_{i+t*}=0}` (unmatched 1‑positions)
   * `V = {j | h_j = 0 and h_{j+t*}=1}` (unmatched 0‑positions)
2. If `U` and `V` are non‑empty, pick a random `i∈U`, `j∈V` and swap them.
3. Re‑evaluate `O[t]`. If `O[t*]` increased, keep the swap; otherwise revert.
4. Iterate until no swap can raise `O[t*]` or a small iteration limit is reached.

Because each successful swap raises the minimum autocorrelation by **exactly 1**, the bound improves by `2/n`. The repair is deterministic and stops quickly (the number of successful swaps is bounded by `w‑O_min`).

**2.2.8. Multi‑start**

* Run the whole SA+repair pipeline **10–20 times** (different random seeds) within the allocated SA budget.
* Keep the best (lowest `C_5`) solution among all runs.
