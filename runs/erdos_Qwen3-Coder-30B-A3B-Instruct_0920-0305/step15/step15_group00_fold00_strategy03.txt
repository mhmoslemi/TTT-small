**Goal** – Produce a step‑function `h` on `[0,2]` (discretised with `N` points) that satisfies  

* `0 ≤ h[i] ≤ 1` for all `i`,  
* `∑ h[i] · dx = 1`  (i.e. `∑ h[i] = N/2` with `dx = 2/N`),

and minimises  

```
C5(h) = max_{k=0,…,N‑1}  ∑_{i=0}^{N‑k‑1} h[i]·(1‑h[i+k])·dx .
```

The current best bound is ≈ 0.38098.  The new approach is a **direct min‑max optimisation** combined with a **binary rounding / local‑swap refinement**, which is fundamentally different from the SLSQP + DE pipeline used before.

### 1.  Problem Representation

* Choose a modest grid size (e.g. `N = 120` – the same size as the provided seed – but keep the code flexible to also try `N = 100, 140` if time permits).
* Store `h` as a NumPy `float64` vector of length `N`.
* Define `target_sum = N/2`.  The feasibility set is the intersection of the box `[0,1]^N` with the hyperplane `∑ h = target_sum`.

All later updates will be **projected** onto this convex set.

### 2.  Overlap and Gradient Computation

For a given `h` the vector of raw overlaps (without the `dx` factor) is

```
O[k] =   Σ_{i=0}^{N‑k‑1} h[i]            –   Σ_{i=0}^{N‑k‑1} h[i]·h[i+k] .
```

Both terms are cheap to obtain:

* `prefix = np.cumsum(h)` → `Σ_{i=0}^{N‑k‑1} h[i] = prefix[N‑k‑1]`.
* `corr = np.correlate(h, h, mode='full')[N‑1:]` gives exactly the second sum for every `k`.

Thus `O = prefix[::-1] – corr` (vectorised, `O` length `N`).  The actual bound is `C5 = max(O)·dx`.

**Sub‑gradient of the max term**  
Let `k* = argmax_k O[k]`.  The directional derivative of `O[k*]` w.r.t. each component is

```
∂O[k*]/∂h[i] =  1_{i ≤ N‑1‑k*}
                – 1_{i ≤ N‑1‑k*}·h[i+k*]
                – 1_{i ≥ k*}·h[i‑k*] .
```

This yields a simple `O(N)`‑time sub‑gradient vector `g`.

### 3.  Projected Sub‑gradient Descent (core optimiser)

1. **Initialisation** – start from several distinct feasible points:
   * the supplied `initial_h_values` (projected onto the feasible set if necessary),
   * a random vector `u~U[0,1]` projected onto the box‑hyperplane,
   * a *binary* seed obtained by thresholding the current best vector (top `N/2` entries set to 1, others 0) and projecting.

2. **Iteration** – for each start perform a loop until the time budget expires:
   * Compute `O` and `k*`.
   * Form the sub‑gradient `g` using the formula above.
   * Choose a diminishing step size `α_t = α₀ / sqrt(t+1)` (e.g. `α₀ = 0.1`).  
     Optionally perform a cheap back‑tracking line‑search: try `α`, `α/2`, `α/4` and pick the first that strictly reduces the current `max(O)`.
   * Update `h̃ = h – α_t·g`.
   * **Projection** onto the feasible set: solve `min‖x‑h̃‖²` s.t. `0 ≤ x ≤ 1` and `∑x = target_sum`.  
     This is the classic “box‑constrained simplex projection” and can be performed by a 1‑D binary search on the Lagrange multiplier `λ`:
     ```
     x_i = clip( h̃_i – λ , 0 , 1 )
     ```
     Adjust `λ` until `∑x_i = target_sum` within a tolerance `1e‑10`.
   * Replace `h ← x`.

### 4.  Smooth‑Max Continuation (optional refinement)

The sub‑gradient method sometimes slows near the optimum because the max‑operator is flat on many components.  To accelerate convergence:

* Replace the objective temporarily by a **log‑sum‑exp** surrogate:
  ```
  f_β(h) = (1/β)·log( Σ_k exp( β·O[k] ) )
  ```
  As `β → ∞` this approaches `max_k O[k]`.
* Its gradient is a weighted sum of the per‑shift gradients:
  ```
  w_k = exp(β·O[k]) / Σ_j exp(β·O[j])
  ∇f_β = Σ_k w_k·∇O[k] .
  ```
* Run a few L‑BFGS‑B or simple gradient steps on `f_β` (still projecting after each step) with **increasing β** (`β = 1, 5, 20, 80`).  Each stage uses the previous solution as start.  This “continuation” sharpens the approximation and often pushes the solution a few thousandths lower.

### 5.  Binary Rounding & Local Swaps

After the continuous optimisation we normally obtain a near‑binary solution (many entries are close to 0 or 1).  A final discrete improvement is performed:

1. **Hard Rounding** – sort indices by `h[i]`, set the largest `N/2` entries to 1 and the rest to 0, obtaining a binary vector `b`.
2. **Local Swap Search** – repeatedly try to improve `b`:
   * Randomly pick a `1`‑position `i` and a `0`‑position `j`.
   * Tentatively flip them (`b[i]=0`, `b[j]=1`).
   * Re‑compute the overlap vector `O` for the altered binary vector (full recompute is cheap for `N≈120`).
   * If the new `max(O)` is smaller, **accept** the swap; otherwise reject.
   * Perform a large number of random trials (e.g. `10·N²`) or stop when no improvement occurs for a while.
   This greedy hill‑climbing on the binary space often finds a configuration with a lower `C5` than the continuous optimum because the binary constraint forces the mass to be used more efficiently.

3. Keep the best binary vector found (may be the original rounded one or a swapped variant).
