### 2.  Phase I – Binary optimisation (Simulated Annealing + Greedy swaps)

**Why binary?**  
If `h` is binary, `∫h·(1‑h)=0` (the shift 0 term vanishes) and the objective reduces to minimising the largest **mismatch count**  

```
M_k = #{ i : h[i]=1 , h[i+k]=0 , i ≤ n‑k‑1 } .
```

Hence the problem becomes: *choose exactly n/2 positions to be 1 so that the worst‑case mismatch count is smallest*.  This is a classic aperiodic autocorrelation problem and can be tackled efficiently by a swap‑based simulated annealing (SA).

#### 2.1  Initial binary seed  
Take the supplied `initial_h_values` (length 120).  Sort them and set the `n/2` largest entries to 1, the rest to 0.  This respects the sum constraint by construction and usually lies close to a good region.

#### 2.2  Temperature schedule  
```
T0   = 0.02 * (dx·n/2)   # a few percent of a typical C5 value
α    = 0.995              # geometric cooling factor
T   = T0
```
Temperature is updated each iteration: `T ← α·T`.  After ~10 000 iterations `T` is ≈1 e‑5, effectively turning the process into a deterministic greedy search.

#### 2.3  Swap proposal & fast Δ‑evaluation  

Pick uniformly at random  

```
i  ∈ {indices with h[i]=1}
j  ∈ {indices with h[j]=0}
```

Swap them (so `h[i]←0`, `h[j]←1`).  The overlap vector changes only locally.  For a given shift `k`

* **Slice contribution** `S_k = ∑_{i≤n‑k‑1} h[i]`  
  – `i` disappears from the slice for all `k ≤ n‑1‑i`  → `ΔS_k = –1` on that interval.  
  – `j` appears for all `k ≤ n‑1‑j`  → `ΔS_k = +1` on that interval.

* **Correlation contribution** `C_k = ∑_{i≤n‑k‑1} h[i]·h[i+k]`  
  – Removing a 1 at `i` eliminates the products `h[i]·h[i+k] = h[i+k]` (if `i+k<n`) and `h[i‑k]·h[i] = h[i‑k]` (if `i≥k`).  
  – Adding a 1 at `j` creates the symmetric products `h[j+k]` and `h[j‑k]`.

Thus for every `k` we can compute  

```
ΔO_k = ΔS_k – ΔC_k
      = (‑1_{k ≤ n‑1‑i} + 1_{k ≤ n‑1‑j})
        + 1_{k ≤ n‑1‑i}·h[i+k] + 1_{k ≥ i}·h[i‑k]
        – 1_{k ≤ n‑1‑j}·h[j+k] – 1_{k ≥ j}·h[j‑k] .
```

All four indicator masks are contiguous ranges, so the whole `ΔO` vector is built with **four slice operations** (O(n) time).  After the swap we update the stored overlap array by `O ← O + ΔO`.  This avoids recomputing convolutions from scratch.

#### 2.4  Acceptance rule  

```
C5_new = dx·max(O) .
Δ     = C5_new – C5_current .
if Δ ≤ 0:   accept.
else:       accept with prob  exp(‑Δ / T).
```

When a swap is accepted we also flip the bits in the binary mask and keep the updated `O`.  The best (lowest) `C5` ever seen is remembered (`best_h`, `best_C5`).

#### 2.5  Termination & fallback  

The loop runs until either the global time budget is < 5 s or a preset iteration limit (e.g. 30 000) is reached.  Because each iteration costs only O(n) ≈ 120 elementary operations, millions of swaps comfortably fit into the 600 s window.

If the SA finishes without improvement over a large number of steps, we trigger a **deterministic greedy pass**: iterate over all (i∈1, j∈0) pairs once, accept any swap that strictly lowers `C5`.  This usually irons out the remaining local bumps.

At the end of Phase I we have a high‑quality binary vector `h_bin` with a concrete bound `C5_bin`.

### 3.  Phase II – Continuous refinement (smooth‑max gradient descent)

Binary solutions are optimal for the integer version but the true optimum may lie slightly inside the box (fractional values can “smooth” the overlap at the most critical shift).  We therefore start from `h_bin` as a real vector and run a **projected gradient descent** on the smoothed max objective.

#### 3.1  Smoothed objective  

For a given smoothing parameter `β > 0`

```
f_β(h) = (1/β)·log∑_k exp(β·O_k(h)) .
```

When `β→∞`, `f_β → max_k O_k`.  A moderate `β` yields a smooth landscape that still points toward the worst shift.

#### 3.2  Gradient computation  

Using the pre‑derived `grad_Ok(k,h)`

```
w_k = exp(β·O_k) / Σ_j exp(β·O_j)    (log‑sum‑exp safely)
∇f_β = Σ_k w_k · grad_Ok(k,h) .
```

All quantities are vectorised: the four slice‑based components of `grad_Ok` are summed with the weights `w_k`.

#### 3.3  Projection after the gradient step  

Update rule  

```
h_new = h - η·∇f_β
h_proj = project(h_new, n/2)          # box + sum constraint
```

The step size `η` follows a simple schedule, e.g. `η = η0 / sqrt(t+1)`, with `η0 ≈ 0.2`.  The projection guarantees feasibility at every iteration.

#### 3.4  β‑schedule (homotopy)  

Start with a gentle smoothness (`β = 1.0`).  After a few hundred iterations increase β (e.g. `β ← 2·β`) until a target `β≈30` is reached.  The gradual tightening lets the iterate first move quickly toward the basin of a good solution, then fine‑tune the actual max.

#### 3.5  Early stopping & time‑aware loop  

The outer loop monitors the remaining wall‑clock time.  Every 200 iterations we compute the **exact** `C5` via `c5_value(h_proj)`.  If it improves the global best, we store a copy.  When less than 2 s remain we break, returning the best discovered vector.

| **SA gets stuck** – temperature too low too early. | Use a *slow* cooling factor (`α=0.997`) and enforce a minimal temperature floor (e.g. `1e‑6`). |
| **Δ‑evaluation overflow** – accidental out‑of‑range indices. | Guard every slice with `if i+k < n` / `if i‑k ≥ 0`.  The vectorised mask construction inherently respects bounds. |
| **Projection fails to converge** (unlikely). | Initialise the bisection interval with generous bounds (`λ∈[‑2, 2]`).  If after 80 iterations the sum ≠ target, fall back to a simple Euclidean projection onto the simplex (the classic “water‑filling” algorithm). |
| **Large β causing numerical overflow**. | Use `logsumexp` from `scipy.special` and compute `w_k` as `exp(β·(O‑maxO))` to keep exponents ≤ 0. |
| **Time budget exceeded**. | All heavy loops check `time.time()` at the beginning of each outer iteration; if the remaining budget falls below a safety margin (≈ 3 s) the algorithm exits immediately with the best solution stored so far. |
| **Discrete optimum not reachable** – binary bound quantised by `dx`. | The continuous refinement (Phase II) deliberately allows fractional values, which can push the final `C5` below the nearest multiple of `dx`. |

### 6.  Overall Workflow (pseudo‑outline)

1. **Set** `n = 120` (or a slightly larger even number if time permits).  
2. **Build** the initial binary mask by thresholding `initial_h_values`.  
3. **Run** the binary simulated‑annealing + greedy sweep (Phase I) while monitoring time.  
4. **Store** `best_h_binary`, `best_C5_binary`.  
5. **Start** continuous refinement from `best_h_binary` (Phase II) with a smooth‑max gradient descent, updating β gradually.  
6. **Whenever** a new exact `C5` beats the global best, clone the current `h`.  
7. **If** after Phase II there is still ≥ 30 s left, **up‑sample** to a larger `n` and repeat Steps 2‑6.  
8. **Return** the globally best vector (as a plain Python list), its exact `C5` (float), and the `n` used.

The combination of a **global combinatorial search** (which quickly discovers a near‑optimal binary pattern) and a **deterministic smooth‑max gradient descent** (which fine‑tunes fractional entries) is fundamentally different from the previous SLSQP / DE pipeline.  It directly attacks the min‑max structure, exploits the binary nature of the optimal set, and uses fast O(n) updates, making it well suited to the 1‑second‑per‑iteration regime required for a noticeable improvement over the reported bound of `0.380975`.  With the described annealing schedule and a modest continuous polishing stage, the algorithm is expected to achieve a bound **≤ 0.3807** well within the allotted 600 seconds.
