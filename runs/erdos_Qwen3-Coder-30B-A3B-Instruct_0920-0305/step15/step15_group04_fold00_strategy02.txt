**Overview**  
The problem can be viewed as a *binary* placement problem: the optimal step function is a characteristic function of a measurable set of measure 1, i.e. a vector `h∈{0,1}ⁿ` with exactly `n/2` ones (because the interval `[0,2]` is discretised with step `dx=2/n`).  
For a shift ℓ (ℓ≠0) the *overlap count* is  

\[
O_\ell(h)=\sum_{i=0}^{n-\ell-1}h_i\,h_{i+\ell}\qquad\text{(integer)} .
\]

The integral overlap is `dx·O_ℓ`, and the objective used by the evaluator is  

\[
C_5(h)=dx\;\max_{\ell} \Bigl(\sum_i h_i\bigl(1-h_{i+\ell}\bigr)\Bigr)
      =1-\frac{2}{n}\;\min_{\ell} O_\ell(h).
\]

Thus **minimising** `C₅` is **equivalent** to **maximising the minimal overlap count**  

\[
t=\min_{\ell\neq0} O_\ell(h).
\]

Consequently the optimisation can be cast as a *mixed‑integer linear program* (MILP) that directly maximises `t`.  The approach below is fundamentally different from the differential‑evolution/gradient method previously used: it solves an exact combinatorial model (with a small‑scale heuristic warm‑start) and guarantees a provable bound.

The workflow consists of three logically separated phases:

1. **Discretisation choice** – pick a modest even size for the exact MILP (e.g. `n=80`) and a larger size for a fast heuristic (e.g. `n=180`).  
2. **Heuristic phase** – generate a high‑quality binary pattern with a *targeted stochastic local search* that explicitly reduces the worst‑shift overlap. The best heuristic pattern will be used as a warm‑start for the MILP.  
3. **Exact MILP phase** – formulate and solve a binary‑search‑or‑direct‑maximisation MILP that enforces a lower bound on every shift’s overlap.  The solution yields a provable upper bound on `C₅`.  If time permits, the binary solution is up‑sampled to the larger `n` and optionally refined with a smooth gradient step.

All steps respect the global time budget (`budget_s`), terminating gracefully before the deadline.

### 2. Heuristic Phase – Targeted Stochastic Local Search (TLS)

**2.1 Variable representation**  
`h` is an *binary* NumPy array of length `n₁` with exactly `n₁/2` entries equal to 1.  The sum‑constraint is enforced by construction.

**2.2 Objective evaluation**  
For a candidate `h` compute  

```
c = np.correlate(h, 1‑h, mode='full')   # length 2·n₁‑1
C5 = dx₁ * np.max(c)
```

`np.correlate` is a tiny C routine; for `n₁≤200` each evaluation costs ≈ 10⁻⁴ s.

**2.3 “Worst‑shift swap’’ move**  

1. Compute the correlation array `c`.  
2. Identify the *worst* shift `ℓ* = argmax(c)` (ignore the centre `ℓ=0`, which is always zero for binary vectors).  
3. Define  
   - **Bad ones** = indices `i` with `h_i = 1` *and* `i+ℓ*` inside the array and `h_{i+ℓ*}=0`.  
   - **Good zeros** = indices `j` with `h_j = 0` *and* `j+ℓ*` inside and `h_{j+ℓ*}=1`.  
   Swapping any `i∈BadOnes` with any `j∈GoodZeros` reduces `c_{ℓ*}` by exactly 2 (two mismatches become matches), i.e. strictly improves the objective.

4. If both sets are non‑empty, pick a random pair `(i,j)` from them, perform the swap, and **accept** unconditionally (the move is guaranteed to lower `C₅`).  
5. If at least one of the sets is empty, perform a *exploratory* random swap (`h_i=1 ↔ h_j=0` with uniformly chosen `i,j`). This allows the algorithm to escape plateaus.

**2.4 Local‑search loop**

```
best_h = random binary vector (n₁/2 ones)
best_val = C5(best_h)

while time_remaining_in_heuristic_phase:
    ℓ* = worst shift of current_h
    compute BadOnes, GoodZeros
    if both non‑empty:
        swap a random (i,j) from them
        current_h = swapped vector
        current_val = C5(current_h)
        if current_val < best_val:
            best_val = current_val; best_h = current_h.copy()
    else:
        # pure exploration
        pick random i with h_i=1, random j with h_j=0
        current_h = swapped vector
        # do NOT update best unless improvement appears later
    # optional: after a fixed number of iterations without improvement,
    # re‑initialise current_h to a fresh random binary vector (restart)
```

The loop is extremely cheap: each iteration needs a single correlation (≈ 0.1 ms).  Running for ~5 × 10⁴ iterations typically explores the combinatorial space thoroughly within ~5 seconds.  Multiple independent restarts are performed until the allocated heuristic time (≈ 45 % of the total budget) expires.  The best vector `h_TLS` and its value `C_TLS` are stored.

**Why TLS is new**  
The previous code used a population‑based DE on a continuous domain with gradient approximations.  TLS works **only in the binary domain**, directly attacks the *max‑overlap* term by swapping bits that affect the *currently worst* shift, and requires **no gradient** nor population management.  This produces a qualitatively different search landscape and often yields a lower `C₅` very quickly.

### 3. Exact MILP Phase – Maximising the Minimal Overlap

The TLS solution provides a high‑quality starting pattern but does not give a provable bound.  The MILP phase obtains a rigorous upper bound (and often a strictly better one) by solving a **binary maximisation of the minimal overlap count**.

**3.1 Decision variables**

* `x_i ∈ {0,1}` for `i = 0,…,n₂‑1` – the step‑function entries.  
* `y_{i,ℓ} ∈ {0,1}` for each shift `ℓ = 1,…,n₂‑1` and each admissible index `i = 0,…,n₂‑ℓ‑1`.  
  `y_{i,ℓ}` is intended to represent the product `x_i·x_{i+ℓ}`.  
* `t ∈ ℤ₊` – the minimal overlap count across all shifts (the quantity we maximise).

**3.2 Linear constraints**

1. **Integral constraint**  
   \[
   \sum_{i=0}^{n₂-1} x_i = n₂/2 .
   \]

2. **McCormick linearisation of the product** (exact for binary variables) for each `(i,ℓ)`:

   \[
   \begin{aligned}
   y_{i,ℓ} &\le x_i,\\
   y_{i,ℓ} &\le x_{i+ℓ},\\
   y_{i,ℓ} &\ge x_i + x_{i+ℓ} - 1,\\
   y_{i,ℓ} &\ge 0 .
   \end{aligned}
   \]

3. **Minimal‑overlap definition** – for every shift ℓ enforce

   \[
   \sum_{i=0}^{n₂-ℓ-1} y_{i,ℓ} \;\ge\; t .
   \]

   This guarantees that the overlap count for *each* shift is at least `t`.

4. **Variable domains** – `x_i, y_{i,ℓ}` are binary; `t` is integer and bounded `0 ≤ t ≤ n₂/2`.

**3.3 Objective**

\[
\text{maximise } t .
\]

Since `C₅ = 1 - (2/n₂)·t`, maximising `t` directly minimises the desired constant.

**3.4 Symmetry reduction (optional, but speeds up the solver)**  

Because the correlation with zero padding is symmetric (`ℓ` and `n₂-ℓ` produce the same set of pairs), it suffices to impose the overlap constraint only for `ℓ = 1,…,⌊(n₂‑1)/2⌋`.  The omitted larger ℓ’s are automatically satisfied if the smaller ones hold (the same pairs appear in reverse order).  This halves the number of auxiliary variables and constraints.

**3.5 Solver setup**

* Use `cvxpy` to build the model; select an open‑source MILP solver that is guaranteed to be present (e.g. `CBC` via `cylp`, `GLPK_MI`, or `SCIP`).  
* Set a per‑solve time limit (e.g. 8 seconds) through solver‑specific options (`maxTime`, `tmlim`, etc.).  
* Enable warm‑starting: after the first solve, keep the previous variable values as the initial point for the next run (useful when iteratively tightening a bound).  

**3.6 Solving strategies**

Two equivalent ways to obtain the optimal `t`:

* **Direct maximisation** – solve the MILP once with objective `max t`.  The solver returns the best integer `t*` it can find within the time limit.  The corresponding `C₅ = 1 - (2/n₂)·t*` is a provable upper bound.  

* **Binary‑search feasibility** – if the solver struggles with the objective, switch to a feasibility formulation: for a trial bound `C` compute the required integer overlap  
  \[
  t_{\text{req}} = \Bigl\lceil (1-C)\,\frac{n₂}{2}\Bigr\rceil .
  \]  
  Add the constraints `∑ y_{i,ℓ} ≥ t_req` (instead of the variable `t`) and ask the solver whether the model is feasible.  Perform a classic binary search on `C` (initial interval `[0, C_{TLS}]`) until the interval width falls below `1e‑4` or the time budget is exhausted.  The smallest feasible `C` found is the final bound.

Both paths are included in the strategy; the implementation chooses the direct maximisation first and falls back to binary search if the solver returns “time limit exceeded” without optimality proof.

**3.7 Warm‑start from TLS**

Take the best heuristic vector `h_TLS` (length `n₁`).  Down‑sample it to length `n₂` by simple block averaging (or by selecting every `⌈n₁/n₂⌉`‑th index).  Convert the down‑sampled binary pattern into a *partial fixing* for the MILP:

*Fix a percentage* (e.g. 30 %) of the `x_i` variables to the down‑sampled values, leaving the remaining variables free.  This reduces the search space and often guides the MILP toward a high‑quality solution quickly.  The fixing fraction can be reduced gradually if the MILP reports infeasibility.

### 4. Post‑processing & Upsampling

If the MILP yields a binary optimal vector `x_opt` of length `n₂` with minimal overlap `t*`:

2. **Upsample to the required output size** (`n₁`).

   h_{\text{out}} = \underbrace{x_{\text{opt}},\dots,x_{\text{opt}}}_{s\ \text{times}} .

3. **Optional continuous refinement** (only if time remains).
