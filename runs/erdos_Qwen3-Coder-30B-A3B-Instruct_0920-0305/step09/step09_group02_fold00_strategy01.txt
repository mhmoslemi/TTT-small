### 1. Mathematical reformulation

For a given shift `k` define  

`f_k(h) = Σ_i h[i]·(1‑h[i+k])·dx = (∑ h)·dx – Σ_i h[i]·h[i+k]·dx`.

Because `∑ h·dx = 1` is constant, minimising `max_k f_k` is equivalent to **maximising the minimum auto‑correlation**  

`min_k Σ_i h[i]·h[i+k]·dx`.

The function `max_k f_k` is non‑smooth.  Introduce the smooth **ℓ‑p surrogate**

```
J_p(h) = ( Σ_k f_k(h)^p )^{1/p} ,     p ≥ 1
```

As `p → ∞`, `J_p → max_k f_k`.  For any finite `p` the surrogate is differentiable and its gradient can be written in closed form.

--------------------------------------------------------------------
### 2. Gradient of the surrogate

Let `F = (f_k)_{k=-(n-1)…(n-1)}` be the vector of all shift values (including negatives).  
Define the **shift operators** for a fixed integer shift `k`:

* `R_k(h)` – `h` shifted **right** by `k` (zero‑filled when the index falls outside).  
* `L_k(h)` – `h` shifted **left** by `k`.

For a single shift `k`

```
∂f_k/∂h = 1 – R_k(h) – L_k(h)        (component‑wise)
```

(the term “1” comes from the derivative of `∑ h[i]·dx`, the other two terms from the bilinear product).

For the ℓ‑p surrogate

```
J_p = ( Σ_k f_k^p )^{1/p}
w_k = f_k^{p‑1} / J_p^{p‑1}               (weights, Σ w_k = 1)
∇J_p = Σ_k w_k · ( 1 – R_k(h) – L_k(h) )  (vector of length n)
```

Thus the gradient is a **weighted sum of the elementary gradients**.  When `p` is small the weights are spread over many shifts, providing a smooth landscape; when `p` grows they concentrate on the worst shifts, approximating the true sub‑gradient of the max.

--------------------------------------------------------------------
### 3. Projection onto the feasible set

After a gradient step we must satisfy both box constraints and the equality sum constraint.  The feasible set is the intersection of an axis‑aligned hyper‑box `[0,1]^n` and the affine hyper‑plane `∑ h = w` (`w = n/2` because `dx·w = 1`).  The projection can be performed analytically:

1. **Shift** each component by a scalar `λ`: `h̃_i = h_i + λ`.  
2. **Clip** to the box: `ĥ_i = clip(h̃_i, 0, 1)`.  

The function `S(λ) = Σ_i ĥ_i` is monotone increasing in `λ`.  A binary search on `λ` finds the unique value with `S(λ) = w`.  The search interval can be safely started at `[-1, 1]` and expanded if `S` does not bracket `w`.  The resulting projection is exact up to floating‑point tolerance and runs in `O(n)` time.

  * Run a fixed number of projected gradient iterations (e.g. 500‑800).  
  * After the stage finish, use the obtained `h` as the start for the next, larger `p`.

Increasing `p` gradually sharpens the objective, allowing the algorithm to first move in a well‑behaved smooth basin and then fine‑tune the worst‑case shift.

--------------------------------------------------------------------
### 5. Detailed iteration loop for a single `p`

For a given `p`:

1. **Compute all shifts** – obtain the full correlation vector `f = corr(h, 1‑h)·dx`.  
2. **Calculate `J_p` and the weights** `w_k = f_k^{p‑1} / J_p^{p‑1}`.  
3. **Assemble the gradient** by looping over all integer shifts `k`  
   * obtain `R_k(h)` and `L_k(h)` via simple slice operations (constant‑time per element)  
   * accumulate `grad += w_k * (1 – R_k – L_k)`.  
   This loop costs `O(n²)` but with `n ≤ 200` it is negligible (< 0.001 s per iteration).  
4. **Projected update** – set `h_new = h – α·grad`; apply the projection described in §3.  
5. **Step‑size adaptation** – if `J_p` decreased, slightly increase `α` (`α ← 1.02·α`, capped); otherwise shrink (`α ← 0.5·α`).  
6. **Optional momentum** – keep a velocity `v` and update via  
   `v ← μ·v – α·grad` (`μ≈0.9`), then `h_new = h + v` before projection.  
7. **Record the best** – after each iteration compute the true `C5 = max(f)`. Keep the `h` with lowest `C5` seen so far (even if `J_p` is larger, because `J_p` is only a surrogate).

Terminate the inner loop when either the maximum iteration count is reached or the elapsed time approaches the global budget.

--------------------------------------------------------------------
### 6. Initialisation

* **Number of points** – choose an even `n` (e.g. `n = 160`).  
* **Target sum** – `w = n/2`.  
* **Starting shape** – a symmetric, monotonically decreasing “tent”:

```
dist = | i – (n‑1)/2 |·dx
h[i] = max(0, 1 – dist / L)    (L chosen so that Σ h = w)
```

The tent already concentrates mass near the centre, which is known to reduce large‑shift overlaps.  
If the global variable `initial_h_values` (length 120) is available, linearly interpolate it to length `n` and then project onto the feasible set – this supplies a strong data‑driven starting point that can be refined.

--------------------------------------------------------------------
### 7. Post‑processing refinement (optional)

After the continuation finishes (largest `p`), a **local nonlinear optimiser** can be called for a final polish:

* Use `scipy.optimize.minimize` with method **SLSQP** or **trust‑constr**.  
* Supply the exact objective `C5(h) = max_k f_k(h)` (computed via correlation).  
* Provide the Jacobian as the sub‑gradient from the current worst shift (same formula as in §2).  
* Keep the bound constraints `[0,1]` and the equality `∑ h = w`.  

Since the starting point is already very close to a local minimum, only a few iterations are needed, and the extra time is negligible.

### 8. Whole algorithm flow (pseudo‑outline)

1. **Set** random seed, parse `budget_s`.  
2. **Define** `n`, `dx`, `w`.  
3. **Initial `h`** – either interpolated `initial_h_values` or the symmetric tent; project onto the feasible set.  
4. **Best record** – store `best_h`, `best_C5`.  
5. **Loop over `p` values** (`4 → 8 → 16 → 32 → 64`):  
   * Run the projected‑gradient inner loop (500–800 iterations).  
   * After each iteration evaluate the true `C5`; update `best_h`/`best_C5` if improved.  
   * Adjust step size as described.  
   * If the global time limit is close, break early.  
6. **Optional local refinement** with SLSQP, using the current `best_h` as start.  
7. **Return** `(best_h.tolist(), float(best_C5), n)`.

### 9. Numerical choices & safeguards

* **FFT vs direct correlation** – For the surrogate’s gradient we need *all* shift values `f_k`.  With `n ≤ 200` the naïve `np.correlate` (O(n²)) is faster than FFT overhead, but an FFT implementation can be kept as a fallback.  
* **Numerical stability** – When `p` becomes large, `f_k^{p‑1}` may overflow.  Before exponentiation, shift the vector by the maximal entry: compute `exp(p·log(f_k) – p·log(f_max))` and renormalise; this is the standard log‑sum‑exp trick.  
* **Projection robustness** – Clamp the binary‑search interval after each iteration; if the sum after clipping at `λ = 0` already exceeds `w`, move the interval left, otherwise right.  Terminate when the absolute sum error falls below `1e‑12`.  
* **Symmetrisation (optional)** – after each projection enforce `h = (h + h[::-1]) / 2`.  This halves the effective dimension and guarantees that the worst shift is the same for left/right directions, often improving the bound.  
* **Failure handling** – If an iteration produces `NaN` (possible only with overflow), reset `α` to a small value and re‑project.  If after a whole `p`‑stage no improvement occurred for > 300 iterations, inject a tiny random perturbation (e.g. add `±0.01` to 5 % of entries) and continue.
