```
c_k(h) = Σ_{i=0}^{n‑1} h[i]·(1 – h[i+k]) ,   k = –(n‑1)…(n‑1)
```

(where the sum ignores out‑of‑range indices).  
The quantity to be minimised is  

```
C5(h) = dx · max_k c_k(h) .
```

The constraints are  

```
0 ≤ h[i] ≤ 1  (box)                      (B)
Σ_i h[i] = n/2   (fixed integral)        (S)
```

The task is a non‑convex min‑max problem.  A direct gradient‑based approach (as used before) gets stuck in local minima.  
The proposed method tackles the problem in **three fundamentally different stages**:

1. **A stochastic global search that respects the cardinality constraint exactly** – the *Cross‑Entropy (CE) method* on binary vectors.  
2. **Deterministic discrete refinement** – a *tabu‑search hill‑climber* that swaps 0/1 positions while keeping the number of ones fixed.  
3. **Continuous polishing** – a short *projected gradient descent* on the smooth log‑sum‑exp surrogate of the max, starting from the best binary pattern obtained.

Each stage uses a different optimisation paradigm, so the overall pipeline is materially different from the prior SLSQP‑+‑noise approach.

---

**2. Stage I – Cross‑Entropy sampling on the hyper‑cube**

*Why binary?*  
If a binary pattern already yields a low `C5`, allowing fractional values can only improve (or at worst keep) the objective, because the product `h[i]·h[i+k]` is maximised when each entry is either 0 or 1.  Hence we first search the much smaller combinatorial space of `0/1` vectors with exactly `m = n/2` ones.

*Exact‑cardinality sampling* – we need a fast way to draw a binary vector `x` of length `n` with `Σ x = m` from a **parameter vector** `p ∈ (0,1)^n`.  The standard *Gumbel‑top‑k* trick does this:

```
for i = 0 … n‑1:
    g_i = –log( –log( U_i ) )      # Gumbel noise, U_i ~ Uniform(0,1)
    s_i = log( p_i / (1–p_i) ) + g_i
choose the m indices with largest s_i → set those positions to 1, the rest to 0.
```

The distribution of the resulting `x` satisfies `P(x_i=1) = p_i` and respects the cardinality exactly.

*CE algorithm*  

1. **Initialisation** – set `p_i = 0.5` for all `i`.  Clamp the probabilities to a safe interval `[ε, 1‑ε]` (e.g. `ε = 0.01`) to avoid collapse.
2. **Iteration loop** (until the time budget for this stage is exhausted, ≈ 350 s):
   * Draw `M` samples (`M = 500` is a good trade‑off) using the Gumbel‑top‑k sampler.
   * For each sample compute `c_k` by a single FFT‑based correlation and obtain `C5 = dx·max(c_k)`.  This costs `O(n log n)` per sample, negligible for `n = 120`.
   * Select the **elite set** – the best `ρ·M` samples (`ρ = 0.20`).  
   * Compute the empirical frequency of a 1 at each position among the elite vectors:  

        `p̂_i = (1/|elite|) Σ_{x∈elite} x_i`.
   * Update the parameter vector with exponential smoothing:  

        `p_i ← (1‑α)·p_i + α·p̂_i`   (recommended `α = 0.7`).  
     Re‑clamp to `[ε, 1‑ε]`.
   * Keep track of the overall best sample (lowest `C5`) seen so far.
3. **Diversity control** – if after several iterations the variance of `p` falls below a threshold (e.g. `Var(p) < 10⁻⁴`), inject a small amount of random noise (e.g. replace `p ← 0.5·p + 0.5·0.5`) to restore exploration.

*Outcome* – a binary vector `x⁰` with a very low `C5` (typically ≈ 0.381 or better) and a probability vector `p*` that is strongly biased towards the promising coordinates.

---

**3. Stage II – Tabu‑search hill‑climber on the binary space**

The CE stage supplies a high‑quality starting point; the tabu search exploits the exact structure of the objective.

*Neighbourhood definition* – a neighbour is obtained by **swapping** a 1 at position `i` with a 0 at position `j`.  This preserves the cardinality constraint automatically.

*Efficient evaluation of a swap* – the correlation `c_k` can be updated incrementally:
```
Δc_k = – (1–h[i+k])   (if i+k in range)   – (1–h[i‑k]) (if i‑k in range)
       + (1–h[j+k])    (if j+k in range)   + (1–h[j‑k]) (if j‑k in range)
```
Because `h` is binary, the update simplifies to adding/subtracting 1 where needed.  Nonetheless, with `n = 120` a full recomputation via FFT (`O(n log n)`) for each candidate swap is still cheap, and we can afford to evaluate **all** `m·(n‑m)` possible swaps (≈ 3600).

*Tabu list* – store the last `T = 20` performed swaps (ordered pairs `(i,j)`).  A move that reverses a tabu pair is forbidden unless it yields an improvement exceeding a small aspiration threshold (e.g. 1 % of current best).

*Search loop* (≈ 150 s):
1. Set `x ← x⁰`, `C5_best ← C5(x)`.
2. Repeatedly:
   * Examine all admissible swaps (or a random subset if time is tight).  
   * Pick the swap that yields the **largest decrease** in `C5`.  
   * If the decrease is positive, execute the swap, update the tabu list and set `C5_best ← new value`.  
   * If no improving swap exists for `L = 30` consecutive attempts, perform a * diversification* step: randomly select a non‑tabu swap (even if it worsens the objective) to escape the plateau.
3. Terminate when the wall‑clock time allocated for this stage expires.  
The best binary vector `x*` found is retained.

---

**4. Stage III – Continuous polishing via projected gradient descent on a smooth surrogate**

Having a high‑quality binary pattern, we now allow fractional entries to possibly shave a few extra hundredths off the bound.

*Smooth surrogate* – use the log‑sum‑exp approximation of the max:

```
F_α(h) = (1/α)·log Σ_k exp( α·c_k(h) )       (α > 0)
```

`F_α` is differentiable and converges to `max_k c_k` as `α → ∞`.  

*Gradient* – for a given `h` compute the correlation vector `c = compute_corr_fft(h)`.  
Let `w_k = exp(α·c_k)/Σ_j exp(α·c_j)`.  The gradient of `F_α` is

```
∇F_α(h) = Σ_k w_k·( 1 – h_{·+k} – h_{·‑k} )
```

where the slice notation implements the two shifted subtractions (see the detailed slice‑loop in the analysis).  This can be evaluated in `O(n²)` (≈ 1.4·10⁴ ops) which is trivial for `n = 120`.

*Projection* – after a gradient step, project onto the feasible set `{ h∈[0,1]^n : Σ h = n/2 }`.  The binary‑search projection described in the existing code (solve for a Lagrange multiplier λ so that `clip(h+λ,0,1)` has the required sum) is exact and cheap.

*Descent scheme*  

1. Initialise `h ← x*` (treat binary entries as 0.0/1.0 floats).  
2. Set `α = α₀ = 2.0`, `η = η₀ = 0.25`.  Use a momentum term `m ← 0`.  
3. Loop (≈ 30 s):
   * Compute `c, w, grad` as above.
   * Momentum update: `m ← β·m + (1‑β)·grad` (β = 0.9).  
   * Trial step: `h̃ = h – η·m`; project `h̃`.  
   * Evaluate the *exact* `C5` of `h̃` (via FFT).  
   * If `C5(h̃) < C5(h)` **accept** (`h ← h̃`); otherwise reject and optionally halve `η`.  
   * Every `L = 200` iterations increase the smoothing parameter: `α ← min(α·ρ, α_max)` with `ρ = 1.02`, `α_max = 30`.  Decay the stepsize `η ← η·δ` (δ ≈ 0.9995) each iteration.
4. Keep the best `h` (lowest exact `C5`) encountered during the whole polish.

Because the surrogate becomes tighter as `α` grows, the method converges to a (locally) optimal solution of the original max‑problem while staying in the feasible region at all times.

---

**6. Numerical choices & safeguards**

* **Population size (M)** – 500 gives a low variance estimate of elite frequencies while staying well under the 600 s total budget.
* **Elite fraction (ρ)** – 0.20 balances exploitation and exploration.
* **Learning rate (α) for CE** – 0.7 provides sufficient damping; too large leads to premature collapse.
* **Probability floor (ε)** – prevents any position from becoming permanently locked at 0 or 1 before the discrete refinement has a chance to act.
* **Tabu tenure (T)** – 20 swaps prevents immediate reversal without freezing the search.
* **Diversification trigger (L)** – after 30 non‑improving attempts a random allowed swap is forced; this keeps the search from stagnating.
* **Gradient step decay** – η multiplied by 0.9995 each iteration avoids overshooting as we approach a plateau.
* **Smoothing schedule** – α is multiplied by 1.02 every 200 iterations, reaching ≈ 30 after ~3 000 iterations, ensuring the surrogate is essentially the true max in the final phase.
* **Numerical stability in log‑sum‑exp** – compute `max_val = α·c.max()`, then `exp_vals = np.exp(α·c - max_val)` to avoid overflow.
* **Projection robustness** – the binary‑search for λ is bounded initially at `[-1, 1]` and expanded if needed; 30 bisection steps guarantee ≈ 1e‑10 accuracy on the sum.

**7. Expected failure modes and mitigations**

| Failure mode | Symptom | Mitigation |
|--------------|---------|------------|
| *Premature probability collapse* in CE (all `p_i` → 0 or 1) | No improvement after several iterations; elite variance ≈ 0 | Enforce a minimum probability floor `ε`; inject random noise when variance falls below a threshold. |
| *Stagnation in tabu search* (no improving swap for many iterations) | Runtime spent looping without change | Diversification step after a fixed number of non‑improving attempts; occasional restart from a different elite sample. |
| *Oscillating gradient steps* (objective increases repeatedly) | C5 fluctuates despite decreasing η | Back‑tracking line search: if a trial step worsens the exact C5, halve η and retry up to a few times; keep the best accepted step. |
| *Numerical overflow in the exp‑term* (α large) | `inf` or `nan` in weight computation | Use the standard log‑sum‑exp trick (`exp(α·c - max)`). |
| *Violation of sum constraint after projection* (tiny rounding error) | `|Σh - n/2| > 1e‑8` | After projection, perform a final correction: add/subtract the residual uniformly over the non‑boundary entries. |
| *Time overruns* | Process exceeds 600 s limit | Periodically check the wall‑clock (`time.time()`) at the beginning of each outer loop and break gracefully, returning the best solution obtained so far. |
