**Overview**  
Instead of stochastic local moves, we solve the problem *globally* by turning it into a mixed‑integer linear program (MILP).  The MILP exactly captures the combinatorial nature of the overlap constraints, and a *cut‑generation* (lazy‑constraint) loop keeps the model tiny – only the shifts that are actually active appear as constraints.  After the integer solution is found we optionally polish it with a few deterministic gradient steps.  The whole pipeline is deterministic, uses only `numpy` and `cvxpy` (with CBC/GLPK/SCIP), and fits comfortably inside the 600 s budget.

--------------------------------------------------------------------
### 1. Algebraic reformulation

Let  

* `n` – number of discretisation points (choose the same `n = 120` as the
  supplied `initial_h_values` to avoid costly resampling).  
* `dx = 2.0 / n`.  
* `w = Σ_i h_i = n/2`   (the integral constraint, because `dx·w = 1`).  

For any integer shift `k` with `-(n‑1) ≤ k ≤ n‑1` define the *raw* overlap  

```
F_k(h) = Σ_i h_i·(1 – h_{i+k})                (indices outside [0,n‑1] are treated as 0)
```

Using `w` we have  

```
F_k(h) = w – Σ_i h_i·h_{i+k}.
```

The objective is  

```
C5(h) = dx· max_k F_k(h) .
```

Hence minimising `C5` ⇔ minimising `T = max_k F_k(h)`.  The integer `T`
is the maximal raw overlap; the final bound is `dx·T`.

### 2. Exact MILP model (binary version)

We force every `h_i` to be binary (`0` or `1`).  This restriction is
standard for Erdős‑type overlap problems; the optimal continuous solution
is always a convex combination of binary extremal points, so a good binary
solution gives a tight *upper* bound.

* `h_i ∈ {0,1}`  for `i = 0,…,n‑1`.

* `T ∈ ℤ`  – the maximal raw overlap we want to minimise.

**Constraints**

1. **Cardinality** – exactly `w = n/2` ones  

   ```
   Σ_i h_i = w .
   ```

2. **AND‑linearisation** (McCormick for binary variables) for every
   overlapping pair `(i,k)`  

   ```
   y_{i,k} ≤ h_i ,
   y_{i,k} ≤ h_{i+k} ,
   y_{i,k} ≥ h_i + h_{i+k} – 1 .
   ```

   These three inequalities are necessary and sufficient for `y_{i,k}`
   to equal the product `h_i·h_{i+k}` when `h` is binary.

3. **Shift‑constraints** – enforce the definition of `T` only for the
   *currently active* shifts `K_active`.  For a shift `k`  

   ```
   w – Σ_{i : i+k∈[0,n)} y_{i,k} ≤ T .
   ```

   Rearranged, `Σ_i y_{i,k} ≥ w – T`.  Adding the constraint for every
   `k` would give a model of size `O(n²)`.  Instead we start with a tiny
   set `K_active = {0}` (shift 0 is always tight) and enrich it later
   (see Section 4).

**Objective**

```
minimise   T .
```

This is a pure linear integer program.

--------------------------------------------------------------------
### 3. Symmetry and monotonicity reductions (optional but extremely
beneficial)

The optimal solution of the continuous problem is symmetric about the
mid‑point `x = 1`.  Imposing this symmetry shrinks the variable set by
roughly a factor two and improves the LP relaxation drastically.

* **Mirror symmetry**  

  ```
  h_i = h_{n-1-i}   for all i .
  ```

  Implement by keeping only the first `⌈n/2⌉` variables and adding equality
  constraints to the mirrored positions.

* **Unimodality (non‑increasing away from the centre)**  

  For indices ordered by distance from the centre (`d₀ ≤ d₁ ≤ …`) impose  

  ```
  h_{d_j} ≥ h_{d_{j+1}} .
  ```

  These are linear inequalities and cut the feasible region to the
  “tent‑shaped” family known to be near‑optimal.  The reduction lowers the
  number of binary variables dramatically (≈ n/2 instead of n) while
  preserving the best known constructions.

Both symmetry and unimodality are *hard* constraints, not penalties; they
do not affect the validity of the bound.

--------------------------------------------------------------------
### 4. Lazy‑constraint (cut‑generation) loop

The full set of shift constraints is huge (`2n‑1` ≈ 239).  In practice only a
small subset becomes active at the optimum.  We therefore adopt the classic
*cut‑generation* scheme:

1. **Initial solve** – build the MILP with only `K_active = {0}` (the zero‑shift
   constraint).  Solve with `cvxpy` + a fast MILP solver (CBC, GLPK_MI,
   SCIP, or the built‑in ECOS_BB).  Impose a solver time limit (e.g. 30 s) so
   we always obtain a feasible incumbent even if optimality is not proven.

2. **Violation test** – from the incumbent `ĥ` compute the exact raw overlap
   vector  

   ```
   f = np.correlate(ĥ, 1 – ĥ, mode='full')   # integer counts, length 2n‑1
   T̂ = max(f) .
   ```

   If `T̂ == T_current` the solution already satisfies all shifts; stop.

3. **Add the worst shift** – otherwise pick any shift `k*` with `f[k*] = T̂`
   (the current maximal overlap).  Append the linear constraint

   ```
   w – Σ_i y_{i,k*} ≤ T .
   ```

   to the model (the `y`‑variables for that shift already exist, because they
   were created for *all* overlapping pairs; only the inequality is new).

4. **Re‑solve** – resolve the MILP with the enlarged `K_active`.  The solver
   keeps the previous feasible solution as a warm start, so the second
   solve is usually much faster.

5. **Iterate** – repeat steps 2‑4 until either  
   * no violating shift remains (optimality proven), or  
   * the global time budget (`budget_s`) is exhausted.  

   In the latter case the *best incumbent* found so far is a valid
   construction and provides a certified upper bound `dx·T_incumbent`.

Because each iteration adds at most one new inequality, the model size grows
linearly with the number of distinct active shifts (typically < 15 for a
good solution).  The total number of MILP solves stays well below 30,
comfortably inside the 600 s limit.

--------------------------------------------------------------------
### 5. Post‑processing (optional continuous polishing)

The binary solution may be slightly sub‑optimal because the true optimum can
use fractional heights.  To tighten the bound we run a short deterministic
projected‑gradient refinement starting from the binary vector:

1. **Lift to continuous** – set `h⁰ = ĥ` (still in `{0,1}`) and keep `T⁰ = T̂`.

2. **Smooth surrogate** – use the log‑sum‑exp envelope  

   ```
   Φ_β(h) = (1/β)·log( Σ_k exp( β·F_k(h) ) )
   ```

   with a modest β (e.g. β = 4).  `Φ_β` is differentiable; its gradient is the
   weighted sum of the per‑shift gradients  

   ```
   ∇F_k = 1 – shift_{+k}(h) – shift_{‑k}(h) .
   ```

   The weights are the normalized exponentials of `β·F_k`.

3. **Projected gradient step** – compute `g = ∇Φ_β(h)`, take a step
   `h ← h – α·g` with a decreasing step size `α` (e.g. α₀ = 0.3, halve every
   200 iterations), then project back onto the feasible set  
   `{0 ≤ h ≤ 1, Σ h = w}` using the simple “shift‑and‑clip” bisection
   (the same routine that appears in the earlier code).

4. **Symmetrisation** – after each projection set `h ← (h + h[::-1])/2` to
   respect the mirror symmetry, then re‑project (the projection automatically
   restores the sum).

5. **Termination** – run for at most 2000 iterations or until the exact
   `C5 = dx·max_k F_k(h)` stops improving.  Because we start from a feasible
   binary point, every iterate remains feasible, and the final `C5` is a
   *strictly* better (or equal) upper bound.

The polishing stage is optional; if the MILP already yields `C5 ≤ 0.3807`
the extra work can be skipped, but in practice the few hundred gradient
steps often shave a few 1e‑4 off the bound.

### 6. Numerical choices and implementation details

| Symbol            | Value / Reasoning                                                          |
|-------------------|----------------------------------------------------------------------------|
| `n`               | 120 (matches the supplied `initial_h_values`; even, so `w = n/2` integer). |
| `dx`              | `2.0 / n`.                                                                  |
| `w`               | `n/2`.                                                                      |
| Symmetry          | Enforced – halves variables.                                                |
| Unimodality       | Linear inequalities `h_{d_j} ≥ h_{d_{j+1}}`.                               |
| Solver            | `cvxpy` with `CBC` (fast open‑source MIP).  Pass `solver_options={'max_iters': 10⁶, 'seconds': remaining_time}` if supported. |
| Initial `K_active`| `{0}` (zero shift) – always tight because `F₀ = w – Σ_i h_i = 0`.            |
| Violation check   | `np.correlate` on the binary vector (O(n²) ≈ 1.4·10⁴ ops).                 |
| Time budget split | ≤ 0.45 · budget for the MILP loop, ≤ 0.15 · budget for gradient polishing. |
| Projection λ‑search| Bisection on `λ∈[-1,1]` with tolerance `1e‑12`; monotone because sum of clipped values is linear in `λ`. |
| Gradient step size| Start `α = 0.3`, decay `α ← 0.9·α` every 500 iterations.                   |
| β schedule (optional) | Start β = 4, optionally increase to 8 after polishing if time allows.   |

All operations are vectorised with NumPy; the MILP model is built once and
augmented incrementally (no re‑creation of the whole problem).  The
correlation used for the violation test is exactly the same as the official
`evaluate_erdos_solution` routine, guaranteeing a consistent bound.

### 7. Failure‑mode analysis & mitigations

| Potential problem                              | Mitigation                                                                                                   |
|-----------------------------------------------|--------------------------------------------------------------------------------------------------------------|
| **Solver exceeds time limit**                  | Use a modest time cap per solve (e.g. 30 s). The solver returns the best incumbent found so far; we keep it. |

| **Binary restriction yields a weak bound**    | After the integer solve we run the continuous polishing stage, which can lift fractional values and improve the bound. |
