### 1.  Problem Re‑formulation – binary (0/1) view  

The integral constraint forces the average height of the step function to be
½, i.e. for a discretisation with *n* points  

```
dx = 2 / n ,     Σ h[i]·dx = 1   ⇒   Σ h[i] = n/2 .
```

If we restrict every sample to the extreme values 0 or 1 the constraint becomes
exactly a **cardinality constraint**  

```
h[i] ∈ {0,1} ,    Σ h[i] = n/2 .
```

For a binary vector the overlap for a discrete lag *ℓ* (ℓ≠0) can be written as  

```
C(ℓ) = Σ_{i=0}^{n-ℓ-1} h[i]·(1 - h[i+ℓ])
     = Aℓ – Sℓ ,
```

where  

* `Aℓ = Σ_{i=0}^{n-ℓ-1} h[i]`  (the number of 1‑entries inside the overlapping
  window) and  
* `Sℓ = Σ_{i=0}^{n-ℓ-1} h[i]·h[i+ℓ]` (the number of coincident 1‑pairs at lag ℓ).

The quantity returned by the judge is  

```
C5 = dx · max_{ℓ≠0} C(ℓ) .
```

Thus **minimising C5 is equivalent to minimising the worst‑case loss
`Aℓ – Sℓ`** over all integer lags.

### 2.  Exact MILP model (the core of the new approach)

All non‑linear products `h[i]·h[i+ℓ]` are linearised by auxiliary binary
variables

```
p[i,ℓ]  =  h[i] ∧ h[i+ℓ]      (ℓ = 1 … n‑1 , i = 0 … n‑ℓ‑1)
```

McCormick (AND) constraints turn the bilinear term into a linear system:

```
p[i,ℓ] ≤ h[i]
p[i,ℓ] ≤ h[i+ℓ]
p[i,ℓ] ≥ h[i] + h[i+ℓ] – 1
```

Define the overlap‑count for each lag

```
Sℓ = Σ_i p[i,ℓ] .
```

Define the “left” and “right” overlapping windows (both are needed because a
positive lag ℓ looks at the left part of the vector, a negative lag looks at
the right part).  With `H = Σ h[i] = n/2`:

```
Aℓ⁺ = Σ_{i=0}^{n‑ℓ‑1} h[i]                (left window)
Aℓ⁻ = H – Σ_{i=0}^{ℓ‑1} h[i]               (right window)
```

Introduce a single scalar variable `M` representing the **raw worst‑case loss**
(in numbers of 1‑entries, i.e. the un‑scaled `maxℓ (Aℓ – Sℓ)`).

For every non‑zero lag ℓ we impose two linear constraints

```
Aℓ⁺ – Sℓ ≤ M
Aℓ⁻ – Sℓ ≤ M .
```

Finally the integral (cardinality) constraint and binary domains:

```
Σ h[i] = n/2
h[i] ∈ {0,1} ,   p[i,ℓ] ∈ {0,1} .
```

**Objective:**   minimise `M`.

All constraints are linear, the model is a *mixed‑integer linear programme*
(MILP).  For the default grid (`n = 42`) the model size is modest:

* 42 binary `h`‑variables,
* Σ_{ℓ=1}^{41} (n‑ℓ) = 861 binary `p`‑variables,
* ≈ 2·41 + 3·861 ≈ 3 000 linear constraints.

--------------------------------------------------------------------
### 3.  Solving the MILP – a bisection on the integer bound  

`M` is an integer (it counts 1‑entries).  Instead of minimising it directly we
run a **binary search** on the feasible values of `M`.  The procedure is:

1. Set `low = 0`, `high = n/2` (worst possible loss is at most half the
   overlapping window, i.e. ≤ 21 for `n=42`).
2. While `high – low > 1`:
   * `mid = (low + high) // 2`.
   * Add the constraints `Aℓ⁺ – Sℓ ≤ mid` and `Aℓ⁻ – Sℓ ≤ mid` for all ℓ.
   * Call a MIP solver (CBC, GLPK_MI, ECOS_BB – any solver available in the
     environment) with a **time limit** equal to the remaining budget.
   * If the solver finds a feasible solution → `high = mid` (we can do better);
     otherwise → `low = mid`.
3. After the loop the smallest feasible integer `M* = high` is known.

The corresponding continuous bound is  

```
C5_MILP = M* · dx .
```

Because the binary search forces the solver to only *prove feasibility*,
the sub‑problems are far easier than the full optimiser: the objective is
removed, the solver stops as soon as any feasible point is found.

### 4.  From a binary feasible point to a *fractional* step function  

The MILP solution is binary, but the original problem permits any values in
`[0,1]`.  A small amount of fractionalisation can reduce the raw loss `M`
by at most a few units, which translates into a noticeable improvement
(`dx ≈ 0.0476` for `n=42`).  The refinement phase is:

1. **Extract** the binary vector `h_bin` from the MILP model.
2. **Scale to a continuous vector** `h₀ = h_bin.astype(float)`.
3. **Define the continuous objective** `f(h) = evaluate_c5(h)` (exactly the
   function used by the judge).
4. **Linear equality for the integral** – keep the average exact:
   `Σ h[i] = n/2`.  In practice we enforce it by a simple renormalisation after
   every trial step or by giving it as an explicit equality to the optimiser.
5. **Bound constraints** – `0 ≤ h[i] ≤ 1`.
6. **Local optimiser** – run `scipy.optimize.minimize` with the
   **SLSQP** method (handles bound + linear equality).  Because the problem is
   non‑convex we perform several *restarts*:
   * start from `h₀` directly,
   * start from `h₀` plus a tiny Gaussian perturbation (σ≈0.02),
   * start from a handful (≈ 5) of random feasible vectors generated by
     randomly swapping a few bits in `h₀` and re‑normalising.
   For each run keep the best value of `f(h)`.
7. **Termination** – stop as soon as the overall time budget (600 s) is about
   to be exhausted (keep a 1‑second safety margin).  The best vector found
   (binary or fractional) is returned.

The polishing step is extremely cheap: each evaluation of `f` is an FFT‑based
correlation (`O(n log n)`), and SLSQP typically needs only a few dozen
iterations for a 42‑dimensional problem.  Hundreds of restarts easily fit
within the remaining time.

--------------------------------------------------------------------
### 5.  Robust fallback – simulated‑annealing / tabu search (if MILP yields
no feasible point in time)

Occasionally the MIP solver may fail to produce any feasible point before the
time limit (e.g. due to missing binary‑capable solver).  In that case we fall
back on a *pure combinatorial heuristic* that works directly on binary
vectors:

1. **Initial population** – generate `P = 10` random binary vectors each with
   exactly `n/2` ones.
2. **Neighbourhood move** – pick a random `1`‑index `i` and a random `0`‑index
   `j` and swap them; this preserves the integral constraint.
3. **Annealing schedule** – start with temperature `T₀ = 0.5`.  After each
   accepted move set `T ← α·T` with `α = 0.9995`.  Continue until `T < 1e‑4`.
4. **Acceptance rule** – compute `Δ = f(new) – f(old)`.  
   *If Δ < 0* → always accept.  
   *Else* accept with probability `exp(‑Δ / T)`.
5. **Best‑ever bookkeeping** – after each iteration compare the current `f`
   to the global best and store the better vector.
6. **Parallel restarts** – when the temperature has annealed, re‑initialise the
   current solution with the best‑ever vector, apply a small random perturbation,
   and start a new annealing run.  Perform as many runs as the remaining budget
   permits.
7. **Polishing** – when the annealing phase stops, feed the best binary vector
   into the same SLSQP polishing described in § 4.

This heuristic explores the *swap‑neighbourhood* of the feasible set and
converges quickly because each move changes only two entries, allowing an
incremental update of the correlation (O(n) instead of O(n²) if desired).

### 6.  Numerical choices and implementation details  

| Item | Choice | Rationale |
|------|--------|-----------|
| Discretisation size | `n = 42` (the size of `initial_h_values`) | Keeps the evaluation identical to the reference implementation, guarantees the integral is an integer (`21` ones). |

| Time allocation | ≤ ½ budget for the MILP (≈ 300 s). The remaining time is used for polishing and, if needed, the fallback heuristic. | Guarantees we never exceed the 600 s limit while still giving the solver sufficient time to find a good feasible point. |
| Correlation evaluation | FFT‑based convolution (`np.fft`) – O(n log n) | Much faster than `np.correlate` for repeated calls during local optimisation. |

| Safety margin | 1 second reserved before returning – prevents premature termination by the outer harness. |
| Symmetry breaking | Force `h[0] = 1` (or `h[0] = 0` consistently) to cut the search space by a factor ≈ 2 without affecting optimality. | Reduces the MILP tree size dramatically. |

### 7.  Anticipated failure modes and mitigations  

| Failure mode | Why it happens | Mitigation |
|--------------|----------------|------------|
| **MIP solver times out without a feasible point** | The binary model may be too hard for the default solver or the time limit is too tight. | Enforce a *hard* time limit per feasibility test, and after the first timeout fall back immediately to the simulated‑annealing heuristic (see § 5). |
| **Too many auxiliary variables (`p[i,ℓ]`) cause memory blow‑up** | For larger `n` the number of `p` grows quadratically. | Keep `n = 42`. If a user chooses a larger `n`, generate `p` only for the *critical* lags (e.g. |ℓ| ≤ 12) because those dominate the bound; add the others later only if needed. |
| **Local optimiser gets stuck in a poor local minimum** | The objective is non‑convex; a single SLSQP run may stop early. | Run many restarts with independent perturbations; keep the best overall. The MILP solution already provides a strong starting point, dramatically reducing the chance of poor minima. |
| **Rounding errors break the integral after polishing** | Numerical noise can drift Σh away from 1. | After each SLSQP iteration (or after the final solution) renormalise `h` by scaling `h ← h / (Σh·dx)`. This preserves feasibility exactly. |
| **Floating‑point overflow/underflow in FFT for very large `n`** | Not an issue for `n ≤ 200`, but for safety we clip the complex result to its real part and round tiny imaginary components to zero. | Use `np.real_if_close` after the inverse FFT. |
| **Random number generator exhaustion** | Extremely unlikely, but reproducibility may be compromised if many restarts are performed. | Use a single `np.random.RandomState(seed)` instance and pass it around; never reseed. |
