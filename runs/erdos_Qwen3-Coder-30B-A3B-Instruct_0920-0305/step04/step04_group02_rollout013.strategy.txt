**Goal** – Find a step‑function `h` on `[0,2]` (discretised with `n` points) that minimizes  

\[
C_5=\max_{k}\int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx
\]

subject to  

* `0 ≤ h[i] ≤ 1` for all `i`  
* `∑_i h[i] * dx = 1`   (where `dx = 2/n`)

The evaluation used in the grader is the discrete correlation  

```
C5 = max( correlate(h , 1‑h , mode='full') ) * dx
```

A good construction is obtained by **(1) solving an exact binary version of the problem with a mixed‑integer linear program (MILP)**, then **(2) refining that binary solution with a continuous local optimiser**.  This two‑stage approach is fundamentally different from the earlier evolutionary‑plus‑SLSQP pipeline and has a clear provable lower bound (the binary optimum) that can be pushed down by fractional adjustments.

### 2. Exact binary formulation (MILP)

#### Variables  
* `x[i] ∈ {0,1}` – the binary step function (`1` ⇔ `h[i]=1`).  
* `t ∈ ℤ₊` – the maximal overlap count we want to minimise.  
* For every shift `d ∈ {‑(n‑1),…,‑1,1,…,n‑1}` and every index `i` for which `i+d` is inside the array, introduce a binary auxiliary variable  

  `w[d,i] ∈ {0,1}`  that will represent the product `x[i] * x[i+d]`.

#### Constraints  

1. **Mass constraint** – exactly half the points are `1`:  

   `∑_i x[i] = n/2`.

2. **Product linearisation (McCormick for binaries)** – for each `w[d,i]`  

   * `w[d,i] ≤ x[i]`  
   * `w[d,i] ≤ x[i+d]`  
   * `w[d,i] ≥ x[i] + x[i+d] – 1`.  

   These three inequalities force `w[d,i] = x[i]·x[i+d]` when `x` are binary.

3. **Definition of overlap for each shift** – the number of `(1,0)` pairs for shift `d` is  

   `N_d = ∑_i x[i] – ∑_i w[d,i]`.  

   Enforce  

   `N_d ≤ t`  for every `d ≠ 0`.

4. **Non‑negativity of `t`** – `t ≥ 0`.

5. **Symmetry breaking (optional, speeds the MILP)** – fix the first entry, e.g. `x[0] = 1`.  Since the problem is shift‑invariant, this does not affect optimality but cuts the search space by a factor of `n`.

#### Objective  

`minimise  t`.

#### Solver strategy  

* Build the model with **CVXPY**.  
* Try a hierarchy of MILP solvers that are usually present:

  1. `CBC` (COIN‑OR branch‑and‑cut).  
  2. `GLPK_MI`.  
  3. `ECOS_BB` (pure interior‑point branch‑and‑bound).  

  Stop at the first solver that returns status *optimal* or *optimal_inaccurate*.  

* If none of the solvers succeed within a short time (≈30 s), fall back to a fast **greedy binary heuristic** (see § 4).  

* The MILP returns a binary vector `x*` and the optimal integer `t*`.  The corresponding raw bound on the continuous problem is  

  `C5_binary = t* * dx`.  

  For `n = 42` the optimal integer is expected to be `t* = 8`, giving `C5_binary ≈ 0.380952`.  This already beats the previous record `0.381054`, but we still need to push under `0.3807`.

### 3. Continuous refinement (local optimisation)

Now allow the entries to become real numbers in `[0,1]` while preserving the total mass.

#### Variables  
`h[i] ∈ [0,1]` (continuous).

#### Constraints  

* Equality: `∑_i h[i] * dx = 1`.  Implemented as `∑ h[i] = n/2`.  
* Box bounds: `0 ≤ h[i] ≤ 1`.

#### Objective  

`C5(h) = max_d  (∑_i h[i] – ∑_i h[i]·h[i+d])`.  
Because the max makes the objective nondifferentiable, we use a **smooth surrogate**:

```
C5_smooth(h) = (1/α) * log( Σ_d exp(α * (∑_i h[i] – ∑_i h[i]·h[i+d])) )
```

with a moderate smoothing parameter `α ≈ 10`.  As `α → ∞` the surrogate converges to the true max, yet for finite `α` it is differentiable and its gradient is easily computed analytically (the gradient of each shift term is `1` minus the two shifted components).  This surrogate works well with gradient‑based optimisers.

#### Optimiser  

* Use **SciPy’s `minimize` with method `SLSQP`** (handles both linear equality and bound constraints).  
* Provide the smooth surrogate as the objective and its analytical gradient (derived from the log‑sum‑exp formula).  
* Initialise the optimiser at the binary solution `h⁰ = x*` (cast to float).  The binary point is feasible (it satisfies the mass constraint), so the optimiser starts from a known good region.

#### Local‑search loop  

1. Run `SLSQP` with a tight tolerance (`ftol=1e‑12`, `maxiter=500`).  
2. If the optimiser converges to a point with `C5 < best`, store it.  
3. Generate **perturbed restarts**: add centred Gaussian noise (`σ ≈ 0.03`) to the current best, clip to `[0,1]`, then **project back onto the mass hyperplane**.  Projection is performed by a simple scaling:  

   `h ← h * ( (n/2) / Σh )`.  
   If clipping changed the sum, re‑scale again – a couple of passes are enough because the dimension is tiny.  
4. Re‑run the SLSQP from each perturbed start.  Keep the best result.  
5. Continue this restart‑refine cycle until the global time budget (≈ 85 % of `budget_s`) is exhausted.

Because the surrogate is smooth, the optimiser can slide the binary step‑function into a fractional shape that reduces the worst shift slightly below the integer bound, often enough to push `C5` under `0.3807`.

### 4. Fast binary fallback heuristic (if MILP stalls)

If the MILP does not finish fast enough, employ a deterministic **swap‑search** that works directly on binary vectors:

1. **Initial binary vector** – random permutation with exactly `n/2` ones.  
2. Compute the full overlap counts `N_d` via correlation (O(n²) ≈ 2 k ops).  
3. While improvement possible:  
   * Identify the shift(s) attaining the current maximum `N_max`.  
   * Enumerate all candidate swaps `(i,j)` with `x[i]=1`, `x[j]=0`.  
   * For each swap compute the new `N_d` only for the two affected shifts (the swap changes at most four overlap terms per shift), update the maximum efficiently.  
   * Perform the swap that yields the largest reduction of `N_max`.  
4. After no improving swap exists, perform a **random restart** (e.g. 200 restarts) and keep the best binary vector found.  
5. The best binary solution from this heuristic is used as the starting point for the continuous refinement stage.

The swap‑search is extremely cheap (a few milliseconds per iteration) and guarantees a binary solution with `t ≤ 9` in practice, enough to meet the target after the subsequent fractional optimisation.
