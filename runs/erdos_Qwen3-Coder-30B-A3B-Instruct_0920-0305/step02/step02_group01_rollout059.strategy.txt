We can propose a DC approach where we rewrite the objective:

```
C5 = max_s [ Σ_i h_i - Σ_i h_i h_{i+s} ] = const - min_s Σ_i h_i h_{i+s}.
```

Define the inner product term as `q_s(h) = Σ_i h_i h_{i+s}`. Using identity `h_i h_{i+s} = 0.5 * [ (h_i + h_{i+s})^2 - h_i^2 - h_{i+s}^2 ]`. Hence

```
q_s(h) = 0.5 * [ Σ_i (h_i + h_{i+s})^2 - Σ_i h_i^2 - Σ_i h_{i+s}^2 ].
```

Now `Σ_i (h_i + h_{i+s})^2` is convex (quadratic with PSD matrix) and `Σ_i h_i^2` is also convex. Their combination yields a **difference of convex** representation: `q_s = convex - convex`. Therefore the max of `-q_s` is a **max of concave functions**? Actually `-q_s` is concave (difference of convex to reverse sign). We can perform a **majorization‑minimization** where at each iteration we linearise the concave part (the negative quadratic) and solve a convex QP.

Specifically, at iteration t we have current `h^t`. For each shift s we compute gradient of `q_s` at `h^t`:

```
∂q_s/∂h_i = h_{i+s} + h_{i-s}  (with appropriate boundary handling)
```

But the max over s of `-q_s` selects the shift s* that gives minimal `q_s`; we can treat it as a piecewise function. The Convex‑Concave Procedure can be applied to the whole objective:

- For each shift s compute `q_s(h^t)`.
- Identify the active shifts (those attaining (or close to) the maximal correlation). You can keep the whole set with weights (softmax) like before, but we can also just take the worst shift s*.
- Then linearise the concave part of `q_s` at `h^t`: `q_s(h) ≈ q_s(h^t) + ∇q_s(h^t)·(h - h^t)`. Substituting into the objective yields a convex quadratic plus linear terms, which is a **quadratic program** (QP) with simple box constraints and an equality sum constraint.
- Solve the QP (using OSQP or cvxopt) to obtain a new `h^{t+1}`.
- Optionally backtrack if objective worsens; repeat until convergence.

This algorithm is different from the previous gradient descent with softmax (which used a smooth approximation). It's a classic DC algorithm (also known as "convex‑concave procedure" or "majorization‑minimization").

Because each iteration solves a QP with `n` variables and a few thousand constraints (if we include all shifts), the cost is moderate for `n ≈ 120`. The QP can be solved quickly with OSQP (an interior‑point or ADMM solver). The algorithm typically converges in tens of iterations.

**Implementation plan:**

1. Choose `n = 120` (dx = 0.016666...). This gives a good trade‑off between discretisation error and QP size.
2. Build a function that, given `h`, computes for every shift `s` the value `q_s(h)` and its gradient `g_s(h)`. Use convolution to compute `q_s` efficiently (`q = correlate(h, h)` gives all autocorrelations) and compute gradient via another convolution (`g = convolve(h, ones) + convolve(ones, h)` depending on shift).
3. At each iteration:
   - Compute the autocorrelation vector `auto = correlate(h, h, mode='full')`. This yields `q_s` (up to scaling by dx).  
   - Identify the shift index `s*` that minimises `auto` (i.e., gives smallest overlap).  
   - Compute the gradient `∇q_{s*}`: for each `i`, `∂q_{s*}/∂h_i = h_{i+s*} + h_{i-s*}` (zero when the shifted index is out of range). This can be obtained by shifting `h` forward and backward and adding.
   - Form the convex surrogate objective  

     ```
     min   Σ_i h_i  –  ( q_{s*}(h^t) + ∇q_{s*}(h^t)·(h - h^t) )
          = const – ∇q_{s*}(h^t)·h .
     ```

     Since `Σ_i h_i` is constant (`n/2`), the problem reduces to a **linear objective** subject to the box and sum constraints. In other words, the DC step collapses to a linear program (LP): minimize `-∇q·h` (or equivalently maximize `∇q·h`) under `0≤h≤1` and `Σ h = n/2`.  
   - Solve this LP (very cheap: just sort the gradient entries and allocate the unit mass to the largest components while respecting bounds – a “capped‑simplex” solution equal to the projection of the gradient onto the feasible set).  
   - The solution of the LP is exactly the projection of the gradient direction onto the feasible region; it can be written in closed form: set `h_i = 1` for indices with the largest gradient values until the sum reaches `n/2`, else set to 0, and possibly a fractional entry for the cut‑off. This yields the optimal `h` for the linear surrogate.
   - Evaluate the true `C5` for the new `h`. If it improves, accept; otherwise keep the previous `h`.
   - Optionally apply a damping factor (e.g., `h_new = α·h_opt + (1-α)·h_old` with `α≈0.7`) to avoid cycling.
4. Iterate until no improvement for, say, 30 consecutive iterations or total time exceeds the allocated budget (≈ 80 % of `budget_s`). Because each iteration is O(n) (thanks to the closed‑form LP solution), we can afford many iterations (several thousand) within the time limit.

**Why this works and why it is materially different**  

- The core optimisation step solves a **linear program on the capped simplex** derived from a **difference‑of‑convex (DC) decomposition** of the quadratic overlap term. This is a classic DC algorithm (Convex‑Concave Procedure), whereas earlier attempts used generic nonlinear solvers (SLSQP) or black‑box evolutionary heuristics (DE).  
- The LP solution can be written analytically, avoiding any generic solver and giving a deterministic, fast update that directly improves the worst‑shift overlap.  
- The algorithm explicitly targets the *worst* shift at each iteration, rather than smoothing over all shifts; this concentrates effort where it matters most.  
- The method works with a modest discretisation (n≈120) and scales linearly per iteration, leaving ample budget for many restarts and final polishing.  
- It can be combined with a final high‑resolution up‑sampling (interpolation + projection) to meet the requirement for smaller `n` if desired, but the essential optimisation machinery remains the DC/LP scheme.
