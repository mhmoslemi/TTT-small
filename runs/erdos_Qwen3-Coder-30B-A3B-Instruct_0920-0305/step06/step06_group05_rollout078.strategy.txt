**Overview**  
We treat the Erdős‑minimum‑overlap problem as a *bilinear maximisation* that can be relaxed to a *semidefinite program* (SDP).  
The SDP gives a provable lower bound on the optimal value and, more importantly, a high‑quality fractional solution that we round to a binary step function.   
After rounding we apply cheap deterministic local swaps and a final continuous polishing.  
All stages are timed so that the whole pipeline finishes within the 600 s budget.  
The method is fundamentally different from the previously used gradient/SLSQP heuristics and from the integer‑linear‑program approach: it works through a convex SDP relaxation and random hyperplane rounding, then refines the result.

--------------------------------------------------------------------
### 1.  Exact discrete formulation

*Discretisation* – choose an even integer `n` (the number of samples).  
The grid step is `dx = 2 / n`.  
Let  

* `h ∈ [0,1]^n` be the vector of sampled values,
* `M = n/2` (the integral constraint `∫_0^2 h = 1` becomes `∑ h_i = M`).

For a non‑negative shift `k` (0 ≤ k ≤ n‑1) define the *autocorrelation term*

\[
A_k(h)=\sum_{i=0}^{n-1-k} h_i\,h_{i+k}.
\]

The overlap at lag `k` is `M – A_k(h)`.  Hence

\[
C_5(h)=dx\;\max_{k\in\{0,\dots ,n-1\}}\bigl(M-A_k(h)\bigr).
\]

Minimising `C_5` is equivalent to **maximising the smallest autocorrelation**
\(\min_k A_k(h)\).

--------------------------------------------------------------------
### 2.  SDP relaxation

Introduce a matrix variable \(X = hh^\top\).  If we could enforce rank‑1,
the constraints would be exact.  Dropping the rank requirement yields a convex set.

*Variables*  

* `h ∈ ℝ^n` (continuous),
* `X ∈ ℝ^{n×n}` symmetric positive semidefinite (`X ≽ 0`),
* scalar `t ≥ 0` (epigraph variable for the worst overlap).

*Linear constraints*  

1. **Mass** – `1ᵀ h = M`.  
2. **Box** – `0 ≤ h ≤ 1`.  
3. **Diagonal coupling** – `diag(X) = h` (since `X_{ii}=h_i^2 = h_i` for binary `h`).  
4. **Lag constraints** – for each shift `k = 0,…,n‑1` define a matrix `P_k` having a 1 at `(i,i+k)` whenever both indices lie in `[0,n)`.  Then  

   \[
   t \;\ge\; M - \operatorname{Tr}(P_k X)
   \qquad\forall k .
   \]

The objective is `minimise t`.  All constraints are linear (or PSD), so the model is a **semidefinite program**.

The SDP value `t*` satisfies `t* ≤` the optimal `t` of the original binary problem, thus providing a rigorous lower bound on `C₅` (after scaling by `dx`).  More importantly, the optimiser returns a feasible pair \((h^{\text{rel}},X^{\text{rel}})\) that we will round.

--------------------------------------------------------------------
### 3.  Solving the SDP

*Solver* – use **cvxpy** with the open‑source **SCS** backend (`solver=cp.SCS`).  
SCS handles moderate‑size PSD cones quickly and accepts a time‑limit.

*Problem size* – for `n = 80` we have a 80×80 matrix (`≈ 3 200` unknowns) and 81 lag constraints.  Even `n = 120` (7 260 unknowns, 121 constraints) solves in < 30 s on a single CPU.

*Time allocation* – reserve **≈ 50 %** of the total budget for the SDP stage.
We will try successively larger `n` values while time permits:

```
n = 60 → 80 → 100 → (if time left) 120
```

Before each solve we compute the remaining wall‑clock time and pass it to SCS through the option `max_iters`/`eps` or the solver‑specific `seconds` parameter.  If the solver stops early, we still keep the feasible point it produced.

--------------------------------------------------------------------
### 4.  Rounding the fractional SDP solution

The SDP solution gives us `h_rel` (real numbers in `[0,1]`) and a PSD matrix `X_rel`.  
We extract a low‑dimensional factorisation of `X_rel`:

1. Compute an eigendecomposition `X_rel = V Λ Vᵀ`.  
2. Keep the eigenvectors corresponding to positive eigenvalues, forming `V₊ ∈ ℝ^{n×r}` (usually `r ≤ 10`).  

Now we perform **random hyperplane rounding**, a standard technique for Boolean quadratic programs:

*For each rounding trial (we will run 15–30 trials per SDP instance)*  

*   Draw a Gaussian vector `g ∈ ℝ^r` (`g ~ N(0,I)`).
*   Compute scores `s = V₊ g`.  The signs of `s` define a binary vector  
    `b_i = 1` if `s_i ≥ 0`, else `0`.
*   The weight of `b` is usually not exactly `M`.  Repair it by
    *if `∑ b > M`* flip a random subset of `∑b - M` ones to zero;  
    *if `∑ b < M`* flip a random subset of `M - ∑b` zeros to one.

A cheaper deterministic alternative is **threshold rounding** of `h_rel`:
set the `M` largest entries to 1, the rest to 0.  We apply both methods,

--------------------------------------------------------------------
### 5.  Fast evaluation of a candidate

For any binary (or floating) vector `h_candidate` we need its `C₅` value quickly.

*FFT‑based correlation* – zero‑pad `h_candidate` to length `2n‑1`, compute its FFT, multiply point‑wise with the FFT of its complement `1‑h_candidate`, inverse‑FFT, and take the real part.  
The result `corr` contains the values `∑ h_i (1‑h_{i+k})` for all lags `k`.  
`C₅ = dx * max(corr)`.  

The FFT of length ≤ 2·120 = 240 costs < 0.2 ms, so we can evaluate thousands of candidates without noticeable overhead.

--------------------------------------------------------------------
### 6.  Deterministic local improvement (swap‑hill‑climbing)

Each rounded binary vector is further refined by an exhaustive **swap search**:

```
repeat
    improved = False
    for each (i in Ones, j in Zeros):
        swap i ↔ j
        compute new C5 (using incremental update: only lags where i or j participates change)
        if new C5 < current best:
            keep swap, improved = True, break both loops
until not improved
```

Because each successful swap strictly reduces `C₅`, the loop terminates after at most O(M·(n‑M)) successful moves; in practice only a few dozen swaps are needed.  The incremental update avoids recomputing the full FFT for every trial: for a given lag `k` the term involving indices `i` and `j` changes by `±h_j` or `±h_i`, and we keep a running array of `A_k` values to compute the new maximum quickly.

The hill‑climbing stage is **deterministic** and fast (≤ 0.1 s per candidate).

### 7.  Final continuous polishing (optional SLSQP)

1. Use `h_bin` as the starting point `x₀ ∈ [0,1]^n`.
2. Run `scipy.optimize.minimize` with method **SLSQP**,
   * bounds `[0,1]`,

3. Provide the analytical sub‑gradient for the worst lag only:
   for the lag `k*` attaining the current maximum,  

   \[
   \frac{\partial C_5}{\partial x_j}

5. After termination, project back onto the simplex (if numerical drift) using the same `project_to_sum_box` routine.

Because the start point is already near a local minimum, this polishing typically reduces `C₅` by a few‑\(10^{-5}\) – a non‑trivial improvement that never harms the bound.
