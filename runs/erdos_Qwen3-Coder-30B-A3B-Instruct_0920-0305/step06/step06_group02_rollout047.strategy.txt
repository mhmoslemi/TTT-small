**1. Problem reformulation – binary “max‑min overlap” view**  

The integral to be minimised can be written as  

\[
C_5=\max_{k}\int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx
        =\frac{1}{2}-\min_{k}\int_0^2 h(x)\,h(x+k)\,dx .
\]

Because the integrand is linear in each factor, an extremal solution may be taken to be an **indicator function** of a measurable set.  After discretisation with an even number of points `n` (step size `dx=2/n`) we may therefore restrict ourselves to **binary vectors**

\[
h_i\in\{0,1\},\qquad i=0,\dots ,n-1,
\]

with the exact weight constraint  

\[
\sum_{i=0}^{n-1}h_i = \frac{n}{2}.
\]

Define for every integer shift `s∈{-(n‑1),…,(n‑1)}` the *overlap count*

\[
O_s(h)=\sum_{i=0}^{n-1} h_i\,h_{i+s},
\]

where out‑of‑range indices are treated as zero (zero‑padding).  
Then  

\[
C_5 = dx\;\Bigl(\frac{n}{2} - \min_s O_s(h)\Bigr).
\]

Hence the optimisation problem is **purely combinatorial**:

```
maximise   𝜇 =   min_s O_s(h)
subject to  h_i ∈ {0,1},
            Σ h_i = n/2 .
```

The target bound `C_5 ≤ 0.3807` corresponds (for `dx=2/n`) to a required
minimum overlap  

\[
\mu_{\text{target}} = \frac{n}{2} - \frac{0.3807}{dx}
                     = \frac{n}{2} - 0.3807\frac{n}{2}
                     = 0.6193\;\frac{n}{2}.
\]

For `n=120` this means `μ ≥ 37.2` (i.e. at least 38 overlapping 1‑positions for every shift).

**2. Core data structures for O(1 – O(w)) updates**  

* `x` – a `numpy.int8` array length `n` storing the current binary pattern.  
* `ones` – a Python list (or NumPy array) of the indices where `x[i]==1`.  
* `zeros` – the complementary list of indices where `x[i]==0`.  
* `ov` – a NumPy integer array of length `L=2n‑1` holding the *full* overlap counts:
  `ov[s + n‑1] = O_s(x)`.  It can be obtained once by `np.correlate(x, x, "full")`.

`ov` is the only expensive object; all other structures are tiny.  The crucial
observation is that swapping a `1` at position `i` with a `0` at position `j`
modifies `ov` **exactly** by adding/subtracting the contributions of the two
positions with respect to every other `1`.  Since the number of `1`s is
`w = n/2`, a swap can be applied in `O(w)` integer operations:

* **Removal of `i`** – for each `k ∈ ones` subtract `1` from `ov[k‑i]` and, if `k≠i`,
  also from `ov[i‑k]`.  
* **Insertion of `j`** – for each `k ∈ (ones \ {i})` add `1` to `ov[k‑j]` and,
  if `k≠j`, also to `ov[j‑k]`.  
* Add the self‑pair contribution `+1` at shift `0` for the new `1` at `j`.

All indices are shifted by `offset = n‑1` to map negative shifts into the array.

Because `w ≈ 60` for `n=120`, a single swap costs only a few hundred integer
operations – far cheaper than recomputing the full correlation via FFT.

**3. Global optimiser – Simulated Annealing on the binary space**  

The objective to maximise is `μ = min_s O_s = ov.min()`.  Simulated Annealing
(SA) is chosen because:

* It works directly on the binary domain, always respecting the exact sum
  constraint (swaps preserve the weight).
* The fast O(w) neighbourhood evaluation allows **millions** of proposals
  within the 600 s budget.
* A temperature schedule gives a principled way to escape local plateaus.

**3.1. Initialisation**

*Option A – “rounded best”.*  
Take the best continuous vector found by the previous gradient method,
threshold it at `0.5` to obtain a binary vector, then adjust the weight to
exactly `n/2` by flipping the smallest‑magnitude entries (or by a short random
swap routine).  
*Option B – pure random.*  
Draw `n/2` distinct indices uniformly and set them to `1`.

Both initialisations are cheap; the algorithm will run many independent SA
episodes, so we can afford a mixture.

**3.2. Temperature schedule**

Let `max_iter` be the planned number of accepted proposals for a single SA run
(e.g. `max_iter = 5·10⁴`).  Define

```
T0      = 0.5                     # magnitude comparable to typical Δμ (≈1)
Tf      = 1e‑4
λ       = -log(Tf/T0) / max_iter   # exponential decay factor
T(iter) = T0 * exp(-λ * iter)
```

The acceptance probability for a non‑improving move with change `Δ = μnew‑μcur`
(Δ ≤ 0) is `exp(Δ / T)`.  Because `Δ` is integer (overlap counts differ by at most a
few units), the temperature can be kept in the integer domain; however using a
float `T` is straightforward.

**3.3. Proposal generation**

*Pick a random `1`‑position `i` from `ones` and a random `0`‑position `j` from
`zeros`.  The move is the swap `i↔j`.  The pair is drawn uniformly; this gives
full connectivity of the state graph.*

**3.4. Incremental evaluation**

*Copy* the current overlap array `ov` to a temporary buffer `ov_new`.  
Execute the O(w) removal/insertion steps described in §2.  
Compute `μnew = ov_new.min()`.  
The cost of this step is negligible compared with the overhead of Python
looping, so we keep the innermost loop in pure Python but use local variables
and avoid repeated attribute lookups.

**3.5. Acceptance & bookkeeping**

* If `μnew > μcur` → **accept** unconditionally.
* Else accept with probability `exp((μnew‑μcur)/T)`.  
  A uniform random number `u∈[0,1)` decides.
* On acceptance:
  * replace `x[i]←0`, `x[j]←1`;
  * update the two index lists (`ones`, `zeros`);
  * replace `ov←ov_new`;
  * set `μcur←μnew`.
* Keep a record of the *best* (`μbest`, `xbest`) encountered in the whole run,
  even if later moves worsen the current state.

**3.6. Termination of a single SA run**

Stop when either

* `iter` reaches `max_iter`, **or**
* the wall‑clock time allocated for the current run (e.g. `budget_s * 0.4`) is
  exhausted.

**3.7. Multiple restarts**

Within the total time budget we launch several SA episodes:

```
while time_left:
    x0 = initialisation()
    ov0 = full_correlation(x0)          # O(n log n), cheap
    x_best, μ_best = simulated_annealing(x0, ov0, remaining_time)
    if μ_best > global_best_μ:
        global_best ← (x_best, μ_best)
```

Because each episode is cheap, we can afford 10‑20 restarts, each with a
different random seed (or a slight random perturbation of the current global
best).  This diversity dramatically reduces the chance of being trapped in the
same basin.

**4. Deterministic “worst‑shift repair” after SA**  

When SA stops, the bottleneck is usually a *single* shift `s*` where the overlap
is minimal.  A **targeted repair** can often raise `μ` by a few units without
hurting any other shift.

* Compute `s* = argmin_s ov[s]`.
* Identify **deficient 1‑positions**  

  \[
  A = \{\,i \mid x_i=1,\; i+s*<n,\; x_{i+s*}=0\,\}.
  \]

  (These are 1‑entries that fail to pair with a partner at distance `s*`.)

* Identify **helpful 0‑positions**  

  \[
  B = \{\,j \mid x_j=0,\; j+s*<n,\; x_{j+s*}=1\,\}.
  \]

* For each pair `(i∈A, j∈B)` compute the *local* effect on the full overlap
  array (again using the O(w) update routine).  Accept the first swap that

  1. raises `ov[s*]` (i.e. `μnew > μcur`), and
  2. does **not** create a new shift whose overlap falls **below** the current
     `μcur` (i.e. `ov_new.min() ≥ μcur`).

* Apply the swap, update `x`, `ones`, `zeros`, `ov`, and repeat from the new
  worst shift.  Stop when no improving pair exists.

Because the sets `A` and `B` are typically small (a few dozen elements), this
repair stage finishes in milliseconds and often yields `μ` that is several units
higher than the SA optimum, translating into a noticeable reduction of `C_5`.

**5. Optional fine‑graining on a larger discretisation**  

If after the repair stage the bound is still marginally above the target,
*scale up* the pattern:

1. Choose a finer grid `n' = 2·n` (or any even larger value, still well below 1000).
2. Upsample the binary solution by simple repetition: each original cell is
   replaced by `n'/n` consecutive copies of its value (nearest‑neighbour
   expansion).  This guarantees the weight is exactly `n'/2`.
3. Run a **short SA** on the enlarged vector (same O(w) update logic; now
   `w = n'/2`).  Because the up‑sampled pattern already has good autocorrelation,
   only a few thousand swaps are typically needed to improve the worst‑shift
   overlap on the finer scale.
4. If the refined pattern beats the target, return it; otherwise fall back to
   the best pattern found on the original grid.

The up‑sampling step is essentially a deterministic “interpolation” that
preserves the macro‑structure while allowing micro‑adjustments.
