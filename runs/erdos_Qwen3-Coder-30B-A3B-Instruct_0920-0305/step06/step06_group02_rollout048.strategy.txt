### 1. Mathematical Formulation

#### 1.1 Discretisation
* Choose an **even** number of points \(n\) (default 120).  
* Step size \(dx = 2 / n\).  
* Desired total mass: \(\sum_{i=0}^{n-1} x_i = n/2\).

#### 1.2 Overlap for a shift
For a binary vector \(x\):
\[
O_s(x) = \sum_{i=0}^{n-1} x_i \, x_{i+s},
\qquad s\in\{-(n-1),\dots ,n-1\},
\]
where out‑of‑range indices are taken as 0 (zero‑padding).  
Define \(w=n/2\). The Erdős bound becomes
\[
C_5 = dx\;\bigl(w - \min_{s} O_s(x)\bigr).
\]
Thus **maximising** \(\displaystyle \theta = \min_{s} O_s(x)\) is equivalent to **minimising** \(C_5\).

#### 1.3 Linear integer model (McCormick linearisation)

Introduce binary decision variables:
* \(x_i\in\{0,1\}\) – indicator at position \(i\).
* For each shift \(s\ge 0\) and each index \(i\) with \(i+s<n\), introduce auxiliary binary variable  
  \(y_{i,s}\in\{0,1\}\) intended to represent the product \(x_i x_{i+s}\).

McCormick constraints (exact for binary variables):
```
y_{i,s} ≤ x_i
y_{i,s} ≤ x_{i+s}
y_{i,s} ≥ x_i + x_{i+s} - 1
y_{i,s} ≥ 0
```
For the symmetric negative shifts we need not create extra variables; the overlap for shift −s equals the overlap for +s, so we enforce the same lower bound on both.

Define the overlap for shift s:
\[
O_s = \sum_{i=0}^{n-1-s} y_{i,s}.
\]

Introduce a scalar integer variable \(\theta\) (the minimum overlap) and enforce:
\[
O_s \ge \theta\quad \forall s \in \{0,\dots ,n-1\}.
\]

**Objective:** maximise \(\theta\).

**Constraints:**
```
∑ x_i = w
x_i ∈ {0,1}
y_{i,s} ∈ {0,1}
McCormick constraints for each (i,s)
O_s ≥ θ   (linear in y's)
```

The model is purely linear; any MILP solver (CBC, GLPK, SCIP, ECOS‑B, etc.) can handle it. For \(n≈80\) the number of binary variables is
\[
|x| = n,\;|y| = \sum_{s=0}^{n-1} (n-s) = n(n+1)/2,
\]
≈ 3 200 for \(n=80\). This size is comfortably solvable within a few seconds on a single CPU.

### 4. Stage C – Fast Binary Local Optimisation

#### 4.1 Data structures (persistent throughout Stage C)

| Structure | Type | Purpose |
|-----------|------|---------|
| `x` | `np.ndarray` (dtype int8) | Current binary pattern. |
| `ones` | Python `list` of indices | Positions where `x_i = 1`. |
| `zeros` | Python `list` of indices | Positions where `x_i = 0`. |
| `ov` | `np.ndarray` (dtype int32) length `2n-1` | Full overlap array `O_s`.  Index `s + n-1` maps a shift `s`. |
| `theta_cur` | `int` | Current minimum overlap `min(ov)`. |
| `c5_cur` | `float` | Current bound `dx*(w-theta_cur)`. |

The overlap array is initially computed **once** using a full convolution:
`ov = np.correlate(x, x, mode='full')`.  
Because `x` is binary, `ov` consists of non‑negative integers and can be updated by simple integer arithmetic.

#### 4.2 Incremental update for a 1↔0 swap

When swapping a 1 at index `i` with a 0 at index `j`:

1. **Remove contributions of `i`.**  
   For each `k` in `ones` (including `i`):
   * `shift = k - i`; `idx = shift + n - 1`.  
   * Decrement `ov[idx]` by 1.  
   * If `k != i`, also decrement `ov[-shift + n - 1]` (the opposite ordered pair).  

2. **Temporarily update the index sets** (`ones_tmp = ones` without `i`, `zeros_tmp = zeros` without `j`).  

3. **Add contributions of the new 1 at `j`.**  
   For each `k` in `ones_tmp`:
   * `shift = k - j`; `idx = shift + n - 1`.  
   * Increment `ov[idx]` by 1.  
   * If `k != j`, also increment `ov[-shift + n - 1]`.  
   * Finally, increment the self‑pair at shift 0: `ov[n-1] += 1`.  

4. **Update `theta_cur`** by recomputing `ov.min()` (O(`2n`) ≈ 240 operations).  
5. **Update `c5_cur = dx * (w - theta_cur)`.**  

All loops involve at most `w = n/2` iterations (≈ 60 for `n=120`), so each candidate evaluation costs only a few hundred integer operations – orders of magnitude faster than a full FFT.

A **copy** of `ov` is made before the swap (`ov_copy = ov.copy()`). If the move is rejected, revert by restoring `ov = ov_copy` and swapping the indices back in `x`, `ones`, `zeros`.

#### 4.4 Deterministic worst‑shift repair (post‑SA)

After SA finishes (or after a fixed time slice), the worst shift `s* = argmin ov` is known. We now perform a *targeted* improvement:

```

```
