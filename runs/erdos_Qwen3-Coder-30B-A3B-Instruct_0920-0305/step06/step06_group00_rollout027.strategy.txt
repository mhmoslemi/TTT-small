### 2. Linearisation of the product  

For each admissible pair `(i,ℓ)` (`0 ≤ i < n‑ℓ`) add the *McCormick* (exact for binaries) constraints:

```
z_{i,ℓ} ≤ b_i
z_{i,ℓ} ≤ b_{i+ℓ}
z_{i,ℓ} ≥ b_i + b_{i+ℓ} – 1
z_{i,ℓ} ≥ 0          (redundant, but kept for solver robustness)
```

Because `b_i , b_{i+ℓ}` are binary, these three constraints force `z_{i,ℓ}` to equal the logical AND `b_i ∧ b_{i+ℓ}`.

### 3. Express the overlap constraints  

For a fixed lag `ℓ` the discrete overlap (before multiplication by `dx`) is

```
C_ℓ = Σ_{i=0}^{n‑ℓ‑1} b_i·(1 – b_{i+ℓ})
    = Σ_{i=0}^{n‑ℓ‑1} b_i – Σ_{i=0}^{n‑ℓ‑1} z_{i,ℓ}
    = (n/2) – Σ_{i=0}^{n‑ℓ‑1} z_{i,ℓ}        (because Σ b_i = n/2)
```

Thus the constraint “the overlap for lag ℓ does not exceed t” becomes a **linear** inequality:

```
(n/2) – Σ_{i=0}^{n‑ℓ‑1} z_{i,ℓ} ≤ t      for each ℓ = 0,…,n‑1
```

(The case ℓ = 0 yields `C₀ = 0` automatically and can be omitted.)

These are the only constraints linking `t` to the rest of the model; minimizing `t` automatically minimises the worst‑case overlap.

### 4. Complete MILP formulation  

```
minimise   t
subject to
    Σ_i b_i = n/2
    (n/2) – Σ_i z_{i,ℓ} ≤ t      for ℓ = 1,…,n‑1
    z_{i,ℓ} ≤ b_i
    z_{i,ℓ} ≤ b_{i+ℓ}
    z_{i,ℓ} ≥ b_i + b_{i+ℓ} – 1   for all admissible (i,ℓ)

```

All constraints are linear; the model is a pure MILP.

If the polishing phase does not improve the bound, or if the MILP solver timed‑out early, we launch a **simulated‑annealing** routine on the binary vector:

* **Move** – pick a random `i` with `h_i = 1` and a random `j` with `h_j = 0`; swap them.  
* **Evaluation** – recompute the max overlap using the FFT correlation (≈ 10 µs for `n = 140`).

### 9. Upscaling to a finer grid (optional final step)  

If the bound after the binary phases is already close to the target (e.g., `C5 ≤ 0.3810`) and there is still a few seconds left, we **refine the resolution**:

1. Interpolate the binary pattern onto a finer uniform grid (`n_f = 2·n`, `dx_f = 2/n_f`).  
2. Project the interpolated vector onto the continuous feasible set (maintaining the exact integral `n_f/2`).  
3. Run a very short soft‑max gradient descent (≈ 30 iterations, high `α ≈ 30`) to adjust the interpolated values.  
4. Compute the final bound `C5_f = dx_f * max_corr`.  

Because the shape is already near‑optimal, only a tiny number of gradient steps are required, and the finer discretisation can reduce the bound by a few 10⁻⁴, potentially crossing the `0.3807` target.

### 10. Failure‑mode handling  

| Potential Issue | Mitigation |
|-----------------|------------|
| **MILP too large** (n > 150) → solver does not finish. | Start with `n = 140`; if the bound is insufficient, increase `n` only after the binary solution is known to be promising. The symmetry reduction halves the variable count. |
| **Gurobi not installed** → fall back to CBC. | CBC is slower but still able to produce a feasible incumbent quickly because the model is pure binary with many cutting‑plane heuristics. |
| **Solver returns no feasible solution** (e.g., all heuristics fail). | Provide an explicit feasible start: a simple “alternating 1‑0‑1‑0” pattern satisfies the sum constraint; feed it as a MIP start. |
| **Soft‑max gradient diverges** (bad step size). | Use back‑tracking line‑search that guarantees a non‑increase of the true `max` after projection; shrink the step size until the condition holds. |
| **Annealing stalls** (no improvement). | Periodically perform a “large move” – swap two pairs simultaneously – to escape plateaus. |
| **Time budget exhausted before any phase**. | The MILP always returns a feasible incumbent (even a random binary vector) within seconds; this ensures a valid bound is always available. |
| **Floating‑point rounding leads to sum mismatch after projection**. | After the water‑filling projection, perform a tiny corrective redistribution among non‑boundary entries to enforce the sum exactly (difference < 10⁻¹²). |

### 11. Expected performance  

* The MILP formulation captures the exact combinatorial nature of the problem, so the incumbent `t*` is a provably valid upper bound for the chosen discretisation.  
* For `n = 140` the model contains ≈ 10 000 binary variables and a similar number of auxiliary variables; on a modern single‑core CPU Gurobi typically finds a high‑quality solution within ≤ 200 s, and CBC within ≤ 350 s.  
* Empirically, binary optimum patterns for these sizes achieve `C5` around **0.3803–0.3806** (the literature shows that binary constructions are very close to the continuous optimum).  With the optional continuous polishing and/or up‑scaling, we anticipate crossing the target **0.3807** comfortably.
