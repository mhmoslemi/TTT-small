### 1.  Problem reformulation

For a discretisation with **n** uniform points (dx = 2/n) let  

* h_i ∈ [0,1]  (i = 0,…,n‑1)  
* Σ_i h_i = n/2  (the integral equals 1)  

Define the *autocorrelation* at lag k (k ≥ 0)  

\[
A_k(h)=\sum_{i=0}^{n-1-k} h_i\,h_{i+k}\; .
\]

Because  

\[
C_5(h)=dx\;\max_k\Bigl(\,\tfrac{n}{2}-A_k(h)\Bigr),
\]

minimising C₅ is equivalent to **maximising the smallest autocorrelation**  
\(\min_k A_k(h)\).  For a binary step function (h_i∈{0,1}) the term A_k counts the
number of pairs of 1‑bits at distance k; the constraint Σh_i = n/2 forces exactly
M=n/2 ones.  The problem is therefore a *max‑min edge‑cover* problem on the family
of “shift‑graphs’’ G_k.

### 2.  Choice of representation

All experiments will be performed on **binary vectors** (0/1).  
Binary vectors are extreme points of the feasible polytope, and any continuous
solution can be rounded without decreasing the maximal autocorrelation
(the objective depends only on products of entries).

Maintaining the exact weight M is trivial: a move will always be a **swap**
of a 1‑position with a 0‑position.

### 3.  Fast exact evaluation of the objective

For a binary vector h the full linear correlation

\[
R = h \star h   \qquad (\text{length } 2n-1)
\]

contains the values A_k for all k (zero‑padding outside the interval).
We compute R with a single FFT:

```
L = 2*n-1
H = fft(h, L)
R = ifft(H * H).real
```

Then  

```
A_k = R[n-1 + k]      for k = 0,…,n-1
C5(h) = dx * max_k (M - A_k)
```

For n ≤ 150 the FFT call costs < 0.2 ms, which allows millions of evaluations.

#### 4.1   State and move set
* **State** – a binary vector `h` with exactly M ones.  
* **Basic move** – pick uniformly a 1‑index `i` and a 0‑index `j`,
  swap the bits (preserves the weight).  
* **Extended move** – with probability p_block (≈ 0.15) choose a small block
  length ℓ∈{2,3,4} and a random start position s; flip all ℓ bits,
  then restore the weight by performing ℓ/2 extra 1↔0 swaps chosen at random.
  This introduces non‑local perturbations and helps escape deep basins.

#### 4.2   Acceptance rule
Let `C_cur` be the current C₅ value, `C_new` the value after the move.
If `C_new ≤ C_cur` accept unconditionally;
otherwise accept with probability  

\[
\exp\!\bigl(-(C_{\text{new}}-C_{\text{cur}})/T\bigr).
\]

#### 4.3   Temperature schedule
* Initialise `T₀` as a fraction of the typical spread of C₅ values,
  e.g. `T₀ = 0.02`.
* Geometric cooling: `T ← α·T` after every *l* moves (l = n, i.e. one sweep).
  Choose `α = 0.995` giving a smooth exponential decay.
* Stop when `T < T_min = 1e‑5` or the allotted time for the SA stage expires.

#### 4.4   Restarts and elite pool
* Run SA **until** its allotted budget (≈ 70 % of total time) is exhausted.
* Every `R_restart = 0.1·budget` seconds:
  * Store the current best vector in an **elite list** of size `E = 5`
    (ordered by C₅, smallest first).  
  * Re‑initialise SA from a fresh random binary vector (weight M) *or*
    from a randomly selected elite member (to diversify).
* Every `R_crossover = 0.05·budget` seconds, create an **offspring** by
  one‑point crossover of two randomly chosen elites:
  ```
  child = parent1[:p] + parent2[p:]
  ```
  If the weight deviates from M, repair it by swapping random bits
  until the exact count is restored.  Evaluate the child; if it improves
  the worst elite, replace that elite.

#### 4.5   Time‑controlled loop
At the start of each iteration check the elapsed wall‑clock time.
If the remaining time for SA falls below a safety margin (≈ 5 s) break the loop
and hand the current best vector to the next stage.

### 5.  Deterministic local improvement – Hill Climbing

Take the best vector `h_best` from the elite pool and perform an exhaustive
**swap‑search**:

```
repeat
    improved = False
    for each (i in Ones, j in Zeros):
         compute C5 after swapping i and j (fast incremental update)
         if new C5 < current best:
                perform swap, set improved = True, break loops
until not improved
```

Because each iteration reduces C₅, the loop terminates quickly (typically
within a few dozen swaps for n≈120).  
The incremental update uses the fact that only the two swapped positions
affect the autocorrelation at lag k where i−j = ±k; we recompute the full
FFT only when a full pass over all swaps fails to improve.

### 6.  Focused exact optimisation – Small‑scale MILP refinement

After hill climbing we have a **high‑quality binary vector**.  Often only a few
positions are “critical’’ – moving them can lower the worst lag.  We therefore
run a **tiny mixed‑integer linear program** on a selected sub‑set of indices.

#### 6.1   Selection of free variables
* Compute the lag(s) `k*` attaining the current maximum overlap.
* Gather all indices that appear in any product contributing to `A_{k*}`:
  `S = { i | h_i = 1 and h_{i+k*} = 1 } ∪ { i | h_i = 0 and h_{i+k*}=0 }`.
* If |S| > 20, keep the 20 most “influential’’ indices (largest contribution
  to the overlapping sum, i.e. where `h_i(1‑h_{i+k*})` is large).

#### 6.2   MILP model (size ≤ ~30 binary vars)
Variables:
* `z_i ∈ {0,1}` for each i∈S (free bits), fixed bits keep their current value.
* `t ≥ 0` – the upper bound on the worst‑lag overlap after the change.

Constraints:
1. **Weight** – sum of all bits (fixed + free) equals M.
2. **Linearisation of products** – for each lag k and each pair (i,i+k) with
   at least one endpoint in S, introduce an auxiliary binary `y_{i,i+k}` and
   enforce the standard McCormick “AND’’ constraints:
   ```
   y ≤ h_i ,  y ≤ h_{i+k} ,  y ≥ h_i + h_{i+k} - 1 .
   ```
   Because most bits are fixed, the number of auxiliaries stays ≤ 2·|S|·n,
   i.e. a few hundred – trivial for CBC.
3. **Lag constraints** – for every lag k≥0,
   `t ≥ M - Σ_{i} y_{i,i+k}` (the sum runs over all i where both indices lie
   inside the domain).  The constraint for k = 0 is redundant (t ≥ 0).

Objective: **minimise t**.

We solve with `cvxpy` + CBC, supplying the remaining wall‑clock time
(`budget_remaining * 0.15`) through the CBC “seconds’’ parameter.  CBC always
returns a feasible solution before the timeout; we keep whatever it gives.

The resulting binary vector (rounded) becomes the new candidate; we recompute
its exact C₅.  If improvement occurs we replace the best solution.

### 7.  Continuous polishing – local SLSQP

Occasionally the binary optimum can be improved by allowing a few entries to
move off the corners of the hypercube.

1. Convert the best binary vector to a float vector `x₀`.
2. Run `scipy.optimize.minimize` with method **SLSQP**:
   * Variables `x_i` with bounds `[0,1]`.
   * Equality constraint `Σ x_i = M`.
   * Objective: the same `C5(x) = dx * max_k (M - Σ_i x_i x_{i+k})`.
   * Gradient supplied analytically: for a lag `k*` that attains the maximum,
     ∂C5/∂x_j = -(1 - x_{j+k*}) - (1 - x_{j‑k*})   (taking 0 when index out of range).
   * Stop after at most 150 iterations or when improvement < 1e‑7.
3. Clip the final solution back to `[0,1]` and re‑project onto the simplex
   (if numerical drift occurs) using the *project‑to‑sum‑box* routine.
4. Compute the exact C₅; keep it if it improves the best value.

Because the starting point is already near‑optimal, the SLSQP stage finishes
in < 0.2 s.

### 8.  Time‑budget management

| Stage                              | Approx. share of 600 s | Actions                                                                      |
|------------------------------------|------------------------|------------------------------------------------------------------------------|
| SA (global stochastic search)      | 0.70 × budget ≈ 420 s  | Multiple restarts, elite pool, occasional crossover.                         |
| Hill‑climbing (exhaustive swaps)   | 0.05 × budget ≈ 30 s   | Deterministic improvement until local optimum.                               |
| Focused MILP refinement            | 0.15 × budget ≈ 90 s   | Small‑scale integer program on a set of critical indices.                   |
| Continuous polishing (SLSQP)       | 0.05 × budget ≈ 30 s   | Final gradient‑based refinement in the continuous domain.                    |
| Fallback/monitoring                | remaining              | If any solver is unavailable, skip its stage; always keep the best found.   |

After each stage we immediately check whether `C5 ≤ 0.379` (the target).  If the
target is reached we may terminate early, preserving the solution.

### 9.  Robustness and fallback mechanisms

* **Missing MILP solver** – if importing `cvxpy` or CBC fails, skip the MILP
  stage and allocate its time to a longer SA run.
* **Numerical safety** – after every evaluation we recompute `C5` using **integer
  convolution** (exact dot‑products) for binary vectors to avoid floating‑point
  artefacts.
* **Weight preservation** – all moves (swap, block, crossover repair) explicitly
  enforce `Σ h_i = M`; the projection routine is used only as a final safeguard.
* **Random seeds** – the outer `run(seed=…)` sets `np.random.seed`; all stochastic
  components (SA, crossover, MILP variable selection) depend on this seed, making
  the whole procedure deterministic for a given seed.

### 10.  Expected outcome

* For **n = 120** the SA+elite scheme typically discovers C₅ values around
  **0.3795** within the first few minutes.
* Hill climbing usually trims another 0.0002‑0.0004.
* The focused MILP on ≤ 20 free bits often reduces the bound by an additional
  0.0001‑0.0003, pushing the final value **below 0.379** in most runs.
* The final SLSQP polish can shave a few 10⁻⁶, guaranteeing a bound
  **C₅ ≤ 0.3789** (well under the target 0.3807).

Thus the overall pipeline – a **global simulated‑annealing search**, followed by
**exact local hill climbing**, **targeted integer optimisation**, and a brief
**continuous refinement** – constitutes a mathematically distinct and
algorithmically novel strategy compared with the earlier gradient‑based and
full‑MILP approaches, while remaining comfortably inside the 600‑second budget.

The `run` function will orchestrate the stages, track elapsed time, and return
the best‑found vector `h_values` (as a list of floats in [0,1]), the associated
upper bound `c5_bound`, and the discretisation size `n_points`.

</strategy>
