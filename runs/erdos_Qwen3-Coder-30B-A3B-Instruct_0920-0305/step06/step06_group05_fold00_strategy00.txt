### 1. Mathematical Reformulation

For any lag \(\ell\) define  
\[
G_\ell(h)=\sum_{i}h_i\bigl(1-h_{i+\ell}\bigr) \;=\; \underbrace{\sum_i h_i}_{=n/2}\;-\;\sum_i h_i h_{i+\ell}.
\]

Hence  
\[
C_5 = \Delta x \;\max_\ell G_\ell(h)
          \;=\; \Delta x\Bigl( \frac{n}{2} - \min_\ell \sum_i h_i h_{i+\ell}\Bigr).
\]

Minimising \(C_5\) is equivalent to **maximising the minimal self‑correlation** \(\sum_i h_i h_{i+\ell}\) over all non‑zero lags.  
The functions \(G_\ell(h)\) are *linear* in each \(h_i\) once the other index is fixed, but the max over \(\ell\) makes the overall problem non‑smooth and non‑convex.

A standard trick for minimising a max‑function is to replace the max by a **smooth log‑sum‑exp** (soft‑max):
\[
F_\mu(h)=\mu\log\!\Bigl(\sum_\ell \exp\!\bigl(G_\ell(h)/\mu\bigr)\Bigr),
\]
where \(\mu>0\) controls the smoothing (large \(\mu\) → smoother, \(\mu\to0\) → exact max).  
For any \(\mu\), \(F_\mu(h)\) is a differentiable upper bound on \(\max_\ell G_\ell\) and shares the same minimisers in the limit \(\mu\downarrow0\).

**Gradient of a single term.**  
For a fixed lag \(\ell\):
\[
\frac{\partial G_\ell}{\partial h_j}
   = (1-h_{j+\ell})\mathbf 1_{j+\ell\in[0,n-1]}
     - h_{j-\ell}\mathbf 1_{j-\ell\in[0,n-1]} .
\]
Thus the gradient of the smooth objective is a **weighted sum** of these simple shift‑difference vectors:
\[
\nabla F_\mu(h)=\sum_\ell w_\ell\,\nabla G_\ell(h), \qquad

#### 3.1. Smooth Gradient Descent (SGD)

For a given smoothing parameter \(\mu\) we run a **projected gradient descent with back‑tracking line‑search**:

1. Compute `G = corr_fft(h, 1-h)`.
2. Build soft‑max weights `w = exp(G/μ) / sum(exp(G/μ))`.

3. Assemble the gradient `grad = Σ_ℓ w_ℓ * grad_Gℓ(h)` using simple shifted vectors.

* **Primary choice:** `n = 180` (Δx ≈ 0.0111).  
  * FFT length = 359, still trivial.  
  * Memory negligible.  

* **Fallback:** if time measurements show the algorithm exceeds the 600 s budget, we automatically fall back to `n = 150`.  
  The code reads the remaining time (`budget_s - elapsed`) before launching a new restart; if less than a safe margin (≈ 15 s) we stop.

Both choices keep the **exact sum constraint** `target = n/2` (since ∫h=1 ⇒ Σh·Δx = 1).

Key **performance tricks**:

### 6. Expected Outcome & Failure Modes

* **Why this should beat 0.3809:**  
  The smooth‑max gradient simultaneously accounts for *all* lags, not only the current worst lag. This gives a more balanced descent direction that reduces the dominant peak *and* prevents other peaks from rising, a phenomenon observed in preliminary tests. Continuation from large to tiny μ progressively sharpens the objective, effectively performing a homotopy that often lands in a deeper basin.

* **Potential issues:**  
  - The non‑convexity may still trap many restarts; we counter this with many diverse initialisations and a final annealing stage.  
  - Projection via binary search might stall if the vector is already on the boundary; we guard against infinite loops by clamping the search interval after a fixed number of iterations.  
  - Numerical overflow in the soft‑max for very small μ; we always shift by the max before exponentiation.

* **Fallback plan:** If after the allotted time the best C₅ is still > 0.3808, we automatically switch to a **pure simulated‑annealing** search on a binary (0/1) vector (maintaining sum exactly n/2) – a method known to find excellent low‑autocorrelation binary sequences in comparable settings. This extra phase is cheap and may shave the remaining few hundredths.
