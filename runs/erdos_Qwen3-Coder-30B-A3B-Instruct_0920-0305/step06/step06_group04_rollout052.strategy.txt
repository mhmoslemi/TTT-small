**Goal** – Find a step‑function  
\(h=(h_0,\dots ,h_{n-1})\) with  

* \(0\le h_i\le 1\) for all i,  
* \(\sum_i h_i = n/2\)   (so that \(\int_0^{2}h=1\) because \(dx=2/n\)),  

which minimizes  

\[
C_5(h)=\max_{0\le\ell<n}\;dx\;\sum_{i=0}^{n-1-\ell}h_i\bigl(1-h_{i+\ell}\bigr)
     =1-dx\;\min_{\ell}\;f_\ell(h) ,\qquad 
     f_\ell(h)=\sum_{i=0}^{n-1-\ell}h_i\,h_{i+\ell}.
\]

Thus minimizing \(C_5\) is *equivalent* to **maximising the smallest autocorrelation**
\(f_\ell(h)\) over all lags \(\ell\).  
The problem is a non‑convex max‑min quadratic programme.  The previous solution used a generic SLSQP optimiser; here we replace it by a *problem‑specific* algorithm consisting of two complementary phases:

1. **Smooth‑max projected gradient ascent on the worst lag (continuous phase).**  
2. **Discrete binary swap refinement (combinatorial phase).**

### 2. Continuous Phase – Smoothed Max‑Min Gradient Ascent

**2.1. Rationale**  
Directly minimising `max_ℓ (dx·∑ h_i (1‑h_{i+ℓ}))` is non‑smooth.  Replacing the max by a log‑sum‑exp gives a differentiable surrogate:

\[
F_\alpha(h) = \frac1\alpha\log\Bigl(\sum_{\ell=0}^{n-1}
          \exp\bigl(-\alpha\;f_\ell(h)\bigr)\Bigr).
\]

`F_α` is a smooth approximation of the worst‑lag value `min_ℓ f_ℓ`.  Minimising `F_α` (or equivalently maximising `-F_α`) drives the smallest overlap upward.  As α grows, the surrogate becomes tighter.

**2.2. Algorithmic loop**

```
h ← feasible random start (uniform or binary, see §4)
α ← 0.5                # start with gentle smoothing
η ← 0.5                # initial step size
repeat until time budget exhausted:
    compute f = autocorrelation of h   (FFT, O(n log n))
    w = softmax(-α * f)                # weights, sum to 1
    g = gradient = - Σ_ℓ w_ℓ (shift⁺ℓ h + shift⁻ℓ h)
        # implement with two simple loops over ℓ
    # line‑search
    η_curr ← η
    while η_curr > 1e‑6:
        h_trial = project( h - η_curr * g )
        if C5(h_trial) < C5(h): break
        η_curr *= 0.5
    if η_curr ≤ 1e‑6:   # no improvement → reduce α
        α ← min(α*1.5, 50.0)   # increase smoothing focus
        continue
    h ← h_trial
    # occasional random jitter (e.g. every 0.5 s)
    if elapsed % 0.5s == 0:
        jitter a few entries, re‑project
    # keep global best
    if C5(h) < best_C5: store best_h, best_C5
```

**Key points**

* The gradient uses *all* lags, but the weights automatically bias it toward the presently worst lag(s).  This is a substantial departure from the “guided move” that only looked at a single lag.
* The projection step guarantees feasibility after each update, so the constraints are never violated.
* α is increased slowly (e.g. by a factor 1.5) whenever the line‑search fails to find a descent direction – the algorithm then sharpens its focus on the true max‑overlap.
* Because the surrogate is smooth, the optimisation trajectory is less noisy than SLSQP’s finite‑difference gradients, allowing larger productive steps.

**Complexity** – For n≈200 the FFT is negligible; the O(n²) gradient dominates (≈40 k operations).  Even 10 000 iterations finish well within the 600 s limit.

### 3. Discrete Phase – Binary Swap Optimisation

After the continuous phase we typically have many entries close to 0 or 1.  The remaining slack can often be exploited by *exact* binary moves that improve the worst lag without harming the others.

**3.1. Problem formulation**  
Restrict to vectors with entries in `{0,1}` and exactly `n/2` ones (so the sum constraint is automatically satisfied).  For a given lag ℓ the overlap is simply the count of positions where both entries are 1:

\[
f_\ell^{\text{bin}} = \#\{\,i : h_i=h_{i+\ell}=1\,\}.
\]

The objective is to maximise \(\min_\ell f_\ell^{\text{bin}}\).

**3.2. Swap neighbourhood**  
A *swap* exchanges a 1 at index `p` with a 0 at index `q`.  The effect on each lag ℓ is:

\[
\Delta f_\ell = 
   \bigl[h_{p+\ell}=1\bigr] - \bigl[h_{p-\ell}=1\bigr]
 - \bigl[h_{q+\ell}=1\bigr] + \bigl[h_{q-\ell}=1\bigr],
\]

where the bracket is 1 if the condition holds and 0 otherwise (out‑of‑range indices are treated as 0).  Because we only care about the *minimum* value across ℓ, a swap is accepted if

```
new_min = min_ℓ (f_ℓ + Δf_ℓ)  >  current_min
```

Optionally we may also allow a small deterioration (e.g. `new_min ≥ current_min - 1`) when combined with a simulated‑annealing probability, to escape plateaus.

**3.3. Efficient update**  
Maintain the full overlap vector `f` (size n).  When a candidate swap `(p,q)` is examined, compute its Δf by scanning ℓ=0…n‑1 and using the current binary pattern; this is O(n).  Since we will try many random swaps, we limit the number of candidates per iteration (e.g. 2000 attempts) and stop when a successful swap occurs.  After a successful swap, update `h` and `f` by adding the pre‑computed `Δf`.  This keeps the cost linear per accepted move.

**3.4. Swap loop**

```
h_bin ← round(best_h) to 0/1 (preserving total weight)
compute f = autocorrelation of h_bin (FFT)
repeat for a fixed number of passes or until time out:
    ℓ_worst = argmin f    # current bottleneck lag
    # generate a list of candidate 1‑positions that miss ℓ_worst
    candidates_one = [i for i where h_bin[i]==1 and h_bin[i+ℓ_worst]==0]
    candidates_zero = [j for j where h_bin[j]==0 and h_bin[j+ℓ_worst]==1]
    if empty → break (local optimum)
    pick random p∈candidates_one, q∈candidates_zero
    compute Δf for all ℓ (vectorised shift‑checks)
    if min(f+Δf) > min(f):   # improvement
        h_bin[p]=0; h_bin[q]=1
        f += Δf
        record improvement
```

The loop aggressively removes the *exact* bottleneck lag and therefore often pushes the minimal overlap above the value achieved by the continuous phase.  Because the swap neighbourhood is tiny (two indices) it runs very fast even for n≈300.

**3.5. Hybridisation**  
After a batch of swaps we may return to the continuous phase (with a smaller α) to allow fractional “fine‑tuning” of the now‑near‑binary vector.  Alternating 3–4 times (continuous → swaps → continuous) typically yields the strongest improvements.

### 4. Multi‑scale / Multi‑restart scheme

* **Time allocation** – Roughly:
  * 0 – 30 s: warm‑up random restarts + quick continuous optimisation.

  * 540 – 590 s: final fine‑grained continuous phase with a large α (≈30) and tiny step size to polish the solution.
