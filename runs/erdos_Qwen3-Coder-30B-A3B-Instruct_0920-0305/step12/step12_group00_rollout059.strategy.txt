### 1.  Conceptual reframing – a zero‑sum game  

Define for a binary vector \(h\in\{0,1\}^{n}\) the overlap for lag \(\ell\)  

\[
c_{\ell}(h)=\sum_{i=0}^{n-1} h_{i}\bigl(1-h_{i+\ell}\bigr)
               = N-\underbrace{\sum_{i}h_{i}h_{i+\ell}}_{S_{\ell}},
\qquad N=\sum_i h_i=n/2 .
\]

Erdős’ constant is  

\[
C_{5}(h)=dx\;\max_{\ell\neq0}c_{\ell}(h) .
\]

Thus the player chooses a binary vector \(h\), the adversary chooses a lag
\(\ell\), and the payoff to the adversary is \(c_{\ell}(h)\).  The
player wants to **minimise** the worst‑case payoff, the adversary wants to
**maximise** it.  This is exactly a *zero‑sum game* with action set
\(\mathcal H=\{h\in\{0,1\}^{n}:\sum h_i=N\}\) for the player and
\(\mathcal L=\{1,\dots ,n-1\}\) for the adversary.

A standard way to approximate the equilibrium of such a game is the
**Multiplicative‑Weights‑Update (MWU)** (or Hedge) algorithm.  MWU keeps a
distribution over the opponent’s actions, solves a simple *best‑response*
subproblem for the player against the current distribution, and updates the
distribution against the observed loss.  Convergence guarantees give a
\(O(1/\sqrt{T})\) approximation after \(T\) rounds.

Our plan is to run MWU with a **convex relaxation** of the player’s action
set (continuous \([0,1]\) variables with the correct sum) – the subproblem
becomes a *convex quadratic program* that can be solved cheaply.  After a
few hundred rounds we will have a collection of high‑quality *fractional*
vectors; each will be rounded to a binary vector and then polished with a
fast discrete hill‑climb.  The best binary vector encountered is returned.

This approach is fundamentally different from the previous DE/gradient,
exact ILP, and SDP pipelines: it treats the problem as a repeated game and
uses a learning‑theoretic update rule rather than direct combinatorial or
convex‑relaxation optimisation.

### 2.  Discretisation and data structures  

| Symbol | Meaning |
|--------|----------|
| `n`    | number of sample points on \([0,2]\).  Choose a power of two, e.g. **128** (or **256** if time permits). |
| `dx`   | \(2/n\). |
| `N`    | required sum of the step‑function, \(N=n/2\). |
| `A_ℓ`  | \(n\times n\) symmetric Toeplitz matrix with ones on the \(\ell\)‑off‑diagonal (i.e. \( (A_ℓ)_{ij}=1\) iff \(|i-j|=\ell\)).  It encodes the quadratic term \(S_{\ell}=h^{\top}A_{\ell}h\). |
| `W`    | weighted sum of the `A_ℓ` matrices: \(W=\sum_{\ell} w_{\ell} A_{\ell}\).  It is automatically positive semidefinite because it is a non‑negative combination of PSD matrices. |

All `A_ℓ` are extremely sparse (two non‑zero entries per row) and can be
represented implicitly as a vector of lag‑weights `w`.  Multiplication of
`W` by a vector `v` is done by a **cyclic convolution**:  
\((Wv)_i = \sum_{\ell} w_{\ell}(v_{i+\ell}+v_{i-\ell})\).  This can be
implemented in \(O(n\log n)\) via FFT, which is crucial for the inner loop.

### 3.  The MWU loop – high‑level description  

1. **Initialisation**  
   * Set uniform weights: \(w_{\ell}^{(0)} = 1/(n-1)\) for all \(\ell=1,\dots,n-1\).  
   * Choose learning rate \(\eta>0\) (e.g. \(\eta = \sqrt{2\log(n-1)/T}\) where \(T\) is the planned number of rounds).  
   * Initialise the *best‑so‑far* record `(h_best, C5_best) = (None, +∞)`.

2. **Iterative rounds**  (repeat until the allocated MWU budget expires, e.g. 45 % of total time)

   For round \(t = 1,\dots,T\):
   
   a. **Form the weighted matrix**  
      Compute the convolution kernel `w = w^{(t-1)}` and use FFT to obtain a
      function that multiplies any vector by \(W\) quickly.

   b. **Solve the player’s sub‑problem**  
      Minimise the *weighted* overlap  
      \[
      \min_{h\in[0,1]^n,\;\sum h_i = N}\; f_t(h)
         = \sum_{\ell} w_{\ell}^{(t-1)}\,c_{\ell}(h)
         = N\sum_{\ell} w_{\ell}^{(t-1)} - h^{\top}W h .
      \]  
      Since the constant term is irrelevant, we simply minimise the *quadratic*
      function \(\phi_t(h)=h^{\top}W h\) under a simplex‑type box constraint.
      
      *Solution method*: a short **projected gradient descent** (PGD) with a
      fixed number of inner iterations (e.g. 30).  Each PGD step:
        - Compute gradient \(g = 2\,W h\) (via the convolution kernel).
        - Take a step \(h\leftarrow h - \alpha g\) with a modest step size
          \(\alpha\) (e.g. \(\alpha = 0.5/N\)).
        - **Projection** onto \(\{h\in[0,1]^n:\sum h_i = N\}\).  This projection is
          the classic “water‑filling” operation: find \(\lambda\) such that
          \(\sum_i \operatorname{clip}(h_i-\lambda,0,1)=N\).  It is \(O(n\log n)\)
          (sort once and scan).  The same routine will be used later for any
          rounding step.

      The PGD loop converges fast because \(\phi_t\) is a convex quadratic
      with Lipschitz gradient \(\|W\|_2 \le 2\sum_\ell w_\ell = 2\).  After the
      inner loop we obtain a **fractional** vector \(h^{(t)}\).

   c. **Evaluate true overlaps**  
      Using FFT, compute the full correlation \(\text{corr}=h^{(t)} * (1-h^{(t)})\)
      and extract the vector of overlaps \(c_\ell(h^{(t)})\).  Let  
      \(\ell^{*}_t = \arg\max_{\ell} c_\ell(h^{(t)})\) (the adversary’s best reply)
      and record the corresponding loss \(L_t = c_{\ell^{*}_t}(h^{(t)})\).

   d. **Weight update (Multiplicative)**  
      For every lag \(\ell\):
      \[
      w_{\ell}^{(t)} \;\leftarrow\;
      w_{\ell}^{(t-1)}\;\exp\!\bigl(\eta\,c_{\ell}(h^{(t)})/C_{\max}\bigr),
      \]
      where \(C_{\max}\) is an upper bound on any overlap (easily \(C_{\max}=N\)).
      After updating, **renormalise** so that \(\sum_{\ell}w_{\ell}^{(t)}=1\).

      *Stabilisation*: to avoid a single lag monopolising the weight,
      optionally mix with a uniform component:
      \[
      w_{\ell}^{(t)} \leftarrow (1-\gamma)w_{\ell}^{(t)}+\gamma/(n-1)
      \]
      with a tiny \(\gamma\approx 10^{-4}\).

   e. **Rounding and discrete refinement**  
      *Rounding*: transform the fractional vector into a binary one:
        - Sort indices by descending \(h^{(t)}_i\).
        - Set the top \(N\) entries to 1, the rest to 0.
        - Apply the same water‑filling projection to be safe (it enforces the sum exactly).  
      *Hill‑climb*: run the **swap improvement** described in Section 5 (a
      greedy search that swaps a 1 and a 0 if the worst lag improves).  Limit
      this local search to a small budget (e.g. 500 swaps) per round because
      we may have many MWU rounds.

      Compute the exact \(C_{5}\) of the refined binary vector.  If it is
      smaller than `C5_best`, update `(h_best, C5_best)`.

3. **Termination of MWU**  
   Stop when the allotted MWU time elapses (≈ 45 % of the total budget) or
   when `T` reaches a preset maximum (e.g. 4000).  The best binary vector
   discovered during the loop is kept for the next phase.

### 4.  Post‑MWU polishing – concentrated hill‑climb  

The binary vector `h_best` obtained from the MWU loop is already near‑optimal.
Nevertheless, a dedicated refinement stage can extract a few extra units of
the minimum autocorrelation.

1. **Full autocorrelation table** – compute once via FFT:
   \[
   S_\ell = \sum_i h_\text{best}[i]\;h_\text{best}[i+\ell],
   \qquad \ell=1,\dots,n-1 .
   \]

2. **Greedy swap neighbourhood** – repeatedly pick a random pair
   \((i\in\text{ones},j\in\text{zeros})\) and evaluate the effect on *all*
   lags using the O(n) formula  
   \[
   \Delta S_\ell = -\bigl(h_{i+\ell}+h_{i-\ell}\bigr)
                  +\bigl(h_{j+\ell}+h_{j-\ell}\bigr).
   \]  
   Accept the swap if the new worst lag (i.e. \(\min_{\ell} (S_\ell+\Delta S_\ell)\))
   strictly improves.  Continue until a full pass of \(5n\) random pairs yields
   no improvement.

3. **Simulated‑annealing fallback** – if the greedy phase stalls early,
   switch to a temperature‑controlled acceptance rule:
   \[
   \Pr(\text{accept}) = \exp\!\bigl((\text{new\_min}-\text{old\_min})/T\bigr),
   \]
   with an exponential decay `T ← 0.97·T` after each accepted or rejected move.
   Run this mode for at most another 30 % of the remaining budget.

4. **Multiple restarts** – after the first refinement, optionally create a
   few *independent* binary seeds (random or derived from earlier fractional
   iterates) and run the same swap‑annealing pipeline for a short burst
   (≈ 2000 swaps each).  Keep whichever yields the lowest `C5`.

The entire polishing stage is allocated about **35 %** of the total time
(below 210 s for a 600 s budget).  All operations are linear or FFT‑based,
so the wall‑clock cost stays well within the limit.

### 6.  Robustness – handling failure modes  

| Possible failure | Detection | Mitigation |
|------------------|-----------|------------|
| **MWU weight collapse** (one lag gets weight ≈ 1) | Observe `max(w) > 0.99`. | Apply mixing factor `γ` each round, or re‑initialise weights uniformly. |
| **PGD stagnates at a boundary point** | Gradient norm stays near zero but `h` is at 0 or 1 for many coordinates. | Add a tiny L2 regulariser `+ε‖h‖²` to the quadratic (ε≈1e‑6) or restart PGD from a random feasible point. |
| **Rounding yields a binary vector with many “bad” lags** | The computed `C5` after rounding is substantially larger than the fractional `dx·max c_ℓ`. | Try several rounding thresholds (e.g. top‑N, median cut, randomized rounding based on probabilities `h_i`) and keep the best before hill‑climb. |
| **Hill‑climb does not improve within its budget** | No improvement after `5·n` swap attempts. | Switch to simulated‑annealing mode, or enlarge the neighbourhood to *double swaps* (swap two pairs simultaneously) for a limited number of trials. |
| **Total time exceeds 600 s** | Continuously monitor `time.time()`; each major phase checks remaining budget before starting a new iteration. | Abort the current phase, return the best binary vector recorded so far (which is always feasible). |

Because every stage updates a global best `(h_best, C5_best)`, the algorithm always produces a valid answer even if it empties its time budget early.
