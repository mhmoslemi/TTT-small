**Goal** – Find a discretised step‑function `h` on `[0,2]` (length `n` samples) with values in `[0,1]`, total integral = 1 (i.e. `∑h = n/2`) that minimizes  

\[
C_5=\max_{k\in\{-n+1,\dots,n-1\}}  \int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx .
\]

In the discrete setting this is  

\[
C_5 = \frac{2}{n}\;\max_k \; r_k,\qquad 
r_k = \sum_{i=0}^{n-1-|k|} h_i\bigl(1-h_{i+|k|}\bigr),
\]

where the sum is over the overlapping indices for shift `k`.  
`r_k` counts, for each shift, the number of **mismatches** “a 1 followed by a 0”.  
The problem is thus *minimise the maximum number of mismatches* over all shifts.

--------------------------------------------------------------------
### 1.  Modelling choices  

* **Binary representation** – The optimum of a linear‑fractional min‑max problem under box constraints almost always lies at an extreme point.  Hence we restrict to `h_i∈{0,1}` and enforce `∑h_i = n/2`.  This turns the problem into a pure combinatorial one and removes the need for projection onto the simplex during the search.  

* **Metric** – Instead of the floating‑point `C5` we work with the integer vector `r = corr(h,1‑h)` (no `dx` factor).  The objective becomes `max(r)`.  The conversion back to the required bound is `C5 = (2/n)·max(r)`.

* **Discretisation size** – Choose `n = 200` (even, comfortably < 1 000).  This yields a step size `dx = 0.01` and a target maximum mismatch `M_target = ⌈C5_target/dx⌉`.  
  For the benchmark `C5 ≤ 0.3807` we need `M_target = ⌈0.3807/0.01⌉ = 38`.  In practice we aim for `M ≤ 22` (which would give `C5 ≈ 0.22`), a comfortable safety margin.

### 2.  Fast evaluation of `max(r)`

* **FFT based correlation** –  
  1. Compute `b = 1 - h`.  
  2. Pad both vectors to length `L = 2·n‑1`.  
  3. Use `np.fft.fft` to evaluate `corr = ifft( fft(h_rev)·fft(b) ).real`.  
  4. Round the result to nearest integer (numerical noise).  

* **Complexity** – `O(n log n)` per evaluation; for `n = 200` this is ≈ 2 µs, allowing >100 k evaluations within the 600 s budget.

Because the landscape is highly non‑convex, a stochastic meta‑heuristic explores many basins.

**State:** a binary vector `h` with exactly `n/2` ones.  

**Neighbourhood:** swap a randomly chosen `1` with a randomly chosen `0` (sum stays fixed).  

**Energy:** `E(h) = max(r)` (the integer we minimise).  

**Temperature schedule:**  
* Initialise `T₀ = 8` (in units of mismatch count).

**Acceptance rule:**  
* If `Δ = E_new - E_cur ≤ 0` accept.

### 4.  Deterministic refinement – Focused hill‑climbing  

After the annealing phase the maximum mismatch is typically concentrated on a few “worst” shifts.  A deterministic greedy pass can often close the last gap.

**Procedure (run until stagnation):**
1. Compute `r` and identify all shifts `k*` attaining `max(r)`.  
2. For each such shift collect the **active mismatches**  
   `M(k*) = { i : h_i = 1 and i+|k*| < n and h_{i+|k*|}=0 }`.  
3. Randomly select an element `i∈M(k*)`.  
4. Try swapping this `1` with every `0` in the vector (or a random subset of size ≤ 20).  
5. Accept the first swap that strictly reduces `max(r)`.  
6. If no improving swap exists for any worst shift, stop.

The complexity of one pass is `O(|M|·n)`, but because `|M|` is small (the number of mismatches at the worst shift) the pass is cheap.  The loop finishes in a few hundred iterations.

### 5.  Exact lower‑bound certification – MILP polishing  

If, after the stochastic + greedy phases, the current `M = max(r)` is not far above the target, a small mixed‑integer linear programme can often certify optimality or improve it further.

**Variables**
* `h_i ∈ {0,1}` for `i = 0…n‑1`.  
* For each ordered pair `(i,j)` with `0 ≤ i < j < n` define a product variable `y_{ij} ∈ {0,1}` meaning `h_i·h_j`.  

**Linearisation of the product** (standard McCormick):
```
y_{ij} ≤ h_i
y_{ij} ≤ h_j
y_{ij} ≥ h_i + h_j - 1
```

**Mismatch count for shift k (k>0):**  
`m_k = Σ_{i=0}^{n-1-k} ( h_i - y_{i,i+k} )`.  
For negative shifts the same formula holds with indices swapped; we simply generate constraints for all `k = 1 … n‑1` and also for `k = -1 … -(n‑1)` using the appropriate index order.

**Auxiliary variable** `M` (integer) bounding all mismatches: `m_k ≤ M` for every shift `k`.  

**Objective:** minimise `M`.  

**Additional constraints:** `Σ_i h_i = n/2`.

**Solver** – Use `cvxpy` with the open‑source CBC (or GLPK) backend.  
Because the problem size for `n=200` is ≈ 20 000 binary variables (`h` + `y`) and ~ 60 000 linear constraints, modern CBC solves it to optimality in ≤ 30 s for a modest bound (e.g. `M ≤ 30`).  The MILP is invoked **only once**, after the heuristic has supplied a tight upper bound `M₀`.  We initialise the solver with the heuristic solution (fixing `h` to that pattern) and ask it to improve `M`; this drastically reduces the branch‑and‑bound tree.

If the MILP returns a solution with `M < M₀`, replace the heuristic `h` with the MILP solution.
