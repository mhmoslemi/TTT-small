### 2. Feasible‑set projection (capped simplex)

All iterates must satisfy:

* Box: `0 ≤ h[i] ≤ 1`.
* Linear equality: `∑h[i] = TARGET`.

We will implement the Euclidean projection onto this *capped simplex*:

1. Clip the vector to `[0,1]`.
2. If the sum equals `TARGET` we are done.
3. Otherwise find a scalar `λ` such that `∑clip(v_i + λ, 0, 1) = TARGET`.
   This is a monotone one‑dimensional problem; solve it with a short bisection
   (≈ 50 iterations, double‑precision).  
   The projection routine will be called after every tentative move.

This projection is exact, cheap (`O(n log n)` for the bisection) and keeps the
iterate inside the feasible region.

### 3. Efficient correlation representation

Define:

* `h` – current vector (float64).  
* `b = 1 - h`.  
* `c = correlate( h , b , mode='full' )` – length `2n‑1`.  
* `Cmax = max(c)` (the current objective value, multiplied later by `dx`).

Computing `c` from scratch via FFT costs `O(n log n)`.  During the stochastic
search we will **update `c` incrementally** after each elementary move, which
costs only `O(n)` (linear scans) and therefore permits many more iterations.

#### 3.1 Incremental update for a change at a single index

Suppose we change `h[i]` by `Δ` (so `b[i]` changes by `‑Δ`).  The correlation
change at shift `s` (in the index range `-(n‑1)…(n‑1)`) is

```
Δc[s] = Δ * b[i+s]  (if 0 ≤ i+s < n)          # contribution from changed h
       - Δ * h[i-s] (if 0 ≤ i-s < n)          # contribution from changed b
```

Using the full‑mode formulation (`index r = s + (n‑1)`) this can be realised
with two vectorised slice operations:

* **b‑part**: `c[ (n-1‑i) : (n-1‑i)+n ] += Δ * b`  
  (the slice length is exactly `n`; out‑of‑range entries of `b` are simply not
  present, so the slice aligns automatically).

* **h‑part**: `c[ i : i+n ] -= Δ * h_rev` where `h_rev = h[::-1]`.

Both slices are of length `n`; the operations are `O(n)` and fully vectorised.

#### 3.2 Simultaneous move at two indices (mass transfer)

A move will always keep the total sum constant: pick two distinct indices
`i, j` and transfer a small amount `δ` from `i` to `j`:

```
Δ_i = -δ ,   Δ_j = +δ
```

Apply the single‑index update for `i` with `Δ_i`, then for `j` with `Δ_j`.
Finally add the quadratic correction (Δa ⋆ Δb) which contributes `+δ²` to the
correlation at the two shifts `s = (j‑i)` and `s = (i‑j)` (indices
`j‑i + (n‑1)` and `i‑j + (n‑1)`).  Because `δ` will be chosen of order `10⁻³`,
the `δ²` term is negligible but we add it for exactness.

After the updates, recompute `Cmax = max(c)` (a plain `np.max` over the
`2n‑1` array).

### 4. Move generation (proposal distribution)

* **Step size schedule** – Start with a relatively large `δ₀ ≈ 0.02`.  
  Every `T_step` successful moves, reduce `δ ← 0.9·δ` down to a minimum of

* **Selection of indices** – Randomly pick `i` and `j` uniformly from `[0,n)`.

* **Mass‑transfer move** – The proposal vector is `h' = h` with
  `h'[i] = h[i] - δ`, `h'[j] = h[j] + δ`.

### 5. Acceptance criterion (Simulated annealing)

Define the current objective value `Obj = dx * Cmax`.  
Let `Obj'` be the value after the proposed move.

* If `Obj' < Obj` → **accept** (improvement).
* Else accept with probability `exp( -(Obj'‑Obj) / T )`, where `T` is a temperature.
  The temperature schedule is geometric: `T ← α·T` after a fixed number of
  iterations (`α ≈ 0.995`).  Initialise `T` so that early non‑improving moves
  are accepted roughly 30 % of the time (e.g. `T₀ = 0.01`).

Because the objective is a max over many shifts, a single move can affect many
terms simultaneously; the annealing helps to traverse local valleys.
