1. Build the LP once, using a sparse representation for the `p`‑variables (each `p_{i,k}` appears only in three constraints: two McCormick bounds and one lag‑sum).  
2. Use **CVXPY** with an LP‑capable solver:
   * Preferred: `GUROBI`/`MOSEK` if available (fast, high‑precision).  
   * Open‑source fallback: `CBC` or `GLPK`.  
   * As a last resort, `ECOS` or `SCS` (they handle LPs but are slower).

3. Set a generous iteration limit (e.g. `max_iters = 5000`) and a relative tolerance of `1e‑6`. The problem size (`≈ 7 200` auxiliary variables, `≈ 30 000` linear constraints) solves comfortably in < 30 seconds on a single CPU with any of the above solvers.

4. Retrieve the optimal vector `h*` (the `h_i` values) and the optimal bound `t*`. Because the LP only relaxes the products, `t*` is a **lower bound** on the true `C₅`. The vector `h*` is already feasible for the original constraints (box and mass), so we can plug it directly into the exact overlap evaluation.

---

### 5. First evaluation of the candidate

1. Project `h*` onto the exact mass constraint using a fast **water‑filling projection**: find a scalar λ such that `clip(h*+λ,0,1)` has sum `S`. (The LP already forces the sum = S, but numerical solvers may leave a tiny residual; the projection removes it.)  

2. Compute the true `C₅` of this `h` with the FFT‑based correlation routine:  

   ```
   corr = real(ifft(fft(h[::-1]) * fft(1-h))) * dx
   C5 = max(corr)
   ```

   This gives an **upper bound** on the constant. Often the LP solution already yields `C₅ ≈ 0.382` or better, already beating the previous record.

If the resulting `C₅` is already below the target of `0.3807`, we can stop. Otherwise we proceed to a short, deterministic refinement.

---

### 6. Local refinement – projected sub‑gradient descent

The LP ignores the exact quadratic term; a few gradient steps can tighten the bound.

1. **Gradient of a single lag** – for a fixed shift `s` (signed integer, `s = k-(n-1)`), the discrete overlap is  

   \[
   L(s)=dx\sum_i h_i\bigl(1-h_{i+s}\bigr),
   \]
   whose (sub‑)gradient is  

   \[
   \nabla_i L(s)=dx\bigl(1 - h_{i+s} - h_{i-s}\bigr),
   \]
   where out‑of‑range indices are omitted (treated as 0).

2. **Active set** – compute the full correlation `corr`; collect all lags attaining the maximal value (within a tolerance `1e‑12`). Let this set be `S_act`.

3. **Sub‑gradient** – take the arithmetic mean of the gradients for all active lags:

   \[
   g = \frac{1}{|S_{\text{act}}|}\sum_{s\in S_{\text{act}}}\nabla L(s).
   \]

4. **Descent step** – choose a step size `η`. A simple adaptive rule works well:

   * Initialise `η = 0.5`.  
   * If a step reduces `C₅`, increase `η ← 1.05 η` (capped at `η_max = 2.0`).  
   * If a step does **not** reduce `C₅`, reject the move and set `η ← 0.3 η` (floor `η_min = 1e‑4`).

5. **Projection** – after a trial update `h' = h - η g`  
   * Clip to `[0,1]`.  
   * Apply the water‑filling projection to restore the exact sum `S`.  

   This projection automatically respects the box constraint and the mass constraint; the gradient step itself preserves the sum up to boundary effects, so the projection is cheap.

6. **Acceptance** – keep the new `h` if its `C₅` is lower; otherwise keep the old `h` (but retain the reduced step size).

7. **Escaping plateaus** – every 30 iterations (or after 200 consecutive non‑improvements) perform a **random mass‑transfer move**:
   * Pick indices `i⁻, i⁺` with `h[i⁻] > 0` and `h[i⁺] < 1`.  
   * Transfer a random amount `ε = min(0.02, h[i⁻])·U(0,1)`.  
   * Clip & project as above.  
   * Accept if `C₅` does not increase by more than `1e‑4`.  
   This injects stochasticity without breaking the deterministic nature of the main loop.

8. **Stopping criterion** – run the descent until the global time budget (`budget_s`) is reached. The loop is cheap (each iteration is `O(n·|S_act|)` ≈ a few hundred operations) so we can afford several thousand iterations.

The descent rapidly reduces any residual excess in the maximal lag because the sub‑gradient directly targets the worst overlap.

### 8. Expected failure modes and mitigations

| Failure mode                                 | Detection & mitigation |
|----------------------------------------------|------------------------|
| **LP infeasibility** (constraints too tight) | *Detect*: solver returns infeasible. *Mitigate*: relax symmetry/monotonicity, or drop the `p ≥ h_i + h_{i+k} - 1` inequality (makes envelope larger). |
| **Solver too slow** (large `n`)              | *Detect*: wall‑time exceeds a preset limit. *Mitigate*: automatically halve `n` and rebuild. |
| **Numerical drift in mass after LP**         | *Detect*: `abs(sum(h) - S) > 1e‑8`. *Mitigate*: apply the water‑filling projection before any evaluation. |
| **Sub‑gradient step overshoots bounds**      | *Detect*: many components become exactly 0 or 1 after clipping. *Mitigate*: shrink `η` aggressively when the acceptance rate drops. |
| **Stagnation (no improvement for many iterations)** | *Detect*: counter of consecutive non‑improving steps exceeds 500. *Mitigate*: trigger a batch of random mass‑transfer moves with larger `ε` (up to 0.1). |
| **Large gap between LP lower bound `t*` and actual `C₅`** | *Detect*: `C₅ - t* > 0.01`. *Mitigate*: run a few *cutting‑plane* iterations: after evaluating the true worst lag `k*`, add the *exact* quadratic constraint `∑ h_i h_{i+k*} ≥ S - C₅` approximated with McCormick bounds and re‑solve the LP (warm‑starting if the solver supports it). Usually one or two such refinements close the gap dramatically. |
| **Memory overflow when constructing `p`‑variables** | *Detect*: MemoryError during model build. *Mitigate*: generate `p` only for lags up to a limited window (e.g. `k ≤ 30`) because far‑away shifts contribute little to the max; the remaining shifts are handled later by the gradient descent. |

### 9. Summary of the algorithmic pipeline

1. **Discretise** `[0,2]` with `n` points (`n≈120`).  
2. **Formulate** the LP with variables `h`, `p_{i,k}`, and `t`, using McCormick envelopes, mass and box constraints, and the max‑over‑lag constraints expressed via `t`. Optionally add symmetry/monotonicity constraints.  
3. **Solve** the LP (fast, globally optimal for the relaxed problem).  
4. **Extract** the feasible `h` (project onto the exact sum).  
5. **Evaluate** the true `C₅` using FFT correlation.  
6. **If** `C₅` already beats the target → return.  
7. **Otherwise**, **refine** with projected sub‑gradient descent (using the exact quadratic gradient for the active lag(s)), interleaved with occasional random mass‑transfer swaps.  
8. **Track** the best `h` and its `C₅` throughout; stop when the overall time budget expires.  
9. **Return** the best `h` (as a Python list), the corresponding `C₅` value, and the grid size `n`.

This strategy leverages a **global convex relaxation** to obtain a near‑optimal shape in one shot, then uses a **structure‑aware deterministic refinement** that directly minimises the true non‑convex objective. It is fundamentally different from pure local optimisation or evolutionary heuristics, and it is well‑suited to the 600 s time budget while keeping the implementation simple (only `numpy`, `scipy`, and `cvxpy` with an LP solver).
