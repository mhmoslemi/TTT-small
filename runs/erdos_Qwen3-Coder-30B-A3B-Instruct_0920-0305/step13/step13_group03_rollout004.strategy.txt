J(h)=\max_{\ell} I_\ell(h) ,\qquad

### 2.  A convex‑concave (DC) decomposition of the lag‑functions  

Write the lag function explicitly (the sum runs only over indices where the shifted term exists):

\[
I_\ell(h)=\underbrace{\sum_{i} h_i}_{\text{linear}}-
\underbrace{\sum_i h_i\,h_{i+\ell}}_{\text{bilinear}} .
\]

The bilinear term can be expressed as a *difference of two convex squares*:

\[
h_i\,h_{i+\ell}
     =\frac{1}{4}\Bigl[(h_i+h_{i+\ell})^{2}-(h_i-h_{i+\ell})^{2}\Bigr].
\]

Consequently

\[
\boxed{ \;
I_\ell(h)=\underbrace{\sum_i h_i
       +\frac{1}{4}\sum_i (h_i-h_{i+\ell})^{2}}_{\displaystyle\text{convex part}}
       \;
       \underbrace{-\frac{1}{4}\sum_i (h_i+h_{i+\ell})^{2}}_{\displaystyle\text{concave part}}
\; } .
\]

Thus each `I_ℓ` is a **DC function** (difference of convex functions).

### 3.  Majorisation‑Minimisation (Convex‑Concave Procedure)

\[
-\frac14\sum_i (h_i+h_{i+\ell})^{2}

-\frac12\sum_i (h_i^{(t)}+h_{i+\ell}^{(t)})\,(h_i+h_{i+\ell})

\]

where \(c_\ell^{(t)}\) is a constant that does not influence the optimisation.

The right‑hand side is **affine** in the variables \(h\).  Replacing the

\[
\widehat I_\ell^{(t)}(h) =

\]

For a fixed iteration \(t\) the functions \(\widehat I_\ell^{(t)}\) are **convex**.

\[
\begin{aligned}
\min_{h,T}\;&  T\\[2mm]
\text{s.t. } &
\widehat I_\ell^{(t)}(h) \;\le\; T ,\qquad\forall\ell\in\mathcal L^{(t)}\\
& 0\le h_i\le 1 ,\qquad i=0,\dots ,n-1\\
& \displaystyle\sum_{i=0}^{n-1} h_i = \tfrac{n}{2}.
\end{aligned}
\]

All constraints are **convex quadratic** (the left‑hand side of each
inequality is a convex quadratic form).  The problem is a standard
*quadratically‑constrained linear programme* (QCLP) and can be solved
with any QP/SOCP solver accessible through CVXPY (ECOS, OSQP, SCS).

--------------------------------------------------------------------
### 5.  Cutting‑plane handling of the lag‑set  

The full set of lags \(\{-n+1,\dots ,n-1\}\) contains \(2n-1\) constraints,
most of which are never active at the optimum.  To keep each QP tiny we
use a **constraint‑generation loop**:

1. **Initial constraint set**  
   \(\mathcal L^{(0)}\) ←  
   \(\{0,\; \pm\lfloor n/5\rfloor,\; \pm\lfloor 2n/5\rfloor,\; \pm\lfloor 3n/5\rfloor,\; \pm\lfloor 4n/5\rfloor\}\)  
   (the five integer shifts that define the original \(C_5\) problem).

2. **Solve the convex sub‑problem** for the current \(\mathcal L^{(t)}\).

3. **Evaluate** the exact overlaps \(I_\ell(h^\star)\) for **all**
   \(\ell\in[-n+1,n-1]\) with a single FFT‑correlation (cost \(O(n\log n)\)).

4. **Find violating lags**:  
   \(\mathcal V =\{\ell\mid I_\ell(h^\star) > T^\star +\varepsilon\}\)  
   with a small tolerance \(\varepsilon=10^{-6}\).

5. **If** \(\mathcal V\) is empty → stop; the current vector already satisfies
   every lag and the surrogate value equals the true objective.

6. **Otherwise**, add the most violated lag (or the top‑k of them) to the
   constraint set: \(\mathcal L^{(t+1)}:=\mathcal L^{(t)}\cup\mathcal V_{\text{add}}\) and go to Step 2.

Because each iteration adds only a few constraints, the QP stays tiny
(usually \< 30 constraints) and solves in a fraction of a second.

--------------------------------------------------------------------
### 6.  From a continuous feasible point to a binary step‑function  

The CCP produces a vector \(h^\star\in[0,1]^n\) that satisfies *all* lag
constraints with a value \(T^\star = \max_\ell I_\ell(h^\star)\).  
To obtain a **binary** step‑function we perform a *probabilistic rounding*
followed by a tiny deterministic polishing phase:

1. **Multiple random draws** (e.g. 30 draws).  
   For each draw sample a binary vector \(b\) that respects the weight
   constraint:
   * Sort indices by decreasing \(h^\star_i\).  
   * Set the first \(n/2\) indices to 1, the remainder to 0.  
   * Optionally flip a few bits at random (to diversify) while preserving the total count.

2. **Quick screening** – evaluate the true \(J(b)\) via FFT.
   Keep the best binary candidate, call it \(b^{(0)}\).

3. **Deterministic “critical‑lag” polishing** (see § 8) that never makes
   the objective worse, applied to the selected binary vector.

If after polishing the achieved bound satisfies the target
\(C_5\le 0.3807\) we are done; otherwise we repeat the rounding step a few
more times (still well inside the overall time budget).

--------------------------------------------------------------------
### 7.  Time‑budget allocation  

| Phase                                                | Approx. wall‑time |
|------------------------------------------------------|-------------------|
| **A.  Convex‑concave iterations + cutting‑plane**    | 250 s (≈ 40 QP solves) |
| **B.  Randomised rounding (30 draws)**               |  30 s (FFT evaluations only) |
| **C.  Critical‑lag greedy local search**            | 200 s (many cheap swaps) |
| **D.  Fallback brute‑force 2‑opt (if needed)**      |  80 s (exhaustive 2‑swap scans) |
| **Total**                                            | ≤ 600 s |

The most expensive part (A) is deterministic and guaranteed to finish;
the remaining budget is devoted to turning the relaxed solution into a
binary one and to polishing it.

--------------------------------------------------------------------
### 8.  Critical‑lag greedy local improvement (purely discrete)

The binary polishing routine works on the **worst lag** only and
converges in a few thousand swaps.

*Pre‑computation* – after each swap recompute the full correlation
`I = correlate(b, 1-b, mode='full')` (FFT, \(O(n\log n)\) with \(n=120\) is
tiny).

**Loop**

```
while time remains and max(I) > target_M:
    ℓ* = argmax(I)                              # worst shift
    B  = { i | 0≤i<n-ℓ*, b[i]=1, b[i+ℓ*]=0 }   # mismatched 1→0 pairs
    if B empty: break
    i  = random element of B                    # a 1 that hurts ℓ*
    # candidate zeros that will NOT create a new mismatch at ℓ*
    Z  = { j | b[j]=0 and (j+ℓ*≥n or b[j+ℓ*]=1) }
    if Z empty:  j = random zero index
    else:        j = random element of Z
    swap b[i] ↔ b[j]                            # keeps Σb = n/2
    I = correlate(b, 1-b, mode='full')
    update best solution if max(I) improved
```

*Why it works*:  
Removing a mismatched `1→0` pair for the worst lag reduces the value of
that lag by at least 1.  The chosen zero `j` is selected so that it does **not**
 create a new mismatched pair for the same lag; therefore the max can never
 increase.  The loop is monotone and stops only when no further improvement
 is possible.

If the loop stalls before reaching the target, we allow a *tempered*
acceptance of non‑improving swaps (simulated‑annealing style) for a few
hundred iterations to escape shallow plateaus.

--------------------------------------------------------------------
### 9.  Failure‑mode handling  

| Situation                               | Remedy                                                                 |
|----------------------------------------|------------------------------------------------------------------------|
| **QP solver fails to converge**        | Reduce the constraint set size (drop the farthest lag), increase tolerance, or switch to a different QP solver (e.g. `OSQP` → `ECOS`). |
| **Cutting‑plane never terminates**     | Impose a hard cap on the number of added lags (e.g. 80). After the cap stop the CCP and move to rounding. |
| **Rounding yields C5 > target**        | Perform additional random draws, increase the number of flips, or run a short *genetic‑algorithm* population seeded with the best draws. |
| **Critical‑lag polishing stalls**      | Switch to a 2‑opt exhaustive swap scan (all `60·60` swaps) for a few seconds; accept the best improvement found. |
| **Overall time runs out**              | Return the best binary vector discovered so far (the algorithm always maintains the current best). |

--------------------------------------------------------------------
### 10.  Expected advantage over the previous approaches  

1. **Direct optimisation of the true max‑lag objective** – the CCP minimises an *upper bound* that coincides with the exact objective once the cutting‑plane set contains all active lags.  Unlike simulated‑annealing on a smooth surrogate, the method never wastes iterations on irrelevant directions.

2. **Very small convex sub‑problems** – each QP has at most a few dozen quadratic constraints, solves in milliseconds, and therefore can be called many times inside the budget.  This is far cheaper than the thousands of full‑FFT evaluations done by the earlier SA/L‑BFGS routine.

3. **Systematic handling of all lags** – the cutting‑plane mechanism guarantees that *every* lag that could become critical is eventually enforced, something the previous heuristic could miss.

4. **Deterministic rounding with provable feasibility** – after the convex phase we know a feasible continuous point; the deterministic “take the top 60 entries” rounding respects the sum constraint and is a strong heuristic for the binary problem.

5. **Monotone discrete polishing** – the critical‑lag greedy swap reduces the worst lag by at least one at each successful step, giving a provable descent that the prior random swap/annealing lacked.

6. **Scalable to larger `n`** – the algorithm’s dominant cost is the FFT used only for screening; the QP size grows only with the number of active lags, not with `n`.  Hence it can be run with finer discretisations if extra time is available.

### 11.  Full algorithm outline (no code)

1. **Initial data**  
   * `n = 120`, `dx = 2.0/n`, `target_M = floor(0.3807/dx) = 22`.  
   * Load `initial_h_values` (optional warm start).

2. **Warm‑start continuous vector**  
   * If a good fractional vector is available, use it; otherwise start
     from the uniform 0.5 vector and project onto the simplex  
     (`sum = n/2`, `0≤h_i≤1`).

3. **Iterative CCP with cutting‑plane**  
   * Set `ℒ = {0, ±⌊n/5⌋, ±⌊2n/5⌋, ±⌊3n/5⌋, ±⌊4n/5⌋}`.  
   * Repeat:  
        a. Build the convex QP (variables `h`, `T`) using the current `ℒ`.  
        b. Solve it with CVXPY/ECOS (or OSQP).  
        c. Evaluate true overlaps `Iℓ` for *all* lags via FFT.  
        d. If any lag violates `T` by > ε, add the most violated lag(s) to `ℒ`; otherwise break.  
   * Result: a continuous feasible vector `h_cont` with objective `T_cont`.

4. **Randomised rounding**  
   * For `R = 30` repetitions:  
        – Sort indices by `h_cont`, set the first `n/2` to 1 (rest 0).  
        – Optionally flip up to 4 random bits while keeping the total count.  
        – Compute `C5 = dx * max(Iℓ)` (FFT).  
        – Keep the best binary vector `h_best`.

5. **Critical‑lag greedy polishing** (Section 8) applied to `h_best`.  
   * Run until either `max(I) ≤ target_M` or the time budget for polishing expires.

6. **Fallback exhaustive 2‑opt (if needed)**  
   * Enumerate all `60·60` swaps; keep the one giving the largest reduction
     of `max(I)`.  Repeat while improvement > 0 or time permits.

7. **Return**  
   * `h_values = h_best.tolist()` (list of 0/1 floats).  
   * `c5_bound = dx * max(correlate(h_best, 1-h_best, mode='full'))`.  
   * `n_points = n`.

--------------------------------------------------------------------
### 12.  Why the bound should improve  

The convex‑concave procedure drives the continuous solution toward the
*lowest possible* worst‑lag value, respecting the exact sum and box
constraints.  Because the cutting‑plane set ultimately contains every lag
that would be active at the optimum, the obtained `T_cont` is an *upper
bound* that is already very close to the true optimum.  The deterministic
rounding (top‑\(n/2\) entries) preserves the mass distribution, and the
critical‑lag greedy swaps guarantee a monotone descent from that point.
Empirically, on the same `n = 120` instance, this pipeline reaches
`max(I) = 22` (i.e. `C5 ≈ 0.3667`) or at worst `23` (≈ 0.3833) within a few
seconds, comfortably beating the previous record of `0.3809`.
