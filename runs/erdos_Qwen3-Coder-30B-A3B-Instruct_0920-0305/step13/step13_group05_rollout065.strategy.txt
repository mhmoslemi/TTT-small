**Goal** – Find a step‑function `h` (discretised as a vector `x∈[0,1]^N`, `N=n_points`) with  
`∑x_i·dx = 1` (`dx = 2/N`) that minimises  

```
C5(x) = dx · max_{k∈{-(N-1)…(N-1)}}  Σ_{i} x_i·(1‑x_{i+k})      (zero‑padded indices)
```

The key is to minimise the *maximum* correlation term.  The previous code relied on simulated‑annealing and a very expensive finite‑difference gradient.  The new plan replaces that by an **exact projected (sub)gradient method** that works directly with the max (or a smooth approximation of it) and by a **cap‑simplex projection** that guarantees both the box and the sum constraints.

The strategy consists of the following stages, each of which is cheap enough to be repeated many times within the 600 s budget.

--------------------------------------------------------------------
### 1. Analytic expressions

*Correlation vector*  
For a given `x` define `b = 1‑x`.  
The full correlation `c = corr(x,b)` (length `2N‑1`) can be obtained with a single FFT:
```
c = ifft( fft(x[::-1], L) * fft(b, L) ).real      with L = 2N‑1
```
The entry `c[t]` (index `t = shift + N‑1`) equals  
`c[t] = Σ_{i} x_i·(1‑x_{i+shift})` for all `i` where both indices lie in `[0,N)`.

*Gradient of a single shift*  
For a fixed integer shift `s` (`-(N‑1) ≤ s ≤ N‑1`) the derivative of the corresponding correlation term `c_s` w.r.t. the components of `x` is

```
∂c_s/∂x_j =   (1‑x_{j+s})   if 0 ≤ j+s < N        (first factor)
           – x_{j‑s}       if 0 ≤ j‑s < N        (second factor)
           0               otherwise
```

In vector form this can be built with two sliced assignments:
- if `s ≥ 0`:
    ```
    g[:N‑s]      += 1‑x[s:]
    g[s:]        += –x[:N‑s]
    ```
- if `s < 0` (let `t = –s`):
    ```
    g[t:]        += 1‑x[:N‑t]
    g[:N‑t]      += –x[t:]
    ```

*Subgradient of the max*  
Let `S = { s | c_s = max_j c_j }`.  Any convex combination of the gradients `{∇c_s | s∈S}` is a valid subgradient of `max_s c_s`.  The simplest choice is the arithmetic mean over all active shifts.

*Smooth approximation*  
To obtain a smooth objective we use a “soft‑max” (log‑sum‑exp) with temperature `γ>0`:

```
F_γ(x) = (dx/γ)·log( Σ_s exp(γ·c_s) )
```

Its gradient is a **weighted average** of the individual gradients with weights

```
w_s = exp(γ·c_s) / Σ_t exp(γ·c_t) .
```

When `γ → ∞` the soft‑max approaches the true max, while for small `γ` the landscape is smoother and easier to optimise.

### 2. Projection onto the capped simplex

After each gradient step we must enforce

```
0 ≤ x_i ≤ 1   and   Σ_i x_i = N/2 .
```

The projection can be performed by a single “water‑filling” (binary‑search on a Lagrange multiplier λ) :

1. For a trial λ compute `y_i = clip(x_i + λ, 0, 1)`.
2. The function `φ(λ) = Σ y_i – N/2` is monotone; binary‑search λ until |φ(λ)| < 1e‑12.
3. Return `y`.

The routine is O(N log precision) and is called after every iteration.

### 3. Main optimisation loop (projected smooth‑max gradient descent)

**Parameters (tuned empirically before the run):**
- `γ_start = 0.5`, `γ_factor = 1.05` (multiply after each epoch)
- `γ_max = 30` (≈ hard max, enough to resemble the true max)
- `α_0 = 0.6` (initial step‑size)
- `α_decay = 1/√t` (standard diminishing step size)
- `epoch_len = 300` iterations (after which `γ` is increased)
- `max_iters = floor( 0.85·budget_s / time_per_iter )` (reserve 15 % for final polishing)

**Loop**
```
x ← initial vector   (use the supplied initial_h_values, projected to the feasible set)
best_x ← x ; best_val ← C5(x)

γ ← γ_start
for iter = 1 … max_iters:
    # 1) correlation
    c ← corr(x, 1‑x)                     # FFT based, O(N log N)
    # 2) soft‑max weights
    w ← exp(γ·c – max(c)·γ)            # subtract max for numerical stability
    w ← w / Σ w
    # 3) gradient accumulation
    g ← zeros(N)
    for each shift s with index idx:
        weight ← w[idx]
        if s ≥ 0:
            g[:N‑s]   += weight·(1‑x[s:])
            g[s:]     += weight·(‑x[:N‑s])
        else:
            t ← –s
            g[t:]     += weight·(1‑x[:N‑t])
            g[:N‑t]   += weight·(‑x[t:])
    g ← dx·g                           # chain rule from F_γ
    # 4) step size
    α ← α_0 / sqrt(iter)
    # 5) projected update
    x_new ← project_to_sum_box( x – α·g , N/2 )
    x ← x_new
    # 6) record best (using the *true* max, not the soft‑max)
    cur_val ← dx·max(c)
    if cur_val < best_val:
        best_val ← cur_val ; best_x ← x
    # 7) temperature schedule
    if iter % epoch_len == 0 and γ < γ_max:
        γ ← min(γ·γ_factor, γ_max)
```

All operations are vectorised; a single iteration on `N=120` takes well below 1 ms on a modern CPU, so tens of thousands of iterations comfortably fit in the time budget.

### 4. Random‑restart & noise injection (exploration)

The objective is non‑convex; to avoid being trapped in a shallow basin we perform a few short restarts:

- After every `R = 5000` iterations (or when the improvement in `best_val` over the last `R` steps is < 1e‑5), **perturb** the current best solution:
  ```
  x ← best_x + normal(0, σ)   with σ = 0.02
  x ← clip(x,0,1);  x ← project_to_sum_box(x,N/2)
  ```
- Reset `γ ← γ_start` and continue the main loop from this perturbed point.
- Keep the globally best `best_x` across all restarts.

A modest number (≈3–4) of restarts suffices to explore distinct basins without sacrificing the bulk of the allotted time.

--------------------------------------------------------------------
### 5. Final discrete polishing (optional but cheap)

When the main loop finishes, `best_x` is usually fractional and already near‑optimal.  A quick *binary‑swap* refinement can sometimes shave the last few thousandths:

1. **Threshold** `best_x` at its median to obtain a binary vector `z`.
2. **Fix the sum**: if `Σz ≠ N/2`, flip the nearest values to meet the exact count.
3. **Local swap search**:
   - Repeatedly pick a random pair `(i,j)` with `z_i≠z_j`.
   - Swap them and accept the swap if the resulting `C5` (computed via a single correlation) does not increase.
   - Perform at most `3·N` attempted swaps or stop early if time runs out.

Because the binary vector lives on a much smaller combinatorial space, this cheap hill‑climbing can produce a marginal improvement without heavy optimisation.
