**1. Mathematical reformulation**

For a discretisation with `N` points (`dx = 2/N`) let  

```
h = (h0,…,hN‑1) ,  0 ≤ hi ≤ 1 ,  Σ hi = N/2 .
```

For an integer shift `k` (‑(N‑1) ≤ k ≤ N‑1)

```
ck(h) = Σi hi ( 1 – h(i+k) )                (h(j)=0 outside [0,N‑1])
```

and the quantity to minimise is  

```
C5(h) = maxk ck(h) .
```

Write  

```
ck(h) = Σi hi – Σi hi·h(i+k) .
```

The first term is linear, the second is a bilinear (product) term.
The optimisation problem is

```
min  t
s.t. Σi hi = N/2
     0 ≤ hi ≤ 1
     ck(h) ≤ t   for all k .
```

The difficulty is the non‑convex product `hi·h(i+k)`.  
We treat the product as a **concave part** and linearise it at the current iterate – a classical *convex‑concave (DC) procedure* (also called sequential linear programming, SLP).

**2. Linearisation of the bilinear term**

For a fixed shift `k` and a current point `h⁰` define

```
aik = ( h⁰i+k   if i+k < N else 0 ) + ( h⁰i‑k   if i‑k ≥ 0 else 0 )
ck_const = - Σ_{i: i+k<N} h⁰i · h⁰(i+k)               (constant)
```

Using the first‑order Taylor expansion of `hi·h(i+k)` at `h⁰`

```
hi·h(i+k) ≈ aik·hi + ck_const .
```

Consequently the *linearised* constraint for shift `k` becomes

```
Σi ( 1 – aik )·hi ≤ t + ck_const .                     (1)
```

All coefficients in (1) are known once `h⁰` is fixed, so (1) is a linear inequality.

**3. Linear programme to be solved at each SLP iteration**

Variables: `h0,…,hN‑1` (continuous) and the epigraph variable `t`.

Constraints  

* (i)   Σi hi = N/2                                         (sum constraint)  
* (ii)  0 ≤ hi ≤ 1   for all i                              (box)  
* (iii) For every shift `k = -(N‑1)…(N‑1)` the linearised inequality (1).  

Objective: minimise `t`.

Because the number of shifts is `2·N‑1` the LP has at most `2·N‑1 + N + 2` constraints, which is tiny for `N ≤ 300`. The LP is **convex** and can be solved in a few milliseconds with any open‑source LP solver available through `cvxpy` (e.g. ECOS, HiGHS, OSQP).

**5. Generation of high‑quality seeds**

A good initial point dramatically improves convergence. We use a *portfolio* of seeds:

* **Random fractional seed** – draw i.i.d. `U(0,1)`, project onto the simplex Σhi = N/2 with the fast “water‑filling” algorithm (sort once, O(N log N)).
* **Binary step‑function seed** – half‑interval of ones, the rest zeros (the classical construction).  
* **Beatty‑sequence seed** – for an irrational `α` (e.g. the golden ratio), set `hi = 1` iff `{ i·α } < 0.5`. After rounding, project to satisfy the exact sum.  
* **Two‑interval symmetric seed** – parameters `(a,b)` with `0<a<b<2`; `h=1` on `[0,a]∪[b,2]`, `0` elsewhere; the length condition `a+(2‑b)=1` leaves a single free parameter `a`. Scan `a` on a fine grid (e.g. 200 points) and keep the best.
* **Hybrid seed** – start from any of the above, then perform a short *hill‑climbing* by swapping a random `1/0` pair whenever it improves the true `C5`.

All seeds are passed through the same projection onto `[0,1]` and the sum constraint before the first SLP iteration.

  *Each trajectory* stops after a fixed maximum number of LP solves (e.g. 30) *or* when the improvement between successive `t` values falls below `1e‑6`.  
  Keep the best feasible `h` (the one with the smallest true `C5`) among all trajectories.

* **30 % of the total time** – a *fine‑grained local refinement* (see §7) starting from the best `h` obtained above.

--------------------------------------------------------------------
**7. Final local refinement (continuous simulated annealing)**

Even after SLP, the solution may be stuck in a shallow local minimum. We therefore run a classic simulated‑annealing (SA) on the *continuous* vector while respecting the box and sum constraints:

* **Move operator** – add a zero‑mean Gaussian perturbation `Δ` with small σ (e.g. 0.05) to the current `h`, then project back onto `[0,1]` and onto the hyperplane Σhi = N/2 (the same water‑filling projection).  
* **Acceptance rule** – if `C5(new) < C5(current)` accept; otherwise accept with probability `exp(-(C5(new)‑C5(current))/T)`.  
* **Temperature schedule** – start at `T0 = 0.02` (roughly the current `C5`), multiply by `α = 0.995` each iteration, never go below `1e‑6`.  
* **Termination** – stop when the allocated time expires or when no improvement has occurred for a large number of steps (e.g. 10 000).

The SA phase typically reduces the true `C5` by a few × 10⁻⁴, enough to push a 0.3809 bound below 0.3807.

--------------------------------------------------------------------
**8. Evaluation routine**

`evaluate_c5(h)` – compute the exact max‑overlap using NumPy’s `np.correlate` (full mode). This routine is called only for verification (once per LP solution and once per SA move) and therefore can be the straightforward O(N²) C implementation, which is perfectly fast for `N ≤ 300`.

--------------------------------------------------------------------
**9. Handling numerical and algorithmic pitfalls**

| Potential issue                                   | Countermeasure |
|---------------------------------------------------|----------------|
| *Infeasible LP* due to badly linearised constraints | Use a small *trust‑region*: add bounds `|hi‑hi⁰| ≤ δ` (δ≈0.2) as extra linear constraints; if LP fails, reduce δ and retry. |
| *Oscillation of iterates*                         | Apply damping (`λ`‑mix) between successive `h`. |
| *Stagnation (no improvement)*                     | Restart from a fresh seed; keep a counter of failed trajectories and switch to a more exploratory seed (e.g. Beatty). |
| *Projection rounding errors*                      | After each projection verify Σhi = N/2 (within 1e‑12) and clip any residual numerical drift. |
| *Too many LP solves in time*                      | Limit each trajectory to a modest number of LP solves (≤30) – empirical tests show most improvement occurs early. |
| *SA temperature too low/high*                     | Adapt `T0` based on the initial `C5` of the seed (`T0 = 0.1·C5`). |
| *Memory blow‑up*                                   | All data structures are tiny (`O(N²)` ≈ 1e⁴ doubles) – well within limits. |

--------------------------------------------------------------------
**10. Expected outcome**

The SLP step rapidly drives the solution from a random feasible point to a region where the worst‑case overlap is already close to the known record (≈ 0.3809). The subsequent SA polishing, operating directly on the original non‑convex objective, typically squeezes out a few × 10⁻⁴, which is sufficient to achieve a bound **≤ 0.3807**. Because the LP sub‑problems are solved exactly, each outer iteration is deterministic and inexpensive, allowing thousands of restarts within the 600 s budget.

**11. Implementation sketch (no code)**

1. **Pre‑compute shift‑index maps** – for each `k` store the pairs `(i, i+k)` that are inside the domain; this speeds up the construction of `aik`.  
2. **Projection routine** – implement the water‑filling algorithm (`O(N log N)`).  
3. **LP builder** – using `cvxpy`, declare variable vector `h` and scalar `t`; add the sum, box, and linearised shift constraints (loop over all `k`).  
4. **SLP driver** – loop as in §4, updating coefficients from the current `h`. After each LP, call `evaluate_c5` to obtain the true bound.  
5. **Seed generator** – functions for random, step, Beatty, two‑interval, hybrid.  
6. **SA driver** – simple loop that perturbs, projects, evaluates, accepts/rejects.  
7. **Time manager** – `time.time()` checkpoints to respect the overall budget (`budget_s`).  

All components use only `numpy`, `scipy` (for correlation if desired) and `cvxpy` with an open‑source LP solver, satisfying the allowed libraries.
