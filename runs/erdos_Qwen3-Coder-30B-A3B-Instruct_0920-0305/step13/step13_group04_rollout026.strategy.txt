**Goal** – Produce a step‑function `h` on `[0,2]` (discretised with `n` points) that satisfies  
`0 ≤ h[i] ≤ 1`, `∑ h[i]·dx = 1` (`dx = 2/n`) and minimises  

```
C₅ = max_k  ∫₀² h(x)·(1–h(x+k)) dx .
```

With a binary discretisation (`h[i]∈{0,1}`) the integral becomes a count:

```
C₅ = dx · max_k  ( Σ_i h[i] – Σ_i h[i]·h[i+k] )
    = dx · ( n/2 – min_k  Σ_i h[i]·h[i+k] )
```

Thus we must **maximise the smallest auto‑overlap**  

```
I_k = Σ_i h[i]·h[i+k] ,   k = –(n–1)…(n–1) .
```

The problem is combinatorial: choose exactly `n/2` indices (the support of `h`) so that the minimum of the `I_k` is as large as possible.

--------------------------------------------------------------------
### 1. Choose a convenient discretisation

*Pick `n` even, not too small (enough resolution) but not too large (so that exact integer programming remains tractable).*  

Recommended default: `n = 256` (so `dx = 2/256 = 0.0078125` and the required number of “1‑entries’’ is `n/2 = 128`).  
The chosen `n` can be reduced if the time budget proves insufficient.

--------------------------------------------------------------------
### 2. Generate a strong *structured* initial family of candidates

A large class of binary patterns with excellent “uniform intersection’’ properties is obtained by **modular arithmetic progressions** (difference‑set‑like constructions).

For any step `p` with `gcd(p,n)=1` define  

```
h_p[i] = 1   if  (i·p) mod n  < n/2
           0   otherwise         (i = 0,…,n–1)
```

Because the map `i → (i·p) mod n` is a permutation, exactly half the entries are 1.  
The pattern consists of points that are evenly spread over the circle, which tends to equalise all overlaps `I_k`.

**Procedure**

1. Loop over all `p = 1 … n‑1` with `gcd(p,n)=1` (≈ φ(n) candidates, ≈ 120 for `n=256`).
2. For each `p`, compute the correlation `corr = np.fft.ifft(fft(h_rev)·fft(1‑h))` (or `np.correlate`) and extract `C₅(p) = dx·max(corr)`.
3. Keep the best `p*` (smallest `C₅`).  

This exhaustive search is cheap: each correlation is `O(n log n)`, and with `n=256` the whole sweep finishes in a few seconds.

*Result*: a deterministic pattern `h₀` that is already competitive (often ≤ 0.382 for `n=256`).  
If the best `C₅` from this step already beats the target (≈ 0.3807) we may stop, but typically a modest improvement is still possible.

### 3. Deterministic *max‑overlap reduction* by targeted swaps

After the structured start we apply a **greedy local optimiser** that directly attacks the current worst shift.

For a given `h`:

1. Compute the full linear correlation `c = corr = convolution(h_rev, 1‑h)` and locate the shift `s` attaining the maximum (`s = argmax c`).
2. Build the “shifted‑support’’ `h_shift` needed for that `s`:
   - If `s ≥ 0`: `h_shift[i] = h[i+s]` for `i+s < n`, otherwise `0`.
   - If `s < 0`: `h_shift[i] = h[i+s]` for `i+s ≥ 0`, otherwise `0`.
3. For every index `i` the *contribution* to the worst overlap is `contrib[i] = 1 – h_shift[i]` **provided** `h[i]=1`.  
   (If `h[i]=0` it contributes nothing now.)
4. Compute:
   - `i_max` = index of a 1‑entry with the *largest* contribution (i.e. most “unmatched’’ with its partner at distance `s`).
   - `j_min` = index of a 0‑entry whose *potential* contribution (if it became a 1) is the *smallest* (`1 – h_shift[j]` minimal).
5. If `contrib[i_max] > 1 – h_shift[j_min]` then swapping `h[i_max]↔h[j_min]` **strictly reduces** the correlation at shift `s` (by at least one count). Perform the swap, recompute `c` and repeat from step 1.
6. Stop when no improving swap exists for the present worst shift.

Because each successful swap reduces the count of the current worst overlap by at least one, this loop converges after at most `n/2` successful swaps per shift, i.e. in < O(n²) operations – negligible compared with the time budget.

**Why this works:** The objective is `max_s (n/2 – I_s)`. Reducing `c(s) = n/2 – I_s` for the worst `s` directly lowers `C₅`. Swapping a “bad’’ 1 (that sees a 0 after shift `s`) with a “good’’ 0 (that would see a 1 after shift `s`) eliminates one mismatch.

### 4. Fine‑grained *local hill‑climbing* (optional)

If the greedy phase stalls but time remains, perform a **simple neighbourhood search**:

* Randomly pick a pair `(i,j)` with `h[i]=1, h[j]=0`.  
* Compute the new `C₅` after swapping (fast via the FFT).  
* Accept the swap **iff** it strictly improves the bound.  
* Iterate this “best‑improvement’’ step for a bounded number of trials (e.g. 20 000) or until the wall‑clock limit is reached.

Because each trial is cheap, this phase can harvest tiny improvements that the deterministic greedy phase cannot see (it only looks at the current worst shift).
