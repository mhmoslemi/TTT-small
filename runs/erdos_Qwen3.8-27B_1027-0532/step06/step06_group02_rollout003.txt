OK this is getting really complicated. Let me take a different approach. Instead of trying to compute the delta analytically, let me just compute it numerically for the affected positions.

For a swap (i, j), the correlation at shift k changes only if at least one of the positions {i, j, i-k, j-k} is valid (in [0, n-1] with m+k also in [0, n-1]).

The set of shifts k that are affected is:
- k such that 0 ≤ i+k < n → k ∈ [-i, n-1-i]
- k such that 0 ≤ i-k < n → k ∈ [i-(n-1), i] = [i-n+1, i]
- k such that 0 ≤ j+k < n → k ∈ [-j, n-1-j]
- k such that 0 ≤ j-k < n → k ∈ [j-n+1, j]

The union of these ranges is at most [-n+1, n-1] (the full range), but typically much smaller.

For each affected k, the delta is:
delta_k = sum over m in unique({i, j, i-k, j-k} ∩ [0,n-1] with m+k ∈ [0,n-1]):
    h_new[m]*(1-h_new[m+k]) - h_old[m]*(1-h_old[m+k])

Where h_new differs from h_old only at positions i and j.

This is at most 4 terms per k, and the number of affected k is at most 4n (union of 4 ranges each of length ≤ n). So total work is O(n) per swap.

For efficiency in the SA, I'll precompute the affected k range and iterate over it.

Actually, for n=600, the full range is 2n-1=1199 shifts. Computing the delta for all 1199 shifts in a vectorized numpy operation (as I did above) takes about 4-6 array operations of length 1199. That's fast enough.
