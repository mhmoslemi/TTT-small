```python
    # w_full = [w[0], w[1], ..., w[2n-2]] (length 2n-1)
    # 
    # A[j] = sum_{m: 0<=j+m-(n-1)<n} (1-h[j+m-(n-1)]) * w[m]
    # Let t = j + m - (n-1), so m = t - j + (n-1)

    # = corr(h, w)[lag = j-(n-1)]...

    # So B[j] = corr(h, w)[lag = (n-1)-j]...

    # n=3, h=[a,b,c], 1-h=[1-a,1-b,1-c]

    #
    # For each j, I need:
    # A[j] = sum over valid k of w[k+n-1] * (1-h[j+k])
    # B[j] = sum over valid k of w[k+n-1] * h[j-k]

    # Then A = (1-h) @ W.T and B = h @ W.T

    m_idx = np.arange(2 * n - 1)[None, :]  # (1, 2n-1)
    k_mat = m_idx - (n - 1)  # (1, 2n-1), shifts
    
    # For A[j]: valid when 0 <= j + k < n
    valid_A = (0 <= j_idx + k_mat) & (j_idx + k_mat < n)  # (n, 2n-1)
    
    # For B[j]: valid when 0 <= j - k < n
    valid_B = (0 <= j_idx - k_mat) & (j_idx - k_mat < n)  # (n, 2n-1)
    
    # A[j] = sum_m w[m] * (1-h[j+k]) * valid_A[j,m]
    # = sum_m w[m] * (1-h[j+k_mat[m]]) * valid_A[j,m]
    
    # I can create (1-h) indexed appropriately:
    # a_val[j,m] = (1-h[j+k]) if valid_A[j,m] else 0
    idx_a = np.where(valid_A, j_idx + k_mat, 0)  # (n, 2n-1)
    a_val = (1.0 - h)[idx_a] * valid_A  # (n, 2n-1)
    
    # b_val[j,m] = h[j-k] if valid_B[j,m] else 0
    idx_b = np.where(valid_B, j_idx - k_mat, 0)
    b_val = h[idx_b] * valid_B
    
    # A = a_val @ w  (n, 2n-1) @ (2n-1,) = (n,)
    # B = b_val @ w
    grad = (a_val @ w - b_val @ w) / beta
    
    if penalty > 0:
        grad += penalty * (np.sum(h) - target)
    
    return grad
```

This creates matrices of size n × (2n-1) = 606 × 1211 ≈ 734K entries. Each entry is a float (8 bytes), so about 6MB per matrix. We create 4 such matrices (valid_A, idx_a, a_val, valid_B, idx_b, b_val), so about 24MB total. That's fine.

The matrix-vector products a_val @ w and b_val @ w are each O(n²) ≈ 734K operations, which is fast.

The total gradient computation is O(n²) with a small constant, which should take maybe 5-10ms per call. With 200 L-BFGS iterations, that's 1-2 seconds per L-BFGS run.
