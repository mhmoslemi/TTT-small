= δ[h[i-k] - h[j+k] - h[i] + h[j]] + δ²

Since j = i+k, h[j] = h[i+k]:
= δ[h[i-k] - h[i+2k] - h[i] + h[i+k]] + δ²

And change[i,k] = (1-h[i+k]) - h[i-k] = 1-h[i+k]-h[i-k]
change[j,k] = (1-h[j+k]) - h[j-k] = (1-h[i+2k]) - h[i]

change[j,k] - change[i,k] = 1-h[i+2k]-h[i] - 1+h[i+k]+h[i-k] = h[i+k]+h[i-k]-h[i+2k]-h[i]

So the linear part matches! But there's an extra δ² term.

So the key issue is: when |i-j| = |k|, the change is NOT exactly linear - there's a quadratic term δ².

In the code's `compute_change_matrix`, the change is computed as:
```
change[p, pos_mask] += (1.0 - h[p + shifts[pos_mask]])
change[p, neg_mask] -= h[p - shifts[neg_mask]]
```

This gives change[p, k] = (1-h[p+k]) - h[p-k] (with boundary conditions), which is exactly the linear coefficient. The δ² term is ignored.

For the bisection to work correctly, we need the objective to be convex in δ (for the specific pair). When there's a δ² term, the function corr[k] + δ*(change[j,k]-change[i,k]) is no longer the exact value of the new correlation.

However, for small δ, the approximation is good. And for the bisection, we're finding the δ that minimizes the max, so if the true function is slightly different from the linear approximation, the bisection might not find the true optimum.

But in practice, the δ values found are usually small (since we're near a local optimum), so the approximation is good enough.
