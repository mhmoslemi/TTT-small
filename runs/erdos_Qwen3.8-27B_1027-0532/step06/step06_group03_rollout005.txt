- 0 ≤ j-s < n → s ∈ [j-(n-1), j] → k ∈ [j, n-1+j]

```python
        if delta_max <= 0 or rng.random() < np.exp(-delta_max / T):
            # Accept
            for k, v in new_vals.items():
                corr[k] = v
            h[i] = 0
            h[j] = 1
            current_max = new_max
            # Update position lists
            one_list[ii] = j  # i was 1, now 0; j was 0, now 1
            zero_list[jj] = i
            if current_max < best_max:
                best_max = current_max
                best_h = h.copy()
                no_improve = 0
            else:
                no_improve += 1
        else:
            # Reject: undo count changes
            for k, v in new_vals.items():
                count[v + offset] -= 1
            for k, v in old_vals.items():
                count[v + offset] += 1
            no_improve += 1
        
        T *= alpha_cool
        if T < Tf:
            T = Tf
            if no_improve > 10000:
                break
    
    return best_h, best_max * dx
```

Hmm, this is getting complex and the Python loops might be slow. Let me think of a faster approach.

For n=400, the full correlation has 799 values. Computing it from scratch with np.correlate is O(n²) = 160K operations, which in numpy takes maybe 50-100μs. The overhead of the Python function call and array allocation adds maybe another 20-50μs. So total ~100-150μs per evaluation.

At 1300 seconds, I can do about 8-13 million evaluations. That's plenty for SA.
