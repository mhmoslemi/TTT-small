def adam_step(h, grad, lr, beta1, beta2, eps, m, v, t):
    m = beta1 * m + (1 - beta1) * grad
    v = beta2 * v + (1 - beta2) * grad ** 2
    m_hat = m / (1 - beta1 ** t)
    v_hat = v / (1 - beta2 ** t)
    h_new = h - lr * m_hat / (np.sqrt(v_hat) + eps)
    return h_new, m, v

        else:

def compute_smooth(h, alpha):
    n = len(h)
    dx = 2.0 / n
    c = np.correlate(h, 1.0 - h, mode='full') * dx
    c_max = np.max(c)
    shifted = c - c_max
    max_shifted = 0.0

    w = exp_c / exp_c.sum()

def compute_grad(h, w, dx):
    n = len(h)
    k_vals = np.arange(-(n-1), n)
    p = np.arange(n)[:, None].astype(np.int64)
    k = k_vals[None, :].astype(np.int64)
    
    pk = p + k
    valid_f = (pk >= 0) & (pk < n)
    pk_clipped = np.clip(pk, 0, n-1)
    first = np.where(valid_f, 1.0 - h[pk_clipped], 0.0)
    
    pk2 = p - k
    valid_s = (pk2 >= 0) & (pk2 < n)
    pk2_clipped = np.clip(pk2, 0, n-1)
    second = np.where(valid_s, h[pk2_clipped], 0.0)
    
    grad = dx * (first.T @ w - second.T @ w)
    return grad

Let me think about a fundamentally different approach:

**Approach: Direct minimax with bisection on C**

For a given C, the question "is there an h with max_k c_k ≤ C?" is a feasibility problem. We can solve it using:
- Nonlinear programming (the constraints are quadratic)
- Or: iterate "for each lag k, push c_k down" (cyclical coordinate descent)

The bisection approach:
1. Start with C_low = 0.3, C_high = 0.4
2. For C_mid = (C_low + C_high) / 2:
   a. Try to find h with max_k c_k ≤ C_mid
   b. If found, C_high = C_mid; else C_low = C_mid
3. Return C_high as the bound

For step (a), we can use a penalty method:
Minimize sum_k max(0, c_k - C_mid)² + λ * (sum(h) - n/2)² + μ * sum(max(0, -h_i)² + max(0, h_i-1)²)

This is a quadratic (well, quartic due to max) program that can be solved with gradient methods.

Actually, this is essentially the same as what the smooth max approach does, just with a different smooth approximation. The smooth max (softmax) is actually better because it directly approximates the max.

Let me try yet another angle: **what if I use a coarser representation and then optimize the "boundary" points?**

The idea: the optimal h is likely close to binary (0 or 1) with transitions at a few points. If I can identify the "active" points (where 0 < h_i < 1), I can optimize just those while keeping the rest at 0 or 1.

This is a combinatorial + continuous optimization problem, which is hard. But I can use the following heuristic:
1. Start with a binary solution
2. Identify the "boundary" points (where h changes from 0 to 1 or vice versa)
3. Allow fractional values at boundary points
4. Optimize the fractional values

This reduces the effective dimensionality from n to O(number of boundaries) ≈ O(sqrt(n)) or so.

But implementing this is complex. Let me stick with the full optimization approach but make it more effective.

**Key insight I've been missing**: The previous code's gradient descent was computing the gradient of a SMOOTH approximation to the max. But the smooth approximation's gradient can be very different from the true gradient of the max (especially when multiple lags are close to the max). 

A better approach: use the **exact** subgradient of the max. At the optimum, the subgradient of max(c) is (1/K) * sum_{k in argmax} grad(c_k), where K = |argmax|. But away from the optimum, we don't know which lags will be in argmax.

The softmax approach approximates this by weighting all lags proportionally to exp(alpha * (c_k - c_max)). As alpha → ∞, this converges to the uniform distribution over argmax. For finite alpha, it gives a smooth approximation.

I think the key issue is: **the alpha needs to be large enough** that the gradient is dominated by the top few lags, but **not so large** that numerical issues arise.

import numpy as np

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    c = np.correlate(h, 1.0 - h, mode='full') * dx
    return float(np.max(c))

def project_feasible(h, target):
    lo = -2.0
    hi = 2.0
    for _ in range(50):
        mid = (lo + hi) * 0.5
        s = np.clip(h + mid, 0.0, 1.0).sum()
        if s < target:
            lo = mid
        else:
            hi = mid
    return np.clip(h + (lo + hi) * 0.5, 0.0, 1.0)

def compute_smooth_and_c5(h, alpha):
    n = len(h)
    dx = 2.0 / n
    c = np.correlate(h, 1.0 - h, mode='full') * dx
    c_max = float(np.max(c))
    shifted = c - c_max
    exp_c = np.exp(alpha * shifted)
    exp_sum = exp_c.sum()
    w = exp_c / exp_sum
    smooth_val = c_max + np.log(exp_sum) / alpha
    k_vals = np.arange(-(n - 1), n, dtype=np.int64)
    p = np.arange(n, dtype=np.int64)[:, None]
    k = k_vals[None, :]
    pk = p + k
    valid_f = (pk >= 0) & (pk < n)
    pk_clipped = np.clip(pk, 0, n - 1)
    first = np.where(valid_f, 1.0 - h[pk_clipped], 0.0)
    pk2 = p - k
    valid_s = (pk2 >= 0) & (pk2 < n)
    pk2_clipped = np.clip(pk2, 0, n - 1)
    second = np.where(valid_s, h[pk2_clipped], 0.0)
    grad = dx * (first.T @ w - second.T @ w)
    return c_max, smooth_val, grad
