For coordinate descent, the key insight is: for a fixed set of all other coordinates, C5 as a function of h[i] is the max of a set of linear functions (since each corr[k] is linear in h[i] when all other h[j] are fixed... wait, no, corr[k] is bilinear, so for fixed h[j≠i], corr[k] is linear in h[i]).

So C5(h[i]) = max_k (a_k * h[i] + b_k) where a_k and b_k depend on the other coordinates. This is a piecewise linear function of h[i], and we want to find h[i] ∈ [0,1] that minimizes it. The minimum occurs at a breakpoint or at the boundary.

The breakpoints occur where two of the functions a_k * h[i] + b_k are equal. There are O(n) such breakpoints (one for each pair, but actually O(n) distinct breakpoints since we only need the "upper envelope").

For practical purposes, we can:
1. Compute all a_k and b_k values
2. Find the upper envelope (min of C5)
3. The optimal h[i] is at one of the breakpoints or boundaries

This is an exact coordinate optimization! And it's O(n log n) per coordinate (to find the upper envelope).

For n=90, this means each coordinate update is O(90 log 90) ≈ O(600), and a full sweep is O(90 * 600) = O(54000). Very fast!

```python
def coord_descent_sweep(h, target_sum, rng, time_limit, start_time):
    """One phase of coordinate descent with periodic projection."""
    n = len(h)
    dx = 2.0 / n
    best_h = h.copy()
    best_c5 = compute_c5(h)
    
    for sweep in range(10000):
        if time.time() - start_time > time_limit:
            break
        
        # Compute correlations
        corr = np.correlate(h, 1.0 - h, mode='full') * dx
        
        # Random order
        order = rng.permutation(n)
        for i in order:
            # Compute a[j] for all j
            a = np.zeros(2 * n - 1)
            for j in range(2 * n - 1):
                k = j - (n - 1)
                coeff = 0.0
                if 0 <= i - k <= n - 1:
                    coeff += (1.0 - h[i - k])
                if 0 <= i + k <= n - 1:
                    coeff += (-h[i + k])
                a[j] = coeff * dx
            
            b = corr - a * h[i]
            x_opt, _ = optimal_coord_value(a, b)
            
            # Update
            delta = x_opt - h[i]
            h[i] = x_opt
            corr += delta * a
        
        # Project at end of sweep
        h = project_to_box_and_sum(h, target_sum)
        c5 = compute_c5(h)
        if c5 < best_c5:
            best_c5 = c5
            best_h = h.copy()
    
    return best_h, best_c5
```

Wait, but after projection, the correlation vector `corr` is stale (it doesn't match the projected h). I need to recompute it at the start of each sweep, which I'm doing. Good.

But there's a subtlety: during the sweep, I'm updating `corr` incrementally, but h is being changed. After the sweep, I project h, which changes all coordinates. So the next sweep starts with a fresh correlation computation. This is correct.

The issue: during the sweep, after many coordinate updates, h might be far from the constraint set (sum ≠ target_sum). The coordinate optimization is solving the wrong problem (minimizing C5 over [0,1]^n without the sum constraint). This might lead to a poor solution after projection.

To mitigate: I can do the projection more frequently (every 10 coordinates, for example) or use a Lagrange multiplier approach.

Actually, let me think about this differently. The problem with the sum constraint is that it's a single linear constraint. The effect of the constraint on the coordinate optimization is:
- If I change h[i] by delta, the sum changes by delta
- To maintain the sum, I'd need to change some other coordinate by -delta
- This is complicated to track
