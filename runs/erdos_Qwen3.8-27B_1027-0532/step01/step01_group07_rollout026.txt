This is a linear programming problem in 1D! The optimal h[i] is at the point where the maximum of the lines a_k * h[i] + b_k is minimized, which is at an intersection of two of the lines (or at a boundary).

This is a "minimax" 1D problem with piecewise linear objective. It can be solved in O(n) time by finding the point where the upper envelope transitions.

For a given pair (i,j) with h[i] + h[j] = s (fixed), parameterize by t = h[i], so h[j] = s - t.

The constraint: 0 ≤ t ≤ 1 and 0 ≤ s-t ≤ 1, so max(0, s-1) ≤ t ≤ min(1, s).

The minimum of the maximum of linear functions is at a "breakpoint" where two of the lines cross, or at a boundary.

This can be found by:
1. Evaluating all g_k at t = 0 and t = 1 (and the boundaries)
2. Finding the t where the "upper envelope" has its minimum

A simple approach: use ternary search or golden section search on t. Since the objective is convex in t (max of linear functions is convex), this will work.

def coord_descent_2var(h, i, j, n):
    """Optimize h[i] and h[j] given h[k] for k != i, j is fixed."""
    s = h[i] + h[j]
    lo = max(0.0, s - 1.0)
    hi = min(1.0, s)
    
    def obj(t):
        h_new = h.copy()
        h_new[i] = t
        h_new[j] = s - t
        return compute_c5(h_new)
    
    # Golden section search
    gr = (np.sqrt(5) - 1) / 2  # golden ratio
    a, b = lo, hi
    c = b - gr * (b - a)
    d = a + gr * (b - a)
    fc = obj(c)
    fd = obj(d)
    
    for _ in range(50):
        if fc < fd:
            b = d
            d = c
            fd = fc
            c = b - gr * (b - a)
            fc = obj(c)
        else:
            a = c
            c = d
            fc = fd
            d = a + gr * (b - a)
            fd = obj(d)
    
    t_opt = (a + b) / 2
    h[i] = t_opt
    h[j] = s - t_opt
    return h

- (0,0), (0,1), (1,0), (1,1) - but only those that satisfy the sum constraint

Wait, in the binary case with sum constraint, the pair (i,j) can only take values that are compatible with the sum. If h[i]=1, h[j]=0, the possible pairs are (1,0), (0,1), (0,0)+compensate, (1,1)+compensate. The last two require changing another coordinate, so they're not valid 2-variable moves.

So for binary coordinate descent, the only valid 2-variable move is: swap (1,0) ↔ (0,1). This is a "1-swap" move.

For each pair (i,j) where {h[i],h[j]} = {0,1}:
- Current state: (1,0) or (0,1)
- Try the other state: (0,1) or (1,0)
- Accept if it improves

This is much simpler than the continuous case. And it's very fast since we only need to evaluate one alternative per pair.
