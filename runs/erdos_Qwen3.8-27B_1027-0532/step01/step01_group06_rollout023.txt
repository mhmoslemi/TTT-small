For coordinate descent, the objective for fixing all except h[i] is:
min_{u ∈ [0,1]} max_k (base_k + a_k * u)

where a_k is the coefficient of h[i] in corr[k], and base_k = corr[k] - a_k * h[i]_current.

This is a 1D convex minimization problem. The optimal u is where the subgradient of max_k(base_k + a_k*u) contains 0, i.e., where 0 is in the convex hull of {a_k : base_k + a_k*u = max}.

We can solve this by:
1. Compute all values base_k + a_k*u for u=0 and u=1
2. Find the active set at u=0 and u=1
3. The optimal u is where the "upper envelope" changes slope through 0

Actually, a simpler approach: the function f(u) = max_k (base_k + a_k*u) is convex piecewise-linear in u. Its minimum over [0,1] is at:
- u=0 if f'(0+) ≥ 0
- u=1 if f'(1-) ≤ 0  
- Otherwise, at the point where f'(u) = 0, which is where the active set changes

We can find this by:
1. Sort the lines by their value at u=0: order by base_k
2. The upper envelope starts with the line with max base_k
3. As u increases, lines with higher slope overtake
4. The minimum of the envelope is where the slope changes from negative to positive

This is essentially finding the tangency point. For 2n-1 ≈ 169 lines, we can just evaluate f(u) at many points and do a ternary search, or more efficiently:

The slope of f(u) at any point is the max of slopes among active lines (those achieving the max). So:
- f'(u) = max{a_k : base_k + a_k*u = max_j(base_j + a_j*u)}

The minimum is where f'(u) crosses 0. Since f is convex, f' is non-decreasing. So we can binary search on f'(u) = 0.

To compute f'(u): find all k such that base_k + a_k*u = max_j(base_j + a_j*u), then return max(a_k for those k).

Let me also think about the LSE (log-sum-exp) temperature. The LSE approximation to max is:
max_k c_k ≈ T * log(sum_k exp(c_k/T))

As T → 0, this approaches the true max. But for optimization, we need T large enough for the function to be smooth. The optimal T depends on the "spread" of the c_k values. If the max is at a single point (sharp peak), we need small T. If it's flat (many near-max), larger T is fine.

Strategy: start with large T (smooth landscape), decrease T gradually.

For L-BFGS-B, I need to provide the gradient of the LSE objective:
∂/∂h[i] of T*log(sum_k exp(corr[k]/T)) = T * (1/sum_k exp(corr[k]/T)) * sum_k exp(corr[k]/T) * (1/T) * ∂corr[k]/∂h[i]
= (sum_k exp(corr[k]/T) * ∂corr[k]/∂h[i]) / sum_k exp(corr[k]/T)
= sum_k w_k * ∂corr[k]/∂h[i] where w_k = exp(corr[k]/T) / sum_j exp(corr[j]/T)

This is the weighted average of the gradients, with weights proportional to softmax(corr/T).

∂corr[k]/∂h[i] is the coefficient we computed earlier (a_k(i) in the coordinate descent).

So the gradient of the LSE objective is the weighted sum of the "coefficient vectors", where the weights are softmax of the correlations.

This can be computed efficiently:
1. Compute all correlations: O(n²) (actually O(n) since it's just a correlation)
2. Compute weights: O(n)
3. Compute weighted sum of gradient vectors: O(n²) (for each lag, add weighted gradient)

Total: O(n²) per gradient evaluation. For n=85, that's ~7225 operations. L-BFGS-B might need a few hundred iterations, so total ~2-3 million operations. Very fast!

def all_corrs(h):
    return np.correlate(h, 1.0 - h, mode='full')

def project_feasible(x):
    n = len(x)
    target = n / 2.0
    lo, hi = -10.0, 10.0
