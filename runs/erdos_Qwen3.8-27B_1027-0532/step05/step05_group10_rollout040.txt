    diff = target_sum - np.sum(h)
    if abs(diff) < 1e-14:
        return h

        return h

        else:

        if len(idx2) > 0:
            h[idx2] += residual / len(idx2)
            h = np.clip(h, 0.0, 1.0)

So maybe 4-8ms of overhead + computation. Total per pass: maybe 50-100ms. That's 10-20 passes per second. In 600 seconds: 6000-12000 passes. Should be enough.

2. The ternary search might not be the most efficient. An alternative is to find the exact minimum of the piecewise-linear function. The minimum of max_k (C_k + v*A_k*dx) occurs at a point where two lines intersect (or at v=0 or v=1). We can find this by:
   - Computing all intersection points of pairs of lines
   - Filtering to [0,1]
   - Evaluating f at each candidate
   But this is O(n_lags^2) which is ~640,000 - too slow per coordinate.
   
   Alternative: since f is piecewise linear and convex, the minimum is where the subgradient contains 0. We can use a "bisection on the subgradient" approach:
   - At v, compute the set of active k (those achieving the max)
   - If all active A_k*dx > 0, minimum is to the left
   - If all active A_k*dx < 0, minimum is to the right
   - If there are both positive and negative, we're at the minimum (or need to check)
   
   This is essentially what ternary search does, but might converge faster in practice.

   Let me stick with ternary search for simplicity. 40 iterations gives precision (2/3)^40 ≈ 4e-7 which is more than enough.
