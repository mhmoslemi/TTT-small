They're related by: corr[k] = sum_n h[n+k]*(1-h[n]) = sum_m h[m]*(1-h[m-k]) (with m=n+k)

And the "overlap at lag k" = sum_j h[j]*(1-h[j+k])

These are different! The overlap at lag k uses h[j] and h[j+k], while corr[k] uses h[n+k] and h[n].

The overlap at lag k is actually corr[-k] (negative lag):
corr[-k] = sum_n h[n-k]*(1-h[n]) for valid n
= sum_m h[m]*(1-h[m+k]) for m = k,...,N-1
= sum_{j=0}^{N-1-k} h[j+k]*... no wait.

Let me be very precise.

np.correlate(a, v, mode='full') is defined as:
c[k] = sum_n a[n+k] * conj(v[n])

where the sum is over all n such that both a[n+k] and v[n] are defined.

With a = h and v = 1-h:
c[k] = sum_n h[n+k] * (1-h[n])

For k = 0: c[0] = sum_n h[n]*(1-h[n])
For k = 1: c[1] = sum_{n=0}^{N-2} h[n+1]*(1-h[n])
For k = -1: c[-1] = sum_{n=1}^{N-1} h[n-1]*(1-h[n])

Now, the "overlap at lag k" (as defined in the problem) is:
overlap(k) = ∫ h(x)(1-h(x+k)) dx

In discrete form: overlap(k) ≈ dx * sum_{j=0}^{N-1-k} h[j] * (1-h[j+k]) for k ≥ 0

Let's compare with c[k]:
c[k] = sum_{n=0}^{N-1-k} h[n+k] * (1-h[n])

These are different! overlap(k) has h[j] * (1-h[j+k]) while c[k] has h[n+k] * (1-h[n]).

Note that:
overlap(k) = sum_j h[j]*(1-h[j+k]) = sum_j h[j] - sum_j h[j]*h[j+k]
c(k) = sum_n h[n+k]*(1-h[n]) = sum_n h[n+k] - sum_n h[n+k]*h[n]

For binary h: overlap(k) = (number of ones in h[0:N-k]) - (number of positions j where both h[j]=1 and h[j+k]=1)
c(k) = (number of ones in h[k:N]) - (number of positions n where both h[n+k]=1 and h[n]=1)

The "number of positions where both h[j]=1 and h[j+k]=1" is the same in both (it's the same set of pairs, just indexed differently).

But the first terms differ: overlap(k) counts ones in h[0:N-k] while c(k) counts ones in h[k:N].

For a "well-mixed" h, both are approximately (N-k)/2, so they'd be similar. But in general they're different.

Now, the evaluation in the code is:
```python
C₅ = max(np.correlate(h, 1-h, mode="full") * dx)
```

This takes the max over ALL lags (from -(N-1) to N-1). So it includes both the "overlap" at positive k and the "overlap" at negative k.

For the negative lags: c[-k] = sum_n h[n-k]*(1-h[n]) = sum_m h[m]*(1-h[m+k]) for m=k,...,N-1

This is exactly the "overlap at lag k"! So c[-k] = overlap(k) for k > 0.

And c[k] = sum_n h[n+k]*(1-h[n]) which is a "reversed" version.

So the max over all c[k] includes:
- c[0] = overlap(0)
- c[k] for k>0: a "reversed" overlap
- c[-k] for k>0: the actual overlap at lag k

The max might be achieved at either a positive or negative lag index in the output.

In any case, the code just takes max over all 2N-1 values, so I should do the same.

                       lr_decay=0.997, deadline=None):

    best_h = h_cur.copy()
    best_score = compute_c5(h_cur)
    dx = 2.0 / n
    lr = lr_init
    for step in range(n_steps):
        if deadline is not None and time.time() > deadline:
            break
        corr = compute_corr(h_cur)
        over = corr[n - 1:n - 1 + n]
        c_curr = float(np.max(over)) * dx
        if c_curr < best_score:
            best_score = c_curr
            best_h = h_cur.copy()
        top_idx = np.argsort(over)[::-1][:n_active]
        diffs = over[top_idx] - over[top_idx[0]]
        weights = np.exp(diffs / 0.003)
        weights /= weights.sum()
        grad = np.zeros(n)
        for wk, k in zip(weights, top_idx):
            k = int(k)
            j_pos = np.arange(0, n - k)
            grad[j_pos] += wk * (1.0 - h_cur[j_pos + k])
            j_neg = np.arange(k, n)
            grad[j_neg] -= wk * h_cur[j_neg - k]
        grad *= dx
        h_new = h_cur - lr * grad
        h_new = project_feasible(h_new, target)
        sc_new = compute_c5(h_new)
        if sc_new < c_curr:
            h_cur = h_new

    return best_h, best_score
