Let me try the step-function parameterization approach. The idea is:

The key challenge is evaluating the objective: for a given step function, compute max_k c(k) where c(k) = ∫_0^{2-k} h(x)h(x+k) dx... wait, c(k) = ∫ h(x)(1-h(x+k)) dx.

For a step function, this integral can be computed exactly by breaking it into sub-intervals where both h(x) and h(x+k) are constant.

Let me code this up:

```python
def step_corr(h_vals, breakpoints, k):
    # h_vals: values on each interval
    # breakpoints: [x_0, x_1, ..., x_m] where x_0=0, x_m=2
    # k: the lag
    # Compute ∫_0^{2-k} h(x)(1-h(x+k)) dx
    m = len(h_vals) - 1
    total = 0.0
    for i in range(m):
        x_start = breakpoints[i]
        x_end = breakpoints[i+1]
        # h(x) = h_vals[i+1] on [x_start, x_end)
        # h(x+k) is constant on [x_start, x_end) ∩ [0, 2-k) shifted by -k
        # We need to find which intervals of h(x+k) overlap with [x_start, x_end) ∩ [0, 2-k)
        a = max(x_start, 0.0)
        b = min(x_end, 2.0 - k)
        if a >= b:
            continue
        # On [a, b), h(x) = h_vals[i+1]
        # h(x+k) is determined by which interval contains x+k
        # x+k ranges from a+k to b+k
        for j in range(m):
            ya = breakpoints[j]
            yb = breakpoints[j+1]
            # Intersection of [a+k, b+k] with [ya, yb]
            lo = max(a + k, ya)
            hi = min(b + k, yb)
            if lo < hi:
                total += (hi - lo) * h_vals[i+1] * (1.0 - h_vals[j+1])
    return total
```

This is O(m²) per evaluation, and we need to evaluate for many k values. With m=20 and 1000 k values, that's 20² · 1000 = 400,000 operations, which is fast.

But actually, we can do better. For a step function, c(k) is piecewise linear in k, with breakpoints at the positions where x+k crosses a breakpoint of h. So c(k) has at most 2m breakpoints in [0, 2], and the maximum occurs at one of these breakpoints or at the endpoints.

So we only need to evaluate c(k) at O(m) points!

The breakpoints of c(k) occur when k = x_j - x_i for some pair of breakpoints (x_i, x_j). There are at most m² such values, but many will be outside [0, 2].

So the algorithm is:
1. Collect all values k = x_j - x_i for all pairs (i,j) with 0 ≤ x_j - x_i ≤ 2
2. Also include k = 0 and k = 2
3. Evaluate c(k) at each of these points
4. The max is the maximum of these values

This gives us an exact way to compute the max for a step function!

Let me refine this. The breakpoints of c(k) = ∫_0^{2-k} h(x)(1-h(x+k)) dx occur at:
- k = 0 (start)
- k = 2 (end, where the integral becomes 0)
- k = x_j - x_i for any pair of breakpoints where the "active" set of intervals changes

More precisely, as k increases from 0 to 2:
- The integration range [0, 2-k] shrinks from the right
- The function h(x+k) shifts, so the "active" interval for h(x+k) changes when x+k crosses a breakpoint, i.e., when k = x_j - x for some breakpoint x_j and some x in the current integration range

The set of critical k values is: {x_j - x_i : i, j = 0, ..., m, 0 ≤ x_j - x_i ≤ 2}

This is at most (m+1)² values, but we can filter to those in [0,2].

For m = 20, that's at most 441 values, which is very manageable.

Let me code this up properly:

```python
def step_max_corr(h_vals, bps):
    """
    h_vals: array of length m, values on m intervals
    bps: array of length m+1, breakpoints [0, ..., 2]
    Returns max_k c(k) where c(k) = ∫_0^{2-k} h(x)(1-h(x+k)) dx
    """
    m = len(h_vals)
    # Collect critical k values
    crit = {0.0, 2.0}
    for i in range(m + 1):
        for j in range(m + 1):
            k = bps[j] - bps[i]
            if 0.0 <= k <= 2.0:
                crit.add(round(k, 12))  # Round to avoid floating point issues
    crit = sorted(crit)
    
    max_val = 0.0
    for k in crit:
        if k >= 2.0 - 1e-12:
            continue
        val = 0.0
        # Compute c(k) = ∫_0^{2-k} h(x)(1-h(x+k)) dx
        for i in range(m):
            # h(x) = h_vals[i] on [bps[i], bps[i+1])
            a = max(bps[i], 0.0)
            b = min(bps[i+1], 2.0 - k)
            if a >= b:
                continue
            # On [a, b), h(x+k) is determined by which interval contains x+k
            for j in range(m):
                # x+k is in [a+k, b+k]
                # Intersection with [bps[j], bps[j+1])
                lo = max(a + k, bps[j])
                hi = min(b + k, bps[j+1])
                if lo < hi:
                    val += (hi - lo) * h_vals[i] * (1.0 - h_vals[j])
        max_val = max(max_val, val)
    return max_val
```

This is O(m² · |crit|) = O(m⁴) in the worst case. For m=20, that's 160,000, which is fine.

Minimize step_max_corr(h_vals, bps)
Subject to:

- 0 < bps[1] < bps[2] < ... < bps[m-1] < 2
- 0 ≤ h_vals[i] ≤ 1

The variables are: bps[1], ..., bps[m-1] (m-1 variables) and h_vals (m variables), total 2m-1 variables with 1 equality constraint.

For m = 15, that's 29 variables. Very manageable for SLSQP!

```python
def step_function_objective(params, m):
    """
    params: array of length 2*m-1
    First m-1: breakpoints bps[1], ..., bps[m-1]
    Next m: heights h[0], ..., h[m-1]
    """
    bps = np.zeros(m + 1)
    bps[0] = 0.0
    bps[-1] = 2.0
    bps[1:-1] = params[:m-1]
    h = params[m-1:]
    
    # Compute critical k values
    crit_ks = set()
    crit_ks.add(0.0)
    for i in range(m + 1):
        for j in range(i + 1, m + 1):
            k = bps[j] - bps[i]
            if 0.0 <= k <= 2.0:
                crit_ks.add(k)
    crit_ks = np.array(sorted(crit_ks))
    
    # Evaluate c(k) at each critical k
    c_vals = np.zeros(len(crit_ks))
    for idx, k in enumerate(crit_ks):
        if k >= 2.0 - 1e-12:
            c_vals[idx] = 0.0
            continue
        val = 0.0
        for i in range(m):
            a = max(bps[i], 0.0)
            b = min(bps[i+1], 2.0 - k)
            if a >= b:
                continue
            for j in range(m):
                lo = max(a + k, bps[j])
                hi = min(b + k, bps[j+1])
                if lo < hi:
                    val += (hi - lo) * h[i] * (1.0 - h[j])
        c_vals[idx] = val
    
    # Soft-max
    alpha = 1000.0
    c_max = np.max(c_vals)
    shifted = alpha * (c_vals - c_max)
    shifted = np.clip(shifted, -700, 0)
    soft_max = c_max + np.log(np.sum(np.exp(shifted))) / alpha
    
    return soft_max
```

But we can optimize: instead of looping over all m² pairs for each k, we can use the fact that for a given k, the mapping x → x+k shifts the grid, and we can compute the overlap more efficiently.

Actually, for a step function, c(k) can be computed in O(m) time if we're clever. The key observation is that as x goes from 0 to 2-k, h(x) takes m values (one per interval), and h(x+k) also takes m values. The product h(x)(1-h(x+k)) is constant on the intersection of an interval of h(x) and a shifted interval of h(x+k). The number of such intersections is at most 2m-1 (since we're overlaying two step functions).

So c(k) can be computed in O(m) time, and the total over all critical k values is O(m³). For m=20, that's 8000. Much better!

Let me implement this:

```python
def step_c_at_k(h, bps, k):
    """Compute c(k) = ∫_0^{2-k} h(x)(1-h(x+k)) dx for a step function."""
    m = len(h)
    if k <= 0:
        return 0.0
    if k >= 2.0:
        return 0.0
    
    total = 0.0
    # The function h(x) changes at bps[1:-1]
    # The function h(x+k) changes at bps[j] - k for j = 1, ..., m-1
    # Combined breakpoints: bps and bps[1:-1] - k, restricted to [0, 2-k]
    
    # Actually, let's just do the O(m²) approach for simplicity
    # It's fast enough for m ≤ 30
    for i in range(m):
        a = bps[i]
        b = bps[i + 1]
        # Clamp to [0, 2-k]
        a = max(a, 0.0)
        b = min(b, 2.0 - k)
        if a >= b:
            continue
        # h(x) = h[i] on [a, b]
        # h(x+k) varies: x+k ranges from a+k to b+k
        # Find which intervals of h contain x+k
        for j in range(m):
            lo = max(a + k, bps[j])
            hi = min(b + k, bps[j + 1])
            if lo < hi:
                total += (hi - lo) * h[i] * (1.0 - h[j])
    return total
```

OK this is O(m²) per k, and we have O(m²) values of k, so O(m⁴) total. For m=20, m⁴=160000, which is fine.
