   - Periodically project onto sum(h) = n/2
   - Repeat until no improvement or time runs out

3. **Phase 3: Paired coordinate descent**
   - For pairs (i, j) where i is "too high" and j is "too low":
     - Try to transfer mass from i to j
     - This maintains the sum constraint automatically
   
4. **Phase 4: SLSQP polish** (as before)

Let me now think about the constraint handling more carefully. 

For the coordinate descent, if we change h[i] from its current value to a new value, the sum changes. We need to compensate by changing another coordinate or by projecting.

**Option A**: After each full sweep of coordinate descent, project onto sum(h) = n/2.
- Project: find the closest point in [0,1]^n with sum = n/2
- This is a simple water-filling problem

**Option B**: Paired moves - always change two coordinates at a time.
- More expensive but maintains feasibility
- Choose pairs based on "pressure" (which coordinates would most benefit from being adjusted)

I'll go with Option A for simplicity, combined with some paired moves.

Now, let me also think about the **pressure objective** for SA. Instead of minimizing the max, we minimize:
P(β) = (1/β) * log(sum_k exp(β * corr_k))

For large β, this approximates the max. For smaller β, it gives a "softer" objective that's easier to optimize with SA.

The beauty of this is that its gradient is well-defined everywhere (unlike the max function), which helps SA make better moves.
