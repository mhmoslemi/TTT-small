def lp_linearize_step(h0, beta=1.0, method='highs'):
    """One step of LP linearization to minimize max overlap."""
    n = len(h0)
    dx = 2.0 / n
    target = n / 2.0
    
    # Compute current overlaps and gradients for all lags
    corr = compute_corr(h0)  # length 2n-1, index n-1 is lag 0
    n_full = 2 * n - 1
    
    # Build LP
    # Variables: h[0..n-1], t => n+1 variables
    # Objective: minimize t => c = [0,...,0, 1]
    c = np.zeros(n + 1)
    c[-1] = 1.0
    
    # Inequality constraints: for each lag k, grad_k · h - t ≤ val_k - grad_k · h0
    A_ub_rows = []
    b_ub_vals = []
    
    for idx in range(n_full):
        k = idx - (n - 1)  # actual lag
        val_k = corr[idx]
        
        # Compute gradient of O(k) at h0
        grad = np.zeros(n)
        if k == 0:
            grad[:] = dx * (1.0 - 2.0 * h0)
        elif k > 0:
            # O(+k) = dx * sum_{i=0}^{n-1-k} h[i+k]*(1-h[i])
            for j in range(k, n):
                grad[j] += dx * (1.0 - h0[j-k])
            for j in range(0, n - k):
                grad[j] -= dx * h0[j + k]
        else:
            m = -k
            # O(-m) = dx * sum_{i=0}^{n-1-m} h[i]*(1-h[i+m])
            for j in range(0, n - m):
                grad[j] += dx * (1.0 - h0[j + m])
            for j in range(m, n):
                grad[j] -= dx * h0[j - m]
        
        b_val = val_k - np.dot(grad, h0)
        
        # Row: grad[0], grad[1], ..., grad[n-1], -1
        row = np.zeros(n + 1)
        row[:n] = grad
        row[n] = -1.0
        A_ub_rows.append(row)
        b_ub_vals.append(b_val)
    
    A_ub = np.array(A_ub_rows)
    b_ub = np.array(b_ub_vals)
    
    # Equality constraint: sum(h) = target
    A_eq = np.zeros((1, n + 1))
    A_eq[0, :n] = 1.0
    b_eq = np.array([target])
    
    # Bounds
    bounds = [(0.0, 1.0)] * n + [(None, None)]
    
    res = linprog(c, A_ub=A_ub, b_ub=b_ub, A_eq=A_eq, b_eq=b_eq,
                  bounds=bounds, method=method)
    
    if res.status == 0:
        h_new = np.clip(res.x[:n], 0.0, 1.0)
        h_new = project_feasible(h_new, target)
        h_blend = (1.0 - beta) * h0 + beta * h_new
        h_blend = project_feasible(h_blend, target)
        return h_blend
    else:
        return h0.copy()

This looks reasonable. Let me now think about whether the LP approach will actually help.

The LP linearization is essentially a first-order method for the non-smooth problem min_h max_k O(k). At a KKT point, the LP should give very small improvements (the linearization becomes tight). But away from the optimum, it should make good progress.

One concern: the LP might not converge monotonically. The linearized problem is a relaxation of the true problem, so the LP solution might have a higher true objective than the current point. That's why I have the blending and the "only accept if better" logic.

Let me also add a "restart" mechanism: if the LP gets stuck (no improvement for 20 iterations), try a different approach.

Actually, let me think about this more carefully. The LP linearization is:
min t s.t. O(k;h₀) + ∇O(k;h₀)·(h-h₀) ≤ t for all k

This is a linear underestimator of the true problem (since O is quadratic and... wait, is it an underestimator?).

O(k) = dx * Σ (1-h[i])*h[i+k]

The linearization at h₀ is:
O(k) ≈ O(k;h₀) + ∇O(k;h₀)·(h-h₀)

The error is: O(k) - [O(k;h₀) + ∇O(k;h₀)·(h-h₀)] = 0.5*(h-h₀)ᵀ H_k (h-h₀)

where H_k is the Hessian of O(k). The Hessian has entries:
H_k[j, j+k] = H_k[j+k, j] = -dx for valid j (from the -h[i]*h[i+k] term)

The eigenvalues of H_k can be positive or negative (it's a banded matrix with -dx on the off-diagonal, which is like -dx * (T_k + T_k^T) where T_k is the k-th shift operator. The eigenvalues of T_k + T_k^T are 2*cos(2πm/(2n)) for m=0,...,2n-1, so the eigenvalues of H_k are -2*dx*cos(2πm/(2n)). For even m, these are negative; for odd m, they can be positive).

So H_k is indefinite, and the linearization is not a global underestimator or overestimator. Near h₀, the quadratic term is small, so the linearization is a good approximation.

This means the LP solution might move in a direction that looks good linearly but is actually bad quadratically. The blending (beta < 1) and the "only accept if better" check handle this.
