    n = len(h_binary)
    h = h_binary.copy()
    B = compute_B(h, n)  # B[k] = #{i: h[i]=1, h[i+k]=0}
    max_B = B.max()
    best_h = h.copy()
    best_max_B = max_B
    
    ones = np.where(h == 1)[0]
    zeros = np.where(h == 0)[0]
    
    for move in range(n_moves):
        T = T_init * (T_final / T_init) ** (move / n_moves)
        p = ones[rng.randint(len(ones))]
        q = zeros[rng.randint(len(zeros))]

        delta_B = np.zeros(n, dtype=int)
        # p: 1 -> 0
        # As first element (i=p): lags k=0..n-1-p
        # B[k] decreases by 1 if h[p+k]==0

        # As second element (i+k=p, i=p-k): lags k=0..p
        # B[k] increases by 1 if h[p-k]==1
        for k in range(min(p+1, n)):

        # q: 0 -> 1
        # As first element (i=q): lags k=0..n-1-q
        # B[k] increases by 1 if h[q+k]==0
        for k in range(min(n-1-q+1, n)):
            if h[q+k] == 0:
                delta_B[k] += 1
        # As second element (i+k=q, i=q-k): lags k=0..q
        # B[k] decreases by 1 if h[q-k]==1
        for k in range(min(q+1, n)):
            if h[q-k] == 1:
                delta_B[k] -= 1
        
        new_B = B + delta_B
        new_max_B = new_B.max()
        
        if new_max_B <= max_B or rng.random() < np.exp((max_B - new_max_B) / max(T, 1e-10)):
            # Accept
            h[p] = 0
            h[q] = 1
            B = new_B
            max_B = new_max_B
            # Update ones and zeros
            ones = ones[ones != p]
            ones = np.append(ones, q)
            zeros = zeros[zeros != q]
            zeros = np.append(zeros, p)
            
            if max_B < best_max_B:
                best_max_B = max_B
                best_h = h.copy()
    
    return best_h, best_max_B * (2.0 / n)

The aperiodic autocorrelation is similar. Low autocorrelation sequences (like m-sequences, Golay sequences) have the property that R(k) is small for k≠0.

But our problem is slightly different. We're looking at B_k = #{i: h[i]=1, h[i+k]=0}, which is related to but not the same as autocorrelation.

Let me define s[i] = 2*h[i] - 1 ∈ {-1, 1}. Then:
h[i] = (s[i]+1)/2
h[i+k] = (s[i+k]+1)/2

B_k = #{i: h[i]=1, h[i+k]=0}
= #{i: s[i]=1, s[i+k]=-1}
= (1/4) * sum_i (1+s[i])(1-s[i+k])
= (1/4) * sum_i (1 + s[i] - s[i+k] - s[i]*s[i+k])
= (1/4) * (n-k + sum_i s[i] - sum_i s[i+k] - sum_i s[i]*s[i+k])
= (1/4) * (n-k + S - S_k - R(k))

where S = sum_i s[i] = 0 (since h has weight n/2), S_k = sum_{i=0}^{n-1-k} s[i+k], R(k) = sum_{i=0}^{n-1-k} s[i]*s[i+k].

So B_k = (1/4) * (n-k - S_k - R(k)).

For a "balanced" sequence where S_k ≈ 0 for all k, this becomes B_k ≈ (n-k-R(k))/4.

To minimize max B_k, we want R(k) to be as large as possible (close to n-k) for all k. But R(k) ≤ n-k, and R(0) = n-k = n.

Actually, for k=0: B_0 = 0 (always, since h[i]=1 and h[i]=0 can't both be true).
Check: B_0 = (1/4)(n - S - S_0 - R(0)) = (1/4)(n - 0 - 0 - n) = 0. ✓

For the maximum to be small, we need R(k) to be close to n-k for all k. But R(k) is the autocorrelation, and for a "random" sequence, R(k) ≈ 0. So B_k ≈ (n-k)/4 for random.

To get B_k small, we need R(k) ≈ n-k, which means the sequence is highly autocorrelated (similar to itself at all shifts). But that's impossible for all shifts simultaneously (it would mean the sequence is constant).

So there's a fundamental trade-off. The best we can do is balance the R(k) values.
