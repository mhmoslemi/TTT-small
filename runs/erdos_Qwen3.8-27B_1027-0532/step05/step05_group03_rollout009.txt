Let me also consider: what if I use CVXPY to solve a relaxed version? 

The problem min max_k W_k subject to 0 ≤ h ≤ 1, sum(h) = n/2 is non-convex because W_k is quadratic in h. But if I fix the "structure" of h (e.g., which pairs (i, i+k) have both h=1), then W_k becomes linear.

Alternatively, I can use a **successive convex approximation** (SCA) approach:
1. Start with a current h.
2. Linearize W_k around the current h: W_k ≈ W_k(h0) + ∇W_k(h0) · (h - h0).
3. Solve the resulting convex problem: min max_k (linear terms) subject to constraints.
4. Update h and repeat.

This is essentially the same as the subgradient method but with a convex relaxation at each step.

Actually, for the SCA approach:
W_k(h) = ∑_j (1-h[j]) h[j+k] = ∑_j h[j+k] - ∑_j h[j] h[j+k]

Linearize at h0:
W_k(h) ≈ ∑_j (h0[j+k] - h0[j] h0[j+k]) + ∑_j [δ(h0[j+k]) - δ(h0[j]) h0[j+k] - h0[j] δ(h0[j+k])]

where δ(h) = h - h0.

This is O(n²) to precompute, and then each swap evaluation is O(n) (just W + D_neg[i] + D_pos[j]).

Actually, the delta vectors depend on h, so they change after each swap. But the change is small (only 2 positions change). I can update the deltas incrementally:

When h[i] changes from 1 to 0:
- D_neg will change for all positions that are affected by h[i].
- Specifically, D_neg[m, k] includes h[m+k] and (1-h[m-k]). If m+k = i or m-k = i, the value changes.

This is getting too complicated. Let me use a simpler approach:

**Vectorized swap evaluation using matrix operations**:

For a fixed i (the position to flip from 1 to 0), the delta vector D_neg[i] is:
D_neg[i, k] = h[i+k] (if i+k < n, k≥1) - (1-h[i-k]) (if i-k ≥ 0, k≥1)

This can be written as:
D_neg[i, 1:] = h[i+1:n] - (1-h[max(0,i-(n-1)):i][::-1]) (with appropriate padding)

Actually, let me just use numpy to compute this efficiently:

```python
def compute_all_deltas(h):
    n = len(h)
    D_neg = np.zeros((n, n))  # flip from 1 to 0
    D_pos = np.zeros((n, n))  # flip from 0 to 1
    
    for i in range(n):
        # D_neg[i, k] for k = 1..n-1
        # = h[i+k] (if i+k < n) - (1-h[i-k]) (if i-k >= 0)
        k_vals = np.arange(1, n)
        # Term 1: h[i+k]
        idx1 = i + k_vals
        valid1 = idx1 < n
        t1 = np.zeros(n)
        t1[valid1] = h[idx1[valid1]]
        t1[0] = 0  # k=0 term is 0
        # Term 2: -(1-h[i-k])
        idx2 = i - k_vals
        valid2 = idx2 >= 0
        t2 = np.zeros(n)
        t2[valid2] = -(1.0 - h[idx2[valid2]])
        t2[0] = 0
        D_neg[i] = t1 + t2
        D_pos[i] = -D_neg[i]  # Wait, is this correct?
    return D_neg, D_pos
```

Hmm, D_pos is NOT simply -D_neg. Let me check:

D_neg[i, k] = h[i+k] - (1-h[i-k]) (for 1→0 flip)
D_pos[i, k] = -h[i+k] + (1-h[i-k]) (for 0→1 flip)

Yes! D_pos[i, k] = -D_neg[i, k]. That makes sense because flipping from 0 to 1 is the reverse of flipping from 1 to 0.

So I only need to compute D_neg, and D_pos = -D_neg.

Now, for a swap (i: 1→0, j: 0→1):
ΔW = D_neg[i] + D_pos[j] = D_neg[i] - D_neg[j]

This is very clean!

So the algorithm becomes:
1. Compute D_neg (n×n matrix). O(n²) time and space.
2. For each candidate swap (i, j): ΔW = D_neg[i] - D_neg[j]. New W = W + ΔW.
3. New score = max(W + D_neg[i] - D_neg[j]).

To find the best swap, I can vectorize:

For a fixed i, I want to find j that minimizes max(W + D_neg[i] - D_neg[j]).
This is still hard to vectorize directly.

But I can use a different strategy: instead of finding the globally best swap, find a swap that's "good enough" (greedy):

```python
# For the worst lag k*:
# Find i (where h[i]=1) that most reduces W[k*]:
#   D_neg[i, k*] is as negative as possible
# Find j (where h[j]=0) that most reduces W[k*]:
#   D_pos[j, k*] = -D_neg[j, k*] is as negative as possible, i.e., D_neg[j, k*] is as positive as possible
```

Then check if the combined swap (i, j) actually improves the overall max.

This is O(n) per iteration, which is very fast!
