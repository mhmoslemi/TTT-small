**For n=45 (odd):**
- Work in continuous space
- Use pair transfer local search
- The solution will naturally have most entries at 0 or 1, with a few fractional

**For n=90, 180, 360 (even):**
- Work with binary solutions
- Use pair swap local search (swap a 1 and a 0)
- This is much more efficient since we just need to check which pair to swap

For the binary case, the local search is:
1. Compute all current overlaps
2. For each possible swap (i where h[i]=1, j where h[j]=0), compute the change in the max overlap
3. Execute the best swap
4. Repeat

The challenge is step 2: computing the change in max overlap for each possible swap. There are 45*45 = 2025 possible swaps (for n=90), and computing the full correlate for each is O(n) = O(90). So 2025 * 90 = 182,250 operations per sweep, which is very fast.

Actually, I can be even smarter. For a swap of positions i (was 1, becomes 0) and j (was 0, becomes 1), the change in g_k is:
- g_k loses the contribution from position i: was h[i]*(1-h[i+k]) = 1*(1-h[i+k])
- g_k gains the contribution from position j: was 0*(1-h[j+k]) = 0, now 1*(1-h[j+k])
- But also, g_k includes terms where i or j appears as the shifted position:
  - For position i: it was contributing to g_k as h[i-k]*(1-h[i]) for the term where t+k=i
  - After swap: h[i] becomes 0, so (1-h[i]) becomes 1, changing that term

Let me be more precise. g_k = sum_t h[t]*h[t+k] ... no wait.

g_k = sum_t h[t] * (1-h[t+k])

If I change h[i] from 1 to 0 and h[j] from 0 to 1:
- Terms involving h[i] as the first factor: h[i]*(1-h[i+k]) changes from 1*(1-h[i+k]) to 0 → decrease by (1-h[i+k])
- Terms involving h[i] as the second factor: h[t]*(1-h[t+k]) where t+k=i, i.e., t=i-k: h[i-k]*(1-h[i]) changes from h[i-k]*0 to h[i-k]*1 → increase by h[i-k]
- Terms involving h[j] as the first factor: h[j]*(1-h[j+k]) changes from 0 to 1*(1-h[j+k]) → increase by (1-h[j+k])
- Terms involving h[j] as the second factor: h[t]*(1-h[t+k]) where t+k=j, i.e., t=j-k: h[j-k]*(1-h[j]) changes from h[j-k]*1 to h[j-k]*0 → decrease by h[j-k]

So the total change in g_k is:
Δg_k = -(1-h[i+k]) + h[i-k] + (1-h[j+k]) - h[j-k]

(with the convention that h[invalid] = 0, and terms are only included if indices are valid)

= h[i-k] + 1 - h[j-k] - h[i+k] + h[j+k]

This is O(1) per k! So I can compute Δg_k for all k in O(n), and then find the new max in O(n). Total: O(n) per swap evaluation.

With 2025 possible swaps and n=90, that's 2025 * 90 = 182,250 operations per full sweep. Very fast.

                # But we need to be careful about which terms are valid in the correlate
                
                # Actually, let me just directly compute the effect on the full correlate
                # by computing the new correlate and comparing
                # For efficiency, use the formula above
                
                # The change in correlate entry at lag k (where k goes from -(n-1) to n-1):
                # We need to map to the correlate index
                # correlate index = k + n - 1
                
                # For a given shift s (where s = t+k-t = k in our notation):
                # Δcorrelate[s + n - 1] = ...
                
                # Let me just use the direct formula with boundary checks
                delta_corr = np.zeros(2*n-1)
                for s in range(-(n-1), n):
                    # Position i as first factor: contributes (1-h[i+s]) if i+s valid
                    val = 0.0
                    if 0 <= i + s < n:
                        val -= (1 - h[i + s])  # was 1*(1-h[i+s]), now 0
                    # Position i as second factor: contributes h[i-s] if i-s valid
                    if 0 <= i - s < n:
                        val += h[i - s]  # was h[i-s]*0, now h[i-s]*1
                    # Position j as first factor: contributes (1-h[j+s]) if j+s valid
                    if 0 <= j + s < n:
                        val += (1 - h[j + s])  # was 0, now 1*(1-h[j+s])
                    # Position j as second factor: contributes -h[j-s] if j-s valid
                    if 0 <= j - s < n:
                        val -= h[j - s]  # was h[j-s]*1, now h[j-s]*0
                    delta_corr[s + n - 1] = val
                delta_c5 = np.max(delta_corr) * dx
                # New c5 ≈ current_c5 + delta_c5 (approximate, since max might change)
                # For exact: new_c5 = max(old_corr + delta_corr) * dx
                # But that requires the old_corr...
                
                # For now, use the sufficient condition: if delta_c5 < 0, the max might decrease
                # But it's not sufficient since a non-max entry might become the new max
                # Let's use a simpler criterion: if max(delta_corr) < 0, improvement is guaranteed
                # Otherwise, check more carefully
                
                if np.max(delta_corr) * dx < best_improvement:
                    # This might be an improvement; let's verify
                    h[i] = 0.0
                    h[j] = 1.0
                    new_c5 = eval_c5(h, dx)
                    improvement = current_c5 - new_c5
                    if improvement > best_improvement:
                        best_improvement = improvement
                        best_pair = (i, j)
                        best_c5_new = new_c5
                    h[i] = 1.0
                    h[j] = 0.0
        
        if best_pair is not None:
            i, j = best_pair
            h[i] = 0.0
            h[j] = 1.0
            current_c5 = best_c5_new
            ones = np.where(h > 0.5)[0]
            zeros = np.where(h < 0.5)[0]
        else:
            # No improvement found; try random perturbation
            if len(ones) > 0 and len(zeros) > 0:
                i = rng.choice(ones)
                j = rng.choice(zeros)
                h[i] = 1.0 - h[i]  # flip
                h[j] = 1.0 - h[j]  # flip
                new_c5 = eval_c5(h, dx)
                # Accept with some probability (simulated annealing)
                if new_c5 < current_c5 or rng.rand() < np.exp(-(new_c5 - current_c5) / 0.01):
                    current_c5 = new_c5
                    ones = np.where(h > 0.5)[0]
                    zeros = np.where(h < 0.5)[0]
                else:
                    h[i] = 1.0 - h[i]
                    h[j] = 1.0 - h[j]
    
    return h, current_c5
