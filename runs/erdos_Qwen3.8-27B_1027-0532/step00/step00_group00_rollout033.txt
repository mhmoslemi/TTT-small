Wait, actually for shift 0 (center), the correlation is ∑h[i]*(1-h[i]) = ∑h[i] - ∑h[i]². To minimize this, we want ∑h[i]² to be large, meaning h should be peaked (close to 0 or 1).

For other shifts, the correlation measures the "mismatch" between h and its shifted version.

So the optimal solution should have h that is "peaked" (for shift 0) AND has high autocorrelation at all other shifts. This is a contradictory requirement, which is why the problem is interesting.

One solution that comes to mind: h that alternates 1, 0, 1, 0, ... gives:
- Shift 0: ∑h(1-h) = 0 (since h is binary)

If h = [1, 0, 1, 0, ...], then h[i+1] = 1-h[i]. So (1-h[i+1]) = h[i]. Thus ∑h[i]*(1-h[i+1]) = ∑h[i]*h[i] = ∑h[i]² = n/2.

So at shift 1, the value is (n/2) * dx = (n/2) * 2/n = 1. That's the worst possible!

So the alternating pattern is terrible for odd shifts. We need a pattern where h[i] and h[i+k] are correlated for ALL k.

from scipy.optimize import minimize
import time

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode="full")
    return np.max(corr) * dx

def soft_max(vals, T):
    m = np.max(vals)
    return m + np.log(np.sum(np.exp(T * (vals - m)))) / T

def fix_sum(h, target):
    h = h.copy()
    for _ in range(500):
        diff = target - np.sum(h)
        if abs(diff) < 1e-14:
            break
        h = h + diff / len(h)
        h = np.clip(h, 0.0, 1.0)
    return h

    def obj(x):
        dx = 2.0 / n
        corr = np.correlate(x, 1.0 - x, mode="full") * dx
        return soft_max(corr, T)
    
    def con_fun(x):
        return np.sum(x) - n / 2.0
    
    cons = [{'type': 'eq', 'fun': con_fun}]
