A better approach for SLSQP: use the "soft max" gradient. Let me define a smooth approximation:

C5_smooth(h) = dx * logsumexp(corr / tau)

where tau is a small positive number. As tau → 0, this approaches the true max. The gradient is:
∂C5_smooth/∂h[m] = dx * sum_k (corr_weight_k) * ∂corr[k]/∂h[m]

where corr_weight_k = exp(corr[k]/tau) / sum_j exp(corr[j]/tau)

This gives a proper (smooth) gradient. Let me implement this:

```python
def gradient_c5_smooth(h, n, tau=0.01):
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode="full")
    max_corr = np.max(corr)
    weights = np.exp((corr - max_corr) / tau)
    wsum = weights.sum()
    if wsum < 1e-30:
        return gradient_c5(h, n)
    weights /= wsum
    
    grad = np.zeros(n)

            grad[i] += wk * (1.0 - h[j])

def c5_smooth_value(h, n, tau=0.01):
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode="full")
    max_corr = np.max(corr)
    return float(dx * (max_corr + tau * np.log(np.exp((corr - max_corr)/tau).sum())))
```

And use this as the objective for SLSQP with the smooth gradient.

Actually, for SLSQP, using the smooth approximation is better because:
1. The gradient is well-defined everywhere (no kinks)
2. SLSQP can converge to a local minimum of the smooth approximation
3. As tau → 0, the smooth approximation converges to the true max

The tradeoff is that with larger tau, we're optimizing a different (smoother) problem. With small tau, the smooth approximation is close to the true problem but the gradient is more "spiky" (concentrated on the argmax).

Let me use tau = 0.01 for SLSQP. This should give a good balance.
