The problem can be viewed as: find h to minimize the maximum of {c_k : k} where c_k are bilinear forms in h.

This is a "minimax" problem. By the minimax theorem, we can write:
min_h max_k c_k(h) = max_{p ∈ Δ} min_h sum_k p_k c_k(h)

where Δ is the simplex over k. The inner problem (for fixed p) is:
min_h sum_k p_k * c_k(h) subject to constraints

This is a quadratic minimization (since c_k is quadratic in h):
sum_k p_k * sum_i h[i]*(1-h[i+k]) = sum_k p_k (sum_i h[i] - sum_i h[i]*h[i+k])
= (sum_k p_k) sum_i h[i] - sum_i h[i] * sum_k p_k h[i+k]
= sum_i h[i] - sum_i h[i] * (p * h)[i]

where (p*h) is a weighted sum of shifted versions of h.

This is a non-convex quadratic (the Hessian involves the p-weighted shift matrix, which is not necessarily PSD).

But we can use this as a lower bound: for any p, min_h sum_k p_k c_k(h) ≤ min_h max_k c_k(h).

And by the minimax duality (which holds for this finite-dimensional problem), we have:
min_h max_k c_k(h) = max_{p ∈ Δ} min_h sum_k p_k c_k(h)

So we can solve this as a game:
- Player 1 chooses h to minimize
- Player 2 chooses p (distribution over k) to maximize
- The value of the game is C_5

This is a zero-sum game! We can solve it using:
- Multiplicative weight updates (follow the regularized leader)
- Fictitious play
- Mirror descent

The advantage of this approach is:
- The inner problem (for fixed p) is a smooth (quadratic) minimization, which we can solve efficiently
- The outer problem (update p) is simple (multiplicative weights)

**Alternative: Benders decomposition / cutting plane**

At each iteration:
1. Solve a relaxed problem (linear or convex) to get a candidate h
2. Evaluate the true objective (max of correlations)
3. Add a cut (valid inequality) that eliminates the gap
4. Repeat

The cuts can be:
- For the active shift k*: sum_i h[i](1-h[i+k*]) ≤ t
  This is a quadratic constraint. We can linearize it at the current point:
  sum_i [(1-h*[i+k*])h[i] - h[i]h[i+k*]] ≤ t
  Linearizing at h*: ≈ sum_i [(1-h*[i+k*])(h[i]-h*[i]) - h*[i](h[i+k*]-h*[i+k*])] + c_{k*}(h*)
  
  This gives a linear cut.

But solving the LP with all accumulated cuts might be slow.

**Alternative: Level-set method**

This is the same as the dual approach: find the optimal t such that the feasible set {h: c_k(h) ≤ t for all k, 0≤h≤1, sum(h)=n/2} is non-empty.

For a given t, check feasibility. If infeasible, t is too small. Use bisection.

The feasibility check for a given t:
min_h 0
s.t. c_k(h) ≤ t for all k
     0 ≤ h ≤ 1
     sum(h) = n/2

This is a non-convex feasibility problem (quadratic constraints). We can solve it approximately with:
- Sequential quadratic programming (SQP)
- Penalty method: minimize sum_k max(0, c_k(h) - t)² + barrier for h ∈ [0,1]
- Interior point method for QCs

This is essentially what the previous SLSQP approach does. The advantage of bisection is that we get a certificate of feasibility.

**Let me try a different approach: iterative reweighted least squares**

The idea: at each iteration, we have a current solution h* and active set K* = {k : c_k(h*) ≈ C₅}.

We linearize the problem around h*: for k ∈ K*, c_k(h) ≈ c_k(h*) + ∇c_k(h*)^T (h - h*)

We want to find h that minimizes the maximum of these linear approximations, subject to constraints. This is a LP (linear program)!

Solve the LP:
min t
s.t. c_k(h*) + ∇c_k(h*)^T (h - h*) ≤ t for k ∈ K*
     0 ≤ h ≤ 1
     sum(h) = n/2

Then update h to the LP solution (or a step towards it), update K*, repeat.

This is a cutting-plane method for the max function. The advantage is that each subproblem is an LP (solvable efficiently with cvxpy).

The disadvantage is that the linear approximation is only valid near h*, so we need to take small steps. But we can use a trust region: restrict ||h - h*|| ≤ Δ.

```python
import cvxpy as cp

def cutting_plane(h_init, n, target, time_limit, max_iters=100, delta_init=0.1):
    start = time.time()
    dx = 2.0 / n
    h = h_init.copy().astype(float)
    best_c5 = compute_c5(h)
    best_h = h.copy()
    
    delta = delta_init
    
    for it in range(max_iters):
        if time.time() - start > time_limit:
            break
        
        corr = compute_correlations(h)
        c_max = np.max(corr) * dx
        if c_max < best_c5:
            best_c5 = c_max
            best_h = h.copy()
        
        # Find active shifts (within tolerance of max)
        tol = 0.01 * c_max
        active = np.where(corr * dx >= c_max - tol)[0]
        
        # Compute gradients for active shifts
        n_corr = len(corr)
        mid = n - 1
        grads = []
        for k_idx in active:
            k = k_idx - mid
            grad = np.zeros(n)
            if k >= 0:
                grad[:n-k] += (1.0 - h[k:n])
                grad[k:] -= h[:n-k]
            else:
                kk = -k
                grad[kk:] += (1.0 - h[:n-kk])
                grad[:n-kk] -= h[kk:]
            grads.append(grad * dx)
        
        # Solve LP (or QP with trust region)
        h_var = cp.Variable(n)
        t_var = cp.Variable()
        
        objective = cp.Minimize(t_var)
        constraints = [h_var >= 0, h_var <= 1, cp.sum(h_var) == target]
        
        for grad in grads:
            c_k = np.dot(grad, (h_var - h)) + (c_max - tol/2)  # linearized constraint
            constraints.append(c_k <= t_var)
        
        # Trust region (simple: L-infinity ball)
        constraints.append(cp.norm(h_var - h, np.inf) <= delta)
        
        prob = cp.Problem(objective, constraints)
        try:
            prob.solve(solver=cp.GLPK)  # or CBC, or ECOS
        except:
            try:
                prob.solve(solver=cp.ECOS)
            except:
                break
        
        if t_var.value is None or np.isnan(t_var.value):
            break
        
        h_new = h_var.value
        h_new = project_feasible(h_new, target)
        
        # Check if we made progress
        new_c5 = compute_c5(h_new)
        if new_c5 < c_max - 1e-8:
            h = h_new
            delta = min(delta * 1.5, 0.5)  # grow trust region
        else:
            delta *= 0.5  # shrink trust region
            if delta < 1e-4:
                break
    
    return best_h, best_c5
```

```python
    dx = 2.0 / n
    n_corr = 2 * n - 1
    mid = n - 1
```

For n=600: 40 * 360000 = 14.4 million ops per sweep. At ~50M ops/s, that's ~0.3s per sweep.
For 1000 sweeps: 300 seconds. That's feasible!

This is much faster than pair_cd! And single-coordinate descent is simpler to implement.

But wait, single-coordinate descent can be slow to converge because it only changes one coordinate at a time. The pair_cd changes two coordinates simultaneously, which is more efficient in practice.

Let me use a compromise: **block coordinate descent** where I update B coordinates at a time. For B = 4 or 8, the subproblem is small enough to solve by enumeration or local search.

(b) Compensate by changing another coordinate

Option (a) is simpler. The projection is O(n) and doesn't change the C₅ much for small perturbations.
