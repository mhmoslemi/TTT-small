Let me also think about the continuous refinement. The key idea is:
- At the optimum, we have h ∈ [0,1] with ∑h = n/2
- The objective is max_k corr_k
- A subgradient of the objective is the average gradient over the active set (lags achieving the max)
- We can do projected subgradient descent

But there's a subtlety: the max function is non-smooth, so subgradient methods converge slowly. The log-sum-exp trick smooths it out.

For the SLSQP approach, the objective is:
f(h) = c_max + (1/alpha) * log(∑ exp(alpha * (corr_k - c_max)))

This is a smooth approximation of c_max that becomes more peaked as alpha increases.

Let me also consider: what if we use a different smooth approximation? For example:
f(h) = (∑ corr_k^p)^(1/p) for large p (approximates the max)

Or: f(h) = c_max^2 + epsilon * ∑ corr_k^2 (minimize the max while also reducing variance)

The second approach might be better because it provides stronger gradients for non-active lags.

Let me try this: minimize (max_corr)^2 + lambda * (std of corr)^2

This is equivalent to minimizing a penalty for both the peak and the spread.

Actually, let me think about this more carefully. The problem is:
minimize t
s.t. corr_k ≤ t for all k
∑h = n/2
0 ≤ h ≤ 1

The Lagrangian is:
L = t + ∑_k μ_k (corr_k - t) + ν(∑h - n/2) + ∑_i λ_i^+ h_i + ∑_i λ_i^- (-h_i)

At the optimum, complementary slackness gives:
- μ_k > 0 only if corr_k = t (active constraint)
- λ_i^+ > 0 only if h_i = 1
- λ_i^- > 0 only if h_i = 0

The KKT conditions give:
1 - ∑_k μ_k = 0 (from ∂L/∂t = 0)
∑_k μ_k ∂corr_k/∂h_i + ν + λ_i^+ - λ_i^- = 0 (from ∂L/∂h_i = 0)

This means that at the optimum, the weighted sum of gradients of active constraints, plus the constraint multiplier, must be zero for free variables (0 < h_i < 1).

This suggests a different approach: **active set method**.
1. Identify the active set A (lags with corr_k ≈ t)
2. Solve the subproblem: minimize ∑_{k∈A} corr_k (or the average) subject to constraints
3. Check if any inactive constraint is violated
4. If yes, add it to the active set and go to step 2
5. If no, we're at the optimum

This is similar to what the previous program does with subgradient, but more structured.

For step 2, minimizing the average of active correlations is a quadratic problem (since each corr_k is quadratic in h). We can solve it with a quadratic solver.

Actually, each corr_k is bilinear in h (not quadratic), because:
corr_k = ∑_i h[i] * (1-h[i+k]) = ∑_i h[i] - ∑_i h[i]*h[i+k]

The term h[i]*h[i+k] is bilinear (product of two different variables). So the problem is a non-convex quadratic program.

However, if we linearize around the current point, we get a QP that we can solve.

Let me try a different approach: **alternating minimization**.

Fix all but one variable h[j], and optimize h[j] given the others.
corr_k as a function of h[j]:
corr_k = ... + h[j]*(1-h[j+k]) + h[j-k]*(1-h[j]) + ...
      = ... + h[j] - h[j]*h[j+k] + h[j-k] - h[j-k]*h[j] + ...
      = ... + h[j]*(1 - h[j+k] - h[j-k]) + (terms not involving h[j])

So corr_k is linear in h[j] for fixed other variables! (The coefficient of h[j] is (1 - h[j+k] - h[j-k]).)

This means that for fixed other variables, each corr_k is linear in h[j], and max_k corr_k is piecewise linear in h[j]. We can find the optimal h[j] by checking the breakpoints.

This gives us a coordinate descent method!

For each coordinate j:
1. Compute the coefficient a_j[k] = (1 - h[j+k]) - h[j-k] for each lag k (with boundary handling)
2. corr_k as a function of x = h[j]: corr_k(x) = b_k + a_j[k] * x, where b_k is corr_k without the h[j] terms
3. We want to minimize max_k (b_k + a_j[k] * x) subject to 0 ≤ x ≤ 1 and the constraint ∑h = n/2

The constraint ∑h = n/2 couples all coordinates, so we can't optimize them independently. But we can use a Lagrange multiplier for the sum constraint:
minimize max_k (b_k + a_j[k] * x) + ν * x
subject to 0 ≤ x ≤ 1

For a given ν, the optimal x is the minimizer of a piecewise linear function, which is at one of the breakpoints.

This is getting complicated. Let me just implement a simpler version:

**Coordinate descent with line search:**
For each coordinate j (in random order):
1. Save h[j]
2. Try several values: h[j] ± {0.01, 0.05, 0.1, 0.2, 0.5}
3. Project to feasible set (adjust some other coordinate to maintain the sum)
4. Accept if it improves

This is O(n * n_values * n_lags) per sweep = O(n³ * n_values) which is too slow for n=600.

Let me think of something faster.

Actually, the key insight for the incremental update is:
When we change h[j] by δ, the change in corr[m] is δ * ((1-h[j+m]) - h[j-m]) (for valid indices).

So if we change h[j] from old to new (δ = new - old), the new correlation is:
corr_new[m] = corr_old[m] + δ * ((1-h[j+m]) - h[j-m])

This is O(n) per change. Then checking if max improved is O(n). Total O(n) per coordinate update.

For a full sweep (all n coordinates): O(n²) = O(360K) for n=600. That's fast!

But we need to handle the sum constraint. If we change h[j] by δ, we need to change some other h[j'] by -δ to maintain the sum. The simplest is to distribute -δ evenly over all other coordinates, but that might push them out of [0,1].

Alternative: use a pair swap in continuous space. Change h[j] from a to a+δ and h[j'] from b to b-δ. The change in corr is:
δ * ((1-h[j+m]) - h[j-m]) - δ * ((1-h[j'+m]) - h[j'-m])

This is still O(n) per pair.

Let me implement a "continuous pair swap" local search:

Actually, I think the most effective approach for this problem is:

1. **Fast binary SA** (the main workhorse) - use the O(n²) correlate each time, which is fast enough
2. **Continuous refinement** - use SLSQP with log-sum-exp smoothing
3. **Multi-start diversity** - try different random seeds and initializations

The key improvement over the previous program should be:
- More efficient use of time (less overhead, more optimization iterations)
- Better SA parameters (adapted to the problem)
- Better continuous refinement (more aggressive)

f(h) = (1/K) * ∑_k max(0, corr_k - t)^2 + (t - 0.38)^2 + penalty * (∑h - n/2)^2
