```python
def compute_corr_fft(h):
    n = len(h)
    N = 2 * n
    H = fft(h, N)
    Gh = fft(1.0 - h, N)
    C = np.real(ifft(np.conj(H) * Gh))
    return np.concatenate([C[n+1:2*n], C[0:n]])
```

One issue with SLSQP: it's a general-purpose optimizer that doesn't know the structure of the problem. It might be getting stuck at a suboptimal continuous solution.

A better approach for the continuous refinement:
1. Identify the active lags (those where g_m is close to the maximum)
2. For each active lag m, compute the gradient ∂g_m/∂h
3. Find a direction d that reduces all active g_m simultaneously
4. Take a small step in direction d

This is essentially a multiplicative weight / exponentiated gradient approach, or a min-max optimization.

Let me implement a mini-max approach:
- Maintain weights w_m for each lag m
- The weighted objective is sum_m w_m * g_m(h)
- Update h to minimize this weighted objective (using gradient descent)
- Update weights: w_m ← w_m * exp(eta * g_m(h)) (larger weight for larger g_m)
- Normalize weights

This is the multiplicative weight update (MWU) for the zero-sum game between the "maximizer" (choosing lag) and the "minimizer" (choosing h). The value of this game converges to the minimax value.

This could be more effective than SLSQP because it directly targets the minimax structure.
