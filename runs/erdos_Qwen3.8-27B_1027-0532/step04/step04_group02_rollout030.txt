4. Check if this reduces the overall max correlation

- It doesn't create new high correlations
- Ideally, it helps reduce other high correlations too

```python
            # Old term: h[k+c] * (1-h[k])
            kc = k + c
            if 0 <= kc < n:
                old_val = h[kc] * (1 - h[k])
            else:
                old_val = 0
            
            # New term: h_new[k+c] * (1-h_new[k])
            h_new_k = (1 - h[k])  # h_new[i]=0, h_new[j]=1, else same
            if k == i:
                h_new_k = 0
            elif k == j:
                h_new_k = 1
            
            if 0 <= kc < n:
                h_new_kc = h[kc]
                if kc == i:
                    h_new_kc = 0
                elif kc == j:
                    h_new_kc = 1
                new_val = h_new_kc * (1 - h_new_k)
            else:
                new_val = 0
            
            delta[c_idx] += new_val - old_val
    
    return delta
```

This is O(n) per swap (since there are 2n-1 lags, and for each we check at most 4 k values). For n=600, that's about 4800 operations per swap evaluation. This is much faster than O(n²) = 360,000 for np.correlate.

Wait, there's an issue with the "k != i" and "k != j" conditions. If i-c = i (c=0), then the k=i term already accounts for it. If i-c = j, then the k=j term already accounts for it. So we should skip the k=i-c term when i-c equals i or j, and similarly for k=j-c.

But there's another subtlety: when i-c = j, the k=j term uses h_new, which already reflects the change at j. Let me verify:

If i-c = j (c = i-j):
- k=i: new term = h_new[i+c] = h_new[i+i-j] = h_new[2i-j]. This is fine.
- k=j: old term = h[j+c] = h[j+i-j] = h[i] = 1. New term = 0. Delta = -1.
- k=i-c=j: This is the same as k=j! So we should NOT add it again. The condition (k != j) handles this.

OK I think the logic is correct. But let me simplify by just computing the delta using the formula:

Δcorr[c] = h_new[i+c] - h[j+c] - (1-h[i-c]) + (1-h[j-c])

where:
- h_new[i+c] = 1 if i+c=j, 0 if i+c=i, h[i+c] otherwise (and 0 if out of range)
- h[j+c] = h[j+c] (0 if out of range)
- (1-h[i-c]) = 1-h[i-c] (0 if out of range, and 0 if i-c = i or i-c = j to avoid double counting)
- (1-h[j-c]) = 1-h[j-c] (0 if out of range, and 0 if j-c = i or j-c = j to avoid double counting)

Actually, I realize the double-counting issue only arises when i-c ∈ {i, j} or j-c ∈ {i, j}. Let me handle this:

- i-c = i ⟺ c = 0
- i-c = j ⟺ c = i-j
- j-c = j ⟺ c = 0
- j-c = i ⟺ c = j-i

So for c=0: both i-c=i and j-c=j, so we skip both the (1-h[i-c]) and (1-h[j-c]) terms.
For c=i-j: i-c=j, so we skip the (1-h[i-c]) term.
For c=j-i: j-c=i, so we skip the (1-h[j-c]) term.

```python
def swap_delta(h, i, j, n):
    """O(n) computation of correlation change for swap i->j."""
    c = np.arange(-(n-1), n)  # shape (2n-1,)
    
    # h_new[i+c]: value of h_new at position i+c
    pos1 = i + c
    valid1 = (pos1 >= 0) & (pos1 < n)
    term1 = np.zeros(2*n-1)
    term1[valid1] = h[pos1[valid1]]
    term1[(pos1 == j)] = 1.0  # h_new[j] = 1
    term1[(pos1 == i)] = 0.0  # h_new[i] = 0
    # (term1 is h_new[i+c], effectively)
    
    # h[j+c]: value of old h at position j+c
    pos2 = j + c
    valid2 = (pos2 >= 0) & (pos2 < n)
    term2 = np.zeros(2*n-1)
    term2[valid2] = h[pos2[valid2]]
    
    # (1-h[i-c]): value of 1-h at position i-c, but 0 if i-c==i or i-c==j
    pos3 = i - c
    valid3 = (pos3 >= 0) & (pos3 < n) & (pos3 != i) & (pos3 != j)
    term3 = np.zeros(2*n-1)
    term3[valid3] = 1.0 - h[pos3[valid3]]
    
    # (1-h[j-c]): value of 1-h at position j-c, but 0 if j-c==i or j-c==j
    pos4 = j - c
    valid4 = (pos4 >= 0) & (pos4 < n) & (pos4 != i) & (pos4 != j)
    term4 = np.zeros(2*n-1)
    term4[valid4] = 1.0 - h[pos4[valid4]]
    
    return term1 - term2 - term3 + term4
```
