At the optimum, for each active constraint k (where O_k = C5), the gradient of O_k with respect to h should be a sum of the gradients of all active constraints, plus a multiple of the gradient of the sum constraint.

This is a complex condition. But it suggests that at the optimum, multiple lags k are "active" (achieving the maximum), and the solution balances them.

The LP approach naturally handles this: the optimal LP solution will have the right balance of active constraints.

```python
def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(corr)) * dx

def project_feasible(h, target_sum):
    h = np.clip(h.astype(float), 0.0, 1.0)
    diff = target_sum - np.sum(h)
    if abs(diff) < 1e-14:
        return h
    if diff > 0:
        idx = np.where(h < 1.0 - 1e-10)[0]
    else:
        idx = np.where(h > 1e-10)[0]
    if len(idx) == 0:
        return h
    h = h.copy()
    h[idx] += diff / len(idx)
    h = np.clip(h, 0.0, 1.0)
    residual = target_sum - np.sum(h)
    if abs(residual) > 1e-10:
        if residual > 0:
            idx2 = np.where(h < 1.0)[0]
        else:
            idx2 = np.where(h > 0.0)[0]
        if len(idx2) > 0:
            h[idx2] += residual / len(idx2)
            h = np.clip(h, 0.0, 1.0)
    return h

def build_corr_matrix(n, g, dx):
    A = np.zeros((2 * n - 1, n))
    for p in range(2 * n - 1):
        k = p - (n - 1)
        lo = max(0, k)
        hi = min(n, n + k)
        if hi > lo:
            A[p, lo:hi] = g[lo - k: hi - k] * dx
    return A

def solve_lp_step(n, g, target, dx):
    A = build_corr_matrix(n, g, dx)
    h_var = cp.Variable(n)
    t_var = cp.Variable()
    ones_vec = np.ones(2 * n - 1)
    constraints = [
        cp.sum(h_var) == target,
        h_var >= 0.0,
        h_var <= 1.0,
        A @ h_var <= t_var * ones_vec
    ]
    prob = cp.Problem(cp.Minimize(t_var), constraints)
    try:
        prob.solve(solver=cp.SCS, max_iters=50000, verbose=False)
    except Exception:
        try:
            prob.solve(solver=cp.ECOS, max_iter=50000, verbose=False)
        except Exception:
            return None
    if h_var.value is None:
        return None
    return np.clip(np.asarray(h_var.value).ravel(), 0.0, 1.0)

    h = project_feasible(h_init.copy(), target)
    best_h = h.copy()
    best_c5 = compute_c5(h)

            break
        g = 1.0 - h
        h_new = solve_lp_step(n, g, target, dx)
        if h_new is None:
            break
        h = (1.0 - damping) * h + damping * h_new
        h = project_feasible(h, target)
        c5_val = compute_c5(h)
        if c5_val < best_c5 - 1e-14:
            best_c5 = c5_val
            best_h = h.copy()
            stuck = 0
        else:
            stuck += 1
        if stuck > 20:
            stuck = 0
        if it % 50 == 0:
            damping = max(0.05, damping * 0.93)
    
    return best_h, best_c5
```

Let me try a different approach: **use SLSQP but with a gradient**. SLSQP supports user-supplied gradients, which would be much faster than finite differences.

The gradient of the log-sum-exp objective is:
d/dh_i [max_k c_k] ≈ sum_k p_k * dc_k/dh_i

where p_k = exp(alpha * c_k) / sum_m exp(alpha * c_m) are the softmax weights.

And dc_k/dh_i = (1-h[i-k])*dx - h[i+k]*dx (for valid indices), as derived earlier.

So the full gradient is:
grad[i] = dx * sum_k p_k * [(1-h[i-k_k*])*1_{valid} - h[i+k_k*]*1_{valid}]

where k_k is the lag corresponding to index k in the correlation array.

This is O(n * 2n) = O(n^2) per gradient evaluation, which is the same order as the objective. But with an analytical gradient, SLSQP converges in fewer iterations.

Let me implement this:

```python
    c = corr * dx
    c_max = np.max(c)

    # Gradient

        valid1 = np.arange(n) - k
        mask1 = (valid1 >= 0) & (valid1 < n)
        grad[mask1] += p[k_idx] * (1.0 - h[valid1[mask1]]) * dx
        valid2 = np.arange(n) + k
        mask2 = (valid2 >= 0) & (valid2 < n)
        grad[mask2] -= p[k_idx] * h[valid2[mask2]] * dx
    return obj, grad
```

Wait, this is O(n * 2n) = O(n^2) per gradient, and the loop over k_idx is O(n). For n=400, that's 400 * 800 = 320K operations per gradient. That's fast.

But the inner loop is in Python, which is slow. Let me vectorize it.

Actually, I can compute the gradient more efficiently:
grad[i] = dx * (sum_k p_k * (1-h[i-k_k]) * 1_{valid} - sum_k p_k * h[i+k_k] * 1_{valid})

The first term is a "correlation" of p with (1-h), and the second is a "correlation" of p with h.

Specifically:
term1[i] = sum_k p_k * (1-h[i-k_k]) * 1_{0<=i-k_k<n}
         = sum_{k: i-k_k in [0,n)} p_k * (1-h[i-k_k])

If I define p_k for k in [-(n-1), (n-1)], then:
term1[i] = sum_{j: j in [0,n), j = i-k for some k} p_{i-j} * (1-h[j])
         = sum_{j in [0,n)} p_{i-j} * (1-h[j]) * 1_{i-j in [-(n-1), n-1]}

Since i and j are both in [0,n), i-j is in [-(n-1), n-1] automatically. So:
term1[i] = sum_{j in [0,n)} p_{i-j} * (1-h[j])

This is a convolution! term1 = convolve(p, 1-h) (with appropriate alignment).

Similarly:
term2[i] = sum_k p_k * h[i+k] * 1_{0<=i+k<n}
         = sum_{j in [0,n)} p_{j-i} * h[j] * 1_{j-i in [-(n-1), n-1]}
         = sum_{j in [0,n)} p_{j-i} * h[j]

This is also a correlation/convolution.

So: grad = dx * (convolve(p_reversed, 1-h) - convolve(p, h)) (approximately)

Let me think about this more carefully using np.correlate.

np.correlate(a, v)[k] = sum_i a[i+k] * v[i]

So if I want sum_j p[i-j] * (1-h[j]), that's:
sum_j p[i-j] * (1-h[j]) = np.correlate(p, 1-h)[i + (len(p)-1)] ... hmm, this is getting complicated with the indexing.

Let me just use the loop approach but vectorize the inner operations:

```python
def smooth_obj_and_grad(h, alpha):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    c = corr * dx
    c_max = np.max(c)
    shifted = np.clip(alpha * (c - c_max), -500.0, 0.0)
    exp_shifted = np.exp(shifted)
    obj_val = float(c_max + np.log(np.sum(exp_shifted)) / alpha)
    
    p = exp_shifted / np.sum(exp_shifted)
    grad = np.zeros(n)
    idxs = np.arange(n)
    n_half = n - 1
    
    for k_idx in range(2 * n - 1):
        w = p[k_idx]
        if w < 1e-15:
            continue
        k = k_idx - n_half
        # Term 1: w * (1-h[i-k]) for valid i-k
        j = idxs - k
        mask = (j >= 0) & (j < n)
        grad[mask] += w * (1.0 - h[j[mask]]) * dx
        # Term 2: -w * h[i+k] for valid i+k
        j2 = idxs + k
        mask2 = (j2 >= 0) & (j2 < n)
        grad[mask2] -= w * h[j2[mask2]] * dx
    
    return obj_val, grad
```

This is O(n) Python loop iterations, each doing O(n) vectorized operations. For n=400, that's 400 * 400 = 160K numpy operations per gradient. Should be fast enough.
