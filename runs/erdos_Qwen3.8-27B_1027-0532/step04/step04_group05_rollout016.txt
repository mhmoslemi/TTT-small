The first term is a quadratic form in h.

So the inner problem is a QP (quadratic program) with a matrix that's a weighted sum of shift matrices.

This QP can be solved efficiently! And the outer problem is over the simplex, which can be solved with a subgradient method (the subgradient with respect to λ_k is f_k(h*).

1. Start with λ⁰ (uniform or concentrated on argmax)
2. Solve QP: min_h ∑_k λ_k f_k(h) s.t. 0≤h≤1, sum(h)=n/2
3. Let h* be the solution
4. Find k* = argmax_k f_k(h*)
5. Update λ: λ_k* ← 1 (or use a step method)
6. Repeat

Actually, the standard approach for max-min is:
- Maintain a distribution λ over k
- At each step: solve the QP for the current λ, get h*
- The value ∑_k λ_k f_k(h*) is a LOWER bound on the optimal value
- The value max_k f_k(h*) is an UPPER bound
- Update λ to put more weight on k* (the worst case)
- Continue until gap is small

        # dx * ∑_i S_i h[i] - dx * ∑_k lam_{k+n-1} * ∑_i h[i]*h[i+k]

        # obj(h) = dx * S @ h - dx * ∑_k lam_{k+n-1} * (h * roll(h, -k)).sum()

        def qp_obj(h_flat):

            S = np.zeros(n)
            lam_shifted = lam  # already indexed as lam[k_idx] where k_idx = k + n - 1
            for k_idx in range(n_shifts):
                k = k_idx - (n - 1)
                # S_i gets lam[k_idx] for i in range(max(0,-k), min(n, n-k))
                lo = max(0, -k)
                hi = min(n, n - k)
                S[lo:hi] += lam[k_idx]
            lin_part = dx * np.dot(S, h_v)
            
            quad_part = 0.0
            for k_idx in range(n_shifts):
                if lam[k_idx] < 1e-15:
                    continue
                k = k_idx - (n - 1)
                lo = max(0, -k)
                hi = min(n, n - k)
                quad_part += lam[k_idx] * np.dot(h_v[lo:hi], h_v[lo+k:hi+k])
            quad_part *= dx
            return lin_part - quad_part
        
        def qp_grad(h_flat):
            h_v = h_flat
            S = np.zeros(n)
            for k_idx in range(n_shifts):
                k = k_idx - (n - 1)
                lo = max(0, -k)
                hi = min(n, n - k)
                S[lo:hi] += lam[k_idx]
            grad = dx * S.copy()
            
            for k_idx in range(n_shifts):
                if lam[k_idx] < 1e-15:
                    continue
                k = k_idx - (n - 1)
                lo = max(0, -k)
                hi = min(n, n - k)
                # d/dh[i] of h[i]*h[i+k] = h[i+k] + h[i-k] (where valid)
                for i in range(lo, hi):
                    grad[i] -= dx * lam[k_idx] * h_v[i+k]
                    j = i - k
                    if 0 <= j < n:
                        grad[i] -= dx * lam[k_idx] * h_v[j]
            return grad

        # Actually for n=400, O(n²) = 160000 per eval is fine.
        
        # But the scipy minimize with constraints is slow. Let me use cvxpy with a different formulation.

        bounds = [(0, 1)] * n
        cons = [{'type': 'eq', 'fun': lambda h: np.sum(h) - target,

        try:

        except Exception:
            break
        
        # Evaluate
        corr_new = np.correlate(h_new, 1.0 - h_new, mode='full')
        f_new = corr_new * dx
        upper = float(np.max(f_new))
        lower = float(np.dot(lam, f_new))
        
        if upper < best_upper:
            best_upper = upper
            best_h = h_new.copy()
        
        # Update lambda: multiplicative weights
        k_new_star = int(np.argmax(f_new))
        alpha = 0.5  # learning rate
        lam = lam * np.exp(-alpha * f_new / (upper + 1e-10))
        lam /= np.sum(lam)
        
        # Also try putting all weight on the worst k
        lam_conc = np.zeros(n_shifts)
        lam_conc[k_new_star] = 1.0
        lam = 0.5 * lam + 0.5 * lam_conc
        
        h_cur = h_new
    
    return best_h, best_upper

Let me focus on implementing an efficient pairwise swap search:

For a swap between positions i and j (transfer δ from i to j):
- h[i] += δ, h[j] -= δ (maintains sum constraint)
- Need 0 ≤ h[i]+δ ≤ 1 and 0 ≤ h[j]-δ ≤ 1

The change in f_k (correlation at shift k) is:
Δf_k = δ * [∂f_k/∂h[i] - ∂f_k/∂h[j]] * dx (approximately, for small δ)

More precisely:
f_k(h + δ(e_i - e_j)) = f_k(h) + δ * (grad_k[i] - grad_k[j]) + O(δ²)

where grad_k[i] = dx * [(1-h[i+k]) * 1_{valid} - h[i-k] * 1_{valid}]

- h[i] becomes h[i]+δ, h[j] becomes h[j]-δ
- The term h[i]*(1-h[i+k]) changes by: δ*(1-h[i+k]) - δ*(1-h[i+k]) if i+k=j... 
  Actually this gets complicated. Let me just compute it directly.

For a swap of δ from position j to position i:
The new h is: h' = h, except h'[i] = h[i]+δ, h'[j] = h[j]-δ.

The correlation at shift k:
corr'(k) = ∑_l h'[l]*(1-h'[l+k])*dx

The change is:
Δcorr(k) = [h'[i]*(1-h'[i+k]) - h[i]*(1-h[i+k])] * dx (if i is in valid range for shift k)

         + changes from h appearing in the (1-h[...]) factor

This is getting messy. Let me just compute the correlation directly after the swap. For n=400, computing the full correlation takes O(n²) ≈ 160000 operations, which is very fast.

So the algorithm is:
1. For each pair (i,j) [or a subset of promising pairs]:
   a. Try several values of δ

This is O(n² * |δ_values| * n) per full pass = O(n³ * |δ|) which for n=400 is 64M * |δ| operations. With |δ|=10, that's 640M operations per pass. At ~100M ops/s, that's ~6 seconds per pass. We can do about 100 passes in 600 seconds.

Actually, we can be smarter: only try pairs where one of the positions is "high" (close to 1) and the other is "low" (close to 0). This reduces the number of pairs to try.

Even better: only try pairs (i,j) where i is in a "high overlap" region and j is in a "low overlap" region. The overlap at position i for shift k* is h[i]*(1-h[i+k*]), so positions with high h[i] and low h[i+k*] are the "worst" positions.

Let me implement a focused version:
1. Find k* (argmax shift)
2. Find the top M positions contributing to the overlap at k*
3. For each such position i, try transferring mass to the best "receiver" j
4. The best receiver minimizes the increase in C₅

This is much more efficient.
