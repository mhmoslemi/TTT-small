One more thought: the previous code's LP approach creates a fresh LP at each iteration with the same topk lags re-identified. This means it's solving a series of LPs where the constraints change each time. This is a valid approach (it's essentially a subgradient method with LP oracle).

An alternative is the "cutting plane" approach where we accumulate cuts:
- Maintain a list of (g_k, b_k) pairs
- At each iteration, add the cut for the currently worst lag
- Solve the LP with all accumulated cuts
- This converges faster but the LP gets larger

For n=400, the LP has 401 variables (400 h values + 1 slack z). Adding one cut adds one row. Even with 1000 cuts, this is a 1000×401 LP, which is very fast for modern solvers.

Let me implement the accumulated cutting plane approach:

```python
def lp_cutting_plane(h_start, target_sum, max_iters, time_limit):
    n = len(h_start)
    h = h_start.copy()
    best_h = h.copy()
    best_score = compute_c5(h)
    t0 = time.time()
    
    cuts = []  # list of (g, b) where g^T h - z <= b
    
    for it in range(max_iters):
        if time.time() - t0 > time_limit:
            break
        
        # Find the worst lag
        corr = overlap_corrs(h)
        worst_idx = np.argmax(corr)
        worst_val = corr[worst_idx]
        
        # Check if we need a new cut
        # (In a proper cutting plane, we'd check all cuts, but for simplicity,
        #  we add a cut for the worst lag at each iteration)
        g = compute_grad_single_lag(h, worst_idx)
        b = g @ h - worst_val
        cuts.append((g, b))
        
        # Limit number of cuts for efficiency
        if len(cuts) > 2000:
            # Keep only the most recent cuts
            cuts = cuts[-2000:]
        
        # Solve LP
        m = len(cuts)
        A = np.zeros((m, n + 1))
        b_vec = np.zeros(m)
        for i, (g_i, b_i) in enumerate(cuts):
            A[i, :n] = g_i
            A[i, n] = -1.0
            b_vec[i] = b_i
        
        c = np.zeros(n + 1)
        c[n] = 1.0
        A_eq = np.ones((1, n + 1))
        A_eq[0, n] = 0.0
        b_eq = np.array([target_sum])
        bounds_lp = [(0.0, 1.0)] * n + [(-1e6, 1e6)]
        
        res = linprog(c, A_ub=A, b_ub=b_vec, A_eq=A_eq, b_eq=b_eq,
                      bounds=bounds_lp, method='highs')
        if not res.success:
            # Try without some cuts
            cuts = cuts[-1000:]
            continue
        
        h_lp = res.x[:n]
        h_lp = project_feasible(h_lp, target_sum)
        score = compute_c5(h_lp)
        
        if score < best_score:
            best_score = score
            best_h = h_lp.copy()
            h = h_lp
        else:
            # Try damped step
            for damp in [0.5, 0.25, 0.1]:
                h_damped = project_feasible((1-damp)*h + damp*h_lp, target_sum)
                sc = compute_c5(h_damped)
                if sc < best_score:
                    best_score = sc
                    best_h = h_damped.copy()
                    h = h_damped
                    break
            else:
                break  # Stagnation
    
    return best_h, best_score
```

This is a proper cutting-plane method! The key advantage over the previous approach is that we accumulate cuts, so the LP gets more restrictive over time, driving the solution toward the true optimum.

However, there's a subtlety: the cuts are linearizations of a non-convex function, so they might not be valid (i.e., the true function might go above the cut). This means the LP solution might not be feasible for the true problem. We handle this by always checking the true objective value.

To make the cuts more reliable, we can use a "second-order correction": instead of just the first-order Taylor approximation, we can add a small quadratic penalty that keeps us close to the linearization point. But this makes it a QP, not an LP.

An alternative: add cuts from MULTIPLE points, not just the current one. If we have a cut from point x_1 and a cut from point x_2, the intersection of the two half-spaces is more restrictive and more likely to contain the true sublevel set.

Actually, for a quadratic function f(x) = x^T A x + b^T x + c, the first-order Taylor approximation at x_0 gives:
f(x) ≥ f(x_0) + ∇f(x_0)^T (x - x_0) - (x-x_0)^T |A| (x-x_0)

where |A| is some bound on the quadratic term. This gives a valid lower bound (cutting plane) if we can bound |A|.

For our case, f = corr[k] = sum_i h[i] - sum_i h[i]h[i+k], and the Hessian has eigenvalues bounded by 4 (in absolute value). So:
f(x) ≥ f(x_0) + ∇f(x_0)^T (x - x_0) - 4*||x - x_0||^2

But this introduces a quadratic term, making it a SOCP (second-order cone program), not an LP. We could use SOCP, but the solvers might be slower.

For now, let me stick with the first-order cuts and rely on the fact that small steps keep us in the region where the linearization is accurate.

```python
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(corr)) * dx

def project_feasible(h, target_sum):
    h = np.clip(h.astype(float).copy(), 0.0, 1.0)
    diff = target_sum - np.sum(h)
    if abs(diff) < 1e-12:
        return h
    for _ in range(100):
        if diff > 0:
            free = h < 1.0 - 1e-14
            nfree = free.sum()
            if nfree == 0:
                break
            per = diff / nfree
            h[free] = np.minimum(h[free] + per, 1.0)
        else:
            free = h > 1e-14
            nfree = free.sum()
            if nfree == 0:
                break
            per = diff / nfree
            h[free] = np.maximum(h[free] + per, 0.0)
        diff = target_sum - np.sum(h)
        if abs(diff) < 1e-12:
            break
    return np.clip(h, 0.0, 1.0)

def overlap_corrs(h):
    return np.correlate(h, 1.0 - h, mode='full')

def compute_grad_single_lag(h, lag_idx):
    n = len(h)
    lag = lag_idx - (n - 1)
    grad = np.zeros(n)
    if lag >= 0:
        if lag < n:
            grad[lag:] += (1.0 - h[:n - lag])
            grad[:n - lag] -= h[lag:]
    else:
        m = -lag
        if m < n:
            grad[:n - m] += (1.0 - h[m:])
            grad[m:] -= h[:n - m]
    return grad

def compute_grad_multi_lag(h, lag_indices, weights):
    n = len(h)
    grad = np.zeros(n)
    for i in range(len(lag_indices)):
        w = weights[i]
        if w < 1e-14:
            continue
        lag = lag_indices[i] - (n - 1)
        if lag >= 0:
            if lag < n:
                grad[lag:] += w * (1.0 - h[:n - lag])
                grad[:n - lag] -= w * h[lag:]
        else:
            m = -lag
            if m < n:
                grad[:n - m] += w * (1.0 - h[m:])
                grad[m:] -= w * h[:n - m]
    return grad

def cons_eq_fun(x):
    return np.sum(x) - _CONS_TARGET

def cons_eq_jac(x):
    return np.ones(_CONS_N)

def smooth_max_obj(x, alpha, topk):
    corr = overlap_corrs(x)
    n_corr = len(corr)
    if topk < n_corr:
        top_idx = np.argpartition(corr, -topk)[-topk:]
        top_vals = corr[top_idx]
        c_ref = np.max(top_vals)
        shifted = np.clip(alpha * (top_vals - c_ref), -500.0, 0.0)
        return c_ref + np.log(np.sum(np.exp(shifted))) / alpha
    else:
        c_max = np.max(corr)
        shifted = np.clip(alpha * (corr - c_max), -500.0, 0.0)
        return c_max + np.log(np.sum(np.exp(shifted))) / alpha

def smooth_max_grad(x, alpha, topk):
    corr = overlap_corrs(x)
    n_corr = len(corr)
    if topk < n_corr:
        top_idx = np.argpartition(corr, -topk)[-topk:]
        top_vals = corr[top_idx]
        c_ref = np.max(top_vals)
        exp_shifted = np.exp(np.clip(alpha * (top_vals - c_ref), -500.0, 0.0))
        total = np.sum(exp_shifted)
        weights = exp_shifted / total
        return compute_grad_multi_lag(x, top_idx, weights)
    else:

        total = np.sum(exp_shifted)
        weights = exp_shifted / total
        return compute_grad_multi_lag(x, np.arange(n_corr), weights)

def slsqp_optimize(h_start, target_sum, alpha_topk_pairs, maxiter, ftol):
```
