Wait, this isn't quite right for a convex piecewise-linear function. Let me think again.

g(δ) = max_k (corr[k] + δ * slopes[k])

This is convex in δ. The subdifferential at δ is:
∂g(δ) = convex hull of {slopes[k] : k is active at δ}

The minimum is where 0 ∈ ∂g(δ), i.e., where there exist active k1, k2 with slopes[k1] ≤ 0 ≤ slopes[k2].

For the binary search:
- If all active slopes < 0: g is decreasing at δ, so minimum is to the right → lo = mid
- If all active slopes > 0: g is increasing at δ, so minimum is to the left → hi = mid
- If some active slopes < 0 and some > 0: we're at the minimum (or a flat region)

But there's a subtlety: at a "kink" point, the subdifferential is an interval [min_active_slope, max_active_slope]. If this interval contains 0, we're at a minimum.

The binary search I wrote above should work, but the convergence might be slow if the function is flat over a large interval. In that case, we want to find any point in the flat minimum interval.

Let me use a different approach: since g is piecewise-linear and convex, its minimum is achieved at a breakpoint or at a flat interval. The breakpoints occur where two functions cross:
corr[k1] + δ * slopes[k1] = corr[k2] + δ * slopes[k2]
δ = (corr[k2] - corr[k1]) / (slopes[k1] - slopes[k2])

But there could be O(n²) breakpoints. Instead, let's use the binary search approach and accept that we'll find a point near the minimum.

Actually, for a piecewise-linear convex function, the binary search I described converges in O(log(range/tol)) iterations, and at each iteration we can check if we're at a minimum. Since the slopes are "quantized" (they're sums/differences of h values), the minimum will be at a specific δ where two specific corr functions cross. But finding it exactly requires solving a 2-SAT-like problem.

For practical purposes, the binary search with 50 iterations should give us δ to precision 2^(-50) * range, which is more than enough.

Let me also think about efficiency. The binary search requires O(n) work per iteration (to compute vals = corr + δ*slopes and find the max and active set). Wait, there's an issue. When I update h[i] and h[j], the slopes for future pairs change. I'm using the old corr and updating it with the slope, which is an approximation (first-order). This is fine for small moves but could be inaccurate for large moves.

For correctness, I should recompute corr after each update (or at least every few updates). The cost of recomputing corr is O(n²) = 160,000 for n=400, which is fast.

Actually, the update corr += delta * slopes is EXACT for the pair (i,j) move, because c_k is linear in h[i] and h[j] (for fixed other values). So the first-order update is exact for the immediate effect. However, it doesn't capture second-order effects (there are none, since c_k is linear in each h[i] individually). So the update IS exact!

Wait, is c_k linear in h[i]? Let's see:
c_k = Σ_n h[n+k] * (1-h[n])

If I change h[i] by δ, which terms change?
- Terms where i = n+k: h[i] * (1-h[i-k]) changes by δ * (1-h[i-k])
- Terms where i = n: h[i+k] * (1-h[i]) changes by h[i+k] * (-δ)

So the change in c_k is: δ * [(1-h[i-k]) - h[i+k]] (for valid indices)

This is exactly δ * ∂c_k/∂h[i] = δ * slope_i[k].

And the change due to h[j] going from h[j] to h[j]-δ is:
-δ * ∂c_k/∂h[j] = -δ * slope_j[k]

Total change: δ * (slope_i[k] - slope_j[k]) = δ * slopes[k]. ✓

So the update IS exact! We can safely use corr += delta * slopes without needing to recompute.

However, there's a subtlety: after the update, h[i] and h[j] have changed, so the slopes for FUTURE pairs will be different. But we recompute slopes for each new pair, so this is handled correctly.

The only issue is if h[i] or h[j] hits a boundary (0 or 1). In that case, the move is clipped, and the actual change is less than δ. We need to handle this.

def pair_descent_sweep(h, target, pair_list, n_inner=1, tol=1e-10):

    corr = compute_corr(h)
    best_score = float(np.max(corr))
    initial_score = best_score
    
    for _ in range(n_inner):
        improved = False
        for (i, j) in pair_list:
            if i == j:
                continue
            slopes = compute_slopes_for_pair(h, i, j)
            
            delta_min = max(-h[i], h[j] - 1.0)
            delta_max = min(1.0 - h[i], h[j])
            if delta_max - delta_min < 1e-15:
                continue
            
            delta = find_optimal_delta(corr, slopes, delta_min, delta_max)
            
            if abs(delta) > 1e-12:
                h[i] += delta
                h[j] -= delta
                h[i] = np.clip(h[i], 0.0, 1.0)
                h[j] = np.clip(h[j], 0.0, 1.0)
                
                # If clipping occurred, recompute
                if h[i] != 0.0 and h[i] != 1.0 and h[j] != 0.0 and h[j] != 1.0:
                    corr += delta * slopes
                else:
                    corr = compute_corr(h)
                
                new_max = float(np.max(corr))
                if new_max < best_score - 1e-15:
                    best_score = new_max
                    improved = True
        
        if not improved and best_score > initial_score - tol:
            break
    
    return h, best_score

def compute_corr(h):
    return np.correlate(h, 1.0 - h, mode='full')

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    return float(np.max(compute_corr(h))) * dx

def project_feasible(h, target_sum):
    h = np.clip(h.astype(float), 0.0, 1.0)
    for _ in range(1000):
        diff = target_sum - np.sum(h)
        if abs(diff) < 1e-14:
            break
        if diff > 0:
            mask = h < 1.0 - 1e-15
        else:
            mask = h > 1e-15
        cnt = int(mask.sum())
        if cnt == 0:
            break
        h = h.copy()
        h[mask] += diff / cnt
        h = np.clip(h, 0.0, 1.0)
    return h

def compute_slopes_for_pair(h, i, j):
    n = len(h)
    out_len = 2 * n - 1
    slope = np.zeros(out_len)
    slope[n-1 : n+i] += (1.0 - h[0:i+1])[::-1]
    slope[n-1-i : 2*n-1-2*i] -= h[0:n-i]
    slope[n-1 : n+j] -= (1.0 - h[0:j+1])[::-1]
    slope[n-1-j : 2*n-1-2*j] += h[0:n-j]
    return slope

def find_optimal_delta(corr, slopes, dmin, dmax, niters=50):
    lo = dmin
    hi = dmax
    if hi - lo < 1e-14:
        return lo
    for _ in range(niters):
        mid = (lo + hi) * 0.5
        vals = corr + mid * slopes
        mx = np.max(vals)
        active = vals >= mx - 1e-12
        ms = np.min(slopes[active])
        xs = np.max(slopes[active])
        if ms <= 0.0 and xs >= 0.0:
            return mid
        elif xs < 0.0:
            lo = mid
        else:
            hi = mid
    return (lo + hi) * 0.5

            continue

        dmin = max(-h[i], h[j] - 1.0)
        dmax = min(1.0 - h[i], h[j])
        if dmax - dmin < 1e-14:
            continue
        delta = find_optimal_delta(corr, slopes, dmin, dmax)
        delta *= relax

            new_score = float(np.max(corr))
