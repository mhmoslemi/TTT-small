- As h[j] in the term h[j]*(1-h[j+d]) (coefficient: (1-h[j+d]))
- As h[j+d] in the term h[j-d]*(1-h[j]) (coefficient: -h[j-d])

So corr_d is linear in h[j]: corr_d = A_d * h[j] + B_d where A_d = (1-h[j+d]) - h[j-d] (with appropriate index handling) and B_d is everything else.

Therefore, f(h[j]) = max_d (A_d * h[j] + B_d) which is the max of linear functions of h[j], hence convex and piecewise linear!

We can find the minimum of this convex piecewise-linear function exactly:
- It's minimized at the "kink" point where two lines cross, or at a boundary (0 or 1), or at the point where the slope changes from negative to positive.
- The slope at h[j] = x is: sum of A_d for all d where the line A_d*x + B_d is the maximum.
- We can binary search for the point where the slope changes sign.

This gives us an EXACT coordinate descent step! And it's very fast because we just need to evaluate the max of linear functions at a few points.

Let me implement this:

```python
def _optimal_coord_value(h, j, n):
    """Find the optimal value of h[j] given all other h fixed.
    
    The objective as a function of h[j] = x is:
    f(x) = max_k (A_k * x + B_k)
    where A_k and B_k are computed from the current h (with h[j] = 0 for computing B_k... 
    actually we need to be careful).
    
    For lag d (corresponding to correlation index k = (n-1)+d):
    corr_d(h) = sum_{i in valid(d)} h[i] * (1 - h[i+d])
    
    h[j] appears in corr_d as:
    - h[j] * (1-h[j+d]) if j is a valid first index for lag d → coefficient (1-h[j+d])
    - h[j-d] * (1-h[j]) if j-d is a valid first index for lag d → coefficient -h[j-d]
    
    So: corr_d = A_d * h[j] + B_d
    where A_d = (1-h[j+d]) * I_j_first(d) - h[j-d] * I_jd_first(d)
    and B_d = corr_d(h) - A_d * h[j] (computed with current h[j])
    
    The objective is f(x) = max_d (A_d * x + B_d) for x ∈ [0,1].
    This is convex (max of linear functions). Its minimum is at the point where
    the subgradient contains 0, or at a boundary."""
    
    dx = 2.0 / n
    h_save = h[j]
    
    # Compute A_d and B_d for all lags
    # For efficiency, compute corr for all lags at h[j]=0 and h[j]=1
    h0 = h.copy()
    h0[j] = 0.0
    h1 = h.copy()
    h1[j] = 1.0
    
    corr0 = np.correlate(h0, 1.0 - h0, mode='full')
    corr1 = np.correlate(h1, 1.0 - h1, mode='full')
    
    # f(x) = max_k (corr0[k] + x * (corr1[k] - corr0[k]))
    # = max_k (B_k + x * A_k)
    B = corr0  # B_k = corr_k with h[j]=0
    A = corr1 - corr0  # A_k = corr_k(h[j]=1) - corr_k(h[j]=0)
    
    # f(x) = max_k (B_k + A_k * x) for x in [0,1]
    # This is convex. Minimum is where subgradient = 0.
    # Subgradient at x: {sum of A_k for k in argmax} if unique max
    #                            [min_A_active, max_A_active] if multiple
    
    # Find minimum: binary search on x
    lo, hi = 0.0, 1.0
    for _ in range(60):
        mid = (lo + hi) / 2.0
        vals = B + A * mid
        k_max = np.argmax(vals)
        max_val = vals[k_max]
        # Check if mid is in subgradient of 0
        active = np.where(vals >= max_val - 1e-12)[0]
        min_A = A[active].min()
        max_A = A[active].max()
        if min_A <= 0 <= max_A:
            lo = mid
            hi = mid
            break
        elif min_A > 0:
            # f is increasing at mid, go left
            hi = mid
        else:
            # f is decreasing at mid, go right
            lo = mid
    
    x_opt = (lo + hi) / 2.0
    h[j] = h_save  # restore
    return x_opt
```

Wait, this is brilliant! And it's exact! The key insight is:

**Given all other coordinates fixed, the objective as a function of h[j] is the max of linear functions, hence convex and piecewise linear. We can find its minimum exactly via binary search.**

This gives us exact coordinate descent, which is much better than the previous heuristic approaches.

The computational cost per coordinate is O(n * 2n) = O(n²) for the two correlation computations. For n=140, that's about 40,000 operations per coordinate, and 140 coordinates, so about 5.6 million operations per full pass. That's very fast.

Let me refine this:

Actually, I realize I can make it even faster. Instead of computing the full correlation for h0 and h1 each time, I can compute A and B analytically:

For a given lag d (correlation index k = (n-1)+d):
- A_k = contribution of h[j] to corr_k when h[j]=1 minus when h[j]=0
  = (1-h[j+d]) * I(j valid first for d) - h[j-d] * I(j-d valid first for d)
  
  Wait, this is the same as the gradient! A_k = _grad_corr(h, k) [with h[j] removed from the gradient... actually no, the gradient IS the coefficient of h[j] in corr_k when all other variables are fixed.]

Actually, let me just verify: if corr_k is linear in h[j] (with other variables fixed), then:
corr_k(h[j]=1) - corr_k(h[j]=0) = d corr_k / d h[j] (evaluated with other variables fixed)

And this is exactly what _grad_corr computes (when the other variables are at their current values). But _grad_corr uses the current h[j] in the formula... let me check.

_grad_corr(h, k) computes:
For lag d ≥ 0:
  grad[:m] += (1.0 - h[lag:lag+m])  → for index j in [0, m): grad[j] += (1-h[j+lag])
  grad[lag:] += -h[:m]  → for index j in [lag, n): grad[j] += -h[j-lag]

So grad[j] = (1-h[j+lag]) * I(0≤j<m) + (-h[j-lag]) * I(j≥lag, j<n)

This is the coefficient of h[j] in the linear expression corr_k = ... + h[j] * coeff + ...

Yes! So A_k = _grad_corr(h, k)[j] (using the current h for the other variables).

And B_k = corr_k(h) - A_k * h[j] = corr_k(h) - _grad_corr(h, k)[j] * h[j]

So I can compute f(x) = max_k (B_k + A_k * x) without computing two full correlations!
