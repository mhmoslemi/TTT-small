Rather than analytically computing a_m and b_m (which is error-prone), I can:

2. Compute all correlations for each

Better approach: use the fact that changing h[j] only affects a limited set of correlations. Specifically, changing h[j] only affects c_m where |m| <= min(j, n-1-j) (as I derived above). For j near the center, this is about n/2 correlations. For j near the edges, it's fewer.

1. Compute the "base" correlations (with h[j] at its current value)
2. For each t in the grid, compute the affected correlations as a_m * t + b_m (or the quadratic for m=0)
3. Take max over all correlations (affected + unaffected)
4. Pick the best t

Step 1 costs O(n^2) (one full correlation computation per sweep, not per coordinate).
Step 2 costs O(n_grid * M) where M = min(j, n-1-j) ≈ n/2.
Step 3 is O(n) per t (take max of all correlations).

**Algorithm: Coordinate Descent with SA**

1. Start from initial_h_values (projected to be feasible)
2. Alternate between:
   a. Coordinate descent sweeps (several sweeps)
   b. SA steps (to escape local optima)
3. Track best solution found

The key advantage over the previous approach:
- Coordinate descent directly optimizes the true (non-smooth) objective
- No smoothing parameter needed
- Each step is a 1D optimization (exact, not approximate)
- Can handle continuous values naturally

Let me also think about the **sum constraint**. When I change h[j] from h[j]_old to t, the sum changes by (t - h[j]_old). To maintain the sum constraint, I need to compensate.

Options:
1. After each coordinate update, project back to the feasible set (adjust all other coordinates proportionally)
2. Use a "paired update": when I set h[j] = t, I adjust one other coordinate h[k] to maintain the sum
3. Use a Lagrange multiplier approach

Option 2 is cleanest for coordinate descent. When I set h[j] = t, the sum changes by delta = t - h[j]_old. I need to find another coordinate k (k ≠ j) and adjust it by -delta (i.e., h[k] = h[k] - delta), keeping it in [0,1].

But this makes the 1D optimization more complex because changing h[k] also affects correlations.

Alternative: Use a "dual coordinate descent" where I optimize h[j] and simultaneously adjust a "global" variable to maintain the sum. Or, I can use a penalty method: add a large penalty for violating the sum constraint.

Actually, the simplest approach: after each coordinate update, project to the feasible set. The projection is: if the sum is too high, reduce the largest elements; if too low, increase the smallest. This is a small perturbation (at most 1/n of the total adjustment spread over n elements), so it shouldn't hurt much.

Or even simpler: use a "free" coordinate descent where I ignore the sum constraint during the 1D optimization, then project at the end of each sweep. The projection is cheap and the performance hit is minimal.

Actually, let me think about this differently. The sum constraint is sum(h) = n/2. If I change h[j] by delta, I need to change the sum of the other n-1 coordinates by -delta. The simplest way is to spread it evenly: add -delta/(n-1) to each other coordinate. This is a tiny perturbation (|delta| ≤ 1, so |delta|/(n-1) ≤ 1/599 ≈ 0.0017).

Let me implement this: after setting h[j] = t, add (h[j]_old - t)/(n-1) to all other coordinates. Then clip to [0,1].

This is approximate but should work well in practice.

def project_feasible(h, target_sum):
    h = np.clip(h.astype(float), 0.0, 1.0)
    diff = target_sum - np.sum(h)
    if abs(diff) < 1e-14:
        return h
    if diff > 0:
        idx = np.where(h < 1.0)[0]
    else:
        idx = np.where(h > 0.0)[0]
    if len(idx) == 0:
        return h
    h = h.copy()
    h[idx] += diff / len(idx)
    return np.clip(h, 0.0, 1.0)

def project_binary(h, target_sum):
    n = len(h)
    h_r = np.round(h)
    h_r = np.clip(h_r, 0, 1).astype(int)
    current_sum = h_r.sum()
    if current_sum == target_sum:
        return h_r.astype(float)
    ones = np.where(h_r == 1)[0]

            h_r[ones[order]] = 0
    else:

    n = len(h)
    M = min(j, n - 1 - j)

    corr = compute_correlations(h)

        corr_unaffected = np.delete(corr, range(idx_start, idx_end + 1))

        k = n - 1 + m
        if m == 0:

            has_quad = True
        elif m > 0:
            a[idx] = 1.0 - h[j + m] - h[j - m]
            b[idx] = corr[k] - h[j] * (1.0 - h[j + m]) - h[j - m] * (1.0 - h[j]) + h[j - m]

Hmm, I realize the `coord_optimize` function is going to be the bottleneck. Let me think about how to speed it up.

For each coordinate j, the computation is:
1. Compute correlations: O(n^2) (but we can cache this across the sweep)
2. Extract affected portion: O(M) where M ≈ n/2
3. Compute a and b: O(M)
4. Evaluate f(t) for all t in grid: O(M * |t_grid|)

Step 1 is the expensive one. If I recompute correlations for every coordinate, that's O(n^3) per sweep.

Better: compute correlations once at the start of the sweep, and update them incrementally. When I change h[j] from old to new, the correlations change by:
- For affected m: c_m changes by a_m * (new - old) (approximately, since a_m depends on h which is changing)

Actually, the a_m values depend on h[j+m] and h[j-m], which don't change when I modify h[j]. So I can compute a_m once and reuse it. But the actual correlation values do change, so I need to update them.

Let me restructure: maintain the correlation array and update it incrementally.

When h[j] changes from old_val to new_val:
- For m > 0 where m <= min(j, n-1-j):
  c_m changes by: new_val*(1-h[j+m]) + h[j-m]*(1-new_val) - [old_val*(1-h[j+m]) + h[j-m]*(1-old_val)]
                 = (new_val - old_val) * (1 - h[j+m] - h[j-m])
                 = delta * a_m

- For m < 0 (p = -m) where p <= min(j, n-1-j):
  c_{-p} changes by: new_val*(1-h[j-p]) + h[j+p]*(1-new_val) - [old_val*(1-h[j-p]) + h[j+p]*(1-old_val)]
                    = delta * (1 - h[j-p] - h[j+p])
                    = delta * a_{-p}

- For m = 0:
  c_0 changes by: new_val*(1-new_val) - old_val*(1-old_val)
                = -(new_val^2 - old_val^2) + (new_val - old_val)
