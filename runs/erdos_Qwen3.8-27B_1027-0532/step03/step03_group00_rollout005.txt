Let me also think about the binary search more. The issue with simulated annealing is that it's slow (only one swap per iteration). A better approach for binary:

**Greedy local search with all-pair evaluation:**
1. For the current binary h, compute count[d] for all d
2. For each 1-position a, compute Δ_a[d] (change in count if we flip a to 0)
3. For each 0-position b, compute Δ_b[d] (change in count if we flip b to 1)
4. For each pair (a,b), the new max is max_d(count[d] + Δ_a[d] + Δ_b[d])
5. Find the pair that minimizes this max
6. Apply the best pair

Step 4 is the expensive part: O(n²) pairs × O(n) lags = O(n³). For n=400, that's 64M × 400 = 25.6B operations. Too slow.

But we can be smarter. After step 2-3, we have:
- Δ_a: shape (200, 399) for the 200 one-positions
- Δ_b: shape (200, 399) for the 200 zero-positions

For pair (a,b): new_count[d] = count[d] + Δ_a[a, d] + Δ_b[b, d]
new_max = max_d(new_count[d])

We want argmin_{a,b} new_max.

This is still O(n² × n) = O(n³) in the naive approach. But we can vectorize:
- new_count for all pairs: shape (200, 200, 399) → 16M × 399 = too much memory

Alternative: for each a (200 options), find the best b:
- For fixed a, new_count_b[d] = (count[d] + Δ_a[a,d]) + Δ_b[b,d]
- Let base[d] = count[d] + Δ_a[a,d]
- We want argmin_b max_d(base[d] + Δ_b[b,d])
- For each b, this is max_d(base[d] + Δ_b[b,d]) which is O(n)
- So for fixed a, finding best b is O(n²)
- Total: O(n³) = 64M. In numpy, this should take about 1-2 seconds per full pass.

Actually wait, for fixed a, I can vectorize over b:
- Δ_b is shape (200, 399)
- base is shape (399,)
- new_count = base[None, :] + Δ_b  # shape (200, 399)
- new_max = new_count.max(axis=1)  # shape (200,)
- best_b = new_max.argmin()

This is O(n²) with numpy vectorization, which is ~160K operations per a, and 200 a's = 32M total. Should take ~0.1 seconds in numpy.

So one full greedy pass is ~0.1 seconds! We can do many passes.
