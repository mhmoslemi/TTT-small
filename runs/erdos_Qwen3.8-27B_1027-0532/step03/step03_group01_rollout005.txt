```python
    dx = 2.0 / n
    v = 1.0 - h
    # Pad to at least 2n-1, use next power of 2 for FFT efficiency
    size = 1

        size *= 2
    H = np.fft.fft(h, size)
    V = np.fft.fft(v, size)
```

**New strategy: Iterated Lag-Directed Local Search**

The key insight is:
- At each state, identify the "critical" lag (the one with maximum correlation)
- Generate swaps that specifically reduce the correlation at that lag
- Use a "tabu list" to avoid cycling

For a swap of h[i]: 1→0 and h[j]: 0→1:
- The change in correlation at lag d is:
  - If we remove a 1 at position i: we lose contributions to CC at all lags d where h[i-d]=0 (i.e., we reduce CC at those lags by 1 each... wait, this gets complicated because CC depends on both h and 1-h.

Let me think about this differently. For a binary h, CC(d) = sum_{valid i} h[i] * (1-h[i+d]).

When we change h[i] from 1 to 0:
- CC(d) changes by: -(1-h[i+d]) for the term where the "i" in the sum is our index
- Plus: for all j such that j+d = i (i.e., j = i-d), the term h[j]*(1-h[j+d]) changes from h[j]*(1-1)=0 to h[j]*(1-0)=h[j], so CC(d) changes by +h[i-d] (if i-d is valid)

So ΔCC(d) = -（1-h[i+d]） + h[i-d] (for the removal at position i)

Similarly, when we change h[j] from 0 to 1:
- CC(d) changes by: +(1-h[j+d]) for the term where our index is the "i"
- Plus: for all k such that k+d = j (k = j-d), the term changes from h[k]*(1-0)=h[k] to h[k]*(1-1)=0, so CC(d) changes by -h[j-d]

So ΔCC(d) for the full swap (i: 1→0, j: 0→1) is:
ΔCC(d) = -(1-h[i+d]) + h[i-d] + (1-h[j+d]) - h[j-d]
        = h[i+d] - 1 + h[i-d] + 1 - h[j+d] - h[j-d]
        = h[i+d] + h[i-d] - h[j+d] - h[j-d]

(with the convention that h[x] = 0 if x is out of [0, n-1])

So the change in CC at lag d is: h[i+d] + h[i-d] - h[j+d] - h[j-d]

This is very useful! It means:
- To reduce CC at lag d, we want to find (i, j) swaps where h[i+d] + h[i-d] is small and h[j+d] + h[j-d] is large.
- In other words: remove a 1 at a position where its neighbors at distance d are mostly 1s (so removing it doesn't increase CC much), and add a 1 at a position where its neighbors at distance d are mostly 0s (so adding it reduces CC).

This gives us a very efficient way to do targeted local search!

Let me implement this:

```python
def lag_directed_move(h, target_lag, rng):
    """Find a swap that reduces CC at the target lag."""
    n = len(h)
    ones = np.where(h == 1)[0]
    zeros = np.where(h == 0)[0]
    
    if len(ones) == 0 or len(zeros) == 0:
        return None, None
    
    d = target_lag
    # For each 1 at position i, compute "cost of removing" = h[i+d] + h[i-d] (lower is better)
    # For each 0 at position j, compute "benefit of adding" = h[j+d] + h[j-d] (higher is better)
    
    # We want to minimize: h[i+d] + h[i-d] - h[j+d] - h[j-d]
    # = (h[i+d] + h[i-d]) - (h[j+d] + h[j-d])
    
    def shifted_val(arr, d):
        """Compute arr[x+d] + arr[x-d] for all valid x, with 0 padding."""
        n = len(arr)
        result = np.zeros(n)
        # arr[x+d] for x = 0 to n-1-d
        if d >= 0:
            valid = slice(0, n-d)
            result[valid] += arr[d:]
            # arr[x-d] for x = d to n-1
            result[d:] += arr[:n-d]
        # Handle out-of-bounds as 0
        return result
    
    # For the target lag d (which could be positive or negative in the full correlation)
    # Actually, in our formulation, d is the "shift" in the correlation
    # full[k] corresponds to lag (k - (n-1))
    # So target_lag is the actual shift
    
    cost_ones = shifted_val(h, d)  # h[i+d] + h[i-d] for each i
    benefit_zeros = shifted_val(h, d)  # same formula for j (but h[j] = 0 here)
    
    # Wait, this isn't quite right. Let me redo.
    # ΔCC(d) for swap (i: 1→0, j: 0→1) = h[i+d] + h[i-d] - h[j+d] - h[j-d]
    # We want this to be negative (to reduce CC at lag d).
    # So we want: h[i+d] + h[i-d] < h[j+d] + h[j-d]
    
    # For i (a 1-position): score_i = h[i+d] + h[i-d] (want this small)
    # For j (a 0-position): score_j = h[j+d] + h[j-d] (want this large)
    
    # Compute for all positions:
    s = np.zeros(n)
    if d > 0:
        s[:n-d] += h[d:]      # h[x+d] for x in [0, n-d-1]
        s[d:] += h[:n-d]      # h[x-d] for x in [d, n-1]
    elif d < 0:
        d_abs = -d
        s[d_abs:] += h[:n-d_abs]  # h[x+d] = h[x-d_abs] for x in [d_abs, n-1]
        s[:n-d_abs] += h[d_abs:]  # h[x-d] = h[x+d_abs] for x in [0, n-d_abs-1]
    # d == 0: s = 0 (no effect on CC(0) which is always 0 for binary)
    
    # For 1-positions, we want small s[i]
    # For 0-positions, we want large s[j]
    
    # Score for the swap = s[i] - s[j] (we want this negative)
    # Best swap: minimize s[i] - s[j] = minimize s[i] + maximize s[j]
    
    # Pick the 1 with smallest s[i] and the 0 with largest s[j]
    best_i = ones[np.argmin(s[ones])]
    best_j = zeros[np.argmax(s[zeros])]
    
    delta = s[best_i] - s[best_j]
    if delta < 0:
        return best_i, best_j
    else:
        return None, None
```

This is O(n) per move (to compute s) + O(n) to find best i and j. Very fast!

But we also need to update the correlation vector efficiently after each move. The change in CC at ALL lags (not just the target lag) matters for tracking the overall C₅.

When we swap i (1→0) and j (0→1), the change in CC at lag d' is:
ΔCC(d') = h[i+d'] + h[i-d'] - h[j+d'] - h[j-d']

We can compute this for all d' in O(n) time.

So the algorithm becomes:
1. Initialize h (binary)
2. Compute CC vector (O(n²) once, or O(n) per step after that)
3. At each step:
   a. Find max lag d* (O(n))
   b. Compute s = h[x+d*] + h[x-d*] for all x (O(n))
   c. Find best swap (i, j) that reduces CC(d*) (O(n))
   d. If found, compute ΔCC for all lags (O(n))
   e. Update CC vector (O(n))
   f. Check if new max < old max → accept
   g. Otherwise, try a random swap or use simulated annealing criterion

Wait, step d is O(n²) if naively done (for each lag d', compute h[i+d'] + h[i-d'] - h[j+d'] - h[j-d']). But we can do it in O(n) using the same "shifted" computation:

ΔCC = shifted_val(h without the swap, i) - shifted_val(h without the swap, j)
    = (h[i+d'] + h[i-d'] for all d') - (h[j+d'] + h[j-d'] for all d')

The first term is a vector of length 2n-1 (for all lags d'), and it's just the "correlation contribution" of a single 1 at position i. Specifically:
- For a 1 at position i, its contribution to CC(d') is: 1*(1-h[i+d']) for the "positive" part and h[i-d']*(1-1)=0 for the "negative" part... 

Hmm, this is getting complicated. Let me just use the fact that n=600 and O(n²) = 360,000 operations per step is fast enough in Python with numpy.

Actually, let me reconsider. If I use the formula:
ΔCC(d') = h[i+d'] + h[i-d'] - h[j+d'] - h[j-d']

I can compute this vector in O(n) using two "shifted" arrays:
- shift_i[d'] = h[i+d'] + h[i-d'] for all d' = -(n-1), ..., 0, ..., n-1
- shift_j[d'] = h[j+d'] + h[j-d'] for all d'

Each of these is just two shifted copies of h, so O(n) to compute.

Then ΔCC = shift_i - shift_j, which is O(n).

Total per step: O(n) for s computation + O(n) for ΔCC + O(n) for CC update + O(n) for max = O(n) per step!

For n=600, each step is about 2400 operations (4 * 600). In Python with numpy, this is maybe 10-20 microseconds per step. So we can do about 5-10 million steps per 1000 seconds. That's a lot!

2. **Phase 2**: Multi-start with random binary initializations
3. **Phase 3**: "Perturbation + local search" (like GRASP or iterated local search)

- Or: take a random subset of the worst lags and try to fix them simultaneously

Let me also think about a "block move" strategy:
- Select a contiguous block of positions
- Try all possible binary patterns for that block (with the correct number of 1s)
- Keep the best

For a block of size 8 with 4 ones, there are C(8,4) = 70 possibilities. For each, we can compute the change in CC in O(n) time. So evaluating all 70 patterns takes 70*600 = 42,000 operations, which is fast.

This "block improvement" is a powerful local search move that can escape from simple 1-swap local optima.

```python
def project_binary(h, target_sum):
    n = len(h)
    h_r = np.round(h)
    h_r = np.clip(h_r, 0, 1).astype(int)
    current_sum = h_r.sum()
    if current_sum == target_sum:
        return h_r.astype(float)
    if current_sum > target_sum:
        need = int(current_sum - target_sum)
        ones = np.where(h_r == 1)[0]
        order = np.argsort(h[ones])[:need]
        h_r[ones[order]] = 0
    else:
        need = int(target_sum - current_sum)
        zeros = np.where(h_r == 0)[0]
        order = np.argsort(-h[zeros])[:need]
        h_r[zeros[order]] = 1
    # Verify
    if h_r.sum() != target_sum:
        if h_r.sum() > target_sum:
            ones = np.where(h_r == 1)[0]
            h_r[ones[:int(h_r.sum() - target_sum)]] = 0

            h_r[zeros[:int(target_sum - h_r.sum())]] = 1
```

```python
def compute_delta_cc_all(h, i, j):
    """Compute delta CC vector for swap i(1->0), j(0->1)."""
    n = len(h)
    # For each lag index k (0 to 2n-2), the lag is d = k-(n-1)
    # Delta = h[i+d] + h[i-d] - h[j+d] - h[j-d]
    # where out-of-bounds = 0
    
    d = np.arange(-(n-1), n)  # lags from -(n-1) to n-1
    
    # h[i+d]: valid when 0 <= i+d < n, i.e., -i <= d < n-i
    a = np.zeros(2*n-1)
    valid_a = (d >= -i) & (d < n-i)
    a[valid_a] = h[i + d[valid_a]]
    
    # h[i-d]: valid when 0 <= i-d < n, i.e., i-n < d <= i
    b = np.zeros(2*n-1)
    valid_b = (d > i-n) & (d <= i)
    b[valid_b] = h[i - d[valid_b]]
    
    # h[j+d]: valid when 0 <= j+d < n
    c = np.zeros(2*n-1)
    valid_c = (d >= -j) & (d < n-j)
    c[valid_c] = h[j + d[valid_c]]
    
    # h[j-d]: valid when 0 <= j-d < n, i.e., j-n < d <= j
    e = np.zeros(2*n-1)
    valid_e = (d > j-n) & (d <= j)
    e[valid_e] = h[j - d[valid_e]]
    
    return a + b - c - e
```

```python
def local_search_lag_directed(h0, target, max_iters, rng, time_limit=None, start_time=None):
    n = len(h0)
    h = h0.copy().astype(float)
    corr = compute_cc_vector(h)
    current_c5_val = float(np.max(corr))  # without dx factor for comparison
    
    ones = np.where(h == 1)[0]
    zeros = np.where(h == 0)[0]
    
    no_improve = 0
    max_stall = 5000
    
    for it in range(max_iters):
        if time_limit is not None and start_time is not None:
            if (time.time() - start_time) > time_limit:
                break
        if no_improve > max_stall:
            break
        
        # Find the worst lag
        max_k = np.argmax(corr)
        d = max_k - (n - 1)  # the actual lag
        
        if d == 0:
            # CC at lag 0 is always 0 for binary, so this shouldn't happen
            # unless there's a numerical issue. Just do a random swap.
            pass
        
        # Compute s[x] = h[x+d] + h[x-d] for all x
        s = np.zeros(n)
        if d > 0:
            s[:n-d] += h[d:]       # h[x+d] for x in [0, n-d-1]
            s[d:] += h[:n-d]       # h[x-d] for x in [d, n-1]
        elif d < 0:
            d_abs = -d
            s[d_abs:] += h[:n-d_abs]  # h[x+d] = h[x-d_abs] for x in [d_abs, n-1]
            s[:n-d_abs] += h[d_abs:]  # h[x-d] = h[x+d_abs] for x in [0, n-d_abs-1]
        # d == 0: s = 0
        
        # Best 1 to remove: minimize s[i] among 1-positions
        # Best 0 to fill: maximize s[j] among 0-positions
        one_scores = s[ones]
        zero_scores = s[zeros]
        
        best_i_idx = np.argmin(one_scores)
        best_j_idx = np.argmax(zero_scores)
        best_i = ones[best_i_idx]
        best_j = zeros[best_j_idx]
        
        delta_s = s[best_i] - s[best_j]
        
        if delta_s < 0:
            # This swap reduces CC at the target lag
            # Compute full delta
            delta = compute_delta_cc_all(h, best_i, best_j)
            new_corr = corr + delta
            new_max = float(np.max(new_corr))
            
            if new_max < current_c5_val:
                # Accept
                h[best_i] = 0
                h[best_j] = 1
                corr = new_corr
                current_c5_val = new_max
                ones = np.where(h == 1)[0]
                zeros = np.where(h == 0)[0]
                no_improve = 0
            else:
                no_improve += 1
                # Try a random swap as fallback
                ...
        else:
            no_improve += 1
            # Try random swap or second-best
    
    return h, current_c5_val * (2.0/n)
```

Now let me think about the continuous refinement phase. The previous algorithm used SLSQP with a soft-max objective. This can be effective but slow. Let me try a different approach: **projected gradient descent** on the continuous relaxation.

The objective is: f(h) = max_k CC_k(h) * dx

A smooth approximation is: f_α(h) = (1/α) * log(sum_k exp(α * CC_k(h)))

The gradient of CC_k with respect to h is:
∂CC_k/∂h[m] = (1 - h[m - k + n - 1]) + (-h[m + ... ]) 

Actually, CC_k(h) = sum_m h[m] * (1 - h[m - k + n - 1]) (for the full correlation indexing)

This is a quadratic form: CC_k(h) = h^T A_k h + b_k^T h (approximately, it's actually just a bilinear form since it's h * (1-h')).

Wait: CC_k = sum_m h[m] * (1-h[m-k+n-1]) = sum_m h[m] - sum_m h[m]*h[m-k+n-1]

The first term is linear in h. The second is quadratic. So the gradient is:
∂CC_k/∂h[m] = 1 - (h[m-k+n-1] + h[m+k-n+1])  (with boundary handling)

This is exactly the same as the "shift sum" formula! So the gradient is:
grad_k[m] = 1 - (h shifted by k)[m] - (h shifted by -k)[m]

For the soft-max objective, the gradient is a weighted average of the individual gradients, weighted by exp(α * CC_k) / sum_j exp(α * CC_j).

This can be computed in O(n²) time (for n lags, each gradient is O(n)).

For n=600, that's 360,000 operations per gradient evaluation. With a step size and projection, each iteration is fast.

Let me also think about whether the block improvement idea is feasible. For a block of size 8 with 4 ones, C(8,4) = 70 patterns. For each pattern, I need to compute the change in CC. The change in CC when changing a block of size b from pattern A to pattern B is:

ΔCC = sum of changes for each position in the block

If I change positions p1, p2, ..., pb (some from 0→1, some from 1→0), the total ΔCC is the sum of individual changes. But wait, the changes are not independent because the CC depends on the current state of h.

Actually, the formula ΔCC(d) = h[i+d] + h[i-d] - h[j+d] - h[j-d] is for a single swap. For a multi-position change, I need to be more careful because changing h[i] affects the "background" that h[j+d] refers to.

The correct formula for changing a set S of positions from their old values to new values:
ΔCC(d) = sum_{m in S} (new_h[m] - old_h[m]) * (1 - h[m+d]) + sum_{m in S} h_old[m] * (-(new_h[m+d] - old_h[m+d]))

Wait, this is getting complicated. The second sum further depends on whether m+d is also in S.

Let me just use a simpler approach: for each candidate pattern, compute the CC vector from scratch using the modified h. For a block of size 8, the modified h differs from the original in at most 8 positions (4 changed from 1 to 0 and 4 from 0 to 1, or fewer). The change in CC is:

ΔCC(k) = sum_{m in changed positions} (new_h[m] - old_h[m]) * (1 - h[m - k + n - 1]) + sum_{m: m-k+n-1 in changed} h[m] * (old_h[m-k+n-1] - new_h[m-k+n-1])

This is O(n * |changed|) per candidate, which for |changed| ≤ 8 and n=600 is about 4800 operations. For 70 candidates, that's 336,000 operations per block position. With 600 block positions, that's 200 million total. That might be too slow in Python.

Let me optimize: instead of trying all 600 positions, just try a random subset (say 100 positions). Then it's 100 * 70 * 4800 ≈ 33 million operations, which should take about 10-20 seconds. That's feasible.

Actually, let me simplify further. For the block improvement, I'll:
1. Pick a random window of size b (say b=8)
2. Count the number of 1s in the window: c_ones
3. Generate all binary patterns of length b with exactly c_ones ones (there are C(b, c_ones) of them)
4. For each pattern (excluding the current one), compute the new CC and check if it improves
5. If an improvement is found, accept it

The number of patterns is at most C(8,4) = 70 (when c_ones=4). For other values of c_ones, it's less (C(8,0)=1, C(8,1)=8, ..., C(8,4)=70, ...).

For computing the effect of a block change, I'll use the following efficient method:
- Save the old values of the block
- Set the new values
- Compute the delta CC using the formula (summing over changed positions)
- Restore old values if not accepted

Let me implement this efficiently using numpy:

```python
def block_improve(h, block_start, block_size, rng):
    """Try to improve h by rearranging a contiguous block."""
    n = len(h)
    end = min(block_start + block_size, n)
    size = end - block_start
    if size < 3:
        return h, False
    
    block = h[block_start:end].copy()
    c_ones = int(block.sum())
    
    # Generate all balanced patterns
    from itertools import combinations
    patterns = []
    for ones in combinations(range(size), c_ones):
        p = np.zeros(size)
        p[list(ones)] = 1.0
        # Skip the current pattern
        if np.array_equal(p, block):
            continue
        patterns.append(p)
    
    if len(patterns) == 0:
        return h, False
    
    best_pattern = None
    best_cc_max = float(np.max(np.correlate(h, 1-h, mode='full')))
    
    for p in patterns:
        h_test = h.copy()
        h_test[block_start:end] = p
        cc = np.correlate(h_test, 1-h_test, mode='full')
        cc_max = float(np.max(cc))
        if cc_max < best_cc_max:
            best_cc_max = cc_max
            best_pattern = p
    
    if best_pattern is not None:
        h[block_start:end] = best_pattern
        return h, True
    return h, False
```

This is O(|patterns| * n²) per block, which for 70 patterns and n=600 is 70 * 360000 = 25 million operations. That's probably too slow for many blocks. Let me reduce: use smaller blocks (size 4-6) and fewer positions.

For size 4: max C(4,2) = 6 patterns. 6 * 360000 = 2.16 million per position. With 100 positions: 216 million. Still a lot.

Alternative: use the incremental update formula. If the block changes at positions {p1, ..., pk} (k ≤ size), the delta CC is:

ΔCC(d) = sum_{m in changed} Δh[m] * (1-h[m+d]) + sum_{m: m+d in changed} h[m] * (-Δh[m+d])

where Δh[m] = new_h[m] - old_h[m].

Let me write this more carefully:
CC(d) = sum_m h[m] * (1-h[m+d])

When we change h at positions in set S (with Δh[m] = new_h[m] - old_h[m]):
New CC(d) - Old CC(d) = sum_m (new_h[m] - old_h[m])*(1-h[m+d]) + sum_m new_h[m]*(1-new_h[m+d] - (1-h[m+d]))
= sum_m Δh[m]*(1-h[m+d]) + sum_m new_h[m]*(h[m+d] - new_h[m+d])
= sum_m Δh[m]*(1-h[m+d]) + sum_m new_h[m]*(-Δh[m+d])

The first sum is over all m (but only m in S have nonzero Δh[m]):
= sum_{m in S} Δh[m]*(1-h[m+d])

The second sum: new_h[m]*(-Δh[m+d]) is nonzero only when m+d in S (i.e., m in S-d):
= -sum_{m: m+d in S} new_h[m]*Δh[m+d]
= -sum_{s in S} new_h[s-d]*Δh[s]  (substituting s = m+d)

So: ΔCC(d) = sum_{m in S} Δh[m]*(1-h[m+d]) - sum_{s in S} new_h[s-d]*Δh[s]

This is O(|S|) per lag d, and O(n*|S|) for all lags. For |S| ≤ 8 and n=600, that's 4800 per pattern, 70 patterns → 336,000 per block position. Much better!

import numpy as np

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(corr)) * dx

def project_binary(h, target_sum):
    n = len(h)
    h_r = np.round(h)
    h_r = np.clip(h_r, 0, 1).astype(int)
    current = h_r.sum()
    if current > target_sum:
        one_positions = np.where(h_r == 1)[0]
        # Remove the ones with lowest h values
        order = np.argsort(h[one_positions])[:int(current - target_sum)]
        h_r[one_positions[order]] = 0
    elif current < target_sum:
        zero_positions = np.where(h_r == 0)[0]
        # Add the zeros with highest h values
        order = np.argsort(-h[zero_positions])[:int(target_sum - current)]
        h_r[zero_positions[order]] = 1
    # Fix any remaining discrepancy
    diff = int(target_sum - h_r.sum())
    if diff > 0:
        zpos = np.where(h_r == 0)[0]
        h_r[zpos[:diff]] = 1
    elif diff < 0:
        opos = np.where(h_r == 1)[0]
        h_r[opos[:(-diff)]] = 0
    return h_r.astype(float)

def cc_vector(h):
    return np.correlate(h, 1.0 - h, mode='full').astype(float)

def lag_search(h0, target, max_iters, rng, time_limit, start_time):
    """Lag-directed local search."""
    n = len(h0)
    h = h0.astype(float).copy()
    corr = cc_vector(h)
    best_val = float(np.max(corr))
    best_h = h.copy()
    
    ones = np.where(h == 1)[0]
    zeros = np.where(h == 0)[0]
    stall = 0
    max_stall = 3000
    
    for it in range(max_iters):
        if (time.time() - start_time) > time_limit:
            break
        if stall > max_stall:
            break
        
        # Find worst lag
        max_k = int(np.argmax(corr))
        d = max_k - (n - 1)
        
        if d == 0:
            # Shouldn't happen for binary, but handle it
            stall += 1
            continue
        
        # Compute s[x] = h[x+d] + h[x-d] (with 0 padding)
        s = np.zeros(n)
        if d > 0:
            s[:n-d] += h[d:]
            s[d:] += h[:n-d]
        else:
            da = -d
            s[da:] += h[:n-da]
            s[:n-da] += h[da:]
        
        # Best swap: minimize s[i] - s[j] for i in ones, j in zeros
        if len(ones) == 0 or len(zeros) == 0:
            break
        
        # Try the best single swap
        one_s = s[ones]
        zero_s = s[zeros]
        bi = ones[int(np.argmin(one_s))]
        bj = zeros[int(np.argmax(zero_s))]
        
        delta_s = s[bi] - s[bj]
        accepted = False
        
        if delta_s < 0:
            # Compute full delta CC
            d_lags = np.arange(-(n-1), n)
            delta = np.zeros(2*n-1)
            for dd in d_lags:
                v = 0.0
                if 0 <= bi+dd < n: v += h[bi+dd]
                if 0 <= bi-dd < n: v += h[bi-dd]
                if 0 <= bj+dd < n: v -= h[bj+dd]
                if 0 <= bj-dd < n: v -= h[bj-dd]
                delta[int(dd + n - 1)] = v
            # This loop is O(n) in Python which is slow. Let me vectorize.
            
            # Vectorized version:
            # For position bi, the contribution vector is:
            # contrib_bi[k] = h[bi + (k-n+1)] + h[bi - (k-n+1)]
            # where out-of-bounds = 0
            kk = np.arange(2*n-1)
            lags = kk - (n-1)
            
            cb = np.zeros(2*n-1)
            v1 = bi + lags
            valid1 = (v1 >= 0) & (v1 < n)
            cb[valid1] += h[v1[valid1]]
            v2 = bi - lags
            valid2 = (v2 >= 0) & (v2 < n)
            cb[valid2] += h[v2[valid2]]
            
            cj = np.zeros(2*n-1)
            v1 = bj + lags
            valid1 = (v1 >= 0) & (v1 < n)
            cj[valid1] += h[v1[valid1]]
            v2 = bj - lags
            valid2 = (v2 >= 0) & (v2 < n)
            cj[valid2] += h[v2[valid2]]
            
            delta = cb - cj
            new_corr = corr + delta
            new_max = float(np.max(new_corr))
            
            if new_max < best_val:
                h[bi] = 0
                h[bj] = 1
                corr = new_corr
                best_val = new_max
                best_h = h.copy()
                ones = np.where(h == 1)[0]
                zeros = np.where(h == 0)[0]
                stall = 0
                accepted = True
        
        if not accepted:
            # Try a random swap (for diversification)
            ri = ones[rng.randint(len(ones))]
            rj = zeros[rng.randint(len(zeros))]
            if ri == rj:
                stall += 1
                continue
            # Quick check: compute delta for this swap
            d_lags = np.arange(-(n-1), n)
            kk = np.arange(2*n-1)
            lags = kk - (n-1)

            v1 = ri + lags
            va = (v1 >= 0) & (v1 < n)
            cb[va] += h[v1[va]]
            v2 = ri - lags
            va = (v2 >= 0) & (v2 < n)
            cb[va] += h[v2[va]]
            cj = np.zeros(2*n-1)
            v1 = rj + lags
            va = (v1 >= 0) & (v1 < n)
            cj[va] += h[v1[va]]
            v2 = rj - lags
            va = (v2 >= 0) & (v2 < n)
            cj[va] += h[v2[va]]
            delta = cb - cj
            new_corr = corr + delta
            new_max = float(np.max(new_corr))
            if new_max < best_val:
