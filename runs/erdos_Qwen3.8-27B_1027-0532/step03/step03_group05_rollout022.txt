  h[j] appears as h[i-l] when i-l = j, i.e., i = j+l, valid if l ≤ j+l ≤ n-1, i.e., 0 ≤ j ≤ n-1-l.
  Contribution: (1-h[j+l])
  
  h[j] appears in (1-h[i]) when i = j, valid if l ≤ j ≤ n-1.
  Contribution: -h[j-l]

So the gradient of the smooth max (weighted sum of corr_at_lag):
grad[j] = Σ_{k} w_k * d(corr_at_k)/dh[j]

For k ≥ 0:
  grad[j] += w_k * (1-h[j-k]) for j = k, ..., n-1
  grad[j] += w_k * (-h[j+k]) for j = 0, ..., n-1-k

For k < 0 (k = -l, l > 0):
  grad[j] += w_k * (1-h[j+l]) for j = 0, ..., n-1-l
  grad[j] += w_k * (-h[j-l]) for j = l, ..., n-1

This can be computed with vectorized operations:

```python
def compute_gradient(w, h):
    n = len(h)
    grad = np.zeros(n)
    for k in range(-(n-1), n):
        wk = w[k + n - 1]
        if wk < 1e-15:
            continue
        if k >= 0:
            grad[k:] += wk * (1.0 - h[:n-k])
            grad[:n-k] -= wk * h[k:]
        else:
            l = -k
            grad[:n-l] += wk * (1.0 - h[l:])
            grad[l:] -= wk * h[:n-l]
    return grad
```

This is O(n²) but with good vectorization, it should be fast for n=400 (each iteration is O(n) with numpy, and we do it 2n-1 ≈ 799 times, so about 799 * 400 = 320K operations, which is fast).

Now let me also think about the LP approach more carefully.

For the LP, I'll use cvxpy. The formulation:

Variables:
- h[0], ..., h[n-1] ∈ [0, 1]
- z[i, j] for 0 ≤ i ≤ j < n (representing h[i]*h[j])
- t ≥ 0

Objective: minimize t

Constraints:
1. Σ h[i] = n/2
2. For each "forward lag" k = 0, ..., n-1:
   Σ_{i=0}^{n-1-k} h[i+k] - Σ_{i=0}^{n-1-k} z[i, i+k] ≤ t/dx
3. For each "backward lag" k = 1, ..., n-1:
   Σ_{i=0}^{n-1-k} h[i] - Σ_{i=0}^{n-1-k} z[i, i+k] ≤ t/dx
4. McCormick constraints for each z[i,j]:
   z[i,j] ≤ h[i]
   z[i,j] ≤ h[j]
   z[i,j] ≥ 0
   z[i,j] ≥ h[i] + h[j] - 1

For n=100, this is very fast. For n=400, it might take a few minutes with GLOP.

Actually, I realize there might be an issue with the LP: the "forward" and "backward" constraints use the same z[i, i+k] variables, but the sums are different:
- Forward: Σ_{i=0}^{n-1-k} h[i+k] (this is a suffix sum of h)
- Backward: Σ_{i=0}^{n-1-k} h[i] (this is a prefix sum of h)

Both subtract the same R[k] = Σ_{i=0}^{n-1-k} z[i, i+k].

So the LP is correct.

Let me now think about whether the LP will give a useful answer. If the optimal h is "spiky" (mostly 0 and 1), then the LP will be exact (the McCormick relaxation is tight at binary points). If the optimal h is "smooth" (many fractional values), the LP gap might be significant.

Given that the current best C₅ ≈ 0.38 and the uniform gives 0.5, the optimal h is probably somewhat spread out (not fully binary). So the LP gap might be non-trivial. But the h from the LP should still be a good starting point for local optimization.

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    N = 2 * n
    H = np.fft.rfft(h, N)
    VH = np.fft.rfft(1.0 - h, N)
    corr = np.fft.irfft(H * np.conj(VH), N)
    return float(np.max(corr[:2*n-1])) * dx

def compute_corr(h):
    n = len(h)
    N = 2 * n
    H = np.fft.rfft(h, N)
    VH = np.fft.rfft(1.0 - h, N)
    return np.fft.irfft(H * np.conj(VH), N)[:2*n-1]

def project_feasible(h, target_sum):
    h = np.clip(h.astype(np.float64).copy(), 0.0, 1.0)
    diff = target_sum - np.sum(h)
    if abs(diff) < 1e-12:
        return h
    if diff > 0:
        mask = h < 1.0
    else:
        mask = h > 0.0
    if not np.any(mask):
        return h
    h[mask] += diff / np.sum(mask)
    return np.clip(h, 0.0, 1.0)

def smooth_max_and_weights(corr, alpha):
    c_max = np.max(corr)
    shifted = np.clip(alpha * (corr - c_max), -500.0, 0.0)

    sw = np.sum(weights)
    if sw < 1e-30:
        weights = np.zeros_like(corr)
        weights[np.argmax(corr)] = 1.0
        return c_max, weights
    weights /= sw
    return c_max + np.log(sw) / alpha, weights
