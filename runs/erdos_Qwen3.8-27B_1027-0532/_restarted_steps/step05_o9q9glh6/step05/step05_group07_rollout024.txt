
This is O(n) per call. For 2 calls per pair (B_i and B_j), and 200 pairs per sweep, that's 400 * O(n) = 400*400 = 160K operations. In numpy, each call is probably ~1-2 microseconds (since it's just a few array operations on arrays of size ~n). So 400 calls * 2μs = 0.8ms per sweep for B computation. The binary search dominates.

Now let me think about the SLSQP with analytical gradient. I need to provide the gradient of the log-sum-exp objective.

For the objective f(h) = (1/α) * log(sum_m exp(α * C_m(h))):
∇f = (1/α) * J_C^T * w where w = softmax(α * C)

J_C[i, m] = B_i[m] (the partial derivative of C_m with respect to h[i])

So ∇f[i] = (1/α) * sum_m w[m] * B_i[m] = (1/α) * (B_i dot w) for each i.

This is: ∇f = (1/α) * B_mat @ w where B_mat is the n × (2n-1) matrix.

Computing B_mat is O(n^2) and the matrix-vector product is O(n*(2n-1)) = O(n^2). For n=400, that's about 320,000 operations.
