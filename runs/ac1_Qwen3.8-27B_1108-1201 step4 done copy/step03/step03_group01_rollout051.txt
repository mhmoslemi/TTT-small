Given current a (normalized to sum=1):

3. Build the convolution matrix C (2n-1 x n) such that C @ g = conv(a, g)

   - If feasible, the solution g gives a direction
5. Direction d = g/sum(g) - a
6. Line search: find best t in a + t*d

The key improvement: use alpha < 1 to push towards sequences with lower max convolution.

But wait, the LP constraint C @ g <= M * alpha means conv(a, g) <= M * alpha. This is NOT the same as conv(g, g) being small. It's a cross-convolution constraint.

The idea is: if we move from a towards g, the new sequence is (1-t)*a + t*g, and its convolution is:
conv((1-t)a + tg, (1-t)a + tg) = (1-t)^2 conv(a,a) + 2t(1-t) conv(a,g) + t^2 conv(g,g)

So the constraint conv(a,g) <= M*alpha helps control the cross term, but we also need conv(g,g) to not be too large.

But a = [1/(n/2), 1/(n/2), ..., 1/(n/2), 0, ..., 0] (mass in first half only):
m = n/2 elements each of value 2/n.
conv has a triangular shape of width 2m-1 = n-1, centered at position m-1 = n/2-1.
Peak = m*(2/n)^2 = (n/2)*(4/n^2) = 2/n.
obj = 2n*(2/n) = 4. Worse!

What about a = [0, ..., 0, 1/(n/2), ..., 1/(n/2)] (mass in second half)?
Same by symmetry.

OK so what structure actually helps? Let me go back to the n=4 example that worked:
a = [0.35, 0.35, 0.15, 0.15]

This is a "decreasing step" - the first half is larger than the second half. The convolution peak is at position 1 (conv[1] = 2*0.35*0.35 = 0.245), not at the center (conv[3] = 0.21).

So the peak is shifted towards the beginning, and its value is determined by 2*a[0]*a[1] rather than the central sum.

For large n, if we use a "decreasing step" structure:
a[i] = c1 for i = 0, ..., m-1
a[i] = c2 for i = m, ..., n-1
where c1 > c2 > 0

The convolution will have:
- conv[0] = c1^2
- conv[1] = 2*c1^2 (if m >= 2)
- ...
- conv[m-1] = m*c1^2 (peak of the "first block" self-convolution)
- Then a mix of c1*c2 terms
- conv[n-1] = m*c1*c2 + (n-m)*c2*c1 = n*c1*c2 (the central element)
- ...
- conv[2n-2] = c2^2

The maximum will be one of: m*c1^2, n*c1*c2, or (n-m)*c2^2 (the peak of the "second block").

With mc1 + (n-m)c2 = 1, we want to minimize max(m*c1^2, n*c1*c2, (n-m)*c2^2).

Let's set m = alpha*n, c1 = 1/(alpha*n), c2 = (1-alpha)/( (1-alpha)*n ) = 1/n... wait that's just uniform.

Let me be more careful. mc1 + (n-m)c2 = 1.
Let c1 = A, c2 = B.
mA + (n-m)B = 1.

The three peak candidates:
P1 = mA^2 (self-conv of first block)
P2 = nAB (cross-conv, which includes the center)
P3 = (n-m)B^2 (self-conv of second block)

We want to minimize max(P1, P2, P3).

Let's set P1 = P2 = P3 = M (all tight).
mA^2 = nAB → A = nB/m
(n-m)B^2 = nAB → B = nA/(n-m)

From the first: A = nB/m
Substitute into the second: (n-m)B^2 = n*(nB/m)*B = n^2*B^2/m
(n-m) = n^2/m
m(n-m) = n^2
mn - m^2 = n^2
m^2 - mn + n^2 = 0

Discriminant: n^2 - 4n^2 = -3n^2 < 0. No real solution!

So we can't make all three equal. Let's try P1 = P2 (the two most important ones).
mA^2 = nAB → A = nB/m
With mA + (n-m)B = 1:
m*nB/m + (n-m)B = 1
nB + (n-m)B = 1
(2n-m)B = 1
B = 1/(2n-m)
A = n/(m(2n-m))

P1 = mA^2 = m*n^2/(m^2*(2n-m)^2) = n^2/(m*(2n-m)^2)
P3 = (n-m)B^2 = (n-m)/(2n-m)^2

For P1 = P2: M = n^2/(m*(2n-m)^2)

Let's check P3 vs M:
P3/M = [(n-m)/(2n-m)^2] / [n^2/(m*(2n-m)^2)] = m(n-m)/n^2

For P3 <= M: m(n-m) <= n^2, which is always true since m(n-m) <= n^2/4 < n^2.

So the binding constraint is P1 = P2, and M = n^2/(m*(2n-m)^2).

Objective = 2n*M = 2n^3/(m*(2n-m)^2)

To minimize this, we want to maximize m*(2n-m)^2.
Let f(m) = m*(2n-m)^2. f'(m) = (2n-m)^2 + m*2*(2n-m)*(-1) = (2n-m)[(2n-m) - 2m] = (2n-m)(2n-3m)
Setting to 0: m = 2n/3.

f(2n/3) = (2n/3)*(2n-2n/3)^2 = (2n/3)*(4n/3)^2 = (2n/3)*(16n^2/9) = 32n^3/27

M = n^2/(32n^3/27) = 27/(32n)
Objective = 2n * 27/(32n) = 54/32 = 27/16 = 1.6875

So with a two-level decreasing step and m = 2n/3, we get objective = 1.6875!

That's much better than 2! And it's close to the target of 1.5027.
