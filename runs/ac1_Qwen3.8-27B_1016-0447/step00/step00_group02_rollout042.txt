So the key insight is: NON-SYMMETRIC sequences can have much lower max autocorrelation than the uniform sequence! The uniform sequence is a local minimum for symmetric perturbations but NOT a global minimum.

This explains why the previous program (which started from uniform and used random block perturbations) got stuck at 2.0 - it couldn't escape the symmetric basin.

Now I understand the problem. We need to find non-symmetric sequences with low max autocorrelation. The structure should be such that the sequence is "concentrated" in a way that avoids large overlaps at any single lag.

For n = 4, a = (1/4, 0, 1/4, 1/4) works. The pattern is: non-zero, zero, non-zero, non-zero. This breaks the symmetry.

For larger n, we want a similar idea: a non-symmetric pattern that minimizes the peak autocorrelation.

One approach: use a "binary" or "sparse" pattern. For example, a sequence that's 1 on some positions and 0 on others, with a specific pattern that minimizes the autocorrelation peak.

This is related to the problem of finding "good" binary sequences (like Barker sequences, Zadoff-Chu sequences) but for the one-sided autocorrelation.

For the one-sided autocorrelation of a binary sequence of length n, the peak is at lag 0 (equal to the Hamming weight). To minimize the peak relative to the sum squared, we want a sequence with a specific autocorrelation structure.

Actually, let's think about it differently. The score is 2n * max_b / S^2. For a binary sequence (a_j in {0,1}) with weight w:
- max_b >= w (at lag 0, (a*a)_0 = sum a_j^2 = w)
- S = w
- Score >= 2n * w / w^2 = 2n/w

To minimize, maximize w (use all 1s) → score 2. Or minimize w (use fewer 1s) → worse.
