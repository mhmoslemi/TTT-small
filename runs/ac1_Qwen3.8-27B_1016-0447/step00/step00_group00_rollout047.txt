Now let me also think about whether we should use just the single argmax or multiple near-max lags. For robustness, let me use a "temperature" approach: weight each lag by exp(k*full) for some small k > 0, and compute a weighted average gradient. But for simplicity, let me start with just the argmax.

Actually, a better approach for the non-smooth max: instead of subgradient at argmax, I can use ALL lags and compute:

f(a) = max_k (a*a)_k

A "smoothed" version: f_ε(a) = ε * log(sum_k exp((a*a)_k / ε))

The gradient of f_ε is: sum_k p_k * d(a*a)_k/da where p_k = exp((a*a)_k/ε) / sum_j exp((a*a)_j/ε).

For small ε, this concentrates on the argmax. But computing all d(a*a)_k/da would require O(n^2) work (one gradient per lag, each O(n)).

Alternatively, I can just use the top few lags (say, the top 10 lags) and average their gradients. Each gradient is O(n) to compute, so 10 lags is O(10n).

But actually, the single-argmax approach should work fine for gradient descent. The main issue is that when the argmax "flips" from one lag to another, there's a kink. Momentum helps smooth this out.

import time

def subgrad_conv(a, tau, n):
    g = np.zeros(n)
    lo = max(0, tau - n + 1)
    hi = min(n, tau + 1)
    if lo < hi:
        g[lo:hi] = 2.0 * a[tau - lo : tau - hi + 1][::-1]
    return g

    mom = 0.7
    iters_since_improve = 0

    while time.monotonic() < deadline:

        Af = np.fft.rfft(a, N)

        M = float(full.max())
        tau = int(full.argmax())
        
        # Subgradient
        g = subgrad_conv(a, tau, n)

        a_new = a - lr * vel
        a_new = np.maximum(a_new, 0.0)
        s = a_new.sum()
        if s > 1e-12:
            a_new = a_new / s
        else:
            a_new = a.copy()
        
        # Evaluate

                a = a / a.sum()
                vel = np.zeros(n)
                lr = 0.02
                iters_since_improve = 0
            else:
                lr = max(0.0005, lr * 0.9)
        
        a = a_new
    
    final = float(evaluate_sequence(best.tolist()))
    if not np.isfinite(final):

    return [float(x) for x in best]

After this perturbation, the gradient will no longer be uniform, and the descent should begin. But will it actually find a direction that reduces the max autocorrelation?

Let's think: starting from near-uniform, the autocorrelation is approximately:
full[k] ≈ (min(k+1, n, 2n-1-k))/n^2 + perturbation

The max is at k=n-1 (center) ≈ 1/n. A small perturbation δa will change the center by:
d(center) = 2 * sum_j (1/n + δa[j]) * δa[n-1-j] ≈ 2 * sum_j (1/n)*δa[n-1-j] + 2*sum_j δa[j]*δa[n-1-j]
= 0 (by sum(δa)≈0 after normalization) + O(||δa||^2)

And the change at other lags is similar. So to first order, the perturbation doesn't change the autocorrelation! We need second-order effects.

This means simple gradient descent from the uniform will be very slow. We need a different approach.

Better idea: use a NON-uniform initialization. What structure would give AC1 < 2?

Key insight: we need the autocorrelation to be FLAT (all lags equal). The uniform sequence has a TRIANGULAR autocorrelation (peaking at center). To flatten it, we need to REDUCE the center and INCREASE the edges.

But we can't increase the edges (boundary lags) because they only have 1 term each (a[0]^2, etc.). So the best we can do is make the center as small as possible while keeping the boundary lags from becoming the max.

The constraint is: a[0]^2 ≤ (a*a)[center] for all i, i.e., max a[i]^2 ≤ (a*a)[n-1].

For the center: (a*a)[n-1] = sum_j a[j]*a[n-1-j].

If a is "anti-symmetric" around the center (a[j] large ↔ a[n-1-j] small), the center is small. But then a[j]^2 (for large j) might exceed the center.

The optimal solution likely has a[i] = c for all i (constant), giving AC1 = 2. Any deviation increases some other lag.
