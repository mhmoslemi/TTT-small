Let me also think about the "principled" LP approach. The LP from the paper:
maximize sum(g) subject to g >= 0 and (a*g)[k] <= M for all k.

The constraint (a*g)[k] = sum_j a[j]*g[k-j] <= M. This is O(n) linear constraints in O(n) variables. The constraint matrix is a convolution matrix, which is dense in general.

However, we can use the fact that we only need a few iterations of an LP solver (or even just a few projected gradient steps on the dual) to get a good direction.

The dual of the LP:
minimize M * sum_k λ_k
subject to sum_k λ_k * (constraint matrix row for i) >= 1 for all i
λ_k >= 0

The constraint for variable g[i] is: sum_k λ_k * a[k-i] + a[i-k] ... wait, let me be more careful.

The primal constraint for lag k: sum_j a[j] * g[k-j] <= M (where j ranges over valid indices).
For a specific g[i], it appears in constraint k when k-j = i, i.e., j = k-i. So g[i] appears in constraint k with coefficient a[k-i].

The dual variable for constraint k is λ_k >= 0.
The dual constraint for g[i]: sum_k λ_k * a[k-i] >= 1 (for all i).
The dual objective: minimize M * sum_k λ_k.

So the dual is:
min M * 1^T λ
s.t. A^T λ >= 1, λ >= 0

where A is the convolution matrix (A[k,i] = a[k-i] if valid, 0 otherwise).

This is a linear program with 2n-1 variables and n constraints. Not too bad in size, but the constraint matrix is dense (each row has n non-zero entries).

For a first-order approach to the dual:
- Start with λ = 0
- At each step, find the most violated constraint (the i with the smallest sum_k λ_k * a[k-i])
- Increase λ for the constraints where a[k-i] is largest for that i
- This is like a cutting plane / subgradient method

def _score(a, n):

    a = np.clip(a, 0.0, 1000.0)

    if s < 0.01:
        return float('inf')
    c = np.convolve(a, a)
    return 2.0 * n * c.max() / (s * s)

def _subgrad(a, peak_idx, n):
    """Compute subgradient at peak lags. O(P*n)."""
    g = np.zeros(n, dtype=np.float64)
    for k in peak_idx:
        lo = max(0, k - n + 1)
        hi = min(k, n - 1)
        if lo <= hi:
            g[lo:hi+1] += a[k-hi:k-lo+1][::-1]
    return 2.0 * g

    A = np.fft.rfft(a)
    mag = np.abs(A)
    # Target: raise low frequencies, cap high

    new_mag = (1.0 - gamma) * mag + gamma * avg
    # Ensure DC component is preserved (sum doesn't change much)

    A_new = new_mag * np.exp(1j * phase)

    a_new = np.clip(a_new, 0.0, None)
    s = a_new.sum()
    if s < 1e-10:
        return a
    return a_new / s

Actually, for the linear convolution, we want c[k] to be flat (constant) for all k. The DFT of c (padded to appropriate length) is |A(f)|^2 (for circular) or something related (for linear). Making |A(f)|^2 flat is the same as making |A(f)| flat. So IFTA should help for the circular case, and approximately for the linear case.

But there's a subtlety: for the linear convolution of length 2n-1, the DFT is NOT simply |A(f)|^2. It's |A(f)|^2 only for the circular convolution. For the linear case, the DFT of the zero-padded convolution is |A_padded(f)|^2 where A_padded is a with zeros appended.

For a sequence of length n, if we zero-pad to length 2n-1 and take the DFT, we get A(ω) * A(ω) (for the padding that makes it circular without aliasing). Actually, the DFT of the linear convolution of two length-n sequences (padded to length 2n-1) is the product of their individual DFTs (also of length 2n-1). For a * a, it's |A_{2n-1}(ω)|^2 where A_{2n-1} is the (2n-1)-point DFT of a.

So if I take the (2n-1)-point DFT of a (zero-padded), and make its magnitude flat, the linear autocorrelation will be more flat. This is different from the n-point DFT I used in _ifta.
