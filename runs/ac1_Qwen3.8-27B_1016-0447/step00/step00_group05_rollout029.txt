    return 2.0 * a.size * c.max() / (sa * sa)

    """Compute g_j = a[k-j] if 0<=k-j<n, else 0. This is the gradient factor for c_k."""

Wait, I think there's an issue with the gradient approach. Let me reconsider.

We want to minimize max_k c_k. The subgradient of max at k* is e_{k*}. So the gradient of c_{k*} w.r.t. a is what we computed. But this gradient says "decrease a_j proportional to a_{k*-j}". This means: where a is large at position k*-j, we decrease a_j. This is like anti-correlating a with its time-reversed version shifted by k*.

For k* = n-1 (center): g_j = a_{n-1-j}. So we decrease a_j proportional to a_{n-1-j}. This is like making a anti-symmetric about n/2. For the center to be reduced, we want a_j * a_{n-1-j} to be small, which happens if one is large and the other is small.

This makes sense! The algorithm will try to make the sequence "one-sided" - large on one half, small on the other. But that might increase other convolution entries (like c_0 = a_0² which would be large if a_0 is large).

So there's a tension: reducing the center peak vs. increasing edge peaks. The algorithm should find a balance.

Let me also add: instead of just the argmax, use the top-α entries to get a more stable gradient direction. This smooths the optimization.
