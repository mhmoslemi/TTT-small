This is related to the "minimum peak sidelobe level" or "optimal autocorrelation" problem for nonnegative sequences. 

For the specific structure, I think the key insight is:
- We want to minimize max_k conv[k] / (sum a)²
- The "peak" is typically at or near the center
- By creating a dip in the middle of the sequence, we can reduce the center of the convolution
- But this shifts energy to other lags

For the AC1 bound, I recall that the optimal value for nonnegative sequences is related to the "Beurling-Selberg" type bounds. But let me think more concretely.

For a "block" sequence: a[i] = h for i in some set S, 0 otherwise.
If S is a contiguous block of length m at one end: a = [1,...,1,0,...,0] (m ones, n-m zeros).

To minimize: maximize m. m=n gives AC1=2. m=n-1 gives 2n/(n-1)≈2+2/n.

Actually, let me think about what local search to use. The previous program used block multiplications. Let me enhance it:
- Try different block sizes
- Try both multiplicative and additive perturbations
- Try the "LP" approach from the state of the art in a simplified form

The LP approach says: given f, find g that maximizes sum(g) subject to g >= 0 and f*g <= M (where M = max(f*f)). This is like finding the best "dual" sequence.

But implementing this LP is complex. Let me instead use a simpler gradient-free approach:
- Compute conv = f*f
- Identify where conv > 0.9*M (near-peak locations)
- These correspond to index pairs (i,j) with i+j = k (where k is the peak)
- Decrease a[i] or a[j] to reduce the peak
- But this might create new peaks elsewhere

A simpler approach: coordinate descent on blocks.
- Split into blocks of size B
- For each block, try scaling it by factors [0.5, 0.7, 0.9, 1.0, 1.1, 1.3, 1.5]
- Accept the best scaling for that block
- Repeat

This is O(n/B * 7) evaluations per sweep, each O(n²). For n=2535, B=50: about 50*7=350 evaluations per sweep, each ~10ms, so ~3.5s per sweep. We can do ~300 sweeps in 1000s.
