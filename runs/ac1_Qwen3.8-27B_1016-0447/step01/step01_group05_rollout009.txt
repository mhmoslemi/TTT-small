Now, for the optimization:
- We want to minimize `max_k c_k` subject to `a >= 0`, `sum a = 1`.
- The active constraint is at `k* = argmax c`.
- Gradient: `g` as computed above.
- Update: `a -= lr * g`, then project.

But this only addresses the peak lag. If we just decrease `c_{k*}`, the peak might shift to another lag. A better approach is to use a "max" approximation:

`f(a) ≈ (1/tau) * log(sum_k exp(tau * c_k))`

This is smooth and its gradient is:
`grad f = sum_k exp(tau * c_k) * grad c_k / sum_k exp(tau * c_k)`
`= sum_k w_k * grad c_k` where `w_k = exp(tau * c_k) / sum exp(tau * c_k)`.

And `grad c_k` is the shifted `a` as before. So:
`grad f_j = sum_k w_k * a_{k-j}` (with the same validity condition).

This is a weighted sum of shifted versions of `a`, which is a convolution: `grad f = a * w` (convolution of `a` with `w`, restricted to the first n elements).

Wait, let's be more careful. `grad f_j = sum_k w_k * a_{k-j}` where `a_t = 0` for `t` outside [0, n-1].

This is `(a * w)_j` where `*` is convolution, but only the part where the index is valid. Actually:

`sum_k w_k * a_{k-j}` = `(w * a)_j` where the convolution is full (length 2n-1), and we take the first n elements.

Wait: `(w * a)_j = sum_k w_k a_{j-k}`. That's not quite right.

Let me redefine. `grad f_j = sum_{k: 0<=k-j<n} w_k * a_{k-j}`.

Let `t = k - j`, so `k = t + j`. Then `grad f_j = sum_{t: 0<=t<n, 0<=t+j<2n-1} w_{t+j} * a_t`.

This is the cross-correlation of `w` and `a`, at lag j. Or equivalently, the convolution of `w` (reversed) with `a`.

In any case, this can be computed via FFT in O(n log n).

Let me think about whether to use the smooth max or just the hard max. For simplicity, let me start with the hard max (just the peak lag) and see if it works. I can always switch to the smooth max.

Actually, for the problem at hand (n ~ 6000), the hard max approach should work fine. The peak will be at the center of the convolution for most shapes, and the gradient step will naturally flatten it.

Let me now think about the initial guess. A Gaussian centered in the array:
`a_i = exp(-(i - (n-1)/2)^2 / (2*sigma^2))`

For sigma = n/6 or so, this gives a nice bell shape. After normalization, the sum is 1.

The self-convolution of a Gaussian is a wider Gaussian, with peak at the center. The peak is proportional to `1/sigma`. So a wider Gaussian has a lower peak. But the Gaussian must be supported on [0, n-1], so sigma can't be too large (otherwise most of the mass is at the edges where the convolution drops off).

Optimal sigma: the Gaussian should be wide enough to be "flat" but narrow enough to be fully supported. I'll try sigma = n/4 or n/6.

Let me also consider the "raised cosine" shape: `a_i = 0.5 + 0.5 * cos(2*pi*i/n)` for i in [0, n-1]. This is nonnegative and has a smooth shape.

Or a "tent" shape: `a_i = 1 - |2i/(n-1) - 1|` (triangular). This is nonnegative and peaks in the center.

import time

def _fft_conv(a, b):
    """Full convolution via FFT."""
    n = len(a)
    m = len(b)
    size = 1
    while size < n + m - 1:
        size *= 2
    fa = np.fft.rfft(a, size)
    fb = np.fft.rfft(b, size)
    return np.fft.irfft(fa * fb, size)[:n + m - 1]
