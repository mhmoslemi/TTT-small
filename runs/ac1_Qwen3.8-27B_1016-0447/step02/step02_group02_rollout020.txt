Let me try a fundamentally different approach: "coordinate descent" or "block coordinate descent."

For each coordinate y[i], the objective (simplified, sum(y)=1) is:
f(y) = 2n * max_k sum_{i'+j'=k} y[i']*y[j']

If we fix all y except y[i], then y[i] appears in:
- conv[2i] (as y[i]^2)
- conv[k] for k ≠ 2i (as 2*y[i]*y[k-i])

So the max is the max of:
- 2i: y[i]^2 + (terms not involving y[i])
- k≠2i: 2*y[i]*y[k-i] + (terms not involving y[i])

To minimize the max, we want to choose y[i] such that the maximum of these terms is minimized. This is a 1D problem (univariate) for each i! We can solve it by bisection.

But doing this for all n coordinates in sequence would be O(n * n * log) = O(n^2 log), which for n=4500 is about 400M operations. That might be too slow per full sweep.

However, we can do a "sweep" where we cycle through coordinates in random order, and for each, do a few bisection steps. Each bisection step requires computing the current max, which is O(1) if we track it incrementally.

1. Use a "weighted" subgradient: instead of uniform weights on top-K, use weights proportional to (conv[lag] - M_min) to emphasize the higher lags
2. Use a decreasing step size schedule (annealing)
3. Add "jitter" to escape plateaus
4. Do more restarts with different perturbation scales
5. Use a smarter "stuck" detection
