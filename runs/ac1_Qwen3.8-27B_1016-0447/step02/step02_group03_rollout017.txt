One more thought: the "active set" in the subgradient should probably include ALL lags where b[k] is within some tolerance of the max. If the convolution is nearly flat (as it should be after LSE), then most lags are active, and the subgradient averages over many lags, giving a smoother direction.

For the peak shaving, let me use a margin of 0.02 (2% of max) instead of the previous 5%. This should capture more of the relevant structure.

But wait, if the margin is too large, the gradient becomes:
g = (1/|active|) * sum_{k in active} 2*(M_k a)

If active is large (say, all 2n-1 lags), this becomes:
g = 2/(2n-1) * sum_k (M_k a) = 2/(2n-1) * (sum_k a[k-j]) * 2 (for each j)

Hmm, this is getting complicated. Let me just use a moderate margin (1-2%) and cap the number of active indices at, say, 100.

Actually, I realize there's a much faster way to compute the gradient when there are many active indices. The gradient is:
g[j] = 2 * sum_{k in active} a[k-j] / |active|

This is a (normalized) cross-correlation between the indicator of "active" and a. I can compute it with one FFT!

Let me define: v = indicator of active (v[k] = 1/|active| if k in active, else 0)
Then g[j] = 2 * sum_k v[k] * a[k-j] = 2 * (v ⊛ a)[j] = 2 * (v * a_rev)[n-1+j]

This can be done with one FFT of size _NF! Much faster than looping.

Let me incorporate this.

```python
def _sgrad_fast(b, a, margin=0.02, max_active=200):
    mx = b.max()
    if mx <= 0: return np.zeros(_N)
    thr = mx * (1 - margin)
    active = np.where(b >= thr)[0]
    if len(active) > max_active:
        # Keep only the top max_active
        idx = np.argsort(b)[::-1][:max_active]
        active = idx
    if len(active) == 0:
        active = np.array([int(np.argmax(b))])
    v = np.zeros(2*_N-1)
    v[active] = 1.0 / len(active)
    a_rev = a[::-1]
    fv = np.fft.rfft(v, _NF)
    fa = np.fft.rfft(a_rev, _NF)
    conv = np.fft.irfft(fv * fa, _NF)
    g = 2.0 * conv[_N-1:_N-1+_N]
    return g
```

This is O(n log n) regardless of the number of active indices.
