```python
hi = min(n - 1, k)
g[lo:hi+1] = 2.0 * a[k-hi:k-lo+1][::-1]
```

This is O(n) per iteration. Combined with the O(n log n) FFT for computing c, the total per iteration is O(n log n).

Now, for the optimization algorithm, I'll use:
1. Projected subgradient descent with line search
2. Normalization: after each step, clip to [0, inf] and normalize to sum = 1
3. The objective to minimize is f(a) = max(conv(a,a)) (with sum(a) = 1, a >= 0)

Actually, since the score is 2n * max_conv / sum^2, and sum^2 is in the denominator, we should be careful about the normalization. If we fix sum = 1, we minimize max_conv. But the scaling matters: if we scale a by c, max_conv scales by c^2 and sum^2 scales by c^2, so the ratio is invariant. Good.

So the algorithm is:
1. Normalize a to have sum = 1
2. Compute c = conv(a, a) via FFT
3. Find k* = argmax(c)
4. Compute subgradient g = d c[k*] / da (as above)
5. Update: a_new = a - lr * g
6. Project: a_new = max(0, a_new)
7. Normalize: a_new = a_new / sum(a_new)
8. Line search: try lr, lr/2, lr/4, ... until f(a_new) < f(a)
9. Repeat

The line search is expensive (each evaluation is O(n log n)), so I'll limit it to a few steps.

Alternative: use a fixed learning rate with a schedule, like the previous program.

Let me also think about the "active set" from the strategy. At the optimum, multiple c[k] values might be at the max (i.e., the max is not unique). In that case, the subgradient is a convex combination of the gradients at all argmax positions. This could give a better descent direction.

I'll implement:
1. Compute c = conv(a, a)
2. Find all k where c[k] >= max(c) - eps (for some small eps)
3. Compute the gradient as a weighted average of the subgradients at these k's
4. Update

This is similar to the softmax approach in the previous program but more principled.
