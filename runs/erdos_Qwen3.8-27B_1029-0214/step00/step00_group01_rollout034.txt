For a perfectly alternating pattern (1,0,1,0,...), the overlap at shift k is 0 for even k (all ones map to ones or zeros map to zeros) and approximately n/4 for odd k. Wait no, for alternating 1,0,1,0,...,1,0:
- Shift by 1: each 1 maps to a 0, so overlap = n/2 (for the interior)
- Shift by 2: each 1 maps to a 1, overlap = 0
- Shift by 3: each 1 maps to a 0, overlap = n/2

So alternating gives max overlap ≈ n/2 * dx = n/2 * 2/n = 1. That's terrible!

What about blocks? If we have a block of n/2 ones followed by n/2 zeros:
- Shift by 1: overlap is 1 (only the boundary)
- Shift by n/2: overlap is n/2 (all ones map to zeros)
- Max is n/2 * dx = 1. Also terrible.

What about a more distributed pattern? The key is to spread out the ones so that no shift causes many ones to map to zeros.

This is essentially the problem ofFinding a binary sequence with low "auto-correlation" in a specific sense.
