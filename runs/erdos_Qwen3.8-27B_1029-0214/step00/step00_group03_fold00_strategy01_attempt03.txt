1. Approach and rationale

1.1 Central idea

Implement a nonlinear, constrained, descent-based optimizer for the exact discrete score

C5(h) = d_x max_s R_s(h),  R_s(h) = sum_{i valid for s} h_i (1 - h_{i+s}),

where s ranges over all finite-support shifts -(N-1), ..., N-1. The final accepted solution is always scored by the supplied task metric. No relaxation is allowed to define the accepted solution.

The primary method is:

  * perform discrete, feasibility-adaptive substitutions to the supplied parent,
  * pick several resolution levels,
  * at each resolution iterate a local sequential trust-region search,
  * inside each local solve, solve a convex subproblem whose minimax term is a linearization of the currently best active lags,
  * test each produced point with the exact objective,
  * verify the exact box/sum constraints,
  * replace the return state only when the exact final objective improves, or when a feasible, submetric-different plateau with no increase can provide exploration while still retaining a safe parent best.

This is materially different from enumerating pair coordinates. The subproblem changes many coordinates in one convex quadratic-programming or linear-programming problem. The allowed libraries make it possible to solve such a subproblem with CVXPY and a standard second-order solver. The use of CVXPY is justified because the subproblem is convex; the externally true nonconvex objective is never solved by CVXPY. Convexity of the subproblem follows from the fact that it contains:

  * linear variable bounds,
  * a linear equality constraint,
  * linear constraints representing active-lag linearizations,
  * elementwise trust-region bounds,
  * a single scalar variable t,
  * a convex penalty in the variable x, specifically t + c * ||x - x^current||_2^2 divided by N.

Every accepted point is evaluated with exact, unscaled, nonconvex objective. No global optimality is claimed.

1.2 Why this addresses the problem

The main obstruction is that the global score is the maximum of many finite-support correlation terms. A parent point probably has a small set of near-maximum lags. Pair moves are limited because they explore a one-dimensional subspace. The approach here builds a convex convex-driven direction that affects every coordinate through linear ratios, while keeping the update near trusted current point. Exact accept-or-reject prevents a safe lower score estimate from returning invalid points.

The combination of:

  * stable box-and-sum projection,
  * exact scoring,
  * multi-resolution transfer from the parent,
  * active-set sequential CVX optimization,
  * a separate deterministic smooth projected-gradient fallback diversification.

gives a self-contained heuristic capable of using 1100 seconds on one CPU.

1.3 Important limitations

The original objective is nonconvex. Linearization of terms may underestimate some terms outside a tiny trust region, even though we use trust bounds. The proposed algorithm:

  * is a local heuristic, not a global optimizer,
  * can become trapped at a local minimum,
  * may produce no exact improvement.

The plan mitigates this through many independent starting points, resolution levels, step-size adaption, gradient candidates, randomized perturbation in trust-region, and time-budgeted stochastic-project gradient exploration. It explicitly returns the parent construction as a fallback whenever no exact improvement can be found.

2. Mathematical representation and exact objective

2.1 Grid, scaling, support, and sums

For h of length integer N > 1:

  d_x = 2.0/N

The discrete sum constraint is:

  0 <= h[i] <= 1, all i
  sum_i h[i] = N/2.

The target discrete sum, not scaled by d_x, is:

  target_sum(N) = N/2.

This target may be half-integral if N is odd. The numerical code uses double precision and finite validation only when requested threshold.

2.2 Exact continuous support lag formula

Define for each finite-support shift s = -N+1, -N-2, ..., N-1:

  R_s(h) = sum_{i=max(0,-s)}^{min(N-1,N-1-s)} h[i] * (1 - h[i+s]).

No assumption of periodic support is used. When s=0:

  R_0 = sum_i h_i(1-h_i),

and valid negative lags are equally present. The output of `np.correlate(h, 1-h, mode="full")` is a permutation of these R_s; the maximum is therefore numerically identical. For internal computation, accept or finalize the score with exactly the supplied formula:

  exact_scaled_score = d_x * max(np.correlate(h, 1-h, mode='full')).

The internal exact unscaled vector R can be used during optimization. It must be tested against the exact final metrics. Bad-side signature transform but min may not be over a representative; internal behavior is justified by the set equivalence of all ordered finite shifts.

2.3 Objective to optimize

Define the unscaled objective:

  U(h) = max_s R_s(h).

Then:

  C5(h) = U(h) * 2.0 / N.

The minimization is with respect to h in the feasible set S_N:

  S_N = {x in R^N: 0 <= x[i] <= 1, sum_i x[i] = N/2}.

It works with U to avoid repeated scaling of constants by 2/N. Minimize unscaled U and store both U and exact scaled score.
