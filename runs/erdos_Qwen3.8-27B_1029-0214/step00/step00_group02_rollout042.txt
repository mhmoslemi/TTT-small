- If i is the "source" (first factor): (1-h[j]) for all j at the appropriate shift
- If i is the "target" (second factor, appearing as 1-h[i]): -h[j] for appropriate j, i.e., subtracting h[j]*(1-h[source_j])

- Decrease h[i] where h[i] is high and (1-h[partner]) is high (i is a source with a "bad" partner)
- Or increase h[partner] where h[source]*(1-h[partner]) is high (making the partner less "off")

def eval_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode="full")
    return float(np.max(corr)) * dx

def project_feasible(h):
    n = len(h)
    target = 0.5 * n
    h = np.clip(h.astype(np.float64), 0.0, 1.0)
    for _ in range(100):
        diff = target - np.sum(h)
        if abs(diff) < 1e-14:
            break
        if diff > 0:
            mask = h < 1.0 - 1e-12
        else:
            mask = h > 1e-12
        if not np.any(mask):
            break
        step = diff / np.sum(mask)
        h[mask] += step
        np.clip(h, 0.0, 1.0, out=h)
    return h

def upsample_to(h_src, n_new):
    n_src = len(h_src)
    if n_src == n_new:
        return project_feasible(h_src)
    x_old = np.linspace(0.0, 2.0, n_src, endpoint=False)
    x_new = np.linspace(0.0, 2.0, n_new, endpoint=False)
    h_new = np.interp(x_new, x_old, h_src)
    return project_feasible(h_new)

Hmm, but this might be too aggressive with kicks. Let me think about what actually works well for this type of problem.

The key insight is: the objective is a piecewise-linear function of h (it's the max of linear functions, where each linear function is a Lagrangian). Wait, no - it's the max of a family of functions, each of which is NOT linear in h because it contains products h[i]*(1-h[j]).

So it's actually the max of quadratic functions. That makes it NP-hard in general. But in practice, local search + occasional kicks should work well.

Let me think about a different approach: what if I use the structure of the problem more directly?

For a given lag k, the overlap is:
f_k(h) = sum_i h[i] * (1-h[i+k-n+1]) (for valid i)

This is a bilinear function of h. If we fix all elements of h except h[i] and h[j], then f_k is linear in each of them.

The max over k of f_k is what we're minimizing. This is like a minimax problem.

A subgradient method would work:
- Compute all f_k(h)
- Let k* = argmax_k f_k(h)
- Compute the subgradient of f_{k*} w.r.t. h
- Take a small step in the negative subgradient direction
- Project back to the feasible set

The subgradient of f_k w.r.t. h[i] is:
For the "full" correlation, the relationship between index i in h and the lag needs to be worked out.

Let me define it more carefully. Let's say h = (h_0, h_1, ..., h_{n-1}).
The "full" correlation of h and (1-h) gives a vector c of length 2n-1 where:

c[m] = sum_i h[i] * (1-h[i+m-(n-1)])

where the sum is over all i such that 0 <= i+m-(n-1) <= n-1.

Let shift = m - (n-1). Then:
c[m] = sum_i h[i] * (1-h[i+shift])

The valid range of i:
- i >= 0
- i + shift >= 0 → i >= -shift
- i <= n-1
- i + shift <= n-1 → i <= n-1-shift

So valid i: max(0, -shift) <= i <= min(n-1, n-1-shift)

The subgradient of c[m] w.r.t. h[p]:
- If p is in the "first factor" position (i = p): (1-h[p+shift]) for p in valid range
- If p is in the "second factor" position (i+shift = p, i.e., i = p-shift): -h[p-shift] for p-shift in valid range

So:
∂c[m]/∂h[p] = (1-h[p+shift]) * [p in valid_range_for_first] + (-h[p-shift]) * [p-shift in valid_range_for_second]

Where the brackets are indicator functions.

This gives us a direction to decrease the active lag. But we need to be careful because:
1. Changing h[p] affects ALL lags, not just the active one
2. The max might switch to a different lag after the step

For a practical implementation, I'll use:
1. Compute the active lag
2. Compute the subgradient direction
3. Take a small step in the negative direction
4. Project to feasible set
5. Accept if it improves

Let me implement this:

```python
def subgradient_step(h, step_size):
    n = len(h)
    corr = np.correlate(h, 1.0 - h, mode="full")
    k_active = np.argmax(corr)
    shift = k_active - (n - 1)
    
    # Compute subgradient of the active lag
    grad = np.zeros(n)
    
    # First factor: h[i] * (1-h[i+shift])
    # For each valid i, contributes (1-h[i+shift]) to grad[i]
    i_start = max(0, -shift)
    i_end = min(n-1, n-1-shift)
    for i in range(i_start, i_end+1):
        j = i + shift
        if 0 <= j < n:
            grad[i] += (1.0 - h[j])
    
    # Second factor: h[i] * (1-h[i+shift])
    # For each valid i, contributes -h[i] to grad[i+shift]
    for i in range(i_start, i_end+1):
        j = i + shift
        if 0 <= j < n:
            grad[j] -= h[i]
    
    # Step in negative gradient direction
    h_new = h - step_size * grad
    h_new = project_feasible(h_new)
    return h_new
```

This is O(n) per step (the loop over i is at most n iterations). Combined with the O(n) evaluation, each step is O(n). Very efficient!

But the issue is that the subgradient might not be very effective because:
1. It only considers the active lag

    dx = 2.0 / n

    return float(np.max(corr)) * dx

    n = len(h)
    target = 0.5 * n
    h = np.clip(h.astype(np.float64), 0.0, 1.0)
    for _ in range(200):
        diff = target - np.sum(h)
        if abs(diff) < 1e-14:
            break
        if diff > 0:
            mask = h < 1.0 - 1e-12
        else:
            mask = h > 1e-12
        cnt = np.count_nonzero(mask)
        if cnt == 0:
            break
        h[mask] += diff / cnt
        np.clip(h, 0.0, 1.0, out=h)
    return h

    n_src = len(h_src)
    if n_src == n_new:
        return project_feasible(h_src.copy())
    x_old = np.linspace(0.0, 2.0, n_src, endpoint=False)
    x_new = np.linspace(0.0, 2.0, n_new, endpoint=False)
    h_new = np.interp(x_new, x_old, h_src)
    return project_feasible(h_new)

def compute_subgradient(h):
    """Compute subgradient of the max overlap w.r.t. h."""
    n = len(h)
    corr = np.correlate(h, 1.0 - h, mode="full")

            grad[i] += (1.0 - h[j])
            grad[j] -= h[i]
