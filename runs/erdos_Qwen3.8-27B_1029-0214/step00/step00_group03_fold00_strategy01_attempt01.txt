1. Approach and rationale
-------------------------

1.1 Central idea
The search will maintain the sampled step function by its evaluated objective and will use a feasibility-preserving epigraph local optimizer. For a vector `h` of length `N`, the exact evaluator maximizes the `2N-1` linear finite-shift correlations. Instead of repeatedly applying pairwise coordinate exchange, define an auxiliary scalar `t` and solve the smooth-gauge problem

    minimize   t
    subject    f_s(h) - t <= 0   for every shift s,
               sum_i h[i] = N/2,
               0 <= h[i] <= 1.

The functions `f_s` are the exact discrete shifted products used by the evaluator, up to the harmless ordering of shift lags. The problem is nonconvex because products `h[i] * h[j]` are bilinear and indefinite. Therefore the method is only a local search generator and a source of certified feasible upper bounds. There is no optimality claim for any minimum found by the local optimizer. The validated best exact evaluator value among all feasible generated vectors, including the supplied parent, is returned.

This is materially different from a pair-exchange algorithm: coordinate pairs are not selected and updated directly. The mechanism is an epi-graph reformulation solved by a local feasible/infeasible smoothing optimizer, with exact evaluation and feasibility after every optimizer call. The main tools are exact analytics for the finite-shift correlation, multistart over deterministic and random feasible parents, and coarse-to-fine resolution continuation.

1.2 Why could it improve the parent
The parent may correspond to a local point determined by a single non-smooth maximum lag. Epigraph methods treat many near-active lags at once through their gradient information, rather than forcing one update to be monotone of a selected pair trajectory. A local optimizer can move many coordinates together while only requiring the approximate maximum constraints, then exact evaluation verifies whether the true maximum has actually decreased. Combinatorial and smooth starting points can escape a poor basin. Up-scaling the resolution lets the optimizer vary a length-90 or length-135 candidate, then the evaluator scores the candidate independently. If the high-resolution candidate gives a lower discrete evaluator value, it may improve the record without ever pretending to be a global proof.

1.3 Bottleneck addressed and limitations
The non-smooth maximum over up to 89, 179, or 269 discrete lags is difficult to optimize with generic scalar solvers because its gradients can switch. The epigraph model analyzes all shift constraints in one vectorized nonlinear program and uses exact analytic gradients. Constraints are kept consistent with boundary truncation, not circular convolution or an autocorrelation shortcut.

Important limitations:

- The local model is nonconvex. A successful SLSQP termination means only that a feasible, lower exact value may have been found, not that it is globally optimal or proven better than all feasible functions.
- Exact evaluator checks are called after all optimizer repair; all returned vectors are recomputed using the evaluator formula.
- If no candidate beats the supplied parent, the construct on the parent remains available and is returned, satisfying the guarantee to return a valid solution.
- Boundary overlap is modeled shift by shift. No boundary term is ignored.
- Higher resolutions can expose finer shapes. If a fixed resolution is globally defined, returning a different `n_points` is permitted by the stated evaluator because the evaluator computes its own objective from any returned array.

1.4 Search character
The method combines:

- a parent-anchored local epigraph search;
- deterministic perturbations and finite pattern starts;
- low-cost random feasible multistart;
- upsampling the best candidate and resuming the same formula at a higher grid size;
- conservative downsampling back to the base size;
- strict exact acceptance only when the evaluator score is lower than the current best.

2. Mathematical specification
-----------------------------

2.1 Discrete samples and constraints
For returned length `N`, let

    dx = 2.0 / N
    target = 0.5 * N

Constraints:

    0 <= h[i] <= 1,   i = 0,...,N-1
    sum_i h[i] = target

The exact evaluator value stored by the task is

    C5(h) = dx * max_l G_l(h)

where

    G_l(h) = np.correlate(h, 1 - h, mode="full")[l]

and `l` ranges over all `2N-1` full linear correlation lags. The maximum is taken over both positive and negative shifts. Do not replace this with a full-interval circular autocorrelation or by `1 - minimum_autocorrelation` because a nonzero shift overlaps only part of the finite support.

2.2 Exact internally used shift representation
To formulate a smooth constraint model, define for each integer shift

    s = -N + 1,..., N - 1

the finite-support shift correlation

    g_s(h) = sum_{p valid} h[p] * (1 - h[p + s])

where valid means

    0 <= p < N,
    0 <= p + s < N.

Equivalently, set

    a_s = max(0, -s)
    b_s = min(N, N - s)

and when `b_s > a_s`,

    g_s(h) = sum_{p=a_s}^{b_s-1} h[p] * (1 - h[p + s]).

Store the corresponding density shift term as

    f_s(h) = dx * g_s(h).

The multiset of these terms over all `s` is exactly the finite-support correlation multiset up to a possible reversal of the lag ordering, because reversing s maps the same overlap sets and the evaluator also maximizes over all shifts. Therefore

    max_s f_s(h) = np.correlate(h, 1-h, mode="full").max() * dx

as a multiset identity. This must still be numerically checked by the final code for the chosen numpy version. Use a comparator: compute the evaluator output array and the internal array and compare their maxima, total lengths, and sorted arrays within tolerance. If the internal representation appears wrong, correct the slice mapping rather than pretending equality.

2.3 Derived ingredients for exact shift functions
Let

    q(h) = 1 - h.

For a valid shift interval

    h slice: h[a:b]
    q slice: q[a+s : b+s]

the overlap length is

    m = b_s - a_s.

The scalar function is:

    g_s = dot(h[a:b], q[a+s:b+s])
    f_s = dx * g_s.

Derivative with respect to h:

For each first-overlap index p in [a,b), term h[p] * q[p+s] contributes:

    partial f_s / partial h[p] += dx * q[p+s].

For each second-overlap index r_p = p+s, where p in [a,b), term q[r_p] = 1 - h[r_p] contributes:

    partial f_s / partial h[r_p] -= dx * h[p].

Vectorized gradient for one shift:

    grad = zeros(N)
    grad[a:b] += dx * q[a+s : b+s]
    grad[a+s : b+s] -= dx * h[a:b]

The two lines use exactly matched valid slices. When `s=0` this yields `grad[p] = dx * (1 - h[p]) - dx * h[p] = dx * (1 - 2*h[p])`, which is the correct derivative of `dx * sum_i h[i]*(1-h[i])`. When one of the slices is empty (which cannot occur inside the internal shift convention because valid shifts always overlap if originally in `-N+1,...,N-1`), gradient is zero.

2.4 Epi-graph continuous problem
Decision variables are ordered as

    z = [h[0], ..., h[N-1], t].

Use the equivalent nonlinear model:

    minimize t
    subject sum_{i=0}^{N-1} h[i] - target = 0
    subject t - f_s(z) >= 0 for all s = -N+1,...,N-1
    subject 0 <= h[i] <= 1
    subject 0 <= t <= 10

where all `f_s(z)` depend only on `z[0:N]`. The inequality functions are smooth within each shift because each shift includes no non-differentiability: the only nonsmoothness from a maximum is replaced by these many differentiable functions. The model is not convex because the bilinear term has an indefinite Hessian. Therefore any deterministic optimum from this model gives no global certificate. It is useful as a directed collection of candidates.

Why this is correct acceptance logic:
If the solver produces a true feasible point `z = (h,t)` with `t = max f_s(h)`, then `h`'s exact objective equals `t`. In numerical implementation we ignore the solver variable `t` for final acceptance; the solver's `h` is repaired to exact feasibility and scored with the original `np.correlate` formula. Acceptance is only when this scored value lower than the incumbent, so a nonsmooth numerical artifact cannot be passed.

2.5 Joint feasibility repair mechanism
All pointwise clipping and independent renormalization are prohibited. When a generated or solver-generated `v` is not exactly feasible, use the top-level helper `repair_feasibility(v, N)`, target = N/2, as follows.

Inputs:
- `v`: a 1-D finite float vector length `N`.
- `target`: `0.5*N`.
Outputs:
- `h`: 1-D float64 vector length `N`.
- `ok`: Boolean exactly indicating 0 <= h_i <= 1 and |sum(h)-target| sufficiently small.

Algorithm:

1. Cast to float64. If non-finite, return failure.
2. Initial clip:
       x = clip(v, 0, 1).
3. If the clipped sum `sx` is already close to `target`, keep x. If target cannot be reached, proceed anyway.
4. Find an interval `lo, hi` satisfying `sum(clip(v+lo)) <= target <= sum(clip(v+hi))`. A monotone continuous scalar family is preserved by offsetting `lo = min(v)-1.0`, `hi = max(v)+1.0`. While lo and hi are equal keep extending.
5. Bisection on `phi(lambda)=sum(clip(v+lambda, 0, 1))` for up to 70 iterations. Because `phi` is monotone, the desired lambda interval brackets target. Use target if phi exactly at target. If phi has a plateau equal to target, returning any plateau offset is acceptable.
6. Let `lambda_final` be a bound close enough, define
       x = clip(v + lambda_final, 0, 1),
   and compute sum. The final difference is typically only machine error.
7. Exact greedy residual repair.
   Let

       r = target - sum(x).

   Use the maximally safe double-count tolerant method:
   For a positive residual `r > 0`, scan i=0,...,N-1 in a loop:
       slack_i = max(0, 1 - x[i])
       delta = min(r, slack_i)
       if delta > 0:
           x[i] += delta
           r -= delta
       if |r| <= tiny: stop.
   For a negative residual `r < 0`, scan in the same order:
       slack_i = max(0, x[i])
       delta = min(-r, slack_i)
       if delta > 0:
           x[i] -= delta
           r += delta
   Repeat repair one or two times if the accumulated `r` remains small. If needed, do one final coordinate tweak: choose one coordinate within its bounds such that `x[k] - residual > 0` and `x[k] - 1 < residual` before adjustment; assign `x[k] -= residual`.
8. Clip all `x` into [0,1] again only by a bounded assignment, then recalculate the residual one final time and distribute it using step 7. The result should satisfy both linear equality and box constraints at the numerical tolerance level.

Tolerance choices:
- feasibility tolerance: `1e-9` absolute for sum.
- (box tolerance: allow eps `1e-12` for a generated float; final correction makes them inside simple min/max.)

Any produced candidate must be passed through this procedure before exact scoring and before evaluation in the run. If repair failure occurs and there is an incumbent parent, discard the candidate; if no incumbent exists, produce a constant `0.5` vector at the current length or fallback length.

2.6 Exact objective recomputation with boundaries
The local optimizer uses the internal shift convention above. However, the authoritative routine computes exact score as:

    score_exact(h) = np.correlate(h, 1.0-h, mode="full").max() * (2.0/len(h))

After local search results plus repair, always:
- copy to a float64 numpy vector,
- repair feasibility,
- rescore using `score_exact`.
- never accept an internal `t` from the solver and never use internal max arrays for final rated value.

2.7 Resolution transfers
Upsampling with linear interpolation:
For parent length `N0`, transfer to target length `N1` using cell-center coordinates:

    x0_i = (i + 0.5) * (2/N0),
    x1_j = (j + 0.5) * (2/N1).

Set `raw = np.interp(x1, x0, h_old)`. Then repair the raw vector to target sum `N1/2` using `repair_feasibility`. Because interpolation is linear, integrals are not guaranteed to be preserved exactly by the discrete sum constraint, so independent repair is required; then the evaluator computes the shifted objective at the current resolution. This is not claiming that interpolation preserves the objective; it only creates a feasible vector that has similar shape and should be re-scored.

Downsampling:
If `N1` is an exact integer multiple of `N0`, average contiguous blocks of `N1/N0`. For non-divisor target lengths, use element-wise linear interpolation evaluated at `N0` centers followed by repair. This path down-samples the best throughput but cannot improve on parent unless verified exact lower.

2.8 Exclusion of global/solver claims
The exact objective can be described as a discontinuous maximum over `2N-1` bilinear constraints. There is no convex reformulation available under the allowed convex finite-dimensional library rules for the original nonconvex problem. Therefore do not use a convex relaxation as a proof. Only a vector accepted because `score_valid <= current_valid` is accepted. A global `Certificate=False` applies to every run result. Even if SLSQP returns success, diagnose output as a nonconvex local candidate learned by a heuristic optimization.
