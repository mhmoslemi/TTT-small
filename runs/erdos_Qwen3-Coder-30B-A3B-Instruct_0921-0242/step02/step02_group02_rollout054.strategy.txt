- 0 ≤ h[i] ≤ 1,
- sum(h) = n/2 (i.e. ∫₀² h = 1),

**Overall plan**
1. **Problem reformulation** – treat the correlation as a convolution on a circle of length 2. The objective is the maximum of the cross‑correlation vector. This is a non‑convex “min‑max” problem.
2. **Two‑phase approach**  
   - **Global search**: use a fast, cheap stochastic sampler that respects the constraints to explore the space and collect promising candidates.

3. **Constraint handling** – keep feasibility at all times using a *simplex projection* onto the affine set `{h∈[0,1]^n : sum(h)=n/2}`. This is done by a water‑filling algorithm that is O(n) and exact.
4. **Efficient evaluation** – compute the full correlation via FFT (O(n log n)) once per evaluation. Store the correlation and the index of the maximal entry; gradients w.r.t. that entry can be computed analytically in O(n).

### 1. Global search (Monte‑Carlo + cheap mutation)

- **Sample size**: start with *M* = 2000 random vectors.
- **Generation**: draw `u ~ Uniform(0,1)^n`, project to feasible set.
- **Evaluation**: compute C5 via FFT. Keep the top *K* = 30 samples (lowest C5) as a *pool*.
- **Mutation loop** (run until time≈0.3 budget):
  - Pick a parent uniformly from the pool.
  - Create a child by applying one of:
    * **Gaussian perturbation** on a random subset of 5‑10 indices (add N(0,σ²), clamp, re‑project). σ initially 0.2, decay with iteration.
    * **Swap‑mass**: pick i with h[i]>δ and j with h[j]<1‑δ, move δ (δ≈0.01) from i to j.
    * **Fourier‑mode tweak**: compute discrete cosine transform (DCT) of h, modify a low‑frequency coefficient, inverse DCT, re‑project. Enables smooth shape changes.
  - Evaluate child, replace worst element in pool if child is better.
- This stage quickly discovers diverse low‑C5 structures (often piecewise‑constant with a few “blocks”).

### 2. Local refinement (targeted min‑max descent)

For each pool member (or just the best few, e.g. top 5) run an iterative improvement:

- **Identify worst shift**: compute correlation `c = correlate(h, 1‑h, mode='full')`; locate `k* = argmax(c)`.
- **Sub‑gradient**: The objective is `f(h)=c[k*]*dx`. Its sub‑gradient w.r.t. h is
  ```
  grad[i] = dx * (  (1‑h[i‑k*]) - (1‑h[i+k*]) )
          = dx * ( h[i+k*] - h[i‑k*] )
  ```
  (indices modulo n). This follows from derivative of the inner product for the selected k*.
- **Projected gradient step**:
  - Compute tentative `h_new = h - η * grad` with step size η chosen by backtracking line search (starting η=0.5, halving until feasibility and improvement).
  - After the step, project back onto the feasible set (water‑filling).
  - Re‑evaluate C5; if improved, accept; otherwise reduce η further.
- **Multiple‑k handling**: after a few iterations the worst shift may change. Each iteration recompute `k*` and its gradient.
- **Stopping criteria**: stop after max 2000 gradient steps, or when improvement <1e‑6, or when time budget for this phase exhausted (~0.5 budget).

### 3. Accelerated refinement via coordinate pair swaps

Gradient descent can stall due to the box constraints. Complement it with a **pairwise exchange** heuristic:

- Randomly select indices (i,j) with h[i]∈(ε,1‑ε), h[j]∈(ε,1‑ε).
- Transfer a small amount δ (δ∈[1e‑4, 1e‑2]) from the larger to the smaller if it reduces the current worst correlation.
- Accept if improvement; otherwise revert. Perform many cheap swaps (≈10 000) quickly.

- After obtaining a good h₀, upscale to n₁ = 500 by linear interpolation of h₀ (preserving integral) and re‑project. Run a short local refinement on the finer grid.
- Optionally a final upscale to n=800 if time permits.
