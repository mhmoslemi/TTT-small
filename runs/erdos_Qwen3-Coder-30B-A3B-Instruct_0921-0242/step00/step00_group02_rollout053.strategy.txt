### 6. Overall workflow inside `run`

```text
1. set RNG seed
2. t0 ← now
3. best ← (initial_h, evaluate(initial_h), len(initial_h))

4. for each n in candidate_sizes:
       a) build initial vector(s) for this n
       b) if n ≤ 36:
              try milp_binary(n, remaining_time)
              if solution improves best → update best
       c) for each start vector:
              h_opt ← local_optimize(start, max_iter, t_end)
              if evaluate(h_opt) < best → update best
              h_ann ← anneal(h_opt, t_end)
              if evaluate(h_ann) < best → update best

5. (optional) up‑sample best from a coarse n to the next finer n
   and run a short local_optimize to polish.

6. return best_h, best_val, best_n
```

All steps respect the global time budget and only use allowed libraries.

### 7. Edge cases & robustness

* **Zero‑division** – `dx` computed as `2.0/n` is never zero.  
* **Projection convergence** – the water‑filling loop runs at most 10 passes; for our modest `n` it always reaches the exact target sum within machine epsilon.  
* **Solver availability** – if `cvxpy` cannot find `CBC`, the code falls back to `GLPK`. If no MILP solver is present, the binary branch is skipped gracefully.  
* **Numerical noise** – bounds are rounded only when comparing for improvement (using a tolerance of `1e‑7`).
