**1. Core mathematical reformulation**  
For a discretisation with `n` points (`dx = 2/n`) let `h∈[0,1]^n` satisfy `∑h_i·dx = 1`.  
Define the aperiodic autocorrelation for shift `k≥1`  

```
R_k(h) = Σ_{i=0}^{n-1-k} h_i·h_{i+k}.
```

The overlap integral equals  

```
C5(h) = max_k Σ_i h_i·(1−h_{i+k})·dx
      = 1 – dx·min_{k≥1} R_k(h).
```

Thus minimising `C5` ⇔ maximising the worst autocorrelation `t(h)=min_k R_k(h)`.  
All constraints are linear; the objective `t` is the pointwise minimum of bilinear forms.  
A standard linear‑programming extremum on a bounded polytope is attained at an extreme point, i.e. at a vertex where each `h_i` is either `0` or `1`.  Consequently we may restrict the search to **binary sequences** with exactly `n/2` ones (the mass constraint forces `∑h_i = n/2`).  The problem then becomes:

```
maximise   t = min_{k≥1} R_k(b)
subject to b∈{0,1}^n ,   Σ b_i = n/2 .
```

The value of `C5` for a binary candidate `b` is `1 – dx·t`.  Finding a high‑`t` binary sequence is precisely the “low‑autocorrelation binary sequence” (LABS) problem, well‑studied in combinatorial optimisation.  We will exploit modern meta‑heuristics for LABS, adapting them to the fixed‑weight requirement.

**2. Data structures for fast evaluation**  
For a binary vector `b` we pre‑compute the correlation vector  

```
R = [R_1, … , R_{n-1}]
```

using a single linear convolution (`np.correlate(b,b,'full')`) and discarding index `0`.  
When a *swap* of two positions `i` (currently 1) and `j` (currently 0) is performed, `R` can be updated in `O(n)` time:

- For each shift `k`:
  * If `i−k≥0` and `b_{i−k}=1` subtract 1 from `R_k` (the pair (i−k,i) disappears).
  * If `i+k<n` and `b_{i+k}=1` subtract 1 from `R_k`.
  * If `j−k≥0` and `b_{j−k}=1` add 1 to `R_k` (new pair (j−k,j)).
  * If `j+k<n` and `b_{j+k}=1` add 1 to `R_k`.

All other entries of `R` remain unchanged.  Maintaining `R` avoids recomputing the full convolution after each move.

**3. Local hill‑climbing on a single sequence**  
Given a binary candidate and its `R`:

1. Identify the *critical shift* `k* = argmin_k R_k`.  The current objective value is `t = R_{k*}`.
2. Enumerate all admissible swaps `(i,j)` where `b_i=1, b_j=0`.  For each swap compute the *delta* in `R_{k*}` using the incremental rule above; the change in `t` is simply the change in `R_{k*}` because all other shifts are ≥ `R_{k*}`.
3. Choose the swap that yields the greatest increase in `R_{k*}` (i.e. largest positive delta).  If no swap improves `R_{k*}`, stop – a local optimum with respect to the critical shift is reached.
4. Apply the chosen swap, update `R`, and repeat from step 1.

Because each iteration strictly increases the minimal autocorrelation, the hill‑climber terminates after at most `n/2` improvements.  The complexity per improvement is `O(n·m)` where `m` is the number of candidate swaps examined; we restrict the search to a *neighbourhood* to keep it cheap:
- Only consider swaps where `i` and `j` lie within distance `w` of any 1‑position that participates in the worst shift (e.g. `w=5`), or
- Randomly sample a fixed number `S` of swaps (e.g. `S=200`) and pick the best among them.  
This yields a fast local optimiser that often lifts the worst autocorrelation by several units.

**4. Evolutionary meta‑heuristic (memetic algorithm)**  
Binary LABS problems are notoriously hard; a population‑based search combined with the hill‑climber above (memetic algorithm) provides a strong global exploration component.

*Parameters (chosen adaptively to `n`):*  
- Population size `P = max(30, 2·n)`.  
- Number of generations per `n` is limited by the time budget (see §7).  
- Tournament size `τ = 3` for selection.  
- Crossover probability `p_c = 0.8`.  
- Mutation strength `µ = 1–2` random swaps per offspring (ensuring weight preservation).  

*Algorithm outline:*  

1. **Initial population**  
   - Include the interpolated version of the supplied `initial_h_values` projected onto binary (top `n/2` entries set to 1).  
   - Fill the remainder with `P-1` random binary vectors of weight `n/2`.  Random generation: draw `n/2` distinct indices uniformly and set them to 1.

2. **Evaluation**  
   - For each individual compute `R` (full convolution) and store `t = min(R)`.  
   - Keep the best individual (highest `t`).

3. **Main loop (generation)**  
   a. **Selection** – repeatedly pick `τ` individuals at random and select the one with highest `t` (tournament).  
   b. **Crossover** – with probability `p_c` combine two parents:
      * Form the union of the two support sets (positions of 1’s).  
      * If the union size exceeds `n/2`, randomly drop excess positions; if it is smaller, randomly add new positions from the complement.  The result is a valid binary child of weight `n/2`.  
   c. **Mutation** – perform `µ` random swaps (pick a 1‑position and a 0‑position and exchange them).  
   d. **Local improvement** – run the hill‑climber from §3 on the child; accept the improved version.  
   e. **Replacement** – insert the child into the population, discarding the worst individual (lowest `t`).  

   After each generation update the global best.

4. **Diversification** – every `G` generations (e.g. `G=20`) inject a fresh random individual (binary weight `n/2`) to avoid premature convergence.

5. **Termination for current `n`** – stop after a preset number of generations (e.g. `150·n / 50` ≈ 3·n generations) *or* when the elapsed time for this `n` exceeds its allocated budget (see §7).  Preserve the best sequence found.

2.
