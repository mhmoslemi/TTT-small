| **5** | Compute `C5 = w·(2/n0)`.  Verify `∑h = 1` (within 1e‑9). | – |

If any phase overruns the remaining budget, the algorithm immediately returns the **best incumbent** (`h` and `C5`) obtained so far.

--------------------------------------------------------------------
### 8. Why this strategy is materially different

1. **Exact integer programming core** – Unlike gradient descent, block enumeration, or heuristic swaps, the main search is an **MILP** that encodes the bilinear products *exactly* via binary product variables; the solver explores the combinatorial space globally using branch‑and‑bound.
2. **Convex‑analytic reduction** – The max‑overlap objective is linearised by introducing a single auxiliary variable `w`; the problem becomes a *linear* objective with *linear* constraints, a formulation not used in previous strategies.
3. **Symmetry‑breaking and duplication** – We deliberately fix a coordinate and enforce a lexicographic order to prune the exponential symmetry, a technique absent from earlier attempts.
4. **Deterministic guarantee** – If the MILP finishes, the reported `C5` is provably optimal for the chosen discretisation; any heuristic approach only yields a (possibly sub‑optimal) bound.
5. **Hybrid fallback** – The greedy + swap fallback is only a *backup* when the MILP cannot finish; the core contribution remains the exact MIP model.

### 9. Anticipated failure modes & mitigations

| Risk | Effect | Mitigation |

| MILP does not finish for `n0=120` within budget. | We fall back to greedy solution with higher `C5`. | Choose `n0=100` as a secondary target (fewer variables) if time runs low; the duplication step guarantees we can still return a bound. |

| Solver not installed (e.g., SCIP unavailable). | Cannot run MILP. | Fall back automatically to the greedy‑plus‑swap heuristic; this path is already part of the algorithm and still yields a respectable bound (`≈ 0.382`). |
