**Goal**: Produce a step‑function discretization `h` (values in [0,1], sum = n_points/2) that yields a smaller maximal overlap  
\(C_5=\max_k \int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx\) than the previous best (≈0.382264) and ideally ≤0.3807, within 600 s on a single CPU.

**Overview of approach**

1. **Model the problem as a convex‑quadratic program (QP) with a max‑over‑shifts constraint**  
   The objective `max_k overlap(k)` can be expressed via an epigraph formulation:
   \[
   \min\; t\quad\text{s.t.}\quad 
   \forall k\in\mathcal{K}: \; \sum_i h_i (1-h_{i+k}) \le t,
   \]
   where indices are taken modulo the discrete grid (or zero‑padded) and `dx` absorbed later.  
   The constraints are *quadratic* in `h` (bilinear term `h_i h_{i+k}`) but **concave** because `-h_i h_{i+k}` appears. However the left‑hand side is linear minus a convex term, giving a *convex* constraint:  
   \[
   \sum_i h_i - \sum_i h_i h_{i+k} \le t .
   \]
   The term \(\sum_i h_i\) is constant (equals target sum), so each constraint reduces to  
   \[
   -\sum_i h_i h_{i+k} \le t - \text{target\_sum}.
   \]
   Multiplying by –1 flips direction:
   \[
   \sum_i h_i h_{i+k} \ge \text{target\_sum} - t .
   \]
   This is a *convex* quadratic inequality (since \(h_i h_{i+k}\) is convex in each variable separately but the sum is convex as a quadratic form with positive semidefinite matrix). Actually the matrix with 1 on the (i,i+k) entries is PSD because it is a sum of rank‑1 PSD matrices \(e_i e_{i+k}^T\). Hence the problem is a **convex QP** that can be solved by a generic QP solver (e.g., OSQP via cvxpy) efficiently for modest n (≤600).

2. **Discretization and shift set**  
   Use a moderate grid \(n=400\) (dx=0.005). Larger n gives finer control but increases QP size quadratically in the number of shifts.  
   Shifts `k` range over integers \(-n+1,\dots,n-1\) (full correlation). However many far shifts produce tiny overlaps because support of `h` is limited; we can restrict to a window `|k| ≤ Kmax` with `Kmax = int(0.8*n)` – still covering the region where the max is attained (empirically around half the interval). The QP will have `2*Kmax+1` quadratic constraints, each cheap.

3. **Convex formulation in CVXPY**  

   Variables: `h = cvxpy.Variable(n)` and scalar `t`.  
   Constraints:  
   - Box: `0 ≤ h ≤ 1`.  
   - Sum: `cvxpy.sum(h) == n/2`.  
   - For each shift `k` in `shifts`:
     \[
     \text{quad}_k = cvxpy.quad_form(h, Q_k) \ge \text{target\_sum} - t,

def build_Q(k, n):
    # returns sparse symmetric PSD matrix for term h_i h_{i+k}
    data = np.ones(n-abs(k))
    rows = np.arange(n-abs(k))
    cols = rows + k if k>=0 else rows - k
    Q = sp.csr_matrix((data, (rows, cols)), shape=(n,n))
    return 0.5*(Q + Q.T)

def solve_qp(n, Kmax, warm_h=None):
    h = cp.Variable(n)
    t = cp.Variable()
    constraints = [h >= 0, h <= 1, cp.sum(h) == n/2]
    for k in range(-Kmax, Kmax+1):
        Q = build_Q(k, n)
        constraints.append(cp.quad_form(h, Q) >= n/2 - t)
    probs = cp.Problem(cp.Minimize(t), constraints)
    if warm_h is not None:
        h.value = warm_h
    probs.solve(solver=cp.OSQP, verbose=False, max_iter=5000)
    return h.value, t.value
