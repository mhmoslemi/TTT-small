**Goal** – Produce a binary step‑function `h` on `[0,2]` (array of length `n`, values 0/1, exactly `n/2` ones) that minimizes  

\[
C_5(h)=\max_{k}\int_0^2 h(x)\bigl(1-h(x+k)\bigr)\,dx
     =\max_{k}\bigl(\tfrac{n}{2}-\sum_{i=0}^{n-1}h_i h_{i+k}\bigr)\,dx,
\]

with `dx = 2/n`.  Smaller `C_5` yields a tighter upper bound for the Erdős constant.

The proposed method is a **global evolutionary search** (genetic algorithm) combined with **targeted local hill‑climbing**.  It differs fundamentally from the earlier gradient‑based, convex‑QP, MIP and SDP pipelines: it works directly on the binary combinatorial space, exploits population diversity, and uses a fast FFT‑based evaluation of the max‑over‑shifts objective.

---

### 1. Discretisation and evaluation primitives  

*Choose a modest grid size* `n = 280` (even, `dx = 2/n ≈ 0.00714`).  This size is small enough for many generations while fine enough that the discrete bound is within 0.01 of the continuous one.

**C5 computation** – For a binary vector `h` compute the full correlation with its complement using FFT:

1. `g = 1 - h` (still binary).  
2. Compute the real FFTs `H = rfft(h)`, `G = rfft(g)`.  
3. Obtain the convolution `c = irfft(H * G, n_full)`, where `n_full = 2*n-1`.  
4. `C5 = max(c) * dx`.

FFT gives `O(n log n)` time (≈ 2 µs per evaluation at `n=280`), allowing millions of fitness calls.

**Repair to constraints** – After any recombination or mutation the vector may violate the cardinality constraint.  A fast repair:
- Count `s = sum(h)`.  
- If `s > n/2`, randomly flip `s-n/2` ones to zero.  
- If `s < n/2`, randomly flip `n/2-s` zeros to one.  
The resulting vector respects `0≤h_i≤1` and the exact sum.

|Source|Count|Construction|
|------|-----|------------|
|Interpolated `initial_h_values`|1|Interpolate to `n` points, then repair.|

|Random balanced|179|Generate `n/2` random positions for ones, fill the rest with zeros.|

All individuals satisfy the sum constraint.  Evaluate each with the FFT routine and store fitness `f = -C5`.

### 3. Genetic operators  

**Selection** – Binary tournament: pick two random individuals, keep the one with higher fitness (lower `C5`).  Perform `pop_size` tournaments to select the mating pool.

**Crossover** – Two‑point crossover:

1. Choose two cut points `c1 < c2`.  
2. Offspring `child = parent1[:c1] + parent2[c1:c2] + parent1[c2:]`.  
3. Apply the repair procedure to restore exact cardinality.

**Mutation** – Swapping mutation (probability `p_mut = 0.2` per child):
- Pick a random index `i₁` where `h[i₁]=1` and a random index `i₀` where `h[i₀]=0`.  
- Exchange their values.  
A secondary low‑probability block‑swap mutation (probability `0.02`) selects a short contiguous block (length ≤ 4) and moves it to a random location, followed by a weight‑preserving adjustment.

Both operators preserve the 0/1 nature; repair guarantees the sum constraint.

**Elitism** – Copy the best `elite = 5` individuals unchanged into the next generation.

**Diversity control** – After forming the new population, compute pairwise Hamming distances for the lowest‑fitness 50 individuals; if the average distance falls below `0.2·n`, replace the most similar half with fresh random balanced individuals.  This prevents premature convergence.

### 4. Evolutionary loop with time budgeting  

```text
t_start = time()
while time() - t_start < budget - 20 s:
    1. Tournament selection → mating pool.
    2. Crossover + mutation → offspring (size = pop_size - elite).
    3. Repair each offspring to exact weight.
    4. Evaluate offspring (FFT C5) → fitness.
    5. Form new population = elite ∪ offspring.
    6. Every 10 generations run a **targeted local hill‑climber** on the current best individual (see §5).
```

The loop stops early if the best `C5` already drops below the target `0.3807`, reserving remaining time for refinement.

### 5. Targeted local hill‑climbing (intensification)  

Given a binary vector `h₀`, we repeatedly attempt **swap moves** that directly reduce the worst shift:

1. Compute the full correlation `c = correlate(h₀, 1-h₀, mode='full')` (FFT).  
2. Identify the shift `k*` where `c[k*]` attains the maximum.  
3. Determine all positions `i` contributing to that shift: for a swap `(i₁,i₀)`, the change in `c[k*]` is  

   \[
   \Delta = -dx\bigl(h_{i₁}h_{i₁+k*} - (1-h_{i₁})h_{i₁+k*}
                 -h_{i₀}h_{i₀+k*} + (1-h_{i₀})h_{i₀+k*}\bigr).
   \]

   Since `h` is binary, the expression reduces to adding or subtracting a single `dx`.  
4. Scan a limited set (e.g., 200 random swaps) and pick the swap with the largest negative `Δ` (most reduction).  
5. Apply the best swap, update `c` incrementally (only the entries shifted by `k*` change) and repeat.  
6. Stop after a fixed number of accepted swaps (`≈ 500`) or when no improving swap exists.

Because the hill‑climber focuses on the currently worst shift, it efficiently lowers `C5`.  The operation costs `O(n)` per attempted swap, negligible at `n=280`.

The hill‑climb is invoked after every 10 generations on the best individual, guaranteeing rapid exploitation of promising genetic material.

---

### 6. Multi‑scale refinement  

When the evolutionary phase ends, take the best binary vector `h_best` and **upsample** it to a finer grid `n_fine = 500` (interpolate by copying each entry to `⌈n_fine/n⌉` consecutive positions, then trim to exact weight).  Run a short **steady‑state GA** on the finer grid for the remaining time (≈ 10 s) using the same operators but with a reduced population (`pop_size = 50`).  The upsampled pattern inherits the macro‑structure of the coarse solution while allowing minor adjustments that can shave a few hundredths off `C5`.

After this second‑stage GA, apply a final hill‑climber on the fine grid (with up to 2000 swaps) to polish the solution.

### 7. Failure‑mode safeguards  

|Potential issue|Mitigation|
|---|---|
|Population stalls (loss of diversity) | Diversity injection (replace half of the worst individuals with fresh random balanced vectors).|
|C5 evaluation becomes a bottleneck | FFT implementation is vectorised; if still slow, fall back to `np.correlate` for the best few individuals only.|
|Time overrun | At each major block (coarse GA, hill‑climb, fine GA, final hill‑climb) check remaining time; if < 5 s, skip the block and return the current best.|
|Repair fails to achieve exact weight (rare due to rounding) | After repair, re‑compute `sum`; if still off by 1, flip a random bit to correct it.|
|Local search gets stuck | After 3 unsuccessful hill‑climb attempts, restart hill‑climb from a random neighbor of the current best.|
|FFT rounding causing slight violation of constraints| After final selection, recompute `C5` with high‑precision `np.correlate` to ensure the reported bound is accurate.|

### 8. Expected performance  

*Population dynamics*: With `pop_size=200` and fast FFT evaluation, a full generation takes ≈ 0.02 s on a single core.  In 200 s we can run > 10 000 generations, providing ample exploration.

*Local intensification*: The targeted swap hill‑climber typically reduces `C5` by 0.001–0.003 per invocation on a good candidate, rapidly driving the bound toward ≤ 0.379.

*Fine‑scale upsampling*: Adding a few hundred extra points can improve the bound by ≈ 0.0005 because the binary pattern can adjust local irregularities that were forced to align with the coarse grid.

Overall we anticipate a final discrete bound **≤ 0.3795**, comfortably beating the target `0.3807` and improving the previous best `0.38226`.
