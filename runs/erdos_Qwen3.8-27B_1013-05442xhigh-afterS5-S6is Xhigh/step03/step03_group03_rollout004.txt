**Approach: Direct minimax via bisection on C₅**

Instead of smooth max, I can formulate it as:
- Find the minimum C such that ∃h with 0≤h≤1, ∫h=1, and for all k: ∫h(x)(1-h(x+k))dx ≤ C

This is a feasibility problem. I can use bisection on C and check feasibility using... what? The constraints are bilinear in h, so it's not convex.

Actually, the constraint ∫h(x)(1-h(x+k))dx ≤ C is NOT convex in h (it's bilinear: -∫h(x)h(x+k)dx + ∫h(x)dx ≤ C). So we can't directly use convex optimization.

But wait: ∫h(x)(1-h(x+k))dx = ∫h(x)dx - ∫h(x)h(x+k)dx

The first term is constant (= 1, the integral of h). So minimizing the max overlap is equivalent to maximizing the min of ∫h(x)h(x+k)dx over k!

So: maximize min_k ∫h(x)h(x+k)dx subject to 0≤h≤1, ∫h=1.

This is still non-convex (the objective involves products of h).

OK so let me stick with the smooth max approach but do it more carefully.

**Key improvement idea: Use a "top-k sparse" smooth max**

Instead of the full log-sum-exp (which requires O(n) work per gradient and has many small weights), I only track the top K lags and compute the smooth max over just those. This gives a lower bound on the true smooth max, but for large beta, the top K dominate anyway.

This makes the gradient computation much faster (only K lags instead of O(n) lags).
