- The term where n=j: h[j+k]*(1-h[j]) changes from h[j+k]*0 to h[j+k]*1. Change: +h[j+k].

So flip_down(j) = -(1-h[j-L])*[valid, L≠0] + h[j+L]*[valid, L≠0]
                = -flip_up(j) ... wait no.

flip_up(j) = (1-h[j-L])*[valid, L≠0] - h[j+L]*[valid, L≠0]
flip_down(j) = -(1-h[j-L])*[valid, L≠0] + h[j+L]*[valid, L≠0] = -flip_up(j)

So flip_down(j) = -flip_up(j). 

But this is only true when h[j] is binary (0 or 1), which it is.

So the combined effect of swapping i (0→1) and j (1→0) is:
corr_new[k] = corr_old[k] + flip_up(i)[k] + flip_down(j)[k]
            = corr_old[k] + flip_up(i)[k] - flip_up(j)[k]

But wait, there's a subtlety. When we compute flip_up(i), we use the current h (where h[j]=1). But after the swap, h[j]=0. Does this matter?

The effect of flipping h[i] from 0 to 1 depends on h at other positions (specifically h[i-L] and h[i+L]). If one of those positions is j, then the effect depends on whether h[j] is 1 or 0 at the time of the flip.

In our case, we're doing both flips simultaneously. So the correct computation is:
- The change at position i (0→1) uses the OLD h for other positions (including h[j]=1)
- The change at position j (1→0) uses the OLD h for other positions (including h[i]=0)

But if i-L = j or i+L = j for some L, then the effect of flipping i depends on h[j], and vice versa. In that case, the linear superposition flip_up(i) - flip_up(j) is not exactly correct because the two flips interact.

However, for n=250, the probability that i and j are within (n-1) of each other (which is always true since they're both in [0, n-1]) is 1. But the specific interaction only happens when |i-j| relates to a specific lag.

Actually, let me think about when the interaction happens. flip_up(i)[k] depends on h[i-L] and h[i+L]. If i-L = j, then flip_up(i)[k] uses h[j] = 1. But after the swap, h[j] = 0. So the actual effect is different.

Specifically, if i-L = j (i.e., L = i-j):
- In flip_up(i)[k]: the term (1-h[i-L]) = (1-h[j]) = 1-1 = 0 (using old h)
- But after the swap, h[j] = 0, so the "true" term would be (1-0) = 1.
- So the actual contribution is 1, not 0. The linear formula gives 0.

Similarly, if i+L = j (i.e., L = j-i):
- In flip_up(i)[k]: the term -h[i+L] = -h[j] = -1 (using old h)
- After the swap, h[j] = 0, so the "true" term would be -0 = 0.
- The linear formula gives -1, but the true value is 0.

And for flip_down(j) = -flip_up(j)[k]:
If j-L' = i (i.e., L' = j-i = -L when L = i-j):
- In flip_up(j)[k]: the term (1-h[j-L']) = (1-h[i]) = 1-0 = 1 (using old h)
- After swap, h[i] = 1, so true term is (1-1) = 0.
- flip_down(j) gives -1, true is 0.

If j+L' = i (i.e., L' = i-j = -L when L = j-i):
- In flip_up(j)[k]: the term -h[j+L'] = -h[i] = -0 = 0 (using old h)
- After swap, h[i] = 1, so true term is -1.
- flip_down(j) gives 0, true is -1.

So the linear superposition is wrong by O(1) at the specific lags where i and j interact. For the purpose of finding a good swap, this is a small error. The linear approximation will still find good candidates; we can just verify the actual correlation after the swap.

So my approach will be:
1. Precompute the effect matrix E (flip_up for each position)
2. For candidate swaps (i,j), use the linear approximation corr + E[i] - E[j] to find the best candidates
3. Verify the best few candidates with exact computation
4. Perform the best swap
5. Update E incrementally (or just recompute if it's fast enough)

For n=250, recomputing E takes O(n^2) = 62500 operations, which is trivial. So I can just recompute E after each swap.

Actually, even better: I can precompute E and update it in O(n) after each swap (since only the row for i, the row for j, and the rows for positions that interact with i or j change).

But for simplicity, let me just recompute E from scratch after each swap. It's O(n^2) = 62500, which is fast.

Let me now write the final clean version:

```python
import numpy as np
from scipy.optimize import minimize
import time

def compute_c5(h, n):
    dx = 2.0 / n
    c = np.correlate(h, 1 - h, mode='full')
    return float(np.max(c) * dx)

def project_feasible(h, n):
    h = np.clip(h, 0.0, 1.0)
    for _ in range(100):
        diff = n / 2.0 - h.sum()
        if abs(diff) < 1e-10:
            break
        if diff > 0:
            room = 1.0 - h
            s = room.sum()
            if s < 1e-14:
                break
            h = h + diff / s * room
        else:
            s = h.sum()
            if s < 1e-14:
                break
            h = h + diff / s * h
    return np.clip(h, 0.0, 1.0)

def build_effect(h, n):
    """Compute flip_up effect for each position.
    E[p, k] = change in corr[k] when h[p] flips 0→1 (all else fixed)."""
    n1 = n - 1
    E = np.zeros((n, 2 * n - 1))
    for p in range(n):
        for k in range(2 * n - 1):
            L = k - n1
            if L == 0:
                continue
            a = p - L
            b = p + L
            if 0 <= a < n:
                E[p, k] += 1.0 - h[a]
            if 0 <= b < n:
                E[p, k] -= h[b]
    return E
```

Wait, this is O(n^2) = 62500 which is fine but the Python loop will be slow. Let me vectorize it.

Actually for n=250, the full matrix E is 250 × 499 = 124750 entries. Computing each entry involves checking two conditions. In a Python loop, that's about 125K * (few ops) ≈ maybe 1-2 seconds. That's too slow if we need to do it many times.

Let me vectorize:

```python
def build_effect(h, n):
    n1 = n - 1
    # For position p and output index k:
    # L = k - n1
    # a = p - L = p - k + n1
    # b = p + L = p + k - n1
    # E[p,k] = (1-h[a])*[0<=a<n] - h[b]*[0<=b<n]
    
    # Vectorize: p ranges over [0, n-1], k ranges over [0, 2n-2]
    P = np.arange(n)[:, None]  # shape (n, 1)
    K = np.arange(2 * n - 1)[None, :]  # shape (1, 2n-1)
    
    a = P - K + n1  # p - (k - n1) = p - k + n1
    b = P + K - n1  # p + (k - n1) = p + k - n1
    
    mask_a = (a >= 0) & (a < n)
    mask_b = (b >= 0) & (b < n)
    
    # For L=0 (k=n1): a = p, b = p, and the effect should be 0
    # (1-h[p]) - h[p] = 1 - 2*h[p], but we need 0 for binary h with h[p]=0 or 1
    # Actually for L=0: the formula gives (1-h[p]) - h[p] = 1-2h[p]
    # But the true effect is 0 (as we derived earlier).
    # So we need to zero out the L=0 column.
    
    E = (1 - h[a]) * mask_a - h[b] * mask_b
    # h[a] and h[b] need to be valid indices
    # Use np.where or clip
    h_a = np.where(mask_a, h[np.clip(a, 0, n-1)], 0)
    h_b = np.where(mask_b, h[np.clip(b, 0, n-1)], 0)
    E = (1 - h_a) * mask_a - h_b * mask_b
    E[:, n1] = 0  # Zero out the L=0 column
    
    return E
```

This is vectorized and should be fast. Let me verify the logic:
- For position p, output index k:
  - L = k - (n-1)
  - a = p - L = p - k + (n-1)
  - b = p + L = p + k - (n-1)
  - E[p,k] = (1-h[a]) if 0≤a<n else 0, minus h[b] if 0≤b<n else 0
  - If k = n-1 (L=0): a = p, b = p, so E[p,n-1] = (1-h[p]) - h[p] = 1-2h[p]
    But we set E[:, n-1] = 0.

For binary h with h[p]=0: E[p,n-1] would be 1, but we set it to 0. ✓
For binary h with h[p]=1: E[p,n-1] would be -1, but we set it to 0. ✓

Good. Now the swap effect:
If we swap i (0→1) and j (1→0), the approximate new correlation is:
corr_new ≈ corr + E[i] - E[j]

(Not exactly correct due to interaction, but good for candidate selection.)
