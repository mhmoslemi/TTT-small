    # sum(clip(y-lambda, 0, 1)) is decreasing in lambda
    # If lambda is very negative: sum ≈ sum(min(y, ...)) which is large

    # Actually clip(y-t, 0, 1) = 0 if y-t <= 0, = y-t if 0 < y-t < 1, = 1 if y-t >= 1

            break

        c = compute_all_overlaps(h)
        c_max = c.max()

        shifted = np.clip(shifted, -300, 300)
        p = np.exp(shifted)

        for m in range(n):
            h_plus = h.copy()
            h_plus[m] = min(1.0, h[m] + eps)
            c_plus = compute_all_overlaps(h_plus)

            h_minus[m] = max(0.0, h[m] - eps)

        # Backtracking line search
        best_h_trial = h.copy()
        best_f = c.max()  # approximate

Now let me think about the binary local search:

For a binary h, a swap of positions a (h=1) and b (h=0) changes the correlation. The change in c[k] for all k can be computed in O(n):

When h[a]: 1→0 and h[b]: 0→1:
- The "first index" contribution of a at shift k: was (1-h[partner_a(k)]) * 1, now 0. Change: -(1-h[partner_a(k)])
- The "first index" contribution of b at shift k: was 0, now (1-h[partner_b(k)]) * 1. Change: +(1-h[partner_b(k)])
- The "second index" contribution of a at shift k: (1-h[a]) was 0, now 1. So the term h[partner'_a(k)] * (1-h[a]) changes from 0 to h[partner'_a(k)]. Change: +h[partner'_a(k)]
- The "second index" contribution of b at shift k: (1-h[b]) was 1, now 0. So the term h[partner'_b(k)] * (1-h[b]) changes from h[partner'_b(k)] to 0. Change: -h[partner'_b(k)]

Where partner_a(k) is the index j such that h[a] and h[j] are paired at shift k (a as first index), and partner'_a(k) is the index i such that h[i] and h[a] are paired at shift k (a as second index).

For the full correlation c = convolve(h, (1-h)[::-1], 'full'):
c[k] = sum_i h[i] * (1-h)[n-1-k+i]

First index: h[i] appears at c[k] for k where n-1-k+i is valid (0 ≤ n-1-k+i ≤ n-1), i.e., i-n+1 ≤ k ≤ i.
So h[a] appears as first index at c[k] for k ∈ [a-n+1, a], i.e., max(0, a-n+1) ≤ k ≤ min(a, 2n-2).
The partner is h[n-1-k+a].

Second index: h[m] appears in (1-h) at c[k] for k where n-1-k+i = m for some valid i, i.e., i = m-n+1+k is valid (0 ≤ m-n+1+k ≤ n-1), i.e., n-1-m ≤ k ≤ n-1+m.
So h[a] appears as second index at c[k] for k ∈ [n-1-a, n-1+a].
The partner is h[a-n+1+k].

So for a swap (a: 1→0, b: 0→1):
Δc[k] for k in the union of relevant ranges:
- If max(0,a-n+1) ≤ k ≤ min(a, 2n-2): Δc[k] += -(1-h[n-1-k+a])  [a as first index]
- If max(0,b-n+1) ≤ k ≤ min(b, 2n-2): Δc[k] += +(1-h[n-1-k+b])  [b as first index]
- If n-1-a ≤ k ≤ n-1+a: Δc[k] += +h[a-n+1+k]  [a as second index]
- If n-1-b ≤ k ≤ n-1+b: Δc[k] += -h[b-n+1+k]  [b as second index]

Each of these is O(n) to compute (iterating over the relevant k values), and there are 4 terms, so total O(n) per swap.

Then the change in max_k c[k]*dx can be computed by updating c and checking the max. If we maintain c as a vector, updating it takes O(n) and checking the max takes O(n). So total O(n) per swap.

For n=270, O(n) = 270 operations per swap. We can do millions of swaps per second.
