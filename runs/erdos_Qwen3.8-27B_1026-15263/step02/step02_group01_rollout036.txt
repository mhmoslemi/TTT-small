Actually, I can speed this up by not doing the full project_to_sum (which iterates up to 500 times) but instead doing a single-step adjustment:

When I change h[i] from old_val to new_val, the sum changes by (new_val - old_val). To restore the sum, I need to adjust the other coordinates. The simplest is to add (old_val - new_val) / (n-1) to each other coordinate (if they're not at bounds). But this is approximate.

A better approach: after setting h[i] = v, compute the deficit = target_sum - sum(h). Then:
- If deficit > 0: add deficit to coordinates that are < 1, proportionally
- If deficit < 0: subtract |deficit| from coordinates that are > 0, proportionally

This is essentially one step of the projection, which is O(n).

1. Find the current maximum correlation index k*
2. Compute the gradient of f_{k*}(h) = corr[k*] · dx
3. Take a step in the negative gradient direction
4. Project to feasible set

This is simpler than the smooth max and might work well in practice. The issue is that the maximum can jump discontinuously, causing oscillations. But with a small enough step size, it should work.
