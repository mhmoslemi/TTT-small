def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode="full")
    return float(np.max(corr) * dx)

def project_to_sum(h, target_sum):
    h = np.clip(h.astype(float), 0.0, 1.0)
    for _ in range(2000):
        diff = target_sum - np.sum(h)
        if abs(diff) < 1e-13:
            break
        mask = (h > 1e-12) & (h < 1.0 - 1e-12)
        if np.any(mask):
            h[mask] += diff / np.sum(mask)
        else:
            h += diff / len(h)
        h = np.clip(h, 0.0, 1.0)
    return h

def make_binary(h, n, target_sum, rng):
    h_bin = (h > 0.5).astype(float)
    n_ones = int(np.sum(h_bin))
    if n_ones == target_sum:
        return h_bin
    if n_ones > target_sum:
        excess = n_ones - target_sum
        ones_idx = np.where(h_bin == 1.0)[0]
        order = np.argsort(h[ones_idx])[:excess]
        h_bin[ones_idx[order]] = 0.0
    else:
        deficit = target_sum - n_ones
        zeros_idx = np.where(h_bin == 0.0)[0]
        order = np.argsort(-h[zeros_idx])[:deficit]
        h_bin[zeros_idx[order]] = 1.0
    return h_bin

def smooth_max_and_grad(h, alpha):
    n = len(h)
    corr = np.correlate(h, 1.0 - h, mode="full")
    m_val = np.max(corr)
    shifted = np.clip(alpha * (corr - m_val), -500.0, 0.0)
    exp_vals = np.exp(shifted)
    w = exp_vals / np.sum(exp_vals)
    obj = m_val + np.log(np.sum(exp_vals)) / alpha
    j_idx = np.arange(n)[:, None]
    m_idx = np.arange(2 * n - 1)[None, :]
    first_idx = j_idx - m_idx + n - 1
    second_idx = j_idx + m_idx - n + 1
    valid_f = (first_idx >= 0) & (first_idx < n)
    valid_s = (second_idx >= 0) & (second_idx < n)
    fc = np.clip(first_idx, 0, n - 1)
    sc = np.clip(second_idx, 0, n - 1)
    cf = valid_f * (1.0 - h[fc]) * w[None, :]
    cs = valid_s * h[sc] * w[None, :]
    grad = np.sum(cf - cs, axis=1)
    return obj, grad

def slsqp_optimize(h0, n, target_sum, alpha, maxiter=800):
    def f(h):
        return smooth_max_and_grad(h, alpha)[0]
    def g(h):
        return smooth_max_and_grad(h, alpha)[1]
    cons = [{'type': 'eq', 'fun': lambda x: np.sum(x) - target_sum,
             'jac': lambda x: np.ones(n)}]
    bounds = [(0.0, 1.0)] * n
    try:
        res = minimize(f, h0.copy(), method='SLSQP', jac=g,
                       bounds=bounds, constraints=cons,
                       options={'maxiter': maxiter, 'ftol': 1e-15})
        return project_to_sum(res.x, target_sum)
    except Exception:
        return project_to_sum(h0.copy(), target_sum)

Now, let me think about the overall strategy more carefully. The key question is: what's the theoretical best for n=240?

For a binary sequence of length 240 with 120 ones:
- The maximum possible value of min_k |A ∩ (A-k)| (in the periodic sense) is related to the autocorrelation properties
- For a "random" set of 120 positions in {0,...,239}, the expected autocorrelation at lag k is 120*120/240 = 60
- We want this to be at least 75 (to get max count ≤ 45)
- That's a 25% improvement over random, which is achievable with structured sequences

One approach: use a **quadratic residue** construction or a **cyclic difference set**.

A (v, k, λ) difference set in Z_v has the property that every nonzero element is represented exactly λ times as a difference of two elements. The autocorrelation is then k - λ for all nonzero lags.

For v=240, k=120: we'd need a (240, 120, λ) difference set where λ = 120 - 75 = 45.
Check: k(k-1) = λ(v-1) → 120*119 = 45*239 → 14280 = 10755. Not equal!

So a perfect difference set doesn't exist for these parameters. But we might be able to get close.

The condition for a (v,k,λ) difference set is k(k-1) = λ(v-1).
For v=240, k=120: λ = 120*119/239 ≈ 59.75. Not an integer!

So we can't have a perfect difference set. The best we can do is have the autocorrelation vary between 59 and 60 for most lags (in the periodic case).

But wait, we're not in the periodic case! The "full" correlation doesn't wrap around. So the boundary effects matter.

For the non-periodic case, at lag k (forward), we have:
count(k) = |{i ∈ A : i+k < n, i+k ∉ A}|

This is different from the periodic autocorrelation. The non-periodic count at lag k can be smaller than the periodic count because we're not counting wrap-around pairs.

Actually, for the non-periodic case:
count_forward(k) = |A| - |{i ∈ A : i+k < n}| + |{i ∈ A : i+k < n, i+k ∈ A}|
= |A| - |{i ∈ A : i < n-k}| + |{i ∈ A ∩ (A-k) : i < n-k}|

**Iterated Local Search (ILS):**
1. h = initial solution
2. h = local_search(h)  [until local optimum]
3. h' = perturb(h, strength)  [random perturbation]
4. if h' is better than best, accept
5. h = h' (or best, depending on strategy)
6. Go to 2

The perturbation strength increases when stuck.
