Term 1: i+k = j, so i = j-k. Valid if max(0,-k) ≤ j-k ≤ min(n-1, n-1-k).
  Contribution: h[j] * (1-h[j-k])
  As function of x=h[j]: x * (1-h[j-k])

Term 2: i = j. Valid if max(0,-k) ≤ j ≤ min(n-1, n-1-k).
  Contribution: h[j+k] * (1-h[j])
  As function of x=h[j]: h[j+k] * (1-x) = h[j+k] - h[j+k]*x

So total dependence on x:
x*(1-h[j-k]) + h[j+k] - h[j+k]*x  [when both terms are present]
= x*(1 - h[j-k] - h[j+k]) + h[j+k]

If only Term 1 is present: x*(1-h[j-k])
If only Term 2 is present: h[j+k] - h[j+k]*x
If neither: 0

So a_k (coefficient of x) and b_k (constant term) for each lag k:
- If both valid: a_k = 1 - h[j-k] - h[j+k], b_k = h[j+k]
- If only Term 1: a_k = 1 - h[j-k], b_k = 0
- If only Term 2: a_k = -h[j+k], b_k = h[j+k]
- If neither: a_k = 0, b_k = 0

And the full correlation is: result[k+n-1] = a_k * x + b_k + c_k
where c_k is the sum of all terms not involving h[j].

For the 1D problem: minimize max_m (a_m * x + b_m + c_m) over x ∈ [0,1].

This is a 1D min-max of linear functions. The optimal x is:
- At a vertex of the upper envelope of {a_m * x + b_m + c_m} on [0,1]
- Or at x=0 or x=1

To find this efficiently:
1. Compute f(0) = max_m (b_m + c_m) and f(1) = max_m (a_m + b_m + c_m)
2. The lines active at x=0 and x=1 are the candidates
3. Check if any other line is above both at some interior point

A simple but effective approach:
1. Find k0 = argmax_m (b_m + c_m) [active at x=0]
2. Find k1 = argmax_m (a_m + b_m + c_m) [active at x=1]
3. If k0 == k1: optimal x is 0 if a_k0 ≥ 0, 1 if a_k0 ≤ 0
4. Else: crossing point x* = (b_k0 + c_k0 - b_k1 - c_k1) / (a_k1 - a_k0)
   - If x* ∈ [0,1]: check if f(x*) ≤ f(0) and f(x*) ≤ f(1). If yes, x* is optimal.
   - Otherwise, check other candidate lines.

For a more robust approach, we can collect the top ~10 candidate lines and solve the min-max over just those.

This coordinate descent approach should be much more targeted than gradient-based methods, since it finds the exact optimal value for each coordinate given the others.

        Value at t*: max(a1*t* + r1, a2*t* + r2)
      
   b. Check if any m ∉ S has a[m]*t* + result[m] > value at t*
      If yes, add that m to S and go to step a.
      If no, done.

This is correct and terminates in at most n iterations (but usually 2-3).

For the 2-line solve:
- If |S| = 1: t* = L if a[S[0]] ≥ 0, else R (or anything if a=0)
  Actually: if a > 0, function is increasing, min at L. If a < 0, decreasing, min at R.
- If |S| = 2: 
  Let m1, m2 be the two lines with a1 < a2 (WLOG).
  If a1 == a2: min at L (if a1 ≥ 0) or R (if a1 < 0)
  Else: t_cross = (result[m2] - result[m1]) / (a1 - a2)
    Since a1 < a2, a1 - a2 < 0, and result[m2] - result[m1] can be anything.
    Line 1 is above line 2 when: a1*t + r1 > a2*t + r2 => (a1-a2)*t > r2-r1 => t < (r2-r1)/(a1-a2) = t_cross
    (since a1-a2 < 0, the inequality flips)
    So for t < t_cross: line 1 is above. For t > t_cross: line 2 is above.
    The max is: line 1 for t < t_cross, line 2 for t > t_cross.
    The minimum of this max on [L, R] is at t = clamp(t_cross, L, R).

Great, this is efficient.

Now, for the overall algorithm, let me think about time budget:
- n = 480 (or we could try 512)
- Each coordinate update: O(n) to compute a[m], O(1) to solve (amortized, since the active set is small)
- Each sweep: O(n²) total
- With n = 480: ~230K operations per sweep
- In 1300 seconds, we can do millions of sweeps (Python is slower, but still)

Actually in Python, each "operation" involves array indexing which is slower. Let's estimate:
- Computing a[m]: O(n) with numpy vectorized ops → ~50μs
- Solving 1D: O(1) to O(few) → ~10μs
- Total per coordinate: ~100μs
- Per sweep (480 coords): ~50ms
- In 1300s: ~26,000 sweeps

That's more than enough! We can also afford to try multiple resolutions and multiple starting points.
