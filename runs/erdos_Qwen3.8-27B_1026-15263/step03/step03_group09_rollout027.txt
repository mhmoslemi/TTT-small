    n = len(h)
    corr = np.correlate(h, 1.0 - h, mode='full')
    m = np.max(corr)
    shifted = alpha * (corr - m)

The C₅ value for a fixed continuous function h is:
C₅ = max_k ∫₀² h(x)(1-h(x+k)) dx

When we discretize with n points, we approximate this integral. With more points, the approximation is better, but the "search space" is also larger (more degrees of freedom).

The question is: can the optimal discrete solution with n points achieve a lower C₅ than the optimal with fewer points? In general, yes (more points = more flexibility). But the improvement might be marginal.

However, there's a subtlety: the "effective" C₅ for the discrete solution depends on n. The evaluator computes:
C₅ = max(np.correlate(h, 1-h, mode='full') * dx)

where dx = 2/n. So for a fixed h (continuous function), as n increases, the discrete approximation of C₅ converges to the true C₅.

But for optimization, having more points gives us more flexibility to design h. The question is whether the optimal h for n=720 has a lower C₅ than the optimal h for n=360 (measured in the same way).

I believe the answer is yes, but the improvement might be small (since n=360 already gives a decent approximation).

Actually, I realize I should also try a completely different approach: **use the fact that the problem is equivalent to a max-min game** and use **mirror descent** or **online gradient descent** in the space of distributions over lags.

The idea:
- Maintain a distribution q over lags
- Update h to minimize Σ_k q(k) * R(h, k) (a convex combination, which is still non-convex in h but weighted)
- Update q to put more weight on lags with high R(h, k)

This is similar to the "multiplicative weights" approach for zero-sum games.

For the h-update: minimize Σ_k q(k) R(h, k) subject to 0 ≤ h ≤ 1, sum(h) = n/2.
The gradient is: Σ_k q(k) ∂R(h,k)/∂h[i] = Σ_k q(k) [(1-h[i-k]) - h[i+k]] (with bounds)

For the q-update: q_new(k) ∝ q(k) * exp(η * R(h, k)) (or similar)

This is essentially a **Frank-Wolfe** or **mirror descent** approach for the inner problem.

Let me implement a simplified version:

```python
def multiplicative_weights(h0, n, target_sum, n_iters, lr, initial_alpha):
    h = h0.copy()
    # Initialize q uniformly over lags
    n_lags = 2 * n - 1
    q = np.ones(n_lags) / n_lags
    
    best_c5 = compute_c5(h)
    best_h = h.copy()
    
    for it in range(n_iters):
        # Compute overlaps for all lags
        corr = np.correlate(h, 1.0 - h, mode='full')
        overlaps = corr  # These are the "unnormalized" overlaps (before multiplying by dx)
        
        # Update q: multiplicative weights
        eta = lr / (1.0 + 0.1 * it)
        shifted = eta * (overlaps - np.max(overlaps))
        q = np.exp(shifted)
        q /= q.sum()
        
        # Compute gradient of weighted sum
        # grad[i] = sum_k q[k] * [(1-h[i-k]) - h[i+k]] (with bounds)
        # This is: q * (1-h) - q_flipped * h (using the same trick as before)
        w = q  # This plays the role of w in the previous derivation
        term1 = np.correlate(w, 1.0 - h, mode='full')[0:n]
        term2 = np.correlate(w, h, mode='full')[n-1:2*n-1][::-1]
        grad = term1 - term2
        
        # Update h
        step = lr / (1.0 + 0.05 * it)
        h_new = h - step * grad
        h_new = np.clip(h_new, 0.0, 1.0)
        h_new = project_to_sum(h_new, target_sum)
        
        c5_new = compute_c5(h_new)
        if c5_new < best_c5:
            best_c5 = c5_new
            best_h = h_new.copy()
        h = h_new
    
    return best_h, best_c5
```

This is a nice approach because:
1. It automatically focuses on the "worst" lags (multiplicative weights).
2. The gradient computation is efficient (O(n²) with np.correlate).
3. It's simple to implement and tune.
