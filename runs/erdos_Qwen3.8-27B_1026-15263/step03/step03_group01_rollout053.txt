**Key idea: The max is non-smooth. At the optimum, multiple shifts are tied. The gradient of the max is the average of the gradients of the active shifts. But between optimization steps, the set of active shifts changes. This non-smoothness can cause oscillation.**

**Solution: Use a "hub-and-spoke" approach.**
1. Identify the active shifts (those near the max)
2. For the current active set, optimize exactly (SLSQP)
3. Re-evaluate the full max
4. If new shifts have become active, add them and re-optimize
5. If some shifts are no longer close to the max, drop them
6. This is essentially the "active set" method for min-max problems

def coord_descent(h, ts, n_iter, rng, alpha):
    n = len(h)
    h = h.copy()
    c5_cur = compute_c5(h)
    lr = 0.05
    for it in range(n_iter):
        grad = smooth_grad(h, alpha, top_m=5)
        # Find best coordinate to change
        # Positive gradient → decrease h[i]; Negative gradient → increase h[i]
        pos = np.argmax(grad)  # most positive gradient, decrease this
        neg = np.argmin(grad)  # most negative gradient, increase this
        if grad[pos] < 1e-10 and -grad[neg] < 1e-10:
            break
        # Try moving mass from pos to neg
        delta = min(lr, h[pos] * 0.5, (1.0 - h[neg]) * 0.5)
        if delta < 1e-10:
            break
        h[pos] -= delta
        h[neg] += delta
        h = np.clip(h, 0, 1)
        h = project_to_sum(h, ts)
        c5_new = compute_c5(h)
        if c5_new < c5_cur:
            c5_cur = c5_new
            lr = min(lr * 1.1, 0.3)
        else:
            h[pos] += delta
            h[neg] -= delta
            h = np.clip(h, 0, 1)
            h = project_to_sum(h, ts)
            lr *= 0.7
            if lr < 1e-8:
                break
    return h, c5_cur
