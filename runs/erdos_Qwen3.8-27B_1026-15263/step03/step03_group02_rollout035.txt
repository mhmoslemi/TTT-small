```python
    obj = m_val + np.log(np.sum(exp_vals)) / alpha
    
    # s_k = n-1-k for k = 0, ..., 2n-2
    # So s ranges from n-1, n-2, ..., -(n-2)
    s = (n - 1) - np.arange(2 * n - 1)  # shape (2n-1,)
    
    # For each j (0 to n-1) and each k (0 to 2n-2):
    # d corr[k]/d h[j] = (1-h[j-s_k])*[0≤j-s_k<n] - h[j+s_k]*[0≤j+s_k<n]
    
    j = np.arange(n)[:, None]  # (n, 1)
    s_row = s[None, :]  # (1, 2n-1)
    
    idx1 = j - s_row  # j - s_k: first term index
    idx2 = j + s_row  # j + s_k: second term index
    
    valid1 = (idx1 >= 0) & (idx1 < n)
    valid2 = (idx2 >= 0) & (idx2 < n)
    
    idx1c = np.clip(idx1, 0, n-1)
    idx2c = np.clip(idx2, 0, n-1)
    
    term1 = valid1 * (1.0 - h[idx1c])  # (1-h[j-s_k])
    term2 = valid2 * h[idx2c]  # h[j+s_k]
    
    dcorr = term1 - term2  # (n, 2n-1)
    grad = np.sum(w[None, :] * dcorr, axis=1)
    
    return obj, grad
```

Let me also think about whether L-BFGS-B is appropriate. The issue is that we have box constraints (0≤h≤1) and an equality constraint (sum h = n/2). L-BFGS-B handles box constraints natively but not equality constraints.

Options:
1. Use L-BFGS-B with a penalty for the equality constraint (add (sum(h) - n/2)² * lambda to the objective)
2. Parameterize to eliminate the equality constraint (e.g., use n-1 free variables and set the last one to make the sum work)
3. Use SLSQP with the correct gradient (slower but handles both constraint types)

I'll go with option 1 (penalty) combined with projection after each step. Actually, for L-BFGS-B, the standard approach is to just use bounds and accept that the sum constraint is handled approximately. Then project at the end.

Actually, a better approach: use the fact that if we parameterize h as h[i] = t[i] for i=0 to n-2, and h[n-1] = n/2 - sum(t[0:n-1]), then we reduce the dimension by 1 and eliminate the equality constraint. But this makes the box constraints on h[n-1] implicit and potentially violated.

Alternatively, I can just use SLSQP with the corrected gradient. SLSQP is slower per iteration but handles both constraint types. With the correct gradient, it should converge to a better solution.

Or I can use a projected gradient method:
1. Compute gradient of smooth max
2. Take a step in the negative gradient direction
3. Project onto the feasible set {0≤h≤1, sum(h)=n/2}

The projection onto {0≤h≤1, sum(h)=n/2} can be done in O(n) time using a bisection on a threshold.

Let me implement the projection:
```python
def project_feasible(h, target_sum):
    """Project h onto {0≤x≤1, sum(x)=target_sum}."""
    n = len(h)
    # First clip to [0,1]
    h = np.clip(h, 0, 1)
    # Now adjust to meet the sum constraint
    # We need to find t such that sum(clamp(h + t, 0, 1)) = target_sum
    # This is a monotone function of t, so bisection works
    for _ in range(100):
        s = np.sum(h)
        if abs(s - target_sum) < 1e-12:
            break
        h = np.clip(h + (target_sum - s) / n, 0, 1)
    return h
```

Actually, a more efficient projection is:
```python
def project_feasible(h, target_sum):
    n = len(h)
    # Find threshold t such that sum(min(max(h+t, 0), 1)) = target_sum
    # Sort h and find the right threshold
    h_sorted = np.sort(h)
    # The optimal projection is: x[i] = clip(h[i] - t, 0, 1)
    # where t is chosen so that sum(x) = target_sum
    # This is the Euclidean projection onto the intersection of the box and the hyperplane
    lo, hi = h.min() - target_sum, h.max()
    for _ in range(100):
        t = (lo + hi) / 2
        x = np.clip(h - t, 0, 1)
        if np.sum(x) > target_sum:
            lo = t
        else:
            hi = t
    return np.clip(h - (lo+hi)/2, 0, 1)
```
