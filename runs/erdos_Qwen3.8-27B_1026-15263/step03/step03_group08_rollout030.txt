If we fix all h except one, say h[j], then:
corr[k] = A_k + h[j] * B_k (for appropriate k)

where A_k and B_k are determined by the other variables. So for a fixed k, corr[k] is linear in h[j]. This means coordinate descent is exact in each coordinate!

Let me exploit this: for coordinate i, the change in corr[k] when we change h[i] by δ is:
Δcorr[k] = δ * (contribution of h[i] to corr[k])

For a given lag k (= l + (n-1) in the full correlation array):
- h[i] appears in the term h[i] (as the first factor) when i - l is valid, contributing (1 - h[i-l])
- h[i] appears in the term (1-h[i]) (as second factor) when i + l is valid, contributing -h[i+l]

Wait, let me be more careful. The full correlation c[m] = ∑_i a[i+m'] * v[i] where a = h, v = 1-h, and m' = m - (n-1).

c[m] = ∑_i h[i + m - (n-1)] * (1 - h[i]) for valid i

For a given index j, h[j] appears in:
- As the first factor: h[j] = h[i + m - (n-1)] → i = j - m + (n-1) = j - l where l = m - (n-1)
  Contribution: 1 * (1 - h[i]) = 1 - h[j - l]
- As the second factor: (1 - h[j]) → i = j
  Contribution: h[i + l] * (-1) = -h[j + l]

So ∂c[m]/∂h[j] = (1 - h[j-l]) - h[j+l] (when both indices are valid)

This confirms that the gradient is as computed in smooth_max_val_grad.

For coordinate descent: if we change h[j] to h[j] + δ, the change in c[m] is:
Δc[m] = δ * ((1 - h[j-l]) - h[j+l])

This is linear in δ! So we can find the optimal δ analytically for a single coordinate.

But we need to minimize max_m c[m], not a single c[m]. So we need:
minimize max_m (c[m] + δ * g_m[j])

where g_m[j] = (1 - h[j-l_m]) - h[j+l_m] is the partial derivative of c[m] with respect to h[j].

This is a 1D minimax problem: find δ that minimizes max_m (a_m + δ * b_m) where a_m = c[m] and b_m = g_m[j].

The solution is: find δ that minimizes the maximum of (a_m + δ * b_m) over m. This can be solved by binary search or by finding the intersection point.

This is actually a very effective coordinate descent! Let me implement it:

```python
def exact_coord_descent(h, n, target_sum, max_rounds):
    h = h.copy()
    c5_cur = compute_c5(h)
    corr = np.correlate(h, 1.0 - h, mode='full')
    
    for rnd in range(max_rounds):
        improved = False
        for j in range(n):
            # Compute gradient of each corr[m] with respect to h[j]
            # corr[m] = sum_i h[i+l]*(1-h[i]) where l = m-(n-1)
            # d(corr[m])/d(h[j]) = (1-h[j-l]) for l = m-(n-1) if j-l valid, 
            #                      - h[j+l] for l = m-(n-1) if j+l valid
            
            # Instead of computing all gradients, we can compute directly:
            # New corr if h[j] changes by delta
            # corr[m] new = corr[m] + delta * grad_m_j
            # where grad_m_j = (1 if j-l is in [0,n) else 0) * (1-h[j-l]) 
            #                  - (1 if j+l is in [0,n) else 0) * h[j+l]
            
            # But we want to minimize max(corr + delta * grad)
            # Let's compute the gradient vector for this coordinate
            grad_j = np.zeros(2*n - 1)
            for l in range(-(n-1), n):
                # h[j] as first factor: h[j] = h[i+l] where i = j-l
                if 0 <= j - l < n:
                    grad_j[l + n - 1] += (1.0 - h[j - l])
                # h[j] as second factor: (1-h[j]) where i = j
                if 0 <= j + l < n:
                    grad_j[l + n - 1] -= h[j + l]
            
            # Now find delta that minimizes max(corr + delta * grad_j)
            # subject to 0 <= h[j] + delta <= 1 and sum constraint
            
            # For the minimax: we want to find delta that minimizes
            # max_m (corr[m] + delta * grad_j[m])
            # This is minimized when the top values are equalized.
            
            # Simple approach: try a few candidate delta values
            # The optimal delta makes the top corr values as equal as possible
            
            current_max = np.max(corr)
            # Sort by current corr value (descending)
            # The "active" lags are those near the max
            
            # Try deltas that reduce the maximum
            best_delta = 0.0
            best_max = current_max
            
            # The maximum after change is max_m(corr[m] + delta * grad_j[m])
            # For small delta, the maximum is at the lag with the highest corr[m]
            # and the highest grad_j[m] (most positive gradient at the max lag)
            
            # To reduce the max, we want delta such that the lag(s) with max corr
            # have negative grad_j (so increasing delta reduces them)
            
            # Let's try a binary search approach:
            # f(delta) = max_m(corr[m] + delta * grad_j[m])
            # We want to minimize f(delta) over delta in [-h[j], 1-h[j]]
            
            lo_d = -h[j]
            hi_d = 1.0 - h[j]
            
            # f is piecewise linear and convex (max of linear functions)
            # So we can find the minimum by ternary search or by finding
            # where the active set changes
            
            # Simplified: try several delta values
            deltas = np.linspace(lo_d, hi_d, 21)
            for d in deltas:
                new_corr = corr + d * grad_j
                new_max = np.max(new_corr)
                if new_max < best_max:
                    best_max = new_max
                    best_delta = d
            
            # Refine with finer search around best_delta
            if best_delta != 0:
                fine_deltas = np.linspace(best_delta - abs(best_delta)*0.1 - 0.01, 
                                          best_delta + abs(best_delta)*0.1 + 0.01, 21)
                fine_deltas = np.clip(fine_deltas, lo_d, hi_d)
                for d in fine_deltas:
                    new_corr = corr + d * grad_j
                    new_max = np.max(new_corr)
                    if new_max < best_max:
                        best_max = new_max
                        best_delta = d
            
            if abs(best_delta) > 1e-10:
                h[j] += best_delta
                h[j] = np.clip(h[j], 0.0, 1.0)
                # Re-project to maintain sum
                h = project_to_sum(h, target_sum)
                corr = np.correlate(h, 1.0 - h, mode='full')
                c5_new = np.max(corr) * (2.0 / n)
                if c5_new < c5_cur - 1e-14:
                    c5_cur = c5_new
                    improved = True
        
        if not improved:
            break
    
    return h, c5_cur
```

Wait, this exact coordinate descent has a problem: after changing h[j], the sum changes, so we need to re-project. The re-projection changes all other coordinates, which invalidates our gradient computation. 

One solution: instead of projecting after each coordinate change, we can use a "lazy projection" approach where we only project every K steps. Or we can incorporate the sum constraint into the optimization.

Actually, the sum constraint is ∑h[i] = n/2. If we change h[j] by δ, the sum changes by δ. To maintain the sum, we need to distribute -δ across the other n-1 coordinates. The simplest way is to add -δ/(n-1) to each other coordinate. But this might push some coordinates out of [0,1].

A better approach: use a "water-filling" projection. After changing h[j], project the entire vector back to the constraining polytope {0≤h≤1, ∑h=n/2}. This is what project_to_sum does.

But the issue is that project_to_sum changes all coordinates, not just h[j]. So the "exact" computation of the new corr is not just corr + delta * grad_j.

For practical purposes, I'll just use the approximate approach: compute the new corr after the projection and accept if it improves.

Let me simplify the coordinate descent:

```python
def coord_descent_v2(h, n, target_sum, max_rounds):
    h = h.copy()
    c5_cur = compute_c5(h)
    
    for rnd in range(max_rounds):
        improved = False
        for j in range(n):
            # Try several step sizes
            best_c5 = c5_cur
            h_best = h.copy()
            
            for step in [0.02, 0.01, 0.005, -0.02, -0.01, -0.005]:
                h_new = h.copy()
                h_new[j] = np.clip(h_new[j] + step, 0.0, 1.0)
                h_new = project_to_sum(h_new, target_sum)
                c5_new = compute_c5(h_new)
                if c5_new < best_c5:
                    best_c5 = c5_new
                    h_best = h_new
            
            if best_c5 < c5_cur - 1e-15:
                h = h_best
                c5_cur = best_c5
                improved = True
        
        if not improved:
            break
    
    return h, c5_cur
```

This is simpler but each step requires a full correlation computation (O(n²)). For n=480, that's about 230K ops × 6 steps × 480 coordinates × rounds = a lot. Let me estimate: 230K × 6 × 480 = ~660M ops per round. At ~100M ops/sec in Python (conservative), that's ~7 seconds per round. With 30 rounds, that's 210 seconds. That's too much.

I need to be smarter. Let me only try coordinates that are likely to help. I can identify "hot" coordinates by looking at which coordinates have the largest gradient magnitude for the active lags.

Or, I can reduce the number of steps tried (e.g., only 3 steps: +0.01, -0.01, 0) and only iterate over a subset of coordinates per round.

Actually, for the final polishing, I think the simplest approach is:
1. Use SLSQP with very high alpha (this handles the optimization well)
2. Only use a few rounds of coordinate descent at the very end with very fine steps

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(corr) * dx)

def project_to_sum(h, target_sum):
    h = np.clip(h.astype(float).copy(), 0.0, 1.0)
    for _ in range(500):
        diff = target_sum - np.sum(h)

            break

            h[mask] += diff / np.sum(mask)
        else:
            h += diff / len(h)
        h = np.clip(h, 0.0, 1.0)
