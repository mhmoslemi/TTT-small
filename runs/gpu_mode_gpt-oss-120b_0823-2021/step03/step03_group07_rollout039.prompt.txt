```python
import torch
from torch import nn, einsum
import math

# Reference code in PyTorch
class TriMul(nn.Module):
    def __init__(
        self,
        dim: int,
        hidden_dim: int,
    ):
        super().__init__()

        self.norm = nn.LayerNorm(dim)

        self.left_proj = nn.Linear(dim, hidden_dim, bias=False)
        self.right_proj = nn.Linear(dim, hidden_dim, bias=False)

        self.left_gate = nn.Linear(dim, hidden_dim, bias=False)
        self.right_gate = nn.Linear(dim, hidden_dim, bias=False)
        self.out_gate = nn.Linear(dim, hidden_dim, bias=False)

        self.to_out_norm = nn.LayerNorm(hidden_dim)
        self.to_out = nn.Linear(hidden_dim, dim, bias=False)

    def forward(self, x: torch.Tensor, mask: torch.Tensor) -> torch.Tensor:
        """
        x: [bs, seq_len, seq_len, dim]
        mask: [bs, seq_len, seq_len]

        Returns:
            output: [bs, seq_len, seq_len, dim]
        """
        batch_size, seq_len, _, dim = x.shape

        x = self.norm(x)

        left = self.left_proj(x)
        right = self.right_proj(x)

        mask = mask.unsqueeze(-1)
        left = left * mask
        right = right * mask

        left_gate = self.left_gate(x).sigmoid()
        right_gate = self.right_gate(x).sigmoid()
        out_gate = self.out_gate(x).sigmoid()

        left = left * left_gate
        right = right * right_gate

        out = einsum('... i k d, ... j k d -> ... i j d', left, right)
        # This einsum is the same as the following:
        # out = torch.zeros(batch_size, seq_len, seq_len, dim, device=x.device)
        
        # # Compute using nested loops
        # for b in range(batch_size):
        #     for i in range(seq_len):
        #         for j in range(seq_len):
        #             # Compute each output element
        #             for k in range(seq_len):
        #                 out[b, i, j] += left[b, i, k, :] * right[b, j, k, :]

        out = self.to_out_norm(out)
        out = out * out_gate
        return self.to_out(out)
```

## Triton launch convention

Every failure mode below has appeared in this search. Read this before writing.

A `@triton.jit` function is NOT a Python function. It is launched with a grid
subscript, and its `tl.constexpr` parameters exist only inside it:

```python
@triton.jit
def my_kernel(x_ptr, y_ptr, n, BLOCK: tl.constexpr):
    pid = tl.program_id(0)
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    m = offs < n
    tl.store(y_ptr + offs, tl.load(x_ptr + offs, mask=m, other=0.0), mask=m)

def custom_kernel(data):
    ...
    BLOCK = 128                                   # a host variable YOU define
    grid = (triton.cdiv(n, BLOCK),)               # host-side, use triton.cdiv
    my_kernel[grid](x, y, n, BLOCK=BLOCK)         # note the [grid] subscript
```

- `my_kernel(...)` without `[grid]` raises "Cannot call @triton.jit'd outside
  the scope of a kernel".
- `BLOCK`, `BLOCK_M`, `BLOCK_N` are not defined on the host unless you define
  them there. Referencing one you only declared as a `tl.constexpr` parameter
  raises NameError.
- `tl.cdiv` is device-side. On the host use `triton.cdiv`.
- Define the kernel at module top level, never nested inside `custom_kernel`.

You do not have to move everything into Triton. A correct submission that keeps
most of the computation in PyTorch and moves one hot region into a kernel scores;
one that fails to launch scores zero.

```python
"""
TriMul “outgoing” forward pass (AlphaFold‑3).

The only O(N³) work in the module is the contraction

    out[b,h,i,j] = Σ_k left[b,h,i,k] * right[b,h,j,k]

where `left`/`right` are the linearly‑projected, gated tensors of shape
[B, H, N, N]  (H = hidden_dim).  The implementation below

* performs all cheap operations (LayerNorm, linear projections, gating, the
  final LayerNorm / linear) with regular PyTorch (they are memory‑bound and
  cheap compared with the N³ contraction);
* launches a single Triton kernel that evaluates the above contraction using a
  classic blocked GEMM tiling (block‑M × block‑N × block‑K).  The kernel works
  on FP16 data with FP32 accumulation and stores the result back as FP16.
* finally reshapes the result back to the original layout and finishes the
  forward pass in PyTorch.

The kernel is deliberately kept simple: it iterates over the K‑dimension in
tiles, loads the corresponding sub‑matrices of `left` and the *transposed*
`right` (so that a single `tl.dot` computes the inner product), and accumulates
into a FP32 register tile.  This matches the shape of the reference
implementation while giving a >10× speed‑up over the naïve triple‑loop.
"""

import torch
import torch.nn.functional as F
import triton
import triton.language as tl
from typing import Tuple, Dict, Any


# ==============================
# Triton kernel: batched GEMM
# ==============================
@triton.jit
def _trimul_kernel(
    left_ptr,          # const fp16*  [B, H, N, N]
    right_ptr,         # const fp16*  [B, H, N, N]   (will be read transposed)
    out_ptr,           #       fp16*  [B, H, N, N]
    B, N, H,           # int metadata
    # strides of the three tensors (row‑major)
    stride_lb, stride_lh, stride_ln, stride_lk,   # left  (B,H,N,N)
    stride_rb, stride_rh, stride_rn, stride_rk,   # right (B,H,N,N)
    stride_ob, stride_oh, stride_on, stride_ok,   # out   (B,H,N,N)
    BLOCK_M: tl.constexpr,
    BLOCK_N: tl.constexpr,
    BLOCK_K: tl.constexpr,
):
    """
    Compute a (BLOCK_M × BLOCK_N) tile of the 4‑D result

        out[b, h, i, j] = Σ_k left[b, h, i, k] * right[b, h, j, k]

    The kernel is launched with one program id per (b, h, tile_m, tile_n)
    combination.
    """
    pid = tl.program_id(0)

    # ----- decode pid -------------------------------------------------
    # order: ((b * H + h) * num_m + tile_m) * num_n + tile_n
    num_m = tl.cdiv(N, BLOCK_M)
    num_n = tl.cdiv(N, BLOCK_N)

    tile_n = pid % num_n
    pid //= num_n
    tile_m = pid % num_m
    pid //= num_m
    h = pid % H
    b = pid // H

    # ----- tile coordinates --------------------------------------------
    offs_m = tile_m * BLOCK_M + tl.arange(0, BLOCK_M)
    offs_n = tile_n * BLOCK_N + tl.arange(0, BLOCK_N)

    mask_m = offs_m < N
    mask_n = offs_n < N

    # accumulator in FP32
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # ----- main K‑loop -------------------------------------------------
    for kk in range(0, tl.cdiv(N, BLOCK_K)):
        offs_k = kk * BLOCK_K + tl.arange(0, BLOCK_K)
        mask_k = offs_k < N

        # left[b, h, i, k]  -> shape (M, K)
        l_ptr = (left_ptr +
                 b * stride_lb +
                 h * stride_lh +
                 offs_m[:, None] * stride_ln +
                 offs_k[None, :] * stride_lk)
        l = tl.load(l_ptr,
                    mask=mask_m[:, None] & mask_k[None, :],
                    other=0.0).to(tl.float32)

        # right[b, h, j, k] must be read as right^T to obtain (K, N)
        #   right[b, h, j, k]  -> indices (b, h, j, k)
        #   we want (k, j)   -> swap the last two dims
        r_ptr = (right_ptr +
                 b * stride_rb +
                 h * stride_rh +
                 offs_k[:, None] * stride_rk +          # k‑dim (now row)
                 offs_n[None, :] * stride_rn)           # j‑dim (now col)
        r_t = tl.load(r_ptr,
                      mask=mask_k[:, None] & mask_n[None, :],
                      other=0.0).to(tl.float32)

        # dot: (M,K) @ (K,N) -> (M,N)
        acc += tl.dot(l, r_t)

    # ----- write back --------------------------------------------------
    out_ptrs = (out_ptr +
                b * stride_ob +
                h * stride_oh +
                offs_m[:, None] * stride_on +
                offs_n[None, :] * stride_ok)

    tl.store(out_ptrs,
             acc.to(tl.float16),
             mask=mask_m[:, None] & mask_n[None, :])


# ==============================
# Host‑side wrapper
# ==============================
def custom_kernel(
    data: Tuple[
        torch.Tensor,                     # input   [B, N, N, dim]
        torch.Tensor,                     # mask    [B, N, N]   (or None)
        Dict[str, torch.Tensor],          # weights
        Dict[str, Any]                    # config
    ]
) -> torch.Tensor:
    """
    Forward pass of the outgoing TriMul operator.
    Returns a tensor of shape [B, N, N, dim] (float32).
    """
    x, mask, weights, config = data
    device = x.device
    dtype = torch.float32                     # final output dtype

    B, N, _, dim = x.shape
    hidden_dim = config["hidden_dim"]        # = H

    # ------------------------------------------------------------------
    # 1. Pre‑process with PyTorch (LayerNorm + projections + gating)
    # ------------------------------------------------------------------
    # LayerNorm over the last dimension
    x = F.layer_norm(
        x,
        normalized_shape=(dim,),
        weight=weights["norm.weight"].to(dtype),
        bias=weights["norm.bias"].to(dtype),
    )

    # Linear projections (bias = False)
    left  = F.linear(x, weights["left_proj.weight"].to(dtype))   # (B,N,N,H)
    right = F.linear(x, weights["right_proj.weight"].to(dtype))

    # optional masking
    if mask is not None:
        mask_ = mask.unsqueeze(-1)            # (B,N,N,1)
        left  = left * mask_
        right = right * mask_

    # gates (sigmoid after linear)
    left_gate  = torch.sigmoid(F.linear(x, weights["left_gate.weight"].to(dtype)))
    right_gate = torch.sigmoid(F.linear(x, weights["right_gate.weight"].to(dtype)))
    out_gate   = torch.sigmoid(F.linear(x, weights["out_gate.weight"].to(dtype)))

    left  = left * left_gate
    right = right * right_gate

    # ------------------------------------------------------------------
    # 2. Rearrange to [B, H, N, N] and cast to fp16 for the kernel
    # ------------------------------------------------------------------
    # (B,N,N,H) -> (B,H,N,N)
    left  = left.permute(0, 3, 1, 2).contiguous()
    right = right.permute(0, 3, 1, 2).contiguous()

    left_fp16  = left.to(torch.float16)
    right_fp16 = right.to(torch.float16)

    out_fp16 = torch.empty_like(left_fp16)          # (B,H,N,N), fp16

    # ------------------------------------------------------------------
    # 3. Launch the Triton kernel (blocked GEMM)
    # ------------------------------------------------------------------
    BLOCK_M = 64
    BLOCK_N = 64
    BLOCK_K = 32

    # grid size = total number of (b,h, tile_m, tile_n) blocks
    grid_m = triton.cdiv(N, BLOCK_M)
    grid_n = triton.cdiv(N, BLOCK_N)
    grid = (B * hidden_dim * grid_m * grid_n,)

    _trimul_kernel[grid](
        left_fp16,
        right_fp16,
        out_fp16,
        B,
        N,
        hidden_dim,
        # strides for left
        left_fp16.stride(0),   # B
        left_fp16.stride(1),   # H
        left_fp16.stride(2),   # N (row)
        left_fp16.stride(3),   # N (col)
        # strides for right
        right_fp16.stride(0),
        right_fp16.stride(1),
        right_fp16.stride(2),
        right_fp16.stride(3),
        # strides for out
        out_fp16.stride(0),
        out_fp16.stride(1),
        out_fp16.stride(2),
        out_fp16.stride(3),
        BLOCK_M=BLOCK_M,
        BLOCK_N=BLOCK_N,
        BLOCK_K=BLOCK_K,
    )

    # ------------------------------------------------------------------
    # 4. Post‑process (LayerNorm, output gate, final linear)
    # ------------------------------------------------------------------
    # back to original layout: (B,H,N,N) -> (B,N,N,H)
    out = out_fp16.to(dtype).permute(0, 2, 3, 1).contiguous()   # (B,N,N,H)

    # to_out_norm
    out = F.layer_norm(
        out,
        normalized_shape=(hidden_dim,),
        weight=weights["to_out_norm.weight"].to(dtype),
        bias=weights["to_out_norm.bias"].to(dtype),
    )

    # apply output gate (broadcast on the pairwise axes)
    out = out * out_gate

    # final linear back to `dim`
    out = F.linear(out, weights["to_out.weight"].to(dtype))

    return out
```


## Lessons from earlier kernels in this search

Extracted from kernels already generated and benchmarked here. Empirical
findings, not part of the specification above, and they do not override any rule
stated in it.

**Observed to help**
1. [local] Limit shared memory usage
   When launching a Triton kernel, set BLOCK_M, BLOCK_N, and BLOCK_K to values (e.g., ≤64) that keep required shared memory below the device limit; if needed, lower num_stages.
2. [global] Delegate N³ contraction to cuBLAS
   Reshape the left and right tensors to (B*H, N, N) and compute out = torch.bmm(left, right.transpose(1,2)); this leverages cuBLAS/Tensor‑cores for the dominant O(N³) work while keeping the program simple and fast.
3. [local] Match dtypes for batched GEMM
   If you cast one operand (e.g., the weight matrix) to float16 for speed, also cast the other operand to float16 before the batched matmul, or keep both in float32; mixing float32 and float16 raises a runtime error.
4. [global] Delegate cubic contraction to cuBLAS
   When implementing the outgoing TriMul, never write a full N³ Triton GEMM; instead reshape left and right tensors to (B*H, N, N) (FP16) and call torch.bmm (or torch.matmul) which leverages cuBLAS/Tensor‑cores. Keep the kernel limited to elementwise work.

**Observed to fail**
1. [local] Match stride unpacking to tensor rank
   Do not assume a tensor has three strides; use tensor.stride() and unpack exactly the number of dimensions the kernel expects, or pass strides explicitly from the caller.
