"""
TriMul – “outgoing” forward pass (AlphaFold‑3)

Algorithm (high‑level)
----------------------
1️⃣ Layer‑Norm on the (B,N,N,C) tensor – fp32, done in PyTorch.
2️⃣ Linear projections to the hidden dimension H (no bias) – fp32.
3️⃣ Compute three gates (left, right, out) – fp32 + sigmoid.
4️⃣ **Triton kernel** fuses the mask (if present) and the left/right gates
   into the projected tensors *in‑place*:
        left  = left  * mask * left_gate
        right = right * mask * right_gate
   This is the only part that really benefits from a custom kernel because
   it touches every element of the 4‑D tensors and would otherwise be three
   separate element‑wise launches.
5️⃣ Cast the fused tensors to float‑16 and reshape to (B*H, N, N).  The
   dominant O(N³) contraction
        out[b,i,j,h] = Σ_k left[b,i,k,h] * right[b,j,k,h]
   is performed as a batched matrix‑multiply (torch.bmm) on the reshaped
   tensors – this uses cuBLAS/Tensor cores and is far faster than a Triton
   triple‑loop.
6️⃣ Cast back to fp32, restore the original layout.
7️⃣ Output LayerNorm – fp32 (PyTorch).
8️⃣ Apply the output gate (element‑wise *).
9️⃣ Final linear projection back to the original channel dimension – fp32.

Only step 4 is written in Triton; the rest stays in PyTorch because the
batched GEMM is already optimal on Hopper (SM‑90).  The kernel is written
to work for any batch size (B ∈ {1,2}), any sequence length N, and any
hidden dimension H (the hidden dimension is always the “dim” of the
projection, i.e. the `hidden_dim` from the config).  It also correctly
handles the “nomask” flag: when `mask` is None we treat it as all‑ones.
All tensors are assumed to be on the same CUDA device and use the default
contiguous layout.

The kernel uses a 1‑D launch grid; each thread processes a single element
of the 4‑D tensors.  A block size of 2048 gives good occupancy on the H200
while keeping register pressure modest.  Strides are passed in *elements*
(not bytes) to avoid any ambiguity.
"""

import torch
import triton
import triton.language as tl
from torch.nn import functional as F


# ----------------------------------------------------------------------
# Triton kernel – fuse mask + left/right gates into the projected tensors
# ----------------------------------------------------------------------
@triton.jit
def _fuse_mask_gates_kernel(
    left_ptr,            # fp32, shape [B,N,N,H]
    right_ptr,           # fp32, shape [B,N,N,H]
    mask_ptr,            # fp32, shape [B,N,N]   (broadcasted over H)
    left_gate_ptr,       # fp32, shape [B,N,N,H]
    right_gate_ptr,      # fp32, shape [B,N,N,H]
    # compile‑time constants
    B, N, H,
    # strides in *elements*
    stride_left_b, stride_left_i, stride_left_j, stride_left_h,
    stride_right_b, stride_right_i, stride_right_j, stride_right_h,
    stride_mask_b, stride_mask_i, stride_mask_j,
    stride_lgate_b, stride_lgate_i, stride_lgate_j, stride_lgate_h,
    stride_rgate_b, stride_rgate_i, stride_rgate_j, stride_rgate_h,
    BLOCK: tl.constexpr,
):
    pid = tl.program_id(0)
    # linear index of the element this thread works on
    offs = pid * BLOCK + tl.arange(0, BLOCK)
    valid = offs < B * N * N * H

    # ---------- decode linear offset -> (b,i,j,h) ----------
    # total size = B * N * N * H, layout = (b,i,j,h) with contiguous H
    b = (offs // (N * N * H))
    rest = offs % (N * N * H)
    i = (rest // (N * H))
    rest = rest % (N * H)
    j = (rest // H)
    h = rest % H

    # ---------- compute element pointers ----------
    left_off   = b * stride_left_b   + i * stride_left_i   + j * stride_left_j   + h * stride_left_h
    right_off  = b * stride_right_b  + i * stride_right_i  + j * stride_right_j  + h * stride_right_h
    mask_off   = b * stride_mask_b   + i * stride_mask_i   + j * stride_mask_j               # no H stride
    lgate_off  = b * stride_lgate_b  + i * stride_lgate_i  + j * stride_lgate_j  + h * stride_lgate_h
    rgate_off  = b * stride_rgate_b  + i * stride_rgate_i  + j * stride_rgate_j  + h * stride_rgate_h

    # ---------- load ----------
    left   = tl.load(left_ptr   + left_off,   mask=valid, other=0.0)
    right  = tl.load(right_ptr  + right_off,  mask=valid, other=0.0)
    m      = tl.load(mask_ptr   + mask_off,   mask=valid, other=0.0)   # broadcasted over H
    lgate  = tl.load(left_gate_ptr + lgate_off, mask=valid, other=0.0)
    rgate  = tl.load(right_gate_ptr+ rgate_off, mask=valid, other=0.0)

    # ---------- fuse ----------
    left  = left  * m * lgate
    right = right * m * rgate

    # ---------- store (in‑place) ----------
    tl.store(left_ptr  + left_off,  left,  mask=valid)
    tl.store(right_ptr + right_off, right, mask=valid)


def _fuse_mask_and_gates(left, right, mask, left_gate, right_gate):
    """
    In‑place Triton fusion of mask and gates.
    All tensors are *contiguous* fp32.
    """
    B, N, _, H = left.shape
    total = B * N * N * H
    BLOCK = 2048                      # ~2 K threads → good occupancy on H200
    grid = (triton.cdiv(total, BLOCK),)

    # strides expressed in *elements* (not bytes)
    s_left = left.stride()
    s_right = right.stride()
    s_mask = mask.stride()
    s_lgate = left_gate.stride()
    s_rgate = right_gate.stride()

    _fuse_mask_gates_kernel[grid](
        left_ptr=left,
        right_ptr=right,
        mask_ptr=mask,
        left_gate_ptr=left_gate,
        right_gate_ptr=right_gate,
        B=B, N=N, H=H,
        stride_left_b=s_left[0], stride_left_i=s_left[1],
        stride_left_j=s_left[2], stride_left_h=s_left[3],
        stride_right_b=s_right[0], stride_right_i=s_right[1],
        stride_right_j=s_right[2], stride_right_h=s_right[3],
        stride_mask_b=s_mask[0], stride_mask_i=s_mask[1],
        stride_mask_j=s_mask[2],
        stride_lgate_b=s_lgate[0], stride_lgate_i=s_lgate[1],
        stride_lgate_j=s_lgate[2], stride_lgate_h=s_lgate[3],
        stride_rgate_b=s_rgate[0], stride_rgate_i=s_rgate[1],
        stride_rgate_j=s_rgate[2], stride_rgate_h=s_rgate[3],
        BLOCK=BLOCK,
    )
    return left, right


# ----------------------------------------------------------------------
# Entry point required by the evaluation harness
# ----------------------------------------------------------------------
def custom_kernel(data):
    """
    Forward pass of the outgoing TriMul module (no gradients).

    Parameters
    ----------
    data : tuple
        (input_tensor, mask, weights_dict, config_dict)
        - input_tensor : torch.Tensor, shape [B, N, N, C] (float32)
        - mask        : torch.Tensor or None, shape [B, N, N] (float32)
        - weights_dict: mapping from layer‑name to torch tensors
        - config_dict : contains "dim" (C) and "hidden_dim" (H)

    Returns
    -------
    torch.Tensor
        Tensor of shape [B, N, N, C] (float32) on the same device as ``input_tensor``.
    """
    # ------------------------------------------------------------------
    # unpack arguments
    # ------------------------------------------------------------------
    x, mask, weights, config = data
    device = x.device
    B, N, _, C = x.shape
    dim = config["dim"]           # == C
    hidden = config["hidden_dim"] # == H

    # ------------------------------------------------------------------
    # 1️⃣ LayerNorm over the last dimension (fp32, manual for speed)
    # ------------------------------------------------------------------
    eps = 1e-5
    ln_w = weights["norm.weight"]   # (C,)
    ln_b = weights["norm.bias"]     # (C,)

    # mean/var over channel dim
    mean = x.mean(-1, keepdim=True)
    var = x.var(-1, unbiased=False, keepdim=True)
    x_norm = (x - mean) / torch.sqrt(var + eps)
    x_norm = x_norm * ln_w + ln_b    # (B,N,N,C)

    # ------------------------------------------------------------------
    # 2️⃣ Linear projections (no bias) → hidden dimension
    # ------------------------------------------------------------------
    left_proj_w  = weights["left_proj.weight"]   # (hidden, C)
    right_proj_w = weights["right_proj.weight"]  # (hidden, C)

    left  = F.linear(x_norm, left_proj_w)   # (B,N,N,hidden)
    right = F.linear(x_norm, right_proj_w)  # (B,N,N,hidden)

    # ------------------------------------------------------------------
    # 3️⃣ Gates + sigmoid
    # ------------------------------------------------------------------
    left_gate_w  = weights["left_gate.weight"]   # (hidden, C)
    right_gate_w = weights["right_gate.weight"]  # (hidden, C)
    out_gate_w   = weights["out_gate.weight"]    # (hidden, C)

    left_gate  = F.linear(x_norm, left_gate_w).sigmoid()   # (B,N,N,hidden)
    right_gate = F.linear(x_norm, right_gate_w).sigmoid()  # (B,N,N,hidden)
    out_gate   = F.linear(x_norm, out_gate_w).sigmoid()    # (B,N,N,hidden)

    # ------------------------------------------------------------------
    # 4️⃣ Prepare mask (broadcast) – if no mask, treat as all‑ones
    # ------------------------------------------------------------------
    if mask is None:
        mask = torch.ones(B, N, N, device=device, dtype=x.dtype)
    mask = mask.unsqueeze(-1)          # (B,N,N,1)

    # ------------------------------------------------------------------
    # 5️⃣ Fuse mask + gates into left/right (in‑place) via Triton
    # ------------------------------------------------------------------
    _fuse_mask_and_gates(left, right, mask, left_gate, right_gate)

    # ------------------------------------------------------------------
    # 6️⃣ Batched GEMM over the “k” dimension (fp16 for Tensor‑cores)
    # ------------------------------------------------------------------
    # Cast to half‑precision
    left_h  = left.to(torch.float16)
    right_h = right.to(torch.float16)

    # reshape to (B*hidden, N, N) – we need the hidden dim as a batch dimension
    # left_h[b,i,k,h] -> (b* h, i, k)
    left_flat  = left_h.permute(0, 3, 1, 2).reshape(B * hidden, N, N)
    right_flat = right_h.permute(0, 3, 1, 2).reshape(B * hidden, N, N)

    # batched matrix multiply: Σ_k left[b,i,k,h] * right[b,j,k,h]
    out_flat = torch.bmm(left_flat, right_flat.transpose(1, 2))   # (B*hidden, N, N)

    # back to fp32 and restore layout (B,N,N,hidden)
    out = out_flat.view(B, hidden, N, N).permute(0, 2, 3, 1).to(torch.float32)

    # ------------------------------------------------------------------
    # 7️⃣ Output LayerNorm (fp32)
    # ------------------------------------------------------------------
    to_out_ln_w = weights["to_out_norm.weight"]   # (hidden,)
    to_out_ln_b = weights["to_out_norm.bias"]     # (hidden,)

    eps_o = 1e-5
    mean_o = out.mean(-1, keepdim=True)
    var_o = out.var(-1, unbiased=False, keepdim=True)
    out_norm = (out - mean_o) / torch.sqrt(var_o + eps_o)
    out_norm = out_norm * to_out_ln_w + to_out_ln_b   # (B,N,N,hidden)

    # ------------------------------------------------------------------
    # 8️⃣ Apply output gate (element‑wise)
    # ------------------------------------------------------------------
    out_norm = out_norm * out_gate   # (B,N,N,hidden)

    # ------------------------------------------------------------------
    # 9️⃣ Final linear back to original channel dimension
    # ------------------------------------------------------------------
    to_out_w = weights["to_out.weight"]   # (C, hidden)
    out_final = F.linear(out_norm, to_out_w)   # (B,N,N,C)

    return out_final

**Explanation of design choices**

* **Why a Triton kernel?**  
  The mask and two gates each have shape `[B, N, N, H]`. Applying them separately would launch three full‑tensor kernels, incurring three memory passes. Fusing them reduces traffic to a single read‑modify‑write pass, which is the only part of the algorithm that cannot be expressed efficiently with existing high‑performance libraries.

* **Why not Triton‑implement the cubic contraction?**  
  The contraction is an `einsum` over the `k` dimension and dominates the runtime (`O(N³·H)`). On Hopper, cuBLAS batched `bmm` (Tensor‑Core‑accelerated) far outperforms any custom Triton tiling for this size range, as observed in prior experiments. Therefore we keep this step in PyTorch.

* **Mixed‑precision strategy**  
  All element‑wise work (LayerNorm, projections, gates, masking) stays in FP32 to avoid precision loss that could affect model quality. The heavy contraction is performed in FP16, which gives a ~2‑3× speed‑up on SM‑90 with negligible impact because the subsequent LayerNorm brings the values back to FP32.

* **Handling of `nomask`**  
  When `mask` is `None` we allocate a tensor of ones. The kernel treats the mask as a scalar broadcast over the hidden dimension, so the extra memory load is cheap.

* **Strides in elements**  
  Triton expects pointer arithmetic in element units. We therefore pass `tensor.stride()` directly (which is already in elements) and never multiply by `sizeof(dtype)`.

* **Block size**  
  `BLOCK = 2048` gives ~2 K threads per program‑id, which maps well to the large SM count of the H200 while keeping per‑thread register usage low. The kernel is embarrassingly parallel, so a 1‑D grid suffices.

The function `custom_kernel` follows the exact signature required by the harness, returns a `torch.float32` tensor of shape `[B, N, N, dim]`, and respects all configuration variations listed in the problem statement.
