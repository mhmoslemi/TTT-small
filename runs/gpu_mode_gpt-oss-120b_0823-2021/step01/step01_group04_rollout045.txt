"""
TriMul “outgoing” forward pass (AlphaFold‑3 style).

Algorithm
---------
1. **Layer‑norm** on the 4‑D input (B,N,N,C).  Implemented in PyTorch because
   the reduction is cheap compared with the O(N³) work and because Triton has
   no built‑in mean/var primitive.
2. **Linear projections** (left, right, left‑gate, right‑gate, out‑gate) are
   performed with `torch.nn.functional.linear` (bias‑free).  The weights are
   taken from the supplied ``weights`` dict.
3. **Fused element‑wise kernel** – a tiny Triton kernel that
   * multiplies the left and right tensors by the mask,
   * multiplies them by their respective gates,
   * writes the results back in‑place.
   This kernel touches each element only once and therefore amortises the
   mask load across the four tensors.
4. **Batched matrix‑multiplication** – the heavy N³ contraction

       out[b,i,j,h] = Σ_k left[b,i,k,h] * right[b,j,k,h]

   is equivalent to a batch of independent matrix products for every head
   ``h``:

       (left_h)  : (B,N,N)  → (B·h, N, N)
       (right_h) : (B,N,N)  → (B·h, N, N)

   The contraction is carried out with a single ``torch.bmm`` (cuBLAS) which
   is heavily tuned on Hopper/H200.
5. **Output layer‑norm → output‑gate → final linear** – again carried out in
   PyTorch.

The only Triton contribution is the element‑wise fusion (step 3); all heavy
linear algebra stays in cuBLAS, which is the fastest path on the target
hardware.  The kernel is deliberately simple, uses a 1‑D launch and
coalesced accesses, and works for any batch size, sequence length and hidden
dimension that fit in GPU memory.
"""

import torch
import triton
import triton.language as tl
from torch.nn import functional as F


# -------------------------------------------------------------
#  Triton kernel: fuse mask, left‑gate and right‑gate into the
#  left/right tensors (in‑place).
# -------------------------------------------------------------
@triton.jit
def _tri_mul_fuse_kernel(
    left_ptr,               # B,N,N,H   (float32)
    right_ptr,              # B,N,N,H   (float32)
    mask_ptr,               # B,N,N,1   (float32) – broadcasted mask
    left_gate_ptr,          # B,N,N,H   (float32)
    right_gate_ptr,         # B,N,N,H   (float32)
    B, N, H,                # static shape
    stride_left_bn, stride_left_n, stride_left_h,
    stride_right_bn, stride_right_n, stride_right_h,
    stride_mask_bn, stride_mask_n,
    stride_lgate_bn, stride_lgate_n, stride_lgate_h,
    stride_rgate_bn, stride_rgate_n, stride_rgate_h,
    BLOCK: tl.constexpr,
):
    """
    For every element (b,i,k,h):
        left  = left  * mask[b,i,k,0] * left_gate[b,i,k,h]
        right = right * mask[b,i,k,0] * right_gate[b,i,k,h]
    The operation is performed in‑place.
    """
    pid = tl.program_id(0)                         # linear thread id
    total = B * N * N * H
    offs = pid * BLOCK + tl.arange(0, BLOCK)       # indices this thread handles
    mask = offs < total

    # ---- decode linear offset into 4‑D indices -----------------
    # linear layout: ((b * N + i) * N + k) * H + h
    b = offs // (N * N * H)
    rest = offs % (N * N * H)
    i = rest // (N * H)
    rest = rest % (N * H)
    k = rest // H
    h = rest % H

    # ---- compute pointer offsets (element‑wise, not bytes) -----
    left_off  = (b * stride_left_bn +
                 i * stride_left_n +
                 k * stride_left_h +
                 h)
    right_off = (b * stride_right_bn +
                 i * stride_right_n +
                 k * stride_right_h +
                 h)
    mask_off  = (b * stride_mask_bn +
                 i * stride_mask_n +
                 k)                                   # no channel dim
    lgate_off = (b * stride_lgate_bn +
                 i * stride_lgate_n +
                 k * stride_lgate_h +
                 h)
    rgate_off = (b * stride_rgate_bn +
                 i * stride_rgate_n +
                 k * stride_rgate_h +
                 h)

    # ---- load -------------------------------------------------
    left  = tl.load(left_ptr + left_off,   mask=mask, other=0.0)
    right = tl.load(right_ptr + right_off, mask=mask, other=0.0)
    m     = tl.load(mask_ptr + mask_off,   mask=mask, other=0.0)
    lgate = tl.load(left_gate_ptr + lgate_off, mask=mask, other=0.0)
    rgate = tl.load(right_gate_ptr + rgate_off, mask=mask, other=0.0)

    # ---- fused arithmetic --------------------------------------
    left  = left  * m * lgate
    right = right * m * rgate

    # ---- store back (in‑place) ---------------------------------
    tl.store(left_ptr  + left_off,  left,  mask=mask)
    tl.store(right_ptr + right_off, right, mask=mask)


def _fuse_mask_and_gates(left: torch.Tensor,
                         right: torch.Tensor,
                         mask: torch.Tensor,
                         left_gate: torch.Tensor,
                         right_gate: torch.Tensor) -> None:
    """
    Launch ``_tri_mul_fuse_kernel``.  All tensors are contiguous, float32,
    and live on the same CUDA device.
    The function mutates ``left`` and ``right`` in‑place and returns ``None``.
    """
    B, N, _, H = left.shape
    total = B * N * N * H

    # One‑dimensional launch; a block size of 1024 gives good occupancy on
    # Hopper while staying well below the per‑SM shared‑memory limit (the
    # kernel uses only registers).
    BLOCK = 1024
    grid = (triton.cdiv(total, BLOCK),)

    # Strides are expressed in number of elements (not bytes).
    s_left = left.stride()
    s_right = right.stride()
    s_mask = mask.stride()
    s_lgate = left_gate.stride()
    s_rgate = right_gate.stride()

    _tri_mul_fuse_kernel[grid](
        left_ptr=left,
        right_ptr=right,
        mask_ptr=mask,
        left_gate_ptr=left_gate,
        right_gate_ptr=right_gate,
        B=B, N=N, H=H,
        stride_left_bn=s_left[0], stride_left_n=s_left[1], stride_left_h=s_left[2],
        stride_right_bn=s_right[0], stride_right_n=s_right[1], stride_right_h=s_right[2],
        stride_mask_bn=s_mask[0], stride_mask_n=s_mask[1],
        stride_lgate_bn=s_lgate[0], stride_lgate_n=s_lgate[1], stride_lgate_h=s_lgate[2],
        stride_rgate_bn=s_rgate[0], stride_rgate_n=s_rgate[1], stride_rgate_h=s_rgate[2],
        BLOCK=BLOCK,
    )
    # No return – tensors have been updated in‑place.


# -------------------------------------------------------------
#  Main entry point required by the evaluation harness
# -------------------------------------------------------------
def custom_kernel(data):
    """
    Forward pass of the outgoing TriMul operator (no gradient needed).

    Parameters
    ----------
    data : tuple
        (input_tensor, mask, weights_dict, config_dict)

        - input_tensor : torch.Tensor of shape [B, N, N, C] (float32, CUDA)
        - mask         : torch.Tensor of shape [B, N, N] (float32, CUDA) or
                         ``None`` (treated as all‑ones)
        - weights_dict : mapping of weight names to tensors (see doc‑string)
        - config_dict  : ``{'dim': C, 'hidden_dim': H}``

    Returns
    -------
    torch.Tensor
        Tensor of shape [B, N, N, C] (float32, same device as input).
    """
    # ------------------------------------------------------------------
    # unpack arguments
    # ------------------------------------------------------------------
    x, mask, w, cfg = data
    dim = cfg["dim"]                # C
    hidden = cfg["hidden_dim"]      # H

    # ------------------------------------------------------------------
    # 1️⃣ Layer‑norm on the input (same as nn.LayerNorm(dim))
    # ------------------------------------------------------------------
    eps = 1e-5
    w_norm = w["norm.weight"]   # (C,)
    b_norm = w["norm.bias"]     # (C,)
    # mean/var over the channel dimension
    mean = x.mean(-1, keepdim=True)
    var = x.var(-1, unbiased=False, keepdim=True)
    x_norm = (x - mean) / torch.sqrt(var + eps)
    x_norm = x_norm * w_norm + b_norm          # (B,N,N,C)

    # ------------------------------------------------------------------
    # 2️⃣ Linear projections (bias‑free)
    # ------------------------------------------------------------------
    left  = F.linear(x_norm, w["left_proj.weight"])   # (B,N,N,hidden)
    right = F.linear(x_norm, w["right_proj.weight"])

    # ------------------------------------------------------------------
    # 3️⃣ Gates (with sigmoid)
    # ------------------------------------------------------------------
    left_gate  = F.linear(x_norm, w["left_gate.weight"]).sigmoid()
    right_gate = F.linear(x_norm, w["right_gate.weight"]).sigmoid()
    out_gate   = F.linear(x_norm, w["out_gate.weight"]).sigmoid()

    # ------------------------------------------------------------------
    # 4️⃣ Mask handling – ``mask`` may be None
    # ------------------------------------------------------------------
    if mask is None:
        # create an all‑ones mask on the same device/dtype as left/right
        mask = torch.ones_like(left[..., :1])   # shape (B,N,N,1)
    else:
        mask = mask.unsqueeze(-1)               # (B,N,N,1)

    # ------------------------------------------------------------------
    # 5️⃣ Fuse mask & gates into left/right (in‑place) with Triton
    # ------------------------------------------------------------------
    _fuse_mask_and_gates(left, right, mask, left_gate, right_gate)

    # ------------------------------------------------------------------
    # 6️⃣ Heavy O(N³) contraction via batched matrix‑multiply
    #    out_h = left_h @ right_hᵀ   for each head h
    # ------------------------------------------------------------------
    B, N, _, H = left.shape                      # reuse the hidden dim
    # reshape to (B*H, N, N)
    left_flat  = left.permute(0, 3, 1, 2).reshape(B * H, N, N)
    right_flat = right.permute(0, 3, 1, 2).reshape(B * H, N, N)

    # (B*H, N, N) @ (B*H, N, N).T  ->  (B*H, N, N)
    out_flat = torch.bmm(left_flat, right_flat.transpose(1, 2))

    # back to [B, N, N, hidden]
    out = out_flat.view(B, H, N, N).permute(0, 2, 3, 1)

    # ------------------------------------------------------------------
    # 7️⃣ Output layer‑norm, output‑gate and final linear
    # ------------------------------------------------------------------
    eps_o = 1e-5
    w_outnorm = w["to_out_norm.weight"]
    b_outnorm = w["to_out_norm.bias"]
    mean_o = out.mean(-1, keepdim=True)
    var_o = out.var(-1, unbiased=False, keepdim=True)
    out_norm = (out - mean_o) / torch.sqrt(var_o + eps_o)
    out_norm = out_norm * w_outnorm + b_outnorm

    out_norm = out_norm * out_gate                     # apply output gate

    # final projection back to original dim
    out_final = F.linear(out_norm, w["to_out.weight"])

    return out_final.to(torch.float32)
```

**Explanation of the design choices**

* **Why only one small Triton kernel?**  
  The expensive part of TriMul is the cubic contraction, which is exactly a
  batch of matrix multiplies.  cuBLAS on Hopper/H200 already saturates the
  device for these shapes (N up to 1024, H = 128).  Writing a custom GEMM in
  Triton would not beat cuBLAS and would dramatically increase code
  complexity.  The element‑wise fusion, however, saves a full pass over the
  four large tensors and removes the need for an extra Python loop.

* **In‑place fusion** keeps memory traffic minimal: each element is loaded
  once, multiplied by three scalars (mask, left_gate/right_gate), and written
  back.  No temporary copies are allocated.

* **1‑D launch with a large block (1024)** gives excellent occupancy on
  SM‑90 while using virtually no shared memory (only registers).  The kernel
  performs only arithmetic and loads/stores, so register pressure is low and
  the scheduler can keep many warps resident.

* **All other ops stay in PyTorch** – they are vectorised, use fused kernels
  (e.g., `torch.nn.functional.linear`, `torch.bmm`) and benefit from the
  highly‑optimised CUTLASS/cuBLAS back‑ends.

* **Correctness** – the implementation follows the reference PyTorch code
  step‑by‑step (layer‑norm → projections → masks/gates → einsum →
  output norm → gate → final linear) and therefore produces identical
  results (within floating‑point round‑off) for every configuration listed in
  the problem statement.
