"""
custom_kernel – “outgoing” TriMul (AlphaFold‑3 style)

The heavy O(N³) part is the einsum
    out[b,i,j,d] = Σ_k left[b,i,k,d] * right[b,j,k,d]
which can be seen as a batched matrix‑multiply per head `d` :

    left  : (B, H, I, K)   =   x projected & gated   (permute 0,3,1,2)
    right : (B, H, K, J)   =   x projected & gated   (permute 0,3,2,1)

For every pair (b, h) we need I×K · K×J → I×J.
The Triton kernel below computes many such products in a single launch.
All cheap operations (LayerNorm, linear layers, gating, final LayerNorm / projection)
stay in PyTorch – they are negligible compared to the N³ kernel.

The kernel works in fp16 for the multiply‑add, accumulates in fp32 to keep
numerical error low, and writes the result in fp16.  The host casts back
to fp32 before the final LayerNorm / linear projection.
"""

import torch
import triton
import triton.language as tl


# ----------------------------------------------------------------------
# Triton kernel : batched mat‑mul (I×K)·(K×J) → (I×J)  for many heads
# ----------------------------------------------------------------------
@triton.jit
def _batch_matmul_kernel(
    a_ptr,                 # left  matrix pointer  (B*H, I, K)
    b_ptr,                 # right matrix pointer  (B*H, K, J)
    c_ptr,                 # output pointer        (B*H, I, J)
    M, N, K,               # matrix sizes
    stride_az, stride_am, stride_ak,   # a strides   (batch, i, k)
    stride_bz, stride_bk, stride_bn,   # b strides   (batch, k, j)
    stride_cz, stride_cm, stride_cn,   # c strides   (batch, i, j)
    BLOCK_M: tl.constexpr,
    BLOCK_N: tl.constexpr,
    BLOCK_K: tl.constexpr,
):
    """Batched fp16 mat‑mul with fp32 accumulation.

    Layout:
        a : (batch, M, K)
        b : (batch, K, N)
        c : (batch, M, N)

    The kernel is launched with a 3‑D grid:
        pid_m ∈ [0, ceil(M/BLOCK_M))
        pid_n ∈ [0, ceil(N/BLOCK_N))
        pid_z ∈ [0, batch)                # batch = B*H
    """
    pid_m = tl.program_id(0)          # tile row
    pid_n = tl.program_id(1)          # tile col
    pid_z = tl.program_id(2)          # batch * head index

    # ------------------------------------------------------------------
    # offsets & masks for the current tile
    # ------------------------------------------------------------------
    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    offs_n = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)

    mask_m = offs_m < M
    mask_n = offs_n < N

    # accumulator in fp32 (more stable than fp16 accumulation)
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # ------------------------------------------------------------------
    # Loop over K dimension in blocks
    # ------------------------------------------------------------------
    for k in range(0, tl.cdiv(K, BLOCK_K)):
        offs_k = k * BLOCK_K + tl.arange(0, BLOCK_K)
        mask_k = offs_k < K

        # load a tile of A (shape BLOCK_M × BLOCK_K)
        a = tl.load(
            a_ptr
            + pid_z * stride_az
            + offs_m[:, None] * stride_am
            + offs_k[None, :] * stride_ak,
            mask=mask_m[:, None] & mask_k[None, :],
            other=0.0,
        )

        # load a tile of B (shape BLOCK_K × BLOCK_N)
        b = tl.load(
            b_ptr
            + pid_z * stride_bz
            + offs_k[:, None] * stride_bk
            + offs_n[None, :] * stride_bn,
            mask=mask_k[:, None] & mask_n[None, :],
            other=0.0,
        )

        # dot‑product accumulation (fp32)
        acc += tl.dot(a, b)

    # ------------------------------------------------------------------
    # Write back (convert to fp16 for memory bandwidth)
    # ------------------------------------------------------------------
    c = acc.to(tl.float16)
    tl.store(
        c_ptr
        + pid_z * stride_cz
        + offs_m[:, None] * stride_cm
        + offs_n[None, :] * stride_cn,
        c,
        mask=mask_m[:, None] & mask_n[None, :],
    )


# ----------------------------------------------------------------------
# Helper that launches the kernel (keeps everything in fp16)
# ----------------------------------------------------------------------
def _triton_batch_matmul(left: torch.Tensor, right: torch.Tensor) -> torch.Tensor:
    """
    left  : (B, H, I, K)   fp16, contiguous
    right : (B, H, K, J)   fp16, contiguous
    returns (B, H, I, J)   fp16
    """
    assert left.is_contiguous() and right.is_contiguous()
    B, H, I, K = left.shape
    _, _, K2, J = right.shape
    assert K == K2

    out = torch.empty((B, H, I, J), device=left.device, dtype=torch.float16)

    # flatten the batch*head dimension – the kernel expects a 3‑D tensor
    batch = B * H
    a = left.view(batch, I, K)
    b = right.view(batch, K, J)
    c = out.view(batch, I, J)

    # strides in *elements*
    stride_az, stride_am, stride_ak = a.stride()
    stride_bz, stride_bk, stride_bn = b.stride()
    stride_cz, stride_cm, stride_cn = c.stride()

    # ------------------------------------------------------------------
    # Tile sizes – tuned for Hopper (SM‑90) with fp16
    # ------------------------------------------------------------------
    BLOCK_M = 64
    BLOCK_N = 64
    BLOCK_K = 32

    grid = (
        triton.cdiv(I, BLOCK_M),
        triton.cdiv(J, BLOCK_N),
        batch,
    )
    _batch_matmul_kernel[grid](
        a_ptr=a,
        b_ptr=b,
        c_ptr=c,
        M=I,
        N=J,
        K=K,
        stride_az=stride_az,
        stride_am=stride_am,
        stride_ak=stride_ak,
        stride_bz=stride_bz,
        stride_bk=stride_bk,
        stride_bn=stride_bn,
        stride_cz=stride_cz,
        stride_cm=stride_cm,
        stride_cn=stride_cn,
        BLOCK_M=BLOCK_M,
        BLOCK_N=BLOCK_N,
        BLOCK_K=BLOCK_K,
        num_warps=4,               # good default for fp16 on H200
        num_stages=2,              # keeps shared‑memory pressure low
    )
    return out


# ----------------------------------------------------------------------
# Full forward (PyTorch for cheap ops, Triton for the O(N³) core)
# ----------------------------------------------------------------------
def custom_kernel(data):
    """
    Forward pass of the “outgoing” TriMul operator.

    Parameters
    ----------
    data : tuple
        (input_tensor, mask, weights, config)
        input_tensor : torch.Tensor [B, N, N, dim]   (float32)
        mask         : torch.Tensor [B, N, N]       (float32 or bool) – may be None
        weights      : dict of leaf tensors (all float32)
        config       : dict with keys  "dim" and "hidden_dim"

    Returns
    -------
    torch.Tensor [B, N, N, dim] (float32)
    """
    input_tensor, mask, weights, config = data
    device = input_tensor.device
    B, N, _, dim = input_tensor.shape
    hidden_dim = config["hidden_dim"]

    # ------------------------------------------------------------------
    # 1. Input LayerNorm  (manual implementation – cheap)
    # ------------------------------------------------------------------
    norm_w = weights["norm.weight"]
    norm_b = weights["norm.bias"]
    # mean / var over the last dimension (dim)
    mu = input_tensor.mean(-1, keepdim=True)
    var = input_tensor.var(-1, unbiased=False, keepdim=True)
    x = (input_tensor - mu) / torch.sqrt(var + 1e-5)
    x = x * norm_w + norm_b          # still fp32

    # ------------------------------------------------------------------
    # 2. Linear projections + gating (switch to fp16 for speed)
    # ------------------------------------------------------------------
    # All linear layers are bias‑free; we only need weight tensors.
    # Convert weight matrices to fp16 once.
    left_proj_w   = weights["left_proj.weight"].to(torch.float16)
    right_proj_w  = weights["right_proj.weight"].to(torch.float16)
    left_gate_w   = weights["left_gate.weight"].to(torch.float16)
    right_gate_w  = weights["right_gate.weight"].to(torch.float16)
    out_gate_w    = weights["out_gate.weight"].to(torch.float16)
    to_out_norm_w = weights["to_out_norm.weight"]   # stays fp32 (LayerNorm)
    to_out_norm_b = weights["to_out_norm.bias"]
    to_out_w      = weights["to_out.weight"]        # final linear stays fp32

    # Cast the normalized activations to fp16 (the heavy part works in fp16)
    x_fp16 = x.to(torch.float16)

    # Project to hidden dimension (shape: [B, N, N, hidden_dim])
    left  = torch.nn.functional.linear(x_fp16, left_proj_w)   # fp16
    right = torch.nn.functional.linear(x_fp16, right_proj_w)  # fp16

    # ------------------------------------------------------------------
    # 3. Optional mask (broadcasted on the hidden dimension)
    # ------------------------------------------------------------------
    if mask is not None:
        # mask shape [B, N, N] -> [B, N, N, 1] -> fp16
        mask_fp16 = mask.unsqueeze(-1).to(torch.float16)
        left = left * mask_fp16
        right = right * mask_fp16

    # ------------------------------------------------------------------
    # 4. Gating (sigmoid on fp16 tensors)
    # ------------------------------------------------------------------
    left_gate  = torch.nn.functional.linear(x_fp16, left_gate_w).sigmoid()
    right_gate = torch.nn.functional.linear(x_fp16, right_gate_w).sigmoid()
    out_gate   = torch.nn.functional.linear(x_fp16, out_gate_w).sigmoid()

    left = left * left_gate
    right = right * right_gate

    # ------------------------------------------------------------------
    # 5. Triton batched mat‑mul
    #    left : (B, N, N, hidden) -> (B, H, I, K)
    #    right: (B, N, N, hidden) -> (B, H, K, J)
    #    where I = J = N, H = hidden_dim
    # ------------------------------------------------------------------
    # permute so that the hidden dimension becomes the “head” axis
    left_perm  = left.permute(0, 3, 1, 2).contiguous()   # (B, H, I, K)
    right_perm = right.permute(0, 3, 2, 1).contiguous()  # (B, H, K, J)

    out_fp16 = _triton_batch_matmul(left_perm, right_perm)   # (B, H, I, J) fp16

    # reshape back to [B, N, N, hidden] and cast to fp32 for the next LN
    out = out_fp16.permute(0, 2, 3, 1).contiguous().to(torch.float32)   # (B,N,N,hidden)

    # ------------------------------------------------------------------
    # 6. Output LayerNorm (fp32 – small tensor)
    # ------------------------------------------------------------------
    mu_o = out.mean(-1, keepdim=True)
    var_o = out.var(-1, unbiased=False, keepdim=True)
    out = (out - mu_o) / torch.sqrt(var_o + 1e-5)
    out = out * to_out_norm_w + to_out_norm_b

    # ------------------------------------------------------------------
    # 7. Final gating + projection back to dim
    # ------------------------------------------------------------------
    out = out * out_gate.to(torch.float32)   # broadcast over hidden dim
    out = torch.nn.functional.linear(out, to_out_w)   # fp32 linear

    return out
```

**Explanation of the design choices**

1. **Kernel tiling** – `BLOCK_M = BLOCK_N = 64` and `BLOCK_K = 32` give a good
   balance between occupancy and shared‑memory usage on Hopper (SM‑90).  
   `num_warps=4` and `num_stages=2` keep shared‑memory pressure low (≈ 16 KB per
   CTA), satisfying the “limit shared memory” lesson.

2. **Accumulation in fp32** – avoids the loss of precision that would otherwise
   hurt the final LayerNorm; the conversion to fp16 only happens at store time,
   which is bandwidth‑friendly.

3. **Batch‑flattening** – the kernel receives a single batch dimension equal to
   `B * hidden_dim`.  This eliminates an extra dimension‑loop inside the kernel
   and matches the stride‑loading pattern used in the earlier reference.

4. **Mask handling** – the mask is applied *before* the heavy kernel, but in
   fp16, so the extra memory traffic is negligible.  When `nomask=True` the
   mask argument is `None` and the branch is skipped.

5. **LayerNorm & final linear** – kept in PyTorch because they are O(B·N·dim)
   and much cheaper than the O(B·hidden·N²) mat‑mul.  Maintaining them in fp32
   ensures numerical stability.

6. **No unnecessary synchronisation** – the kernel never needs a global
   reduction; each CTA works on an independent `(batch, i‑tile, j‑tile)` slice,
   avoiding expensive cross‑CTA communication.

The resulting implementation follows the specification, runs the core N³
computation completely on the GPU with Triton, and returns a float‑32 tensor
compatible with the original PyTorch reference.
