Actually, for binary h, c_k = sum h[n+k](1-h[n]) = sum h[n+k] - sum h[n+k]h[n] (over valid n).

The first sum is the number of 1s in h[k:n] (i.e., sum of h[k:]).
The second sum is the autocorrelation of h at lag k (one-sided).

So: c_k = sum(h[k:]) - autocorr_h[k] (for k > 0, one-sided)

And autocorr_h[k] = sum_{n=0}^{n-1-k} h[n]*h[n+k] which is the standard autocorrelation.

I can compute the full autocorrelation using FFT:
autocorr = np.fft.ifft(np.abs(np.fft.fft(h, n=2*n))**2).real[:n]

Then c_k = sum(h[k:]) - autocorr[k] for k > 0.
And c_{-k} = sum(h[:n-k]) - autocorr[k] for k > 0.

Wait, let me verify:
c_{-k} = sum_{n=k}^{n-1} h[n-k](1-h[n]) = sum_{n=k}^{n-1} h[n-k] - sum_{n=k}^{n-1} h[n-k]h[n]
= sum_{m=0}^{n-1-k} h[m] - autocorr[k]
= sum(h[:n-k]) - autocorr[k]

And c_k = sum_{n=0}^{n-1-k} h[n+k](1-h[n]) = sum_{n=0}^{n-1-k} h[n+k] - sum_{n=0}^{n-1-k} h[n+k]h[n]
= sum(h[k:]) - autocorr[k]

So I can compute all c_k using:
- The cumulative sums of h
- The autocorrelation (via FFT)

This would be O(n log n) per evaluation instead of O(n^2). For n=1000, that's a significant speedup.

```python
def fast_eval_binary(h):
    """Fast evaluation for binary (or general) h using FFT."""
    n = len(h)
    dx = 2.0 / n
    # Compute autocorrelation using FFT
    f = np.fft.fft(h, n=2*n)
    autocorr = np.fft.ifft(f * np.conj(f)).real[:n]
    # autocorr[k] = sum_{i=0}^{n-1-k} h[i]*h[i+k]
    
    cumsum = np.concatenate([[0], np.cumsum(h)])
    # sum(h[k:]) = cumsum[n] - cumsum[k]
    # sum(h[:n-k]) = cumsum[n-k]
    
    # c_k for k=0..n-1:
    c_pos = (cumsum[n] - cumsum[:n]) - autocorr  # c_k = sum(h[k:]) - autocorr[k]
    # Wait, that's not right. c_k = sum_{i=0}^{n-1-k} h[i+k] - autocorr[k] = sum(h[k:]) - autocorr[k]
    # sum(h[k:]) = cumsum[n] - cumsum[k]
    
    c_pos = (cumsum[-1] - cumsum[:n]) - autocorr  # c_k for k=0,...,n-1
    # c_{-k} for k=0,...,n-1: c_{-k} = sum(h[:n-k]) - autocorr[k] = cumsum[n-k] - autocorr[k]
    c_neg = cumsum[n-1::-1] - autocorr  # c_{-(n-1)}, ..., c_1, c_0... 
    
    # Actually let me redo this more carefully
    # c_k for k = 0, 1, ..., n-1:
    # c_k = sum(h[k:]) - autocorr[k]
    sum_h_from_k = cumsum[-1] - cumsum[:n]  # array of length n: [sum(h[0:]), sum(h[1:]), ..., sum(h[n-1:])]
    c_pos = sum_h_from_k - autocorr  # c_0, c_1, ..., c_{n-1}
    
    # c_{-k} for k = 0, 1, ..., n-1:
    # c_{-k} = sum(h[:n-k]) - autocorr[k]
    # For k=0: c_0 (same as above)
    # For k=1: c_{-1} = sum(h[:n-1]) - autocorr[1] = cumsum[n-1] - autocorr[1]
    # For k=2: c_{-2} = sum(h[:n-2]) - autocorr[2] = cumsum[n-2] - autocorr[2]
    sum_h_to_n_minus_k = cumsum[n - np.arange(n)]  # [cumsum[n], cumsum[n-1], ..., cumsum[1]]
    c_neg = sum_h_to_n_minus_k - autocorr  # c_0, c_{-1}, ..., c_{-(n-1)}
    
    # The full correlation is: c_{-(n-1)}, ..., c_{-1}, c_0, c_1, ..., c_{n-1}
    # We want max of all these
    all_c = np.concatenate([c_neg[::-1][1:], c_pos])  # c_{-(n-1)}, ..., c_{-1}, c_0, ..., c_{n-1}
    
    return np.max(all_c) * dx
```

Hmm wait, I need to double-check the FFT autocorrelation. For a signal h of length n:
np.fft.ifft(np.abs(np.fft.fft(h, n=2*n))**2).real[:n]

This gives the circular autocorrelation of h zero-padded to length 2n, truncated to n. The k-th element is:
sum_{i=0}^{n-1} h[i] * h[(i+k) mod 2n]

For k = 0, 1, ..., n-1: since h is zero-padded to 2n, h[(i+k) mod 2n] = h[i+k] for i+k < 2n, which is always true since i ≤ n-1 and k ≤ n-1, so i+k ≤ 2n-2 < 2n.

So autocorr[k] = sum_{i=0}^{n-1-k} h[i] * h[i+k] (since h[i+k] = 0 for i+k ≥ n due to zero-padding).

Yes, this is correct! It's the one-sided autocorrelation.
