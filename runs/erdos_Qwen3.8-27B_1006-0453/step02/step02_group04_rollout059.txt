```python
    # Contribution to ∂c_s/∂h[j]:

        if f1 < f2:
            hi_t = t2
        else:
            lo_t = t1

    return t_opt
```

Wait, I need to double-check the coordinate descent. The issue is that when I update h[j], the corr_arr becomes stale. For Gauss-Seidel, I should update corr_arr incrementally.

When h[j] changes from old to new (Δ = new - old):
- For each shift k, c_k changes by Δ * b_k (where b_k is the coefficient computed before the update)
- But b_k itself changes after the update (since b_k depends on h)

For a simple approximation, I'll just recompute corr_arr every sweep (which is what I do above). Within a sweep, I use the stale corr_arr. This is "Jacobi" style and should still converge (just slower).

Actually, I can do better: update corr_arr in place after each coordinate change. Since c_k is linear in h[j] (for k≠0):
corr_arr[k] += Δ * b_k

where b_k was computed before the update. This is exact for the linear part. For the k=0 term (quadratic), the update is:
c_0 changes by: new*(1-new) - old*(1-old) = new - new² - old + old² = (new-old) - (new²-old²) = Δ - (new+old)*Δ = Δ(1-new-old)

So I can update corr_arr[0] (the k=0 entry, which is at index n-1 in the full correlation) by Δ*(1-new-old).

Wait, which index in the full correlation corresponds to k=0? In np.correlate(h, 1-h, mode='full'), the result has 2n-1 elements. The index for shift 0 is at position n-1 (the middle).

Let me verify: np.correlate([1,2,3], [4,5,6], mode='full') gives [1*6, 2*6+1*5, 3*6+2*5+1*4, 3*5+2*4, 3*4] = [6, 17, 28, 23, 12]. The "zero shift" (correlation of a[i] with v[i]) is at index len(v)-1 = 2, which gives 3*6+2*5+1*4 = 18+10+4 = 32... hmm that doesn't match.

Actually, np.correlate(a, v) = c_{kl} where c is defined as the cross-correlation. Let me just check:
- a = [h_0, h_1, ..., h_{n-1}]
- v = [1-h_0, 1-h_1, ..., 1-h_{n-1}]
- np.correlate(a, v, mode='full')[k] for k=0..2n-2

The documentation says: c_k = sum_n a[n+k] * conj(v[n])

So c_k = Σ_n h[n+k] * (1-h[n]) where the sum is over valid n (0≤n<n and 0≤n+k<n).

For k=0: c_0 = Σ_n h[n](1-h[n]) ← this is at index 0 in the full output? No wait...

Actually, looking at the NumPy source: for mode='full', the output has size len(a)+len(v)-1 = 2n-1. The output index i corresponds to the correlation at "lag" i - (len(v)-1) = i - (n-1).

So the output[n-1] (middle element) corresponds to lag 0, which is Σ h[n](1-h[n]).

Let me verify with a small example:
a = [1, 2, 3], v = [4, 5, 6]
output = np.correlate(a, v, mode='full')
output[0] = a[0]*v[2] = 1*6 = 6 (lag = 0 - 2 = -2)
output[1] = a[1]*v[2] + a[0]*v[1] = 2*6 + 1*5 = 17 (lag = -1)
output[2] = a[2]*v[2] + a[1]*v[1] + a[0]*v[0] = 3*6 + 2*5 + 1*4 = 18+10+4 = 32 (lag = 0)
output[3] = a[2]*v[1] + a[1]*v[0] = 3*5 + 2*4 = 15+8 = 23 (lag = +1)
output[4] = a[2]*v[0] = 3*4 = 12 (lag = +2)

So the middle element (index n-1 = 2) is the "zero lag" = Σ a[i]*v[i].

Great, so in my code, corr_arr[n-1] is c_0 = Σ h[i](1-h[i]).

Now, for the Gauss-Seidel update: when I change h[j] from old to new (Δ = new - old):
- For lag k (output index = k + n - 1): c_k changes by Δ * b_k
  where b_k = (1-h[j-k])*[0≤j-k<n] - h[j+k]*[0≤j+k<n]
  
  But wait, this b_k is the derivative of c_k w.r.t. h[j] evaluated at the current point. For the linear part (k≠0), this is exact. For k=0, c_0 = Σh[i](1-h[i]) is quadratic, and the change is:
  Δc_0 = new*(1-new) - old*(1-old) = Δ - new² + old² = Δ - (new-old)(new+old) = Δ(1 - new - old)
  
  The linear approximation gives: Δ * (1 - 2*old) which is correct to first order but not exact.

For simplicity, let me just update all c_k using the linear formula (including k=0), and periodically recompute the full correlation. The error at k=0 will be small (O(Δ²)) and will be corrected on the next sweep.

Let me update the code to do Gauss-Seidel within a sweep:

```python
def coord_descend(h, n, max_sweeps=300):
    h = h.copy()
    s_all = np.arange(-(n-1), n)
    for sweep in range(max_sweeps):
        corr_arr = np.correlate(h, 1.0 - h, mode='full')
        total_change = 0.0
        for j in range(n):
            js = j - s_all
            jp = j + s_all
            b = np.zeros(2*n - 1)
            mn = (js >= 0) & (js < n)
            mp = (jp >= 0) & (jp < n)
            b[mn] += (1.0 - h[js[mn]])
            b[mp] -= h[jp[mp]]
            
            old_hj = h[j]
            A = corr_arr - old_hj * b
            lo, hi = 0.0, 1.0
            for _ in range(40):
                t1 = lo + (hi - lo) / 3.0
                t2 = hi - (hi - lo) / 3.0
                if np.max(A + t1 * b) < np.max(A + t2 * b):
                    hi = t2
                else:
                    lo = t1
            t_opt = (lo + hi) * 0.5
            delta = t_opt - old_hj
            if abs(delta) > 1e-14:
                corr_arr += delta * b  # Gauss-Seidel update
                total_change += abs(delta)
                h[j] = t_opt
        if total_change < 1e-12:
            break
    return fix_sum(h, n)
```

```python
import numpy as np
import time

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(corr) * dx)

def fix_sum(h, n):
    target = n * 0.5
    h = np.clip(h.astype(float), 0.0, 1.0)
    s = np.sum(h)
    diff = target - s
    if abs(diff) < 1e-14:
        return h
    interior = (h > 1e-10) & (h < 1.0 - 1e-10)
    n_int = int(np.sum(interior))
    if n_int > 0 and abs(diff) < n_int * 0.4:
        h[interior] += diff / n_int
        h = np.clip(h, 0.0, 1.0)
    s = np.sum(h)
    diff = target - s
    if abs(diff) > 1e-13:
        if diff > 0:
            for i in np.argsort(h):
                add = min(diff, 1.0 - h[i])
                h[i] += add
                diff -= add
                if diff <= 1e-14:
                    break
        else:
            for i in np.argsort(-h):
                rem = min(-diff, h[i])
                h[i] -= rem
                diff += rem
                if diff >= -1e-14:
                    break
    return h

def resample(h, new_n):
    old_n = len(h)
    x = np.linspace(0.0, 2.0, old_n, endpoint=False)
    x_new = np.linspace(0.0, 2.0, new_n, endpoint=False)
    return fix_sum(np.interp(x_new, x, h, period=2.0), new_n)

def coord_descend(h, n, max_sweeps=300, recompute_every=60):
    h = h.copy()
    s_all = np.arange(-(n - 1), n)
    for sweep in range(max_sweeps):
        corr_arr = np.correlate(h, 1.0 - h, mode='full')
        total_change = 0.0
        for j in range(n):
            js = j - s_all
            jp = j + s_all
            b = np.zeros(2 * n - 1)
            mn = (js >= 0) & (js < n)
            mp = (jp >= 0) & (jp < n)
            b[mn] += (1.0 - h[js[mn]])
            b[mp] -= h[jp[mp]]
            old_hj = h[j]
            A = corr_arr - old_hj * b
            lo, hi = 0.0, 1.0
            for _ in range(35):
                t1 = lo + (hi - lo) / 3.0
                t2 = hi - (hi - lo) / 3.0
                if np.max(A + t1 * b) < np.max(A + t2 * b):
                    hi = t2
                else:
                    lo = t1
            t_opt = (lo + hi) * 0.5
            delta = t_opt - old_hj
            if abs(delta) > 1e-14:
                corr_arr += delta * b
                total_change += abs(delta)
                h[j] = t_opt
            if j % recompute_every == recompute_every - 1:
                corr_arr = np.correlate(h, 1.0 - h, mode='full')
        if total_change < 1e-12:
            break
    return fix_sum(h, n)

def block_init(n, npats=3):
    h = np.zeros(n)
    for p in range(npats):
        start = int(p * n / npats)
        length = int(n / (2 * npats))
        h[start:start + length] = 1.0
    return fix_sum(h, n)
```
