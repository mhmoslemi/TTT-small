```python
def gradient_smooth_max(h, T, dx):
    n = len(h)
    # Compute all c[d] for d = -(n-1) to n-1
    Nh = 1.0 - h
    c = np.correlate(h, Nh, mode='full')  # length 2n-1, c[k] corresponds to lag k-(n-1)
    
    # Softmax weights
    Td = T * dx
    c_scaled = c * Td
    c_max = np.max(c_scaled)
    exp_c = np.exp(c_scaled - c_max)
    p = exp_c / np.sum(exp_c)  # length 2n-1
    
    # Gradient
    grad = np.zeros(n)
    for j in range(n):
        # Term 1: sum over u of (1-h[u]) * P[(u-j)+(n-1)]
        # Term 2: sum over v of h[v] * P[(j-v)+(n-1)]
        t1 = 0.0
        t2 = 0.0
        for u in range(n):
            idx1 = (u - j) + (n - 1)
            if 0 <= idx1 < 2*n - 1:
                t1 += Nh[u] * p[idx1]
        for v in range(n):
            idx2 = (j - v) + (n - 1)
            if 0 <= idx2 < 2*n - 1:
                t2 += h[v] * p[idx2]
        grad[j] = dx * (t1 - t2)
    
    return grad, p
```

    val = c * dx  # actual c values

= -(t - h[j])² + h[j]² - 2h[j] + 3h[j]² ... this is getting messy.

Let me just compute:
exact(t) = c_0 - old + old² + t - t² (where old = h[j])
linear(t) = c_0 + (1-2*old)*(t-old)
difference = (c_0 - old + old² + t - t²) - (c_0 + t - 2*old*t - old + 2*old²)
= -old + old² + t - t² - t + 2*old*t + old - 2*old²
= -t² + 2*old*t - old²
= -(t - old)²

So the correction for lag 0 is: -delta² where delta = t - old.

So the incremental update is:
- For k ≠ n-1: c[k] += delta * a_k[j]
- For k = n-1: c[k] += delta * a_{n-1}[j] - delta²

where a_k[j] = dx * [(1-h[j+d_k])*[0≤j+d_k<n] - h[j-d_k]*[0≤j-d_k<n]] for d_k = k-(n-1).

This is easy to precompute for each j!

Let me restructure:

```python
def coord_descent_fast(h, n, n_passes=10):
    h = h.copy()
    dx = 2.0/n
    c = np.correlate(h, 1.0-h, mode='full') * dx  # length 2n-1
    nk = 2*n - 1
    
    for _ in range(n_passes):
        improved = False
        for j in range(n):
            if h[j] <= 1e-8 or h[j] >= 1.0-1e-8:
                continue
            # Precompute a_k for this j
            # a_k[j] = dx * (1-h[j+d]):[valid] - dx*h[j-d]:[valid] for d = k-(n-1)
            # Let's compute it as an array over k
            d = np.arange(nk) - (n-1)  # lag values, length 2n-1
            # For each k (lag d):
            # term1 = (1-h[j+d]) if 0 <= j+d < n else 0
            # term2 = h[j-d] if 0 <= j-d < n else 0
            jd = j + d
            jd2 = j - d
            mask1 = (jd >= 0) & (jd < n)
            mask2 = (jd2 >= 0) & (jd2 < n)
            term1 = np.where(mask1, 1.0 - h[jd], 0.0)
            term2 = np.where(mask2, h[jd2], 0.0)
            a_k = dx * (term1 - term2)  # length 2n-1
            
            # Now find best t in [0,1]
            old = h[j]
            best_t = old
            best_obj = np.max(c)
            
            # Grid search + refinement
            grid = np.linspace(0, 1, 200)
            for t in grid:
                delta = t - old
                c_new = c + delta * a_k
                c_new[n-1] -= delta * delta  # quadratic correction for lag 0
                if t == 0 or t == 1:
                    # Can't go negative
                    pass
                obj = np.max(c_new)
                if obj < best_obj - 1e-15:
                    best_obj = obj
                    best_t = t
            
            if best_t != old:
                delta = best_t - old
                c += delta * a_k
                c[n-1] -= delta * delta
                h[j] = best_t
                improved = True
        
        if not improved:
            break
    
    return h
```

This is O(n * nk * grid) per pass = O(n² * 200) per pass. For n=400: 400*799*200 ≈ 64 million per pass. With 10 passes: 640 million. In Python/NumPy, each "iteration" is a vectorized operation on arrays of length 799, so it should be fast. Let's say ~1μs per array operation, then 400*200 = 80,000 array ops per pass, ~80ms per pass, 800ms for 10 passes. That's fine!

Actually wait, I'm doing `c_new = c + delta * a_k` which creates a new array of size 799 for each grid point. That's 200 allocations per coordinate. For 400 coordinates: 80,000 allocations per pass. NumPy handles this efficiently but it might be ~1-5μs each, giving 80-400ms per pass. Still fine.
