    h = h * (target / s)
    h = np.clip(h, 0.0, 1.0)

                    lags = np.arange(2*n-1) - (n-1)  # l = k-(n-1) for k=0..2n-2
                    j1 = i - lags
                    j2 = i + lags
                    m1 = (j1 >= 0) & (j1 < n)
                    m2 = (j2 >= 0) & (j2 < n)
                    grad_k = np.zeros(2*n-1)
                    grad_k[m1] += (1.0 - cur[j1[m1]])
                    grad_k[m2] -= cur[j2[m2]]
                    new_corr = corr + d * grad_k
                    new_max = float(np.max(new_corr))
                    if new_max < curr_max - 1e-12:
                        # Accept
                        cur[i] = h_new_val
                        corr = new_corr
                        curr_max = new_max
                        improved = True
                        break
            if not improved:
                break
        c5 = float(curr_max * dx)
        if c5 < best_c5:
            best_c5 = c5
            best = cur.copy()
    
    return best, best_c5

Wait, I have a problem with the coordinate descent. The `lags` and `j1`, `j2` arrays are computed inside the inner loop, which is wasteful. Let me precompute them.

Actually, for coordinate i, the gradient vector for all lags is:
grad_k = (1-cur[i-l]) - cur[i+l] for l = -(n-1), ..., n-1

where cur[out] = 0.

Let me precompute this more efficiently:

```python
# For coordinate i:
# l ranges from -(n-1) to (n-1)
# j1 = i - l, j2 = i + l
# For l = 0: j1 = i, j2 = i, grad = (1-cur[i]) - cur[i] = 1 - 2*cur[i]
```

The computation is O(n) per (i, delta) pair. With n=360 and trying 2*360=720 pairs per sweep, that's 720*360=259K ops per sweep. With 500 sweeps, that's 130M ops. Fine.

But wait, I'm computing `lags`, `j1`, `j2`, `m1`, `m2`, `grad_k` inside the inner loop for each i and delta. That's wasteful since for a given i, the gradient is the same for +delta and -delta (just negated). Let me restructure:

For each i:
  Compute grad_k (O(n))
  Try +step: new_corr = corr + step*grad_k, check max
  Try -step: new_corr = corr - step*grad_k, check max
  (Both can be done in O(n) each)

That's 3*O(n) per coordinate = 3n per sweep, n² per full pass. For n=360, 130K per pass. Good.

Actually, the problem says "Smaller sequences with less than 1k samples are preferred". So 360-720 is fine. Let me try 360 first, and if time remains, try 720.

Wait, but the evaluation uses the returned h as-is. If I return a 360-point h, the C₅ is computed with dx=2/360. If I return a 720-point h, dx=2/720. The C₅ value will be different for different resolutions of the same "true" function.

Actually, for a step function, the C₅ depends on the discretization. A finer discretization can only make C₅ smaller or equal (since it can represent more functions). Wait, no. The C₅ is max_k sum_i h[i]*(1-h[i+k])*dx. If we double the resolution, each h[i] is a narrower strip, so the integral changes.

Actually, for the same "underlying" function, a finer discretization gives a better approximation. But the optimization problem is different at each resolution. So we should optimize at the chosen resolution.

Let me stick with 360 (the initial resolution) and focus on optimizing well at that resolution.

Let me also add a "basin hopping" element: after the initial optimization, perturb the solution and re-optimize, keeping the best.

import numpy as np
from scipy.optimize import minimize
import time

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(corr) * dx)

def get_corr(h):
    return np.correlate(h, 1.0 - h, mode='full')

def obj_lse(h, temp, pen):
    n = len(h)
    dx = 2.0 / n
    corr = get_corr(h)
    cmax = np.max(corr)
    shifted = corr - cmax
    sm = cmax + temp * np.log(np.sum(np.exp(shifted / temp)))
    c = np.sum(h) * dx - 1.0
    return sm * dx + pen * c * c

def project_h(h):
    n = len(h)
    h = np.clip(h, 0.0, 1.0)
    target = n / 2.0
    s = np.sum(h)
    if s < 1e-15:
        return np.full(n, 0.5)
    h = h * (target / s)
    h = np.clip(h, 0.0, 1.0)
    diff = target - np.sum(h)
    if abs(diff) > 1e-9:
        k = max(1, min(n, int(np.ceil(abs(diff))) + 1))
        if diff > 0:
            idx = np.argsort(h)[:k]
            h[idx] = np.clip(h[idx] + diff / k, 0, 1)
        else:
            idx = np.argsort(h)[-k:]
            h[idx] = np.clip(h[idx] + diff / k, 0, 1)
    return h
