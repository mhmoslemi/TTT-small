This is a critical bug! The algorithm was doing the wrong thing for 1-swaps. It might have still found improvements by accident (since it's exploring the space), but it was guided incorrectly.

Let me also verify the 2-swap to make sure that part is right:

This is: c_cur + (D[p1] + D[p2]) - (D[q1] + D[q2])

Great, so the 2-swap is correct but the 1-swap has a sign error.

This is a HUGE finding. The previous code's 1-swap was essentially looking for the worst moves (maximizing instead of minimizing the peak). But the 2-swap was correct, so the algorithm could still make progress through 2-swaps.
