def greedy_descent(h, N, deadline):
    h = h.astype(float).copy()
    corr = fft_corr(h)
    best = corr.max()
    improved = True
    while improved and time.time() < deadline:
        improved = False
        pk = int(np.argmax(corr))
        k_off = pk - (N - 1)
        if k_off == 0:
            break  # For binary, corr at lag 0 is 0
        if k_off > 0:
            pp = np.arange(0, N - k_off)
            valid = (h[pp] == 1) & (h[pp + k_off] == 0)
            candidates = pp[valid]
        else:
            M = -k_off
            pp = np.arange(M, N)
            valid = (h[pp] == 1) & (h[pp - M] == 0)
            candidates = pp[valid]
        
        if len(candidates) == 0:
            break
        
        # For each candidate, compute the new max corr
        best_new = best
        best_p = -1
        for p in candidates:
            q = p + k_off if k_off > 0 else p - (-k_off)
            # Compute new corr max
            # delta: flipping p (1→0) and q (0→1)
            # For the specific shift k_off: value decreases by 1
            # For other shifts: need full computation
            # Quick check: just look at the current corr and the shift k_off
            # The value at k_off decreases by 1, but other shifts might increase
            # For a cheap check: new_max ≈ max(corr with k_off reduced by 1, other shifts unchanged)
            # This is valid if no other shift increases. But some might.
            # For an exact check, we need the full delta.
            
            # Cheap upper bound: max(corr with corr[pk]-1, second_max)
            # This tells us if this swap definitely helps
            second_max = np.sort(corr)[-2] if corr[pk] > 0 else 0
            cheap = max(corr[pk] - 1, second_max)
            if cheap < best_new:
                # Promising, do exact check
                h[p], h[q] = 0, 1
                new_corr = fft_corr(h)
                new_max = float(new_corr.max())
                h[p], h[q] = 1, 0
                if new_max < best_new:
                    best_new = new_max
                    best_p = p
                    best_q = q
        
        if best_p >= 0 and best_new < best - 1e-10:
            h[best_p], h[best_q] = 0, 1
            corr = fft_corr(h)
            best = best_new
            improved = True
    
    return h, best * (2.0/N)

            # h[i-M] for M=1..i: h[i-1], h[i-2], ..., h[0]
        
        # D[i, N-1-M] for M=1..N-1-i: -= h[i+M] -> indices N-2, N-3, ..., N-i
        # h[i+M] for M=1..N-1-i: h[i+1], h[i+2], ..., h[N-1]
        if i < N-1:
            D[i, N-2 : N-2-(N-1-i) : -1] -= h[i+1:N]
    return D

The issue is that the deltas are NOT linear in general! When you change two positions simultaneously, the cross-term matters. The delta for position i depends on the values of other positions.

Specifically, delta_i depends on h[j] for j≠i. So when we change both p and q simultaneously, the deltas are not simply additive.

The correct formula for a simultaneous swap (p:1→0, q:0→1):
new_corr[j] = old_corr[j] + Δ_p^corr[j] + Δ_q^corr[j] + cross_term

Where Δ_p^corr is the change at p assuming only p changes, Δ_q similarly, and cross_term accounts for the interaction.

The cross-term: it's zero unless p and q are at positions that interact in the correlation. Specifically, if p and q appear in the same term of the correlation sum, there's a cross-term.

For shift k: corr[N-1+k] = sum_i h[i]*(1-h[i+k])
If p = i and q = i+k (or vice versa), then the term h[p]*(1-h[q]) is affected by both changes simultaneously.
- Before: h[p]*(1-h[q]) = 1*1 = 1 (since h[p]=1, h[q]=0)
- After: h[p]*(1-h[q]) = 0*0 = 0
- Change: -1
- Sum of individual changes: Δ_p: h[p] changes 1→0, term goes from 1*(1-h[q])=1 to 0*(1-h[q])=0, change=-1. Δ_q: h[q] changes 0→1, term goes from h[p]*(1-0)=1 to h[p]*(1-1)=0, change=-1. Sum = -2.
- Cross term: -1 - (-2) = 1. So there IS a cross-term of +1.

Similarly for other positions where p and q interact.

So the correct delta for a swap is NOT simply d_p - d_q. The previous code was wrong!

However, the error is small in practice because:
- For random p, q (not at shift-related positions), the cross-term is 0
- For targeted (p, p+k_off) swaps, the cross-term is +1 at shift k_off (and possibly -1 at shift -k_off)

So the previous code's approximation is:
- Correct for random swaps (no interaction)
- Off by +1 for targeted swaps at the peak shift

This means the previous code was slightly overestimating the improvement of targeted swaps. It would accept more suboptimal swaps. This explains why it got 0.380891 but couldn't do better.

For N=380: FFT of length 759 takes ~5μs. Evaluating 50 candidates: 250μs. At 4000 evals/sec, in 250s I can do 1M evaluations. That's 20K swaps (each swap = 50 candidate evals). Plenty.

def fft_corr(h):
    N = len(h)
    L = 2 * N - 1
    H = np.fft.rfft(h, L)
    G = np.fft.rfft(np.flip(1.0 - h), L)
    return np.real(np.fft.irfft(H * G, L))
