One key thing: the previous code uses `slsqp_opt` which uses a smooth_c5 objective. This is a smoothed max. The smoothing parameter T controls how "sharp" the approximation is. Low T = smooth (easy to optimize but far from true max). High T = sharp (close to true max but hard to optimize).

The issue is that at high T, the smooth_c5 ≈ max_c5 + (n-1)/T (since there are 2n-1 terms, and at high T, the softplus of the max gap is approximately the log-sum-exp, which for the max element gives approximately 0, and for others gives exp(T*(c_k - m)) which is tiny). So at high T, the smooth objective is very close to the true max, but the gradient is concentrated on the argmax, making it hard to optimize.

A better approach might be to use the "epsilon-insensitive" objective:
f(h) = max_k c_k + ε * (number of k with c_k > max_k - δ)

Or use a "second-order" smoothing:
f(h) = max_k c_k + σ * std(c)

This penalizes not just the max but the spread. Let me try this.

        hc = focused_slsqp(best_h, n, maxiter=1500)
        c5v = compute_c5(hc)
        if c5v < best_c5:
            best_c5 = c5v
            best_h = hc
    except Exception:
        pass
    try:
        hc = slsqp_opt(best_h, 100000, n, maxiter=800, ftol=1e-16)
        c5v = compute_c5(hc)
        if c5v < best_c5:
            best_c5 = c5v
            best_h = hc
    except Exception:
        pass

    best_h = proj(best_h, len(best_h))
    best_c5 = compute_c5(best_h)
    return best_h, best_c5, len(best_h)
