def softmax_grad(corr, h, N, T):
    """Gradient of T*log(sum(exp(corr/T))) w.r.t. h."""
    # Numerical stability
    mc = np.max(corr)
    exp_c = np.exp((corr - mc) / T)
    w = exp_c / exp_c.sum()
    
    grad = np.zeros(N)
    center = N - 1
    for k_idx in range(len(corr)):
        if w[k_idx] < 1e-10:
            continue

One idea: **use the structure of the problem**. The objective is:
min_h max_k C(k) where C(k) = sum_{j=0}^{N-k-1} h[j]*(1-h[j+k])

This is equivalent to:
min_h max_k [sum_{j=0}^{N-k-1} h[j] - sum_{j=0}^{N-k-1} h[j]*h[j+k]]

Let A(k) = sum_{j=0}^{N-k-1} h[j] (the "prefix sum" of h up to N-k)
Let B(k) = sum_{j=0}^{N-k-1} h[j]*h[j+k] (the "autocorrelation" of h at lag k)

C(k) = A(k) - B(k)

We want to minimize max_k [A(k) - B(k)].

Note that A(k) depends on h, and B(k) depends on h. For a given h, both are determined.

For binary h: A(k) = number of 1s in positions 0..N-k-1, B(k) = number of consecutive 1-pairs at distance k.

Key insight: if h is a "balanced" sequence where 1s are evenly distributed, then A(k) ≈ (N-k)/2 for all k. And B(k) is maximized when 1s are close together. To minimize A(k)-B(k), we want B(k) to be as large as possible relative to A(k), meaning we want 1s to cluster together.

But if 1s cluster together, then for large k (beyond the cluster size), B(k) = 0 and A(k) ≈ (N-k)/2, giving C(k) ≈ (N-k)/2.

This suggests a trade-off: clustering helps for small k but hurts for large k.

The optimal structure is probably something like: groups of 1s separated by groups of 0s, with the group sizes chosen to balance the trade-off.
