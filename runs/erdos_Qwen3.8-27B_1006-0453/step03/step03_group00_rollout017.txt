    corr = np.correlate(h, 1.0 - h, mode='full')
    m = np.max(corr)

    h = np.clip(h, 0.0, 1.0)
    target = n / 2.0

    if diff > 0:

        tot = room.sum()

3. Evaluate f at all breakpoints in [0,1] plus 0 and 1.
4. Return the t with minimum f(t).

Number of breakpoints: O(n²) = O((2n-1)²) ≈ 100,000 for n=160. Each evaluation is O(n). Total: O(n³) ≈ 16 million. This might be a bit slow per coordinate (160 coords × 16M = 2.5B per sweep). Too slow.

Better: just use the LP approach or minimize_scalar. minimize_scalar with bounded method does about 30-50 evaluations of a O(n) function, so O(n) per coordinate. One sweep: O(n²). Very fast.

Let me just use minimize_scalar. It's simple and fast enough.

Now, the critical question: how many sweeps of coordinate descent are needed? The previous code does up to 80 sweeps in Phase 3 and 40 in Phase 6. Maybe I should do more, or use a different strategy.

**Idea: alternate between full coordinate descent and SLSQP.**

After each full sweep of coordinate descent, run a quick SLSQP step. This can escape from coordinate descent plateaus.

**Idea: random restarts within coordinate descent.**

If coordinate descent plateaus (no improvement in a sweep), perturb the solution randomly and restart.

**Idea: use a "warm" basin hopping.**

Instead of large random perturbations, use small perturbations that are accepted with a simulated annealing schedule.

    m = np.max(corr)
    shifted = np.clip(T * (corr - m), -500, 500)
    val = m + np.log(np.sum(np.exp(shifted))) / T

            return h
        h += room * (diff / tot)
    else:
        if s < 1e-12:
            return h
        h *= (1.0 + diff / s)

Wait, there's an issue. When I project after each coordinate update, the projection changes all coordinates, not just h[i]. This means the "exact" 1D optimization is invalidated. 

A better approach: **don't project after each coordinate update**. Instead, accumulate the sum error and project at the end of each sweep. Or: use a "dual" approach where I maintain a Lagrange multiplier for the sum constraint.

Actually, the simplest fix: after optimizing h[i], if the sum drifts, distribute the correction uniformly over all other coordinates. The correction is O(1/n) per step, so it's small.
