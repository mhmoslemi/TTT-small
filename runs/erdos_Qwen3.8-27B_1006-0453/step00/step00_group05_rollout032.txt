B+C would give: +h[i+lag] + (1-h[j-lag]) = h[j] + (1-h[i]) = 0+0 = 0
Correction: +1

If A and B are at the same position (i-lag = i, i.e., lag = 0):
At n = i:
Original: h[i]*(1-h[i]) = 0
New: h'[i]*(1-h'[i]) = 0
Change: 0
A+B would give: -(1-h[i]) + h[i+0] = -0 + 1 = 1
Correction: -1

If C and D are at the same position (j-lag = j, i.e., lag = 0):
At n = j:
Original: h[j]*(1-h[j]) = 0
New: h'[j]*(1-h'[j]) = 0
Change: 0
C+D would give: (1-h[j]) + (-h[j]) = 1 + 0 = 1
Correction: -1

So for lag=0, we need corrections -1 and -1, total -2. And A+B+C+D = 0+1+1+0 = 2. 2-2=0. ✓

Also: if A=D (lag=i-j) AND B=C (lag=j-i), that requires i-j=j-i, so i=j. Impossible.

Can A=C? i-lag=j-lag → i=j. No.
Can B=D? i=j. No.
Can A=B? lag=0 (handled above)
Can C=D? lag=0 (handled above)

What about A being at the same position as C? Already showed i=j. No.
What about B being at the same position as D? i=j. No.

What about A being at the same position as B? lag=0. Handled.
What about A=C? No. B=D? No.

Can A be at the same position as D and C be at the same position as B simultaneously?
A=D: lag=i-j. B=C: lag=j-i. Both can't hold unless i=j. No.

So the only colliding pairs are:
- lag=0: A&B collide (correction -1), C&D collide (correction -1). Total correction: -2
- lag=j-i: B&C collide (correction +1)
- lag=i-j: A&D collide (correction +1)

And these are mutually exclusive (can't have lag=0 and lag=j-i simultaneously unless j=i).

Great, so the formula is:
ΔC[m] = A + B + C + D + correction

where:
A = -(1-h[i-lag]) if 0 ≤ i-lag < n else 0
B = h[i+lag] if 0 ≤ i+lag < n else 0
C = (1-h[j-lag]) if 0 ≤ j-lag < n else 0
D = -h[j+lag] if 0 ≤ j+lag < n else 0
correction = -2 if lag==0, +1 if lag==j-i or lag==i-j, 0 otherwise

And C_new[m] = C_old[m] + ΔC[m]

This gives O(1) per m, so O(n) per swap evaluation. For n=70, that's 139 operations per swap (since output length is 2n-1=139). Much faster than O(n²).

But actually, I only need to update the 4 positions that change (A, B, C, D), not all 139! The rest of the correlate is unchanged.

For a fixed i (one position to flip from 1 to 0), the change in C for all j (zeros) can be computed as:
ΔC_from_i[m] = -(1-h[i-k]) * [i-k valid] + h[i+k] * [i+k valid]  (for each m, k=m-(n-1))

This is the same for all j! So I can precompute it for each i.

And ΔC_from_j[m] = (1-h[j-k]) * [j-k valid] - h[j+k] * [j+k valid]

So ΔC[m] = (h[i+k]+h[i-k]-1) * [i±k valid] + (1-h[j-k]-h[j+k]) * [j±k valid] + correction

For each m, this is a scalar computation. I can vectorize over m for a fixed (i,j) pair. But I can also vectorize over j for a fixed i!

For fixed i, the change ΔC[m] from flipping i (1→0) is fixed (doesn't depend on j). Let me call it ΔC_i[m].
For each j, the change from flipping j (0→1) is ΔC_j[m].

Total: ΔC[m] = ΔC_i[m] + ΔC_j[m] + correction(i,j,m)

The correction is only non-zero at specific m values (m where lag = i-j or j-i or 0).

1. Compute ΔC_i[m] for all m (O(n) vectorized)
2. For each j: compute ΔC_j[m] for all m (O(n) vectorized) + correction
3. new_C = C + ΔC_i + ΔC_j
4. new_max = new_C.max()
