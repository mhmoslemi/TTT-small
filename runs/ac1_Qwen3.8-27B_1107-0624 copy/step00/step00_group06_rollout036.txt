Alternative: use a "reduced" set of constraints. Instead of all 2n-1 constraints, use only the "active" ones (those where (a*a)[j] is close to the maximum). This is the "active set" method.

At each iteration:
1. Compute (a*a). Find the peak value p.
2. Select the "active" set: indices j where (a*a)[j] >= p - delta (for some small delta).
3. Solve the LP with only the active constraints.
4. Update a, go to 1.

If the active set is small (say, m << n), the LP has only m + n + 1 constraints, which is much smaller.

But there's a chicken-and-egg problem: we need to know the active set to solve the LP, but the active set depends on the solution.

The standard approach is:
1. Start with all constraints active.
2. Solve the LP.
3. Identify which constraints are "binding" (active at the solution).
4. Keep only the binding constraints (plus a few others) for the next LP.
5. Repeat.

This is the "revision method" for LPs.

For our problem, I think a simpler approach works:
1. At each iteration, select the top-K indices where (a*a)[j] is largest (K is a parameter, say K=100).
2. Solve the LP with only those K constraints.
3. Update a.

def _lp_step_active(a, K=100):
    """One LP step using the top-K active constraints."""
    n = len(a)
    conv = np.convolve(a, a)
    # Find top-K indices
    top_k_idx = np.argsort(conv)[-K:]
    
    # Build the constraint matrix
    # Constraint j: 2 * sum_i a_0[j-i] * a[i] <= t + conv[j]
    # i.e., 2 * sum_i a_0[j-i] * a[i] - t <= conv[j]
    
    rows = []
    rhs = []
    for j in top_k_idx:
        row = np.zeros(n + 1)
        for i in range(n):
            k = j - i
            if 0 <= k < n:
                row[i] = 2.0 * a[k]
        row[n] = -1.0  # coefficient of t
        rows.append(row)
        rhs.append(conv[j])
    
    A_ub = np.array(rows)  # shape (K, n+1)
    b_ub = np.array(rhs)  # shape (K,)
    
    # Objective: minimize t
    c_obj = np.zeros(n + 1)
    c_obj[n] = 1.0
    
    # Constraints: a[i] >= 0 (handled by bounds), sum(a) = 1
    A_eq = np.zeros((1, n + 1))
    A_eq[0, :n] = 1.0
    b_eq = [1.0]
    
    bounds = [(0, None)] * n + [(None, None)]
    
    result = linprog(c_obj, A_ub=A_ub, b_ub=b_ub, A_eq=A_eq, b_eq=b_eq,

        s = new_a.sum()
        if s > 1e-10:

            return new_a
    return a  # fallback: no change

Actually, let me also think about whether there are any known results for this specific problem.

The problem of minimizing the peak of the self-convolution of a non-negative sequence is related to:
1. "Minimum peak-to-mean envelope power ratio" (PMEPR) in OFDM.
2. "Prolate spheroidal sequences" (Slepian sequences).
3. "Fejér kernel" and its variants.

In the OFDM literature, the "MULIN" (minimum unimodular linear) algorithm and "BLISS" (BLind Iterative Sub-Space Search) algorithm are used to reduce PMEPR. These are based on eigenvalue decompositions of the "peak constraint" matrix.

The "BLISS" algorithm works as follows:
1. Compute the peak constraint: identify the samples where the signal exceeds the threshold.
2. Form the "constraint matrix" M = V^H * P * V, where V is a matrix of basis vectors (e.g., DFT vectors) and P is a diagonal matrix with 1 at peak positions and 0 elsewhere.
3. Compute the eigenvector of M corresponding to the largest eigenvalue.
4. Update the signal by projecting it onto this eigenvector.

This is a "spectral" method that works in the frequency domain. It's very effective for reducing peaks.

For our problem, the "signal" is the sequence a (non-negative), and the "peaks" are in the time domain (the self-convolution). The BLISS-like approach would be:
1. Identify the peak positions in (a*a).
2. Form a matrix that penalizes these peaks.
3. Use eigenvalue decomposition to find the "direction" that reduces peaks.
4. Update a.

But the non-negativity constraint makes this more complex. We'd need to project back to the non-negative simplex after each update.

Let me think about a simpler "BLISS-like" approach:
1. Compute conv = (a*a).
2. Find the peak position j*.
3. The gradient at j* is: g[i] = 2*a[j*-i] (if valid).
4. This gradient is a "reflected and shifted" copy of a.
5. To reduce the peak, we want to move a in the direction -g, i.e., reduce a[i] where g[i] is large.
6. g[i] = 2*a[j*-i] is large when a[j*-i] is large, i.e., when i is close to j* - (positions where a is large).

So the "BLISS-like" update is: reduce a[i] where a[j*-i] is large. This effectively "anti-correlates" a with its reflected-shifted version.

This is exactly what the subgradient method does! So the subgradient method is already a "BLISS-like" method.

The key insight from BLISS is to use MULTIPLE peak positions simultaneously (not just the single peak). This is what the soft-max approach does.
