import numpy as np
import time
from scipy.optimize import linprog

def solve_lp_direction(a, M):
    """Solve LP: max sum(b) s.t. convolve(a,b) <= M, b >= 0"""
    n = len(a)
    # Build constraint matrix A such that A @ b <= M * ones(2n-1)
    # A[k, i] = a[i] if 0 <= k-i < n, else 0
    # i.e., A[k, i] = a[i] if max(0, k-n+1) <= i <= min(k, n-1)
    
    # This is a (2n-1) x n matrix
    # A[k, i] = a[i] if i <= k <= i+n-1, i.e., k-i in [0, n-1]
    
    # Actually: convolve(a, b)[k] = sum_{i: 0<=i<n, 0<=k-i<n} a[i]*b[k-i]
    # Let j = k-i, so i = k-j. We need 0<=k-j<n and 0<=j<n.
    # So j ranges from max(0, k-n+1) to min(k, n-1).
    # convolve(a,b)[k] = sum_{j=max(0,k-n+1)}^{min(k,n-1)} a[k-j]*b[j]
    
    # So A[k, j] = a[k-j] if max(0,k-n+1) <= j <= min(k,n-1), else 0
    
    # This is a lower-Hessenberg-like matrix (actually it's a full matrix but structured)
    # For n=4498, this is an 8995 x 4498 matrix, which is about 40M entries.
    # Most are zero, so we should use sparse format.
    
    from scipy.sparse import lil_matrix
    A = lil_matrix((2*n-1, n))
    for k in range(2*n-1):
        j_start = max(0, k-n+1)
        j_end = min(k, n-1)
        for j in range(j_start, j_end+1):
            A[k, j] = a[k-j]
    A = A.tocsr()
    
    # Objective: max sum(b) = -min -sum(b)

Wait, this has an issue. The LP solution gives a direction, but the "sum" normalization might not be the right one. Let me reconsider.

The LP maximizes sum(b) subject to conv(a, b) <= M and b >= 0. The solution b* satisfies conv(a, b*) <= M elementwise.

If we update a_new = (1-t)*a + t*b*, then:
conv(a_new, a_new) = (1-t)^2 conv(a,a) + 2t(1-t) conv(a, b*) + t^2 conv(b*, b*)
<= (1-t)^2 M + 2t(1-t) M + t^2 conv(b*, b*)
= M((1-t)^2 + 2t(1-t)) + t^2 conv(b*, b*)
= M(1-t) + t^2 conv(b*, b*)

For small t, this is approximately M(1-t) + t^2 * conv(b*,b*) ≈ M - t*M + t^2*conv(b*,b*).

If conv(b*, b*) < M (which it should, since b* is a "flatter" direction), then for small t, the new peak is less than M. Good.

But the sum of a_new is: (1-t)*sum(a) + t*sum(b*). If we want to keep the sum the same, we need to normalize.

Actually, since the objective is homogeneous, we don't need to keep the sum the same. The score 2n*max_b/(sum)^2 is invariant under scaling. So we can just work with the unscaled values.

Let me simplify: just update a = (1-t)*a + t*direction, without normalizing. The objective will be the same regardless of scaling.

But we need to be careful: if the sum becomes too small (< 0.01), the evaluator returns inf. So we should ensure the sum stays reasonable.

For n=4498, building the sparse matrix takes O(n^2) time and memory. The LP solve with HiGHS on a 8995 x 4498 sparse matrix with ~10M non-zeros... I'm not sure how fast that will be.

Let me think of an alternative: instead of solving the full LP, use a simpler approximation.

**Approximate LP (Greedy Water Filling):**

The LP wants to maximize sum(b) subject to conv(a, b) <= M. A greedy approximation:

1. Initialize b = 0
2. For j = 0 to n-1:
   - Compute the current conv(a, b_partial) where b_partial has b[0..j-1] set
   - Find the maximum value b[j] can take: b[j] <= min_k (M - conv(a,b)[k]) / a[k-j] over all k where a[k-j] > 0
   - Set b[j] to that maximum
3. Repeat until b converges (or just do one pass)

This is O(n^2) per pass (computing conv(a, b) is O(n^2) naively, but can be done in O(n log n) with FFT).

Actually, for n=4498, O(n^2) = 20M operations per pass, which is very fast in numpy. And we only need a few passes.
