So the recursive approach is worse for n=3! The problem is that by trying to make c[0]=c[1]=c[2]=... equal, we end up with a large c[2] (the middle element).

This makes sense: for a symmetric sequence, c[n-1] (the middle) tends to be the largest. The recursive approach makes the "edges" flat but the center bulges.

So what we really want is to make the CENTER as small as possible, since that's typically the bottleneck.

c[n-1] = sum_{j=0}^{n-1} a[j] * a[n-1-j]

For a symmetric sequence (a[j] = a[n-1-j]), this is sum a[j]^2, which by Cauchy-Schwarz is >= (sum a[j])^2 / n = 1/n (for sum=1).

For a non-symmetric sequence, c[n-1] = sum a[j]*a[n-1-j] can be smaller! If a[j] and a[n-1-j] have "disjoint" support (large a[j] where a[n-1-j] is small and vice versa), then c[n-1] can be close to 0.

For example, if a = [1, 0, 0, ..., 0] (all mass at position 0):
c[n-1] = a[0]*a[n-1] + a[1]*a[n-2] + ... = 1*0 + 0*0 + ... = 0

But then c[0] = a[0]^2 = 1, which is huge.

The tradeoff is: we want to spread the mass so that no single c[k] is too large. The optimal balance depends on n and the structure.

**Key insight**: The optimal sequence is NOT symmetric in general! A non-symmetric sequence can have a smaller max autocorrelation than any symmetric sequence.

This is because for a non-symmetric sequence, c[n-1] = sum a[j]*a[n-1-j] can be made small by having a[j] and a[n-1-j] "avoid" each other.

For example, if a[0] is large and a[n-1] is small (and vice versa for other positions), then the product a[j]*a[n-1-j] is small for all j.

This suggests a "tilted" or "asymmetric" design: large values on one side, small values on the other, arranged to minimize the cross-products.
