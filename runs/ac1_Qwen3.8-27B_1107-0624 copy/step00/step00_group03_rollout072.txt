So the total convolution has:
- A triangle peaking at m, centered at lag m-1 (auto of block 1)
- A triangle peaking at m, centered at lag 2m+g-1 (auto of block 2)
- Two cross terms: triangles peaking at m, centered at lag m+g-1 (block1-block2) and lag m+g-1 (block2-block1)

Wait, the cross terms:
conv[block1, block2] has a triangle of width 2m-1, centered at lag (m+g) - 1 = m+g-1, peak m.
conv[block2, block1] has the same shape (by symmetry of the two identical blocks).

So the total has three triangles, each peaking at m:
- At lag m-1 (auto of block 1)
- At lag m+g-1 (cross, doubled since both directions contribute)
- At lag 2m+g-1 (auto of block 2)

The cross triangle has peak 2m (since both conv[block1,block2] and conv[block2,block1] contribute).

So max_c = 2m (at the center of the cross-correlation), unless m > 2m which is never the case.

Wait, that means the cross-correlation peak (2m) is larger than the auto-correlation peaks (m). So max_c = 2m.

Same as before! So two identical blocks don't help.

What if the blocks have different heights?
a = [h1]*m1 + [0]*g + [h2]*m2

Auto of block 1: peak = h1^2 * m1
Auto of block 2: peak = h2^2 * m2
Cross: peak = 2 * h1 * h2 * min(m1, m2) (if m1 = m2 = m, peak = 2*h1*h2*m)

sum = h1*m1 + h2*m2

For the peaks to be equal: h1^2*m1 = h2^2*m2 = 2*h1*h2*min(m1,m2)

If m1 = m2 = m: h1^2*m = 2*h1*h2*m => h1 = 2*h2
And h2^2*m = 2*h1*h2*m => h2 = 2*h1

These are contradictory unless h1 = h2 = 0. So we can't equalize all three peaks with equal-length blocks.

What about different-length blocks?
m1 ≠ m2. Say m1 = m, m2 = 2m.
Auto 1: peak = h1^2*m
Auto 2: peak = h2^2*2m
Cross: peak = 2*h1*h2*m (since min(m,2m) = m)

Setting equal: h1^2*m = 2*h1*h2*m => h1 = 2*h2
And: h2^2*2m = 2*h1*h2*m => 2*h2 = 2*h1 => h2 = h1

Contradiction again.

What about three blocks? This gets even more complex.

I think the fundamental issue is that for non-negative sequences, the autocorrelation always has significant structure that prevents it from being perfectly flat. The best we can do is balance the peaks.

Let me think about this differently. What if we use a sequence where the values vary smoothly, creating a "spread out" autocorrelation?

Consider a[j] = sin(πj/(n-1))^p for different p values.
- p=1: linear taper (sin)
- p=2: quadratic taper
- p=0.5: more peaked

The autocorrelation of sin(πx) on [0,1] is:
R(τ) = ∫_0^{1-τ} sin(πx)*sin(π(x+τ)) dx → this gives a smooth function of τ.

For the discrete case, the autocorrelation of the sine window is also smooth (it's related to the sine of the lag times a sinc-like function).

I think the practical approach is:
1. Use a tapered initial guess (sine or cosine window)
2. Use the gradient-based method to optimize
3. The key is that the gradient method should be able to find the optimal perturbations

Let me focus on making the gradient method work well. The key issues are:
1. Step size: should be related to the condition number of the problem
2. Beta for soft-max: should be high enough to focus on the true max, but not so high that it becomes numerically unstable
3. Escape from local minima: periodic noise injection
