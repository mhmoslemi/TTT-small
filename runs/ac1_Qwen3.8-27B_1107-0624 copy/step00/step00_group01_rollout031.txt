    # Clip to avoid overflow
    shifted = np.clip(shifted, -50, 50)
    weights = np.exp(shifted)
    w_sum = np.sum(weights)
    weights /= w_sum
    smax = c_max + np.log(w_sum) / beta
    return smax, weights

    # = 2 * correlate(weights, a, 'valid')[i]

    """Perform gradient descent steps to minimize smooth max of a*a."""

        if S < 1e-10:

def compute_objective_fast(a):

    """Compute gradient of smooth max of a*a with respect to a."""
    c = np.convolve(a, a)
    c_max = np.max(c)
    shifted = beta * (c - c_max)
    shifted = np.clip(shifted, -100, 100)
    weights = np.exp(shifted)
    weights /= np.sum(weights)
    # g[i] = 2 * sum_j weights[j+i] * a[j]
    h = np.correlate(weights, a, mode='valid')
    return 2.0 * h

    S = np.sum(a)
    eta = 1.0
    func = compute_objective_fast(a)

        a_new = np.maximum(a_new, 0)
        S_new = np.sum(a_new)

        else:
            return a, eta
        func_new = compute_objective_fast(a_new)
        if func_new < func:
            return a_new, eta

The sum of all $(a*a)[k]$ is $S^2$, spread over $2n-1$ values. The average is $S^2/(2n-1) < S^2/n$. So we need the maximum to be less than $S^2/n$ but at least $S^2/(2n-1)$.

This means the convolution should be "flatter than triangular" - the peak should be less than the triangular peak ($S^2/n$) but above the uniform value ($S^2/(2n-1)$).

For a triangular convolution (uniform sequence), the peak is $S^2/n$ (approximately). We need to reduce the peak by making the convolution more "peaky in the wrong places" - i.e., having the energy spread more evenly.

One way: use a sequence whose "power spectrum" (in the circular sense) is concentrated at certain frequencies, making the circular autocorrelation have a specific shape.

Actually, let me think about it differently. If the circular autocorrelation is $R[m] = c_0 + \sum_{k=1}^{n/2} c_k \cos(2\pi k m/n)$, then:
- $R[0] = c_0 + \sum c_k$ (the peak)
- The linear convolution in the middle approximates this.
- $S^2/n = R[0]$ (by Parseval, for the circular case).

Wait, that's circular. Let me be more careful.

For the circular autocorrelation $R[m] = \sum_i a_i a_{(i+m) \mod n}$:
$R[0] = \sum a_i^2$
$S^2 = \sum_i \sum_j a_i a_j = \sum_m R[m]$

So the average of the circular autocorrelation is $S^2/n$, and $R[0] = \sum a_i^2 \geq S^2/n$ (by Cauchy-Schwarz), with equality iff $a_i$ is constant.

So for the circular case, $R[0] \geq S^2/n$, meaning the peak of the circular autocorrelation is always at least $S^2/n$. The score for the circular case would be $J_{circ} = 2n R[0] / S^2 \geq 2$.

But we're dealing with the LINEAR convolution, not circular! The linear convolution at the center $(a*a)[n-1] = \sum_i a_i a_{n-1-i}$ is NOT the same as $R[0] = \sum_i a_i^2$.

For the linear convolution:
- $(a*a)[n-1] = \sum_i a_i a_{n-1-i}$ (the "anti-correlation" or "flip correlation")
- $(a*a)[n-1+j] = \sum_i a_i a_{n-1+j-i}$ for $j = 0, ..., n-1$ (right side)
- $(a*a)[n-1-j] = \sum_i a_i a_{n-1-j-i}$ for $j = 1, ..., n-1$ (left side)

The maximum could be at the center or off-center, depending on the sequence.

For a symmetric sequence ($a_i = a_{n-1-i}$), $(a*a)[n-1] = \sum_i a_i^2 = R[0]$ (the zero-lag circular autocorrelation). In this case, the peak is at least $S^2/n$ and the score is at least 2.

But for a NON-symmetric sequence, $(a*a)[n-1] = \sum_i a_i a_{n-1-i}$ can be LESS than $S^2/n$! Because the "flip correlation" can be lower than the "direct correlation."

This is the key insight! **By making the sequence non-symmetric (non-palindromic), we can reduce the center value of the linear convolution below $S^2/n$, potentially achieving a score below 2.**

For example, consider a sequence that's "lopsided" - high on one side, low on the other. The flip correlation $\sum a_i a_{n-1-i}$ will be low because the high values on one side are multiplied by low values on the other side.

But we also need to check that the OTHER lags of the linear convolution don't exceed the center. The peak might shift to an off-center lag.
