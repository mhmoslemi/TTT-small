`grad = corr(p, s) + corr(p, s_flipped)` or something like that.

Actually, let me think of it differently. Define a vector `w` of length 2n-1 (same as the convolution output) where `w[k] = p[k]`. Then:

`grad_j = sum_k w[k] * s[j + k - (n-1)] * I(0 <= j+k-(n-1) < n) + s[j - k + (n-1)] * I(0 <= j-k+(n-1) < n)`

The first term is like a "cross-correlation" of w with s (with appropriate alignment).

I can compute this using FFT:
- Zero-pad s to length 4n (or the next power of 2)
- Zero-pad w to the same length
- Compute the cross-correlation via FFT

But for simplicity and correctness, let me just use the direct O(n^2) approach with numpy vectorization. For n up to 4096, this should be fine.

Here's the vectorized gradient computation:

```python
def compute_grad_sm(s, p):
    """Compute gradient of soft-max autocorrelation w.r.t. s.
    p is the softmax weight vector of length 2n-1.
    """
    n = len(s)
    grad = np.zeros(n)
    
    # Lag 0: k = n-1
    if p[n-1] > 0:
        grad += 2.0 * p[n-1] * s
    
    # Non-zero lags (using symmetry)
    for lag in range(1, n):
        pk = p[n-1+lag] + p[n-1-lag]
        if pk < 1e-12:
            continue
        # Contribution from s[j+lag] (valid for j = 0, ..., n-lag-1)
        grad[:n-lag] += pk * s[lag:]
        # Contribution from s[j-lag] (valid for j = lag, ..., n-1)
        grad[lag:] += pk * s[:n-lag]
    
    return grad
```

This is O(n^2) in the worst case (when all p[k] are non-negligible). But in practice, with a large enough tau, only a few p[k] values are significant, so the effective complexity is O(n * num_significant_peaks).

However, for the initial iterations with small tau, many p[k] will be significant. Let me add a threshold:

```python
threshold = 1e-10
for lag in range(1, n):
    pk = p[n-1+lag] + p[n-1-lag]
    if pk < threshold:
        continue
    ...
```

This should make it fast in practice.

```python
import numpy as np
import time

"""
Multi-scale soft-max gradient descent with momentum to minimize
2n*max(conv(s,s))/(sum(s))^2 for non-negative sequences.
Uses log-sum-exp smoothing of the max, adaptive temperature, 
backtracking line search, and multi-scale refinement.
"""

def fast_score(s):
    n = len(s)
    S = np.sum(s)
    if S < 1e-15:
        return float('inf')
    c = np.convolve(s, s)
    return 2.0 * n * np.max(c) / (S * S)

def compute_grad_sm(s, p):
    n = len(s)
    grad = np.zeros(n)
    if p[n-1] > 1e-12:
        grad += 2.0 * p[n-1] * s
    for lag in range(1, n):
        pk = p[n-1+lag] + p[n-1-lag]
        if pk < 1e-12:
            continue
        grad[:n-lag] += pk * s[lag:]
        grad[lag:] += pk * s[:n-lag]
    return grad

def soft_max_obj_grad(s, tau):
    n = len(s)
    S = np.sum(s)
    c = np.convolve(s, s)
    u = tau * c
    u = u - u.max()
    exp_u = np.exp(u)
    p = exp_u / exp_u.sum()
    soft_max_val = np.dot(p, c)
    grad_sm = compute_grad_sm(s, p)
    obj = 2.0 * n * soft_max_val / (S * S)
    obj_grad = (2.0 * n / (S * S)) * grad_sm - (4.0 * n * soft_max_val / (S ** 3))
    return obj, obj_grad

def optimize(s_init, n, tau_start, tau_end, max_iters, deadline, rng, use_momentum=True):
    s = s_init.copy()
    s = np.maximum(s, 0.0)
    S = s.sum()
    if S < 1e-15:
        return s_init, fast_score(s_init)
    s = s / S
    
    best_s = s.copy()
    best_score = fast_score(s)
    
    eta = 0.05
    momentum = np.zeros(n)
    beta = 0.9
    tau = tau_start
    no_imp = 0
    
    for it in range(max_iters):
        if time.monotonic() > deadline:
            break
        
        _, grad = soft_max_obj_grad(s, tau)
        
        if use_momentum:
            momentum = beta * momentum + (1.0 - beta) * grad
            direction = momentum
        else:
            direction = grad
        
        # Line search
        S = np.sum(s)
        c = np.convolve(s, s)
        f0 = 2.0 * n * np.max(c) / (S * S)
        
        found = False
        for ls in range(30):
            step = eta * (0.5 ** ls)
            s_new = s - step * direction
            s_new = np.maximum(s_new, 0.0)
            S_new = s_new.sum()
            if S_new < 1e-15:
                continue
            s_new = s_new / S_new
            f_new = fast_score(s_new)
            if f_new < f0 - 1e-14:
                s = s_new
                found = True
                break
        if not found:
            no_imp += 1
            if no_imp > 10:
                # Perturb
                s = s + 0.002 * rng.standard_normal(n)
                s = np.maximum(s, 0.0)
                s = s / s.sum()
                momentum *= 0.5
                no_imp = 0
                eta = 0.01
            continue
        
        # Update tau (decrease over time to sharpen)
        tau = max(tau_end, tau * 0.995)
        
        cur_score = fast_score(s)
        if cur_score < best_score - 1e-12:
            best_score = cur_score
            best_s = s.copy()
            no_imp = 0
    
    return best_s, best_score
```

Now, let me think about the multi-scale strategy and initializations.

For initializations at a given scale n:
1. Uniform + noise
2. Parameterized families (ramp, exponential, two-level, bump)
3. Upsampled from a smaller scale
4. Random

Let me also think about the **number of iterations** I can afford. Each iteration involves:
- Computing the convolution: O(n log n) with FFT or O(n^2) directly
- Computing the gradient: O(n * num_peaks) ≈ O(n) for large tau
- Line search: up to 30 evaluations of fast_score, each O(n^2) or O(n log n)

For n = 2048:
- conv: ~2*2048*log2(2048) ≈ 45k operations (FFT)
- gradient: ~2048 * (number of significant peaks) ≈ 2048 * 10 = 20k
- line search: 30 * 45k = 1.35M

Total per iteration: ~2M operations. In Python with numpy, this might take about 1-5 ms per operation, so maybe 1-10 ms per iteration.

In 1800 seconds, I can do about 180K to 1.8M iterations. That's plenty.

But wait, the line search is the bottleneck. If I use FFT-based convolution, the line search becomes faster. Let me use FFT:

```python
def fast_conv(s):
    n = len(s)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()  # next power of 2
    S = np.fft.rfft(s, fft_size)
    c = np.fft.irfft(S * S, fft_size)[:size]
    return c
```

This should be much faster for large n.
