Actually, a better local search:
- Identify the peak position `k*` in the convolution.
- The peak is `(a*a)[k*] = Σ_j a[j]·a[k*-j]`.
- To reduce this peak, we want to reduce the products `a[j]·a[k*-j]`.
- The most effective way is to reduce the larger of `a[j]` and `a[k*-j]` for the pairs with the largest product.
- Move mass from those positions to positions that don't contribute to the peak.

This is a greedy peak-reduction strategy. Let me implement it:

```python
def peak_reduction(f, n_steps=100):
    """Greedy peak reduction: move mass from peak-contributing positions to non-peak positions."""
    f = f.copy()
    n = len(f)
    for step in range(n_steps):
        c = np.convolve(f, f)
        k_star = int(np.argmax(c))
        peak = c[k_star]
        
        # Find the pair (j, k_star - j) with the largest product
        best_j = -1
        best_prod = 0
        for j in range(n):
            k2 = k_star - j
            if 0 <= k2 < n:
                prod = f[j] * f[k2]
                if prod > best_prod:
                    best_prod = prod
                    best_j = j
        
        if best_j < 0:
            break
        
        j = best_j
        k2 = k_star - j
        
        # Move a small amount of mass from the larger of f[j], f[k2] to a position that doesn't affect the peak
        if f[j] >= f[k2]:
            src = j
        else:
            src = k2
        
        # Find a destination that minimizes the increase in other peaks
        # Simple heuristic: move to a position where f is already small
        dst = int(np.argmin(f))
        
        # Move a small amount
        delta = 0.01 * f[src]
        f[src] -= delta
        f[dst] += delta
        f = np.maximum(f, 0)
        f = f / f.sum()
    
    return f
```

**Another idea: Use a "water-filling" approach.**

The convolution peak at lag k is `Σ_j a[j]·a[k-j]`. We want all peaks to be equal (by the minimax principle). So we want:
`a[j]·a[k-j]` to be "balanced" across all (j, k) pairs.

This is similar to the "flat spectrum" problem in signal processing. A flat spectrum (in the frequency domain) corresponds to a specific time-domain shape.

Actually, for a periodic sequence, a flat power spectrum means the autocorrelation is a delta (only the zero lag is non-zero). For a non-periodic (finite) sequence, we can't have a perfectly flat spectrum, but we can get close.

The DFT of a finite sequence `a` has `|A[k]|^2 = Σ_j Σ_l a[j]a[l] e^{-2πi(k(j-l))/n}`. The "flat spectrum" condition is `|A[k]| = constant` for all k. This means the periodic autocorrelation is a delta.

For a linear (non-periodic) autocorrelation to be flat, we need a different condition. But the idea is similar: we want the autocorrelation to be as "spread out" as possible (no peaks).

**Practical approach: Optimize in the frequency domain.**

If we parameterize `a` as `a = IDFT(φ)` where `φ` is a complex frequency-domain representation, then the autocorrelation peak is related to the "peakiness" of `|φ|^2`. But the constraint `a >= 0` becomes a constraint in the frequency domain, which is hard.

```python
def local_search(f, deadline, rng, max_iters=5000):

        c = np.convolve(f, f)
        k_max = int(np.argmax(c))

        contribs = []
        for j in range(n):
            k2 = k_max - j
            if 0 <= k2 < n:
                contribs.append((f[j]*f[k2], j, k2))
        contribs.sort(reverse=True)
        
        improved = False
        for prod, j, k2 in contribs[:5]:
            if j == k2: continue

            bigger = j if f[j] >= f[k2] else k2
            smaller = k2 if f[j] >= f[k2] else j
```

**Another idea: Use the LP dual variables to guide the optimization.**

When we solve the LP `max sum(g) s.t. (f*g)[k] <= M, g >= 0`, the dual variables `y_k` tell us which constraints are active. The active constraints correspond to the lags `k` where `(f*g)[k]` is at its maximum (equal to M). These are the "important" lags.

We can use this information: after blending `f` with `g`, the new `f` should have its mass distributed such that the convolution peaks at the identified lags are reduced. We can directly adjust `f` to reduce the contribution to those specific lags.
