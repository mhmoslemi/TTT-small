For complex sequences (allowing negative values), it's known that one can get very close to the lower bound using Barker-like codes or m-sequences. For non-negative sequences, the problem is harder.

Let me think about what structure would help. If we could make conv(p,p) as flat as possible (all values equal to 1/(2n-1)), we'd achieve the lower bound. But this requires the DFT of p to have constant magnitude (a "flat spectrum" sequence), which for non-negative sequences is very restrictive.

A flat magnitude DFT for a non-negative sequence of length n means |DFT(p)[k]| = 1/sqrt(2n-1) for all k. But the DC component is DFT(p)[0] = sum(p) = 1, which is much larger than 1/sqrt(2n-1) for large n. So a truly flat spectrum is impossible for non-negative sequences (since the DC is always 1).

This means the autocorrelation will always have a "bump" at lag 0 (or near it) that's larger than the average. The question is how large this bump can be.

For the uniform sequence, conv[0] = sum(p^2) = 1/n, and the average is 1/(2n-1). The ratio is (2n-1)/n ≈ 2. So the peak is about 2x the average, giving a score of about 2 (which matches our earlier calculation).

To do better, we need to reduce the ratio max(conv)/average, i.e., make the autocorrelation more uniform.

One approach: make the sequence have "negative correlation" at certain lags. But since the sequence is non-negative, we can't have negative values. However, we can have alternating high and low values, which creates destructive interference in the autocorrelation at certain lags.

For example, a two-level sequence [H, L, H, L, ...] with H > L > 0:
- conv[0] = (n/2)(H^2 + L^2)
- conv[1] = (n/2 - 1) * 2HL ≈ n*HL
- conv[2] = (n/2 - 1)(H^2 + L^2) ≈ (n/2)(H^2+L^2)

The ratio conv[0]/conv[2] ≈ 1 (approximately). And conv[1] = n*HL. If H*L < (H^2+L^2)/2, then conv[1] < conv[0], so the peak is at lag 0 and 2.

To minimize the peak, we want to balance conv[0] and conv[1]:
(n/2)(H^2+L^2) = n*HL
(H^2+L^2)/2 = HL
H^2 - 2HL + L^2 = 0
(H-L)^2 = 0
H = L

So the two-level alternating sequence doesn't help! The peak is always at lag 0 for non-negative sequences.

This makes sense: for non-negative sequences, conv[0] = sum(p^2) is always the "natural" peak, and any attempt to reduce it just shifts energy to other lags.

def fast_score(s):
    """Compute 2n*max(conv(s,s))/(sum(s))^2."""
    n = len(s)
    total = s.sum()
    if total < 1e-15:
        return float('inf')

def compute_soft_subgradient(s, beta):
    """Compute soft subgradient of max(conv(s,s))."""
    n = len(s)
    conv = np.convolve(s, s)
    max_conv = conv.max()
    if max_conv < 1e-15:
        return np.zeros(n), conv, 0.0
    
    weights = np.exp(beta * (conv - max_conv) / max_conv)
    weights = weights / weights.sum()
    
    # g[j] = 2 * sum_m weights[j+m] * s[m]
    s_flip = s[::-1]
    conv_ws = np.convolve(weights, s_flip)
    g = 2.0 * conv_ws[n-1 : 2*n-1]
    
    return g, conv, max_conv

def lp_direction(s, M, time_limit=3.0):
    """LP: max sum(b) s.t. conv(s,b)[k] <= M, b >= 0."""
    n = len(s)
    # A matrix: A[k, j] = s[k-j] if 0<=k-j<n, else 0
    # This is the convolution matrix
    A = np.zeros((2*n-1, n))
    for j in range(n):
        A[j:j+n, j] = s
    c = -np.ones(n)
    b_ub = np.full(2*n-1, M)
    bounds = [(0.0, None)] * n
    try:
        res = linprog(c, A_ub=A, b_ub=b_ub, bounds=bounds, method='highs',
                      options={'time_limit': time_limit, 'presolve': True})
        if res.success and res.x is not None:
            return np.maximum(res.x, 0.0)
    except Exception:
        pass
    return None

def diverse_starts(n, rng):

        s = 1 + a * (2*x - 1)
        s = np.maximum(s, 0.01)
        candidates.append(s / s.sum())
    
    # Exponential
    for alpha in [-2, -1, 1, 2]:
        s = np.exp(alpha * x)
        candidates.append(s / s.sum())
    
    # Two-level
    for frac in [0.3, 0.5, 0.7]:
        k = int(frac * n)
        for ratio in [2.0, 3.0, 5.0]:
            s = np.ones(n)
            s[:k] = ratio
            candidates.append(s / s.sum())
    
    # Alternating (two-level with high contrast)
    for ratio in [1.5, 2.0, 3.0]:
        s = np.ones(n)
        s[::2] = ratio
        candidates.append(s / s.sum())
    
    # Random
    for _ in range(10):
        s = rng.random(n) + 0.01
        candidates.append(s / s.sum())
    
    return candidates
