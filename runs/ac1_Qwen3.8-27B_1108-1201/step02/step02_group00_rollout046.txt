import numpy as np
import time
from scipy.optimize import minimize

def fast_convolve(a):
    """Linear auto-convolution via FFT."""
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    A = np.fft.rfft(a, fft_size)
    return np.fft.irfft(A * A, fft_size)[:size]

def project_simplex(v):
    """Euclidean projection onto probability simplex."""
    n = len(v)
    if n == 1:
        return np.array([max(0.0, v[0])])
    u = np.sort(v)[::-1]
    cssv = np.cumsum(u)
    cond = u * np.arange(1, n + 1) > (cssv - 1)
    if not cond.any():
        return np.ones(n) / n
    rho = np.nonzero(cond)[0][-1]
    theta = (cssv[rho] - 1.0) / (rho + 1.0)
    return np.maximum(v - theta, 0.0)

def lse_max(conv, beta):
    """Log-sum-exp approximation to max."""
    m = conv.max()
    if beta < 1e-10:
        return m
    scaled = beta * (conv - m)
    return m + np.log(np.sum(np.exp(scaled))) / beta

- `result[2] = a[0]*b[2] + a[1]*b[1] + a[2]*b[0] = 1*1 + 0*0 + 1*1 = 2`
- `result[3] = a[0]*b[3] + a[1]*b[2] + a[2]*b[1] + a[3]*b[0] = 0 + 0 + 0 + 0 = 0`
- `result[4] = a[1]*b[3] + a[2]*b[2] + a[3]*b[1] = 0 + 1 + 0 = 1`
- `result[5] = a[2]*b[3] + a[3]*b[2] = 0 + 0 = 0`
- `result[6] = a[3]*b[3] = 0`

So `max = 2`, `sum = 2`, `n = 4`, objective = `2*4*2/4 = 4`.

OK so I was right that the convolution at position 0 is just `a[0]^2`, not `sum(a_i^2)`.

The key constraint is:
- `(a*a)[n-1] = sum_i a[i] * a[n-1-i]` (the "center" of the convolution)
- By Cauchy-Schwarz: `(a*a)[n-1] <= sum(a_i^2) * sum(a_{n-1-i}^2)`... wait, that's not helpful.
- Actually, `(a*a)[n-1] = sum_i a[i] * a[n-1-i] <= (sum a_i) * max(a_i)`... not helpful either.

The key point is that there's NO lower bound of 2 on the objective! The conv[0] = a[0]^2 can be very small, and the max could be at a different position.

So what's the actual lower bound? We have:
- `sum_k (a*a)[k] = (sum a_i)^2` (Parseval / total energy)
- There are `2n-1` values
- So `max_k (a*a)[k] >= (sum a)^2 / (2n-1)`
- Objective >= `2n / (2n-1) ≈ 1`

So the lower bound is about 1, and we're at 1.5. The question is how much of the "gap" is due to the non-negativity constraint.

OK, so now I understand the problem correctly. Let me think about what kind of sequences can achieve low values.

For the target of ~1.5, we need `max(conv) ≈ 1.5 * S^2 / (2n) = 0.75 * S^2 / n`.

The "average" value of the convolution is `S^2 / (2n-1) ≈ S^2 / (2n)`. So we need the max to be about 3x the average. That's actually not too bad - it means the convolution is fairly flat.

For a truly flat convolution (all values = S^2/(2n-1)), we'd get objective = 2n/(2n-1) ≈ 1. Getting 1.5 means the peak is about 50% above average. That's quite flat!

So the goal is to make the autocorrelation as flat as possible. This is essentially the "low peak factor" problem or "flat spectrum" design.

Now, what structures achieve a flat autocorrelation with non-negative sequences?

One approach: sequences that are "spread out" with varying amplitudes. For instance, a Gaussian distribution gives a roughly Gaussian autocorrelation (which peaks at the center). A more "spread" distribution might give a flatter autocorrelation.

def fast_convolve(a):
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    A = np.fft.rfft(a, fft_size)
    return np.fft.irfft(A * A, fft_size)[:size]

def project_simplex(v):
    n = len(v)
    if n == 1:
        return np.array([max(0.0, v[0])])
    u = np.sort(v)[::-1]
    cssv = np.cumsum(u)
    cond = u * np.arange(1, n + 1) > (cssv - 1)
    if not cond.any():
        return np.ones(n) / n
    rho = np.nonzero(cond)[0][-1]
    theta = (cssv[rho] - 1.0) / (rho + 1.0)
    return np.maximum(v - theta, 0.0)
