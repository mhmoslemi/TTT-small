Let me think about this more carefully. The standard FW step is:
g = argmin_{g in simplex} <∇f(a), g>

Where ∇f(a) is a subgradient of f at a. For f(a) = max_k (a*a)[k], a subgradient at a is:
∇f(a)[j] = sum_{k in argmax} (a[j+k] + a[j-k]) (with appropriate bounds)

The FW step then becomes:
g = argmax_{g in simplex, g >= 0} sum_j g[j] * (-∇f(a)[j])
  = put all mass on the j with minimum ∇f(a)[j]

Wait, that's not right. The FW step for minimizing f over the simplex is:
g = argmin_{g in simplex} <∇f(a), g>

Since the simplex is {g >= 0, sum g = 1}, and the objective is linear in g, the minimum is achieved by putting all mass on the j with minimum ∇f(a)[j].

But that's a vertex of the simplex, which is a unit vector e_j. This is the "vertex SWAP" method, which is a simplified version of FW.

The LP oracle generalizes this: instead of just finding the best vertex, it finds the best point in the intersection of the simplex with the constraint set {(f*g)[k] <= M}. This allows for a "spread" of mass across multiple coordinates, which is better.

Now let me think about the peak surgery approach more carefully.

**Peak Surgery Algorithm:**

Given a, find the top K peaks in conv(a,a). For each peak at position k:
- The peak value is R(k) = sum_j a[j] * a[k-j]
- The "donor" coordinates are those j where a[j] * a[k-j] is large
- We want to move mass from donor to a "safe" recipient

For the recipient, we want a coordinate u such that:
- Increasing a[u] has minimal impact on all top peaks
- The impact on peak k' is: a[u+k'] + a[u-k'] (with bounds)

So the "safety score" of coordinate u is:
safety(u) = sum_{k' in top_peaks} (a[u+k'] + a[u-k'])^2 (with bounds)

We want to minimize this.

For the donor, we want a coordinate d such that:
- a[d] is large
- The contribution to the target peak k is high: a[d] * (a[d+k] + a[d-k])
- The "damage" to other peaks is low

Algorithm:
1. For the target peak k, compute contribution[d] = a[d] * (a[d+k] + a[d-k]) for all d
2. Compute damage[d] = sum_{k' != k} (a[d+k'] + a[d-k'])^2 for all d
3. Donor score = contribution[d] / (damage[d] + eps)
4. Recipient score = sum_{k'} (a[u+k'] + a[u-k'])^2 (minimize this)
5. Move a small fraction of a[donor] to a[recipient]
6. Check if the max peak decreased; if so, accept

This is O(K * n) per iteration, which is fast.
