```python
import cvxpy as cp

def active_set_lp(h_curr, n, top_m=50, max_iter_lp=100):
    dx = 2.0 / n
    c_all = np.correlate(h_curr, 1.0 - h_curr, mode="full") * dx
    c_max = c_all.max()
    
    # Select active shifts
    active_mask = c_all > c_max - 0.005
    active_idx = np.where(active_mask)[0]
    
    h_var = cp.Variable(n)
    t_var = cp.Variable()
    
    constraints = [h_var >= 0, h_var <= 1, cp.sum(h_var) == n/2.0]
    
    for idx in active_idx:
        shift = idx - (n - 1)
        # Compute gradient of c_shift at h_curr
        grad = np.zeros(n)
        for j in range(n):
            g = 0.0
            if 0 <= j - shift <= n - 1:
                g += (1 - h_curr[j - shift])
            if 0 <= j + shift <= n - 1:
                g += (-h_curr[j + shift])
            grad[j] = g
        grad *= dx
        # Linearized constraint: c_shift(h_curr) + grad^T (h - h_curr) <= t
        constraints.append(c_all[idx] + grad @ (h_var - h_curr) <= t_var)
    
    obj = cp.Minimize(t_var)
    prob = cp.Problem(obj, constraints)
    prob.solve(solver=cp.ECOS)  # or GLPK, CLARABEL
    
    if h_var.value is not None:
        return np.clip(h_var.value, 0, 1)
    return h_curr
```

```python
def vec_grad(h, s, n):
    dx = 2.0 / n
    # Part 1: (1-h[j-s]) for j where 0<=j-s<=n-1
    # This is (1-h) shifted right by s (with zeros)
    p1 = np.zeros(n)
    if s >= 0:
        p1[s:] = 1 - h[:n-s]
    else:
        p1[:n+s] = 1 - h[-s:]
    # Part 2: -h[j+s] for j where 0<=j+s<=n-1
    p2 = np.zeros(n)
    if s >= 0:
        p2[:n-s] = -h[s:]
    else:
        p2[-s:] = -h[:n+s]
    return dx * (p1 + p2)
```

This is O(n) per shift, vectorized.

Wait, I realize there might be an issue with the cutting-plane approach. After solving the LP, the new solution minimizes the LINEARIZED objective over the active constraints. But the true objective (nonlinear) might be worse at the new point for the active constraints (since we linearized). However, for the non-active constraints, the new point might violate them.

The standard approach is:
1. Solve LP with linearized active constraints → get h_new
2. Evaluate TRUE c_k(h_new) for ALL k
3. If any non-active constraint is violated (c_k(h_new) > t_new), add it to the active set
4. Repeat

This is the separation oracle / cutting-plane method for convex problems. Since our problem isn't exactly convex (the c_k are quadratic, not linear), the linearization is an approximation. But if the steps are small enough, it should still make progress.

Let me also think about: should I use the exact quadratic constraints in a QP instead of linearizing? cvxpy can handle QPs. The constraint c_k(h) ≤ t is:
∑_i h_i(1-h_{i+k}) * dx ≤ t
⟺ ∑_i (h_i - h_i*h_{i+k}) * dx ≤ t
⟺ -∑_i h_i*h_{i+k} * dx + ∑_i h_i * dx ≤ t

The term -∑h_i*h_{i+k} is a quadratic form -h^T A_k h / 2 (or similar). Is it convex or concave?

A_k has entries A_k[i,j] = 1 if j = i+k (for the correlation), so it's a permutation-like matrix. h^T A_k h = ∑_i h_i * h_{i+k} (approximately). This is NOT convex or concave in general (it's indefinite).

Wait, actually for the specific structure here: h^T A_k h where A_k is a shift matrix. Is this convex?

For k=0: A_0 = I, h^T I h = ∑h_i² which IS convex.
For k>0: A_k is a "shifted identity" - not symmetric, not PSD in general.

So the constraint -h^T A_k h + 1^T h * dx ≤ t is not a convex constraint (the -h^T A_k h part is not concave for k≠0).

Therefore, we can't directly use cvxpy for the exact problem. We must use linearization (or some other approximation).

OK so my cutting-plane approach with linearization is the way to go. Let me make sure it's correct and efficient.

One concern: the linearized constraint at h is:
c_k(h) + ∇c_k(h)^T (h' - h) ≤ t

This is a lower bound on c_k(h') only if c_k is concave. But c_k(h) = dx * ∑ h_i(1-h_{i+k}) is NOT concave in general (it's a bilinear/quadratic form). So the linearization is just a local approximation, not a valid bound.

This means the cutting-plane method might not have convergence guarantees. But in practice, if the steps are small (the LP solution is close to h), the approximation is good enough.
