For the uniform sequence, ALL lags near the center have b[k] ≈ S^2/n. If we can make the center lags slightly smaller while keeping the edge lags also small, we can reduce the max.

One way: use a sequence that's slightly "triangular" in the frequency domain. If the power spectrum |A[k]|^2 has a slight dip at k=0 (DC), then the circular convolution at lag 0 (= which is related to b[n-1]) would be reduced.

Actually, let me think about this in terms of the circular convolution. For a sequence padded to length N (N >= 2n-1), the circular convolution has the same values as the linear convolution. So we can work with the circular convolution of length N.

The DFT of the circular convolution is |A[k]|^2 (for N-point DFT). The circular convolution at lag 0 is (1/N) * sum_k |A[k]|^2 = (1/N) * ||a||^2 * N = ||a||^2 (by Parseval, sum |A[k]|^2 = N * sum |a[k]|^2... wait, let me be careful with normalization).

With the unitary DFT convention (1/sqrt(N) factor), Parseval gives sum |a[k]|^2 = sum |A_k|^2. And the circular convolution c = ifft(fft(a) * fft(a)) (using the N-point DFT).

Let me just focus on a practical approach.

**Practical approach: iterative peak reduction**

1. Start with a good initial sequence (from the parent or a structured initialization).
2. Normalize to sum = sqrt(2n).
3. Compute the convolution b.
4. Find the peak lag k*.
5. The peak b[k*] = sum_j a[j]*a[k*-j].
6. To reduce this peak, we want to reduce the products a[j]*a[k*-j].
   - For each pair (j, k*-j), we can reduce one or both elements.
   - The most effective is to reduce the larger element.
7. Apply a small reduction: a[j] = a[j] - delta * a[j]*a[k*-j] / b[k*] (proportional to the contribution to the peak).
8. Renormalize.
9. Repeat.

This is essentially the subgradient method, but we can make it more efficient by:
- Using multiple peaks simultaneously (top-k)
- Using adaptive step sizes
- Using acceleration (Nesterov)

**Idea: Bisection on M with feasibility check**

For a given M, check if there exists a >= 0 with sum a = S and b[k] <= M for all k.

The constraint b[k] <= M is a quadratic inequality: sum_j a[j]*a[k-j] <= M. This is a quadratic constraint, so the feasibility problem is a non-convex quadratic feasibility problem.

However, if we relax the constraint to b[k] <= M for only the "active" set of k (those where b[k] is close to M), the problem might be easier.

**Idea: Use CVXPY with a convex relaxation**

We can relax the problem by minimizing the max of the top few b[k] values, which is still non-convex. Or we can use a SOC (second-order cone) relaxation.
