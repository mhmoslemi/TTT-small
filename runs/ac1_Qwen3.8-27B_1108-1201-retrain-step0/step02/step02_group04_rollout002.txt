This is the gradient of `2n * sum(a^2) / sum(a)^2`, not of `2n * max(conv(a,a)) / sum(a)^2`. So the optimization was following the wrong gradient direction!

This explains why it got stuck at a suboptimal point. The correct approach would be to use the subgradient of the actual objective.

```python
import numpy as np
import time
from scipy.optimize import linprog

def fft_convolve(a, b):
    n = len(a)
    m = len(b)
    size = 1
    while size < n + m - 1:
        size <<= 1
    fa = np.fft.rfft(a, size)
    fb = np.fft.rfft(b, size)
    return np.fft.irfft(fa * fb, size)[:n + m - 1]

def compute_score(a):
    a = np.clip(a, 0.0, 1000.0)
    n = len(a)
    sum_a = np.sum(a)
    if sum_a < 0.01:
        return np.inf
    c = fft_convolve(a, a)
    return 2.0 * n * np.max(c) / (sum_a ** 2)

def solve_lp(a, M, n):
    """
    Solve: maximize sum(b) subject to conv(a,b)_k <= M for all k, b >= 0.
    """
    # conv(a,b)_k = sum_i a_i * b_{k-i} <= M
    # For k = 0, ..., 2n-2:
    #   sum_{i: max(0,k-n+1) <= i <= min(n-1,k)} a_i * b_{k-i} <= M
    
    # Decision variables: b_0, ..., b_{n-1}
    # c = -ones(n) (minimize -sum(b))
    c_obj = -np.ones(n)
    
    # Constraints: A @ b <= M * ones(2n-1)
    # For each k, the row is: A[k, j] = a_{k-j} if 0 <= k-j < n, else 0
    A = np.zeros((2*n-1, n))
    for k in range(2*n-1):
        for j in range(n):
            idx = k - j
            if 0 <= idx < n:
                A[k, j] = a[idx]
    
    b_vec = M * np.ones(2*n-1)
    
    bounds = [(0, None)] * n
    
    result = linprog(c_obj, A_ub=A, b_ub=b_vec, bounds=bounds, method='highs')
    
    if result.success:
        return result.x
    else:
        return None

def lp_iteration(a, t=1.0, n=None):
    """
    One iteration of the LP-based method.
    1. Compute M = max(conv(a,a))
    2. Solve LP to find b that maximizes sum(b) subject to conv(a,b) <= M, b >= 0
    3. Rescale b to have same sum as a
    4. Update a = (1-t)*a + t*b
    """
    if n is None:
        n = len(a)
    
    c = fft_convolve(a, a)
    M = np.max(c)
    
    b = solve_lp(a, M, n)
    if b is None:
        return a, M
    
    # Rescale b to have same sum as a
    sum_a = np.sum(a)
    sum_b = np.sum(b)
    if sum_b > 0:
        b = b * (sum_a / sum_b)
    
    # Update
    new_a = (1-t)*a + t*b
    new_a = np.clip(new_a, 0, 1000)
    
    return new_a, M
```

But actually, I realize there might be a subtlety. The LP maximizes `sum(b)` subject to `conv(a,b)_k <= M for all k`. The optimal `b` will have `sum(b) >= sum(a)` (since `a` itself is feasible: `conv(a,a)_k <= M` for all k by definition of M). In fact, `sum(b) > sum(a)` unless `a` is already optimal.

When we rescale `b` to have the same sum as `a`, we're finding a direction to move that maintains the sum but potentially reduces the max of the self-convolution.

Actually wait, I need to think about this more carefully. The LP finds `b` that maximizes `sum(b)` subject to `conv(a,b)_k <= M`. This `b` is in the "dual" sense - it's the sequence that, when convolved with `a`, stays below `M` while having the largest total mass.

The intuition is: if `a` has a large peak in its self-convolution, then there's a "bottleneck" - some positions in the convolution are at the limit. The LP finds a `b` that redistributes mass to avoid these bottlenecks.

Then, moving from `a` towards `b` (i.e., `a_new = (1-t)*a + t*b`) redistributes the mass of `a` in a way that should reduce the peak of its self-convolution.

This is similar to the "biconvex" approach or "alternating directions" where we alternate between optimizing `a` and `b` in `conv(a,b)`.

Let me think about the step size `t`. If `t` is too small, convergence is slow. If `t` is too large, we might overshoot. A good strategy is to use a line search: try `t = 1, 0.5, 0.25, ...` and pick the first one that improves the score.

Let me also think about the correct subgradient approach:

For the normalized problem (sum(a) = 1), minimize `f(a) = max_k conv(a,a)_k`.

The subgradient at `a` is: `g = (1/|A|) * sum_{k in A} 2 * a_{k-j}` where A is the active set and `a_{k-j}` means the reversed sequence.

More precisely, if we let `r_k[j] = a_{k-j}` if `0 <= k-j < n` else 0, then:
`grad(g_k) = 2 * r_k` (as a vector)

And the subgradient of `f = max_k g_k` at point `a` is:
`s = (1/|A|) * sum_{k in A} 2 * r_k`

Then we do: `a_new = a - lr * s`, project onto `{a >= 0, sum(a) = 1}`.

The projection onto `{a >= 0, sum(a) = 1}` is the euclidean projection onto the probability simplex, which can be done in O(n log n) using the standard algorithm.

For a sequence `a` of length `n` with `sum(a) = S`:
- Score = `2*n*max(conv(a,a))/S^2`

The convolution has `2n-1` entries. The "average" value of the convolution entries is approximately `S^2/(2n)` (since `sum_k conv(a,a)_k = (sum a)^2 = S^2`). So the average is `S^2/(2n)`, and the score is `2*n*max/S^2 = n/(S^2/2) * max/avg * ... `

Actually: `sum_k c_k = S^2`, so `avg(c) = S^2/(2n-1) ≈ S^2/(2n)`.
Score = `2n * max(c) / S^2 = 2n * max(c) / ((2n-1) * avg(c)) ≈ max(c) / avg(c)`.

So the score is approximately the ratio of the maximum to the average of the convolution. We want this ratio to be as close to 1 as possible (flat convolution).

For the uniform sequence, `max/avg = n / (S^2/(2n)) = n / (n^2/(2n)) = 2` (when S=n). So score ≈ 2.

To get score < 2, we need `max(c) < 2*avg(c) = 2*S^2/(2n) = S^2/n`.

This means we need the convolution to be "flatter" than the triangular shape of the uniform sequence.

Now, what kind of sequences have flat autocorrelation? In signal processing, these are called "low PNP" (Peak to Nominal Power ratio) or "low autocorrelation peak" sequences. Examples include:
- m-sequences (but they have ±1 values, not non-negative)
- Barker sequences (short, optimal for their length)
- Golay sequences

For non-negative sequences, the problem is different. We can't use negative values to cancel out peaks.

One idea: use a sequence that is concentrated in a sub-band of the frequency domain (i.e., has a specific spectral structure). By the uncertainty principle, this would spread out the time-domain convolution.

Another idea: use a "random" sequence (i.i.d. non-negative entries). For random sequences, the convolution entries are approximately Gaussian with mean `S^2/(2n)` and some variance. The maximum of `2n-1` approximately Gaussian entries would be around `mean + std * sqrt(2*log(2n))`. This gives a peak-to-average ratio that depends on the distribution.

For i.i.d. uniform [0, 2] (mean 1):
- `c_k ≈ sum of k+1 (or 2n-1-k) terms of products of uniform [0,2] random variables`
