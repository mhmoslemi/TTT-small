2. **Use a smart coordinate descent**: At each step, find the coordinate that gives the largest improvement in the objective, and update it optimally (or near-optimally).
3. **Use FFT for fast evaluation**: After each update, update the convolution in O(n) time (using the formula I derived above) instead of O(n log n) for a full FFT.

Wait, actually the update formula `b_new[k] - b[k] = 2δ * a[k-j] * I(0≤k-j<n) + δ² * I(k=2j)` means that after changing `a[j]`, I can update the entire convolution `b` in O(n) time (just add `2δ * a[·-j]` to `b`). This is much faster than a full FFT!

So the algorithm would be:
1. Compute initial `b = a * a` via FFT: O(n log n)
2. Repeat:
   a. Find the coordinate `j` and value `δ` that most reduces `max(b)`.
   b. Update `a[j] += δ` and `b[k] += 2δ*a[k-j] + δ²*I(k=2j)` for all k: O(n)
   c. If no improvement found, exit or restart.

The challenge is step (a): finding the best `(j, δ)` pair. If we check all n coordinates and for each try a few values of δ, that's O(n * n) = O(n²) per iteration, which for n=8192 is about 67 million operations per iteration. At 100 million ops/sec, that's about 0.7 seconds per iteration. In 2400 seconds, we'd get about 3000 iterations. That might be enough.

But we can do better. Instead of trying many values of δ for each j, we can:
- For each j, the effect on `b` is `b_new[k] = b[k] + 2δ*a[k-j] + δ²*I(k=2j)`.
- We want to minimize `max_k b_new[k]`.
- The current max is `M = max(b)`. Let `S = {k : b[k] = M}` be the set of maximizing lags.
- For the new max to be < M, we need `b_new[k] < M` for all k in S.
- For k in S: `b[k] + 2δ*a[k-j] + δ²*I(k=2j) < M`
  - If b[k] = M: `2δ*a[k-j] + δ²*I(k=2j) < 0`
  - This requires `δ * a[k-j] < 0` (approximately, ignoring the δ² term)
  - So we need `a[k-j] < 0` if `δ > 0`, or `a[k-j] > 0` if `δ < 0`.

Since `a >= 0`, if `δ > 0` (increasing a[j]), we need `a[k-j] = 0` for all k in S (or at least `a[k-j]` small). If `δ < 0` (decreasing a[j]), we need `a[k-j] > 0` for all k in S.

This gives a nice geometric interpretation: we should decrease `a[j]` when `a[k-j]` is large for the maximizing lags k, and increase `a[j]` when `a[k-j]` is small (zero) for all maximizing lags.

Let me refine the algorithm:

**Algorithm: Accelerated coordinate descent with O(n) updates**

```
1. a = initial sequence (previous best)
2. b = fft_convolve(a)  # O(n log n)
3. M = max(b)
4. For iteration = 1, 2, ...:
   a. Compute subgradient: sg[j] = (1/|S|) * sum_{k in S} (a[k-j] + a[j-k])
      where S = {k : b[k] ≈ M} (use a tolerance to include near-max lags)
   b. Find j* that minimizes sg (most negative subgradient component)
   c. Line search: find optimal δ for coordinate j*
      - Try a few values of δ (geometric sequence)
      - For each δ, compute new max in O(n): b_new = b + 2δ*a[·-j*] + δ²*I(·=2j*)
      - Pick δ that minimizes max(b_new)
   d. Update: a[j*] += δ, b += 2δ*a[·-j*] + δ²*I(·=2j*)
   e. M = max(b)
   f. If improvement < threshold, try a random coordinate or restart
```

The key insight is that updating `b` after a single-coordinate change is O(n), not O(n log n). This means we can do many more iterations.

For the line search, instead of trying many values, we can note that:
- If we decrease `a[j]` by δ (δ > 0, so new value is `a[j] - δ`):
  - `b_new[k] = b[k] - 2δ*a[k-j] + δ²*I(k=2j)`
  - The max can only decrease (or stay the same) at lags k where `a[k-j] > 0`
  - The max can increase at lags k where `a[k-j] = 0` (only by δ² at k=2j)
  
- The optimal δ for decreasing a[j] is approximately `δ* = min(M - b'[k]) / (2*a[k-j])` where b'[k] is b[k] with the δ² term ignored, and the min is over k where b[k] is near max and a[k-j] > 0.

Actually, this is getting complicated. Let me just use a simple approach:
- For the selected coordinate j, try δ values in a geometric sequence: `δ = a[j] * 2^{-i}` for i = 0, 1, 2, ..., and also negative values.
- For each candidate, compute the new max in O(n).
- Pick the best one.

With about 20 candidate values per coordinate, and O(n) per candidate, that's O(20*n) per iteration. For n=8192, that's about 160K operations per iteration. At 100 million ops/sec, that's about 0.0016 seconds per iteration. So we can do about 1.5 million iterations in 2400 seconds!

But we also need to find the best coordinate j, which requires computing the subgradient for all j. The subgradient at j is:
`sg[j] = (1/|S|) * sum_{k in S} (a[k-j] + a[j-k])`

This is a cross-correlation of `a` with the indicator of S (or the weights on S). We can compute this for all j simultaneously using FFT: O(n log n) per iteration.

So the total cost per iteration is:
- Compute subgradient via FFT: O(n log n) ≈ 100K ops
- Line search: O(20*n) ≈ 160K ops
- Update b: O(n) ≈ 8K ops
Total: ~270K ops per iteration

In 2400 seconds at 100M ops/sec: about 8.9 million iterations. That's more than enough.

But wait, the subgradient computation via FFT gives us the gradient of `max(b)` only if S is a single point. For a set S, we need to weight by the subgradient weights. If we use uniform weights on S (top-k lags), we can compute the subgradient as a convolution of `a` with the weighted indicator of S.
