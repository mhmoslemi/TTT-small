def fast_convolve(a):

    result = np.fft.irfft(A * A, fft_size)

    A_ub = np.zeros((2*n-1, n))

        j_end = min(n - 1, k)
        for j in range(j_start, j_end + 1):
            A_ub[k, j] = a[j]
    
    b_ub = np.full(2*n-1, M)
    bounds = [(0, None)] * n
    
    result = linprog(c, A_ub=A_ub, b_ub=b_ub, bounds=bounds, method='highs')
    if result.success:
        return result.x
    else:
        return None

Let me also think about what makes this problem tick from a theoretical perspective.

The objective is: min_{a>=0, sum=1} 2n * max_k (a*a)(k)

This is related to the "Sliding Window" multiplexing problem in communications, and to "Cami" (Constant Amplitude) sequence design.

Known results:
- For cyclic convolutions (CSI - Cycle (auto)Correlation Sequence Index), the minimum peak-to-mean ratio is related to the "Zadoff-Chu" sequences.
- For linear convolutions, the problem is different.

One key insight: the problem is equivalent to finding a probability distribution on {0,...,n-1} such that the distribution of the sum of two independent draws from this distribution has minimum maximum probability mass.

This is a "sumset" problem in additive combinatorics! We want to minimize the maximum probability mass of X+Y where X,Y are i.i.d. from the distribution a.

For a uniform distribution on {0,...,n-1}, X+Y has a triangular distribution with max mass at n-1, equal to 1/n. The objective is 2n*(1/n) = 2.

To do better, we need a non-uniform distribution where X+Y is more "spread out".

One approach: use a distribution that's concentrated on a "substructure" of {0,...,n-1} that has good additive properties. For example, if we use a distribution supported on {0, 2, 4, ..., n-2} (every other element), then X+Y is supported on {0, 2, 4, ..., 2n-4}, and the distribution is more concentrated... that's worse.

What about a distribution on a "Sidon set" or "BSE(n)" set? These are sets where all pairwise sums are distinct (or nearly so). But Sidon sets have size O(√n), so our distribution would be very sparse, leading to large edge peaks.

Actually, I think the optimal solution has a specific structure related to "difference sets" in finite groups. A (v,k,λ) difference set D in a group G of order v has the property that every non-identity element is represented exactly λ times as a difference d1-d2 with d1,d2 in D.

If we identify our sequence with the indicator of a difference set (scaled), the convolution (which is related to the difference set property) would be nearly flat. But difference sets exist only for specific parameter combinations.

For our problem, we're not restricted to 0-1 sequences; we can use any non-negative values. This gives more flexibility.
