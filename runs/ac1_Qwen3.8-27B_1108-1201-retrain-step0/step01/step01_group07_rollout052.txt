Actually, here's another idea: **dual ascent / cutting plane**.

The objective is `F(a) = max_k c_k(a)`. We can write this as:

(The max is the dual of the min over the simplex of λ.)

This is a minimax problem. We can use the von Neumann minimax theorem if the problem is convex-concave, but it's not (c_k(a) is not convex in a).

However, we can still use a game-theoretic / multiplicative weights approach:
1. Maintain a distribution λ over the lags
2. For the current λ, compute `g = sum_k λ_k * grad c_k(a)` (this is the gradient of the weighted sum)
3. Update a in the direction -g (with projection)
4. Update λ to put more weight on lags with high c_k

This is essentially the same as the subgradient method with the "improvement" of using a distribution over active lags rather than just the argmax.

Let me formalize this:

**Algorithm: Mirror Descent / Multiplicative Weights for the dual**

State: a (current sequence), λ (distribution over lags, length 2n-1)

Initialization: a = some init, λ = uniform or based on initial c

Loop:
1. c = conv(a, a)
2. g = sum_k λ_k * grad c_k(a) / (sum λ) [gradient of the weighted loss]
3. a_new = project(a - step * g)
4. Update λ: λ_k *= exp(eta * c_k) then normalize [mirror descent step for the max]
5. a = a_new
6. Check convergence

The update of λ is a multiplicative weights / exponential weights step that shifts weight toward the lags with highest c_k. Over time, λ concentrates on the active lags.

The step size for a could be adaptive (backtracking).
The step size η for λ controls how quickly it concentrates (too fast = too narrow, too slow = too diffuse).

This is a nice approach because:
- It naturally handles the non-smoothness (λ smooths the max)
- It's efficient (O(n) per lag, O(n * |support(λ)|) total)
- It has theoretical guarantees (O(1/sqrt(T)) convergence for the minimax)

```python
import numpy as np
import time

def compute_conv(a):
    return np.convolve(a, a)

def compute_subgradient(a, active_indices):
    """Compute subgradient of max(conv(a,a)) at a.
    active_indices: array of indices where conv is (near) max."""
    n = len(a)
    grad = np.zeros(n)
    for k in active_indices:
        k = int(k)
        lo = max(0, k - n + 1)
        hi = min(k, n - 1)
        seg_start = max(0, k - n + 1)
        seg_end = min(k, n - 1) + 1
        grad[lo:hi+1] += 2.0 * a[seg_start:seg_end][::-1]
    grad /= len(active_indices)
    return grad

def project_simplex(a, S):
    """Project a onto {x >= 0, sum(x) = S}."""
    a = np.maximum(a, 0.0).copy()
    n = a.size
    s = a.sum()
    if s == 0:
        return np.full(n, S / n)
    if s <= S:
        return a + (S - s) / n
    lo, hi = 0.0, a.max()
    for _ in range(60):
        mid = (lo + hi) * 0.5
        if np.maximum(a - mid, 0.0).sum() > S:
            lo = mid
        else:
            hi = mid
    t = (lo + hi) * 0.5
    res = np.maximum(a - t, 0.0)
    res[np.argmax(res)] += S - res.sum()
    return res

def fista_exact(a0, S, step0, tol, max_time, force_eps=0.0):
    """FISTA with exact max objective.
    a0: initial point (will be normalized to sum S)
    S: target sum
    step0: initial step size
    tol: tolerance for active set (lags within force_eps of max are active)
    max_time: time budget in seconds
    """
    n = a0.size
    a = project_simplex(a0.copy(), S)
    y = a.copy()
    t_mom = 1.0
    step = step0
    best_a = a.copy()
    
    c = np.convolve(a, a)
    cmax = c.max()
    best_cmax = cmax
    t0 = time.monotonic()
    iter_count = 0
    no_improve = 0
    
    while time.monotonic() - t0 < max_time:
        # Compute subgradient at y
        # Active set: indices within tol of max
        active = np.where(c >= cmax - force_eps)[0]
        # But c was computed at the previous a, not y. Let me recompute at y.
        c_y = np.convolve(y, y)
        cmax_y = c_y.max()
        active = np.where(c_y >= cmax_y - force_eps)[0]
        
        g = compute_subgradient(y, active)
        
        # FISTA step
        a_new = project_simplex(y - step * g, S)
        
        # Check if we improved
        c_new = np.convolve(a_new, a_new)
        cmax_new = c_new.max()
        
        if cmax_new < best_cmax - 1e-10:
            best_cmax = cmax_new
            best_a = a_new.copy()
            no_improve = 0
            # Increase step slightly
            step = min(step * 1.02, 5.0)
        else:
            no_improve += 1
            if no_improve > 50:
                step *= 0.9
                no_improve = 0
            if no_improve > 500:
                break
        
        # Nesterov momentum update
        t_new = (1.0 + np.sqrt(1.0 + 4.0 * t_mom * t_mom)) / 2.0
        y = a_new + ((t_mom - 1.0) / t_new) * (a_new - a)
        # Ensure y is in the feasible set (optional, can skip for efficiency)
        # y = project_simplex(y, S)
        
        a = a_new
        t_mom = t_new
        iter_count += 1
    
    return best_a, best_cmax, iter_count
```

**Idea: Fourier-domain optimization**

The convolution `conv(a,a)` is related to the Fourier transform: `conv(a,a) = IFFT(|FFT(a)|^2)` (approximately, for the aperiodic case with zero-padding).

Actually, more precisely: if we zero-pad a to length 2n-1, then `FFT(conv(a,a)) = |FFT(a_padded)|^2`. So the convolution is the inverse Fourier transform of the squared magnitude of the Fourier transform.

This means: `conv(a,a)_k = (1/N) * sum_ω |A(ω)|^2 * exp(i*ω*k)` where N is the padded length and A is the DFT of the padded sequence.

The max of the convolution over k is the peak of the inverse Fourier transform of `|A(ω)|^2`. We want this peak to be as small as possible.

This is related to the problem of finding a signal whose power spectrum has a flat inverse transform, i.e., whose autocorrelation is as flat as possible. This is the "minimum peak sidelobe" problem.

One approach: optimize in the frequency domain. Let `A(ω) = |A(ω)| * exp(i*φ(ω))`. The constraint is that `a = IFFT(A)` is real and non-negative. The objective is `max_k IFFT(|A|^2)_k`.

This is a non-convex problem in the frequency domain too, but it might be easier to optimize with certain parameterizations.

However, I think the time-domain approach with FISTA is simpler and likely to work well enough.

```python
    grad_a /= len(active)
    
    # Chain rule through softmax: da_i/dw_j = a_i*(delta_ij - a_j/S)
    # df/dw_j = a_j * grad_a_j - (a_j/S) * sum_i a_i * grad_a_i
    inner = np.dot(a, grad_a) / S
    grad_w = a * (grad_a - inner)
    
    return cmax, grad_w

result = minimize(objective_and_grad, w0, args=(S,), method='L-BFGS-B', jac=True)
```

The issue with this approach is that the objective is non-smooth, and L-BFGS-B is designed for smooth objectives. In practice, it often works, but it can get stuck or behave erratically at non-smooth points.

A hybrid approach: use L-BFGS-B for a while, then switch to FISTA for fine-tuning.

**Idea: Coordinate descent on the active lags**

Once we've identified the active lags (the ones at the max), we can try to reduce them specifically. For each active lag k, we want to minimize `conv(a,a)_k = sum_i a_i * a_{k-i}`. This is a quadratic in a, and we can try to reduce it by adjusting the pairs (a_i, a_{k-i}) that have large products.

A simple greedy approach:
1. For the current max lag k, find the pair (i, k-i) with the largest product a_i * a_{k-i}
2. Reduce the larger of a_i and a_{k-i} slightly, and redistribute
3. Repeat

This is like a "water-filling" approach.

But this is probably not as efficient as the gradient-based methods.
