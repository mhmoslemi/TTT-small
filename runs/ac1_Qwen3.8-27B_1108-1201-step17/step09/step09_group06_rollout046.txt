import numpy as np

from scipy.fft import rfft, irfft
from scipy.optimize import minimize, linprog

def fast_convolve_self(a):
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    A = rfft(a, fft_size)
    return irfft(A * A, fft_size)[:size]

def fast_convolve_ab(a, b):
    size = len(a) + len(b) - 1
    fft_size = 1 << (size - 1).bit_length()
    A = rfft(a, fft_size)
    B = rfft(b, fft_size)
    return irfft(A * B, fft_size)[:size]

    """Score = 2n * max(conv(a,a)) assuming sum(a)=1."""
    n = len(a)
    b = fast_convolve_self(a)
    return 2.0 * n * b.max()

    """Compute subgradient of max(conv) at active positions."""

        c[-1] = 1.0

        b_ub_full = np.zeros(len(active))

        b_eq = np.array([1.0])

- Each iteration is O(n log n) (FFT for convolution + O(n log n) for simplex projection)
- Fast convergence (O(1/t) rate)

The disadvantage:
- We're optimizing a smoothed version of the max (since p is a probability distribution, not a single point)
- We need to let p concentrate for the solution to approach the true max

But in practice, p will naturally concentrate on the active set as the iterations progress.

Let me implement this. The simplex projection is:
proj_simplex(v, s) = v - lambda where lambda is chosen so that sum(proj) = s and proj >= 0.

The standard algorithm for this is O(n log n):
1. Sort v in descending order
2. Find the threshold using the sorted values
3. Clamp and normalize

Here's the algorithm:
```
def proj_simplex(v, s=1.0):
    n = len(v)
    u = np.sort(v)[::-1]
    cv = np.cumsum(u)
    rho = np.nonzero(u * np.arange(1, n+1) > (cv - s))[0][-1]
    theta = (cv[rho] - s) / (rho + 1.0)
    return np.maximum(v - theta, 0)
```

This is the standard algorithm by Duchi et al. (2011).

The gradient computations require FFT convolutions, which are O(n log n) each.

So each PDHG iteration is about O(n log n), and we can do millions of iterations in 1770 seconds (if each takes ~1ms, that's 1.7M iterations).

This is way more iterations than the LP-based approach (which might do 1000-5000 iterations in the same time).

The trade-off is that PDHG converges slower per iteration (O(1/t) vs. potentially faster for LP), but the per-iteration cost is much lower.
