**Approach: Direct LP for the full problem (one step)**

The problem `min max_k conv(a,a)[k] s.t. a >= 0, sum(a)=1` is non-convex. But if I fix the "dual" sequence `b`, the problem becomes:

`min max_k conv(a, b)[k] s.t. a >= 0, sum(a)=1`

which is a LP (linear in a). The optimal value as a function of b gives a lower bound.

By alternating between optimizing a given b and optimizing b given a (both are LPs), we get a **minimax algorithm** that converges to a saddle point.

This is the **von Neumann minimax** approach, and it's guaranteed to converge for the bilinear game `min_a max_k (a^T C_k b)` (where C_k are the convolution matrices).

Actually, the game is: Player 1 chooses `a >= 0, sum(a)=1` to minimize `max_k conv(a,b)[k]`, and Player 2 chooses `b >= 0, sum(b)=1` to maximize `min_a max_k conv(a,b)[k]`.

The value of this game is the optimum of our problem!

And the LP at each step is:
- Player 1's LP (given b): min M s.t. conv(a,b)[k] <= M for all k, a >= 0, sum(a)=1.
- Player 2's LP (given a): max m s.t. conv(a,b)[k] >= m for all k, b >= 0, sum(b)=1.

Wait, Player 2 wants to MAXIMIZE the minimum, so:
- Player 2's LP: max m s.t. conv(a,b)[k] >= m for all k, b >= 0, sum(b)=1.

Both are LPs! And we alternate between them.

At the optimal pair (a*, b*), we have `conv(a*, a*) = conv(a*, b*) = conv(b*, a*) = M*` (the value of the game).

This is a very clean algorithm! Let me implement it.

**Minimax Algorithm:**
1. Initialize a and b (e.g., both uniform, or from parent).
2. Alternate:
   a. Given b, solve: min M s.t. `sum_m a[m]*b[k-m] <= M` for all k, a >= 0, sum(a)=1.
      This updates a.
   b. Given a, solve: max m s.t. `sum_m b[m]*a[k-m] >= m` for all k, b >= 0, sum(b)=1.
      This updates b.
3. The value M* (which equals the minimum of Player 1's LP) gives a lower bound on `max(conv(a*, a*))`.
4. The actual objective is `max(conv(a*, a*))`, which is >= M*.
5. Iterate until convergence.

At convergence, M* = max(conv(a*, a*)) and we've found the optimum (or close to it).

But wait, the game value might not equal the optimum of the original non-convex problem. The minimax inequality gives:
`min_a max_k conv(a,a)[k] >= min_a max_k conv(a,b)[k] for all b >= max_b min_a conv(a,b)[k]`

So the game value is a LOWER bound on the original optimum. The gap between the game value and the actual optimum tells us how close we are.

In practice, for symmetric problems like this, the gap is often small, and the iterates a_t converge to a good solution.
