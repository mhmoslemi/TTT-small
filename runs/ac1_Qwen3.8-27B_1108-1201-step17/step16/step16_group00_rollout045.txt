```python
def lp_frank_wolfe(a0, time_limit, solver, verbose=True, top_K=300, adapt_K=True):
    """LP-based Frank-Wolfe with adaptive constraint selection."""
    n = len(a0)
    a = norm_sum1(a0)
    best_a = a.copy()
    best_m = fast_autocorr(a).max()
    t0 = time.monotonic()
    
    y = a.copy()
    iter_count = 0
    current_K = min(top_K, 2 * n - 1)
    patience = 0
    max_patience = 200
    
    for t in range(1, 500000):
        if time.monotonic() - t0 > time_limit:
            break
        
        ac = fast_autocorr(y)
        M_curr = ac.max()
        
        # Compute all convolution values with y
        # conv(y, b)[k] = sum_i y[i] * b[k-i]
        # For the LP, we need: for all k, sum_i T[k,i] * b[i] <= M_curr
        # where T[k,i] = y[k-i] if 0 <= k-i < n, else 0
        
        # Build constraint matrix for selected constraints
        K_sel = min(current_K, 2 * n - 1)
        
        # Select constraints: the K most binding (smallest margin)
        # margin[k] = M_curr - conv(y,y)[k] = M_curr - ac[k]
        # We want the K smallest margins
        margins = M_curr - ac
        binding_idx = np.argsort(margins)[:K_sel]
        
        # Build sparse constraint matrix
        # For constraint k: sum_i y[k-i] * b[i] <= M_curr
        # (where y[k-i] is defined only when 0 <= k-i < n)
        
        # For efficiency, build as dense for small n
        if n <= 2000:
            T = np.zeros((K_sel, n))
            for idx_i, k in enumerate(binding_idx):
                k_int = int(k)
                for i in range(n):
                    j = k_int - i
                    if 0 <= j < n:
                        T[idx_i, i] = y[j]
        else:
            # For larger n, use the structure
            T = np.zeros((K_sel, n))
            for idx_i, k in enumerate(binding_idx):
                k_int = int(k)
                i_start = max(0, k_int - n + 1)
                i_end = min(n, k_int + 1)
                if i_start >= i_end:
                    continue
                for i in range(i_start, i_end):
                    j = k_int - i
                    T[idx_i, i] = y[j]
        
        b_var = cp.Variable(n, nonneg=True)
        constraints = [T @ b_var <= M_curr]
        prob = cp.Problem(cp.Maximize(cp.sum(b_var)), constraints)
        
        try:
            prob.solve(solver=solver, verbose=False)
        except Exception:
            continue
        
        if prob.status not in ('optimal', 'optimal_inaccurate'):
            continue
        
        b_val = np.maximum(np.asarray(b_var.value, dtype=np.float64), 0.0)
        b_sum = b_val.sum()
        if b_sum < 1e-15:
            continue
        g_dir = b_val / b_sum
        
        # Frank-Wolfe step
        alpha = 2.0 / (t + 2.0)
        y_new = (1.0 - alpha) * y + alpha * g_dir
        y_new = np.maximum(y_new, 0.0)
        sy = y_new.sum()
        if sy < 1e-15:
            y_new = y.copy()
        else:
            y_new = y_new / sy
        
        y = y_new
        iter_count += 1
        
        my = fast_autocorr(y).max()
        if my < best_m:
            best_m = my
            best_a = y.copy()
            patience = 0
        else:
            patience += 1
        
        # Adaptive K: grow if stalled
        if adapt_K and patience > 50 and current_K < 2 * n - 1:
            current_K = min(current_K + 50, 2 * n - 1)
            patience = 0
        
        if patience > max_patience:
            break
        
        if verbose and t % 10 == 0:
            elapsed = time.monotonic() - t0
            J = 2.0 * n * best_m
            print(f"    LP iter={t} ({elapsed:.0f}s): J={J:.6f}, K={current_K}")
    
    return best_a, best_m
```

Hmm, the LP approach with dense matrices for n=3200 would be very slow. Let me think of a better approach.

Actually, for the LP, the constraint matrix T has a special structure: each row is a "reversed" version of a shifted version of y. This is a Toeplitz-like (but not exactly) matrix. We could use this structure, but cvxpy won't exploit it automatically.

For n=3200, the matrix T would be K_sel x n. If K_sel = 300, that's 300 * 3200 = about 1 million entries. The dense matrix would be 300 * 3200 = ~3MB, which is manageable.

But the LP solve time would be the bottleneck. For 300 constraints and 3200 variables, a modern solver should handle this in maybe 0.1-1 seconds per iteration. So we might get 100-1000 iterations in the time budget.

Let me reconsider the overall strategy. Given that we need to improve from 1.504158 to below 1.5027 (a 0.1% improvement), I think the most effective approach is:

1. **Fine-tuning the existing solution**: Use coordinate descent with very small steps on the parent solution.
2. **Try slightly different n values**: Maybe n=3000 or n=3500 works better than n=3200.
3. **Parametric perturbations**: Add small structured perturbations to the parent.
