    # This is related to the regular convolution by: (a anti_conv w)[i] = (a * w_rev)[i + len(w) - 1 - len(a) + 1]... 
    
    # Simpler: just do it directly for n=3200 (O(n^2) ~ 10M ops)
    grad = np.zeros(n)
    for i in range(n):
        # j from 0 to n-1, need i+j < 2n-1, so j < 2n-1-i
        j_max = min(n, 2*n-1-i)
        if j_max > 0:
            grad[i] = 2.0 * np.dot(a[:j_max], w[i:i+j_max])
    return grad

Wait, O(n^2) for n=3200 is about 10 million operations per gradient evaluation. That's fine for a few thousand iterations. But if I want to do 100,000 iterations, that's too slow.

Let me use FFT for the gradient:

The operation `grad_i = sum_j a[j] * w[i+j]` is a "sliding dot product" or "cross-correlation with offset". 

Actually, this is equivalent to: if I define `w_rev[j] = w[2n-2-j]` (reversed w), then:
`grad_i = sum_j a[j] * w[i+j]`

Let me think of it as a convolution. Define `a_pad = [0, ..., 0, a[0], a[1], ..., a[n-1], 0, ..., 0]` (padded to length 3n-2 or so). Then `(a_pad * w_rev)[?]`...

Actually, the simplest FFT approach:
- We want `c[i] = sum_{j=0}^{n-1} a[j] * w[i+j]` for i = 0, ..., n-1.
- This is a cross-correlation. `c = np.correlate(w, a, mode='valid')` would give `c[i] = sum_j w[i+j] * a[j]` for i = 0, ..., len(w)-n = n-1. 

Wait, `np.correlate(w, a, 'valid')` gives the output where the smaller signal slides over the larger. If w has length 2n-1 and a has length n, then 'valid' gives length (2n-1)-n+1 = n. And `c[i] = sum_j w[i+j] * conj(a[j])`. For real signals, this is `sum_j w[i+j] * a[j]`.

So `c = np.correlate(w, a, 'valid')` gives exactly what I want! And numpy's correlate uses FFT for large inputs.

Let me verify: w has length 2n-1, a has length n. `np.correlate(w, a, 'valid')` gives an array of length (2n-1) - n + 1 = n. Element i is `sum_{j=0}^{n-1} w[i+j] * a[j]`. Yes!

So `grad = 2.0 * np.correlate(w, a, 'valid')`.

This should be O(n log n) using FFT.

Actually, for the smooth max approximation, the Lipschitz constant of the gradient is bounded by `2 * beta * 2 * n` (roughly), since each conv[k] is a bilinear form and the Hessian involves the weights. But this is a rough bound.

Let me use a simpler approach: mirror descent (exponential weights / multiplicative updates), which is what the previous program's AMD method uses. This avoids the step size issue.

Mirror descent for minimizing f(a) subject to a >= 0, sum a = 1:
a_new = a * exp(-eta * grad) / (a * exp(-eta * grad)).sum()

This is the softmax update (Hayes-Kasparis). The step size eta can be chosen adaptively.

My strategy:

import numpy as np

def fast_autocorr(a):
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    A = np.fft.rfft(a, fft_size)
    return np.fft.irfft(A * A, fft_size)[:size]

    if s < 1e-15:

def smooth_max_and_grad(a, beta):
    """Compute smooth max of autocorrelation and its gradient."""
    n = len(a)
    ac = fast_autocorr(a)
    ac_shifted = ac - ac.max()
    exp_vals = np.exp(beta * ac_shifted)
    w = exp_vals / exp_vals.sum()

    grad = 2.0 * np.correlate(w, a, 'valid')
    return ac, w, grad

    stall = 0
