**Alternative: Use a "black box" solver more efficiently**

Instead of solving the full LP at each iteration, we can:
1. Solve the LP once to get a direction g
2. Take multiple Frank-Wolfe steps in the same direction (with decreasing step sizes)
3. Only re-solve the LP when we detect that the direction is no longer good

This could save many LP solves.

**Another idea: Use the structure of the problem**

The convolution constraint conv[k] <= M can be written as:
sum_j a[j] a[k-j] <= M

This is a QUADRATIC constraint, not linear! The previous LP formulation linearizes it by fixing one factor (using the current a as the "other factor"):
sum_j a_current[k-j] * g[j] <= M

This is valid for Frank-Wolfe (the linearization is at the current point), but it means the LP is only an approximation.

The exact problem is:
min max_k sum_j a[j] a[k-j]
s.t. sum(a) = 1, a >= 0

This is a quadratically constrained optimization problem (QCQP). The LP is a relaxation (linearizing the quadratic).

- Semidefinite programming (SDP) relaxation
- Benders decomposition
- Direct nonlinear optimization (since the objective is convex)
