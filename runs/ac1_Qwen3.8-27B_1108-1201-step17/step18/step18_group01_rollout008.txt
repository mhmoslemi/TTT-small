Actually, I want to think more carefully about the LP approach. The state of the art description says:

"compute g0 by solving a linear program, i.e. maximizing sum b_j subject to b_j >= 0 and ||f * g0||_inf <= M"

This is: max 1^T b s.t. (T_f) b <= M * 1, b >= 0

where T_f is the (2n-1) x n Toeplitz matrix with (T_f)_{k,j} = f[k-j] (for valid indices).

The dual is: min M * 1^T y s.t. T_f^T y >= 1, y >= 0.

For the primal, we can use scipy.optimize.linprog with method='highs'. The number of constraints is 2n-1 + n (for b >= 0) ≈ 3n, and the number of variables is n. For n=5000, that's 15000 constraints and 5000 variables. This might take a few seconds with HiGHS.

But we don't need to solve the full LP every iteration. We can solve it every few iterations or at the end.
