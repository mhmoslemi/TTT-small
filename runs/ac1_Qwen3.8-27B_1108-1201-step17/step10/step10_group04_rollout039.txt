from scipy.fft import rfft, irfft

def fast_convolve(a):
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    A = rfft(np.asarray(a, dtype=np.float64), fft_size)
    return irfft(A * A, fft_size)[:size]

def fast_cross_convolve(a, b):
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    A = rfft(np.asarray(a, dtype=np.float64), fft_size)
    B = rfft(np.asarray(b, dtype=np.float64), fft_size)
    return irfft(A * B, fft_size)[:size]

def build_conv_T(a):
    """Build matrix T where T @ b = conv(a, b)."""
    n = len(a)
    size = 2 * n - 1
    T = np.zeros((size, n))
    for j in range(n):
        T[j:j+n, j] = a
    return T

def solve_br_lp(a_fixed, solver=None):
    """Solve LP: min M s.t. conv(a_fixed, b)_k <= M for all k, sum(b)=1, b>=0."""
    n = len(a_fixed)

    M = cp.Variable()
    T = build_conv_T(a_fixed)
    constraints = [T @ b <= M, cp.sum(b) == 1]
    prob = cp.Problem(cp.Minimize(M), constraints)
    prob.solve(solver=solver)
    if prob.status not in ('optimal', 'optimal_inaccurate'):
        return None, None
    b_val = np.asarray(b.value, dtype=np.float64)
    b_val = np.maximum(b_val, 0)
    s = b_val.sum()
    if s < 1e-15:
        return None, None
    b_val = b_val / s
    return b_val, float(M.value)

            break
        
        # Solve both best responses
        b_br, _ = solve_br_lp(y, solver)  # best response for b given y
        if b_br is None:
            continue
        
        a_br, _ = solve_br_lp(b_br, solver)  # best response for a given b_br
        if a_br is None:

        # Nesterov update
        alpha = 2.0 / (it + 2.0)
        y = (1 - alpha) * y + alpha * b_br
        y = np.maximum(y, 0)
        y = y / y.sum()
        
        a = (1 - alpha) * a + alpha * a_br
        a = np.maximum(a, 0)
        a = a / a.sum()

        if score_a < best_score:

`min M s.t. conv(a_fixed, b)_k ≤ M ∀k, sum(b) = 1, b ≥ 0`

And uses the solution b as a "direction" to update a. The update is:
`a_new = (1-α) * a + α * b`

This is like a "weighted average" between the current a and the best-response b. The intuition is:
- b is the distribution that minimizes the worst cross-correlation with a
- By moving toward b, we reduce the worst cross-correlation
- Since conv(a,a) ≤ max_b conv(a,b) for the current a, reducing the cross-correlation should also reduce the autocorrelation

But this heuristic isn't guaranteed to work. The Nesterov acceleration helps by extrapolating beyond the current point.

A potentially better approach: Instead of mixing a and b, use b directly as the new a (with some smoothing). Or use the "optimistic" update:
`a_new = a + α * (b - a)` (which is the same as `(1-α)a + αb`)

Or the "extrapolated" update:
`a_extrap = 2*a - a_prev` (extrapolate in the direction of motion)
`a_new = (1-α)*a_extrap + α*b`

Let me implement both and see which works better.

Let me think about the local search more carefully.

**Local search: Peak-directed coordinate descent**

At the current point a, the objective is `f(a) = max_k conv(a,a)_k`. Let k* = argmax_k conv(a,a)_k.

The local model: `f(a) ≈ conv(a,a)_{k*}` (the peak dominates).

`conv(a,a)_{k*} = sum_i a_i * a_{k*-i}` (over valid i).

This is a product of pairs of a's. To reduce it, we can:
1. Decrease a_i where a_i * a_{k*-i} is large (the "contributors")
2. Increase a_j where a_j * a_{k*-j} is small (the "non-contributors")
3. But we need to maintain sum(a) = 1 and a ≥ 0

A specific move: pick i with large a_i * a_{k*-i}, and j with small a_j * a_{k*-j}. Transfer a small amount ε from i to j:
- a_i → a_i - ε
- a_j → a_j + ε

The change in conv(a,a)_{k*} is approximately:
- Δ ≈ -ε * a_{k*-i} + ε * a_{k*-j} = ε * (a_{k*-j} - a_{k*-i})

If a_{k*-j} < a_{k*-i}, this reduces the peak. But it might increase other lags!

So we need to check all lags, not just k*. This is expensive but necessary.

A more practical approach: use gradient information.
- ∇_a conv(a,a)_{k*} has components: (∇_a conv(a,a)_{k*})_i = a_{k*-i} (for valid i, i.e., 0 ≤ k*-i < n)
- We want to move in the direction that reduces conv(a,a)_{k*} while maintaining the constraints.

The steepest descent direction (projected onto the tangent space of the simplex) is:
d_i = -(a_{k*-i} - mean(a_{k*-i})) (for valid i)
d_i = -(0 - mean(0)) = mean(0) (for invalid i, i.e., k*-i < 0 or k*-i ≥ n)

Wait, for invalid i, the derivative is 0. So:
d_i = -a_{k*-i} + μ where μ is chosen so that sum(d_i) = 0 (tangent to the hyperplane sum(a)=1).

μ = (1/n) * sum_{valid i} a_{k*-i}

Then do a line search: a_new = a + α * d, project onto a ≥ 0, renormalize.

This is essentially what the mirror_descent_bt function does, but with a single active set (just the peak) instead of a fraction of the top peaks.

I think using a larger active set (top 5-10% of peaks) gives a better direction. The previous code uses `n_active_frac=0.08` (top 8%).

Let me also consider: **what if we use the LP solution as a subgradient?**

The LP `min M s.t. conv(a, b)_k ≤ M ∀k, sum(b) = 1, b ≥ 0` can be interpreted as: find the b that "uniformly" minimizes the cross-correlation with a. The solution b is like a "fair" distribution that doesn't concentrate on the peaks of a.

If we then compute `conv(a, b)`, it should be roughly flat (all lags similar). This means b "distributes" its mass to avoid the peaks of a.

Now, if we set a ← b (or mix a and b), the new a should have a flatter autocorrelation. This is the intuition behind the LP-based method.
