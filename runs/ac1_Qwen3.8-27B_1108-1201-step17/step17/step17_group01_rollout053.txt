But wait, I need to check that the sequence stays non-negative. a[i] = 1 + eps*sin(2*pi*i/n) >= 0 requires eps <= 1. And the max convolution value should indeed be at the center.

However, this is just a first-order approximation. The actual sequence a[i] = 1 + eps*sin(2*pi*i/n) for i=0,...,n-1 has:
- a[0] = 1 (sin(0) = 0)
- The values range from 1-eps to 1+eps.

For eps < 1, all values are positive. Good.

But the linear convolution is NOT exactly the periodic autocorrelation. There are edge effects. Let me think about whether the max could be at a non-center position.

For k < n-1: conv[k] = sum_{i=0}^{k} a[i]*a[k-i]
This sums fewer terms than the center, so it's generally smaller.

For k > n-1: conv[k] = sum_{i=k-n+1}^{n-1} a[i]*a[k-i]
Also fewer terms.

So the center should be the max. Good.

Now, can we do even better with multiple sinusoidal components?

a[i] = 1 + sum_m eps_m * sin(2*pi*m*i/n + phi_m)

The center convolution would be:
conv[n-1] = sum_i a[i]*a[n-1-i]

For a single sine at frequency m:
a[i] = 1 + eps*sin(2*pi*m*i/n)
a[n-1-i] = 1 + eps*sin(2*pi*m*(n-1-i)/n) = 1 + eps*sin(2*pi*m - 2*pi*m*(1+i)/n) = 1 + eps*sin(-2*pi*m*(1+i)/n) [since sin(2*pi*m - x) = -sin(x) for integer m... wait, sin(2*pi*m - x) = sin(2*pi*m)*cos(x) - cos(2*pi*m)*sin(x) = -sin(x)]

So a[n-1-i] = 1 - eps*sin(2*pi*m*(1+i)/n)

a[i]*a[n-1-i] = (1+eps*sin(2*pi*m*i/n))*(1-eps*sin(2*pi*m*(1+i)/n))
= 1 - eps*sin(2*pi*m*(1+i)/n) + eps*sin(2*pi*m*i/n) - eps^2*sin(2*pi*m*i/n)*sin(2*pi*m*(1+i)/n)

The cross term: sin(2*pi*m*i/n)*sin(2*pi*m*(1+i)/n) = sin(2*pi*m*i/n)*[sin(2*pi*m/n)*cos(2*pi*m*i/n) + cos(2*pi*m/n)*sin(2*pi*m*i/n)]

sum_i sin(2*pi*m*i/n) = 0 (for m not a multiple of n)
sum_i sin(2*pi*m*(1+i)/n) = 0 (for m not a multiple of n)
sum_i sin(2*pi*m*i/n)*cos(2*pi*m*i/n) = 0 (for m not a multiple of n)
sum_i sin^2(2*pi*m*i/n) = n/2 (for m not a multiple of n)

So conv[n-1] = n - eps^2 * (n/2) * cos(2*pi*m/n)

For m=1: conv[n-1] = n(1 - eps^2/2 * cos(2*pi/n)) ≈ n(1 - eps^2/2)
For m=n/2: conv[n-1] = n(1 - eps^2/2 * cos(pi)) = n(1 + eps^2/2) — this INCREASES the center!

So using m=1 (or m close to 1) is good, but m=n/2 is bad. We want low frequencies.

For multiple components:
a[i] = 1 + eps_1*sin(2*pi*i/n) + eps_2*sin(2*pi*2*i/n) + ...

conv[n-1] = n - (n/2)*sum_m eps_m^2 * cos(2*pi*m/n) (assuming cross terms vanish, which they do for different frequencies)

So we want to maximize sum_m eps_m^2 * cos(2*pi*m/n), subject to a[i] >= 0 for all i.

The constraint a[i] >= 0 is:
1 + sum_m eps_m*sin(2*pi*m*i/n) >= 0 for all i = 0, ..., n-1.

This is the key constraint. The maximum possible "reduction" of the center depends on how much we can modulate while staying non-negative.

For the single-frequency case (m=1, phi=0, i.e., sine):
a[i] = 1 + eps*sin(2*pi*i/n) >= 0 requires eps <= 1.
Reduction: eps^2/2 * cos(2*pi/n) ≈ eps^2/2.
Max reduction with eps=1: 1/2.
J = 2*(1-1/2) = 1.

Wait, that gives J=1? That seems too good. Let me double-check.

If a[i] = 1 + sin(2*pi*i/n), then:
- a is non-negative (min value is 0, at i = 3n/4).
- sum a[i] = n.
- conv[n-1] = n(1 - cos(2*pi/n)/2) ≈ n/2 for large n.
- J = 2*n*(n/2)/n^2 = 1.

But wait, is the center really the max? Let me check for a specific small n.

n=4: a = [1+sin(0), 1+sin(pi/2), 1+sin(pi), 1+sin(3pi/2)] = [1, 2, 1, 0].
conv = [1, 4, 6, 4, 1, 0, 0]. Max = 6 at k=2 (center, n-1=2).
sum = 4. J = 2*4*6/16 = 3. Not 1!

Hmm, for n=4 it's 3, not close to 1. The approximation breaks down for small n because the "periodic" assumption fails.

n=10: a[i] = 1 + sin(2*pi*i/10) for i=0..9.
a = [1, 1.588, 1.951, 1.951, 1.588, 1, 0.412, 0.049, 0.049, 0.412]
