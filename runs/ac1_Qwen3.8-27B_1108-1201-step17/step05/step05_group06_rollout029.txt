Let me also think about the "peak-targeted coordinate descent" more carefully.

If the convolution peak is at position k*, then `conv[k*] = sum_i a[i] * a[k*-i]` (with valid indices). To reduce this, we can:
- Reduce the product terms that contribute most to the sum.
- The term `a[i] * a[k*-i]` is largest when both a[i] and a[k*-i] are large.

So we want to "spread out" the mass: reduce a[i] and increase a[k*-i] (or vice versa) to reduce the product.

This is like a "balancing" operation. For each pair (i, k*-i), we can transfer mass from the larger to the smaller.

**Balancing algorithm:**
1. Compute conv, find peak position k*.
2. For each pair (i, k*-i) with both indices in [0, n-1]:
   - If a[i] > a[k*-i], transfer δ from a[i] to a[k*-i] (and compensate elsewhere to maintain sum).
   - Choose δ to minimize conv[k*].
3. Repeat.

But we need to maintain sum(a) = 1, so transferring from a[i] to a[k*-i] is fine (sum is preserved).

The optimal δ for a pair (i, j) where j = k*-i:
`conv[k*]` contains the term `a[i]*a[j]` (plus other terms). If we change a[i] -> a[i]-δ and a[j] -> a[j]+δ:
New product: `(a[i]-δ)*(a[j]+δ) = a[i]*a[j] + δ*(a[i]-a[j]) - δ^2`

This decreases when `δ*(a[i]-a[j]) - δ^2 < 0`, i.e., `δ < a[i]-a[j]` (assuming a[i] > a[j]).

The maximum decrease is at `δ = (a[i]-a[j])/2`, giving a decrease of `(a[i]-a[j])^2/4`.

But changing a[i] and a[j] also affects other convolution values! So we need to check that we don't increase another peak.

This is where it gets tricky. Let me just implement a simple version:
- For the peak position k*, find the pair (i, j) with the largest product a[i]*a[j] (where j = k*-i).
- Transfer mass from the larger to the smaller, but limited to not increase any other convolution value above the current max.
- Use line search to find the best transfer amount.

This is essentially a two-coordinate descent specialized for the peak.
