1. Approach and rationale

1.1 Central idea
The final method is a hybrid stochastic/deterministic search for a small discretization of the one-dimensional Erdős overlap problem. The core deterministic improvement step is a trust-region linear minimax subproblem: at any current feasible `h`, every correlation value `C_d(h)` is approximated by its exact value plus its exact gradient times a proposed displacement. The linearized max feels real correctly according to `np.correlate(h, 1 - h, mode="full")`, and minimizing its maximum subject to the true line-sum and box constraints is exactly a linear program. This gives a strong, non-smooth, locally-global direction that preserves feasibility and evaluates a concrete increase/decrease value `t`. The LP step is paired with (a) anti-palindromic even/odd reductions, which naturally satisfy the mass constraint, (b) global random restarts across several resolutions, (c) binary simulated annealing in the naturally balanced anti-palindromic binary subspace, and (d) continuous final polishing by the same linear trust-region method. Exact `np.correlate` evaluation is always authoritative; no surrogate value is ever trusted.

1.2 Why this can improve a stuck parent
The supplied parent has already been driven by active-set/smooth local methods. If its approximate active correlations are stationary, refining with another local BFGS/SLSQP process may fail. A trust-region linear minimax step is different because each internal step exactly computes the minimum of a global epigraph model over all lag directions, rather than smoothing the maximum or optimizing active constraints heuristically. The method also starts from many globally generated candidates, including binary and non-anti candidates, to avoid the parent’s local basin.

1.3 Scope and limitations
The objective contains quadratic interactions `h_i (1 - h_j)`, so the overall problem is nonconvex. The linear program is only a trust-region model, not a global convex relaxation. Therefore the method cannot claim global optimality or even a guaranteed decrease. Every accepted improvement must pass the original evaluator. The stochastic parts are heuristics: simulated annealing may move to worse objective states without guarantee. Their only validity comes from exact evaluation and ranked best storage. If all temporal subtasks fail, the supplied valid parent is returned.

2. Mathematical specification

2.1 Exact discrete problem
For a returned vector `h ∈ ℝ^n` and `dx = 2.0 / n`, the official objective is
```
C5(h) = dx * max(np.correlate(h, 1 - h, mode="full"))
```
There are `2n - 1` correlation outputs. Define lag index `k = 0, 1, ..., 2n - 2`, and integer sign `d = k - (n - 1)`.

Use the following exact lag value, including finite boundary restrictions:
```
if d >= 0:
    C_d = sum_{i=0}^{n-1-d} h[i+d] * (1 - h[i])
else:
    e = -d
    C_d = sum_{i=e}^{n-1} h[i] * (1 - h[i-e])
```
The official correlation-normalized scalar is `F_d = dx * C_d`. Desired optimization objective is `max_{d} F_d(h)`.

The mass constraint is equivalent to both:
```
dx * sum_i h[i] = 1
sum_i h[i] = n / 2
```
Use the latter for feasibility repair.

2.2 Feasible subspace
Every returned sequence must satisfy:
- `0 <= h[i] <= 1`, allowing only numerical tolerance `< 1e-12`, with a safe joint repair described in section 3.
- `abs(sum(h) - n / 2) <= 1e-12`, again repaired immediately before evaluation.

Positive relationships: If a candidate produced by a reduced representation is compared directly with a parent at a different resolution, no attempt is made to call the representations intrinsically equivalent. The scan completes with exact original-function verification.

2.3 Anti-palindromic representation
For even `n = 2m`, use variables `q ∈ ℝ^m` and
```
h = [ q[0], q[1], ..., q[m-1],
      1 - q[m-1], ..., 1 - q[1], 1 - q[0] ]
```
The full `sum(h)` is exactly `m` independent of the actual values of `q`, hence `sum(h)=n/2`.

For odd `n = 2m + 1`, use variables `q ∈ ℝ^m` and fixed center `0.5`:
```
h = [q[0], ..., q[m-1], 0.5, 1-q[m-1], ..., 1-q[1], 1-q[0]]
```
The full `sum(h)` is exactly `m + 0.5 = n/2`.
