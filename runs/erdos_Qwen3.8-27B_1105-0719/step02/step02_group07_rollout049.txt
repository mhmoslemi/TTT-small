def continuous_refine(h0, n, beta, time_limit=20.0):
    dx = 2.0 / n
    target_sum = n / 2.0
    
    def obj(x):
        h = np.clip(x, 0.0, 1.0)
        # Project for feasibility
        h = project_feasible(h, target_sum)
        f = np.correlate(h, 1.0 - h, mode='full') * dx
        return np.logsumexp(beta * f) / beta
    
    def obj_grad(x):
        h = project_feasible(np.clip(x, 0.0, 1.0), target_sum)
        f = np.correlate(h, 1.0 - h, mode='full') * dx
        shifted = f - f.max()
        w = np.exp(beta * shifted)
        w /= w.sum()
        # Gradient of each f_k with respect to h
        n_lags = 2 * n - 1
        grad = np.zeros(n)
        for k in range(n_lags):
            wk = w[k]
            if wk < 1e-15:
                continue
            d = k - (n - 1)
            # f_k = sum_i h[i]*(1-h[i+d])*dx over valid i
            # df_k/dh[i] = (1-h[i+d])*dx + (-h[i-d])*dx (where valid)
            i_vals = np.arange(n)
            # Terms where i is first index: i+d valid means 0 <= i+d < n
            mask1 = (i_vals + d >= 0) & (i_vals + d < n)
            # Terms where i is second index: i-d valid means 0 <= i-d < n
            mask2 = (i_vals - d >= 0) & (i_vals - d < n)
            grad[mask1] += wk * (1.0 - h[i_vals[mask1] + d]) * dx
            grad[mask2] += wk * (-h[i_vals[mask2] - d]) * dx
        return grad
    
    try:
        res = minimize(obj, h0, jac=obj_grad, method='L-BFGS-B',
                       bounds=[(0.0, 1.0)] * n,
                       options={'maxiter': 200, 'ftol': 1e-15})
        h_out = project_feasible(res.x, target_sum)
        return h_out, exact_score(h_out)
    except Exception:
        return h0, exact_score(h0)

Wait, I need to be more careful about the binary local search. The greedy best-improvement approach (try all positions, pick the best) is correct but can be slow. Let me make it more efficient.

Actually, for n=126, each round involves trying 126 positions, and for each position, we compute a delta vector of length ~126 and add it to a copy of f (length 251). So each round is about 126 * (126 + 126 + 251) ≈ 73,000 operations. With numpy, this should be about 0.1-0.5 ms per round. In 30 seconds, that's 60,000-300,000 rounds. Should be more than enough.

But I realize there might be an issue: the "best improvement" hill climbing will converge to a local minimum very quickly (probably in less than 1000 rounds). After that, no single flip improves the solution, and we're stuck.

To escape local minima, I should:
1. Allow occasional worsening moves (simulated annealing)
2. Do multi-start from different initial points
3. Try "2-flip" moves (flip two bits simultaneously)
