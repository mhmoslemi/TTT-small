`h_i = v_i` for `i < m`,  
`h_i = 1 - v_{n-1-i}` for `i >= m`.

For odd `n=2m+1`, place `h_m = 0.5` and do the same for side pairs. This family always has the correct integral in exact real arithmetic because every pair contributes `v + (1-v) = 1`, and numeric feasibility can be restored by projection. It also naturally controls the two lag directions instead of representing every state through Newton music-like constraint spaces.

Why this is potentially better than the current parent:

- The parent around `0.380934` has several nearly tied active lags. Soft-max smoothing gives near-zero gradients to lag values just below the maximum. A true epigraph or tangent LP solution treats active and near-active lags as their own constraints and can make coordinated moves found only by balance, rather than an average.
- The needed improvement is small. Local exact constraint engines are better suited than broad smooth reoptimization.
- Tangent LP moves are computed from current exact derivatives for the top lags. Exact line搜索 evaluates the true bilinear nonconvex quadratic; false predicted directions are rejected before acceptance.
- Structural `anti-complement` feasible starts are outside the copied smooth parent basin but are not manually hard-coded. They are constructed by formulas and seeded generation and are exactly easy to enforce.
- Dimensional transfer you − one simple but often harmful interpolation plus projection to smaller grid lengths gives additional opportunities.

Important limitations:

- This is not a global verification method. The original problem is nonconvex because each correlation is bilinear in `h`; there is no claim of exact global optimality.
- Tangent LP moves are not exact proofs: the tangent system is a linear approximation of bilinear functions. Acceptance is always by exact finite-array re-evaluation.
- Exact epigraph NLP is nonconvex and local. It can remain in the same basin if starting too close. A good mix of structural starts should help, but no debit claim is made outside the solution search.
- All lower bounds obtained are upper bounds for the discrete solver problem. If the project fails locally, the fallback is a valid around the supplied parent or the constructed fallback, with its honest exact score, not current needed goal.

1.2 Distinction from merely re-calling a smoother

The primary descent methods are not `logsumexp` smoothing of all lag values. The primary methods are: constraint-aware direct epigraph optimization for small high-precision stationary steps; and a tangent-LP subproblem that enforces structural active set reductions. Only if time remains after the primary LP/NLP sequence is a generalized weighted-near-average `subgradient step` employed, and its output is accepted by an exact evaluator.

1.3 Critical acceptance principle

No returned array or score depends on a relaxed surrogate objective, discrete validation code path alone, or the linearized LP value. Every proposed array is put through projection, its sum enforced, full validity checked, and then scored by the original correlation evaluator. Only exact-score additions to a candidate registry update the output.

2.1 Authoritative exact objective and dimensions

For every formed candidate:

`h` is a 1D float vector with length `n >= 2`.

`dx = 2.0 / n`.

`target_sum = n / 2.0`.

Define:

`corr = np.correlate(h, 1.0 - h, mode="full")`, a raw array of length `2n-1`.

The reported exact score is:

`raw_max = max(corr)`

`C_exact = raw_max * dx`.

All comparisons across candidate lengths or near-neighbor frequencies use `C_exact`, never raw correlation numbers alone. All positive and negative lag boundary contacts are present because one uses the full two-sided linear correlation with no circular wrap and none of full circular wrap.
