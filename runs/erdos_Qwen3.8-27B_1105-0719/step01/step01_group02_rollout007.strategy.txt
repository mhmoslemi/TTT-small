1. Approach and rationale

The supplied evaluator is a finite nonlinear max-over-lags problem

    C(h) = max_t [ dx * np.correlate(h, 1 - h, mode="full")[t] ],

where h is a sampled vector of length n over an interval of length 2, dx = 2/n, and feasibility is h[i] in [0,1] and sum_i h[i] = n/2. The previous construction is already very close to the desired upper bound, so very broad global exploration is unlikely to be decisive. The bottleneck is more likely high-precision local reduction of the profiles that are currently binding at the maximum. A single binding lag can decline, while another lag becomes binding because of boundary terms and the nonconvex quadratic structure of h_i(1-h_j). Generically smoothing the objective or doing random pairwise moves either dilutes the improvement signal from the active lags or fails to move all binding profiles down together.

The primary proposed algorithm is an exact-objective active-lag penalty-direction local search:

1. Use the official linear correlation to compute the exact profiles and exact maximum score.
2. At a current feasible h, identify only the contemporaneous active or near-active lag profiles.
3. For those active profiles, construct their exact first-order signed-lag derivatives in a way that is explicitly aligned with np.correlate(h, 1-h, mode="full").
4. Solve a convex quadratic penalty problem for a step direction d in h-space that attempts to make the linearized active profiles decrease together, while preserving the sum of h exactly and taking the box constraints into account through variable bounds on d.
5. Do not trust the surrogate solution. Accept a step only after computing the original evaluator on h + alpha*d for a small decreasing list of alphas, after restoring exact feasibility.
6. When the single-direction step engine stalls, use active-gradient-ranked and random pair transfers, stochastic block perturbations, candidate rescaling to other dimensions, and exact restart from the incumbent best.

This is materially different from the earlier log-sum-exp-smoothed SLSQP and generic pairwise-search program. The original numerical optimization does not directly confront the singularities of the max-of-quadratics objective: the active set determines feasible descent directions much more sharply than the full set of inactive profiles. The proposed direction problem is convex only for its linearized active constraints, but all moves are validated by the exact objective. No global optimum, complete KKT convergence, or a proof of global uniqueness is claimed. The goal is to produce a better feasible discrete vector than the parent; a general-purpose claim of optimality would be false for this finite nonconvex quadratic-max problem.

The program must always retain a feasible parent or a feasible fallback. If no improvement is found, it must return the best feasible vector and its exact score before timeout.

2. Mathematical specification

2.1 Exact sampled objective

Use n even. Let

    dx = 2.0 / n,
    target = n / 2.0,
    g = 1.0 - h.

The raw profile array is exactly

    r = np.correlate(h, g, mode="full").

The profile length is 2n-1. The exact score is

    C(h) = dx * max(r).

This exact expression is authoritative for all acceptance, candidate comparison, and final return. Do not replace it with circular convolution, periodic autocorrelation, FFTs that alias lags, or any transformation of the form 1 minus an autocorrelation unless the transformation has been redone from the explicit array profile and exactly matches np.correlate.

2.2 Signed lag indexing compatible with np.correlate

For an output profile index t with 0 <= t < 2n-1, define the signed lag

    s = t - (n - 1).

With this definition, the built-in correlate output obeys

    r[t] = sum_m h[m + s] * (1 - h[m]),

where m is restricted to indices for which

    0 <= m < n,
    0 <= m + s < n.

Equivalently:

- if s >= 0, m ranges from 0 to n-1-s, giving terms h[m+s](1-h[m]);
- if s < 0, m ranges from -s to n-1, again giving terms h[m+s](1-h[m]).

A necessary implementation check is that for a small numeric h and any selected t, the raw value computed by a direct loop over the valid m range matches Python/numpy `np.correlate(h, 1.0 - h, mode="full")[t]`. If this check fails, never apply it instead of the actual evaluator; all scoring must still be performed from `np.correlate` so that the accepted bound remains valid.

2.3 Exact gradient of a raw profile row

For fixed h, the raw profile row r[t] is a quadratic function of h. Define its gradient with respect to the coordinate vector h, in raw units and without any dx scaling. For s = t - (n-1), let G_t be a length-n vector initialized to zero. For all valid m in the range above:

    i = m + s
    G_t[i] += 1.0 - h[m]
    G_t[m] -= h[i]

This accumulation handles rows where a coordinate appears twice. For s=0 each coordinate receives exactly (1-h[i]) - h[i] = 1 - 2h_i, which is the derivative of h_i(1-h_i).

To verify this row numerically inside the implemented solver before it is relied upon heavily:

- Generate a tiny deterministic non-boundary h.
- Pick one or more random nonempty lags.
- Choose a random direction q.
- For a small epsilon, compute raw[t](h+epsilon*q) and raw[t](h-epsilon*q).
- Compare (raw[t](h+eps*q)-raw[t](h-eps*q))/(2*epsilon) with G_t dot q.
- Use relative tolerance around 1e-7 to 1e-5.

If the row-gradient formula fails this check, then disable gradient-based active solving and rely only on exact pair transfer, random block perturbations, and parent retaining; do not use a conflicting corrected-derivative error because the main objective has not been accepted exactly.

2.4 Feasibility repair that preserves both box and sum

Use a joint water-filling projection, not sequential clipping followed by naive rescaling. Let a be an input vector of valid length, with NaNs mapped to 0, positive infinities mapped to 1, negative infinities mapped to 0. It must return y satisfying:

    0 <= y[i] <= 1,
    abs(sum(y) - n/2) <= 1e-9 or as close as floating point permits,
    and if the target is representable, the returned vector is usable for rebuild exact scoring.

Algorithm:

1. Set lower cap 0 and upper cap 1, target = n/2.
2. If n is odd or otherwise invalid for the intended exact discrete constraint, resize or interpolate it to the nearest corresponding even length before projection. Do not return odd n.
3. Start with y_low = clip(a,0,1). If the target already lies within a tolerance, return.
4. The family T(lambda, a) = clip(a + lambda, 0, 1) has a sum S(lambda). S(lambda) is continuous and nondecreasing because each component is clipped coordinatewise. S(lambda) approaches 0 for lambda -> -infinity and approaches n for lambda -> +infinity.
5. Expand a scalar bracket [lambda_low, lambda_high]: begin low=-1, high=1 and expand by factors of two until S(lambda_low) <= target <= S(lambda_high).
6. Solve for the lambda at which S(lambda) = target with 60 to 80 bisection steps.
7. Return y = clip(a + lambda_star, 0, 1) and then perform a small final mass repair only if needed:
   - diff = sum(y) - target.
   - If abs(diff) <= 1e-11, no repair is necessary.
   - If abs(diff) is larger or the verification requires a tighter sum, choose indices with actual capacity in the required direction and add or subtract exactly the needed amount, bounded so every coordinate stays in [0,1]. Prefer distributing over multiple non-boundary coordinates if possible. Because the final diff in this use case is usually only a floating residual after bisection, this final repair is a diagnostic stability step.

For short-step feasibility-preserving directions, use exact repair rather than full projective water-filling whenever the step sum is only numerically nonzero:

- Candidate v = h + alpha*d.
- Compute error = sum(v) - target.
- If |error| is tiny relative to n, add a distribution while preserving box capacity; if the error is large, discard the candidate or apply water-fill on v.
- Every candidate accepted into the exact line search must be rechecked against bounds and the sum objective before it is called feasible.

2.5 Active-lag linearized-test direction problem

At a feasible h, compute profiles r and raw maximum r_max. Choose active profile indices A. For row t in A, compute the raw gradient vector G_t as in section 2.3. Let m = |A| and assemble matrix G of shape (m, n), rows G_t. In raw units, a step d changes row t approximately by G_t dot d. We want to lower active rows by at least a desired raw amount eta > 0, meaning the linearized constraint should seek

    G_t dot d <= -eta.

Then formulate the following convex quadratic penalty problem in variables d_i and violation variables z_j:

    minimize    ||d||_2^2 + alpha_violation * sum_j z_j

subject to

    sum_i d_i = 0,
    d_i >= max(-R, -h_i),
    d_i <= min(R,  1 - h_i),
    z_j >= G_j dot d + eta,
    z_j >= 0.

Here d's lower and upper bounds correspond to allowing the vector h+d to remain in boxes if the step is full, except that the exact line search later may use smaller h+alpha*d. The equality is linear and operates on raw d values, but it does not imply that projected h+d in the later feasibility step is correction-only unless sum(d)=0 exactly; enforce it numerically. The problem is not a global convex relaxation of the original nonconvex problem; it is a local convex active-first-order model. Nonactive profiles can still cause failing behavior at finite h changes, and that nonlinearity is resolved by exact line acceptance and not assumed.

A solver implementation should use CVXOPT (via cvxpy if available) because all constraints are linear and the objective is a convex quadratic in d plus a linear term in z. Carefully enforce:
  dim(row_active) of z equals G active size;

1. Approach and rationale

The supplied evaluator is

    C(h) = dx * max_t [ np.correlate(h, 1.0 - h, mode="full")[t] ],
    dx = 2.0 / n,

with length n even, h[i] in [0,1], and sum_i h[i] = n/2. The current parent is already extremely close to the target magnitude, so the main computational bottleneck is high-precision local descent of the binding shifted profiles while rigorously maintaining finite box constraints and the exact discrete sum.

The proposed primary algorithm is an active-lag penalty-direction local solver. At a feasible h, it identifies the nonnegatively weighted active or near-maximum lag profiles, builds their exact first-order signed-lag derivatives, and solves a convex active-linearization model that tries to move all active profile rows down together. Every candidate step is then accepted only after recomputing the original discrete objective exactly. This avoids diluting descent directions by smoothing over many inactive profiles and it explicitly addresses a major source of local stagnation in functions of the form max_t quadratic_t.

The method does not claim global optimality. The finite nonconvex objective is a max over many quadratic terms, and an active-linearization step may fail because inactive profiles become binding at finite h. Therefore:

- The incumbent best exact objective and its corresponding feasible vector are always retained.
- Inactive constraints are rechecked by exact evaluation at every accepted candidate.
- When the active direction engine stalls, the algorithm falls back to active-gradient-ranked pair-transfer moves, randomized pair/block perturbations, exact binary/bit refinement from thresholded vectors, and candidate rescaling to adjacent or smaller discretizations.
- If a valid bound below the target is found, the algorithm can stop early while preserving that bound.
- If `cvxpy` or a QP solver is unavailable, a SLSQP-based differentiable penalized hinge direction fallback is used. Failure of the optional solver does not terminate execution; a feasible incumbent is returned.

Correct requirements, explicitly imposed throughout: every returned `h_values` must have finite entries within [0,1] and sum equal to `len(h)/2` to numerical tolerance; the returned score must be recomputed with the same exact signed-lag `np.correlate` evaluator. No asymptotic Fourier, continuous, circular, or autocorrelation identity is used.
