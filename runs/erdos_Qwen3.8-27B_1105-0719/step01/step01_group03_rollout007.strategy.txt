1. Approach and rationale

1.1 Problem structure and failure mode of the previous run  
For a discrete vector `h` of length `n`, with `dx = 2/n`, the exact objective analyzed by the evaluator is the maximum, over all `2n-1` finite lags, of the cross-overlap profile

`p(h) = corr(h, 1-h, mode="full") * dx`.

The feasible set is the convex polytope

`P_n = {h : sum_i h_i = n/2, 0 <= h_i <= 1}`.

For fixed bounds and the linear sum constraint, `P_n` is simple, but each profile entry is a bilinear polynomial in the variables `h_i`: the products `h_i h_j` make the true maximization nonconvex. The previous program attempted a constrained epigraph SLSQP solve from the parent and Gaussian perturbations. That framework is already constrained-nonlinearity-aware, but appears too local: the search remained around the parent basin and did not reach the supplied target `C_5 <= 0.3808`. The main experimental vulnerability is therefore not only numerical tolerance: the search size and the starting geometry do not provide enough independent directions inside the bilinear nonconvex landscape.

1.2 New central idea  
Use a search engine whose raw motion is driven by smooth one-objective approximations of the maximization problem, but whose decided motion always uses feasible long moves in the polytope and exact recomputation. The primary method will be a sequence of smoothed epigraphic maximization problems solved in the feasible polytope by a combination of:

- projected smooth Frank-Wolfe/conditional-gradient moves, including a full feasibility-preserving line search;
- gradient descent/Trust-region projected polishing on the same smooth objective from many good feasible starts;
- exact epigraph-style constraint methods only as local polishers after the objective-maximization stages have produced better feasible candidates.

This differs materially from simply running SLSQP on the full epigraph. Rather than solving one full nonlinear program, the algorithm:

- anneals a smooth surrogate objective for the unsmooth maximum;
- makes geometrically large, exactly feasible steps by moving toward useful simplex/polytope vertices or projected directions;
- creates several initial basis functions by transformation, symmetrization, rank/binary calibration, and interpolation between dimensions;
- re-evaluates every candidate using the original evaluator after all transformations;
- never returns a candidate from a surrogate value unless the exact evaluator has confirmed it is feasible and lower.

1.3 Why this can improve  
The feasible set has a simple structure: the linear constraints are box and one affine equality, and segments inside the polytope remain feasible. Conditional-gradient-style moves can traverse from the parent into geometrically very different feasible regions: rank-extreme vertices, binarized rank patterns, and averaged tilings that can require simultaneous coordinate movement. These long moves are exactly feasible throughout; no repair is needed once inside the polytope except when constructing padded starting points. The smooth surrogate (log-sum-exp over the full profile) is differentiable and enables gradient/line-search calculations that the exact `max` does not, but acceptance remains exact and thus correct with respect to the evaluator.

There are important limitations. The nonconvex profile means smoothed phases can converge to smooth local hollows. The method is heuristic: there is no global optimality claim. The exact epigraph stage also cannot prove optimality. But because every suggested solution is tested and validated by exact `np.correlate`, all returned bounds remain valid.

1.4 Material difference from the previous code  
The old program integrated smooth-gradient local descent into an Newton/line procedure. This plan replaces its main global motion with the natural convex feasible-polytope geometry used by Frank-Wolfe. It avoids optimizing SLSQP directly through bimodal semi-adjoint constraints when only smoothing is needed. It also treats dimension transformation as an explicit size exchange platform rather than a single interpolation/reoccupation. The exact epigraph is retained as polishing, but no longer as the sole local optimizer.

2. Mathematical specification

2.1 Exact evaluator as objective

For `h` of length `n`:

`dx = 2.0 / n`

`profile = np.correlate(h, 1.0 - h, mode="full") * dx`

`C(h) = max(profile)`.

Use `profile` in all exact scoring calls. Do not replace it with circular autocorrelation or with an identity omitting frontier terms. The returned bound must use this same formula.

For smooth safety with large `h` arrays, compute `np.logaddexp` forms for the smooth function, but the accepted objective remains `max(profile)*(only if entirely nonnegative? profile entries are probabilities times dx; nonnegative)`.

2.2 Feasible set

Given `target = n/2.0`, required feasibility is exact interval and sum:

`0 <= h_i <= 1` for all `i`,

`sum_i h_i = target`.

At evaluation, allow floating-point tolerance only in code selection, but the final stored candidate is repaired so remaining difference is near machine precision. APIs in the preceding program had repair functions and can optionally reuse them, but repair should be safer.

2.3 Feasible objective polytope

Because the final constraint is an affine equality with bounds, `P` is a convex polytope. Any convex combination `x(α) = (1-α)x(1) + αx(0)` inside `P` remains inside `P`, as long as both endpoints are in `P`. This structure enables exact section lines.

2.4 Profile row indexing and gradient formulas

Let `M = 2n - 1` and row index `m = 0,...,M-1`. Let the signed finite lag be

`d = m - (n - 1)`.

The rows used in `np.correlate(h, 1-h, mode="full")` are the two possible profile overlaps. The correct orientation is what must be used in gradient construction. Use formulas consistent with `np.correlate`.

For `d = 0`:

`p_center = dx * sum_{i=0}^{n-1} h_i (1 - h_i)`.

Derivative:

`∂p_center / ∂h_i = dx(1 - 2h_i)`.

For `d > 0`:

`p_d = dx * sum_{i=0}^{n-1-d} h_{i+d} * (1 - h_i)`.

Derivative:

`∂p_d/∂h_{i+d} += dx (1 - h_i)`

`∂p_d/∂h_i       -= dx h_{i+d}`.

In array slices, with vector row weight `w_d`:

`grad[d:n]   += w_d * dx * (1 - h[0:n-d])`

`grad[0:n-d] -= w_d * dx * h[d:n]`.

For `d < 0`, let `s = -d`:

`p_{-s} = dx * sum_{i=0}^{n-1-s} h_i * (1 - h_{i+s})`.

Derivative:

`∂p_{-s}/∂h_i += dx (1 - h_{i+s})`

`∂p_{-s}/∂h_{i+s} -= dx h_i`.

In slices with row weight `w_s_reset`:

`grad[0:n-s] += w_s * dx * (1 - h[s:n])`

`grad[s:n]   -= w_s * dx * h[0:n-s]`.
