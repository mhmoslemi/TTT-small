    """Compute change in overlap at lag k when swapping h[i] (1→0) and h[j] (0→1)."""
    # Lag k in the full profile: index = (n-1) + k for k >= 0
    # The overlap at lag k is sum of h[p]*(1-h[p+k]) for p in [0, n-1-k]
    # Affected positions p: i, i-k, j, j-k (if in valid range)
    
    affected = set()
    for p in [i, i-k, j, j-k]:
        if 0 <= p <= n-1-k:
            # Check that p+k is also valid
            if 0 <= p+k < n:
                affected.add(p)
    
    delta = 0.0
    new_h_i = 0.0  # h[i] becomes 0
    new_h_j = 1.0  # h[j] becomes 1
    
    for p in affected:
        q = p + k
        # old contribution
        old_h_p = h[i] if p == i else (h[j] if p == j else h[p])
        old_h_q = h[i] if q == i else (h[j] if q == j else h[q])
        old_contrib = old_h_p * (1.0 - old_h_q)

        new_contrib = new_h_p * (1.0 - new_h_q)
        
        delta += new_contrib - old_contrib
    
    return delta

The issue is that no matter how we arrange the 1s and 0s, there will be some lag where many 1s are followed by 0s.

This is similar to the problem of constructing a binary sequence with flat autocorrelation (like a Costas array or a Barker sequence, but for the "one-sided" autocorrelation).

Actually, this is related to the concept of a "minimum peak sidelobe" sequence! In radar/communications, we want sequences with low peak sidelobe levels in their autocorrelation. The problem here is slightly different (we're looking at the cross-correlation of h with 1-h, not the autocorrelation of h), but it's in the same spirit.

For the autocorrelation of a binary sequence, the problem of minimizing peak sidelobe is well-studied. The best known binary sequences have peak sidelobe around O(√n) for length n.

For our problem, the "overlap" at lag k is related to the autocorrelation:
overlap_k = Σ h[i](1-h[i+k]) = Σ h[i] - Σ h[i]h[i+k] (over valid i)

The autocorrelation R(k) = Σ h[i]h[i+k]. So overlap_k = (sum of h[i] for valid i) - R(k).

The "sum of h[i] for valid i" depends on k (it's the number of 1s in positions [0, n-1-k]).

This makes it harder to directly apply results from the autocorrelation literature.

```python
def swap_delta_profile(h, i, j, n):
    """Compute the delta in the full profile when swapping h[i] (1→0) and h[j] (0→1)."""
    # Returns array of deltas for each lag in the full profile
    # Full profile has 2n-1 entries, index = (n-1) + lag
    deltas = np.zeros(2*n-1)
    
    for lag in range(-(n-1), n):
        if lag == 0:
            continue  # overlap at lag 0 is always 0
        k = abs(lag)
        sign = 1 if lag > 0 else -1
        
        if lag > 0:
            # overlap_k = sum_{p=0}^{n-1-k} h[p]*(1-h[p+k])
            # Affected p values: i, i-k, j, j-k (if in [0, n-1-k])
            for p in [i, i-k, j, j-k]:
                if 0 <= p <= n-1-k and 0 <= p+k < n:
                    # old contribution
                    old_hp = h[i] if p == i else (h[j] if p == j else h[p])
                    old_hq = h[i] if (p+k) == i else (h[j] if (p+k) == j else h[p+k])
                    old_c = old_hp * (1.0 - old_hq)
                    # new contribution
                    new_hp = 0.0 if p == i else (1.0 if p == j else h[p])
                    new_hq = 0.0 if (p+k) == i else (1.0 if (p+k) == j else h[p+k])
                    new_c = new_hp * (1.0 - new_hq)
                    deltas[(n-1) + lag] += new_c - old_c
        else:
            # lag < 0, let a = -lag = k
            # overlap = sum_{p=k}^{n-1} h[p]*(1-h[p-k])
            k = -lag
            for p in [i, i+k, j, j+k]:
                if k <= p <= n-1 and 0 <= p-k < n:
                    old_hp = h[i] if p == i else (h[j] if p == j else h[p])
                    old_hq = h[i] if (p-k) == i else (h[j] if (p-k) == j else h[p-k])
                    old_c = old_hp * (1.0 - old_hq)
                    new_hp = 0.0 if p == i else (1.0 if p == j else h[p])
                    new_hq = 0.0 if (p-k) == i else (1.0 if (p-k) == j else h[p-k])
                    new_c = new_hp * (1.0 - new_hq)
                    deltas[(n-1) + lag] += new_c - old_c
    
    return deltas
```

Actually, let me think about this differently. For a given swap (i, j), the affected lags are:

  So position i affects lags k ∈ {1, 2, ..., max(i, n-1-i)} (roughly)

The total affected lags for a swap is at most i + j + (n-1-i) + (n-1-j) ≈ 2(n-1) in the worst case, but typically around n.

Actually, let me think about this more carefully. For a fixed lag k, the overlap is:
overlap_k = Σ_{i=0}^{n-1-k} h[i](1-h[i+k])

A swap (i, j) changes this by:
- If i ≤ n-1-k: the term at position i changes from 1*(1-h[i+k]) to 0. Delta: -(1-h[i+k]) = h[i+k]-1
- If i-k ≥ 0 and i-k ≤ n-1-k: the term at position i-k changes from h[i-k]*(1-1) to h[i-k]*(1-0). Delta: h[i-k]
- If j ≤ n-1-k: the term at position j changes from 0*(1-h[j+k]) to 1*(1-h[j+k]). Delta: 1-h[j+k]
- If j-k ≥ 0 and j-k ≤ n-1-k: the term at position j-k changes from h[j-k]*(1-0) to h[j-k]*(1-1). Delta: -h[j-k]

But we need to be careful about double-counting when i = j-k or j = i-k, etc.

Let me define the delta more carefully. The terms that are affected are those where the index p (first position) or p+k (second position) equals i or j.

Affected first positions p: {i, j, i-k, j-k} ∩ [0, n-1-k]

For each such p, q = p+k:
- old: h_old[p] * (1 - h_old[q])
- new: h_new[p] * (1 - h_new[q])
where h_new differs from h_old only at positions i and j.

So:
- h_new[p] = 0 if p=i, 1 if p=j, h_old[p] otherwise
- h_new[q] = 0 if q=i, 1 if q=j, h_old[q] otherwise

The delta for position p is: new_contrib - old_contrib.

Total delta at lag k = sum over affected p of (new_contrib_p - old_contrib_p).

This is at most 4 terms per lag, O(1) per lag.

Now, for ALL swaps simultaneously at a fixed lag k:
- For swap (i, j), the affected positions are {i, j, i-k, j-k} ∩ [0, n-1-k]

I can vectorize this: for all i in ones, all j in zeros:
- Compute the delta for each (i, j) pair

This is a 2D array of deltas, size (n/2) × (n/2) = 70×70 = 4900 for n=140.

For a fixed lag k, I can compute all 4900 deltas in vectorized NumPy:
- delta_1[i,j] = contribution from position p=i (if valid)
- delta_2[i,j] = contribution from position p=i-k (if valid)
- delta_3[i,j] = contribution from position p=j (if valid)
- delta_4[i,j] = contribution from position p=j-k (if valid)
- total_delta[i,j] = delta_1 + delta_2 + delta_3 + delta_4 (with corrections for overlap)

This is O(n²) per lag, and O(n³) for all lags. But with NumPy, the constant factor is much smaller.
