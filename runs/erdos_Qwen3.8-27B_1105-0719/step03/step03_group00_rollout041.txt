    # k ranges from -(n-1) to (n-1), stored as offset 0 to 2n-2

        delta[ks + n-1] += h[i+ks] - 1

h[m-d]: m-d from m-m=0 to m-(m-(n-1))=n-1. So h[0:n]. ✓

So second part for coordinate m:
dx * dot(p[m : m+n], h) (both length n)

And first part for coordinate m:
dx * dot(p[n-1-m : 2n-1-m], 1-h) (both length n)

Let me verify with a small example. n=3, so p has length 5 (indices 0-4, shifts -2,-1,0,1,2).
m=1:
First part: p[n-1-m : 2n-1-m] = p[3-1-1 : 6-1-1] = p[1:4] (length 3)
dot with (1-h)[0:3].
The sum should be: sum_{d=-1}^{1} p[d+2] * (1-h[1+d])
d=-1: p[1] * (1-h[0])
d=0: p[2] * (1-h[1])
d=1: p[3] * (1-h[2])
= p[1:4] · (1-h)[0:3] ✓

Second part: p[m:m+n] = p[1:4] (length 3)
dot with h[0:3].
The sum should be: sum_{d=-(n-1-m)}^{... } ... let me use the formula: d from m-(n-1) to m = 1-2 to 1 = -1 to 1.
d=-1: p[-1+2] * h[1-(-1)] = p[1] * h[2]
d=0: p[2] * h[1]
d=1: p[3] * h[0]
= p[1]*h[2] + p[2]*h[1] + p[3]*h[0]
= reverse(p[1:4]) · h[0:3]

But I said dot(p[m:m+n], h) = p[1]*h[0] + p[2]*h[1] + p[3]*h[2]. That's WRONG!

The issue: h[m-d] when d goes from m-(n-1) to m:
m-d goes from m-(m-(n-1)) = n-1 down to m-m = 0.
So h[m-d] goes from h[n-1] down to h[0]. That's REVERSED h!

So the second part is: dx * dot(p[m:m+n], h[::-1])

Let me verify: p[1:4] · h[::-1] = p[1]*h[2] + p[2]*h[1] + p[3]*h[0]. ✓

Similarly, let me recheck the first part.
First part: sum_{d} p[d+n-1] * (1-h[m+d]) for d from -m to n-1-m.
m+d goes from m+(-m)=0 to m+(n-1-m)=n-1. So (1-h[m+d]) = (1-h)[0:n] in order.
p[d+n-1] for d from -m to n-1-m: p index from n-1-m to n-1-m+n-m = 2n-m-1. So p[n-1-m : 2n-m] (length n).
First term = p[n-1-m] * (1-h)[0] + p[n-m] * (1-h)[1] + ... + p[2n-m-1] * (1-h)[n-1]
= dot(p[n-1-m : 2n-m], (1-h))

For m=1, n=3: p[1:4] · (1-h)[0:3] = p[1]*(1-h[0]) + p[2]*(1-h[1]) + p[3]*(1-h[2]). ✓ (matches earlier)

So the final formula:
grad[m] = dx * [dot(p[n-1-m : 2n-m], (1-h)) - dot(p[m : m+n], h[::-1])]

In numpy:
```python
def compute_smooth_grad(h, beta, dx):
    n = len(h)
    one_minus_h = 1.0 - h
    S = np.correlate(h, one_minus_h, mode='full')
    S_scaled = beta * dx * S
    S_scaled -= S_scaled.max()
    p = np.exp(S_scaled)
    p /= p.sum()
    
    h_rev = h[::-1]
    # For each m: first_part = dot(p[n-1-m : 2n-m], one_minus_h)
    # This is a correlation of p with one_minus_h
    # second_part = dot(p[m : m+n], h_rev)
    # This is a cross-correlation of p with h_rev
    
    # first_part[m] = sum_i p[n-1-m+i] * one_minus_h[i] for i=0..n-1
    # = correlation of p and one_minus_h at shift (n-1-m)
    # Actually this is: (p * one_minus_h)[?] in the convolution sense
    
    # Let me just use explicit computation for clarity (n=160 is small)
    # Or use matrix multiplication:
    # first_part = P @ one_minus_h where P[m,i] = p[n-1-m+i]
    # second_part = Q @ h_rev where Q[m,i] = p[m+i]
    
    # Actually, these are just sliding dot products, which can be done with:
    # np.correlate or a matrix
    
    # Simpler: use the fact that first_part[m] = np.correlate(p, one_minus_h, 'full')[2n-2-m]
    # Let me verify: np.correlate(p, x, 'full')[k] = sum_i p[i] * x[k-i] for valid i, k-i
    # p has length 2n-1, x has length n.
    # At k = 2n-2-m: sum_i p[i] * x[2n-2-m-i]
    # Valid: 0 ≤ i ≤ 2n-2 and 0 ≤ 2n-2-m-i ≤ n-1
    # Second: 2n-2-m-(n-1) ≤ i ≤ 2n-2-m → n-1-m ≤ i ≤ 2n-2-m
    # Combined: max(0, n-1-m) ≤ i ≤ min(2n-2, 2n-2-m) = 2n-2-m (since m ≥ 0)
    # For m ∈ [0, n-1]: n-1-m ≤ n-1 < 2n-1, so upper = 2n-2-m
    # Lower = max(0, n-1-m) = n-1-m (since m ≤ n-1)
    # So i from n-1-m to 2n-2-m: n values.
    # = sum_{i=n-1-m}^{2n-2-m} p[i] * x[2n-2-m-i]
    # Let j = i - (n-1-m), so i = n-1-m+j, j from 0 to n-1:
    # = sum_{j=0}^{n-1} p[n-1-m+j] * x[2n-2-m-(n-1-m+j)] = sum_j p[n-1-m+j] * x[n-1-j]
    # = dot(p[n-1-m : 2n-m], x[::-1])
    
    # Hmm, that gives x[::-1] not x. So np.correlate(p, x)[2n-2-m] = dot(p[n-1-m:2n-m], x[::-1])
    # But I want dot(p[n-1-m:2n-m], x). So I need np.correlate(x, p)[?] instead.
    # np.correlate(x, p, 'full')[k] = sum_i x[i] * p[k-i]
    # At k = n-1-m: sum_i x[i] * p[n-1-m-i], valid when 0≤i≤n-1 and 0≤n-1-m-i≤2n-2
    # n-1-m-i ≥ 0 → i ≤ n-1-m
    # n-1-m-i ≤ 2n-2 → i ≥ n-1-m-(2n-2) = 1-m-n ≤ 0 (for m ≤ n-1)
    # So i from 0 to n-1-m: that's n-m values, not n.
    
    # This approach is getting complicated. Let me just do it with a loop or matrix.
    
    # For n=160, a simple loop is fast enough:
    grad = np.zeros(n)
    for m in range(n):
        first = np.dot(p[n-1-m : 2*n-1-m], one_minus_h)
        second = np.dot(p[m : m+n], h_rev)
        grad[m] = dx * (first - second)
    return grad
```

This is O(n²) with a Python loop, which for n=160 is 160 iterations of a dot product of length 160. Each dot product is a single numpy operation. So 160 numpy calls per gradient evaluation. That's fast (~160 * 1μs = 0.16ms per gradient).

Actually, I can vectorize this further using a Toeplitz-like matrix, but for n=160 it's not necessary.
