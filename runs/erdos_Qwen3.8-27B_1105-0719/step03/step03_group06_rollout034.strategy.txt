1. Approach and rationale
=========================

This plan improves the supplied parent by combining a different model-driven candidate generator with a separate local descent that does not rely on one hard maximum or a direct nonlinear epigraph solver. The central new ingredient is a **linearized epigraph MILP/LP relaxation for binary/candidate h**, in which the binary cross-products are represented by auxiliary variables. This is materially different from repeatedly running active descent, coordinate moves, and epigraph SLSQP/SQP: here the search space is modeled by an exact finite-support correlation surrogate solved with SciPy’s MILP/LP functionality, producing structurally different warm starts. The final bound is still judged entirely by the required objective

`max(np.correlate(h, 1-h, mode="full")) * dx`

and every returned vector is repaired to satisfy both the box constraints and the exact mass constraint.

The second major change is the smoother local refinement. Instead of using only the current maximal correlation row or a full-scale SLSQP epigraph, the method uses **log-sum-exp (LSE) weighted profile descent with conservative acceptance**. The LSE objective is only a weighted surrogate for the maximum correlation; it is used to form gradient directions and candidate steps, but every accepted move must strictly improve the exact evaluator objective (besides feasibility). LSE weighting uses all near-maximal lags, so it can reduce several active constraints at once rather than only the single largest one. This is orthogonal to hard-Max active descent and SLSQP.

Substate/risk note: the MILP/LP model is used as a heuristic candidate generator because the cross-correlation with `1-h` is nonconvex and the product terms are bilinear. 2. Mathematical specification
=============================

2.1 Exact representation and evaluator
--------------------------------------

Given integer `n` and vector `h = h[0],...,h[n-1]`, define

`dx = 2.0 / n`

The exact profile is:

`P(h) = np.correlate(h, 1.0 - h, mode="full") * dx`

with length `M = 2*n - 1`, and the exact score is:

`exact_score(h) = max(P(h))`

The required direction is minimization of this maximum, subject to:

`0 <= h[i] <= 1` for every `i`
`sum(h) = n / 2` exactly (up to a tolerance below machine-epsilon-level repair and a final re-evaluation).

For dimensions that are not even, `n/2` is still valid as a fractional target, so continuous feasibility is possible. MILP integer candidate generation will preferably use even `n` so that the binary mass constraint `sum(h) = n/2` has an integer feasible sum.

2.2 Feasibility repair
----------------------

All candidate operations that can exit the feasible set are immediately passed through a top-level feasibility repair stream. This repair is not a simple clip-then-rescale; it is designed to enforce both constraints jointly.

Top-level helper

`repair_feasible(y)`

receives arbitrary real vector `y` of length `n`, and returns `h` such that `0 <= h[i] <= 1` and `sum(h)` is numerically equal to `target = n / 2` to within a tolerance around `1e-12`, with residual direct correction.

Algorithmic specification:

1. Convert `y` to float64. Replace nonfinite values by `0.5`. Clip to `[0, 1]` initially.
2. If `abs(sum(h) - target) <= 1e-12`, return `h`.
3. Use monotone threshold-based mass correction:
   - For a candidate displacement `theta`, define `z(theta) = clip(h - theta, 0, 1)`.
   - The function `S(theta) = sum(z(theta) - target)` is monotone decreasing in `theta`.
   - Pick `lo = min(y) - 1.0` and `hi = max(y) + 1.0`.
   - Perform at most 80 bisection iterations:
     `mid = (lo + hi) / 2`
     `z = clip(y - mid, 0, 1)`
     `s = sum(z) - target`
     if `s > 0`: `lo = mid`
     else: `hi = mid`
     stop when `abs(s) <= 1e-13` or after iterations.
   - Return `h = y - hi` clipped to `[0,1]`.
4. Compute residual `r = target - sum(h)`.
   - If `abs(r) > 1e-12` and `r > 0`, allocate additional mass proportionally to coordinates with slack `1 - h[i]`, in an order from largest slack to smaller slack, preserving box constraints.
   - If `abs(r) > 1e-12` and `r < 0`, remove mass from coordinates ordered by descending current `h[i]`, never below 0.
   - Perform one direct reduce: if there is any coordinate not exactly at the needed boundary with enough capacity, shift it by `r` and clip; otherwise accept residual if `abs(r) <= 1e-11`.
5. For final exactness and return checks, re-assert target using a direct correction:
   - `r = target - sum(h)`
   - if `abs(r) > 0`, add `r` to the coordinate with the largest positive slack (if `r > 0`) or largest current value (if `r < 0`), and clip. Recompute score after return.

Repair result is always a valid “good” vector because its mass is within requested tolerance and the exact evaluator will be used to report its final value.
