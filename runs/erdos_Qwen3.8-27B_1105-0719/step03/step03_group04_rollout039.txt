    # Project x onto {h: 0<=h<=1, sum h = target}
    # Using bisection on lambda
    lo, hi = x.min() - target, x.max()
    for _ in range(100):
        mid = (lo + hi) / 2
        h = np.clip(x - mid, 0, 1)
        s = h.sum()
        if s > target:
            lo = mid
        else:
            hi = mid
    h = np.clip(x - (lo+hi)/2, 0, 1)
    # Final correction
    diff = target - h.sum()
    if abs(diff) > 1e-12:
        # Adjust one element
        if diff > 0:
            idx = np.argmax(1 - h)
        else:
            idx = np.argmax(h)
        h[idx] += diff
    return np.clip(h, 0, 1)

h[i] ∈ [max(0, L0, all lower bounds), min(1, all upper bounds)]

We binary search on T to find the minimum T where this interval is non-empty.

Then we set h[i] to some value in the feasible interval. A good choice: the value that minimizes the "second-order" objective. But for simplicity, let's just pick the midpoint of the feasible interval, or the value that minimizes h[i] (to leave room for other coordinates), or the value closest to the current h[i].

Actually, the best choice for h[i] given T* is:
- If the binding constraint is from k=n-1 (lower bound): set h[i] = L0 (minimum that works)
- If the binding constraint is from some k≠n-1 (upper bound): set h[i] = U (the tightest upper bound)
- If both: pick the midpoint

Actually, any value in [L, U] achieves max profile ≤ T*. The question is which value is best for future coordinates. A good heuristic: pick h[i] to minimize the maximum of the "nearly active" profiles (the ones just below T*). This is like a lookahead.

For simplicity, let's just pick the value in [L,U] that's closest to the current h[i] (minimum change), or the midpoint.

But wait - we also need to maintain the sum constraint! When we change h[i], we break sum(h) = n/2.

1. After changing h[i], repair the sum (like the previous code does)
2. Do paired coordinate descent (change h[i] and h[j] simultaneously, maintaining h[i]+h[j])
3. Use the sum constraint as a soft constraint (penalty)

Let me go with option 1 for now (it's simpler and the previous code showed it works).

Actually, here's a better idea: **simultaneous coordinate update with sum preservation**. 

Instead of changing one coordinate at a time, change TWO coordinates h[i] and h[j] simultaneously, maintaining h[i] + h[j] = const. This is a 2D problem:

For fixed h[i] + h[j] = s, the profiles become:
- profile[n-1] = A - dx*(h[i]² + h[j]²) + const = A - dx*(h[i]² + (s-h[i])²) + const
  = A + const - dx*(2*h[i]² - 2s*h[i] + s²)
  = (A + const - dx*s²) + 2*dx*s*h[i] - 2*dx*h[i]²
  
  This is a concave quadratic in h[i].

- For other k: profile[k] = P0_k + P1_k * h[i] + Q1_k * h[j] = P0_k + P1_k * h[i] + Q1_k * (s - h[i])
  = P0_k + Q1_k*s + (P1_k - Q1_k) * h[i]
  
  Linear in h[i].

So we have the same structure: max of a concave quadratic and linear functions, which we can solve by bisection on T.

This is more complex but maintains the sum exactly. Let me implement the simpler version first (single coordinate + repair).

    n = len(h)
    dx = 2.0 / n
    return float(np.max(np.correlate(h, 1 - h, mode="full") * dx))

def compute_profile(h):

    dx = 2.0 / n
    return np.correlate(h, 1 - h, mode="full") * dx

def project_feasible(x, target):
    """Euclidean projection onto {h: 0<=h<=1, sum(h)=target}"""
    n = len(x)
    lo = x.min() - target - 1
    hi = x.max() + 1
    for _ in range(80):
        mid = (lo + hi) / 2.0
        h = np.clip(x - mid, 0.0, 1.0)
        if h.sum() > target:
            lo = mid
        else:
            hi = mid
    h = np.clip(x - (lo + hi) / 2.0, 0.0, 1.0)
    # Exact fix
    diff = target - h.sum()
    if abs(diff) > 1e-14:
        if diff > 0:
            idx = np.argmax(1.0 - h)
        else:
            idx = np.argmax(h)
        h[idx] += diff
    return np.clip(h, 0.0, 1.0)

def repair_feasible(h):
    n = len(h)
    target = n / 2.0
    return project_feasible(h, target)

def ldse_profile(h, tau):
    """Log-sum-exp of profile, for smooth objective."""
    n = len(h)
    dx = 2.0 / n
    prof = np.correlate(h, 1 - h, mode="full") * dx
    m = np.max(prof)
    return m + tau * np.log(np.sum(np.exp((prof - m) / tau)))

def ldse_gradient(h, tau):

    n = len(h)
    dx = 2.0 / n
    M = 2 * n - 1
    prof = np.correlate(h, 1 - h, mode="full") * dx
    m = np.max(prof)
    w = np.exp((prof - m) / tau)
    w /= w.sum()
    # Build gradient
    grad = np.zeros(n)
    center = n - 1
    # profile[k] = dx * sum_j h[j] * (1 - h[j+k-center])
    # d profile[k] / d h[i] = dx * [(1-h[i+k-center])*I(0<=i+k-center<n) - h[i-k+center]*I(0<=i-k+center<n)]
    # Wait, let me use the build_gradient approach
    G = np.zeros((M, n))
    G[center, :] = dx * (1.0 - 2.0 * h)
    for d in range(1, n):
        G[center + d, 0:n-d] += -dx * h[d:n]
        G[center + d, d:n] += dx * (1.0 - h[0:n-d])
        G[center - d, 0:n-d] += dx * (1.0 - h[d:n])
        G[center - d, d:n] += -dx * h[0:n-d]
    grad = G.T @ w
    return grad

    dx = 2.0 / n
    M = 2 * n - 1
    prof = np.correlate(h, 1 - h, mode="full") * dx
    m = np.max(prof)
    w = np.exp((prof - m) / tau)
    w /= w.sum()
    
    grad = np.zeros(n)

        wv = w[idx]

        lo = max(0, -shift)

        lo2 = max(0, shift)

So profile[idx] = dx * n/2 - dx * R_shift = n*dx/2 - dx*R_shift = 1 - dx*R_shift

Wait: dx * n/2 = (2/n) * n/2 = 1. So profile[idx] = 1 - dx * R_shift.

And we want to minimize max_idx profile[idx] = 1 - min_shift dx*R_shift = 1 - dx * min_shift R_shift.

So minimizing max profile is equivalent to maximizing min_shift R_shift (the minimum autocorrelation over all shifts).

This is a nice reformulation! The problem becomes:
maximize min_shift R_shift(h)
subject to 0≤h≤1, sum(h) = n/2

where R_shift = sum_j h[j]*h[j+shift] for valid j.

This is the "maximin autocorrelation" problem. It's still non-convex, but the reformulation might help with algorithm design.

For the log-sum-exp approach, we'd minimize the log-sum-exp of (1 - dx*R_shift), which is the same as what we had before.

Actually, a better discrete approach: **coordinate descent with the exact solution**. For each coordinate, the optimal value is either at a boundary (0 or 1) or at the point where the max of the active constraints is minimized. This gives a finite set of candidate values for each coordinate, and we can pick the best one.

Let me implement this:

For coordinate i, given all other h[j] fixed:
- The profile as a function of h[i] is:
  - profile[n-1] (idx=n-1, shift=0): dx*(n/2 - sum_{j≠i}h[j]² - h[i]²) = A - dx*h[i]²
  - profile[idx] for idx≠n-1: P0_idx + P1_idx * h[i] (linear)

The max of these as a function of t = h[i] is:
f(t) = max(A - dx*t², max_idx≠n-1 (P0_idx + P1_idx * t))

We want to minimize f(t) over t ∈ [0,1].

f(t) is the max of a concave quadratic and several linear functions. The minimum occurs at:
- t = 0, t = 1, or
- A point where two (or more) of the constraints are tight.

The "interesting" points are where the concave quadratic equals one of the linear functions:
A - dx*t² = P0_idx + P1_idx * t
→ dx*t² + P1_idx*t + (P0_idx - A) = 0
→ t = (-P1_idx ± sqrt(P1_idx² - 4*dx*(P0_idx - A))) / (2*dx)

For each idx, there are at most 2 roots. The minimum of f(t) occurs at one of these roots (or at t=0 or t=1).

So the algorithm for coordinate i:
1. Compute A, and P0_idx, P1_idx for all idx
2. For each idx≠n-1, compute the roots of dx*t² + P1_idx*t + (P0_idx-A) = 0
3. Collect all candidate t values: {0, 1} ∪ {valid roots}
4. Evaluate f(t) at each candidate
5. Pick the t with minimum f(t)

This gives the EXACT optimal h[i] (ignoring the sum constraint). Then we repair the sum.

This is O(n * M) = O(n²) per coordinate, and O(n³) per sweep. For n=70, that's about 343K operations per sweep. Very fast!
