1. Approach and rationale
=========================

1.1 Central idea
----------------

Construct a verified candidate by running a small but disciplined family of feasible-face local searches on the actual discrete evaluator. The final reported quantity is always

`C(h) = dx * max_l np.correlate(h, 1-h, mode="full")[l]`,

with `dx = 2.0 / len(h)`, and feasibility is checked with the actual box and sum constraints `0 <= h_i <= 1` and `sum_i h_i = len(h)/2`. No autocorrelation proxy, circular metric, dropped boundary terms, fixed binary assumption, or substituted smooth value is used for the returned bound.

The plan combines four nontrivial layers, with a verified fallback parent kept throughout:

1. Evaluator-faithful pair decomposition. Build a pair-to-output index assignment for `np.correlate(h, 1-h, mode="full")` directly from the evaluator for the active `n`. This removes orientation ambiguity from correlation lag indexing and enables exact internal gradients of the internal additive product representation, provided a sorted-array check against the evaluator matches.

2. Smooth constrained local search on the feasible face. A log-sum-exp surrogate over the evaluator-matching correlation lags is optimized under the exact equality `sum(h) = n/2` and box constraints using a smooth constrained optimizer. This surrogate is deliberately not the final objective; it only creates candidate points.

3. Exact pair-transfer golden line polishing. Candidate points are polished by transferring mass between two coordinates while preserving the sum exactly and retaining box bounds by interval clipping. Each pair line uses the exact objective. These line searches exploit the fact that global maximum peaks can sometimes be reduced by tiny appropriate mass rebalancing between bins that participate in many high-valued pair products.

4. Resolution-bounded multistart and an optional integer-sequence certification. The same procedure is applied to parent-perturbed starts and to several coarser/finer resolutions, all exact-judged. If time allows, short branch-and-bound/MINLP feasibility checks over binary candidates with even `n` can prove a much smaller max count bound such as `C <= floor(0.3808*n/2) * dx`. This MILP part is optional; if no solver/time, the parent-derived polished best remains valid.

The claimed likely source of improvement is the focused pair-transfer and smooth constrained frontier around a parent that is already near the best known solution, not a claim that the final algorithm has found a global optimum.

1.2 Why this could improve the supplied parent
----------------------------------------------

The parent is likely close to a local minimum of a nonconvex box-constrained minimax problem. Pure projection-descent may stall because many lags have similar steep penalties and the exact objective is nonsmooth. A log-sum-exp surrogate lets a constrained optimizer coordinate simultaneous changes to multiple active maxima. Exact golden line polishing is then used because pair-transfer direction moves independently preserve the equality by construction and the evaluator is cheap for components with `n` roughly 40--60. Such line moves often reduce the dominant top lags after a surrogate point nudges the solution away from a flat or slightly wrong smooth surrogate basin.

The optional binary integer path also materializes a fundamentally different construction class: an even-length binary sequence can prove an objective upper bound through an integer maximum lag sum. If one sequence for `n=48` satisfies all directional lag sums at most `9`, the evaluated C is `9/24 = 0.375`, much below the target. Even if that integer path fails, the nonbinary feasible manifold tools can polish small records after surrogate and parent diversification.

1.3 Hypotheses versus facts
---------------------------

Facts used by construction:
- Pair-transfer moves of fixed mass between distinct entries keep `sum(h)` exactly unchanged.
- Exact feasibility can be restored jointly by monotone clipped projections and a last proportional repair that respects lower/upper capacities.
- The probated objective used for scoring is the program’s actual metric, not a differentiable surrogate value.
- Correlation full output consists only of finite support sums of products, not full circular overlaps; boundary/final lags have partial sums.

Hypotheses:
- The smoothed constrained search can move points closer to lower exact maxima near the parent.
- Adjacent/random feasible transfer vectors added during local search can break local stalls.
- If a binary branch plan solves a tightly targeted upper, this could produce much fewer program improvements necessary if not completely broken.
- A smaller-bit-tested `n` enumeration could prove an upper `0.375` if balanced input solutions exist. If not, fallback return parent safe.

No formal proof of global minimality is even by solver objective success; final reported value always checked exactly.

2. Mathematical specification
============================

2.1 Objective, constraints, and units
-------------------------------------

For a candidate one-dimensional array `h`, length `n = len(h)`:

`dx = 2.0 / n`;

Feature equality preserved: `sum(h) * dx = 1`, equivalently `sum(h) = s = n / 2`;

Box constraint: `0 <= h[i] <= 1` for all i.

The evaluator objective is exactly:

`raw(h) = np.correlate(h, 1 - h, mode="full")`;

`C(h) = dx * max(raw(h))`.

The metric treats all 2n-1 lags of full finite-support linear correlation including both half-orientations. It must not be replaced by one-minus autocorrelation without a derivation; none is used here. The exact task evaluator is final. If `h` requires numeric float conversion repairs that can move it outside `0..1`, C gets rescored after projection repair. `n` stays inclusive. Boundary lags have partial sums precisely because the finite support breaks away except deciding pair counts. Autocoric methods are not substituted. Do not reconstruct initial fixed parental table. Use `initial_h_values` directly as runtime input if it exists.

2.2 Correlation pair map derived from the evaluator itself
---------------------------------------------------------

Let `m = 2*n - 1`. To produce derivatives, construct the pair-to-output assignment via basis vectors using the actual evaluator for the given `n`:

For every ordered pair `(i,j)` in `{0,...,n-1} x {0,...,n-1}`:

- Vector `e_i` of length n with 1 at i and 0 scattered except i basis point.
- Vector `e_j` of length n with 1 at j.
- Compute `corr_ij = np.correlate(e_i, e_j, mode="full")`.
- All nonzero entries of `corr_ij` give the output indices where the product term `h_i * (1 - h_j)` can contribute for a known unknown but practical modes. If the numpy structure has only one nonzero encoded then accept; if more values with identical units/tolerance, group every nonzero with fixed by magnitude signs (if negative because norm complement, collect both contribution signs).
- Store `lag_id[i,j] = list output indices assigned to term i,j;`.

Then define the internal additive lag values:

`G_l(h) = sum_{(i,j) assigned to l} h[i] * (1 - h[j)`.
