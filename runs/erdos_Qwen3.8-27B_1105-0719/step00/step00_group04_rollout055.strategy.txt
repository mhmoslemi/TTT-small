1. Approach and rationale

1.1 Primary idea: solve an epigraph of the exact finite-support objective as a local nonconvex constrained program, then certify every returned bound by the original evaluator.

The supplied task evaluates a candidate array exactly by

    exact_score(h) = max(np.correlate(h, 1 - h, mode="full") * (2 / len(h))).

This is a nonsmooth minimax of finitely many quadratic functions over the box-sum polytope. The posterior supplied parent is already close to the best known value, so the main bottleneck is not generating a roughly valid shape; it is finding a tiny, exact reduction while preserving the global half-integral constraint. A safe and substantively different strategy from sample-smoothing or pure coordinate moves is:

    minimize t
    subject to exact lag-slice constraints  t >= all correlations,
               equality sum(h) = n/2,
               0 <= h <= 1.

The reason this is attractive is that a general nonlinear constrained optimizer can propose a simultaneous direction that changes many coordinates and changes several inactive/active lags all at once. In particular, it can reduce several active near-critical lags by correlated coordinated movements, something single-coordinate moves tend to miss. The optimizer result is merely a candidate; only the exact objective accepted by the problem statement can be reported. If the solver fails, the parent fallback is returned.

1.2 Secondary explored structures, used only as candidate generators

The first epigraph search is supported by:

- parent symmetrization and tiny feasible perturbations;
- resolution transfer between dominant parent-scale sizes;
- local interpolation/blending between all promising feasible vectors;
- a small active-set linearized directional test checked by the true max objective;
- optional tiny objective regularizers inside the NLP to escape flat/inactive solver surfaces;
- shorter or larger discretizations to see whether the legal point set improves; the returned size is only preferred smaller when the exact score is not materially worse.

None of these steps is claimed to solve the continuous or discrete global optimum. The resulting program is a validated, multi-start local minimizer with exact fallback. The central nonconvexity is never assumed convex and is never solved by a direct convex relaxation unless that exact evaluation and feasibility normalization are also performed.

1.3 Fundamental valid facts versus heuristics

Objective constraints are finite-support linear correlations with finite support: include both negative and positive lags. Smaller n is allowed and preferred for performance, but the computational bound compares only exact scores in the current discrete problem; there is no monotonic score guarantee when n changes. If transfer to n changes the value, the new score is valid and is compared only after full reevaluation.

The score h_i(1-h_{i+delta}), as a function of two coordinates and across multiple lags, has indefinite quadratic cross terms. The epigraph formulation is not a global convex optimization. The nonlinear solver is a local solver with accepted multi-restart abilities. Constraint violations, even modest finite-difference/inexact solver error, do not itself invalidate the return: repair the feasibility and re-score exact evaluator output.

2. Mathematical specification

2.1 Exact primal finite problem

Let

    n = len(h)
    dx = 2 / n
    S = n / 2
    b_i = 1 - h_i.

The constraint set is

    h_i <= 1,
    h_i >= 0,
    sum_i h_i = S.

The objective is

    C(h) = max_m F_m(h),

where m runs over the 2n-1 correlation output positions. A direct, lag-slice representation is

    F_m(h) = dx * sum_i h_i * b_j,
    where j = i + delta_m,
    0 <= i<n and 0 <= j<n.

A sign/offset ambiguity with np.correlate output order is handled as follows. Let

    E0 = np.correlate(h, 1 - h, mode="full") * dx.

Define one trial direction:

    offsets_plus[m] = m - (n - 1)

and the corresponding direct profile `P_plus`. If all entries agree with `E0` within tolerance, use plus. Otherwise use

    offsets_minus[m] = (n - 1) - m.

This gives one global `direct_profile(h, offsets_m)` function with the same orientation needed for the gradient and NLP constraints. The official evaluator remains the final writer regardless.

For any selected offset delta:

    if delta >= 0:
        i_lo = 0, i_hi = n - delta
        j_lo = delta, j_hi = n
    else:
        i_lo = -delta, i_hi = n
        j_lo = 0, j_hi = n + delta

and

    profile_row = dx * dot(h[i_lo:i_hi], 1 - h[j_lo:j_hi]).

The zero-lag row is included and must be used for Ballback active descent and for the optional NLP regularizer.

2.2 Lag gradients matching the row orientation

For a row output m with selected offset `delta`, row profile increases/decreases with:

    row_m(h) = dx * sum_{i=i_lo to i_hi -1} h_i (1 - h_{i+delta}).

For coordinate a, define 0 if expressions are undefined.

    dq_m(oa a) =
      dx * (
            1_if 0 <= a + delta < n  * (1 - h[a + delta])
            - 1_if 0 <= a - delta < n * h[a - delta 0]
           )
When delta = 0, both are valid for the same pair and py decode row becomes

    dq/da = dx * (1 - h_a - h_a) = dx * (1 - 2h_a)

which matches maximizing H0=h(1-h). This row value is the derivative of the direct profile with respect to h[a], not t. In SLSQP epigraph g=t-profile, derivative wrt h is row multiplied by negative, and wrt t is 1.
