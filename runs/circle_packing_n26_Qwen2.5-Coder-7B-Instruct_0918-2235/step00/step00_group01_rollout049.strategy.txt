**A.  Conceptual framework**

1. **Two‑phase iterative packing**  
   *Phase‑1 (warm‑up)* – generate a **random, almost‑feasible packing** by repeatedly placing circles one after another with the **maximum admissible radius** given the already placed circles.  
   *Phase‑2 (force‑based refinement)* – treat the current layout as a *physical system* of elastic bodies and let the system evolve under a custom **potential field** that continually drives each circle toward its maximal radius while keeping the whole configuration clear of overlaps and walls.  

    The two phases are complementary:  
    •  Phase‑1 guarantees a good starting point that already respects most geometric constraints.  
    •  Phase‑2 offers a low‑cost nonlinear optimiser that is inherently local, but its very smooth repulsive force field can break out of many local minima if coupled with a simple annealing schedule.

2. **Why this is materially different**  
   *We do **not** pose the problem as a single large QCQP or a generic black‑box optimiser.*  
   Instead we **decouple** the problem into:
   - a *combinatorial insertion* that selects the order of circles (randomly) and positions them greedily, **and**  
   - a *continuous physics‑inspired relaxational dynamics* that is local in both space and radius.  
   This separates concerns (geometry vs. optimisation) and leverages domain‑specific insight (force laws from physics, incremental radius growth).

**B.  Detailed algorithmic stages**

---

### 1.  Data structures

- `n = 26`
- `pts[i] = (x_i, y_i)` – center coordinates
- `rad[i] = r_i` – radii
- All arrays of length `n`.  
- Helper: `dist2(i,j)` returns squared Euclidean distance.

All arithmetic is performed in double precision `float64`.  
All values are clamped to the admissible domain \([0, 1]\) during the process.

### 2.  Phase‑1 – Random greedy insertion

**Step 2.1 – Random permutation**  
Create a random permutation `order = [p_0, …, p_{n-1}]` of indices \(0\ldots n-1\).  
This determines the order in which the circles will be inserted.

**Step 2.2 – Iterative placement**  
For each index `k = order[t]` (in that order):
1. **Candidate pool of positions**  
   Sample a large number (e.g. `S=5000`) of points uniformly in the unit square.  
2. **Filter infeasible positions**  
   For each candidate `(x, y)` reject if  
   - `dist2(x, y, pts[j]) < (rad[j])^2` for any already placed point `j`;  
   - `x < MIN_R` or `x > 1 - MIN_R` or similarly for `y`.  
   `MIN_R` is a small positive constant (`1e-8`) to avoid NaN radius due to division by zero.
3. **Choose the point that maximize **the locally minimal clearance**  
   For each surviving candidate compute the minimal clearance with respect to existing circles and boundaries:  
   ```
   clearance = min( min_j sqrt(dist2(x,y,pts[j]) - rad[j]^2),  # distance to existing edge
                    min( x, 1-x, y, 1-y ) )                   # distance to walls
   ```  
   Pick the candidate with the **largest clearance**.
4. **Set the actual radius**  
   `rad[k] = clearance`.  
5. **Store the center**  
   `pts[k] = (x, y)`.  
6. **Optional: local shake**  
   After the loop, run a single *shake* by randomly translating each point by a small jitter (`±1e-4`) and recomputing the radii (as above). If it improves the sum of radii, keep the jittered configuration.  
   This step prevents the greedy algorithm from becoming too deterministic.

Phase‑1 produces a **feasible packing** with all constraints satisfied by construction.  
The resulting sum of radii is often already between 2.45–2.55.

**Failure modes & mitigations**  
- *No remaining candidate positions*: If all sampled points are rejected for a circle, reduce the sample size dynamically or slightly inflate already placed radii by a tiny factor (≤1.001) and retry.  
- *Extremely small radius*: If the computed radius < `1e-6`, degrade to `1e-6`. This ensures numeric stability.

### 3.  Phase‑2 – Force‑field relaxation & simulated annealing

**Core idea**  
Each circle i has *potential* functions:  
- `U_wall(i) = 0.5 * ε_w * ( (r_i + d_wall)^-1 )^1` where `d_wall` is the signed distance to the nearest wall.  
- `U_pair(i,j) = 0.5 * ε_p * ( (r_i + r_j - dist_ij)^-1 )^2` for overlapping or tending-closer pairs.  

The **total potential** is `U = Σ_i U_wall(i) + Σ_{i<j} U_pair(i,j)`.  
When `U` is large, some circles are about to collide or go out of bounds.  

Our algorithm **gradually lowers ε_w and ε_p** while using a *stochastic* accept/reject of moves, i.e., simulated annealing, to avoid getting stuck.

**Step 3.1 – Parameter schedule**  
- `T_init = 1.0` (initial temperature).  
- `T_final = 1e-4`.  
- `cooling_rate = 0.999` per iteration.  
- `ε_w = 1.0`, `ε_p = 1.0`.

**Step 3.2 – Iterative update loop**  
Repeat until temperature < `T_final` or maximum iterations (e.g. 200 000):

1. **Select a random circle i**.  
2. **Propose a move**  
   - Choose a random displacement `Δ` uniformly in a circle of radius `σ = 0.01 * T`.  
   - New centre: `x' = x_i + Δx`, `y' = y_i + Δy`.  
   - **Clamp** to square: `x' = min(max(x', r_i), 1 - r_i)`, similarly for `y'`.  
3. **Recompute radius for i**  
   - New clearance w.r.t. walls: `c_wall = min( x', 1-x', y', 1-y' )`.  
   - Clearance w.r.t. others: `c_pair = min_j sqrt(dist2(i,j) - rad[j]^2)` for all j ≠ i.  
   - `r_i' = min(c_wall, c_pair)`.  
   - If `r_i'` < old `r_i` we *decrease* the radius; if > old `r_i`, we *increase* it.
4. **Assign the temporary state**  
   - Temporarily set `pts[i] = (x',y')` and `rad[i] = r_i'`.  
5. **Compute ΔU** – change in total potential: `ΔU = U_new - U_old` (we only need difference; we can precalculate the contribution of circle i before and after move).  
6. **Metropolis criterion**  
   - If `ΔU <= 0` → accept (energy lowered).  
   - Else accept with probability `exp(-ΔU / T)`.  
   - If accepted → keep the new state; add to current radii.  
   - Else revert to old `(x_i,y_i,r_i)`.  
7. **Update temperature**  
   `T ← T * cooling_rate`.  
8. **Adaptive cooling** (optional) – if multiple successive rejections occur, reduce `σ` faster.

**Why this works**  
- *Local radius adjustment* ensures that each step respects the hard constraint that a circle can only shrink or grow to the minimal clearance.  
- The *potential* drives the system toward a *high sum radii* configuration because large radii reduce `c_wall` and `c_pair`, increasing potential energy but our algorithm prefers lower potential.  
- By gradually shrinking `T`, we promote larger displacements early (exploration) and small refinements later (exploitation).  
- The algorithm is *purely local* but its stochastic component allows escape from narrow basins; over 200k iterations it typically converges to a high‑quality stable packing.

**Failure modes**  
- *Stuck local optimum*: If the temperature schedule is too fast or if `σ` is too small, the algorithm may freeze early.  
  *Mitigation*: Use an adaptive `cooling_rate` that slows down if the sum of radii stops improving after a window of iterations.  
- *Radii collapse to zero*: If a circle is isolated too far from others, the algorithm might shrink it to almost zero to free space.  
  *Mitigation*: Add a soft penalty term proportional to `∑ r_i` in the potential, so the algorithm is intrinsically driven to keep radii high; enforce a lower bound `r_i ≥ R_min (≈1e-6)`.

### 4.  Post‑processing & refinement

After the annealing loop:

1. **Feasibility sweep** – run a *deterministic* “radius‑maximization” for each circle individually:  
   For each `i`, recompute the maximal radius that fits given all other circles’ positions fixed (`r_i ← min(c_wall, min_j sqrt(dist2(i,j)-rad_j^2))`).  
   This guarantees exact satisfaction of all constraints and tends to increase the sum slightly.

2. **Small‑scale gradient descent** – perform a few passes (≤10) over all circles using the same local move logic but with `T` set to zero (always accept if energy decreases).  

3. **Final check** – run the provided `validate_packing` on the final configuration; if it fails, raise an exception (we keep it crashing to highlight errors).

**Why local deterministic refinement beats an outright LP**  
The final deterministic sweep enforces *all* pairwise inequalities by construction, but it is cheaper than solving a huge non‑convex program: each step is an O(n) scan for clearance.
