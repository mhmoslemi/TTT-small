**Goal**  
Return a packing of 26 circles in the unit square that satisfies all geometric constraints and achieves a sum of radii strictly larger than 2.636.

**High‑level idea**  
Treat the circle centres as the *design variables* and, for each candidate configuration of centres, compute the largest radii that can be placed without overlap by solving a *linear programme* (LP).  
The LP is convex and very fast because it has only 26 variables (the radii) and ≈ 400 linear inequalities.  
We then optimise the centres with a cheap, derivative‑free optimiser (Differential Evolution, DE).  
The optimiser evaluates the LP for each candidate centre set, obtains the optimal total radius, and tries to find a configuration that pushes this sum beyond the target threshold.

**Why this works**  
* For a fixed set of centres, the problem “maximise ∑ rᵢ subject to rᵢ+rⱼ ≤ dᵢⱼ and 0 ≤ rᵢ ≤ min{xᵢ,1‑xᵢ,yᵢ,1‑yᵢ}” is a linear optimisation in the radii.  
  Hence, for any placement of centres, we can *exactly* compute the best possible radii in a few milliseconds with a modern LP solver (SciPy’s “highs” backend).  
* DE is well‑suited to high‑dimensional, multimodal optimisation with very few evaluations needed if the landscape is smooth; the objective (sum of radii) reacts smoothly to small perturbations in centre positions.  
* Because each LP run is deterministic and provides a full optimal radius vector, if DE converges to a configuration whose LP solution reaches the desired sum, we have a guaranteed valid packing.

**Numerical precautions**

1. **Distance computation** – use `numpy` broadcasting or `scipy.spatial.distance.cdist` to ensure tight tolerance (`1e-12`).  
2. **LP RHS** – for boundary constraints, directly use the coordinates; for pairwise constraints, use the exact Euclidean distance (not squared) because LP expects linear inequalities.  
3. **Solver tolerance** – use default “highs” with `tol=1e-9` to guarantee that `r_i + r_j ≤ d_ij` is respected within `1e-12`.  
4. **Rounding** – after LP, clip radii to `max(0, r)` to avoid tiny negative values due to numerical noise.  
5. **Verification** – always call `validate_packing`; if it fails, raise an exception (the platform will crash rather than silently return a wrong solution).
