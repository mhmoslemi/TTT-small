**1.  High‑level idea**

* Treat the circle centres as the design variables and, for any specific placement, compute the *global* optimum radii by solving a small **linear programme** (LP).  
* Instead of searching the 78‑dimensional space of both centres and radii, search only the **52‑dimensional** space of centre coordinates.  
* Use a **simulated‑annealing (SA)** meta‑heuristic that, at each step, perturbates a single centre, recomputes the optimal radii with the LP, and decides whether to accept the move based on the change in the total radius.  
* Because the LP is convex and extremely cheap (≈ 400 linear inequalities), we can evaluate the objective thousands of times in a few seconds, which gives the SA a smooth, numerically stable landscape.

This strategy is fundamentally different from the earlier “DE‑over‑positions + LP‑for‑radii” approach because it:

* uses a stochastic **temperature‑controlled** acceptance rule instead of DE’s differential mutation,
* evaluates many perturbations in a **single‑pass** manner (one random centre at a time) rather than full‑population evolution,
* allows an **automatic cooling schedule** that guarantees convergence to a near‑optimal local optimum if no better configuration is found.

**2.  Mathematical formulation**

Let the centre coordinates be \(C \in [0,1]^{26\times 2}\).  
Denote the pairwise Euclidean distances by  
\(d_{ij} = \|C_i-C_j\|_2\).

The radii vector \(r \in \mathbb{R}^{26}\) is obtained by solving:

\[
\begin{aligned}
\max_{\,r } & \quad \sum_{i=1}^{26} r_i \\
\text{s.t. } & r_i + r_j \le d_{ij}, \qquad 1\le i<j\le26,\\
& r_i \le x_i, \quad r_i \le 1-x_i,\\
& r_i \le y_i, \quad r_i \le 1-y_i,\\
& r_i \ge 0.
\end{aligned}
\]

This is a standard LP with 26 variables, at most  
\( \binom{26}{2}=325\) pairwise inequalities and 104 boundary inequality
constraints, solved with SciPy’s ‘highs’ solver in microseconds.

The resulting objective value is
\(S(C)=\sum_{i} r_i(C)\).
Our SA algorithm seeks a placement \(C^*\) that maximises \(S(C)\).

**3.  Initial configuration**

A remarkably good “seed” comes from a **hexagonal‐type layout** adapted to the unit square:

* Horizontal spacing \(a = 0.18\).  
* Vertical spacing \(v = \frac{\sqrt{3}}{2}\,a \approx 0.156\).  
* Five rows: 6,5,6,5,6 circles (28 total); we delete the two circles in the lower‑left and upper‑right corners, yielding 26 circles.  

The computed coordinates obey the boundary constraints exactly (every centre lies in \([0,1]^2\)).  
If for any reason this layout is infeasible due to the LP (e.g., some radii become zero), we fall back to a uniform \(5\times 5\) grid with a margin of \(0.1\).

**4.  SA detailed steps**

1. **Parameters**  
   * Temperature \(T_0 = 0.1\).  
   * Cooling factor \(\alpha = 0.995\).  
   * Maximum iterations \(N_{\max}=50000\).  
   * Proposal step size \(\sigma = 0.02\).  

2. **Loop** (for \(k=0,\dots,N_{\max}-1\)):
   * Pick a random index \(i\).
   * Propose new coordinates  
     \(C'_i = C_i + \mathcal{N}(0,\sigma^2)\).  
     If any coordinate falls outside \([0,1]\), clip it.
   * Form the candidate centre set \(C'\) (only the \(i\)‑th row changed).
   * Call `calc_max_radii(C')` → radii vector \(r'\) and sum \(S'\).
   * Compute change \(\Delta = S' - S\) where \(S\) is the current sum.
   * **Acceptance**  
     *If* \(\Delta \ge 0\) accept.  
     *Else* accept with probability \(\exp(\Delta/T)\).  
   * If accepted, set \(C=C'\), \(S=S'\).  
   * Update the temperature: \(T \leftarrow \alpha T\).
   * If no improvement has been seen in the last \(1000\) steps, *restart* from a new random seed (uniform centres in \([0.05,0.95]^2\)) to escape local minima.

3. **Termination**  
   * Stop early if \(S > 2.636\).  
   * Otherwise run to \(N_{\max}\) iterations and keep the best configuration found.

**5.  Numerical safeguards**

* **Distance precision** – compute pairwise distances with `numpy.linalg.norm` on the broadcasted difference, ensuring `1e-12` tolerance.  
* **LP tolerance** – use SciPy’s `highs` solver; set `tol=1e-9` to prevent violating the \(\pm10^{-12}\) constraint tolerance of `validate_packing`.  
* **Rounding** – after the LP, clip tiny negative radii to exactly zero to avoid NaNs.  
* **Fallback** – if the LP becomes infeasible (which might happen on a badly perturbed configuration), we assign all radii zero for that candidate, which will automatically be rejected by SA.  

**6.  Post‑processing**

Once the SA has converged (or the target sum is reached), we perform a final LP solve on the best centre set found to obtain the clean optimum radii vector.  
We then run the provided `validate_packing` function.  
If it passes, we return `(centres, radii, sum_radii)` as required by the specification.

**7.  Potential failure modes and mitigations**

| Cause | Symptom | Fix |
|-------|---------|-----|

**8.  Why this beats the previous attempts**

* **Face‑to‑face optimisation** – our LP always finds the maximal radii for the current layout; we never settle for a sub‑optimal radius assignment.  
* **Efficient search** – SA explores the centre space gradually, adjusting only one circle at a time. This reduces the dimensionality of the search compared to full‑population methods and provides a fine‑grained control over the temperature, ensuring that once a good configuration is found it is not lost.  
* **Robustness** – the algorithm never relies on the existence of any pre‑computed equal‑radius packing. It can discover completely new spatial arrangements that exploit gaps near the walls or between circles.  
* **Deterministic guarantees** – because the LP is solved exactly at every iteration, the final packing is guaranteed to satisfy the strict overlap‑ and boundary‑constraints up to the machine precision prescribed by `validate_packing`.
