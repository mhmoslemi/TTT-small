**A distinct, physics‑inspired optimisation scheme for packing 26 arbitrary‑size circles in [0,1]²**

---

### 1.  Core idea

We solve the *non‑convex, continuous* packing problem by treating it as a single differentiable optimisation problem:
\[
\min_{\mathbf{x},\mathbf{y},\mathbf{r}}\;
   \mathcal{E}(\mathbf{x},\mathbf{y},\mathbf{r})
   = -\sum_{i=1}^{26} r_i+
     \lambda\,\mathcal{P}(\mathbf{x},\mathbf{y},\mathbf{r}) .
\]

* The first term simply pushes all radii to be as large as possible (our objective).  
* The second term is a **penalty** that is zero on the feasible set and grows smoothly when a constraint is violated.  
* The penalty coefficient λ is *gradually increased* (a continuous‑depressed “barrier” routine) so that the optimisation is driven into the feasible region while still being guided by the objective.

Unlike the previous strategy, we avoid an explicit two‑stage “refine radii then test move” loop.  All variables (centres and radii) are updated *simultaneously* by a full‑gradient optimiser (L‑BFGS‑B) at each λ‑step.

### 2.  Penalty terms

All geometric constraints are expressed as signed distances.  Whenever a signed distance is negative, the penalty is an *exponential* or *quadratic* hinge.

| Constraint | Signed distance *s* | Penalty contribution | λ‑multiplication |
|------------|---------------------|----------------------|------------------|
| Boundary (left) | \(s_{ix}^{(L)} = x_i - r_i\) | \(\bigl[ \max(0,-s_{ix}^{(L)})\bigr]^2\) | λ |
| Boundary (right) | \(s_{ix}^{(R)} = 1 - x_i - r_i\) | \(\bigl[ \max(0,-s_{ix}^{(R)})\bigr]^2\) | λ |
| Boundary (bottom) | \(s_{iy}^{(B)} = y_i - r_i\) | \(\bigl[ \max(0,-s_{iy}^{(B)})\bigr]^2\) | λ |
| Boundary (top) | \(s_{iy}^{(T)} = 1 - y_i - r_i\) | \(\bigl[ \max(0,-s_{iy}^{(T)})\bigr]^2\) | λ |
| Overlap | \(s_{ij} = \sqrt{(x_i-x_j)^2+(y_i-y_j)^2}-r_i-r_j\) | \(\bigl[ \max(0,-s_{ij})\bigr]^2\) | λ |

The total penalty is the sum of all contributions.  The quadratic form is chosen because:

* It is smooth and differentiable (except at the “kink” zero, but sub‑gradients exist).  
* It keeps the optimiser away from the infeasible region with a mild force that becomes stronger as λ grows.  
* It is easy to differentiate analytically for every variable.

> **Numerical safeguard** – All squared distances are pre‑computed so that we never divide by zero (when two centres coincide the gradient is set to zero).

### 3.  Gradient derivation

For every variable we can write a closed‑form partial derivative.  The gradient is assembled by looping over all constraints once; the overall cost per iteration is \(O(n^2)\) with \(n=26\) (approx. 676 terms), negligible for modern CPUs.

*Example*: for the overlap penalty of pair \((i,j)\):
\[
s_{ij} = d_{ij} - r_i - r_j,\quad d_{ij} = \sqrt{(x_i-x_j)^2+(y_i-y_j)^2}.
\]
If \(s_{ij} < 0\), the penalty is \(p_{ij} = s_{ij}^2\), and its derivatives are

\[
\partial_{x_i}p_{ij}
   = 2\,s_{ij}\,\frac{x_i-x_j}{d_{ij}},\quad
\partial_{r_i}p_{ij}
   = -2\,s_{ij}.
\]

All similarly for the other constraints.  For constraints that are *not* violated (\(s \ge 0\)) the penalty and all its derivatives are zero.

The final gradient vector is simply the sum of contributions from each violation.  The gradient routine is rigorous and does not rely on numerical differencing, ensuring fast, stable optimisation.

### 4.  Barrier–style optimisation loop

1. **Initialisation**  
   * Randomly sample 26 centres uniformly in \([0,1]^2\).  
   * Initialise every radius to a very small value (e.g. \(10^{-4}\)).  
   * Set λ = λ₀ = 1.0 (small penalty).
2. **Barrier progression**  
   * For **k = 0 … K‑1**  
     * Call SciPy’s `minimize` with method = ‘L‑BFGS‑B’ to minimise the energy \(\mathcal{E}\) **starting from the current variables**.  
     * Use the analytic gradient computed in step 3 (passed as `jac`).  
     * After convergence, multiply λ by a factor ρ > 1 (e.g. ρ = 1.5).  This gradually stiffens the penalty, forcing the optimiser deeper into the feasible region.  
     * Keep the optimisation result as the new starting point for the next λ step.  
   * Stop when λ exceeds a large threshold (e.g. 10⁵) or when successive sums of radii change by less than \(10^{-8}\).  
3. **Multi‑restart**  
   * Run the entire barrier cycle **R** times (e.g. R = 50), each time with a fresh random initialisation, and keep the packing with the largest sum of radii.  

> **Why this works**  
>  * The first few barrier steps allow the optimiser to spread the circles out, rejecting overlaps early.  
>  * Later barrier steps push the system to *exact* feasibility while still optimizing the objective because the gradient of the objective (\(-{r_i}\)) always pulls to enlarge the radii.  
>  * The barrier coefficient ρ guarantees that the optimisation trajectory eventually lands very close to the feasible boundary; because λ is large, any remaining violation will be heavily penalised, effectively satisfying the validator constraints within numerical tolerance.
