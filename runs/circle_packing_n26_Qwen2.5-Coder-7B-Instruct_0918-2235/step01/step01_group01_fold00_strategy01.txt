**Concept – a fully stochastic, population‑free search that keeps the solution in the feasible region at every step.**  
The goal is to avoid any requirement for a “deterministic” mathematical programming engine such as SLSQP or a trust‑region solver.  
Instead we treat the problem as a 52‑dimensional combinatorial search (`x_i,y_i,r_i` for 26 circles) and use a *Simulated‑Annealing* (SA) scheme that samples only from feasible configurations.  
Because feasibility is checked after every mutation, the best solution returned is guaranteed to satisfy all boundary and non‑overlap constraints, while the stochasticity allows exploration of many local basins that a single‑path optimiser might miss.

### 1.  Data structures and helpers

1. **State representation**  
   ```python
   centers : np.ndarray shape (26,2)   # x,y in [0,1]
   radii   : np.ndarray shape (26,)    # ≥0
   ```

2. **Feasibility test (`is_feasible`)** – exactly the validator logic but vectorised for speed.  
   It checks  
   * 0 ≤ r ≤ min(x, y, 1‑x, 1‑y) for each circle (implicit by the distance test)  
   * pairwise separation `dist_ij >= r_i + r_j`.

3. **Objective** – simply the sum of radii  
   `obj(state) = radii.sum()`  
   Because the state is guaranteed feasible, there is no need for a penalty term.

4. **Neighborhood moves**  
   * **Radius perturbation**: pick a random circle `k` and set

5. **Clamping helper** – keeps a variable inside a prescribed interval.

### 2.  Temperature schedule

The SA temperature `T` decreases monotonically from an initial value `T0` ≈ 1.0 to a small value `T_min` ≈ 1e‑4.  
An exponential decay that reaches `T_min` by the end of the run works well:  

```
T ← T0 * (T_min / T0) ** (t / N_iter)
```

where `t` is the current iteration index (`0 ≤ t < N_iter`).  
Typical values:  
* `N_iter` ≈ 8 000 – 12 000 iterations per run  
* `T0 = 1.0`, `T_min = 1e‑4`

### 3.  Move acceptance rule

Given the current state `S` and a candidate neighbour state `S'`:

1.  Compute `Δ = obj(S') – obj(S)`  
2.  If `Δ ≥ 0`  → accept the move unconditionally.  
3.  If `Δ < 0`  → accept with probability  
    `p = exp(Δ / T)`  
    (this allows occasional downhill steps that help escape local maxima).  

The key difference from standard gradient‑based methods is that *feasibility is never violated*: a candidate state that fails `is_feasible` is simply discarded and no acceptance decision is made.

### 4.  Multiple independent restarts

Because SA can get trapped in a local optimum, we run several (e.g., 6–8) independent restarts.  
Each restart:

* starts with a fresh random feasible configuration (e.g., 26 circles of radius 0.02 placed randomly inside `[0,1]²`);  
* evolves with the SA dynamics described above;  
* records the best feasible configuration seen during the run.

The global best among all restarts is returned as the final packing.
