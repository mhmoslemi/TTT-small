**Idea – End‑to‑end nonlinear optimisation of centres and radii**

*Instead of first fixing the centres and then solving a linear program for the radii (as in the
previous solution), we treat the 26 centres *and* the 26 radii as decision variables in a
single continuous optimisation problem.  The objective is linear in the radii but the
feasibility conditions are nonlinear (they involve squared distances).  
The SciPy  `trust-constr` solver can handle such a problem with thousands of inequality
constraints and finds a local optimum in a few hundred function evaluations.*

---

### 1.  Decision vector

```
x = [x₁, y₁, r₁,  x₂, y₂, r₂,  … , x₂₆, y₂₆, r₂₆]   (78 variables)
```

* `xᵢ, yᵢ  ∈ [0, 1]`  – circle centres must lie in the unit square.  
  These bounds are supplied directly to the optimiser.  

* `rᵢ ≥ 0` – radii are non‑negative and are treated as free variables with a simple
  lower bound of 0.

---

### 2.  Objective function

We wish to maximise the *sum of radii*.  In minimisation form:

```
f(x) = - ∑_{i=1}^{26} rᵢ
```

The gradient is trivial (`∂f/∂rᵢ = -1`, zero for the positional coordinates).  
Only the scalar value is needed – `trust‑constr` can approximate the gradient
numerically if we do not supply it.

---

### 3.  Inequality constraints

All feasibility conditions are written as “g(x) ≤ 0”, i.e. they are
inequalities that must hold with a non‑positive value.

1. **No‑overlap (pairwise)** – for every unordered pair `(i, j)`  
   ```
   g_{ij}(x) = (rᵢ + rⱼ)²  -  [(xᵢ - xⱼ)² + (yᵢ - yⱼ)²] ≤ 0
   ```
   Squaring eliminates the square‑root present in the Euclidean distance, keeping
   the function smooth.

2. **Boundary containment** – for every circle `i`  
   ```
   g_{i,xe}  = rᵢ - xᵢ          ≤ 0          (xᵢ ≥ rᵢ)
   g_{i,xw}  = rᵢ - (1 - xᵢ)     ≤ 0          (xᵢ + rᵢ ≤ 1)
   g_{i,ys}  = rᵢ - yᵢ          ≤ 0          (yᵢ ≥ rᵢ)
   g_{i,yn}  = rᵢ - (1 - yᵢ)     ≤ 0          (yᵢ + rᵢ ≤ 1)
   ```

   Each of these is linear in the variables and perfectly compatible with
   `trust‑constr`.

**Count of constraints**  
* Pairwise: 26 × 25 / 2 = 325 constraints.  
* Boundary: 4 × 26 = 104 constraints.  
Total ≈ 430 inequality constraints – manageable for the optimizer.

---

### 4.  Initial guess

`trust‑constr` needs a feasible starting point.  We construct a high‑quality
feasible vector by:

1. **Central circle**  
   ```
   x₁  = y₁  = 0.5
   r₁  = 0.5                     # fits exactly in the square
   ```

2. **Around the centre – hexagonal pattern**  
   * Choose a spacing `d = 0.22`.  
   * Place circles on a hexagonal lattice inside the square, avoiding the exact
     corners (where the radius would be zero).  
   * This yields 25 additional points (the ones that stay at least `d/2` away
     from all sides).  
3. **Remaining circles** – randomly perturb a few of the 26 positions slightly
   (plus a few uniform random points inside the square) and shrink their radii
   so that the point set is strictly feasible (each `rᵢ` is set to the **minimum**
   of the boundary distance and the smallest distance to any other centre).  
   This guarantees that `f(x)` is finite and all inequalities are satisfied.

The resulting vector is already a valid packing with a reasonably large
sum of radii (typically ≳ 2.4) and serves as a strong starting point for the optimiser.

`trust‑constr` employs a variable‑metric augmented‑Lagrangian approach; for the

The expensive part is evaluating all ~430 constraints, but each evaluation is

### 6.  Multiple restarts

Because the problem is highly non‑convex, we run *several* optimisations with
different random perturbations of the initial guess:

1. Start from the deterministic initial guess described above.  
2. For each restart, apply a random 2‑D Gaussian jitter (`σ = 0.02`) to
   *every* centre and a uniform shrinkage to all radii (so that all inequality
   constraints stay satisfied).  
3. Run `trust‑constr` with this perturbed start.  
4. Keep the solution with the largest sum of radii.

Four to six restarts usually suffice to reach the best attainable sum for this
scheme.

| Strength | Explanation |

| **Exact treatment of radii** | Radii are optimised simultaneously with positions, eliminating the need for iterative radius inflation. |
| **Smooth optimisation problem** | All constraints are twice differentiable (except the linear boundary ones), so the solver converges efficiently. |
| **Deterministic starting point** | The central‑circle + hexagonal seed guarantees a high‑quality feasible start, avoiding the gradient‑free stage of the previous approach. |
| **Multiple restarts** | Mitigates the risk of local optima by exploring diverse neighbourhoods of the initial guess. |
| **Scalability** | Only 78 variables and ≈ 430 constraints – the problem remains far below the complexity limits of a single‑CPU SciPy call. |

| Possible failure | Mitigation |
|------------------|-------------|
|  **Solver stagnation** – optimizer stalls at a non‑optimal stationary point. | We run several random restarts and a brief local SA afterwards; the combined pool of solutions usually contains a high‑quality packing. |
|  **Numerical infeasibility** – constraints violated slightly due to rounding. | After optimisation we clip the radii to the minimum of the two relevant constraints; additionally, we check the packing with the provided validator. |
|  **Local optima due to symmetry** – the algorithm may linger on highly symmetric solutions that are not globally optimal. | The random perturbations in the restarts break the symmetry early, giving the optimiser a chance to escape. |

* The earlier strategy used simulated‑annealing on the 78‑dimensional space but
  relied on an *iterative* radius‑inflation routine (a heuristic relaxation

* Here the radii are **exactly** optimised via the *trust‑constr* nonlinear optimizer
  together with the positions, turning the whole problem into a *single*
  nonlinear optimisation problem rather than a two‑stage hierarchical one.  
* The constraints are formulated as *smooth* nonlinear inequalities, and the optimisation
  routine exploits curvature information (variable‑metric).  
* The final solution is reached deterministically after a handful of optimisation runs, with no delicate tuning of annealing schedules or step‑size heuristics.

This strategy is thus truly distinct in both mathematical formulation and
