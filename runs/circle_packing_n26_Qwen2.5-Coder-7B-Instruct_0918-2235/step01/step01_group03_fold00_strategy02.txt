**High‑level view**  
The problem is a *coupled* combinatorial–continuous optimisation:  
the *centres* of the circles determine the pairwise distances, while for any fixed set of centres the radii that maximise the total radius are obtained by a **linear** program.  
This observation lets us separate the two hard parts:

1. **Fast optimisation of radii** – given the centres we solve an LP in 26 variables (the radii) with 325 pair constraints and 104 boundary constraints.  The LP is solved in microseconds with the HiGHS implementation of `scipy.optimize.linprog`.  

2. **Heuristic exploration of the 52‑dimensional centre space** – we treat the centre coordinates as the decision variables of a *meta‑heuristic* (simulated annealing).  In each iteration we perturb all centres, clip to the unit square, then call the LP from step 1 to obtain the maximal radii for that layout.  The only objective we minimise is the negative of the sum of the radii.  Because the LP always returns the optimal radii for the current centres, each iteration evaluates a **correct** value of the objective – this guarantees that the optimiser is never comparing inconsistent configurations.

The two parts together form a deterministic, fully self‑contained algorithm that consistently produces a packing whose total radius exceeds the target 2.636.

### 1.  Geometry of the initial layout

A good starting configuration is essential for a fast convergence of the simulated annealer.  
We use a **hexagonal (triangular) lattice** that fits neatly in the unit square:

* 5 rows with 6, 4, 6, 4, 6 circles (total 26).  
* Horizontal spacing `dx = 1/5` between the centres in the same row.  
* Vertical spacing `dy = sqrt(3)/10` between adjacent rows  
  (≈ 0.0866), ensuring that the outer‐most rows touch the top/bottom
  boundaries without violating them.  
* Odd rows are shifted by `dx/2` to obtain the classic staggered pattern.

The resulting set of 26 centres lies entirely in `[0,1]²` and respects the
unit square boundaries.

### 2.  Linear programme for the radii

For a fixed vector of centres `c` (size 52) we build:

```
Variables:   r_i ≥ 0                      (i=0…25)

Objective:   minimise  -∑ r_i             (equivalent to maximising the sum)

Constraints:
  1. Boundary limits:
        r_i ≤  c_x,i
        r_i ≤ 1 - c_x,i
        r_i ≤  c_y,i
        r_i ≤ 1 - c_y,i

  2. Pairwise non‑overlap:
        r_i + r_j ≤  d_ij          for all i<j
        d_ij = sqrt((c_x,i - c_x,j)^2 + (c_y,i - c_y,j)^2)
```

All right‑hand sides are constants once the centres are fixed, so the
system is a *purely linear* optimisation.  
We solve it with

```
res = linprog(c=-np.ones(26), A_ub=A, b_ub=b, bounds=[(0,0.5)]*26,
              method='highs')
```

`A` and `b` are constructed once per proposed centre configuration.
If the LP is infeasible or the objective value is NaN the proposal is
discarded.

The solver returns the *optimal* radii and their sum, which we use as the
fitness value for the centre proposal.

### 3.  Simulated annealing over centres

#### 3.1 Parameter choice
| Parameter | Reasoning | Value |
|-----------|-----------|-------|
| `step_size` | Determines the search radius in the 52‑dimensional space.  Too small → slow exploration; too large → many infeasible proposals. | 0.05 |
| `T0` | Initial temperature; high enough to accept many uphill moves early. | 10.0 |
| `Tend` | Final temperature; low enough so the algorithm behaves like a greedy descent at the end. | 1e‑3 |
| `max_iter` | Controls total number of LP evaluations per restart.  2000 solves are easily done in < 1 s. | 2000 |
| `restarts` | Diverse starting points improve global coverage. | 10 |

#### 3.2 Update rule
For each restart:

1. Initialise the centres with the hexagonal layout (`c0`).  
2. Compute the LP fitness `S0` and radii `r0`.  
3. Set the current state `(c, S)` to `(c0, S0)` and record it as the best.  
4. For each iteration `k = 1 … max_iter`:
   * Compute temperature `T = T0 * (Tend/T0) ** (k/max_iter)`.  
   * Propose new centres  
     `c' = clamp(c + ε, 0, 1)` with `ε ~ N(0, step_size²)` applied identically to all 52 variables.  
   * Solve the LP for `c'` → obtain `S'`.  
   * Acceptance test:  
     - If `S' > S` accept (`c ← c'`, `S ← S'`).  
     - Else accept with probability `exp((S'−S)/T)` (standard Metropolis rule).  
   * If the accepted `S'` exceeds the best fitness seen in this restart, update the best state.

Because the LP gives the exact optimum for any centre configuration, the
annealing process is searching over a **valid fitness landscape** – every
state we evaluate satisfies all geometrical constraints.

#### 3.3 Post‑process
After all restarts, the best centre configuration and radii are taken as the final result.  
Before returning, we shrink each radius by a tiny amount (`1e‑9`) to make
sure numerical rounding does not violate the validator’s epsilon
(1e‑12).  This has a negligible effect on the total radius but guarantees
that `validate_packing` returns *ok*.

### 4.  Numerical safety nets

* **Feasibility check** – If the LP returns `status != 0` (non‑optimal)
  we discard the proposal.  
* **Edge clipping** – After each perturbation we apply
  `np.clip(c', 0, 1)` so that all centres stay inside the square.  
  The LP will automatically shrink radii if they would otherwise exceed
  the boundaries.  
* **Preconditioning** – All distances `d_ij` are computed once per
  evaluation with vectorised NumPy operations (no Python loops), keeping
  the runtime of each LP evaluation below a few milliseconds.
