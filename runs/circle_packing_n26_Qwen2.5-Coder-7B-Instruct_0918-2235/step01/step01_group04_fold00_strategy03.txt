**Overall idea**  
Formulate the whole optimisation – both the circle centres and radii – as a *single, non‑linear* constrained optimisation problem and solve it with a *trust‑region solver* that uses the true Jacobian of every inequality.  
This contrasts sharply with the earlier “LP‑plus‑annealing” or “block‑coordinate” schemes: the objective, the constraints and the optimisation routine are all completely different, and the solver now guarantees feasibility at every iteration (subject only to numerical tolerances).

--------------------------------------------------------------------

### 1.  Decision vector

Let  
\[
x=\Bigl[
\underbrace{c_{1x},c_{1y},\dots ,c_{26x},c_{26y}}_{\text{positions } \in [0,1]^{52}},
\underbrace{r_{1},\dots ,r_{26}}_{\text{radii }\ge 0}
\Bigr]^{\!T}\in\mathbb{R}^{78}.
\]

--------------------------------------------------------------------

### 2.  Objective function

Maximise the total radius  
\[
S(x)=\sum_{i=1}^{26} r_{i}.
\]
The optimizer of `scipy.optimize.minimize` works on minimisation, so we use  
\[
f(x)=-S(x)= -\sum_{i=1}^{26} r_{i}.
\]
Its gradient is trivial: \(\frac{\partial f}{\partial r_i}=-1\), all other partials are zero.

--------------------------------------------------------------------

### 3.  Constraints

All constraints are written as *inequalities* in the form \(c_k(x)\ge 0\).

#### 3.1  Boundary constraints (four per circle)

For each circle \(i\) ( \(i=1,\dots ,26\) ):

\[
\begin{aligned}
c_{i}^{(b_L)}(x) &= x_i      - r_i,\\
c_{i}^{(b_R)}(x) &= 1 - x_i  - r_i,\\
c_{i}^{(b_B)}(x) &= y_i      - r_i,\\
c_{i}^{(b_T)}(x) &= 1 - y_i  - r_i.\\
\end{aligned}
\]

They guarantee that the circle stays inside the unit square.

#### 3.2  Non‑overlap constraints (one per unordered pair)

For each distinct pair \((i,j)\) with \(i<j\):

\[
c_{ij}^{(n)}(x)=
\bigl((x_i-x_j)^2+(y_i-y_j)^2\bigr)-\bigl(r_i+r_j\bigr)^2\;\ge 0.
\]

When the inequality is tight the two circles are tangent; when strictly positive there is a gap.

--------------------------------------------------------------------

### 4.  Jacobians

The trust‑region solver needs the Jacobian \(J_{k,\ell}=\frac{\partial c_k}{\partial x_\ell}\) for every constraint.  
Explicit formulas are easily written:

*Boundary constraints*  
For a fixed circle *i*:

\[
\frac{\partial c_{i}^{(b_L)}}{\partial x_i}=1,\quad
\frac{\partial c_{i}^{(b_L)}}{\partial r_i}=-1,
\]
all other partials zero (similarly for the other three sides).

*Non‑overlap constraints*  
Let \(dx=x_i-x_j,\;dy=y_i-y_j,\;sr=r_i+r_j\).

\[
\begin{aligned}
\frac{\partial c_{ij}^{(n)}}{\partial x_i} &= 2dx, \;\;
\frac{\partial c_{ij}^{(n)}}{\partial x_j} = -2dx,\\[4pt]
\frac{\partial c_{ij}^{(n)}}{\partial y_i} &= 2dy, \;\;
\frac{\partial c_{ij}^{(n)}}{\partial y_j} = -2dy,\\[4pt]
\frac{\partial c_{ij}^{(n)}}{\partial r_i} &= -2sr,\;\;
\frac{\partial c_{ij}^{(n)}}{\partial r_j} = -2sr.
\end{aligned}
\]

All other partials are zero.  
Because the Jacobian is sparse (each constraint touches only a handful of variables) the evaluation is \(O(n^2)\) with \(n=26\) – completely negligible.

### 5.  Initialisation

A good starting point is crucial for a non‑linear solver.

1. **Hexagonal lattice** – 26 centres placed on a 5 × 5 grid with alternating rows offset by half a horizontal step (exact coordinates 0.10, 0.30, 0.50, 0.70, 0.90; offset rows start at 0.20, 0.40, 0.60, 0.80).  
   Add a tiny Gaussian jitter (σ = 0.01) to each coordinate to avoid perfect symmetry.  
2. **Initial radii** – set all \(r_i=0.05\).  
3. **Bounds** – the optimiser will enforce \(x\in[0,1]^{52}\) and \(r\ge0\).

--------------------------------------------------------------------

### 6.  Optimiser

`scipy.optimize.minimize` with method **`trust-constr`** is used:

* **Arguments**  
  * `fun=f` (objective function).  
  * `jac=∇f` (vector of ones on radiator components).  
  * `hess=None` (the default – numerical approximation).  
  * `constraints=...` – list of 4 × 26 + C(26,2) × 1 inequality constraints, each supplied with its explicit Jacobian.  
  * `bounds=` – box bounds for coordinates and radii as described above.  
  * `options={'maxiter':2000,'gtol':1e-10,'xtol':1e-10}`.

* **Why trust‑constr?**  
  The solver constructs a quadratic model of the objective under all constraints and uses the exact Jacobian to build an inexact Newton system. The method handles inequality constraints naturally and stops only when feasibility and optimality tolerances are satisfied.  

* **Multiple restarts** – Because the global optimum may be hidden behind local minima, the optimisation is executed **three times** with different random initial seeds (smallly perturbed versions of the hex lattice).  
  The solutions are compared on the objective value \(S(x)\); the best is retained.

### 7.  Numerical safety

* **Projection** – the bounds automatically keep the coordinates in \([0,1]\) and radii \(\ge0\).  
* **Post‑processing clip** – after the solver terminates, any radii that marginally exceed the exact boundary allowance (due to numerical noise) are clipped:
  \[
  r_i \leftarrow \min\bigl( r_i,\; \min(x_i,1-x_i,y_i,1-y_i) \bigr).
  \]
* **Validation check** – the final \((centres,radii)\) pair is passed to the provided `validate_packing` function.  Because all inequalities are enforced with a relative tolerance of \(1\!\times\!10^{-10}\), the result trivially satisfies the validator.

| Risk                                 | Symptom                                 | Remedy                                           |
|--------------------------------------|-----------------------------------------|---------------------------------------------------|
| **Non‑unique Jacobian (division by zero)** | Solver raises “zero‑gradient” error     | The Jacobian never contains divisions – safe.     |
| **Stalled at a poor local optimum** | Objective stops improving far below target | Use additional random restarts, increase `maxiter`. |
| **Too many constraints (memory)**   | Solver memory error                     | The problem has only 4×26+325≈429 constraints – trivial. |
| **Numerical overflow (very large radii)** | Radii grow unbounded before constraints tightened | Trust‑constr automatically enforces inequalities; if overflow occurs, start with smaller initial radii. |

Because the full non‑linear model is solved with an exact Jacobian and the algorithm always respects the constraints, the returned circles are mathematically *feasible* by construction.

### 10.  Extensions

* **Adding a global scaling factor** – if a higher sum is desired, we can apply a uniform scaling to all radii after the optimiser converges and then re‑run the solver as a fine‑tuning step.
* **Hybrid with LP** – for each concentric circle that achieves a tight contact in the non‑linear solution, we can freeze the corresponding pairwise distance in a linear program and re‑optimise radii to obtain an infinitesimally larger sum (usually a negligible improvement but a useful sanity check).
* **GPU acceleration** – the Jacobian construction is embarrassingly parallel and can be off‑loaded to a GPU using `jax` or `numba`, speeding up the multiple restart loop.
