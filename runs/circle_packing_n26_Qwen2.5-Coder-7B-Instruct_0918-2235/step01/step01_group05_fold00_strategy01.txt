**High‑level idea**

To maximize the sum of radii we decouple the problem into two parts:

1. **Choosing the positions of the 26 centres** – a combinatorial problem on a finite set of candidate points.
2. **Computing the largest admissible radii for a *fixed* set of centres** – a linear program (LP) because all constraints are linear in the radii once the centres are fixed.

By solving (2) exactly we avoid any heuristic “inflate while overlapping” steps.  
By searching the combinatorial space intelligently we keep the number of LPs to a few thousand, which is trivial for a modern laptop.

**Step–by–step algorithm**

1. **Generate a rich candidate set of centres**

   * Create a fine regular grid inside the unit square, e.g. a 20 × 20 grid → 400 points.
   * Add the four corners and four edge mid‑points to increase diversity.
   * Store every point as a 2‑D array `P` of shape `(N, 2)` (with `N ≈ 410`).

2. **Pre‑compute geometric data**

   * Compute and store the Euclidean distance matrix `D` (shape `(N,N)`) using broadcasting – this is only done once.
   * For each point `k`, also store its distances to the four sides of the square:
     ```
     d_left  = P[k,0]      # distance to x=0
     d_right = 1 - P[k,0]  # distance to x=1
     d_bot   = P[k,1]      # distance to y=0
     d_top   = 1 - P[k,1]  # distance to y=1
     ```

3. **LP model for a fixed set of centres**

   For a set `S` of indices (|S| = m ≤ 26) the variables are the radii `r_0 … r_{m-1}`.

   Constraints:

   * **Boundary** (for each `i` in `S`):  
     `r_i ≤ min(d_left[i], d_right[i], d_bot[i], d_top[i])`.
   * **Non‑overlap** (for each unordered pair `i < j` in `S`):  
     `r_i + r_j ≤ D[i, j]`.

   All `r_i ≥ 0`.  
   Objective: **maximise** `Σ r_i`.

   This is a standard linear program with a very small number of variables (≤ 26) and few constraints (`O(m^2)`), so it can be solved hundreds of times per second by SciPy’s `linprog` (method `'highs'`).

4. **Greedy construction of 26 centres**

   * Start with an empty set `S = ∅` and current best total radii `total = 0`.
   * While `|S| < 26`:
     - For each candidate `c` not in `S`:
       * Build the LP for `S ∪ {c}` (adding the new centre only enlarges the problem by one variable).
       * Solve it; obtain a sum `new_total`.
       * Compute the marginal gain `gain = new_total - total`.
     - Pick the candidate with the **maximum gain** (ties broken arbitrarily).
     - Update `S ← S ∪ {c}` and `total ← new_total`.
   * This guarantees that after the loop we have exactly 26 centres whose radii can coexist and whose overall sum is locally optimal within the greedy moves.

5. **Local search (swap improvement)**

   * After the greedy phase, run a deterministic bump‑search:
     - For every `i ∈ S` and every `j ∉ S`:
       * Compute the LP for `S' = (S \ {i}) ∪ {j}`.
       * If `Σ r_k` for `S'` > current best, accept the swap (`S ← S'`).
     - Repeat the whole scan until no improving swap is found.
   * Optionally repeat the greedy + swap chain several times with a random perturbation: after a full pass, randomly remove `t` centres (t=1–3) and restart the greedy phase. This helps escape shallow local optima.
   * Keep the best solution across all restarts.

6. **Final extraction**

   * Once a best subset `S*` is found, solve its LP once more to obtain the optimal radii vector `r*`.
   * Compose the `centers` array by selecting the points from `P` indexed by `S*`.
   * Compute the sum `sum_r = r*.sum()` – this is the objective value that the validation function will reward.

7. **Numerical safeguards**

   * All LPs are solved with double precision; the HiGHS solver reports a duality gap < 1e‑9, which guarantees feasibility to within 1e‑12 (the tolerance used by the validator).
   * Clip any tiny negative radii (< 1e‑15) to zero just before returning.
   * Verify the final solution with the supplied `validate_packing`; if it fails, fall back to a deterministic 5 × 5 grid (sum = 2.5) – an acceptable but sub‑optimal failure mode.
   * Time budget: with ~5 restarts we perform < 30 000 LPs. Each LP with ≤ 26 variables takes < 1 ms; total runtime stays well below a few seconds on a single CPU.

**Why this works better than a single unconstrained optimisation**

* The LP guarantees the maximum sum of radii for the chosen geometrical layout, eliminating the risk of a local optimum in the radii space.
* The combinatorial search is guided by the LP objective, so every candidate addition or swap is evaluated objectively.
* The grid of candidates supplies enough geometric diversity (many points near the centre and many near the edges) to mimic the optimal irregular pattern that often appears in high‑sum‑radius packings.
* Because the algorithm works deterministically (except for optional random restarts) and is fully self‑contained, it respects all execution constraints.

**Potential failure modes and mitigations**

| Failure | Cause | Fix |
|---------|-------|-----|
| LP solver crashes on degenerate constraints | Many distances are zero or very small | Add a small epsilon (1e‑12) to all distances in `D` before building constraints. |
| Greedy gets stuck choosing sub‑optimal corner points | Greedy makes too many “good‑look” but mutually incompatible picks | Use multiple random restarts; after each greedy pass, perform a few random swaps before re‑running the greedy. |
| Local search never improves (plateau) | Current subset already locally optimal but global optimum higher | Increase number of restarts; increase the perturbation size `t` in random removal. |
| Total sum < 2.636 (needed target) | Candidate grid too coarse or geometry poor | Increase grid resolution (e.g., 25 × 25) – still manageable size. |
| Runtime too long on extreme restarts | 410 × 410 distance matrix large | Reduce grid size after initial tests; pre‑filter candidates by rejecting points too close to each other (distance < 0.02). |
