```python
                else:
                    if -k <= i1 <= n-1:
                        grad[j] += w[m_idx] * (1.0 - h[i1])
            
            # Case 2: h[j] is in (1-h[i]), so i = j
            # For k>=0: i ranges [0, n-1-k], so need 0 <= j <= n-1-k, i.e., k <= n-1-j
            # For k<0: i ranges [-k, n-1], so need -k <= j <= n-1, i.e., k >= 1-j
            if k >= 0:
                if 0 <= j <= n-1-k:
                    jk = j + k
                    if 0 <= jk < n:
                        grad[j] -= w[m_idx] * h[jk]
            else:
                if -k <= j <= n-1:
                    jk = j + k
                    if 0 <= jk < n:
                        grad[j] -= w[m_idx] * h[jk]
    
    grad *= dx
    return grad
```

This is O(n²) with a small constant. For n=100, it's about 2*100*199 ≈ 40,000 operations per gradient call. Very fast.

But the inner loop over m_idx for each j makes it O(n * (2n-1)) = O(n²) with a Python loop overhead. For n=100, that's 100*199 = 19,900 iterations of the inner loop. In Python, each iteration is maybe 100ns-1μs, so total is about 2-20ms per gradient call. That's fine.
