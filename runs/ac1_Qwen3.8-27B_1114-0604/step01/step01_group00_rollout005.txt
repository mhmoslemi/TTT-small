import numpy as np
from scipy.signal import correlate
import time


def _convolve_fft(f):
    """Full linear convolution f*f via FFT."""
    n = len(f)
    size = 1 << (2 * n - 1).bit_length()
    F = np.fft.rfft(f, size)
    return np.fft.irfft(F * F, size)[:2 * n - 1]


def _softmax(x, T):
    """Stable softmax with temperature."""
    x = x / T
    x -= x.max()
    e = np.exp(x)
    s = e.sum()
    if s < 1e-300:
        out = np.zeros_like(x)
        out[np.argmax(x)] = 1.0
        return out
    return e / s


def _mirror_descent_step(log_f, grad, eta):
    """One mirror descent step in log-space."""
    log_f_new = log_f - eta * grad
    log_f_new -= log_f_new.max()  # for numerical stability
    f_new = np.exp(log_f_new)
    f_new /= f_new.sum()
    log_f_new = np.log(f_new)
    return f_new, log_f_new


def _objective_from_conv(c, n, S):
    """Compute objective from precomputed convolution."""
    return 2.0 * n * c.max() / (S * S)

**Polish phase: Targeted peak reduction**

Given the current best solution f with peak at lag k*:
1. The peak value is c[k*] = sum_i f[i] * f[k*-i].
2. The "dominant" terms are those where f[i] * f[k*-i] is large.
3. To reduce c[k*], we can:
   a. Reduce f[i] for i where f[k*-i] is large (and vice versa).
   b. But this might increase other c[k] values.
4. A safe move: find i where f[i] is large AND f[k*-i] is large (both contribute to the peak). Then find j where f[j] is small AND f[k*-j] is also small (moving mass there won't create new peaks). Transfer mass from i to j.

**Even better: Simultaneous reduction of top-K peaks**

If the top K peaks are at lags k_1, ..., k_K, we want a move that reduces all of them. The condition for a move δf to reduce c[k_m] is:
`2 * sum_i f[k_m - i] * δf[i] <= 0` for all m.

We want δf to be "large" (to make progress) while satisfying all K inequalities. This is a linear program in δf (with K constraints and n variables).

For K=2 or 3, we can solve this in closed form. For larger K, we can use a simple heuristic:
- δf[i] = -f[k_m - i] for the "worst" m (the one with the largest c[k_m]).
- This reduces the worst peak but might not reduce others.

A better heuristic:
- δf[i] = -sum_m w_m * f[k_m - i] where w_m are weights proportional to (c[k_m] - target)^+.
- This reduces all peaks proportionally to their excess.

This is essentially the softmax-weighted subgradient, which is what we're already using!

So the main improvement should be in the optimization dynamics (momentum, adaptive step size, better exploration), not in the gradient computation.
