Let me think about an optimization algorithm:

**Algorithm: Subgradient with projection onto simplex**

1. Start with a on the simplex (sum = 1, a >= 0).
2. Compute c = convolve(a, a).
3. Find k* = argmax c.
4. Compute gradient: g[m] = 2*a[k*-m] (with boundary handling).
5. Take a step: a_new = a - eta * g.
6. Project a_new onto the simplex.
7. Repeat.

But this is a subgradient method for a non-smooth function, so convergence is slow. We can use averaging.

**Better algorithm: Use the "active set" of peak lags**

Instead of just the single argmax, track all lags that are within ε of the maximum. This gives a smoother gradient.

**Even better: Use a different formulation**

Since c[k] = sum_j a[j]*a[k-j], and we want to minimize max_k c[k], this is equivalent to:
minimize t
subject to c[k] <= t for all k
         a[j] >= 0 for all j
         sum a[j] = 1

This is a quadratic constraint (c[k] is quadratic in a). It's not a convex problem.

However, if we linearize the constraints around the current point, we get a linear program! This is the basis of the "linearization" or "successive linear programming" approach.

**Algorithm: Successive Linear Programming (SLP)**

1. Start with a feasible point a^(0).
2. Compute c^(k) for all k.
3. Find active constraints: k where c[k] is close to max.
4. Linearize: c[k] ≈ c^(k) + grad_c[k] · (a - a^(0)) for active k.
5. Solve LP: minimize t subject to linearized constraints, a >= 0, sum(a) = 1.
6. Update a, repeat.

This is similar to the approach mentioned in the "previous state of the art" description!

Actually, re-reading the previous state of the art:
"compute g_0=(b_0,...,b_{n-1}) by solving a linear program, i.e. maximizing sum_j b_j subject to b_j>=0 and ||f*g_0||_infinity <= M"

This is solving: max sum(b) s.t. b >= 0, and (f*b)[k] <= M for all k.
This is a linear program! (f*b) is linear in b.

The idea is: given the current sequence f, find a new sequence g that, when convolved with f, stays below the current peak M, while having the maximum possible sum. Then blend f and g.

This is a clever approach because:
- The LP is in g (linear constraints, linear objective).
- The constraint (f*g)[k] <= M is linear in g.
- Maximizing sum(g) pushes g to be as "large" as possible while keeping the convolution bounded.

Then the update f <- (1-t)f + t*g moves f towards g while maintaining the bound.

Let me think about why this works:
- If f has a peak at lag k*, then the constraint (f*g)[k*] <= M limits g in a specific way.
- The LP finds the g that maximizes the sum while respecting all peak constraints.
- By moving towards g, we're effectively redistributing mass to reduce the peak.

This is essentially a "proximal" or "mirror" step in a specific direction.

1. The LP-based approach (from the state of the art) as the main optimization loop.
2. A different initialization strategy.
3. Different blending strategies.
4. Possibly a polynomial-time approach for the LP (since the structure is special).

The LP is:
maximize sum(g)
subject to: for all k in [0, 2n-2], sum_{j: valid} f[j]*g[k-j] <= M
