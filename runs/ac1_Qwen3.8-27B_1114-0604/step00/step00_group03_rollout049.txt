d(log a[j])/dt = -sum_k p_k * a[k-j]

The equilibrium is: sum_k p_k * a[k-j] = constant for all j.

At equilibrium, the "weighted convolution" of p and a is constant. Since p depends on a (through the softmax of a*a), this is a self-consistent equation.

If p is uniform (all lags equally weighted), then the equilibrium is: sum_k a[k-j] = constant, which means a is "band-limited" in some sense. For a uniform p, this gives a uniform a (the only solution with sum=1 and a>=0).

If p is concentrated on one lag k*, the equilibrium is: a[k*-j] = constant for all j, which means a is constant (if k* > 0 and the range covers all j). Again, uniform!

So the only equilibrium of this update rule is the uniform sequence (when p is determined by a). This means the algorithm will converge to the uniform sequence, which gives score 2!

That's a problem. The uniform sequence is a fixed point, and it's not the global optimum (as we showed, n=3 with a=[8/15,4/15,3/15] gives score 1.707).

Wait, but the softmax p is not uniform when a is not uniform. Let me reconsider.

If a is the optimal non-uniform sequence, then at the "fixed point" of the update, we need:
sum_k p_k * a[k-j] = constant for all j

where p_k = exp(t * conv[k]) / sum exp(t*conv[k]).

For the optimal a, conv is "nearly flat" (all values close to each other). So p is nearly uniform, and the fixed point condition is nearly "sum_k a[k-j] = constant", which is nearly satisfied by a uniform a.

But the optimal a is not uniform! So the update rule has a "bias" towards uniform, and it might converge to uniform instead of the true optimum.

The issue is that the softmax with finite t doesn't perfectly capture the max. As t -> infinity, p concentrates on the argmax, and the fixed point condition becomes a[k*-j] = constant, which has the uniform solution. But for finite t, the balance might shift.

I think the problem is that the multiplicative update is too "gentle" and always converges to the uniform (or near-uniform) solution. To escape this, I need a stronger update or a different approach.

Let me go back to the LP approach, but fix the degeneracy issue.

The degeneracy occurs when f is uniform: the LP constraint (f*g)[k] <= M is satisfied by any g with sum <= 1. So the LP doesn't give a useful direction.

Fix: instead of using M = max(f*f), use M = (1-epsilon) * max(f*f). This makes the constraint tighter, forcing g to be "anti-correlated" with f.

But if epsilon is too large, the LP might be infeasible. We need epsilon small enough that f itself is (almost) feasible.

Actually, f is feasible with M = max(f*f) (since (f*f)[k] <= max(f*f) = M). If we use M' = (1-eps)*M, then f is NOT feasible (since (f*f)[k*] = M > M' for k* = argmax). So the LP might still be feasible with other g values.

Let me think about this differently. The LP is:
maximize sum(g)
subject to: (f*g)[k] <= M for all k
            g >= 0

The optimal value is: max sum(g) = ?

If f is uniform (f[j] = 1/n), then (f*g)[k] = (1/n) * sum_{valid j} g[j].
The constraint (f*g)[k] <= M = 1/n means sum_{valid j} g[j] <= 1 for all k.
The tightest constraint is k = n-1: sum_{j=0}^{n-1} g[j] <= 1.
So max sum(g) = 1, achieved by any g with sum = 1.

The LP is degenerate: infinitely many optimal solutions. The solver will pick one (dependent on the algorithm), but it won't be particularly informative.

Fix: add a secondary objective to the LP. For example, minimize ||g - f||^2 (to find the solution closest to f). But this makes the LP a QP.

Alternatively: minimize ||g - f||_1 (still an LP).

Let me verify: if f is triangular (f[j] = (n-j)/sum), then M = max(f*f) is at the center. The LP constraint (f*g)[k] <= M will be tight at specific k values, giving a non-degenerate solution.

1. Start with a non-uniform initial sequence (triangular or exponential decay).
2. Use the iterative LP with a slightly tightened M (M * (1 - 0.01) or so).

The idea:
1. Maintain a population of sequences.
2. At each generation, select the best few, create offspring by mixing/mutating them.
3. Evaluate all offspring.
4. Replace the worst members of the population with the best offspring.

This is a "memetic algorithm" that combines global search (genetic) with local search (LP or gradient).

The mutation should be:
- Mix two sequences: child = (1-t)*parent1 + t*parent2, then normalize.
- Perturb: child[j] *= exp(noise), then normalize.
- "Invert": child = 1 - child (then normalize... but this requires child < 1 componentwise).

The population size should be small (e.g., 10-20) to keep computational cost low.

At each generation, for the best member, run a few iterations of the local LP/gradient to improve it.

def _evaluate_fast(a):
    """Fast evaluation without security checks (a is known to be valid)."""
    n = len(a)
    conv = np.convolve(a, a)
    max_b = conv.max()
    sum_a = a.sum()
    if sum_a < 0.01:
        return float('inf')
    return 2.0 * n * max_b / (sum_a ** 2)

def _local_improve(a, n_iters, rng):
    """Local improvement using multiplicative soft-max gradient."""
    a = a.copy()
    n = len(a)
    best_local = a.copy()
    best_local_score = _evaluate_fast(a)
    
    eta = 1.0
    t_param = 10.0
    
    for it in range(n_iters):
        conv = np.convolve(a, a)
        max_conv = conv.max()
        score = 2.0 * n * max_conv / a.sum()**2
        
        if score < best_local_score:
            best_local_score = score
            best_local = a.copy()
        
        # Softmax
        temp = t_param / max_conv
        p = np.exp(temp * (conv - max_conv))
        p = p / p.sum()

        a_rev = a[::-1]

            if eta < 0.01:
                break

            a = a_new
            t_param = min(t_param * 1.01, 100.0)

def _lp_step(a, rng):
    """One LP-based step."""
    from scipy.optimize import linprog
    n = len(a)
    conv = np.convolve(a, a)
    M = conv.max()
    
    # Build constraint matrix
    A = np.zeros((2*n-1, n))
    for k in range(2*n-1):
        j_start = max(0, k - n + 1)
        j_end = min(n - 1, k)
        for j in range(j_start, j_end + 1):
            A[k, j] = a[k - j]
    
    c = -np.ones(n)
    # Use a slightly tighter bound to avoid degeneracy
    b_ub = np.full(2*n-1, M * 0.999)
    
    res = linprog(c, A_ub=A, b_ub=b_ub, bounds=[(0, None)]*n, method='highs')
    
    if res.status == 0:
        g = res.x
        sum_g = g.sum()
        if sum_g > 1e-10:
            g = g / sum_g
            return g
    return None
