from scipy.optimize import linprog
from scipy.fft import fft, ifft

def compute_convolution(a, b):
    """Compute linear convolution using FFT for efficiency."""
    n = len(a)
    m = len(b)
    size = n + m - 1
    # Next power of 2 for FFT efficiency
    fft_size = 1
    while fft_size < size:
        fft_size *= 2
    A = fft(a, fft_size)
    B = fft(b, fft_size)
    result = ifft(A * B).real[:size]
    return result

def lp_step(f, M):
    """Solve the LP: max sum(g) s.t. g >= 0, (f*g)[k] <= M for all k."""
    n = len(f)

    # (f*g)[k] = sum_i f[k-i] * g[i] (with appropriate bounds)
    # For a Toeplitz matrix, row k has f[k], f[k-1], ..., f[0], 0, ..., 0 on the left
    # and 0, ..., 0, f[k-n+1] on the right

    # So the j-th coefficient in row k is f[k-j] if 0 <= k-j <= n-1, else 0.
    
    # Building the full matrix explicitly would be O(n * 2n) = O(n^2) which is fine for n~2500.
    # But let's use a more memory-efficient approach.

    # Row 1: [f[1], f[0], 0, ..., 0]
    # ...
    # Row n-1: [f[n-1], f[n-2], ..., f[0]]
    # Row n: [0, f[n-1], f[n-2], ..., f[0]]

Actually, here's another idea that might be more effective: use the "alternating projection" or "POCS" (Projection Onto Convex Sets) approach.

The feasible set is: {a >= 0 : max_k (a*a)[k] <= 1}. This is non-convex (intersection of quadratic constraints). But we can approximate it:

1. Linearize the constraints at the current point: (a*k + a*k)[k] - (k*k)[k] <= 1 for each k.
2. Project onto the linearized feasible set (which is a polytope).
3. Repeat.

This is like "conditional gradient" or "Frank-Wolfe" for non-convex problems.

Let me also add a key optimization: instead of solving the full LP with 2n-1 constraints, I can use only the "most violated" constraints. At each iteration:
1. Use the current f to compute (f*g_old) for the previous direction g_old.
2. Find the top k constraints (by violation) and use only those.
3. Solve the reduced LP.

This "constraint generation" approach can be much faster.
