If the sequence is concentrated in the middle (inverted U / Gaussian shape), then sum a[j]^2 is also large. Also bad.

What if the sequence is "anti-symmetric" in a sense? Like high on the left, low on the right? Then (a*a)[n-1] = sum_j a[j]*a[n-1-j] would involve products of large*small terms, potentially reducing the center value.

But the edges of the convolution: (a*a)[0] = a[0]^2 and (a*a)[2n-2] = a[n-1]^2. If a[0] is large, (a*a)[0] is large.

So there's a trade-off: reducing the center increases the edges.

This suggests that the optimal sequence might have a specific structure, possibly related to the eigenvectors of some matrix.

Let me think about it from an optimization perspective. We want to minimize max_k (a*a)[k] subject to a >= 0, sum(a) = 1.

At the optimum, the active constraints (where the max is achieved) should all be equal (otherwise we could reduce the max by transferring mass). This is a KKT condition.

So at the optimum: (a*a)[k_1] = (a*a)[k_2] = ... = (a*a)[k_m] = M (the maximum)
And for all other k: (a*a)[k] <= M

This is similar to the "water-filling" problem.

**Practical approach: Iterative proportional fitting / Sinkhorn-like algorithm**

Another idea: use the "mirror descent" approach in the exponential family.

Parameterize: a_i = exp(θ_i) / sum(exp(θ_j))
Objective: 2n * max_k (a*a)[k] (with sum(a) = 1 automatically)

The gradient with respect to θ_i:
dF/dθ_i = 2n * d(max b)/dθ_i = 2n * sum_{k in S} db_k/dθ_i

And db_k/dθ_i = (1 - a_i) * db_k/d(a_i) + a_i * sum_j db_k/d(a_j) ... this gets complicated because of the normalization.

Actually, since the objective is scale-invariant, working on the simplex (sum = 1) is natural, and the mirror descent with log barrier is equivalent to multiplicative updates.

**Multiplicative updates (like EM algorithm):**
a_i ← a_i * (1 - η * g_i / a_i) ... no, that's not right for multiplicative updates.

For multiplicative updates to minimize a function f(a) subject to a >= 0, sum(a) = 1:
a_i ← a_i * exp(-η * g_i) / normalizing_constant

where g_i is the gradient (subgradient) of f with respect to a_i.

This is the mirror descent step with the negative entropy mirror map.

Let me now think about potential issues:
1. The subgradient might be noisy if we use too few peaks (small K) or too many peaks (large K).
2. The step size needs to be tuned.
3. We might converge to a local minimum.

To address these:
1. Use a "soft" subgradient: weight each peak by its value (not just 0/1).
2. Use a decreasing step size schedule.
3. Periodically restart with random perturbations.

Actually, let me reconsider the "soft" subgradient. Instead of using a hard mask S (top K peaks), I can use a smooth function of b:
w_k = (b[k] - threshold) / (b_max - threshold + eps) for b[k] > threshold, else 0

Or even: w_k = softmax(b / T) for some temperature T. This gives a smooth approximation to the indicator of the argmax.

The smooth subgradient would be:
g[i] = 2 * sum_k w_k * a[k-i]

This is still computable via FFT!

Let me use this approach. With a soft weight, the optimization is smoother and less likely to get stuck.

**Revised algorithm:**
1. Compute b = convolve(a, a) via FFT
2. Compute weights: w = softmax(b / T) or w = max(0, b - threshold)^p (for some p > 1)
3. Compute g = 2 * cross_correlation(a, w) via FFT
4. Update: a = project_to_simplex(a - eta * (beta * momentum + (1-beta) * g))
5. Update momentum

Let me also think about the "project to simplex" step. The projection of a vector onto the simplex {x >= 0, sum(x) = 1} is:
1. sort x in decreasing order
2. find the largest ρ such that x_(ρ) - (sum_{j<=ρ} x_(j) - 1)/ρ > 0
3. threshold = (sum_{j<=ρ} x_(j) - 1)/ρ
4. projected = max(0, x - threshold)

This is O(n log n) due to sorting, which might be a bottleneck. Alternative: use an iterative method (like the bisection method to find the threshold) which is O(n log(1/eps)).

For n=6121, sorting takes about 6121 * log2(6121) ≈ 6121 * 12.6 ≈ 77K comparisons, which is fast. So sorting is fine.

Includes adaptive step size, momentum, and periodic restarts for escaping local minima.

import numpy as np
import time
from scipy.fft import fft, ifft


def project_to_simplex(v):
    """Project vector v onto the probability simplex {x >= 0, sum(x) = 1}."""
    n = len(v)
    u = np.sort(v)[::-1]
    cssv = np.cumsum(u)
    rho = np.nonzero(u * np.arange(1, n + 1) > (cssv - 1))[0][-1]
    theta = (cssv[rho] - 1) / (rho + 1.0)
    return np.maximum(v - theta, 0)


def compute_convolution(a, fft_size):
    """Compute full auto-convolution of a using FFT."""
    A = fft(a, fft_size)
    return ifft(A * A).real[:2 * len(a) - 1]
