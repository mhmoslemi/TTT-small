```python
import numpy as np
from scipy import sparse
from scipy.optimize import linprog
import time

def solve_lp(f, M):
    """Solve the LP: max sum(g) s.t. f*g <= M (componentwise), g >= 0."""
    n = len(f)
    # Build constraint matrix A where A[k, j] = f_j if 0 <= k-j < n
    # A is (2n-1) x n
    rows = []
    cols = []
    vals = []
    for k in range(2*n - 1):
        j_start = max(0, k - n + 1)
        j_end = min(n - 1, k)
        for j in range(j_start, j_end + 1):
            rows.append(k)
            cols.append(j)
            vals.append(f[j])
    
    A = sparse.csr_matrix((vals, (rows, cols)), shape=(2*n-1, n))
    
    # Maximize sum(g) => minimize -sum(g)
    c_vec = -np.ones(n)
    
    res = linprog(c_vec, A_ub=A, b_ub=np.full(2*n-1, M), bounds=(0, None), method='highs')
    if res.success:
        return res.x
    return None
```

This means: a_j is reduced in proportion to a_{n-1-j}. If a is symmetric (a_j = a_{n-1-j}), then a_j is reduced in proportion to a_j, which is a uniform scaling (no shape change). This confirms that symmetric sequences are "stagnation points" for this update.

To break the symmetry, we need to start from a non-symmetric sequence, or add a non-symmetric perturbation.

For a non-symmetric sequence (e.g., decaying), the update a_j <- a_j * exp(-eta * a_{n-1-j}) will:
- For small j (where a_j is large): a_{n-1-j} is small, so the reduction is small
- For large j (where a_j is small): a_{n-1-j} is large, so the reduction is large

This effectively "pushes mass" from the right side to the left side, making the sequence even more left-heavy. This might help reduce b_{n-1} (the center term) because the "overlap" of a with its reverse is reduced.

But it might also increase b_0 (the left edge term) if a_0 becomes too large.

I think the right approach is to let the optimization find the balance. Let me just implement it and see.

Let me also consider the **size** of the sequence. The objective is 2n * max(b) / S^2. For a given "quality" of flatness (ratio = max(b) * (2n-1) / S^2), the objective is approximately ratio (for large n). So the size doesn't matter much for the objective value (it cancels out). 

However, larger n gives more "degrees of freedom" to shape the sequence, which might allow a flatter convolution. But it also makes the optimization harder.

I'll use n around 2000-10000.

Let me now write the final implementation. I'll combine several strategies:
1. Subgradient descent with soft-max (main method)
2. Random perturbations (to escape local minima)
3. Coordinate-wise local search (for refinement)
4. Multiple starting points

def compute_score(a):
    n = len(a)
    b = np.convolve(a, a)
    S = np.sum(a)
    if S < 0.01:
        return np.inf
    return float(2.0 * n * np.max(b) / (S * S))

def subgradient_update(a, eta, tau):
    """One multiplicative subgradient step."""
    n = len(a)
    b = np.convolve(a, a)
    max_b = np.max(b)
    if max_b <= 0:
        return a
    w = np.exp(b / (tau * max_b) - 1.0)
    w /= w.sum()
    p = correlate(w, a, mode='valid')
    mean_p = p.mean()
    if mean_p > 0:
        a = a * np.exp(-eta * p / mean_p)
    S = a.sum()
    if S > 0:
        a = a / S
    return a
