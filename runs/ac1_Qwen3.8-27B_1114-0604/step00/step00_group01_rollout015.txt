- out[0] (n=-2): sum_m p[m-2]*a[m]. m=2: p[0]*a[2] = p[0]*a[2].
- out[1] (n=-1): m=1: p[0]*a[1]. m=2: p[1]*a[2]. Total: p[0]*a[1]+p[1]*a[2].
- out[2] (n=0): m=0: p[0]*a[0]. m=1: p[1]*a[1]. m=2: p[2]*a[2]. Total: p[0]*a[0]+p[1]*a[1]+p[2]*a[2] = g[0]! ✓
- out[3] (n=1): m=0: p[1]*a[0]. m=1: p[2]*a[1]. m=2: p[3]*a[2]. Total: p[1]*a[0]+p[2]*a[1]+p[3]*a[2] = g[1]! ✓
- out[4] (n=2): m=0: p[2]*a[0]. m=1: p[3]*a[1]. m=2: p[4]*a[2]. Total: p[2]*a[0]+p[3]*a[1]+p[4]*a[2] = g[2]! ✓

So `g = np.correlate(p, a, mode='full')[n-1 : 2*n-1]` is correct.

Now, `np.correlate` uses direct computation which is O(n * len(p)) = O(n * (2n-1)) = O(n^2) ≈ 37M for n=6121. That might be a bit slow per iteration.

Alternative: use FFT. The cross-correlation can be computed as:
`corr = ifft(fft(p, N) * conj(fft(a, N)))` (for circular correlation)

With zero-padding to N >= len(p) + len(a) - 1, the circular correlation equals the linear correlation.

Wait, I need to be careful. `ifft(fft(p) * conj(fft(a)))` gives the circular cross-correlation `sum_k p[k] * conj(a[(k-m) mod N])`. For real signals, conj doesn't matter.

With zero-padding to N >= (2n-1) + n - 1 = 3n-2, the circular correlation equals the linear one. But that's a large N (about 18363, next power of 2 is 32768).

Alternatively, I can use the convolution formula I derived earlier:
`g = np.convolve(p, a[::-1], 'full')[n-1:2*n-1]`

This is also O(n^2) with direct convolution, but numpy uses a fast algorithm (FFT-based for large arrays).

Actually, for arrays of this size, numpy's convolve and correlate should use FFT internally. Let me just use `np.correlate` and trust that it's fast enough.

Let me estimate: for n=6121, `np.correlate(p, a, 'full')` computes a 3n-2 ≈ 18361 element output. With FFT-based computation, this is O(N log N) where N is the next power of 2 >= 18361, which is 32768. So about 32768 * 15 ≈ 500K operations per correlate. That's very fast.

So each iteration is:
1. FFT of a (size 16384): ~16384 * 14 = 230K
2. IFFT to get c: similar
3. Softmax p: O(n)
4. Correlate p with a: ~500K (FFT-based)
5. Update: O(n)

Total per iteration: ~1M operations. In Python with numpy, maybe 1-5 ms per iteration. So we can do ~1000-5000 iterations per second, giving millions of iterations in 2400 seconds. That's more than enough.

The bottleneck will be numerical convergence, not computation.

        if max_c < 1e-15:
            break
        
        # Temperature annealing
        progress = min(1.0, iteration / 5000)  # anneal over 5000 iterations
        tau_ratio = tau_ratio_start + (tau_ratio_end - tau_ratio_start) * progress
        tau = tau_ratio * max_c
        tau = max(tau, 1e-12)

        c_shifted = (c - max_c) / tau
        p = np.exp(c_shifted)
        p_sum = p.sum()
        p = p / p_sum

        # Using correlate

        grad_raw = np.correlate(p, a, mode='full')[n-1:2*n-1]
        grad = grad_raw / tau

            a_new = np.maximum(a_new, 0.0)

                iteration += 1

        if no_improve > patience:

            lr = max(0.1, lr * 0.8)

        iteration += 1
    
    # Final evaluation
    final_score = evaluate_sequence(best_a.tolist())
    print(f"Final: n={n}, score={final_score:.6f}, iterations={iteration}")
    
    return [float(x) for x in best_a]

**Alternative: Direct optimization of the peak**

Instead of using log-sum-exp, what if I directly identify the peak positions and use a "penalty" approach?

Idea:
1. Compute c = a*a
2. Find the top-K positions where c is largest
3. Add a quadratic penalty at those positions: `F(a) = sum_{k in top-K} (c[k] - target)^2`
4. Minimize F using gradient descent
5. Update top-K periodically

This is like a barrier method for the constraint c[k] <= target.

The gradient of `F = sum_k (c[k] - T)^2` is:
`dF/da[i] = 2 * sum_k (c[k] - T) * a[k-i]`

This is similar to the log-sum-exp gradient but with a different weighting.

Actually, let me think about this differently. The problem is essentially:
- Minimize `max_k c[k]` subject to `sum(a) = 1, a >= 0`

This is a convex optimization problem! Because:
- `c[k] = (a*a)[k]` is a quadratic form in a (specifically, `c[k] = a^T A_k a` where A_k is a symmetric matrix)
- `max_k c[k]` is the max of convex functions, hence convex
- The constraint set `{a : sum(a) = 1, a >= 0}` is convex

Wait, is `c[k]` convex in `a`? `c[k] = sum_i a[i] * a[k-i]`. This is a quadratic form `a^T A_k a` where `(A_k)_{ij} = 1/2` if `j = k-i` or `i = k-j` (i.e., `i + j = k`), else 0.

Actually, `c[k] = sum_{i+j=k} a[i] * a[j]` (with the convention that a[j] = 0 for j outside [0,n-1]).

This can be written as `a^T A_k a` where `(A_k)_{ij} = 1` if `i + j = k` (and i, j in [0, n-1]), else 0. But this matrix is not necessarily positive semi-definite!

For example, with n=3, k=2: `c[2] = a[0]*a[2] + a[1]*a[1] + a[2]*a[0] = 2*a[0]*a[2] + a[1]^2`.
The matrix A_2 has entries (A_2)_{0,2} = (A_2)_{2,0} = 1, (A_2)_{1,1} = 1.
Eigenvalues: the matrix is [[0,0,1],[0,1,0],[1,0,0]] which has eigenvalues 1, 1, -1. NOT PSD!

So `c[k]` is NOT convex in general! The problem is non-convex.

This explains why the optimization is hard. The log-sum-exp approach is still valid as a smooth approximation of the max, but the underlying problem is non-convex.

Given the non-convexity, I should use a global-ish optimization strategy:
1. Multiple random starts
2. Smooth gradient descent from each start
3. Keep the best result

Or, I can use a more sophisticated local optimization that's good at navigating non-convex landscapes.

Let me also think about what "good" sequences look like. For the autocorrelation to be flat, the sequence should have a "random-like" structure. But it needs to be non-negative.

One idea: start with a random positive sequence and optimize.
Another: use a structured initialization like a "windowed random" sequence.

Let me also consider: what if I use the sequence `a[i] = 1 + eps * x[i]` where x is a zero-mean random sequence? For small eps, the autocorrelation is approximately flat (since the cross-terms average out). This gives a good starting point.

Actually, a better starting point: `a[i] = (1 + x[i])^2` where x[i] is i.i.d. standard normal, then clip to non-negative. This gives a positive sequence with some randomness.
