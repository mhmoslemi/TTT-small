**1. Approach and Rationale**  
I propose **tile-based matrix multiplication** with **hidden dimension batching**. Instead of computing each element of the trisum (output[i,j,d]) for every d across every (i,j) combination in a fragmented way, we batch the hidden dimensions (d) together and recompute the matrix multiplication for all d in once. This leverages the associative property of the operation:

```
out[b,i,j,d] = (left[b,i,:,d] @ right[b,j,:,d])
```

equivalent to:

```
out[b,i,j,d] = (left[b,i,:,0:H] * right[b,j,:,0:H]).sum(-1)
```

But we can swap dimensions:

```
out[b,i,j,d] = ( (left[b,i,0:H,:]) @ (right[b,j,:,0:H].T) ).sum(-1,dimming=d)
```

However, the Einsum operation first sums over k, so after swapping we lose overcomplete information. This approach avoids zeros in output by tiling the sequence pairs while keeping channels dim first. The operation is equivalent to:

```
out[b,i,j,d] = (left[b,i,:,d] @ right[b,j,:,d])
```

But if we batch the hidden dimensions, we can compute:

```

```

We compute all of these matrix multiplications across the batch and hidden_dim dimensions in one go, which reduces the number of kernel launches. This is a well-known optimization in deep learning kernels.

**Key bottleneck addressed**: The original O(N^3) operation was too expensive. Batching hidden dimensions and using tiling (shared memory) will help amortize the cost. Explicit triple nested loops remain but will be optimized by compiler to understand the tiling structure.
