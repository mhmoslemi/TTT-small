Let me also think about whether I should use a smarter approach for the discrete search. The key insight is:

For a {0,1} sequence, f_k (correlation at lag k) counts the number of "1→0" transitions at distance k. To minimize the max, we want these to be as uniform as possible across all lags.

A greedy approach: compute the current max lag, and try to find a swap that reduces it. This is like a steepest-descent step.

Let me implement a "greedy + random" hybrid:
- At each step, compute all correlation values
- Find the top 3 lags with highest correlation
- For the worst lag k*, try all possible swaps that could reduce f_{k*}
- Pick the swap that gives the best improvement (or is least harmful)

But trying all swaps is O(n^2) per step, and computing the new correlation is O(n), so it's O(n^3) per step. For n=100, that's 10^6 per step, and with 1000 steps, 10^9. Might be too slow.

Alternatively, for a specific swap (i→j, where h[i]=1 and h[j]=0), the change in f_k can be computed quickly:
- The positions affected are i, j, and their relatives at distance k
- For a given k, the change depends on h[i], h[j], h[i+k], h[j+k], h[i-k], h[j-k]

This is O(1) per (swap, lag) pair. So for a specific swap, computing the change in all 2n-1 correlations is O(n). And trying all n^2 swaps is O(n^3).
