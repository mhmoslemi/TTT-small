def fft_convolve(a, b):

    n, m = len(a), len(b)
    size = 1
    while size < n + m - 1:
        size <<= 1
    fa = rfft(a, size)
    fb = rfft(b, size)
    return irfft(fa * fb, size)[:n + m - 1]

def local_score(a):
    """Compute score = 2*n*max(conv(a,a))/sum(a)^2."""
    a = np.clip(a, 0.0, 1000.0)

    if n == 0:

    sum_a = np.sum(a)
    if sum_a < 0.01:

    c = fft_convolve(a, a)
    return 2.0 * n * np.max(c) / (sum_a ** 2)

This is a quadratic program in t. We can solve it by:

2. For each k, the value at step t is: c0[k] + 2t*c1[k] + t^2*c2[k]
3. We want min_t max_k (c0[k] + 2t*c1[k] + t^2*c2[k])

- We want the t in this range that minimizes... well, any t in the range works (it gives value <= V).

Let me also think about the theoretical lower bound more carefully.

For a non-negative sequence of length n with sum = sqrt(2n), the center of the convolution is:
c[n-1] = sum_i a[i] * a[n-1-i]

By the rearrangement inequality, this is maximized when a is sorted (all large values together) and minimized when a is "anti-sorted" (large values paired with small values).

The minimum of sum_i a[i] * a[n-1-i] subject to sum(a) = sqrt(2n) and a >= 0 is 0 (achieved when a[i] > 0 only for i < n/2, say). But then the edge values c[0] = a[0]^2 and c[n/2-1] would be large.

So there's a fundamental trade-off. The optimal sequence balances the edge values (which depend on a[0]^2, a[n-1]^2, etc.) with the center value.

Let me think about what the optimal structure looks like. For a symmetric sequence (a[i] = a[n-1-i]), we have:
- c[0] = a[0]^2
- c[n-1] = sum a[i]^2 >= (sum a)^2 / n = 2
- So for symmetric sequences, the score is at least 2 (since c[n-1] >= 2).

This means symmetric sequences can't beat 2! We need asymmetric sequences.

For an asymmetric sequence, c[n-1] = sum a[i]*a[n-1-i] can be much less than sum a[i]^2. For example, if a[i] = 1 for i < n/2 and a[i] = 0 for i >= n/2 (with appropriate scaling), then c[n-1] = 0.
