1. Approach and rationale

1.1 Central idea

The parent construction is already in the low-C basin at approximately 0.38085, and the target is only about 0.00005 lower. The principal obstruction is therefore not the need for an entirely new global construction, but the ability to make a very small improvement while preserving the exact finite-support cross-correlation objective, the box constraints, and the exact integral constraint.

This plan uses a full-coordinate continuous smooth-chase method as the primary optimization mechanism:

- Build an analytic smooth surrogate for the finite-support maximum by using a log-sum-exp over all output entries of `np.correlate(h, 1-h, "full")`.
- Minimize this smooth surrogate on the continuous feasible set `[0,1]^n` with the exact sum constraint `sum(h) = n/2` using SciPy constrained local nonlinear optimization.
- Continue the chain of smooth problems over a decreasing temperature sequence, so the surrogate becomes closer and closer to the original non-differentiable maximum.
- Do not accept candidates from the smooth problem directly. Convert every candidate through a joint feasibility-restoration procedure and score it with the original evaluator. Only exact evaluator scores are stored as valid candidates.
- Because the final returned vector must exactly satisfy the discrete feasibility constraints, convert the accepted continuous vector to a high-resolution dyadic vector and enforce exact integer sum by bounded unit corrections. Because the denominator is a power of two and the integer sum target is exact, this gives an exactly feasible floating-point vector with no clipping/rescaling inconsistency.

This is materially different from a solely dyadic enumerative or pair-move technique. It uses all gradients in the full `n`-dimensional space under the linear equality constraint, letting the optimizer chase several roughly active overlaps at once. The dyadic stage is final, not the main long-term search variable.

1.2 Why it can improve the supplied parent

The original optimum of the discretized problem is stationary where there is no feasible descent direction for the max of the overlap polynomials. A smoothed version of the maximum has gradients spread over the near-active overlaps, which provides a usable average direction even when only one or a few overlaps are exactly tied. Decreasing the temperature then progressively concentrates that direction on the damaging overlaps. SLSQP, with the equality constraint and bounds handled directly, can follow that full dimension direction better than methods that move only a few coordinate pairs.

The improvement sought is tiny, so high final precision and exact evaluation are crucial. A continuous optimizer can explore where a random dyadic local-search method cannot, while the final exact dyadic repair prevents the reported solution from slipping due to sum or bound rounding errors.

1.3 Limitations and claims

The problem is bilinear and nonconvex. SLSQP may become trapped at a local stationary point of the smoothed or original problem. There is no global optimality claim and no certified global bound. This algorithm provides a strong local nonconvex exploration pipeline and guarantees only that the returned vector is feasible and that the returned numeric bound is its score under the exact evaluator.

Facts versus heuristics:
- Fact: the exact returned objective and feasibility are checked by the prescribed evaluator.
- Fact: the vector is made exactly feasible by construction: entries are dyadic rationals generated from integer counts with an integer sum target, so `sum(h)=n/2` in exact arithmetic and in the final representation.
- Fact: the finite-support correlation includes both signed lags exactly as `np.correlate(..., mode="full")` does, including boundary terms.
- Hypothesis/heuristic: a decreasing log-sum-exp temperature sequence from a balanced starting profile will locate a better local optimum.
- Hypothesis/heuristic: random full-coordinate and low-temperature line-search step directions may escape modest traps. These are search accelerators, not proof.

2. Mathematical specification

2.1 Exact finite-resolution objective and index correspondence

For a final returned vector `h` of length `n` and `dx = 2.0/n`:

- Feasibility domain:
  - `0 <= h[r] <= 1` for all `r`.
  - `dx * sum(h) = 1`, equivalently `sum(h) = n/2`.
- Exact objective as used by the evaluator:
  - `Z(h) = np.correlate(h, 1-h, mode="full") * dx`.
  - `C5(h) = max_r Z(h)[r]`.

The problem statement explicitly defines the objective by this finite-support linear cross-correlation over all `2*n-1` lags, not as a customerly chosen autocorrelation, circular correlation, or a heuristic `-1 - min()` formula. The final evaluator must therefore always call `np.correlate(h, 1.0-h, mode="full")` and multiply the maximum entry by `dx`.

For formulating gradients, use the manual slice representation that matches the NumPy full array. For output index `m`, define:

- `d = m - (n - 1)`.
- For `d >= 0`, the corresponding finite-support sum is:
  `correlate[m] = sum_{i=0}^{n-d-1} h[d+i] * (1 - h[i])`.
- For `d < 0`, with `r = -d`:
  `correlate[m] = sum_{i=0}^{n-r-1} h[i] * (1 - h[r+i])`.
- `m = n-1` therefore corresponds to `d=0` and contains `h[i]^2` terms.

The proper implementation includes all positive and negative `d` separately. A compact implementation may verify this manual formula on a small generated feasible vector against `np.correlate`; if not satisfied, it should not proceed subjectively to different formulas.

2.2 Smooth nonconvex surrogate

Let `R_m(h)` denote the raw correlation output without the final multiplying scalar `dx`:

`R_m(h) = correlate_raw[m] = (np.correlate(h, 1-h, mode="full"))[m]`.

The targeted exact raw objective is:

`R_max(h) = max_m R_m(h)`, and `C5(h) = dx * R_max(h)`.

Define the log-sum-exp surrogate with temperature `tau > 0`:

`F_tau(h) = tau * log( sum_m exp(R_m(h) / tau) )`.

In code to avoid overflow, compute with `S = max_m R_m(h)`:

`log_sum = log(sum_m exp((R_m(h) - S) / tau))`,
`F_tau(h) = S + tau * log_sum`.

As `tau -> 0+`, `F_tau(h) -> R_max(h)` from above or at least cluster at the active set scale; it is a stable smoothing of the max that retains the bilinear expression rather than substituting a separate penalty. Use `tau` in raw-correlation units, not scaled by `dx`, because `dx` is a positive common factor in a given dimension and scalar multiples do not change minimizers of a pure sum constrained problem. The final reported bound uses the exact scaled maximum.

2.3 Gradient of the smooth surrogate

Every returned candidate will be evaluated in the original objective. For internal smooth optimization only, compute `grad F_tau(h)`.

Let:

`w_m = exp((R_m(h) - S) / tau) / sum_j exp((R_j(h) - S) / tau)`.

Write `grad = sum_m w_m * grad R_m(h)`. The derivatives of `R_m` are exactly determined by the manual slices from section 2.1.

For output term `m`:

- If `d = m-(n-1) >= 0`:
  `R_m = sum_{i=0}^{n-d-1} h[d+i]*(1-h[i])`.

  The gradient contributions are:
  - For `r=d,...,n-1`:
    `grad[r] += w_m*(1-h[r-d])`.
  - For `r=0,...,n-d-1`:
    `grad[r] -= w_m*h[r+d]`.

  In slices:
  - `grad[d:n] += w_m * (1 - h[0:n-d])`.
  - `grad[0:n-d] -= w_m * h[d:n]`.

- If `d = m-(n-1) < 0`, let `r0 = -d`:
  `R_m = sum_{i=0}^{n-r0-1} h[i]*(1-h[i+r0])`.

  The gradient contributions are:
  - For `r=0,...,n-r0-1`:
    `grad[r] += w_m*(1-h[r0:n])`.
  - For `r=r0,...,n-1`:
    `grad[r] -= w_m*h[0:n-r0]`.

  In slices:
  - `grad[0:n-r0] += w_m * (1-h[r0:n])`.
  - `grad[r0:n] -= w_m * h[0:n-r0]`.

For `d=0`, the first case is used once:
`grad += (1-h) - h`, which is correct for the self-products.

No convexity is claimed: terms `h_i h_j` are bilinear. SLSQP must handle the Hessian approximation numerically. The objective gradient should be finite for if one active overlap dominates; `w_m` zeroes weights correctly because the shifted argument contains a zero unit at `R_m-S`.
