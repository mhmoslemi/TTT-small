1. Approach and rationale

1.1 Central idea

The proposed method treats the supplied evaluator for the chosen resolution `n` as an exact smooth finite-support minimax problem and solves it directly in epigraph form:

minimize t subject to t >= every raw correlation entry, 0 <= h_i <= 1, sum_i h_i = n/2, t >= 0.

The raw correlations are the exact entries of

`np.correlate(h, 1-h, mode="full") * dx`, with `dx = 2/n`.

For one fixed dimension `n`, multiplying all entries by the positive constant `dx` does not change the set of minimizers, so the epigraph variable is kept in raw correlation units internally. The only optimization used internally is a nonlinear local constrained minimization via SLSQP with the objective `t` and the nonlinear inequalities `t - raw_correlation[np_index] >= 0`. Unlike log-sum-exp, p-norm, or scalar relaxation approaches, no scalarization of the maximum is used during the main search. Unlike the earlier linearized trust-region approach, the epigraph constraints are supplied to the solver in their actual bilinear forms, not as a one-step linear model.

Because the main solver is local and nonconvex, every proposed vector is rechecked with the original evaluator and passed through a joint feasibility repair that produces an exactly feasible dyadic final vector. A deterministic exact-pair transfer polish is then used around accepted exact veins to recover small improvements that are lost or distorted by final rounding.

1.2 Why this addresses the bottleneck

The parent is already close to the target and the requested improvement is only about `5e-5` in the displayed upper bound. Two operations are therefore critical:

- The direction must account initially for all correlation entries that are near maximum. The epigraph constraint list does this by requiring all correlation entries to be reduced together.
- The final output must remain exactly feasible at high resolution. The nearest-unit dyadic repair mechanism makes feasible vectors from continuous candidates without clipping-then-rescaling.

1.3 Limitations and scientific status

- The transformation of the evaluator into an epigraph form is exact for a fixed `n`.
- The returned upper bound is certified by recomputation from the exact evaluator; no solver prediction is reported as a bound.
- No global minimum is claimed. The epigraph local SLSQP applies to a nonconvex feasible relaxation of the original bilinear minimax problem and may produce only a local stationary point. It may fail to converge or find a worse candidate at a particular starting point; the parent/best-so-far candidate is always retained.
- The dyadic repair is a construction mechanism, not an optimizer. It gives a feasible candidate that approximates the continuous solver iterate, and the candidate is accepted only by evaluating the original objective.
- Orientation detection is essential for correct gradients and constraint Jacobians. The plan specifies deterministic detection and validation relative to the evaluator.

2. Mathematical specification

2.1 Exact evaluator

For an array `h` of length `n >= 1`:

- `dx = 2.0 / n`
- `raw = np.correlate(h, 1.0 - h, mode="full")`, output length `L = 2*n - 1`
- exact score: `score(h) = dx * max(raw)`

Feasibility except for solver tolerances:

- every entry is finite and `0 <= h_i <= 1`
- `sum_i h_i == n/2`
- dx * sum_i h_i is equivalently 1. For the final vectors, an exact dyadic representation enforces this constraint through integer sums.

2.2 Epigraph subproblem for one fixed dimension

Let `R_m(h)` be the mth component of `raw` corresponding to m in `{0,...,L-1}`. Define the epigraph variable `t` in raw units.

Minimize `t` subject to:

1. `t >= R_m(h)` for every m
2. `t >= 0`
3. `0 <= h_i <= 1` for every i
4. `sum_i h_i = n/2`

The objective bound is `dx*t` for fixed `n`. This is direct epigraph minimax optimization. The inequalities use actual `R_m` values at evaluation time, so the exact maximum is handled within the local nonlinear programming process.

SLSQP's nonlinear constraint convention is `c(x) >= 0`, so implement it as one vector constraint:

`c_m(x) = t - R_m(h)`, where variables `x = [h_0,...,h_{n-1},t]`.

Thus `c_m(x) >= 0` if and only if `t >= R_m(h)`. The solver feasibility wording is compatible because all rows define an inequality constraint vector and SciPy SLSQP accepts vector-valued nonlinear constraints. The left-hand side is the raw output row value in the order returned by `np.correlate`'s full mode, not an arbitrary ordering.

2.3 Raw correlation indexing and orientation

The objective is defined through `np.correlate`, so the inequalities and exact evaluator agree without ambiguity. Derivative support formulas must match the same output order. The plan constructs an orientation map once per dimension at startup.

Use a test vector `y`. Evaluate `a = np.correlate(y, 1-y, mode="full")`. Consider candidate maps.

For a signed integer lag `d` from `-(n-1)` to `n-1`, define scalar and vector expressions:

If `d >= 0`:

`Rplus_d(y) = sum_{i=0}^{n-d-1} y_{d+i} * (1 - y_i)`

If `d < 0`, let `r = -d`:

`Rminus_d(y) = sum_{i=0}^{n-r-1} y_i * (1 - y_{i+r})`

At `m` map possible `d = m - (n-1)`.

Candidate mapping families:

- A: `d_m = m - (n-1)`
- B: `d_m = (n-1) - m`
- C: `d_m = -(m - (n-1))`
- D: `d_m = -((n-1) - m)`

Build the array from candidate values `Rplus_d` for `d >= 0`, `Rminus_d` for `d < 0`. Use the map whose exactly generated array has `max abs difference from a < 5e-12`. At least one will match; if multiple do, use the first detected. If none match due to implementation detail, the program may raise a controlled failure marker but final reported summaries still use exact evaluator; for correctness, the coder must fix the derivative mapping before a production run. The objective itself remains correct even if gradients are wrong, but the local step direction would fail, so startup `_need orientation verify` is a runtime requirement.

The map is stored as `lag_for_output_index[m]`. Derivative handling uses the same `d` associated with each output entry.

2.4 Raw correlation value formulas

In rac units, for each index m and associated signed lag d:

If d >= 0:

`R_m = dot(y[d:n], 1.0 - y[0:n-d])`

If d < 0:

`r = -d`; `R_m = dot(y[0:n-r], 1.0 - y[r:n])`

These formulas are used only when generating orientation violations and as a reliability check. The solver constraint values should call actual `np.correlate` directly because that is the evaluator.

2.5 Derivatives and Jacobian

Let `g_m(y)` be the vector of partial derivatives with respect to h components at the current point y.

If d >= 0:

`g_m[d:n] += 1.0 - y[0:n-d]`
`g_m[0:n-d] -= y[d:n]`

If d < 0, with r = -d:

`g_m[0:n-r] += 1.0 - y[r:n]`
`g_m[r:n] -= y[0:n-r]`

For d=0, either branch gives `g_m = 1 - 2*y`.

The full multiplier is sum of nonnegative first factor by one-h, so row bounds: entries may be negative due complement terms. Constraint derivative:

jacobian row m length `n+1`:

- First n entries: `-g_m(y)`
- Last entry: `1.0` (derivative of `t` term)

The equality constraint for all dimensions is:

`sum(h) - n/2 = 0`

Jacobian: `[1,1,...,1,0]`.

Bounds: both vector inequality and variable bounds impose `0 <= h <= 1`. No separate inequality needed if variable bounds are enabled. `t` has bounds `[0, y_raw_max_initial + 4*n]`; upper bound prevents numerical wander and does not exclude a normal optimum.

2.6 Continuous projection to the hyperplane

Use this only as an in-solver feasibility step after a candidate emerges. Given arbitrary finite `v`, define `v0 = clip(v,0,1)` and solve monotonic scalar root:

`G(alpha) = sum_i clip(v0_i + alpha)`, target `n/2`.

Locate bracket:

`alpha_low = -max(v0) - 1.0`,
`alpha_high = 1 - min(v0) + 1.0`.

`G(alpha_low) <= 0` and `G(alpha_high) >= n`, so the target is bracketed. Perform 70 bisection steps, selecting midpoint; return `clip(v0 + midsum)`. If input is nonfinite, return invalid. This projection maintains exactness only in continuous arithmetic and is not used as the final output.
