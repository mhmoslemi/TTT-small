1. **Approach and rationale**

   The target is to return a genuinely validated `h` with lower exact `np.correlate(h, 1-h, mode="full") * dx` maximum than the supplied construction. The essential difficulty is that the objective is a finite, aperiodic, nonconvex max over lagged bilinear overlaps, and tiny improvements near `0.38085` can require coordinated changes in many entries while preserving `0 <= h_i <= 1` exactly and `sum(h) = n/2` exactly.

   This plan deliberately does not rely on a single smooth surrogate or a single high-dimensional local optimizer. Its central mechanism is a three-level search:

   1. A compact **global generator** using low-dimensional bounded basis families (smooth Fourier/logistic screens and polyline screens) creates structurally new feasible candidates. These are effective for escaping the supplied local basin.
   2. The supplied parent, or fallback construction, is transformed between several compact resolutions. Every transformation is re-projected into the exact discrete feasible set and evaluated by the authoritative metric.
   3. Every good candidate is polished by **exact pairwise transfer transfers**: all moves explicitly preserve the sum and bounds, but every accepted move must reduce the original evaluator value. The polish uses deterministic sifted pair selection plus one-dimensional exact line tests, rather than merely adding random noise or optimizing a relaxed surrogate.

   This is materially different from simply optimizing the native grid with an epigraph/LP/QP or independent random-evolution routines. The new element is that the lowest-complexity successful structural changes are first generated in a low-dimensional representation, then immediately converted to exact feasible discrete vectors, and finally refined by exhaustive-but-budgeted exact pair transfers that accept only original-metric improvements. The final accepted output is always the discrete vector best found by the authoritative evaluator; low-dimensional scores are only candidate embarkation masks and never carried as output claims.

   The mathematical formulation is nonconvex because it contains products `h_i h_j`. The limiting consequence is unavoidable: the procedure has no global optimality guarantee. The justified facts are: (a) all `h` returned are accepted only after exact feasibility and exact objective checks; (b) the supplied workable parent remains a valid fallback; (c) the residual functions for every formula directly correspond to the discrete evaluator, with no circular, periodic, or autocorrelation-only substitutions.

   The target improvement is very small relative to the current `0.38085`, so the method must spend most of its budget in compact calculations and high-precision line refinement. If no improvement is found, the program still has to output a feasible candidate; that fallback is recommended to be the best initially supplied feasible vector whenever it exists.

2. **Mathematical specification**

   2.1 **Representation and constraints**

   Let the returned array be
   ```
   h = [h[0], h[1], ..., h[n_points-1]]
   ```
   with uniform grid centers
   ```
   x_j = (j + 0.5) * (2.0 / n_points),  0 <= j < n_points
   ```
   and spacing
   ```
   dx = 2.0 / n_points.
   ```

   The feasible set is exactly
   ```
   0 <= h[i] <= 1 for all i
   sum_i h[i] = n_points / 2
   ```
   (the equivalent continuous condition is `dx * sum(h) = 1`).

   More precisely, let `target_sum = n_points / 2`. All candidate conversions use
   ```
   |sum(h) - target_sum| <= 1e-10
   |min(h)| <= 1e-12 and max(h) <= 1 + 1e-12
   ```
   as an operational tolerance. Any final returned vector should also be repaired after this tolerance pass by tiny exact transfers to reduce numerical residual further. If the evaluator parser uses exact equality, the repair procedure must perform finite precision corrections until the Python side tolerance is essentially machine-symbol; tolerance-based repair is requested rather than insisting on unproven floating-point exactness.

   2.2 **Exact evaluator and correlation orientation**

   The authoritative objective must be computed identically to the supplied evaluator:
   ```
   r = np.correlate(h_values, 1.0 - h_values, mode = "full")
   c_full = r * dx
   C_exact(h) = max_j c_full[j]
   ```
   The output length is `2*n_points - 1`. Edges of this output correspond to all lags `-(n-1), ..., -1, 0, ... +(n-1)`, including boundary-incomplete overlap. No smoothing, trimming edges, restricting to `|lag|`, circular correlation, or replacement by `1 - autocorrelation` is permitted for decision output. Decision code may use a smooth surrogate only for optimization; decision acceptance is allowed only after computing `C_exact` as above.

   The plan prevents accidental index convention mistakes by parameterizing all score evaluations through a single top-level routine named `_exact_score(h)`. That routine chooses the harness helper if available from the environment, e.g. `evaluate_erdos_solution(h)`; if no suitable helper or callable signature exists, it uses the exact `np.correlate` line quoted. If it uses both metrics, it first checks that they return a scalar nonnegative finite number for a tiny system. Final output always re-evaluates the exact metric with the final `h` and returns this value.

   2.3 **Feasible construction with exact box preservation**

   Given a raw vector `raw` of finite numbers, construct an infeasible candidate:
   1. Clear nonfinite values by replacing them with `0.5`.
   2. For all `s`, define `F(s) = sum(clip(raw + s, 0, 1))`.
   3. This `F(s)` is a continuous nondecreasing piecewise-linear function. Choose an interval:
      ```
      lo = -np.max(raw) - 1.0
      hi = -np.min(raw) + 1.0
      ```
      Then at least `F(lo) <= 0` and `F(hi) >= n_points`, and `target_sum` lies inside `[0, n_points]`.
   4. Use a bracket bisect for 70 iterations toward root `(bias)` cut, which approximately solves
      ```
      sum(clip(raw + bias, 0, 1)) = target_sum.
      ```
   5. Return `h = clip(raw + bias, 0, 1)`. This step alone has no sum-consistent clipping and does not satisfy the sum constraint exactly.

   The joint repair maintains both constraints:
   - Compute residual `delta = target_sum - sum(h)`.
   - If `delta > 0`, pick an index up to six values with maximum remaining headroom `slack(j) = 1 - h(j)`. Set
     ```
     mu = min(delta, slack(j))
     h(j) = h(j) + mu
     delta = target_sum - sum(h)
     ```
     Repeat while `|delta| > 1e-12` using the largest slack coordinate or small cyclic pairs.
   - If `delta < 0`, do the same with `slack(j) = h(j)` to reduce h.
   - If this residual stalls while all relevant entries are at their respective bounds at machine precision, apply a spectral transfer sequence among values not already exactly saturated in both directions. Perform many reductions of residual by roughly `1e-14`. Such cycles are acceptable because they preserve exact feasible bounds at machine precision and only change by tiny allowed amounts.

   No method returns clipped followed by a rescaling without corrective joint repair. A candidate rejected as not finite after additional includes small parity. Coder may implement only above repair rules.

   2.4 **Smooth surrogate objective for smooth family optimization**

   Let
   ```
   c = dx * np.correlate(h, 1-h, mode="full")
   C = max(c)
   ```
   To guide raw parameter optimization, define a **strict surrogate** (never returned as the score):
