1. Approach and rationale

1.1 Central idea

The task is a small, discrete, bounded, finite-support cross-correlation minimax problem. Let a candidate vector be `h` of length `n`, with `dx = 2/n`. The standardized evaluator is

`C5(h) = max(np.correlate(h, 1 - h, mode="full")) * dx`.

The supplied construction is already near a credible basin with `C5 ≈ 0.38085`, and the goal is only about `5e-5` lower, namely target `C5 <= 0.3808`. The main barrier is therefore not obtaining a fresh crude construction, but making a precisely controlled local minimax movement while ending with an exactly feasible vector.

This plan uses a sequential linearized-minimax, or Remez-like trust-region, strategy. At a current candidate, the two-sided finite-support overlap functions are expressed explicitly, their first-order gradients are computed exactly for each active or near-active lag/orientation, and a bounded linear program (LP) is solved:

- variables: coordinate perturbations `delta_i` and a predicted scalar maximum `t`,
- linear constraints: every selected/near-max overlap function is linearized as
  `F_s(h) + gradient_s · delta <= t`,
- equality constraint: `sum_i delta_i = 0` so that the integral constraint is preserved to first order,
- box/trust-region constraints on `delta_i` to stay inside and near the feasible box,
- objective: minimize `t`.

The LP direction is not accepted by trusting its linear model. It is sampled, continuously projected in bounds and sum, then repaired to a dyadic feasible representation and scored by the exact evaluator. Only exact scores are accepted and stored.

This differs substantively from smoother continuous objectives or purely random coordinate-transfer local search. The central move solves a linear minimax problem: it can move multiple active overlaps down at once under box and sum constraints, instead of collapsing the max to a single smoothed scalar gradient or accepting only random pairwise moves. The linear model is overconstraints, but the line-search plus exact acceptance restores failing or overoptimistic candidates.

1.2 Why this may improve the parent

- If the parent is close to but not stationary for the discrete exact objective, the linearization of the largest many overlaps will reveal a common improving direction.
- If several nearly equal peeks dominate the maximum, the LP can distribute coordinate changes among many locales so that all near-peeks decrease, rather than only following one dominant constraint.
- If several variables are saturated at `0` or `1`, the LP recognizes feasible marginal shifts required for exact transfer of mass without violating boundaries.
- Because each test uses exact repair and exact scorer, the algorithm cannot lie about the final bound; every candidate in the registry is a valid, discretely feasible vector.

1.3 Limitations and heuristics

This is a local nonconvex heuristic. The bilinear overlap functions are neither convex nor concave. A stationary parent under the first-order model does not imply a global or even local optimum of the exact discrete problem. The method can be trapped. It compensates with:

- randomized active-set sizes/values,
- multiple trust-region radii,
- randomized candidates and pool restarts,
- dimension transfers,
- a guaranteed valid fallback.

Justified facts:
- exact evaluation uses only the original discriminator formula,
- every accepted output has entrywise boundary and exact dyadic sum feasibility enforced,
- the reference objective contains all `2n - 1` linear-lag outputs, including boundaries and both lag signs.

Heuristic hypotheses:
- near-optimal vectors have a near equioscillatory active set,
- a small matching LP trust step will frequent reduce the exact objective before destroying non-linear behavior,
- random pool exchanges enable escape from one active-set stagnation state.

No global optimality or proof is claimed.

1. Approach and rationale

1.1 Central idea

The discrete problem is a bounded finite-support cross-correlation minimax problem:

`C5(h) = dx * max(np.correlate(h, 1 - h, mode="full"))`, with `dx = 2/n`, `0 <= h_i <= 1`, and `sum(h)=n/2`.

The supplied parent is already very close to the target: current record about `0.38085`, target about `0.3808`. Hence the bottleneck is not building a new crude construction, but making a controlled local minimax move while preserving exact discrete feasibility and scoring every move with the exact evaluator.

The proposed algorithm is a sequential linearized minimax scheme, inspired by Remez-style active-set control:

1. At a Dyadically feasible current candidate, enumerate every actual overlap function that appears in the finite cross-correlation. Use an explicit two-sided representation independent of NumPy orientation.
2. Select near-maximal overlap functions (the active/near-active set).
3. Linearize those overlap functions at the current point and solve a bounded linear program whose variables are coordinate perturbations plus a predicted maximum `t`. The LP moves as much shared descent as possible across several active overlaps while keeping the sum perturbation zero and respecting coordinate boundaries.
4. Do not accept the LP model. Normalize the direction, apply line-search factors, continuously project approximately onto the clip-plus-sum feasible set, then repair exactly to a dyadic feasible vector.
5. Score the repaired vector with the evaluator. Only exact improvements are accepted into the candidate pool and global best.
6. Use randomized active sets, dimension transfers, perturbation restarts, and multiple bit resolutions to escape local linear-model plateaus.

This is materially different from using a log-sum-exp smooth objective or a purely random dyadic pair-transfer search. The core move solves a bounded linear minimax relaxation over selected first-order overlap functions. It directly balances several active constraints rather than reducing the maximum to one smoothed scalar gradient or only making random coordinate transfers.

1.2 Why this may improve the parent

- If the parent is not exactly stationary under the discrete evaluator, the linear model of the largest overlaps exposes a feasible descent direction.
- If several peeks are nearly tied, the LP distributes changes among many coordinates so that multiple near-maxima decrease simultaneously.
- If coordinates are near the bounds, the LP explicitly accounts for the one-sided capacity available at those coordinates, which many smooth gradient methods can distort.
- Every accepted repository entry is recomputed by the exact evaluator and repaired from integers, so no optimistic final bound can be accidentally stored.

1.3 Limitations

- The objective is bilinear and nonconvex. This is a heuristic nonconvex local search.
- If the linear model becomes stationary, improvements require randomization and restart; no global or local-optimality certificate.
- The LP uses a selected constraint subset, so hidden constraints may spoil a step. Line-search shrink and exact acceptance mitigate this; they do not overcome all nonconvex traps.
- Final resolution depends on the denominator and repair heuristic. Too coarse resolution may miss a small numerical improvement; too fine resolution may make candidates round to nearly identical states before an exact improvement. Multiple bit settings provide variation.

Facts versus hypotheses:
- Fact: exact scoring and exact feasible repair can be implemented independently of the internal LP model.
- Fact: the manual overlap-family representation can cover all linear lag outputs generated by NumPy if both orientations are included and checked.
- Opinion/heuristic: a small exact LP step for the active set, followed by exact shrink and dyadic scoring, is strong for improving a near-optimal parent by `O(1e-4)` in `C5`.

2. Mathematical specification

2.1 Grid and objective units

For dimension `n`:

- `dx = 2.0 / n`.
- `h` is a real one-dimensional vector of length `n`.
- Final feasible candidates have the form `h_i = k_i / Q`, where `k_i` are integers, `Q=2^B`, `0 <= k_i <= Q`, and `sum(k_i) = nQ/2` exactly. Thus the integral constraint is enforced by integer construction rather than clip/rescale heuristics.
- Exact output objective:

  `C5_exact(h) = (2/n) * max(np.correlate(h, 1.0-h, mode="full"))`.

Intermediate subproblems use raw values without multiplying by `dx`:

`M_raw(h) = max overlap functions raw`. Then `C5_raw_to_C5 = dx * M_raw`.

The LP variable `t` is in raw overlap units. At the accepted/repaired candidate step, multiply raw maximum by `dx` to compare candidates. This keeps internal LP units stable across `n`, while global comparison remains exact `C5`. Keep separate comparisons: internal local progress raw is tuned in raw units, but global best uses `C5`. Dimension differences may distort raw values, so never rank final records solely by raw values.

2.2 Exact manual overlap functions

For each lag `k=0,...,n-1`, define:

- Positive orientation:

`P_k(h) = sum_{i=0}^{n-k-1} h[i] * (1 - h[i+k])`.

  For `k=0`, interpret as `sum_i h[i]*(1-h[i])`.

- Negative orientation:

`N_k(h) = sum_{i=0}^{n-k-1} h[i+k] * (1 - h[i])`.

  Again `N_0 = P_0`.

Set `S = {P_0} union {P_k, N_k : k=1,...,n-1}`. This is a complete float-scale exact representation of finite-support overlaps. Its maximum equals the maximum over `np.correlate(h, 1-h, mode="full")` up to the orientation-order of output entries. The plan does not replace the evaluator with `1 - autocorrelation()`; the functions include only actual valid finite-support pairs and boundary truncation terms.

2.3 Gradients

For `k>0` and `P_k`:

Derivative wrt coordinate `j`:

- If `0 <= j <= n-k-1`, `j` is the left factor term: derivative `1 - h[j+k]`.
- If `k <= j <= n-1`, `j` is the right factor: derivative `-h[j-k]`.

Slice formula:

```
G_p_p = length-n zero vector
    G[0:n-k] += 1 - h[k:n]
    G[k:n]   -= h[0:n-k]
```

For `N_k`:

Slice formula:

```
G_n_k = length-n zero vector
    G[0:n-k] -= h[k:n]
    G[k:n]   += 1 - h[0:n-k]
```

For the single `k=0` function, use `P_0`:

```
G_p_0 = 1 - 2h.
```

These gradients come only from differentiating `a * (1-b)` on finite valid index ranges and are qualified over finite-support boundaries.

2.4 LP subproblem: linearized minimax

Let current feasible candidate be `h` and its actual raw max be `Mraw = max F_s(h)` over all selected overlap functions. Select a near-active subset `A` such that each selected function satisfies roughly `F_s(h) >= Mraw - window`. The optimization variable is:

`y = [delta_0, ..., delta_{n-1}, t]`

Minimize `t`.

For each selected overlap function `s` with raw current value `F_s` and gradient `g_s`:

Original linear model constraint:

`F_s + g_s^T delta <= t`

Equivalent LP row:

`g_s^T delta - t <= -F_s`.

Add sum constraint:

`sum_j delta_j = 0`.

Box/trust constraints:

`-h_j <= delta_j <= 1-h_j`.

Added trust bounds via interior capacities (detailed below):

`-down_j <= delta_j <= up_j`.

This is a true linear program (one decision variable for each coordinate plus scalar `t`). All linearized constraints are linear equalities/inequalities. The equality and bounds are touched exactly by the LP. If current continuous candidate may have sum tolerance issues, enforce sum bound; but LP variables should preserve current sum linearly.

2.5 Numerical row normalization

With raw overlap functions, some rows may be large if many terms, and gradients can have different norms. A constraint can be divided by a positive number without changing it:

`srow = max(1.0, mean(|g_s|) + |F_s|) `

Then use:

`(g_s/srow)^T delta - t/srow <= -F_s/srow`.

This preserves the halfspace but improves numeric LP conditioning. Do not use any custom max-min rate defined by manually replacing by `1 - min autocorrelation`; this LP is strictly committed to listed functions generated by terms or evaluator.

1. Approach and rationale

1.1 Central idea

This plan treats the discrete Erdős overlap evaluation as a bounded finite-support minimax problem and attacks it with a sequential linearized-minimax trust-region method. At a current dyadically feasible candidate, the exact set of overlap functions produced by the evaluator is explicitly represented. A near-active subset is selected, each selected overlap is linearized at the current point, and a bounded linear program is solved to find both coordinate perturbations and a predicted overlap maximum. The LP is not trusted blindly: every direction is converted to a continuous candidate, approximately projected onto the bounded-sum feasibility set, repaired to a exactly sum-feasible dyadic vector, and scored with the original evaluator. Only exact evaluator-score improvements enter the candidate pool or global best.

This choice is materially different from optimizing a log-sum-exp smoothing surrogate of the correlation maximum, from random/dyadic pair-transfer searches, and from using a general nonlinear solver on one scalar objective. The core move is a linear minimax relaxation: it can move several active or near-active overlaps downward while explicitly accounting for the sum constraint and coordinate boundary capacities. The exact evaluator filters all optimistically accepted elements.

1.2 Why this may improve a parent construction whose `C5 ≈ 0.38085`

The target only requires a tiny improvement. At this precision, the obstacle is not finding a broad basin, but making an exact feasible movement that reduces the largest evaluated overlap without accidentally increasing another one.

- If the supplied parent is not already stationary for the exact discrete evaluator, a linear model of the largest overlaps should expose a feasible improvement direction.
- When several peak overlaps are nearly equal, the LP can sacrifice movement where it is cheap and protect coordinates near bounds.
- Explicit `sum(delta)=0` use prevents sequential clip/rescale drift; final dyadic integer repair enforces exact sum for the returned vector.
- Exact evaluation and validation of each move mean that solver optimism cannot corrupt the reported bound.

1.3 Limitations

- The original bilinear problem is nonconvex; this heuristic local method does not prove global or local optimality.
- For a stationary point of the linear model, no descent can be extracted by algorithm; recovery requires randomized restarts and candidate-pool sampling.
- Selecting only a subset of constraints for the LP means hidden constraints can spoil a step; shrinking line search and exact objective rejection handle this only as a heuristic safeguard.
- If too coarse an intermediate grid is used, small target improvements near `10^-4` to `10^-5` in `C5` may be lost in exact quantization repair. High bit denominators are used.

Facts: exact evaluation, bounds construction, and integer-sum repair can be guaranteed. Hypotheses: an active-set LP step will find a valid tiny improvement before hidden constraints kill the trial; random restart/perturbations help escape a plate table near parent basin.

2. Mathematical specification

2.1 Grid, objective, feasibility, and exact evaluation

For final output length `n`, `dx = 2/n`. The exact evaluator is

`C5_exact(h) = (2/n) * max_d np.correlate(h, 1-h, mode="full")[d]`.

The returned vector must satisfy

- `0 <= h_i <= 1`,
- `sum_i h_i = n/2`
  (enforced in the proposed implementation by exact integer dyadic vector representation).

Do not replace by circular correlation, an autocorrelation identity `1 - autocorr`, or an unconstrained Fourier derivation. The intended evaluator includes all `2n-1` finite-support overlap functions and boundary terms directly.

2.2 Exact two-sided overlap family

For `k = 0,1,...,n-1`, define:

Positive orientation:

`P_k(h) = sum_{i=0}^{n-k-1} h[i] * (1 - h[i+k])`
  for `k=0`, this is `sum_i h[i]*(1-h[i])`.

Negative orientation:

`N_k(h) = sum_{i=0}^{n-k-1} h[i+k] * (1 - h[i])`
  for `k=0`, `N_0=P_0`.

Use the one combined set `{P_0} ∪ {P_k, N_k : k≥1}` as internal constraint values. Its maximum is the raw non-scaled correlation max, i.e. without multiplying by `dx`. No orientation ambiguity remains because both orientations are explicitly evaluated. An input validator may compare maximum of this set against evaluator value on a small current candidate; compare outside production, candidate acceptance always uses the original evaluator.

2.3 Exact gradients of the overlap functions

For `P_k`, `k>0`:

`grad(P_k) = zeros(n)`
`grad(P_k)[0:n-k] += 1 - h[k:n]`
`grad(P_k)[k:n] -= h[0:n-k]`

For `N_k`, `k>0`:

`grad(N_k) = zeros(n)`
`grad(N_k)[0:n-k] -= h[k:n]`
`grad(N_k)[k:n] += 1 - h[0:n-k]`

For `P_0/N_0`:

`grad(P_0) = 1 - 2h`.

Differentiate only finite valid terms; do not introduce appended outer ones that create a new problem.
