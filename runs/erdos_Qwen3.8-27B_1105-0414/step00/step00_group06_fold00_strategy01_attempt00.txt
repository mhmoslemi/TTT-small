1. Approach and rationale

1.1 Central idea and why it can help

The supplied parent construction is the authoritative locally validated point, but its objective depends on many simultaneous bilinear correlation constraints. Instead of solving a large nonconvex epigraph problem or using a smooth surrogate in a way that may only move transversely along local ridges, the proposed method treats the evaluator formula itself as the only valid local oracle and searches in an exactly feasible tangent neighborhood generated by feasible mass transfers between pairs of sampled coordinates:

- Keep the supplied parent untouched as the permanent fallback.
- Build additional feasible descendants of the parent by compact deterministic or seeded algorithmic resampling rather than hard-coding a numeric table.
- Explore the search space using an exact-evaluator stochastic local search whose one-step proposals are always sum-preserving transfers of mass between two coordinates or binary swaps. Every proposal is fully re-scored with the official correlation formula before acceptance.
- Run the same search across multiple viable grid resolutions, including smaller grids and grids near the parent. The objective is scored by the actual returned grid and dx, and smaller grids are allowed because the evaluation is over the returned sequence, not a hidden fixed grid.

This approach attacks the apparent bottleneck directly: to improve from roughly 0.38085 to below 0.3808, we need actual local or semi-global deductions of maximum overlap. The method does not depend on deriving a global convex relaxation or on approximating the maximum with a potentially misleading scalar surrogate. It maximizes the number of exact feasible neighborhoods tested inside the allowed 1100 seconds, with an explicit safeguard that the parent or any verified descendant is never lost.

1.2 Distinguished claims and hypotheses

- Proven/defined:
  - The final candidate and the final score must be generated by the exact formula specified in the problem.
  - A pairwise change where one coordinate is increased by t and another decreased by t preserves the finite sum exactly in an ideal-mathematical sense. With controlled floating-point repair this can be made numerically exact to a tolerance suitable for the final return.
  - Resampling a supplied parent onto a different grid, followed by a correct sum-and-box feasibility repair, yields a valid vector for that new grid.
- Heuristic:
  - A grid different from the supplied parent grid may contain a discretized construction with lower reported overlap because the same continuous idea is represented by fewer or more samples. This is an advantage of the requested discrete construction, not a hidden continuous guarantee.
  - Simulated annealing plus many random mass-transfer proposals may leave a local basin of the supplied parent and discover lower values. There is no global optimality claim.
  - Stopping early once a clearly below-target value is accepted is a practical heuristic to avoid wasting time. It will stop only after exact re-evaluation of that vector.

1.3 Rejection of alternatives

Epigraph optimization of log-sum-exp or max-appearance constraints was considered, but:

- The product terms make the original problem nonconvex. A direct CVXPY solution for the real objective would either violate CVXPY convexity rules or require products and disallowed epigraph substitutions.
- A smooth epigraph can be misleading for a low-precision local improvement goal and may spend too much time solving poor-quality nonlinear programs.

Therefore the core method is exact-evaluator guided, constrained stochastic/pairwise local exploration, not a generic nonlinear epigraph solver.

2. Mathematical specification

2.1 Discrete representation and feasibility

Let h be a NumPy array of length n over float64. The grid spacing is

dx = 2.0 / n

and the required discrete sum is

S = sum(h) = n / 2

吩咐 since sum(h) * dx = 1. For binary demands:

- if n is even, sample values in {0, 1} with exactly n/2 ones;
- if n is odd, binary sampling with exact half-sum is not used, but continuous vectors remain valid.

Validity test for a vector v:

- all entries finite;
- -1e-12 <= min(v) and max(v) <= 1 + 1e-12;
- abs(sum(v) - n/2) <= 1e-11, which is enough if the final exact target is 1e-12 and is protected by under-determined arithmetic via exact repair.

It is not enough to clip many values and then scale because of clipping-vs-sum interference. A feasible vector is created by a sum-repair routine specified below.

2.2 Exact objective

For every lag index r from 0 to 2n - 2, define

full_corr[r] = dx * sum over valid ordered index pairs (a, b) of h[a] * (1 - h[b])

with lag offset constrained by the exact definition of NumPy full correlation between h and 1-h. The reported score is

score(h) = max(full_corr)

The implementation must generate a vector c_lag using the same ordered evaluation as the user specifies:

C5(h) = max(np.correlate(h, 1-h, mode="full") * dx)

The final return, including all design helper choices, must always be re-evaluated using this expression.

For the internal pair-description used in localization, use the following ordered description inside the duration. Validate it once against NumPy using a simple all-zero and random vector. Let lag r have d = r - (n - 1), where d ranges from -(n - 1) to +(n -1).

- If d >= 0:
  - valid b runs from 0 to n - d - 1.
  - valid a equals b + d, so a runs from d to n - 1.
  - term is h[a] * (1 - h[b]).
- If d < 0:
  - valid a runs from 0 to n + d - 1 because d is negative, equivalently 0 to n - |d| - 1.

In binary cases, the max involves overlap lengths varying by lag. Boundary lags, especially lag 0, are retained in the objective. Do not drop them.

2.4 Pairwise feasible transfer formulas

v = copy(h)
v[i] = h[i] + delta
v[j] = h[j] - delta

Legitimate delta range ensures both boxes:

lower = max(-h[i], h[j] - 1.0)
upper = min(1.0 - h[i], h[j])
delta must lie in [lower, upper]

The sum preserved:

sum(v) = sum(h) + delta - delta

in ideal math. Numerical error is handled by exact_feasibility_project as specified above.
