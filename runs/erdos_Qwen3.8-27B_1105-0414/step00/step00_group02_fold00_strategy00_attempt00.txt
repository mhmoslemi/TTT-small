1. Approach and rationale

The evaluation is a finite-dimensional nonconvex problem because the objective is the maximum of many quadratic correlation terms. The known supplied construction with about 47 samples is the best available trusted incumbent, so the plan is to keep it as a fallback and explore nearby and transformed representations whose final candidates are always judged by the exact evaluator, not by surrogate scores.

The central algorithmic idea is to solve a sequence of constrained nonlinear programming local problems in epigraph form:

- variables are the sample vector h and a scalar upper-bound variable t;
- minimize t subject to t greater than or equal to every finite-support correlation at every signed lag, feasibility bounds 0 <= h_i <= 1, and the exact area constraint sum(h_i) = n/2;
- the local solver uses analytic gradients for all correlation terms;
- every returned or improved candidate is re-feasibilized exactly and re-scored using the authoritative evaluator score max(np.correlate(h, 1-h, full) * (2/n));
- store the best validated candidate throughout the run.

Why this can improve the parent:
- The epigraph formulation directly targets the maximum in the true score rather than a smooth surrogate.
- The analytic derivatives are exact for the same quadratic pairwise expressions, so SLSQP-style trading between the active correlation lags, the area constraint, and the bounds is reliable.
- Multi-start variants, complement, perturbations, and resolution transfer reduce dependence on the local basin of the supplied parent.
- High-resolution candidates can sometimes represent a better continuous function while keeping sample count modest.

Facts versus hypotheses:
- It is a fact that the objective is not convex because each correlation contains products of two h components.
- It is a fact that every local method may get stuck; no global optimality proof is claimed.
- It is a hypothesis that multi-start refinement plus resolution transfer will lower the parent score. It is explicitly tested and accepted only after exact evaluation.
- The method makes no promise of a global optimum, but it robustly returns the best validated incumbent found before the time limit.

2. Mathematical specification

Let n be the number of samples, indices i = 0,...,n-1, and dx = 2/n. The sample values are h_i in [0,1] and the discrete area constraint is

S = sum_i h_i = n/2.

The authoritative discrete score is

C5(h) = max over r=0,...,2n-2 of dx * R_r,

where R = np.correlate(h, 1-h, full). The maximum covers all 2n-1 signed finite-support lags.

For the optimization constraints, define scaled correlations in signed-lag order. Use the signed lag ell in {-(n-1), ..., n-1}, with unscaled correlation M_ell as follows.

Center lag ell = 0:

M_0 = sum_i h_i (1 - h_i).

Positive shift ell = d > 0:

M_{+d} = sum_{i=0}^{n-d-1} h_{i+d} (1 - h_i).

Negative shift ell = -d with d>0:

M_{-d} = sum_{i=0}^{n-d-1} h_i (1 - h_{i+d}).

These correspond to the two correlated directions appearing in np.correlate, just possibly ordered differently. Because all signed lags are included, the set of constraints is equivalent in direction; the final score is still recomputed with the official np.correlate formula, which also guarantees consistency.

Epigraph variables:

x = [h_0, ..., h_{n-1}, t].

Constraints:

- Box bounds: 0 <= h_i <= 1. For the scalar t, use a safe finite interval, e.g. [0, U] with U = max(1, 2 + parent_score).
- Equality: sum_i h_i - n/2 = 0.
- Inequality constraints, written in SciPy SLSQP convention c(x) >= 0:

  G_ell(h, t) = t - dx * M_ell(h) >=0, for each signed ell.

Objective:

  min t.

Derivatives.

The equality gradient with respect to the full epigraph vector is ones for h components and 0 for t.

The linear objective gradient is zeros for h components and 1 for t.

For inequality G_ell = t - dx*M_ell, the derivative is negative of the correlation derivative for h components and +1 for t.

Derivatives of M_ell:

Center ell=0:

dM_0 / dh_q = 1 - 2h_q.

Positive shift ell = d > 0:

M_{+d} = sum_{i=0}^{n-d-1} h_{i+d}(1-h_i).

For q:
- Add (1 - h_{q-d}) if q >= d.
- Subtract h_{q+d} if q <= n-d-1.
Equivalently, for that row:
- row[q] += 1 - h_{q-d} for q=d,...,n-1.
- row[q] -= h_{q+d} for q=0,...,n-d-1.

Negative shift ell = -d < 0:

M_{-d} = sum_{i=0}^{n-d-1} h_i(1-h_{i+d}).

For q:
- Add (1 - h_{q+d}) if q <= n-d-1.
- Subtract h_{q-d} if q >= d.
Equivalently:
- row[q] += 1 - h_{q+d} for q=0,...,n-d-1.
- row[q] -= h_{q-d} for q=d,...,n-1.

The inequality row gradient is the negative of the above multiplied by dx for h components, with +1 at the last column for t.

All derivative expressions preserve partial interval boundary effects because the sums exclude samples where either index falls outside [0,n-1]; no circular or periodic simplification is used.

No convex regularization is claimed. A direct CVXPY call is not the primary route because M_ell is bilinear and indefinite. If any relaxed or smoothed candidate is ever returned, it must first be transformed through the same feasibility projection and accepted only if it satisfies the exact box, exact area, and finite-score checks.

3.1 Authoritative evaluation helper policy

Implement a top-level helper with an interface equivalent to:

3.2 Exact joint projection helper

Implement a top-level helper with interface equivalent to:

- function name candidate: make_feasible
- inputs: h_raw, target, small params tolerance and max_bisection_iters
- output: h_proj in [0,1] with sum close to target, finite.

The target should be computed as n / 2.0 from the runtime length. Use a joint feasibility projection rather than clipping then rescaling repeatedly. Use the following deterministic construction.

Step A: Validate and clip.
- Convert to ndarray with float dtype. Flatten.
- If length n is 0, return a compact fallback vector of new length 48 filled with 0.5.
- Clip entries into 0,1. Replace nonfinite values with 0.5.
- If n <= 1, return either [0.5] then set the single value to target if target is in [0,1], then return.
- target = n/2.0. For target > n or target < 0, push target into [0,n] and clip. For initial problems target = n/2 perfectly feasible.

Step B: Global translation root to adjust area without destroying bounds.
Define h0 as clipped array. Solve for a scalar shift b such that

F(b) = sum_i clip(h0_i + b, 0, 1) = target.

Properties:
- F is continuous and monotone nondecreasing in b.
- Since h0_i in [0,1], F(-1)=0 and F(1)=n, and target = n/2 lies in [0,n], a root exists in [-1,1].

Use bisection with, for example, 60 iterations. At each iteration:
- mid = 0.5*(lo+hi).
- s = sum(clip(h0+mid,0,1)).
- If s < target, set lo=mid. If s >= target, set hi=mid.

After bisection set b = 0.5*(lo+hi), h1 = clip(h0 + b, 0, 1). This gives a close area, usually within floating numerical limits.

Why this is useful: shifting and then clipping can solve the summation constraint while keeping all values within [0,1]. Repeating raw clip and rescale separately is not relied on.

Step C: Final local exact compensation.
After Step B, let s = h1.sum(), residual = target - s. Implement an exact residual handling loop up to three passes:

- If residual > tolerance, add residual to entries with slack above h1. Pass through entries sorted by descending slack 1-h1_i, and consume residual or slack exactly until residual is close to zero.
- If residual < -tolerance, remove -residual from entries with above lower bound, sorted by descending h1_i, consuming residual or surface.
- Use enough sorting passes; n is expected 47 or similar small step sizes; sorting has negligible cost.
- If after passes the residual is still between a tiny error threshold and a larger threshold, choose one index i such that h1_i + residual is within [0,1] and apply. This one final compensation usually closes residual to floating precision. Prefer an index that had most slack during the previous pass.
- If magical floating residual remains, accept error if abs(sum-target) <= 1e-9. Spec final return must pass this tolerance check.

Do not set values equal to target - sum before sum using only ceil floats; compute residual freshly after any bound operations.

Step D: Feasibility assertion:
- Return finite h.
- Guarantee (0 <= h_i + tol) and (h_i <= 1 + tol) and abs(sum-target) <= 1e-9 or smaller. Internally clip final to 0,1 immediately before returning or after compensation, but never forget that simple post-clip can change sum; if clipping after residual compensation is needed, rerun a tiny residual correction event or use a local tolerance fallback.

3.5 Epigraph local solver components

All numerical derivatives are computed directly in vectorized loops inside top-level functions. Use exact same ordering for values and Jacobian.

Use helper routines with these responsibilities:

Internal correlation helper:
- horizon? for exact solver values named e.g. epigraph_correlations
- input: h length n
- output: length 2n-1

Algorithm for correlations in signed-lag row order suitable for constraints:
- Preallocate out length 2n-1.
- center_index = n-1.
- out[center_index] = dx * dot(h, 1-h).
- For d from 1 to n-1:
  - positive row index = n-1 + d.
    m_pos = dot(h[d:], 1-h[:n-d]).
    out[n-1+d] = dx*m_pos.
  - negative row index = n-1 - d.
    m_neg = dot(h[:n-d], 1-h[d:]).
    out[n-1-d] = dx*m_neg.

The exact row order is not required for objective value but must match the helper used to generate inequality constraints and their Jacobian. All lags are present. Unlike a cyclic autocorrelation, the overlap length shrinks with lag automatically because the slice lengths are n-d.

Constraint value helper:
- Signature: epigraph_constraint_value(x, args)
- args must include n maybe target not required for inequality except for M number, dx.
- Partition x into h = x[:n] and t = x[-1].
- corr = epigraph_correlations(h)
- return t - corr.

Constraint Jacobian helper:
- Signature: epigraph_constraint_jac(x,args)
- Create dense J of shape (2n-1, n+1), float64.
- If n is not sane, return all-zero, since this case is impossible for expected input.
- For square rows: start with zeros.
- Need fill derivative of corr to then negate. Possible implementation to reduce per-call overhead:

  Build corr_grad = zeros(2n-1,n).
  Center row = 1 - 2*h.
  For d=1..n-1:
    positive row (n-1+d):
      corr_grad[row, d:] += 1 - h[:-d]
      corr_grad[row, :-d] -= h[d:]
    negative row (n-1-d):
      corr_grad[row, :-d] += 1 - h[d:]
      corr_grad[row, d:] -= h[:-a] where a=d. Use h[:n-d].
  corr_grad *= dx.
  J[:, :n] = -corr_grad
  J[:, n] = 1.0

Return J.

Check dimensions: rows = 1 + (n-1)+(n-1)=2n-1; columns = n h-values plus 1 t-value.

Equality value and Jacobian helpers:
- Equality returns scalar or length-one vector sum(h) - target.
- Its Jacobian row has first n entries equal 1, last entry 0.

Objective helpers:
- Objective value returns x[-1].
- Objective gradient returns zeros followed by last entry 1.

All these must be top-level functions with arguments. Do not use lambdas. SciPy can pass args in f_args. The run function can allocate args tuple locally; that is data, not a closure function.
