Let me also try a **coordinate descent** approach as an alternative to subgradient. For each coordinate j, find the value that minimizes the max of the top few lag values. This is a 1D problem (minimize max of linear functions), which can be solved exactly.

Here's the coordinate descent step:
- For coordinate j, the value of corr[k] as a function of h[j] is:
  corr[k] = C_k + B_k * h[j] (linear in h[j])
  where C_k = corr[k] - B_k * h[j]_current (the "rest")
  and B_k = coefficient of h[j] in corr[k]

- We want to minimize max_k (C_k + B_k * t) over t ∈ [0,1]
- The optimum is where the two largest values are equal (or at a boundary)

This can be solved in O(K²) time where K is the number of active lags (by checking all pairs).

Let me implement this:

```python
def coord_step(h, corr, active_lags, n):
    """Perform one pass of coordinate descent."""
    n_pts = len(h)
    for j in range(n_pts):
        B = np.zeros(len(active_lags))
        C = np.zeros(len(active_lags))
        for idx, k in enumerate(active_lags):
            lag = k - (n_pts - 1)
            b = 0.0
            if 0 <= j + lag < n_pts:
                b += (1.0 - h[j + lag])
            if 0 <= j - lag < n_pts:
                b -= h[j - lag]
            B[idx] = b
            C[idx] = corr[k] - h[j] * b
        
        # Minimize max_k (C_k + B_k * t) over t in [0,1]
        # Candidate t: 0, 1, and intersections of pairs
        candidates = [0.0, 1.0]
        for a in range(len(active_lags)):
            for b2 in range(a+1, len(active_lags)):
                denom = B[a] - B[b2]
                if abs(denom) > 1e-12:
                    t = (C[b2] - C[a]) / denom
                    if -0.1 <= t <= 1.1:
                        candidates.append(t)
        
        best_t = h[j]
        best_val = np.max(C + B * h[j])
        for t in candidates:
            t = np.clip(t, 0.0, 1.0)
            val = np.max(C + B * t)
            if val < best_val - 1e-13:
                best_val = val
                best_t = t
        h[j] = best_t
    return h
```

This is O(n * K²) per pass, where K is the number of active lags. For n=140, K=5, that's 140*25 = 3500 operations per pass. Very fast!

The issue is that after changing h[j], the correlation values change, so C and B for subsequent coordinates are based on outdated corr values. To handle this correctly, I should recompute corr after each coordinate update, but that's O(n²) per update.

A compromise: do multiple passes over the coordinates, recomputing corr at the start of each pass. Within a pass, use the corr from the start of the pass (stale values). After the pass, check if the maximum decreased.
