3. Find `g >= 0` maximizing `sum(g)` subject to `conv(f, g)_k <= M` for all k.
4. Blend: `f_new = (1-t)*f + t*g`.
5. Repeat.

This is a valid approach because step 3 is a linear program in g. The constraint `conv(f, g)_k <= M` is linear in g (since f is fixed).

The LP has n variables and 2n-1 inequality constraints (plus n non-negativity). The constraint matrix is the Toeplitz/convolution matrix of f, which is (2n-1) × n. This is O(n^2) elements, which for n=5582 is about 31 million - too much for dense storage.

For r = 1.001: 1/ln(r) ≈ 1000.5, k* ≈ 11163 - 1000.5 ≈ 10162.5.

conv[k*] ≈ 1000 * r^{10162} = 1000 * e^{10162*0.0009995} ≈ 1000 * e^{10.157} ≈ 1000 * 25750 ≈ 25,750,000.

compare with conv[n-1] = n * r^{n-1} = 5582 * e^{5581*0.0009995} ≈ 5582 * e^{5.578} ≈ 5582 * 264.4 ≈ 1,476,000.

So the peak is at k* ≈ 10163, not at n-1. The peak value is about 25.7 million vs 1.48 million at the center.
