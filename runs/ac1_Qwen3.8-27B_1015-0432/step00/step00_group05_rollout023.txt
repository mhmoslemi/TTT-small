**Simpler approach: Direct optimization via projected gradient with FFT.**

The key challenge is that the objective `max(conv(a,a))` is non-smooth (kink at the max). But we can handle this with subgradient methods.

Let me also consider: what if I use a SOFTENED objective? Instead of `max(c)`, use `logsumexp(beta * c)` for large beta. This is smooth and approximates the max. The gradient is well-defined everywhere.

`f_beta(a) = (1/beta) * log(sum_k exp(beta * c[k]))`

Gradient: `∂f_beta/∂a[j] = sum_k p[k] * ∂c[k]/∂a[j]` where `p[k] = exp(beta*c[k]) / sum exp(beta*c[l])`.

This is a weighted average of the individual gradients, weighted by the softmax of c. For large beta, this concentrates on the max.

The computation:
1. `c = fftconvolve(a, a)` → O(n log n)
2. `p = softmax(beta * c)` → O(n)
3. Gradient: `s[j] = sum_k p[k] * 2*a[k-j]` (approximately, ignoring boundary) → this is `2 * (p * a)[j]` in some sense...

Actually, `sum_k p[k] * a[k-j]` is a weighted sum of shifted a's, which is a convolution-like operation! Specifically:
`s[j] = 2 * sum_k p[k] * a[k-j]` (for valid k-j)

This is `2 * conv(p, flip(a))[j]` approximately! Let me verify:
`conv(p, flip(a))[j] = sum_k p[k] * flip(a)[j-k] = sum_k p[k] * a[n-1-j+k]`... no, that's not quite right.

Let me just compute it directly. `s[j] = sum_k p[k] * a[k-j]` where k-j is in [0, n-1]. This is a cross-correlation of p and a!

`crosscorr(p, a)[j] = sum_k p[k] * a[k-j]`

This can be computed as `conv(p, flip(a))` with appropriate indexing, or using FFT:
`IFFT(FFT(p) * conj(FFT(a)))` gives the circular cross-correlation. For linear, we pad.
