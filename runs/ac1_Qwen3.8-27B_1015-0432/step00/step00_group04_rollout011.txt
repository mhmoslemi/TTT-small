For the self-convolution, the key is at each lag k, the sum of products a[i]*a[k-i]. The number of terms ranges from 1 (at the edges) to n (at the center). To minimize the max, we want:
- Edge values (a[0], a[n-1]) to be small (they appear in only 1-2 terms)
- Actually, a[0] appears in conv[0] = a[0]², conv[1] = a[0]*a[1], conv[2] = a[0]*a[2], etc.
- a[0] appears in n terms of the convolution (lags 0 through n-1)
- a[n/2] appears in conv lags n/2 through 3n/2-1, but with different partners

The total "exposure" of a[j] across all convolution terms is sum_k (number of times a[j] appears in conv[k]) = sum_k 1 (for each valid k-j) = n. So every element appears in exactly n convolution terms.

This means the "average" convolution value, weighted by element, is (d/d a[j]) (sum_k conv[k]) / n = d/d a[j] (sum a)² / n = 2*sum(a)/n.

So the "average contribution per element per lag" is 2*sum(a)/n / (2n-1) ≈ 2/(2n) = 1/n (for large n, with sum=1).

For a flat sequence (a[j] = 1/n): conv[k] ≈ (k+1)/n² for k < n, and (2n-1-k)/n² for k >= n. Max = 1/n (at center). Score = 2n * (1/n) = 2. ✓

To beat 2, we need the max to be < 1/n (with sum=1). The center lag has n terms, each a[i]*a[n-1-i]. For a palindrome, this is sum a[i]². By Cauchy-Schwarz, sum a[i]² >= (sum a)²/n = 1/n. So for palindromes, the center is >= 1/n, meaning we CAN'T beat 2 with palindromes!

This is a key insight: **for palindromic (symmetric) sequences, the score is >= 2, with equality iff the sequence is constant.**

So to beat 2, the sequence must be asymmetric! The center of the convolution for a non-palindrome is sum a[i]*a[n-1-i], which can be less than sum a[i]².
