2. Use FFT to compute the convolution.
3. Identify the peak lags.
4. Use a "water-filling" or "proximal gradient" approach to reduce the peaks.

For step 4, a simple approach:
- Let M = max(conv). We want to reduce all lags that are near M.
- The "gradient" of conv[k] w.r.t. a[j] is a[k-j] + a[j-k] (the two ways j can appear in the sum for lag k).
- The total gradient (summed over active lags) at position j is: sum_{k active} (a[k-j] + a[j-k]).
- Update: a[j] ← max(0, a[j] - η * grad[j]) / norm * S (to preserve sum).

The gradient can be computed efficiently:
- grad[j] = sum_{k active} a[k-j] + sum_{k active} a[j-k]
- The first term: for fixed j, sum over k in active set such that 0 <= k-j < n of a[k-j]. Let m = k-j, so k = j+m. This is sum_{m: j+m in active} a[m].
- This is a sliding window sum of a, where the window is determined by the active lags shifted by j.
- If the active lags form a contiguous block [k_min, k_max], then for position j, the valid m range is [max(0, k_min-j), min(n-1, k_max-j)].
- This is a sliding window sum, computable in O(n) with a prefix sum!

Similarly for the second term.

So the algorithm is O(n) per iteration (plus O(n log n) for the FFT to compute conv).
