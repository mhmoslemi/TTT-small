Actually, let me reconsider the problem from scratch. The "previous state of the art" uses an LP-based approach:
- Given f, find g ≥ 0 with ||f*g||∞ ≤ M (where M = ||f*f||∞) that maximizes sum(g).
- Then blend f and g.

The key insight is that g is found by LINEAR programming (not quadratic), because the constraint f*g is LINEAR in g (f is fixed). This makes it a much easier optimization than the original QP.

The LP is:
maximize sum(g)
subject to: (f*g)[k] ≤ M for all k = 0,...,2n-2
g ≥ 0

where (f*g)[k] = sum_i f[i]*g[k-i].

This is a linear program with n variables and 2n-1 constraints. The constraint matrix is the Toeplitz matrix of f, which is sparse (each row has at most n nonzeros, but really it's a banded structure).

For n=6733: 6733 variables, 13465 constraints. This is a large but solvable LP!

The constraint matrix T has T[k,i] = f[k-i] (if 0 ≤ k-i < n, else 0). This is a Toeplitz matrix. We can apply it to a vector in O(n²) time, or O(n log n) with FFT.

For the dual:
minimize M * sum(λ_k)
subject to: sum_k λ_k * T[k,:] ≥ 1 (i.e., (T^T λ)[i] ≥ 1 for all i)
λ ≥ 0

The dual has 2n-1 = 13465 variables and n = 6733 constraints.

This is a large LP but could be solved with scipy.optimize.linprog (using the HiGHS solver) or a custom simplex/interior-point method.

But the constraint matrix is 13465 × 6733 ≈ 91 million entries, which is about 730 MB as float64. That's too large to store densely!

However, we can apply the matrix (and its transpose) to a vector in O(n²) time (or O(n log n) with FFT) without storing it. So we can use a matrix-free solver.

scipy.optimize.linprog with method='highs' can handle sparse matrices. But constructing a sparse representation of the Toeplitz matrix requires about 2n² nonzeros in the worst case (since each row has O(n) nonzeros), which is about 91 million. That's too many for a sparse matrix too.

Alternative: use the FFT to apply the convolution matrix to a vector. The (k)-th row of T is the convolution kernel f shifted to position k. Applying T to a vector g gives:
(Tg)[k] = sum_i f[k-i]*g[i] = (f*g)[k]

So Tg = convolve(f, g)! We can compute this in O(n log n) with FFT.

Similarly, T^T applied to a vector λ:
(T^T λ)[i] = sum_k λ[k]*f[k-i]

This is the cross-correlation of λ and f, which can also be computed in O(n log n) with FFT.

So we can write a matrix-free LP solver that uses FFT for matrix-vector products. But scipy's linprog doesn't support matrix-free operations directly.
