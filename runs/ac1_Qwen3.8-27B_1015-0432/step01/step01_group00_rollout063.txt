def fft_conv(a, b):
    n, m = len(a), len(b)
    size = 1 << (n + m - 2).bit_length()
    return np.fft.irfft(np.fft.rfft(a, size) * np.fft.rfft(b, size))[:n + m - 1]

def fast_score(f):
    s = f.sum()
    if s < 1e-15:
        return np.inf
    b = fft_conv(f, f)
    return float(2 * len(f) * b.max() / (s * s))

    inits = []
    # Parent

    inits.append(np.ones(n))
    
    # Exponential (right-heavy)
    x = np.arange(n)
    inits.append(np.exp(-x / (n/4)))
    
    # Exponential (left-heavy)
    inits.append(np.exp(-x / (n/4))[::-1])

    inits.append(1.0 / d**0.5)
    inits.append(1.0 / d**1.0)

        inits.append(u)

    n = f.size
    b = fft_conv(f, f)
    M = b.max()
    if M < 1e-30:
        return f, b, M
    
    w = np.exp(beta * b / M)

When k is even, f[k/2]*f[k/2] = f[k/2]² appears in the sum (once, at i=k/2).
When k is odd, no such middle term.

So: c_k = 2*f[0]*f[k] + sum_{i=1}^{k-1} f[i]*f[k-i]

Setting c_k = C:
f[k] = (C - sum_{i=1}^{k-1} f[i]*f[k-i]) / (2*f[0])

This is the simplest form. The inner sum is O(k), and the total is O(n²). For n=4806, that's about 11.5M operations. In Python, this would be slow (maybe 5-10 seconds). I can speed it up with numpy:

```python
def make_flat_auto(n, C=1.0):
    f = np.zeros(n)
    f[0] = np.sqrt(C)
    for k in range(1, n):
        # Compute sum_{i=1}^{k-1} f[i]*f[k-i]
        # This is the (k)-th element of conv(f[0:k], f[0:k]) minus f[0]*f[k] and f[k]*f[0]
        # But we don't have f[k] yet. So:
        # sum_{i=1}^{k-1} f[i]*f[k-i] = conv(f[0:k], f[0:k])[k] - f[0]*f[k] - f[k]*f[0]
        # But f[k] is unknown. So:
        # sum_{i=1}^{k-1} f[i]*f[k-i] = conv(f[1:k], f[1:k])... no, that's not right either.
        
        # Simplest: just compute the sum directly
        if k == 1:
            sq = 0.0
        else:
            sq = np.dot(f[1:k], f[k-1:0:-1])  # f[1]*f[k-1] + f[2]*f[k-2] + ... + f[k-1]*f[1]
        f[k] = max((C - sq) / (2 * f[0]), 0.0)
    return f
```

The `np.dot(f[1:k], f[k-1:0:-1])` computes sum_{i=1}^{k-1} f[i]*f[k-i]. This is O(k) per iteration, O(n²) total. In numpy, each dot product is fast (C-optimized), so the total time is dominated by the Python loop overhead: n iterations, each with O(1) Python overhead + O(k) C computation. For n=4806, this is about 4806 iterations, each taking maybe 1-5 microseconds for the dot product (for small k) up to 100 microseconds (for k=4805). Total: maybe 50-200ms. That's fine.
