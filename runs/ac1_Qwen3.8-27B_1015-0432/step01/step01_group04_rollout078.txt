Hmm wait, I realize there might be an issue with my gradient formula. Let me re-derive it for the softmax parametrization.

Score = 2n * M where M = max_k c[k], c = conv(a,a), a = softmax(y) (sum = 1).

For a specific lag k (where c[k] = M):
dM/da[i] = d c[k]/da[i] = 2*a[k-i] (for valid k-i) [as derived earlier]

Now, da[i]/dy[j] = a[i]*(δ_{ij} - a[j])

dM/dy[j] = sum_i (dM/da[i]) * (da[i]/dy[j])
= sum_i 2*a[k-i]*a[i]*(δ_{ij} - a[j])
= 2*a[k-j]*a[j] - a[j]*sum_i 2*a[k-i]*a[i]
= 2*a[j]*(a[k-j] - sum_i a[i]*a[k-i])
= 2*a[j]*(a[k-j] - c[k])
= 2*a[j]*(a[k-j] - M)

So d(score)/dy[j] = 2n * 2 * a[j] * (a[k-j] - M) = 4n * a[j] * (a[k-j] - M)

For top-m lags with equal weight:
d(score)/dy[j] ≈ (2n/m) * sum_{k in top-m} 2*a[j]*(a[k-j] - c[k])
= (4n/m) * a[j] * (sum_k a[k-j]/m - sum_k c[k]/m)

This is what I had. Good.

But wait, I should be careful: when I write `a[k-j]`, this means the element of `a` at index `k-j`, which is only valid if `0 <= k-j < n`. Otherwise it's 0. That's what my `partner_vec` function does.

Let me verify the gradient direction makes sense. If a[j] is the element at position j, and a[k-j] is its "partner" for lag k:
- If a[k-j] > M (= c[k] = sum_i a[i]*a[k-i]), then the product a[j]*a[k-j] is "above average" for this lag, so we want to DECREASE a[j]. The gradient is positive (4n*a[j]*(a[k-j]-M) > 0), and since we do y -= lr*gy, we decrease y[j], which decreases a[j]. ✓
- If a[k-j] < M, we want to increase a[j]. Gradient is negative, y increases. ✓

But wait, M is the MAX of the convolution, and c[k] = M for the peak lag. The "average" of a[k-i] weighted by a[i] is c[k]/sum(a) = c[k] = M. So a[k-j] - M is the deviation from the weighted average. This makes sense: we're trying to make the "partner products" more even.

Actually, I realize there's a subtlety. We're minimizing the MAX, not a specific lag. The gradient I computed is the subgradient of the max (picking one active constraint). This is valid for convex optimization, but our problem is NOT convex (the max of convolutions is not convex in a). Still, using the subgradient at the active constraint is a reasonable heuristic.

The issue is that the active constraint (argmax lag) can change during optimization, causing the gradient to jump. Using top-m lags smooths this out.
