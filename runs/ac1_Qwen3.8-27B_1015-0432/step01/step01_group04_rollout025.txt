One key issue: the gradient in log-space `g[j] = 2*a[j]*(a[k*-j] - c[k*])` only considers the single peak lag. If there are multiple peaks, we should consider them all.

Actually, for the score `2n*max(c)/s^2`, only the single max matters. But in practice, reducing the max might create a new max at a different lag, causing oscillation.

A better approach: consider the top-K peaks and average the gradients.

Another approach: instead of just the peak, use the "excess" over the mean:
g[j] = 2*a[j] * (ar[j] - c_mean)

This pushes to flatten c, not just reduce the peak.

Actually, let me think about this more carefully. The objective is max(c), which is non-smooth. A common approach is to use a smooth approximation:

f_smooth(a) = (1/beta) * log(sum_k exp(beta * c[k]))

as beta → ∞, this approaches max_k c[k]. The gradient is:
∂f_smooth/∂a[i] = sum_k p[k] * 2*a[k-i]

where p[k] = exp(beta*c[k]) / sum_j exp(beta*c[j]).

This gives a weighted average of gradients at all lags, weighted by "how close to the max" each lag is. This is much smoother and avoids the oscillation problem.

In log-space:
∂f_smooth/∂y[j] = 2*a[j] * sum_k p[k]*a[k-j] - 2*a[j] * sum_k p[k]*c[k]

The second term is 2*a[j]*E_p[c]. The first term is 2*a[j] * (conv(a, p_reversed_shifted))[j].

This can be computed with FFT! Let me implement this.

The computational cost:
- Compute p from c: O(n)
- Compute conv(a, p_rev): O(N log N) via FFT
- Total per iteration: O(N log N)

This is the same cost as before, but with a much better gradient signal.
