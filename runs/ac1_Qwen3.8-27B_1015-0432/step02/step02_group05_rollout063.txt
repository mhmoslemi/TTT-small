Actually, one more idea: instead of just top-k peaks, I could use the "k/m ratio" from signal processing. In the autocorrelative, the "side lobes" are what we want to minimize. Let me think about what the "right" scale for eta is one more time.

The update is: a_new[i] = a[i] * exp(-eta * g[i])

The log-update is: log(a_new[i]) - log(a[i]) = -eta * g[i]

For this to be a meaningful step (changing log(a) by O(1)), we need eta * g[i] ~ 1.

g[i] = sum_{k in topk} w_k * 2 * a[k-i]

For a normalized sequence (sum a = 1), a[k-i] ~ 1/n on average.
g[i] ~ 2/n * sum w_k = 2/n (since sum w = 1)

So eta ~ n/2 for O(1) log-changes. For smaller changes, eta ~ n * 0.01 to n * 0.1.

The previous code uses eta0 = n * es where es is 0.05-0.08. So eta ~ 0.05n to 0.08n. That gives log-changes of O(0.05 to 0.08), which is a ~5-8% change per step. Reasonable.

I'll use eta = n * 0.06 * decay, with decay starting at 1 and going down.
