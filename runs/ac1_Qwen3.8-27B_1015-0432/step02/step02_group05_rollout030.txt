Let me also think about a completely different approach: **alternating projection**.

The problem is: minimize max_k cv_k subject to a >= 0, sum(a) = 1.

This can be seen as finding the point in the simplex {a >= 0, sum(a) = 1} that minimizes the max correlation. We can use a bisection approach:
- For a given M, check if there exists a >= 0, sum(a) = 1, with (a*a)_k <= M for all k.
- This is a feasibility problem (convex in a? No, (a*a)_k is quadratic in a, not linear).

So bisection doesn't directly work. But we can use it as a heuristic: start with a feasible M and try to reduce it.

Another approach: **Frank-Wolfe (conditional gradient) method**. The constraint set is the simplex. At each iteration:
1. Compute the gradient of the objective (max correlation) at the current point.
2. Find the vertex of the simplex that minimizes the linear approximation.
3. Move toward that vertex.

But the "vertex" that minimizes the linear approximation is just one coordinate set to 1 and the rest 0, which is not useful.

What about **projected gradient** with a projection onto the simplex? The projection of x onto {a >= 0, sum(a) = 1} is: a_i = max(x_i - τ, 0) where τ is chosen so that sum(a) = 1. This is O(n log n).

The gradient of max_k cv_k at a is: for the active set S = {k : cv_k = max}, the gradient is (1/|S|) * sum_{k in S} grad_cv_k where grad_cv_k[j] = a_{k-j} (for valid j).

So: `gradient[j] = (1/|S|) * sum_{k in S} a[max(0,k-n+1) : min(n-1,k)][reversed or not]`

This is what the top-k code does, but with the full active set instead of top-k.

Let me try a **projected gradient in log-space** approach:
- Work with u = log(a) (infinite for a=0, but in practice clip)
- Gradient step: u -= lr * grad_in_log_space
- Project back to simplex: a = exp(u) / sum(exp(u))

The gradient in log-space of max_k cv_k:
- d(max_k cv_k)/du_j = a_j * (d cv_k / da_j) = a_j * a_{k-j} (for active k)
- So grad_log[j] = a_j * sum_{k in S} a_{k-j} / |S|

This is slightly different from the original-space gradient (multiplied by a_j). In the multiplicative update, this corresponds to `a_j *= exp(-lr * a_j * g_j)` which is a "self-damped" update.

Actually, the multiplicative update `a *= exp(-lr * g)` where g is the original-space gradient is equivalent to:
- In log-space: u_new = u_old - lr * g
- Then a_new = exp(u_new) / sum(exp(u_new))

So it's already log-space gradient with a specific normalization.

Let me try adding **Nesterov momentum** to the log-space update:
- v = beta * v - lr * g  (velocity)
- u = u + v  (messy position)
- a = exp(u) / sum(exp(u))

Or more simply:
- g_avg = alpha * g_avg + (1-alpha) * g  (exponential moving average of gradient)
- a *= exp(-lr * g_avg)

This is what the previous code does with `gavg = 0.85 * gavg + 0.15 * g`.

Actually, here's a cleaner idea for the "dual" step:
- The LP: max sum(g) s.t. g >= 0, (a*g)_k <= M
- This is equivalent to: max c^T g s.t. T(a) g <= M*1, g >= 0 where T(a) is the Toeplitz matrix

The dual has 2n-1 variables (y) and n constraints. The primal has n variables and 2n-1 constraints.

def fft_conv(a, fsz):
    fa = np.fft.rfft(a, n=fsz)
    return np.fft.irfft(fa * fa, n=fsz)

    n = a.size
