f(c*a) = 2n * max(conv(c*a)) / (sum(c*a))^2 = 2n * c^2 * max(conv(a)) / (c*sum(a))^2 = f(a).

So the scale doesn't matter. We can fix S = sqrt(2n) without loss of generality. If we fix S, then the objective simplifies to max(conv(a)), and the gradient is just 2*r[m] (no second term).

But L-BFGS-B optimizes in the unconstrained (well, box-constrained) space. If we fix S, we'd need to project onto the simplex. That's more complex.

Alternative: optimize f(a) directly with the correct gradient (including the 1/S^2 term). The optimizer will naturally find the right scale.

OR: we can parameterize a = S * w where sum(w) = 1, and optimize over w. But that changes the problem.

I think the cleanest approach is:
1. Use the correct gradient for f(a) = 2n * smax(conv(a), tau) / S(a)^2.
2. After each L-BFGS-B call, normalize to S = sqrt(2n).
3. During the L-BFGS-B call, the gradient accounts for the changing S.

Let me write the corrected gradient:
```python
def _grad(a, tau):
    n = a.size
    S = a.sum()
    if S < 1e-8:
        return np.zeros(n)
    c = _conv(a)
    mv, p = _smax(c, tau)
    pr = p[::-1]
    L = _fpow2(3 * n)
    cv = ifft(fft(a, L) * fft(pr, L)).real
    g = 2.0 * cv[n - 1:2 * n - 1][::-1]  # This is 2*r[m], the grad of smax
    return (2.0 * n / (S * S)) * g - (4.0 * n * mv / (S ** 3)) * a
```

The key fix is the `* a` at the end.

Now, let me also think about whether there's a smarter approach than L-BFGS-B.

For very large n (6733), L-BFGS-B with 500 iterations might be slow. Each function/gradient evaluation involves an FFT of size ~2n or 3n, which is O(n log n). With 500 iterations and maybe 30 line search evals each, that's 15000 FFTs of size ~20000. Each FFT takes maybe 1ms, so 15 seconds per tau value. With 12 tau values, that's 180 seconds. Should fit in budget.

Actually, for n=6733, 3n ≈ 20000, FFT of size 32768 (next power of 2) takes about 0.5ms in NumPy. So 15000 * 0.5ms = 7.5 seconds per tau. 12 taus = 90 seconds. Fine.

Let me also add a "direct subgradient" step for the non-smooth max:
- Compute actual conv(a)
- Find the top few positions
- Take a step in the direction that reduces those peaks

And a "coordinate descent" on the active set:
- For the position k* where conv is max, the gradient of conv(a,a)[k*] w.r.t. a is 2*a (shifted). We can try to reduce this by adjusting a.
