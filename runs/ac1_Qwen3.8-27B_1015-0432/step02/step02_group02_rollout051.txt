Actually, for the 1D search, I don't need to recompute the full convolution. I just need to:
1. Start with current conv
2. For a trial value of a_i, update conv: conv[k] += (new_a_i - old_a_i) * r[k] for all k≠2i, and conv[2i] = conv_b[2i] + new_a_i^2
3. Find max(conv)
4. Compute objective

But updating conv in O(n) per trial and doing ~20 trials per coordinate means 20*n per coordinate, and n coordinates total: 20*n^2 per pass. For n=6733: 20*45M = 900M operations per pass. At ~1ns/op, that's ~1 second per pass. 3 passes = 3 seconds. Fine!

But actually, I can be smarter. Instead of updating the full conv array, I can compute:
max_k (conv_b[k] + r[k] * a_i) for k ≠ 2i, and conv_b[2i] + a_i^2

This is: max(max_k≠2i (conv_b[k] + r[k] * a_i), conv_b[2i] + a_i^2)

For the linear part, this is the max of (2n-2) lines in a_i, plus one parabola. I can evaluate this in O(n) by just computing the vector conv_b + r*a_i (excluding index 2i) and taking its max, then comparing with conv_b[2i]+a_i^2.
