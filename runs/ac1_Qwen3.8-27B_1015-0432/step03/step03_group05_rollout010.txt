import time

def fft_conv(a, b):
    n, m = len(a), len(b)
    sz = 1 << (n + m - 2).bit_length()
    return np.fft.irfft(np.fft.rfft(a, sz) * np.fft.rfft(b, sz))[:n + m - 1]

    L = 2 * n - 1
    h = np.zeros(L)
    h[peaks] = 1.0
    c = fft_conv(f, h[::-1])
    return 2.0 * c[n - 1:2 * n - 1][::-1]

    b = fft_conv(f, f)
    s = f.sum()
    if s < 0.01:
        return np.inf
    return 2.0 * f.size * b.max() / (s * s)

Actually, let me think about what "deflation" means here. If the peak is at convolution lag p, then b[p] = sum_i a[i]*a[p-i]. To reduce b[p] without reducing sum(a) too much, we want to redistribute mass: reduce a[i] where a[p-i] is large, and increase a[j] where a[p-j] is small.

But this is exactly what the multiplicative gradient does! So maybe the issue is just the learning rate and peak selection.

Let me try a different approach for the gradient: instead of using a fixed number of peaks, use a "soft" assignment:
g[i] = 2 * sum_p w[p] * a[p-i] / max_p(w[p]*b[p])

where w[p] = exp(b[p]/T) for a temperature T. This gives a smooth gradient that focuses on the peak but isn't as sharp.

Actually, for the score 2n*max_b/sum², the subgradient of max_b with respect to a[i] is:
- If unique peak at p*: 2*a[p*-i]
- If multiple peaks: any convex combination of {2*a[p-i] : p ∈ argmax}

The parent uses a uniform average over peaks within a threshold, which is a valid subgradient. The "soft" version with exp(b[p]/T) is not a valid subgradient of max, but it might work as a heuristic.

Key insight for improvement: the parent caps peaks at 600. For n=4806, the convolution has 9611 elements. Having 600 peaks is a lot. The true argmax might be just 1-5 points. Using too many "near-peak" points dilutes the gradient.

def fft_conv(a, b):
    n, m = len(a), len(b)
    sz = 1 << (n + m - 2).bit_length()
    return np.fft.irfft(np.fft.rfft(a, sz) * np.fft.rfft(b, sz))[:n + m - 1]

def subgrad(f, peaks):
    n = f.shape[0]
    L = 2 * n - 1
    h = np.zeros(L)
    h[peaks] = 1.0
    c = fft_conv(f, h[::-1])
    return 2.0 * c[n - 1:2 * n - 1][::-1]

    b = fft_conv(f, f)
    s = f.sum()
    if s < 1e-15:

    return 2.0 * f.size * b.max() / (s * s)
