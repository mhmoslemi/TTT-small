3. **Direct peak reduction**: After the main optimization, identify the top 3-5 peaks and do a targeted optimization to reduce them specifically.

4. **Better learning rate**: Use a backtracking line search instead of a fixed decay.

Let me implement a weighted subgradient approach:

```python
def weighted_subgrad(f, b, thresh):
    n = f.shape[0]
    L = 2 * n - 1
    M = b.max()
    w = np.maximum(b / M - thresh, 0)  # weight proportional to how far above threshold
    if w.sum() < 1e-30:
        # fallback to top peak
        pk = np.argmax(b)
        w = np.zeros(L)
        w[pk] = 1
    h = w / w.sum()  # normalize weights
    c = fft_conv(f, h[::-1])
    return 2.0 * c[n - 1:2 * n - 1][::-1]
```

This gives a smoother gradient that considers all lags above the threshold, weighted by their values.

```python
import numpy as np
import time

def fft_conv(a, b):
    n, m = len(a), len(b)
    sz = 1 << (n + m - 2).bit_length()
    return np.fft.irfft(np.fft.rfft(a, sz) * np.fft.rfft(b, sz))[:n + m - 1]

def score(f):
    b = fft_conv(f, f)
    s = f.sum()
    return 2.0 * f.size * b.max() / (s * s)

def subgrad_weighted(f, b, frac):

        w /= ws

    c = fft_conv(f, h[::-1])
    return 2.0 * c[n - 1:2 * n - 1][::-1]
```

Wait, I realize there might be an issue with the weighted subgradient. The subgradient of max should be a convex combination of the subgradients at the maximizing points. If I use all points above a threshold with weights proportional to their values, I'm computing a weighted average of subgradients, which is still a valid subgradient of the max function (as long as the weights are non-negative and sum to 1).

Actually, the subgradient of max_k b_k is the convex hull of {e_k : k in argmax}. A weighted average of subgradients at non-peak points is NOT a valid subgradient of the max function. It IS a valid subgradient of a smoothed approximation like log-sum-exp.

So using weights on non-peak points gives a smoothed gradient, which is actually good for optimization (smoother landscape, less oscillation). It's like optimizing a smoothed version of the max, which converges to the same optimum but with better numerics.

Let me refine the approach:

```python
def smooth_grad(f, b, tau):
    """Compute smoothed gradient using softmax weights."""
    n = f.shape[0]
    L = 2 * n - 1
    # Softmax weights (log-sum-exp smoothing)
    w = np.exp(b / tau - b.max() / tau)
    w /= w.sum()
    c = fft_conv(f, w[::-1])
    return 2.0 * c[n - 1:2 * n - 1][::-1]
```

With tau small, this approaches the true subgradient at the peak. With tau large, it's smoother. We can anneal tau from large to small.

But computing exp(b/tau) for all 2n-1 elements might overflow. We can use the log-sum-exp trick:
w = exp((b - b.max()) / tau)
w /= w.sum()

This is safe since (b - b.max()) <= 0.
