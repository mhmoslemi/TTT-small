A potentially better approach: use the "LP subproblem" more explicitly.

Given the current f and its max M = max(f*f), the LP:
max sum(g) s.t. (f*g)_k <= M for all k, g >= 0

The optimal g, when rescaled to sum=1, gives the next iterate. This is the "mirror" of the gradient step.

To solve this LP without a dense matrix, I can use:
1. Bisection on a parameter: find the largest c such that the feasible set {g: sum(g)=1, g>=0, (f*g)_k <= c for all k} is nonempty. At the solution, the active constraints determine g.
2. Or: use the dual. The dual is min c * sum(y) s.t. A^T y >= 1, y >= 0. At optimum, y is determined by the active constraints.

Let me try a different angle: the "subgradient" of the max is only defined at the argmax. Near the optimum, the argmax set might be small (just a few points). In that case, the subgradient is:
g_i = 2 * sum_{k in argmax} f_{k-i}

And the multiplicative update is:
f_i *= exp(-eta * g_i)

This is what we're already doing. The issue is that when the argmax shifts, the update direction changes abruptly.

A smoother approach: use the "log-sum-exp" smoothing:
h(f) = log(sum_k exp(beta * (f*f)_k / M))
This is a smooth approximation to max, and its gradient is well-defined everywhere.

The gradient of h w.r.t. f_i:
= sum_k [beta * f_{k-i} / M * exp(beta * (f*f)_k / M)] / sum_j exp(beta * (f*f)_j / M)

This is a weighted average of f_{k-i} over all k, with weights proportional to exp(beta * b_k / M).

For large beta, this concentrates on the max (recovering the subgradient). For small beta, it's smoother.

This could be more stable! Let me implement this:

def smooth_subgrad(f, beta, M):
