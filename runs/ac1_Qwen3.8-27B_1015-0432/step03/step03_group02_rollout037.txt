The key question: what's limiting the previous program? Is it:
(a) The optimization is converging slowly (need better step sizes or direction)?

Let me think about a different approach for the final fine-tuning:

**Coordinate descent in log-space**: For each coordinate i, find the optimal f_i that minimizes the score, holding all other coordinates fixed. This can be done analytically for a fixed active set.

If the active set is fixed (the indices k where c[k] = M), then:
score = 2n * max_k c[k] / S²

For a specific k: c[k] = sum_i f[i] * f[k-i]
Changing f[i] affects c[k] for k in [i, i+n-1] (specifically, c[k] += delta * f[k-i] for the active k).

This is complex but doable for a small active set.

Actually, let me think about a simpler but effective improvement: **deterministic annealing** combined with the multiplicative update.

Instead of random restarts, gradually reduce the temperature of the multiplicative update:
f <- f * exp(-eta * g / gmax) * (1 + temp * noise)

Where temp decreases over time.

Or better: use a **deterministic perturbation** based on the gradient of the smooth approximation of the max.

The smooth max: M_smooth(T) = T * log(sum_k exp(c[k]/T))
This is a smooth approximation of max(c) that becomes exact as T -> 0.

The gradient of M_smooth is:
∂M_smooth/∂f_i = (1/S_k) * sum_k exp(c[k]/T) * f[k-i]
where S_k = sum_k exp(c[k]/T)

This gives a smooth gradient direction that we can use instead of the hard active set.

Let me implement this:

```python
def optimize_smooth(f, deadline, rng, T_init=0.01, T_end=0.0001, eta_init=0.10):

        b_shifted = (b - M) / T

        w_sum = w.sum()
        w /= w_sum
        # Gradient: g[i] = sum_k w[k] * f[k-i] (shifted to position i)

        np.maximum(g, 0.0, out=g)
        gmax = g.max()
        if gmax < 1e-30:
```

This smooth approach might be better because:
1. It uses all convolution values (weighted by softmax) instead of a hard active set
2. It's more stable (no discontinuities in the gradient)
3. The temperature annealing provides a natural exploration->exploitation schedule

But computing the softmax over 2n-1 = 9611 values at each iteration might be slower. Let me check: exp of 9611 values, sum, divide - this is O(n) and very fast. The FFT is the bottleneck anyway.

Actually, the issue with the smooth approach is that with T very small, the softmax becomes effectively a hard active set (only the max index has weight ~1). With T large, it's more uniform. The annealing schedule controls this.

Let me also think about a hybrid approach: use the smooth gradient for the main optimization, then switch to the hard active set for the final refinement.

Let me also consider: the previous program's `run_opt` function computes `g` as the convolution of f with the active set indicator, then takes `g[n-1:2n-1][::-1]`. This is the gradient of the max at the active indices. The smooth version replaces the hard indicator with softmax weights.

```python
def fft_conv(a, b):
    n, m = len(a), len(b)
    size = 1 << (n + m - 2).bit_length()
    return np.fft.irfft(np.fft.rfft(a, size) * np.fft.rfft(b, size))[:n + m - 1]

    return 2.0 * len(f) * b.max() / (s * s)
```
