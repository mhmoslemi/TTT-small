The key observation: We want to minimize max(a*a) subject to a >= 0, sum(a) = 1 (WLOG).

This is equivalent to: find a >= 0, sum(a) = 1, such that a*a(k) <= M for all k, minimizing M.

For a fixed M, this is a feasibility problem (or: maximize sum(a) subject to a>=0 and a*a <= M). This is a non-convex problem in general (the constraint a*a <= M involves products of variables).

However, if we fix some variables and optimize others, it becomes linear (each constraint a*a(k) <= M is bilinear, but if one "side" is fixed, it's linear in the other).

This is the approach of the "state of the art" mentioned:
- Fix a, solve for g: maximize sum(g) subject to g >= 0, a*g <= M
- Rescale g
- Update a = (1-t)*a + t*g

This is a block-coordinate descent! At each step:
1. Given a, solve a linear program for g (this IS linear because a is fixed)
2. Rescale and mix

The LP is: max sum(g) s.t. (a*g)(k) <= M for k=0,...,2n-2, g >= 0.
The matrix a*g is Toeplitz (or rather, the convolution matrix is Toeplitz), so this is a linear program with O(n^2) constraints and O(n) variables.

For n=6733, that's ~45 million constraints. That's a lot for an LP solver. But the constraint matrix has a special structure (Toeplitz) that might be exploitable.

Actually, the constraint matrix for the LP is:

Actually, let me think about a simpler approach: projected gradient descent on the LP.

Given a (fixed), we want to maximize sum(g) subject to (a*g)(k) <= M, g >= 0.

This is equivalent to: g = argmax sum(g) s.t. T@g <= M, g >= 0, where T is the Toeplitz matrix.

The Lagrangian: L = sum(g) - sum_k lambda_k ((a*g)(k) - M) - sum_j mu_j * g[j]
KKT: 1 - T^T @ lambda - mu = 0, mu >= 0, g >= 0, lambda >= 0, lambda_k * ((a*g)(k) - M) = 0

We can solve this with a simple iteration:
- Start with g = ones
- Iterate: g = proj_{g>=0}(g + eta * (1 - T^T @ lambda))
- Update lambda_k = max(0, lambda_k + eta * ((a*g)(k) - M))

But T^T @ lambda = (a_reversed * lambda) which is a convolution, computable in O(n log n)!

This is essentially a projected gradient / ADMM-style approach for the LP. Let me formalize:

Given a (fixed), M = max(a*a):
- Initialize g = ones(n)
- Initialize lambda = zeros(2n-1)
- Iterate:
  - Compute T^T @ lambda = convolution of a_reversed with lambda (padded)
  - g = max(0, g + eta * (1 - T^T @ lambda))
  - Compute T @ g = convolution of a with g
  - lambda = max(0, lambda + eta * (T@g - M))
  
This is O(n log n) per iteration due to the FFT convolutions.

Then: rescale g to have sum = sum(a), mix: a_new = (1-t)*a + t*g.

This is a valid approach! And it's matrix-free.
