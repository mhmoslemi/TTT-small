But Q_k here has both positive and negative entries in general... actually no, Q_k for the convolution has only nonnegative diagonal and the form is Σ_i a[i]a[k-i] which is not a standard quadratic form x^T Q x.

Actually, c_k = Σ_{i: 0≤i≤n-1, 0≤k-i≤n-1} a_i · a_{k-i}. If we write this as a^T Q_k a / 2 + (diagonal correction), it's a quadratic form. But Q_k is not in general PSD.

So the problem is nonconvex in general. The L-BFGS-B approach with softmax is appropriate.

import numpy as np
import time
from scipy.optimize import minimize
from numpy.fft import fft, ifft

def _fpow2(s):
    m = 1
    while m < s:
        m <<= 1
    return m

def _conv(a):
    n = a.size
    L = _fpow2(2*n - 1)
    fa = fft(a, L)
    return ifft(fa*fa).real[:2*n-1]

def _smax(c, tau):
    cm = c.max()
    d = (c - cm)/tau
    np.maximum(d, -50.0, out=d)
    e = np.exp(d)
    s = e.sum()
    return cm + tau*np.log(s), e/s

def _obj(a, tau):
    S = a.sum()
    if S < 1e-8:
        return 1e10
    mv, _ = _smax(_conv(a), tau)
    return 2.0*a.size*mv/(S*S)

def _grad(a, tau):
    n = a.size
    S = a.sum()
    c = _conv(a)
    mv, p = _smax(c, tau)
    pr = p[::-1]
    L = _fpow2(3*n - 2)
    cv = ifft(fft(a, L)*fft(pr, L)).real
    g = 2.0*cv[n-1:2*n-1][::-1]
    return (2.0*n/(S*S))*g - (4.0*n*mv/(S**3))

def _eval(a):
    return float(evaluate_sequence(a.tolist()))

    a0 = par/par.sum()*sc
    
    best = a0.copy()
    best_sc = [_eval(best)]
    cur = a0.copy()
    
    bl = [(0.0, 1000.0)]*n
    
    # Multi-phase L-BFGS-B
    phases = [

        (0.1, 600), (0.05, 600), (0.02, 700), (0.01, 700),
        (0.005, 800), (0.002, 800), (0.001, 1000), (0.0005, 1000),

    for tv, iters in phases:

            nx = np.clip(res.x, 0.0, 1000.0)
            if nx.sum() > 0.01:
                s2 = _eval(nx)
                if np.isfinite(s2) and s2 < best_sc[0]:
                    best_sc[0] = s2
                    best = nx.copy()
            cur = nx.copy()
        except Exception:
            pass

    if time.monotonic() < dl - 30:
        improved_any = True
        while improved_any and time.monotonic() < dl - 30:

            c = _conv(cur)
            top_k = 8

            for jp in reversed(idx):

                    break

                hi = min(n-1, jp)
                ks = np.arange(lo, hi+1)

        s = int(rng.integers(0, n-nw))

    b2 = best.copy()

Ideas for improvement:
1. Use a tighter tau schedule (more iterations at very small tau).
2. After L-BFGS-B converges, do a "peeling" step that specifically targets the argmax of the convolution.
3. Try a different parametrization: instead of optimizing a directly, optimize the "log" of the positive entries.
4. Use the convex structure: the objective is a ratio of a convex function (max of linear conv) to a convex function (sum²). This is a fractional program but with homogeneous numerator and denominator.

Actually, I realize there might be an issue with the softmax approximation. When tau is very small (like 0.001), the softmax essentially picks out the single maximum element. The gradient then only has support on the elements that contribute to that single maximum. This means the optimizer can't "see" the other near-maximum elements and might get stuck.

A better approach might be to use a "folding" strategy: at each step, identify the top few convolution peaks and try to reduce them simultaneously.

Let me also consider: what if I try a completely different initialization? Instead of starting from the parent, what if I try:
- A cosine bump: a[i] = cos(π*i/(n-1)) for i in [0, n-1] (nonnegative since cos goes from 1 to 0).
- A Gaussian: a[i] = exp(-((i-n/2)/(n/4))²).
- A Fejér window: a[i] = (n-1-|i-(n-1)/2|)/(n/2) (triangular).

These might give different starting points that lead to different local optima.

Actually, let me think about what the optimal shape should be. The parent has a score of 1.513, which is well below 2. This suggests a very non-uniform shape.

For the convolution max to be small relative to S², we need the sequence to "spread out" the autocorrelation. This is similar to the "Sidelobe suppression" problem in radar.

A key insight: if a is "two-sided" (high at both ends, low in the middle), then the convolution at the center (k = n-1) involves products of high×low, which are small. But the convolution at the edges (k near 0 or 2n-2) involves products of high×high, which are large.

If a is "centered" (high in the middle, low at edges), then the convolution at the center involves high×high (large), but at the edges involves low×low (small). The max is at the center.

The optimal shape might be something in between, where the convolution is as flat as possible.
