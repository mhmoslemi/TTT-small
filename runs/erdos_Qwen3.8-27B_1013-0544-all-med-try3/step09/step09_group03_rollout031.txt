- Generate candidate moves: for each i where h[i]=1 and h[i+k*]=0 (or vice versa for negative shifts), consider swapping h[i] with h[i+k*] (if h[i+k*]=0)
- Actually, a swap means: set h[i]=0, h[j]=1 for some j where h[j]=0
- The best swap for shift k* is to find i with h[i]=1, h[i+k*]=0, and set h[i]=0, and find j with h[j]=0, h[j+k*]=1, and set h[j]=1
- But we need a single swap (one position changes from 1 to 0, one from 0 to 1)
- So: pick i where h[i]=1, h[i+k*]=0, pick j where h[j]=0, h[j+k*]=1 (if k*>0) or h[j-k*]=1 (if k*<0)
- After the swap h[i]→0, h[j]→1:
  - At shift k*: the term at position i is removed (h[i](1-h[i+k*]) = 1*1 = 1 is removed)
  - But a new term might be added at position j: h[j](1-h[j+k*]) = 1*(1-h[j+k*]) = 1-1 = 0 (since h[j+k*]=1)
  - So net effect at shift k* is -1 (good!)
  - But effects at other shifts need to be checked

This is a good heuristic but requires checking all shifts after each move. For n=500, that's O(n) per move, and we might do O(n) moves per round, so O(n²) per round. With maybe 50 rounds, that's O(50*n²) = 50*250000 = 12.5M operations. Should be fine.

But s must be in [-(n-1), n-1], so the range is [max(p-(n-1), -(n-1)), min(p, n-1)] = [p-(n-1), min(p, n-1)] since p-(n-1) ≥ -(n-1) when p ≥ 0.

The number of affected shifts is min(p, n-1) - (p-(n-1)) + 1 = min(p, n-1) - p + n-1 + 1.

But actually, for the pair move (flip p: 1→0, flip q: 0→1), the total delta is:
delta_total[s] = -(1-h[p-s]) * [s in range_p] + (1-h[q-s]) * [s in range_q]

Where range_p = [p-(n-1), min(p,n-1)] and range_q = [q-(n-1), min(q,n-1)]

And the new correlation is: C_new[s] = C[s] + delta_total[s] * dx (if we include dx)

We want to minimize max_s C_new[s].

This is still a hard optimization over (p,q) pairs. But we can use a heuristic:
- Focus on the worst shifts
- For the worst shift s*, find p that has large (1-h[p-s*]) (so removing h[p] reduces C[s*] a lot)
- Find q such that (1-h[q-s*]) is small (so adding h[q] doesn't increase C[s*] much)
