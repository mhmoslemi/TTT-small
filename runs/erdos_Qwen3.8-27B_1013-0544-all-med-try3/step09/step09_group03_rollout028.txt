def local_binary_search(h, n, deadline, max_rounds=50):
    h = np.where(h > 0.5, 1.0, 0.0).astype(float)
    # Ensure exactly n/2 ones
    num_ones = int(h.sum())
    if num_ones > n // 2:
        idx = np.argsort(h)[::-1][:num_ones - n//2]
        h[idx] = 0.0
    elif num_ones < n // 2:

                return h, best_c
            h[i] = 1.0 - h[i]
            # Adjust: need to flip another bit to maintain sum
            if h[i] == 1.0:

    """Local search: swap a 1 with a 0 to maintain sum constraint."""
    h = np.where(h > 0.5, 1.0, 0.0).astype(float)
    num_ones = n // 2
    # Ensure correct number of ones
    ones = np.where(h == 1.0)[0]
    zeros = np.where(h == 0.0)[0]
    if len(ones) > num_ones:
        h[ones[len(ones)-num_ones:]] = 0.0
    elif len(ones) < num_ones:
        h[zeros[:num_ones-len(ones)]] = 1.0
    best_c = compute_c5(h, n)
    improved = True
    rounds = 0
    while improved and rounds < max_rounds and time.time() < deadline:
        improved = False
        rounds += 1
        ones = np.where(h == 1.0)[0]
        zeros = np.where(h == 0.0)[0]

                h[j] = 1.0

                    improved = True
                    break

                    h[j] = 0.0

At any point, only a few shifts are "active" (near the maximum). We can:

4. Solve it with a QP or LP

This is the **active set method** for minimax problems!

For the discrete problem:
- minimize t
- subject to: sum_i h[i]*(1-h[i+k]) * dx ≤ t for k in active set
- 0 ≤ h[i] ≤ 1
- sum_i h[i] = n/2

The constraints are bilinear in h (because h[i]*(1-h[i+k]) = h[i] - h[i]*h[i+k]), so this is NOT convex. The active set method works for convex minimax, not for bilinear.

This is bilinear. But if we fix one of the two factors, it becomes linear in the other. This suggests an **alternating direction** approach:
1. Fix h[i+k], optimize over h[i] (linear constraints)
2. Fix h[i], optimize over h[i+k] (linear constraints)

This is essentially a **block coordinate descent** or **alternating minimization** approach.
