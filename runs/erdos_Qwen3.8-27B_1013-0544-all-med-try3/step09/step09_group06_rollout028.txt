```python
            tot = room.sum()

            if tot < 1e-14:

    f_lag corresponds to the correlation at the given lag.
    lag = 0: sum h_i*(1-h_i)

        return grad
    if lag == 0:

        return grad
```

```python
    # Plus: h - eps <= h_new <= h + eps (2n constraints, but handled by bounds)
    
    A_ub = np.zeros((M, n_var))
    b_ub = np.zeros(M)
    
    for j, idx in enumerate(top_idx):
        lag = int(idx - (n - 1))
        g = lag_gradient(h, n, lag) * dx
        f_val = c_all[idx]
        A_ub[j, :n] = g
        A_ub[j, n] = -1.0
        b_ub[j] = g @ h - f_val
    
    A_eq = np.zeros((1, n_var))
    A_eq[0, :n] = 1.0
    b_eq = np.array([n / 2.0])
    
    # Bounds with epsilon constraint
    lo = np.maximum(0.0, h - epsilon)
    hi = np.minimum(1.0, h + epsilon)
    bounds = list(zip(lo, hi)) + [(0.0, 3.0)]
    
    res = linprog(c_obj, A_ub=A_ub, b_ub=b_ub, A_eq=A_eq, b_eq=b_eq,
                 bounds=bounds, method='highs')
    if res.status == 0:
        return res.x[:n]
    return None
```

Let me be more careful about the local search. I want it to be effective at finding small improvements (the kind that would take us from 0.380863 to 0.3808).

Key idea: for the worst lag k*, the overlap f_{k*} = sum_i h_i(1-h_{i+k*}). To reduce this, we want to either:
- Decrease h_i where h_{i+k*} = 0 (reduce the "1" part)
- Increase h_{i+k*} where h_i = 1 (increase the "1-h" part)

The most effective move is to transfer mass from h_i to h_{i+k*} (or vice versa) for pairs where this reduces f_{k*} the most.

For a small transfer δ from h_i to h_{i+k*}:
Δf_{k*} ≈ δ * [h_{i+k*} - (1-h_i)] + O(δ²)
         = δ * [h_{i+k*} + h_i - 1] + O(δ²)

If h_i + h_{i+k*} < 1, this is negative (reduces f_{k*}), so transferring from i to i+k* helps.
If h_i + h_{i+k*} > 1, this is positive, so transferring from i+k* to i helps.

But we also need to consider the effect on other lags. A move that helps f_{k*} might hurt f_{k'} for another lag k'.

So the local search should:
1. Find the worst lag k*
2. Generate candidate moves (transfers along lag k*)
3. For each move, evaluate the FULL C₅ (not just f_{k*})
4. Accept the move if it improves C₅

This is what the previous code does, but it's slow because of the full C₅ evaluation at each step.

To speed it up, I can:
- Use the fact that a single transfer only affects O(1) lags (well, actually it affects all lags, but the change is small)
- Use a fast approximation for the change in C₅

Actually, a transfer of δ from h_i to h_j (where j = i + k) only directly changes f_k. But it also changes f_{k'} for other lags k' because h_i and h_j appear in f_{k'} for various k'.

Specifically, changing h_i by -δ affects f_k for all k where h_i appears:
- f_k for k where i is in the first factor: f_k changes by -δ(1-h_{i+k})
- f_k for k where i is in the second factor: f_k changes by -δ*h_{i-k}

So the change in f_k is:
Δf_k = -δ(1-h_{i+k}) - δ*h_{i-k} + δ(1-h_{j+k}) + δ*h_{j-k} (approximately)
     = -δ(1-h_{i+k}) - δ*h_{i-k} + δ(1-h_{j+k}) + δ*h_{j-k}

where j = i + k_transfer (the lag of the transfer, not the lag in f_k).
