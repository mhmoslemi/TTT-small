delta = delta(i1, j1) + delta(i2, j2) + interaction terms

The interaction terms arise because when computing delta(i1, j1), we use the current h values, but after the swap, h[i2] and h[j2] have changed. For binary h, the interaction is:
- When computing delta(i1, j1), the term involving h[i2] or h[j2] is affected.

This gets complicated. A simpler approach: just compute the full correlation after the multi-swap and compare. But that's O(n²) per evaluation.

Alternative: use a "decomposition" approach. For a 2-swap, compute:
delta_total = delta_single(i1→1) + delta_single(i2→1) + delta_single(j1→0) + delta_single(j2→0) + corrections

Where delta_single(i→1) is the change when setting h[i] from 0 to 1 (without compensating), and delta_single(j→0) is the change when setting h[j] from 1 to 0.

For setting h[i] from 0 to 1 (without removing a 1 elsewhere):
The correlation c[k] = sum_n h[n+k]*(1-h[n]) changes by:
- Terms where h[i] appears as h[n+k]: add (1-h[n]) for n = i-k
- Terms where h[i] appears as h[n]: subtract h[n+k] for n = i

So delta_plus(i)[k] = (1-h[i-k]) - h[i+k] (for valid indices)

For setting h[j] from 1 to 0:
delta_minus(j)[k] = -(1-h[j-k]) + h[j+k] (for valid indices)

For a swap (i: 0→1, j: 1→0):
delta = delta_plus(i) + delta_minus(j)
= (1-h[i-k]) - h[i+k] - (1-h[j-k]) + h[j+k]

But wait, when i and j are involved in the same term, we need a correction. Specifically:
- If i-k = j (i.e., k = i-j): the term h[i]*(1-h[j]) changes from 0*(1-1)=0 to 1*(1-0)=1. The formula gives (1-h[j])-h[i+k] = (1-1)-h[i+(i-j)] = 0-h[2i-j]. That's not right.

I think the cleanest approach is to just use the full delta formula from the previous code (which handles the corrections) and for multi-swaps, compute the new correlation directly.
