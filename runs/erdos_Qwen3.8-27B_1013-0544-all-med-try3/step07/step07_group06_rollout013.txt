Actually, the change in C[m] when h[i] goes from 0 to 1 is:

This doesn't depend on h[i] itself (since we're computing the marginal change). So gain_i is the same regardless of whether h[i] is currently 0 or 1.

For a swap (i: 0→1, j: 1→0), the total change is:
ΔC[m] = gain_i[m] - gain_j[m] + cross(i,j,m)

where cross(i,j,m) handles the interaction between i and j.

The cross terms are:
- If i + (m-(n-1)) = j: the gain_i computation used h[j] (which is about to change), so we need to correct
- If j + (m-(n-1)) = i: similar correction
- If i - (m-(n-1)) = j: correction for the second term of gain_i
- If j - (m-(n-1)) = i: correction for the second term of gain_j

These are O(1) corrections per swap (at most 4 shifts are affected).

So the algorithm is:
1. Precompute gain[i][m] for all i (O(n²) total, but vectorizable)
2. For each pair (i∈zeros, j∈ones):
   ΔC = gain[i] - gain[j] + cross(i,j)
   new_max = max(C + ΔC)
   Track the best (i,j)
3. Apply the best swap
4. Update gain for the new zero/one positions (O(n) each)
5. Repeat
