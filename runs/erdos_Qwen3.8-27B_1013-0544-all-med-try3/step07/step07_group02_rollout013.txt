So we need to recompute c[k] for k up to max(p, q, n-1-p, n-1-q). In the worst case, that's up to n-1 lags, which is O(n) per swap. With n=500, that's 500 operations per swap, which is fast.

But we also need to check ALL lags (including negative ones) to make sure we don't increase the max. For negative lag -k (i.e., the correlation at index n-1-k):
c[-k] = #{i: h[i-k]=1, h[i]=0} for i=k..n-1
= #{j: h[j]=1, h[j+k]=0} for j=0..n-k-1
= #{i: h[i]=1, h[i+k]=0} for i=0..n-k-1

This is the "reverse" count: positions where h goes from 1 to 0 at offset k.

So for binary h, we have 2(n-1) lags to consider (positive and negative), plus lag 0 (which is 0 for binary h).

The max over all lags is what we're minimizing.

**Algorithm for binary local search**:
1. Start with a binary h
2. Compute all c[k] for k = -(n-1)..(n-1), k≠0
3. Find the max lag k*
4. Try all possible (p,q) swaps where:
   - h[p]=1, h[q]=0
   - The swap reduces c[k*]
   - The swap doesn't increase any other c[k] above the current max
5. Accept the best swap
6. Repeat
