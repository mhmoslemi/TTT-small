def try_block_move(h, corr, n, old_start, new_start, block_len):
    """Try moving a block of 1s. Returns (new_corr, improvement) or None if invalid."""
    # Check old block is all 1s
    if not np.all(h[old_start:old_start+block_len] == 1.0):
        return None
    # Check new block is all 0s
    if not np.all(h[new_start:new_start+block_len] == 0.0):
        return None
    
    h_new = h.copy()
    h_new[old_start:old_start+block_len] = 0.0
    h_new[new_start:new_start+block_len] = 1.0
    
    corr_new = compute_corr(h_new, n)
    c_new = corr_new.max() * (2.0/n)
    return h_new, corr_new, c_new

Let me also think about a completely different strategy: **iterative reduction of the max shift**.

Algorithm:
1. Find the shift s* that gives the maximum overlap.
2. For that shift, the overlap is sum_{valid i} h[i]*(1-h[i+s*]).
3. For binary h, this means we want to minimize the number of (1,0) pairs at shift s*.
4. Each (1,0) pair at shift s* can be eliminated by:
   a. Changing h[i] from 1 to 0 (but then we need to change some other 0 to 1 to maintain the count)
   b. Changing h[i+s*] from 0 to 1 (same constraint)
5. So we look for a swap that reduces the count at shift s* while not increasing other shifts too much.

This "targeted" approach might be more effective than random/greedy search.
