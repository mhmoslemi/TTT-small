    #   Actually k = s + (n-1), s = k - (n-1)
    #   op - (k-(n-1)) in [0,n-1] => op - k + n - 1 in [0,n-1] => op+n-1-k in [0,n-1]
    #   => op in [k-n+1, k+0]... this is confusing.
    
    # Let me just use direct index computation.
    # c_full has indices 0 to 2n-2.
    # c_full[k] involves pairs (i, i-s) where s = k-(n-1)
    # i ranges over max(0,s) to min(n-1, n-1+s) if s>0, or max(0,-s) to min(n-1, n-1-s) if s<0
    
    # When h[op] changes:
    #   As first factor (i=op): s = op - j where j is the second index, j = op-s
    #     Valid: 0<=op<n (yes) and 0<=op-s<n => op-n+1<=s<=op => k = s+(n-1) in [op-n+1+n-1, op+n-1] = [op, op+2n-2]
    #     But k must be in [0, 2n-2], so k in [max(0,op), min(2n-2, op+2n-2)]
    #     The j value: j = op-s = op-(k-(n-1)) = op+n-1-k
    #     Valid: 0<=j<n => 0<=op+n-1-k<n => op<=k<=op+n-1
    #     So k ranges over [max(0, op), min(2n-2, op+n-1)] with j = op+n-1-k
    #   As second factor (j=op, i=op+s): s = i-op, i = op+s
    #     Valid: 0<=i<n => 0<=op+s<n => -op<=s<=n-1-op => k in [n-1-op, n-1+op]
    #     And k in [0, 2n-2]
    #     The i value: i = op+s = op+k-(n-1) = op+k-n+1
    #     Valid: 0<=i<n => n-1-op<=k<=2n-2-op... hmm
    
    # This is getting too complex. Let me just use numpy to find the affected indices.
    
    # Simpler approach: the swap changes h at exactly 2 positions.
    # The correlate c[k] = sum_i h[i]*(1-h[i-s(k)])
    # is affected only where i=op or i-s(k)=op or i=zp or i-s(k)=zp
    # i.e., k-s(k) = op-s(k) = j1, or i = op+s(k) = i1, or j2 = zp-s(k), or i2 = zp+s(k)
    
    # Let me just compute the delta for all k in the affected range.
    # For op (1->0):
    #   Type A: i=op, j=op-s. Valid j: 0<=op-s<n => s in [op-(n-1), op] => k in [op, op+2n-2]
    #   Type B: j=op, i=op+s. Valid i: 0<=op+s<n => s in [-op, n-1-op] => k in [n-1-op, n-1+op]
    # For zp (0->1):
    #   Type C: i=zp, j=zp-s. Valid j: 0<=zp-s<n => s in [zp-(n-1), zp] => k in [zp, zp+2n-2]
    #   Type D: j=zp, i=zp+s. Valid i: 0<=zp+s<n => s in [-zp, n-1-zp] => k in [n-1-zp, n-1+zp]
    
    # Affected k range: union of the above, clipped to [0, 2n-2]
    k_min = max(0, min(op, n-1-op, zp, n-1-zp))
    k_max = min(2*n-2, max(op+2*n-2, n-1+op, zp+2*n-2, n-1+zp))
    
    # For each k in [k_min, k_max], compute delta
    # But this could be up to 4n values... let's just compute all of them.
    
    h_new = h.copy()
    h_new[op] = 0
    h_new[zp] = 1
    
    # Recompute only the affected part? Nah, just recompute the whole thing.
    # For n=500, it's fast enough.
    
    new_c = np.correlate(h_new, 1 - h_new, mode='full')
    new_max = new_c.max()
    
    h[op] = 0  # Keep the change
    h[zp] = 1
    
    return new_max, new_c

OK I think I'm overcomplicating this. For n=500, a full correlate call in numpy takes about 10-50 microseconds. In 1100 seconds, I can do about 20-100 million correlate calls. That's more than enough for any reasonable number of swaps.

Let me just go with the simple approach: random swaps + full recompute. The key optimization is to:
1. Focus on promising swaps (not purely random)
2. Use multiple resolutions
3. Use both binary and fractional optimization

Let me also think about the fractional optimization. The parent uses SLSQP with a smooth-max objective. This is effective but slow. An alternative is to use the **CVXPY** solver to solve a related convex problem:

minimize t
subject to:
  ∫ h(x)(1-h(x+k)) dx ≤ t for all k
  0 ≤ h(x) ≤ 1
  ∫ h(x) dx = 1

This is an LP! (Linear programming) Because h(x)(1-h(x+k)) is... wait, it's NOT linear in h. h(x)*(1-h(x+k)) = h(x) - h(x)*h(x+k) is not linear.

Hmm, but if I fix the values at shift k, then it's linear in h(x). But we need to handle all shifts simultaneously, which makes it not a simple LP.

However, I can use a **successive linearization** approach:
1. Start with a current h
2. Linearize h(x)*(1-h(x+k)) around the current h
3. Solve the LP
4. Repeat

The linearization of h(x)*(1-h(x+k)) at h₀ is:
h₀(x)*(1-h₀(x+k)) + (h(x)-h₀(x))*(1-h₀(x+k)) + h₀(x)*(-(h(x+k)-h₀(x+k)))
= h₀(x)*(1-h₀(x+k)) + (h(x)-h₀(x))*(1-h₀(x+k)) - h₀(x)*(h(x+k)-h₀(x+k))

This is linear in h(x) and h(x+k). So the LP at each iteration is well-defined.

Let me use CVXPY for this:
