c_rev[1] = #(0,1) = #(1,0) (in a circular sense) but in linear, #(0,1) = #(1,0) ± 1 (depending on boundary).

Actually in linear: #(1,0) + #(0,1) + #(0,0) + #(1,1) = n-1 = 399
And #(1,0) - #(0,1) = h[0] - h[n-1] (telescoping), so |#(1,0) - #(0,1)| ≤ 1.

So if #(1,0) ≤ 76, then #(0,1) ≤ 77.
And #(0,0) + #(1,1) ≥ 399 - 76 - 77 = 246.

For k=2: c[2] = sum_{i=0}^{n-3} h[i]*(1-h[i+2]) ≤ 76
This is the number of pairs at distance 2 that are (1,0).

For a "block" structure like 1111000011110000..., the large-lag correlations are small but small-lag correlations within blocks can be large.

I think the optimal structure is something like a "balanced" pattern where ones and zeros are well-mixed at all scales. This is similar to a digital (m, s) sequence or a Sobol sequence.

**Practical approach:**

Given the complexity of the theoretical analysis, let me focus on practical improvements:

1. **Start from multiple initial patterns** and pick the best after local search
2. **Use a faster local search** with precomputation
3. **Add 2-swap moves** to escape local optima
4. **Try different resolutions** (n=400, 448, 512)
5. **Better annealing** with adaptive cooling

Let me also think about a key insight: the previous code's binary_local_search only does 1-swap moves (exchange one 0 with one 1). Adding 2-swap moves (exchange two 0s with two 1s) could help escape local optima.

For a 2-swap (i1,i2 zeros → ones; j1,j2 ones → zeros), the delta in correlation is:
delta = delta(i1,j1) + delta(i2,j2) - correction_terms

Where correction_terms account for the interaction between the two swaps.

This is O(n) to compute per 2-swap candidate. But there are O(n⁴) possible 2-swaps, which is way too many. We'd need to restrict to nearby pairs or use a heuristic.

Alternative: Use a "block swap" where we swap a contiguous block of 0s with a contiguous block of 1s.

def project(h, n):
    """Project h onto the constraint set: 0≤h≤1, sum(h)=n/2."""
    target = n / 2.0
    h = h.copy()
    lo, hi = -2.0, 2.0
    for _ in range(100):
        mid = (lo + hi) / 2.0
        hp = np.clip(h - mid, 0.0, 1.0)
