The integral ∫ h(x)(1-h(x+k)) dx — over what domain?

Looking at the discretization:
"np.correlate(h, 1-h, mode='full') * dx"

np.correlate(h, 1-h, mode='full') for arrays of length n gives an array of length 2n-1.
The m-th element (0-indexed) is: sum_i h[i] * (1-h)[i + m - (n-1)]

For m = 0: sum_i h[i] * (1-h)[i-(n-1)] — only i = n-1 gives a valid index (0), so = h[n-1]*(1-h[0])
For m = n-1: sum_i h[i] * (1-h)[i] — this is the "zero lag" correlation
For m = 2(n-1): only i=0 gives valid index, so = h[0]*(1-h[n-1])

So the shifts range from -(n-1) to (n-1) in index space, which corresponds to shifts from -(n-1)*dx to (n-1)*dx ≈ ±2.

But the key point is: the correlation is computed over the OVERLAP of the two arrays. When the shift is large, there are fewer overlapping elements, so the sum is over fewer terms.

For shift k (in index space, positive means h is shifted right relative to 1-h):
result[m] = sum_{i} h[i] * (1-h[i + m - (n-1)])
where the sum is over all i where both indices are valid.

The number of valid i is: n - |m - (n-1)| = n - |shift_in_indices|

So for shift s = m - (n-1) (in index space):
result = sum_{i=max(0,-s)}^{min(n-1, n-1-s)} h[i] * (1-h[i+s])

The number of terms is n - |s|.

And the integral approximation is: result * dx = result * 2/n.

So for large |s| (close to n-1), there are very few terms, and the integral is small!

This is different from what I was computing before! The integral is NOT over the "boundary" region. It's only over the overlap region where both h(x) and h(x+k) are defined.

Let me redo the analysis:
overlap(k) = ∫_{max(0,-k)}^{min(2, 2-k)} h(x)(1-h(x+k)) dx

For |k| < 2, the integration domain has length 2-|k|.
For |k| ≥ 2, the integration domain is empty and overlap = 0.

So the max is over |k| < 2, and the overlap goes to 0 as |k| → 2.
