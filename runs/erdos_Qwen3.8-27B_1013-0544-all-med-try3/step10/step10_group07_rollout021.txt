We need to find a step function h: [0, 2] → [0, 1] that minimizes:
C₅ = max_k ∫ h(x)(1-h(x+k)) dx

With constraints:
- h(x) ∈ [0, 1]
- ∫₀² h(x) dx = 1

The discretization: n_points samples, dx = 2/n_points, sum(h) = n/2.

Current best: C₅ ≤ 0.38085 (record), previous run achieved 0.380866.

The key insight is that we want to minimize the maximum overlap of h with (1-h) shifted by any amount k. This is essentially finding a set of measure 1 in [0,2] such that its complement (measure 1) minimizes the maximum correlation with the original set.

Let me think about what approaches could improve upon the previous result:

1. **The previous approach** used SLSQP + binary local search. The binary local search is O(n²) per swap evaluation which is very slow for large n.

2. **Key observations**:
   - The problem is fundamentally about finding a subset S of [0,2] with measure 1 such that the maximum over all shifts k of the measure of S ∩ (S+k)^c is minimized.
   - For binary (0/1) functions, this is equivalent to finding a subset of n/2 grid points.
   - The correlation computation can be done efficiently with FFT.

3. **Strategy improvements**:
   - Use FFT-based correlation for O(n log n) instead of O(n²)
   - Use a smarter local search that evaluates moves in O(n) using the FFT structure
   - Try multiple resolutions
   - Use simulated annealing or other global optimization
   - The key bottleneck in the previous code was the O(n²) local search - each evaluation required computing the full correlation delta

Let me think about a more efficient approach:

For binary h (values 0 or 1), the overlap at shift k is:
correl(h, 1-h, k) = sum_i h[i] * (1-h[i-k]) (with appropriate bounds)

If we flip h[j] from 1 to 0:
- For shift k: the change is (1-h[j-k]) - h[j] for the term at position j with shift k... 

Actually, let me think more carefully. The correlation is:
c[k] = sum_i h[i] * (1-h[i-k]) for valid i, i-k

If we change h[j] from 1 to 0:
- For each shift k where j is in the sum: the term h[j]*(1-h[j-k]) goes to 0, so c[k] decreases by (1-h[j-k])
- For each shift k where j-k = i for some i: the term h[i]*(1-h[j]) goes to h[i]*1, so c[k] changes by h[i]*(1-0) - h[i]*(1-1) = h[i]*0... wait.

Let me be more careful. c[k] = sum_i h[i] * (1-h[i-k])

If h[j] changes from 1 to 0:
- Terms where i=j: h[j]*(1-h[j-k]) → 0, change = -(1-h[j-k]) for each valid k (i.e., j-k is in range)
- Terms where i-k=j, i.e., i=j+k: h[j+k]*(1-h[j]) → h[j+k]*(1-0) = h[j+k], change = h[j+k]*(1-0) - h[j+k]*(1-1) = h[j+k] - 0 = h[j+k] for each valid k (i.e., j+k is in range)

So the delta for change h[j]: 1→0 is:
delta[k] = -(1-h[j-k]) for k where j-k ∈ [0,n)
delta[k] = +h[j+k] for k where j+k ∈ [0,n)

This is O(n) to compute! Not O(n²).

Similarly for h[j]: 0→1:
delta[k] = +(1-h[j-k]) for k where j-k ∈ [0,n)
delta[k] = -h[j+k] for k where j+k ∈ [0,n)

So a swap (j: 1→0, i: 0→1) has delta = delta_j(1→0) + delta_i(0→1), which is O(n).

This means we can do local search in O(n) per swap evaluation instead of O(n²)!

For n=250, O(n²) = 62500 operations per swap, while O(n) = 250. That's a 250x speedup!

    """Evaluate the effect of swapping h[i](=0) and h[j](=1) on correlation."""
    # delta_c[k] for all k
    # Using the formula derived above
    m_range = np.arange(-(n-1), n)
    k = m_range  # shifts
    
    # (1-h[i-k]) * I(0<=i-k<n)
    i_minus_k = i - k
    term1 = np.where((i_minus_k >= 0) & (i_minus_k < n), 1 - h[i_minus_k[(i_minus_k >= 0) & (i_minus_k < n)]], 0)

    j_minus_k = j - k
    term2 = np.where((j_minus_k >= 0) & (j_minus_k < n), -(1 - h[j_minus_k[(j_minus_k >= 0) & (j_minus_k < n)]]), 0)

    term3 = np.where((i_plus_k >= 0) & (i_plus_k < n), -h[i_plus_k[(i_plus_k >= 0) & (i_plus_k < n)]], 0)

    cross = np.zeros(2*n-1)
    k0_idx = n-1  # index where k=0
    cross[k0_idx] -= 2
    
    dij_idx = n-1 + (i-j)  # index where k=i-j
