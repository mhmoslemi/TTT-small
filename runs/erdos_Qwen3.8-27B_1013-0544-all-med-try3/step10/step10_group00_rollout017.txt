So the affected m values are: 0 to max(i_1, j, n-1-i_1, n-1-j). In the worst case, all m from 0 to n-1.

But the CHANGE at each m is just a small number of terms (at most 4 lookups). So computing the new max after a swap is:
- Start with the current result vector
- Apply the O(1) changes at each affected m
- Find the new max

This is O(n) per swap evaluation. For n=500, that's 500 operations per swap. With 2500 candidate swaps per iteration, that's 1.25M operations per iteration. At 1ns per operation (optimistic), that's 1.25ms per iteration. So in 1 second, ~800 iterations. In 100 seconds, 80K iterations.

Actually, numpy will handle this much faster than 1ns per op. Let me just use numpy for the vector operations.

But wait, I can be smarter. The max can only decrease if ALL the currently-maximal shifts decrease. And it can only increase if some shift increases above the current max. So I can:
1. Track the current max value and which shifts achieve it
2. For a candidate swap, check if any of the max shifts increase
3. If yes, the swap is bad (reject)
4. If no, check if the max shifts decrease enough to make the max lower

This is a significant speedup if the number of max shifts is small.

Let me implement this more efficiently. Actually, for the initial implementation, let me just use the simple approach (compute full C₅ after each swap) and see if it's fast enough. If not, I'll optimize.

For n=500, `np.correlate` is probably 5-10 microseconds. So one evaluation takes ~10μs. 2500 evaluations per "batch" = 25ms. In 1 second, 40 batches. In 100 seconds, 4000 batches. Each batch involves trying 2500 swaps.

That should be more than enough iterations. Let me just go with the simple approach.
