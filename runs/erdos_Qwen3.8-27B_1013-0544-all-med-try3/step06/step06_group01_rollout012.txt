Let me also provide the analytical gradient to L-BFGS-B to speed things up. The gradient of the smooth objective:

∂f_smooth/∂h_i = dx * sum_k p_k * ∂c_k/∂h_i

where p_k = exp(alpha * c_k * dx) / sum_j exp(alpha * c_j * dx)

And ∂c_k/∂h_i = (1-h_{i+k}) - h_{i-k} (with boundary handling, as I derived earlier).

This is a convolution, so it can be computed in O(n log n) using FFT, or O(n²) directly.

For n=250, O(n²) = 62500 operations, which is negligible compared to the function evaluation. Let me just compute it directly.

Actually, I realize I already have the `compute_sig` function which computes exactly ∂c/∂h! sig[i] = ∂c/∂h_i (the gradient of the correlation vector w.r.t. h_i).

So the gradient of f_smooth is:
grad[i] = dx * sum_k p_k * sig[i][k] = dx * (p @ sig[i]) = dx * sig[i] @ p

And for all i at once:
grad = dx * (sig @ p)

This is a matrix-vector product of shape (n, 2n-1) @ (2n-1,) = O(n * (2n-1)) = O(n²). For n=250, that's about 125K operations. Very fast!

So with the analytical gradient, each L-BFGS-B iteration is:
- 1 function evaluation: O(n²) for the correlation
- 1 gradient evaluation: O(n²) for the sig computation + O(n²) for the matvec
- L-BFGS-B internal computation: O(n²) for the line search

Total per iteration: O(n²) ≈ 62500 for n=250. With 100 iterations, that's 6.25M operations. Very fast!
