```python
def compute_lag_deltas(h_bin, i, j, n):
    """Compute the change in correlation values when h[i] goes 1->0 and h[j] goes 0->1.
    Returns an array of length 2n-1 of deltas."""
    # Correlation index k corresponds to lag L = k - (n-1)
    # c[k] = sum_t h[t] * (1-h[t+L]) for valid t
    
    deltas = np.zeros(2*n-1)
    
    # h[i]: 1 -> 0
    # As first index (t=i): L range where i+L is in [0,n-1]: L in [-i, n-1-i]
    #   delta for each such L: -(1 - h[i+L]) = h[i+L] - 1
    # Correlation index: k = L + (n-1), so k in [(n-1)-i, (n-1)+(n-1-i)] = [n-1-i, 2n-2-i]
    L_start = -i
    L_end = n-1-i  # inclusive
    for L in range(L_start, L_end+1):
        k = L + (n-1)
        deltas[k] += h_bin[i+L] - 1.0  # = -(1-h[i+L])
    
    # As second index (t+L=i, t=i-L): L range where i-L is in [0,n-1]: L in [i-(n-1), i]
    #   delta: h[i-L] - 0 = h[i-L]  (old was h[i-L]*(1-1)=0, new is h[i-L]*(1-0)=h[i-L])
    L_start = i-(n-1)
    L_end = i  # inclusive
    for L in range(L_start, L_end+1):
        k = L + (n-1)
        deltas[k] += h_bin[i-L]
    
    # h[j]: 0 -> 1
    # As first index (t=j): L range where j+L is in [0,n-1]: L in [-j, n-1-j]
    #   delta: (1-h[j+L]) - 0 = 1-h[j+L]
    L_start = -j
    L_end = n-1-j
    for L in range(L_start, L_end+1):
        k = L + (n-1)
        deltas[k] += 1.0 - h_bin[j+L]
    
    # As second index (t+L=j, t=j-L): L range where j-L is in [0,n-1]: L in [j-(n-1), j]

    L_end = j

        k = L + (n-1)
        deltas[k] -= h_bin[j-L]
```

```python
            # Compute old and new term
            old_term = h[nc] * (1 - h[nc + lag])
            # New h: h[i]=0, h[j]=1
            h_nc = 0.0 if nc == i else (1.0 if nc == j else h[nc])
            h_nc_lag = 0.0 if (nc + lag) == i else (1.0 if (nc + lag) == j else h[nc + lag])
            new_term = h_nc * (1 - h_nc_lag)
            deltas[k] += new_term - old_term
    
    return deltas
```

This is correct but involves a Python loop over 2n-1 values. For n=400, that's 799 iterations, each with a few operations. In Python, this might take ~0.1ms per swap. With 100000 swaps, that's 10 seconds. That's borderline.

Let me try to vectorize this. The key observation is that for each of the 4 "types" of affected positions, the valid range of lags is a contiguous interval, and within that range, the delta is a simple function of h values.

Let me go back to the 4-case approach but handle the overlaps correctly.

**Type A: n = i (i as first factor)**
- Valid for lag in [-i, n-1-i] (i.e., k in [n-1-i, 2n-2-i])
- Old term: h[i]*(1-h[i+lag]) = 1*(1-h[i+lag])
- New term: 0*(1-h'[i+lag]) = 0
- Delta: -(1-h[i+lag]) = h[i+lag] - 1
- For k = n-1-i+p (p=0,...,n-1-i): lag = -i+p, i+lag = p
- Delta at k: h[p] - 1
- So deltas[n-1-i : 2n-1-i] += h[0:n-i] - 1

**Type B: n = i-lag (i as second factor)**
- Valid for lag in [i-n+1, i] (i.e., k in [i, i+n-1])
- Old term: h[i-lag]*(1-h[i]) = h[i-lag]*0 = 0
- New term: h'[i-lag]*(1-0) = h'[i-lag]
- Case: if i-lag = j (i.e., lag = i-j): h'[j] = 1, delta = 1
- Case: if i-lag ≠ j: h'[i-lag] = h[i-lag], delta = h[i-lag]
- For k = i+p (p=0,...,n-1): lag = p-(n-1), i-lag = i+n-1-p
- Delta at k=i+p: h[i+n-1-p] (or 1 if i+n-1-p = j)
- Normally: deltas[i:i+n] += h[n-1::-1] (reversed h)
- Correction: if j is in [i, i+n-1] as an index into h (i.e., 0 ≤ j ≤ n-1, which is always true), then at position k=i+p where i+n-1-p=j, i.e., p=i+n-1-j, we need to add 1 instead of h[j]=0. So add 1 at that position.

Wait, let me re-examine. The delta for Type B at position k=i+p is h'[i+n-1-p].
- If i+n-1-p = j: h'[j] = 1. The "normal" formula gives h[j] = 0. So add 1.
- If i+n-1-p = i: h'[i] = 0. The "normal" formula gives h[i] = 1. So add -1.
- Otherwise: h'[i+n-1-p] = h[i+n-1-p]. Normal formula is correct.

So for Type B:
deltas[i:i+n] += h[n-1::-1]  (the reversed h array)
Then corrections:
- At position k = i+n-1-j (where i+n-1-p = j, p = i+n-1-j): add 1 (correction from h[j]=0 to h'[j]=1)
  This is valid if 0 ≤ i+n-1-j < n, i.e., j ≥ i and j ≤ i+n-1. Since j is in [0,n-1] and i is in [0,n-1], j ≥ i is the binding constraint.
  k_correction = i+n-1-j. Valid if i ≤ j ≤ i+n-1, and k in [i, i+n-1] (which is true since i+n-1-j is in [0,n-1] when i≤j).

- At position k = i+n-1-i = n-1 (where i+n-1-p = i, p = n-1): add -1 (correction from h[i]=1 to h'[i]=0)
  k_correction = n-1. This is in [i, i+n-1] iff i ≤ n-1, which is always true.
  So always subtract 1 at position k=n-1.

**Type C: n = j (j as first factor)**
- Valid for lag in [-j, n-1-j] (i.e., k in [n-1-j, 2n-2-j])
- Old term: h[j]*(1-h[j+lag]) = 0
- New term: 1*(1-h'[j+lag]) = 1-h'[j+lag]
- For k = n-1-j+p (p=0,...,n-1-j): lag = -j+p, j+lag = p
- Delta at k: 1-h'[p]
- If p = i: 1-h'[i] = 1-0 = 1. Normal: 1-h[i] = 1-1 = 0. Add 1.
- If p ≠ i: 1-h[p]. Normal formula.
- So: deltas[n-1-j : 2n-1-j] += 1-h[0:n-j]
  Correction at k = n-1-j+i (where p=i): add 1 (if i < n-j, i.e., i+j < n)

**Type D: n = j-lag (j as second factor)**
- Valid for lag in [j-n+1, j] (i.e., k in [j, j+n-1])
- Old term: h[j-lag]*(1-h[j]) = h[j-lag]*1 = h[j-lag]
- New term: h'[j-lag]*(1-1) = 0
- Delta: -h'[j-lag]
- For k = j+p (p=0,...,n-1): lag = p-(n-1), j-lag = j+n-1-p
- Delta at k=j+p: -h'[j+n-1-p]
- If j+n-1-p = i: -h'[i] = -0 = 0. Normal: -h[i] = -1. Add 1.
- If j+n-1-p = j: -h'[j] = -1. Normal: -h[j] = -0 = 0. Add -1.
- So: deltas[j:j+n] -= h[n-1::-1]
  Correction at k = j+n-1-i (where j+n-1-p=i, p=j+n-1-i): add 1 (if i ≥ j, since p must be in [0,n-1], so j+n-1-i in [0,n-1] means i in [j, j+n-1], i.e., i ≥ j)
  Correction at k = j+n-1-j = n-1 (where j+n-1-p=j, p=n-1): add -1 (always valid since n-1 is in [j, j+n-1])

Now, let me also check: are there any cases where Type A and Type B both affect the same k with the same n? No, because Type A has n=i and Type B has n=i-lag. They'd be the same n only if lag=0, in which case n=i for both. Similarly for C and D.

What about Type A and Type D? Type A has n=i, Type D has n=j-lag. Same if i=j-lag, i.e., lag=j-i.
Type B and Type C? Type B has n=i-lag, Type C has n=j. Same if i-lag=j, i.e., lag=i-j.

These overlaps mean that for these specific lags, a single n is affected by both the i-change and the j-change, and we've computed the delta as the sum of two separate deltas. But the actual delta should be computed as new_term - old_term for that single n, which equals the sum of the two individual deltas only if the changes are independent (which they are, since the term is bilinear in h[n] and h[n+lag]).

Wait, actually since the term is h[n]*(1-h[n+lag]), and we're changing both h[n] and h[n+lag] potentially, the delta is NOT simply the sum of the individual deltas!

Let's verify: Suppose n=i and n+lag=j (so lag=j-i).
Old term: h[i]*(1-h[j]) = 1*1 = 1
New term: h'[i]*(1-h'[j]) = 0*0 = 0
Actual delta: -1

Type A delta (n=i, first factor): -(1-h[i+lag]) = -(1-h[j]) = 0
Type D delta (n=j-lag=i, second factor): -h'[j-lag] = -h'[i] = 0
Sum: 0. But actual is -1!

So the 4-type approach with simple summing is WRONG when there's overlap!

The issue is that the term h[n]*(1-h[n+lag]) is a product, so when both factors change, the cross term matters.

- i-lag is a valid n if 0 ≤ i-lag < n AND 0 ≤ i < n (second condition always true)
- j is a valid n if 0 ≤ j+lag < n
- j-lag is a valid n if 0 ≤ j-lag < n

For most lags, at least one of these will be valid. So yes, essentially all lags are affected.

Let me try a different approach: **vectorized computation using numpy.**

Actually, I realize I can vectorize the 4-type approach by handling the corrections separately. The key insight is:

For most lags, there's no overlap between the 4 types. Overlaps only happen at at most a few specific lags:
- lag = 0: Type A & B overlap (at n=i), Type C & D overlap (at n=j)
- lag = j-i: Type A & D overlap (at n=i)
- lag = i-j: Type B & C overlap (at n=j)

So I can compute the 4 types independently (vectorized), then fix up the at most 3 problematic lags.

Let me implement this:

def fast_swap_deltas(h, i, j, n):
    """Compute delta for all 2n-1 correlation indices when h[i]:1->0, h[j]:0->1.
    Uses vectorized 4-type approach with corrections for overlaps."""
    # h is a numpy array of 0s and 1s
    h_float = h.astype(float)
    rev_h = h_float[::-1]  # reversed
    
    deltas = np.zeros(2*n-1)
    
    # Type A: n=i as first factor. k in [n-1-i, 2n-2-i]. delta = h[i+lag]-1 = h[p]-1
    A_start = n-1-i
    A_len = n-i
    deltas[A_start:A_start+A_len] += h_float[0:A_len] - 1.0
    
    # Type B: n=i-lag as second factor. k in [i, i+n-1]. delta = h'[i-lag]
    # Normal: h[i+n-1-p] for p=0..n-1, which is rev_h[p]
    B_start = i
    deltas[B_start:B_start+n] += rev_h
    
    # Correction for Type B:
    # At k where i+n-1-p = i (p=n-1): k=n-1. Normal gives h[i]=1, correct is h'[i]=0. Add -1.
    deltas[n-1] += -1.0
    # At k where i+n-1-p = j (p=i+n-1-j): k=i+n-1-j. Normal gives h[j]=0, correct is h'[j]=1. Add +1.
    # Valid if 0 <= i+n-1-j < n and i+n-1-j is in [B_start, B_start+n), i.e., i <= i+n-1-j <= i+n-1
    # i+n-1-j >= i iff j <= n-1 (always true)
    # i+n-1-j <= i+n-1 iff j >= 0 (always true)
    # i+n-1-j >= 0 iff j <= i+n-1 (always true since j < n <= i+n-1)
    # So always valid.
    kB = i + n - 1 - j
    if 0 <= kB < 2*n-1:
        deltas[kB] += 1.0
    
    # Type C: n=j as first factor. k in [n-1-j, 2n-2-j]. delta = 1-h'[j+lag] = 1-h'[p]
    C_start = n-1-j
    C_len = n-j
    deltas[C_start:C_start+C_len] += 1.0 - h_float[0:C_len]
    
    # Correction for Type C:
    # At k where p=i (k=C_start+i = n-1-j+i): Normal gives 1-h[i]=0, correct is 1-h'[i]=1. Add +1.
    # Valid if i < C_len = n-j, i.e., i < n-j, i.e., i+j < n.
    if i + j < n:
        kC = n - 1 - j + i
        deltas[kC] += 1.0
    
    # Type D: n=j-lag as second factor. k in [j, j+n-1]. delta = -h'[j+n-1-p]
    # Normal: -rev_h[p]
    D_start = j
    deltas[D_start:D_start+n] -= rev_h
    
    # Correction for Type D:
    # At k where j+n-1-p = j (p=n-1): k=n-1. Normal gives -h[j]=0, correct is -h'[j]=-1. Add -1.
    deltas[n-1] += -1.0
    # At k where j+n-1-p = i (p=j+n-1-i): k=j+n-1-i. Normal gives -h[i]=-1
