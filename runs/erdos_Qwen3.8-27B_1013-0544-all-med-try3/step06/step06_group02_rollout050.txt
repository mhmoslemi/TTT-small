def thue_morse_binary(n):
    """Generate Thue-Morse binary sequence of length n with exactly n//2 ones (or close)."""
    # Thue-Morse: t(i) = parity of number of 1 bits in i
    tm = np.array([(i & (i >> 1) & (i >> 2) & (i >> 3) & (i >> 4) & (i >> 5) & (i >> 6) & (i >> 7)).sum() % 2 for i in range(n)])

    tm = np.array([bin(i).count('1') % 2 for i in range(n)])
    # Adjust to have exactly n/2 ones
    if n % 2 == 0:
        target = n // 2
        ones = tm.sum()
        if ones > target:
            # Flip some 1s to 0s
            excess = ones - target
            indices_1 = np.where(tm == 1)[0]
            to_flip = indices_1[:excess]
            tm[to_flip] = 0
        elif ones < target:
            deficit = target - ones
            indices_0 = np.where(tm == 0)[0]
            to_flip = indices_0[:deficit]
            tm[to_flip] = 1
    return tm.astype(float)

    c = compute_c5_vec(h, n)
    # Subgradient: gradient of the max component
    max_idx = np.argmax(c)

        grad[kk:n] += (1.0 - h[0:nv]) * dx

When we swap h[i] and h[j] (changing h[i] from a to b and h[j] from b to a), the change in the correlation at shift k is:
- For shift k: the terms involving position i and position j change
- Specifically, the correlation c[k] changes by:

Let me work out the details. The correlation is:
c[m] = sum_i h[i] * (1-h[i - (m-(n-1))]) for valid i

Let's define the shift as s = m - (n-1), so c[m] = sum_i h[i] * (1-h[i-s]) for valid i.

When we change h[i] from a to b (so Δh[i] = b-a) and h[j] from b to a (Δh[j] = a-b = -(b-a)):

The change in c[m] (shift s = m-(n-1)):
- Terms where i appears as the first factor: (1-h[i-s]) * Δh[i] = (1-h[i-s]) * (b-a)
- Terms where i appears as the second factor: h[i+s] * (-Δh[i]) = -h[i+s] * (b-a) [if i+s is valid]
- Similarly for j

So Δc[m] = (b-a) * [(1-h[i-s]) - h[i+s] + h[j+s] - (1-h[j-s])] (for valid indices only)

This is O(1) per shift, so O(n) total per swap. Much better than O(n²)!

```python
def correlation_from_h(h, n):
    """Compute the full correlation vector."""
    return np.correlate(h, 1 - h, mode='full') * (2.0 / n)

def swap_delta(h, i, j, n):
    """Compute the change in correlation vector when swapping h[i] and h[j]."""
    a, b = h[i], h[j]
    delta = b - a
    if abs(delta) < 1e-15:
        return np.zeros(2*n-1)
    
    c_new = np.zeros(2*n-1)
    dx = 2.0 / n
    
    # For each shift m (0 to 2n-2), shift s = m - (n-1)
    # The correlation at shift s is sum over valid l of h[l] * (1-h[l-s])
    # Changing h[i] by delta and h[j] by -delta
    
    # Effect on c[m] from changing h[i]:
    # - i appears as "first" factor (h[l] where l=i) when i-s is valid (0 ≤ i-s < n)
    #   Contribution: delta * (1 - h[i-s])
    # - i appears as "second" factor (h[l-s] where l-s=i, so l=i+s) when i+s is valid
    #   Contribution: -delta * h[i+s] (because (1-h[l-s]) changes by -delta, so h[l]*(1-h[l-s]) changes by -delta*h[l])
    
    # Wait, let me be more careful.
    # c[m] = sum_l h[l] * (1 - h[l - s]) where s = m - (n-1)
    # When h[i] changes by delta:
    #   - If i is used as l: term i changes by delta * (1 - h[i-s]) [if i-s in [0,n-1]]
    #   - If i is used as l-s (i.e., l = i+s): term (i+s) changes by h[i+s] * (-delta) [if i+s in [0,n-1]]
    
    # When h[j] changes by -delta:
    #   - If j is used as l: term j changes by -delta * (1 - h[j-s]) [if j-s in [0,n-1]]
    #   - If j is used as l-s (i.e., l = j+s): term (j+s) changes by h[j+s] * delta [if j+s in [0,n-1]]
    
    for m in range(2*n-1):
        s = m - (n + 1 - 2)  # s = m - (n-1)
        val = 0.0
        # i as l
        idx = i - s
        if 0 <= idx < n:
            val += delta * (1.0 - h[idx])
        # i as l-s (l = i+s)
        idx2 = i + s
        if 0 <= idx2 < n:
            val += -delta * h[idx2]
        # j as l
        idx = j - s
        if 0 <= idx < n:
            val += -delta * (1.0 - h[idx])
        # j as l-s (l = j+s)
        idx2 = j + s
        if 0 <= idx2 < n:
            val += delta * h[idx2]
        c_new[m] = val * dx
    
    return c_new
```

Wait, this is still O(n) per swap (looping over all m). But it's O(n) not O(n²), which is a factor of n improvement.

Actually, I can vectorize this:
- For a given shift s, the affected correlations are only at shifts s' = s_i and s_j where:
  - s_i = i - idx for some valid idx (i.e., all s' = i - idx where idx ranges over [0, n-1]... that's all s' from i-(n-1) to i)
  - Similarly for j

So for position i, the affected shifts are s' ∈ [i-(n-1), i] ∩ [-(n-1), n-1]. That's at most n shifts.
For position j, same thing.

So the total number of affected shifts is at most 2n (with some overlap). For each affected shift, the update is O(1).

Let me vectorize:

```python
def apply_swap(h, c_vec, i, j, n):
    """Apply swap h[i]<->h[j] and update c_vec incrementally. Returns new c_vec (modified in place)."""
    a, b = h[i], h[j]
    delta = b - a
    if abs(delta) < 1e-15:
        return
    
    dx = 2.0 / n
    
    # Shorthand
    # c[m] = sum_l h[l] * (1-h[l-s]) * dx, where s = m-(n-1)
    
    # Effect of changing h[i] by delta:
    # For shift s:
    #   - i as first factor (l=i): need i-s in [0,n-1], i.e., s in [i-(n-1), i]
    #     Change: delta * (1-h[i-s]) * dx
    #   - i as second factor (l-s=i, l=i+s): need i+s in [0,n-1], i.e., s in [-(n-1), n-1-i]... wait
    #     Actually l = i+s must be in [0, n-1], so s in [-i, n-1-i]
    #     Change: -delta * h[i+s] * dx
    
    # Let me just loop over the affected shifts
    # Affected shifts from i: s in [i-(n-1), i] (first factor) UNION s in [-i, n-1-i] (second factor)
    # = s in [i-(n-1), max(i, n-1-i)]... this is getting complicated
    
    # Simpler: just iterate over all s in [-(n-1), n-1] and check
    # But that's O(n) which is what we want
    
    # Actually, let's be smart:
    # For position i, the shifts where i matters are:
    #   As first factor: s such that 0 <= i-s < n → i-(n-1) <= s <= i
    #   As second factor: s such that 0 <= i+s < n → -i <= s <= n-1-i
    
    s_min_i_first = max(-(n-1), i-(n-1))
    s_max_i_first = min(n-1, i)
    s_min_i_second = max(-(n-1), -i)
    s_max_i_second = min(n-1, n-1-i)
    
    s_min_j_first = max(-(n-1), j-(n-1))
    s_max_j_first = min(n-1, j)
    s_min_j_second = max(-(n-1), -j)
    s_max_j_second = min(n-1, n-1-j)
    
    # For each relevant shift, update c_vec
    for s in set(range(s_min_i_first, s_max_i_first+1)) | set(range(s_min_i_second, s_max_i_second+1)) | set(range(s_min_j_first, s_max_j_first+1)) | set(range(s_min_j_second, s_max_j_second+1)):
        m = s + (n-1)
        val = 0.0
        # i as first factor
        idx = i - s
        if 0 <= idx < n:
            val += delta * (1.0 - h[idx])
        # i as second factor
        idx2 = i + s
        if 0 <= idx2 < n:
            val += -delta * h[idx2]
        # j as first factor
        idx = j - s
        if 0 <= idx < n:
            val += -delta * (1.0 - h[idx])
        # j as second factor
        idx2 = j + s
        if 0 <= idx2 < n:
            val += delta * h[idx2]
        c_vec[m] += val * dx
    
    h[i], h[j] = b, a
```

This is O(n) per swap (since the union of the four ranges has at most O(n) elements), compared to O(n²) for recomputing the full correlation. That's a significant speedup.

But wait, for n=300, O(n) = 300 vs O(n²) = 90,000. The speedup is 300x. So if a full correlation takes 20μs, an incremental update takes about 67ns. That's very fast.

With this, I can do millions of swap evaluations per second.

Let me now think about the search strategy with this efficient evaluation:

1. **Hill-climbing with swaps**: Try all possible swaps, accept any improvement. Repeat until no improvement.
   - There are (n/2)² = n²/4 ≈ 22,500 possible swaps for n=300
   - Each takes O(n) ≈ 300 operations
   - One full pass: 22,500 * 300 = 6.75 million operations ≈ a few ms
   - We can do thousands of passes in the time budget

2. **First-improvement vs best-improvement**: 
   - First-improvement: accept the first improving swap found
   - Best-improvement: find the best improving swap in each iteration
   - Best-improvement is slower per iteration but converges in fewer iterations

3. **Multi-start**: Try different initial binary sequences

Given the speed of incremental updates, I think the best approach is:
1. Start from parent
2. Snap to binary (round to 0 or 1, then project to feasible)
3. Do exhaustive hill-climbing with swaps (best-improvement)
4. If stuck, try perturbations (flip a few random bits) + re-optimize
5. Also try the continuous version (using L-BFGS)
6. Track the best overall
