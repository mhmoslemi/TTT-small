A much more efficient approach: **use the gradient to guide the pair search**.

The gradient tells us which direction to move. For a pair (i,j), the change in the objective is approximately:
Δf ≈ grad[i] * δ + grad[j] * (-δ) = (grad[i] - grad[j]) * δ

So the best pair to move is the one that maximizes (grad[i] - grad[j]) (for positive δ) or (grad[j] - grad[i]) (for negative δ).

This means I can sort the gradient values and look at pairs with the largest gradient difference! This reduces the search from O(n²) to O(n log n) + checking a few top candidates.

def gradient_guided_pair_search(h, n, deadline, max_iters=5000):
    best_h = h.copy()
    best_c = compute_c5(h, n)

        if time.time() > deadline:
            break

        p = e / e.sum()

        # We want to move δ from j to i where grad[i] < grad[j] (to decrease the objective)
        # Δf ≈ (grad[i] - grad[j]) * δ, so we want grad[i] - grad[j] < 0, i.e., grad[i] < grad[j]
        
        # Sort by gradient
        order = np.argsort(grad)
        # Best pair: i with smallest grad, j with largest grad
        # But we also need 0≤h[i]+δ≤1 and 0≤h[j]-δ≤1
        
        # Try the top few candidates
        found = False

            i = order[rank]  # low gradient (want to increase)
            j = order[n-1-rank]  # high gradient (want to decrease)
