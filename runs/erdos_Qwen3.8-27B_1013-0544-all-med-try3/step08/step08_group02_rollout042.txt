Let me also think about a completely different approach: what if I use a "direct" method that doesn't rely on gradient optimization?

**Idea: Use a linear programming relaxation**

Introduce variables:
- h[i] for i = 0, ..., n-1
- t (the upper bound on all overlaps)
- y[k] = overlap(k) for each shift k

Constraints:
- t ≥ y[k] for all k
- y[k] = sum_{valid i} h[i] * (1-h[i+k]) for all k (QUADRATIC, not linear!)

The quadratic constraint makes this a SOCP or QP, not an LP. But if we fix the product h[i]*(1-h[i+k]), we can linearize...

Actually, for binary h, h[i]*(1-h[i+k]) is determined by the binary values, and the constraint y[k] ≤ t becomes linear in the binary variables. But binary LP is NP-hard in general.

However, we can relax the binary constraint to 0 ≤ h ≤ 1, which gives a non-convex QP (because of the product terms). This is what we're already solving with gradient methods.

**Idea: Use a "copositive" or "semidefinite" relaxation**

The quadratic form h^T A_k h (where A_k depends on shift k) can be relaxed using SDP. But this might be too expensive for n=1000.

**Idea: Use a "parabolic" or "quadratic" approximation**

At the current iterate h*, approximate the overlap as:
overlap(k) ≈ overlap_k(h*) + ∇_h overlap_k(h*)^T (h - h*)

Then solve the linearized minimax:
min t s.t. overlap_k(h*) + g_k^T (h-h*) ≤ t, 0 ≤ h ≤ 1, sum(h) = n/2

This is a linear program! We can solve it efficiently and use it as a subgradient method.

This is essentially the "cutting plane" or "ellipsoid" method for minimax problems. At each iteration:
1. Compute all overlaps and their gradients at the current point
2. Solve the LP to get a new point
3. Project to the feasible set
4. Repeat

The LP has n variables (h[0], ..., h[n-1]) and 2n-1+2 constraints (n-1 overlap constraints + 1 sum constraint + 2n box constraints). For n=1000, that's ~4000 constraints and 1000 variables. This is a moderately sized LP that scipy's linprog or cvxpy can solve.

Let me try a different angle: what if I use the "hammer" method (also known as the "augmenting path" method for graphical games)?

The idea:
1. Start with a feasible h
2. Find the shift k* that achieves the maximum overlap
3. Modify h to reduce the overlap at k* (while maintaining feasibility)
4. Repeat until all overlaps are balanced

Step 3 is the tricky part. To reduce overlap at shift k*, we want to decrease h(x)(1-h(x+k*)) for some x. This means either:
- Decrease h(x) where h(x+k*) is small (already 0 or close to 0)
- Increase h(x+k*) where h(x) is large (already 1 or close to 1)

Both of these moves also affect other shifts' overlaps, so we need to be careful.

    """Compute the change in all overlaps when swapping h[i]=1 to 0 and h[j]=0 to 1."""
    # Shifts go from -(n-1) to n-1, indexed 0 to 2n-2
    shifts = np.arange(-(n-1), n)  # shape (2n-1,)
    
    # h[i+k] is valid when 0 <= i+k < n
    idx_ik = i + shifts  # position in h for h[i+k]
    valid_ik = (idx_ik >= 0) & (idx_ik < n)
    
    # h[i-k] is valid when 0 <= i-k < n
    idx_ik2 = i - shifts  # position in h for h[i-k]
    valid_ik2 = (idx_ik2 >= 0) & (idx_ik2 < n)
    
    # h[j+k] is valid when 0 <= j+k < n
    idx_jk = j + shifts
    valid_jk = (idx_jk >= 0) & (idx_jk < n)
    
    # h[j-k] is valid when 0 <= j-k < n

    valid_jk2 = (idx_jk2 >= 0) & (idx_jk2 < n)

    delta[valid_jk2] -= h[idx_jk2[valid_jk2]]
    
    return delta
