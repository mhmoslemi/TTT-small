assistantfinal**Solution Overview**

The *outgoing* TriMul block can be written as a batched matrix‑multiply  

\[
\text{out}[b,i,j,d] = \sum_{k=0}^{N-1}
   \underbrace{\text{left}[b,i,k,d]}_{\displaystyle L_{b,d}[i,k]}
   \;\underbrace{\text{right}[b,j,k,d]}_{\displaystyle R_{b,d}[j,k]}
   =\;L_{b,d}\;R_{b,d}^{\top}[i,j]
\]

For a fixed batch `b` and hidden‑dimension `d` we only need one GEMM of shape
`(N,N)·(N,N)ᵀ`.  If we flatten the batch and hidden dimension (`M = B·H`) we obtain
`M` *independent* GEMMs of exactly the same size.  The heavy‑weight work is
therefore a *batched GEMM* that can be executed efficiently with a single
Triton kernel.

The rest of the TriMul pipeline (LayerNorms, linear projections, sigmoids,
masking, and the final linear) is cheap compared with the `O(N³)` contraction
and is kept in PyTorch for simplicity.

Key points of the implementation

| Concern | How it is handled |
|---|---|
| **Data layout for the kernel** | `left` / `right` are permuted from `(B,N,N,H)` → `(B,H,N,N)` and made contiguous.  The kernel receives pointers with the stride order `(M,N,N)`. |
| **Precision** | Input tensors are cast to **float16** before the kernel, the dot product is performed in fp16, and the accumulator is kept in **float32** (the default for `tl.dot`).  The result is stored as fp32 and later cast back to fp32 for the remaining PyTorch layers. |
| **Tiling** | Block sizes `(BLOCK_M, BLOCK_N, BLOCK_K) = (128, 128, 64)` were chosen after small experiments on Hopper – they give enough work per thread block to keep the SM busy while fitting in shared memory (2 × 64 × 128 × 2 bytes ≈ 32 KB). |
| **Mask handling** | Masking, gating and the element‑wise multiplication are performed *before* the kernel, so the kernel only sees the already‑masked `left` and `right`. |
| **Launch grid** | `grid = (ceil(N/BLOCK_M), ceil(N/BLOCK_N), M)`.  `M = B*hidden_dim` is the third axis, giving one independent GEMM per `(batch, hidden)` pair. |
| **Memory‑access pattern** | Inside the kernel we load a `BLOCK_M×BLOCK_K` tile of `L` and a `BLOCK_K×BLOCK_N` tile of `Rᵀ` (the original `right` is accessed transposed) and accumulate with `tl.dot`.  Tail masks take care of sizes that are not multiples of the block size. |
| **Correctness** | All linear layers use the supplied weight tensors (no bias).  LayerNorm uses the provided weight/bias tensors.  The final output shape is `[B, N, N, dim]` and has `float32` dtype. |

The code below is a **single, self‑contained Python file** that can be imported
and called as `custom_kernel(data)`.  It conforms to the Triton 3.3.1 API and
targets the NVIDIA H200 (SM 90) architecture.

```python
"""TriMul “outgoing” kernel (AlphaFold‑3 style)

The dominant cost is the 4‑D einsum
    out[b,i,j,d] = Σ_k left[b,i,k,d] * right[b,j,k,d]

For each hidden dimension `d` this is exactly a matrix multiplication
    L = left[b,:, :, d]   (N×N)
    R = right[b,:, :, d]  (N×N)
    out[b,:, :, d] = L @ Rᵀ            (N×N)

We flatten the batch and hidden dimensions:
    M = B * hidden_dim
and compute M independent GEMMs of shape (N×N)·(N×N)ᵀ with a tiled Triton kernel.
All other operations (LayerNorm, linear projections, sigmoids, masking) stay in
PyTorch – they are negligible compared to the O(N³) work.
"""

import torch
import torch.nn.functional as F
import triton
import triton.language as tl


# ----------------------------------------------------------------------
# Triton kernel: batched GEMM (A @ Bᵀ) for many independent (N,N) matrices
# ----------------------------------------------------------------------
@triton.jit
def _trimul_gemm_kernel(
    a_ptr, b_ptr, c_ptr,          # pointers
    N, M,                         # N = seq_len, M = B*hidden
    stride_ah, stride_ai, stride_ak,   # A strides (M,N,N)
    stride_bh, stride_bj, stride_bk,   # B strides (M,N,N)
    stride_ch, stride_ci, stride_cj,   # C strides (M,N,N)
    BLOCK_M: tl.constexpr,
    BLOCK_N: tl.constexpr,
    BLOCK_K: tl.constexpr,
):
    """ Compute C = A @ Bᵀ   where
        A, B, C have shape (M, N, N)
        The kernel processes one (M‑index) slice per program (pid_z). """
    pid_m = tl.program_id(0)      # block row   i
    pid_n = tl.program_id(1)      # block col   j
    pid_z = tl.program_id(2)      # flattened batch * hidden

    # ------------------------------------------------------------------
    # Offsets for the current tile
    # ------------------------------------------------------------------
    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)   # [i0 … i0+BLOCK_M)
    offs_n = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)   # [j0 … j0+BLOCK_N)

    mask_m = offs_m < N
    mask_n = offs_n < N

    # Base pointers for the current (M‑th) matrix pair
    a_batch = a_ptr + pid_z * stride_ah
    b_batch = b_ptr + pid_z * stride_bh
    c_batch = c_ptr + pid_z * stride_ch

    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # ------------------------------------------------------------------
    # Loop over K dimension (the reduction axis)
    # ------------------------------------------------------------------
    for k in range(0, tl.cdiv(N, BLOCK_K)):
        offs_k = k * BLOCK_K + tl.arange(0, BLOCK_K)
        mask_k = offs_k < N

        # A[i, k]   -> (BLOCK_M, BLOCK_K)
        a_ptrs = (
            a_batch
            + offs_m[:, None] * stride_ai
            + offs_k[None, :] * stride_ak
        )
        a = tl.load(a_ptrs, mask=mask_m[:, None] & mask_k[None, :], other=0.0)
        a = a.to(tl.float16)           # fp16 compute

        # Bᵀ[k, j]  -> (BLOCK_K, BLOCK_N)
        # Original B is indexed as B[j, k]; we load it transposed.
        b_ptrs = (
            b_batch
            + offs_k[:, None] * stride_bk          # k axis (row of Bᵀ)
            + offs_n[None, :] * stride_bj          # j axis (col of Bᵀ)
        )
        b = tl.load(b_ptrs, mask=mask_k[:, None] & mask_n[None, :], other=0.0)
        b = b.to(tl.float16)

        # Accumulate dot product (fp16×fp16 → fp32)
        acc += tl.dot(a, b)

    # ------------------------------------------------------------------
    # Write back the result
    # ------------------------------------------------------------------
    c_ptrs = (
        c_batch
        + offs_m[:, None] * stride_ci
        + offs_n[None, :] * stride_cj
    )
    tl.store(c_ptrs, acc, mask=mask_m[:, None] & mask_n[None, :])


# ----------------------------------------------------------------------
# Helper that launches the kernel
# ----------------------------------------------------------------------
def _batched_gemm(left: torch.Tensor, right: torch.Tensor) -> torch.Tensor:
    """
    Batched GEMM for TriMul.
    Arguments:
        left, right – tensors of shape (B, H, N, N) and dtype float16.
    Returns:
        out – tensor of shape (B, H, N, N), dtype float32.
    """
    B, H, N, _ = left.shape
    M = B * H                     # flattened batch*head

    # Flatten the first two dimensions so the kernel sees (M, N, N)
    left_f = left.reshape(M, N, N)
    right_f = right.reshape(M, N, N)

    out = torch.empty_like(left_f, dtype=torch.float32)

    # Strides as int64 (required by Triton)
    stride_ah, stride_ai, stride_ak = left_f.stride()
    stride_bh, stride_bj, stride_bk = right_f.stride()
    stride_ch, stride_ci, stride_cj = out.stride()

    # ------------------------------------------------------------------
    # Tunable block sizes – a good trade‑off for Hopper (SM90)
    # ------------------------------------------------------------------
    BLOCK_M = 128
    BLOCK_N = 128
    BLOCK_K = 64

    grid = (
        triton.cdiv(N, BLOCK_M),   # pid_m
        triton.cdiv(N, BLOCK_N),   # pid_n
        M,                         # pid_z
    )
    _trimul_gemm_kernel[grid](
        left_f, right_f, out,
        N, M,
        stride_ah, stride_ai, stride_ak,
        stride_bh, stride_bj, stride_bk,
        stride_ch, stride_ci, stride_cj,
        BLOCK_M=BLOCK_M,
        BLOCK_N=BLOCK_N,
        BLOCK_K=BLOCK_K,
    )
    return out.reshape(B, H, N, N)


# ----------------------------------------------------------------------
# Main entry point required by the evaluator
# ----------------------------------------------------------------------
def custom_kernel(data):
    """
    Forward pass of the “outgoing” TriMul module.
    The heavy O(N³) contraction is performed by a Triton batched‑GEMM kernel;
    all other ops (LayerNorm, linear projections, sigmoids, mask) are done in
    PyTorch for simplicity.
    """
    input_tensor, mask, weights, config = data
    device = input_tensor.device
    bs, seq_len, _, dim = input_tensor.shape
    hidden_dim = config["hidden_dim"]
    nomask = config.get("nomask", True)

    # ------------------------------------------------------------------
    # 1. Input LayerNorm over last dim (dim)
    # ------------------------------------------------------------------
    norm_w = weights["norm.weight"].to(device)
    norm_b = weights["norm.bias"].to(device)
    x = F.layer_norm(input_tensor, (dim,), weight=norm_w, bias=norm_b)

    # ------------------------------------------------------------------
    # 2. Linear projections: dim -> hidden_dim (no bias)
    # ------------------------------------------------------------------
    left_proj_w = weights["left_proj.weight"].to(device)   # (hidden, dim)
    right_proj_w = weights["right_proj.weight"].to(device)

    left = F.linear(x, left_proj_w)        # (B, N, N, H)
    right = F.linear(x, right_proj_w)

    # ------------------------------------------------------------------
    # 3. Apply mask if it exists
    # ------------------------------------------------------------------
    if not nomask:
        mask = mask.to(device).unsqueeze(-1)   # (B, N, N, 1)
        left = left * mask
        right = right * mask

    # ------------------------------------------------------------------
    # 4. Gating (sigmoid) + element‑wise multiplication
    # ------------------------------------------------------------------
    left_gate_w = weights["left_gate.weight"].to(device)
    right_gate_w = weights["right_gate.weight"].to(device)
    out_gate_w = weights["out_gate.weight"].to(device)

    left_gate = torch.sigmoid(F.linear(x, left_gate_w))
    right_gate = torch.sigmoid(F.linear(x, right_gate_w))
    out_gate = torch.sigmoid(F.linear(x, out_gate_w))

    left = left * left_gate
    right = right * right_gate

    # ------------------------------------------------------------------
    # 5. Prepare tensors for the kernel
    #    Permute to (B, H, N, N) and cast to fp16.
    # ------------------------------------------------------------------
    left_perm = left.permute(0, 3, 1, 2).contiguous().to(torch.float16)
    right_perm = right.permute(0, 3, 1, 2).contiguous().to(torch.float16)

    # ------------------------------------------------------------------
    # 6. Batched GEMM: out = left @ rightᵀ  (per hidden channel)
    #    Result is (B, H, N, N) float32.
    # ------------------------------------------------------------------
    out_perm = _batched_gemm(left_perm, right_perm)   # (B, H, N, N)

    # ------------------------------------------------------------------
    # 7. Back‑to original layout (B, N, N, H)
    # ------------------------------------------------------------------
    out = out_perm.permute(0, 2, 3, 1).contiguous()   # (B, N, N, H)

    # ------------------------------------------------------------------
    # 8. Output LayerNorm (hidden_dim) and out‑gate
    # ------------------------------------------------------------------
    to_out_norm_w = weights["to_out_norm.weight"].to(device)
    to_out_norm_b = weights["to_out_norm.bias"].to(device)

    out = F.layer_norm(out, (hidden_dim,), weight=to_out_norm_w, bias=to_out_norm_b)
    out = out * out_gate

    # ------------------------------------------------------------------
    # 9. Final linear projection back to original dim
    # ------------------------------------------------------------------
    to_out_w = weights["to_out.weight"].to(device)   # (dim, hidden)
    out = F.linear(out, to_out_w)                    # (B, N, N, dim)

    return out.to(torch.float32)
```

**Explanation of the performance choices**

* **Mixed‑precision kernel** – `float16` for the matrix tiles reduces memory bandwidth
  (2 ×  less data) while the accumulation stays in `float32`, preserving numerical
  quality.  On Hopper the tensor cores are fully utilized for `fp16·fp16 → fp32`
  dot products.

* **Block size (128,128,64)** – Each thread block loads `128×64` and `64×128`
  tiles, totaling ~32 KB of shared memory (well within the 64 KB per SM on H200)
  and giving enough arithmetic work to hide latency.

* **Single launch for all heads** – By flattening `(batch, hidden)` into one
  dimension we avoid kernel‑launch overhead and let the hardware schedule many
  independent GEMMs concurrently.

* **Tail handling** – Simple boolean masks (`mask_m`, `mask_n`, `mask_k`) guarantee
  correctness when `N` is not a multiple of the block size (the test suite uses
  256, 512, 768, 1024).

The kernel therefore fulfills the requirement of moving the expensive part of
TriMul into Triton while keeping the overall implementation compact, correct,
and fast on the target H200 accelerator.
