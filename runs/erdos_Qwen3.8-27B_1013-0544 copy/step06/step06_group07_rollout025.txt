def compute_c5(h, n):
    dx = 2.0 / n
    c = np.correlate(h, 1 - h, mode='full')
    return float(np.max(c) * dx)

def compute_corr(h):
    return np.correlate(h, 1 - h, mode='full')

def lse_gradient(corr, h, n, alpha):
    """Compute gradient of log-sum-exp of alpha*corr*dx"""
    dx = 2.0 / n
    z = alpha * corr * dx
    z_max = z.max()
    exp_z = np.exp(z - z_max)
    w = exp_z / exp_z.sum()  # softmax weights, length 2n-1
    g = 1.0 - 2.0 * h  # length n
    # grad[j] = dx * sum_{t=0}^{n-1} w[j+t] * g[t]
    grad = np.zeros(n)
    for j in range(n):
        grad[j] = dx * np.dot(w[j:j+n], g)
    return grad

def project_h(h, n):
    target = n / 2.0
    h = np.clip(h, 0.0, 1.0)
    for _ in range(100):
        s = h.sum()
        if abs(s - target) < 1e-12:
            break
        diff = target - s
        # Proportional adjustment
        mask_pos = h < 1.0
        mask_neg = h > 0.0
        if diff > 0:
            room = (1.0 - h) * mask_pos
            rsum = room.sum()
            if rsum < 1e-14: break
            h = h + diff / rsum * room
        else:
            room = h * mask_neg
            rsum = room.sum()
            if rsum < 1e-14: break
            h = h + diff / rsum * h
    return np.clip(h, 0.0, 1.0)

But wait, these are the SAME term when i = k-i, i.e., k=2i. In that case, the term is h[i]*(1-h[i]) and its derivative is (1-h[i]) - h[i] = 1-2h[i].

But if we apply the formula: (1-h[k-i]) - h[k-i] with k=2i gives (1-h[i]) - h[i] = 1-2h[i]. Same! ✓

So actually, the formula ∂c[k]/∂h[i] = (1-2h[k-i]) * I(0≤k-i<n) is correct for the continuous case.

But for the binary case where we change h[i] by exactly 1 (from 0 to 1), the actual change is:
Δc[k] = c_new[k] - c_old[k]

Since c[k] is bilinear in h (each term is a product of two h values), the change when h[i] goes from 0 to 1 is:
= (1-h[k-i]) - h[k-i] (if 0≤k-i<n, and k≠2i)
= (1-h[i]) - h[i] = 1-2h[i] (if k=2i)

Wait, for k≠2i (i.e., i ≠ k-i, so the two occurrences of h[i] are in different terms):
The m=i term changes from 0 to (1-h[k-i]): change = 1-h[k-i]
The m=k-i term changes from h[k-i] to 0: change = -h[k-i]
Total: 1-2h[k-i]

For k=2i (same term):
The term h[i]*(1-h[i]) changes from 0 to 0: change = 0.

Wait! h[i]=0, so old term = 0*(1-0) = 0. New: h[i]=1, term = 1*(1-1) = 0. Change = 0!

But the formula gives 1-2h[i] = 1-0 = 1. That's wrong!

So the formula ∂c[k]/∂h[i] = (1-2h[k-i]) is the CONTINUOUS derivative, but for the discrete change (0→1), we need to be more careful.

For k=2i: the term is h[i]*(1-h[i]). 
Old (h[i]=0): 0*(1) = 0
New (h[i]=1): 1*(0) = 0
Change: 0

For k≠2i, 0≤k-i<n:
Change = (1-h[k-i]) - h[k-i] = 1-2h[k-i]

So: E[i][k] = (1-2h[k-i]) if 0≤k-i<n and k≠2i, else 0.

Let me verify with the example: i=0, h=[0,1,0], n=3.
E[0][k] for k=0,1,2,3,4:
k=0: k-i=0, k=2i=0. So k=2i, E[0][0]=0.
k=1: k-i=1, k≠2i. E[0][1]=1-2h[1]=1-2=-1.
k=2: k-i=2, k≠2i. E[0][2]=1-2h[2]=1-0=1.
k=3: k-i=3, invalid (≥n). E[0][3]=0.
k=4: k-i=4, invalid. E[0][4]=0.

So E[0] = [0, -1, 1, 0, 0].

Similarly for j=1, E[1][k]:
k=0: k-j=-1, invalid. E[1][0]=0.
k=1: k-j=0, k=2j=2? No, k=1≠2. E[1][1]=1-2h[0]=1-0=1.
k=2: k-j=1, k=2j=2. So k=2j, E[1][2]=0.
k=3: k-j=2, k≠2j. E[1][3]=1-2h[2]=1-0=1.
k=4: k-j=3, invalid. E[1][4]=0.

So E[1] = [0, 1, 0, 1, 0].

Now, the total change for swapping i=0 (0→1) and j=1 (1→0):
We add E[0] (for h[0] going 0→1) and subtract E[1] (for h[1] going 1→0).

But wait, we need to be careful: when we change h[0] to 1, the "E[1]" should be computed with the NEW h[0]=1, not the old h[0]=0. And vice versa.

The interaction: E[0] is computed assuming h[1]=1 (old), and E[1] is computed assuming h[0]=0 (old). But in reality, both change simultaneously.

The interaction term: when computing the change in c[k] due to h[0] going 0→1, we used h[1]=1 in the formula (1-2h[k-0]). But if k-0=1, i.e., k=1, then the formula used h[1]=1. But h[1] is also changing to 0!

So we need a correction for the interaction. The interaction happens when k-i=j (i.e., k=i+j) or k-j=i (same condition).

At k=i+j=1:
E[0][1] = 1-2h[1] = 1-2(1) = -1 (using old h[1]=1)
But the actual change should use h_new[1]=0: the term (1-h_new[1]) = 1, not (1-h_old[1]) = 0.
And the term -h_new[1] = 0, not -h_old[1] = -1.
So actual change at k=1 from h[0]: 1+0 = 1, but formula gives -1. Difference = +2.

Similarly, E[1][1] = 1-2h[0] = 1-2(0) = 1 (using old h[0]=0)
But actual: (1-h_new[0]) = 0 (since h_new[0]=1), and -h_new[0] = -1.
So actual change at k=1 from h[1] going 1→0: 0+(-1) = -1, but formula gives +1. Difference = -2.

Total correction at k=i+j: +2 + (-2) = 0? That doesn't seem right.

Let me just compute the total Δc[1] directly:
Old c[1] = h[0]*(1-h[1]) + h[1]*(1-h[0]) = 0*0 + 1*1 = 1
New c[1] = h_new[0]*(1-h_new[1]) + h_new[1]*(1-h_new[0]) = 1*1 + 0*0 = 1
Δc[1] = 0.

Using E[0][1] - E[1][1] = -1 - 1 = -2.
Actual is 0. So correction needed: +2.

So the total formula is:
Δc[k] = E[i][k] - E[j][k] + correction

where correction at k=i+j is +2 (when i≠j and 0≤k-i<n and 0≤k-j<n).

Wait, let me also check: is there a correction when k=2i or k=2j?

At k=2i: E[i][2i] = 0 (by our special case). Is there an interaction?
The term at m=i in c[2i] is h[i]*(1-h[i]). Changing h[i] from 0 to 1 doesn't change this term (both give 0).
But does changing h[j] affect it? Only if j=i (impossible) or if h[j] appears in the term h[i]*(1-h[i]) - it doesn't (the term only involves h[i]).
So no correction needed at k=2i. ✓

At k=2j: Similarly, no correction needed. ✓

So the final formula:
Δc[k] = E[i][k] - E[j][k] + 2*I(k=i+j)

where E[i][k] = (1-2h[k-i]) if 0≤k-i<n and k≠2i, else 0.

Let me verify all k for the example:
i=0, j=1, h=[0,1,0]

k=0: E[0][0]=0, E[1][0]=0, correction: 0*I(0=1)=0. Δ=0. ✓
k=1: E[0][1]=-1, E[1][1]=1, correction: 2*I(1=1)=2. Δ=-1-1+2=0. ✓
k=2: E[0][2]=1, E[1][2]=0, correction: 2*I(2=1)=0. Δ=1-0+0=1. ✓
k=3: E[0][3]=0, E[1][3]=1, correction: 0. Δ=0-1+0=-1. ✓
k=4: E[0][4]=0, E[1][4]=0, correction: 0. Δ=0. ✓

The formula works.

Now, for efficient computation:
- E[i] can be precomputed for all i in O(n²) total (each E[i] has at most n nonzero entries)
- The swap delta is then: delta = E[i] - E[j] + 2*e_{i+j} (where e_k is the unit vector at position k)

This makes each swap evaluation O(1) after precomputation!

But E[i] depends on h, so we need to recompute it whenever h changes. Recomputing all E[i] is O(n²) which is fine.

Actually, we can be even smarter. When we perform a swap (i goes 0→1, j goes 1→0), only E[i] and E[j] change (and the correction term changes). All other E[m] are unchanged because they depend on h[k-m] for k-m ≠ i,j (since h only changed at positions i and j).

Wait, E[m][k] = (1-2h[k-m]) if 0≤k-m<n and k≠2m. This depends on h at position k-m. If k-m = i or k-m = j, then E[m][k] changes.

So E[m] changes for all m where there exists k such that k-m = i or k-m = j, i.e., for all m (since k = m+i and k = m+j are always valid for some k).

So actually all E[m] can change. But the change is small: for E[m], only the entries where k-m=i (i.e., k=m+i) and k-m=j (i.e., k=m+j) change.

So after a swap, we update:
- E[m][m+i]: was (1-2h_old[i]), now (1-2h_new[i]) = (1-2*1) = -1 (was 1-2*0=1 if h[i] was 0)
  Change: -2
- E[m][m+j]: was (1-2h_old[j]), now (1-2h_new[j]) = (1-2*0) = 1 (was 1-2*1=-1 if h[j] was 1)
  Change: +2

So for each m, we update at most 2 entries of E[m]. Total updates: O(n).

This gives us an efficient incremental approach:
1. Precompute all E[m] in O(n²)
2. For each swap evaluation: O(1) (just E[i][k] - E[j][k] + 2*correction)
3. After performing a swap: update E in O(n)

This means a full pass over all O(n²/4) swaps costs O(n²/4 * O(1)) = O(n²) for evaluation, plus O(n) for the update. For n=250, that's about 15,625 evaluations per pass, which is very fast!

Let me now design a better algorithm using this efficient swap evaluation:

def compute_E(h, n):
    """Precompute E[i][k] for all i, k"""
    E = np.zeros((n, 2*n-1))
    for i in range(n):
        for k in range(n):  # k-i ranges from 0 to n-1
            kk = i + k  # this is the shift index
            if kk < 2*n-1 and kk != 2*i:
                E[i][kk] = 1 - 2*h[k]
    return E

```python
def compute_E(h, n):
    E = np.zeros((n, 2*n-1))
    for i in range(n):
        for dk in range(n):  # dk = k - i, ranges 0 to n-1
            k = i + dk
            if k < 2*n-1 and k != 2*i:
                E[i][k] = 1.0 - 2.0*h[dk]
    return E
```

Then for a swap of position i (0→1) and position j (1→0):
delta[k] = E[i][k] - E[j][k] + 2.0 * (1.0 if k == i+j and i+j < 2*n-1 else 0.0)

And to update E after the swap:
- h[i] changed from 0 to 1, h[j] changed from 1 to 0
- For each m in 0..n-1:
  - E[m][m+i]: if m+i < 2n-1 and m+i != 2m (i.e., i != m), change by (1-2*1)-(1-2*0) = -2
    Wait: h[i] went from 0 to 1, so h[dk] where dk=i changes from 0 to 1.
    E[m][m+i] = 1-2*h[i] changes from 1-0=1 to 1-2=-1. Change: -2.
    But only if m+i < 2n-1 and m+i != 2m (i.e., i≠m).
  - E[m][m+j]: h[j] went from 1 to 0, so h[dk] where dk=j changes from 1 to 0.
    E[m][m+j] = 1-2*h[j] changes from 1-2=-1 to 1-0=1. Change: +2.
    But only if m+j < 2n-1 and m+j != 2m (i.e., j≠m).

So the update is: for each m:
  if m+i < 2n-1 and m != i: E[m][m+i] -= 2
  if m+j < 2n-1 and m != j: E[m][m+j] += 2

This is O(n) per swap.
