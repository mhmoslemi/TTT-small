```python
    dx = 2.0 / n
    grad = np.zeros(n)
    for k_idx in range(2*n-1):
        wk = w[k_idx]
        if wk < 1e-15: continue
        k = k_idx - (n-1)

        else:

                grad[:n-k] += wk * (1 - h[k:])

                grad[k:] -= wk * h[:n-k]
            else:  # k < 0

                # j from 0 to n-1-lk: subtract h[j+lk]  (because j-k = j+lk, and we subtract h[j-k])

                #   Wait: j+k = j+(-lk) = j-lk. For this to be in [0,n): 0 ≤ j-lk < n, so lk ≤ j < n+lk, but j < n, so lk ≤ j < n.

                # Add (1-h[j+k]) = (1-h[j-lk]) for j in [lk, n)
                # Subtract h[j-k] = h[j+lk] for j in [0, n-lk)
                grad[lk:] += wk * (1 - h[:n-lk])  # (1-h[j-lk]) for j=lk..n-1, h[j-lk] = h[0..n-1-lk]
                grad[:n-lk] -= wk * h[lk:]  # h[j+lk] for j=0..n-1-lk
```

```python
    vb = (mk >= 0) & (mk < n) & (ks != 0)
    a = np.zeros(2*n-1)
    a[vf] += 1.0 - h[pk[vf]]  # Note: h has already been updated at p
    # Wait, we need to be careful. After updating h[p], the a_k values change
    # because h[p+k] or h[p-k] might be h[p] if k=0... but we excluded k=0.
    # For k≠0, p+k ≠ p and p-k ≠ p, so a_k doesn't depend on h[p].
    # So we can use the current h (with h[p] = new_val) to compute a_k.
    a[vb] -= h[mk[vb]]
    c = c + delta * a
    # Diagonal: c_0 changes by (new_val*(1-new_val) - old_val*(1-old_val))
    c[n-1] += new_val*(1-new_val) - old_val*(1-old_val)
    return c
```

Wait, but h has already been updated (h[p] = new_val). The a_k for k≠0 depends on h[p+k] and h[p-k], which are not h[p] (since k≠0). So they're correct.

But wait, for the "forward" part (1-h[p+k]), if p+k = p, that would be a problem, but k≠0 so p+k≠p. Good.

For the "backward" part (h[p-k]), if p-k = p, that would be a problem, but k≠0 so p-k≠p. Good.

So the incremental update is correct. This makes each CD step O(n) instead of O(n²), and each pass O(n²) instead of O(n³).
