```python
def active_set_grad(h, n, tol=0.01):
    c = np.correlate(h, 1-h, mode='full')
    m = c.max()
    active = np.flatnonzero(c >= m - tol)
    p = np.zeros(2*n-1)
    p[active] = 1.0 / len(active)
    # Compute gradient
    off = n - 1
    g = np.zeros(n)
    for k in active:
        d = k - off
        if d >= 0:
            # dc/dh[j] = (1-h[j+d])*[j<=n-1-d] - h[j-d]*[j>=d]
            g[:n-d] += p[k] * (1.0 - h[d:])
            if d > 0:
                g[d:] -= p[k] * h[:n-d]
        else:
            e = -d
            g[e:] += p[k] * (1.0 - h[:n-e])
            if e > 0:
                g[:n-e] -= p[k] * h[e:]
    return (2.0/n) * g, active, m
```

def compute_c5(h, n):
    c = np.correlate(h, 1.0 - h, mode='full')
    return float(c.max()) * 2.0 / n

def project_feasible(z, n):
    z = np.asarray(z, dtype=float)
    z = np.nan_to_num(z, nan=0.5, posinf=1.0, neginf=0.0)
    z = np.clip(z, 0.0, 1.0)
    target = 0.5 * n
    if abs(z.sum() - target) < 1e-12:
        return z
    lo, hi = -2.0, 3.0
    for _ in range(60):
        mid = 0.5 * (lo + hi)
        s = np.clip(z - mid, 0.0, 1.0).sum()
        if s > target:
            lo = mid
        else:
            hi = mid
    y = np.clip(z - 0.5*(lo+hi), 0.0, 1.0)
    res = target - y.sum()
    if abs(res) > 1e-10:
        if res > 0:
            mask = y < 1.0
            room = 1.0 - y
        else:
            mask = y > 0.0
            room = y
        tot = room[mask].sum()
        if tot > 1e-12:
            y[mask] += (res/tot) * room[mask]
    return np.clip(y, 0.0, 1.0)

def softmax_components(h, n, alpha):
    c = np.correlate(h, 1.0 - h, mode='full')
    m = float(c.max())
    z = alpha * (c - m)
    e = np.exp(z - z.max())
    s = e.sum()
    p = e / s
    return (m + np.log(s)/alpha) * (2.0/n), p, c

def softmax_grad(h, n, alpha):
    _, p, _ = softmax_components(h, n, alpha)
    return weighted_grad(h, n, p)

def weighted_grad(h, n, p):
    off = n - 1
    g = np.zeros(n)
    for k in range(2*n - 1):
        w = p[k]
        if w < 1e-14:
            continue
        d = k - off
        if d >= 0:
            g[:n-d] += w * (1.0 - h[d:])
            if d > 0:
                g[d:] -= w * h[:n-d]
        else:
            e_ = -d
            g[e_:] += w * (1.0 - h[:n-e_])
            if e_ > 0:
                g[:n-e_] -= w * h[e_:]
    return (2.0/n) * g

def sd_step(h, n, alpha, max_iter=200, deadline=None):
    """Steepest descent with adaptive softmax."""
    best = h.copy()
    best_c = compute_c5(best, n)
    x = h.copy()
    step = 0.01
    for it in range(max_iter):
        if deadline is not None and time.time() > deadline:
            break
        val, p, c = softmax_components(x, n, alpha)
        g = weighted_grad(x, n, p)
        # Project gradient: only move in directions that maintain feasibility
        # Use backtracking line search
        for _ in range(30):
            xn = np.clip(x - step * g, 0.0, 1.0)
            xn = project_feasible(xn, n)
            cn = compute_c5(xn, n)
            if cn < best_c:
                best = xn.copy()
                best_c = cn
                x = xn
                step = min(step * 1.2, 0.1)
                break
            step *= 0.7
        else:
            break
    return best, best_c

For the coordinate descent: at each step, pick an index i, and find the optimal h[i] value (treating all other h[j] as fixed, and using a Lagrange multiplier for the sum constraint). The optimal h[i] minimizes max_k c[k] where c[k] depends on h[i] linearly (through the terms involving h[i]).

Actually, c[k] is linear in h[i] for fixed other coordinates (since c[k] = sum_j h[j]*(1-h[j+k]) and h[i] appears in at most 2 terms for each k). So the problem of finding the optimal h[i] is:

minimize max_k (c[k] + h[i] * g_i[k])
over h[i] ∈ [0,1]

where g_i[k] is the coefficient of h[i] in c[k].

This is a 1D minimax problem! The function max_k (c[k] + t * g_i[k]) is convex in t (max of linear functions), so we can find the minimum by finding where the "upper envelope" is minimized. This can be done in O((2n-1) log(2n)) time.

This is a very efficient approach! Each coordinate update is O(n log n), and we can do many updates quickly.

For each i, try h[i] → t for t in {h[i]-0.1, h[i]-0.05, h[i]+0.05, h[i]+0.1} (clipped to [0,1]), and adjust h[j] for the "least important" j (the one where changing it the least affects the max correlation).

Actually, the simplest effective approach is: for each i, compute the "cost" of changing h[i] to t (which is the change in max correlation), and pick the best t. To maintain the sum constraint, spread the adjustment over all other coordinates.

import numpy as np
import time
from scipy.optimize import minimize

def compute_c5(h, n):
    return float(np.max(np.correlate(h, 1.0-h, mode='full'))) * 2.0 / n

def project_feasible(z, n):
    z = np.clip(np.nan_to_num(z, nan=0.5, posinf=1.0, neginf=0.0), 0.0, 1.0)
    target = 0.5 * n
    if abs(z.sum() - target) < 1e-10:
        return z
    lo, hi = -2.0, 3.0
    for _ in range(60):
        mid = 0.5*(lo+hi)
        if np.clip(z-mid, 0.0, 1.0).sum() > target:
            lo = mid
        else:
            hi = mid
    y = np.clip(z - 0.5*(lo+hi), 0.0, 1.0)
    res = target - y.sum()
    if abs(res) > 1e-10:
        mask = y < 1.0 if res > 0 else y > 0.0
        room = (1.0-y) if res > 0 else y
        tot = room[mask].sum()
        if tot > 1e-12:
            y[mask] += (res/tot) * room[mask]
    return np.clip(y, 0.0, 1.0)

def softmax_obj(h, n, alpha):
    c = np.correlate(h, 1.0-h, mode='full')
    m = c.max()
    z = alpha*(c-m)
    e = np.exp(z-z.max())
    return (m + np.log(e.sum())/alpha) * 2.0/n

def softmax_grad(h, n, alpha):
    c = np.correlate(h, 1.0-h, mode='full')
    m = c.max()
    z = alpha*(c-m)
    e = np.exp(z-z.max())
    p = e/e.sum()
    off = n-1
    g = np.zeros(n)
    for k in range(2*n-1):
        w = p[k]
        if w < 1e-14: continue
        d = k - off
        if d >= 0:
            g[:n-d] += w*(1.0-h[d:])
            if d>0: g[d:] -= w*h[:n-d]
        else:
            e_ = -d
            g[e_:] += w*(1.0-h[:n-e_])
            if e_>0: g[:n-e_] -= w*h[e_:]
    return (2.0/n)*g

def slsqp_opt(h, n, alphas, max_iters, deadline):
    best_h, best_c = h.copy(), compute_c5(h, n)
    bounds = [(0.0,1.0)]*n
    cons = [{'type':'eq', 'fun': lambda x: x.sum()-0.5*n, 'jac': lambda x: np.ones(n)}]
    x = h.copy()
    for alpha in alphas:
        if time.time() > deadline: break
        try:
            res = minimize(softmax_obj, x, args=(n,alpha), method='SLSQP',
                          jac=softmax_grad, bounds=bounds, constraints=cons,
                          options={'maxiter':max_iters, 'ftol':1e-14})
            x = project_feasible(res.x, n)
            c = compute_c5(x, n)
            if c < best_c: best_h, best_c = x, c
        except: pass
    return best_h, best_c

def pair_search(h, n, max_moves, deadline):
    h = h.copy()
    c = np.correlate(h, 1-h, mode='full')
    off = n-1
    rng = np.random.RandomState(int(sum(h)*1000) % 10000)
    moves = 0
    for _ in range(max_moves):
        if time.time() > deadline: break
        cur_max = c.max()
        # Pick active lag
        tol = 0.01 * cur_max
        active = np.flatnonzero(c >= cur_max - tol)
        k = active[rng.randint(len(active))]
        d = k - off
        if d >= 0:
            m = n - d
            if m <= 0: continue
            j = rng.randint(m)
            i = j + d
        else:
            e_ = -d
            m = n - e_
            if m <= 0: continue
            i = e_ + rng.randint(m)
            j = i - e_
        # Find optimal delta: h[i]+=delta, h[j]-=delta
        # c changes linearly in delta
        # Compute the effect
        # For each lag k', dc[k']/ddelta = g_i[k'] - g_j[k']
        # This is complex, so use bisection on delta
        lo, hi = -min(h[i], 1-h[j]), min(1-h[i], h[j])
        if hi - lo < 1e-10: continue
        for _ in range(40):
            mid = 0.5*(lo+hi)
            # Evaluate max(c + mid * (g_i - g_j))
            # But computing this for all k is O(n)
            # For speed, just evaluate at the active lags
            # Actually, let's just do a simple bisection
            h[i] += mid; h[j] -= mid
            new_c = np.correlate(h, 1-h, mode='full')
            h[i] -= mid; h[j] += mid
            if new_c.max() < c.max():
                lo = mid
            else:
                hi = mid
        # Apply best delta
        delta = 0.5*(lo+hi)
        h[i] += delta; h[j] -= delta
        h = np.clip(h, 0.0, 1.0)
        c = np.correlate(h, 1-h, mode='full')
        moves += 1
    h = project_feasible(h, n)
    return h, compute_c5(h, n)

def interp_h(h, m):
    n = len(h)
    if n == m: return project_feasible(h.copy(), m)
    xo = np.linspace(0, 2, n, endpoint=False)
    xn = np.linspace(0, 2, m, endpoint=False)
    return project_feasible(np.interp(xn, xo, h), m)

Wait, I realize the pair search with full np.correlate at each bisection step is O(n) per step, and 40 bisection steps × n moves = 40n × n = 40n² operations. For n=500, that's 40×250000 = 10 million per move. With 10000 moves, that's 100 billion. Way too slow!

I need to make the pair search faster. The key is to compute the effect of a pair move on c without recomputing the full correlation.

When we change h[i] by +δ and h[j] by -δ, the change in c[k] is:
Δc[k] = δ * [(1-h[i+d_k]) * [i+d_k valid] - h[i-d_k] * [i-d_k valid and d_k≠0] 
              - (1-h[j+d_k]) * [j+d_k valid] + h[j-d_k] * [j-d_k valid and d_k≠0]]

where d_k = k - (n-1).

This can be precomputed as a vector A_pair[k] = g_i[k] - g_j[k] for each k.

Then c_new[k] = c[k] + δ * A_pair[k], and we want to find δ that minimizes max_k (c[k] + δ * A_pair[k]).

This is a 1D convex minimization problem (max of linear functions). We can solve it efficiently!

The function f(δ) = max_k (c[k] + δ * A[k]) is convex and piecewise linear. Its minimum is at a point where at least two "active" lines cross,

or at a boundary. We can find it by:
1. Computing all breakpoints: δ_k = -c[k]/A[k] for A[k] ≠ 0
2. Sorting the breakpoints
3. Evaluating f(δ) at each breakpoint (or using a sweep)

But with 2n-1 lines, this is O(n log n) per pair move, which gives O(n² log n) total for n moves. For n=500, that's about 500² × 9 = 2.25 million, which is fast!

Actually, a simpler approach: since f(δ) is convex, we can use ternary search over δ ∈ [lo, hi]. Each evaluation of f(δ) is O(n) (compute c + δ*A, take max). With 50 iterations of ternary search, that's 50n per move, giving 50n² total. For n=500: 50×250000 = 12.5 million. That's fine!
