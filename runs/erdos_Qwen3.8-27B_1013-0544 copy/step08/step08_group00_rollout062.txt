Let me also think about a completely different approach: **use the structure of the problem more directly**.

The key observation is that we're minimizing max_k c_k where c_k = ∑_i h_i(1-h_{i+k}).

At the optimum, by the KKT conditions (informally), the subgradient of the max should be in the normal cone of the constraint set. This means:
- The active set (k values where c_k = max) determines the gradient
- The gradient of c_k with respect to h_i is: (1-h_{i+k}) - h_{i-k} (with appropriate boundary handling)

So at the optimum: for all i with 0 < h_i < 1, we need ∑_{k active} [(1-h_{i+k}) - h_{i-k}] = λ (the Lagrange multiplier for the sum constraint).

This gives us a system of equations we can try to solve iteratively (like a fixed-point iteration).

**Fixed-point / iterative approach:**
1. Start with some h
2. Compute c_k and find the active set (top few k values)
3. For each i with 0 < h_i < 1, compute the "pressure" = ∑_{k active} [(1-h_{i+k}) - h_{i-k}]
4. Update h_i to try to equalize the pressure across all free i's
5. Project to [0,1] and fix the sum
6. Repeat

This is similar to the "water-filling" algorithm used in resource allocation.

    grid = np.linspace(0.0, 1.0, n_grid)  # (G,)

        a[vb] -= h[jb[vb]]

def solve_1d_exact(c, h, p, n):
    """Find the x = h[p] that minimizes max_m c_m(x), given all other h fixed.
    Uses bisection on the target level L."""
    h0 = h[p]
    m_lo = max(0, n-1-p, p)
    m_hi = min(2*n-2, n-1+p)
    if m_lo > m_hi:
        return h0
    
    ms = np.arange(m_lo, m_hi+1)
    off = ms - (n-1)
    jf = p + off
    jb = p - off
    
    a = np.zeros(len(ms))
    vf = (jf >= 0) & (jf < n)
    vb = (jb >= 0) & (jb < n)
    a[vf] += (1.0 - h[jf[vf]])
    a[vb] -= h[jb[vb]]
    
    # For off==0 (m=n-1): c_m(x) = c[m] + (x-h0)*(1-x-h0)
    # For off!=0: c_m(x) = c[m] + (x-h0)*a[idx]
    
    unaff = 0.0
    if m_lo > 0: unaff = max(unaff, float(np.max(c[:m_lo])))
    if m_hi < 2*n-2: unaff = max(unaff, float(np.max(c[m_hi+1:])))
    
    L_lo = unaff
    L_hi = float(np.max(c))  # current value at x=h0
    
    for _ in range(50):
        if L_hi - L_lo < 1e-15: break
        L = 0.5 * (L_lo + L_hi)
        # Check if feasible: ∃x ∈ [0,1] s.t. all c_m(x) ≤ L
        x_lo, x_hi = 0.0, 1.0

        lin_mask = (off != 0)

            c_lin = c[ms[lin_mask]]
            # c_m + (x-h0)*a_m ≤ L → x ≤ (L-c_m)/a_m + h0 (if a_m > 0)
            #                           x ≥ (L-c_m)/a_m + h0 (if a_m < 0)
            pos = a_lin > 1e-14
            neg = a_lin < -1e-14
            if np.any(pos):

            if np.any(neg):

            zero = np.abs(a_lin) <= 1e-14

                ok = False

        quad_mask = (off == 0)

            # c_q + (x-h0)*(1-x-h0) ≤ L

            # t² - (1-h0)t + (L-c_q) ≥ 0

                ok = False

                r2 = (b_c + sq) / 2.0  # larger root
                # Need t ≤ r1 or t ≥ r2
                # i.e., x ≤ h0+r1 or x ≥ h0+r2
                excl_lo = h0 + r1
                excl_hi = h0 + r2
                # Feasible x: [0,1] ∩ ((-∞, excl_lo] ∪ [excl_hi, +∞))
                # = [0, min(excl_lo, 1)] (if excl_lo > 0) ∪ [max(excl_hi, 0), 1] (if excl_hi < 1)
                # Check if [x_lo, x_hi] has any point in this set
                # Case 1: x_hi ≤ excl_lo → [x_lo, x_hi] is feasible (intersection with [0, min(excl_lo,1)])
                # Case 2: x_lo ≥ excl_hi → [x_lo, x_hi] is feasible
                # Case 3: x_lo < excl_lo and x_hi > excl_hi → need to check if either sub-interval is non-empty
                #   [x_lo, min(excl_lo, x_hi)] or [max(excl_hi, x_lo), x_hi]
                if x_hi <= excl_lo + 1e-12 or x_lo >= excl_hi - 1e-12:
                    # Entire [x_lo, x_hi] is feasible (or partially)
                    # But we need to tighten:
                    # If x_hi <= excl_lo: x_hi stays the same (or tighten to excl_lo)
                    # If x_lo >= excl_hi: x_lo stays the same
                    # If both: no change needed
                    pass
                else:
                    # x_lo < excl_lo and x_hi > excl_hi
                    # Feasible: [x_lo, excl_lo] ∪ [excl_hi, x_hi]
                    # Both non-empty since x_lo < excl_lo and excl_hi < x_hi
                    # But we can't represent this as a single interval for the bisection
                    # Solution: just check feasibility (both sub-intervals non-empty)
                    # For the bisection, we just need to know if feasible or not
                    pass
        # 
        # The issue: with the quadratic constraint, the feasible set might be two intervals.
        # For the bisection to work, I just need to know if the feasible set is non-empty.
        # Above, I check:
        #   - Linear constraints give [x_lo, x_hi]
        #   - Quadratic constraint excludes (excl_lo, excl_hi)
        #   - Feasible = [x_lo, x_hi] \ (excl_lo, excl_hi) ≠ ∅
        #   - This is true if: min(x_hi, excl_lo) ≥ x_lo OR max(x_lo, excl_hi) ≤ x_hi
        #     i.e., x_lo ≤ excl_lo AND x_hi ≥ x_lo (first piece) OR x_lo ≤ x_hi AND excl_hi ≤ x_hi (second piece)
        #     Simplified: (x_lo ≤ excl_lo AND x_lo ≤ x_hi) OR (excl_hi ≤ x_hi AND x_lo ≤ x_hi)
        #     Since x_lo ≤ x_hi is already checked:
        #     = (x_lo ≤ excl_lo) OR (excl_hi ≤ x_hi)
        
        if ok:
            if np.any(quad_mask):
                # Already handled above in the else case
                # Re-check: feasible if (x_lo ≤ excl_lo) or (excl_hi ≤ x_hi)
                # (which should always be true since x_lo=0 ≤ excl_lo=h0+r1 < 1 and excl_hi=h0+r2 > 0)
                # Wait, not always. Let me re-derive.
                # excl_lo = h0 + r1, excl_hi = h0 + r2
                # r1 < r2 always (since sq > 0 when disc > 0)
                # r1 + r2 = b_c = 1-h0
                # r1*r2 = rhs = L - c_q
                # If L < c_q (rhs < 0): r1 < 0 < r2, so excl_lo < h0 < excl_hi
                #   Feasible: x ≤ excl_lo or x ≥ excl_hi
                #   [x_lo, x_hi] \ (excl_lo, excl_hi) is non-empty iff x_lo ≤ excl_lo or x_hi ≥ excl_hi
                #   Since x_lo=0 and excl_lo = h0+r1: if r1 > -h0, excl_lo > 0, so x_lo=0 ≤ excl_lo ✓
                #   If r1 ≤ -h0, excl_lo ≤ 0, so the exclusion starts before 0, and [x_lo,x_hi] is fully feasible ✓
                # So actually for the quadratic, it's always feasible as long as the linear constraints are feasible?
                # Not quite - if r1 is very close to -h0 from above, excl_lo is very close to 0,
                # and if x_lo is also close to 0 but > excl_lo... but x_lo starts at 0.
                # I think for practical purposes, the quadratic constraint is not binding
                # when the linear constraints are already tight.
                pass
        
        if ok:
            L_hi = L
        else:
            L_lo = L
    
    # At L = L_hi (feasible), find the x that achieves c_m(x) ≤ L for all m
    # Use the linear constraints to find [x_lo, x_hi], then pick the midpoint (or the point
    # that minimizes the max)
    x_lo, x_hi = 0.0, 1.0
    lin_mask = (off != 0)
    if np.any(lin_mask):
        a_lin = a[lin_mask]
        c_lin = c[ms[lin_mask]]
        pos = a_lin > 1e-14
        neg = a_lin < -1e-14
        if np.any(pos):
            x_hi = min(x_hi, float(np.min((L_hi - c_lin[pos]) / a_lin[pos] + h0)))
        if np.any(neg):
            x_lo = max(x_lo, float(np.max((L_hi - c_lin[neg]) / a_lin[neg] + h0)))
    x_lo = max(x_lo, 0.0)
    x_hi = min(x_hi, 1.0)
    
    # Also check quadratic
    quad_mask = (off == 0)
    if np.any(quad_mask):
        qi = np.where(quad_mask)[0][0]
        c_q = c[ms[qi]]
        rhs = L_hi - c_q
        b_c = (1.0 - h0)
        disc = b_c*b_c - 4.0*rhs
        if disc >= 0:
            sq = np.sqrt(disc)
            r1 = (b_c - sq) / 2.0
            r2 = (b_c + sq) / 2.0
            excl_lo = h0 + r1
