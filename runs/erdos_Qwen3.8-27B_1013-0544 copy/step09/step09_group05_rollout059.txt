- Rejecting a step that would actually improve c

To handle this, I'll recompute the full correlation every 5-10 passes.

Let me also think about whether there's a fundamentally better approach.

**Alternative approach: Use the structure of the problem.**

The problem has a lot of symmetry. The function h is defined on [0,2], and the shifts k range over roughly [-2, 2]. The key observation is:

For the discrete problem with n points, the correlation has 2n-1 lags. The constraint is that the maximum of these 2n-1 values (times dx) should be minimized.

This is a min-max problem. We can think of it as:
minimize t
subject to: c[k] * dx ≤ t for all k
           0 ≤ h[i] ≤ 1 for all i
           sum(h) = n/2

This is a non-linear program (because c[k] is quadratic in h). But we can solve it iteratively:
1. Fix t, check feasibility (is there an h satisfying all constraints?)
2. Binary search on t

The feasibility check is:
c[k] ≤ t/dx for all k (where c[k] = sum_i h[i]*(1-h[i+k-(n-1)]))

This is a system of quadratic inequalities, which is NP-hard in general. But for the specific structure here, we might be able to use the coordinate descent approach as a heuristic.

Actually, the coordinate descent approach IS solving this problem: it's minimizing the max by adjusting one coordinate at a time, keeping the max as low as possible.

Let me now think about what specific improvements to make:

1. **Incremental correlation with periodic recomputation**: This should speed up the coordinate descent significantly.

2. **Adaptive coordinate ordering**: Instead of random or sequential order, order coordinates by their "slack" (how far they are from the boundary [0,1]). Coordinates with more slack can potentially reduce the max more.

3. **Multi-coordinate updates**: Update 2 coordinates at a time. The joint update can be solved as a 2D optimization problem.

4. **Better initialization**: Use a combination of the previous solution and a parametric form.
