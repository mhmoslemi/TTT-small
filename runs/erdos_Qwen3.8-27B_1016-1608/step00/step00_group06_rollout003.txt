    return h_proj

Actually, there's a subtlety: if many elements are at 0 or 1, adding a uniform alpha won't work perfectly. But the bisection on alpha for clip(h+alpha, 0, 1) is correct because:
- alpha → -inf: all h+alpha → 0, sum → 0
- alpha → +inf: all h+alpha → 1, sum → n
- The sum is continuous and monotonically increasing in alpha
So bisection finds the right alpha.

But actually, this gives the projection onto the set {x: x = clip(h+alpha, 0,1) for some alpha, sum(x) = target}. This is NOT the Euclidean projection onto {x: 0≤x≤1, sum(x)=target} in general. The Euclidean projection is more complex.

For our purposes, this "soft projection" is good enough - it maintains feasibility approximately and the optimization will handle the rest.
