```python
        # grad[j] = p[k_star - j] for j in [lo, hi]
        # k_star - j ranges from k_star-hi to k_star-lo
        grad[lo:hi+1] = p[k_star-hi : k_star-lo+1][::-1]
        grad = np.maximum(grad, 1e-15)
        
        # Multiplicative update
        p_new = p / grad
        s_new = p_new.sum()
        if not np.isfinite(s_new) or s_new < 1e-10:
            break
        p_new = p_new / s_new
        
        alpha = 0.5
        p = (1 - alpha) * p + alpha * p_new
    
    return p
```

Actually, you know what, let me think about this from a different angle. The problem is equivalent to:

minimize t
subject to conv(p,p)[k] <= t for all k
sum(p) = 1
p >= 0

This is a convex optimization problem (minimize a scalar t subject to convex quadratic constraints and linear constraints). Wait, is conv(p,p)[k] convex in p?

conv(p,p)[k] = sum_i p[i]*p[k-i]. This is a quadratic form. The Hessian is 2*B_k where B_k is the symmetric matrix with B_k[i,j] = 1 if i+j=k.

For B_k to be positive semidefinite, all eigenvalues must be >= 0. The matrix B_k is a permutation matrix (or half of one), and its eigenvalues are ±1 (or 0). So B_k is NOT positive semidefinite in general!

For example, B_{n-1} (the anti-diagonal) has eigenvalues +1 (with multiplicity ceil(n/2)) and -1 (with multiplicity floor(n/2)). So the quadratic form is NOT convex.

This means the problem is NOT convex. The multiplicative update is a heuristic that works when the problem is "approximately convex" (i.e., near the optimum, the active constraints are "well-behaved").

Despite the non-convexity, I expect the iterative method to work well in practice for this specific problem. The non-convexity comes from the "sign" of the anti-diagonal matrix, which corresponds to the asymmetry of the optimal solution.
