**My final implementation plan:**

1. Start from initial_h_values
2. Run fast coordinate descent (the main workhorse)
3. Add "perturbation" steps: randomly change a few coordinates, then re-run CD
4. Try a few different initial conditions (based on initial_h_values with different perturbations)
5. Multi-resolution: interpolate to different n and optimize
6. Use remaining time for final CD refinement

The key improvement over the previous code:
- Faster CD (use the precomputed A vectors, avoid recomputing them every pass)
- Better perturbation strategy
- More aggressive resolution search
- Time-aware scheduling

Let me code this up now, keeping it concise:

```python
import numpy as np
from scipy.optimize import minimize
import time

def compute_c5(h, n):
    dx = 2.0 / n
    return float(np.max(np.correlate(h, 1.0 - h, mode='full')) * dx)

def project_feasible(h, n):
    target = n / 2.0
    h = np.clip(h.copy(), 0.0, 1.0)
    for _ in range(5000):
        diff = target - h.sum()
        if abs(diff) < 1e-13:
            break
        if diff > 0:
            room = 1.0 - h
            tot = room.sum()
            if tot < 1e-15: break
            h += (diff / tot) * room
        else:
            tot = h.sum()
            if tot < 1e-15: break
            h += (diff / tot) * h
    return np.clip(h, 0.0, 1.0)

def build_A_matrices(h, n):
    """Precompute A[p] = change in c when h[p] increases by 1 (linear part)."""
    A = np.zeros((n, 2*n-1))
    Q = np.zeros((n, 2*n-1))  # quadratic part (only one nonzero per row)
    for p in range(n):
        ep = np.zeros(n)
        ep[p] = 1.0
        A[p] = np.correlate(ep, 1.0-h, mode='full') - np.correlate(h, ep, mode='full')
        Q[p] = np.correlate(ep, ep, mode='full')  # single 1 at the diagonal position
    return A, Q
```

Wait, this precomputation is O(n * 2n) = O(n²) per rebuild, and we need to rebuild after each update. That's too slow for large n.

Better approach: compute A[p] on-the-fly for each p visited, but cache it until h changes significantly.

Actually, the A[p] vector depends on h (specifically, on h[p-k] and h[p+k] for various k). So it changes every time h changes. The previous code computes it on-the-fly using the index cache.

Let me just use the same approach as the previous code for A computation (it's correct), but make the overall algorithm faster.

Key speedup ideas:
1. Instead of golden section (35 iterations), use a ternary search with fewer iterations (the function is unimodal in most cases)
2. Skip coordinates that are at bounds (0 or 1)
3. Use a "warm start" for the 1D search (use the previous t as initialization)
4. Early termination if the max hasn't changed

Let me also think about a completely different approach:

**Approach: Bisection on C₅ with feasibility check**

For a target C₅ = t, we need:
- c[k] * dx ≤ t for all k
- 0 ≤ h[i] ≤ 1
- sum(h) = n/2

This is a feasibility problem. The constraints c[k]*dx ≤ t are quadratic (bilinear) in h.

We could try a "sequential quadratic programming" approach:
1. Start from a feasible point (h=1/2)
2. Linearize the quadratic constraints
3. Solve the resulting QP (or LP)
4. Update and iterate

But this is complex. Let me stick with the coordinate descent approach but make it smarter.

**Alternative: Use scipy's SLSQP directly on the max function**

The function f(h) = max_k c[k]*dx is convex in h (max of linear functions... wait, c[k] is NOT linear in h! c[k] = sum_i h[i](1-h[i+k]) which is bilinear).

So the problem is non-convex. SLSQP won't work well.

**What about fixing the "hard" part and optimizing the rest?**

If I fix h at "active" lags (the ones at the max), and optimize the rest, I get a QP. But identifying the active set is tricky.

OK, I think the best approach is still coordinate descent, but with improvements:

1. **Faster 1D optimization**: The function f(t) = max_k (c0[k] + t*A[k] - t²*Q[k]) is the max of quadratics. The maximum of quadratics is convex. So we can use bisection on the derivative, or a convex optimization approach.

Actually, for the 1D subproblem, f(t) is convex (max of convex functions). We can minimize it using:
- Bisection on f'(t) (if differentiable)
- Or ternary search (works for convex functions)
- Or directly: the minimum is where the subgradient contains 0

The subgradient of f(t) at t is {sum_{k in active} λ_k * (A[k] - 2t*Q[k]) : λ_k ≥ 0, sum λ_k = 1} where active = {k : c0[k] + t*A[k] - t²*Q[k] = f(t)}.

This is complex. Let me just use a robust ternary search with ~30 iterations. That should be fast enough.

2. **Priority-based coordinate selection**: Instead of cycling through all coordinates, prioritize those that appear in the "active" (max) constraints.

3. **Early stopping**: Stop when the improvement is below threshold.
