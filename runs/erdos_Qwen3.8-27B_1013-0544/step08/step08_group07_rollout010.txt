Actually, the ternary search can be replaced by an exact solution. The function f(t) = max_m (b[m] + t*a[m]) is the upper envelope of lines. The minimum of f on [0,1] occurs at a point where two lines intersect (or at a boundary). 

The lines are y = a[m]*t + b[m]. The upper envelope changes at intersection points. The minimum of the envelope on [0,1] is at one of these intersection points that lies in [0,1].

Finding the intersection points: line m1 and line m2 intersect at t = (b[m2]-b[m1])/(a[m1]-a[m2]).

But there are O(n²) pairs, so O(n²) intersection points. That's 250,000 for n=500. For each coordinate, that's too expensive.

Alternative: Since f(t) is convex, we can find the minimum by:
1. f(0) = max(b)
2. f(1) = max(b+a)
3. The subgradient at t is the set of a[m] for which b[m] + t*a[m] = f(t) (i.e., the active constraints)
4. At the minimum, 0 is in the subgradient, meaning there exist active constraints with a[m] > 0 and a[m] < 0 (or a[m] = 0 for all active)

So the optimal t satisfies: there exist m1, m2 such that:
- b[m1] + t*a[m1] = b[m2] + t*a[m2] = f(t)
- a[m1] >= 0 >= a[m2] (or similar)

This means t = (b[m2]-b[m1])/(a[m1]-a[m2]) for some pair (m1,m2) where m1 is active with positive slope and m2 is active with negative slope.

But finding the right pair is still hard in general.

Let me also think about the sum constraint. When we change h[j] to a new value, the sum changes. We need to maintain sum(h) = n/2.

Actually, if we're doing cyclic coordinate descent and we always project back after each update, the sum constraint is maintained (approximately). The projection is: add (target - sum)/n to all coordinates, then clip to [0,1]. This might disturb other coordinates, but in practice it's a small perturbation.

Alternatively, we can do: update h[j], then adjust one other coordinate h[j'] to maintain the sum. But this is more complex.

I'll go with option (a): update one coordinate, then project.

Actually, a better approach: since we're changing h[j] by δ, the sum changes by δ. To maintain the sum, we can distribute -δ uniformly across all other coordinates: h[i] -= δ/(n-1) for i ≠ j. But this might push some coordinates outside [0,1].

The simplest approach: just project after each update. The projection is:
1. Clip to [0,1]
2. Adjust to make sum = n/2 (distribute the correction to coordinates that have room)

This is what the existing `project_feasible` does.

But doing a full projection after each of n coordinate updates is expensive. Let me think...

Actually, the sum constraint correction is: after changing h[j] by δ, the sum is off by δ. We need to remove δ from the total. The simplest way: scale all other coordinates by (n/2 - t) / (sum(h) - t) where t is the new h[j]. But this changes all coordinates.

A cheaper approach: just subtract δ/n from every coordinate (including j). This maintains the sum exactly and is a uniform shift. Then clip to [0,1]. The clipping might slightly violate the sum, but by a small amount.

Actually, the cleanest approach for coordinate descent:
1. Compute the optimal t for coordinate j (ignoring the sum constraint)
2. Set h[j] = t
3. Compute the sum error: err = h.sum() - n/2
4. Distribute -err/n to all coordinates: h -= err/n
5. Clip to [0,1]
6. (Optional) iterate steps 3-5 a few times

This should work well in practice.

```python
import numpy as np
from scipy.optimize import minimize
import time

def compute_c5(h, n):
    dx = 2.0 / n
    c = np.correlate(h, 1.0 - h, mode='full')
    return float(c.max()) * dx

def project_feasible(h, n, max_iter=1000):
    target = n / 2.0
    h = np.clip(h.copy(), 0.0, 1.0)
    for _ in range(max_iter):
        diff = target - h.sum()
        if abs(diff) < 1e-12:
            break
        if diff > 0:
            room = 1.0 - h
            tot = room.sum()
            if tot < 1e-15:
                break
            h += (diff / tot) * room
        else:
            tot = h.sum()
            if tot < 1e-15:
                break
            h -= (-diff / tot) * h
    return np.clip(h, 0.0, 1.0)

    """Coordinate descent with exact 1D minimization via ternary search."""
    h = h.copy()
    best_c = compute_c5(h, n)

            break
        c = np.correlate(h, 1.0 - h, mode='full')  # length 2n-1
        current_max = float(c.max())
        improved = False
        
        for j in range(n):
            # Compute a[m] for all m in [0, 2n-2]
            # a[m] = (1-h[p]) - h[q] where p = j+m-n+1, q = m-n+1-j
            # p valid when 0 <= j+m-n+1 < n, i.e., n-1-j <= m <= 2n-2-j
            # q valid when 0 <= m-n+1-j < n, i.e., j <= m <= n-1+j
            
            a = np.zeros(2*n-1)
            # First term: 1-h[p] for valid p
            p_lo = max(0, n-1-j)
            p_hi = min(2*n-2, 2*n-2-j)
            if p_lo <= p_hi:
                p_vals = np.arange(p_lo, p_hi+1)
                idx_p = p_vals - (n-1) + j  # = p_vals - n + 1 + j
                a[p_vals] += 1.0 - h[idx_p]
            
            # Second term: -h[q] for valid q
            q_lo = max(0, j)
            q_hi = min(2*n-2, n-1+j)
            if q_lo <= q_hi:
                q_vals = np.arange(q_lo, q_hi+1)
                idx_q = q_vals - (n-1) - j  # = q_vals - n + 1 - j
                a[q_vals] -= h[idx_q]
            
            b = c - a * h[j]
            
            # Ternary search for min_t max(b + t*a) over t in [0,1]
            lo, hi = 0.0, 1.0
            for _ in range(40):
                m1 = lo + (hi - lo) / 3.0
                m2 = hi - (hi - lo) / 3.0
                if np.max(b + m1 * a) < np.max(b + m2 * a):
                    hi = m2
                else:
                    lo = m1
            t_new = (lo + hi) / 2.0
            
            if abs(t_new - h[j]) > 1e-10:
                h[j] = t_new
                # Maintain sum constraint
                err = h.sum() - n/2.0
                if abs(err) > 1e-12:
                    h -= err / n
                    h = np.clip(h, 0.0, 1.0)
                improved = True
                # Update c for next coordinates
                c = c + (t_new - (h[j] + err/n if abs(err) > 1e-12 else 0)) * a  # approximate
                
        if not improved:
            break
        h = project_feasible(h, n)
        new_c = compute_c5(h, n)
        if new_c < best_c:
            best_c = new_c
    
    return h, compute_c5(h, n)
```

```python
def opt_1d(a, b, n, j):
    """Find t in [0,1] minimizing max_k (b[k] + a[k]*t) with special handling of diagonal."""
    # Diagonal index is n-1
    # For m = n-1: value = b[n-1] + t - t²
    # For m ≠ n-1: value = b[m] + a[m]*t
    
    # Grid search
    ts = np.linspace(0, 1, 200)
    best_t = 0
    best_val = np.inf
    for t in ts:
        vals = b + t * a
        vals[n-1] = b[n-1] + t - t*t
        v = vals.max()
        if v < best_val:
            best_val = v
            best_t = t
    
    # Local refinement
    idx = np.argmin(np.abs(ts - best_t))
    lo = ts[max(0, idx-1)]
    hi = ts[min(len(ts)-1, idx+1)]
    for _ in range(50):
        m1 = lo + (hi-lo)/3
        m2 = hi - (hi-lo)/3
        v1 = b.copy() + m1 * a
        v1[n-1] = b[n-1] + m1 - m1*m1
        v2 = b.copy() + m2 * a
        v2[n-1] = b[n-1] + m2 - m2*m2
        if v1.max() <= v2.max():
            hi = m2
        else:
            lo = m1
    best_t = (lo+hi)/2
    return best_t
```
