def project_h(h, target):
    h = h.copy()
    diff = target - np.sum(h)
    if abs(diff) < 1e-14:
        return np.clip(h, 0, 1)
    # We need to add diff to the sum
    # If diff > 0, increase some elements (those < 1)
    # If diff < 0, decrease some elements (those > 0)
    # Water filling approach:
    for _ in range(10):  # iterate until converged
        h = np.clip(h, 0, 1)
        new_sum = np.sum(h)
        residual = target - new_sum
        if abs(residual) < 1e-14:
            break
        if residual > 0:
            mask = h < 1.0
        else:
            mask = h > 0.0
        cnt = np.sum(mask)
        if cnt == 0:
            break
        h[mask] += residual / cnt
    return np.clip(h, 0, 1)

```python
def coord_descent_step(h, n_grid=100):
    n = len(h)
    dx = 2.0 / n
    out = np.correlate(h, 1.0 - h, mode='full')  # length 2n-1
    
    x_grid = np.linspace(0, 1, n_grid)
    
    for m in range(n):
        # Compute a_k for all k
        k_vals = np.arange(2*n - 1)
        idx1 = m - k_vals + n - 1
        idx2 = m + k_vals - n + 1
        
        valid1 = (idx1 >= 0) & (idx1 < n)
        valid2 = (idx2 >= 0) & (idx2 < n)
        
        a_k = np.zeros(2*n - 1)
        a_k[valid1] += (1.0 - h[idx1[valid1]])
        a_k[valid2] -= h[idx2[valid2]]
        
        b_k = out - a_k * h[m]
        
        # Evaluate f(x) = max_k (a_k * x + b_k) at grid points
        vals = np.max(a_k[None, :] * x_grid[:, None] + b_k[None, :], axis=1)
        best_idx = np.argmin(vals)
        x_new = x_grid[best_idx]
        
        # Update
        h[m] = x_new
        # Recompute out (expensive but correct)
        out = np.correlate(h, 1.0 - h, mode='full')
    
    return h
```

```python
def coord_descent_sweep(h, n_grid=100):
    n = len(h)
    out = np.correlate(h, 1.0 - h, mode='full')
    x_grid = np.linspace(0, 1, n_grid)
    k_vals = np.arange(2*n - 1)
    
    for m in range(n):
        idx1 = m - k_vals + n - 1
        idx2 = m + k_vals - n + 1
        valid1 = (idx1 >= 0) & (idx1 < n)
        valid2 = (idx2 >= 0) & (idx2 < n)
        
        a_k = np.zeros(2*n - 1)
        a_k[valid1] = (1.0 - h[idx1[valid1]])
        a_k[valid2] -= h[idx2[valid2]]
        
        b_k = out - a_k * h[m]
        
        vals = np.max(a_k[None, :] * x_grid[:, None] + b_k[None, :], axis=1)
        best_idx = np.argmin(vals)
        x_new = x_grid[best_idx]
        
        delta = x_new - h[m]
        h[m] = x_new
        out += delta * a_k
    
    return h
```

This is O(n_grid * n) per coordinate (for the max computation) + O(n) for the update. Total per sweep: O(n * n_grid * n + n * n) = O(n² * n_grid). For n=180, n_grid=100: O(180² * 100) = O(3.24M). Very fast!

Actually, let me think about this differently. The function f(x) = max_k (a_k*x + b_k) is convex piecewise linear. Its minimum is at a breakpoint (where two lines cross) or at a boundary. I can find it exactly:

The breakpoints are at x = (b_j - b_i) / (a_i - a_j) for pairs (i,j) where a_i ≠ a_j, and the two lines are active (i.e., both are in the upper envelope) at that x.

Finding all breakpoints is O(n²) which is fine for n=359 (2n-1 values). But I need to check which ones are actually on the upper envelope, which is more work.

Alternatively, since f is convex, I can use the fact that the minimum is where the subgradient contains 0. The subgradient at x is {a_k : k ∈ argmax}. So I need:
- min_{k active} a_k ≤ 0 ≤ max_{k active} a_k

I can find this by:
1. Sort the lines by slope a_k
2. Use a rotating calipers / convex hull approach to find the upper envelope
3. Find where the envelope's slope changes from negative to positive

But this is overkill. A simpler approach: since f is convex, I can use ternary search or golden section search. Each evaluation is O(n). With 50 iterations of golden section, that's O(50n) per coordinate, O(50n²) per sweep. For n=180: O(50*32400) = O(1.6M). Very fast.

Actually, for a convex piecewise-linear function, bisection on the "direction" is even better:
- At point x, compute the active set (all k that achieve the max)
- If all active a_k > 0: minimum is to the left (decrease x)
- If all active a_k < 0: minimum is to the right (increase x)  
- If there's a mix (some positive, some negative): x is optimal (0 is in subgradient)

Wait, that's not quite right. If all active a_k > 0, the function is increasing at x, so the minimum is to the left. If all active a_k < 0, the function is decreasing at x, so the minimum is to the right.

But "all active a_k > 0" means the function is strictly increasing at x (the slope of the upper envelope is positive). So we should decrease x.

Bisection:
- lo = 0, hi = 1
- Repeat:
  - mid = (lo+hi)/2
  - Compute active set at mid
  - If min active a_k > 0: hi = mid (minimum is to the left)
  - Elif max active a_k < 0: lo = mid (minimum is to the right)
  - Else: return mid (optimal)

This converges in O(log(1/ε)) iterations, each O(n). For ε=1e-6, about 20 iterations. Total per coordinate: O(20n). Per sweep: O(20n²). For n=180: O(20*32400) = O(648K). Extremely fast!

But there's a subtlety: at the optimum, the function might be flat (all active a_k = 0). In that case, any point in the flat region is optimal. The bisection will converge to one such point.

Also, the optimum might be at a boundary (x=0 or x=1). The bisection handles this: if at mid the function is always decreasing (max active a_k < 0), we move lo up, eventually converging to x=1.

Let me implement this bisection approach. It's exact (up to numerical precision) and very fast.

Actually, I realize there might be an issue with the bisection: the "direction" at a point is determined by the active set, which can change discontinuously. But since f is convex, the set of points where f is decreasing is an interval [0, x*] and where f is increasing is [x*, 1] (approximately). The bisection will converge to x*.

Let me just use the grid approach with a reasonable resolution (say 200 points) and then refine with bisection in the neighborhood. Or just use the grid alone - for our purposes, the precision of 1/200 = 0.005 in h values is more than sufficient.
