Let me also think about a key mathematical insight:

For the discrete problem, if we define the "error" at lag k as e[k] = corr[k] - target, where target is the desired maximum, then we want all e[k] ≤ 0. The minimum feasible target is what we're looking for.

We can binary search on the target: for a given target T, check if there exists h with all corr[k] ≤ T/dx. This is a feasibility problem, which is non-convex in h (due to the quadratic terms).

But we can use the following observation: if we fix all of h except one element h[j], then each corr[k] is a quadratic function of h[j]. Specifically:
corr[k] = sum_i h[i+k]*(1-h[i])

If we change h[j] to h[j]+δ:
- For lags where j appears as i+k: corr[k] changes by (1-h[i])*δ
- For lags where j appears as i: corr[k] changes by -h[i+k]*δ

So the effect is linear in δ for each lag. This means we can do a coordinate descent where at each step, we find the optimal h[j] given all others fixed.

For a single coordinate j, the objective max_k corr[k] as a function of h[j] is the max of a collection of linear functions (each corr[k] is linear in h[j] for fixed other h). So it's a convex piecewise-linear function of h[j], and we can find the minimizer by checking where the upper envelope is minimized.

This gives us an exact coordinate descent algorithm! And it's very efficient because we only need to evaluate O(n) linear functions at O(n) candidate points.

If we change h[j] by δ:

  Change: δ*(1-h[j-k])
- (1-h[n]) = (1-h[j]) when n=j. So corr[k] includes the term h[j+k]*(1-h[j]) if j+k is valid.
  Change: -h[j+k]*δ

So: d(corr[k])/d(h[j]) = (1-h[j-k]) * [j-k valid] - h[j+k] * [j+k valid]

where [condition] is 1 if the index is in [0,n-1] and 0 otherwise.

This is indeed linear in h[j] (the derivative is constant with respect to h[j]).

So for coordinate descent on h[j]:
- corr[k] is linear in h[j] with slope s_k = (1-h[j-k])*[valid] - h[j+k]*[valid]
- We want to minimize max_k (corr[k]_0 + s_k * δ) * dx where δ = h[j] - h[j]_old
- Subject to 0 ≤ h[j]_old + δ ≤ 1 and sum constraint

Without the sum constraint, this is: minimize the upper envelope of linear functions, which is a 1D convex optimization problem. The minimum is at a point where two of the "active" lines cross, or at a boundary.

With the sum constraint, if we fix all other h's, the sum constraint becomes: h[j] = target - sum_{i≠j} h[i], which fixes h[j]. So we can't do coordinate descent with the sum constraint active.

Solution: remove the sum constraint from the coordinate descent, and periodically renormalize. Or: do pair swaps (change h[j] by +δ and h[k] by -δ, keeping the sum constant).

**Pair swap approach:**
- Pick a pair (j, k)
- Change h[j] → h[j]+δ, h[k] → h[k]-δ (sum preserved)
- For each lag L, corr[L] changes by:
  d(corr[L])/dδ = s_L(j) - s_L(k) where s_L(j) is the slope computed above
- Minimize max_L (corr[L] + (s_L(j)-s_L(k))*δ) * dx
- Subject to 0≤h[j]+δ≤1 and 0≤h[k]-δ≤1

This is again a 1D convex optimization (minimize upper envelope of linear functions).

def compute_c5(h, dx):
    corr = np.correlate(h, 1 - h, mode="full")
    return float(np.max(corr) * dx), corr

def compute_slopes(h):
    """Compute slope matrix: slopes[j, l] = d(corr[l])/d(h[j])"""
    n = len(h)
    lags = np.arange(-(n-1), n)
    J, L = np.meshgrid(np.arange(n), lags, indexing='ij')
    JL = J - L
    JL2 = J + L
    valid1 = (JL >= 0) & (JL < n)
    valid2 = (JL2 >= 0) & (JL2 < n)
    h_pad = np.zeros(2*n)  # pad for safe indexing
    h_pad[n:n+n] = h  # actually, let me think about this differently
    
    # For safe indexing:
    # h[j-ℓ] is valid when 0 ≤ j-ℓ < n
    # We can use np.take with where
    temp1 = np.where(valid1, 1.0 - h[JL], 0.0)
    temp2 = np.where(valid2, h[JL2], 0.0)
    return temp1 - temp2

def pair_descent(h, dx, n_iters=20000, seed=0):
    """Pair coordinate descent with exact 1D minimization"""
    n = len(h)
    rng = np.random.RandomState(seed)
    corr = np.correlate(h, 1-h, mode="full")
    slopes = compute_slopes(h)
    best_c5 = np.max(corr) * dx
    
    for it in range(n_iters):
        j, k = rng.choice(n, 2, replace=False)
        dcorr = slopes[j] - slopes[k]
        
        delta_lo = max(-h[j], h[k] - 1.0)
        delta_hi = min(1.0 - h[j], h[k])
        
        if delta_hi - delta_lo < 1e-12:
            continue
        
        # Minimize g(δ) = max(corr + dcorr * δ) over δ ∈ [delta_lo, delta_hi]
        def g(delta):
            return np.max(corr + dcorr * delta)
        
        res = minimize_scalar(g, bounds=(delta_lo, delta_hi), method='bounded',
                              options={'xatol': 1e-10})
        delta = res.x
        new_max = g(delta)
        
        if new_max < np.max(corr) - 1e-12:
            h[j] += delta
            h[k] -= delta
            corr += dcorr * delta
            best_c5 = new_max * dx
            # Update slopes (only rows j and k change significantly)
            # For efficiency, recompute every 50 steps
            if it % 50 == 0:
                slopes = compute_slopes(h)
    
    return h, best_c5

    corr = np.correlate(h, 1 - h, mode="full")

    J, L = np.meshgrid(np.arange(n), lags, indexing='ij')

One more optimization: instead of calling minimize_scalar for every pair (which has overhead), I can implement a simple bisection/golden section search myself:

```python
def min_max_linear(corr, dcorr, lo, hi):
    """Minimize max(corr + dcorr * x) for x in [lo, hi]"""
    # Golden section search (works for unimodal functions)
    gr = (np.sqrt(5) - 1) / 2  # golden ratio ≈ 0.618
    
    a, b = lo, hi
    c = b - gr * (b - a)
    d = a + gr * (b - a)
    fc = np.max(corr + dcorr * c)
    fd = np.max(corr + dcorr * d)
    
    for _ in range(50):
        if b - a < 1e-12:
            break
        if fc < fd:
            b = d
            d = c
            fd = fc
            c = b - gr * (b - a)
            fc = np.max(corr + dcorr * c)
        else:
            a = c
            c = d
            fc = fd
            d = a + gr * (b - a)
            fd = np.max(corr + dcorr * d)
    
    x = 0.5 * (a + b)
    return x, np.max(corr + dcorr * x)
```

This avoids the overhead of scipy's minimize_scalar. 50 iterations of golden section on a range of at most 1 gives precision ~ 1/φ^50 ≈ 10^-10. Good enough.

Actually, for a convex piecewise-linear function, golden section is not optimal (it's designed for smooth unimodal functions). But it still works and converges. The convergence rate is the same as bisection: O((1/φ)^n).

    n = len(h)
