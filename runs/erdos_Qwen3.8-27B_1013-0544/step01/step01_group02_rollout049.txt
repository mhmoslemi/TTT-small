```python
        slope = D[ell_star]
        if slope < -1e-15:
            δ_lo = mid
        elif slope > 1e-15:
            δ_hi = mid
        else:
            break
    
    return (δ_lo + δ_hi) / 2
```

This is clean and efficient! Each pair evaluation is O(n) (for computing D and B) + O(n) (for the bisection) = O(n). With n² pairs, one full sweep is O(n³).

For n=80: 80³ = 512,000 operations per sweep. At maybe 10 ns per operation, that's about 5ms per sweep. We can do thousands of sweeps in the time budget!

The key question is: will this converge to a good solution? Coordinate descent on a convex function (for fixed other variables) should converge, but the overall problem is non-convex. However, since each step is a guaranteed improvement (we're minimizing a convex function exactly), the sequence of objective values is monotonically decreasing.

The main risk is getting stuck in a "pairwise local optimum" where no single pair swap improves the solution, but a triple swap would. To handle this, I can:
1. Do many sweeps until convergence
2. Add random perturbations and restart
3. Combine with SLSQP for final polish

Let me also think about the computational cost more carefully. The inner loop (computing D and B for each ell) is O(n) per pair. With the bisection (40 iterations), each pair takes O(n·40) = O(40n). For n=80, that's 3200 operations per pair. With n² = 6400 pairs, one sweep is about 20 million operations. At Python speed (maybe 10-50 ns per operation for numpy, but the loop is in Python so maybe 100-500 ns per iteration), the Python loop over ell (2n-1 = 159 iterations) would be the bottleneck.

Let me vectorize the computation of D:

```python
def pair_descent_step_vec(h, n, j, k):
    dx = 2.0 / n
    c = np.correlate(h, 1.0-h, mode='full') * dx
    
    # Compute d(c[ell])/d(h[j]) for all ell
    # d(c[ell])/d(h[j]) = dx * (1-h[j-lag]) - dx * h[j+lag] (with validity)
    # where lag = ell - (n-1)
    
    lags = np.arange(2*n-1) - (n-1)  # shape (2n-1,)
    
    # For j: valid where 0 <= j-lag < n AND 0 <= j+lag < n
    valid_j1 = (j - lags >= 0) & (j - lags < n)
    valid_j2 = (j + lags >= 0) & (j + lags < n)
    
    dj = np.zeros(2*n-1)
    dj[valid_j1] = (1.0 - h[j - lags[valid_j1]]) * dx
    dj[valid_j2] -= h[j + lags[valid_j2]] * dx
    
    valid_k1 = (k - lags >= 0) & (k - lags < n)
    valid_k2 = (k + lags >= 0) & (k + lags < n)
    
    dk = np.zeros(2*n-1)
    dk[valid_k1] = (1.0 - h[k - lags[valid_k1]]) * dx
    dk[valid_k2] -= h[k + lags[valid_k2]] * dx
    
    D = dj - dk
    B = c
    
    δ_lo = max(-h[j], h[k]-1)
    δ_hi = min(1-h[j], h[k])
    
    if δ_lo >= δ_hi:
        return 0.0
    
    for _ in range(40):
        mid = (δ_lo + δ_hi) / 2
        vals = B + mid * D
        ell_star = np.argmax(vals)
        slope = D[ell_star]
        if slope < -1e-15:
            δ_lo = mid
        elif slope > 1e-15:
            δ_hi = mid
    
    return (δ_lo + δ_hi) / 2
```

This is much faster - the vectorized operations are O(n) each, and the bisection is O(40n) = O(n) with small constant.

```python
def full_pair_sweep(h, n, max_sweeps=100):
    dx = 2.0 / n
    improved = True
    sweep = 0
    while improved and sweep < max_sweeps:
```

```python
def single_coord_step(h, n, j):
    """Optimize h[j] with others fixed, ignoring sum constraint."""
    dx = 2.0 / n
    c = np.correlate(h, 1.0-h, mode='full') * dx
    
    lags = np.arange(2*n-1) - (n-1)
    
    valid1 = (j - lags >= 0) & (j - lags < n)
    valid2 = (j + lags >= 0) & (j + lags < n)
    
    A = np.zeros(2*n-1)
    A[valid1] = (1.0 - h[j - lags[valid1]]) * dx
    A[valid2] -= h[j + lags[valid2]] * dx
    
    B = c - A * h[j]
    
    # Minimize max(A*x + B) for x in [0, 1]
    lo, hi = 0.0, 1.0
    for _ in range(30):
        mid = (lo + hi) / 2
        vals = A * mid + B
        slope = A[np.argmax(vals)]
        if slope < 0:
            lo = mid
        elif slope > 0:
            hi = mid
    
    return (lo + hi) / 2
```

This is even faster per step (no need to compute dk), but doesn't preserve the sum constraint. I'll use it in combination with periodic projection.
