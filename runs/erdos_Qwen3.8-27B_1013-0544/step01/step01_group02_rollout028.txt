Actually, the sum constraint couples all coordinates, so pure coordinate descent won't work directly. But we can do:

- Optimize h[i] and h[j] jointly (2D subproblem)

So it's still 1D! We just need to find a ∈ [max(0, const-1), min(1, const)] that minimizes max_k (C_k + D_k * a).

This is a 1D convex min-max problem that can be solved by bisection or by finding the intersection points.

2. Set b = s - a where s = h[i] + h[j] (constant)
3. c_k(a) = C_k + D_k * a where C_k = A_k + B_k^j * s, D_k = B_k^i - B_k^j
4. Find a* = argmin_a max_k (C_k + D_k * a) over a ∈ [max(0, s-1), min(1, s)]

The optimal a* is where the two "active" constraints intersect (the two lags that define the max at the optimum).

This can be found by:
- Computing the upper envelope of lines {C_k + D_k * a}
- Finding the minimum of this envelope on the interval

The minimum of the upper envelope of lines occurs at an intersection point of two lines (or at an endpoint).

Algorithm:
1. For each pair of lines (k1, k2), find their intersection: a = (C_k2 - C_k1) / (D_k1 - D_k2) (when D_k1 ≠ D_k2)
2. Check if this a is in the valid range
3. At that a, check if both lines are active (i.e., c_k1(a) = c_k2(a) ≥ c_k(a') for all k')
4. Track the best
