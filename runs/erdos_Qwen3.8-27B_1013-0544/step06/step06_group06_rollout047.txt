Let me go back to the g-matrix approach which is O(1) per swap evaluation (once g is built).

The g-matrix approach:
- Build g: O(n²) once
- For each swap (i, j): new_corr = corr + g[i] - g[j], new_max = new_corr.max(): O(n)
- To find the best swap: need to search over all (i, j) pairs: O(n²) per iteration
- Total: O(n²) per iteration, same as building g

But we can be smarter: only consider swaps that affect the top lags.

Actually, the previous code's approach is:
1. Take top_k lags
2. For each (i in zeros, j in ones), compute max of (corr[top_idx] + g[i, top_idx] - g[j, top_idx])
3. This gives a lower bound on the new max (since we're only looking at top_k lags)
4. Pick the best (i, j) based on this bound
5. Verify with full correlation

This is O(n_zeros * n_ones * top_k) per iteration = O(n² * top_k) which for n=250, top_k=10 is about 625*10 = 6250 ops. That's very fast!

The issue is that after the swap, g needs to be updated. The g matrix depends on h, so when h changes, g changes too.

The update of g after swapping h[i] (0→1) and h[j] (1→0):
g[p, m] = (1-h[p-lag_m])*1_{valid} - h[p+lag_m]*1_{valid}

This changes only for positions p where p-lag_m = i or j, or p+lag_m = i or j.
- p-lag_m = i means p = i + lag_m. For each m, there's at most one p.
- p-lag_m = j means p = j + lag_m.
- p+lag_m = i means p = i - lag_m.
- p+lag_m = j means p = j - lag_m.

So for each m (2n-1 values), at most 4 positions p are affected. Total affected entries: 4*(2n-1) ≈ 8n.

The change in g[p, m] when h[i] changes from 0 to 1:
- If p-lag_m = i: g[p,m] changes by -(1) = -1 (since (1-h[i]) goes from 1 to 0)
- If p+lag_m = i: g[p,m] changes by -1 (since h[i] goes from 0 to 1)

When h[j] changes from 1 to 0:
- If p-lag_m = j: g[p,m] changes by +1 (since (1-h[j]) goes from 0 to 1)
- If p+lag_m = j: g[p,m] changes by +1 (since h[j] goes from 1 to 0)

So the update is:
For each m:
  p1 = i + lag_m: if 0≤p1<n, g[p1, m] -= 1 (h[i] went 0→1, (1-h[i]) went 1→0)
  p2 = j + lag_m: if 0≤p2<n, g[p2, m] += 1 (h[j] went 1→0, (1-h[j]) went 0→1)
  p3 = i - lag_m: if 0≤p3<n, g[p3, m] -= 1 (h[i] went 0→1)
  p4 = j - lag_m: if 0≤p4<n, g[p4, m] += 1 (h[j] went 1→0)

This is O(n) per swap if done carefully. Let me implement this.

g[p, m] = (1-h[p-lag]) * 1_{0≤p-lag<n} - h[p+lag] * 1_{0≤p+lag<n}

where lag = m - (n-1).

When h[i] goes from 0 to 1:
- In the first term (1-h[p-lag]): if p-lag = i, this term goes from 1 to 0, so g[p,m] decreases by 1.
  p = i + lag = i + m - (n-1)
- In the second term h[p+lag]: if p+lag = i, this term goes from 0 to 1, so g[p,m] decreases by 1.
  p = i - lag = i - m + (n-1)

When h[j] goes from 1 to 0:
- In the first term (1-h[p-lag]): if p-lag = j, this term goes from 0 to 1, so g[p,m] increases by 1.
  p = j + lag = j + m - (n-1)
- In the second term h[p+lag]: if p+lag = j, this term goes from 1 to 0, so g[p,m] increases by 1.
  p = j - lag = j - m + (n-1)

So for each m:
  g[i+lag_m, m] -= 1 (if valid)
  g[i-lag_m, m] -= 1 (if valid)
  g[j+lag_m, m] += 1 (if valid)
  g[j-lag_m, m] += 1 (if valid)

Where lag_m = m - (n-1).
