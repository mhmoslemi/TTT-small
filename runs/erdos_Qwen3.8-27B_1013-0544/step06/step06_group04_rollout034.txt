For the 2-swap, the delta computation is more complex. If we swap positions p1, p2 (both 1) with q1, q2 (both 0):

For a 2-swap (p1, p2 → 0, q1, q2 → 1):
- Position p1: 1→0
- Position p2: 1→0  
- Position q1: 0→1
- Position q2: 0→1

The change in correlation at lag k is the sum of changes from each position change, where each position change is (new_value - old_value) * (partner's value).

But the partner's value might also change! For example, if p1 + shift = q1, then when computing the effect of p1's change, the partner q1 has already changed from 0 to 1.

To handle this correctly, I need to compute the exact new correlation minus the old one. The most straightforward way is:
1. Copy h
2. Apply the swap
3. Compute new correlation
4. delta = new_corr - old_corr

This is O(n) for the correlation computation (well, O(n²) for full correlation, but we can use the fact that only 4 positions changed to compute the delta in O(n)).

Actually, the full correlation is O(n²) to compute from scratch, but the delta from a 4-position change is O(n) since each position affects O(n) lags.

For a 2-swap with positions p1, p2 (1→0) and q1, q2 (0→1):
delta = effect(p1: 1→0) + effect(p2: 1→0) + effect(q1: 0→1) + effect(q2: 0→1) + interaction terms

The interaction terms arise when a position's "partner" is also being changed. For position i with change Δi, and partner at position j:
- If j is also changed by Δj, the interaction is Δi * Δj (cross term)

This gets complicated. Let me just compute it directly:

```python
def multi_swap_delta(h, changes, n):
    """changes is a dict {position: new_value}"""
    # For each lag k, the change in corr[k] is:
    # sum over positions i in changes: 
    #   As first factor: (new_h[i] - old_h[i]) * (1 - new_h[i-shift])
    #   As second factor: new_h[i+shift] * ((1-new_h[i]) - (1-old_h[i]))
    # But we need to use the NEW values for all positions in changes.
    
    delta = np.zeros(2*n-1)
    h_new = h.copy()
    for pos, val in changes.items():
        h_new[pos] = val
    
    for pos, new_val in changes.items():
        old_val = h[pos]
        diff = new_val - old_val
        if diff == 0:
            continue
        # Position as first factor (h[pos] * (1-h[pos-shift])):
        lo = max(0, pos-n+1)
        hi = min(n-1, pos)
        if lo <= hi:
            shifts = np.arange(lo, hi+1)
            partners = pos - shifts
            delta[n-1+shifts] += diff * (1 - h_new[partners])
        
        # Position as second factor (h[pos+shift] * (1-h[pos])):
        lo2 = 0
        hi2 = min(n-1-pos, n-1)
        if lo2 <= hi2:
            shifts = np.arange(lo2, hi2+1)
            partners = pos + shifts
            delta[n-1-shifts] += h_new[partners] * (-diff)
    
    return delta
```

This correctly handles interactions because we use h_new for the partner values.

```python
def gradient_refine(h, n, alpha=100, steps=1000, lr=0.01):
    dx = 2.0/n
    h = h.copy()
    for step in range(steps):
        corr = compute_corr(h)
        # Soft-max weights
        max_c = corr.max()
        exp_c = np.exp(alpha * (corr - max_c))
        p = exp_c / exp_c.sum()
        
        # Gradient
        grad = np.zeros(n)
        for j in range(n):
            for k in range(2*n-1):
                # ∂g[k]/∂h[j]
                # First factor: i=j, partner is j-k+(n-1)
                partner1 = j - k + (n-1)
                if 0 <= partner1 < n:
                    grad[j] += p[k] * (1 - h[partner1])
                # Second factor: i = j+k-(n-1), partner contributes -h[j+k-(n-1)]
                partner2 = j + k - (n-1)
                if 0 <= partner2 < n:
                    grad[j] += p[k] * (-h[partner2])
        
        # Gradient descent step
        h = h - lr * grad
        # Project to [0,1]
        h = np.clip(h, 0, 1)
        # Fix sum constraint
        target = n/2
        h = h + (target - h.sum()) / n  # crude projection
        h = np.clip(h, 0, 1)
    
    return h
```
