**Approach: Iterative "bottleneck reduction"**

1. Start from initial_h_values, project to feasible.
2. Compute c = correlate(h, 1-h).
3. Find the maximum: c_max = max(c).
4. Identify the "bottleneck" lags: B = {k : c[k] > c_max - ε}.
5. Compute the direction that most reduces the bottleneck:
   - For each p in [0, n-1], compute the "effect" of increasing h[p] on the bottleneck lags.
   - The effect is: for k in B, c[k] changes by (1-h[p+k-n+1]) - h[p-k+n+1].
   - We want to find the p that most reduces the max over B.
6. Take a step in that direction, project, repeat.

This is essentially a "greedy" approach that focuses on the worst lags. It's similar to coordinate descent but targets the bottlenecks specifically.

Let me implement this more carefully:

For a given p, if I increase h[p] by δ:
- For lag k: c[k] changes by δ * [(1 - h[p+k-n+1]) - h[p-k+n+1]] (with validity checks)
- Plus the quadratic term: -δ² for k = n-1 (center lag)

So the "gradient contribution" at p for lag k is:
g_k[p] = (1 - h[p+k-n+1]) * [valid] - h[p-k+n+1] * [valid]

And for the center lag k=n-1: g_{n-1}[p] = 1 - 2h[p] (plus the -δ² term).

For the bottleneck reduction:
If I increase h[p] by δ, the new bottleneck values for k in B are:
c[k] + δ * g_k[p]

I want to minimize max_{k in B} (c[k] + δ * g_k[p]).

This is a 1D optimization for each (p, δ), which I can solve analytically or with a small search.

    best_h = project_feasible(best_h, len(best_h))
    best_c = compute_c5(best_h, len(best_h))
    return best_h, best_c, len(best_h)
