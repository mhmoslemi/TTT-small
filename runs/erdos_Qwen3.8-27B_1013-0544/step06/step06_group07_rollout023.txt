The previous program got 0.380866. The gap to 0.3808 is tiny (0.000066). For n=250 with non-binary h, this is achievable if we can find the right continuous values.

I think the most effective approach is:
1. Get a good binary structure (using SA)
2. Then do continuous optimization to fine-tune the values

The continuous optimization is where the small improvement comes from. Let me focus on making the continuous optimization more effective.

**Key insight for continuous optimization**: At the optimum, the active constraints (shifts k where O(k) = max) should be "balanced" - the gradient of O(k) for active k should be in the normal cone of the feasible set.

A practical approach: **coordinate descent on the active shifts**
1. Identify active shifts (O(k) near the max)
2. For each active shift, adjust h to reduce O(k) while not increasing other active shifts
3. This is like a multi-objective optimization

But this is complex. Let me try something simpler:

**Lambda iteration / multiplicative weight updates**:
- Maintain a "dual variable" λ_k for each shift k
- Update: h[j] ← h[j] * exp(-lr * sum_k λ_k * ∂O(k)/∂h[j])
- Update λ: λ_k ← λ_k * exp(eta * O(k)) (boost shifts with high overlap)
- This is a primal-dual method

This is related to the "Hedge" algorithm and should converge to the optimum.

Let me implement this:

```python
def primal_dual(h, n, steps, lr=0.01, eta=0.1):
    dx = 2.0 / n
    h = h.copy()
    lambdas = np.ones(2*n-1)
    m_range = np.arange(-(n-1), n)
    for it in range(steps):
        corr = np.correlate(h, 1-h, mode='full') * dx
        # Update dual variables
        lambdas *= np.exp(eta * (corr - corr.mean()))
        lambdas /= lambdas.sum()
        # Compute gradient: sum_k lambda_k * dO(k)/dh[j]
        g = np.zeros(n)
        for m in range(2*n-1):
            if lambdas[m] < 1e-10:
                continue
            s = m - (n-1)
            g += lambdas[m] * gradient_at_shift(h, n, s)
        # Multiplicative update
        h *= np.exp(-lr * g)
        h = project_feasible(h, n)
    return h
```

The inner loop over m is O(n) with each iteration O(n), so total O(n²) per step. For n=250, that's 62500 per step. With 10000 steps, that's 625M operations. In numpy, each iteration involves a few vector ops of length 250, so maybe 1-2 seconds per 1000 steps. Total: 10-20 seconds. That's fine.

But wait, the gradient_at_shift function creates a new array each time, which involves memory allocation. Let me optimize by precomputing.

Actually, let me vectorize the entire gradient computation. The total gradient is:
g[j] = sum_m λ[m] * [(1-h[j+s_m]) * 1[j+s_m valid] - h[j-s_m] * 1[j-s_m valid]]

where s_m = m - (n-1).

First term: sum_m λ[m] * (1-h[j+s_m]) * 1[j+s_m ∈ [0,n-1]]
= sum_m λ[m] - sum_m λ[m] * h[j+s_m] * 1[j+s_m valid]

The first part sum_m λ[m] is just a constant (let's call it Λ).
The second part: for each j, sum over m where j+s_m is valid of λ[m] * h[j+s_m].
Let i = j+s_m, so s_m = i-j, m = n-1+i-j.
= sum_i h[i] * λ[n-1+i-j] * 1[i valid and n-1+i-j valid]
This is a cross-correlation of h with λ (with appropriate index shifts).

Similarly for the -h[j-s_m] term.

So I can compute g using two cross-correlations:
g[j] = Λ - (h ⊛ λ_shifted)[j] - (h ⊛ λ_shifted2)[j]

where ⊛ denotes cross-correlation. This can be done with FFT in O(n log n).

But for n=250, the O(n²) loop is already fast enough. Let me not over-optimize.

def gradient_at_shift(h, n, s):
    g = np.zeros(n)
    if s >= 0:
        if n - s > 0:
            g[0:n-s] += (1.0 - h[s:n])
        if s < n:
            g[s:n] -= h[0:n-s]
    else:
        sp = -s
        g[sp:n] += (1.0 - h[0:n-sp])
        g[0:n-sp] -= h[sp:n]
    return g
