    c = np.correlate(h, 1.0 - h, mode='full')

def project_feasible(h, n):
    target = n / 2.0
    h = np.clip(h, 0.0, 1.0)
    for _ in range(100):
        diff = target - h.sum()
        if abs(diff) < 1e-14:
            break
        if diff > 0:
            room = 1.0 - h
            s = room.sum()
            if s < 1e-14:
                break
            h = h + diff / s * room
        else:
            s = h.sum()
            if s < 1e-14:
                break
            h = h + diff / s * h
    h = np.clip(h, 0.0, 1.0)
    # Final correction
    diff = target - h.sum()
    if abs(diff) > 1e-12:
        # Distribute among non-bound variables
        mask = (h > 1e-6) & (h < 1.0 - 1e-6)
        if mask.sum() > 0:
            h[mask] += diff / mask.sum()
            h = np.clip(h, 0.0, 1.0)

def compute_c5(h, n):
    dx = 2.0 / n
    c = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(c) * dx)

def project_feasible(h, n):
    target = n / 2.0
    h = np.clip(h, 0.0, 1.0)
    for _ in range(200):
        diff = target - h.sum()
        if abs(diff) < 1e-14:
            break
        if diff > 0:
            room = 1.0 - h
            s = room.sum()
            if s < 1e-14: break
            h = h + diff / s * room
        else:
            s = h.sum()
            if s < 1e-14: break
            h = h + diff / s * h
    return np.clip(h, 0.0, 1.0)

1. Find a good binary pattern (SA/ILS) - this gives a starting point near the optimum
2. Do continuous optimization from that starting point

The binary pattern should be one where the maximum correlation is as "flat" as possible (all the top correlation values are close to each other). This way, the continuous optimization can reduce the maximum by "smoothing" the peaks.

Let me now focus on making the continuous optimization better. The SLSQP approach with log-sum-exp should work, but I need to be careful about:
- The smoothness parameter α (too small → bad approximation; too large → numerical issues)
- The number of iterations
- The starting point

For α = 20000: exp(α * (c - c_max)) where c - c_max ∈ [-c_max, 0]. If c_max ≈ 47 (correlation units) and dx = 0.008, then in C5 units, c_max ≈ 0.376. The range of (c - c_max) * dx is about [-0.376, 0]. So α * (c-c_max) * dx ranges from -7520 to 0. exp(-7520) underflows! That's a problem.

Let me work in correlation units (not C5 units) for the SLSQP:

obj(x) = max_k c[k] + (1/α) * log(sum_k exp(α * (c[k] - max_j c[j])))

In correlation units, c[k] is around 47, and the range is maybe [-10, 0] relative to max. So α * (c[k] - max) ranges from -α*10 to 0. For α=100, that's [-1000, 0]. exp(-1000) underflows.

I need to be more careful. Let me use:

obj(x) = c_max + (1/α) * log(sum_k exp(α * (c[k] - c_max)))

where c_max = max_k c[k]. Now (c[k] - c_max) ≤ 0, and for a "typical" solution, most values are a few units below the max. If the range is about [-5, 0], then for α=10, α*(c[k]-c_max) ∈ [-50, 0]. exp(-50) ≈ 2e-22, which is fine.

But the issue is that c_max is not differentiable. However, in practice, we can just compute it numerically.

Let me rewrite:

```python
def slsqp_obj(x, n, alpha):

```

Actually, since c_shift ≤ 0, exp(alpha * c_shift) ≤ 1, and the sum is at most (2n-1) = 499. So log(sum) ≤ log(499) ≈ 6.2. The issue is underflow for very negative c_shift. Let me just use:

```python
def slsqp_obj(x, n, alpha):
    c = np.correlate(x, 1.0 - x, mode='full')
    m = c.max()
    c_shift = c - m
    c_shift = np.maximum(c_shift, -40.0 / alpha)  # prevent underflow
    return m + np.log(np.exp(alpha * c_shift).sum()) / alpha
```

With alpha = 50, the minimum c_shift is -0.8 correlation units. So we're effectively ignoring any correlation value that's more than 0.8 units below the max. That should be fine.

Let me also add the gradient for faster convergence:

∂/∂x[i] of c[k] = (1-x[i+k-(n-1)]) - x[i-k+(n-1)] (roughly, with boundary handling)

This is complex to get right. Let me just use numerical gradients (SLSQP does this by default if no jac is provided).

Actually, SLSQP uses finite differences for the gradient by default, which takes n evaluations per gradient step. With n=250, that's 250 correlation computations per gradient, taking ~12ms. With 300 iterations, that's 3.6 seconds. Should be fine.
