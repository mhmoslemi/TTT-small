**New idea: Use the structure of the problem.**

The correlation c[m] = sum_i h[i]*(1-h[i+k]) for valid i. For the max to be small, we need all c[m] to be small. The most constraining shifts are typically the small ones (k=1, 2, 3, ...).

What if we focus specifically on minimizing the first few shifts? We could use a "water-filling" approach:
1. Compute c[m] for all m
2. Identify the top few m values (the "active" constraints)
3. Optimize to equalize the top c[m] values (like in coordinate descent for min-max)

This is essentially what the smooth max does, but we could be more targeted.

**Another idea: Use the KKT conditions.**

At the optimum, for the active constraints (those m where c[m] = C5*), the gradients should be linearly dependent with the constraint gradients. This gives us a system of equations that we could try to solve.

But this is complex to implement. Let me think of something simpler.

**Idea: Coordinate descent with exact 1D optimization.**

For each coordinate i, given all other coordinates fixed, find the optimal h[i] that minimizes C5. This is a 1D optimization problem (minimize max over m of a piecewise-linear function of h[i]).

For a fixed i, c[m] as a function of h[i] is:
- If i is in the valid range for shift k: c[m] = h[i]*(1-h[i+k]) + const = -h[i]*h[i+k] + h[i] + const
  This is linear in h[i] (coefficient is 1-h[i+k], which is fixed).
- If i appears as the second factor: c[m] = h[i-k]*(1-h[i]) + const = -h[i-k]*h[i] + h[i-k] + const
  This is also linear in h[i] (coefficient is -h[i-k]).

So for each m, c[m] is an affine function of h[i]. The max of affine functions is a convex piecewise-linear function of h[i]. We can find its minimum in [0,1] by checking the breakpoints.

This gives us an exact coordinate descent! And it's O(n²) per coordinate (n shifts to check, each requiring finding the max of the resulting c values).

Wait, but when we change h[i], ALL c[m] values change (for all m where i is in the valid range). So the new C5 = max_m (c[m] + Δc[m]) where Δc[m] is the change due to modifying h[i].

For a given h[i] = t, the new c[m] values are:
c_new[m] = c_old[m] + (t - h[i]) * dc[m]/dh[i]

where dc[m]/dh[i] is the derivative (which is 0, ±1, or a combination depending on whether i appears as first or second factor for shift m).

So the new C5 as a function of t is:
C5(t) = max_m (c_old[m] + (t - h[i_old]) * a_m[i])

where a_m[i] = dc[m]/dh[i] is a constant (for fixed i and m).

This is the max of linear functions of t, hence convex and piecewise linear. Its minimum over [0,1] can be found by:
1. Computing all breakpoints (where two linear functions cross)
2. Evaluating at each breakpoint and at 0 and 1
3. Taking the minimum

The number of breakpoints is O(n) (one for each pair of m values), so this is O(n²) per coordinate. For n=300, that's 90,000 operations per coordinate, and 300 coordinates = 27 million per full sweep. That's very fast!

Let me implement this exact coordinate descent!

- The new C5(t) = max_m (c[m] + (t - h[i]) * a_m)

- Its minimum is at a point where the subgradient contains 0

The minimum is where 0 is in the subgradient, i.e., where there exist active m with a_m ≤ 0 and active m' with a_m' ≥ 0.

This is exactly the condition that the maximum is "flat" at the minimum.

However, there's a subtlety: the coordinate descent finds a local minimum (or a point where no single coordinate change improves). For a non-convex problem, this might not be the global minimum. But combined with L-BFGS and pair search, it should be a powerful tool.

Let me also think about the "sum constraint". In the coordinate descent, when I change h[i], the sum changes. I need to either:
1. Enforce the sum constraint separately (project after each coordinate change) - this breaks the exactness
2. Incorporate the sum constraint into the 1D optimization

For option 2: the constraint is sum(h) = n/2. If h[i] changes by δ, the sum changes by δ. To maintain feasibility, we'd need to change another coordinate too. This makes it a 2D optimization, which is more complex.

For option 1: after changing h[i], project back to the feasible set. But the projection changes all coordinates, which invalidates the c_vec update. We'd need to recompute c_vec after each projection, making it O(n²) per coordinate instead of O(n).

Alternative: use the penalty method. Add μ*(sum(h) - n/2)² to the objective. Then the 1D optimization includes the penalty term. The penalty term as a function of t is:
μ * (sum_others + t - n/2)²
which is convex in t. So the total objective (max of linear + quadratic penalty) is convex in t. We can still use ternary search.

But this requires a large μ to enforce the constraint, and it changes the optimal solution.

Better approach: use the Lagrangian. At the optimum, there exists a Lagrange multiplier λ such that:
min_h max_m c[m]*dx + λ*(sum(h) - n/2)

For coordinate i, the 1D problem becomes:
min_t max_m (c[m] + (t-h[i])*a_m)*dx + λ*(sum_others + t - n/2)

This is convex in t (max of linear + linear = convex). We can optimize it with ternary search.

But we need to find the right λ. We can use a bisection on λ:
- If at the current λ, the optimal t gives sum > n/2, increase λ
- If sum < n/2, decrease λ

This is the standard approach for constrained optimization.

Actually, for the coordinate descent, a simpler approach: after each full sweep, project to the feasible set. The projection is cheap (O(n)). The coordinate descent finds a local min of the unconstrained problem, and then we project. Repeat.

This won't find the exact constrained optimum, but it should be close, especially if we alternate between coordinate descent and projection many times.

Actually, I think the cleanest approach is:

2. Update h[i] = t*
3. After the full sweep, project to satisfy sum constraint

The 1D optimization in step 1 doesn't account for the sum constraint, but that's OK as a heuristic. The projection in step 3 fixes the sum, and the next sweep will adjust.

```python
import numpy as np
from scipy.optimize import minimize
import time

def compute_c5_vec(h, n):
    dx = 2.0 / n
    return np.correlate(h, 1.0 - h, mode='full') * dx

def compute_c5(h, n):
    return float(np.max(compute_c5_vec(h, n)))

def project_feasible(h, n):
    target = n / 2.0
    h = np.clip(h.copy(), 0.0, 1.0)
    for _ in range(500):
        diff = target - h.sum()
        if abs(diff) < 1e-15:
            break
        if diff > 0:
            room = 1.0 - h
            tot = room.sum()
            if tot < 1e-15: break
            h += (diff / tot) * room
        else:
            tot = h.sum()
            if tot < 1e-15: break
            h += (diff / tot) * h
    return np.clip(h, 0.0, 1.0)

def _smooth_obj(h, n, alpha):
    c = compute_c5_vec(h, n)
    cmax = c.max()
    sh = alpha * (c - cmax)
    mx = sh.max()
    return float(cmax + (mx + np.log(np.sum(np.exp(sh - mx)))) / alpha)

def _smooth_grad(h, n, alpha):
    c = compute_c5_vec(h, n)
    cmax = c.max()
    sh = alpha * (c - cmax)
    mx = sh.max()
    w = np.exp(sh - mx)
    w /= w.sum()
    dx = 2.0 / n
    grad = np.zeros(n)
    for m in range(2 * n - 1):
        if w[m] < 1e-13: continue
        k = m - (n - 1)
        wm = w[m] * dx
        if k >= 0:
            nv = n - k
            grad[0:nv] += wm * (1.0 - h[k:n])
            grad[k:n] += wm * (-h[0:nv])
        else:
            kk = -k
            nv = n - kk
            grad[kk:n] += wm * (1.0 - h[0:nv])
            grad[0:nv] += wm * (-h[kk:n])
    return grad

def lbfgs_phase(h, n, deadline):
    h = project_feasible(h, n)
    best_c = compute_c5(h, n)
    bounds = [(0.0, 1.0)] * n
    for alpha in [50, 200, 1000, 5000, 20000, 100000, 500000, 2000000]:
        if time.time() > deadline - 3: break
        try:
            res = minimize(_smooth_obj, h, jac=_smooth_grad,
                          args=(n, alpha), method='L-BFGS-B',
                          bounds=bounds,
                          options={'maxiter': 300, 'ftol': 1e-18,
                                   'gtol': 1e-15, 'maxls': 40})
            h_new = project_feasible(res.x, n)
            c_new = compute_c5(h_new, n)
            if c_new < best_c - 1e-15:
                best_c = c_new; h = h_new
        except Exception:
            pass
    return h, best_c

    h = project_feasible(h, n).copy()
    best_c = compute_c5(h, n)
    dx = 2.0 / n
    c_vec = compute_c5_vec(h, n)
    
    for sweep in range(max_sweeps):
        if time.time() > deadline:
            break
        improved = False
        for i in range(n):
            if time.time() > deadline:
                return h, best_c
            hi_old = h[i]
            # Compute a[m] = d(raw_c[m])/dh[i]
            a = np.zeros(2 * n - 1)
            for m in range(2 * n - 1):
                k = m - (n - 1)
                if 0 <= i + k < n:
                    a[m] += (1.0 - h[i + k])
                if 0 <= i - k < n:
                    a[m] += (-h[i - k])
            # Minimize max_m (c_vec[m] + (t - hi_old) * a[m] * dx) over t in [0,1]
            # Ternary search
            lo, hi = 0.0, 1.0
            for _ in range(50):
                t1 = lo + (hi - lo) / 3.0

                f1 = np.max(c_vec + (t1 - hi_old) * a * dx)
                f2 = np.max(c_vec + (t2 - hi_old) * a * dx)
                if f1 < f2:
                    hi = t2
                else:
                    lo = t1
            t_star = (lo + hi) / 2.0
            if abs(t_star - hi_old) > 1e-14:

                c_vec += (t_star - hi_old) * a * dx
                c_new = float(np.max(c_vec))
                if c_new < best_c - 1e-15:
                    best_c = c_new
                    improved = True
        # Project after sweep
        h = project_feasible(h, n)
        c_vec = compute_c5_vec(h, n)
        c_now = float(np.max(c_vec))

def pair_search(h, n, deadline, deltas, radius=None):

    best_c = compute_c5(h, n)
    for d in deltas:
        while time.time() < deadline:

                    return h, best_c
                if radius is None:
