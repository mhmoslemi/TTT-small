If we have a sequence of length n and create a sequence of length 2n by repeating each element, the sum doubles, the convolution gets messier, and the max might change. It's not straightforward.

Actually, let me just focus on n=3072 and try to get the best score there.

One more thought: the evaluator clips to [0, 1000], so all our values are in that range. Since we normalize to sum=1 for n=3072, each element is at most 1 (and typically around 1/3072 ≈ 0.0003), well within the clip range.

def _score_fft(a):
    a = np.asarray(a, dtype=np.float64).ravel()
    n = a.size
    if n == 0:
        return math.inf
    s = float(a.sum())
    if s < 0.01:
        return math.inf
    L = 2 * n - 1
    size = next_fast_len(L)
    F = rfft(a, size)
    c = irfft(F * F, size)[:L]
    c = np.maximum(c, 0.0)
    m = float(c.max())
    if not math.isfinite(m):
        return math.inf
    return float(2.0 * n * m / (s * s))


def _score_exact(a):
    a = np.asarray(a, dtype=np.float64).ravel()
    if a.size == 0:
        return math.inf
    a = np.where(np.isfinite(a), a, 0.0)

    b = np.convolve(a, a)
    m = float(b.max())
    if not math.isfinite(m):
        return math.inf
    return float(2.0 * a.size * m / (s * s))

    return e / s
