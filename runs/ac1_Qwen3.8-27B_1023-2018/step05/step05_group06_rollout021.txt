The key insight is: the convolution is NOT the same as the autocorrelation (sum of products at same offset). The convolution (a*a)[k] = sum_i a[i]*a[k-i], which for k near n-1 involves products of elements that are "far apart" in the original sequence.

For a sequence that's concentrated in the middle, the convolution peak will also be in the middle, and the value depends on how the elements multiply across the offset.

This changes the optimization problem significantly! It's no longer simply "make the sequence uniform." Instead, we want to shape the sequence so that the peak of the convolution is as small as possible relative to the sum squared.

For a sequence of length n that's concentrated (most mass in a few elements), the sum is concentrated, but the convolution peak could be small if the non-zero elements don't "overlap" much in the convolution.

For example, if a has non-zero entries only at positions 0 and n-1:
a = [c, 0, ..., 0, c] (n elements)
conv = [c^2, 0, ..., 0, 2c^2 (at position n-1), ..., 0, c^2]
Wait: conv[k] = sum_i a[i]*a[k-i].
conv[0] = c*c = c^2
conv[n-1] = c*c + c*c = 2c^2 (from a[0]*a[n-1] + a[n-1]*a[0])
conv[2n-2] = c*c = c^2
All other entries are 0.
max = 2c^2. sum = 2c.
score = 2*n*2c^2/(4c^2) = n.

That's terrible for large n.

Now, for the general problem with n=3072, the optimization is much more complex. The key insight is:

The convolution (a*a)[k] = sum_i a[i]*a[k-i] is maximized when the "overlap" of a with its time-reversed version is largest. For a "monotonically increasing" sequence (like [1, 1, ..., 1, x] with x large), the convolution peak is at k=n-1 (the center) and involves many cross-terms.

The strategy to minimize the convolution max relative to (sum)^2/n is to make the sequence shape such that the "cross-correlation" at the peak lag is minimized.

This is related to the theory of "low-autocorrelation sequences" but with nonnegativity constraint and a different objective (minimize peak of linear convolution, not circular).

For the optimization, I think the best approach is:
1. Start from the parent (which presumably already has a good shape)
2. Use coordinate descent or gradient-based methods to minimize the score
3. The key is the peak of the convolution, which is typically near the center (lag n-1)

1. Coordinate descent (like the previous program but more efficient)
2. Maybe a gradient-based approach

For n=3072, the convolution has 6143 elements. The peak is typically near index 3071 (the center). The score depends only on the max of the convolution and the sum.

For coordinate descent: changing one element a[i] affects conv[k] for k in [i, i+n-1] (n elements). The update is:
conv_new[k] = conv_old[k] + 2*(a_new - a_old)*a[k-i] + (a_new - a_old)^2 * delta(k, 2i)

Wait, more precisely: conv[k] = sum_j a[j]*a[k-j]. If we change a[i] from v to v+w:
conv_new[k] = conv_old[k] + w*(a[k-i] + a[i + (k-i)] ... 

Actually: conv[k] = sum_j a[j]*a[k-j]. The terms involving a[i] are:
- j=i: a[i]*a[k-i] (if 0 <= k-i < n)
- k-j=i, i.e., j=k-i: a[k-i]*a[i] (if 0 <= k-i < n)

So if k-i != i (i.e., k != 2i), both terms are present and contribute 2*w*a[k-i].
If k = 2i (i.e., k-i = i), the two terms are the same: w^2 + 2*w*v (the cross term squared gives w^2, and the cross term with the old value gives 2vw, total = (v+w)^2 - v^2).

So the update is: for k in [i, i+n-1]:
conv[k] += 2*w*a[k-i] (old values)
conv[2i] += w^2 (extra diagonal term, if 2i is in range)

This O(n) update per coordinate is what the previous program does. With n=3072 and potentially thousands of sweeps, it's feasible.
