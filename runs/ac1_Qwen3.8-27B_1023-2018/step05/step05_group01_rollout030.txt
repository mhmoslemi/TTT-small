We want max(c) to be as close to the mean as possible. This is like minimizing the "excess" max(c) - mean(c).

A useful metric: the ratio max(c) / mean(c) = max(c) * (2n-1). The minimum is 1 (all equal). For the parent, it's about 1.5077 * (2n-1) / (2n) ≈ 1.5077.

**Improved coordinate polish:**

Key optimization: Instead of scanning all n coordinates in each sweep, only scan coordinates that affect the current peak.

If the current peak is at lag k*, then c(k*) = sum_j a_j * a_{k*-j}. The coordinates that affect c(k*) are those i where 0 <= k*-i < n, i.e., max(0, k*-n+1) <= i <= min(n-1, k*).

For n = 3072 and k* ≈ n-1 = 3071, this is all coordinates (since k* - i ranges from 0 to 3071 when i ranges from 0 to 3071). So for the middle peak, all coordinates are relevant.

But we can be smarter: only update coordinates where a_i is large (since they contribute most to the peak).

**Another idea: Direct peak constraint approach**

Instead of minimizing the max directly, use a constrained formulation:
- Minimize sum of squares of c(k) (or some other smooth objective)
- Subject to c(k) <= M for all k, where M is a target

Use bisection on M: start with M = current max, and try to reduce it.

For a given M, the feasibility problem is:
- Find a >= 0, sum(a) = 1, such that c(k) <= M for all k

This is a quadratically constrained program (QCP), which is non-convex. But we can use it as a heuristic: try to find a feasible a for a given M, and if we can't, increase M.

def peak_shave(p, c, n, steps=100):
    """Directly reduce the peak by adjusting coordinates."""
    L = 2*n - 1
    best_p = p.copy()
    best_c = c.copy()
    best_score = 2.0*n*c.max()

        peak_locs = np.where(c >= peak_val * 0.999)[0]

        # c[k*] = sum_j p[j]*p[k*-j]
