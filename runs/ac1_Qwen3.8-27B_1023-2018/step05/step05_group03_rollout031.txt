Key efficiency tricks:
1. **Vectorized candidate evaluation**: For each coordinate, evaluate all G candidates at once using numpy vectorization.
2. **Precompute affected indices**: For each coordinate i, the affected lags are [i, i+n-1] (clipped to [0, 2n-2]).
3. **Background max**: Precompute the max of c outside the affected range.

Here's the efficient coordinate evaluation:

```python
def _eval_candidates(c, a, i, v, candidates, S, n, bg_max):
    """
    Evaluate score for each candidate value of a[i].
    c: current convolution
    a: current sequence
    i: coordinate index
    v: current value of a[i]
    candidates: array of candidate values for a[i]
    S: current sum
    n: sequence length
    bg_max: max of c outside affected range [i, i+n-1]
    Returns: array of scores
    """
    deltas = candidates - v  # shape (G,)
    # Affected lags: k in [i, min(i+n-1, 2n-2)]
    k_start = i
    k_end = min(i + n, 2 * n - 1)  # exclusive
    L = k_end - k_start
    
    # a[k-i] for k in [k_start, k_end): this is a[0 : L]
    # Wait: k-i ranges from 0 to k_end-1-i = min(n-1, 2n-2-i)
    # So a[k-i] = a[0 : L]  (since L = k_end - k_start = min(n, 2n-1-i))
    
    a_affected = a[:L]  # a[0], a[1], ..., a[L-1]
    
    # New c values: c[k_start:k_end] + 2*delta*a_affected + delta^2*I(k=2i)
    # Shape: (G, L)
    new_c = c[k_start:k_end][None, :] + 2.0 * deltas[:, None] * a_affected[None, :]
    
    # Add delta^2 where k = 2i
    diag_offset = 2 * i - k_start
    if 0 <= diag_offset < L:
        new_c[:, diag_offset] += deltas ** 2
    
    # Max for each candidate
    new_max = np.maximum(new_c.max(axis=1), bg_max)
    
    # Score: 2n * new_max / (S + delta)^2
    new_S = S + deltas
    valid = new_S > 1e-10
    scores = np.full(len(candidates), math.inf)
    scores[valid] = 2.0 * n * new_max[valid] / (new_S[valid] ** 2)
    
    return scores
```

This is O(G*L) per coordinate, which is O(G*n) on average. Vectorized in numpy, this should be fast.

Wait, but G*L might be large. With G=50 and L~n=3072, that's 153,600 elements per coordinate. Creating a (50, 3072) array for each of the 3072 coordinates means creating ~472M elements total per sweep. At 8 bytes each, that's ~3.8 GB per sweep! That's way too much memory.

I need to be smarter. Options:
1. Use a smaller G (e.g., G=20)
2. Don't create the full (G, L) array; instead, compute the max more efficiently
3. Process in batches

Actually, option 2 is possible. The new_c values are:
new_c[k] = c[k] + 2*delta*a[k-i] + delta^2*I(k=2i)

For a fixed candidate delta, the max over k in [k_start, k_end) is:
max(c[k_start:k_end] + 2*delta*a[:L] + delta^2*I(k=2i))

This is the max of an array plus a scaled version of another array (plus a correction at one point). There's no closed-form for this in general, but we can compute it efficiently.

For positive delta: the array c[k] + 2*delta*a[k-i] is a "shifted" version. The max will be near where c is large or where a is large (weighted by delta).

For negative delta: similar but the contribution is negative, so the max will be at the largest c[k] where a[k-i] is smallest.

Actually, for small |delta| (which is the case in coordinate descent near the optimum), we can use the first-order approximation:
new_max ≈ max(c) + delta * 2 * a[argmax(c) - i] (if the argmax is in the affected range)

But this isn't accurate enough for precise optimization.

Let me go with a smaller G and accept that each sweep takes a bit longer. With G=32:
- Per coordinate: 32 * 3072 = 98,304 elements
- Per sweep: 3072 * 98,304 * 8 bytes = 2.4 GB... still too much!

OK, the issue is that we can't hold the (G, L) array in memory for all coordinates simultaneously. But we process one coordinate at a time, so we only need one (G, L) array in memory at a time. That's 32 * 3072 * 8 = 786 KB, which is fine!

So the approach is:
- For each coordinate i (one at a time):
  - Create the (G, L) array (small enough to fit in L1/L2 cache)
  - Compute the max along axis 1
  - Find the best candidate
  - Update the convolution and sequence

The total computation per sweep is O(n * G * L) = O(n^2 * G) flops, but with good memory access patterns (each (G, L) array fits in cache), this should be fast.
