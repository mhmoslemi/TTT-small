One more thought: the problem is to minimize `max_k result[k]` (with normalization). This is the minimum of a maximum of 2n-1 quadratic forms over the simplex. The LP-based Frank-Wolfe approach works by:
1. At current point f, compute M = max(f*f)
2. Find the "best" g such that all cross-terms (f*g)[k] <= M
3. Move towards g

The key insight: if (f*g)[k] <= M for all k, then for small t:
((1-t)f + t*g) * ((1-t)f + t*g)[k] = (1-t)² (f*f)[k] + 2t(1-t)(f*g)[k] + t²(g*g)[k]

The first two terms are bounded (≤ (1-t)²M + 2t(1-t)M), but the t²(g*g)[k] term is unbounded. So for large t, the new point might have a larger max. This is why we need the line search.

However, if g is chosen to also have (g*g)[k] <= M (or at least bounded), then the move is safe. The LP as stated doesn't guarantee this. A stronger LP would be:
maximize sum(g) subject to (f*g)[k] <= M AND (g*g)[k] <= M for all k.

But (g*g)[k] <= M is a quadratic constraint, making this a QCQP. We could linearize: (g*g)[k] ≈ 2*g[k-m]*f[m]... actually, let's use the first-order approximation:
(g*g)[k] ≈ (f*f)[k] + 2(g-f) * gradient of (f*f)[k] at f

This gives linear constraints on g. But it's a relaxation.

Alternatively, we can solve the LP and then check: if max(g*g) > M, we reduce the step size.

I think the practical approach is:
1. Solve the LP to get direction g
2. Use backtracking: try t = 0.5, 0.25, 0.125, ... until score improves

- For each k, the quadratic q_k(t) = t²(G_k - 2C_k + F_k) + t(2C_k - 2F_k) + F_k
- We want min_t max_k q_k(t)
- This can be solved by bisection on the value: for a given value V, check if there exists t with all q_k(t) <= V
