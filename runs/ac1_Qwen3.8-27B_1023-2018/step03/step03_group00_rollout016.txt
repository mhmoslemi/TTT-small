Key improvements over the parent:

Let me also think about the coordinate descent more carefully. For the objective max_k c_k(x) with sum(x)=1, x>=0:

When I change x_i, the convolution changes. I need to recompute the full convolution. For n=416, one FFT convolution takes maybe 0.1ms. So even scanning 416 coordinates × 9 multipliers = 3744 evaluations per epoch, that's about 0.4s per epoch. That's reasonable.

But actually, I can be smarter. When I change x_i from a to b, the change in c_k is:
Δc_k = (b-a) * (x_{k-i} + x_{i-k}) for valid indices... wait, no.

c_k = sum_j x_j x_{k-j}
If I change x_i from a to b:
c_k = sum_{j≠i} x_j x_{k-j} + x_i x_{k-i}
     = sum_{j≠i} x_j x_{k-j} + b * x_{k-i}

But also, x_i appears as the second factor when j = k-i:
c_k = ... + x_{k-i} x_i + ... (when j = k-i)

So the change is more subtle. Let me think again.

c_k = sum_j x_j x_{k-j}

If x_i changes by Δ = b - a:
Δc_k = Δ * x_{k-i} (from j=i term) + x_i * Δ (from j=k-i term, if k-i ≠ i)
     = Δ * (x_{k-i} + x_i) if k-i ≠ i (i.e., k ≠ 2i)
     = Δ * 2*x_i if k = 2i (since x_{k-i} = x_i)

Wait, that's not right either. Let me be very explicit.

c_k = sum_{j: valid} x_j * x_{k-j}

The terms involving x_i are:
- j = i: x_i * x_{k-i} (if 0 ≤ k-i < n)
- j = k-i: x_{k-i} * x_i (if 0 ≤ k-i < n and k-i ≠ i)

If k-i = i (i.e., k = 2i), there's only one term: x_i * x_i. Δc_k = 2Δ*x_i.
If k-i ≠ i, there are two terms. Δc_k = Δ*x_{k-i} + Δ*x_i = Δ*(x_{k-i} + x_i).

So I can compute the change in the convolution efficiently:
Δc = Δ * (x shifted) + Δ * (x reflected and shifted)

This is O(n) per coordinate change. 

But for n=416, the FFT convolution is already so fast that it might not matter. Let me just use FFT.

Actually, let me reconsider. The main bottleneck is the LP solve. Each LP solve takes about 0.5-2 seconds for n=416. The line search is O(n * num_t_values) = O(416 * 16) ≈ 6K ops, which is negligible.

So the main cost is the LP. In 1300s, if each LP takes 1s, I can do about 1000 LP iterations. The parent does much fewer.

Let me think about whether there's a way to avoid the LP entirely and use a different approach.

**Alternative: Alternating projection / Bregman iteration**

The problem is: min max_k c_k(x) s.t. x ≥ 0, sum(x) = 1.

This is equivalent to: min t s.t. c_k(x) ≤ t for all k, x ≥ 0, sum(x) = 1.

We can use a penalty method: min_{x} max_k c_k(x) + λ * max(0, 1 - sum(x))^2 + μ * ||min(x,0)||^2

Or we can use the ADMM split:
- Introduce t: min t s.t. c_k(x) ≤ t, x ≥ 0, sum(x) = 1
- ADMM: x-update: min max_k c_k(x) + ρ/2 ||x - z + u||^2 + indicator(x ≥ 0, sum(x)=1)
- t-update: min t + ρ/2 ||t - s + u||^2 + indicator(c_k ≤ t for all k)
- z-update: min ρ/2 ||z - x + u||^2 + indicator(z ≥ 0, sum(z)=1)

This is getting complicated. Let me stick with the LP approach but make it faster.

**Key optimization: avoid rebuilding the A matrix each iteration.**

The A matrix is determined by f, which changes each iteration. So I can't cache it. But I can use the structure of A (it's a block Toeplitz matrix). For n=416, the explicit matrix is 831×416 ≈ 346K entries, which is fine.

Actually, wait. I just realized something. The A matrix construction with the loop `for j in range(n): A[j:j+n, j] = f` is O(n²) = O(173K) for n=416. That's fast.

The LP solve with HiGHS for 831 constraints and 416 variables should take < 1s typically.

Let me now think about the line search more carefully.

Given f (sum=1), g (sum=1), and t ∈ [0,1]:
x(t) = (1-t)f + tg
c(t)_k = (1-t)² c^ff_k + 2t(1-t) c^fg_k + t² c^gg_k

We want to minimize max_k c(t)_k.

Each c(t)_k is a quadratic in t. The max of quadratics is a convex piecewise-quadratic function.

I can find the minimum by:
1. Evaluating at a grid of t values
2. Refining with golden section search
3. Or finding all "crossing points" of the quadratics (expensive)

For practical purposes, a grid of 20-30 points in [0,1] should be sufficient.

But there's a subtlety: x(t) must have all non-negative entries. Since f, g ≥ 0 and t ∈ [0,1], x(t) ≥ 0 automatically. Good.

Also, sum(x(t)) = (1-t)*1 + t*1 = 1. Good, the normalization is preserved.

    """Compute the change in convolution when x[i] changes by delta.
    x: the current sequence (length n)
    i: the index to change
    delta: the change (new value - old value)
    current_c: current convolution (length 2n-1)
    Returns: updated convolution
    """
    n = len(x)
    new_c = current_c.copy()
    # Change: c_k = sum_j x_j x_{k-j}
    # When x[i] changes by delta:
    # c_k_new = c_k + delta * x_{k-i} (for j=i) + delta * x_i (for j=k-i, if k-i ≠ i)

    Fa = rfft(a, fa)

    return irfft(Fa * Fb, fa)[:len(a)+len(b)-1]

def _exact_score(a):
    n = len(a)
    s = float(a.sum())
    if s < 0.01: return math.inf
    m = float(_conv(a).max())
    if not math.isfinite(m): return math.inf
    return 2.0 * n * m / (s * s)

def _project_simplex(v, target=1.0):
    """Project v onto {x>=0, sum(x)=target}"""
    n = len(v)
    if n == 0: return v
    w = np.sort(v)[::-1]
    cw = np.cumsum(w)
    rho = np.nonzero(w * np.arange(1, n+1) > (cw[-1] - target))[0]
    if len(rho) == 0:
        return np.zeros(n)
    rho = rho[-1]
    theta = (cw[rho] - target) / (rho + 1.0)
    result = np.maximum(v - theta, 0.0)
    return result
