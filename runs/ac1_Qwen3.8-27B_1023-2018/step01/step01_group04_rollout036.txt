    stop = time.monotonic() + time_limit
    a = np.asarray(a, dtype=np.float64).copy()
    a = np.clip(a, 0.0, None)
    s = float(a.sum())
    if s > 1e-15:
        a = a / s

            break

        M = float(np.max(b))
        if not math.isfinite(M):
            break

        threshold = M * 0.999
        active_lags = np.where(b >= threshold)[0]
        
        # Compute subgradient: sum over active lags of 2*a[k-j]
        grad = np.zeros(n, dtype=np.float64)
        for k in active_lags:
            for j in range(n):

                if 0 <= idx < n:

        gn = float(np.linalg.norm(grad))
        if gn < 1e-15:

            gn = float(np.linalg.norm(grad))
            if gn < 1e-14:

                cand = np.clip(cand, 0, None)
                cs = cand.sum()
                if cs < 1e-15:
                    continue
                cand /= cs
                v = sc(cand)
                if v < best_sc:
                    best_sc, best_c = v, cand

            if best_c is not None and best_sc < local * (1 - 1e-12):
                a = best_c
                local = best_sc
                stale = 0
                ub(a)
            else:

                    if ap.sum() > 1e-15:

                        if sc(ap) < local:
                            a, local = ap, sc(ap)

                            ub(a)

Actually, I just realized something important. The LP formulation:
max sum(g) s.t. (a*g)[k] <= M for all k, g >= 0

This finds a g that is "easy to correlate with" a (in the sense that a*g is bounded). The idea is that g represents a "target" autocorrelation shape that is compatible with a.

But the actual improvement comes from the blend (1-t)*a + t*g. The blend's autocorrelation is:
((1-t)*a + t*g) * ((1-t)*a + t*g)
= (1-t)^2 (a*a) + 2t(1-t)(a*g) + t^2 (g*g)

We know (a*a) has max M and (a*g) has max <= M (by LP constraint). But we don't know about (g*g)!

If (g*g) also has max <= M, then the blend has max <= M for all t. But the LP doesn't ensure this.

However, if g is close to a (which happens when the LP constraint is tight), then (g*g) is also close to (a*a) and the blend is good.

The issue is that when the LP constraint is loose (margin < 1), g might be very different from a, and (g*g) could have a much larger peak. The line search handles this by finding the best t.
