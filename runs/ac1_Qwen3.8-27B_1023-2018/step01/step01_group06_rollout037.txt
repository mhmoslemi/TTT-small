g[j] = 2 * sum_{m: 0 <= m < n} p_{j+m} * a[m] (where p_{j+m} = 0 if j+m >= 2n-1)

This is a cross-correlation between p and a! Specifically:
g[j] = 2 * (p ⋄ a)[j]

where ⋄ denotes cross-correlation. This can be computed with FFT in O(n log n).

So the algorithm is:
1. Compute c = convolve(a, a) [FFT, O(n log n)]
2. Compute p = softmax(c / tau) [O(n)]
3. Compute g = 2 * correlate(p, a) [FFT, O(n log n)]
4. Update: a = a * exp(-eta * g / max(g)), normalize [O(n)]

Each iteration is O(n log n), dominated by the FFTs.

With n = 4498, each FFT is about 4498 * 13 ≈ 58,000 operations. We need 2 convolutions (one for c, one for the correlation) and a few O(n) operations. So each iteration is maybe 200,000-500,000 operations. At ~100M operations/second (conservative for numpy with FFT), that's about 2-5ms per iteration. In 1300 seconds, we can do about 260,000 to 650,000 iterations. That should be more than enough.

Wait, but numpy's FFT isn't that fast for real arrays of size 4498. Let me be more conservative. Let's say each iteration takes 10ms. Then in 1300 seconds, we can do about 130,000 iterations. Still plenty.

The key question is: how fast does the log-sum-exp gradient descent converge?

For the log-sum-exp objective, the strong convexity parameter depends on tau. For small tau (closer to the true max), the convergence is slower but the solution is more accurate. For large tau, convergence is faster but the solution is less accurate.

A good strategy is to use a decreasing tau schedule: start with large tau (fast convergence to a rough solution) and gradually decrease tau (refine the solution).
