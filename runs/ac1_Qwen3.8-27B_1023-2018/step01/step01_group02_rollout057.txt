2. The gradient computation - O(n log n) with FFT.
3. The softmax - O(n).
4. Adam update - O(n).

In practice, for n=127:
- Convolution: ~10μs
- Gradient (FFT): ~5μs
- Softmax + Adam: ~5μs
- Python overhead: ~20μs
Total: ~40μs per iteration

So in 160s, we can do about 4 million iterations. Way more than enough.

Let me focus on making the optimization converge well rather than doing millions of iterations.

Key improvements to make:
1. **Better annealing schedule**: Start with low beta (50), increase gradually to high beta (50000+)
2. **Adaptive learning rate**: Start high, decay over time
3. **Multiple restarts**: Don't just do one long run; do several shorter runs from different starting points
4. **Local search**: Gradient-free polishing in the final phase
5. **The "equalization" trick**: When we identify which convolution terms are at the max, we can try to equalize them

Let me also think about whether there's a structural insight I'm missing.

For the problem min max(f*f) s.t. f ≥ 0, sum(f) = 1:
- The optimal f should make f*f as "flat" as possible
- The flat value would be 1/(2n-1)
- So we want f*f ≈ 1/(2n-1) for all k

This is related to "sliding block codes" and "low autocorrelation sequences." For binary sequences, this is the Chen-Fineitch problem. For continuous nonnegative sequences, it's related to "Gaussian minimum phase sequences" in signal processing.

I think the optimal structure for moderate n has a "bell-shaped" profile in the frequency domain (concentrated in low frequencies), which corresponds to a smooth, roughly unimodal profile in the time domain. But with a specific shape that equalizes the convolution.
