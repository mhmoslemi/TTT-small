```python
def project_simplex(z, target=1.0):
    n = len(z)
    zs = np.sort(z)[::-1]
    cumsum = np.cumsum(zs)
    rho = np.arange(1, n+1)
    # Find largest rho where z_(rho) > (cumsum[rho-1] - target) / rho
    # i.e., rho * z_(rho) > cumsum[rho-1] - target
    # i.e., cumsum[rho-1] - rho * z_(rho) < target
    # Note: cumsum[rho-1] - rho * z_(rho) = sum_{i=1}^{rho-1} (z_(i) - z_(rho))
    condition = (cumsum - rho * zs) < target
    rho_star = np.max(np.where(condition)[0]) + 1 if condition.any() else 0
    if rho_star == 0:
        return np.full(n, target / n)
    tau = (cumsum[rho_star-1] - target) / rho_star
    return np.maximum(0.0, z - tau)
```

Hmm, I'm not sure the line search is the best approach. It does up to 5 convolution computations per iteration, which is expensive. Let me simplify: just take the step, and if it doesn't improve, halve the step size (but don't recompute the gradient).

- Always take the step
- If the new cmax > old cmax, revert and halve lr
- If new cmax <= old cmax, accept and slightly increase lr

This is like a "barrier" method.

Let me also reconsider: do I really need the line search? The gradient is approximate (softmax approximation of max). If the softmax is sharp enough, the gradient is a good descent direction. The issue is the step size.

Let me try a different approach: **exponential gradient (ExponGrad)**. Instead of `a - lr * g`, use:
`a_new[i] = a[i] * exp(-lr * g[i]) / (1 + lr * g[i])` (or something similar)
Then normalize.

This naturally preserves positivity and can be more stable.

Actually, the simplest and most robust approach is:
1. Compute gradient
2. `a_new = a - lr * g`
3. `a_new = max(a_new, 0)`
4. `a_new = a_new / sum(a_new)`
5. Accept if improved, else halve lr

The projection (step 3-4) is a simple projection onto the nonnegative simplex. It's not the exact Euclidean projection, but it's close enough and much faster than the sort-based method.

Wait, `max(a, 0)` then normalize is NOT the same as the Euclidean projection. The Euclidean projection is:
- Find tau such that sum(max(0, z_i - tau)) = 1
- Return max(0, z_i - tau)

The simple "clip and normalize" is:
- max(0, z) / sum(max(0, z))

These can differ. But for practical purposes, the simple version might work fine, especially if we're not too far from the simplex.

Let me go with the simple version for speed, and switch to the proper projection if we have time.
