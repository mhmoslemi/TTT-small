This is similar to the primal-dual method. The key question is: does max(a*a) decrease?

At the LP optimum, we have (a*g)_k <= M for all k. By the constraint sum g = 1, we have sum_k (a*g)_k * p_k = M for some "average" sense. But (a*a) is what we care about, not (a*g).

Hmm wait, the LP approach builds a 2n-1 by n+1 matrix, which for n=127 is 253x128. That's fine. But doing it in a Python loop is slow. Let me vectorize.

Actually, for the LP, I can construct A_ub more efficiently. The (a*g)_k values form the convolution of a and g. As a function of g, (a*g)_k is linear. The matrix A such that (a*g)_k = (Ag)_k is a Toeplitz-like matrix.

Let me use scipy.signal.convolve or just construct the matrix properly.

For n=127, the LP has 253 constraints and 128 variables. This is tiny. Even constructing the matrix in a loop takes < 1ms. The LP solve should be < 10ms. So we can do thousands of iterations.

Let me also think about whether the LP approach actually helps. The LP finds g that minimizes M such that (a*g)_k <= M for all k. This M is not the same as max(a*a). But the idea is that by iterating a <- blend(a, g), we move toward a sequence where (a*a) is more "flat".

Actually, I realize there might be an issue. The LP minimizes M subject to (a*g)_k <= M. The optimal g will try to put weight where a is small (to make (a*g)_k small at most lags). But this g might not be a good direction for a.

Let me think differently. The problem is:
min 2n * max_k (a*a)_k / (sum a)^2

Let me try a direct approach: use the subgradient method on the max.

The subgradient of max_k c_k(a) where c_k(a) = (a*a)_k is any convex combination of the active subgradients. If the max is unique at k*, the subgradient is ∇c_{k*}(a).

So the gradient descent direction is just: a <- a - lr * ∇c_{k*}(a), where k* = argmax (a*a)_k.

But this only reduces the active peak; other peaks might grow. A better approach is to use a "planning" subgradient: pick k* with some probability proportional to exp(beta * (c_k - c_max)).

Actually, the previous program's approach of using a smoothed max (Gumbel-softmax) is essentially this. The issue is convergence speed.

Let me try a different strategy: **alternating between peak reduction and spreading**.

1. Find the active lag k* = argmax (a*a)_k
2. Compute ∇c_{k*}(a)
3. Update a in the negative gradient direction (reducing the peak)
4. Also add a small component that spreads a more uniformly (reducing sum a_i^2)

Or better: use an **adaptive weighting** approach. Weight each lag k by w_k = exp(beta * c_k / c_max) / sum_j exp(beta * c_j / c_max). Then the gradient is sum_k w_k * ∇c_k(a). This is the smoothed max approach.

Let me try yet another approach: **direct optimization with adaptive subgradient**.

At each step:
1. Compute c = convolve(a, a)
2. Find top-M lags: k_1, ..., k_M (say M=5)
3. For each active lag, compute its gradient
4. Take a weighted combination (weights proportional to c_k)
5. Update a with step size decay
6. Project onto a >= 0 (clip negatives)

This is more robust than the full softmax approach.

Let me code this up properly. For n=127, each iteration is:
- convolve: O(n^2) = ~16K ops (or O(n log n) with FFT)
- gradient computation: O(n * n_active) 
- update: O(n)
Total: very fast. Can do 100K+ iterations in the time budget.

def _normalize(a):
    a = np.asarray(a, dtype=np.float64).copy()
    a = np.maximum(a, 0.0)
    s = a.sum()
    if s < 1e-300:
        return np.ones(a.size, dtype=np.float64) / a.size
    return a / s

def _score(a):
    a = np.asarray(a, dtype=np.float64)
    n = a.size
    if n == 0:
        return np.inf
    s = a.sum()
    if s < 1e-300:
        return np.inf
    c = np.convolve(a, a)
    return 2.0 * n * float(c.max()) / (s * s)

def _convolve(a, b):
    return np.convolve(a, b)

def _grad_conv(a, k):
    """Gradient of (a*a)_k w.r.t. a, where a has length n."""
    n = a.size
    g = np.zeros(n)
    for i in range(n):
        j = k - i
        if 0 <= j < n:
            g[i] += a[j]
        # Check if a[i] appears as the second factor
        j2 = i
        if k - j2 != i and 0 <= k - j2 < n:
            # a[i] is the second factor: a[k-j2] where k-j2 = i, so j2 = k-i
            # This is the same as above, already counted
            pass
    # Actually, (a*a)_k = sum_i a[i]*a[k-i] for valid indices
    # d/d a[m] = a[k-m] (first factor) + a[m] (second factor, when k-i=m, i=k-m)
    # Wait, the second factor: a[k-i] depends on a[m] when k-i = m, i.e., i = k-m
    # So d/d a[m] = a[k-m]*I(0<=k-m<n) + a[k-m]*I(0<=k-m<n) [when i=k-m is valid]
    # But if m = k-m (i.e., k=2m), it's just 2a[m] (derivative of a[m]^2)
    # In general: d/d a[m] = 2*a[k-m] * I(0<=k-m<n) BUT
    # wait, that's only if both i=m and i=k-m give valid terms AND m != k-m
    # Let me redo carefully:
    # (a*a)_k = sum_{i valid} a[i] * a[k-i]
    # where valid means 0<=i<n and 0<=k-i<n
    # d/d a[m]:
    #   - a[m] appears as first factor when i=m: valid if 0<=m<n and 0<=k-m<n → contributes a[k-m]
    #   - a[m] appears as second factor when k-i=m, i.e., i=k-m: valid if 0<=k-m<n and 0<=m<n → contributes a[k-m]
    #   - If m = k-m (k=2m): a[m] appears in both factors of the same term a[m]*a[m], derivative = 2a[m]
    #   - If m != k-m: a[m] appears in two different terms, derivative = a[k-m] + a[k-m] = 2a[k-m]
    # In both cases: derivative = 2*a[k-m] * I(0<=k-m<n and 0<=m<n)
    # But wait, if m = k-m, then a[k-m] = a[m], and the derivative of a[m]^2 is 2a[m] = 2a[k-m]. ✓
    # So: grad[m] = 2*a[k-m] if 0<=k-m<n, else 0
    
    g = np.zeros(n)
    # k-m in [0,n) → m in [k-(n-1), k] intersect [0,n)
    m_min = max(0, k - n + 1)
    m_max = min(n - 1, k)
    if m_max >= m_min:
        g[m_min:m_max+1] = 2.0 * a[k - np.arange(m_min, m_max+1)]
    return g
