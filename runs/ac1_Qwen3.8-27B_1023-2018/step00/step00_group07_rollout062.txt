from scipy.fft import fft, ifft

def _fft_convolve(a, b):
    """Linear convolution via FFT."""
    n = len(a) + len(b) - 1
    size = 1 << (n - 1).bit_length()  # next power of 2
    A = fft(a, size)
    B = fft(b, size)
    return ifft(A * B).real[:n]

def _compute_score(a):
    """Compute 2n * max_conv / sum^2."""
    n = len(a)
    conv = _fft_convolve(a, a)
    return 2 * n * conv.max() / (a.sum() ** 2)

    beta = 100.0

        a = a_new

                no_improve_count = 0

At k=n-2: (n-2+1)/n^2 - 1/n = (n-1-n)/n^2 = -1/n^2.

So the "drop" from the peak at k=n-2 is only 1/n^2 ≈ 2.2*10^-8. To make exp(β*(-1/n^2)) significantly less than 1, we need β >> n^2.

This confirms that β needs to be very large (order n^2 or more) to resolve the peak.

Alternatively, I can work with a different normalization. Instead of normalizing to sum=1, I can normalize to max_conv = 1 and optimize sum. Or I can use a different smoothing.

Actually, the issue is that for very large n, the triangular autocorrelation is very "pointy" - the peak sticks up above the rest by a large factor. So even a small β gives a delta-like weight at the peak, and the gradient is essentially the subgradient at a single point.

For a single-point subgradient (k*=n-1):
grad[j] = 2*a[n-1-j] for j in [0, n-1] (all valid since 0 <= n-1-j <= n-1).
For uniform a: grad[j] = 2/n for all j. Uniform gradient, killed by normalization.

So for the uniform sequence, the subgradient is in the "null space" of the normalization. The optimization is stuck!

To escape, I need to either:
1. Start from a non-uniform sequence
2. Use the smoothed max with appropriate β to get non-uniform weights
3. Use a different strategy altogether

For option 1: the parent (height_sequence_1) has score 2.0, which is the same as uniform. Is it actually uniform? If it's exactly uniform, we're in the same stuck situation.

The parent has length 6733 and score 2.0. It might not be exactly uniform (it could have small variations), but the score being exactly 2.0 suggests it's very close to uniform.

With weights concentrated near k*=n-1:

The corrections from neighboring k give a non-uniform component! Specifically, weight at k=n-2 (slightly less than k=n-1) gives:

For uniform a, a[n-2-j] = 1/n = a[n-1-j]. So the contribution is proportional to w[n-2] * 1/n, same as the k=n-1 contribution scaled by w[n-2]/w[n-1].

Hmm, for uniform a, ALL the gradient components are still 2/n regardless of k! Because a[k-j] = 1/n for all valid k-j.

Let me also consider a completely different approach: solve the problem as a sequence of linear programs or use a semidefinite programming relaxation.

Actually, here's another idea. The problem is:
minimize max_k conv[k] subject to sum(a) = 1, a >= 0.

This is equivalent to:
minimize t
subject to: sum_i a[i] a[k-i] <= t for all k
           sum(a) = 1
           a >= 0

The constraints are quadratic (non-convex in general), but if we fix a[0] = c (some constant) and optimize the remaining n-1 variables, the constraints become:
sum_i a[i] a[k-i] <= t, which is quadratic in the remaining variables.

Still non-convex. But if we use the LP relaxation from the hint:
Fix f = current a. M = max conv(f, f).
Solve: max sum(b) s.t. conv(f, b)[k] <= M for all k, b >= 0.
This IS linear in b!

The solution b* gives a direction. Then normalize b* to sum=1 and mix: a_new = (1-α)a + α*b*.

The LP has n variables and 2n-1 constraints. For n=6733, that's 6733 vars, 13465 constraints. The constraint matrix is 13465 × 6733, which is about 726 MB in float64. Too much for memory.

But we can use a reduced LP with only the top K constraints:
max sum(b) s.t. conv(f, b)[k] <= M for k in top_K, b >= 0

With K=100: 100 × 6733 matrix ≈ 2.7 MB. Very manageable!

The LP can be solved with scipy.optimize.linprog or cvxpy with CBC.

Let me combine both approaches:
1. Use the smoothed gradient method for most iterations (fast, O(n log n))
2. Periodically use the LP direction (slower but potentially more effective)
