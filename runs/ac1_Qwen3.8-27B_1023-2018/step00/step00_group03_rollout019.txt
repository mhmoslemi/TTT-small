conv[n-1] ≈ (1/n²) * (n + ε * sum_i (δ_i + δ_{n-1-i}))
= (1/n) * (1 + ε * 2*sum_i δ_i / n)

For k = 0:
conv[0] ≈ (1/n²) * (1 + 2εδ_0)

The max is at the center for small ε (since n >> 1). So perturbing doesn't help much - the center is always the bottleneck for near-uniform sequences.

But the LP method is not a small perturbation. It finds the GLOBAL optimum of the LP, which could be very different from the uniform. The constraint (a*g)[k] <= M for all k is a set of linear constraints on g, and the optimum g will be very different from a if a is uniform.

For uniform a = (1/n) * ones:
(a*g)[k] = (1/n) * sum_{valid i} g[i] (where i and k-i are both in [0,n-1])
= (1/n) * (sum of g over the overlap window)

The constraint is: sum of g over overlap window <= n*M (where M = max(a*a) = 1/n for uniform, so n*M = 1).

Actually, M = max(conv(a,a)) = max of (1/n²) * [1, 2, 3, ..., n, n-1, ..., 2, 1] = 1/n.
So the constraint is: (1/n) * (sum of g over window) <= 1/n, i.e., sum of g over window <= 1.

For the center window (k=n-1): sum of ALL g <= 1.
For the edge windows (k=0): g[0] <= 1.
For k=1: g[0] + g[1] <= 1.
...
For k=n-1: g[0] + ... + g[n-1] <= 1.

The most binding constraint is the center: sum(g) <= 1.
So the LP is: max sum(g) s.t. sum(g) <= 1, g >= 0.
The optimum is any g with sum = 1, and the objective is 1.

That means the LP doesn't change the sequence at all when starting from uniform! Because the constraints are not tight enough to force a specific direction.

This is a problem. The LP method as described works when the constraints are active in a meaningful way, but for the uniform, only the center constraint is tight.

I need a different approach for breaking the uniform symmetry.

**Alternative: Direct gradient-based optimization**

Let me define:
f(a) = max_k conv(a)[k] / (sum a)² (with the 2n factor, but it's just a constant)

Since the objective is homogeneous, fix sum(a) = 1 and minimize max_k conv(a)[k].

The gradient of max_k h_k(a) where h_k(a) = conv(a)[k] = sum_i a_i * a_{k-i}:
∂h_k/∂a_j = a_{k-j} + a_{k-j}... wait.

h_k(a) = sum_i a_i * a_{k-i}
∂h_k/∂a_j = a_{k-j} + (k-j) * a_j... no.

Let me be careful:
h_k = sum_i a_i * a_{k-i}

∂h_k / ∂a_j = a_{k-j} (from the term where i=j) + sum_i a_i * ∂a_{k-i}/∂a_j
The second term: ∂a_{k-i}/∂a_j = 1 if k-i = j, i.e., i = k-j. So:
∂h_k / ∂a_j = a_{k-j} + a_{k-j} = 2*a_{k-j} (if k-j is in [0,n-1])
But wait, this double-counts when i = k-i, i.e., when 2i = k. In that case, the term is a_i² and the derivative is 2*a_i, not 2*a_{k-i} = 2*a_i. So actually:

h_k = sum_i a_i * a_{k-i}
When i ≠ k-i (i.e., i ≠ k/2): terms are a_i * a_{k-i}, contributing 2 * a_{k-i} to ∂h_k/∂a_i.
Wait, no. Let me just differentiate directly:

h_k = sum_i a_i * a_{k-i}
∂h_k / ∂a_j = sum_i [∂a_i/∂a_j * a_{k-i} + a_i * ∂a_{k-i}/∂a_j]
= sum_i [δ_{ij} * a_{k-i} + a_i * δ_{k-i,j}]
= a_{k-j} + a_{k-j}
= 2 * a_{k-j} (if k-j is in [0,n-1], else 0)

Wait, but when i = k-i (i.e., k is even and i = k/2), the term a_i * a_i appears once in the sum, and its derivative w.r.t. a_j is:
If j = i = k/2: ∂(a_j²)/∂a_j = 2*a_j.
In my formula: 2 * a_{k-j} = 2 * a_{k-k/2} = 2 * a_{k/2} = 2*a_j. ✓

So the gradient is: ∇_j h_k = 2 * a_{k-j} (if 0 <= k-j < n) else 0.

But wait, this doesn't account for the fact that a_{k-i} is the same variable as a_{(k-i)} when we sum over i. Let me re-derive.

h_k = sum_{i: 0<=i<n, 0<=k-i<n} a_i * a_{k-i}

Let me split: for each pair (i, j) with i+j=k:
- If i ≠ j: the term a_i * a_j appears twice (once with i, once with j).
- If i = j (k even, i=k/2): the term a_i² appears once.

So h_k = sum_{i < k-i} 2*a_i*a_{k-i} + (if k even) a_{k/2}²

∂h_k/∂a_j:
- From terms where i=j: 2*a_{k-j} (if j < k-j, i.e., j < k/2)
- From terms where k-i=j, i.e., i=k-j: 2*a_{k-j} (if k-j < j, i.e., k-j < k/2, i.e., j > k/2)
- From the diagonal term (if j = k/2): 2*a_j

In all cases: ∂h_k/∂a_j = 2*a_{k-j} (if 0 <= k-j < n).

Great, so the subgradient of max_k h_k is 2*a_{k*-j} where k* is an argmax.

For the objective F(a) = max_k h_k(a) / (sum a)² (with sum a = 1, this is just max h_k):
∇F = 2 * a_{k*-j} (cyclic, with a[i]=0 for i outside [0,n-1])

For gradient descent: a_new = a - η * 2 * a_{k*-j} (then project to nonnegative and renormalize).

This is like: "reduce the values of a that contribute to the peak." Specifically, if the peak is at k*, then a_{k*-j} is the "reverse" of a shifted by k*. So we reduce a[j] proportional to a[k*-j].

This is a multiplicative-like update: a[j] *= exp(-2η*a[k*-j])

Let me implement this:

```python
# Gradient descent on max-conv
for iteration in range(max_iters):
    conv = fftconvolve(a, a)
    k_star = argmax(conv)
    # subgradient: 2 * a[fliplr shifted by k_star]
    # a[k_star - j] for j in 0..n-1, clamped
    idx = k_star - np.arange(n)
    valid = (idx >= 0) & (idx < n)
    grad = np.zeros(n)
    grad[valid] = 2 * a[idx[valid]]
    
    # Update
    eta = 0.1  # step size
    a = a - eta * grad / n  # normalize gradient
    a = np.maximum(a, 0)
    a = a / a.sum()
```

But this only looks at the maximum. A better approach: use the top-K peaks or a softmax weighting.

Actually, let me think about a more principled approach. The problem is:
min_a max_k conv(a)[k] subject to sum(a) = 1, a >= 0

This is a convex optimization problem! (minimize the max of linear functions, subject to linear constraints.)

Wait, is conv(a)[k] linear in a? No! conv(a)[k] = sum_i a_i * a_{k-i} is QUADRATIC in a. So the problem is NOT convex.

Hmm. That makes it harder. The subgradient approach still works (it's a DC programming / minimax problem), but we might get stuck in local minima.

Let me think about the structure more. For the uniform a = 1/n * ones:
conv[k] = (min(k+1, n, 2n-1-k)) / n²

The max is at k=n-1: n/n² = 1/n.

If I perturb: a[i] = (1+ε_i)/n, sum ε_i = 0.
conv[k] = (1/n²) * sum_i (1+ε_i)(1+ε_{k-i})
= (1/n²) * (overlap + sum_i ε_i + sum_i ε_{k-i} + sum_i ε_i ε_{k-i})
= (1/n²) * (overlap + sum_i ε_{k-i} * 2 + sum_i ε_i ε_{k-i})

For k = n-1: overlap = n
conv[n-1] = (1/n²) * (n + 2*sum_i ε_i + sum_i ε_i ε_{n-1-i})
= (1/n) * (1 + 0 + (1/n) * sum_i ε_i ε_{n-1-i})
= (1/n) * (1 + (1/n) * C) where C = sum_i ε_i ε_{n-1-i}

For k = 0: overlap = 1
conv[0] = (1/n²) * (1 + 2*ε_0 + ε_0²) ≈ (1/n²)(1 + 2ε_0)

For the max to decrease, we need conv[n-1] to decrease AND all other conv[k] to stay below the new max.

conv[n-1] decreases if C < 0, i.e., sum_i ε_i ε_{n-1-i} < 0.
This means ε should be "anti-symmetric" in the sense that ε_i and ε_{n-1-i} have opposite signs.

For example: ε_i = sin(πi/n) (roughly positive in first half, negative in second half).
Then ε_i * ε_{n-1-i} = sin(πi/n) * sin(π(n-1-i)/n) = sin(πi/n) * sin(π - π(n-1-i)/n)
= sin(πi/n) * sin(π(1)/n + πi/n - π) ... hmm, this is getting messy.

Let me just try: ε_i proportional to (i - (n-1)/2) (linear ramp).
ε_i = c*(2i - n + 1) (so sum = 0 by symmetry).
ε_i * ε_{n-1-i} = c²(2i-n+1)(2(n-1-i)-n+1) = c²(2i-n+1)(n-1-2i)
= c² * [-(2i-n+1)²] = -c²(2i-n+1)² < 0 for all i ≠ (n-1)/2.

So C = -c² * sum_i (2i-n+1)² < 0. 

So a linear ramp perturbation DECREASES the center convolution! But it might increase other conv values.

Let's check conv[k] for general k with the linear ramp:
a_i = (1 + c*(2i-n+1))/n, sum = 1 (since sum of ramp is 0).

conv[k] = (1/n²) * sum_i (1 + c*r_i)(1 + c*r_{k-i})
where r_i = 2i-n+1
= (1/n²) * (overlap + c*sum_i(r_i + r_{k-i}) + c²*sum_i r_i * r_{k-i})

sum_i r_i over valid range [max(0,k-n+1), min(n-1,k)]:
This is the sum of an arithmetic sequence. For k = n-1: sum of r_0 to r_{n-1} = 0 (by symmetry).
For k = 0: r_0 = -(n-1).
For small k: sum of r_0 to r_k = sum(2i-n+1 for i=0..k) = 2*k(k+1)/2 - (k+1)(n-1) = k(k+1) - (k+1)(n-1) = (k+1)(k-n+1)

So the linear term in conv[k] is c*(k+1)(k-n+1) for k < n (approximately).
This is negative for k < n-1 and zero for k = n-1.
So the linear ramp DECREASES conv[k] for all k < n-1 (when c > 0) and doesn't change conv[n-1] to first order.

Wait, but I need to check: does it decrease the MAX? The max is at k=n-1 for the uniform. After perturbation:
conv[n-1] ≈ (1/n)(1 + c² * C/n) where C = sum r_i² (positive, so this INCREASES conv[n-1] to second order).
conv[k] for k < n-1: (1/n²)(overlap + c*(k+1)(k-n+1) + ...)

For k near n-1, say k = n-2:
overlap = n-1
conv[n-2] ≈ (1/n²)(n-1 + c*(n-1)(n-2-n+1) + ...) = (1/n²)(n-1 + c*(n-1)(-1) + ...)
= (1/n)(1 - 1/n - c/n + ...)

For c small, this is less than 1/n (the original max). Good.

But conv[n-1] = (1/n)(1 + c²*sum(r_i)²/n ...) which is slightly above 1/n.

So the max might still be at n-1, but the change is second order in c. We need to go to higher order or use a different perturbation.

Actually, the key insight is: for a symmetric perturbation (ε_i = ε_{n-1-i}), the center conv[n-1] changes only at second order. For an anti-symmetric perturbation (ε_i = -ε_{n-1-i}), the center changes at first order (and decreases).

But the anti-symmetric perturbation (linear ramp) also changes the edge conv values at first order. The question is whether the net effect reduces the max.

Let me just try it computationally. For n=4:
Uniform: a = [1,1,1,1]/4. conv = [1,2,3,4,3,2,1]/16. max = 4/16 = 1/4.

Ramp: a = [1-c, 1-c/3, 1+c/3, 1+c]/4 (approximately, with r = [-3,-1,1,3]).
Let c = 0.5: a = [0.5, 0.83, 1.17, 1.5]/4 = [0.125, 0.208, 0.292, 0.375]. sum = 1.

conv = np.convolve([0.125, 0.208, 0.292, 0.375], same)
conv[0] = 0.0156
conv[1] = 2*0.125*0.208 = 0.052
conv[2] = 0.125*0.292 + 0.208² + 0.292*0.125 = 0.0365 + 0.0433 + 0.0365 = 0.1163
conv[3] = 0.125*0.375 + 0.208*0.292 + 0.292*0.208 + 0.375*0.125 = 0.0469 + 0.0607 + 0.0607 + 0.0469 = 0.2152
conv[4] = 0.208*0.375 + 0.292² + 0.375*0.208 = 0.078 + 0.0853 + 0.078 = 0.2413
conv[5] = 0.292*0.375 + 0.375*0.292 = 0.2175
conv[6] = 0.375² = 0.1406

max = 0.2413 at k=4.
Original max was 0.25. New max is 0.2413 < 0.25! 

So the ramp perturbation DID reduce the max! And the max shifted from k=3 (center) to k=4 (off-center).

Objective: 2n * max / (sum a)² = 2*4*0.2413/1 = 1.93 < 2.
