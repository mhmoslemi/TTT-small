            # Actually, since we renormalize after each step, we don't need to project.
            
            direction = -grad
            dir_norm = np.max(np.abs(direction)) + 1e-15
            
            a_new = a + step * direction / dir_norm * (n / S)
            a_new = np.maximum(0, a_new)
            S_new = a_new.sum()
            if S_new > 0:
                a_new = a_new * (n / S_new)
            
            c_new = convolve(a_new)
            M_new = c_new.max()
            score_new = 2.0 * M_new / n
            
            if score_new < a_score:
                a = a_new
                a_score = score_new
                stall = 0
                if a_score < best_score:
                    best_a = a.copy()
                    best_score = a_score
                step = min(step * 1.1, 1.0)
                # Switch to smooth mode after some progress
                if stall == 0 and it > 100 and mode == 'argmax':
                    mode = 'smooth'
            else:
                step *= 0.7
                stall += 1
                if stall > 50:
                    # Perturb and reset
                    idx = rng.choice(n, size=min(100, n), replace=False)
                    a[idx] *= np.exp(0.1 * rng.standard_normal(len(idx)))
                    a = np.maximum(0, a)
                    a = a * (n / a.sum())
                    step = 0.1
                    stall = 0
                    mode = 'argmax'
                    if it > 500:
                        break
    
    # Final validation
    fs = float(evaluate_sequence(best_a.tolist()))
    if not np.isfinite(fs):
        best_a = np.clip(height_sequence_1.astype(np.float64), 0, 1000)
    
    return [float(x) for x in best_a]

Wait, I realize there might be an issue with the gradient when using argmax. The gradient `grad[j] = 2*a[k-j]` means we should DECREASE a[j] where the gradient is large (i.e., where a[k-j] is large). This makes sense: if a[m] is large and m is close to k (the peak location), then decreasing a[m] will reduce the peak.

But wait, the descent direction is `-grad`, so we're doing `a_new = a - step * grad` (before normalization). This means we decrease a[j] where grad[j] is large. Since grad[j] = 2*a[k-j], we decrease a[j] where a[k-j] is large, i.e., where the "mirror" of j (with respect to k/2) has a large value.

This is the correct subgradient direction for minimizing the peak of the convolution.

However, I realize there might be an issue: the subgradient at the argmax might point in a direction that increases other convolution values. In that case, the overall max might not decrease. This is where the smooth max (softmax) helps: it gives a gradient that accounts for ALL lags, not just the argmax.
