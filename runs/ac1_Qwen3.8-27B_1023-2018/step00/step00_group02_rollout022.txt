Let me focus on making the LP-based tide method work. The key is:
- Given a, compute c = a⋆a, M = max(c)
- Solve: max sum(b) s.t. (a⋆b)_k <= M for all k, b_j >= 0
- The constraint matrix is the (2n-1) × n "convolution matrix" of a
- Update: a <- (1-t)*a + t * (b / sum(b))

For the LP, I'll use scipy.optimize.linprog with the HiGHS solver (fast for LPs).

The constraint matrix A is: A[k, j] = a[k-j] if 0 <= k-j < n, else 0. This is a Toeplitz matrix.

For n=6962, the matrix is 13923 × 6962, which is about 97M elements = 780MB as float64. That's too much memory!

So I can't form the full matrix. I need to either:
1. Use a sparse representation (each row has at most n nonzeros, but actually at most min(k+1, 2n-1-k, n) nonzeros)
2. Use a matrix-free approach
3. Reduce the problem

The total number of nonzeros in the constraint matrix is sum_{k=0}^{2n-2} min(k+1, 2n-1-k, n) = n^2 (it's a full Toeplitz, so about n^2/2 nonzeros on average per row... actually it's exactly n per row on average, giving n^2 total nonzeros).

Wait, for a Toeplitz convolution matrix of size (2n-1) × n:
- Row k (0-indexed) has nonzeros in columns j where 0 <= k-j < n, i.e., k-n+1 <= j <= k (intersected with [0, n-1])
- Number of nonzeros in row k: min(k+1, n, 2n-1-k)
- Total nonzeros: sum_{k=0}^{2n-2} min(k+1, n, 2n-1-k) = n^2

For n=6962, that's about 48M nonzeros, which as COO format is about 48M * (4+4+8) = 864MB. Still too much.

So the LP approach with the full constraint matrix is not feasible for n=6962 in terms of memory.

Alternative: reduce the problem. Instead of all 2n-1 constraints, use only the "tight" ones (those near the maximum). Or use a smaller "active set."

Or: use a matrix-free approach. The constraint `(a⋆b)_k <= M` can be evaluated without forming the matrix: just compute `fft_convolve(a, b)` and check element-wise.

scipy.optimize.linprog doesn't support matrix-free. But we could use cvxpy with a custom constraint, or implement the algorithm ourselves.

Let me implement the "dual ascent" method manually:
1. Start with y = ones/(2n-1) (dual variables)
2. Compute the "dual objective" gradient: for each j, g[j] = sum_k A[k,j]*y[k] = (a⋆y)[j] (partial correlation)
3. Update y to push g[j] above 1
4. This is equivalent to projecting onto the dual feasible set

Actually, this is getting complicated. Let me try a different approach.

**Simplified approach: Iterative projected gradient on a smooth surrogate**

Use the "entropic" or "log-sum-exp" approximation:
`h_beta(a) = (1/beta) * log(sum_k exp(beta * (a⋆a)_k))`

This approximates `max_k (a⋆a)_k` for large beta and is smooth. The gradient is:
`∇h_beta = (sum_k exp(beta*(a⋆a)_k) * ∇(a⋆a)_k) / (beta * sum_k exp(beta*(a⋆a)_k))`
= `sum_k softmax_k(a⋆a) * ∇(a⋆a)_k`

where `softmax_k(a⋆a) = exp(beta*(a⋆a)_k) / sum_j exp(beta*(a⋆a)_j)`.

This is a weighted average of the gradients, with weights concentrated on the "active" lags.

For the gradient computation, I need `∇(a⋆a)_k` for the active k's. As computed earlier, `∇(a⋆a)_k[m] = 2*a[k-m]` (for valid indices).

So the total gradient is: `sum_k w_k * 2 * shifted_a[k]` where `w_k` are the softmax weights.

This can be computed as: `2 * (w ⋆ shifted_a)` where `w` is the softmax vector of length 2n-1 and `shifted_a` is... hmm, let me think.

`grad[m] = 2 * sum_k w_k * a[k-m]` (for valid k-m)
= `2 * sum_k w_k * a[k-m]`

Let me change variable: let j = k-m, so k = j+m. Then:
`grad[m] = 2 * sum_j w[j+m] * a[j]` (for valid j+m in [0, 2n-2])
= `2 * (sum_j a[j] * w[m+j])`

This is `2 * (a cross-correlated with w)` or `2 * (a ⋆ w')[m]` where w' is the reversed w.

Either way, it's a convolution/correlation that can be computed with FFT!

So the gradient computation is:
1. Compute c = fft_convolve(a, a) [O(n log n)]
2. Compute w = softmax(beta * c) [O(n)]
3. Compute grad = 2 * fft_correlate(a, w) [O(n log n)]
4. Total: O(n log n)

This is very efficient! I can do thousands of gradient steps.
