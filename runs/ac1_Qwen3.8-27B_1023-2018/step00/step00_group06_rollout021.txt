The LP has n variables and 2n-1 + n (nonnegativity) + 1 (sum) = 3n constraints. For n=5582, that's ~16746 constraints and 5582 variables. This is a large LP but should be solvable with a good solver.

However, solving an LP this size might take 0.1-1 seconds each, limiting us to maybe 1000-10000 iterations in 1300s. That should be enough.

But wait - I need to implement the LP constraint matrix. `(a * a')[m] = sum_k a[k]*a'[m-k]` is linear in `a'`. The coefficient of `a'[j]` in the constraint for lag `m` is `a[m-j]` (if valid). So the constraint matrix is a Toeplitz-like matrix.

For n=5582, the constraint matrix is (2n-1) x n = 11163 x 5582. Each entry is either 0 or `a[some_index]`. This is banded (bandwidth n). Memory: 11163 * 5582 * 8 bytes ≈ 500 MB. That's too much for a dense matrix!

We need a sparse formulation. Each row of the constraint matrix has at most n nonzeros (actually, row m has `min(m+1, 2n-1-m, n)` nonzeros). Total nonzeros: sum over m of min(m+1, 2n-1-m, n) = n^2 + n ≈ 31M. That's manageable as sparse (CSR format).

Actually, for row m (0-indexed, 0 <= m <= 2n-2):
- The vector `c_m` has `c_m[j] = a[m-j]` if `0 <= m-j < n`, else 0.
- Valid j: `max(0, m-n+1) <= j <= min(n-1, m)`.
- Number of nonzeros: `min(n-1, m) - max(0, m-n+1) + 1 = min(m+1, 2n-1-m, n)`.

Total nonzeros in the (2n-1) x n matrix: `sum_{m=0}^{2n-2} min(m+1, 2n-1-m, n) = n + 2*(sum_{m=n}^{2n-2} min(m+1, 2n-1-m)) + ... `

Actually it's simpler: for m=0 to n-1: n-m nonzeros... no.

For m=0: valid j is just j=0. 1 nonzero.
For m=1: j=0,1. 2 nonzeros.
...
For m=n-1: j=0,...,n-1. n nonzeros.
For m=n: j=1,...,n-1. n-1 nonzeros.
...
For m=2n-2: j=n-1. 1 nonzero.

Total: 1+2+...+n+(n-1)+...+1 = n(n+1)/2 + (n-1)n/2 = n^2.

So the matrix has n^2 ≈ 31M nonzeros. In sparse format, that's 31M * (1+8) bytes ≈ 280 MB (values + indices) + row pointers. That's a lot but might be feasible.

Actually, scipy's sparse matrix and CVXPY can handle this. Let me think about whether to use CVXPY or scipy.optimize.linprog.

For scipy.optimize.linprog with method='highs':
- It can handle sparse constraint matrices.
- 11163 constraints, 5582 variables, 31M nonzeros.
- HIGHS is very fast for LPs of this size. Should solve in < 1 second.

But building the sparse matrix each iteration is O(n^2) = 31M operations, which is fine.

Let me code this up:

```python
import numpy as np
from scipy import sparse
from scipy.optimize import linprog

def solve_lp(a, S, T):
    """Solve: max sum a' s.t. a' >= 0, sum a' = S, (a*a')[m] <= (T + b[m])/2 for all m."""
    n = len(a)
    b = np.convolve(a, a)  # or use FFT
    
    # Constraint: (a * a')[m] <= (T + b[m]) / 2
    # (a * a')[m] = sum_j a[m-j] * a'[j] (valid j)
    # So row m of A has: A[m, j] = a[m-j] if 0 <= m-j < n, else 0
    
    # Build sparse matrix A (2n-1) x n
    rows = []
    cols = []
    vals = []
    for m in range(2*n-1):
        j_lo = max(0, m - n + 1)
        j_hi = min(n-1, m)
        for j in range(j_lo, j_hi + 1):
            rows.append(m)
            cols.append(j)
            vals.append(a[m-j])
    
    A_conv = sparse.csr_matrix((vals, (rows, cols)), shape=(2*n-1, n))
    bounds_r = (T + b) / 2.0
    
    # Full constraint matrix: [A_conv; I_n (for nonneg, handled by bounds); 1^T (for sum)]
    # Actually, nonnegativity is handled by variable bounds.
    # We need: A_conv @ a' <= bounds_r, and 1^T @ a' = S
    
    # For linprog: A_ub @ x <= b_ub, A_eq @ x = b_eq
    A_ub = A_conv
    b_ub = bounds_r
    A_eq = sparse.csr_matrix(np.ones((1, n)))
    b_eq = np.array([S])
    lbounds = [(0, 1000)] * n
    
    res = linprog(
        c=-np.ones(n),  # minimize -sum a' => maximize sum a'
        A_ub=A_ub, b_ub=b_ub,
        A_eq=A_eq, b_eq=b_eq,
        bounds=lbounds,
        method='highs'
    )
    return res
```

Wait, but the original LP in the parent strategy was: maximize `sum b_j` s.t. `b_j >= 0` and `(f * g_0)[m] <= M` for all m. This finds the best `g` that's "compatible" with `f` at level M.

Then the update is `f <- (1-t)f + t*g`.

Let me follow this approach more directly:

1. Given current `a`, compute `M = max(a*a)`.
2. Solve LP: maximize `sum g` s.t. `g >= 0`, `(a*g)[m] <= M` for all m.
3. Rescale: `g = g * S / sum(g)` where `S = sum(a)`.
4. Update: `a <- (1-t)*a + t*g` for small t.
5. Repeat.

This is cleaner. The LP constraint is `(a*g)[m] <= M`, which is linear in g with coefficient `a[m-j]`.

- Solving the LP: HIGHS can handle this in ~0.1-1s.
- Total per iteration: ~1-2s.
- In 1300s: ~650-1300 iterations.
