```python
# This is conv(a, q)[2n-2-j]
#
# Or equivalently: define q[k] = p[k] and compute:
# (a * q)[k] = sum_m a[m] * q[k-m] = sum_m a[m] * p[k-m]
# Set k-m = m+j => m = (k-j)/2... this doesn't work cleanly.
#
# Simplest: just use the direct method. For n=192, it's fast enough.
# Or use: correlate via FFT
#
# Actually, scipy.signal.correlate(a, p, mode='valid') should work.
# Let me just use that.
```

You know what, for n=192, the direct computation `np.array([np.dot(p[j:j+n], a) for j in range(n)])` is fast enough. Each dot product is 192 multiplications, very fast in numpy. The loop of 192 iterations adds maybe 50 microseconds of Python overhead. Total per gradient: ~100 microseconds. For 50K iterations: ~5 seconds. That's fine.

But wait, I can vectorize it! Using a stride trick or a Toeplitz matrix:

```python
# Create a Toeplitz-like matrix T where T[j, m] = p[j+m]
# Then grad = T @ a
# But T is n x n with T[j,m] = p[j+m]
# This is equivalent to: for each j, T[j,:] = p[j:j+n]
# Can create with: indices = np.arange(n)[:,None] + np.arange(n)[None,:]
# T = p[indices]  (advanced indexing, creates n*n array)
# grad = T @ a
```

This is O(n^2) memory but very fast (one matrix-vector multiply). For n=192: 192*192 = 37K elements. Trivial.

Let me use this approach:
```python
idx = np.arange(n)[:, None] + np.arange(n)[None, :]  # (j+m) for all j,m
T = p[idx]  # shape (n, n)
grad = 2.0 * (T @ a)
```

This is clean and fast. One matrix-vector multiply of 192x192.

```python
        rho = int(np.nonzero(cond)[0][-1]) if cond.any() else 0
```
