This LP has 192 variables and 383 inequality constraints. Very small!

The key insight: this LP finds the "best" g that, when convolved with a, doesn't exceed M in any coordinate. Since we want to minimize max(conv(a,a)), pushing towards such a g reduces the "peaks" of the autocorrelation.

```python
from scipy.optimize import linprog

def _solve_lp(a, M):
    n = len(a)
    c_neg = -np.ones(n)  # minimize -sum(g) = maximize sum(g)
    
    # Build constraint matrix: (2n-1) x n
    # Row k: sum_{i: max(0,k-n+1)<=i<=min(k,n-1)} a[i] * g[k-i] <= M
    # Wait, I need to be careful about the indexing.
    # conv(a,g)[k] = sum_i a[i]*g[k-i] where 0<=i<n, 0<=k-i<n
    # = sum_{i: 0<=i<n, 0<=k-i<n} a[i]*g[k-i]
    # Let j = k-i, so i = k-j. Then: sum_{j: 0<=k-j<n, 0<=j<n} a[k-j]*g[j]
    # So (A @ g)[k] = sum_j A[k,j]*g[j] where A[k,j] = a[k-j] if 0<=k-j<n and 0<=j<n, else 0
    
    A = np.zeros((2*n-1, n))
    for k in range(2*n-1):
        for j in range(n):
            idx = k - j
            if 0 <= idx < n:
                A[k, j] = a[idx]
    
    constraints = {'A_ub': A, 'b_ub': np.full(2*n-1, M)}
    
    res = linprog(c_neg, A_ub=A, b_ub=constraints['b_ub'], bounds=[(0, None)]*n, method='highs')
    
    if res.success:
        g = res.x
        s = g.sum()
        if s > 1e-15:
            return g / s
    return None
```

Let me also think about whether I should try a completely different approach. What about:

**Approach: Direct minimization using Nesterov's method**

The objective f(a) = max_k C_k(a) is the max of C_k(a) = sum_i a[i]*a[k-i]. Each C_k is a quadratic form. The max of quadratics is generally non-convex.

However, we can use the "smooth approximation": f_ε(a) = logsumexp((C_k - t)/ε) * ε + t, and optimize this with gradient descent. But this adds complexity.

**Approach: Frank-Wolfe (conditional gradient) on the simplex**

The Frank-Wolfe algorithm for minimizing f(a) over the simplex:
- At each iteration, solve the linear approximation: find v = argmin_{s in simplex} <∇f(a), s>
- The simplex has vertices e_j, so v = e_{argmin_j ∇f_j}
- Update: a ← (1-t) * a + t * v

This is very simple and fast! The subgradient at k*=argmax C is:
g[j] = (a[k*-j] + a[j]) * 1_{0≤k*-j<n}

The vertex with minimum inner product with g is e_j where j = argmin g.

So the Frank-Wolfe step is:
1. Compute k* = argmax conv(a,a)
2. Compute g = subgradient
3. j* = argmin g
4. a ← (1-t)*a + t*e_{j*}
5. t = 2/(2+it) or a line search step

This is O(n log n) per iteration (for the conv) + O(n) for the rest. Very fast!

The downside of Frank-Wolfe is slow convergence (O(1/it) for convex problems, potentially worse for non-convex). But it's a great "mandatory" step that never makes things worse (with line search).
