   = a_j if j = k/2 and 0 <= k-j < n
   = 0 otherwise

   For integer indices, j = k/2 only when k is even and j = k/2.

   So the subgradient of the max is a convex combination of these 2*a (with a special case for the diagonal).

2. **Practical algorithm**:
   - Normalize to sum(a) = 1
   - Find active lag k* = argmax_k b_k
   - Compute subgradient: sg_j = 2 * a_{k*-j} (with diagonal correction)
   - Project gradient descent step: a_new = a - alpha * sg, then project to {a >= 0, sum(a) = 1}
   - Adaptive step size via backtracking

   The projection onto {a >= 0, sum(a) = 1} (the simplex) can be done efficiently.

To project v onto {a >= 0, sum(a) = 1}:
- Find τ such that sum_i max(v_i - τ, 0) = 1
- Projected point is max(v_i - τ, 0)

The standard efficient algorithm:
1. Sort v in decreasing order: v_{(1)} >= v_{(2)} >= ... >= v_{(n)}
2. For each k = 1, ..., n, define τ_k = (sum_{i=1}^k v_{(i)} - 1) / k
3. Find the largest k such that v_{(k)} > τ_k
4. τ = τ_k, and the projection is max(v_i - τ, 0)

This is O(n log n) due to sorting.

- Simplex projection: O(n log n) via sorting
- LSE gradient: O(n²) via direct computation (or O(n log n) via FFT)
- Convolution: O(n log n) via FFT or O(n²) direct (for n=192, O(n²) is fine)
- LP: O(n³) or so, called infrequently

- 1 LSE computation: O(n) trivial
- 1 gradient computation: O(n²) ≈ 10^5
- 1 simplex projection: O(n log n) ≈ 2000
- Total: ~2*10^5 operations
