def _score(a):
    """Compute AC1 score."""
    a = np.asarray(a, dtype=np.float64).ravel()
    a = np.clip(a, 0, 1000)
    n = a.size
    s = a.sum()
    if s < 1e-300:
        return float('inf')
    b = np.convolve(a, a)
    return 2.0 * n * b.max() / (s * s)

def _lp_solve(f, time_limit=10):
    """Solve LP: max sum(g) s.t. f*g <= M, g >= 0."""
    n = f.size
    b = np.convolve(f, f)
    M = b.max()
    if M < 1e-300:
        return None

    # A[k, i] = f[k-i] if 0 <= k-i < n, else 0

            sg = g.sum()
            if sg > 1e-300:
                return g / sg
    except:
        pass
    return None

Note that `b_0 = sum a_i^2` (the "energy") and `b_k = sum a_i * a_{i+k}` for k > 0.

By Parseval: `sum_k b_k = S^2 = 1` (in the continuous case). In the discrete case, `sum_{k=-(n-1)}^{n-1} b_k = S^2`.

Wait, let me verify. `b_k = sum_i a_i * a_{k-i}` where the sum is over valid i.
`sum_k b_k = sum_k sum_i a_i * a_{k-i} = sum_i sum_k a_i * a_{k-i} = sum_i a_i * sum_j a_j = S^2`.

So `sum_k b_k = S^2`. If all b_k were equal, each would be `S^2 / (2n-1)`, and the max would be `S^2 / (2n-1)`. The AC1 bound would be `2n * S^2/(2n-1) / S^2 ≈ 1` for large n. But we can't make all b_k equal due to the positivity constraint.

The theoretical minimum of `max(b_k)` given `sum(b_k) = S^2` is `S^2/(2n-1)` (when all b_k are equal). But this requires the autocorrelation to be flat, which means the sequence is a "Singer difference set" or similar structure. For nonnegative sequences, this is generally not achievable.

The best we can do with nonnegative sequences is probably around `S^2/n` (achieved by the uniform sequence for the peak at lag 0, but the peak at other lags is lower).

Wait, for the uniform sequence `a_i = 1/n`:
`b_0 = n * (1/n)^2 = 1/n`
`b_1 = (n-1) * (1/n)^2 = (n-1)/n^2`
...
`max(b) = 1/n`
AC1 = `2n * (1/n) / 1 = 2`.

To get AC1 = 1.5, we need `max(b) = 1.5/(2n) = 0.75/n`.

So we need to reduce the peak from `1/n` to `0.75/n`, a 25% reduction.

This means we need a sequence where the autocorrelation peak is 25% below the uniform case.

For a "bump" sequence (higher in the middle, lower at edges), the lag-0 autocorrelation (`sum a_i^2`) increases, but the lag-k autocorrelations for small k decrease. The trade-off determines the optimum.

Let me think about a specific family: `a_i = 1 + c * cos(2πi/n)` for some c.
- `S = n` (the cos term integrates to 0)
- `b_0 = sum (1 + c*cos(2πi/n))^2 = n + c^2 * n/2 = n(1 + c^2/2)`
- `b_k ≈ n * (1 + c^2/2 * cos(2πk/n))` (approximately, for the periodic case)
- `max(b) ≈ n(1 + c^2/2)` (at k=0 or k=n)
- AC1 ≈ `2n * n(1+c^2/2) / n^2 = 2(1+c^2/2) > 2`

So adding a cosine makes it worse. We need a different structure.

What about `a_i = 1 + c * sin(πi/n)` (a bump)?
- This is higher in the middle
- `b_0` increases (more energy)
- `b_k` for small k might decrease

Let me think about this differently. The key is to spread the autocorrelation energy across many lags rather than concentrating at lag 0.

A "chirp" or random-like sequence would spread the autocorrelation, but nonnegativity limits how much spreading we can do.

Actually, I think the optimal structure for a nonnegative sequence is something like a "top-hat" with smooth edges, or perhaps a sequence that alternates between high and low values in a structured way.
