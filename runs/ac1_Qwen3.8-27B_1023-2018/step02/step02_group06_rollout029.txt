```python
                break
            
            # Simpler approach: binary search / golden section on a[m] >= 0
            # Find a[m] that minimizes max(b)
            # max(b) is convex in a[m] (since b[k] is convex in a[m] for each k,
            # and max of convex is convex)
            
            lo = 0.0
            hi = old_m * 3 + 1.0/n
            # Golden section search
            gr = (math.sqrt(5) - 1) / 2
            for _ in range(30):
                x1 = lo + gr * (hi - lo)
                x2 = hi - gr * (hi - lo)
                a[m] = x1
                b1 = _self_conv(a).max()
                a[m] = x2
                b2 = _self_conv(a).max()
                if b1 < b2:
                    hi = x2
                else:
                    lo = x1
            a[m] = (lo + hi) / 2
            mb = float(_self_conv(a).max())
            if mb < best_mb * (1 - 1e-12):
                best_mb = mb
            a = _normalize(a)
            improved = True
        
    return a, best_mb
```

Actually, the simplest correct approach: for each coordinate m, the contribution of a[m] to b[k] is:
- If k-m is in [0, n-1]: a[m] * a[k-m]
- If m-k is in [0, n-1] AND m-k ≠ k-m (i.e., k ≠ 2m): a[m-k] * a[m]
- If k = 2m: a[m]² (counted once, since j=m gives a[m]*a[m])

So the change in b[k] when we change a[m] from old to new is:
Δb[k] = (new - old) * (a[k-m]*I(0≤k-m<n) + a[m-k]*I(0≤m-k<n, k≠2m))
       + (new² - old²) * I(k=2m)

Wait, that's not right either. Let me be very careful.

b[k] = sum_{j=0}^{n-1} a[j] * a[k-j] * I(0 ≤ k-j < n)

Let x = a[m]. The terms involving x are:
- j = m: x * a[k-m] * I(0 ≤ k-m < n)
- j = k-m (if k-m ≠ m and 0 ≤ k-m < n): a[k-m] * x

So the total linear-in-x part is: x * (a[k-m]*I(0≤k-m<n) + a[m-k]*I(0≤m-k<n))
where for k=2m, both terms give x*a[m] = x², and they're the same j, so we only count once.

Actually no. j=m gives the term a[m]*a[k-m] = x*a[k-m]. If k-m = m (i.e., k=2m), this is x*a[m] = x².
j=k-m gives the term a[k-m]*a[m] = a[k-m]*x. If k-m=m (k=2m), this is a[m]*x = x².
But j=m and j=k-m are the SAME j when k=2m! So we only count it once.

So the x-dependent part of b[k] is:
- If k ≠ 2m: x * (a[k-m]*I(0≤k-m<n) + a[m-k]*I(0≤m-k<n)) [two separate terms, linear in x]
- If k = 2m: x * a[m] * I(0≤m<n) = x² [one term, quadratic]

Wait, for k=2m: j=m gives a[m]*a[2m-m] = a[m]*a[m] = x². That's the only j that involves x (the other j=k-m=m is the same). So yes, b[2m] has an x² term.

For k≠2m: j=m gives x*a[k-m] (if valid), and j=k-m gives a[k-m]*x (if valid and k-m≠m). Total: x*(a[k-m]+a[m-k]) for appropriate validity.

So: b[k] = rest[k] + alpha[k]*x + beta[k]*x²
where:
- beta[k] = 1 if k=2m and 0≤2m<2n-1, else 0
- alpha[k] = a[k-m]*I(0≤k-m<n, k≠2m) + a[m-k]*I(0≤m-k<n, k≠2m)
- rest[k] = b[k] - alpha[k]*x - beta[k]*x² (using old x)

And max_k b[k] = max_k (rest[k] + alpha[k]*x + beta[k]*x²)

This is the max of (2n-1) quadratic functions of x, each of which is convex (coefficient of x² is 0 or 1 ≥ 0). The max of convex functions is convex. So we can use bisection on the derivative, or just ternary/golden section search.

For the coordinate descent, I'll precompute the "rest" and "alpha" arrays once per coordinate, then do a fast 1D minimization.

My smooth gradient approach should be much faster per iteration and can take many more steps. The key is the temperature parameter τ:
- Small τ: smooth, captures all b values, gradient is a weighted average.
- Large τ: sharp, focuses on the maximum b.

I'll use annealing: start with small τ, increase over time.
