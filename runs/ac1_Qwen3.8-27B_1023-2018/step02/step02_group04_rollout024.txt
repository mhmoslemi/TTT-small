Let me think about a better approach:

**Alternative: Direct minimization via bisection**

We want to find the minimum value of max(a*a) / (sum a)^2. Let's fix sum(a) = 1 and minimize max(a*a).

This is equivalent to: find the smallest t such that there exists a >= 0, sum(a) = 1, and (a*a)_k <= t for all k.

For a given t, this is: sum(a) = 1, a >= 0, and for each k: sum_{i} a[i]*a[k-i] <= t.

The constraint sum_i a[i]*a[k-i] <= t is NOT linear in a (it's quadratic). So this is a feasibility problem with quadratic constraints, which is non-convex.

However, for a FIXED a, checking (a*a)_k <= t is linear in t. And the LP approach works by fixing a and finding a good direction.

Let me think about yet another approach: **coordinate descent / coordinate LP**.

For each coordinate i, fix all other a_j (j != i) and optimize a_i. The convolution entries involving a_i are:
- conv[2i] includes a_i^2
- conv[i+k] includes a_i * a[i+k] and a_i * a[i-k] for valid indices

So changing a_i affects O(n) convolution entries. The optimal a_i (given others fixed) would balance these.

This is a 1D problem: for each i, find the optimal a_i given the others. The objective is max_k conv[k], and changing a_i from x to x+dx changes conv by a linear function of dx.

This could be done with a 1D bisection or Newton's method for each coordinate, cycling through coordinates.

- LP solve: HiGHS with 192 vars, 383 constraints - should be < 10ms
- Line search: ~10 score evaluations, each O(n^2) for convolution - ~370K operations

So each iteration is maybe 1-5ms. In 1300s, we could do hundreds of thousands of iterations. But we're limited by the LP solve time and Python overhead.

Actually, building the matrix A as a dense (383, 192) array each iteration is the bottleneck in Python. Let me optimize: use a structured approach or precompute the structure.

Actually, for n=192, the matrix A has a Toeplitz-like structure (each column j is a shifted version of a). We can exploit this, but for n=192 it's small enough that dense is fine.

Let me also think about whether we should try different lengths. The parent is 192. The objective has n in the numerator, so for a given "shape" of the sequence, a larger n gives a larger objective. But we can also make the sequence more "spread out" for larger n.

Actually, the objective is scale-invariant but NOT length-invariant. If I take a sequence of length n and pad it with zeros to length n+k, the sum stays the same but n increases, so the objective increases by factor (n+k)/n. And the max convolution might change.

So it's generally better to use the minimum n that captures the structure. The parent has n=192, which is a good choice.

Let me also think about whether we can use a smarter LP formulation.

**Better LP**: Instead of `max sum(g) s.t. (a*g)_k <= M`, what about:
`min t s.t. (a*g)_k <= t, sum(g) = 1, g >= 0`

This directly minimizes the peak of the cross-correlation. The solution g tells us where to put mass to minimize the overlap with a's peaks.

Then the update would be: a_new = normalize(a + g) or a_new = a^(1-t) * g^t (geometric mean).
