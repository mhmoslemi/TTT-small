2. **Mathematical Specification**

The problem is to minimize:
    f(a) = 2 * n * \max(convolve(a, a)[0]) / (\sum_{i} a_i)^2
over a \in \mathbb{R}^n^+ with \sum a_i \geq 0.01 and 0 \leq a_i \leq 1000.

The self-convolution is calculated via FFT for efficiency, and the gradient is computed using subspace differentiation. The optimization is partitioned into two distinct phases:

**Phase 1: Boundary Extraction**
  - Explicitly define and search extremal boundaries: normalize a to unit-sum and assume unity mean, then the problem becomes minimizing \max(convolve(a, a)) under these constraints. But standard normalization doesn't fit here—use the conditions to form an objective:
      f(a) \equiv 2 * n * \max_b - (\sum a_i)^2

  - Boundary domains are defined by constrained extrema structures. The key constraint is a_i \geq 0, equivalent to boundary-finding in the simplex of positive orthant.

**Phase 2: Interior Search with Clamped Derivatives**
  - The initial exploration uses scaled gradients for curvature detection, then high-curvature regions are exploited under a monotonicity framework. Redefine the objective:
      \phi(a) = 2 * n / (\sum a_i)^2 * \max convolve(a, a)

  - Outer iteration: Use LBFGS-B with finite differences (but optimizes direction based on curvature). Automatic derivative detection cascades from directional gradients.

  - Inner iteration: For boundary points, use projected gradients adjusted for orthant restrictions.

  All computations use 64-bit IEEE floating point with range checks, and the sequences are limited to 3072-dimensions unless environmental constraints on storage (e.g., sandbox memory limits) force degradation.

4. **Search Choices and Variations**

Primary variation: gradient steering. Allow a full dimension search to be temporarily reduced if gradient computations indicate fat-tail properties. Following the detection, project the gradient to the lower-dimensional space.

Secondary variation: boundary amplification. Increase perturbations at boundaries to detect non-smoothness. This is useful when the parent sequence is near a boundary.

Thirdary variation: dimension-wise perturbation. Similar to gradient-based, but uses stochastic comparison against stored histories.

 These are implemented as:

        gradient_strength = adaptive_function(history)
        queries = random_slice(dimensions, ..., adjust_by=gradient_strength)

And callable from main loop.

By default, runs at 3072 dimensions, with descent adjusted for dimension-size.
