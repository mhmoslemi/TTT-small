```python
    # Build G efficiently:
    # G = zeros(n,n)
    # for j in range(n): G[j,:n-1-j... no, G[j,m] = p[j+m] for m=0..n-1
    # But j+m can be up to 2n-2, which is within p (length 2n-1). So all valid.
    
    # G is actually a Toeplitz matrix! G[j,m] depends on j+m.
    # We can build it as: G = toeplitz-like
    # G[j,m] = p[j+m]
    # Row j: [p[j], p[j+1], ..., p[j+n-1]]
    
    # Build using stride tricks or just explicit construction
    idx = np.arange(n)
    G = p[np.add.outer(np.arange(n), np.arange(n))]  # G[j,m] = p[j+m]
    grad = 2.0 * (G @ f)
    
    return lse, grad
```

Wait, `p[np.add.outer(np.arange(n), np.arange(n))]` creates an n×n matrix where entry [j,m] = p[j+m]. For n=414, this is a 414×414 matrix (171K elements). Building it takes O(n²) which is fast. The matrix-vector product G@f is also O(n²). Total per gradient evaluation: O(n²) ≈ 171K ops. Very fast.

But wait, I'm allocating a 414×414 array every time. That's 1.37 MB. For 100000 iterations, that's a lot of allocations. Let me pre-allocate or use a more efficient method.

Actually, for the smooth optimization phase, I'll do at most a few thousand iterations, so it's fine.

def _fft_conv(a):
    n = len(a)
    fsize = next_fast_len(2 * n - 1)
    F = rfft(a, fsize)
    c = irfft(F * F, fsize)[:2 * n - 1]
    np.maximum(c, 0.0, out=c)
    return c
