So the max convolution changes by $\max_k 2\epsilon(a_{k-j} - a_{k-i})$ (approximately, for small $\epsilon$).

Actually, I think the most impactful improvement would be to use a **subgradient method with momentum** on the function $M(a) = \max_k (a*a)_k$, projected onto the simplex $\{a \geq 0, \sum a = 1\}$.

The subgradient at $a$ is the average of the gradients at all argmax positions:
$\nabla M(a) = \frac{1}{|\mathcal{K}|} \sum_{k \in \mathcal{K}} \nabla (a*a)_k$

where $\mathcal{K} = \{k : (a*a)_k = M\}$.

Then we update: $a_{new} = \text{Proj}_{\Delta}(a - \eta \nabla M(a))$ where $\Delta$ is the simplex.

The projection onto the simplex (with non-negativity) is: find $\lambda$ such that $a_i - \eta g_i - \lambda \geq 0$ for all $i$ and $\sum (a_i - \eta g_i - \lambda) = 1$.

This is a water-filling problem and can be solved in $O(n \log n)$ time.

```python
def _proj_simplex(v):
    """Project v onto the simplex {x >= 0, sum(x) = 1}."""
    n = len(v)
    u = np.sort(v)[::-1]
    cssv = np.cumsum(u)
    rho = np.where(u * np.arange(1, n+1) > (cssv - 1))[0][-1]
    theta = (cssv[rho] - 1) / (rho + 1)
    return np.maximum(v - theta, 0)

def _subgrad_optimize(a0, stop_time, seed=42):
    n = a0.size
    a = _norm(np.clip(a0, 0, 1000).astype(np.float64).copy())
    best_a = a.copy()
    best_M = _max_conv(a)
    rng = np.random.default_rng(seed)
    
    eta = 0.01  # initial step size
    momentum = 0.9
    v = np.zeros(n)
    
    no_improve = 0
    max_no_improve = 500

        M = float(c_full.max())

                idx = k - j
                if 0 <= idx < n:
                    grad[j] += 2.0 * a[idx]
        grad /= len(k_stars)
        
        # Center the gradient (we're on the simplex)
        grad -= np.mean(grad)
        
        # Momentum
        v = momentum * v - eta * grad
        v -= np.mean(v)  # re-center
        
        # Update

                no_improve += 1
            eta *= 0.999
        else:
            no_improve += 1
            eta *= 0.9
            v *= 0.5

```

This is a standard subgradient method with momentum. It should work well for this type of problem.

But the subgradient is only defined at the argmax positions, which means the gradient is "spiky" - it only points in the direction of the current maximum. This can cause oscillation.

A better approach is to use a **smoothing parameter**: instead of the hard max, use a soft max:
$M_\tau(a) = \tau \log \sum_k \exp((a*a)_k / \tau)$

for small $\tau > 0$. The gradient of this is a weighted average of the individual gradients, with weights proportional to $\exp((a*a)_k / \tau)$.

But computing the soft max requires the full convolution, which we already have. And the gradient of the soft max is:
$\nabla M_\tau(a)_i = \frac{1}{|\mathcal{K}_\tau|} \sum_k w_k \cdot 2a_{k-i}$

where $w_k = \exp((a*a)_k / \tau) / \sum_l \exp((a*a)_l / \tau)$.

This is a smooth approximation to the subgradient and should give better convergence.

Let me implement this:

```python
def _soft_max_grad(a, tau):
    """Gradient of the soft max of the convolution."""
    n = a.size
    c = np.convolve(a, a)
    # Soft max
    c_max = c.max()
    exp_c = np.exp((c - c_max) / tau)
    w = exp_c / exp_c.sum()
    
    # Gradient
    grad = np.zeros(n)
    for k in range(2*n - 1):
        if w[k] < 1e-10:
            continue
        lo = max(0, k - n + 1)
        hi = min(n, k + 1)
        for j in range(lo, hi):
            idx = k - j
            if 0 <= idx < n:
                grad[j] += 2.0 * w[k] * a[idx]
    
    return grad, c_max + tau * np.log(exp_c.sum())
```

The inner loop is O(n) per $k$, and we have $O(n)$ values of $k$, so the total is $O(n^2)$. For $n = 281$, that's about 79K operations, which is fast.

Actually, we can vectorize this. The gradient at position $i$ is:
$\text{grad}_i = 2 \sum_k w_k a_{k-i} \cdot [0 \leq k-i < n]$

This is $2 \cdot (w * a)$ evaluated at index $i$, where $*$ is the full convolution. Wait, let me check.

$(w * a)_i = \sum_k w_k a_{i-k}$. But we want $\sum_k w_k a_{k-i}$. These are the same if we reverse $w$: $(\tilde{w} * a)_i = \sum_k \tilde{w}_k a_{i-k} = \sum_k w_{k} a_{i-k}$.

Hmm, let me think about this differently. We have:
$\text{grad}_i = 2 \sum_{k: 0 \leq k-i < n} w_k a_{k-i} = 2 \sum_{j: 0 \leq j < n} w_{i+j} a_j$

where $j = k-i$. So $\text{grad}_i = 2 \sum_j w_{i+j} a_j$.

This is like a "cross-correlation" of $w$ and $a$. Specifically, if we define $(w \star a)_i = \sum_j w_{i+j} a_j$, then $\text{grad} = 2(w \star a)$.

Note that $w$ has length $2n-1$ and $a$ has length $n$. The cross-correlation can be computed as a convolution:
$(w \star a)_i = \sum_j w_{i+j} a_j = (w_{rev} * a)_{(2n-2)-i}$

where $w_{rev}$ is $w$ reversed.

So we can compute the gradient in $O(n \log n)$ using FFT, or $O(n^2)$ directly. For $n = 281$, both are fast.

Let me just use the direct computation for clarity:

```python
def _soft_grad(a, tau):
    n = a.size
    c = np.convolve(a, a)
    c_max = c.max()
    exp_c = np.exp((c - c_max) / tau)
    w = exp_c / exp_c.sum()
    
    # grad_i = 2 * sum_j w[i+j] * a[j]
    # This is a cross-correlation
    # We can compute it as: for each i, sum over j of w[i+j] * a[j]
    # w has length 2n-1, a has length n
    # For i = 0: sum_j w[j] * a[j] = dot(w[:n], a)
    # For i = 1: sum_j w[1+j] * a[j] = dot(w[1:n+1], a)
    # ...
    # For i = n-1: sum_j w[n-1+j] * a[j] = dot(w[n-1:2n-1], a)
    
    grad = np.zeros(n)
    for i in range(n):
        grad[i] = 2.0 * np.dot(w[i:i+n], a)
    
    return grad, c_max + tau * np.log(exp_c.sum())
```

Wait, this is $O(n^2)$ because each dot product is $O(n)$ and we do $n$ of them. For $n = 281$, that's $281^2 \approx 79K$ operations per gradient evaluation. Very fast.

Actually, we can do it even faster with a matrix-vector product:
```python
W = np.array([w[i:i+n] for i in range(n)])  # n x n matrix
grad = 2.0 * W @ a
```

The matrix $W$ is a "profile" matrix (each row is a shifted version of $w$). We can construct it once and reuse it... but $w$ changes every iteration, so we can't reuse it.

Anyway, for $n = 281$, the $O(n^2)$ computation is fast enough.

Let me now think about the overall algorithm:

1. **Initialize**: Start from parent (or other initializations)
2. **Soft max gradient descent with momentum**:
   - Compute soft max gradient with temperature $\tau$
   - Update with momentum
   - Project onto simplex
   - Slowly decrease $\tau$ (annealing)
   - If stuck, perturb
3. **LP-based refinement**: Use the LP method to polish
4. **Coordinate descent**: Final polish

Let me also think about the temperature schedule. Initially, $\tau$ should be large enough that the soft max is a good approximation of the true max. As we converge, we should decrease $\tau$ to sharpen the computation.

A good schedule: start with $\tau = M/10$ and decrease by a factor of 0.99 each iteration, with a floor of $M/1000$.
