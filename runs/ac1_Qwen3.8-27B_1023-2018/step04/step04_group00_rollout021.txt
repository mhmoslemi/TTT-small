- The j=i term gives p[k-i]
- The j=k-i term gives p[i-k]
- But p[k-i] and p[i-k] are the SAME element p[k-i] = p[i-k]... no, they're different elements!
  - p[k-i] is the element at index k-i
  - p[i-k] is the element at index i-k
  - These are different unless k-i = i-k, i.e., k=2i.

If k-i > i-k (i.e., k > 2i): p[k-i] is at a higher index.
If k-i < i-k (i.e., k < 2i): p[i-k] is at a higher index.

The key point: dC[k]/dp[i] = p[k-i] + p[i-k] (with the convention that p[j] = 0 if j < 0 or j ≥ n).

If k-i = i-k (k = 2i): dC[k]/dp[i] = 2*p[i].

So: dF/dp[i] = sum_k w[k] * (p[k-i] + p[i-k])

Let me change variables: sum_k w[k]*p[k-i] + sum_k w[k]*p[i-k]

For the first sum: let j = k-i, k = j+i: sum_j w[j+i]*p[j] (for valid j, j+i)
For the second sum: let j = k, sum_j w[j]*p[i-j] (for valid j, i-j)

First sum = sum_j p[j]*w[j+i] = (p ⋆ w)[i] (cross-correlation at lag i)
Second sum = sum_j w[j]*p[i-j] = (w * p)[i] (convolution at lag i)

So dF/dp[i] = (p ⋆ w)[i] + (w * p)[i]

For the cross-correlation (p ⋆ w)[i] = sum_j p[j]*w[j+i].
For the convolution (w * p)[i] = sum_j w[j]*p[i-j].

These are NOT the same in general (since w is not symmetric).

So the gradient is:
gdp[i] = (p ⋆ w)[i] + (w * p)[i]

The previous program computes q[i] = (p ⋆ w)[i] (via xfast) and then sets gdp = 2*q. This would be correct only if (p ⋆ w)[i] = (w * p)[i] for all i, which requires w to be symmetric.

But w[k] = exp(C[k]-cmax)/T where C[k] is the full linear convolution (not symmetric in general).

HOWEVER, let me reconsider. The full linear convolution C[k] = sum_j p[j]*p[k-j]. 

Is C symmetric? C[k] = sum_j p[j]*p[k-j]. C[2n-2-k] = sum_j p[j]*p[2n-2-k-j].

Let j' = 2n-2-j: C[2n-2-k] = sum_j' p[2n-2-j']*p[k-j'] = sum_j' p[j']*p[k-j'] (since p has length n, p[2n-2-j'] = p[j'] only if... no, that's not right).

p[2n-2-j'] is the (2n-2-j')-th element, but p only has n elements (indices 0 to n-1). So p[2n-2-j'] is 0 unless 0 ≤ 2n-2-j' ≤ n-1, i.e., n-1 ≤ j' ≤ 2n-2.

So C[2n-2-k] = sum_{j'=n-1}^{2n-2} p[2n-2-j']*p[k-j']. This is NOT the same as C[k] in general.

Example: p = [1, 0, 0] (n=3).
C[0] = 1, C[1] = 0, C[2] = 0, C[3] = 0, C[4] = 0.
Not symmetric.

p = [1, 1, 0] (n=3).
C[0] = 1, C[1] = 2, C[2] = 1, C[3] = 0, C[4] = 0.
Not symmetric.

p = [1, 0, 1] (n=3).
C[0] = 1, C[1] = 0, C[2] = 2, C[3] = 0, C[4] = 1.
Symmetric! But this is special.

So in general, C is NOT symmetric, and the gradient formula gdp = 2*q is WRONG.

This is a significant bug in the previous program! But it still achieved 1.507966... How?

Well, L-BFGS-B with a wrong gradient will still make some progress (it's using the wrong direction, but the function value is still evaluated correctly). The wrong gradient acts like a perturbation, and the optimizer may still find a reasonable local minimum. But it's not going to be optimal.

If I fix the gradient, the LSE optimization should converge faster and more accurately to the true minimum of the LSE surrogate. And with proper annealing, the LSE minimum should be close to the true max.

So fixing the gradient is a key improvement!

Let me implement the correct gradient:
gdp[i] = (p ⋆ w)[i] + (w * p)[i]

For (p ⋆ w)[i] = sum_j p[j]*w[j+i]: this is what xfast computes (q[i]).
For (w * p)[i] = sum_j w[j]*p[i-j]: this is a standard convolution.

I can compute (w * p) using FFT:
conv_size = next_fast_len(2n-1) (since w has length 2n-1 and p has length n, the convolution has length 3n-2)
Actually: len(w) + len(p) - 1 = (2n-1) + n - 1 = 3n-2.
size = next_fast_len(3n-2)
F = rfft(p, size)
G = rfft(w, size)
conv_wp = irfft(F * G, size)[:3n-2]

Then (w*p)[i] = conv_wp[i] for i = 0, ..., n-1.

And (p ⋆ w)[i] = q[i] from xfast.

So: gdp[i] = q[i] + conv_wp[i]
