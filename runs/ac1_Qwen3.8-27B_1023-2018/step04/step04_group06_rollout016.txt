The LP gives a "best response" in a zero-sum game sense. If we think of the game:
- Player 1 chooses a (probability distribution on {0,...,n-1})
- Player 2 chooses g (probability distribution on {0,...,n-1})
- Payoff: max_k (a*g)[k]

Then the value of the game is V, and at equilibrium, both players' strategies satisfy a*g ≤ V (element-wise) and a*g = V on the support.

Our objective is 2n * max_k (a*a)[k]. If we set g = a, the payoff is max_k (a*a)[k]. The LP finds the best g against fixed a, and the iterates should converge to a Nash equilibrium where max_k (a*a)[k] is minimized.

But this is only a local optimum in general, since the game is not necessarily zero-sum in the right way, and the LP relaxation might not capture the full structure.

Key insight for improvement: **Alternate the roles of a and g**. After solving the LP to get g, also solve the LP with g as the "filter" to get a new a. This is like a coordinate descent.

Actually, that's exactly what the LP does: given a, find g that maximizes sum(g) subject to a*g ≤ M. The next a is a blend of the old a and g. This is a multiplicative-update-like iteration.

This is the classical low-autocorrelation sequence design. In the continuous (nonnegative) domain, the optimal solution should have a very flat autocorrelation (all peaks equal).

    # Phase 2: Diverse inits at parent length
    x = np.arange(np_, dtype=np.float64)
    pn = parent / max(parent.sum(), 1e-15)
    inits = []
    for pw in (0.3, 0.5, 0.7, 1.0, 1.5, 2.0, 3.0, 5.0):
        v = np.maximum(1.0 - x/(np_-1), 1e-8)**pw
        inits.append(v/v.sum())

        v = np.exp(-al * x / np_)
        inits.append(v/v.sum())
    for wd in (0.08, 0.12, 0.18, 0.3, 0.5):
        ctr = (np_-1) / 2.0
        v = np.exp(-0.5 * ((x-ctr)/(wd*np_))**2)
        inits.append(v/v.sum())
    for fr in (1, 2, 3, 4, 5):
        v = np.maximum(1.0 + 0.3*np.cos(2*np.pi*fr*x/(np_-1)), 0.01)
        inits.append(v/v.sum())

        for ii in inits[::3][:5]:
            v = fr2*pn + (1-fr2)*ii
            inits.append(v/v.sum())

    per = max(3.0, (t2 - time.monotonic()) / max(1, len(inits)))
    for i, init in enumerate(inits):
        if time.monotonic() > t2 - 5:
            break
        try:
            upd(_opt(init, min(time.monotonic()+per, t2-3), 1000+i))
        except Exception:
            pass
    
    # Phase 3: Polish best
    t3 = t0 + min(1000.0, budget_s * 0.80)
    try:
        upd(_opt(best, t3, 2000))
    except Exception:
        pass
    
    # Phase 4: Length exploration
    if time.monotonic() < dl - 60:
        for dn in (-100, -60, -40, -20, -10, 10, 20, 40, 60, 100, 150):
            if time.monotonic() > dl - 30:
                break
            nt = np_ + dn
            if nt < 16 or nt > 800:
                continue
            xo = np.linspace(0, 1, np_)
            xn = np.linspace(0, 1, nt)
            init = np.clip(np.interp(xn, xo, best), 0, 1000)
            s = init.sum()
            if s < 1e-10:
                continue
            init /= s
            try:
                upd(_opt(init, time.monotonic()+25, 3000+nt))
            except Exception:
                pass
    
    # Phase 5: Final polish
    if time.monotonic() < dl - 12:
        try:
            upd(_opt(best, dl, 9999))
        except Exception:
            pass
    
    # Validate
    try:
        fs = float(evaluate_sequence([float(v) for v in best]))
        if not np.isfinite(fs):
            raise ValueError
    except Exception:
        return [1.0]*32
    
    return [float(v) for v in best]
