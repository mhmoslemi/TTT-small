Better approach: instead of copying b each time, compute the max analytically.

For a given x (i.e., w = x-v):

           + w^2 * δ(k, 2i)

    max_{k NOT in [i,i+n-1]} b[k],
    max_{k in [i,i+n-1]} (b[k] + 2w*f[k-i]),
    b[2i] + 2w*f[i] + w^2  (if 2i in [i, i+n-1], which is always true)
)

The first term is just the max of b over the complement of [i, i+n-1].
The second term: max of (b[k] + 2w*f[k-i]) for k in [i, i+n-1] = max of (b[i:i+n] + 2w*f).

So I can precompute:
- b_ext_max = max of b outside [i, i+n-1] (which is max(b[0:i], b[i+n:2n-1]))
- b_seg = b[i:i+n] (the segment)
- Then for each x: m = max(b_ext_max, (b_seg + 2w*f).max(), b[2i]+2w*f[i]+w^2)

The (b_seg + 2w*f).max() is a max of 400 linear functions of w. I can precompute the max of this for a range of w values.

Actually, for the grid search, I just need to evaluate (b_seg + 2w*f).max() for about 30 values of w. That's 30 * 400 = 12000 operations per coordinate. For 400 coordinates: 4.8M per sweep. At ~50M ops/sec, that's ~0.1s per sweep. Very fast!

And I don't need to copy b at all! I just keep b and update it in-place after each accepted coordinate change.

Now, for the LP step, the main cost is building the A matrix (799 x 400) and solving the LP. The matrix is:
A[k,j] = f[j] if max(0, k-n+1) <= j <= min(n-1, k) else 0
        = f[k-j] if 0 <= k-j <= n-1 else 0

This is a Toeplitz-like matrix (actually, it's the convolution matrix). We can build it efficiently:

```python
def _build_conv_matrix(f):
    n = len(f)
    A = np.zeros((2*n-1, n))
    for j in range(n):
        A[j:j+n, j] = f
    return A
```

This is O(n^2) = O(160K) for n=400, which is fast.

Alternatively, we can use the fact that A = sum_j f[:,j] * e_j^T where the columns are shifted versions of f. This is a Hankel/Toeplitz matrix and can be applied to a vector via FFT. But for the LP solver, we need the explicit matrix (at least for presolve).

For n=400, the matrix has 799*400 = 319,600 entries, of which about 400*400/2 = 80,000 are non-zero (it's a banded matrix with bandwidth n). Actually, each column j has n non-zero entries, so total non-zeros = n*n = 160,000. In a 799x400 matrix, that's about 50% density. Not very sparse.

The LP has 400 variables and 799 constraints. HiGHS should handle this quickly (well under 1 second).

Let me also think about a better objective for the LP. Instead of maximizing sum(g), we could maximize a weighted sum that focuses on the "deficit" at high-convolution positions. Or we could minimize the maximum of the new convolution directly (as a QP).

Actually, a better approach: solve the LP with a TIGHTER bound. Instead of (f*g)[k] <= M, use (f*g)[k] <= M * (1 - epsilon) for some small epsilon. This forces the direction to reduce the peak more aggressively.

Or even better: solve the LP with (f*g)[k] <= M - delta_k where delta_k > 0 for active constraints. This is like a barrier method.
