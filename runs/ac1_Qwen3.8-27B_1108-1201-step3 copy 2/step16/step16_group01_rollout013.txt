Let me focus on approach #5: **Peak Reduction via Quadratic Programming**

At each iteration:
1. Find the current peak lag k*.
2. Solve: min a^T C_{k*} a subject to a >= 0, sum(a) = 1, and the other top peaks don't increase too much.
3. This is a QP (quadratic program) which can be solved efficiently.

Actually, minimizing a quadratic form subject to linear constraints is a convex optimization problem (if the quadratic form is positive semidefinite, which it is for C_k since it's a Gram matrix).

Wait, is C_k positive semidefinite? C_k is the matrix such that a^T C_k a = conv(k). Let's see:
conv(k) = sum_i a[i] * a[i+k] (for valid i)

This can be written as: if we define b[i] = a[i] and c[i] = a[i+k], then conv(k) = b^T c = b^T P_k a where P_k is a shift matrix.

So a^T C_k a = a^T P_k a where P_k is the "k-th shift" matrix. P_k is NOT symmetric in general, so C_k = (P_k + P_k^T)/2.

For the autocorrelation, P_k + P_k^T is the matrix such that a^T (P_k + P_k^T)/2 a = sum_i a[i]*a[i+k] (for valid i).

Is this positive semidefinite? It's a Toeplitz-like matrix. For k=0, it's the identity (sum a[i]^2), which is PSD. For k > 0, it's not necessarily PSD.

Actually, for non-negative a, a^T C_k a = sum_i a[i]*a[i+k] >= 0 always. But C_k itself might not be PSD for all a (it's only guaranteed to be non-negative on the non-negative orthant).

So the QP approach might not be directly applicable. Let me think of another way.

Alternative: **Subgradient + Projected Gradient with Momentum**

The subgradient of max_k conv[k] at a is:
- If k* is the unique argmax: 2 * P_{k*} a (where P_{k*} is the shift matrix)
- If there are multiple argmax: any convex combination of the corresponding subgradients

We can use this subgradient in a projected gradient descent (projecting onto the simplex {a >= 0, sum(a) = 1}).

The projection onto the simplex is: given v, find the closest point on the simplex. This can be done in O(n log n) using a sorting-based algorithm.

This is similar to what the AMD does, but with a different step size and projection.

Actually, the AMD is already doing essentially this (mirror descent in log-space is equivalent to multiplicative weights, which is a form of projected gradient on the simplex).

**Idea: Use the "Peeling" Method**

Instead of moving all the mass at once, "peel off" small amounts from the positions that most contribute to the peak, and redistribute them optimally.

The contribution of position i to the peak at lag k* is: 2 * a[i] * a[k*-i] (if k*-i is valid).

So the "peak sensitivity" of position i is: s[i] = 2 * a[k*-i] (for the peak lag k*).

We want to move mass from high-sensitivity positions to low-sensitivity positions. The optimal amount to move is determined by the trade-off between reducing the current peak and potentially increasing other peaks.

This is essentially a small-step coordinate descent, which the previous program already does. But we can make it more efficient by:
1. Computing the exact optimal transfer amount (not just trying a few fractions)
2. Considering the effect on ALL lags, not just the peak

**Idea: Lagrangian Relaxation**

Introduce a Lagrange multiplier for each peak constraint:
L(a, lambda) = sum_k lambda_k * (conv(k) - M) + penalty for a not being on the simplex

At the optimum, lambda_k > 0 only for the active constraints (peaks at M). This gives a way to identify the "important" lags and focus the optimization.

This is similar to the active-set approach in the previous code, but more principled.

**Idea: Spectral Method via FFT**

The autocorrelation can be computed via FFT. We can also use the FFT to compute the "gradient" of the autocorrelation with respect to the sequence.

The gradient of conv(k) with respect to a[i] is: 2 * a[k-i] (if valid).

So the gradient of max_k conv(k) is: 2 * a[k*-i] for the peak lag k*.

This is what the previous code already uses. But we can also compute the "full gradient" (gradient of the sum of all conv values, weighted by their importance) to get a smoother direction.
