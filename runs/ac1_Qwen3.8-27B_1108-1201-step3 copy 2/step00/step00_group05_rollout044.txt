Let me think about this more carefully. The self-convolution `a*a` at lag k is the number of ways to write k as i+j where both a[i] and a[j] are non-zero (weighted by their values). For a binary sequence, it's the number of pairs (i,j) with i+j=k and both 1.

To minimize the maximum of this, we want the "addition table" to be as balanced as possible. This is related to the concept of "sumsets" in combinatorics.

If A is the set of indices where a[i]=1, then c[k] = |{i ∈ A : k-i ∈ A}| = |A ∩ (k-A)| where k-A = {k-i : i ∈ A}.

We want to minimize max_k |A ∩ (k-A)|.

For |A| = m out of n positions, the average of c[k] over all k is m^2/(2n-1) (since sum_k c[k] = m^2).

So we want c[k] to be as close to m^2/(2n-1) as possible for all k.

The score is 2n * max(c) / m^2. If max(c) ≈ m^2/(2n-1), then score ≈ 2n/(2n-1) ≈ 1.

So the question becomes: can we find a large subset A of {0,...,n-1} such that all the "difference" (or rather "sum") counts are approximately equal?

This is related to "difference sets" and "Costas arrays" but for sums instead of differences.

Actually, for sums: c[k] = |{(i,j) ∈ A×A : i+j = k}|. This is the "sumset" counting function.

A set A where all sum counts are equal is called a "perfect difference set" for sums, or more precisely, it's related to "Bose-Chowla" type constructions.

Actually, this is exactly the problem of finding a set A ⊂ Z_n (cyclic) such that every element of Z_n can be written as a sum of two elements of A in exactly the same number of ways. This is the definition of a "perfect 1-error-correcting code" or more precisely, it's related to "Hadamard difference sets."
