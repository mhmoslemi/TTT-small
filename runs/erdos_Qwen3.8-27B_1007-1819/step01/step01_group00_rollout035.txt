                h = best_h.copy()
                curr = best_c
                improved = True

Hmm, this is getting messy. The feasibility fixing during coordinate descent is problematic because adjusting one coordinate to fix the sum means we're really doing a 2-variable move.

Let me use a cleaner approach: parameterize the feasible set. Let h = 0.5 + x where sum(x) = 0 and -0.5 ≤ x[i] ≤ 0.5. Then instead of optimizing h directly, I optimize x with the constraint sum(x) = 0.

For coordinate descent on x: changing x[i] by delta requires changing some other x[j] by -delta to maintain sum(x) = 0. So each "move" is really a 2D move: (delta at i, -delta at j).

This is cleaner! Let me use this.

Actually, even simpler: I'll just do the coordinate descent on h with a "paired" move. For coordinate i, I try different values of h[i], and for each trial value, I distribute the sum correction to the coordinate with the most room. This is a heuristic but works well in practice.
