```python
def subgradient_optimize(h, n, n_iters=500, lr=0.05):
    h_curr = h.copy()
    best = compute_c5(h_curr)
    for it in range(n_iters):
        dx = 2.0 / n
        corr = np.correlate(h_curr, 1.0 - h_curr, mode="full") * dx
        k_max = np.argmax(corr)
        k = k_max - (n - 1)
        # Gradient of g_k at h_curr
        grad = np.zeros(n)
        if k >= 0:
            idx = np.arange(n - k)
            grad[idx] += (1.0 - h_curr[idx + k])
            grad[idx + k] -= h_curr[idx]
        else:
            ks = -k
            idx = np.arange(ks, n)
            grad[idx] += (1.0 - h_curr[idx - ks])
            grad[idx - ks] -= h_curr[idx]
        grad *= dx
        # Adaptive learning rate
        lr_adapt = lr / (1.0 + it * 0.01)
        h_new = h_curr - lr_adapt * grad
        # Project to {h: 0<=h<=1, sum(h)=n/2}
        h_new = project_feasible(h_new, n)
        c5_new = compute_c5(h_new)
        if c5_new < best:
            best = c5_new
            h_curr = h_new
        # If stuck, reduce lr
        if it > 50 and c5_new >= best - 1e-14:
            lr_adapt *= 0.9
    return h_curr, best
```

Actually, I just realized something. The problem with the smooth max approach is that it smooths over ALL shifts, not just the worst one. When beta is very high, it focuses on the worst shifts, which is good. But when multiple shifts are tied for worst, it averages their gradients, which might not be the right direction.

A better approach: **Identify the top-K worst shifts and only smooth over those.** This gives a tighter approximation with lower beta:

```python
def smooth_topk_obj(h, n, K, beta, lam):
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode="full") * dx
    # Get top K shifts
    topk_idx = np.argsort(corr)[-K:]
    topk = corr[topk_idx]
    m = np.max(topk)
    val = m + np.log(np.sum(np.exp(beta * (topk - m)))) / beta
    val += lam * (h.sum() - n / 2.0) ** 2
    return val
```

With K=5 and beta=20, this focuses specifically on the worst 5 shifts. This is more targeted than using all 359 shifts.

```python
def project_feasible(x, n):
    target = n / 2.0
    lo, hi = -2.0, 2.0
    for _ in range(50):
        mid = (lo + hi) / 2.0
        if np.clip(x - mid, 0.0, 1.0).sum() > target:

            hi = mid
```
