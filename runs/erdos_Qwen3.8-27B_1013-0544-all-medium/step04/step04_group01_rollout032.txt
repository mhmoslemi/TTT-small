```python
                    if 0 <= hi <= 1 and 0 <= hj <= 1:
                        h[i], h[j] = hi, hj
                        c_new = np.correlate(h, 1-h, mode='full')
                        val = float(c_new.max() * dx)
                        if val < best_c:
                            best_c = val
                            improved = True
                        else:
                            h[i], h[j] = hi-d, hj+d
        if not improved:
            break
    return h, best_c
```

Actually, this pair polish is O(n² * n) per pass (n² pairs, each O(n) to compute correlation), which is too slow. Let me use the incremental update:

When I change h[i] by +d and h[j] by -d, the correlation changes by:
c_new[p] = c[p] + d * b_p(i) - d * b_p(j)

where b_p(i) is the coefficient of h[i] in c[p] (as computed before).

So I can precompute b for both i and j, and update c in O(n) time. This makes the pair polish O(n³) per pass, which for n=200 is 8M per pass. With 10 passes: 80M. That's manageable.

The function g(t) = max_p (a_p + b_p * t) is the upper envelope of n lines. The minimum of this envelope on [0,1] is at:
- t = 0, if the slope of the active line at t=0 is ≥ 0
- t = 1, if the slope of the active line at t=1 is ≤ 0
- An intersection point of two lines, where the slope changes from negative to positive

The intersection of lines p and q is at t = (a_p - a_q) / (b_q - b_p) (when b_p ≠ b_q).

To find the minimum, I can:
1. Find the active line at t=0 (max of a_p)
2. If its slope b_p ≥ 0, the minimum is at t=0
3. Otherwise, find the next line that becomes active as t increases
4. Continue until the active line has slope ≥ 0

Finding the "next active line" is the expensive part. It's essentially a linear programming problem in 1D.
