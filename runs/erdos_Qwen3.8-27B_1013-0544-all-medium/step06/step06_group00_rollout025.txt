    # sum(clip(h[i] + t, 0, 1)) is a piecewise linear function of t

Now let me think about the projected gradient more carefully. The key challenge is the learning rate. If it's too large, we oscillate. If too small, we converge slowly.

A common approach is to use a decaying learning rate: lr = lr0 / (1 + decay * iter) or lr = lr0 / sqrt(iter).

Another approach is to use backtracking line search: try a step, if the objective increases, reduce the step size.

For the smooth max approximation, the function is α-Lipschitz (approximately), so the optimal step size is O(1/α). But in practice, we can do better with line search.

Let me use a simple approach: fixed learning rate with restarts. If the objective doesn't improve in 100 iterations, reduce the learning rate.

Actually, let me think about this differently. The smooth max C_α(h) is a smooth approximation to the max. As α increases, it becomes steeper (more like the true max). For small α, it's smoother and easier to optimize, but the solution might not be optimal for the true max.

Strategy:
1. Start with small α (smooth), optimize to convergence
2. Increase α, continue optimizing from current point
3. This should "sharpen" the solution towards the true max minimizer

The learning rate for projected gradient on an L-Lipschitz smooth function is 1/L. For the smooth max, L ≈ α * (max f_k - min f_k) / n or something like that. In practice, I'll use a heuristic.

Let me also think about the **binary local search** more carefully.
