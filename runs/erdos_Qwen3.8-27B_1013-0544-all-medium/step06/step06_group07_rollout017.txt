```python
def fast_smooth_max_grad(h, n, alpha):
    dx = 2.0 / n
    corr = np.correlate(h, 1 - h, mode='full')
    c = corr * dx
    m = c.max()
    shifted = alpha * (c - m)
    max_sh = shifted.max()
    exp_vals = np.exp(shifted - max_sh)
    w_sum = exp_vals.sum()
    weights = exp_vals / w_sum
    obj = m + (max_sh + np.log(w_sum)) / alpha
    
    A = np.zeros(n)  # sum_k w_k * h[j-k]
    B = np.zeros(n)  # sum_k w_k * h[j+k]
    
    for k_idx in range(2 * n - 1):
        k = k_idx - (n - 1)
        w = weights[k_idx]
        if w < 1e-14:
            continue
        if k >= 0:
            A[k:] += w * h[:n-k]
            B[:n-k] += w * h[k:]
        else:
            A[:n+k] += w * h[-k:]
            B[-k:] += w * h[:n+k]
    
    grad = dx * (1.0 - A - B)
    return obj, grad
```

This is O(n * (2n-1)) = O(n²) per call. For n=250, that's about 125000 operations. Very fast.

Now let me also think about the **coordinate descent** approach more carefully.

For coordinate descent, at each step we fix all variables except h[j] and optimize h[j]. The objective as a function of v = h[j] is:

f(v) = max_k C_k(v) * dx

where:
- C_0(v) = C(0)_old + (v - v²) - (h[j] - h[j]²) [quadratic, concave]
- C_k(v) = C_k_old + (v - h[j]) * s_k for k ≠ 0 [linear]

where s_k = (1 - h[j-k]) - h[j+k] (with 0 for out of bounds) for k ≠ 0.

Note: for k=0, s_0 would be (1-h[j]) - h[j] = 1-2h[j], but since C_0 is quadratic, we handle it separately.

The function f(v) is the max of 2n-2 linear functions and 1 quadratic function. 

For the quadratic term C_0(v) = C_0_old + v - v² - h[j] + h[j]²:
- This is a concave parabola with vertex at v = 0.5
- Its maximum value is C_0_old + 0.25 - h[j] + h[j]² (at v=0.5)
- At v=0: C_0_old - h[j] + h[j]²
- At v=1: C_0_old + 1 - 1 - h[j] + h[j]² = C_0_old - h[j] + h[j]²

Interesting: C_0(0) = C_0(1) = C_0_old - h[j] + h[j]². And C_0(0.5) = C_0_old + 0.25 - h[j] + h[j]².

For the linear terms, the max of lines is a convex piecewise-linear function.

So f(v) = max(convex_pwl(v), concave_quadratic(v)) which is NOT necessarily convex.

However, in practice, if the linear terms dominate (which they usually do when h[j] is not extremely close to 0.5), the function is approximately convex and unimodal.

For a practical approach: just do a fine grid search (e.g., 100 points) and then refine with bisection.

Actually, the simplest approach: just change h[j] and then project. The projection is a small perturbation to all other values (proportional to their "room" or "mass"), so it's approximately a coordinate update.
