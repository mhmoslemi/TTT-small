import numpy as np
import time

def compute_c5(h, n):
    dx = 2.0 / n
    c = np.correlate(h, 1 - h, mode='full')
    return float(np.max(c) * dx)

def project_feasible(h, n):
    target = n / 2.0
    h = np.clip(h, 0.0, 1.0)
    for _ in range(300):
        diff = target - h.sum()
        if abs(diff) < 1e-14:
            break
        if diff > 0:
            room = 1.0 - h
            s = room.sum()
            if s < 1e-14:
                break
            h = h + (diff / s) * room
        else:
            s = h.sum()
            if s < 1e-14:
                break
            h = h * (target / s)
    return np.clip(h, 0.0, 1.0)

def compute_gradient(h, n, alpha):
    """Compute gradient of log-sum-exp smoothed C5."""
    dx = 2.0 / n
    c = np.correlate(h, 1 - h, mode='full') * dx
    shifted = alpha * (c - c.max())
    exp_vals = np.exp(shifted)
    p = exp_vals / exp_vals.sum()
    
    # A_i = conv(h, p_rev, 'full')[i + n - 1]
    # B_i = conv(h, p, 'full')[i + n - 1]
    conv_A = np.convolve(h, p[::-1], mode='full')
    conv_B = np.convolve(h, p, mode='full')
    
    A = conv_A[n-1 : 2*n-1]  # indices n-1 to 2n-2, length n
    B = conv_B[n-1 : 2*n-1]
    
    grad = dx * (1.0 - A - B)
    return grad, c
```

The problem min_h max_k ∑_j h_j(1-h_{j+k}) is non-convex. But we can use the following trick:
- Fix the value of the maximum: T
- Check feasibility: does there exist h with ∑_j h_j(1-h_{j+k}) ≤ T for all k?
- This is equivalent to: h^T I h - h^T A_k h ≤ T for all k (where A_k is the shift matrix)
- i.e., h^T (I - A_k) h ≤ T for all k
- These are quadratic constraints (QCQPs)
- The matrices (I - A_k) are symmetric but not necessarily positive semidefinite

Since (I - A_k) is not PSD in general, these are non-convex QCQPs. So this approach doesn't directly help.

However, we can use a **trust region** approach:
- Linearize the quadratic constraints around the current point
- Solve the resulting convex problem (LP or QP)
- Update the point
- This is essentially what the LP step in the previous code does!

So the LP approach is actually quite natural and hard to beat in terms of local optimization quality. The key is to make it faster and to escape local minima.

**Key insight for improvement**: The previous code's LP step considers ALL shifts (2n-1 of them). This makes the LP large. If we only consider the top M shifts (which are close to the maximum), the LP is much smaller and faster, allowing more iterations.

But there's a risk: by ignoring the other shifts, we might make them worse. Mitigation: periodically check all shifts and add any that have become too large.

def sparse_lp_step(h, n, eps, M=30):
    """LP step considering only top M shifts."""
    C = np.correlate(h, 1 - h, mode='full').astype(float)
    mc = C.max()
    
    # Get top M shifts
    top_idx = np.argsort(C)[-M:]
    
    # Build gradient for only these shifts
    # G[i, m] = ∂C[top_idx[m]]/∂h[i]
    G = np.zeros((n, M))
    for m_idx, shift_idx in enumerate(top_idx):
        k = shift_idx - (n - 1)
        # ∂c_shift/∂h_i = (1-h_{i+k}) - h_{i-k}
        for i in range(n):
            val = 0.0
            if 0 <= i + k < n:
                val += 1.0 - h[i + k]
            if 0 <= i - k < n:
                val -= h[i - k]
            G[i, m_idx] = val
    
    # LP: minimize t
    # s.t. C[top_idx] + G^T delta <= t
    #      -eps <= delta <= eps
    #      -h <= delta <= 1-h
    #      sum(delta) = 0
    import cvxpy as cp
    delta = cp.Variable(n)
    t = cp.Variable()
    constraints = [
        C[top_idx] + G.T @ delta <= t,
        delta >= -eps,
        delta <= eps,
        delta >= -h,
        delta <= 1.0 - h,
        cp.sum(delta) == 0
    ]
    prob = cp.Problem(cp.Minimize(t), constraints)
    prob.solve(solver='GLOP')
    if delta.value is None:
        return h, mc
    d = delta.value
    # Line search
    best_h = h.copy()
    best_mc = mc
    for lam in [1.0, 0.7, 0.5, 0.3, 0.1]:
        h_try = project_feasible(h + lam * d, n)
        mc_try = compute_c5(h_try, n)
        if mc_try < best_mc:
            best_mc = mc_try
            best_h = h_try
    return best_h, best_mc

    if k >= 0:
        valid_i = range(n - k)  # i + k < n
        grad[valid_i] += 1 - h[k:]  # h[i+k] for i=0..n-1-k
    else:
        valid_i = range(-k, n)  # i + k >= 0
        grad[valid_i] += 1 - h[:n+k]  # h[i+k] for i=-k..n-1
    # -h[i-k] part
    if k >= 0:
        valid_i = range(k, n)  # i - k >= 0
        grad[valid_i] -= h[:n-k]  # h[i-k] for i=k..n-1
    else:
        valid_i = range(n + k)  # i - k < n
        grad[valid_i] -= h[-k:]  # h[i-k] for i=0..n-1+k
    return grad
```

Let me also think about one more potential improvement: **coordinate descent**.

Since the objective is a max of bilinear forms, we can optimize one coordinate at a time. For a fixed i, the objective as a function of h_i is:
f(h_i) = max_k [c_k(h_{-i}) + h_i * (1 - h_{i+k}) - h_i * (1-h_{i-k}) * (-1)]

Wait, let me be more careful. c_k = ∑_j h_j(1-h_{j+k}). The terms involving h_i are:
- j=i: h_i(1-h_{i+k})
- j+k=i, i.e., j=i-k: h_{i-k}(1-h_i)

So c_k = c_k(h_{-i}) + h_i(1-h_{i+k}) + h_{i-k}(1-h_i)
= c_k(h_{-i}) + h_i - h_i*h_{i+k} + h_{i-k} - h_{i-k}*h_i
= c_k(h_{-i}) + h_i(1 - h_{i+k} - h_{i-k}) + h_{i-k}

where c_k(h_{-i}) is c_k with h_i removed.

So f(h_i) = max_k [A_k + h_i * B_k] where A_k = c_k(h_{-i}) + h_{i-k} and B_k = 1 - h_{i+k} - h_{i-k}.

This is the max of linear functions of h_i, which is convex in h_i! So for fixed h_{-i}, the optimal h_i is:
- If B_k < 0 for the active k: h_i = 1 (maximize h_i)
- If B_k > 0 for the active k: h_i = 0 (minimize h_i)
- If B_k = 0: any h_i in [0,1] works (but we need to satisfy the sum constraint)

This suggests a coordinate descent approach where:
1. For each i, compute the optimal h_i given the sum constraint
2. Cycle through all coordinates

This is an exact (not approximate) coordinate descent, and each coordinate update is O(n) (to compute B_k for all k and find the max).

Total cost per full sweep: O(n²). For n=400, that's 160K operations. Very fast!

The convergence might be slow (sublinear for non-smooth objectives), but it's a good complement to the gradient/LP methods.

def compute_c5(h, n):
    dx = 2.0 / n
    c = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(c) * dx)

def project_feasible(h, n):
    target = n / 2.0
    h = np.clip(h, 0.0, 1.0)
    for _ in range(300):
        diff = target - h.sum()
        if abs(diff) < 1e-14:
            break
        if diff > 0:
            room = 1.0 - h
            s = room.sum()
            if s < 1e-14:
                break
            h = h + (diff / s) * room
        else:
            s = h.sum()
            if s < 1e-14:
                break
            h = h * (target / s)
    return np.clip(h, 0.0, 1.0)

def compute_gradient(h, n, alpha):
    dx = 2.0 / n
    c = np.correlate(h, 1.0 - h, mode='full') * dx
    shifted = alpha * (c - c.max())
    exp_vals = np.exp(shifted)
    p = exp_vals / exp_vals.sum()
    conv_A = np.convolve(h, p[::-1], mode='full')
    conv_B = np.convolve(h, p, mode='full')
    A = conv_A[n-1:2*n-1]
    B = conv_B[n-1:2*n-1]
    grad = dx * (1.0 - A - B)
    return grad
