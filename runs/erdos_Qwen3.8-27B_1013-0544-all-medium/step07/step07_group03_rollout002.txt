= -h[l-i] + h[l-j] + (1-h[l-i]) - (1-h[l-j]) - [l==2i] - [l==2j] + 2[l==i+j]
= -h[l-i] + h[l-j] + 1 - h[l-i] - 1 + h[l-j] - [l==2i] - [l==2j] + 2[l==i+j]
= 2(h[l-j] - h[l-i]) - [l==2i] - [l==2j] + 2[l==i+j]

So the formula is:
delta[l] = 2*(h[l-j] - h[l-i]) - [l==2i] - [l==2j] + 2*[l==i+j]

where h[x] = 0 if x < 0 or x >= n.

This is O(n) to compute for a given (i, j) pair, since we need to compute h[l-j] and h[l-i] for all l.

Actually, we can do it even faster! Note that h[l-j] - h[l-i] is just a shifted version of h. Let me define d[m] = h[m] for m in [0,n), 0 otherwise. Then:

delta[l] = 2*(d[l-j] - d[l-i]) - [l==2i] - [l==2j] + 2*[l==i+j]

The vector [d[l-j] - d[l-i]] for l = 0, ..., 2n-2 is just a circular convolution-like thing. Actually, it's:
- d shifted by j, minus d shifted by i, evaluated at each l.

So delta_vec = 2*(d_shifted_by(j) - d_shifted_by(i)) + correction terms.

Where d_shifted_by(k)[l] = d[l-k] (which is d at position l-k, i.e., a right shift by k).

In numpy:
d = h (padded with zeros conceptually, but we can handle bounds)
For l in [0, 2n-2]:
  d[l-j] is h[l-j] if 0 <= l-j < n, else 0
  d[l-i] is h[l-i] if 0 <= l-i < n, else 0

So delta_vec = 2*(h_shifted(j) - h_shifted(i)) where h_shifted(k)[l] = h[l-k] if valid.

Let me implement this:

```python
def compute_delta(h, i, j, n):
    """Compute delta in correlation for swap i(0->1) and j(1->0)."""
    # delta[l] = 2*(h[l-j] - h[l-i]) - [l==2i] - [l==2j] + 2*[l==i+j]
    delta = np.zeros(2*n-1)
    # h[l-j] for l in [0, 2n-2]: valid when 0 <= l-j < n, i.e., j <= l < j+n
    lo1 = max(0, j)
    hi1 = min(2*n-1, j+n)
    delta[lo1:hi1] += 2.0 * h[lo1-j:hi1-j]
    # - h[l-i] for l in [0, 2n-2]: valid when 0 <= l-i < n, i.e., i <= l < i+n
    lo2 = max(0, i)
    hi2 = min(2*n-1, i+n)
    delta[lo2:hi2] -= 2.0 * h[lo2-i:hi2-i]
    # Correction terms
    if 0 <= 2*i < 2*n-1:
        delta[2*i] -= 1.0
    if 0 <= 2*j < 2*n-1:
        delta[2*j] -= 1.0
    if 0 <= i+j < 2*n-1:
        delta[i+j] += 2.0
    return delta
```

This is O(n) per swap evaluation. For n=400, each sweep tries O(n) swaps, so O(n²) = 160k operations per sweep. Very fast!

Hmm wait, I realize there's an issue with my smooth max. Let me reconsider.

The smooth max approximation is:
f_α(v) = (1/α) ln(Σ exp(α v_i))

This satisfies f_α(v) → max(v_i) as α → ∞, and f_α(v) ≥ max(v_i).

So to minimize max(c), we can minimize f_α(c) for large α.

The issue is that for very large α, f_α becomes very peaked and the optimization becomes hard. A common trick is to use a "surrogate" that's the max plus a small smooth term:

g_α(c) = max(c) + (1/α) ln(Σ exp(α(c_i - max(c))))

This is ≥ max(c) and → max(c) as α → ∞. But it's not convex in the same way.

Actually, the standard approach in the previous code was:
m = c.max()
shifted = alpha * (c - m)
logsum = log(sum(exp(shifted)))
return m + logsum / alpha

This equals m + (1/alpha)*ln(Σ exp(alpha*(c_i - m)))

When c_i = m: exp(0) = 1
When c_i < m: exp(alpha*(c_i - m)) < 1

So logsum ≥ 0 (since at least one term is 1), and logsum/alpha → 0 as alpha → ∞.

So this objective is m + small_positive, which is a valid smooth approximation of m from above. Good.

But the gradient of this is:
∂/∂x [m + (1/alpha)*ln(Σ exp(alpha*(c_i - m)))]

This is complicated because m depends on x too. The previous code just lets SLSQP handle it numerically.
