Actually, let me think about this differently. The problem is related to the "minimum overlap" problem. For the E(5) constant, we're looking at 5-fold overlaps. The optimal construction for small E(n) constants often involves functions that are close to 1/2 with small perturbations.

Let me try a different approach: **Fourier-based optimization**.

The overlap integral can be expressed in terms of the Fourier transform:
∫ h(x)(1-h(x+k)) dx = ∫ h(x)dx - ∫ h(x)h(x+k) dx

The autocorrelation ∫ h(x)h(x+k) dx can be computed via the inverse Fourier transform of |H(ω)|².

So the problem becomes: minimize max_k (∫h dx - inverse_FFT(|H(ω)|²)(k))

This doesn't immediately help, but it suggests that we could work in Fourier space.

However, for a numerical implementation, I think the direct approach is fine. Let me focus on making the optimization more effective.

**Another idea: Use Nelder-Mead on a reduced set of parameters**

If the optimal solution has a specific structure (e.g., it's piecewise constant with a few pieces), I could parameterize it with fewer parameters and use Nelder-Mead to optimize those parameters.

For example, parameterize h as:
h(x) = 0.5 + a1*sin(πx) + a2*sin(2πx) + ... + am*sin(mπx)

Then clip to [0,1] and project to satisfy the integral constraint.

This gives a smooth family of functions with m parameters, which is much easier to optimize.

Let me try this approach as an alternative.

Actually, combining both approaches would be best:
1. Use Fourier parameterization to find a good starting point

    n = len(h)

    return float(np.max(corr) * dx)

def project_h(h, target_sum):
    h = np.clip(h, 0.0, 1.0)
    for _ in range(300):
        diff = target_sum - h.sum()
        if abs(diff) < 1e-13:
            break
        free = (h > 1e-9) & (h < 1.0 - 1e-9)
        if free.sum() == 0:

        h = np.clip(h, 0.0, 1.0)
