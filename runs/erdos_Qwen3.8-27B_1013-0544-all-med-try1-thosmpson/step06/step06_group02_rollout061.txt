```python
def grad_lag(h, k):
    """Gradient of correlation at lag k w.r.t. h."""
    N = len(h)
    g = np.zeros(N)
    # Term 1: (1-h[j-k]) for valid j-k
    # j-k >= 0 → j >= k
    # j-k < N → j < N+k
    s1 = max(0, k)
    e1 = min(N, N + k)
    if s1 < e1:
        g[s1:e1] += 1.0 - h[s1-k:e1-k]
    # Term 2: -h[j+k] for valid j+k
    # j+k >= 0 → j >= -k
    # j+k < N → j < N-k
    s2 = max(0, -k)
    e2 = min(N, N - k)
    if s2 < e2:
        g[s2:e2] -= h[s2+k:e2+k]
    return g
```

Actually, there's a simpler way to solve the 1D minimax. The function f(x) = max_k (b_k + m_k * x) where m_k = a_k + lambda is convex. Its minimum is where f'(x) changes sign, i.e., where the "active" line changes from negative slope to positive slope.

2. The optimal x is where the maximum of the lines is minimized.

Actually, the simplest correct approach for 1D:
- The optimal x* is either 0, 1, or an intersection point of two "active" lines.
- We can find it by:
  a. Evaluate f(x) at x=0 and x=1
  b. Find the x where the upper envelope has its minimum (this is where two lines with slopes of opposite sign cross)

For efficiency, I'll use the following algorithm:
1. Compute all lines (m_k, b_k)
2. The minimum of max_k(b_k + m_k*x) over x ∈ [0,1] can be found by:
   - Binary search on the optimal value t
   - For a given t, check feasibility: is there x ∈ [0,1] such that b_k + m_k*x <= t for all k?
     - This gives: for m_k > 0: x <= (t-b_k)/m_k
     - For m_k < 0: x >= (t-b_k)/m_k
     - For m_k = 0: need t >= b_k
   - The feasible x interval is [max(0, max_{m_k<0}(t-b_k)/m_k), min(1, min_{m_k>0}(t-b_k)/m_k)]
   - Feasible if lower <= upper

The binary search on t takes about 30 iterations (for double precision), each O(N). Total: O(N * 30) per coordinate. For N=120, that's 3600 per coordinate, 432K per full sweep. Still very fast.

Wait, I realize there's an issue. After I set h[j] = x_opt, the correlation changes, but I'm using the old correlation for the next coordinates. This is the "Gauss-Seidel" vs "Jacobi" issue. In Gauss-Seidel, I'd use the updated h for subsequent coordinates, but the correlation would be different.

For simplicity, I'll use the "Jacobi" approach (use the correlation at the start of the sweep for all coordinates within that sweep), and do multiple sweeps to converge.

But actually, the correlation depends on ALL of h, not just h[j]. So when I change h[j], the correlation for the next coordinate j+1 is different. This means my b_k is stale after the first coordinate update.

To handle this properly, I should either:
1. Use the stale correlation (faster, but less accurate) - multiple sweeps will help
2. Update the correlation incrementally after each coordinate change

Option 2: When h[j] changes by delta, how does corr change?
corr[k] = sum_n h[n+k]*(1-h[n])
The change in corr[k] when h[j] → h[j]+delta:
- Terms where n+k=j (n=j-k): delta*(1-h[j-k])
- Terms where n=j (in 1-h[n]): -delta*h[j+k]

So: corr_new[k] = corr_old[k] + delta*((1-h[j-k])*1_{0<=j-k<N} - h[j+k]*1_{0<=j+k<N})
= corr_old[k] + delta * a_k

This is O(N) to update! So I can do exact Gauss-Seidel with O(N) per coordinate, O(N^2) per sweep.

def project_feasible(v, N):
    target = N / 2.0
    lo, hi = -1.5, 1.5
    for _ in range(60):
        mid = (lo + hi) / 2.0
        if np.clip(v - mid, 0.0, 1.0).sum() > target:
            lo = mid
        else:
            hi = mid

def solve_1d_minimax(b_k, m_k):

    t_lo = float(np.min(b_k)) - 1.0
    t_hi = float(np.max(b_k + m_k)) + 1.0
    for _ in range(45):

def coord_refine(h, N, n_sweeps=5):

    _, corr, _ = obj_and_corr(h)
    lam = 0.0
