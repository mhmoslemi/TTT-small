    hi = h.max() + 1.0

def smooth_obj_weights(h, T):
    n = len(h)
    corr = np.correlate(h, 1 - h, mode="full")
    mc = np.max(corr)
    sh = T * (corr - mc)
    sh -= sh.max()
    e = np.exp(sh)
    se = e.sum()
    obj = (mc + np.log(se) / T) * (2.0 / n)
    sw = e / se
    return obj, sw

def grad_from_weights(h, sw):
    n = len(h)
    grad = np.zeros(n)
    c = n - 1
    for j in range(2 * n - 1):
        w = sw[j]
        if w < 1e-14:
            continue

        if k == 0:
            grad += w * (1.0 - 2.0 * h)
        elif k > 0:

        else:
            p = -k
            grad[:n - p] += w * (1.0 - h[p:])
            grad[p:] -= w * h[:n - p]
    return grad * (2.0 / n)

Let me also think: what's the actual structure of the optimal solution? For the Erdős problem, I believe the optimal h is related to a "balanced sequence" - one where no shift creates too much agreement or disagreement. 

A key insight: if h is binary (0 or 1), then h(x)*(1-h(x+k)) is 1 when h(x)=1 and h(x+k)=0. The sum over x counts the number of "1-to-0" transitions at shift k. For a binary sequence of length n with n/2 ones, the minimum possible maximum over all shifts is related to the "autocorrelation" properties.

For a balanced binary sequence (n/2 ones, n/2 zeros), the average number of 1-to-0 transitions at shift k is about n/4 (by symmetry). We want to minimize the maximum, which should be close to n/4.

C5 for binary: max_k (count of 1s followed by 0 at shift k) * dx = max_k (count) * 2/n.
If max count ≈ n/4, then C5 ≈ (n/4) * 2/n = 0.5.

But the optimal is 0.38, which is less than 0.5. This means the optimal solution is NOT binary - it uses intermediate values (0 < h < 1) to reduce the maximum overlap.

If h is binary with n/2 ones: sum_i h[i]*(1-h[i+k]) for a specific k counts positions where h[i]=1 and h[i+k]=0 (for k≥0, this is i=0 to n-1-k). The maximum over k of this count, times dx, gives C5.

For a perfectly "balanced" binary sequence (like alternating 1,0,1,0,...), at even shifts the overlap is n/2 (all 1s align with 0s) and at odd shifts it's 0. So C5 = (n/2) * 2/n = 1.0. That's terrible.
