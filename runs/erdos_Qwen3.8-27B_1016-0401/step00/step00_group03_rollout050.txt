    c = np.correlate(h, v, mode='full')  # length 2n-1

def compute_smooth_grad(h, n, dx, beta):
    """Compute gradient of smooth max of dx*correlate(h, 1-h)"""
    v = 1 - h
    c = np.correlate(h, v, mode='full') * dx  # length 2n-1
    
    # Log-sum-exp
    c_max = np.max(c)
    exp_c = np.exp(beta * (c - c_max))
    logsumexp = c_max + np.log(np.sum(exp_c)) / beta
    p = exp_c / np.sum(exp_c)  # softmax weights
    
    # Gradient
    grad = np.zeros(n)
    for k in range(2*n - 1):
        m = k - (n - 1)  # lag
        lo = max(0, m)
        hi = min(n-1, n-1+m)
        if lo > hi:
            continue
        indices = np.arange(lo, hi + 1)
        grad[indices] += p[k] * (1 - h[indices - m])
        grad[indices - m] -= p[k] * h[indices]
    grad *= dx
    
    return logsumexp, grad

Let me also add a coordinate descent approach for local refinement:
- For each coordinate j, find the optimal h[j] given all other coordinates fixed
- This is a 1D quadratic minimization (since c_k is quadratic in h)
- With the max objective, it's minimizing the max of quadratics, which can be done by bisection on C

Actually, for coordinate descent with the max objective:
Given all h[i] for i ≠ j, we want to find h[j] ∈ [0,1] that minimizes max_k c_k(h)

Each c_k(h) is a quadratic in h[j]:
c_k = A_k * h[j]² + B_k * h[j] + D_k

where the coefficients depend on the other coordinates.

We want min_{h[j]} max_k (A_k * h[j]² + B_k * h[j] + D_k) s.t. 0 ≤ h[j] ≤ 1

This is a 1D problem that can be solved by:
- Binary search on C: find smallest C such that there exists h[j] with all A_k*h[j]² + B_k*h[j] + D_k ≤ C
- The constraint A_k*h[j]² + B_k*h[j] + D_k ≤ C is a quadratic inequality in h[j]
- For each k, the feasible set for h[j] is an interval (or union of intervals)
- The intersection of all feasible intervals is the feasible set for this C
- Bisection finds the smallest C where the intersection is non-empty

This is O(n²) per coordinate (n coordinates, n correlations, O(1) per quadratic). Total O(n³) per full pass. For n=500, that's 125M per pass... might be too slow. Let me only do this for smaller n.

Actually, n correlations × n coordinates = n² pairs, and for each we just evaluate a quadratic. For n=200, that's 40,000 evaluations per pass, which is fine.
