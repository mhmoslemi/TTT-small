def gen_binary_pattern(n, ptype, seed):

One more optimization: for the local search, instead of recomputing the full correlate for each swap, I can compute the change analytically.

When h[i] changes from 1 to 0 and h[j] from 0 to 1:
The correlation at lag k changes by:
- For the "i" position: it was contributing h[i]*(1-h[i-k']) = 1*(1-h[i-k']) = 1-h[i-k'] at lag k' where i is the "source"
  After change: 0*(...) = 0. Change: -(1-h[i-k']) = -1 + h[i-k']
- For the "j" position: it was contributing h[j]*(1-h[j-k']) = 0 at all lags.
  After change: 1*(1-h[j-k']) = 1-h[j-k']. Change: +(1-h[j-k'])

So the total change at lag k' is:
Δ(k') = [1-h[j-k']]*δ_j(k') - [1-h[i-k']]*δ_i(k')

where δ_i(k') is 1 if position i is a valid "source" at lag k' (i.e., i-k' is in [0,n-1]) and 0 otherwise. Similarly for j.

This means for each swap, I need to update O(n) lags (the ones affected by i or j). That's O(n) per swap instead of O(n²). Total per pass: O(n² * n) = O(n³) instead of O(n³) (same asymptotic but better constant).
