        alpha = 20 + 20 * it / n_iters  # increasing sharpness

        G_new = np.fft.fft(C_new)
        F_new = np.sqrt(G_new)  # complex square root
        a_new = np.fft.ifft(F_new).real[:n]
        
        # Enforce non-negativity
        a_new = np.maximum(a_new, 0.0)
        S_new = a_new.sum()
        if S_new < 1e-12:

        a_new = a_new / S_new
        a = a_new
        
        sc = compute_score(a)
        if sc < best_sc:
            best_sc = sc
            best_a = a.copy()
    
    return best_a

4. Use the solution to update a.

With K=100 constraints and n=7000 variables, the LP is small and fast.

But wait, with only K=100 constraints, the LP might be very unbounded (many b_i are unconstrained). I need to ensure that each b_i appears in at least one constraint.

For the top-K constraints at indices k_1, ..., k_K, the constraint k constrains b[m] for m in [max(0, k-n+1), min(k, n-1)] with coefficient a[k-m]. So each constraint constrains at most n variables. With K=100 constraints, we constrain at most 100*n = 700000 (var, constraint) pairs, but each variable b_i is constrained by at most K constraints.

Actually, for the LP to be bounded, each variable b_i needs to appear in at least one constraint with a positive coefficient. This is true if for each i, there exists a k in {k_1, ..., k_K} such that 0 <= k-i < n and a[k-i] > 0. If a is positive everywhere (which it should be after initialization), then for any k, b[k] appears in constraint k (with coefficient a[0] > 0). So as long as we include constraint 0 (or any constraint where a[0] appears), b[0] is constrained. Similarly, constraint n-1 constrains all b_i with coefficient a[n-1-i].

To be safe, let me always include constraints 0, n-1, and 2n-2, plus the top-K-3 other constraints.

Actually, a simpler approach: always include all constraints where C[k] > 0.5*M (i.e., the top 50% or so). This ensures good coverage.
