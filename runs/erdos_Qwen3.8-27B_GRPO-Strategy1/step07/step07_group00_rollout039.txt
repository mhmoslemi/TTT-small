  AND for k in [max(0, p-N+1), p] (as second factor position: m=p, so (1-h[p]) is the factor)
  Wait no: m is the index of (1-h). m=p means (1-h[p]) appears, and the h index is m+k-N+1 = p+k-N+1. Valid when 0≤p+k-N+1≤N-1.
  
  So h[p] (as first factor, i.e., h[m+k-N+1] = h[p]) appears when m+k-N+1=p, m=p-k+N-1, valid for k in [p-N+1, p].
  (1-h[p]) (as second factor, i.e., m=p) appears when 0≤p+k-N+1≤N-1, i.e., k in [N-1-p, 2N-2-p].

So position p affects lags k in [max(0, p-N+1), p] ∪ [N-1-p, 2N-2-p].
This is a set of at most 2N-1 lags (the whole range), but typically about N lags.

For a swap, the union of affected lags for p and q is still O(N).

The delta at each affected lag can be computed in O(1) if I have the current h values.

So the algorithm is:
1. Compute C = correlate(h, 1-h, 'full') [O(N log N) via FFT]
2. Generate candidate swaps (p, q)
3. For each candidate, compute delta[k] for affected k's [O(N) per candidate]
4. Find the candidate that minimizes max(C + delta)
5. Apply the best swap

Step 4 is the bottleneck. For a candidate (p,q), the new max is max over all k of C[k] + delta[k]. Since delta is zero for most k, the new max is at most max(max(C[k] for unaffected k), max(C[k]+delta[k] for affected k)).

The "unaffected" max can be precomputed (it's the max of C excluding the O(N) affected positions). Actually, it's simpler: the new max = max(max_unaffected, max_affected_new) where:
- max_unaffected = max(C[k] for k not in affected set)
- max_affected_new = max(C[k] + delta[k] for k in affected set)

The affected set changes per candidate, so this isn't trivially precomputable. But if the affected set is small (O(N) out of 2N-1), we can just compute it directly.

For N=380, the affected set has at most ~760 lags (out of 759 total). So basically all lags are affected. This means we can't shortcut the max computation.

Alternative: just compute C[k] + delta[k] for all k (or just the affected ones, which is most of them) and take the max. This is O(N) per candidate. With maybe 100 candidates, that's O(N*100) = O(38000) per SA step. That's fine.

OK let me design the improved algorithm:

1. **Start from initial_h_values** (380 points), make binary.
2. **Phase 1: Gradient-based continuous optimization** using a smoothed max objective.
3. **Phase 2: Binary local search** with smart move generation (peak-targeted + random).
4. **Phase 3: Multi-resolution exploration** (downsample, optimize, upsample).
5. **Phase 4: Fine-tuning** with very targeted moves.

- Use the CORRECT correlation (np.correlate) for evaluation
- Better continuous optimization (log-sum-exp smoothing of the max)

import numpy as np
import time

def fft_corr(h):
    """Compute correlation using FFT. Returns same max as np.correlate(h, 1-h, 'full')."""
    N = len(h)
    L = 2 * N - 1
    H = np.fft.rfft(h, L)
    G = np.fft.rfft(np.flip(1.0 - h), L)
    return np.real(np.fft.irfft(H * G, L))

def compute_c5(h, N):
    """Compute C5 using the standard definition."""
    c = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(c)) * (2.0 / N)

def make_binary(h, N):
    h = h.astype(float).copy()
    n1 = int(np.round(h.sum()))
    target = N // 2
    if n1 > target:
        # Remove random excess ones
        ones = np.where(h > 0.5)[0]
        if len(ones) >= n1 - target:
            h[np.random.choice(ones, n1 - target, replace=False)] = 0
    elif n1 < target:
        zeros = np.where(h < 0.5)[0]
        if len(zeros) >= target - n1:
            h[np.random.choice(zeros, target - n1, replace=False)] = 1
    # Sort by value to make clean binary
    h[h > 0.5] = 1.0
    h[h <= 0.5] = 0.0
    # Fix count
    n1 = int(h.sum())
    if n1 > target:
        idx = np.where(h == 1)[0]
        for i in np.random.choice(idx, n1 - target, replace=False):
            h[i] = 0
    elif n1 < target:
        idx = np.where(h == 0)[0]
        for i in np.random.choice(idx, target - n1, replace=False):
            h[i] = 1
    return h
