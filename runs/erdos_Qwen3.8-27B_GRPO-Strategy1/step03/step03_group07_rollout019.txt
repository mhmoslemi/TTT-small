```python
    corr = np.correlate(h, 1.0 - h, mode='full')

    top_corr = corr[top_idx]
    m = np.max(top_corr)
    val = m + np.log(np.sum(np.exp(T * (top_corr - m)))) / T
    return val * dx

            return smooth_max_top(h, T, K)
        else:
            return smooth_max_all(h, T)

                   maxiter=maxiter, options={'ftol': ftol, 'gtol': 1e-10})
```

Let me check for potential issues:
1. The `smooth_grad_vec` function has a Python loop over lags (up to 399 for n=200). Each iteration does a few numpy slice operations. This should be fast enough.
2. The `lbfgs_step` function uses L-BFGS-B with bounds, which handles the 0≤h≤1 constraint.
3. The sum constraint is handled by `make_feasible` after optimization. This is a soft constraint - L-BFGS-B doesn't enforce it during optimization. This could be a problem.

Actually, this is a significant issue. L-BFGS-B only enforces box constraints (0≤h≤1), not the linear sum constraint. The optimization might drift away from sum(h) = n/2 during the process, and only at the end do we project back. This could lead to suboptimal solutions.

Options:
1. Add a penalty term to the objective: + λ * (sum(h) - n/2)²
2. Use a parameterization that automatically satisfies the constraint
3. Use SLSQP which can handle linear constraints (but it's slow)
4. Use a projected gradient method

Let me go with option 1 (penalty) since it's simple and works well with L-BFGS-B:

```python
def obj_penalized(x, T, K, n, lam):
    h = np.clip(x, 0, 1)
    base = smooth_obj_vec(h, T, K)
    pen = lam * (h.sum() - n / 2.0) ** 2
    return base + pen

def grad_penalized(x, T, K, n, lam):

    base_g = smooth_grad_vec(h, T, K)
    pen_g = 2 * lam * (h.sum() - n / 2.0) * np.ones(n)
    return base_g + pen_g
```

With a large enough λ (like 100 or 1000), the penalty will keep the sum close to n/2.

Actually, let me think about this more carefully. If I use a penalty, the optimizer will try to minimize both the smooth max and the penalty. At the optimum, the gradient of the penalty will be 2*λ*(sum-n/2)*1, which for the constraint to be satisfied needs sum ≈ n/2. With λ=1000, the constraint will be satisfied to within about 1/sqrt(1000) ≈ 0.03 in the sum, which is about 0.00015 per element. That might not be tight enough.

Better approach: After each L-BFGS-B call, project to the feasible set. The projection is cheap (clip + rescale). The issue is that during the optimization, the sum might drift, but if we're minimizing a smooth function and the projection is close, the final result should be fine.

```python
    n = len(h)

    return float(np.max(corr) * dx)

def make_feasible(h, n):
    h = np.clip(h, 0.0, 1.0).astype(float).copy()
    target = n / 2.0
    diff = target - h.sum()
    if abs(diff) < 1e-15:
        return h
    if diff > 0:
        room = 1.0 - h
        t = room.sum()
        if t > 1e-15:
            h += room * (diff / t)
    else:
        t = h.sum()
        if t > 1e-15:
            h += h * (diff / t)
    return np.clip(h, 0.0, 1.0)

def smooth_obj_vec(h, T, K, n):
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    if K > 0 and K < len(corr):
        idx = np.argpartition(corr, -K)[-K:]
        cs = corr[idx]

    val = m + np.log(np.sum(np.exp(T * (cs - m)))) / T
```
