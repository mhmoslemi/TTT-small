```python
    grad = np.zeros(n)
    for k in range(-(n-1), n):
        if p[k + n - 1] < 1e-15:
            continue
        pk = p[k + n - 1]
        if k >= 0:
            grad[k:] += pk * v[:n-k]
            grad[:n-k] -= pk * h[k:]
        else:
            grad[:n+k] += pk * v[-k:]
            grad[-k:] -= pk * h[:n+k]
    
    return grad * (dx / temp)
```

Wait, this is O(n^2) due to the loop over k. For n=360, that's 719 iterations, each with O(n) vector ops. Total ~250K ops. That's fast!

Actually, I realize I can do this more efficiently with convolutions, but for n=360-720, the loop approach is fine (719 * 720 ≈ 500K ops per gradient call).

Let me now design the full algorithm:

1. Use the analytical gradient of the smooth max
2. Use L-BFGS-B with the provided gradient (much faster than numerical!)
3. This should allow many more iterations in the same time

With analytical gradient, each function + gradient evaluation is:
- One np.correlate: O(n^2)
- One loop of n iterations with O(n) ops each: O(n^2)
Total: ~2*n^2 ≈ 500K for n=360, ~2M for n=720.

L-BFGS-B typically does about 2-3 function evals per iteration (one for function, one for possible gradient). So per iteration: ~2 * 2 * n^2 = 4n^2 ≈ 1M for n=360, ~4M for n=720.

At numpy speed (~100M simple ops/sec for these patterns), that's ~10ms per iteration for n=360, ~40ms for n=720.

So I can do:
- n=360: 10000 iterations in ~100s
- n=720: 5000 iterations in ~200s

This is much more than the previous code's 200-300 iterations! The key improvement is the analytical gradient.

    n = len(h)
    dx = 2.0 / n

    return float(np.max(corr) * dx)

def smooth_value(h, temp):
    n = len(h)
    dx = 2.0 / n
    v = 1.0 - h
    corr = np.correlate(h, v, mode='full')
    cmax = np.max(corr)

def smooth_grad(h, temp):
