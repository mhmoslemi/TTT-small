import numpy as np

def compute_c5(h):
    n = len(h)
    dx = 2.0 / n
    corr = np.correlate(h, 1.0 - h, mode='full')
    return float(np.max(corr) * dx)

def upsample(h, n_new):
    n_old = len(h)
    if n_new == n_old:
        return h.copy()
    factor = max(1, n_new // n_old)
    out = np.repeat(h, factor)[:n_new]
    return out

def ensure_bin(h, n):
    h = (h > 0.5).astype(float)
    target = n // 2
    s = int(h.sum())
    if s > target:
        idx = np.where(h == 1)[0]
        rng_sh = np.random.permutation(len(idx))
        h[idx[rng_sh[:s-target]]] = 0.0
    elif s < target:
        idx = np.where(h == 0)[0]
        rng_sh = np.random.permutation(len(idx))
        h[idx[rng_sh[:target-s]]] = 1.0
    return h

def ls(h, tlim, seed, target_frac=0.5):
    rng = np.random.RandomState(seed)
    n = len(h)
    h = ensure_bin(h.copy(), n)
    best = compute_c5(h)
    t_start = time.time()
    
    while time.time() - t_start < tlim:
        if rng.random() < target_frac:
            # Target peak lag
            corr = np.correlate(h, 1.0-h, mode='full')
            pi = int(np.argmax(corr))

Actually, one important optimization: instead of recomputing the full correlation each time, I can compute the change in correlation for a specific swap. This saves the O(n^2) computation.

When I swap h[i] (from 1 to 0) and h[j] (from 0 to 1):
- The change in corr at lag k is:
  Δcorr[k] = (new contribution at i) - (old contribution at i) + (new contribution at j) - (old contribution at j)
  
  Old contribution at position m to corr[k]: h[m] * (1-h[m-k]) [if m and m-k are valid]
  
  For position i (1→0):
  - As h[i]: old = 1*(1-h[i-k]) = 1-h[i-k], new = 0 → change = -(1-h[i-k])
  - As h[m-k] where m=i+k: old = h[i+k]*(1-1) = 0, new = h[i+k]*(1-0) = h[i+k] → change = +h[i+k]
  
  For position j (0→1):
  - As h[j]: old = 0*(1-h[j-k]) = 0, new = 1*(1-h[j-k]) = 1-h[j-k] → change = +(1-h[j-k])
  - As h[m-k] where m=j+k: old = h[j+k]*(1-0) = h[j+k], new = h[j+k]*(1-1) = 0 → change = -h[j+k]

So Δcorr[k] = -(1-h[i-k]) + h[i+k] + (1-h[j-k]) - h[j+k]
             = h[i-k] - 1 + h[i+k] + 1 - h[j-k] - h[j+k]
             = h[i-k] + h[i+k] - h[j-k] - h[j+k]

(Where terms with out-of-bounds indices are 0.)

This is O(1) per lag! So I can compute the new max in O(n) instead of O(n^2).

But I still need to track all corr[k] values. Let me maintain the corr array and update it incrementally:
- When swapping i and j: for each k, corr[k] += Δcorr[k]
- This is O(n) per swap (since there are 2n-1 lags)

But computing Δcorr[k] for each k is O(1) (just looking up h[i-k], h[i+k], h[j-k], h[j+k]). So the total per swap is O(n) for updating all lags + O(n) for finding the max = O(n).

This is a 2n-1 fold speedup over recomputing from scratch (O(n^2))!
