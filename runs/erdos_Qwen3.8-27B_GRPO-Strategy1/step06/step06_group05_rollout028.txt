Wait, the D matrix update is problematic. When I change h[p] and h[q], the values D[other, k] also change because they depend on h[other±s_k], and if s_k happens to reach p or q, the value changes.

Actually, let me just recompute D every swap. It's simpler and the overhead is manageable.

Let me also reconsider the D matrix semantics:
D[i, k] = ∂c_k / ∂h[i] (the derivative of the k-th correlation value w.r.t. h[i])

For binary h, changing h[i] from 1 to 0 changes c_k by -D[i, k] (approximately, since the change is -1 in h[i]).
Changing h[i] from 0 to 1 changes c_k by +D[i, k] (approximately).

Wait, for binary: if h[i] goes from 1 to 0, the change in c_k is:
New c_k - Old c_k = D[i,k] * (0-1) = -D[i,k]

If h[i] goes from 0 to 1: D[i,k] * (1-0) = D[i,k]

For a swap p→q (h[p]: 1→0, h[q]: 0→1):
New c_k = Old c_k - D[p,k] + D[q,k]

But wait, this isn't exactly right because D depends on h, and changing h[p] and h[q] also affects D for other positions. However, if we compute D based on the current h (before the swap), then:
- The change due to h[p] going 1→0: -D[p,k] (this is exact if D is computed with h[p]=1)
- The change due to h[q] going 0→1: +D[q,k] (this is exact if D is computed with h[q]=0)
- Cross terms: the effect of h[p] and h[q] on each other's D values

Actually for the correlation c_k = Σ_j h[j](1-h[j+s_k]):
∂c_k/∂h[i] = (1-h[i+s_k])*[valid] - h[i-s_k]*[valid]

If we change h[p] by δp and h[q] by δq:
Δc_k ≈ D[p,k]*δp + D[q,k]*δq + (second order terms)

For binary (δp=-1, δq=+1):
Δc_k = -D[p,k] + D[q,k] + (correction)

The correction is: if s_k = q-p (i.e., p+s_k = q), then there's an interaction term h[p]*h[q] that appears/disappears. Specifically:
c_k includes the term h[p]*(1-h[q]) when p+s_k = q.
If h[p]: 1→0, h[q]: 0→1: this term goes from 1*(1-0)=1 to 0*(1-1)=0, change = -1.
But D[p,k] with h[p]=1, h[q]=0 includes (1-h[q]) = 1 in the contribution, so -D[p,k] correctly accounts for this.
And D[q,k] with h[q]=0 includes -h[p] = -1 in the contribution, so +D[q,k] adds -1.
Total from these: -1 + (-1) = -2? That doesn't seem right.

Let me be more careful. c_k = Σ_j h[j](1-h[j+s_k])

The term involving both h[p] and h[q]:
- If p + s_k = q: term is h[p](1-h[q]). Change: was 1*(1-0)=1, now 0*(1-1)=0. Δ = -1.
- If q + s_k = p: term is h[q](1-h[p]). Change: was 0*(1-1)=0, now 1*(1-0)=1. Δ = +1.

Now D[p,k] = (1-h[p+s_k])*[valid] - h[p-s_k]*[valid]
  = (1-h[q])*[p+s_k=q valid] - h[p-s_k]*[valid]
  With h[q]=0: (1-0) - h[p-s_k]*[valid] = 1 - h[p-s_k]*[valid]

D[q,k] = (1-h[q+s_k])*[valid] - h[q-s_k]*[valid]
  = (1-h[q+s_k])*[valid] - h[p]*[q-s_k=p valid]
  With h[p]=1: (1-h[q+s_k])*[valid] - 1*[q-s_k=p valid]

-D[p,k] + D[q,k] = -(1 - h[p-s_k]*[valid]) + (1-h[q+s_k])*[valid] - 1*[q-s_k=p valid]

The actual Δc_k includes ALL terms, not just the p,q interaction. The linear approximation -D[p,k]+D[q,k] is correct for the first-order change, and for binary (unit changes), the only second-order term is the direct interaction between p and q in the product h[j]h[j+s_k].

Specifically: c_k = Σ_j h[j] - Σ_j h[j]h[j+s_k]
The linear part: Σ_j h[j] (sum changes by -1+1=0, so no net change)
The quadratic part: Σ_j h[j]h[j+s_k]
  - Term j=p: h[p]h[p+s_k] = h[p]h[q] (if p+s_k=q): was 1*0=0, now 0*1=0. Δ=0.
  - Term j=q: h[q]h[q+s_k] (if q+s_k=p): was 0*1=0, now 1*0=0. Δ=0.
  - Other terms: h[j]h[j+s_k] only changes if j=p or j+s_k=p (i.e., j=p-s_k) or j=q or j+s_k=q.
    - j=p-s_k: h[p-s_k]*h[p]: was h[p-s_k]*1, now h[p-s_k]*0. Δ = -h[p-s_k].
    - j=s_k's where j+s_k=q, i.e., j=q-s_k=p: h[p]*h[q]: already counted.
    - j=q: h[q]*h[q+s_k]: was 0*h[q+s_k], now 1*h[q+s_k]. Δ = h[q+s_k].
    - j+s_k=p, i.e., j=p-s_k: h[p-s_k]*h[p]: counted above.

So the total change in Σ_j h[j]h[j+s_k] is:
-h[p-s_k] + h[q+s_k] (from the "neighbor" terms)
(assuming p≠q±s_k, which is true for distinct p,q unless s_k=±(q-p))

And -D[p,k] + D[q,k] gives:
-(1-h[p+s_k]) + h[p-s_k] + (1-h[q+s_k]) - h[q-s_k]
= -1 + h[p+s_k] + h[p-s_k] + 1 - h[q+s_k] - h[q-s_k]
= h[p+s_k] + h[p-s_k] - h[q+s_k] - h[q-s_k]

The actual Δ(Σ h[j]h[j+s_k]) = -h[p-s_k] + h[q+s_k] (as computed above, ignoring the p↔q direct interaction which is 0 for the specific case)

So the discrepancy is:
(-D[p,k] + D[q,k]) - Δ = h[p+s_k] + h[p-s_k] - h[q+s_k] - h[q-s_k] - (-h[p-s_k] + h[q+s_k])
= h[p+s_k] + 2h[p-s_k] - 2h[q+s_k] - h[q-s_k]

This is NOT zero in general! So the linear approximation is not exact for the quadratic part.

However, for the purpose of the greedy swap, what matters is which swap gives the lowest maximum. The linear approximation is a good guide, and we can verify the actual change after making the swap.

        h_bt = to_binary(h_interp, N_try)
        sub_dl = min(deadline - 15, time.time() + 35)
        h_rt, c5_rt = bin_search(h_bt, N_try, sub_dl, max_sweeps=300, anneal=0.03)
        if c5_rt < best_c5:
            best_c5, best_h = c5_rt, h_rt.copy()
            x_best = np.linspace(0, 2, N_try, endpoint=False)

    # Phase 7: Final polish - short binary + ls
    NT = len(best_h)
    if time.time() < deadline - 10:
        d7 = min(deadline - 5, time.time() + 40)
        h_b7 = to_binary(best_h, NT)
        h_f, c5_f = bin_search(h_b7, NT, d7, max_sweeps=300, anneal=0.02)
        if c5_f < best_c5:
            best_c5, best_h = c5_f, h_f.copy()

    # Final binary cleanup
    if time.time() < deadline - 1:
        hF = to_binary(best_h, len(best_h))
        hF, c5F = bin_search(hF, len(best_h), deadline - 0.5, max_sweeps=40, anneal=0.0)
        final_c5 = compute_c5(hF, len(best_h))
        if final_c5 < best_c5:
            best_c5, best_h = final_c5, hF
    else:
        final_c5 = compute_c5(best_h, len(best_h))

    return best_h, final_c5, len(best_h)
