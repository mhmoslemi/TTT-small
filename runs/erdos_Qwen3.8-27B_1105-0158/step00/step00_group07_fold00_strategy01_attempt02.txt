It performs a targeted local improvement of the exact discrete objective, while treating every candidate with the evaluator’s original metric. The main scientific difference from a plain soft-max minimization is that the finite maximization is written as an explicit hypograph problem:

    minimize z
    subject to 0 <= h_i <= 1,
               sum_i h_i = n/2,
               dx * (np.correlate(h, 1-h, "full"))_j <= z for every lag j.

The exact shifted overlap terms have known finite-support pairwise structure and explicit finite derivatives. The algorithm solves a sequence of these nonconvex constrained local programs, mostly with active or near-active constraints, by sequential quadratic programming (`scipy.optimize.minimize(..., method="SLSQP")`). Every `h` produced by a subproblem is then repaired to the exact box and area constraints and scored with `dx * max(correlate(h, 1-h, "full"))`. The exact score is the only quantity used for acceptance. Thus the optimization heuristic may be nonconvex, but no candidate is ever accepted on a surrogate or relaxed score.

Why this can help:
- The objective is nonsmooth because it is the maximum of many shifted overlap sums. A smoothed mean or normal soft-max may waste effort on relaxed lags. The active hypograph formulation focuses computational attention on the constraints that determine the literal `max`.
- The exact boundary terms of linear correlation are retained. The algorithm never replaces the objective by a circular autocorrelation or by a global `1 - min autocorrelation` proxy.
- Resolution transfer is done as average densities over intervals, preserving the integral. This allows the search to explore different finite discretizations without hard-coding endless arrays.
- Robust fallbacks are retained, so failure of nonconvex solvers still returns the best verified vector, including the supplied parent if it is feasible.

Justified facts:
- The evaluator is explicitly `dx * max(np.correlate(h, 1-h, mode="full"))`, with `dx = 2.0/n`.
- The sum of any feasible candidate must be exactly or nominally `n/2` because the density total is `1`.
- The raw overlap for each lag is determined by nonnegative shifted pairs `(h_i, 1-h_j)`; finite changing direction and boundary overhang is fully included in the correlation vector.
- Local methods do not guarantee global optimality, and this plan does not claim it. Any returned number is a valid upper bound only if the returned vector satisfies the constraints and the uniform score is recomputed from that exact vector.

2. Mathematical specification

Let alternating `n = n_points`, `L = n - 1`, and `dx = 2.0 / n`. The target-area is `T = n / 2`, because `sum_i h_i dx = 1`.

For any vector `h` of length `n`, the exact array scored by the test compiler is defined by the evaluator operation:

    R(h) = np.correlate(h, 1-h, mode="full"), length 2*n-1.

The returned objective is:

    C(h) = dx * max_j R(h)[j].

The discrete pair interpretation of this operation is derived from `correlate = convolve(a, reversed(b))`. For output index `j = 0, ..., 2*n-2`, define

    delta_j = L - j, where delta_j in {-(n-1), ..., n-1}.

If `delta >= 0`, the correlation output is

    R_j(h) = sum_{i=0}^{n-delta-1} h_i * (1 - h_{i+delta}).

If `delta = -e < 0`, the output is

    R_j(h) = sum_{i=0}^{n-e-1} h_{i+e} * (1 - h_i).

This laminar indexing proves that zero, positive-shift, negative-shift, and boundary reversed lag terms are included exactly as in NumPy. The maximum is over the full vector; it does not mean circular autocorrelation.

2.1 Candidate constraints and decision vector

For solver subproblems, collect

    x[i] = h_i for i=0,...,n-1,
    x[n] = z.

The bounds are

    0 <= x[i] <= 1 for i < n,
    -barrier_z_min <= z, with `z_min = 0` effectively enough since true overlaps are nonnegative. Box upper bounds are not resting sum pressure but should be larger than current parent bound; default `0 <= z <= 2.0` provides slack.

The linear constraint is

    g(x) = sum_{i=0}^{n-1} x[i] - T = 0.

For various active lag indices `j`, each explicit nonlinear inequality is

    c_j(h,z) = z - dx * R_j(h) >= 0.

The solver minimizes

    f(x) = z + small_penalty * (sum_i h_i - T)^2,

where initially choose `small_penalty = 1e-6`; then enforce area twice at the outcome. The penalty is not in the final metric and prevents failure if sum constraint tolerance drifts. If needed, restore sum exactly via solver. The descent rotates around the current point using exact gradients provided. Budget equality with bound allowed small drift for SLSQP but job track retain returning repaired lean or abort in failure.
