1. Approach and rationale

1.1 Central idea

The core problem is the discrete minimax problem

$$
\min_{0\le h_i\le 1,\ \sum_i h_i=n/2}
\ C(h)=\max_m \mathrm{correlate}(h,1-h)_m\,\frac{2}{n}.
$$

The evaluator is literal: all `2n-1` correlation lags, both directions, finite overlap weights, and the final maximum. It is not circular correlation and not a one-sided autocorrelation minimum.

The plan improves the parent construction by combining two empirically strong, implementation-friendly mechanisms and then finally checking every candidate only with the exact evaluator:

1. A differentiable soft-max homotopy on the full vector of correlation lag values. This provides well-defined gradients for a nonsmooth max-min objective and can move the optimization away from the parent local point after a perturbation or resampled initialization.
2. An exact validation followed by a linearized minimax direction step. Around a candidate, each correlation lag is linearized, and a trust-region linear programme minimizes the maximum predicted lag. The proposed direction is retained only if the exact discrete objective improves. This directly attacks the max structure and can make very small adjustments that enable crossing a barrier near the current 0.38085 level.

The approach deliberately does not assert global optimality, convexity, or global convergence. Products `h_i(1-h_j)` make the exact objective nonconvex and nonsmooth. The method is a search heuristic with exact validation. Its purpose is to make repeated high-precision local refinements from many nearby feasible points.

1.2 Why this is materially different from a generic optimizer

A simple direct nonlinear optimization of a scalar epigraph variable or a plain SLSQP run can stagnate because of the nonsmooth maximum and because active max constraints can switch during the trajectory. The plan does two things to prevent that:

- The smooth objective forces nearby near-maximal lags to be treated jointly, while the final exact step is driven by the real maximum vector. It also uses a global-like multi-start/resolution search.
- The local trust-region linear minimax direction does not wait for a penalty objective to discover the active lag structure. It explicitly builds a linear approximation of all lag values and determines a direction that would decrease the overall first-order upper model. Any improvement is accepted only if the true correlation evaluator improves. Thus it is a high-precision local minimax step, not a generic minimizer.

1.3 Main limitations and honest assumptions

- The local linearization is a first-order model of nonlinear functions; it can suggest a step that improves the model but not the exact maximum. Therefore every direction is accepted only after an exact reevaluation.
- The LSE objective is a smooth overestimate of the maximum correlation, not necessarilyูง the exact best direction.
- Symmetrization is a useful low-dimensional exposure but is not known to never worsen the objective. A symmetrized parent is included only after exact evaluation, or its optimizer is accepted only if the resulting vector has a good exact value.
- Higher grid resolutions can change the discrete objective because they alter the available step function and overlap coverage. Testing sizes derived from the parent is therefore part of the search, not a mathematical equivalence transformation.

2. Mathematical specification

2.1 Notation and discrete correlation matching the evaluator

For a vector `h ∈ R^n`:

- `dx = 2.0 / n`
- The exact evaluator is:
  `exact_aval = dx * max(np.correlate(h, 1.0-h, mode="full"))`
- The constraint is:
  `h_i ∈ [0,1]` and `sum(h_i)=n/2`.

Define a signed lag indexed representation. For integer lag `k ∈ {1-n,...,n-1}`, define

$$
R_k(h)=\sum_i h_i(1-h_{i+k}),
$$

where the sum only has `i` satisfying `0 ≤ i < n` and `0 ≤ i+k < n`. If `i+k` is outside `[0,n-1]`, the pair is absent. For different uncrossed bounds, only existing pairs are counted; this automatically accounts for boundary truncation.

Let `R(h)` be a vector of these values for all signed lags. For the optimization we only need the multiset of all lag values because all of them are included in the maximum and in the LSE smoothing. Therefore it does not matter whether the evaluator’s full ordering differs from the manual signed ordering by a permutation, provided the manual formula enumerates all pairs and only finitely. Implementation must nevertheless perform a runtime validation against `np.correlate`; the exact output always uses `np.correlate` to avoid indexing-substitution errors.

For the zero lag:

$$
R_0(h)=\sum_i h_i(1-h_i)=n/2-\sum_i h_i^2.
$$

For a nonzero lag with terms `i, i+k`, term-by-term correction is important: first and second factors are not separately full because on the boundaries the number of overlapping pairs is `n-|k|`.

2.2 Exact constraints and feasibility

The feasible set is the intersection of two simple constraints:

- box: `0 <= h <= 1`
- equality affine mass: `dot(ones,h)=n/2` for unsym, `dot(W,y)=n/2` for sym.

Here `W` is a symmetric mass weight vector; for symmetric coordinates if `n` is even `W = 2*ones(n/2)`, if odd `W=[2,...,2,1]`. The symmetry is optional and operationally applied only as a lower-dimensional start/sanitized test.

2.3 Gradient of a user-defined full-ration correlation

For each signed correlation value `R_k(h)`, a direct term-by-term gradient is:

For existing pair `(i, j=i+k)`,

- derivative from `h_i` in the first factor: contributor to coordinate `i`: `1 - h_j`
- derivative from coordinate `j` in the second factor: contributor to coordinate `j`: `-h_i`

For `k=0`, both contributions affect the same coordinate and sum to `1-2h_i`.

This yields a dense or manageable sparse gradient array `D[k,i]`. Use it for the smooth maxim cost. When using symmetric coordinates, the transform step is linear: expanded `h` = `E y` where each interior variable appears twice. Consequently, the gradient in the symmetric variable space is `g_y = E^T g_h` (off-center variables receive the sum of the two matching lag-row entries, center receives its own entry). The gradient objective multiplies by `dx` if the LSE is scaled by dx; keep this multiplier consistent.

2.4 soft-max surrogate
