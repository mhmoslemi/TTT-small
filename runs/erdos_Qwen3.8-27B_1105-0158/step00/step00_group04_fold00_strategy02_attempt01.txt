1. Approach and rationale

1.1 Central idea

The supplied evaluator is authoritative:
```
C(h) = max_k (np.correlate(h, 1-h, mode="full"))_k * (2.0 / n)
```
where `h` is a finite one-dimensional array, `0 <= h_i <= 1`, and `sum_i h_i = n/2` to the required tolerance. No surrogate, cyclic correlation, minimum autocorrelation, smoothing weighted integral, or convex relaxation can replace this final score. All acceptance decisions must be made after a candidate has been forced to satisfy the box-and-sum constraints and then rescored with the exact evaluator above.

The proposed algorithm searches directly in the original nonsmooth objective. It decomposes the 70-dimensional feasible box-simplex path into one-dimensional feasible lines of two main types:

- Coordinate transfer lines `e_a - e_b`: move mass from coordinate `b` to coordinate `a` or vice versa. This is feasible by construction and preserves the total sum to machine precision before rounding correction.
- Random feasible nullspace lines: directions with components summing to zero. Bounds translate into an interval in the path parameter `t` that keeps all samples within `[0,1]`.

On any such line, every full-length `np.correlate` output is a quadratic polynomial in `t`, because each output is a sum of terms `(h_i + t d_i)(1 - h_j - t d_j)`. Thus every line can be investigated by extracting algebraic quadratic approximately from three surrogate evaluations outside the feasible box, then finding a candidate line minimum by a nonsmooth one-dimensional solver. A line update is accepted only if the actual evaluator on the repaired feasible candidate is lower.

The method is called exact nonsmooth line-transfer descent. It is not a global optimizer, and it does not claim to certify global optimality. It is designed to move from a high-quality parent in a very small nonsmooth plateau, because it avoids the common failure modes of penalty and epigraph smoothing: hidden active-lag mismatch, infeasible epigraph steps, and smoothing-only candidates whose exact maximum is unchanged.

There is a second major improvement: changing the discretization resolution can move the exact evaluator due to boundary terms and quantization changes. Therefore the algorithm transfers the parent (or the current best) to several derived resolutions, restores the box-simplex feasibility exactly, and re-evaluates. Often a finer or slightly smaller discretization permits a strict improvement that a pure fixed-resolution search cannot easily find. The final returned candidate is any valid size that gives the best exact score, with smaller sizes preferred in near-ties.

1.2 Motivation for improving the current parent

The current parent is already close to the target. A fixed-resolution gradient or log-sum-exp method tends to move active-lag penalties in a monotone but overly averaged subspace. Around a minimax optimum, several correlation lags are close to the active maximum. Small two-coordinate or random-direction transfers have a better chance to reduce the peak lag without accidentally increasing a nearby lag, because the final step is accepted by the exact full-lag evaluator.

The central bottleneck is not the construction of the feasible vector but the nonsimitedness of the objective peak. The algorithm addresses that by:

- exact objective vectors on each candidate;
- coordinate directions that locally expose a single-lag peak structure;
- line polynomial coefficients that can form union-like improvements not available from one-visible pairwise-step evaluation;
- cheap feasibility formulas with accurate low-dimensional sum enhancement after line update;
- size-transfer restarts to traverse the evaluator's discrete boundary structure;
- broad fallback pool, retaining at least the parent.

1.3 Justified facts and hypotheses

Mathematical facts used:

- A pairwise or constant-sum linear move preserves `sum h_i` mathematically.
- A full support linear correlation output restricted to a straight affine line in the variable vector is a quadratic polynomial in the line parameter.
- Linear interpolation and exact summation carry the parent vector to another feasible discrete vector after projection, and the resulting vector is scored using the same evaluator.
- `mode="full"` gives all finite-support lags from negative to positive; no missing boundary terms.
- No convexity of the complete problem is claimed or used.

Engineering hypotheses under test:

- Search across nearest neighbor resolutions can find a score below `0.3808`.
- Coordinate and random directions can reduce active-lag values within budget.
- Size transfer seeded by the parent remains feasible enough to be locally improved.

If those hypotheses fail, the algorithm retains the best feasible solution and returns the parent fallback if the parent is valid.

2.2 Objective vector and line behavior

Define the evaluator output vector:
```
F(h) = dx * np.correlate(h, 1 - h, mode="full")
C(h) = max(F(h))
```
Each output component `F_k` is a sum over suitable indices of `(h_i + t d_i) * (1 - h_j - t d_j)`. Therefore, for a fixed direction `d` with `sum_i d_i = 0` and fixed base `h`, there exist coefficient arrays `A, B, Q` (each length `2n-1`) such that:
```
F_k(t) = A_k + B_k t + Q_k t^2
```
All three coefficient sets are directly extracted from the evaluator at levels `t=0,1,2`:
```
F0 = F(h)
F1 = F(h + d)       // physically invalid values are acceptable here
F2 = F(h + 2*d)
A  = F0
Q  = 0.5 * (F2 - 2.0*F1 + F0)
B  = F1 - F0 - Q
```
The polynomial relation is only an algebraic extraction; it is not used to bypass the feasible constraints. After a reported `t` is found and capitalization if needed, one constructs `h(t)`, clips only numerical roundoff, enforces the exact sum, and uses actual `F(h(t))` for acceptance and recording.

2.3 Feasible line-length intervals

For a general direction `d` with the preserved direction:
```
h_i(t) = h_i + t * d_i
0 <= h_i + t*d_i <= 1
```
At `t=0`, the vector is feasible. The interval is constructed component-wise:

For positive direction component `d_i > eps`:
```
lower_bound = -h_i / d_i
upper_bound = (1.0 - h_i) / d_i
```
For negative direction component `d_i < -eps`:
```
lower_bound = (1.0 - h_i) / d_i
upper_bound = -h_i / d_i
```
For negligible components ignore the constraint. Then:
```
L = max_i lower_i
U = min_i upper_i
```
Since h is feasible, 0 should be inside `[L,U]`. If `U-L < line_dMU`, skip the direction.

For pairwise unsigned-direction vector `d` defined by:

```
d_b = -1

```

Interpreting `t>0` gives transfer `b -> a`; interpret `t<0` gives `a -> b`. The line includes all directions of mass movement between the two samples.
