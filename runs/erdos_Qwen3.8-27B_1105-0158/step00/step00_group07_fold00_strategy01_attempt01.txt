1. Approach and rationale

Central idea: replace the nonsmooth max-over-lags minimization by a smooth constrained epigraph problem and polish it with a derivative-based local nonlinear programming method, scoring every candidate using the original discrete evaluator. The supplied parent at `n=95` is already close to the record, so the most useful mathematical objective is a strong local polishing scheme that does not replace the evaluator by a surrogate. The primary method therefore keeps all shifted overlap constraints, the original box constraints, and the exact discrete-area constraint.

The previous proposal family suggested in the task used a log-sum-exp surrogate and/or global smooth descent over a penalized maximum. The plan below is materially different because it does not replace the maximum by a smooth approximation for optimization. It introduces an auxiliary variable and solves the smooth epigraph system

    minimize t
    subject to dx * np.correlate(h, 1-h, full)_j - t <= 0 for every lag j
               0 <= h_i <= 1
               sum_i h_i = n/2.

This formulation includes the finite-support shifted boundary terms exactly as evaluated by `np.correlate(..., mode="full")`; it does not use autocorrelation-only reductions or circular assumptions. It permits the optimizer to pay attention to whichever shifted lags are active through smooth inequality constraints. The original nonsmooth objective is recovered by re-evaluating the returned vector with the exact evaluator.

The algorithm will improve or at least retain the parent by:
- validating and repairing the supplied parent,
- solving local epigraph nonlinear programs from the parent and current best,
- generating small structured and noisy escapes that preserve feasibility,
- comparing adjacent resolutions using exact integration-based transfers,
- rejecting any candidate whose exact score or constraints fail,
- returning the best exact solution found before the deadline.

Important limitation: the epigraph feasible set is not globally convex because the correlation constraints include shifted bilinear terms, including the zero-lag quadratic term. Therefore the nonlinear-program stage is a local KKT payoff service, and local minima of the exact nonsmooth objective are possible. No global optimality is claimed. The expected benefit is that the parent is close to optimal and the epigraph NLP can exploit second-order structure around the active shifted constraints better than a smoothed maximum method. This is a tested-style hypothesis for noisy small-margin polishing, not a theorem.

2. Mathematical specification

2.1 Representation and exact objective

Let `n = len(h)`, `dx = 2.0 / n`, and `T = n / 2`. The continuous step interpretation is not used in scoring. The scoring vector is

    C(h) = dx * max_j r_j(h)

where `r_j(h)` are all values returned by exact

    np.correlate(h, 1 - h, mode="full")

for all `2*n - 1` lags. This includes both lag signs and finite-support boundary effects. The area constraint is

    sum_i h_i = T
    0 <= h_i <= 1.

The returned `c5_bound` is the exact value `C(h_final)` after feasibility repair, not the epigraph variable.

2.2 Epigraph nonlinear program

For fixed resolution `n`, define variables

    x = (h_0, ..., h_{n-1}, t)

or equivalently a vector `x` of length `n+1`, where `t` is named `z` in implementation notes. The smooth NLP is

    minimize z + rho * || h - a ||_2^2
    subject to
        z - dx*r_j(h) >= 0 for j = 0,...,2n-2,
        sum_i h_i - T = 0,
        0 <= h_i <= 1,
        0 <= z <= current_best_plus_margin.

The variable `a` is the anchor from which the local solve starts. Usually it is the current best feasible vector. The regularization constant `rho` is chosen small; `rho=0` is the pure objective. A small nonnegative `rho` is used initially or for noisy restarts to prevent the projected nonlinear step from moving into a much worse region. Candidate acceptance still uses the exact score without any regularization.

Constraints use the inequality convention required by SciPy's SLSQP implementation: inequality constraint functions must satisfy `g(x) >= 0`. Thus there are `M = 2n-1` vector inequality components

    g_j(x) = z - dx*r_j(h).

There is one equality component

    e(x) = T - sum_i h_i = 0.

Bounds

    0 <= h_i <= 1,
    lower_z <= z <= upper_z

are handled by SciPy bounds. `lower_z` is set to `0.0` or the previous best lower bound minus a few units, and `upper_z` to `max(parent_score, current_best + 0.05)`. These bounds do not change the returned exact score; they merely protect the local solve.

2.3 Closed-form constraint functions and derivatives

The full correlation relation used by NumPy for this task is

    r_s(h) = sum_i h_{i+s} * (1 - h_i)

for all indices for which `0 <= i < n` and `0 <= i+s < n`, where the full lag index `s` is

    s = j - (n - 1), j = 0,...,2n-2.

This formula is true for positive, negative, and zero lags. The zero-lag component is

    r_0(h) = sum_i h_i * (1 - h_i).

For `g_j(h,z)=z-dx*r_s(h)`, the derivative with respect to the auxiliary variable is

    partial g_j / partial z = 1.

For each component index `q` of `h`, the derivative of `r_s` is derived by summing two contributions from each term `h_{i+s}(1-h_i)`:

    partial r_s / partial h_q
      = I(0 <= q-s < n) * (1 - h_{q-s})
        - I(0 <= q+s < n) * h_{q+s}.

The indicators `I` are one when the index is in `[0, n-1]`, zero otherwise. Hence

    partial g_j / partial h_q
      = -dx * [ I(0 <= q-s < n) * (1 - h_{q-s})
                - I(0 <= q+s < n) * h_{q+s} ].

For the equality constraint `e(x)=T - sum(h)`,

    partial e / partial h_q = -1,
    partial e / partial z = 0.

For the objective `f(x)=z + rho*sum_i (h_i-a_i)^2`,

    partial f / partial h_q = 2*rho*(h_q-a_q),
    partial f / partial z = 1.

For exact gradient validation, use a pure Python brute-force finite-difference check once during startup for a small `n` (8 to 12) against a slow loop implementing `g_j`. If the analytic mismatch exceeds `1e-5` relative, halt that solver use and rely on finite-difference Jacobians inside SciPy, or skip that resolution. The exact accepted final candidate never depends on gradients.

2.4 Exact vectorized player

The derivative matrix can be assembled without loops for `n` up to about 192. Precompute integer source arrays of shape `(M,n)`:

    left_source[j,q] = clip(q - s_j, 0, n-1)
    left_mask[j,q]   = (0 <= q - s_j <= n-1)

    right_source[j,q] = clip(q + s_j, 0, n-1)
    right_mask[j,q]   = (0 <= q + s_j <= n-1)

Then

    dr_dh[j,q] = dx * (left_mask[j,q] * (1 - h[left_source[j,q]])
                       - right_mask[j,q] * h[right_source[j,q]]).

The inequality Jacobian row is `-dr_dh` plus a final column of ones. This direct construction avoids copying and aligns exactly with `np.correlate(..., "full")`.

Important indexing detail: do not rearrange by centering and do not assume signed lags in a formula different from this. The derivative code itself should be validated against the objective evaluator using brute force before large solves.
