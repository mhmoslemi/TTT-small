1. Approach and rationale

1.1 Central idea

The primary algorithm searches the feasible set
- `0 <= h[i] <= 1` for all `i`, and
- `sum(h) = n/2`,

using the *physical, non-smooth objective* only for acceptance and reporting, while optimizing inside a constrained solver a smooth relaxation of the maximum correlation. The relaxation is a log-sum-exp smoothing of the correlation values. At a current iterate, the gradient of the smooth surrogate can be computed relatively cheaply by accumulating the gradients of the finite-support correlation entries that are selected by the smoothing weights. This produces direct candidate moves in the full `n`-dimensional vector without explicitly introducing an epigraph variable and without repeatedly solving a large nonlinear envelope problem. The original discontinuous maximum objective remains the sole selection criterion after each smoothed step.

The physical nonconvexity remains. This is not a global-optimality proof. It is a local and exploratory ensemble method with a strict exact-validity gate.

1.2 Why this is likely useful for the supplied parent

The parent is already near the current record, so it is almost certainly a local basin rather than an arbitrary initial object. A direct non-smooth minimizer may stall because several lag correlations compete and the active set changes frequently. The smooth objective:
- gives a differentiable vector field that initially follows a weighted average of the worst lags,
- can reduce an entire cluster of near-worst correlations before applying a type increasingly hard to the true maximum, and
- does not impose an artificial endpoint-flat interior representation; the exact feasible set is enforced only through the linear sum constraint and bound constraints during the smooth solve, with an exact feasibility repair when returning or transferring candidates between stages.

1.3 Limitations

- The bilinear terms `h_i(1-h_j)` make the true problem nonconvex. Smooth constraint solvers obtain only locally constrained stationary points or paths.
- The smoothing parameter creates a nonconvex optimization even on the smooth surrogate. Eventually resetting to the unsupervised exact objective is mandatory.
- If the current record is a strict local optimum or its basin has very flat candidate sway, additional low-dimensional basin exploration and random constrained drift are provided, then rest of hom.
- No claimed global optimality. The returned rigorous bound is measured against the task evaluator.

2. Mathematical specification

2.1 Exact sampled-value convention

For a candidate vector `h`, shape `(n,)`, let

- `dx = 2.0 / n`
- `target = n / 2.0` so `sum(h) = target`.
- `v_s(h) = np.correlate(h, 1-h, mode="full")[s]`, for `s = 0,...,2*n-2`.
- The physical constant measured by the evaluator is

`C(h) = dx * max_s v_s(h)`.

All returned metrics are recomputed in this exact form, not substitute a maximum over a subset of shifts. There must be `2*n-1` full linear-correlation entries and no circular correlation.

The term represented by correlation entry `s` corresponds to lag/offset

`d_s = (n-1) - s`.

For this pair offset `d`, the overlapping pairs are
- `d >= 0`: `(i, i+d)` for `i=0,...,n-1-d`;
- `d < 0`: `(i, i+d)` for `i=-d,...,n-1`, inclusive.

For a term `h_i * (1 - h_j)` at offset `d = j-i`, derivatives are

`d/d h_i [h_i(1-h_j)] = 1-h_j`,  
`d/d h_j [h_i(1-h_j)] = -h_i`.

For `i=j`, combining the terms or applying the zero-offset formulas directly yields `1 - 2*h_i`.

These offset formulas follow the common full-correlation convention equivalent to convolution with the reversed second argument. If the coder uses another pair-order hypothesis, the exact finite difference test described later must force correction before using the gradient in high-dimensional solves.

2.2 Smooth envelope objective

Use a scalar attenuation `beta` in units of physical `C`, and define

`v_s^C(h) = dx * v_s(h)`.

Then the smooth envelope is

`L_beta(h) = (1/beta) * log(sum_s exp(beta * v_s^C(h)))`.

This is exactly `dx` times the log-sum-exp of the dimensionless correlation entries, so smoothing is무료 and minimizer choices coincide with using `dx` scaling. It is a differentiable surrogate that approaches `max_s v_s^C(h)` as `beta` increases.

The smoothing weights are

`w_s = exp(beta * (v_s(h)-max_v)) / sum_t exp(beta * (v_t(h)-max_v))`.

Thus

`L_beta(h) = max_v + (1/beta)*log(sum_s exp(beta*(v_s-max_v)))`, and

`grad L_beta = dx * sum_s w_s * grad v_s`.

The location of the true objective is known set `w_s`, but the exact physical `C` remains independent.

2.3 Efficiency of the surrogate gradient

Let `G` be the dimensionless gradient, column length `n`. For each entry `s` with scaled weight `w_s`, offset `d = (n-1)-s`, add to `G`:

For valid correlated linear-support pairs:
- increase `G[i]` by `w_s * (1 - h[i+d])`;
- decrease `G[i+d]` by `w_s * h[i]`.

In pseudocode, equality is included by `d=0` and the plus-minus contributions combine to `1-2*h[i]`.

Overall:

`grad L_beta = dx * G`.

The gradient must be tested against finite difference and, in particular, a deliberately skewed single-lag surrogate, to check the offset convention.

2.4 Constraints used by the optimizer

Each constrained solve uses:
- variables: full vector `h` of length `n`;
- bound constraints: `0 <= h_i <= 1`;
- one equality constraint: `sum(h) - target = 0`;
- objective: `L_beta(h)`, not exact `C(h)`.

The nonlinear equality is a linear or `NonlinearConstraint` from SciPy with gradient consisting of a all-one vector. Bounds are native bound constraints. CVXPY is not needed and is not appropriate for a global nonconvex solver in an unsupported sense.

The solver is a local solver. The plan invokes multiple starts. Every raw solver output is:
1. feasibility-projected, if needed;
2. converted to exact objective `C`;
3. accepted only by the exact physical objective.

2.5 Joint feasibility project

For any finite vector `x`, the projection needs both box constraints and the sum constraint. A practical deterministic projection is:

1. Clean non-finite entries. Replace them with `0.5`.
2. Clip all entries to `[0, 1]`, obtaining `z`.
3. Let residual `r = target - sum(z)`. If residual lies within tolerance, return `z`.
4. Deposit `r` under/pugar a feasibility loop:
   - If `r > 0`, use coordinates with slack `1-z[i]`; prefer a coordinate with the largest slack. Add to it at most its slack or at most `r`, then subtract from `r`.
   - If `r < 0`, use slack `z[i]`; subtract at most its value or at most `|r|`.
   - Prefer exact-value comparison and adjust thereafter. If tolerance persists and the maximum available cap is too small for that value, move to another real valued `ria`. Stop loops after `n` iterations; if impossible, call a bisection fallback.
5. Bisection fallback: find `lambda` such that `sum(clip(z - lambda,0,1)) = target`, because the left-hand sum is monotone nonincreasing in `lambda` and every clip is in the box. The bracket may be `[min(z)-1, max(z)+1]`, iterated 80 times. If bisection residual is small, apply greedy slack-subfx.
6. Return the feasible vector only if all values finite and `[0,1]`; otherwise return a structured anchor.

This projection maintains bounds whenever changing variables with slack and shifts the sum toward target; it does not first clip and then scale in arbitrary order.

2.6 Exact feasible fallback anchor

If a supplied parent is invalid or no parent is available, generate an explicit finite fallback to end exactly. Let `c = floor(target)`, `frac = target - c`.
- Start with a zero vector length `n`.
- Set the first `min(c,n)` entries to `1`.
- If `c < n`, set one remaining coordinate to `frac`.
For every legal `n` this vector has values `0, 0.5` or `1` and exact sum `n/2` (up to floating accuracy). If `n=0` or no positive support is legal, the caller layer must return a valid empty or very heavy fallback; however, the function `run` receives a positive sampled parent / parent condition, so target has meaningful length.

2.7 Transfer between resolutions

Candidates with different `n` are legal but, because evaluator correlation entries are dimensionful in sample offset and scaling, comparisons are made only by exact recomputed `C`, never by a dimensionless normalized value. If an `old` vector is transferred to a `new` length:
- Down-resolution if `new <= old`: group old entries into approximately equal contiguous bins or use linear piecewise interpolation on cell midpoints; then large-neighbor再说了 anti-alias. When lengths divide evenly for speed, use `remainder = old // new`, reshape `(new, old//new)`, and average along axis 1. If not divisible, compute discrete grid coordinates.
- Up-resolution: linearly interpolate the old grid to include both boundaries or use midpoint preserves. The boundary choice must be deterministic.
- Perform exact joint feasibility projection.
- Evaluate exactly. Accept a different length only if the physical score is lower than by an explicit acceptance margin. For a vector length change, an acceptance threshold of `1e-7` in physical `C` prevents exchanging a nearly equal score for a slightly lower numerical test overhead and floating ambiguity.
