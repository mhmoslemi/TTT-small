1. Approach and rationale

The supplied evaluator defines a finite, exact nonconvex minimax objective. The principal difficulty is not the maximum of the correlations per se, but the need to move a large feasible vector in directions that lower many nearly tied active correlations while maintaining the linear integral constraint and the entrywise bounds. A small improvement from the reported parent around 0.38085 is very sensitive: numerical drift in the sum constraint, bad transfers between grid sizes, or an objective formula that differs by lag ordering can destroy the attempt. Therefore the proposed program is built around an exact score evaluator as the only acceptance gate, a set of local/global driver algorithms, and a deterministic numerical representation that allows every returned vector to be made feasible after optimization.

The central idea is a multi-driver candidate-improvement loop. Different drivers are suited to different problems:

- A generic zero-sum direction step, driven by a weighted average gradient over active lags, proposes global simultaneous changes. This can move several flat correlations even when one-coordinate pair moves cannot.
- Full coordinate-pair minimization exactly solves one-dimensional max-of-affine subproblems along each feasible pair direction. This is powerful near a coordinated local minimum because any successful coordinated change decomposes into a sequence of pair moves and the exact subproblem can refine each movement immediately.
- A paired-reparametrized smooth-log-sum-exp optimizer reduces an even-size vector to natural constraints. This avoids numerical violations from general nonlinear projection and is useful from random and parent-derived starts.
- A resolution ladder transfers good candidates between small and larger grids, where the discrete objective and interpolation grids should be qualitatively similar but might expose better or slightly different constructions.

The exact evaluator remains authoritative. All smooth objectives, initialized directions, local one-dimensional subproblems, transfers, and rejected uphill explorations are merely drivers. A candidate is saved only if the exact evaluator proves a lower actual maximum. The method is local/heuristic. It is not a proof of global optimality. Its goal is to make repeated searches robust enough that a small improvement over the parent is found quickly when possible.

The algorithm prioritizes a guaranteed feasible vector over optimization ambition. The fallback hierarchy is explicit, including the parent construction, repaired/rescaled transfers, simple deterministic balanced constructions, and a feasibility-preserving quantized final repair. The final program never returns an array unless a feasibility check and exact score check have been performed on the array actually being returned.

2. Mathematical specification

2.1 Grid, constraints, and exact discrete objective

Let n be the sample count, dx = 2.0 / n, and h be a real vector of length n. The constraints are:
- 0 <= h[i] <= 1 for all i.
- sum_i h[i] = target = n / 2, equivalently integral equal to 1.

For the evaluator the authoritative score is:
C(h) = dx * max_k np.correlate(h, 1-h, mode="full")[k].

The sum over all discrete lags is over exactly 2n-1 lag locations, covering both orientations of every nonzero integer offset. The optimization and internal search must expose, or at least not replace, this exact objective. Formally define for k = -(n-1), ..., n-1:
- For k >= 0: F_k(h) = sum_{j=0}^{n-1-k} h[j+k] * (1 - h[j]).
- For k < 0: with p = -k, F_k(h) = sum_{j=p}^{n-1} h[j-p] * (1 - h[j]).
- For k = 0: F_0(h) = sum_{i=0}^{n-1} h[i] * (1 - h[i]).

Then C(h) = dx * max_k F_k(h). This expression includes both orientations of positive distances and always includes the zero lag. It matches the full-discrete-correlation sum after a possible reversal of the output vector. Therefore its maximum is the same, no matter which lag index an implementation uses. For acceptance and final evaluation, however, the plan still uses the actual evaluator formula based on np.correlate to avoid any indexing ambiguity between this alternate derivation and the supplied evaluator.

2.2 Internal component scoring function for fast search

All nonfinal candidate evaluations should use a helper equivalent to:

fast_score(h):
  n = len(h)
  dx = 2/n
  Create an array F of length 2n-1 initialized to zero.
  F[n-1] = dot(h, 1-h).
  For p = 1,...,n-1:
    F[n-1+p] = dot(h[p:n], 1-h[0:n-p])  # positive orientation
    F[n-1-p] = dot(h[0:n-p], 1-h[p:n])   # negative orientation
  Return dx * max(F)

This is a direct O(n^2) computation with length-n dot products. It should be used as the fast internal objective, except in final acceptance where the actual np.correlate evaluator is explicitly checked. If in implementation both are available, a cheap sanity check should compare fast_score(h) with max(np.correlate(h, 1-h, "full")*dx) for small random h; the maxima should agree up to numerical error.

2.3 Objective gradients for generic smooth and active steps

For a generic h in the interior of constraints, use the derivative of the same F_k. These formulas are exact for the discrete objective components and should be used by the smooth/active directions.

For lag k=0:
  dF_0/dh_i = 1 - 2*h_i.

For p=1,...,n-1, define positive part P_p = F_p:
  For 0 <= i < n-p: contribution to dF_p/dh_i is -h[i+p].
  For p <= i < n: contribution to dF_p/dh_i is 1-h[i-p].

For negative part N_p = F_{-p}:
  For 0 <= i < n-p: contribution to dN_p/dh_i is 1-h[i+p].
  For p <= i < n: contribution to dN_p/dh_i is -h[i-p].

All gradient components with respect to the final normalized score C(k)=dx*F_k are multiplied by dx. A helper should return a matrix G of shape (2n-1, n), whose row corresponding to each lag is dx times the above vector. If memory is needed for larger n, the helper may compute rows on demand or accumulate only active rows. The implementation should be careful not to overwrite vectorized slicing contributions; use slices with += and correct signs.

Internal gradients need not use lag permutation that exactly matches np.correlate output, as long as all positive/negative orientations are included and consistent between the value and gradient. The final score is still verified with the evaluator.

2.4 Paired feasible representation for even sizes

For even n, let m = n/2. Introduce u in [-0.5, 0.5]^m and define:
  h[2i] = 0.5 + u[i]
  h[2i+1] = 0.5 - u[i]
for i=0,...,m-1.

Each pair sums mathematically to 1, so total sum is m = n/2. Bounds are exactly equivalent to -0.5 <= u[i] <= 0.5. This map provides a sum-preserving explicit parameterization. In floating arithmetic, use this only as a driver; final quantization guarantees an exactly feasible float array.

A cyclic pair partition can also be used for smoother continuation:
  For offset s, take the ordered index list Perturb = tuple handle cyclic arrangement (s+2i mod n, s+2i+1 mod n), assign 0.5+u[i], 0.5-u[i]. Numerically, the sum remains balanced albeit float-drifted, and final quantization corrects drift.

The offset family is useful because adjacent-pair parameterizations of a parent approximation may otherwise distort a desired pattern. Try offsets 0 at least. For random smooth-started runs, try several offsets.

2.5 Smooth log-sum-exp driver

Smooth objective on scores C_l = dx*F_l:
  S_tau(h) = tau * log(sum_l exp(C_l / tau)).
where tau > 0 is a temperature. As tau -> 0, S_tau approaches max_l C_l. The search descends its gradient. Chain rule derivative:
  weights w_l = softmax(C_l / tau), sum_l w_l = 1.
  dS_tau/dh_i = sum_l w_l * dC_l/dh_i.

For paired variables u, apply:
  dS_tau/du_i = dS_tau/dh_{even_index} - dS_tau/dh_{odd_index} for the paired indices.

Use temperature schedule. Start tau_0 = clamp(0.02 * current_score(C)) in range [1e-4, 0.02]. Multiply tau by a decay factor given despite cycles convergence, until tau <= 5e-7. In implementation, maintain value/grad objective using the same internal helpers and the exact constructed h from pair variables. The smooth subproblem is not convex in u because the underlying objective components are bilinear. The L-BFGS-B method is only a smooth local driver.

2.6 One-dimensional exact form along pair moves

For a pair of distinct indices p,q in a general n vector, define a pair move parameter delta:
  h_p(delta) = h_p + delta
  h_q(delta) = h_q - delta
All other coordinates fixed.

The feasible delta interval is:
  lower = max(-h[p], h[q] - 1.0)
  upper = min(1.0 - h[p], -h[q])

The objective in delta is the maximum of finitely many affine functions so long as all other values remain fixed. It is actually convex on a feasible interval for the maximum of five affine horoz? Need necessarily monotonic? Max affine functions is convex in delta. Thus a standard interval unimodal search is valid. The paired variables for exact-pair are LSE smooth surrogate too.

A robust interval minimizer can be specified by ternary/golden-section search:
- Initialize interval endpoints as feasible lower, upper if lower <= upper (always for distinct variables, unless degenerate).
- Run for a fixed 60–90 evaluation stage.
- In each step split the interval with two slightly interior points.
- Evaluate by fast, nonrepairing raw objective C_raw(delta).
- If middle values indicate the minimum is left, replace upper; else lower.
- Finally evaluate endpoints and the golden candidate. The actual point with lower fast score is the minimizer proposal.

Since fast_score uses float h excluding final repair, drift of sum in the trial is only due to float addition/subtraction; if wrong, direct construction may be faithful e.g. evaluate all possible matrix or corrections. Since all returned stored vector will undergo exact quantile check, propagation approximation remains safe for driving.

For randomness or very large n, may use news grid with intervender relay to guarantee class steps, but final stored continuous candidate formation does—with quantize-sum output.
