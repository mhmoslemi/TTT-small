1. Approach and rationale
1.1 Central idea
The discretized problem is a nonsmooth nonconvex minimax problem over a bounded affine feasible set. A direct global optimization is not required or expected; the task is to obtain a better certified value for the discrete metric, preferably at a modest resolution and preferably near or below 0.3808.

The proposed construction uses a portfolio of local nonsmooth optimization methods that all use the exact discrete evaluator for acceptance:
- start from any supplied parent `initial_h_values`;
- repair it exactly onto the feasible set `0 <= h <= 1`, `sum(h) = n_points/2`;
- repeatedly create candidate vectors using:
  - active-lag linearized descent directions obtained from a small LP solved by `scipy.optimize.linprog`;
  - projected random perturbations and simulated-annealing-like moves;
  - stochastic binary and balanced-rotation seeds, then continuous polishing;
  - resolution transfer tests at nearby even sizes;
- accept and store only candidates whose exact objective, computed with `np.correlate`, is smaller than the current best.

This addresses the main bottleneck: the objective is nonsmooth and dominated by a small number of active lags. The linearized LP changes these active lags locally, preserving the constraints at the code model level; projected perturbations and rotations escape local minima; exact re-evaluation prevents any false improvement from surrogate relaxations. No global optimality is claimed.

1.2 Limitations
- The objective is nonconvex, so this is a local/global-heuristic search, not a proof of optimality.
- Active-lag LP directions use first-order linearizations around the current point and can overshoot, violate feasibility after repair, or be blocked at nonsmooth local stationary points.
- The best result might serve only a small or working resolution. If the supplied 42-point parent cannot be improved enough within the budget, the code returns the best valid candidate found. The fallback is the repaired parent or another valid seed.

2. Mathematical specification
2.1 Feasible set and profit score
Let `n = retry_points`. The discrete cell size is:
`dx = 2.0 / n`
and the feasibility constraints are:
`0 <= h[i] <= 1` and `sum(h) = n/2`.
The required score is exactly:
`F(h) = max_{q=0}^{2n-2} [np.correlate(h, 1-h, mode="full")[q] * dx]`.
Use only this value for reporting and for acceptance. Do not replace it with a different normalization, circular correlation, or a minimum/maximum autocorrelation heuristic.

2.2 Feasibility projection
Given any finite vector `z`, project it onto the feasible set in the `L2` sense. The feasible set is the intersection:
`[0,1]^n ∩ {x : sum(x)=target}`, where `target=n/2`.

Projection formula:
The projected point is `h = clip(z + lambda, 0, 1)` where scalar `lambda` satisfies
`sum(clip(z + lambda, 0, 1)) = target`.
Use monotonicity: this sum is nondecreasing in `lambda`. Use bisection, 50 to 60 iterations, followed by a residual correction so final sum exactly equals `target` up to tolerance. Add or remove residual mass only from coordinates that have available capacity in `[0,1]`. This provides a joint mechanism; clipping followed by naive scaling is never used.

2.3 Exact lag representation and derivative convention
For `lag = q - (n-1)` in `[-n+1, ..., n-1]`, use the evaluator-compatible convention: for lag `m >= 0`, the scalar correlation term is:
`corr_m = sum_{j=0}^{n-1-m} h[j+m] * (1 - h[j])`.
For lag `m = -s`, with `s > 0`, the scalar correlation term is:
`corr_{-s} = sum_{j=0}^{n-1-s} h[j] * (1 - h[j+s])`.
If `s=0`, `corr_0 = sum_i h[i]*(1-h[i])`.

Define `score_lag = corr_lag * dx`.

Unscaled gradient of `corr_lag` w.r.t. `h` is as follows. Let the overlap length `L = n - abs(lag)`.
For `lag = m >= 0`:
`g = zeros(n)`;
`g[m:n] += 1.0 - h[0:L]`;
`g[0:L] -= h[m:n]`.
For `lag = -s < 0`:
`g[0:L] += 1.0 - h[s:n]`;
`g[s:n] -= h[0:L]`.
For `m = 0` this simplifies to `g = 1.0 - 2.0*h`.

The exact-correlation gradient is `g_score = g * dx`.

At startup, compute the full score array by calling the real `np.correlate` evaluator and compare against a direct formula using the lag formula above. Use a runtime `reverse_lag_flag`: if direct formula matches `np.correlate`, use actual lag `q-(n-1)`. If direct formula matches it with lag sign reversed, because of a NumPy orientation difference, set `actual_lag = -(q-(n-1))` for gradients and active rollback. If neither mode matches, retain direct gradient disabled and use random finite-difference/projection methods. This self-check prevents relying on an undocumented indexing error.

2.4 Smoothed surrogate
For exploration, use the log-sum-exp surrogate:
`S(h; alpha) = alpha * log(sum_q exp(score[MAX_lag][q] - max_score)/(alpha))) / n)`.
Equivalent stable form:
`max_s = max_q score[q]`;
`shift = score - max_s`;
`S = (max_s + alpha * log(mean(exp(shift/alpha))))`.
Use finite `alpha`, typically `alpha = 0.03*max(best_score, 1e-4)` then anneal on a fixed multiplicative schedule towards `1e-4`. The gradient is:
`grad_S = sum_q softmax_q * grad_score[q]`,
where weights `softmax_q = exp((score[q]-max_s)/alpha)` and are normalized. When a runtime lag reversal was detected, use the corresponding actual lag before applying the gradient formula.

The smooth surrogate is only source-p; every accepted saved or output candidate requires `F(h)` computed from the actual evaluator and the candidate rescaled onto the feasible set.

2.5 Active-lag linearized direction
Let `h0` be feasible, let `s0=F(h0)`, and let active lag set `A` contain all lags satisfying `score[q] >= s0 - epsilon_active`. Use top few extra `q` if the active-set empty. For each active lag `q`, `grad_a` is the gradient of `score[q]`.
We search for a feasible perturbation direction `d`, with `sum(d)=0`, box-safe for step size 1, and an LP variable margin `m`, solving an LP:
maximize `m`
subject to for each active `a`: `grad_a dot d + m <= 0`;
`d_i + y_i >= 0`;
`-d_i - y_i >= 0`;
`sum_i y_i <= R.lp`;
`sum_i d_i = 0`;
`-h0_i <= d_i <= 1 - h0_i`;
`0 <= y_i <= R.lp`;
`0 <= m <= 1000`.
`R.lp` controls direction scale. The solver method is feasible if `d=0,m=0`. A positive `m` is a linearized direction reducing all active lags to first order.

After solving, direction `d` exact margin and point `candidate = clip(h0 + step*d, 0, 1)`, then repair projection and re-evaluate `F`. If step produces a new `F` worse after edge-projection, backtrack on `step`. Many local moves are rejected; only best exact improvement is retained. The LP formulation stays exact and linear once active gradients are numerical. The nonconvexity is addressed via exact verification, not proof.
