    if w_sum < 1e-300:

The real improvement needs to come from better optimization at a fixed n (or similar n).

Let me focus on making the optimization as effective as possible. Key ideas:

1. **The "plateau" problem**: Near the optimum, many peaks are nearly equal, and the objective is very flat in many directions. The subgradient is not very informative. The LSE smoothing helps by providing a smoother gradient that points in a more useful direction.

2. **The "bottleneck" peaks**: There are a few peaks that are significantly higher than the others. These are the "bottleneck" peaks that we need to reduce. The optimization should focus on these.

3. **Adaptive peak selection**: Instead of always targeting the top K peaks, I should target peaks that are "hard to reduce" (i.e., peaks where the subgradient has a small component in the feasible direction).

Let me try a different approach: **iteratively reweighted minimization with exact objectives**.

Algorithm:
1. Start with `a`
2. Compute `conv = a * a`
3. Find the peak locations `P = {k : conv_k > threshold}`
4. Construct the quadratic `Q(a) = sum_{k in P} w_k * conv_k(a)` where `w_k` are weights emphasizing the highest peaks
5. Minimize `Q(a)` subject to `a >= 0, sum(a) = 1` using projected gradient or other methods
6. Go to step 2

The key difference from LSE is that I use the exact quadratic (no exponential smoothing), but I select which peaks to include.

For step 5, the objective `Q(a) = a^T H a` where `H_{jm} = sum_{k in P} w_k * ([j+m=k] + [m+j=k])` (with appropriate bounds). This is a quadratic function, and I can minimize it using projected gradient with exact line search.

Actually, this is essentially the same as the LSE approach, just with different weights. The LSE approach uses `w_k = exp(beta * conv_k)` which naturally emphasizes the highest peaks. My approach would use similar weights.

So the main improvement I can make is:
1. **Better step size control** (Polyak or backtracking)
2. **More peaks** (include more peaks in the gradient)
3. **Better initialization**
4. **Adaptive switching between methods**

Minimizes 2*n*max(conv(a,a))/(sum(a))^2.
Uses:
1. Multi-init (parent, parametric windows, random)
2. LSE gradient with Polyak-inspired step size
3. Exact subgradient with near-peak averaging
4. Adaptive method switching
5. Multi-n exploration

import numpy as np
import time

def fast_convolve(a):
    n = len(a)
    size = 2 * n - 1
    fft_size = 1 << (size - 1).bit_length()
    A = np.fft.rfft(a, fft_size)
    return np.fft.irfft(A * A, fft_size)[:size]

def project_simplex(v):
    n = v.size
    if n == 1:
        return np.array([max(v[0], 0.0)])
    u = np.sort(v)[::-1]
    cssv = np.cumsum(u)
    cond = u * np.arange(1, n + 1) > (cssv - 1)
    if not cond.any():
        return np.ones(n) / n
    rho = np.nonzero(cond)[0][-1]
    theta = (cssv[rho] - 1.0) / (rho + 1.0)
    return np.clip(v - theta, 0.0, None)

def grad_at_peak(f, k):
    n = len(f)
    kr = int(k)
    lo = max(0, kr - n + 1)
    hi = min(n - 1, kr)
    g = np.zeros(n)
    if lo <= hi:
        m1 = np.arange(lo, hi + 1)
        g[m1] += f[kr - m1]
    m2lo = max(0, kr - hi)
    m2hi = min(n - 1, kr - lo)
    if m2lo <= m2hi:
        m2 = np.arange(m2lo, m2hi + 1)
        g[m2] += f[kr - m2]
    return g

def weighted_grad(f, w, max_terms=500):
    """Compute sum_k w[k] * grad_k efficiently using only top w terms."""
    n = len(f)
    g = np.zeros(n)
    idx = np.argsort(w)[::-1][:max_terms]
    for ki in idx:
        wi = w[ki]
        if wi < 1e-18:
            continue
        g += wi * grad_at_peak(f, ki)
    return g

def lse_grad(f, beta, n_peaks=300):
    n = len(f)
    conv = fast_convolve(f)
    bc = beta * conv
    m = bc.max()
    w = np.exp(bc - m)
    ws = w.sum()
    if ws < 1e-300:
        w = np.zeros_like(conv)
        w[np.argmax(conv)] = 1.0
    else:
        w /= ws
    return weighted_grad(f, w, max_terms=n_peaks), conv
