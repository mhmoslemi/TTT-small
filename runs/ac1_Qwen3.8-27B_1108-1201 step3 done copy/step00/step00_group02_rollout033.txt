This is a polynomial of degree $n-1$ only if the square root is a polynomial. In general, it's not. So a perfectly flat convolution is generally impossible with a polynomial $A(z)$ of degree $n-1$.

But we can get close! The "closest" polynomial to this square root (in some norm) would give a nearly flat convolution.

This is related to the concept of "perfect sequences" in signal processing.

**Practical approach: Minimize the variance of the convolution**

Instead of trying to achieve a perfectly flat convolution, let's minimize the variance (or the max-min gap) of the convolution. This is a convex-ish problem that we can attack with gradient methods.

Objective: $\text{Var}(a*a) = \frac{1}{2n-1} \sum_k ((a*a)_k - \bar{c})^2$ where $\bar{c} = 1/(2n-1)$ (since $\sum c = 1$ when $\sum a = 1$).

This is a quartic function of $a$ (since $(a*a)_k$ is quadratic in $a$, and we're squaring it). But we can compute its gradient.

Alternatively, minimize $(\max c - \min c)$ or just $\max c$ (since $\min c \geq 0$ for non-negative $a$).

Let me go with the **subgradient method on max(c)** with FFT-accelerated convolution.

**Final algorithm design:**

1. Start from the given sequence (or a better initialization).
2. Iterate:
   a. Compute $c = a * a$ via FFT.
   b. Find the max position $k^*$.
   c. Compute the subgradient of $(a*a)_{k^*}$: $g_i = 2 a[k^*-i]$ (if valid).
   d. Update $a \leftarrow a - \eta g$, project onto $\{a \geq 0, \sum a = 1\}$.
   e. Adapt $\eta$ based on progress.
3. Periodically try alternative moves (random perturbations, different peak positions).
4. Keep track of the best solution.

For efficiency, I'll compute the score using FFT internally and only call `evaluate_sequence` at the end (or occasionally to verify).

Let me also add a **multi-peak** consideration: instead of just the single max, consider the top few peaks and use their combined gradient.

```python
import numpy as np
import time

def auto_convolve(a):
    """Compute auto-convolution using FFT for speed."""
    n = len(a)
    N = 1  # Find next power of 2 >= 2n-1
    while N < 2*n - 1:
        N *= 2
    F = np.fft.rfft(a, N)
    result = np.fft.irfft(F * F, N)
    return result[:2*n-1]

def fast_score(a):
    """Compute the score without calling evaluate_sequence."""
    n = len(a)
    c = auto_convolve(a)
    max_c = c.max()
    sum_a = a.sum()
    if sum_a < 0.01:
        return np.inf
    return float(2 * n * max_c / (sum_a ** 2))
```

```python
def compute_grad(a, k):
    """Compute gradient of (a*a)_k with respect to a."""
    n = len(a)
    grad = np.zeros(n)
    # (a*a)_k = sum_j a_j * a[k-j]
    # d/d a_i = 2 * a[k-i] for valid i
    # k-i must be in [0, n-1], so i in [k-n+1, k]
    i_start = max(0, k - n + 1)
    i_end = min(n, k + 1)
    # For i in [i_start, i_end]: grad[i] = 2 * a[k - i]
    # k - i ranges from k - i_start to k - i_end + 1
    j_start = k - (i_end - 1)  # = max(0, k - i_end + 1)
    j_end = k - i_start + 1    # exclusive
    grad[i_start:i_end] = 2.0 * a[j_start:j_end][::-1]
    return grad
```

This is $O(n)$ with no Python loop, so it's fast.

```python
        N *= 2
    F_ax = np.fft.rfft(a[::-1], N)
    F_y = np.fft.rfft(Cc, N)
    conv = np.fft.irfft(F_ax * F_y, N)
    # cross_correlate(x, y)[i] = conv[i + len(x) - 1]
    grad = (4.0 / (2*n-1)) * conv[n-1 : n-1+n]
    return grad
```

This is $O(n \log n)$ per iteration, which is fast.

But wait, I also need to handle the constraint $\sum a = 1$. The gradient should be projected onto the tangent space of the constraint. The simplest way is to subtract the mean of the gradient:

$g_{\text{proj}} = g - \text{mean}(g)$

This ensures $\sum g_{\text{proj}} = 0$, so the step doesn't change the sum.

Then the update is: $a \leftarrow a - \eta \cdot g_{\text{proj}}$, followed by projection to $a \geq 0$ and renormalization.

Actually, if I project to $a \geq 0$ and renormalize, the constraint is handled. But the projection might undo some of the gradient step. For a "good" initial point, the non-negativity constraint should not be active (all $a_i > 0$), so the projection is a no-op.

Hmm, but minimizing the variance might not directly minimize the max. The variance is a "softer" objective. Let me try both: first minimize variance, then minimize max.

Actually, I think minimizing the max directly (via subgradient) would be more effective, but the variance gradient is smoother and might help with convergence.

Let me combine both: use the variance gradient for the main update, and occasionally use the max gradient for a "correction" step.

Or better: use a **composite objective** $\max(C) + \lambda \cdot \text{Var}(C)$ with a small $\lambda$. The max part gives the right direction, and the variance part smooths it out.

But the max is not differentiable. I can use a smooth approximation: $\log(\sum \exp(C_k / T)) \cdot T$ (the "log-sum-exp" approximation to the max).

For a single iteration:
- Compute $C$.
- Compute the smooth max: $f = T \cdot \log(\sum \exp(C_k / T))$.
- Compute the gradient: $\partial f / \partial a_i = \frac{1}{\sum \exp(C_k / T)} \sum_k \exp(C_k / T) \cdot 2 a[k-i]$.

This is a weighted average of the individual gradients, weighted by $\exp(C_k / T)$. For small $T$, this concentrates on the max; for large $T$, it's more spread out.

The gradient can be computed as:
$\text{grad} = 2 \cdot \text{cross-correlate}(a, w)$ where $w_k = \exp(C_k / T) / \sum \exp(C_k / T)$.

This is again a cross-correlation, computable via FFT!

Let me implement this:

```python
def smooth_max_gradient(a, C, T=1.0):
    """Compute gradient of smooth max of C with respect to a."""
    n = len(a)
    # Softmax weights
    C_shifted = C - C.max()  # For numerical stability
    w = np.exp(C_shifted / T)
    w = w / w.sum()
    
    # grad_i = 2 * sum_k w_k * a[k-i] (for valid k-i)
    # = 2 * cross_correlate(a, w)
    N = 1
    while N < n + len(w) - 1:
        N *= 2
    F_ax = np.fft.rfft(a[::-1].copy(), N)
    F_w = np.fft.rfft(w, N)
    conv = np.fft.irfft(F_ax * F_w, N)
    grad = 2.0 * conv[n-1 : n-1+n]
    return grad
```

This gives a smooth, well-defined gradient that points in the direction of reducing the "soft max" of the convolution.

**Final algorithm:**

1. Compute $C = a * a$ via FFT.
2. Compute the soft-max gradient via FFT.
3. Update $a$ with gradient descent (with momentum).
4. Project to $a \geq 0, \sum a = 1$.
5. Adapt learning rate and temperature $T$.

The temperature $T$ controls the "sharpness" of the focus on the max:
- Large $T$: gradient is spread over all peaks (smoother, slower but more stable).
- Small $T$: gradient focuses on the single max (sharper, faster but noisier).

I'll start with a moderate $T$ and decrease it over time.

Let me also add a **restart mechanism**: if progress stalls (no improvement for many iterations), perturb the solution and restart.
