1. Approach and rationale
Use a projected, multi-start local search for the finite-dimensional minimax problem. At each point, replace the nonsmooth maximum over lags temporarily by a log-sum-exp approximation, take projected gradient steps on that smooth objective, and gradually lower its temperature. Use exact evaluator scores—not the surrogate—to maintain and return the best feasible candidate. Start from the supplied construction when it is valid, then explore seeded random feasible starts and perturbations of the best candidate found.

The supplied construction has 45 samples, so each full-support correlation and its gradient are small enough for direct lag-by-lag calculations. The objective is generally nonconvex because it contains products of entries of h; a local method with restarts is appropriate, whereas an unsupported convex formulation would not solve the stated problem. Projection onto the capped simplex enforces the box and integral constraints jointly. This is a heuristic search: it may find a better construction, but neither local descent nor restarts guarantee a global minimum or that the target 0.3808 is reached. The expected parent score and target are goals, not promised results.

2. Mathematical specification
For a vector h of length n, let dx = 2/n and S = n/2. The feasible set is {h in R^n : 0 ≤ h[i] ≤ 1 and sum_i h[i] = S}. Use all integer lags k from -(n-1) through n-1, with finite-support overlap
q_k(h) = dx * sum over i from max(0,-k) through min(n-1,n-1-k) of h[i+k] * (1-h[i]).
The authoritative objective is C(h) = max_k q_k(h). This is exactly the maximum of np.correlate(h, 1-h, mode="full") multiplied by dx: the lag convention may reverse the order of the full-correlation output, but the set of terms and its maximum are identical. Do not use circular correlation or omit the shortened overlap at nonzero lags.

For each lag, the derivative is
∂q_k/∂h[j] = dx * ( 1[j-k is in I_k] * (1-h[j-k]) - 1[j is in I_k] * h[j+k] ),
where I_k is the summation interval above and a term is absent when its indicator is zero. Equivalently, for each i in I_k, add dx*(1-h[i]) to the derivative at i+k and subtract dx*h[i+k] at i. This latter rule is straightforward to implement with slices and also covers k=0.

For temperature τ > 0, optimize the smooth surrogate Fτ(h) = τ log(sum_k exp(q_k(h)/τ)). Compute it stably as m + τ log(sum_k exp((q_k-m)/τ)), where m=max_k q_k. Its gradient is sum_k w_k ∇q_k, with w_k=exp((q_k-m)/τ)/sum_l exp((q_l-m)/τ). It satisfies max_k q_k ≤ Fτ ≤ max_k q_k + τ log(2n-1). The surrogate guides the search only; every stored score and the returned score use the exact maximum correlation.

Project any finite vector v onto the feasible set by finding λ such that sum_i clip(v[i]-λ,0,1)=S, then returning clip(v-λ,0,1). The left-hand side is continuous and nonincreasing. Bracket the root with low=min(v)-1 and high=max(v), and bisect. Correct the remaining floating-point sum residual by adding it across available capacities 1-h[i], or subtracting it across available h[i], never crossing a box bound. This is a joint projection/repair, not sequential clipping and rescaling.

3. Implementation procedure
1. Implement `run(seed=42, budget_s=1100, **kwargs)` at top level, and define any helpers as top-level functions, with no closures or lambdas. Use only NumPy and the standard library as needed; no solver is required. Do not perform filesystem or network I/O, and do not mutate the pre-imported `initial_h_values` array.

2. Start a monotonic timer. Convert a finite, nonnegative budget_s to a usable number of seconds; if it is absent or invalid, use 1100. Set a work deadline earlier than the hard deadline by reserve = min(5 seconds, max(0.05 seconds, 0.005*budget_s)). If the budget is zero or too small to leave work time, skip search and return a valid fallback after its score is available. Check the work deadline between trials, temperatures, iterations, and line-search attempts. Allow final validation and authoritative scoring to use the reserved interval.

3. Determine n from a usable, one-dimensional, nonempty `initial_h_values` if available; otherwise use n=45. Convert the parent with `np.asarray(..., dtype=float)` so an already-float NumPy parent can be used directly, and do not write into it. Reject a malformed shape, empty array, or nonfinite parent. A finite parent of the supplied dimensions is used as the source of the starting point; do not hard-code or reconstruct its entries. This plan keeps the parent resolution, so no interpolation or resolution transfer is performed. If no usable parent exists, construct a seeded NumPy generator from seed and start at n=45.

4. Provide a top-level capped-simplex projection helper implementing the formula in Section 2. Use 70 bisection iterations, then make a residual correction by traversing coordinates and consuming only their available capacity; recompute the residual from the resulting array and make a second correction pass if needed. Return float64 values. The correction must preserve 0 ≤ h[i] ≤ 1 and leave sum(h) within a small floating-point tolerance of S. Reject nonfinite input to this helper rather than returning a nonfinite candidate.

5. Provide a top-level exact-score helper. For a finite one-dimensional feasible h, calculate dx=2.0/n and return `float(np.max(np.correlate(h, 1.0-h, mode="full") * dx))`. This direct operation is authoritative. Provide a separate feasibility helper checking the expected shape, finiteness, box bounds, and `abs(sum(h)-n/2) <= 1e-9*max(1,n)`. Allow only harmless floating-point tolerance at the box endpoints; if a candidate exceeds that tolerance, project it before considering it. Do not silently accept a nonfinite score.

6. Provide a top-level lag helper that returns a float64 vector of length 2*n-1. Enumerate k in ascending order from -(n-1) to n-1, set lo=max(0,-k), hi=min(n-1,n-1-k), and compute q[k+n-1] as dx times the dot product of h[lo+k:hi+k+1] and 1-h[lo:hi+1]. This uses only overlapping indices and has no wraparound. Provide a top-level smooth-value-and-gradient helper: compute these q values, the stable log-sum-exp value, its normalized weights, and the gradient by iterating over lags and applying the derivative accumulation rule in Section 2. Do not allocate a dense n-by-n matrix.

7. Establish a fallback before searching. If the parent is finite, in the box, and has sum within the feasibility tolerance, retain that supplied array as a valid fallback and score it exactly. Use the parent itself as the initial search source, passing it through the joint projection when a repair is needed; projection and all later updates must produce new arrays rather than mutating the parent. If a finite but infeasible parent is available, project it and retain the projected vector as fallback. If there is no usable parent, draw a seeded uniform vector in [0,1], project it, and retain that feasible vector. If an exact score is nonfinite or scoring fails, do not use that vector; generate or keep a finite projected fallback. Keep the best vector and its score separately from the current local-search vector so a worse surrogate step can never erase the fallback.

8. Run projected gradient descent independently from each trial start. Defaults are temperatures [0.02, 0.005, 0.001, 0.0002], 40 iterations per temperature, initial step size α=1, maximum 16 backtracking attempts, Armijo constant 1e-4, and a maximum accepted step size of 10. At each temperature compute Fτ and its gradient g. For a proposed step, form y=Project(h-αg) and d=y-h. If the squared norm of d is at most 1e-18, stop that temperature. Otherwise evaluate Fτ(y) and accept when Fτ(y) ≤ Fτ(h) + 1e-4*g·d + 1e-12. If the condition fails, halve α and retry. If no attempt is accepted, end that trial rather than applying an unchecked step. After acceptance set h=y, carry the accepted point into the next iteration, and increase the next α by a factor of 1.25 up to 10. Reset α to 1 when beginning each temperature. Stop the trial if its gradient, surrogate, or proposal becomes nonfinite, or the work deadline is reached.

9. At each trial start and after every accepted step, check feasibility and compute the exact score with the exact-score helper. Update the global best only when the candidate passes all checks and its exact score is strictly lower than the stored score (using a 1e-12 comparison tolerance to avoid replacing a candidate for roundoff-level differences). The current local-search point may be retained even when its exact score is worse, because the next smoothed step can improve it; the global best is never replaced by such a point.

10. The first trial starts from the supplied parent, or the projected random fallback if there is no parent. Subsequent trials are seeded and deterministic for the same seed. Every fifth subsequent trial starts from a newly drawn uniform [0,1] vector projected onto the feasible set. Other trials start from `Project(best_h + sigma*z)`, where z has independent standard-normal entries and sigma cycles through [0.03, 0.08, 0.20, 0.45, 0.80]. After six consecutive trials without a best-score improvement, use the largest sigma for the next three perturbation trials, then resume the cycle. These are basin-escape heuristics, not guarantees.

11. Permit at most 200 total trials and stop sooner at the work deadline. Check time inside the descent and line-search loops as well as between trials. If a time limit interrupts a trial, discard any incomplete proposal and keep the last feasible best. If no improvement occurs, continue with the specified restarts while budget and trial count remain; do not invent an unbounded inner loop.

12. Before return, recheck the stored vector. If it is infeasible only from roundoff, project it and score the repaired vector; compare that exact score against the retained fallback and use the better valid candidate. Recompute the selected candidate's authoritative score using the exact `np.correlate` expression immediately before returning. If this final check fails, return the already validated fallback and recompute its exact score. Return `(h_values, c5_bound, n_points)`, where h_values is a one-dimensional finite NumPy array, c5_bound is the exact score just computed, and n_points is its length.

4. Search choices and useful variations
Use the defaults in Section 3 without preliminary tuning. The principal correctness requirements are finite-support full correlation, the capped-simplex constraint, exact-score candidate comparison, parent preservation, and a deadline-protected fallback. The permitted heuristic choices are restart count, temperatures, iteration count, and perturbation scales. A coder may vary these within practical ranges of 20–80 iterations per temperature, 50–200 total trials, temperatures from roughly 0.01 down to 0.0001, and perturbation scales from 0.02 to 1.0, but must keep a complete default and bounded loops. If using result-dependent changes, make them deterministic rules within the running program, such as increasing perturbation after a specified number of stale trials; do not rely on experiments or external feedback. Do not change resolution for the supplied 45-sample parent. No claim of reaching the target or of global optimality is justified.

5. Compute budget and robustness
All cost estimates here are unmeasured. For one overlap-vector or gradient calculation, the total number of contributing pairs across lags is n squared, so the dominant work is O(n²); exact `np.correlate` has the same order for the evaluator’s direct operation. Projection costs O(70n) with the specified bisection. For n=45, each lag pass has only 45² pair contributions and the lag vector has 89 entries. Memory is O(n), plus O(2n-1) lag values and weights; do not build dense quadratic arrays. Larger runtime parents increase the quadratic work, so the deadline checks are essential.

Use the monotonic deadline and reserve described in Section 3. The supplied parent or projected initial construction is scored before search and retained throughout. A nonfinite gradient, surrogate, score, or proposal terminates that trial; a failed line search terminates that trial; a candidate outside the feasibility tolerance is rejected or jointly projected before scoring. Stable log-sum-exp prevents exponential overflow. If no candidate improves the starting solution, return the valid starting fallback. The final exact score is recomputed within the reserved time; all these estimates are resource-planning estimates, not measured performance claims.

6. Runtime safeguards and return contract
During execution, verify input shape, nonempty length, and finite values before using a parent. Verify every initialized, projected, or accepted candidate for one-dimensional shape, finite entries, box bounds, and the sum constraint. The only feasibility repair is projection onto the capped simplex with residual correction; never clip and then independently rescale. Score every candidate eligible to become the best with the exact full `np.correlate` evaluator expression, and reject nonfinite scores. Keep the validated starting construction as a fallback even if all optimization trials fail or the deadline is reached.

Immediately before returning, verify the selected vector again and calculate its authoritative score from the exact evaluator formula. If validation or scoring fails, use the retained fallback and calculate that fallback’s score. Return only the required three-tuple `(h_values, c5_bound, n_points)` with n_points equal to `len(h_values)`. No result-dependent external action, testing, or follow-up is part of the program.
